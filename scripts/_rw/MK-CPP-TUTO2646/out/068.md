### уровень доступа и спецификатор protected

если переменные или функции базового класса закрыты, то есть объявлены со спецификатором `private`, производный класс эти члены наследует, но обращаться к ним не может. наследование включает их в подобъект базового класса, а проверка имён выполняется при компиляции. ниже в производном классе определяется функция, которая пытается вывести значения приватных переменных базового класса:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name, unsigned age)

    {

        this->name = name;

        this->age = age;

    }

    void print() const

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

private:		// закрытые переменные - доступ из производного класса недоступен

    std::string name;       //  имя

    unsigned age;           // возраст

};



class Employee: public Person

{

public:

    Employee(std::string name, unsigned age, std::string company): Person(name, age)

    {

        this->company = company;

    }

    void printEmployee() const

    {

        std::cout << name << " works in " << company << std::endl;	// ! Ошибка

    }

private:

    std::string company;

};
```

в базовом классе `Person` определены приватные переменные `name` и `age`. в производном классе `Employee` функция `printEmployee` обращается к `name`, чтобы вывести её значение на консоль. такое обращение ошибочно: `name` и `age` являются закрытыми членами `Person`, и класс `Employee` к ним доступа не имеет. закрытость не меняет размещение полей в памяти объекта. приватные члены входят в подобъект `Person` и занимают место, но их имена видны только в `Person` и в его друзьях.

иногда нужны члены базового класса, доступные производным классам и недоступные из внешнего кода. это уровень `private`, дополненный доступом для производных классов. для таких членов используется спецификатор `protected`.

например, переменная `name` определяется со спецификатором `protected`:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name, unsigned age)

    {

        this->name = name;

        this->age = age;

    }

    void print() const

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

protected:

    std::string name;   // доступно из производных классов

private:

    unsigned age;

};

class Employee: public Person

{

public:

    Employee(std::string name, unsigned age, std::string company): Person(name, age)

    {

        this->company = company;

    }

    void printEmployee() const

    {

        std::cout << name << " works in " << company << std::endl;

    }

private:

    std::string company;    // компания

};



int main()

{

    Person person {"Tom", 38};

    person.print();     // Name: Tom       Age: 38



    Employee employee {"Bob", 42, "Microsoft"};

    employee.printEmployee();   // Bob works in Microsoft

}
```

переменная `name` используется в производном классе, в том числе в методе `printEmployee`, но извне базового и производного классов к ней по-прежнему нельзя обратиться. `protected` входит в интерфейс для наследников и связывает их с представлением базы: производный класс может читать и менять такое состояние. если инвариант базового класса держится на этих членах, наследник способен его нарушить.

### уровень доступа членов базового класса

спецификаторы доступа `public`, `private`, `protected` определяют, к каким именно переменным и функциям базового класса могут обращаться производные классы. на доступ также влияет спецификатор доступа базового класса, который указывается при установке наследования:

```cpp
class Employee: public Person
```

в примере выше используется спецификатор `public`. допустимы три варианта: `public`, `protected` или `private`. если спецификатор базового класса явным образом не указан:

```cpp
class Employee: Person
```

по умолчанию применяется спецификатор `private`. при наследовании структур, если спецификатор доступа не указан, по умолчанию применяется спецификатор `public`. то же соглашение действует и для членов: у `class` члены по умолчанию закрыты, у `struct` открыты.

в базовом классе при определении переменных и функций доступны три спецификатора управления доступом: `public`, `protected` или `private`. те же три спецификатора применяются при установке наследования от базового класса. эти спецификаторы накладываются друг на друга и образуют 9 возможных комбинаций. для членов `public` и `protected` эффективный доступ имени в производном классе равен более строгому из двух спецификаторов. члены `private` базы во всех трёх комбинациях со спецификатором наследования остаются для производного класса недоступными.

если члены базового класса определены со спецификатором `private`, в производном классе они недоступны независимо от спецификатора доступа к базовому классу.

если спецификатор базового класса `public`, уровень доступа унаследованных членов остаётся неизменным. унаследованные открытые члены являются общедоступными, а унаследованные члены со спецификатором `protected` сохраняют этот спецификатор и в производном классе. публичное наследование задаёт отношение подтипа: снаружи класса указатель и ссылка на производный тип неявно преобразуются к указателю и ссылке на базовый, а открытый интерфейс базы остаётся открытым интерфейсом наследника.

если спецификатор базового класса `protected`, все унаследованные члены со спецификаторами `protected` и `public` в производном классе наследуются как `protected`. смысл в том, что если у производного класса будут свои классы-наследники, в этих классах-наследниках также можно обращаться к подобным членам базового класса. внешний по отношению к иерархии код такого доступа не получает.

если спецификатор базового класса `private`, все унаследованные члены со спецификаторами `protected` и `public` в производном классе наследуются как `private`. они доступны в любой функции производного класса, но вне производного класса, в том числе у его наследников, недоступны. закрытое наследование не публикует отношение подтипа: неявное преобразование к базе снаружи производного класса недоступно, база используется как деталь реализации.

пример со спецификатором базового класса `private`:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name, unsigned age)

    {

        this->name = name;

        this->age = age;

    }

    void print() const

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

protected:

    std::string name;   // доступно из производных классов

private:

    unsigned age;

};

class Employee: private Person

{

public:

    Employee(std::string name, unsigned age, std::string company): Person(name, age)

    {

        this->company = company;

    }

    void printEmployee() const

    {

		print();    // функция print внутри класса Employee доступна

        std::cout << name << " works in " << company << std::endl;

    }

private:

    std::string company;    // компания

};



int main()

{

    Employee employee {"Bob", 42, "Microsoft"};

    employee.printEmployee();   // Bob works in Microsoft

    // employee.print();       // функция print недоступна

}
```

поскольку спецификатор базового класса `Person` равен `private`, класс `Employee` наследует переменную `name` и функцию `print` как private-члены. к таким переменным и функциям можно обратиться внутри класса `Employee`. вне класса `Employee` они недоступны:

```cpp


Employee employee {"Bob", 42, "Microsoft"};

// employee.print();       // функция print недоступна
```

если создать новый класс и унаследовать его от `Employee`, например класс `Manager`:

```cpp


class Manager: public Employee

{

public:

    Manager(std::string name, unsigned age, std::string company): Employee(name, age, company)

    { }

};
```

то переменная `name` и функция `print`, закрытые в `Employee`, в классе `Manager` недоступны. для `Manager` эти имена уже закрыты в `Employee`, дальнейший наследник их не видит.

### установка публичного доступа

если в примере выше для класса `Employee` всё же нужно вызвать функцию `print`, уровень доступа восстанавливается ключевым словом `using`:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name, unsigned age)

    {

        this->name = name;

        this->age = age;

    }

    void print() const

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

protected:

    std::string name;   // доступно из производных классов

private:

    unsigned age;

};

class Employee: private Person

{

public:

    Employee(std::string name, unsigned age, std::string company): Person(name, age)

    {

        this->company = company;

    }

    using Person::print;

    void printEmployee() const

    {

        std::cout << name << " works in " << company << std::endl;

    }

private:

    std::string company;    // компания

};



int main()

{

    Employee employee {"Bob", 42, "Microsoft"};

    employee.print();  // Name: Bob       Age: 42 - функция доступна

}
```

в классе `Employee` уровень доступа к функции `print` базового класса `Person` устанавливается как `public`:

```cpp
using Person::print;
```

после этого функция `print` имеет свой первоначальный спецификатор доступа `public` и доступна вне класса `Employee`:

```cpp


Employee employee {"Bob", 42, "Microsoft"};

employee.print();    // Name: Bob       Age: 42 - функция доступна
```

объявление `using` не создаёт новую функцию. оно вводит в область видимости производного класса уже существующее имя и назначает ему доступ той секции, в которой стоит `using`. исходный член при этом должен быть доступен: поднять доступ так можно у членов `public` и `protected`.

подобным образом делается публичной и переменная `name`, несмотря на то, что в базовом классе `Person` она определена как `protected`:

```cpp
using Person::name;
```

если переменные и функции определены в базовом классе как приватные, сделать их публичными нельзя. имя закрытого члена в производном классе недоступно, и `using`-объявление для него не составляется.
