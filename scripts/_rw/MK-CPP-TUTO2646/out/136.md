выражение **requires** конкретизирует и детализирует ограничения до уровня отдельных выражений. оно имеет следующие формы:

```cpp


requires { требования }

requires (параметры) { требования }
```

после слова `requires` может идти необязательный список параметров в круглых скобках, во многом аналогичный списку параметров функции. за списком параметров в фигурных скобках указываются требования, которые могут использовать эти параметры. каждое требование заканчивается точкой с запятой. требования бывают простыми и составными. параметры выражения `requires` никогда не привязываются к фактическим аргументам, а выражения в фигурных скобках никогда не выполняются во время выполнения. компилятор проверяет только одно: образуют ли эти выражения допустимый код c++. проверяется корректность подстановки. значение выражения при этом не вычисляется.

#### простые требования

простое требование представляет произвольное выражение c++. если это выражение для указанных типов допустимо, тип удовлетворяет требованию.

для выражения `requires` может быть задано множество требований, и тип должен удовлетворять всем этим требованиям. например:

```cpp


#include <iostream>

#include <string>



template <typename T>

concept operation = requires (T item)

{

    item + item; item - item; item * item;

};



class Counter{};

int main()

{

    std::cout << std::boolalpha << operation<int> << std::endl;         // true

    std::cout << std::boolalpha << operation<char> << std::endl;        // true

    std::cout << std::boolalpha << operation<std::string> << std::endl; // false

    std::cout << std::boolalpha << operation<Counter> << std::endl;     // false

}
```

здесь определён концепт `operation`, ограничения которого задаются выражением `requires`:

```cpp


requires (T item)

{

    item + item; item - item; item * item;

};
```

выражение `requires` определяет один параметр типа `T`, который проверяется на соответствие требованиям. здесь заданы три требования: `item + item`, `item - item` и `item * item`. берётся тип `T`, и проверяется, допустимы ли для объекта этого типа подобные выражения. чтобы выражения были допустимы, для типа `T` должны быть определены операции сложения, вычитания и умножения. тип `T` должен соответствовать **всем** этим требованиям: набор требований является конъюнкцией.

в функции `main` различные типы проверяются на соответствие концепту `operation`. например:

```cpp
operation<int>
```

для типа `int` определены все заявленные операции: сложение, вычитание и умножение. данное выражение возвращает `true`. то же касается типа `char` в выражении `operation<char>`.

тип `std::string` поддерживает только операцию сложения, объединение строк, поэтому следующее выражение возвращает `false`:

```cpp
operation<std::string>  // false
```

то же касается пустого класса `Counter`, для которого не определено никаких из этих операций:

```cpp
operation<Counter>  // false
```

в качестве выражений в блоке `requires` используются не только арифметические операции. это могут быть любые выражения: вызовы функций, конструкторы, преобразования типов, доступ к членам класса и т. д. локальные переменные внутри фигурных скобок определять нельзя. все переменные, которые нужны в выражениях, должны быть либо глобальными переменными, либо переменными из списка параметров. например, добавим параметр типа `int`:

```cpp


#include <iostream>

#include <string>

#include <vector>



template <typename T>

concept is_collection = requires (T collection, int n)

{

    collection[n];

};

 

int main()

{

    std::cout << std::boolalpha << is_collection<int> << std::endl;                 // false

    std::cout << std::boolalpha << is_collection<char[]> << std::endl;              // true

    std::cout << std::boolalpha << is_collection<std::string> << std::endl;         // truee

    std::cout << std::boolalpha << is_collection<std::vector<int>> << std::endl;    // true

}
```

здесь определён концепт `is_collection`. он проверяет, является ли тип `T` коллекцией, в которой можно обратиться к элементам по индексам.

выражение `requires` теперь принимает два параметра. второй параметр имеет тип `int`.

```cpp


requires (T collection, int n)

{

    collection[n];

};
```

здесь используется одно требование, `collection[n]`. тип `T` должен поддерживать обращение к элементам по целочисленному индексу.

тип `int` коллекцией не является, для этого типа возвращается `false`:

```cpp
is_collection<int>  // false
```

строки, массивы и векторы поддерживают обращение по индексу, для них возвращается `true`:

```cpp


is_collection<char[]>                     // true

is_collection<std::string>                // true

is_collection<std::vector<int>>     // true
```

применим выражение `requires` для создания концепта, ограничивающего шаблон:

```cpp


#include <iostream>

#include <string>

#include <concepts>



template <typename T>

concept sum_types = requires (T x) { x + x;} ;  // T должен поддерживать операцию +



template <sum_types T>

T sum(T a, T b){ return a + b;}



int main()

{

    std::cout << sum(10, 3) << std::endl;       // 13

    std::cout << sum(10.6, 3.2) << std::endl;   // 13.8

    std::cout << sum(std::string("Hello "), std::string("world")) << std::endl; // Hello world

}
```

ограничение

```cpp
requires (T x) { x + x;} ;
```

указывает, что `T` может представлять любой тип, который поддерживает операцию сложения. это могут быть и числа, и строки `std::string`.

выражение `requires` можно использовать и напрямую после оператора **requires**:

```cpp


template <typename T> requires requires (T x) { x + x; } 

T sum(T a, T b){ return a + b;}
```

первое слово `requires` представляет оператор, который устанавливает ограничение для шаблона. второе слово `requires` представляет выражение, которое определяет требования. именованный концепт при такой записи не нужен.

### составные требования

составное требование похоже на простое требование. дополнительно оно может запрещать выражению генерировать исключение и ограничивать тип, к которому выражение приводится. составное требование может принимать следующие формы:

```cpp


{ expr };           // expr - любое допустимое выражение

{ expr } noexcept; // expr валидно, если никогда не генерируется исключение

{ expr } -> ограничение_типа; // expr валидно, если тип удовлетворяет ограничению_типа

{ expr } noexcept -> type-constraint;
```

требование `{ expr } noexcept` выполняется, если все функции, которые вызываются в выражении `expr`, определены как **noexcept**, и само выражение не порождает исключение. в требовании `{ expr } -> ограничение_типа` после стрелки `->` должно идти ограничение типа. например:

```cpp


#include <iostream>

#include <concepts>



template <typename Pointer>

concept is_pointer = requires (Pointer ptr, int n)

{

    {ptr[n]};

    { ptr - n } -> std::same_as<Pointer>;

    { ptr + n } -> std::same_as<Pointer>; 

};



int main()

{

    std::cout << std::boolalpha << is_pointer<int> << std::endl;    // false

    std::cout << std::boolalpha << is_pointer<int[]> << std::endl;  // false

    std::cout << std::boolalpha << is_pointer<int*> << std::endl;    // true

    std::cout << std::boolalpha << is_pointer<char*> << std::endl;    // true

}
```

концепт `is_pointer` использует составное требование из трёх требований:

```cpp


requires (Pointer ptr, int n)

{

    {ptr[n]};

    { ptr - n } -> std::same_as<Pointer>;

    { ptr + n } -> std::same_as<Pointer>; 

};
```

требование `ptr[n]` проверяет, допустимо ли обращение к значениям операцией индексации. далее идёт ряд требований с ограничением типа:

```cpp
{ ptr - n } -> std::same_as<Pointer>;
```

для типа `Pointer` должна поддерживаться операция вычитания, причём вычитается целое число. результат этой операции должен представлять тот же тип `Pointer`. для установки ограничения типа применяется встроенный концепт **std::same_as** из заголовочного файла `<concepts>`. арифметика указателей устроена так: разность указателя и целого имеет тип указателя. разность двух указателей имеет целый тип и этому требованию уже не удовлетворяет.

концепту с подобными ограничениями соответствуют, например, указатели на значения любого типа:

```cpp


is_pointer<int*>  // true

is_pointer<char*> // true
```

составное требование для ограничения шаблона:

```cpp


#include <iostream>

#include <string>

#include <concepts>



template <typename T>

concept sum_types = requires (T x) { {x + x} -> std::convertible_to<T>; };



template <sum_types T>

T sum(T a, T b){ return a + b;}



int main()

{

    std::cout << sum(10, 3) << std::endl;       // 13

    std::cout << sum(10.6, 3.2) << std::endl;   // 13.8

    std::cout << sum(std::string("Hello "), std::string("world")) << std::endl; // Hello world

}
```

требование предписывает, что тип `T` должен поддерживать операцию сложения, а её результат должен представлять тип, который может быть преобразован в тип `T`, в том числе сам тип `T`. концепт `std::convertible_to` проверяет неявную преобразуемость результата.
