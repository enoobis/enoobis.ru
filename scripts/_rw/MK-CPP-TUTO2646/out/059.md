если класс сам не объявляет конструктор копирования, компилятор объявляет его неявно. этот специальный конструктор создаёт объект по другому объекту того же типа и почленно копирует подобъекты. для членов классового типа вызывается их конструктор копирования, поэтому `std::string` копирует собственный буфер. простейший пример:

```cpp


#include <iostream>

#include <string>



class Person 

{

private:

    std::string name;

    unsigned age;

public:

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        age = p_age;

    }

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

};

int main()

{

    Person tom{"Tom", 38};

    Person tomas{tom};    // создаем объект tomas на основе объекта tom

    tomas.print();    // Name: Tom   Age: 38

}
```

в этой строке:

```cpp
Person tomas{tom};
```

вызывается конструктор копирования. в тексте класса нет конструктора, который принимал бы другой `Person`: такое объявление добавляет компилятор. в результате `tomas` получает те же значения полей, что и `tom`.

неявное почленное копирование достаточно, пока семантика члена совпадает с копированием значения. если член является указателем, копируется адрес, и поля обоих объектов указывают на одну область памяти. изменение данных по этому адресу видно через оба объекта, а двойное освобождение при уничтожении становится ошибкой. тогда определяют собственный конструктор копирования и задают нужную семантику: глубокое копирование, запрет копирования или явное разделение владения.

### создание конструктора копирования

конструктор копирования принимает объект того же класса. параметр берут по ссылке. передача по значению потребовала бы копии, для копии снова вызвался бы конструктор копирования, и вызов зациклился бы. ссылку делают константной, в форме `const Person&`: источник не изменяется, а к параметру привязываются и константный объект, и временный. собственный конструктор копирования:

```cpp


#include <iostream>

#include <string>



class Person 

{

    std::string name;

    unsigned age;

public:

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        age = p_age;

    }

    Person(const Person &p)

    {

        name = p.name;

        age = p.age + 1;    // для примера

    }

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

};

int main()

{

    Person tom{"Tom", 38};

    Person tomas{tom};    // создаем объект tomas на основе объекта tom

    tomas.print();		// Name: Tom       Age: 39

}
```

конструктор принимает константную ссылку на `Person` и копирует поля источника в создаваемый объект. к `age` в примере прибавлена единица, чтобы копия отличалась от оригинала и было видно, что отработал именно этот конструктор. объявление собственного конструктора копирования подавляет неявный: дальше используется пользовательский.

### удаление конструктора копирования

конструктор копирования нужен не каждому типу. его удаляют спецификатором **delete**. удалённая функция остаётся объявленной, поэтому неявный конструктор копирования не генерируется, но любое её использование, включая копирующую инициализацию, делает программу некорректной. удаление только конструктора копирования оставляет оператор копирующего присваивания: он может быть объявлен неявно и по-прежнему копировать объект присваиванием. тип, который копировать нельзя, обычно удаляет и копирующее присваивание.

```cpp


#include <iostream>

#include <string>



class Person 

{

    std::string name;

    unsigned age;

public:

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        age = p_age;

    }

    Person(const Person &p) = delete;   // удаляем конструктор

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

};

int main()

{

    Person tom{"Tom", 38};

    //Person tomas{tom};    // конструктор копирования отсутствует

}
```
