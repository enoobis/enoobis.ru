### параметры компилятора gcc

по умолчанию при успешной компиляции предупреждения не печатаются. предупреждение при этом сообщает о возможном дефекте даже в программе, которая компилируется: трансляция доходит до конца, но диагностика указывает на подозрительное место. простейший пример состоит в том, что переменная определена и нигде не используется. сообщение компилятора позволяет заметить это сразу.

компиляция с предупреждениями включается флагом `-Wall`:

```bash
g++ -Wall source.cpp
```

имя флага историческое. `-Wall` включает большой, но не полный набор предупреждений. дополнительные группы задаются отдельными флагами, например `-Wextra`.

у языка есть несколько редакций стандарта, и каждая добавляет средства, которые программа может использовать. флаг **-std=** выбирает редакцию: к нему дописывается `c++11`, `c++14`, `c++17` или `c++20`. компиляция в режиме `c++17` записывается так:

```bash
g++ -std=c++17 source.cpp
```

выбор диалекта меняет множество допустимых конструкций и семантику части библиотеки. программа, корректная как c++20, может быть отвергнута в режиме c++11, если опирается на более поздние средства.

для стандарта `c++20` в лекции приведена команда:

```bash
g++ -std=c++20 source.c
```

чтобы потребовать соответствия выбранному стандарту, добавляется флаг `-pedantic`:

```bash
g++ -std=c++11 -Wall -pedantic app.cpp
g++ -std=c++14 -Wall -pedantic app.cpp
g++ -std=c++17 -Wall -pedantic app.cpp
g++ -std=c++20 -Wall -pedantic app.cpp
```

в этом режиме компилятор выдаёт предупреждения, если код нарушает ограничения стандарта или использует расширение, для которого стандарт требует диагностику. `-pedantic` не отключает расширения полностью, но делает отступление от iso видимым.

запустить программу сразу после компиляции можно такой командой:

```bash
g++ source.cpp & ./a.out
```

если параметр `-o` не задан, драйвер записывает результат в a.out, и вторая часть строки его запускает. в командной строке windows символ `&` разделяет последовательные команды. в оболочке bash тот же знак отправляет предшествующую команду в фон, а последовательный запуск с проверкой кода возврата записывается через `&&`.

в одну команду можно собрать и диалект, и предупреждения, и имя результата:

```bash
g++ -std=c++20 -Wall -pedantic app.cpp -o app & app
```

здесь `-std=c++20` выбирает диалект, `-Wall` и `-pedantic` включают диагностику, `-o app` задаёт имя исполняемого файла, а `& app` запускает его следом.

### параметры компилятора clang

основные параметры clang в ряде случаев совпадают с параметрами gcc: оба драйвера ориентируются на один и тот же интерфейс командной строки. компиляция clang под выбранный стандарт с предупреждениями выглядит так:

```bash
clang++ -std=c++20 -Wall -pedantic app.cpp -o app.exe & app.exe
```

смысл флагов тот же, что у g++. `-std=c++20` фиксирует диалект, `-Wall` и `-pedantic` включают предупреждения, `-o app.exe` задаёт имя результата для windows, `& app.exe` запускает собранный файл.
