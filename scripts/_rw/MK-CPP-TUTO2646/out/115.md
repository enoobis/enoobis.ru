параметр типа `std::string` принимает и объект `std::string`, и строковый литерал. литерал приводится к строке конструированием временного объекта.

```cpp

#include <iostream>
#include <string>
 
void print(const std::string&);
int main()
{
    std::string message{"hello"};
    print(message);         // можем передать std::string
    print("Hello Work");    // можем передать строковый литерал
}

void print(const std::string& text)
{
    std::cout << text << std::endl;
}
```

параметр объявлен как `const std::string&`. ссылка на уже существующий объект `std::string` обходится без копии его буфера, а `const` не дает изменить символы через параметр. литерал и символьный массив объектами `std::string` не являются. приведение строит временную строку, копирует в нее символы и для длинного текста выделяет динамический буфер. короткая строка может занять внутренний буфер объекта `std::string`, но копирование символов при этом остается. ссылка снимает копирование только у аргумента, который уже имеет тип `std::string`.

эту цену убирает `std::string_view`, объявленный в заголовке `<string_view>` с c++17. по чтению он близок к константному `std::string`. представление строится по объекту `std::string`, по строковому литералу и по символьному массиву одинаково: отдельный буфер под символы не выделяется, символы остаются в памяти источника. внутри представления хранятся указатель на первый символ и длина. копирование `std::string_view` копирует эти два поля и выполняется за постоянное время, поэтому параметр такого типа естественно передавать по значению. когда функции достаточно чтения на время вызова, тип параметра `std::string_view` предпочтительнее `const std::string&`.

время жизни источника представление не продлевает. оно действительно, пока последовательность символов жива и буфер, на который указывает `data()`, не переразмещен. у строкового литерала статическая продолжительность хранения, поэтому представление на него остается корректным все время работы программы. представление на локальный `std::string` годно, пока жив этот объект и операции над ним не переразместили буфер. сохранить `std::string_view` дольше источника нельзя.

символы через `std::string_view` доступны только для чтения: тип элемента есть `const char`. исходная формулировка лекции фиксирует то же ограничение. константность символов задана типом `std::string_view` и от квалификатора `const` у параметра не зависит. квалификатор `const` фиксирует сам объект представления: его указатель и длину. без этого квалификатора функции вроде `remove_prefix` сдвигают окно просмотра и по-прежнему не пишут в исходные символы.

та же функция печати на `std::string_view`:

```cpp

#include <iostream>
#include <string>
#include <string_view>
 
void print(std::string_view);
int main()
{
    std::string message{"hello"};
    print(message);         // можем передать std::string
    print("Hello Work");    // можем передать строковый литерал
}

void print(std::string_view text)
{
    std::cout << text << std::endl;
}
```

вызов с `message` строит представление на буфер объекта `std::string`. вызов с литералом строит представление прямо на массив литерала. временный `std::string` для этого аргумента не создается.

большинство операций чтения у `std::string_view` совпадает с `std::string`. ниже та же программа подсчета слов, что и в предыдущей лекции. текст приходит как `std::string_view`, а элементы вектора тоже являются представлениями.

```cpp

#include <iostream>
#include <vector>
#include <string>
#include <string_view>
 
std::vector<std::string_view> get_words(std::string_view);

int main()
{
    std::string text = " An apple a day keeps the doctor away."; // Исходный текст

    std::vector<std::string_view> words = get_words(text);

    // выводим количество слов
    std::cout << "\nText contains " << words.size() << " words:" << std::endl;
    // выводим все слова на консоль
    for (const auto& word : words)
    {
        std::cout << word << std::endl;
    }
}

std::vector<std::string_view> get_words(std::string_view text)
{
    const std::string_view separators{ " ,;:.\"!?'*\n" };
    std::vector<std::string_view> words; // вектор для хранения слов
    size_t start { text.find_first_not_of(separators) }; // начальный индекс первого слова
    while (start != std::string_view::npos) // проходим, пока в строке не окажется других символов, кроме separators
    {
        size_t end = text.find_first_of(separators, start + 1); // находим, где кончается слово
        if (end == std::string_view::npos) // если НЕ найден ни один из символов-разделителей
            end = text.length();        // устанавливаем переменную end на конец текста
        words.push_back(text.substr(start, end - start)); // добавляем в вектор слово
        start = text.find_first_not_of(separators, end + 1); // находим начальный индекс следующего слова и переустанавливаем start
    }
    return words;
}
```

разбор повторяет предыдущий алгоритм. `find_first_not_of`, `find_first_of` и `length` возвращают те же позиции и ту же длину, что одноименные члены `std::string`. признак неудачного поиска есть `std::string_view::npos`. `substr` у представления возвращает новый `std::string_view` на тот же буфер. владеющей строки этот вызов не создает, поэтому помещение слова в вектор не копирует его символы. вектор владеет только объектами представления. возвращенный вектор осмыслен, пока жив буфер аргумента. в `main` объект `text` объявлен раньше вызова и живет дольше печати слов, так что все представления внутри `words` на время вывода указывают в действительную память. параметр `get_words` принят по значению, но копируются указатель и длина. сама копия представления данные не держит. если передать в `get_words` временный `std::string`, временный объект будет уничтожен в конце полного выражения вызова, а возвращенные представления останутся висячими.

для юникода и прочих наборов кодовых единиц стандарт задает соседние типы: `std::wstring_view`, `std::u16string_view` и `std::u32string_view` с c++17, `std::u8string_view` с c++20. каждый из них есть псевдоним `std::basic_string_view` для `wchar_t`, `char16_t`, `char32_t` или `char8_t`. работа с ними устроена так же, как с `std::string_view`.
