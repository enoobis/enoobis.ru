конструктор перемещения и оператор присваивания с перемещением имеет смысл объявлять со спецификацией **noexcept**, если они не генерируют исключений. ниже видно, зачем это нужно контейнеру.

`std::vector` является динамическим массивом и для добавления элемента определяет `push_back` в двух версиях.

```cpp


void push_back(const Message &_Val)

void push_back(Message &&_Val)
```

при передаче rvalue выбирается вторая версия. она сохраняет элемент внутри вектора конструктором перемещения. картина меняется, когда в вектор добавляют несколько объектов и буфер приходится расширять.

```cpp


#include <iostream>

#include <vector>

 

// класс сообщения

class Message

{

public:

    // обычный конструктор

    Message(const char* data, unsigned count)

    {

        size = count;

        text = new char[size];  // выделяем память

        for(unsigned i{}; i < size; i++)    // копируем данные

        {

            text[i] = data[i];

        }



        id = ++counter;

        std::cout << "Create Message " << id << std::endl;

    }

    // конструктор копирования

    Message(const Message& copy) : Message{copy.getText(), copy.size }  // обращаемся к стандартному конструктору

    {

        std::cout << "Copy  Message " << copy.id << " to " << id << std::endl;

    }

    Message(Message&& moved)

    {

        id = ++counter;

        std::cout << "Create Message " << id << std::endl;



        text = moved.text;  // перемещаем текст сообщения

        size = moved.size;  // копируем размер сообщения

        moved.text = nullptr;

        std::cout << "Move Message " << moved.id << " to " << id << std::endl;

    }

    // деструктор

    ~Message()

    { 

        std::cout << "Delete Message "  << id << std::endl;

        delete[] text;  // освобождаем память

    }

    char* getText() const { return text; }

    unsigned getSize() const { return size; }

    unsigned getId() const {return id;}

private:

    char* text{};  // текст сообщения

    unsigned size{};    // размер сообщения

    unsigned id{};  // номер сообщения

    static inline unsigned counter{};   // статический счетчик для генерации номера объекта

};



int main()

{

    std::vector<Message> messages{};

    messages.push_back(Message{"Hello world", 12});

    messages.push_back(Message{"Bye world", 10});

}
```

класс `Message` снова изображает сообщение. текст лежит в динамической памяти и доступен через указатель `text`. для наглядности взяты обычные указатели, а не умные: каждый вызов конструктора и деструктора виден в выводе. статическая переменная `counter` увеличивается с каждым новым объектом, текущее значение попадает в поле `id`, номер сообщения.

```cpp


char* text{};  // текст сообщения

unsigned size{};    // размер сообщения

unsigned id{};  // номер сообщения

static inline unsigned counter{};   // статический счетчик для генерации номера объекта
```

конструктор выделяет динамическую память под символы, записывает размер и номер. деструктор память освобождает. копирование обеспечивает конструктор копирования: он делегирует обычному конструктору и тем самым получает собственный буфер.

в том же классе определён конструктор перемещения.

```cpp


Message(Message&& moved)

{

    id = ++counter;

    std::cout << "Create Message " << id << std::endl;



    text = moved.text;  // перемещаем текст сообщения

    size = moved.size;  // копируем размер сообщения

    moved.text = nullptr;

    std::cout << "Move Message " << moved.id << " to " << id << std::endl;

}
```

обычный конструктор, в отличие от конструктора копирования, здесь не вызывается: память заново не выделяется. в поле `text` записывается адрес блока из объекта `moved` (`text = moved.text`). затем указателю источника присваивается `nullptr`, чтобы деструктор `moved` этот блок не освободил.

в `main` в вектор добавляются **два** объекта `Message`, оба являются rvalue.

```cpp


std::vector<Message> messages{};

messages.push_back(Message{"Hello world", 12});

messages.push_back(Message{"Bye world", 10});
```

консольный вывод:

```bash


Create Message 1

Create Message 2

Move Message 1 to 2

Delete Message 1

Create Message 3

Create Message 4

Move Message 3 to 4

Create Message 5

Copy  Message 2 to 5

Delete Message 2

Delete Message 3

Delete Message 5

Delete Message 4
```

в вектор попадают два объекта `Message`, а конструкторы создают пять. разбор по этапам. сначала добавляется один объект.

```cpp
messages.push_back(Message{"Hello world", 12});
```

создаётся один объект `Message` как rvalue. конструктор перемещения переносит его данные в объект, который хранится внутри вектора. временный объект затем уничтожается.

```bash


Create Message 1

Create Message 2

Move Message 1 to 2

Delete Message 1
```

вектор является динамическим массивом: элементы лежат в одном непрерывном буфере, а вместимость этого буфера конечна. когда места для нового элемента нет, реализация выделяет новый участок, способный вместить уже лежащие элементы и добавляемый, переносит старые элементы в новый участок и освобождает прежний. при выполнении строки

```cpp


messages.push_back(Message{"Bye world", 10});
```

выделяется память уже под два объекта `Message`. снова создаётся rvalue, его данные перемещаются в элемент вектора. одновременно первый добавленный объект копируется из старого буфера в новый, и для этого копирования вызывается конструктор копирования. это видно по выводу.

```bash


Create Message 3

Create Message 4

Move Message 3 to 4

Create Message 5

Copy  Message 2 to 5

Delete Message 2

Delete Message 3
```

конструктор копирования выбирается потому, что у вектора нет гарантии, что конструктор перемещения не бросит исключение. при расширении буфера контейнер держит строгую гарантию безопасности исключений: если перенос элементов сорвётся, исходный вектор должен остаться прежним. копирование это обеспечивает, старый буфер цел, пока новый не готов. перемещение портит источник сразу, и откатить частично перемещённый буфер уже нельзя. поэтому реализация вызывает что-то вроде `std::move_if_noexcept`: если конструктор перемещения объявлен как `noexcept`, элемент перемещается, иначе копируется.

в данном конструкторе перемещения исключений нет. присваивание указателей и запись целого числа исключений не генерируют. конструктор можно пометить **noexcept**.

```cpp


Message(Message&& moved) noexcept

{

    id = ++counter;

    std::cout << "Create Message " << id << std::endl;



    text = moved.text;  // перемещаем текст сообщения

    size = moved.size;  // копируем размер сообщения

    moved.text = nullptr;	// обнуляем указатель перемещенного объекта

    std::cout << "Move Message " << moved.id << " to " << id << std::endl;

}
```

после перекомпиляции и запуска вместо конструктора копирования при переносе старого элемента применяется конструктор перемещения.

```bash


Create Message 1

Create Message 2

Move Message 1 to 2

Delete Message 1

Create Message 3

Create Message 4

Move Message 3 to 4

Create Message 5

Move Message 2 to 5

Delete Message 2

Delete Message 3

Delete Message 5

Delete Message 4
```

тот же критерий используют не только `std::vector`, но и другие контейнеры и алгоритмы, которым нужна строгая гарантия при переносе элементов. конструктор перемещения и оператор присваивания с перемещением, которые не бросают исключений, поэтому объявляют со спецификацией **noexcept**. неявные версии этих функций и так получают `noexcept`, если перемещение всех полей само является `noexcept`. написанная вручную версия без спецификации считается потенциально бросающей, даже если в теле исключений нет.
