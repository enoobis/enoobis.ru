**smart pointers**, интеллектуальные указатели, суть объекты, которые ведут себя как обычные указатели. они хранят адрес, как правило адрес динамической памяти, и через этот адрес к объекту обращаются. отличие от обычного указателя в том, что память не освобождают вручную операторами `delete` и `delete[]`. память, которой владеет интеллектуальный указатель, освобождается сама, когда указатель уничтожается или отпускает объект. тем самым закрываются утечка, рассогласование `new` и `delete` и висячий указатель после уничтожения владельца. управление памятью становится короче и строже по инварианту владения. типы интеллектуальных указателей объявлены в заголовочном файле `<memory>` стандартной библиотеки c++ (в исходном конспекте он назван модулем `memory`) и лежат в пространстве имён `std`.

`unique_ptr<T>` есть указатель на тип `T` с единоличным владением: один и тот же адрес в каждый момент принадлежит только одному объекту `unique_ptr`. двух объектов `unique_ptr`, одновременно владеющих одним адресом, модель типа не предусматривает. копирование такого указателя не компилируется: копирующий конструктор и копирующее присваивание удалены. если записать второй `unique_ptr` как копию первого, перевод единицы трансляции останавливается. конструктор от сырого указателя при этом остаётся. передать ему адрес, которым уже владеет другой `unique_ptr`, система типов не отвергает, и оба владельца вызовут `delete` по одному адресу. корректная передача владения записывается перемещением: исходный указатель после перемещения становится пустым, а адрес остаётся только у одного объекта.

когда `unique_ptr` уничтожается, уничтожается и объект, которым он владеет. деструктор вызывает `delete` или, для специализации на массив, `delete[]`. тип применяют там, где на объект не должно быть других владельцев и где удаление обязано совпасть с концом жизни указателя. это частный случай raii: ресурс захватывается в конструкторе и отпускается в деструкторе, в том числе при выходе по исключению.

по умолчанию `unique_ptr` инициализируется значением `nullptr`:

```cpp


std::unique_ptr<int> ptr;	// ptr = nullptr

// аналогично

std::unique_ptr<int> ptr{};

std::unique_ptr<int> ptr{nullptr};
```

чтобы выделить память и создать в ней объект, вызывают `std::make_unique`. аргумент задаёт значение, которым объект инициализируется:

```cpp
std::unique_ptr<int> ptr { std::make_unique<int>(125) };
```

здесь в динамической памяти размещается число 125, и `ptr` владеет этой памятью. `make_unique` появился в c++14. он выделяет память и конструирует объект одной операцией, так что указатель сразу владеет результатом. до c++14 ту же конструкцию записывали через `new`:

```cpp
std::unique_ptr<int> ptr { new int(125) };
```

форма с `new` передаёт в `unique_ptr` уже полученный сырой адрес. если этот адрес нужно передать дальше вместе с другим выражением, которое тоже может бросить исключение, между `new` и захватом указателя возможна утечка. `make_unique` этот промежуток убирает.

сырой указатель из `std::unique_ptr` даёт функция `get()`:

```cpp


std::unique_ptr<int> ptr { std::make_unique<int>(125) };

int* pointer = ptr.get();
```

`get()` не забирает владение. возвращённый `int*` нельзя передавать в `delete` и нельзя отдавать другому `unique_ptr`. пока `ptr` жив, адрес действителен. после `reset` или уничтожения `ptr` этот сырой указатель становится висячим.

после создания интеллектуального указателя значение читают и меняют так же, как через обычный указатель. разыменование определено, если указатель не пуст:

```cpp


#include <iostream>

#include <memory>



int main()

{

    // указатель ptr указывает на объект 125

    std::unique_ptr<int> ptr { std::make_unique<int>(125) };

    std::cout << "Address: " << ptr.get() << std::endl;   // получим адрес объекта

    std::cout << "Initial value: " << *ptr << std::endl;     // получим значение объекта



    // изменяем значение

    *ptr = 254;

    std::cout << "New value: " << *ptr << std::endl;     // получим значение объекта

}
```

консольный вывод:

```bash


Address: 0x2775dfa8030

Initial value: 125

New value: 254
```

адрес в выводе зависит от выделения и от запуска к запуску меняется. существенны само значение 125 и запись 254 поверх него.

начиная со стандарта c++20 адрес из `unique_ptr` печатают прямо, без `get`:

```cpp
std::cout << "Address: " << ptr << std::endl;   // получим адрес объекта
```

для этого в c++20 добавлен оператор `<<`, который выводит результат `get()`. неявного преобразования `unique_ptr` в сырой указатель нет: там, где параметр имеет тип `int*`, по-прежнему нужен `get()`.

`unique_ptr` работает и с массивами. указатель на массив:

```cpp


unsigned n{5};   // размер массива

auto pnumbers { std::make_unique<int[]>(n) };    // массив из n элементов, равных 0
```

`pnumbers` указывает на массив из 5 элементов. специализация `unique_ptr<int[]>` при уничтожении вызывает `delete[]`. элементы уже инициализированы значением по умолчанию. для встроенных типов это 0. `std::make_unique<int[]>(n)` выполняет инициализацию значением каждого элемента.

к элементу обращаются квадратными скобками. оператор `[]` есть у массива-специализации и отсутствует у `unique_ptr` на одиночный объект:

```cpp


#include <iostream>

#include <memory>



int main()

{

    unsigned n{5};   // размер массива

    auto pnumbers { std::make_unique<int[]>(n) };    // массив {0, 0, 0, 0, 0}



    std::cout << "pnumbers[1] initial value: " << pnumbers[1] << std::endl; // pnumbers[1] initial value: 0

    pnumbers[1] = 121;  // изменяем значение

    std::cout << "pnumbers[1] new value: " << pnumbers[1] << std::endl;     // pnumbers[1] new value: 121

}
```

массив обходят циклом:

```cpp


#include <iostream>

#include <memory>



int main()

{

    unsigned n{5};   // размер массива

    auto pnumbers { std::make_unique<int[]>(n) };    // массив из n элементов



    // изменим и выведем все элементы на консоль

    for (unsigned i {}; i < n; i++)

    {

        pnumbers[i] = i+1;

        std::cout << "pnumbers[" << i <<"] = " << pnumbers[i] << std::endl;

    }

}
```

консольный вывод:

```bash


pnumbers[0] = 1

pnumbers[1] = 2

pnumbers[2] = 3

pnumbers[3] = 4

pnumbers[4] = 5
```

если память нужно отпустить раньше уничтожения указателя, вызывают `reset()`:

```cpp


#include <iostream>

#include <memory>



int main()

{

    auto ptr { std::make_unique<int>(123) };



    // освобождаем память и удаляем объект 123

    ptr.reset();

    if(!ptr)   // если ptr

    {

        std::cout << "Memory is free" << std::endl;

    }

    else    

    {

        std::cout << *ptr << std::endl;

    }

}
```

после `reset()` без аргумента указатель получает значение `nullptr`, а прежний объект удалён. условие `if (!ptr)` истинно для пустого указателя: у `unique_ptr` есть преобразование в `bool`, истинное при ненулевом адресе. комментарий в примере стоит у отрицания, то есть ветвь `Memory is free` выполняется именно когда владения уже нет.

в `reset()` можно передать новый объект. для него указатель станет владельцем, а прежний объект будет удалён до захвата нового:

```cpp


#include <iostream>

#include <memory>



int main()

{

    auto ptr { std::make_unique<int>(123) };



    std::cout << "Old address: " << ptr.get() << std::endl;

    std::cout << "Old value: " << *ptr << std::endl;

    // освобождаем память и удаляем массив

    ptr.reset(new int{254});

    

    std::cout << "New address: " << ptr.get() << std::endl;

    std::cout << "New value: " << *ptr << std::endl;

}
```

после `reset()` прежняя память освобождена, выделен новый участок для числа 254. меняются и адрес, и значение. комментарий в тексте программы говорит про массив, но выражение `new int{254}` создаёт один `int`. консольный вывод:

```bash


Old address: 0x2b13dd73270

Old value: 123

New address: 0x2b13dd68010

New value: 254
```
