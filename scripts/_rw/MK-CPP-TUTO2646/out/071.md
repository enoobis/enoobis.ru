при вызове функции программа должна определять, с какой именно реализацией функции соотносить этот вызов, то есть связать вызов функции с самой функцией. в c++ есть два типа связывания: статическое и динамическое.

когда вызовы функций фиксируются до выполнения программы на этапе компиляции, это называется статическим связыванием (static binding), либо ранним связыванием (early binding). при этом вызов функции через указатель определяется статическим типом указателя. динамический тип адресуемого объекта на выбор реализации не влияет. например:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name}

    { }

    void print() const

    {

        std::cout << "Name: " << name << std::endl;

    }

private:

    std::string name;       //  имя

};

class Employee: public Person

{

public:

    Employee(std::string name, std::string company): Person{name}, company{company}

    { }

    void print() const

    {

        Person::print();

        std::cout << "Works in " << company << std::endl;

    }

private:

    std::string company;    // компания

};

 

int main()

{

    Person tom {"Tom"};

    Person* person {&tom};

    person->print();     // Name: Tom



    Employee bob {"Bob", "Microsoft"};

    person = &bob;

    person->print();    // Name: Bob

}
```

класс `Employee` наследуется от класса `Person`, и оба этих класса определяют функцию `print()`, которая выводит данные об объекте. в функции `main` создаются два объекта, их адреса поочерёдно присваиваются указателю на тип `Person`, и через этот указатель вызывается функция `print`. даже если этому указателю присваивается адрес объекта `Employee`, вызывается реализация функции из класса `Person`:

```cpp


Employee bob {"Bob", "Microsoft"};

person = &bob;

person->print();    // Name: Bob
```

выбор реализации функции определяется типом указателя. статический тип выражения `person` есть `Person*`, поиск имени `print` выполняется в `Person`, а в этом объявлении функция не виртуальная, поэтому адрес объекта `Employee` на выбор не влияет. функция `print` в `Employee` скрывает одноимённую функцию базы. консольный вывод программы:

```bash


Name: Tom

Name: Bob
```

### динамическое связывание и виртуальные функции

другой тип связывания представляет динамическое связывание (dynamic binding), его также называют поздним связыванием (late binding). оно позволяет на этапе выполнения решить, функцию какого типа вызвать. для этого в языке c++ применяют виртуальные функции. для определения виртуальной функции в базовом классе она объявляется с ключевым словом `virtual`. спецификатор `virtual` ставится на объявление функции-члена внутри определения класса. тело может находиться и вне класса. функция, не являющаяся членом класса, виртуальной быть не может: у неё нет объекта и динамического типа. производный класс может переопределить поведение виртуальной функции.

функция `print` в базовом классе `Person` делается виртуальной:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name}

    { }

    virtual void print() const  // виртуальная функция

    {

        std::cout << "Name: " << name << std::endl;

    }

private:

    std::string name;

};

class Employee: public Person

{

public:

    Employee(std::string name, std::string company): Person{name}, company{company}

    { }

    void print() const

    {

        Person::print();

        std::cout << "Works in " << company << std::endl;

    }

private:

    std::string company;

};

 

int main()

{

    Person tom {"Tom"};

    Person* person {&tom};

    person->print();     // Name: Tom

    Employee bob {"Bob", "Microsoft"};

    person = &bob;

    person->print();    // Name: Bob

                            // Works in Microsoft

}
```

базовый класс `Person` определяет виртуальную функцию `print`, а производный класс `Employee` переопределяет её. в первом примере, где функция `print` не была виртуальной, класс `Employee` эту функцию скрывал. теперь при вызове функции `print` для объекта `Employee` через указатель `Person*` вызывается реализация функции именно класса `Employee`. консольный вывод другой:

```bash


Name: Tom

Name: Bob

Works in Microsoft
```

в этом состоит отличие переопределения виртуальных функций от скрытия. при скрытии выбор функции завершается при компиляции по статическому типу выражения. при переопределении вызов через указатель или ссылку использует динамический тип объекта.

класс, который определяет или наследует виртуальную функцию, называется полиморфным (polymorphic class). `Person` и `Employee` являются полиморфными классами.

вызов виртуальной функции через объект, у которого статический тип совпадает с типом самого объекта, разрешается статически: динамический тип такого выражения известен при компиляции.

```cpp


Employee bob {"Bob", "Microsoft"};

Person p = bob;

p.print();  // Name: Bob - статическое связывание
```

во фрагменте `Person p = bob` объект копируется, и часть `Employee` отсекается (object slicing). переменная `p` хранит только подобъект `Person`, поэтому вызывается `Person::print`.

динамическое связывание возможно только через указатель или ссылку. только в этих случаях статический тип выражения может расходиться с динамическим типом объекта.

```cpp


Employee bob {"Bob", "Microsoft"};

Person &p {bob};    // присвоение ссылке

p.print();  // динамическое связывание



Person *ptr {&bob};    // присвоение адреса указателю

ptr->print();  // динамическое связывание
```

при определении виртуальных функций есть ряд ограничений. чтобы функция попадала под динамическое связывание, в производном классе она должна иметь тот же самый набор параметров и возвращаемый тип, что и в базовом классе. если в базовом классе виртуальная функция определена как константная, в производном классе она тоже должна быть константной. если функция имеет другой набор параметров или не совпадает по константности, объявление скрывает функцию базового класса. к такому объявлению применяется статическое связывание. по возвращаемому типу есть исключение: ковариантные типы. переопределение может возвращать указатель или ссылку на производный класс там, где база возвращает указатель или ссылку на базовый. набор параметров и константность при этом совпадают.

статические функции не могут быть виртуальными. у статической функции нет параметра `this` и нет динамического типа объекта.

### ключевое слово override

чтобы явным образом пометить переопределение функции, в производном классе после списка параметров указывается слово `override`. спецификатор заставляет компилятор проверить, что объявление переопределяет виртуальную функцию базы:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name}

    { }

    virtual void print() const  // виртуальная функция

    {

        std::cout << "Name: " << name << std::endl;

    }

private:

    std::string name;

};

class Employee: public Person

{

public:

    Employee(std::string name, std::string company): Person{name}, company{company}

    { }

    void print() const override // явным образом указываем, что функция переопределена

    {

        Person::print();

        std::cout << "Works in " << company << std::endl;

    }

private:

    std::string company;

};

 

int main()

{

    Person tom {"Tom"};

    Person* person {&tom};

    person->print();     // Name: Tom

    Employee bob {"Bob", "Microsoft"};

    person = &bob;

    person->print();     // Name: Bob

                        // Works in Microsoft

}
```

выражение

```cpp
void print() const override
```

указывает, что функция `print` явным образом переопределяется. в предыдущем примере `override` для виртуальной функции не указывался, но переопределение всё равно работало. `override` явным образом указывает компилятору, что это переопределяемая функция. если она не соответствует виртуальной функции базового класса по списку параметров, возвращаемому типу, константности, или в базовом классе вообще нет функции с таким именем, компилятор при компиляции генерирует ошибку. по ошибке видно, что с переопределённой функцией что-то не так. если `override` не указать, компилятор считает, что речь идёт о скрытии функции, и ошибку не генерирует, компиляция проходит успешно. поэтому при переопределении виртуальной функции в производном классе лучше указывать слово `override`.

виртуальную функцию можно переопределить по всей иерархии наследования, в том числе не в прямых производных классах. промежуточный класс может не давать собственного переопределения, и тогда дальнейший наследник по-прежнему подменяет реализацию базового класса.

### принцип выполнения виртуальных функций

виртуальные функции имеют свою цену: объекты классов с виртуальными функциями требуют немного больше памяти и немного больше времени для выполнения. стандарт задаёт семантику виртуального вызова и не предписывает способ реализации. при создании объекта полиморфного класса, который имеет виртуальные функции, в обычной реализации в объекте создаётся специальный указатель. этот указатель используется для вызова любой виртуальной функции в объекте. специальный указатель указывает на таблицу указателей функций, которая создаётся для класса. эта таблица, называемая виртуальной таблицей или vtable, содержит по одной записи для каждой виртуальной функции в классе. в типичной реализации такой указатель, vptr, один на объект. при множественном наследовании их может быть несколько, по числу полиморфных подобъектов.

когда функция вызывается через указатель на объект базового класса, происходит следующая последовательность событий:

- указатель на vtable в объекте используется для поиска адреса vtable для класса.

- затем в таблице идёт поиск указателя на вызываемую виртуальную функцию.

- через найденный указатель функции в vtable вызывается сама функция. в итоге вызов виртуальной функции происходит немного медленнее, чем прямой вызов невиртуальной функции, поэтому каждое объявление и вызов виртуальной функции несёт некоторые накладные расходы.

### запрет переопределения

с помощью спецификатора `final` запрещается определение в производных классах функций, которые имеют то же самое имя, возвращаемый тип и список параметров, что и виртуальная функция в базовом классе. например:

```cpp


class Person

{

public:

	virtual void print() const final

	{

		

	}

};

class Employee : public Person

{

public:

	void print() const override		// Ошибка!!!

	{

		

	}

};
```

также можно переопределить функцию базового класса, но запретить её переопределение в дальнейших производных классах:

```cpp


class Person

{

public:

	virtual void print() const // переопределение разрешено

	{

		

	}

};

class Employee : public Person

{

public:

	void print() const override final	// в классах, производных от Employee переопределение запрещено

	{

		

	}

};
```

`final` проверяется при компиляции. попытка переопределить такую функцию ниже по иерархии становится ошибкой. на уже разрешённые вызовы спецификатор не влияет: до класса, где функция помечена `final`, динамическое связывание сохраняется.
