для программы на c++ нужны как минимум две вещи: текстовый редактор, в котором набирается код, и компилятор, который превращает этот текст в приложение. компиляцию при этом запускают из консоли или терминала: компилятору передают файлы единиц трансляции и ключи, на выходе получают объектные файлы, а компоновщик собирает из них исполняемый модуль. ту же цепочку замыкает на себе среда разработки, ide. в ней есть текстовый редактор и компилятор, сборка и запуск выполняются одной командой, и рядом лежат вспомогательные средства: навигация по символам, отладчик, окно свойств проекта.

для программирования под windows наиболее распространённая среда для c++ это visual studio. её берут со страницы [https://visualstudio.microsoft.com/ru/vs/community/](https://visualstudio.microsoft.com/ru/vs/community/).

после загрузки и запуска установщика visual studio в нём отмечают пункт `Разработка классических приложений на C++`. эта нагрузка ставит компилятор msvc, заголовки и библиотеки для классических приложений windows, без неё шаблон консольной программы на c++ собрать нечем:

![установка с++ в visual studio](/uploads/course-lectures/81fb16f69e9709b740b8d065617672fcc34264a5.png)

когда отмечены все нужные пункты, установку запускают кнопкой ок. после установки создают первый проект. visual studio открывают и на стартовом экране среди шаблонов для языка c++ выбирают тип `Console App`, шаблон консольного приложения:

![первый проект на c++ в visual studio](/uploads/course-lectures/d64add5f91c2ce18339d5af363bfe1228f1eca0b.png)

на следующем экране в поле имени проекта задают имя `HelloApp`. там же можно указать расположение проекта на диске. создание запускают кнопкой `Create`:

![создание проекта консольного приложения на c++ в visual studio](/uploads/course-lectures/53f959b48410a748b2dcbb7cfe66d63426b8696a.png)

visual studio создаёт типовой проект консольного приложения на c++:

![первый проект консольного приложения на c++ в visual studio](/uploads/course-lectures/696236a97ee80645e8539100270cda6dfff0a727.png)

справа окно `Solution Explorer` показывает структуру. в этом окне находится решение. в примере оно называется `HelloApp`. решение может содержать несколько проектов, у каждого свой набор файлов и свои свойства сборки. по умолчанию проект один, и имя у него то же, `HelloApp`. в проекте есть ряд узлов:

- `External Dependencies`: файлы, которые используются файлами исходного кода, но в состав проекта не входят
- `Header Files`: узел для заголовочных файлов с расширением `.h`
- `Resource Files`: узел для файлов ресурсов, например изображений
- `Source Files`: узел для файлов с исходным кодом

по умолчанию каталог `Source Files` содержит один файл исходного кода, `HelloApp.cpp`. имя складывается из названия проекта и расширения `.cpp`. у исходных файлов на c++ расширение обычно `.cpp`.

`HelloApp.cpp` содержит код на c++, и этот код открыт слева в текстовом редакторе visual studio. по умолчанию в `HelloApp.cpp` такой текст:

```cpp
#include <iostream>        			// подключение модуля iostream

int main()									// определяем функцию main
{											// начало функции
	std::cout << "Hello World!\n";	// выводим строку на консоль
}
```

это тот же код, который разбирался в начальных темах: подключается заголовок потока ввода-вывода, определяется функция `main` как точка входа, и в стандартный поток вывода отправляется строка.

программу запускают сочетанием `Ctrl+F5` или пунктом меню `Debug -> Start Without Debugging`. этот пункт стартует процесс без подключения отладчика: останова на точках останова не будет, программа просто выполняется:

![запуск программы на c++ в visual studio](/uploads/course-lectures/b1750f49e5f4c852637a379c95a8f5f079db8718.png)

visual studio передаёт исходный код компилятору. компилятор строит объектный файл единицы трансляции, компоновщик собирает из него исполняемый файл exe, и этот файл запускается. на открывшейся консоли видно сообщение программы:

![первое приложение на языке программирования c++](/uploads/course-lectures/90823921ba0d7f8bdae8fab5a3297e38de4434eb.png)

после сборки на диске, в папке решения, в каталоге `\x64\Debug` лежит скомпилированный exe. его можно запускать отдельно от visual studio. каталог соответствует платформе `x64` и конфигурации debug: у конфигураций debug и release выходные каталоги различаются, в каталоге debug рядом с exe лежат сведения для отладчика:

![компиляция кода на языке программирования c++](/uploads/course-lectures/c49db25cee11db642cf706ef53bb6116ecdc26dc.png)

файл `HelloApp.exe` и есть собранный исполняемый файл. в той же папке среда автоматически создаёт вспомогательный файл `HelloApp.pdb`. в нём отладочная информация: соответствие адресов инструкций исходным строкам и именам, по которому отладчик показывает точку останова в тексте программы.

### настройка проекта

у языка c++ несколько стандартов, и каждый следующий добавляет свои возможности. visual studio позволяет указать стандарт, по которому компилируется приложение. для этого открывают свойства проекта:

![установка стандарта языка программирования c++ в среде visual studio](/uploads/course-lectures/91aca6cb7003e5841f0800231fe5b2d7d29b61c6.png)

в окне свойств переходят к пункту `Configuration Properties` -> `C/C++` -> `Language`. на этой странице опция `C++ Language Standard` задаёт стандарт языка, который должна использовать сборка. опция записывается в выбранную конфигурацию и платформу, поэтому у debug и release набор свойств может различаться, и компилятор получает соответствующий ключ стандарта:

![настройка стандарта языка программирования c++ в среде visual studio](/uploads/course-lectures/436227f57a9b111163dc0b65671c6b0a4837a93b.png)
