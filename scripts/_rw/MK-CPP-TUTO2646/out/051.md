в c++ объекты различаются временем хранения, и от него зависит, кто выделяет память и когда она освобождается. глобальные объекты создаются при запуске программы и освобождаются при её завершении. локальные автоматические объекты создаются при входе в блок и уничтожаются, когда выполнение блока заканчивается. локальные статические объекты создаются перед первым прохождением их определения и освобождаются при завершении программы. стандарт отдельно задаёт ещё потоковое время хранения (`thread_local`). ниже речь о трёх категориях, от которых зависит размещение объекта.

глобальные объекты и локальные статические объекты попадают в статическую память. локальные автоматические объекты размещаются в стеке. объекты статической памяти и стека создаёт и уничтожает реализация по правилам языка, без явного запроса из текста программы. статическая память живёт до завершения программы. объект в стеке существует, пока выполняется блок, в котором он определён. когда блок завершается, память стека, отведённая его переменным, освобождается, а для объектов классового типа к этому моменту уже отработали деструкторы. память стека имеет ограниченный фиксированный размер, который задаётся при создании потока. большой автоматический массив или глубокая рекурсия этот предел исчерпывают.

помимо этих категорий создают **динамические объекты**. время их жизни не привязано к блоку, в котором стоял запрос на создание. динамический объект существует, пока его явно не удалят. такие объекты размещаются в **динамической памяти** (free store). стандарт называет free store память, которой управляют `new` и `delete`. это область, не занятая кодом операционной системы и другими загруженными программами в той мере, в какой её выделяет аллокатор. функции `malloc` и `free` из c относятся к другому механизму. реализации часто берут оба пула из одной кучи операционной системы, но смешивать `new` с `free` и `malloc` с `delete` нельзя: формы выделения и освобождения должны совпадать.

у динамических объектов два практических следствия. память выделяется в том объёме, который нужен объекту, и после использования её возвращают, а не держат до выхода из блока. доступный объём заметно больше стека: предел задаёт адресное пространство и политика ос, а не фиксированный кадр стека. плата за это явная: каждый успешный `new` должен быть согласован с `delete`, иначе память остаётся занятой до конца процесса.

динамическими объектами управляют операторы `new` и `delete`.

оператор `new` выделяет место в динамической памяти и возвращает указатель на объект.

оператор `delete` получает указатель на динамический объект и уничтожает объект, после чего освобождает память.

### выделение памяти

создание динамического объекта:

```cpp


int *ptr{new int};

// или так

int *ptr = new int;
```

`new` создаёт объект типа `int` в динамической памяти и возвращает указатель на него. `ptr` хранит адрес выделенной памяти. форма `new int` выполняет инициализацию по умолчанию. для скалярного типа значение при этом неопределено: читать его до записи нельзя.

объект можно инициализировать в том же выражении:

```cpp


int *ptr{new int()};	// значение по умолчанию - 0

// int *ptr = new int(); - или так

std::cout << *ptr << std::endl;		// 0
```

объект, на который указывает `ptr`, получает значение по умолчанию, число 0. круглые скобки в `new int()` задают инициализацию значением (value-initialization). для `int` это нуль.

ту же инициализацию записывают фигурными скобками:

```cpp


int *ptr{new int{}};	// значение по умолчанию - 0

// int *ptr = new int{}; - или так

std::cout << *ptr << std::endl;		// 0
```

`new int{}` тоже есть инициализация значением, и для `int` результат снова 0. фигурные скобки дополнительно запрещают сужающие преобразования, если в них передают аргумент другого типа.

объект инициализируют и конкретным значением:

```cpp


int *ptr{new int{5}};	

// альтернативные варианты

// int *ptr = new int{5};

// int *ptr {new int(5)};

// int *ptr = new int(5);

std::cout << *ptr << std::endl;		// 5
```

значение объекта в динамической памяти равно 5. формы `new int{5}` и `new int(5)` прямо инициализируют объект этим значением. скобки вокруг всего инициализатора в объявлении указателя (`int *ptr{...}` и `int *ptr = ...`) относятся уже к инициализации самого указателя, а не к способу вызвать `new`.

через указатель динамическому объекту присваивают другое значение. разыменование даёт lvalue объекта, и обычное присваивание пишет в выделенную память:

```cpp


int *ptr{new int{5}};

std::cout << "*ptr = " << *ptr << std::endl;  // *ptr = 5

*ptr = 22;

std::cout << "*ptr = " << *ptr << std::endl;  // *ptr = 22
```

### освобождение памяти

динамический объект живёт, пока его явно не удалят. после использования память освобождают оператором `delete`:

```cpp


#include <iostream>

 

int main()

{

    int *ptr{new int{5}};   // выделяем память

    std::cout << "*ptr = " << *ptr << std::endl;  // *ptr = 5

    delete ptr;             // освобождаем память

}
```

это особенно важно, когда объект создаётся в одной части программы, а используется в другой. указатель можно вернуть из функции, и время жизни объекта тогда не совпадает со временем жизни ни одной автоматической переменной:

```cpp


#include <iostream>

 

int* createPtr(int value)

{

    int *ptr {new int{value}};

    return ptr;

}

void usePtr()

{

    int *obj = createPtr(10);

    std::cout << *obj << std::endl;  // 10

    delete obj;  // объект надо освободить

}

int main()

{

    usePtr();

}
```

`usePtr` получает от `createPtr` указатель на динамический объект. после выхода из `usePtr` объект сам не уничтожается, в отличие от локального автоматического объекта. его удаляют явно, оператором `delete`. удаление обязано произойти ровно один раз и на том указателе, который ещё адресует живой объект.

если `delete` так и не вызван, выделенная динамическая память будет возвращена при завершении процесса: операционная система забирает адресное пространство целиком. до этого момента память считается утечкой. утечка в короткой программе часто незаметна, в долгоживущем процессе она накапливается.

после `delete` указатель по-прежнему содержит прежний адрес, хотя память по нему уже освобождена и может быть выдана другому динамическому объекту. такой указатель называют висячим, или болтающимся (dangling pointer). обращение по нему и повторный `delete` дают неопределённое поведение. наблюдаемый эффект не фиксирован стандартом: порча данных, аварийное завершение или видимость старого значения одинаково возможны.

```cpp


int *ptr {new int{12}};

std::cout << *ptr << std::endl;  // 12

delete ptr;



// ошибочные сценарии

std::cout << *ptr << std::endl;  // объект по указателю ptr уже удален!

delete ptr;	// объект по указателю ptr уже удален!
```

чтобы не оставить висячий указатель, после освобождения его обнуляют:

```cpp


int *ptr {new int{12}};

std::cout << *ptr << std::endl;  // 12

delete ptr;

ptr = nullptr;          // обнуляем указатель
```

разыменование нулевого указателя тоже есть неопределённое поведение. на практике программа при этом обычно завершается аварийно, но язык такого завершения не обещает. применение `delete` к нулевому указателю определено стандартом и не делает ничего: проверка на `nullptr` внутри `delete` не требуется.

часто на один динамический объект указывают сразу несколько указателей. `delete`, применённый к одному из них, освобождает память, и второй указатель становится висячим. второй `delete` по тому же адресу повреждает структуру динамической памяти: это повторное освобождение.

недействительность адреса после `delete` не запрещает использовать саму переменную-указатель дальше. ей присваивают адрес другого объекта:

```cpp


#include <iostream>



int main()

{

	int *p1 {new int{12}};

    int *p2 {p1};   // p1 и  p2 указывают на один и тот же объект

    

    std::cout << *p1 << std::endl;  // 12

    std::cout << *p2 << std::endl;  // 12

    delete p1;      // адреса в p1 и p2 недопустимы

	p1 = nullptr;

    p2 = nullptr;

 

    p1 = new int{11};   // p1 указывает на новый объект

    std::cout << *p1 << std::endl;  // 11

    delete p1;

}
```

после удаления объекта, на который указывал `p1`, этому указателю передают адрес нового объекта в динамической памяти, и `p1` снова можно разыменовывать. адрес в `p2` остаётся недействительным: обнуление `p2` это фиксирует, нового объекта `p2` не получает. владение динамическим `int` в этом примере вручную ведётся программистом. каждый `new` имеет свой `delete`, и ни один адрес не освобождается дважды.
