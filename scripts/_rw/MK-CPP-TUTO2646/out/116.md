в c++ выражения относятся к категориям значений. лекция работает с двумя категориями: lvalue и rvalue. имена сложились из положения относительно присваивания. left value стоит слева, right value справа. с c++11 стандарт уточняет состав этих категорий. rvalue включает prvalue и xvalue. lvalue вместе с xvalue образует glvalue: выражение, которое обозначает объект, битовое поле или функцию с уже установленной идентичностью. примеры этой лекции читаются и в исходных терминах. ссылка `T&&` и `std::move` опираются на уточненную схему, поэтому рядом с формулировками лекции даны категории стандарта.

lvalue обозначает сущность с идентичностью и с адресом. объект занимает память в течение своего времени жизни. у автоматической переменной это тело блока, у объекта со статической продолжительностью хранения это весь запуск программы. к lvalue относятся имена переменных, параметров и константных объектов. неконстантный lvalue ставится слева от присваивания. константный объект тоже остается lvalue и тоже имеет адрес. присваивание ему запрещает квалификатор `const`.

rvalue в формулировке лекции есть источник присваивания или инициализации: литерал либо результат выражения. в классификации стандарта литерал вроде `5` есть prvalue. prvalue инициализирует объект и сам объект с именем не обозначает.

```cpp

int n = 5;
```

выражение `n` есть lvalue: у переменной есть имя и адрес. литерал `5` есть rvalue и служит инициализатором. отсюда исторические имена. имя слева от оператора присваивания есть left value, значение справа есть right value. то же деление действует в инициализации и при связывании ссылок, без оператора `=`.

```cpp

int n{5}
int k{n + 7};
```

`n` и `k` есть lvalue. литерал `5` и выражение `n + 7` есть rvalue. сумма не именует отдельный объект. её результат инициализирует `k`. во фрагменте после инициализации `n` нет точки с запятой. в таком виде фрагмент не переводится как корректная программа. на категории выражений пропуск не влияет.

### rvalue-ссылка

rvalue-ссылка связывается с результатом выражения, включая временный объект. если временный объект связан с rvalue-ссылкой, которая сама является локальной переменной, время жизни временного объекта продлевается до конца области видимости этой ссылки. освобождение откладывается до выхода из области видимости ссылки. конец полного выражения, создавшего временный объект, этот объект уже не уничтожает. у параметра функции такого продления нет: временный аргумент живет до конца полного выражения вызова.

объявление rvalue-ссылки ставит два амперсанда после имени типа: `T&&`.

```cpp

#include <iostream>

int main()
{
    int n {5};
	int&& tempRef {n+3}; 				// ссылка rvalue
	std::cout << tempRef << std::endl; // 8
}
```

выражение `n + 3` материализуется во временный объект типа `int`. у автоматического временного объекта реализация отводит память в стеке. `tempRef` ссылается на этот объект, и печать дает `8`. область видимости `tempRef` есть тело `main`. по завершении `main` ссылка уничтожается, вместе с ней заканчивается продленное время жизни временного объекта.

выражение `tempRef` при этом есть lvalue. категория значения принадлежит выражению, тип принадлежит сущности. тип переменной есть `int&&`, имя у нее есть, и использование имени дает lvalue. именованная rvalue-ссылка в дальнейшем коде ведет себя как lvalue. чтобы снова получить rvalue, выражение нужно явно привести. для этого ниже используется `std::move`.

### функция std::move

rvalue-ссылка с lvalue не связывается. инициализация в следующем фрагменте некорректна и не компилируется.

```cpp

int n {5};
int&& tempRef = n; 	// ! Так нельзя
```

`n` есть lvalue. ссылке `int&&` нужен rvalue. иногда lvalue все же нужно передать в параметр, который принимает только rvalue, в частности в конструктор перемещения. стандартная библиотека дает для этого шаблон функции `std::move`. объявление находится в заголовке `<utility>`. переноса ресурсов внутри `std::move` нет. шаблон приводит аргумент к rvalue-ссылке и по действию совпадает с `static_cast<std::remove_reference_t<T>&&>(t)`. результат есть xvalue: объект прежний, а выражение помечает его как объект, из которого разрешено перемещать. опустошает объект тот конструктор или тот оператор присваивания, который примет эту rvalue-ссылку.

```cpp

#include <iostream>

int main()
{
    int n {5};
	int&& tempRef = std::move(n); 	// преобразуем int в int&&
	std::cout << tempRef << std::endl; // 5
}
```

здесь `std::move(n)` имеет категорию rvalue, и `tempRef` связывается с тем же объектом `n`. печать выводит `5`. для типа `int` внешнего буфера нет, забирать из объекта нечего. практическая польза приведения появляется у классов с ресурсами. её показывает конструктор перемещения в следующих лекциях. фрагмент подключает `<iostream>` и вызывает `std::move`. стандарт помещает объявление `std::move` в `<utility>`. перевод фрагмента как он записан зависит от транзитивного включения. переносимая программа подключает `<utility>` сама.

приведение константного объекта дает константную rvalue-ссылку.

```cpp

const int m{2};
const int&& mRef = std::move(m);	// результат - константная ссылка
```

тип результата есть `const int&&`. временного объекта здесь нет: ссылка обозначает тот же `m`. приведение сохраняет `const`. конструктор перемещения с параметром `T&&` на аргумент `const int&&` не связывается.

### rvalue-ссылка как параметр функции

rvalue-ссылка допустима как параметр функции. два амперсанда после типа параметра требуют аргумент категории rvalue.

```cpp

#include <iostream>
#include <string>

void print(std::string&& text)
{
	std::cout << text << std::endl;
}

int main()
{
	print("hello");
}
```

`print` принимает `std::string&&`. вызов с литералом корректен.

```cpp
print("hello");
```

литерал `"hello"` есть lvalue типа `const char[6]`. у массива литерала статическая продолжительность хранения и есть адрес. массив литерала остается на месте. для параметра `std::string&&` из него строится временный `std::string` конструктором от `const char*`. с параметром связывается этот временный объект, и он есть rvalue. временный объект жив все время выполнения вызова, потому что время жизни покрывает полное выражение, и уничтожается в конце этого выражения. параметр функции продления за границы вызова не дает.

передать lvalue в тот же параметр нельзя. строки ниже не компилируются.

```cpp

std::string message = "hi world";
print(message);		// ! Ошибка - передаем lvalue
```

`message` именует объект, выражение `message` есть lvalue. rvalue-ссылка с ним не связывается. перегрузки `print` для `const std::string&` и для `std::string` по значению нет, поэтому вызов некорректен.

то же имя становится допустимым аргументом после `std::move`.

```cpp
print(std::move(message));
```

`std::move(message)` есть xvalue и обозначает объект `message`. параметр `text` именует этот объект, копии символов нет. `print` только печатает строку, и после возврата значение `message` прежнее. если бы вызванная функция переместила ресурсы из параметра, `message` остался бы в корректном, но не специфицированном состоянии. стандарт гарантирует для такого объекта безопасное уничтожение и присваивание. конкретное содержимое буфера он не фиксирует.

### возвращение rvalue из функции

возврат локальной автоматической переменной делает выражение пригодным для неявного перемещения. разрешение перегрузки сначала рассматривает его как rvalue, поэтому у `std::string` доступен конструктор перемещения. этот конструктор обязан быть доступен и тогда, когда вызов в итоге устранен оптимизацией. с c++20 то же правило охватывает параметр функции. дополнительно, если возвращается имя локальной автоматической переменной, объявленной в теле, компилятору разрешена оптимизация nrvo, named return value optimization. параметр функции в nrvo не участвует: его инициализирует вызывающий в другом объекте. nrvo необязательна. гарантированное исключение копирования из c++17 применяется к prvalue. именованная локальная переменная под него не подпадает.

```cpp

#include <iostream>
#include <string>

void print(std::string&& text)
{
	std::cout << text << std::endl;
}

std::string defaultMessage()
{
	std::string message{"hello world"};
	return message;
}
int main()
{
	print(defaultMessage()); // передаем rvalue
}
```

`defaultMessage` возвращает rvalue, и этот результат передается в `print`. при срабатывании nrvo компилятор строит объект сразу в памяти, отведенной под возвращаемое значение. отдельной автоматической переменной `message` тогда нет. в программе создается один объект `std::string`. без nrvo возврат все равно трактуется как rvalue. конструктор перемещения `std::string` забирает ресурсы локального объекта за постоянное время. на коротком интервале существуют два объекта строки.

```cpp

#include <iostream>
#include <string>

std::string defaultMessage()
{
	std::string message{"hello world"};
	return message;
}
int main()
{
	std::string text = defaultMessage();
    std::cout << text << std::endl;
}
```

сохранение результата во внешнюю переменную устроено так же. при nrvo объект `text` и есть тот единственный `std::string`, который создается при возврате. локальное имя `message` в отдельную сущность не материализуется.

лекция задает семантику rvalue и правила работы с rvalue-ссылкой. практическое применение, прежде всего конструктор перемещения, разбирается в следующих лекциях курса.
