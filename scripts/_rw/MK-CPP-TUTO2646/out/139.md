для работы с файлами стандартная библиотека задаёт заголовочный файл `fstream`. в нём объявлены базовые типы файловых потоков:

- `ifstream`: чтение из файла

- `ofstream`: запись в файл

- `fstream`: совмещает запись и чтение

для данных типа `wchar_t` у этих потоков есть широкие двойники:

- `wifstream`

- `wofstream`

- `wfstream`

узкий поток передаёт символы типа `char`. широкий поток передаёт `wchar_t`. внешнюю последовательность байтов во внутренний тип символа переводит фасет кодировки той локали, которая назначена потоку.

### открытие файла

перед чтением и записью файл связывают с потоком. связь устанавливает функция-член `open`. у неё две формы:

- `open(путь)`

- `open(путь, режим)`

в функцию передаётся путь к файлу в виде строки. вторым аргументом можно задать режим открытия, маску типа `ios_base::openmode`. несколько флагов соединяются оператором `|`. режимы такие:

- `ios::in`: файл открывается для ввода, то есть для чтения. флаг задают объекту `ifstream` или `fstream`

- `ios::out`: файл открывается для вывода, то есть для записи, и прежние данные удаляются. сочетание с `out` и без `in` соответствует режиму создания заново и усекает уже существующий файл. флаг задают объекту `ofstream` или `fstream`

- `ios::app`: файл открывается для дозаписи. старые данные сохраняются. перед каждой операцией вывода позиция записи переносится в конец файла

- `ios::ate`: сразу после открытия текущая позиция переносится в конец файла. куда попадут следующие чтение и запись, решают уже последующие операции

- `ios::trunc`: при открытии файл усекается до пустого. флаг ставят вместе с режимом `out`

- `ios::binary`: файл открывается в двоичном режиме. текстовый режим вправе подменять концы строк под соглашение платформы, двоичный режим передаёт байты без этой подстановки

если режим не указан, для объекта `ofstream` применяется `ios::out`, для объекта `ifstream` применяется `ios::in`. для объекта `fstream` совмещаются `ios::out` и `ios::in`. сочетание ввода и вывода без `trunc` сохраняет уже записанные байты и открывает файл, когда он существует.

```cpp


std::ofstream out;			// поток для записи

out.open("hello1.txt"); // окрываем файл для записи

	

std::ofstream out2;

out2.open("hello2.txt", std::ios::app); // окрываем файл для дозаписи



std::ofstream out3;

out2.open("hello3.txt", std::ios::out | std::ios::trunc); // установка нескольких режимов



std::ifstream in;		// поток для чтения

in.open("hello4.txt"); // окрываем файл для чтения



std::fstream fs;		// поток для чтения-записи

fs.open("hello5.txt"); // окрываем файл для чтения-записи
```

первый поток открывает `hello1.txt` для записи. второй открывает `hello2.txt` для дозаписи, флаг `app`. вызов `out2.open` открывает `hello3.txt` с флагами `out` и `trunc`. выше в том же фрагменте объявлен `out3`. поток `in` открывает `hello4.txt` для чтения, поток `fs` открывает `hello5.txt` для чтения и записи.

открыть файл можно и конструктором. он принимает тот же путь и, второй формой, режим:

```cpp


fstream(путь)

fstream(путь, режим)
```

конструктор, которому передан путь, открывает файл сразу, в момент создания объекта:

```cpp


std::ofstream out("hello.txt");

std::ifstream in("hello.txt");

std::fstream fs("hello.txt", std::ios::app);
```

в примере принимается, что файл `hello.txt` лежит в той же папке, где лежит файл программы. относительный путь реализация разбирает от текущего каталога процесса. у запуска из среды разработки текущим каталогом часто оказывается каталог проекта, и тот же относительный путь указывает уже туда.

конструктор для открытия предпочтителен. определение переменной файлового потока уже предполагает, что поток будет открыт для чтения или записи. конструктор с путём выполняет открытие вместе с созданием объекта, и операции не начинаются на потоке, который ещё не связан с файлом. если открытие не удалось, поток получает `failbit`.

пока идёт работа с файлом, связь проверяют функцией `is_open()`. у открытого файла она возвращает `true`:

```cpp


std::ifstream in;		// поток для чтения

in.open("hello.txt"); // окрываем файл для чтения

// если файл открыт

if (in.is_open())

{

}
```

### закрытие файла

после завершения работы с файлом его закрывают функцией `close()`. она сбрасывает буфер на устройство и отсоединяет файл от потока. при выходе объекта потока из области видимости объект уничтожается, и деструктор сам вызывает `close`. явный вызов нужен, когда файл закрывают раньше конца области видимости, когда тот же объект затем открывают для другого пути или когда нужно узнать результат: ошибка сброса буфера при закрытии тоже выставляет `failbit`.

```cpp


#include <iostream>

#include <fstream>



int main()

{

	std::ofstream out;			// поток для записи

	out.open("hello.txt"); // окрываем файл для записи

	out.close();			// закрываем файл



	std::ifstream in;		// поток для чтения

	in.open("hello.txt"); // окрываем файл для чтения

	in.close();				// закрываем файл



	std::fstream fs;		// поток для чтения-записи

	fs.open("hello.txt"); // окрываем файл для чтения-записи

	fs.close();				// закрываем файл

}
```

в программе три потока по очереди открывают `hello.txt` и закрывают его через `close`: `ofstream` для записи, `ifstream` для чтения и `fstream` для чтения и записи.
