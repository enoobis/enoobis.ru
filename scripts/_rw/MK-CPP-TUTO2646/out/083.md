в процессе работы программы возникают различные ошибки. при передаче файла по сети может оборваться сетевое подключение, либо в программу попадут некорректные и недопустимые данные, после которых выполнение обрывается. такие ошибки называют исключениями. исключение представляет собой временный объект любого типа, который используется для сигнализации об ошибке. цель объекта-исключения состоит в том, чтобы передать информацию из точки, в которой произошла ошибка, в код, который должен её обработать. если исключение не обработано, при его возникновении программа прекращает работу.

например, в следующей программе выполняется деление чисел:

```cpp


#include <iostream>



double divide(int a, int b)

{

	return a / b;

}



int main()

{

	int x{500};

	int y{};

	double z {divide(x, y)};



	std::cout << z << std::endl;

	std::cout << "The End..." << std::endl;

}
```

эта программа успешно компилируется, но при выполнении возникает ошибка: в коде производится деление на ноль, после чего программа аварийно завершается. для целочисленного деления деление на ноль является неопределённым поведением. язык сам по себе не превращает его в исключение c++. аварийное завершение здесь следствие этого поведения, а не работы механизма `throw`.

проверку можно поместить в функцию `divide` и выполнять деление, если параметр `b` не равен 0. из функции `divide` при этом всё равно нужно вернуть некоторый результат, некоторое число. обойтись одним сообщением нельзя:

```cpp


double divide(int a, int b)

{

	if (b)

		return a / b;

	else

		std::cout << "Error! b must not be equal to 0" << std::endl;

}
```

ветка ошибки ничего не возвращает, хотя тип результата функции есть `double`. такое завершение функции с возвращаемым значением само по себе некорректно. вызывающий код нужно известить об ошибке отдельно. для этого используется оператор `throw`.

оператор `throw` генерирует исключение. через оператор `throw` передают информацию об ошибке. функция `divide` может выглядеть так:

```cpp


double divide(int a, int b)

{

	if (b)

		return a / b;

    throw "Division by zero!";

}
```

если параметр `b` равен 0, генерируется исключение. при ненулевом `b` функция возвращает частное и до оператора `throw` выполнение не доходит.

это исключение ещё нужно обработать в коде, где вызывается функция `divide`. для обработки исключений применяется конструкция `try...catch`. она имеет такую форму:

```cpp


try

{

	инструкции, которые могут вызвать исключение

}

catch(объявление_исключения)

{

	обработка исключения

}
```

в блок кода после служебного слова `try` помещается код, который потенциально может сгенерировать исключение.

после служебного слова `catch` в скобках идёт параметр, который передаёт информацию об исключении. затем в блоке выполняется собственно обработка исключения.

весь пример с обработкой выглядит так:

```cpp


#include <iostream>



double divide(int a, int b)

{

    if (b)

		return a / b;

    throw "Division by zero!";

}



int main()

{

	int x{500};

    int y{};

    

    try

    {

        double z {divide(x, y)};

		std::cout << z << std::endl;

	}

	catch (...)

	{

		std::cout << "Error!" << std::endl;

	}

	std::cout << "The End..." << std::endl;

}
```

код, который потенциально может сгенерировать исключение, то есть вызов функции `divide`, помещается в блок `try`.

в блоке `catch` выполняется обработка исключения. многоточие в скобках после оператора `catch` (`catch(...)`) позволяет обработать любое исключение, независимо от типа объекта.

когда выполнение дойдёт до строки

```b
double z {divide(x, y)};
```

при выполнении этой строки будет сгенерировано исключение. последующие инструкции блока `try` выполняться не будут, а управление перейдёт в блок `catch`, где на консоль выводится сообщение об ошибке. после блока `catch` программа аварийно не завершается и продолжает работу, выполняя операторы после блока `catch`:

```bash


Error!

The End...
```

в этом варианте известно лишь то, что произошла какая-то ошибка, а какая именно, неизвестно. через параметр блока `catch` получают то сообщение, которое передано оператору `throw`:

```cpp


#include <iostream>



double divide(int a, int b)

{

    if (b)

		return a / b;

    throw "Division by zero!";

}

 

int main()

{

    int x{500};

    int y{};

    

    try

    {

        double z {divide(x, y)};

        std::cout << z << std::endl;

    }

    catch (const char* error_message)

    {

        std::cout << error_message << std::endl;

    }

    std::cout << "The End..." << std::endl;

}
```

параметр `const char* error_message` получает сообщение, переданное оператору `throw`, и это сообщение выводится на консоль. тип параметра равен `const char*`, потому что после оператора `throw` стоит строковый литерал, а строковый литерал имеет тип `const char*`. консольный вывод тогда выглядит так:

```bash


Division by zero!

The End...
```

по тексту сообщения видна суть возникшего исключения. информацию об исключении передают через любые типы, например через `std::string`:

```cpp
throw std::string{"Division by zero!!"};
```

тогда в блоке `catch` эту информацию получают в виде объекта `std::string`:

```cpp


catch (std::string error_message)

{

    std::cout << error_message << std::endl;

}
```

если исключение не обработано, вызывается функция `std::terminate()` из заголовка `<exception>` стандартной библиотеки c++. она по умолчанию вызывает другую функцию, `std::abort()` из `<cstdlib>`, и уже `std::abort()` завершает программу. обработчик завершения можно сменить через `std::set_terminate`, но при необработанном исключении нормальное продолжение `main` не выполняется.

функций в стандартной библиотеке c++ и в сторонних библиотеках очень много. какие из них вызывать внутри `try-catch`, чтобы не столкнуться с необработанным исключением и аварийным завершением, подсказывает прежде всего документация по функции, если она есть. другой сигнал даёт служебное слово `noexcept`. в заголовке функции оно указывает, что эта функция не будет генерировать исключения. пример:

```cpp
void print(int argument) noexcept;
```

здесь указано, что функция `print()` не вызовет исключение. встретив функцию с таким служебным словом, ожидают, что она исключения не бросит, и помещать её вызов в конструкцию `try-catch` нет необходимости. если функция с `noexcept` всё же выполнит `throw` и исключение покинет её тело, реализация вызывает `std::terminate`. спецификатор описывает контракт, а не перехватывает ошибку.

### создание объекта исключения

при обработке исключения учитывают, что при передаче объекта оператору `throw` блок `catch` получает копию этого объекта. копия существует только в пределах блока `catch`. оператор `throw` копирует (или перемещает) операнд в объект исключения, которым управляет механизм обработки. параметр `catch`, принятый по значению, копирует этот объект ещё раз.

для значений примитивных типов, например `int`, копирование значения может не влиять на производительность программы. при передаче объектов классов издержки выше. поэтому объекты обычно передают по ссылке:

```cpp


#include <iostream>

#include <string>



double divide(int a, int b)

{

    if (b)

		return a / b;

    throw std::string{"Division by zero!"};

}

 

int main()

{

    int x{500};

    int y{};

    

    try

    {

        double z {divide(x, y)};

        std::cout << z << std::endl;

    }

    catch (const std::string& error_message)	// строка передается по ссылке

    {

        std::cout << error_message << std::endl;

    }

    std::cout << "The End..." << std::endl;

}
```

константная ссылка `const std::string&` связывается с объектом исключения без дополнительной копии и не позволяет обработчику менять этот объект. время жизни объекта исключения покрывает соответствующий блок `catch` и заканчивается при выходе из него, если исключение не выпускают дальше.

### обработка и генерация разных типов исключений

генерировать и обрабатывать можно несколько разных исключительных ситуаций. требуется, чтобы при делении делитель (второе число) был не больше, чем делимое (первое число):

```cpp


#include <iostream>



double divide(int a, int b)

{

    if(!b)  // если b == 0

    {

        throw 0;

    }

    if(b > a) 

    {

        throw "The second number is greater than the first one";

    }

	return a / b;

}



void test(int a, int b)

{

    try

    {

        double result {divide(a, b)};

        std::cout << result << std::endl;

    }

    catch (int code)

    {

        std::cout << "Error code: " << code << std::endl;

    }

    catch (const char* error_message)

    {

        std::cout << error_message << std::endl;

    }

}

 

int main()

{

    test(100, 20);      // 5

    test(100, 0);       // Error code: 0

    test(100, 1000);    // The second number is greater than the first one

}
```

в функции `divide` в зависимости от значения числа `b` оператору `throw` передаётся либо число:

```cpp
throw 0;
```

либо строковый литерал:

```cpp
throw "The second number is greater than the first one";
```

для тестирования функции `divide` определена другая функция, `test`. вызов `divide()` помещён в конструкцию `try..catch`. при генерации исключения ошибка приходит в одном из двух типов: `int`, если `b` равно 0, и `const char*`, если `b` больше `a`. для каждого типа определён свой блок `catch`:

```cpp


catch (int code)

{

    std::cout << "Error code: " << code << std::endl;

}

catch (const char* error_message)

{

    std::cout << error_message << std::endl;

}
```

обработчики просматриваются по порядку текста, и выбирается первый, чей параметр совместим с типом объекта исключения. порядок блоков поэтому часть интерфейса обработки.

в функции `main` функция `test` вызывается с различными числами. при вызове

```cpp
test(100, 20);      // 5
```

число `b` не равно 0 и меньше `a`, поэтому исключения не возникает. блок `try` выполняется до конца, и функция завершает работу.

при втором вызове

```cpp
test(100, 0);      // Error code: 0
```

число `b` равно 0, поэтому генерируется исключение, а в качестве объекта исключения передаётся число 0. программа выбирает тот блок `catch`, где обрабатываются исключения типа `int`:

```cpp


catch (int code)

{

    std::cout << "Error code: " << code << std::endl;

}
```

при третьем вызове

```cpp
test(100, 1000);    // The second number is greater than the first one
```

число `b` больше `a`, поэтому объект исключения представляет собой строковый литерал типа `const char*`. программа выбирает блок `catch`, где обрабатываются исключения типа `const char*`:

```cpp


catch (const char* error_message)

{

    std::cout << error_message << std::endl;

}
```

консольный вывод в этом примере такой:

```bash


5

Error code: 0

The second number is greater than the first one
```

возможна ситуация, когда исключение генерируется внутри конструкции `try-catch` и блок `catch` присутствует, однако он обрабатывает другие типы исключений:

```cpp


void test(int a, int b)

{

    try

    {

        double result {divide(a, b)};

        std::cout << result << std::endl;

    }

    catch (const char* error_message)

    {

        std::cout << error_message << std::endl;

    }

}
```

здесь нет блока `catch` для исключения типа `int`. поэтому при генерации исключения

```cpp
throw 0;
```

программа не находит подходящий блок `catch`. исключение остаётся необработанным, и программа аварийно завершает выполнение. `catch(...)`, если его поставить последним, принял бы и этот тип, потому что многоточие совместимо с любым объектом исключения.

### try-catch и деструкторы

если в блоке `try` создаются объекты, при возникновении исключения у них вызываются деструкторы. поиск обработчика сопровождается раскруткой стека: для объектов с автоматическим временем хранения, созданных в блоке и ещё живых в момент `throw`, деструкторы выполняются до входа в `catch`. пример:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name) :name{ name }

    {

        std::cout << "Person " << name << " created" << std::endl;

    }

    ~Person()

    {

        std::cout << "Person " << name << " deleted" << std::endl;

    }

    void print()

    {

        throw "Print Error";

    }

private:

    std::string name;

};



int main()

{

    try

    {

        Person tom{ "Tom" };

        tom.print();    // Здесь генерируется ошибка

    }

    catch (const char* error)

    {

        std::cerr << error << std::endl;

    }

}
```

в классе `Person` определён деструктор, который выводит сообщение на консоль. в функции `print` генерируется исключение.

в функции `main` в блоке `try` создаётся один объект `Person` и у него вызывается функция `print`. это приводит к генерации исключения и переходу управления в блок `catch`. консольный вывод

```bash


Person Tom created

Person Tom deleted

Print Error
```

показывает, что прежде чем начнётся обработка исключения в блоке `catch`, будет вызван деструктор объекта `Person`. объект `tom` покидает область видимости из-за перехода к обработчику, и уничтожение автоматического объекта выполняется до первой инструкции `catch`. если деструктор во время раскрутки сам сгенерирует исключение, которое покинет деструктор, программа вызовет `std::terminate`.
