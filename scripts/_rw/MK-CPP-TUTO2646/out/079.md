компилятор по умолчанию объявляет для классового типа оператор копирующего присваивания. благодаря этому значение некоторого типа присваивают переменной, параметру или другому объекту того же типа, если объект слева уже существует. создаваемый по умолчанию оператор присваивания копирует все нестатические члены класса один за другим, в том порядке, в котором они объявлены в определении класса. рядом с ним язык объявляет копирующий конструктор: он выполняет такое же почленное копирование, но вызывается при инициализации нового объекта.

```cpp


#include <iostream>



class Counter

{

public:

    Counter(int val)

    {

        value =val;

    }

    void print()  const

    {

        std::cout << "Value: " << value << std::endl;

    }

    void setValue(int val){ value=val;} // для изменения переменной value

private:

    int value;

};



int main()

{

    Counter c1{25};

    Counter c2 = c1;    // с2 получает копию состояния c1

    c1.setValue(30);    // изменения в c1 не влияют на c2

    c1.print();     // Value: 30

    c2.print();     // Value: 25

}
```

в классе `Counter` есть поле `value`. когда состояние одного объекта передаётся другому, копия получает значение `value` источника.

```cpp


Counter c1{25};

Counter c2 = c1;    // с2 получает копию состояния c1
```

запись `Counter c2 = c1` является копирующей инициализацией. объект `c2` создаётся копирующим конструктором, и тот копирует `value` из `c1`. оператор присваивания применяется, когда оба объекта уже сконструированы, как в примере `c2 = c1` ниже. последующее изменение `value` в одном объекте `Counter` не затрагивает другой: у каждого объекта собственное поле типа `int`, и копирование передаёт значение, а не связывает два имени с одной переменной.

так работает создаваемый по умолчанию оператор присваивания. его можно определить заново. оператор присваивания объявляется только как функция-член класса.

оператор присваивания возвращает ссылку на объект, а его параметр представляет собой ссылку на константу. для типа `Counter` реализация такая:

```cpp


#include <iostream>



class Counter

{

public:

    Counter(int val)

    {

        value =val;

    }

    void print()  const

    {

        std::cout << "Value: " << value << std::endl;

    }

    Counter& operator=(const Counter& counter)

    {

        if(&counter != this)

        {

            value = counter.value;

        }

        return *this;

    }

private:

    int value;

};



int main()

{

    Counter c1{25};

    Counter c2{30};

    c2 = c1;    // с2 получает копию состояния c1

    c2.print();     // Value: 25

}
```

устройство оператора видно по телу:

```cpp


Counter& operator=(const Counter& counter)

{

    if(&counter != this)

    {

        value = counter.value;

    }

    return *this;

}
```

функция оператора неконстантная: в ней меняется состояние объекта. параметром передаётся константная ссылка на присваиваемый объект `Counter`. источник изменять не нужно, а ссылка избегает копирования аргумента.

результатом возвращается ссылка на текущий объект `Counter`, то есть на левый операнд. параметр `counter` для возврата не подходит. оператор `=` правоассоциативен и по соглашению возвращает левый операнд, чтобы цепочка присваиваний собиралась слева направо по скобкам. пример цепочки:

```cpp


Counter counter1{25};

Counter counter2{0};

Counter counter3{0};

counter3 = counter2 = counter1;
```

цепь присваиваний раскрывается так:

```cpp


counter3 = (counter2 = counter1);
```

сначала `counter2` получает значение `counter1`. затем `counter3` получает результат предыдущей операции, а этот результат представляет собой объект `counter2` после присваивания. ссылка на левый операнд делает тип и объект результата той же сущностью, которой присвоили значение.

отдельная проверка сравнивает адрес параметра с адресом текущего объекта:

```cpp


if(&counter != this)

{

    value = counter.value;

}
```

если параметр обозначает текущий объект, присваивание полю `value` ничего не меняет, и выполнять его нет смысла. проверка закрывает самоприсваивание:

```cpp
counter1 = counter1;
```

такая проверка убирает лишнюю работу и заметна по производительности там, где операция освобождает и заново выделяет память. она же предупреждает запись в уже освобождённую память. при наивной реализации указатель `this` сначала освобождают, а затем читают источник. если источник и приёмник совпадают, чтение идёт из освобождённого блока.

### копирование указателей

иногда собственный оператор присваивания необходим из-за семантики ресурса. это показывает программа, в которой объект владеет динамической памятью.

```cpp


#include <iostream>



class Counter

{

public:

    Counter(int n)

    {

        value =new int{n};    // выделяем память

    }

    ~Counter()

    {

        delete value;    // освобождаем память

    }

    void print()  const

    {

        std::cout << *value << std::endl;

    }

private:

    int* value;

};



int main()

{

    Counter counter1{5};

    {

        Counter counter2{3};

        counter1 = counter2;

        counter1.print();     // 3

    }

    counter1.print();     // ????

}
```

класс `Counter` хранит указатель на `int`. в конструкторе выделяется память для одного числа, переданного параметром. в деструкторе память освобождается. на первый взгляд владение согласовано. применение класса в функции `main` показывает иное:

```cpp


Counter counter1{5};

{

    Counter counter2{3};

    counter1 = counter2;

    counter1.print();     // 3

}

counter1.print();     // ????
```

во вложенном блоке создаётся объект `counter2`, и он присваивается объекту `counter1`. неявный оператор присваивания копирует адрес, а не число. в итоге `counter1` и `counter2` указывают на один и тот же блок. по завершении вложенного блока заканчивается время жизни `counter2`, вызывается его деструктор, и память освобождается. освобождается и память, на которую всё ещё ссылается `counter1`, потому что адрес был один. `counter1` при этом продолжает существовать: он создан вне вложенного блока. дальнейшее разыменование `value` даёт непредсказуемый результат. инвариант исключительного владения нарушен: деструктор предполагает, что блок принадлежит только этому объекту, а почленное копирование указателя размножило владение.

положение исправляет явно определённый оператор присваивания:

```cpp


#include <iostream>



class Counter

{

public:

    Counter(int n)

    {

        value =new int{n};    // выделяем память

    }

    ~Counter()

    {

        delete value;    // освобождаем память

    }

    void print()  const

    {

        std::cout << *value << std::endl;

    }

    Counter& operator=(const Counter& counter)

    {

        if(&counter != this)

        {

            *value = *counter.value;

        }

        return *this;

    }

private:

    int* value;

};



int main()

{

    Counter counter1{5};

    {

        Counter counter2{3};

        counter1 = counter2;

        counter1.print();     // 3

    }

    counter1.print();     // 3

}
```

здесь присваивание копирует само число, `*value = *counter.value`, и не копирует адрес. оба объекта сохраняют собственные блоки, выделенные в конструкторах. деструктор `counter2` освобождает только свой блок. после выхода из вложенного блока `counter1.print()` по-прежнему печатает 3. проверка `&counter != this` и в этой версии отсекает самоприсваивание, при котором чтение и запись шли бы в один и тот же `int`.

### удаление оператора присваивания

вместо реализации оператора присваивания неявный оператор можно удалить. для этого применяется служебное слово `delete`:

```cpp
Counter& operator=(const Counter& counter) = delete;
```

если в программе затем встретится присваивание вида

```cpp
counter1 = counter2;
```

компилятор сообщит об ошибке. удаление закрывает операцию на этапе компиляции и не оставляет возможности случайно скопировать указатель присваиванием. копирующий конструктор при этом остаётся неявным, и инициализация вида `Counter b = a` по-прежнему копирует адрес. полный запрет копирования требует удалить и копирующий конструктор.
