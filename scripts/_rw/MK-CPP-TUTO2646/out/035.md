### передача аргументов по значению

аргументы, которые являются переменными или константами, передаются в функцию **по значению** (by value) или **по ссылке** (by reference). способ передачи есть свойство параметра и фиксируется в его типе.

при передаче **по значению** функция получает копию значения. параметр инициализируется этой копией и является отдельным объектом. изменения параметра остаются внутри функции.

```cpp


#include <iostream>

 

void square(int);   // прототип функции



int main()

{

    int n {4};

    std::cout << "Before square: n = " << n << std::endl;

    square(n);

    std::cout << "After square: n = " << n << std::endl;

}



void square(int m)

{

    m = m * m;  // изменяем значение параметра

    std::cout << "In square: m = " << m << std::endl;

}
```

функция `square` принимает число типа `int` и возводит его в квадрат. в `main` до вызова и после вызова выводится переменная `n`, которая передана в `square` как аргумент.

изменение параметра `m` внутри `square` действует только в пределах этой функции. переменная `n`, переданная как аргумент, не меняется:

```bash


Before square: n = 4

In square: m = 16

After square: n = 4
```

причина в том, как устроен вызов. для параметров функции отводится отдельная память, как правило в кадре активации. при вызове вычисляются аргументы, и полученные значения записываются в эту память: параметр инициализируется копией. дальше функция работает с копиями значений. объекты вызывающего кода при этом не затрагиваются. присваивание `m = m * m` меняет копию. объект `n` в `main` остаётся равным 4, и после возврата копия уничтожается вместе с кадром.

### передача параметров по ссылке

при передаче **по ссылке** в функцию передаётся ссылка на объект. через неё меняется сам объект. отдельной копии значения у ссылочного параметра нет. ниже тот же пример переписан на передачу по ссылке:

```cpp


#include <iostream>

 

void square(int&);   // прототип функции

 

int main()

{

    int n {4};

    std::cout << "Before square: n = " << n << std::endl;

    square(n);

    std::cout << "After square: n = " << n << std::endl;

}

void square(int& m)

{

    m = m * m;  // изменяем значение параметра

    std::cout << "In square: m = " << m << std::endl;

}
```

параметр `m` передаётся **по ссылке**. ссылочный параметр связывается непосредственно с объектом-аргументом, поэтому присваивание по ссылке есть присваивание этому объекту. при вызове параметр `m` в функции `square` обозначает тот же объект, что и переменная `n`. отдельного значения `m` нет: ссылка есть другое имя уже существующего объекта. тип параметра `int&` есть lvalue-ссылка, и она связывается только с lvalue подходящего типа.

после компиляции и запуска результат другой:

```bash


Before square: n = 4

In square: m = 16

After square: n = 16
```

передача по ссылке позволяет вернуть из функции сразу несколько значений: функция записывает результаты в несколько объектов вызывающего кода через несколько ссылочных параметров. для очень больших объектов передача по ссылке ещё и дешевле. копирования значения не происходит, функция использует сам объект. стоимость вызова не зависит от размера объекта и сводится к передаче адреса, которым ссылка представлена в реализации. обратная сторона той же семантики есть псевдоним: параметр и аргумент обозначают одну память, и запись через параметр видна вызывающему коду немедленно.

от передачи параметра по ссылке отличается передача ссылки в качестве аргумента функции, которая принимает параметр по значению:

```cpp


#include <iostream>



void square(int);   // прототип функции

 

int main()

{

    int n = 4;

    int &nRef = n;  // ссылка на переменную n

    std::cout << "Before square: n = " << n << std::endl;

    square(nRef);

    std::cout << "After square: n = " << n << std::endl;

}

void square(int m)

{

    m = m * m;  // изменяем значение параметра

    std::cout << "In square: m = " << m << std::endl;

}
```

если функция принимает аргумент по значению, изменение параметра не затрагивает внешние объекты. это остаётся верным и тогда, когда в вызов передана ссылка на объект. выражение `nRef` есть lvalue, обозначающее `n`, и по значению из него снимается копия. параметр `m` снова отдельный объект. внешняя ссылка `nRef` не превращает передачу по значению в передачу по ссылке: способ передачи определяет тип параметра. запись аргумента в виде ссылки на этот способ не влияет.

```bash


Before square: n = 4

In square: m = 16

After square: n = 4
```

передача по значению подходит для небольших объектов. их значения копируются в память параметров, и функция работает с этими копиями, не создавая псевдонимов. для встроенных арифметических типов копирование обычно дешевле, чем косвенное обращение по ссылке, и семантика проще: функция не может изменить аргумент.

передача по ссылке подходит для больших объектов. содержимое объекта не копируется в память параметра, и за счёт этого сокращается работа на вызове. тот же механизм используется, когда функция должна изменить объект вызывающего кода или записать в него результат.

### преобразования типов

передача по значению и передача по ссылке различаются ещё и правилами инициализации. c++ умеет неявно преобразовывать значения одних типов в другие, в том числе с потерей точности, например из `double` в `int`. при передаче по неконстантной ссылке такие автоматические преобразования исключены. неконстантная lvalue-ссылка связывается только с lvalue того же типа. временный объект, который возник бы при преобразовании, к ней привязать нельзя.

```cpp


#include <iostream>

 

void printVal(int);

void printRef(int&);



int main()

{

    double value{3.14159};

    printVal(value);    // 3

    printRef(value);    // ! Ошибка

}

void printVal(int n)

{

    std::cout << n << std::endl;

}

void printRef(int& n)

{

    std::cout << n << std::endl;

}
```

здесь две функции устроены почти одинаково. `printVal` получает параметр по значению, `printRef` получает параметр по ссылке. в обе передаётся число типа `double`, а параметр обеих объявлен как `int`. при передаче по значению `double` успешно преобразуется в `int`, хотя дробная часть отбрасывается: параметр инициализируется значением 3. при передаче по ссылке преобразование создало бы временный `int`, а неконстантная ссылка `int&` с временным объектом не связывается, поэтому вызов `printRef(value)` отвергается при компиляции. это отдельное основание предпочитать ссылочный параметр там, где преобразование нежелательно: непредусмотренное сужение типа не проходит молча на месте вызова. для параметра по значению то же сужение разрешено правилами инициализации копии и ошибкой не считается.
