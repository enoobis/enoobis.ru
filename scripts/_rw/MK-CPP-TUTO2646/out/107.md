## строки с поддержкой unicode

для строк в кодировках unicode заголовок `<string>` задает еще несколько специализаций `std::basic_string`.

- `std::wstring` содержит строку символов типа `wchar_t`

- `std::u8string` содержит строку символов типа `char8_t` (добавлена в c++20)

- `std::u16string` содержит строку символов типа `char16_t`

- `std::u32string` содержит строку символов типа `char32_t`

пустая широкая строка:

```cpp
std::wstring text;
```

инициализация литералом требует префикса кодировки. у `wstring` префикс `L`. у `u8string` префикс `u8`, у `u16string` префикс `u`, у `u32string` префикс `U`. префикс задает тип элемента литерала: `wchar_t`, `char8_t`, `char16_t` или `char32_t`.

```cpp
std::wstring text {L"Hello World!"};
std::u8string text8{u8"Hello World!"};
std::u16string text16 {u"Hello World!"};
std::u32string text32 {U"Hello World!"};
```

`std::wstring` печатают потоком `std::wcout`. этот поток работает с `wchar_t`. ориентация стандартного вывода на широкие символы должна быть согласована с тем, как терминал декодирует поток. в примере строка уходит в широкий поток:

```cpp
#include <iostream>
#include <string>

int main()
{
    std::wstring text {L"Hello World!"};
    std::wcout << text << std::endl;  // Hello! Good bye...
}
```

для `std::u8string`, `std::u16string` и `std::u32string` отдельных стандартных потоков нет. `char8_t` не приводится к `char` неявно, поэтому объект `u8string` в `std::cout` напрямую не передается.

в остальном эти типы повторяют интерфейс `std::string`: те же функции длины, конкатенации, поиска и подстроки, потому что все они есть специализации одного шаблона `std::basic_string`.

размер и кодировка `wchar_t` зависят от платформы. стандарт фиксирует только то, что это отдельный широкий символьный тип. в windows `wchar_t` обычно занимает 16 бит, и `wstring` хранит данные в utf-16, где часть символов кодируется суррогатной парой из двух единиц `wchar_t`. в большинстве других систем `wchar_t` занимает 32 бита, и широкая строка хранит utf-32. на этом фоне `u8string`, `u16string` и `u32string` имеют фиксированную ширину кодовой единицы: 8, 16 и 32 бита. поддержка unicode в стандартной библиотеке при этом остается ограниченной: классификация символов, нормализация и отдельный ввод-вывод для этих типов средствами одной только стандартной библиотеки не покрываются.
