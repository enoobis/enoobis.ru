### динамическое связывание при передаче параметров

если необходимо обеспечить динамическое связывание при передаче параметров в функцию, то такой параметр должен представлять ссылку или указатель на объект базового типа:

```cpp
#include <iostream>
#include <string>

class Person
{
public:
    Person(std::string name): name{name} { }
    virtual void print() const  // виртуальная функция
    {
        std::cout << name << std::endl;
    }
    std::string getName() const {return name;}
private:
    std::string name;
};
class Employee: public Person
{
public:
    Employee(std::string name, std::string company): Person{name}, company{company}{ }
    void print() const override // функция переопределена
    {
        std::cout << getName() << " (" << company << ")" << std::endl;
    }
private:
    std::string company;
};

void printPerson(const Person& person) 
{
    person.print();
}
 
int main()
{
    Person tom {"Tom"};
    Employee bob {"Bob", "Microsoft"};
    printPerson(tom);   // Tom
    printPerson(bob);   // Bob (Microsoft)
}
```

функция `printPerson` в качестве параметра принимает константную ссылку на объект типа `Person`, которым в реальности также может быть объект `Employee`. такая привязка не копирует объект и не срезает его. при вызове функции `print` программа динамически решает, какую именно реализацию функции вызвать.

### динамическое связывание и коллекции

объекты базовых и производных классов можно хранить в одной коллекции, например в массиве. например:

```cpp
#include <iostream>
#include <string>

class Person
{
public:
    Person(std::string name): name{name} { }
    virtual void print() const  // виртуальная функция
    {
        std::cout << name << std::endl;
    }
    std::string getName() const {return name;}
private:
    std::string name;
};
class Employee: public Person
{
public:
    Employee(std::string name, std::string company): Person{name}, company{company}{ }
    void print() const override // функция переопределена
    {
        std::cout << getName() << " (" << company << ")" << std::endl;
    }
private:
    std::string company;
};

void printPerson(const Person& person) 
{
    person.print();
}
 
int main()
{
    Person tom {"Tom"};
    Employee bob {"Bob", "Microsoft"};
    Employee sam {"Sam", "Google"};
    Person people[]{tom, bob, sam};
    for(const auto& person: people)
    {
        person.print();
    }
}
```

массив `people` хранит объекты `Person`, в качестве которых также могут выступать объекты `Employee`. однако при такой организации каждый объект `Employee`, который помещается в массив, преобразуется в объект `Person`. преобразование выполняется по значению и срезает объект: элемент массива является самостоятельным объектом `Person`, его динамический тип совпадает со статическим. в итоге при переборе такого массива вызывается функция `print` из класса `Person`:

```bash
Tom
Bob
Sam
```

если для элементов массива нужно динамическое связывание, то такие объекты должны представлять указатели. например, используются указатели:

```cpp
int main()
{
    Person tom {"Tom"};
    Employee bob {"Bob", "Microsoft"};
    Employee sam {"Sam", "Google"};
    Person* people[]{&tom, &bob, &sam}; // массив указателей
    for(const auto& person: people)
    {
        person->print();
    }
}
```

массив хранит адреса всех объектов, срезки нет, динамический тип каждого элемента сохраняется. вывод другой:

```bash
Tom
Bob (Microsoft)
Sam (Google)
```

### виртуальные деструкторы

деструктор определяет логику удаления объекта класса. при удалении объекта производного класса ожидается, что будет выполняться деструктор производного класса, а затем и деструктор базового, что позволяет выполнить необходимую логику, например освобождение выделенной памяти, для обоих классов. однако в некоторых ситуациях ожидаемый порядок вызова не выполняется. например:

```cpp
#include <iostream>
#include <memory>
#include <string>

class Person
{
public:
    Person(std::string name): name{name} { }
     ~Person()
    {
        std::cout << "Person " << name << " deleted" << std::endl;
    }
    virtual void print() const  // виртуальная функция
    {
        std::cout << name << std::endl;
    }
    std::string getName() const {return name;}
private:
    std::string name;
};
class Employee: public Person
{
public:
    Employee(std::string name, std::string company): Person{name}, company{company}{ }
    ~Employee()
    {
        std::cout << "Employee " << getName() << " deleted" << std::endl;
    }
    void print() const override // функция переопределена
    {
        std::cout << getName() << " (" << company << ")" << std::endl;
    }
private:
    std::string company;
};
void printPerson(const Person& person)
{
    person.print();
}
 
int main()
{
    std::unique_ptr<Person> sam { std::make_unique<Employee>("Sam", "Google") };
    sam->print();
}
```

переменная `sam` представляет smart-указатель `std::unique_ptr<Person>` на объект `Person`, и этот указатель автоматически выделяет память для одного объекта `Employee`. поскольку объект `Employee` одновременно является объектом `Person`, приведение типа здесь корректно.

для обоих классов определены деструкторы, которые просто выводят строку на консоль. после завершения функции `main` объект указателя `sam` будет удалён, и ожидается выполнение деструкторов классов `Employee` и `Person`, потому что динамический тип объекта есть `Employee`. консоль показывает другое:

```bash
Sam (Google)
Person Sam deleted
```

для объекта по указателю `sam` вызывается только деструктор класса `Person`, хотя объект имеет тип `Employee`. если деструктор базового класса не виртуальный, удаление объекта производного класса через указатель на базовый класс даёт неопределённое поведение. наблюдаемый вывод соответствует распространённой реализации: вызывается деструктор статического типа. это может иметь неприятные последствия, особенно если в конструкторе `Employee` выделяется память, а в деструкторе `Employee` она освобождается. этот деструктор не выполнится, и ресурс не будет возвращён. чтобы деструктор `Employee` вызывался, деструктор базового класса надо определить как виртуальный. деструктор класса `Person` дополняется словом `virtual`:

```cpp
virtual ~Person()
{
    std::cout << "Person " << name << " deleted" << std::endl;
}
```

весь остальной код остаётся прежним. консольный вывод другой:

```bash
Sam (Google)
Employee Sam deleted
Person Sam deleted
```

теперь вызывается деструктор обоих классов: сначала `Employee`, затем `Person`. деструктор производного класса переопределяет виртуальный деструктор базы, хотя имена `~Employee` и `~Person` различны. в языке деструкторы образуют отдельную цепочку переопределения. если деструктор базового класса виртуальный, деструкторы производных классов тоже виртуальные. `std::unique_ptr<Person>` уничтожает объект через указатель на `Person` и при виртуальном деструкторе вызывает деструктор динамического типа.

### переопределение спецификатора доступа

виртуальные функции позволяют обойти ограничения на доступ к функциям. например, функция `print` в классе `Employee` делается приватной:

```cpp
#include <iostream>
#include <string>

class Person
{
public:
    Person(std::string name): name{name}
    { }
    virtual void print() const  // виртуальная функция
    {
        std::cout << "Name: " << name << std::endl;
    }
private:
    std::string name;
};
class Employee: public Person
{
public:
    Employee(std::string name, std::string company): Person{name}, company{company}
    { }
private:
    void print() const override // функция переопределена
    {
        Person::print();
        std::cout << "Works in " << company << std::endl;
    }
    std::string company;
};
 
int main()
{
    Employee bob {"Bob", "Microsoft"};
    Person* person {&bob};
    //bob.print();            // так нельзя - функция приватная
    person->print();        // а так можно
}
```

поскольку теперь функция `print` в `Employee` приватная, вне класса нельзя вызвать эту функцию напрямую для объекта `Employee`:

```cpp
Employee bob {"Bob", "Microsoft"};
bob.print();	// так нельзя - функция приватная
```

эту реализацию можно вызвать через указатель на тип `Person`:

```cpp
Person* person {&bob};
person->print();        // а так можно
```

проверка доступа выполняется по статическому типу выражения, которым записан вызов, а выбор реализации виртуальной функции выполняется по динамическому типу объекта. у выражения `bob.print()` статический тип есть `Employee`, и имя `print` в этом классе закрыто, поэтому вызов недопустим. у выражения `person->print()` статический тип есть `Person*`, а в `Person` функция `print` открыта, поэтому вызов допустим и попадает в `Employee::print`. спецификатор доступа в переопределении на проверку по статическому типу не влияет: доступ в производном классе может быть уже или шире, чем в базовом.
