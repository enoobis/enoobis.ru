если программа печатает на консоль кириллицу, вместо букв могут появиться другие знаки. чаще всего так происходит в windows. узкий поток `std::cout` пишет байты в той кодировке, в которой они лежат в исходном файле, а консоль интерпретирует эти байты по своей кодовой странице. когда кодировки не совпадают, на экране оказывается другая последовательность символов. кодировку вывода тогда задают явно, устанавливая текущую локаль. в c++ для этого есть функция **setlocale()**. её объявление находится в заголовке `<clocale>`.

код из предыдущих лекций меняется так:

```cpp
#include <iostream>
 
int main()
{
    std::cout << "Привет мир!" << std::endl;
}
```

компиляция и запуск в windows могут выглядеть так:

```bash
c:\cpp>g++ -std=c++20 -Wall -pedantic app.cpp -o app & app
Р?С?РёР?РчС' Р?РёС?!

c:\cpp>
```

вместо текста "Привет мир!" на консоли появляются посторонние знаки: байты строки, набранной в utf-8, прочитаны в другой кодовой странице.

тот же пример переписывается с вызовом **setlocale()**:

```cpp
#include <iostream>
 
int main()
{
	setlocale(LC_ALL, "");
    std::wcout << L"Привет мир!" << std::endl;
}
```

для вывода здесь используется не `std::cout`, а объект **std::wcout**. это широкий поток: он работает с единицами типа `wchar_t`, а не с байтами `char`. предполагается, что сам файл сохранён в utf-8. перед строковым литералом стоит префикс **L**, он задаёт широкий литерал. вызов `setlocale(LC_ALL, "")` переключает все категории локали на локаль окружения. пустая строка во втором аргументе означает локаль, выбранную системой, а не локаль "C", которая действует по умолчанию и не описывает национальные наборы символов. `LC_ALL` охватывает и категорию символьной классификации, и категорию формата чисел.

повторные компиляция и запуск дают уже ожидаемый текст:

```bash
c:\cpp>g++ -std=c++20 -Wall -pedantic app.cpp -o app & app
Привет мир!

c:\cpp>
```

на части платформ, например в ubuntu, расхождения кодировок нет: и исходный файл, и локаль терминала обычно используют utf-8, и те же байты отображаются как кириллица. вызов `setlocale` тогда не меняет видимый результат.

манипулятор `std::endl` записывает перевод строки и сбрасывает буфер потока. для одного короткого сообщения это совпадает с эффектом символа `\n` с последующим принудительным выводом.
