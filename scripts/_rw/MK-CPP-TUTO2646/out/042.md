язык c++ позволяет определить несколько функций с одним именем и разными наборами параметров. эта возможность называется **перегрузкой функций** (**function overloading**). при компиляции по аргументам вызова выбирается одна из версий. выбор делает разрешение перегрузки (overload resolution): строится множество кандидатов с этим именем, из них оставляются жизнеспособные, и среди жизнеспособных выбирается лучшее соответствие. происходит это целиком во время компиляции, отдельной таблицы выбора во время выполнения нет.

чтобы несколько версий с одним именем сосуществовали, они должны различаться хотя бы одним из признаков:

- имеют разное количество параметров

- соответствующие параметры имеют разный тип

версии могут различаться и возвращаемым типом. при выборе версии компилятор на возвращаемый тип не смотрит: в тип функции для перегрузки входят имя и список параметров. две функции, которые отличаются только возвращаемым типом, перегрузкой не являются и не могут быть объявлены вместе.

простейший пример:

```cpp


#include <iostream>



int sum(int, int);

double sum(double, double);



int main()

{

    int result1 {sum(3, 6)}; // выбирается версия int sum(int, int)

    std::cout << result1 << std::endl; // 9



    

    double result2 {sum(3.3, 6.6)}; // выбирается версия double sum(double, double)

    std::cout << result2 << std::endl; // 9.9

}

int sum(int a, int b)

{

    return a + b;

}

double sum(double a, double b)

{

    return a + b;

}
```

здесь две версии `sum`, обе складывают два числа. одна складывает значения типа `int`, другая значения типа `double`. по переданным аргументам компилятор определяет, какую версию вызвать. при первом вызове передаются числа `int`:

```cpp
int result1 {sum(3, 6)};
```

для этого вызова выбирается версия

```cpp
int sum(int, int);
```

во втором вызове передаются числа с плавающей точкой:

```cpp
double result2 {sum(3.3, 6.6)};
```

поэтому выбирается версия, которая принимает `double`:

```cpp
double sum(double, double);
```

соответствие здесь точное: тип аргумента совпадает с типом параметра, и преобразование не требуется. если бы точного совпадения не было, рассматривались бы стандартные преобразования, но при наличии точной версии она предпочтительнее.

перегруженные версии могут различаться и числом параметров. имя то же, а арность разная, поэтому вызов с двумя аргументами и вызов с тремя аргументами однозначны:

```cpp


#include <iostream>



int sum(int, int);

int sum(int, int, int);



int main()

{

    int result1 {sum(3, 6)}; // выбирается версия int sum(int, int)

    std::cout << result1 << std::endl; // 9



    

    int result2 {sum(3, 6, 2) }; // выбирается версия int sum(int, int, int)

    std::cout << result2 << std::endl; // 11

}

int sum(int a, int b)

{

    return a + b;

}

int sum(int a, int b, int c)

{

    return a + b + c;

}
```

### перегрузка функций с параметрами-ссылками

при перегрузке с параметрами-ссылками учитывают, что пара `data_type` и `data_type&` не даёт практически различимых версий. типы функций формально различны: параметр по значению и параметр по неконстантной ссылке суть разные типы. для обычного аргумента-переменной, то есть модифицируемого lvalue, оба кандидата оказываются точным соответствием, и вызов неоднозначен. два следующих прототипа поэтому не образуют пригодный набор версий `print`:

```cpp


void print(int);

void print(int&);
```

они не работают как разные версии `print` для типичного вызова с переменной типа `int`. литерал или иное rvalue сделало бы жизнеспособной только версию по значению, потому что неконстантная ссылка с rvalue не связывается, но перегрузка, которая распадается на большинстве вызовов, не используется.

### перегрузка и параметры-константы

константный параметр отличается от неконстантного при перегрузке только для ссылок и указателей. в остальных случаях константный параметр тождественен неконстантному. константность верхнего уровня в тип функции не входит и при сравнении объявлений отбрасывается. два следующих прототипа при перегрузке различаться не будут:

```cpp


void print(int);

void print(const int);
```

во втором прототипе компилятор игнорирует **const**. оба объявления задают одну функцию `void print(int)`. определить их как две версии нельзя: это повторное объявление одного и того же типа.

пример перегрузки, где константность входит в тип, потому что квалифицируется указуемый объект:

```cpp


#include <iostream>



int square(const int*);

int square(int*);



int main()

{

    const int n1{2};

    int n2{3};

    int square_n1 {square(&n1)};

    int square_n2 {square(&n2)};

    std::cout << "square(n1): " << square_n1 << "\tn1: " << n1 << std::endl;

    std::cout << "square(n2): " << square_n2 << "\tn2: " << n2 << std::endl;

}



int square(const int* num)

{

    return *num * *num ;

}

int square(int* num)

{

    *num = *num * *num; // изменяем значение по адресу в указателе

    return *num;

}
```

функция `square` принимает указатель на число и возводит число в квадрат. в первой версии параметр есть указатель на константу, во второй обычный указатель. это разные типы, `const int*` и `int*`, и обе версии могут сосуществовать.

в первом вызове

```cpp
int square_n1 {square(&n1)};
```

компилятор выбирает версию

```cpp
int square(const int*);
```

передаваемое число `n1` есть константа, и адрес константы приводится к `const int*`. версия с `int*` для этого аргумента нежизнеспособна: она позволила бы изменить константу. число `n1`, переданное в выбранную функцию, не изменяется. функция только читает значение и возвращает квадрат.

во втором вызове

```cpp
int square_n2 {square(&n2)};
```

компилятор выбирает версию

```cpp
int square(int*);
```

в ней для демонстрации меняется и переданное значение: запись идёт по адресу, хранящемуся в указателе. число `n2` после вызова уже другое. если бы обе версии были жизнеспособны, предпочтение получила бы версия без добавления `const`, как более точное соответствие. для неконстантного `n2` точной является `int*`, а переход к `const int*` добавляет квалификатор. консольный вывод программы:

```bash


square(n1): 4   n1: 2

square(n2): 9   n2: 9
```

с передачей константной ссылки правила те же. `const int&` и `int&` суть разные типы параметров и образуют перегрузку. константный аргумент связывается со ссылкой на константу. неконстантный lvalue предпочитает неконстантную ссылку, потому что связывание без добавления `const` точнее.
