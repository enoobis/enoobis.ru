когда состояние одного или нескольких объектов меняется в несколько шагов и ошибка возможна на любом шаге, для операции с предсказуемым поведением при исключениях применяется идиома копирования и замены, copy-and-swap idiom. порядок фиксирован:

- создаётся копия объекта или нескольких объектов
- изменяется копия, исходные объекты при этом остаются прежними
- если все изменения копии завершились успешно, исходный объект заменяется изменённой копией. если при изменении копии на каком-то шаге возникла ошибка, замена не выполняется

обычно идиома оформляется функцией. частный и распространённый случай такой функции: оператор присваивания. в общем случае он выглядит так:

```cpp


// оператор присвоения некоторого класса Copyable

Copyable& operator=(const Copyable& obj) {

    Copyable copy{obj};	// создаем копию через конструктор копирования

    swap(copy);			// обмениваем значения копии и оригинального объекта

    return *this;

}

// некоторая функция для обмена значениями

void swap(Copyable& copy) noexcept;
```

сначала строится временная копия присваиваемого объекта. конструктор копирования либо доводит копию до конца, либо выбрасывает исключение, пока целевой объект ещё не затронут. после успешного копирования текущий объект `*this` и копия обмениваются содержимым через `swap()`.

`swap` может быть свободной функцией или функцией-членом. во фрагменте выше это функция-член. спецификатор `noexcept` задаёт договор: обмен не выпускает исключение наружу. если исключение всё же покинет функцию, объявленную `noexcept`, реализация вызывает `std::terminate`. поэтому единственное место, где исключение может штатно прервать оператор, это конструктор копирования. если копирование не удалось, управление до `swap` не доходит, и целевой объект сохраняет прежнее состояние. для целевого объекта это сильная гарантия безопасности исключений: операция либо завершается целиком, либо оставляет наблюдаемое состояние таким, каким оно было до вызова.

в самом операторе присваивания нет точки, где исключение привело бы к утечке памяти. приведённая реализация корректна и при присваивании объекта самому себе, `a = a`: сначала строится отдельная копия, затем она обменивается с оригиналом, а временный объект уничтожается уже с прежним ресурсом. плата за это в том, что временная копия создаётся и при самоприсваивании. текст лекции предлагает снять эти издержки дополнительной проверкой:

```cpp


// оператор присвоения некоторого класса Copyable

Copyable& operator=(const Copyable& obj) {

    Copyable copy{obj};		// создаем копию через конструктор копирования

	if(this != &obj)		// если не текущий объект

        swap(copy);			// обмениваем значения копии и оригинального объекта

    return *this;

}

// некоторая функция для обмена значениями

void swap(Copyable& copy) noexcept;
```

сравнение `this != &obj` отсекает обмен, когда аргумент и целевой объект суть один и тот же объект. во фрагменте объект `copy` создаётся до проверки, поэтому затраты на конструктор копирования при самоприсваивании остаются: пропускается только `swap`. чтобы не копировать при самоприсваивании, сравнение адресов ставят до создания временного объекта и в этой ветке просто возвращают `*this`.

ниже та же схема на шаблоне массива. сначала видна поломка, которую идиома закрывает. класс устроен так:

```cpp


template <typename T>

class Array

{

public:

    Array(unsigned size) : data{ new T[size] }, size{size} {}  // выделяем память

    ~Array() { delete[] data;}          // освобождаем память 



    // оператор присвоения

    Array<T>& operator=(const Array& array)

    {

        if (&array != this)

        {

            delete[] data;      // освобождаем память

            size = array.size;

            data = new T[size];          // выделяем память - может столкнуться с std::bad_alloc

            // копируем значения

            for (unsigned i{}; i < size; ++i)

                data[i] = array.data[i];  // можем столкнуться с исключением в зависимости от типа T

        }

        return *this;

    }

    // оператор индексирования для доступа к элементам

    T& operator[](unsigned index) { return data[index]; }

    unsigned getSize() const {return size;}

private:

    T* data;         // хранимые данные

    unsigned size;  // размер массива

};
```

шаблон класса `Array` получает в конструкторе размер и выделяет динамический массив элементов типа `T`. деструктор эту память освобождает. владение буфером лежит на объекте: конструктор захватывает ресурс, деструктор его отдаёт.

```cpp


Array(unsigned size) : data{ new T[size] }, size{size} {}  // выделяем память

~Array() { delete[] data;}          // освобождаем память
```

оператор присваивания должен привести текущий объект к состоянию объекта-параметра. в наивной записи ранее выделенная память освобождается, затем выделяется новый буфер нужного размера. кажется, что порядок согласован, раз старая память уже удалена. узкое место в самом выделении:

```cpp
data = new T[size];
```

оператор `new[]` при неудаче выделения выбрасывает `std::bad_alloc`. так бывает, когда запрошенный массив не помещается в доступную память. к моменту исключения `delete[] data` уже выполнен, а присваивание `data = ...` не выполнено: указатель `data` по-прежнему хранит адрес освобождённого буфера. это висячий указатель. поле `size` к тому же уже перезаписано размером источника. даже если `std::bad_alloc` перехвачен снаружи, объект `Array` остаётся непригодным: инвариант «`data` указывает на живой массив длины `size`» нарушен. вызов деструктора выполнит `delete[]` по освобождённой памяти, что является неопределённым поведением.

дальше цикл копирует элементы:

```cpp
data[i] = array.data[i];
```

элементу типа `T` присваивается значение типа `T`. параметр шаблона может быть любым типом с оператором присваивания, и этот оператор вправе выбросить исключение по своей логике. если исключение возникнет на середине цикла, часть элементов уже перезаписана, прежний буфер уничтожен вызовом `delete[]`, и откатить присваивание нельзя. деструктор корректен, если новое выделение успело завершиться: тогда `data` адресует новый буфер, и `delete[]` освободит именно его. наблюдаемое состояние при этом уже не совпадает ни с прежним, ни с присваиваемым. наивная запись не даёт сильной гарантии, а при `std::bad_alloc` ломает инвариант. проверка `&array != this` в этом варианте нужна и по другой причине: без неё самоприсваивание освободило бы буфер и тут же стало бы читать элементы из освобождённой памяти.

та же операция через копирование и замену:

```cpp


#include <iostream>

 

template <typename T>

class Array

{

public:

    Array(unsigned size) : data{ new T[size] }, size{size} {}  // выделяем память

    ~Array() { delete[] data;}          // освобождаем память 



    Array(const Array& array) : Array{array.size}

    {

        for (unsigned i {}; i < size; ++i)

            data[i] = array.data[i];

    }

    // оператор присвоения

    Array<T>& operator=(const Array& other)

    {

        Array<T> copy{ other };     // вызываем конструктор копирования

        swap(copy);                 // обмениваем значениями

        return *this;

    }

 

    // оператор индексирования для доступа к элементам

    T& operator[](unsigned index) { return data[index]; }

 

    // функция обмена значениями

    void swap(Array& other) noexcept

    {

        std::swap(data, other.data);    // обмениваем два указателя

        std::swap(size, other.size);    // обмениваем размеры

    }

    unsigned getSize() const {return size;}

private:

    T* data;         // хранимые данные

    unsigned size;  // размер массива

};



int main()

{   

    const unsigned count {5};   // количество элементов

    Array<int> values{count};     // создаем объект

 

    // присваиваем элементам values некоторые значения

    for (unsigned i {}; i < count; ++i)

    {

        values[i] = i;

    }

    Array<int> numbers{0};

    numbers = values;     // применение оператора присвоения

    // выводим элементы из объекта numbers на консоль

    for (unsigned i {}; i < numbers.getSize(); ++i)

    {

        std::cout << numbers[i] << "\t";

    }

    std::cout << std::endl;

}
```

добавлен конструктор копирования. чтобы не повторять логику выделения памяти, он делегирует обычному конструктору `Array(unsigned)`, а в теле копирует значения в уже выделенный буфер текущего объекта.

```cpp


Array(const Array& array) : Array{array.size}

{

    for (unsigned i {}; i < size; ++i)

        data[i] = array.data[i];

}
```

делегирующий конструктор, средство c++11, сначала полностью строит объект через `Array{array.size}`: отрабатывает `new T[size]`, поля `data` и `size` инициализированы. затем тело копирует элементы. если присваивание элемента выбросит исключение, объект к этому моменту уже сконструирован делегированием, поэтому отработает деструктор и выполнит `delete[]`. целевой объект оператора присваивания в этом построении не участвует и остаётся прежним. в результате получается отдельная копия источника.

для обмена значениями реализована `swap`:

```cpp


void swap(Array& other) noexcept

{

    std::swap(data, other.data);    // обмениваем два указателя

    std::swap(size, other.size);    // обмениваем размеры

}
```

обмен полей делает стандартная `std::swap`. она меняет местами два объекта одного типа. с c++11 типовая реализация переносит значения перемещением: временная переменная забирает первый аргумент, затем аргументы перемещаются навстречу друг другу. для указателя и для `unsigned` такой перенос не выделяет память и не вызывает операторы типа `T`, поэтому он согласован со спецификацией `noexcept` у `Array::swap`. в функции по отдельности обмениваются указатель `data` и размер `size`. элементы динамического массива при этом не присваиваются по одному: вместе с указателем к другому объекту переходит владение всем буфером.

в операторе присваивания используются конструктор копирования и `swap`:

```cpp


Array<T>& operator=(const Array& other)

{

    Array<T> copy{ other };     // вызываем конструктор копирования

    swap(copy);                 // обмениваем значениями

    return *this;

}
```

временный `copy` владеет новым буфером. `swap` за постоянное время отдаёт этот буфер объекту `*this` и забирает старый буфер во временный объект. возврат ссылки на `*this` оставляет оператору обычную сигнатуру присваивания, при которой вызовы можно записывать цепочкой. при выходе из оператора деструктор `copy` освобождает прежнюю память целевого объекта. если конструктор копирования выбросил исключение, `swap` не вызывается, `*this` не меняется, и утечки нет: память, успевшая выделиться внутри копии, освобождает деструктор этой копии.

в функции `main` один объект `Array` присваивается другому:

```cpp


Array<int> numbers{0};

numbers = values;     // применение оператора присвоения
```

консольный вывод:

```bash
0       1       2       3       4
```

часто этот приём стоит именно в операторе присваивания, но та же схема годится для любой модификации объекта, которой нужна устойчивость к исключениям. принцип один: сначала копируется объект, который предстоит изменить, затем изменения выполняются над копией, и только после их успеха целевой объект обменивается с копией.
