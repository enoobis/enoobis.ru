производный класс может иметь несколько прямых базовых классов. подобный тип наследования называется множественным наследованием, в отличие от одиночного наследования, при котором используется один базовый класс. поскольку множественное наследование усложняет иерархию, оно используется гораздо реже, чем одиночное. объект производного класса содержит отдельный подобъект каждого прямого базового класса, и порядок этих подобъектов задаётся порядком баз в списке базовых спецификаторов.

простейший пример:

```cpp


#include <iostream>



class Camera    // класс фотокамеры

{

public:

    void makePhoto()

    {

        std::cout << "making photo" << std::endl;

    }

};



class Phone    // класс телефона

{

public:

    void makeCall()

    {

        std::cout << "making call" << std::endl;

    }

};

// класс смартфона

class Smartphone : public Phone, public Camera   

{ };



int main()

{

    Smartphone iphone;

    iphone.makePhoto();     // making photo

    iphone.makeCall();      // making call

}
```

класс `Camera` представляет фотокамеру и для съёмки фото предоставляет функцию `makePhoto`. класс `Phone` представляет телефон и для звонков предоставляет функцию `makeCall`. оба эти класса наследуются классом `Smartphone`, который представляет смартфон и может и делать фото, и выполнять звонки.

при установке наследования для каждого базового класса указывается спецификатор доступа:

```cpp
class Smartphone : public Phone, public Camera
```

через объект `Smartphone` вызываются функции обоих базовых классов:

```cpp


Smartphone iphone;

iphone.makePhoto();     // making photo

iphone.makeCall();      // making call
```

### конструкторы и деструкторы

при множественном наследовании также необходимо вызывать конструкторы базовых классов, если они имеют параметры. пусть есть класс книги `Book`, класс компьютерного файла `File` и класс электронной книги `Ebook`, который наследуется от этих классов:

```cpp


#include <iostream>

#include <string>



class Book    // класс книги

{

public:

    Book(unsigned pages): pages(pages)

    {

        std::cout << "Book created" << std::endl;

    }

    ~Book()

    {

        std::cout << "Book deleted" << std::endl;

    }

    void printPageCount()

    {

        std::cout << pages << " pages" << std::endl;

    }

private:

    unsigned pages; // количество страниц

};



class File    // класс электронного файла

{

public:

    File(double size): size(size)

    {

        std::cout << "File created" << std::endl;

    }

    ~File()

    {

        std::cout << "File deleted" << std::endl;

    }

    void printSize()

    {

        std::cout << size << "Mb" << std::endl;

    }

private:

    double size;  // размер файла

};

// класс электронной книги

class Ebook : public Book, public File   

{

public:

    Ebook(std::string title, unsigned pages, double size): 

        Book{pages}, File{size}, title{title}

    {

        std::cout << "Ebook created" << std::endl;

    }

    ~Ebook()

    {

        std::cout << "Ebook deleted" << std::endl;

    }

    void printTitle()

    {

        std::cout << "Title: " << title << std::endl;

    }

private:

    std::string title;	// название книги

};



int main()

{

    Ebook cppbook {"About C++", 320, 5.6};

    cppbook.printTitle();

    cppbook.printPageCount();

    cppbook.printSize();

}
```

оба базовых класса имеют конструкторы с одним параметром. в конструкторе `Ebook` эти конструкторы вызываются:

```cpp


class Ebook : public Book, public File   

{

public:

    Ebook(std::string title, unsigned pages, double size): 

        Book{pages}, File{size}, title{title}
```

порядок вызова конструкторов задаёт порядок базовых классов в определении класса. от порядка записей в списке инициализации он не зависит. в определении класса `Ebook` первым базовым классом указан класс `Book`, поэтому сначала выполняется конструктор класса `Book` и только потом конструктор класса `File`. если список инициализации перечислит базы в другом порядке, инициализация всё равно пойдёт в порядке объявления баз. члены самого производного класса, здесь поле `title`, инициализируются после базовых подобъектов.

для каждого класса также определён деструктор. очередность вызова конструкторов и деструкторов видна, если в функции `main` создать один объект `Ebook` и вызвать у него все функции базовых классов:

```cpp


int main()

{

    Ebook cppbook {"About C++", 320, 5.6};

    cppbook.printTitle();

    cppbook.printPageCount();

    cppbook.printSize();

}
```

консольный вывод следующий:

```bash


Book created

File created

Ebook created

Title: About C++

320 pages

5.6Mb

Ebook deleted

File deleted

Book deleted
```

первым вызывается конструктор класса `Book`, который указан первым среди базовых классов. деструкторы вызываются в обратном порядке: сначала отрабатывает деструктор самого производного класса, затем деструкторы баз от последней к первой. деструктор `Book` выполнится последним.

### двойственность при одинаковых названиях

в примере выше все классы имели функции с разными именами. следующий случай устроен иначе:

```cpp


#include <iostream>

#include <string>



class Book    // класс книги

{

public:

    Book(unsigned pages): pages(pages) { }

    void print()

    {

        std::cout << pages << " pages" << std::endl;

    }

private:

    unsigned pages; // количество страниц

};



class File    // класс электронного файла

{

public:

    File(double size): size(size) { }

    void print()

    {

        std::cout << size << "Mb" << std::endl;

    }

private:

    double size;  // размер файла

};

// класс электронной книги

class Ebook : public Book, public File   

{

public:

    Ebook(std::string title, unsigned pages, double size): 

        Book{pages}, File{size}, title{title}

    { }

    void printTitle()

    {

        std::cout << "Title: " << title << std::endl;

    }

private:

    std::string title;

};



int main()

{

    Ebook cppbook {"About C++", 320, 5.6};

    cppbook.print();    // Ошибка компиляции

}
```

базовые классы `Book` и `File` имеют функцию с одним и тем же именем `print()`. получается неоднозначность, и такой код не скомпилируется. неквалифицированный поиск имени `print` находит два объявления в разных базовых подобъектах, и одно из них автоматически не выбирается.

чтобы выбрать реализацию, указывается, из какого конкретного класса нужно вызвать функцию `print`:

```cpp


int main()

{

    Ebook cppbook {"About C++", 320, 5.6};

    cppbook.Book::print();    // 320 pages

    cppbook.File::print();    // 5.6Mb

}
```

в качестве альтернативы выполняется преобразование к нужному типу, и затем вызывается функция:

```cpp


int main()

{

    Ebook cppbook {"About C++", 320, 5.6};

    static_cast<Book&>(cppbook).print();    // 320 pages

    static_cast<File&>(cppbook).print();    // 5.6Mb

}
```

`static_cast<Book&>` привязывает ссылку к подобъекту `Book` внутри объекта `Ebook`. статический тип ссылки есть `Book`, поэтому вызывается `Book::print`. `static_cast<File&>` аналогично выбирает подобъект `File`. при публичном наследовании преобразование к прямой базе корректно по типам и на этапе выполнения не проверяется.

### двойственное наследование и виртуальные базовые классы

ещё одна форма неоднозначности при наследовании возникает, когда класс наследуется от нескольких классов, которые косвенно или напрямую наследуются от одного и того же класса. например:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name} 

    { 

        std::cout << "Person created" << std::endl;

    }

    ~Person() 

    { 

        std::cout << "Person deleted" << std::endl;

    }

    void print() const

    {

        std::cout << "Person " << name << std::endl;

    }

private:

    std::string name;

};



class Student: public Person

{

public:

    Student(std::string name): Person{name} {}

};

class Employee: public Person

{

public:

    Employee(std::string name): Person{name} {}

};

// работающий студент

class StudentEmployee: public Student, public Employee

{

public:

    StudentEmployee(std::string name): Student{name}, Employee{name} {}

};



int main()

{

    StudentEmployee bob{"Bob"};

    //bob.print();

}
```

в основе иерархии классов находится класс человека `Person`, от которого наследуются класс работника `Employee` и класс студента `Student`. работающий студент описывается классом `StudentEmployee`, который наследуется от `Student` и `Employee`. подобных ситуаций лучше избегать, но они тоже могут встречаться. при запуске программы для одного объекта `StudentEmployee` два раза вызывается конструктор и деструктор класса `Person`:

```bash


Person created

Person created

Person deleted

Person deleted
```

вызов `bob.print()` не компилируется. в объекте два различных подобъекта `Person`, и неквалифицированное имя `print` неоднозначно.

для решения этой проблемы в c++ применяются виртуальные базовые классы: при установке наследования перед именем базового класса указывается ключевое слово `virtual`. пример с виртуальными базовыми классами:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name} 

    { 

        std::cout << "Person created" << std::endl;

    }

    ~Person() 

    { 

        std::cout << "Person deleted" << std::endl;

    }

    void print() const

    {

        std::cout << "Person " << name << std::endl;

    }

private:

    std::string name;

};



class Student: public virtual Person

{

public:

    Student(std::string name): Person{name} {}

};

class Employee: public virtual Person

{

public:

    Employee(std::string name): Person{name} {}

};

// работающий студент

class StudentEmployee: public Student, public Employee

{

public:

    StudentEmployee(std::string name): Person{name}, Student{name}, Employee{name}  {}

};



int main()

{

    StudentEmployee bob{"Bob"};

    bob.print();

}
```

при определении классов `Student` и `Employee` базовый класс `Person` указан как виртуальный:

```cpp


class Student: public virtual Person

class Employee: public virtual Person
```

виртуальное наследование оставляет в конечном объекте один общий подобъект виртуальной базы. отдельная копия на каждую ветвь иерархии не создаётся. инициализировать этот подобъект обязан самый производный класс, поэтому конструктор `StudentEmployee` явно вызывает `Person{name}`. вызовы `Person{name}` в конструкторах `Student` и `Employee` при создании `StudentEmployee` не выполняются: эти классы не являются самым производным, и их инициализаторы виртуальной базы игнорируются. если же завершённым объектом создаётся сам `Student` или сам `Employee`, инициализацию `Person` выполняет уже его конструктор.

для объекта `StudentEmployee` вызывается функция `print`:

```cpp


int main()

{

    StudentEmployee bob{"Bob"};

    bob.print();

}
```

консольный вывод следующий:

```bash


Person created

Person Bob

Person deleted
```

конструктор и деструктор класса `Person` вызываются только один раз. виртуальное наследование требует дополнительной косвенности: в типичной реализации объект хранит сведения о смещении общего подобъекта, и обращение к членам виртуальной базы дороже, чем при обычном наследовании.
