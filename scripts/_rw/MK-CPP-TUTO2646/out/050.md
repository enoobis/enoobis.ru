внешние файлы содержат не только функции, но и объекты: переменные и константы. чтобы имя объекта, определённого в другой единице трансляции, было видно в текущем файле, объявление помечают ключевым словом `extern`. такое объявление не определяет объект и не выделяет для него память. оно обещает, что определение есть ровно в одной единице трансляции, а компоновщик подставит адрес.

файл `objects.cpp` определяет объекты:

```cpp


#include <string>



std::string message {"Hello"};

unsigned times {3};
```

здесь определены переменные типа `std::string` и `unsigned int`. для имени `std::string` нужно подключить заголовочный файл `<string>`. в `objects.cpp` это уже сделано директивой `#include <string>`. определение на уровне пространства имён есть определение с внешним связыванием: имя `message` и имя `times` видны другим единицам трансляции.

главный файл `app.cpp` эти переменные использует:

```cpp


#include <iostream>

#include <string>



extern std::string message;

extern unsigned times;



int main()

{

    for(unsigned i{}; i < times; i++)

    {

        std::cout << message << std::endl;

    }

}
```

чтобы использовать переменные из внешнего файла, их объявляют с `extern`:

```cpp


extern std::string message;

extern unsigned times;
```

в `main` цикл выполняется `times` раз и каждый раз печатает строку `message`. компиляция через g++ снова передаёт все файлы с определениями через пробел:

```bash


g++ app.cpp objects.cpp -o app
```

подразумевается, что `app.cpp` и `objects.cpp` лежат в одной папке. то же верно для компиляции через clang:

```bash


clang++ app.cpp objects.cpp -o app.exe
```

на выходе получается один файл `app`. консольный вывод:

```bash


Hello

Hello

Hello
```

### подключение констант

у констант есть особенность: `extern` пишут и при определении константы. файл `objects.cpp` меняется так:

```cpp


#include <string>



extern const std::string message {"Hello"};	// константа

unsigned times {3};
```

файл `app.cpp`:

```cpp


#include <iostream>

#include <string>



extern const std::string message;   // подключаем константу

extern unsigned times;



int main()

{

    for(unsigned i{}; i < times; i++)

    {

        std::cout << message << std::endl;

    }

}
```

результат тот же, что и в предыдущей программе.

причина в связывании. неконстантный объект в области пространства имён по умолчанию имеет внешнее связывание, поэтому одного `extern` в месте использования достаточно, а определение пишется без `extern`. объект `const` в области пространства имён по умолчанию имеет внутреннее связывание: каждое определение видно только своей единице трансляции, и компоновщик не объединяет такие имена. `extern const` задаёт внешнее связывание и у определения, и у объявления, после чего константа становится одной на всю программу. без `extern` на определении символ из `objects.cpp` был бы локален для этого файла, а `extern` в `app.cpp` не нашёл бы его при компоновке.

### вынесение объявления в заголовочные файлы

в примере выше главный файл сам объявляет два внешних объекта. при большом числе переменных и констант эти объявления загромождают файл. как и для функций, объявления внешних объектов выносят в заголовок. в той же папке, где лежат `app.cpp` и `objects.cpp`, создаётся файл `objects.h`:

```cpp


extern const std::string message;   // подключаем константу

extern unsigned times;
```

заголовок подключают в `app.cpp`:

```cpp


#include <iostream>

#include "objects.h"		// подключаем внешние объекты



int main()

{

    for(unsigned i{}; i < times; i++)

    {

        std::cout << message << std::endl;

    }

}
```

директива `#include "objects.h"` текстуально вставляет оба объявления `extern`. повтор таких объявлений в разных единицах трансляции правилу одного определения не противоречит: это объявления, а не определения. определение `message` и `times` по-прежнему одно и находится в `objects.cpp`. имя `std::string` в заголовке должно быть к этому месту объявлено. в показанном `app.cpp` до включения `objects.h` подключён только `<iostream>`, а `<string>` в этот файл не входит. переносимый заголовок сам подключает `<string>`, чтобы объявление `std::string` не зависело от того, какие заголовки единица трансляции успела включить раньше.
