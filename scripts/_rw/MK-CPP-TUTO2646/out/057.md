класс определяет состояние и операции над ним. открывать каждый член для произвольного кода снаружи не всегда согласуется с инвариантом типа: внешний код способен записать значение, которое класс не считает допустимым. доступ к членам разграничивают **спецификаторы доступа**. ограничение проверяется при компиляции. обращение, которое спецификатор запрещает, делает программу некорректной, и транслятор её отклоняет. в представлении объекта закрытый член занимает память наравне с открытым. спецификатор действует на имена в программе, байты объекта во время выполнения остаются на своих местах, а проверку предметного инварианта класс выполняет сам.

```cpp


#include <iostream>

#include <string>



class Person 

{

public:

    std::string name;

    unsigned age;

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        age = p_age;

    }

};

int main()

{

    Person tom{"Tom", 38};

    // поля name, age и функция print общедоступные

    tom.name = "Tomas"; 

    tom.age = 22;

    tom.print();    // Name: Tomas   Age: 22

}
```

поля `name` и `age` и функция `print` стоят в секции **public**, поэтому входят в открытый интерфейс `Person` и доступны всюду, где виден объект. плата за открытые поля прямая: внешний код присваивает им любые значения, в том числе противоречащие предметным ограничениям.

```cpp


Person tom("Tom", 22);

tom.name = "";

tom.age = 1001;
```

среди таких значений есть и те, которые тип `unsigned` принимает, а предметная область отвергает. полю `age` можно записать нереальный возраст, полю `name` пустую строку. для системы типов присваивание законно, для инварианта класса оно ломает состояние.

скрыть представление позволяет спецификатор **private**. члены, объявленные после него, инкапсулированы в классе и в интерфейс для внешнего кода не входят. тот же `Person` со скрытыми полями:

```cpp


#include <iostream>

#include <string>



class Person 

{

private:

    std::string name;

    unsigned age;

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        age = p_age;

    }

};

int main()

{

    Person tom{"Tom", 38};

    // функция print общедоступная

    tom.print();    // Name: Tom   Age: 22



    // поля name и age вне класса недоступны

    // tom.name = "";  

    // tom.age = 1001;

}
```

члены от **private** до следующего **public** закрыты. вне `Person` имена `name` и `age` недоступны, и выражение вида `tom.name` не компилируется. читать и изменять их могут члены класса, а также функции, которым класс явно открыл доступ. функция `print` и конструктор остаются в секции **public**, поэтому вызов допустим в любом месте программы, где виден объект.

закрытые поля сами по себе аргументы не проверяют. некорректное значение по-прежнему можно передать в конструктор: спецификатор ограничивает имена, диапазон данных он не ограничивает. реакцию на нарушение задаёт класс. типичные стратегии: отказаться создавать объект, подставить значение по умолчанию, сообщить об ошибке. в ближайших примерах такая проверка опущена, чтобы отделить её от правил доступа.

если спецификатор у члена не записан, для `class` действует **private**. определение выше равносильно следующему: поля до секции **public** закрыты по умолчанию. у `struct` члены без спецификатора открыты, это различие относится к теме структур.

```cpp


#include <string>



class Person 

{

    std::string name;

    unsigned age;

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        age = p_age;

    }

};
```

### опосредование доступа

прямая запись произвольных значений исключена, но чтение состояния и его контролируемое изменение остаются нужны. возраст увеличивается на год, имя требуется получить отдельно. для этого в интерфейс добавляют функции, и вся работа с закрытыми полями идёт через них.

```cpp


#include <iostream>

#include <string>



class Person 

{

private:

    std::string name;

    unsigned age;

public:

    Person(std::string p_name, unsigned p_age)

    { 

        name = p_name; 

        if (p_age > 0 && p_age < 110) 

            age = p_age;

		else

			age = 18;	// если значение некорректное, устанавливаем значение по умолчанию

    }

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    void setAge(unsigned p_age) 

    {

        if (p_age > 0 && p_age < 110) 

            age = p_age;

    }

    std::string getName()

    {

        return name;

    }

    unsigned getAge()

    {

        return age;

    }

};

int main()

{

    Person tom{"Tom", 38};

    // изменяем возраст

    tom.setAge(22);

    tom.setAge(123);

    tom.print();    // Name: Tom   Age: 22



    //отдельно получаем имя

    std::cout << "Person name: " << tom.getName() << std::endl;

}
```

чтение `name` и `age` снаружи дают `getName` и `getAge`. записать `name` можно только из конструктора. записать `age` можно из конструктора и из `setAge`. `setAge` выполняет присваивание только при условии `p_age > 0 && p_age < 110`, иначе поле не меняется. конструктор на том же диапазоне при нарушении записывает 18. одна граница обслуживается двумя стратегиями: отказом от обновления и подстановкой значения по умолчанию.

состояние снаружи недоступно напрямую. клиентский код видит функции интерфейса, и эти функции удерживают инвариант класса. представление при этом можно позже заменить, оставив вызовы `getName`, `getAge` и `setAge` прежними.
