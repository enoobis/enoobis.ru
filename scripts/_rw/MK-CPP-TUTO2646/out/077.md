c++ позволяет определить функцию оператора преобразования из типа текущего класса в другой тип. целевой тип может быть фундаментальным либо типом класса. в общем случае оператор преобразования имеет такую форму:

```cpp


class MyClass

{

public:	

	operator OtherType() const; // преобразование из типа MyClass в тип OtherType

	..........................

};
```

`OtherType` обозначает тип, в который преобразуется объект. тип возвращаемого значения у функции оператора не указывается: целевой тип уже входит в имя функции, и функция должна вернуть объект `OtherType`.

оператор преобразования, в отличие от большинства операторов, определяется только как функция-член класса. свободной функцией его объявить нельзя. это единственный оператор, у которого перед служебным словом `operator` не записывают тип результата: целевой тип стоит после `operator`. простейший пример:

```cpp


#include <iostream>

 

class Counter

{

public:

    Counter(int number)

    {

        value = number;

    }

    operator int() const { return value; }

private:

    int value;

};



int main()

{

    Counter counter{25};

    int n = counter;    // преобразуем от Counter в int

    std::cout << n << std::endl;             // 25

	// или так

    int m {counter};

    std::cout << m << std::endl;             // 25

}
```

в классе `Counter` определён оператор преобразования в тип `int`:

```cpp
operator int() const { return value; }
```

функция возвращает значение поля `value`.

после этого переменной или параметру типа `int` можно присвоить значение типа `Counter`. такое значение автоматически преобразуется в `int`.

```cpp


Counter counter{25};

int n = counter;    // преобразуем от Counter в int - n=25
```

оператор преобразования делает эту конвертацию неявной. то же преобразование записывают и явно, например функцией `static_cast`:

```cpp


Counter counter{25};

int n = static_cast<int>(counter);  // явное преобразование из Counter в int

std::cout << n << std::endl;        // 25

// или так

int m {static_cast<int>(counter)};  // явное преобразование из Counter в int

std::cout << m << std::endl;        // 25
```

следующий пример задаёт преобразование в тип `bool`.

```cpp


#include <iostream>



class Counter

{

public:

    Counter(double n)

    {

        value = n;

    }

    void print() const

    {

        std::cout << "value: " << value << std::endl;

    }

    // Оператор преобразования в bool

    operator bool() const  { return value != 0; } 

private:

    int value;

};

// тестируем операторы

void testCounter(const Counter& counter)

{

    counter.print();

    if (counter)

	    std::cout << "Counter is non-zero." << std::endl;

    if (!counter)

	    std::cout << "Counter is zero." << std::endl;

}



int main()

{

    Counter counter1{22};

    testCounter(counter1);



    Counter counter2{0};

    testCounter(counter2);

}
```

в операторе преобразования при `value`, равном 0, возвращается `false`, иначе возвращается `true`:

```cpp
operator bool() const  { return value != 0; }
```

объект `Counter` после этого допустим в контекстах, где ожидается `bool`, в том числе в условиях:

```cpp


if (counter)

if (!counter)
```

оператор `!` для типа `Counter` не объявлен, однако выражение `!counter` корректно. объект `counter` сначала неявно преобразуется в `bool`, и уже к этому значению применяется встроенное логическое отрицание. контекстное преобразование в `bool` входит в стандартные преобразования, поэтому пользовательский `operator bool` подхватывается без отдельной перегрузки `operator!`.

### явные преобразования

неявные преобразования участвуют в разрешении перегрузки и подходят не для всякого интерфейса. их отключают, объявив оператор со служебным словом `explicit`:

```cpp


#include <iostream>

 

class Counter

{

public:

    Counter(int number)

    {

        value = number;

    }

    explicit operator int() const { return value; } // Только явные преобразования

private:

    int value;

};



int main()

{

    Counter counter{25};

    int n = static_cast<int>(counter);  // явное преобразование

    std::cout << n << std::endl;        // 25



    // int m = counter;  // так нельзя, допустимы только явные преобразования

    // std::cout << m << std::endl;

}
```

при `explicit operator int()` копирующая инициализация вида `int m = counter` становится некорректной. остаётся явное приведение, в примере это `static_cast<int>`. спецификатор `explicit` не меняет тело преобразования, он меняет множество контекстов, в которых преобразование разрешено.

### преобразование между классами

тем же способом задаётся преобразование между типами классов:

```cpp


#include <iostream>

#include <string>



class PrintBook;



// электронная книга

class Ebook

{

public:

    Ebook(std::string book_title)

    {

        title=book_title;

    }

    operator PrintBook() const;

    std::string getTitle(){return title;}

private:

    std::string title;

};

// печатная книга

class PrintBook

{

public:

    PrintBook(std::string book_title)

    {

        title=book_title;

    }

    operator Ebook() const;

    std::string getTitle(){return title;}

private:

    std::string title;

};



Ebook::operator PrintBook() const

{

    return PrintBook{title};

}

PrintBook::operator Ebook() const

{

    return Ebook{title};

}



int main()

{

    PrintBook book{"C++"};

    Ebook ebook{ book };    // оцифровываем книгу - из PrintBook в Ebook

    std::cout << ebook.getTitle() << std::endl;        // C++

    PrintBook print_book{ebook}; // распечатываем книгу из Ebook в PrintBook

    std::cout << print_book.getTitle() << std::endl;        // C++

}
```

класс `Ebook` представляет электронную книгу, класс `PrintBook` печатную. операторы преобразования переводят объект одного типа в другой и обратно: книга переводится в электронный вид или в печатный. объявление оператора и его определение разнесены, чтобы один класс не опирался на другой в момент, когда тот ещё не завершён. для объявления `operator PrintBook()` достаточно предварительного объявления `PrintBook`. тело, которое конструирует `PrintBook{title}`, требует полного типа и поэтому помещено после определения обоих классов. взаимные операторы преобразования делают обе стороны неявными источниками друг друга, и при перегрузке функций с параметрами обоих типов это источник неоднозначности. там, где направление преобразования должно быть однозначным, оператор помечают как `explicit`.
