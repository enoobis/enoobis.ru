указатели участвуют в арифметических операциях: сложение, вычитание, инкремент, декремент. операции устроены иначе, чем для чисел, и масштаб шага зависит от типа указателя. к адресу прибавляется не число байт, равное слагаемому, а число байт, равное слагаемому, умноженному на размер адресуемого типа. так `p + 1` указывает на следующий объект того же типа.

к указателю прибавляют целое число и вычитают из указателя целое число. кроме того, из одного указателя вычитают другой указатель того же типа.

сначала инкремент и декремент указателя на объект типа `int`:

```cpp


#include <iostream>

 

int main()

{

    int n{10};

    int *pn {&n};

    std::cout << "address=" << pn << "\tvalue=" << *pn << std::endl;

      

    pn++;

    std::cout << "address=" << pn << "\tvalue=" << *pn << std::endl;

      

    pn--;

    std::cout << "address=" << pn << "\tvalue=" << *pn << std::endl;

}
```

операция инкремента `++` увеличивает числовое значение на единицу. для указателя единица означает размер типа, на который указатель ссылается. указатель имеет тип `int*`, а размер объекта `int` в большинстве архитектур равен 4 байтам. увеличение указателя типа `int*` на единицу увеличивает хранимый адрес на 4. на одном из запусков вывод выглядит так:

```bash


address=0x81315ffd84    value=10

address=0x81315ffd88    value=828374408

address=0x81315ffd84    value=10
```

после инкремента значение указателя выросло на 4: с `0x81315ffd84` до `0x81315ffd88`. после декремента, то есть уменьшения на единицу, указатель снова получил прежний адрес. увеличение на единицу есть переход к следующему объекту того же типа, который лежал бы сразу за текущим. уменьшение на единицу есть переход к предыдущему объекту. после сдвига адреса по новому адресу можно прочитать значение, однако это значение может быть неопределённым, как во второй строке вывода. разыменование указателя, который не адресует существующий объект, есть неопределённое поведение.

для указателя типа `int*` увеличение и уменьшение на единицу меняют адрес на 4. для указателя типа `short*` те же операции меняли бы адрес на 2, для указателя типа `char*` на 1. ниже тот же шаг виден на `double` и `short`:

```cpp


#include <iostream>

 

int main()

{

    double d {10.6};

    double *pd {&d};

    std::cout << "Pointer pd: address:" << pd << std::endl;

    pd++;   // увеличение адреса на 8 байт - размер double

    std::cout << "Pointer pd: address:" << pd << std::endl;

          

    short n {5};

    short *pn {&n};

    std::cout << "Pointer pn: address:" << pn << std::endl;

    pn++;   // увеличение адреса на 2 байта - размер short

    std::cout << "Pointer pn: address:" << pn << std::endl;

}
```

на одном из запусков вывод такой:

```bash


Pointer pd: address:0x2731bffd58

Pointer pd: address:0x2731bffd60



Pointer pn: address:0x2731bffd56

Pointer pn: address:0x2731bffd58
```

увеличение на единицу указателя типа `double*` увеличило хранимый адрес на 8 (размер объекта `double` равен 8 байтам). увеличение на единицу указателя типа `short*` увеличило адрес на 2 (размер типа `short` равен 2 байтам).

тот же масштаб действует, когда прибавляют или вычитают не единицу, а другое целое. прибавление `n` сдвигает адрес на `n * sizeof(тип)`:

```cpp


#include <iostream>

 

int main()

{

    double d {10.6};

    double *pd {&d};

    std::cout << "Pointer pd: address:" << pd << std::endl;

    pd = pd + 2;   // увеличение адреса на 16 байт - 2 объекта double

    std::cout << "Pointer pd: address:" << pd << std::endl;

          

    short n {5};

    short *pn {&n};

    std::cout << "Pointer pn: address:" << pn << std::endl;

    pn = pn - 3;   // уменьшение адреса на 6 байт - размер 3 объектов short

    std::cout << "Pointer pn: address:" << pn << std::endl;

}
```

добавление к указателю типа `double*` числа 2

```cpp
pd = pd + 2;
```

означает переход на два объекта `double` вперёд, то есть изменение адреса на 2 * 8 = 16 байт.

вычитание из указателя типа `short*` числа 3

```cpp
pn = pn - 3;
```

означает переход на три объекта `short` назад, то есть изменение адреса на 3 * 2 = 6 байт.

на одном из запусков вывод такой:

```bash


Pointer pd: address:0xb88d5ffbe8

Pointer pd: address:0xb88d5ffbf8



Pointer pn: address:0xb88d5ffbe6

Pointer pn: address:0xb88d5ffbe0
```

в отличие от сложения, вычитание применяют не только к указателю и целому числу, но и к двум указателям одного типа. результат есть число элементов между адресами, а не число байт:

```cpp


#include <iostream>

 

int main()

{

    int a{10};

    int b{23};

    int *pa {&a};

    int *pb {&b};

    auto ab {pa - pb};

      

    std::cout << "pa: " << pa << std::endl;

    std::cout << "pb: " << pb << std::endl;

    std::cout << "ab: " << ab << std::endl;

}
```

по стандарту разность указателей имеет тип `std::ptrdiff_t`. это знаковый целый тип, зависящий от платформы. на конкретной реализации он совпадает с `int`, `long` или `long long`. какой из них выбран, определяет платформа. на 64-разрядной windows это тип `long long`: в модели данных llp64 тип `long` остаётся 32-битным, а разность адресов должна вмещать расстояние между объектами в 64-битном адресном пространстве. переменная `ab`, которая хранит разность адресов, поэтому объявлена через `auto`. вывод на одном из запусков:

```bash


pa: 0x6258fffab4

pb: 0x6258fffab0

ab: 1
```

результат разности двух указателей есть расстояние между ними в элементах. в показанном запуске адрес из первого указателя на 4 больше, чем адрес из второго (`0x6258fffab0 + 4 = 0x6258fffab4`). размер одного объекта `int` равен 4 байтам, поэтому расстояние равно `(0x6258fffab4 - 0x6258fffab0) / 4 = 1`. стандарт определяет эту разность для указателей на элементы одного массива (или на позицию сразу за его концом). для двух независимых локальных переменных операция формально не определена, а напечатанная единица отражает конкретный запуск, в котором переменные оказались соседними.

### некоторые особенности операций

операции над самим указателем отличают от операций над значением по адресу, на который указатель указывает. скобки и приоритет решают, к чему относится оператор:

```cpp


int a {10};

int *pa {&a};

int b {*pa + 20};	// операция со значением, на который указывает указатель

pa++; 				// операция с самим указателем

	

std::cout << "b: " << b << std::endl;  ;	// 30
```

через разыменование `*pa` получают значение, на которое указывает указатель `pa`, то есть число 10, и выполняют сложение. выражение `*pa` здесь обозначает число, и сложение обычное, между двумя числами. отдельный оператор `pa++` меняет уже адрес в указателе.

у инкремента и декремента есть отдельная тонкость приоритета. унарный оператор `*` и префиксные операторы `++` и `--` имеют одинаковый приоритет, а стоя рядом выполняются справа налево.

префиксный инкремент значения:

```cpp


int a {10};

int *pa {&a};

std::cout << "pa: address=" << pa << "\tvalue=" << *pa << std::endl;

int b {++*pa};      // инкремент значения по адресу указателя

          

std::cout << "b: value=" << b << std::endl;

std::cout << "pa: address=" << pa << "\tvalue=" << *pa << std::endl;
```

в выражении `b {++*pa}` сначала выполняется разыменование: по адресу получается число 10. затем к этому числу прибавляется единица. адрес в указателе не меняется. на одном из запусков результат такой:

```bash


pa: address=0x7ff7b31bd8b8	value=10

b: value=11

pa: address=0x7ff7b31bd8b8	value=11
```

другое расположение тех же операторов:

```cpp
int b{*++pa};      // инкремент адреса указателя с последующим разыменовыванием
```

сначала к указателю прибавляется единица, то есть к адресу добавляется 4, потому что указатель имеет тип `int*`. затем по новому адресу читается значение и присваивается переменной `b`. полученное значение в этом случае может быть неопределённым:

```bash


pa: address=0x7ff7b13d78b8	value=10

b: value=0

pa: address=0x7ff7b13d78bc	value=0
```

постфиксные инкремент и декремент имеют приоритет выше, чем унарное разыменование `*`. программа с постфиксной формой:

```cpp


int a {10};

int *pa {&a};

std::cout << "pa: address=" << pa << "\tvalue=" << *pa << std::endl;

int b{*pa++};      // инкремент адреса указателя с последующим разыменовыванием

          

std::cout << "b: value=" << b << std::endl;

std::cout << "pa: address=" << pa << "\tvalue=" << *pa << std::endl;
```

поскольку постфиксный инкремент приоритетнее, выражение `*pa++` разбирается как `*(pa++)`. сначала адрес указателя `pa` увеличивается на единицу (фактически на 4, тип указателя есть `int*`), затем читается значение по адресу. постфиксный инкремент возвращает прежнее значение, поэтому в переменную `b` попадает значение, которое было по адресу до инкремента. на одном из запусков вывод такой:

```bash


pa: address=0x7ff7b55288b8	value=10

b: value=10

pa: address=0x7ff7b55288bc	value=0
```

скобки меняют порядок:

```cpp
b {(*pa)++};
```

сначала выполняется разыменование и получается значение, затем это значение увеличивается на 1. по адресу в указателе оказывается число 11. инкремент постфиксный, поэтому переменная `b` получает значение, которое было до инкремента, снова число 10. все операции применяются к значению по адресу, который хранит указатель. адрес в самом указателе остаётся прежним, и результат отличается от выражения `*pa++`:

```bash


pa: address=0x7ff7b7b268b8	value=10

b: value=10

pa: address=0x7ff7b7b268b8	value=11
```
