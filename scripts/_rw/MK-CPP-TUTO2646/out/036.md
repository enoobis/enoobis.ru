параметры могут быть константными. значение такого параметра менять нельзя. константный параметр предваряется служебным словом **const**.

```cpp
#include <iostream>
 
void square(int);
 
int main()
{
    int number {4};
    square(number);   // n * n = 16
}
void square(const int n)
{
    //n = n * n;     так нельзя сделать
    std::cout << "n * n = " << n * n << std::endl;  
}
```

в функции `square` параметр `n` константный. внутри `square` его значение изменить нельзя: присваивание параметру было бы ошибкой компиляции. по ограничениям внутри тела он совпадает с константой. сам объект параметра при передаче по значению всё равно отдельный, просто он объявлен неизменяемым.

служебное слово `const` для константного параметра, передаваемого по значению, относится к определению функции и ограничивает тело:

```cpp
void square(const int n) { ...
```

в прототипе для параметров, которые передаются по значению, указывать **const** не обязательно. константность верхнего уровня не входит в тип функции: после отбрасывания такого `const` оба объявления именуют одну и ту же функцию.

```cpp
// можно так
void square(int);
// можно и так
void square(const int);
```

для параметров, которые передаются по ссылке или через указатель, **const** в прототипе обязателен. здесь `const` квалифицирует тип объекта, на который ссылаются, и входит в тип функции. прототип без `const` объявляет другую функцию, и определение с константной ссылкой ему не соответствует.

константный параметр нужен, когда значение должно оставаться равным начальному от входа в функцию до выхода из неё. у неконстантного параметра есть возможность случайно изменить значение в теле, и дальнейший код будет читать уже другое состояние. если менять параметр не предполагается, его объявляют константным: ограничение проверяет компилятор.

константному параметру по значению можно передать и константу, и переменную. в обоих случаях параметр инициализируется копией, а `const` запрещает менять уже эту копию.

от этого отличается передача констант в неконстантные параметры:

```cpp
#include <iostream>

void square(int, int);

int main()
{
	const int a = 4;
	const int b = 5;
	square(a, b);	// 400
	return 0;
}
void square(int a, int b)
{
	a = a * a;
	b = b * b;
	std::cout << "In square: a * b = " << a * b << std::endl;
}
```

хотя в вызов передаются константы, сами параметры константными не являются, и функция меняет их значения. меняются копии внутри `square`. объекты `a` и `b` в `main` остаются константами, и присваивание им было бы невозможно. вывод 400 есть произведение уже изменённых копий, 16 и 25.

### константные ссылки

параметр, передаваемый по ссылке, тоже может быть константным:

```cpp
#include <iostream>
 
void square(const int&);	// функция получает константную ссылку
 
int main()
{
    int number = 5;
    square(number);  // n * n = 25
}
void square(const int &n)
{
    // n = n * n;     так нельзя сделать
    std::cout << "n * n = " << n * n << std::endl;
}
```

значение, доступное через константную ссылку, менять нельзя. ссылка `const int&` допускает чтение объекта и запрещает запись. присваивание `n = n * n` в теле было бы некорректным.

если функция получает аргумент по ссылке и в неё нужно передать константу, параметр должен быть ссылкой на константу. неконстантная ссылка с константным объектом не связывается: иначе через ссылку можно было бы изменить константу.

```cpp
#include <iostream>
 
void square(const int&);
 
int main()
{
    const int number {6};
    square(number);  // n * n = 36
}
void square(const int &n)
{
    std::cout << "n * n = " << n * n << std::endl;
}
```

когда в функцию передаётся большой объект, который функция изменять не должна, параметр оформляют именно как константную ссылку. копирования нет, потому что передаётся ссылка. значение объекта при этом не копируется. изменение исключено, потому что ссылка константная. такой параметр связывается и с переменной, и с константой, и с временным объектом, полученным преобразованием: константная lvalue-ссылка, в отличие от неконстантной, имеет право быть связанной с временным объектом.
