как уже разобрано в статье «введение в строки», для строк в c++ определен тип `std::string` из заголовка `<string>`. ниже собраны основные операции этого типа.

объект `string` хранит последовательность символов типа `char`. последовательность может быть пустой. пустая строка получается конструктором по умолчанию:

```cpp
std::string message;
```

переменной можно присвоить конкретный литерал или инициализировать ее литералом. работают списковая инициализация, копирующая инициализация и прямая инициализация:

```cpp


std::string message {"Hello enoobis.ru!"};

// или так

std::string message2 = "Hello enoobis.ru!";

std::string message3("Hello enoobis.ru!");
```

переменная `message` получает копию литерала `Hello enoobis.ru!`. с c++11 хранение `std::string` непрерывно. `c_str()` и `data()` указывают на эту последовательность, а за последним символом расположен нулевой байт. нулевой байт в `size()` не входит. непрерывный буфер и контроль длины делают работу со строкой безопаснее, чем ручное управление массивом `char`. короткие строки реализации обычно размещают внутри самого объекта, без отдельного блока в куче. стандарт эту оптимизацию не требует.

есть и другие конструкторы. строку из повторяющегося символа задает конструктор `string(count, char)`:

```cpp


std::string message (4, 'd'); // повторяем d 4 раза - message = dddd
```

объект `string` копируется из другого объекта `string`. показаны списковая, прямая и копирующая формы. все три вызывают копирующий конструктор:

```cpp


std::string hello{"hello world"};

std::string message {hello}; // message = "hello world"

// или так

// std::string message (hello);

// std::string message = hello;
```

часть символов берется отдельными конструкторами:

```cpp


std::string message1 {"hello world", 4}; // берем первые 4 символа - message1 = hell

std::string message2 {"hello world", 6, 5}; // 5 символов начиная с 6 символа - message2 = world



std::string hello{"hello world"};

std::string message3 {hello, 4}; 			// message3 = hell

std::string message4 {hello, 6, 5}; 		// message4 = world
```

конструктор `string(const char*, count)` копирует первые `count` символов литерала. `message1` поэтому равен `hell`. конструктор `string(const string&, pos, count)` копирует `count` символов другого объекта, начиная с индекса `pos`. `message4` построен так и равен `world`. форма с одним индексом, `string(const string&, pos)`, берет хвост от `pos` до конца: длина по умолчанию равна `npos`. у `message3` индекс равен 4, хвост строки `hello world` есть `o world`. комментарий в листинге приписывает `message3` значение `hell`. с этой сигнатурой такое значение не получается. префикс литерала дает конструктор от `const char*` и числа, как у `message1`.

инициализация `std::string{"hello world", 6, 5}`, записанная для `message2`, по комментарию должна дать подстроку `world`. отдельного конструктора `string(const char*, pos, count)` в стандарте нет. шаблонный конструктор c++17 от объекта, приводимого к `std::string_view`, с позицией и длиной не рассматривается, если тип приводится к `const char*`, а строковый литерал приводится. рабочая форма той же подстроки показана на `message4`: сначала строка `hello`, затем `string(hello, 6, 5)`.

такую строку печатают потоком вывода:

```cpp


#include <iostream>

#include <string>



int main()

{

    std::string message {"Hello enoobis.ru!"};

    std::cout << "Message: " << message << std::endl;	// Message: Hello enoobis.ru!

}
```

потоки `std::cin` и `std::cout` читают строку и печатают ее:

```cpp


#include <iostream>

#include <string>



int main()

{	

	std::string name;

	std::cout << "Input your name: ";

	std::cin >> name;

	std::cout << "Your name: " << name << std::endl;

}
```

консольный вывод:

```bash


Input your name: Tom

Your name: Tom
```

оператор `>>` для `std::string` читает до первого пробельного символа. имя из двух слов он целиком не забирает. строку до перевода строки, вместе с пробелами, читает свободная функция `std::getline` из `<string>`. перевод строки из потока извлекается и в строку не записывается:

```cpp


#include <iostream>

#include <string>



int main()

{	

	std::string name;

	std::cout << "Input your name: ";

	getline(std::cin, name);

	std::cout << "Your name: " << name << std::endl;

}
```

в показанном вызове `std::getline` принимает поток `std::cin` и строку, в которую записывается результат. есть перегрузка с явным символом-разделителем.

консольный вывод:

```bash


Input your name: Tom Smith

Your name: Tom Smith
```

### размер строки

`length()` и `size()` возвращают число символов. для `std::string` это одна и та же величина. завершающий нулевой байт в нее не входит:

```cpp


#include <iostream>

#include <string>



int main()

{

    std::string message {"Hello"};

    std::cout << "Length: " << message.length() << std::endl;   // Length: 5

    std::cout << "Size: " << message.size() << std::endl;       // Size: 5

}
```

пустая строка содержит 0 символов. `empty()` возвращает `true`, если строка пуста, и `false` в противном случае. условие эквивалентно `size() == 0`:

```cpp


#include <iostream>

#include <string>



int main()

{

    std::string message;

    if(message.empty())

        std::cout << "string is empty " << std::endl;

    else

        std::cout << "string is not empty" << std::endl;

}
```

### объединение строк

конкатенация записывается оператором `+`. хотя бы один операнд должен иметь тип `std::string`. результат есть новый объект `string`, операнды не меняются:

```cpp


#include <iostream>

#include <string>



int main()

{

    std::string hello {"hello"};

    std::string world {"world"};

    std::string message{ hello + " " + world};

    std::cout <<  message  << std::endl;    // hello world

}
```

оба операнда одновременно не могут быть строковыми литералами. у двух указателей `const char*` оператора конкатенации нет, выражение некорректно:

```cpp
std::string message{ "hello " + "world" + "!"};   // ! Ошибка
```

два литерала, стоящие в программе рядом, сливаются еще при трансляции, на фазе объединения соседних строковых литералов. оператор `+` между ними тогда не нужен. далее обычный `std::string` складывается с уже единым литералом:

```cpp


std::string hello {"hello"};

std::string message{ hello + " world" "!"};   // hello world!
```

литерал можно превратить в `std::string` суффиксом пользовательского литерала. для этого импортируют пространство имен `std::string_literals` и ставят суффикс `s`. оператор `operator""s` возвращает объект `std::string`, и складывать такие операнды уже можно:

```cpp


#include <iostream>

#include <string>

using namespace std::string_literals; 



int main()

{

    std::string message{ "hello "s + "world"s + "!"s};

    std::cout <<  message  << std::endl;    // hello enoobis.ru

}
```

литерал с суффиксом `s`, например `"hello "s`, имеет тип `std::string`. значение выражения в программе есть `hello world!`.

### raw-литералы

в обычном литерале часть последовательностей имеет отдельный смысл. `"\t"` задает табуляцию, `"\n"` задает перевод строки. обратная косая черта открывает такую последовательность, поэтому один символ `\` в тексте записывают как `"\\"`. двойная кавычка внутри литерала тоже экранируется: `"\""`.

```cpp


#include <iostream>

#include <string>



int main()

{

    std::string text {"Name: \t\"Tom\"\nAge:\t38"};

    std::cout << text << std::endl;

}
```

консольный вывод:

```bash


Name:   "Tom"

Age:    38
```

raw-литерал отключает разбор escape-последовательностей. он начинается префиксом `R`, текст стоит в кавычках и в круглых скобках: `R"(...)"`. скобки входят в синтаксис литерала и в значение строки не попадают. перевод строки, табуляция и кавычки берутся из исходного текста как есть:

```cpp


#include <iostream>

#include <string>



int main()

{

    std::string text 

{R"(Name:   "Tom"

Age:    38)"};

    std::cout << text << std::endl;

}
```

отступы, переводы строки и кавычки интерпретируются буквально. результат совпадает с предыдущей программой, где те же символы были заданы escape-последовательностями. если внутри текста нужна последовательность `)"`, у литерала задают явный ограничитель, например `R"delim(...)delim"`. в примере ограничитель не потребовался.
