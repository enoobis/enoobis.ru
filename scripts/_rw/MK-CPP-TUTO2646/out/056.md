конструктор есть специальная функция. у неё то же имя, что у класса, и нет возвращаемого значения, даже типа `void`. конструктор инициализирует объект в момент создания и тем самым задаёт полям определённые значения до того, как с объектом начнёт работать остальной код. время жизни объекта классового типа начинается, когда конструктор завершился. при каждом создании объекта конструктор вызывается. повторно для уже живого объекта его не вызывают: конструктор привязан к инициализации.

в предыдущей теме класс выглядел так:

```cpp


#include <iostream>

#include <string>



class Person 

{

public:

    std::string name;

    unsigned age;

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

};

int main()

{

    Person person;	// вызов конструктора

    person.name = "Tom";

    person.age = 22;

    person.print();

}
```

при создании объекта `person` класса `Person`

```cpp
Person person;
```

вызывается **конструктор по умолчанию**. если в классе ни один конструктор явно не объявлен, компилятор объявляет его сам. такой конструктор не принимает параметров. в тексте он не содержит присваиваний: для членов без инициализатора по умолчанию встроенного типа значение остаётся неопределённым, пока его не зададут отдельно, а члены классового типа инициализируются своими конструкторами по умолчанию. формулировка «конструктор ничего не делает» описывает отсутствие пользовательского кода. инициализация членов при этом всё равно происходит по правилам языка.

свой конструктор нужен, когда поля должны получить значения уже при создании, а не отдельными присваиваниями после него:

```cpp


#include <iostream>

#include <string>



class Person 

{

public:

    std::string name;

    unsigned age;

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    {

        name = p_name;

        age = p_age;

        std::cout << "Person has been created" << std::endl;

    }

};

int main()

{

    Person tom("Tom", 38);	// создаем объект - вызываем конструктор

    tom.print();

}
```

в классе `Person` конструктор объявлен так:

```cpp


Person(std::string p_name, unsigned p_age)

{

    name = p_name;

    age = p_age;

    std::cout << "Person has been created" << std::endl;

}
```

конструктор есть функция, которая может принимать параметры и обязана называться именем класса. этот конструктор принимает два параметра, записывает их в поля `name` и `age` и печатает сообщение о создании объекта. присваивание в теле работает, потому что оба поля изменяемые. к моменту тела члены уже инициализированы, и тело именно присваивает, а не выполняет первичную инициализацию.

если объявлен свой конструктор, компилятор конструктор по умолчанию больше не создаёт. создать объект можно только обращением к одному из объявленных конструкторов. объявление `Person person;` после этого было бы ошибкой: конструктора без параметров нет.

вызов передаёт аргументы и инициализирует объект класса:

```cpp
Person tom("Tom", 38);
```

после вызова поле `name` объекта равно `"Tom"`, поле `age` равно 38. позже к этим полям можно обратиться и записать другие значения: конструктор задаёт начальное состояние, а не запрещает последующие присваивания открытым полям.

объект создают и инициализатором в фигурных скобках. список инициализации проверяет сужающие преобразования строже, чем круглые скобки:

```cpp
Person tom{"Tom", 38};
```

объекту присваивают и результат записи конструктора в виде правого значения:

```cpp
Person tom = Person("Tom", 38);
```

по наблюдаемому результату это тот же объект с теми же полями. с c++17 для prvalue действует обязательное исключение копии: временный объект не материализуется, и инициализация `tom` выполняется конструктором `Person(std::string, unsigned)` напрямую.

консольный вывод программы:

```bash


Person has been created

Name: Tom       Age: 38
```

сначала печатает конструктор, затем `print`. порядок фиксирован: тело конструктора завершается до того, как вызывающий код продолжает работу.

конструкторы упрощают создание нескольких объектов с разными значениями. каждый объект получает собственные поля, инициализированные своими аргументами:

```cpp


#include <iostream>

#include <string>



class Person 

{

public:

    std::string name;

    unsigned age;

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    {

        name = p_name;

        age = p_age;

        std::cout << "Person has been created" << std::endl;

    }

};

int main()

{

    Person tom{"Tom", 38};

    Person bob{"Bob", 42};

    Person sam{"Sam", 25};

    tom.print();

    bob.print();

    sam.print();

}
```

создаются три объекта класса `Person`, условно три разных человека. конструктор вызывается трижды, по разу на объект. консольный вывод:

```bash


Person has been created

Person has been created

Person has been created

Name: Tom       Age: 38

Name: Bob       Age: 42

Name: Sam       Age: 25
```

три сообщения о создании идут раньше трёх строк `print`, потому что все три объекта созданы до вызовов `print`.

### определение нескольких конструкторов

конструкторов может быть несколько. выбор перегрузки определяется числом и типами аргументов, как у обычной функции:

```cpp


#include <iostream>

#include <string>



class Person 

{

    std::string name{};

    unsigned age{};

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    {

        name = p_name;

        age = p_age;

    }

    Person(std::string p_name)

    {

        name = p_name;

        age = 18;

    }

    Person()

    {

        name = "Undefined";

        age = 18;

    }

};

int main()

{

    Person tom{"Tom", 38};  // вызываем конструктор Person(std::string p_name, unsigned p_age)

    Person bob{"Bob"};      // вызываем конструктор Person(std::string p_name)

    Person sam;             // вызываем конструктор Person()

    tom.print();

    bob.print();

    sam.print();

}
```

в `Person` три конструктора, и все три используются при создании объектов. поля `name` и `age` в этом варианте закрыты: они стоят до `public:` и для `class` по умолчанию имеют доступ `private`. внешний код их не присваивает, начальные значения приходят только из конструкторов. вывод:

```bash


Name: Tom       Age: 38

Name: Bob       Age: 18

Name: Undefined Age: 18
```

все три конструктора делают одну и ту же работу: записывают `name` и `age`. определения сокращают, вызывая из одного конструктора другой:

```cpp


#include <iostream>

#include <string>



class Person 

{

    std::string name{};

    unsigned age{};

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    {

        name = p_name;

        age = p_age;

        std::cout << "First constructor" << std::endl;

    }

    Person(std::string p_name): Person(p_name, 18) // вызов первого конструктора

    {

        std::cout << "Second constructor" << std::endl;

    }

    Person(): Person(std::string("Undefined")) // вызов второго конструктора

    { 

        std::cout << "Third constructor" << std::endl;

    }

};

int main()

{

    Person sam;     // вызываем конструктор Person()

    sam.print();

}
```

запись `Person(std::string p_name): Person(p_name, 18)` вызывает конструктор, которому передаются `p_name` и число 18. второй конструктор поручает инициализацию полей первому и дополнительно выполняет собственное тело. конструктор, который делегирует, не инициализирует поля собственным списком: целью в списке инициализации стоит только другой конструктор того же класса.

создание объекта

```cpp
Person sam;
```

использует третий конструктор. тот вызывает второй, а второй обращается к первому. целевой конструктор отрабатывает целиком, включая тело, и только потом выполняется тело делегирующего. для `Person sam` порядок тел такой: сначала первый конструктор (`First constructor`), затем второй (`Second constructor`), затем третий (`Third constructor`). после этого объект жив, и `print` печатает имя `Undefined` и возраст 18.

этот приём называется **делегированием конструктора**: инициализация поручена другому конструктору. делегирование не может быть циклическим. компилятор такое объявление отвергает, иначе инициализация не завершилась бы.

### параметры по умолчанию

как и у других функций, у конструктора бывают параметры по умолчанию:

```cpp


#include <iostream>

#include <string>



class Person 

{

    std::string name;

    unsigned age;

public:

    // передаем значения по умолчанию

    Person(std::string p_name = "Undefined", unsigned p_age = 18)

    { 

        name = p_name; 

        age = p_age;

    }

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

};

int main()

{

    Person tom{"Tom", 38};

    Person bob{"Bob"};

    Person sam;

    tom.print();    // Name: Tom   Age: 38

    bob.print();    // Name: Bob   Age: 18

    sam.print();    // Name: Undefined   Age: 18

}
```

один конструктор покрывает три способа вызова. пропущенный аргумент заменяется значением по умолчанию на стороне вызова, и в теле разницы между явно переданным и подставленным аргументом нет. `Person tom{"Tom", 38}` передаёт оба аргумента, `Person bob{"Bob"}` подставляет возраст 18, `Person sam` подставляет и имя, и возраст. перегрузки с тем же набором параметров рядом с таким конструктором объявить нельзя: вызов стал бы неоднозначным.

### инициализация констант и списки инициализации

в теле конструктора полям передают значения присваиванием. константы так инициализировать нельзя. класс:

```cpp


class Person 

{

    const std::string name;

    unsigned age{};

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age)

    {

        name = p_name;

        age = p_age;

    }

};
```

этот класс не компилируется: константа `name` не инициализирована. присваивание в теле конструктора выполняется уже после начала жизни члена, а константному члену присваивать нельзя. к моменту первой инструкции тела константы должны быть инициализированы. для этого служит **список инициализации**:

```cpp


#include <iostream>

#include <string>



class Person 

{

    const std::string name;

    unsigned age{};

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age) : name{p_name}

    {

        age = p_age;

    }

};

int main()

{

    Person tom{"Tom", 38};

    tom.print();    // Name: Tom    Age: 38

}
```

список инициализации есть перечисление инициализаторов членов после двоеточия, сразу за списком параметров конструктора:

```cpp


Person(std::string p_name, unsigned p_age) : name{p_name}
```

выражение `name{p_name}` инициализирует константу значением параметра `p_name`. значение стоит в фигурных скобках. допустимы и круглые:

```cpp


Person(std::string p_name, unsigned p_age) : name(p_name)
```

тем же списком задают начальные значения обычных переменных. инициализация в списке происходит до тела и для константы, и для переменной. тело тогда может остаться пустым:

```cpp


class Person 

{

    const std::string name;

    unsigned age;

public:

    void print() 

    {

        std::cout << "Name: " << name << "\tAge: " << age << std::endl;

    }

    Person(std::string p_name, unsigned p_age) : name(p_name), age(p_age)

    { }

};
```

порядок инициализации есть порядок объявления членов в классе, а не порядок имён в списке. список только сообщает значения. в примере сначала объявлена константа `name`, затем переменная `age`, и в этом же порядке они инициализируются, даже если в списке имена переставить. запись списка в порядке объявления нужна, чтобы зависимости между полями не читались ложно: если инициализатор одного поля использует другое, фактически уже построен тот член, который объявлен раньше, а не тот, который стоит левее в списке. компиляторы предупреждают, когда порядок в списке расходится с порядком объявления. при добавлении полей или перестановке существующих список сверяют с определением класса. то же правило относится к членам-ссылкам: ссылка, как и константа, связывается при инициализации и в теле конструктора уже не пересаживается.
