если программа велика, отдельные части кода размещают в разных файлах. одни функции лежат в одном файле исходного текста, другие в другом. каждый файл с расширением `.cpp`, который подают компилятору, образует единицу трансляции: препроцессор собирает её текст, компилятор переводит единицу в объектный код, компоновщик связывает объектные файлы в программу. объявление функции может встретиться во многих единицах, определение с телом по правилу одного определения (odr) должно быть одно.

файл `sum.cpp` содержит определение:

```cpp
int sum(int a, int b)
{
	return a + b;
}
```

это функция вычисления суммы двух чисел. определение порождает код и внешний символ `sum`, который компоновщик позже сопоставит с вызовами.

файл `sum.h` содержит объявление `sum`:

```cpp
int sum(int, int);
```

объявление сообщает тип функции и не выделяет для неё код. заголовок включают в те единицы трансляции, которым нужно имя `sum`.

главный файл называется `app.cpp`:

```cpp
#include <iostream>
#include "sum.h"	// подключаем файл sum.h

int main()
{
	int result { sum(5, 4)};
	std::cout << "result = " << result << std::endl;	// result = 9
}
```

функция `main` вызывает `sum` для суммы чисел. до использования функция должна быть определена или хотя бы объявлена: компилятор проверяет число и типы аргументов по видимому объявлению. раньше объявление писали прямо в единственном файле программы. когда определения лежат в других файлах, объявления помещают в заголовочные файлы и подключают эти файлы. директива `#include` в начале вставляет текст `sum.h`, а вместе с ним объявление `sum`.

```cpp
#include "sum.h"
```

`sum.h` называют заголовочным файлом (header file): в нём лежит объявление, заголовок функции. форма `#include "..."` в типичной реализации сначала ищет файл относительно текущего исходника, форма с угловыми скобками ищет в системных путях. здесь все файлы лежат в одном каталоге:

![заголовочные файлы в языке программирования c++](/uploads/course-lectures/e4d550d3680c41390340f197be627e4795f34bf5.png)

файл `sum.h` можно было бы не создавать и написать объявление прямо в `app.cpp`. при изменении функции меняется и объявление. если `sum` используется в нескольких файлах, править объявление пришлось бы в каждом. при общем заголовке достаточно изменить объявление в одном файле `sum.h`: следующая компиляция каждой единицы, которая его включает, увидит новый заголовок. определение в `sum.cpp` при этом остаётся единственным.

компиляция через g++ передаёт компилятору все файлы с определениями, через пробел:

```bash
g++ app.cpp sum.cpp -o app
```

`sum.h` в командную строку не входит: он попадает в `app.cpp` через `#include`. без `sum.cpp` компиляция `app.cpp` прошла бы, но компоновка сообщила бы о неопределённой ссылке на `sum`.

то же верно для компиляции через clang:

```bash
clang++ app.cpp sum.cpp -o app.exe
```

на выходе получается один исполняемый файл `app`. оба исходника компилируются в объектный код и компонуются вместе. имя `app` задаёт ключ `-o`. у clang в примере расширение `.exe` записано явно, у g++ имя `app` без расширения.

в visual studio заголовочные файлы обычно помещают в каталог `Headers`:

![header files в языке программирования c++ в visual studio](/uploads/course-lectures/8652f92cd10144100e870747478655d356503fa4.png)

при сборке проекта файлы исходного кода компилируются и компонуются в один результат без ручного перечисления имён в команде: среда сама передаёт их компилятору.
