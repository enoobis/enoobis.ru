объект производного класса одновременно является объектом базового класса. поэтому преобразования из производного типа в базовый выполняются автоматически, если наследование публичное и преобразование доступно снаружи.

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name} 

    {  }

    void print() const

    {

        std::cout << "Person " << name << std::endl;

    }

private:

    std::string name;

};



class Employee: public Person

{

public:

    Employee(std::string name): Person{name} {}

};



int main()

{

    Employee employee{"Bob"};

    employee.print();    // Person: Bob



    // преобразуем в базовый тип

    Person person1{employee};    // через конструктор копирования

    person1.print();        // Person: Bob



    Person person2{"Tom"};

    person2 = employee;   // через операцию присваивания

    person2.print();        // Person: Bob

}
```

класс `Person` является базовым, а `Employee` производным. поэтому компилятор может автоматически преобразовать объект `Employee` в тип `Person`. это можно сделать с помощью конструктора копирования:

```cpp
Person person1{employee};
```

или через операцию присваивания:

```cpp


Person person2{"Tom"};

person2 = employee;
```

при преобразовании по значению копируется только подобъект `Person`. члены, объявленные в `Employee`, в результат не входят: происходит срезка объекта (object slicing). динамический тип копии есть `Person`, даже если источник имел тип `Employee`.

преобразование можно выполнить и явным образом, например с помощью функции `static_cast()`:

```cpp


int main()

{

    Employee employee{"Bob"};

    employee.print();    // Person: Bob



    // преобразуем в базовый тип

    Person person1{static_cast<Person>(employee)};    // через конструктор копирования

    person1.print();        // Person: Bob



    Person person2{"Tom"};

    person2 = static_cast<Person>(employee);   // через операцию присваивания

    person2.print();        // Person: Bob

}
```

явный `static_cast` к значению базового типа выполняет ту же срезку: используется конструктор копирования или операция присваивания `Person`.

### преобразование указателей

указатель на объект производного класса можно преобразовать автоматически в указатель на объект базового типа:

```cpp


#include <iostream>

#include <string>



class Person

{

public:

    Person(std::string name): name{name} {  }

    virtual void print() const

    {

        std::cout << name << std::endl;

    }

    std::string getName() const {return name;}

private:

    std::string name;

};



class Employee: public Person

{

public:

    Employee(std::string name, std::string company): Person{name}, company{company}{}

    void print() const override

    {

        std::cout << getName() << " (" << company << ")" << std::endl;

    }

    std::string getCompany() const { return company;}

private:

    std::string company;

};

int main()

{

    Employee bob{"Bob", "Google"};

    // преобразуем в указатель на базовый тип

    Person* person{&bob};

    person->print();    // Bob (Google)

}
```

указатель на объект `Person` получает адрес объекта `Employee`.

подобным образом можно создать указатель производного класса и преобразовать его автоматически в указатель на базовый тип:

```cpp


int main()

{

    Employee bob{"Bob", "Google"};

    Employee* employee = &bob;



    // преобразуем в указатель на базовый тип

    Person* person{employee};

    person->print();    // Bob (Google)

}
```

то же самое касается ссылок:

```cpp


int main()

{

    Employee sam{"Sam", "Microsoft"};

    // ссылка базового типа ссылается на объект производного класса

    Person &person1 {sam};

    person1.print();    // Sam (Microsoft)





    Employee &employee{sam};

    // преобразуем ссылку производного класса в ссылку базового класса

    Person &person2 {employee};

    person2.print();    // Sam (Microsoft)

}
```

преобразование указателя и ссылки не копирует объект и не срезает его. указатель или ссылка обозначают тот же объект, а адрес при необходимости сдвигается к началу подобъекта базы. динамический тип остаётся типом полного объекта, поэтому виртуальный вызов `print` выбирает реализацию `Employee`. неявное преобразование доступно при публичном наследовании. при защищённом и закрытом наследовании снаружи производного класса оно недоступно.

в некоторых случаях возможно приведение в обратную сторону, от базового типа к производному. автоматически оно не выполняется, для этого надо использовать функции преобразования, в частности `static_cast()`. будет ли приведение корректным, зависит от динамического типа объекта. чтобы можно было привести объект базового класса, например `Person`, к указателю производного класса, например `Employee`, указатель базового класса должен указывать на объект класса `Employee` или класса, производного от `Employee`. если указатель адресует объект другого типа, результат приведения не определён: поведение программы не определено. например:

```cpp


int main()

{

    Employee sam{"Sam", "Microsoft"};

    // указатель базового класса указывает на объект производного класса

    Person* person {&sam};

    // обратное преобразование - из базового типа в производный

    Employee* employee{static_cast<Employee*>(person)};

    employee->print();  // Sam (Microsoft)

}
```

указатель `person`, хотя и представляет указатель на тип `Person`, в реальности указывает на объект `Employee`. поэтому с помощью функции `static_cast()` этот указатель можно привести к типу `Employee*`. нисходящее `static_cast` динамический тип на этапе выполнения не проверяет. компилятор принимает приведение, если типы состоят в одной иерархии.

другая ситуация:

```cpp


int main()

{

    Person tom{"Tom"};

    Person* person {&tom};

    // обратное преобразование - из базового типа в производный

    Employee* employee{static_cast<Employee*>(person)};

    employee->print();  // Sam (Microsoft)

    std::cout << employee->getCompany() << std::endl;   // ???

}
```

указатель `person` указывает на объект `Person`. однако с помощью функции `static_cast` его можно успешно привести к указателю на `Employee`, и компиляция проходит. теоретически через подобный указатель можно обратиться к функции `getCompany`, которая определена в классе `Employee`. в классе `Person` её нет, и поэтому при попытке к ней обратиться программа завершится с ошибкой. если нет уверенности, что объект представляет определённый производный класс, подобные преобразования из базового типа в производный лучше не выполнять. проверку динамического типа на этапе выполнения даёт динамическое приведение.

### преобразование smart-указателей

smart-указатели на базовый класс также могут указывать на объект производного класса:

```cpp


int main()

{

    std::unique_ptr<Person> bob{std::make_unique<Employee>("Bob", "Google")};

    bob->print();    // Bob (Google)



    std::shared_ptr<Person> tom{std::make_shared<Employee>("Tom", "Microsoft")};

    tom->print();    // Tom (Microsoft)



    std::shared_ptr<Employee> sam{std::make_shared<Employee>("Sam", "Jetbrains")};

    std::shared_ptr<Person> person{sam};

    person->print();    // Sam (Jetbrains)

}
```

`std::unique_ptr<Person>` принимает результат `std::make_unique<Employee>`: владеющий указатель на производный класс преобразуется к владеющему указателю на базовый, и владение переносится. `std::shared_ptr<Person>` строится из `std::shared_ptr<Employee>` и разделяет владение тем же объектом. удаление объекта производного класса через smart-указатель на базовый определено, когда деструктор базового класса виртуальный. иначе при уничтожении `std::unique_ptr` или последнего `std::shared_ptr` поведение не определено.
