c++ является статически типизированным языком. тип переменной задаётся в определении и в дальнейшем не меняется. переменная принимает значения своего типа. если нужно записать значение другого типа, применяется преобразование. преобразование может быть неявным, когда его вставляет компилятор, или явным, когда его записывает программист.

ряд преобразований компилятор выполняет неявно, то есть автоматически. пример:

```cpp


#include <iostream>



int main()

{

    unsigned int age{25};

    std::cout << "age = " << age << std::endl;

}
```

переменная `age` имеет тип `unsigned int` и по смыслу хранит возраст. инициализатор 25 записан без суффикса, а целочисленный литерал без суффикса имеет тип `int` (`signed int`). компилятор умеет преобразовать значение 25 к `unsigned int`. число входит в диапазон обоих типов, информация не теряется.

другой инициализатор уже выходит за пределы целевого типа:

```cpp


#include <iostream>



int main()

{

    unsigned int age{-25};

    std::cout << "age = " << age << std::endl;

}
```

переменной `age` передаётся -25, отрицательное значение, тогда как `unsigned int` представляет только неотрицательные вычеты по модулю 2 в степени ширины типа. списковая инициализация в фигурных скобках запрещает такое сужающее преобразование, и компиляция завершается ошибкой. диагностика g++:

```consoletext
error: narrowing conversion of '-25' from 'int' to 'unsigned int' [-Wnarrowing]
```

### примеры неявных преобразований

базовые преобразования при присваивании и инициализации копированием устроены так.

- переменной типа `bool` присваивается значение другого типа. переменная получает `false`, если значение равно 0, и `true` во всех остальных случаях. к `bool` приводится проверка «не равно нулю», а не перенос всех битов:

```cpp


bool a = 1;		// true

bool b = 0;		// false

bool c = 'g'; // true

bool d = 3.4; 	// true
```

- числовой или символьной переменной присваивается значение типа `bool`. переменная получает 1, если значение равно `true`, и 0, если присваиваемое значение равно `false`:

```cpp


int c = true; 		// 1

double d = false;	// 0
```

- целочисленной переменной присваивается дробное число. дробная часть отбрасывается, округления к ближайшему нет. направление усечения для положительных чисел совпадает с отбрасыванием доли в сторону нуля:

```cpp


int a = 3.4; 		// 3

int b = 3.6;		// 3
```

- переменной с плавающей точкой присваивается целое число. если целое содержит больше значащих битов, чем вмещает мантисса целевого типа, младшая часть информации теряется при округлении к представимому значению:

```cpp


float a = 35005; 				// 35005

double b = 3500500000033;		// 3.5005e+012
```

- переменной беззнакового типа присваивается значение вне её диапазона. результат равен остатку от деления по модулю 2 в степени числа битов. тип `unsigned char` хранит значения от 0 до 255, то есть 256 различных значений. значение вне диапазона заменяется остатком по модулю 256. присваивание -5 переменной типа `unsigned char` даёт 251, потому что -5 + 256 = 251:

```cpp


unsigned char a = -5; 			// 251

unsigned short b = -3500;		// 62036

unsigned int c = -50000000;		// 4244967296
```

- переменной знакового типа присваивается значение вне её диапазона. результат таким модулем однозначно не задаётся: программа может показать правдоподобное значение, а может вести себя некорректно. для знакового целого стандарт долго оставлял это преобразование на усмотрение реализации. с c++20 преобразование целого к знаковому типу, который не способен представить значение, определено как приведение по модулю 2 в степени ширины типа. преобразование из плавающего типа, если значение не представимо в целевом целом, по-прежнему не даёт переносимого результата.

### преобразования в арифметических операциях

в арифметической операции оба операнда приводятся к общему типу. если типы различаются, выбирается операнд с меньшим диапазоном значений и преобразуется к типу второго операнда, у которого диапазон шире. по приоритету преобразований типы располагаются от более высокого к более низкому так:

- `long double`
- `double`
- `float`
- `unsigned long long`
- `long long`
- `unsigned long`
- `long`
- `unsigned int`
- `int`

если в операции участвуют `float` и `long double`, операнд типа `float` преобразуется к `long double`: в этом списке у `long double` приоритет выше. общий тип выражения есть тип после этих преобразований, и именно он определяет тип результата.

эта линейная шкала передаёт обычную учебную схему. стандарт формулирует обычные арифметические преобразования точнее. сначала выполняются целочисленные продвижения, затем сравниваются ранги. если один операнд беззнаковый и его ранг не ниже ранга знакового операнда, общий тип беззнаковый. если знаковый тип способен представить все значения беззнакового, общий тип знаковый. иначе оба операнда переходят к беззнаковому аналогу знакового типа. на платформе, где `long` шире `unsigned int`, выражение с этими двумя типами получает тип `long`, а не `unsigned int`.

операнды типов `char`, `signed char`, `unsigned char`, `short` и `unsigned short` перед операцией продвигаются как минимум к `int`, если `int` вмещает весь их диапазон. если не вмещает, продвижение идёт к `unsigned int`. на распространённых платформах `int` не уже 32 бит, и даже `unsigned short` укладывается в `int`.

пример считает почасовой заработок: за 8 часов получено 100.2, требуется величина за один час:

```cpp


#include <iostream>



int main()

{

    double sum {100.2};

    int hours {8};

    double revenuePerHour {sum / hours};

    std::cout << "Revenue per hour = " << revenuePerHour << std::endl;

}
```

переменная `hours` имеет тип `int`. в делении она преобразуется к более приоритетному типу `double`, потому что второй операнд, `sum`, имеет тип `double`. частное тоже имеет тип `double`.

неявное приведение избавляет от ручной записи преобразования и одновременно может дать нежелательный результат. пример:

```cpp


#include <iostream>



int main()

{

    int n {5};

    unsigned int x {8};

    std::cout << "result = " << n - x << std::endl;	// result = 4294967293

}
```

в выражении `n - x` значение `n` преобразуется к более приоритетному по приведённой шкале типу `unsigned int`. математически `5 - 8` равно -3. оба операнда и результат имеют тип `unsigned int`, поэтому получается вычет по модулю 2^32, значение `4294967293`. это то же битовое представление, которое у знакового типа читалось бы как -3.

### опасные и безопасные преобразования

преобразование, при котором информация не теряется, считается безопасным. обычно это переход от типа с меньшей разрядностью к типу с большей. такие цепочки:

**bool -> char -> short -> int -> double -> long double**

**bool -> char -> short -> int -> long -> long long**

**unsigned char -> unsigned short -> unsigned int -> unsigned long**

**float -> double -> long double**

примеры безопасных преобразований:

```cpp


short a = 'g'; // преобразование из char в short

int b = 10;

double c = b; // преобразование из int в double

float d = 3.4;

double e = d; // преобразование из float в double

double f = 35; // преобразование из int в double
```

существуют и опасные преобразования. при них точность или само значение могут быть потеряны. обычно это переход от типа с большей разрядностью к типу с меньшей либо переход к типу, в диапазон которого значение не входит.

```cpp


unsigned int a = -25;           // 4294967271

unsigned short b = -3500;		// 62036
```

переменным `a` и `b` присваиваются значения вне диапазона их типов. дальше поведение зависит от компилятора и от формы инициализации. часть компиляторов выдаёт предупреждение, но успешно переводит программу. часть не выдаёт предупреждения. опасность в том, что программа компилируется, а точность или знак уже потеряны. значение переменной есть набор битов, который интерпретируется согласно типу. один и тот же набор битов для разных типов читается по-разному. при записи значения приходится сверять его с диапазоном целевого типа.

если речь идёт об инициализации и нужно исключить опасное преобразование с потерей точности, используют инициализацию в фигурных скобках:

```cpp


unsigned int a {-25};           // ! Ошибка 

unsigned short b {-3500};		// ! Ошибка
```

в этом случае компилятор выдаёт ошибку, и программа не компилируется. списковая инициализация запрещает сужение: преобразование, которое не всякое значение исходного типа способно перенести в целевой. копирующая инициализация вида `unsigned int a = -25` таким запретом не защищена.

### явные преобразования типов

для явного преобразования типа (explicit type conversion) применяется оператор `static_cast`:

```cpp
static_cast<type>(value)
```

оператор преобразует значение в круглых скобках, `value`, к типу, указанному в угловых скобках, `type`. слово `static` в имени оператора отражает статическую проверку: допустимость приведения выясняется при компиляции, а не во время выполнения. `static_cast` не снимает `const` и не переинтерпретирует биты произвольного объекта. для чисел он выполняет осмысленное преобразование значения.

применение `static_cast` сообщает компилятору, что преобразование в этой точке намеренное. даже при инициализации в фигурных скобках ошибки сужения тогда не возникает: сужение уже выполнено явным оператором, а переменная инициализируется значением своего типа. пример снова считает почасовой заработок за 8 часов при сумме 100.2, но результат нужен как `unsigned int`:

```cpp


#include <iostream>



int main()

{

    double sum {100.2};

    unsigned int hours {8};

    unsigned int revenuePerHour { static_cast<unsigned int>(sum/hours) };  // revenuePerHour = 12

    std::cout << "Revenue per hour = " << revenuePerHour<< std::endl;

}
```

выражение `static_cast<unsigned int>(sum/hours)` сначала вычисляет `sum/hours`. частное имеет тип `double`. затем это значение преобразуется к `unsigned int`, дробная часть отбрасывается, и в переменную попадает 12.

раньше в c++ применялась операция преобразования, унаследованная от c:

```cpp
(тип) значение
```

перед преобразуемым значением в круглых скобках указывался целевой тип. та же задача в старой записи:

```cpp


#include <iostream>



int main()

{

    double sum {100.2};

    unsigned int hours {8};

    unsigned int revenuePerHour { (unsigned int)sum/hours};		// revenuePerHour = 12

    std::cout << "Revenue per hour = " << revenuePerHour<< std::endl;

}
```

числовой результат совпадает. в современном c++ эту форму практически вытеснил `static_cast`. приведение в стиле c способно выполнить сразу несколько видов преобразования, включая снятие квалификаторов и переинтерпретацию указателя, и по тексту вызова этого не видно. `static_cast` ограничен преобразованиями, которые компилятор может проверить, и намерение в точке вызова читается явно. у формы в стиле c приоритет выше, чем у деления, поэтому в выражении `(unsigned int)sum/hours` приведение относится только к `sum`, а не к частному. в данном наборе чисел итог всё равно равен 12.
