наследование в dart подчиняется существенному ограничению: класс не может наследовать сразу несколько классов. следующая запись недопустима:



```dart

class Worker{
    String company = "Necrosoft";
    Worker(this.company);
    void work()=>print("works in $company");
}
class Student{
    String university = "Stanford";
    Student(this.university);
    void study() =>print("studies in $university");
}
class WorkingStudent extends Worker, Student{ // ! Ошибка - множественное наследование не допускается
}
```



здесь определены два класса: Worker (работающий) и Student (студент). класс работающего студента WorkingStudent должен был бы сочетать функциональность обоих, но унаследовать его от Worker и Student одновременно нельзя, поскольку dart поддерживает только одиночное наследование реализации. такое решение избавляет язык от проблем множественного наследования, прежде всего от ромбовидной иерархии и неоднозначности при выборе реализации.



одно из средств обойти это ограничение в dart составляет реализация интерфейсов. в отличие от java или c#, где интерфейс объявляется отдельной конструкцией interface, в dart каждый класс неявно определяет интерфейс, состоящий из всех его экземплярных членов. класс одновременно выступает в роли интерфейса, и другой класс может этот интерфейс реализовать.



интерфейс задаёт синтаксический контракт, которому обязаны следовать реализующие его классы: если класс-интерфейс объявляет поля и методы, реализующий класс должен определить те же поля и методы с совместимыми сигнатурами. поле в интерфейсе при этом соответствует паре геттера и сеттера (для final поля только геттеру), и реализовать его можно как полем, так и явными методами доступа.



реализация интерфейсов записывается с помощью ключевого слова **implements**, после которого перечисляются реализуемые классы:



```dart

class Worker{
    String company = "Microsoft";
    Worker(this.company);
    void work()=>print("works in $company");
}
class Student{
    String university = "Stanford";
    Student(this.university);
    void study() =>print("studies in $university");
}
class WorkingStudent implements Worker, Student{
    
    String name;
    @override
    String company;
    @override
    String university;
    WorkingStudent(this.name, this.university, this.company);
    @override
    void study() =>print("$name studies in $university");
    @override
    void work()=>print("$name works in $company");
}

void main (){

    WorkingStudent tom = WorkingStudent("Tom", "MIT", "Google");
    tom.study();    // Tom studies in MIT
    tom.work();     // Tom works in Google
}
```



класс WorkingStudent реализует интерфейсы классов Worker и Student:



```dart
class WorkingStudent implements Worker, Student
```



реализация интерфейса означает, что WorkingStudent обязан определить все поля и методы, объявленные в Worker и Student: поле company и метод work из Worker, поле university и метод study из Student. реализация при этом не наследуется, от Worker и Student берутся только сигнатуры, весь код приходится писать заново. если бы WorkingStudent определил не все члены этих классов, компилятор выдал бы ошибку.



из примера видно также, что конструкторы в интерфейс не входят: WorkingStudent не обязан повторять конструкторы реализуемых классов и вообще может не определять ни одного конструктора.



реализация интерфейса делает WorkingStudent подтипом Worker и Student. везде, где ожидается объект Worker или объект Student, можно использовать объект WorkingStudent: работающий студент одновременно является и работающим, и студентом. например:



```dart

void makeWork(Worker worker){
    worker.work();
}
void makeStudy(Student student){
    student.study();
}

void main (){

    WorkingStudent tom = WorkingStudent("Tom", "MIT", "Google");
    // вместо Worker можно передать WorkingStudent
    makeWork(tom);      // Tom works in Google
    // вместо Student можно передать WorkingStudent
    makeStudy(tom);     // Tom studies in MIT
}
```






### совмещение наследования с реализацией



наследование и реализацию интерфейсов можно сочетать. пусть класс WorkingStudent наследует Student, а интерфейс Worker по-прежнему реализует:



```dart

class Worker{
    String company = "Microsoft";
    Worker(this.company);
    void work()=>print("works in $company");
}
class Student{
    String university = "Stanford";
    Student(this.university);
    void study() =>print("studies in $university");
}
class WorkingStudent extends Student implements Worker{
    
    String name;
    @override
    String company;
    WorkingStudent(this.name, super.university, this.company);
    @override
    void study() =>print("$name studies in $university");
    @override
    void work()=>print("$name works in $company");
}

void main (){

    WorkingStudent tom = WorkingStudent("Tom", "MIT", "Google");
    tom.study();    // Tom studies in MIT
    tom.work();     // Tom works in Google
}
```



теперь WorkingStudent наследуется от Student и реализует интерфейс Worker:



```dart
class WorkingStudent extends Student implements Worker{
```



поле university определять в WorkingStudent уже не нужно, оно унаследовано от базового класса. метод study тоже можно было бы не определять, здесь он переопределён лишь для того, чтобы выводить имя работающего студента.



поскольку в Student объявлен конструктор, конструктор WorkingStudent обязан вызвать конструктор базового класса:



```dart
WorkingStudent(this.name, super.university, this.company);
```



параметр `super.university` (super-параметр, появившийся в dart 2.17) передаёт своё значение в одноимённый параметр university конструктора Student.



через ключевое слово **super** доступна и остальная функциональность базового класса. к членам класса-интерфейса через `super` обратиться нельзя, поскольку реализации от интерфейса не наследуется.



начиная с dart 3.0 в языке появились модификаторы классов, среди них **interface**. класс с модификатором **interface** можно наследовать только внутри его собственной библиотеки, за её пределами его допускается лишь реализовывать как интерфейс. так автор библиотеки гарантирует, что внешний код не унаследует его реализацию и не будет зависеть от её внутренних деталей.



```dart

interface class Worker{
    String company;
    Worker(this.company);
    void work()=>print("works in $company");
}
class Manager implements Worker{
     
    String name;
    @override
    String company;
    Manager(this.name, this.company);
    @override
    void work()=>print("$name works in $company");
}
 
void main (){
 
    var tom = Manager("Tom", "Google");
    tom.work();     // Tom works in Google
}
```



### абстрактные интерфейсы



в примерах выше классы-интерфейсы содержат реализацию по умолчанию: объявляют переменные, а их методы выполняют конкретные действия. это требуется не всегда. часто интерфейс нужен только для того, чтобы зафиксировать набор методов типа без всякой реализации. тогда интерфейс объявляют абстрактным:



```dart

abstract interface class Worker{
    void work();
}
abstract interface class Student{
    void study();
}
class WorkingStudent implements Worker, Student{

    String name;
    String university;
    String company;
    WorkingStudent(this.name, this.university, this.company);
    @override
    void study() =>print("$name studies in $university");
    @override
    void work()=>print("$name works in $company");
}

void main (){

    WorkingStudent tom = WorkingStudent("Tom", "MIT", "Google");
    studentStudy(tom);
    workerWork(tom);
}
void studentStudy(Student st){
    st.study();
}
void workerWork(Worker w){
    w.work();
}
```



Worker не содержит реализации метода work, Student не содержит реализации метода study. оба метода абстрактные, их реализует класс WorkingStudent. сочетание abstract interface class ближе всего к интерфейсу в java или c#: экземпляр такого класса создать нельзя, а внешние библиотеки могут его только реализовать.



### наследование классов и реализация интерфейсов



при наследовании производный класс не обязан заново определять поля и методы базового класса, за исключением абстрактных методов. если базовый класс объявляет конструктор с параметрами, производный класс должен определить свой конструктор и вызвать в нём конструктор базового класса. к реализации базового класса производный класс обращается через ключевое слово **super**. множественное наследование не поддерживается.



при реализации интерфейса класс обязан определить все поля и методы класса-интерфейса. конструкторы в интерфейс не входят, поэтому наличие конструктора у интерфейса не обязывает реализующий класс объявлять свой. обращаться к методам реализованного интерфейса через ключевое слово **super** нельзя. реализация нескольких интерфейсов одновременно поддерживается.
