однопоточность приложения на dart не означает, что другие потоки использовать нельзя. в частности, можно создать новый **изолят** (isolate). новый изолят получает собственную память и собственный поток, который выполняется параллельно основному потоку приложения. при этом два изолята не имеют доступа к памяти друг друга и взаимодействуют только посредством обмена сообщениями. такая модель исключает гонки данных на уровне языка: разделяемого изменяемого состояния между изолятами нет.

для отправки сообщений используется объект, называемый **send port** (порт отправки), который передаётся новому изоляту при создании. для получения сообщений в изоляте главного потока служит объект **receive port** (порт приёма). при этом каждый из изолятов может как отправлять, так и получать сообщения.

новые изоляты обычно создаются для того, чтобы вынести в отдельный поток вычисления, способные занять продолжительное время. сначала рассмотрим простую задачу:

```dart
void main() async{
  print("Start calculation");
  final result = count();
  print(result);
  print("Some work...");
}

int count() {
  var result = 0;
  for (var i = 1; i <= 10000000000; i++) {
    result = i;
  }
  return result;
}
```

функция count последовательно перебирает числа от 1 до 10000000000 и возвращает последнее из них. функция бессмысленна, но позволяет имитировать долгую работу. на практике на её месте могли бы находиться реальные вычисления, например обработка изображений или видео. если такое вычисление выполняется в графическом приложении, где пользователь нажимает кнопку и ожидает результата, приложение зависает до окончания вычисления.

асинхронная версия функции ситуацию существенно не меняет:

```dart
void main() async{
  print("Start calculation");
  final result = await count();
  print(result);
  print("Some work...");
}

Future<int> count() async {
  var result = 0;
  await Future((){
    for (var i = 1; i <= 10000000000; i++) {
      result = i;
    }
  });
  return result;
}
```

асинхронная операция в функции count просто помещается в конец очереди событий event queue. когда она начинает выполняться, приложение точно так же блокируется до её завершения: цикл в функции, переданной в Future, выполняется синхронно в том же потоке, и пока он не закончится, цикл событий не может обработать ни одной другой задачи. асинхронность меняет лишь момент выполнения работы, но не даёт параллелизма.

теперь используем изоляты:

```dart
import 'dart:isolate';

void main() async{
  print("Start calculation");
  // создаем порт приема сообщений от нового изолята
  final receivePort = ReceivePort();
  // создаем новый изолят
  final isolate = await Isolate.spawn(count, receivePort.sendPort);
  // запускаем прослушивание входящих сообщений
  receivePort.listen((message) {
    print(message);
    // изолят больше не нужен  - завершаем его
    receivePort.close();
    isolate.kill();
  });
  print("Some work...");
}

void count(SendPort sendPort) {
  var result = 0;
  for (var i = 1; i <= 10000000000; i++) {
    result = i;
  }
  sendPort.send(result);
}
```

теперь функция count принимает параметр типа **SendPort**, порт отправки, через который будет передано сообщение. по завершении вычислений результат отправляется в изолят основного потока методом `sendPort.send()`. при передаче между изолятами сообщение, как правило, копируется, поскольку у получателя своя куча.

чтобы выполнить функцию count, в функции main сначала создаётся порт приёма сообщений, объект **ReceivePort**:

```dart
final receivePort = ReceivePort();
```

затем статическим методом **Isolate.spawn** создаётся новый изолят. в метод передаются значения двух обязательных параметров:

```dart
final isolate = await Isolate.spawn(count, receivePort.sendPort);
```

первый параметр задаёт функцию, которую будет выполнять изолят, второй: объект, передаваемый в эту функцию. функция count принимает объект SendPort, и значение `receivePort.sendPort` передаёт в неё нужный порт отправки. метод spawn асинхронный и возвращает `Future<Isolate>`, поэтому результат получают через await.

если бы функции count требовались и другие значения, их можно было бы передать в виде списка или словаря либо определить специальный класс, объединяющий все значения.

далее для прослушивания входящих сообщений вызывается метод **listen()**:

```dart
receivePort.listen((message) {
    print(message);
    receivePort.close();
    isolate.kill();
  });
```

этот метод принимает функцию, которая получает сообщение от изолята. здесь сообщение просто выводится на консоль. ReceivePort реализует интерфейс Stream, поэтому listen здесь является обычной подпиской на поток событий.

после того как результат получен во входящем сообщении, то есть функция count завершила выполнение, её изолят больше не нужен. поэтому порт приёма сообщений закрывается:

```dart
receivePort.close();
```

пока порт открыт, он удерживает цикл событий главного изолята, и программа не завершается. затем работа изолята, созданного для функции count, прекращается:

```dart
isolate.kill();
```

в итоге консольный вывод программы следующий:

```bash
Start calculation
Some work...
10000000000
```

строка "Some work..." выводится до результата: главный изолят продолжает работу, пока вычисление идёт параллельно в другом изоляте. для одноразовых вычислений такого рода в dart 3 есть и более краткая форма `Isolate.run`, которая сама создаёт изолят, возвращает результат функции в виде Future и завершает изолят.
