во время работы программы могут возникать ошибки, которые нарушают нормальный ход выполнения и даже приводят к его прерыванию. такие ситуации называются исключениями. dart, как и многие языки программирования, поддерживает обработку исключений, что позволяет избежать аварийного завершения программы. в отличие от java, в dart нет проверяемых исключений: сигнатура функции не объявляет, какие исключения она может сгенерировать, и компилятор не требует их обработки.

рассмотрим простейшую ситуацию:

```dart
void main (){
     
	 int x = 9;
	 int y = 0;
	 int z = x ~/ y;
	 
	 print(z);
}
```

здесь выполняется целочисленное деление (операция ~/) на 0. в результате программа генерирует исключение и завершает выполнение. ситуация выглядит искусственной, поскольку очевидно, что одна из переменных равна 0, и закономерно, что программа завершится с ошибкой. статический анализ такую ошибку не выявляет: деление на ноль обнаруживается только во время выполнения.

```bash
c:\dart>dart main.dart
Unhandled exception:
IntegerDivisionByZeroException
#0      int.~/ (dart:core-patch/integers.dart:30:7)
#1      main (file:///c:/dart/main.dart:5:16)
#2      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:297:19)
#3      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:26)

c:\dart>
```

однако на практике данные часто поступают из внешнего источника, и заранее неизвестно, равно значение 0 или нет. кроме того, деление на ноль далеко не единственная причина исключений в dart, аварийная остановка программы возможна во многих ситуациях.

для обработки подобных ситуаций dart предоставляет прежде всего конструкцию **try...on...catch...finally**:

```dart
try{
    // Код, который может привести к генерации исключения  
}
on Тип_Исключения{
     // Обработка возникшего исключения
}
catch (e){
     // Обработка возникшего исключения
}
finally{
     // 
}
```

при выполнении конструкции **try..on..catch..finally** сначала выполняются все инструкции блока **try**. если в нём не возникло исключений, затем выполняется блок **finally**, и на этом конструкция `try..on..catch..finally` завершает работу.

если же в блоке try возникает исключение, обычный порядок выполнения прерывается, и управление передаётся блоку **on** или **catch**, способному обработать это исключение. если подходящий блок on или catch найден, он выполняется, а после его завершения выполняется блок finally.

разница между **on** и **catch** в том, что **on** обрабатывает исключения определённого типа (подробнее оператор **on** рассматривается в следующей теме), а **catch** без указания типа обрабатывает любые исключения.

если подходящий блок on или catch не найден, при возникновении исключения всё равно выполняется блок finally, после чего исключение распространяется дальше по стеку вызовов, и если его никто не перехватит, программа завершается аварийно. гарантированное выполнение finally делает его местом для освобождения ресурсов независимо от исхода блока try.

применим конструкцию try..on..catch..finally для обработки деления на 0:

```dart
void main (){
     
	 try{
		int x = 9;
		int y = 0;
		int z = x ~/ y;
	 
		print(z);
	}
	catch(e){
		 print("Возникло исключение $e");
	}
	print("Завершение программы");
}
```

код, который может сгенерировать исключение, помещён в блок try. блок catch в скобках содержит список параметров, которые передаются при генерации исключения. здесь параметр один, `(e)`, и он содержит объект исключения. поскольку в dart можно сгенерировать любой ненулевой объект, а не только наследника определённого класса, статическим типом e в блоке catch без on является `Object`.

при выполнении этой программы консольный вывод будет следующим:

```bash
Возникло исключение IntegerDivisionByZeroException
Завершение программы
```

несмотря на генерацию исключения, программа не завершилась аварийно и после выполнения блока catch продолжила работу.

ненужные блоки конструкции можно опускать. обязателен только блок try, но вместе с ним должен присутствовать хотя бы один блок on и(или) catch либо блок finally. в примере выше использовались только блоки try и catch. добавим блок finally:

```dart
void main (){
     
	 try{
		int x = 9;
		int y = 0;
		int z = x ~/ y;
	 
		print(z);
	}
	catch(e){
		 print("Возникло исключение $e");
	}
	finally{
		 print("Выполнение блока finally");
	}
	print("Завершение программы");
}
```

консольный вывод:

```bash
Возникло исключение IntegerDivisionByZeroException
Выполнение блока finally
Завершение программы
```

здесь можно опустить блок catch:

```dart
void main (){
     
	 try{
		int x = 9;
		int y = 0;
		int z = x ~/ y;
	 
		print(z);
	}
	finally{
		 print("Выполнение блока finally");
	}
	print("Завершение программы"); 	// эта строка не выполняется
}
```

после генерации исключения в блоке try выполняется блок finally, и затем программа аварийно останавливается, поскольку исключение осталось необработанным. консольный вывод:

```bash
Выполнение блока finally
Unhandled exception:
IntegerDivisionByZeroException
#0      int.~/ (dart:core-patch/integers.dart:30:7)
#1      main (file:///c:/dart/main.dart:6:13)
#2      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:297:19)
#3      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:26)
```

### параметры блока catch

в блок catch передаются параметры с информацией об исключении, которую при необходимости можно получить и использовать:

```dart
void main (){
     
	try{
        int x = 9;
        int y = 0;
        int z = x ~/ y;
        
        print(z);
    }
    catch(e, s){
        print("Обработка исключения $e");
        print("Стек $s");
    }
	print("Завершение программы"); 
}
```

первый параметр блока catch, e, содержит объект исключения, а второй, s, содержит трассировку стека (объект типа `StackTrace`), по которой можно понять, где возникло исключение. в отличие от java и c#, где трассировка хранится в самом объекте исключения, в dart она передаётся отдельно, поскольку сгенерировать можно произвольный объект, у которого такого поля нет. консольный вывод:

```bash
Обработка исключения IntegerDivisionByZeroException
Стек #0      int.~/ (dart:core-patch/integers.dart:30:7)
#1      main (file:///c:/dart/main.dart:6:12)
#2      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:297:19)
#3      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:26)

Завершение программы
```

по консольному выводу видно, что проблема находится в 6 строке файла c:/dart/main.dart, где и возникло исключение. если после частичной обработки исключение нужно передать дальше с сохранением исходной трассировки, внутри catch используется инструкция `rethrow`.
