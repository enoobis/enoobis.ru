по умолчанию конструктор класса создаёт и возвращает новый экземпляр этого класса. однако новый объект нужен не всегда: иногда из конструктора требуется вернуть уже существующий объект. для этого в dart применяются фабричные конструкторы, то есть конструкторы, объявленные с ключевым словом **factory**. в отличие от генеративного конструктора, фабричный не создаёт экземпляр автоматически и не имеет списка инициализации: это по сути статическая функция с синтаксисом вызова конструктора, которая обязана явно вернуть объект с помощью return. возвращаемый объект может быть уже существующим экземпляром или экземпляром подтипа.

фабричный конструктор позволяет выполнить начальную логику перед непосредственным созданием объекта: проверку и валидацию переданных значений, их модификацию и любые другие действия, которые нужны до создания экземпляра.

```dart
class Person{

	String name;
	int age;     
	
    factory Person(String name, int age)
    {
        if(name.length <2)
        {
            name = "Undefined";
        }
        if(age <1 || age > 110)
        {
            age = 18;
        }
        return Person._create(name, age);
    }

    Person._create(this.name, this.age);
	
    void display() => print("Name: $name \tAge: $age");
}

void main() {

    Person tom = Person("Tom", 38);
    tom.display();      // Name: Tom    Age: 38

    Person li = Person("L", 100500);
    li.display();      // Name: Undefined    Age: 18
}
```

в классе Person определён фабричный конструктор, который принимает два параметра:

```dart
factory Person(String name, int age)
{
    if(name.length <2)
    {
        name = "Undefined";
    }
    if(age <1 || age > 110)
    {
        age = 18;
    }
    return Person._create(name, age);
}
```

при создании объекта могут быть переданы некорректные значения. в этом примере принято, что если длина имени меньше 2 символов, переменной name присваивается строка "Undefined". аналогично, если передан недопустимый возраст, меньше 1 или больше 110, устанавливается значение по умолчанию.

сам объект Person создаётся вызовом приватного именованного генеративного конструктора `Person._create()`. для вызывающего кода разница между фабричным и обычным конструктором не видна: выражение `Person("Tom", 38)` выглядит одинаково в обоих случаях, поэтому замена одного на другой не ломает клиентский код.

### синглтон

особенно полезен фабричный конструктор при реализации синглтона, то есть объекта, который должен существовать в единственном экземпляре. синглтон также является паттерном проектирования, который гарантирует, что в программе существует только один объект данного типа. такие объекты применяются в самых разных областях, например подключение к базе данных нередко реализуется как синглтон.

общую форму синглтона в dart можно записать так:

```dart
class Singleton {
    Singleton._();
    static Singleton _instance = Singleton._();
    factory Singleton() => _instance;
}
```

в классе есть приватный конструктор, который можно вызвать только внутри библиотеки, где объявлен класс. единственный объект хранится в приватном статическом поле, которое инициализируется вызовом приватного конструктора. поскольку статические поля в dart инициализируются лениво, объект будет создан при первом обращении. фабричный конструктор просто возвращает значение этого статического поля.

пусть в приложении одновременно может быть залогинен только один пользователь. для представления пользователя определим в файле **user.dart** класс User:

```dart
class User{

    String name = "";       // логин для входа в приложение
    bool isLogged = false;     // залогинен ли пользователь
    static final User user = User._();

    User._();

    factory User.login(String name) {

        if(!user.isLogged){             // если пользователь не залогинен
            user.name = name;           // устанавливаем логи
            user.isLogged = true;       // указываем, что пользователь вошел в приложение
            print("Пользователь ${user.name} вошел в приложение");
        }
        else{ 
             // в фабричных конструкторах нельзя обращаться к this
            // print("С приложением уже работает ${this.name}");
            print("С приложением уже работает ${user.name}");
        }
        return user;
    }
    void info() {
        if(user.isLogged) print("Текущий пользователь ${user.name}");
    }
    // выход из приложения
    void logout(){
        print("${user.name} вышел из приложения");
        user.isLogged = false;
    }
}
```

для хранения логина, то есть имени пользователя, класс определяет переменную name. признак того, залогинен ли пользователь, хранится в переменной isLogged, по умолчанию равной false.

поскольку в системе может существовать только один пользователь, он представлен статическим полем user

```dart
static final User user = User._();
```

значение этого поля менять не планируется, поэтому оно объявлено как final-константа. неизменяемой при этом является только ссылка, состояние объекта (name и isLogged) меняется.

объект User создаётся приватным конструктором `User._()`, который доступен только в текущем файле класса.

в классе также определён именованный фабричный конструктор `User.login()`:

```dart
factory User.login(String name) {

    if(!user.isLogged){             // если пользователь не залогинен
        user.name = name;           // устанавливаем логи
        user.isLogged = true;       // указываем, что пользователь вошел в приложение
        print("Пользователь ${user.name} вошел в приложение");
    }
    else{ 
        // в фабричных конструкторах нельзя обращаться к this
        // print("С приложением уже работает ${this.name}");
        print("С приложением уже работает ${user.name}");
    }
    return user;
}
```

фабричный конструктор, как и обычный, может принимать параметры. здесь через параметр передаётся значение для name.

в теле конструктора проверяется, залогинен ли пользователь, то есть равна ли true переменная isLogged. если она равна false, значения name и isLogged изменяются. если пользователь уже вошёл в приложение, выводится соответствующее сообщение. в конце конструктор возвращает объект User.

фабричный конструктор всегда возвращает объект User из статической константы, и программа получает объект, существующий в единственном экземпляре.

в фабричных конструкторах нельзя обращаться к текущему объекту через ключевое слово **this**: фабричный конструктор выполняется в статическом контексте, и экземпляра, на который мог бы указывать this, на этот момент не существует:

```dart
// print("С приложением уже работает ${this.name}");
```

в функции main определяются две переменные этого класса:

```dart
import 'user.dart'; // подключаем класс User

void main (){
      
    User tom = User.login("Tom");
    User bob = User.login("Bob");
    bob.info();
}
```

консольный вывод:

```consoletext
Пользователь Tom вошел в приложение
С приложением уже работает Tom
Текущий пользователь Tom
```

по выводу видно, что обе переменные, tom и bob, ссылаются на один и тот же объект User, то есть `identical(tom, bob)` равно true. чтобы второй пользователь мог войти в приложение, первый должен выйти из него, вызвав метод logout:

```dart
import 'user.dart'; // подключаем класс User
void main (){
      
    User tom = User.login("Tom");
    tom.info();
    tom.logout();

    User bob = User.login("Bob");
    bob.info();
}
```

такая техника применяется прежде всего в различных вариантах кэширования: вместо того чтобы тратить ресурсы на создание нового объекта, фабричный конструктор берёт из кэша уже существующий, а если его там нет, создаёт новый и помещает в кэш.
