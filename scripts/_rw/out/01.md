для создания программы на dart достаточно файла с расширением `*.dart`, содержащего программный код. такой файл можно запустить средствами dart sdk или скомпилировать в исполняемую программу, как было показано в предыдущей лекции. dart sdk предлагает и другой способ: создание полноценного проекта командой **create**.

смысл проекта в том, что команда **create** формирует базовую структуру с готовой конфигурацией: описанием пакета, его зависимостей, правил статического анализа и каталогов для кода и тестов. для отдельного скрипта это избыточно, однако в крупных программах единая структура упрощает управление кодом, подключение библиотек и работу инструментов sdk.

для проекта выбирается каталог, в примере это **C:\dart**. в консоли командой **cd** выполняется переход в этот каталог, после чего запускается команда

```bash
dart create hello
```

после `create` указывается имя создаваемого проекта, здесь hello. имя проекта одновременно становится именем пакета, поэтому оно должно быть допустимым идентификатором dart в нижнем регистре. команда выводит список созданных файлов и дополнительную информацию:

```bash
C:\Users\eugen>cd c:\dart

c:\dart>dart create hello
Creating hello using template console...

  .gitignore
  analysis_options.yaml
  CHANGELOG.md
  pubspec.yaml
  README.md
  bin\hello.dart
  lib\hello.dart
  test\hello_test.dart

Running pub get...
  Resolving dependencies...
  Changed 46 dependencies!

Created project hello in hello! In order to get started, run the following commands:

  cd hello
  dart run


c:\dart>
```

из вывода видно, что после генерации файлов автоматически выполняется `pub get`: менеджер пакетов pub разрешает зависимости, перечисленные в pubspec.yaml, и загружает их.

### структура проекта

структура проекта по умолчанию выглядит так:

![создание первого проекта на языке программирования dart](/uploads/course-lectures/2a2d14e59e918ef0a98ed813c5ec56f3710240ec.png)

- .dart_tool : каталог служебных файлов, которые используют различные инструменты dart sdk.

- bin : каталог для исполняемых скриптов. по умолчанию содержит главный файл программы, скрипт hello.dart (назван по имени проекта) с функцией main, которая вызывается при запуске программы.

- lib : каталог для библиотек, которые затем импортируются и используются в других частях приложения. по умолчанию здесь создаётся файл hello.dart (с тем же именем, что и главный файл проекта) с демонстрационным содержимым. как правило, основная логика приложения размещается именно в этом каталоге. содержимое lib образует публичный интерфейс пакета: именно оно доступно через импорт вида `package:hello/...`.

- test : каталог для тестов. по умолчанию здесь создаётся файл hello_test.dart, тестирующий функциональность из файла `lib/hello.dart`.

- .gitignore : файл, в котором перечисляются файлы проекта, исключаемые из репозитория git, например на github.

- analysis_options.yaml : правила статического анализатора, которые помогают выявлять проблемы в программном коде (так называемый линтинг).

- CHANGELOG.md : журнал изменений проекта. при командной работе он позволяет всем участникам отслеживать, какие изменения были внесены.

- README.md : описание проекта.

- pubspec.yaml : манифест пакета, содержащий его имя, ограничение на версию sdk и список сторонних зависимостей (внешних библиотек), используемых в проекте.

программный код приложения в основном размещается в каталоге `lib` в файлах с расширением `.dart`. по умолчанию здесь уже есть файл `lib/hello.dart` со следующим кодом:

```dart
int calculate() {
  return 6 * 7;
}
```

здесь определена функция `calculate()`, вычисляющая произведение чисел 6 и 7. содержательного смысла этот код не несёт и служит для демонстрации того, как связаны и взаимодействуют части проекта. используется он в одноимённом файле `hello.dart` из каталога `bin`:

```dart
import 'package:hello/hello.dart' as hello;

void main(List<String> arguments) {
  print('Hello world: ${hello.calculate()}!');
}
```

все элементы этого кода подробно разбираются в последующих лекциях. для общего понимания достаточно следующего. сначала импортируется функциональность из файла `lib/hello.dart`:

```dart
import 'package:hello/hello.dart' as hello;
```

uri `package:hello/hello.dart` разрешается относительно каталога lib пакета hello, а конструкция `as hello` вводит префикс, через который доступны имена импортированной библиотеки. префикс ограничивает область видимости импортированных имён и исключает конфликты с именами из других библиотек.

далее определяется обязательная для программы на dart функция main:

```dart
void main(List<String> arguments) {
```

здесь используется вторая допустимая форма main: параметр `arguments` получает список аргументов командной строки, переданных программе при запуске.

в этой функции с помощью `print` на консоль выводится текст, а именно результат функции `calculate` из `lib/hello.dart`, подставленный в строку через интерполяцию:

```dart
print('Hello world: ${hello.calculate()}!');
```

### запуск проекта

для запуска проекта в консоли выполняется переход в каталог проекта и вызывается команда

```bash
dart run bin/hello.dart
```

здесь исполняется файл `bin/hello.dart`, содержащий функцию main. если вызвать `dart run` без аргументов, как предлагает вывод команды create, будет запущен скрипт из bin с именем пакета, то есть тот же файл. в результате на консоль выводится результат программы:

```bash
c:\dart\hello>dart run bin/hello.dart
Hello world: 42!

c:\dart\hello>
```

так создаются и запускаются проекты dart.

### типы проектов

выше был создан проект консольного приложения, простейший тип проекта. dart sdk поддерживает и другие шаблоны для разных задач:

- `console` : проект консольного приложения (шаблон по умолчанию)

- `package` : проект библиотеки dart

- `server-shelf` : проект серверного приложения, использующего `package:shelf`

- `web` : проект веб-приложения

шаблон задаётся опцией --template (-t) команды `dart create`, после которой указывается тип проекта. например, создание проекта веб-приложения:

```bash
dart create hello_web -t web
```

проект в этом случае называется "hello_web". в нём несколько больше каталогов и файлов, чем в проекте консольного приложения, но общий принцип работы с проектом тот же.
