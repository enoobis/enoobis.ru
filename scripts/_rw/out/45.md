### оператор throw

оператор **throw** позволяет явно сгенерировать исключение в нужном месте программы. в dart throw является выражением, а не только инструкцией, поэтому его можно использовать и там, где синтаксически ожидается значение, например в теле стрелочной функции или в правой части операции `??`. рассмотрим следующий код:

```dart
void main (){
     
	 try{
		Person tom = Person("Tom", -45);
		print(tom.age);
	}
	on Exception catch(e){
		 print(e);
	} 
}

class Person{
	String name;
	int age = 1;
	
	Person(this.name, age){
		if(age < 1 || age > 110) {
			throw Exception("Недопустимый возраст");
		}
		this.age = age;	// если возраст корректный, устанавливем его
	}
}
```

при создании нового пользователя, объекта класса Person, требуется предотвратить ситуацию, когда в конструктор передаётся недопустимое значение возраста, например отрицательное. для этого с помощью оператора throw генерируется исключение:

```dart
throw Exception("Недопустимый возраст");
```

в конструктор Exception передаётся сообщение, которое затем можно получить при обработке исключения. Exception объявлен как абстрактный тип с фабричным конструктором, и такой вызов возвращает экземпляр внутренней реализации, хранящей переданное сообщение.

в конструкторе Person есть две существенные детали. параметр age объявлен без типа и поэтому имеет тип `dynamic`, сравнение и присваивание полю проверяются только во время выполнения. поле age инициализировано значением 1 при объявлении, потому что поле ненулевого типа должно получить значение до начала выполнения тела конструктора, а присваивание `this.age = age` происходит уже в теле.

при выполнении следующей строки в блоке try возникает исключение:

```dart
Person tom = Person("Tom", -45);
```

а в блоке on..catch это исключение обрабатывается:

```dart
on Exception catch(e){
	print(e);
}
```

через параметр e в блоке catch можно получить сообщение об ошибке. консольный вывод:

```bash
Exception: Недопустимый возраст
```

### создание своих исключений

стандартная библиотека dart предоставляет большое количество типов ошибок и исключений. тем не менее для отдельных предметных ситуаций бывает нужно определить собственные типы исключений. в примере выше с возрастом пользователя всю информацию о нарушении можно оформить в виде отдельного исключения:

```dart
void main (){
     
	 try{
		Person tom = Person("Tom", -45);
		print(tom.age);
	}
	on AgeException catch(e){
		print(e);
		print(e.value);
	}
}

class Person{
	String name;
	int age = 1;
     
    Person(this.name, age){
		if(age < 1 || age > 110) {
			throw AgeException(age);	// генерируем исключение AgeException
		}
		this.age = age;
	}
}
class AgeException implements Exception{
    int value;
    AgeException(this.value);
    @override
    String toString() =>"Недопустимый возраст";
}
```

консольный вывод программы:

```bash
Недопустимый возраст
-45
```

здесь определён класс исключения AgeException, который реализует интерфейс типа Exception. формально можно определить класс и без реализации Exception, поскольку сгенерировать в dart можно любой ненулевой объект, однако реализация Exception сообщает о назначении класса и позволяет перехватывать его вместе с другими исключениями через `on Exception`. в классе определено собственное поле value, в котором хранится некорректное значение возраста, вызвавшее исключение. кроме того, переопределён унаследованный от `Object` метод **toString()**, который возвращает строковое представление объекта, а здесь сообщение об ошибке. аннотация `@override` фиксирует намерение переопределить метод, и анализатор выдаст предупреждение, если метода с такой сигнатурой в супертипе нет.

при обработке исключения этот метод используется для вывода сообщения об ошибке:

```dart
on AgeException catch(e){
	print(e);
	print(e.value);
}
```

параметр e в catch здесь имеет статический тип AgeException, поэтому у него можно обратиться к полю value. поскольку в классе AgeException переопределён метод toString(), объект этого класса можно вывести на консоль вызовом `print(e)`: print вызывает toString() у переданного объекта, и фактически выводится сообщение об исключении.
