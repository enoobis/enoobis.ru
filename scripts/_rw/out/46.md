язык dart, подобно большинству современных языков программирования, поддерживает асинхронное выполнение. потребность в асинхронности удобно пояснить на примере графического приложения для android. при запуске такое приложение работает в основном потоке пользовательского интерфейса, который обрабатывает все события интерфейса: нажатия кнопок, касания экрана, ввод текста в поля и т.д. однако работа приложения этим обычно не ограничивается. почтовый клиент, например, параллельно с действиями пользователя отправляет сетевые запросы: передаёт ранее написанные письма или опрашивает сервер на предмет новых. сетевой запрос может длиться долго, особенно при нестабильном соединении, поэтому такие запросы выполняются так, чтобы не блокировать основной поток. если бы запрос выполнялся в основном потоке, пользователь был бы вынужден ждать его завершения, а приложение на всё это время перестало бы реагировать на ввод. в корректно спроектированном приложении письмо отправляется, и пользователь сразу может начать писать следующее без заметных задержек интерфейса: сетевой запрос выполняется асинхронно, а о его завершении приложение сообщает уведомлением. в этом и состоит преимущество асинхронности, причём оно относится не только к сетевым запросам, но и к любым тяжеловесным операциям, способным занять продолжительное время.

сам dart является однопоточным языком в том смысле, что код одного изолята в каждый момент выполняет только одну задачу. асинхронное выполнение при этом обеспечивается циклом событий (event loop) и двумя очередями: очередью событий (event queue) и очередью микрозадач (microtask queue). очередь микрозадач предназначена для небольших внутренних задач и используется главным образом самой средой выполнения и библиотеками dart.

основная часть задач поступает в очередь событий: это внешние события, в частности события графического интерфейса (нажатие кнопки в графическом приложении), срабатывание таймеров, завершение операций чтения и записи файлов, получение данных от сетевых ресурсов и т.д.

при запуске любого приложения на dart начинает выполняться единственный поток приложения. этот поток работает в рамках сущности, которая называется **изолятом** (**isolate**). каждый изолят обладает собственной выделенной областью памяти (кучей), поэтому никакой другой изолят не может получить доступ к его состоянию. отсюда следует, что в модели изолятов не нужна сложная система блокировок и синхронизации доступа к разделяемым ресурсам, характерная для потоков java или c#, а данные одного изолята защищены от доступа из другого. по своей модели изоляты ближе к акторам, чем к потокам с общей памятью.

единственный поток приложения инициализирует две очереди, microtask и event, в которых хранятся задачи, ожидающие выполнения. затем поток вызывает функцию main() и прежде всего выполняет все синхронные инструкции. синхронные задачи в основном потоке всегда выполняются немедленно. если dart встречает длительную задачу, выполнение которой можно отложить, она помещается в очередь событий **event queue**.

после завершения синхронных задач цикл событий (**event loop**) проверяет очередь микрозадач **microtask queue**. если в ней есть задачи, цикл событий передаёт их в основной поток на выполнение.

когда синхронный код и все задачи из **microtask queue** выполнены, цикл событий начинает извлекать задачи из очереди **event queue** и передавать их в основной поток, где каждая из них выполняется синхронно, до конца.

если в **microtask queue** поступает новая микрозадача, цикл событий выполняет её раньше любой следующей задачи из **event queue**. иначе говоря, перед извлечением каждого очередного события очередь микрозадач опустошается полностью.

процесс продолжается до тех пор, пока обе очереди не станут пустыми.

например, когда приложение на dart считывает файл, сама операция ввода-вывода выполняется не в потоке приложения, а операционной системой. по завершении чтения система передаёт результат обратно в приложение, и dart помещает в очередь event queue код, который обработает результат считывания файла.

### класс Future

основной класс для описания асинхронных задач: **Future**. объект Future представляет результат отложенной операции, которая завершится в будущем. результатом операции может быть значение или ошибка. в терминологии других языков это аналог promise в javascript, `Task<T>` в c# или `CompletableFuture<T>` в java.

объект Future находится в одном из двух состояний: **незавершённом** (uncompleted) и **завершённом** (completed). в незавершённом состоянии операция, которую представляет Future, может уже выполняться, но её результат ещё не получен. в завершённом состоянии операция окончена и её результат, значение или ошибка, уже получен. переход из незавершённого состояния в завершённое происходит ровно один раз и необратим.

простейший пример:

```dart
Future getMessage() {
  // для эмуляции длительной операции делаем задержку в 3 секунды
  return Future.delayed(Duration(seconds: 3), () => print("Пришло новое сообщение от Тома"));
}

void main() {
  getMessage();
  print("Проверка сообщений...");
}
```

здесь определена функция getMessage, возвращающая объект **Future**. в ней вызывается один из именованных конструкторов класса Future: **Future.delayed()**. конструктор принимает два параметра. первый из них, объект Duration, задаёт время задержки (`Duration(seconds: 3)`), здесь три секунды. второй параметр: функция, выполняющая некоторое действие, в примере это вывод сообщения на консоль.

```dart
() => print("Пришло новое сообщение от Тома")
```

следовательно, через три секунды на консоль будет выведена строка "Пришло новое сообщение от Тома". это и есть отложенная операция, которую представляет объект Future.

в функции main сначала вызывается getMessage, а затем выводится ещё одно сообщение. несмотря на то что getMessage вызывается первой, консольный вывод программы оказывается следующим:

```bash
Проверка сообщений...
Пришло новое сообщение от Тома
```

функция getMessage сама по себе возвращает управление сразу, а отложенное действие выполняется лишь после того, как отработает весь остальной код main. то есть трёхсекундная операция выполняется асинхронно. при вызове getMessage возвращает объект Future в незавершённом состоянии, и только через три секунды, после выполнения функции, переданной в `Future.delayed`, он переходит в завершённое состояние.

механика работы Future такова, что операция, которую представляет новый объект Future (здесь получение сообщения), планируется для последующего выполнения и не исполняется в момент создания объекта. для `Future.delayed` планирование выполняется через таймер, и по его срабатыванию задача попадает в event queue. после того как функция main завершится, цикл событий извлекает эту операцию из event queue и выполняет её.

### конструкторы Future

для создания объекта Future служат следующие конструкторы:

- `Future(FutureOr<T> computation())`: создаёт объект Future, который с помощью метода Timer.run запускает функцию computation асинхронно и завершается её результатом. тип `FutureOr<T>` означает, что computation должна возвращать либо объект `Future<T>`, либо значение типа T. например, чтобы получить объект `Future<int>`, функция computation должна возвращать либо `Future<int>`, либо `int`. с точки зрения системы типов `FutureOr<T>` является объединением типов `T` и `Future<T>`, встроенным в язык специально для асинхронного кода.

- `Future.delayed(Duration duration, [FutureOr<T> computation()])`: создаёт объект Future, который выполняется после временной задержки, заданной первым параметром Duration. второй, необязательный параметр задаёт функцию, вызываемую по истечении задержки.

- `Future.error(Object error, [StackTrace stackTrace])`: создаёт объект Future, завершённый с ошибкой и содержащий информацию о ней.

- `Future.microtask(FutureOr<T> computation())`: создаёт объект Future, который с помощью функции scheduleMicrotask запускает функцию computation асинхронно и завершается её результатом. в отличие от обычного конструктора задача помещается в очередь микрозадач, а не в очередь событий.

- `Future.sync(FutureOr<T> computation())`: создаёт объект Future, содержащий результат функции computation, которая вызывается немедленно, синхронно.

- `Future.value([FutureOr<T> value])`: создаёт объект Future, содержащий значение value.

применение первого из перечисленных конструкторов:

```dart
void main() {
  Future myFuture = Future(() => print("Hello Future"));
  
  print("Main ends");
}
```

в конструктор Future передаётся анонимная функция без параметров, которая ничего не возвращает и лишь выводит сообщение. вместо анонимной функции можно передать и обычную именованную функцию. консольный вывод:

```bash
Main ends
Hello Future
```

практического смысла такая программа не имеет: выводить строку на консоль через Future незачем. однако уже здесь консольный вывод показывает, что сначала выполняется код в конце функции main и только затем действие, представленное объектом Future.

именованный конструктор `Future.delayed()` применяется аналогично, с той разницей, что перед вызовом функции из второго параметра он выжидает время, заданное первым параметром:

```dart
void main() {
  Future future = Future.delayed(Duration(seconds: 3), () => print("Hello Future"));
  print("Main ends");
}
```

конструктор `Future.value()` используется, когда значение, которое будет содержать Future, уже известно. в частности, он полезен при реализации веб-сервисов с кэшированием: при попадании в кэш результат возвращается через тот же асинхронный интерфейс, что и при реальном запросе.

```dart
Future future = Future.value(35);
```

здесь Future получает число 35, хотя на его месте может быть любой объект. впоследствии программа может извлечь это значение из future.

конструктор `Future.error()` принимает объект ошибки и необязательный параметр, трассировку стека:

```dart
Future future = Future.error(ArgumentError.notNull("input"));
```

в качестве объекта ошибки здесь используется выражение `ArgumentError.notNull("input")`, которое сообщает, что аргумент input не должен быть равен null. в dart выбросить можно любой ненулевой объект, а не только наследников некоторого базового класса исключений, как в java или c#.

### получение значения

на самом деле Future является обобщённым (generic) типом, параметризованным типом значения: `Future<T>`. параметр T в угловых скобках задаёт тип значения, которое несёт объект Future.

вернёмся к одному из примеров выше:

```dart
void main() {
  Future myFuture = Future(() => print("Hello Future"));
  
  print("Main ends");
}
```

функция, переданная в конструктор, ничего не возвращает и лишь выводит сообщение на консоль. поэтому фактически здесь получается не просто Future, а `Future<void>`. если тип не указан явно, как в примере, параметр типа выводится как dynamic, то есть переменная имеет тип `Future<dynamic>`. запись с явным типом выглядит так:

```dart
Future<void> myFuture = Future(() => print("Hello Future"));
```

изменим функцию так, чтобы она возвращала строку:

```dart
Future<String> myFuture = Future(() {
	return "Hello Future";
});
```

поскольку функция возвращает строку, объект Future будет содержать объект String и будет иметь тип `Future<String>`.

то же относится и к другим конструкторам:

```dart
void main() {
	Future<double> future1 = Future(() {
		return 23.5;	// возвращает число double
	});
	Future<String> future2 = Future.delayed(Duration(seconds: 3), 
						() => "Hello Future");		// возвращает строку
	Future<int> future3 = Future.value(35);			// хранит число int
	Future<String> future4 = Future.value("Hello Dart");	// хранит строку
  
  print("Main ends");
}
```
