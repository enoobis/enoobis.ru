обобщения (generics) делают код гибче и избавляют его от жёсткой привязки к конкретным типам. они нужны, когда функциональность должна одинаково работать с данными разных типов, то есть реализуют параметрический полиморфизм.



пусть определён класс пользователя, который хранит id (идентификатор пользователя):



```dart

class Person{
	int id;	// идентификатор пользователя
	String name; // имя пользователя
	Person(this.id, this.name);
}
```



здесь id имеет числовой тип и может принимать значения 2, 5, 7 и так далее. впоследствии может потребоваться использовать в качестве id строки или объекты других классов. один из способов уйти от жёсткой привязки к типу состоит в объявлении поля с типом dynamic:



```dart

class Person{
	dynamic id;	// идентификатор пользователя
	String name; // имя пользователя
	Person(this.id, this.name);
}
void main (){
	
	Person tom = Person(134, "Tom");
	print(tom.id);
	Person bob = Person("324", "Bob");
	print(bob.id);
}
```



тип dynamic отключает статическую проверку: какой объект реально хранится в поле id, заранее неизвестно, особенно если класс Person определён во внешней библиотеке сторонних разработчиков. попытка получить из такого поля число приводит к исключению:



```dart

Person bob = Person("324", "Bob");
int id = bob.id;	// Ошибка
```



компилятор этот код пропускает, поскольку неявное приведение из dynamic разрешено, а ошибка TypeError возникает только во время выполнения, когда выясняется, что в поле лежит строка.



можно завести отдельный вариант Person для каждого типа идентификатора:



```dart

class PersonInt{
	int id;
	String name;
	PersonInt(this.id, this.name);
}
class PersonString{
	string id;
	String name;
	PersonString(this.id, this.name);
}
```



(в классе PersonString тип поля id должен записываться как String, со строчной буквы такого типа в dart нет.) такой подход порождает другую проблему: дублирование кода.



обобщения одновременно обеспечивают безопасность типов и избавляют от дублирования. перепишем класс Person с использованием generics:



```dart

void main (){
	
	Person bob = Person("324", "Bob");
	print(bob.id.runtimeType);	// String
	Person sam = Person(123, "Sam");
	print(sam.id.runtimeType);	// int
}

class Person<T>{
	T id;	// идентификатор пользователя
	String name; // имя пользователя
	Person(this.id, this.name);
}
```



запись `<T>` после имени класса означает, что класс Person параметризован типом T. T называют параметром типа (универсальным параметром). имя параметра произвольно, но по соглашению используют заглавные буквы, чаще всего T. внутри класса T применяется как обычный тип, например, в объявлении переменных: `T id;`.



при использовании класса вместо T подставляется конкретный тип-аргумент. если он не указан явно, компилятор выводит его из контекста и из переданных аргументов. в примере выше переменные объявлены с «сырым» типом Person, который dart дополняет до Person<dynamic>, поэтому сам параметр T здесь равен dynamic, а конкретный тип значения видно лишь через поле **runtimeType**, возвращающее тип объекта во время выполнения. тип можно указать и явно:



```dart

Person<String> bob = Person<String>("324", "Bob");
print(bob.id.runtimeType);
Person<int> sam = Person<int>(123, "Sam");
print(sam.id.runtimeType);
```



тип-аргумент указывается в угловых скобках после имени класса (`Person<String>`). в отличие от java, где параметры типа стираются при компиляции, обобщения в dart реифицированы: тип-аргумент сохраняется во время выполнения, и проверка вида `bob is Person<String>` даёт осмысленный результат.





аналогично определяются обобщённые методы и функции. например, небольшая функция логирования:



```dart

void main (){
	
	int x = 20;
	log(x);
	x = 34;
	log(x);
	String name = "Tom";
	log(name);
}
void log<T>(T a){
	
	// DateTime.now() - получает текущую дату и время
	print("${DateTime.now()} a=$a");
}
```



у обобщённой функции параметр типа указывается в угловых скобках после её имени. затем универсальный тип T используется внутри функции как тип параметров или локальных переменных. при вызове `log(x)` тип-аргумент выводится из типа аргумента, явно его можно задать записью `log<int>(x)`.



### ограничения обобщений



иногда обобщение нужно, но подстановка вместо T произвольного типа нежелательна. например, класс Account описывает банковский счёт:



```dart

class Account{

    int id; 	// номер счета
    int sum; 	// сумма на счете
    Account(this.id, this.sum);
}
```



для перевода средств между счетами можно определить класс Transaction, который выполняет все операции над объектами класса Account.



у класса Account может быть много наследников: DepositAccount (депозитный счёт), DemandAccount (счёт до востребования) и т.д. заранее неизвестно, какие именно типы счетов будут использоваться в Transaction, например, транзакции могут проводиться только между счетами до востребования. поэтому параметр типа ограничивают сверху типом Account:



```dart

class Transaction<T extends Account>{

    T fromAccount;  // с какого счета перевод
    T toAccount;    // на какой счет перевод
    int sum;        // сумма перевода
	Transaction(this.fromAccount, this.toAccount, this.sum);
    void execute(){
	
        if (fromAccount.sum > sum){
            fromAccount.sum -= sum;
            toAccount.sum += sum;
            print("Счет ${fromAccount.id}: ${fromAccount.sum}\$ \nСчет ${toAccount.id}: ${toAccount.sum}\$");
        }
        else
        {
            print("Недостаточно денег на счете ${fromAccount.id}");
        }
    }
}
```



запись `<T extends Account>` требует, чтобы тип T был классом Account или его подтипом. благодаря такому ограничению (верхней границе) внутри Transaction все значения типа T можно использовать как объекты Account и обращаться к их полям и методам, и это проверяется статически. без явной границы параметр типа ограничен типом Object?, и обращаться к членам Account было бы нельзя.



применение класса Transaction:



```dart

void main (){
	
	Account acc1 = Account(1857, 4500); // sum = 4500;
    Account acc2 = Account(3453, 5000); // sum = 5000;
	Transaction transaction = Transaction<Account>(acc1, acc2, 1900);
	transaction.execute();
}
```



консольный вывод:



```bash

Счет 1857: 2600$
Счет 3453: 6900$
```



### наследование обобщённых классов



обобщённые классы, как и обычные, могут наследоваться, и здесь есть свои особенности. если унаследованная функциональность должна остаться обобщённой, производный класс тоже объявляется обобщённым:



```dart

void main (){
	
	Employee bob = Employee(123, "Bob", "Google");
	bob.display();
}

class Person<T>{
	T id;	// идентификатор пользователя
	String name; // имя пользователя
	Person(this.id, this.name);

    void display() => print("id: $id \t name: $name");
}
class Employee<T> extends Person<T>{
	String company;
	Employee(super.id, super.name, this.company);
	@override
	void display(){
		super.display();
		 print("Works in $company");
	}
}
```



класс Employee здесь тоже обобщённый: его параметр T передаётся в суперкласс Person<T>, поэтому в конструктор Employee в качестве id можно передать значение любого типа.



можно и зафиксировать тип-аргумент при наследовании, то есть унаследовать класс, параметризованный конкретным типом:



```dart

void main (){
	
	Employee bob = Employee(123, "Bob", "Google");
	bob.display();
}

class Person<T>{
	T id;	// идентификатор пользователя
	String name; // имя пользователя
	Person(this.id, this.name);

    void display() => print("id: $id \t name: $name");
}
class Employee extends Person<int>{
	String company;
	Employee(super.id, super.name, this.company);
	@override
	void display(){
		super.display();
		 print("Works in $company");
	}
}
```



теперь Employee наследует Person, параметризованный типом int. Employee уже не обобщённый класс, и унаследованное поле id в нём имеет тип int.
