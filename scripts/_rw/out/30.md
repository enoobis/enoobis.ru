в программе часто возникает ситуация, когда имеется объект одного типа, а логика требует рассматривать его как объект другого типа. часть преобразований dart выполняет автоматически и неявно, другие требуют явной записи. одни преобразования допустимы, другие невозможны в принципе. ниже разбираются оба случая и средства проверки типа во время выполнения.

### неявные преобразования

экземпляр производного класса одновременно является экземпляром базового класса: в терминах теории типов производный класс задаёт подтип базового. поэтому dart неявно приводит значения производных типов к базовому типу, и такое приведение (upcast) всегда безопасно, его корректность проверяется во время компиляции. в качестве примера используются следующие классы:

```dart
// класс человека 
class Person{
  
    String name;
    Person(this.name);
    void display() => print("Person $name");
}
// класс работника
class Employee extends Person{

    String company;
    Employee(super.name, this.company);
    @override
    void display() => print("Employee $name works in $company");
}
// класс студента
class Student extends Person{

    String university;
    Student(super.name, this.university);
    @override
    void display() => print("Student $name studies in $university");
}
```

базовый класс Person описывает человека и хранит имя в поле name. производные классы Employee и Student расширяют его: Employee описывает работника и хранит в поле company название компании, Student описывает студента и хранит в поле university название вуза. поскольку оба класса унаследованы от Person, любой экземпляр Student или Employee является также экземпляром Person, и его можно присвоить переменной типа Person:

```dart
void main (){
     
    Person bob = Employee("Bob", "Google");
    bob.display();  // Employee Bob works in Google

    Person sam = Student("Sam", "MIT");
    sam.display();  // Student Sam studies in MIT
}
```

статический тип переменной bob здесь Person, а динамический тип хранимого объекта Employee. объект Employee неявно приводится к типу Person. при вызове метода display у этого объекта:

```dart
bob.display();  // Employee Bob works in Google
```

выполняется реализация из класса Employee, поскольку bob ссылается на объект Employee. вызов экземплярного метода в dart диспетчеризуется динамически, по типу объекта во время выполнения, а статический тип переменной определяет лишь, какие члены доступны для вызова на этапе компиляции. то же относится к переменной sam: её статический тип Person, но она хранит ссылку на объект Student.

из этого следует принцип подстановки: везде, где ожидается объект базового класса, допустимо передать объект производного класса. например, функция принимает параметр типа Person:

```dart
void printName(Person person)
{
    print(person.name);
}

void main (){
     
    Person tom = Person("Tom");
    Employee bob = Employee("Bob", "Google");
    Student  sam = Student("Sam", "MIT");
    printName(tom);
    printName(bob); // неявное преобразование от Employee к Person
    printName(sam); // неявное преобразование от Student к Person
}
```

поскольку Student и Employee наследуют Person, их экземпляры можно передать в функцию printName, параметр которой имеет тип Person.

### явные преобразования и оператор as

приведение от производного класса (Employee или Student) к базовому (Person) выполняется автоматически. обратное направление, от базового типа к производному (downcast), в общем случае небезопасно, так как не всякий объект базового класса принадлежит производному типу. такое преобразование записывается явно с помощью оператора **as**:

```dart
объект as тип;
```

слева от оператора указывается преобразуемое выражение, справа целевой тип. результатом служит то же самое значение, но со статическим типом, указанным справа. новый объект при этом не создаётся, as лишь проверяет тип во время выполнения. например:

```dart
void printCompany(Person person)
{
    Employee emp = person as Employee; // преобразуем Person в Employee
    print(emp.company);
}

void main (){
     
    Person bob = Employee("Bob", "Google");
    printCompany(bob);  // Google
}
```

функция printCompany принимает объект Person, приводит его к типу Employee и выводит поле company преобразованного объекта:

```dart
Employee emp = person as Employee;
```

может показаться странным, что объект Employee сначала неявно приводится к Person, а внутри функции обратно к Employee. на практике данные нередко приходят извне, и конкретный производный тип объекта заранее неизвестен, поэтому в сигнатуре фигурирует общий базовый тип Person.

отсюда возникает другая проблема: в printCompany можно передать объект Person, который не является экземпляром Employee:

```dart
void printCompany(Person person)
{
    Employee emp = person as Employee;
    print(emp.company);
}

void main (){
     
    Person tom = Person("Tom");
    printCompany(tom);  // ! Ошибка
}
```

переменная tom не ссылается на объект Employee, поэтому привести её к Employee и прочитать поле company невозможно. компилятор такую ошибку не обнаруживает, проверка as происходит во время выполнения и при несовпадении типа выбрасывает исключение TypeError, на котором выполнение функции прерывается. чтобы этого избежать, перед явным преобразованием тип проверяют оператором **is**.

### проверка типа и оператор is

оператор **is** возвращает `true`, если объект принадлежит указанному типу, то есть его динамический тип совпадает с указанным или является его подтипом:

```dart
объект is тип
```

противоположный оператор **is!** возвращает `true`, если объект указанному типу не принадлежит:

```dart
объект is! тип
```

применение оператора:

```dart
void printCompany(Person person)
{
    if(person is Employee){     // если person представляет класс Employee

        Employee emp = person as Employee;
        print(emp.company);
    } 
    else{
        print("person is not Employee");
    }
}

void main (){
     
    Person bob = Employee("Bob", "Google");
    printCompany(bob);  // Google

    Person tom = Person("Tom");
    printCompany(tom);  // person is not Employee
}
```

стоит учитывать механизм продвижения типов (type promotion) в dart: если локальная переменная или параметр проверены через is, то внутри ветки if анализатор уже считает их значением проверенного типа. поэтому в примере выше явное as формально избыточно, и к person.company можно обращаться напрямую. продвижение работает для локальных переменных и параметров, а для полей класса в общем случае нет, поскольку значение поля может измениться между проверкой и обращением.

аналогично проверяются и другие типы:

```dart
void printPerson(Person person)
{
    print(person.name);
    if(person is Employee){     // если тип - Employee

        Employee emp = person as Employee;
        print(emp.company);
    } 
    else if(person is Student){ // если тип - Student

        Student student = person as Student;
        print(student.university);
    } 
}

void main (){
     
    Person tom = Person("Tom");
    printPerson(tom);  // person is not Employee

    Person bob = Employee("Bob", "Google");
    printPerson(bob);  // Google

    Person sam = Student("Sam", "MIT");
    printPerson(sam);  // MIT
}
```
