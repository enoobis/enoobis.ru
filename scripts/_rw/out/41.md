класс **Iterable<E>** является базовым типом для других коллекций, в частности для `List` и `Set`, и задаёт их общую функциональность. абстракция `Iterable` описывает последовательность элементов, которую можно обойти с помощью итератора (`Iterator<E>`), и именно этот контракт используется циклом `for-in`. ниже разбираются общие методы, которые `Iterable` предоставляет всем производным коллекциям. большинство из них являются функциями высшего порядка: они принимают другую функцию в качестве аргумента.



### фильтрация элементов



метод **where()** выбирает элементы, удовлетворяющие условию. результатом метода является отфильтрованная последовательность `Iterable`:



```dart
where(bool test(E element)) -> Iterable<E>
```



условие фильтрации задаётся функцией-предикатом, которая передаётся в where в качестве параметра. в примере выбираются строки длиной 3 символа:



```dart


void main (){

	

    var list = ["Tom", "Alice", "Bob", "Sam", "Kate"];

    var new_list = list.where((item)=> item.length==3);

    print(new_list);   // (Tom, Bob, Sam)

}
```



тип элемента в результате сохраняется: new_list имеет статический тип `Iterable<String>`. круглые скобки в выводе показывают, что это не список, а ленивая последовательность.



### преобразование



метод **map()** преобразует элементы коллекции:



```dart
map<T>(T toElement(E e)) -> Iterable<T>
```



метод принимает функцию преобразования. в неё по очереди передаётся каждый элемент коллекции, а возвращает она преобразованное значение. результатом **map()** является новая последовательность из преобразованных значений, тип элементов которой T может отличаться от исходного E. одноимённый метод есть и у класса `Map`, хотя там он работает с парами ключ - значение и возвращает новый словарь. пример:



```dart


void main (){

	const numbers = [1, 2, 3, 4];

    final squares = numbers.map((n) => n * n);

    print(squares);     // (1, 4, 9, 16)

}
```



в метод map передаётся анонимная функция `(n) => n * n`. параметр n обозначает элемент списка, результатом функции является квадрат числа. в итоге squares представляет последовательность `(1, 4, 9, 16)`.



### reduce: сведение элементов



метод **reduce()** сводит элементы коллекции к одному значению. в функциональном программировании эта операция называется свёрткой.



```dart
reduce(E combine(E value, E element)) -> E
```



метод принимает функцию с двумя параметрами. первый параметр содержит накопленное значение, второй текущий элемент коллекции. тип накопленного значения совпадает с типом элементов E. в примере вычисляется сумма элементов списка:



```dart


void main (){

	const numbers = [1, 2, 3, 4];

    final sum = numbers.reduce((total, element) => total += element);

    print(sum);     // 10

}
```



в reduce передаётся анонимная функция



```dart
(total, element) => total += element
```



параметр total содержит накопленное значение, которое в итоге вернёт reduce, второй параметр содержит текущий элемент. функция прибавляет к total значение текущего элемента. в качестве начального значения total берётся первый элемент коллекции, после чего функция последовательно вызывается для всех остальных элементов, так что каждый из них прибавляется к total, и в результате получается сумма. присваивание `+=` здесь избыточно: изменяется лишь локальный параметр функции, а в reduce попадает значение выражения, поэтому запись `total + element` дала бы тот же результат.



### fold



метод **fold()** также сводит все элементы коллекции к одному значению.



```dart
fold<T>(T initialValue, T combine(T previousValue, E element)) -> T
```



в отличие от `reduce()`, метод **fold()** принимает начальное значение. это нужно, если коллекция может оказаться пустой. кроме того, тип результата T у fold не обязан совпадать с типом элементов E, так что, например, из списка строк можно получить число.



первый параметр **fold()** задаёт начальное значение, второй функцию, аналогичную функции в `reduce()`. пример:



```dart


void main (){

	const numbers = <int>[];

    final sum = numbers.fold(0, (total, element) => total += element);

    print(sum);     // 0

}
```



в fold передаётся та же функция суммирования, что и в примере с reduce, но дополнительно задано начальное значение 0. коллекция numbers пуста, поэтому fold возвращает 0.



если бы в этом случае использовался reduce, а не fold:



```dart
final sum = numbers.reduce((total, element) => total += element);
```



то программа завершилась бы ошибкой во время выполнения: у пустой коллекции нет первого элемента, который мог бы стать начальным значением, и reduce генерирует `StateError`.




### проверка элементов



методы **every()** и **any()** проверяют, удовлетворяют ли элементы условию, которое передаётся в метод в виде функции:



```dart


any(bool test(E element)) -> bool

every(bool test(E element)) -> bool
```



метод `any()` возвращает `true`, если условию удовлетворяет хотя бы один элемент, а `every()` возвращает `true`, если условию удовлетворяют все элементы. соответствуют они кванторам существования и всеобщности. оба метода прекращают перебор, как только результат становится известен. для пустой коллекции any возвращает `false`, а every возвращает `true`, что согласуется с логикой кванторов на пустом множестве.



```dart


void main (){

	var list = ["Tom", "Bob", "Sam", "Kate"];

    

    print(list.every((element)=>element.length > 2));    // true

    print(list.every((element)=>element.length > 3));   // false



    print(list.any((element)=>element.length > 3));    // true

    print(list.any((element)=>element.length > 4));   // false

}
```



### пропуск элементов



метод **skip()** пропускает заданное количество элементов.



```dart
skip(int count) -> Iterable<E>
```



в качестве параметра передаётся количество пропускаемых элементов. результатом являются все элементы коллекции, кроме пропущенных:



```dart


void main (){

	var list = ["Tom", "Bob", "Sam", "Kate", "Alice"];

    var new_list = list.skip(2);    // пропускаем 2 первых элемента

    print(new_list);    // (Sam, Kate, Alice)

}
```




метод **skipWhile()** пропускает элементы с начала коллекции, пока они удовлетворяют условию.



```dart
skipWhile(bool test(E value)) -> Iterable<E>
```



в качестве параметра передаётся функция-условие. результатом являются все элементы коллекции, кроме пропущенных:



```dart


void main (){

	var list = ["Tom", "Bob", "Kate", "Alice", "Sam"];

    var new_list = list.skipWhile((elem) => elem.length==3);  // пропускаем первые строки с длиной в 3 символа

    print(new_list);    // (Kate, Alice, Sam)

}
```



элементы пропускаются до первого элемента, не удовлетворяющего условию, после чего условие больше не проверяется. поэтому строка "Sam", которая условию удовлетворяет, но стоит в конце, попадает в результат. в этом skipWhile принципиально отличается от фильтрации через where.




### взятие элементов



метод **take()** берёт из коллекции заданное количество элементов.



```dart
take(int count) -> Iterable<E>
```



в качестве параметра передаётся количество извлекаемых элементов. результатом является новая последовательность:



```dart


void main (){

	var list = ["Tom", "Bob", "Kate", "Alice", "Sam"];

    var new_list = list.take(3);    // берем 3 первых элемента

    print(new_list);    // (Tom, Bob, Kate)

}
```




метод **takeWhile()** извлекает элементы с начала коллекции, пока они удовлетворяют условию.



```dart
takeWhile(bool test(E value)) -> Iterable<E>
```



в качестве параметра передаётся функция-условие. результатом являются извлечённые элементы в виде новой последовательности:



```dart


void main (){

	var list = ["Tom", "Bob", "Kate", "Alice", "Sam"];

    var new_list = list.takeWhile((elem) => elem.length==3);  // берем первые строки с длиной в 3 символа

    print(new_list);    // (Tom, Bob)

}
```



элементы извлекаются до первого элемента, не удовлетворяющего условию. поэтому строка "Sam", которая условию удовлетворяет, но стоит в конце, в результат не попадает.




### цепочки методов



методы, которые возвращают новый объект **Iterable** (например, map или where), выполняются отложенно, то есть лениво. вызов такого метода лишь строит описание вычисления, а реальная работа происходит в момент, когда элементы действительно запрашиваются: при обращении к конкретному элементу, при переборе в цикле, при вызове `toList()` или выводе на консоль. за счёт этого можно строить цепочки методов, которые выполняют над данными сразу несколько операций без создания промежуточных коллекций. аналогичную модель используют потоки java (`Stream`) и linq в c#.



в примере данные выбираются по условию и затем преобразуются:



```dart


class Person{

    String name;

    Person(this.name);

}



void main (){

	var people = [Person("Tom"), Person("Bob"), Person("Kate"), Person("Alice"), Person("Sam")];

    var new_people = people

                        .where((person) => person.name.length == 3)  // выбираем, если длина имени - 3 символа

                        .map((person) => person.name);               // преобразуем объекты Person в строки

    print(new_people);    // (Tom, Bob, Sam)

}
```



здесь имеется список people из объектов Person. к нему применяется метод `where()`, который выбирает объекты Person с именем из 3 символов. к результату применяется метод `map()`, который извлекает из объектов Person их имена и помещает их в результирующую последовательность. статический тип new_people выводится как `Iterable<String>`.



реальное выполнение этих методов происходит только при обращении к данным, здесь при выводе на консоль:



```dart
print(new_people);    // (Tom, Bob, Sam)
```



это легко проследить, если добавить в функции вывод на консоль:



```dart


class Person{

    String name;

    Person(this.name);

}



void main (){

	var people = [Person("Tom"), Person("Bob"), Person("Kate"), Person("Alice"), Person("Sam")];

    var new_people = people

                        .where((person){

                                    print("where for ${person.name}");

                                    return person.name.length == 3;

                                })

                        .map((person){

                                print("map for ${person.name}");

                                return person.name;

                            });

    print("Test where and map");

    print(new_people);    // (Tom, Bob, Sam)

}
```



консольный вывод:



```bash


Test where and map

where for Tom

map for Tom

where for Bob

map for Bob

where for Kate

where for Alice

where for Sam

map for Sam

(Tom, Bob, Sam)
```



строка "Test where and map" выводится первой, хотя where и map вызваны раньше. кроме того, вызовы чередуются поэлементно: каждый элемент проходит всю цепочку, прежде чем обрабатывается следующий, и map вызывается только для элементов, прошедших фильтр. у ленивости есть и обратная сторона: при каждом новом переборе new_people вся цепочка вычисляется заново. если результат нужен многократно, его материализуют вызовом `toList()`.



другой пример цепочки методов: постраничная навигация по данным.



```dart


void main (){

	var people = ["Tom", "Bob", "Kate", "Alice", "Sam"];

    var page2 = people.skip(2).take(2); // пропускаем 2 элемента и берем 2 элемента (3 и 4-й)

    print(page2);    // (Kate, Alice)

}
```
