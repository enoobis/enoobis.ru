начиная с версии 3.0 в dart появилось **pattern matching**, или сопоставление с образцом. шаблон (паттерн) описывает форму множества значений, с которой сопоставляется фактическое значение. сопоставление отвечает на два вопроса: соответствует ли значение заданной форме и, если соответствует, как разложить его на составные части. идея заимствована из функциональных языков семейства ml и haskell и близка к сопоставлению с образцом в scala, kotlin и c#.

простейший вид сопоставления с образцом представляет сопоставление с литералами в конструкции **switch**:

```dart
void main() {
    int num = 2;
    switch(num){
                 
        case 1: 
            print("num = 1");
        case 2: 
            print("num = 2");
        case 3: 
            print("num = 3");
        default:
            print("num is undefined");
    }
}
```

выражение case задаёт шаблон, с которым сопоставляется значение. здесь значение переменной num сопоставляется с рядом константных значений, представленных целочисленными литералами 1, 2, 3. такой константный паттерн проверяет равенство через оператор `==`. если сопоставление успешно (значение num равно одному из литералов), выполняется код соответствующего блока case. в dart 3 непустой блок case не переходит в следующий, поэтому `break` не требуется.

однако возможности pattern matching этим не ограничиваются. ниже рассматриваются другие виды шаблонов.

### сопоставление с константами

значение можно сопоставлять не только с литералами, но и с именованными константами:

```dart
void main() {
    int num = 2;
    const int a = 1, b =2, c = 3;

    switch(num){   
        case a: 
            print("num = a");
        case b: 
            print("num = b");
        case c: 
            print("num = c");
        default:
            print("num is undefined");
    }
}
```

здесь значение переменной num сопоставляется с константами a, b, c. a, b и c обязаны быть константами времени компиляции: идентификатор в позиции шаблона case трактуется как константный паттерн, и обычная переменная в этом месте вызовет ошибку компиляции. это ограничение позволяет компилятору проверять шаблоны статически.

### возвращение результата

конструкция **switch** может использоваться и как выражение, возвращающее значение. до dart 3 для этого приходилось возвращать значение из каждого блока case оператором **return**. например:

```dart
void main() {
    
    print(createMessage("english"));    // Hello
    print(createMessage("russian"));    // Привет
    print(createMessage("spanish"));    // Hello World
}

String createMessage(String language)
{
    switch(language)
    {
        case "english": 
            return "Hello";
        case "russian":
            return "Привет";
        case "german":
            return "Hallo";
        default: return "Hello World";
    };
}
```

функция createMessage принимает название языка и передаёт его в конструкцию switch. значение language сопоставляется с рядом значений, и в зависимости от результата оператор return в соответствующем блоке case возвращает ту или иную строку.

пример работает корректно, но конструкция switch в нём громоздка. dart 3 позволяет записать её короче с помощью switch-выражения:

```dart
void main() {
    
    print(createMessage("english"));    // Hello
    print(createMessage("russian"));    // Привет
    print(createMessage("spanish"));    // Hello World
}

String createMessage(String language)
{
    return switch(language)
    {
        "english" => "Hello",
        "russian" => "Привет",
        "german" => "Hallo",
        _ => "Hello World"
    };
}
```

теперь оператор **return** указан один раз, перед конструкцией `switch`. ключевое слово **case** внутри неё не используется: вместо него указываются сами шаблоны, с которыми сопоставляется значение language, здесь это строковые литералы. после шаблона ставится оператор `=>`, за которым следует возвращаемое значение:

```dart
"english" => "Hello",
```

отдельные ветви отделяются друг от друга запятой, а не точкой с запятой, поскольку каждая ветвь является выражением, а не оператором.

отдельно рассмотрим последний шаблон:

```dart
_ => "Hello World"
```

шаблон **_** (wildcard) сопоставляется с любым значением и задаёт ветвь для всех остальных случаев, аналогично блоку `default`. для switch-выражения он здесь необходим: switch-выражение обязано быть исчерпывающим, то есть покрывать все возможные значения типа, иначе компилятор выдаст ошибку. множество строк бесконечно, поэтому без ветви `_` исчерпываемость недостижима.

в результате код стал компактнее, а сама конструкция приобрела статус выражения, которое можно использовать везде, где ожидается значение.
