интерфейсы, как и классы, могут наследоваться: производный интерфейс расширяет контракт базового.

```c#


interface IAction

{

	void Move();

}

interface IRunAction : IAction

{

	void Run();

}

class BaseAction : IRunAction

{

	public void Move()

	{

		Console.WriteLine("Move");

	}

	public void Run()

	{

		Console.WriteLine("Run");

	}

}
```

при применении `IRunAction` класс `BaseAction` обязан реализовать методы и свойства интерфейса `IRunAction` и методы и свойства базового интерфейса `IAction`, если у этих членов нет реализации по умолчанию.

в отличие от классов, к интерфейсам нельзя применить модификатор **sealed**, чтобы запретить наследование интерфейсов.

к интерфейсам нельзя применить и модификатор **abstract**. интерфейс и без этого, как правило, предоставляет абстрактную функциональность, которую реализует класс или структура (исключение составляют методы и свойства с реализацией по умолчанию).

методы интерфейсов могут использовать служебное слово **new**, чтобы скрыть методы базового интерфейса:

```c#


IAction action1 = new RunAction();

action1.Move(); // I am moving



IRunAction action2 = new RunAction();

action2.Move(); // I am running



interface IAction

{

    void Move() => Console.WriteLine("I am moving");

}

interface IRunAction : IAction

{

    // скрываем реализацию из IAction

    new void Move() => Console.WriteLine("I am running");

}

class RunAction : IRunAction { }
```

метод `Move` из `IRunAction` скрывает метод `Move` из базового интерфейса `IAction`. это имеет смысл, когда в базовом интерфейсе задана реализация по умолчанию, как в примере выше, и её нужно заменить для производного контракта. если переменная имеет тип `IRunAction`, для `Move` вызывается реализация этого интерфейса:

```c#


IRunAction action2 = new RunAction();

action2.Move(); // I am running
```

если же переменная имеет тип `IAction`, для `Move` применяется реализация этого интерфейса:

```c#


IAction action1 = new RunAction();

action1.Move(); // I am moving
```

класс `RunAction` может задать собственный `Move` сразу для обоих интерфейсов. публичный метод класса сопоставляется и со скрывающим членом, и с членом базового интерфейса, и тело по умолчанию больше не выбирается:

```c#


IAction action1 = new RunAction();

action1.Move(); // I am tired



IRunAction action2 = new RunAction();

action2.Move(); // I am tired



interface IAction

{

    void Move() => Console.WriteLine("I am moving");

}

interface IRunAction : IAction

{

    new void Move() => Console.WriteLine("I am running");

}

class RunAction : IRunAction

{

    public void Move() => Console.WriteLine("I am tired");

}
```

при наследовании интерфейсов, как и при наследовании классов, производный интерфейс должен иметь тот же уровень доступа или более строгий, чем базовый интерфейс.

```c#


public interface IAction

{

	void Move();

}

internal interface IRunAction : IAction

{

	void Run();

}
```

обратное объявление даёт ошибку, и программа не компилируется: производный интерфейс имеет менее строгий уровень доступа, чем базовый.

```c#


internal interface IAction

{

	void Move();

}

public interface IRunAction : IAction	// ошибка IRunAction может быть только internal

{

	void Run();

}
```
