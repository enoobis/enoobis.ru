кроме неявного применения интерфейсов, разобранного в предыдущей лекции, существует явная реализация. при ней имя метода или свойства указывают вместе с именем интерфейса. модификаторы доступа при такой реализации запрещены:

```c#


interface IAction

{

	void Move();

}

class BaseAction : IAction

{

	void IAction.Move() => Console.WriteLine("Move in Base Class");

}
```

при явной реализации методы и свойства интерфейса не входят в состав членов класса. напрямую через объект класса к ним не обратиться:

```c#


BaseAction baseAction1 = new BaseAction();



// baseAction1.Move();  // ! Ошибка - в BaseAction нет метода Move

// необходимо приведение к типу IAction

// небезопасное приведение

((IAction)baseAction1).Move();   

// безопасное приведение 

if (baseAction1 is IAction action) action.Move();

// или так

IAction baseAction2 = new BaseAction();

baseAction2.Move();
```

явная реализация нужна, когда класс применяет несколько интерфейсов, а у них один и тот же метод с одним и тем же типом результата и одним и тем же набором параметров. неявная реализация тогда одна на оба контракта:

```c#


class Person : ISchool, IUniversity

{

    public void Study() => Console.WriteLine("Учеба в школе или в университете");

}

interface ISchool

{

    void Study();

}

interface IUniversity

{

    void Study();

}
```

класс `Person` определяет один метод `Study()` и тем даёт общую реализацию обоим интерфейсам. результат один и тот же независимо от того, рассматривается объект `Person` как `ISchool` или как `IUniversity`.

чтобы разграничить реализуемые интерфейсы, их применяют явно:

```c#


class Person : ISchool, IUniversity

{

    void ISchool.Study() => Console.WriteLine("Учеба в школе");

    void IUniversity.Study() => Console.WriteLine("Учеба в университете");

}
```

использование:

```c#


Person person = new Person();



((ISchool)person).Study();

((IUniversity)person).Study();
```

другая ситуация: базовый класс уже реализовал интерфейс, а производному классу нужна своя реализация того же интерфейса.

```c#


interface IAction

{

    void Move();

}

class BaseAction : IAction

{

    public void Move() =>Console.WriteLine("Move in BaseAction");

}

class HeroAction : BaseAction, IAction

{

    void IAction.Move() => Console.WriteLine("Move in HeroAction");

}
```

базовый класс `BaseAction` уже реализовал интерфейс `IAction`, но производный класс реализует его по-своему и заменяет запись в карте интерфейса. применение классов:

```c#


HeroAction action1 = new HeroAction();

action1.Move();            // Move in BaseAction

((IAction)action1).Move(); // Move in HeroAction



IAction action2 = new HeroAction();

action2.Move();             // Move in HeroAction
```

### модификаторы доступа

члены интерфейса могут иметь разные модификаторы доступа. если модификатор отличен от `public`, при реализации метода, свойства или события в классах и структурах есть два способа. первый: явная реализация всех нужных членов интерфейса без модификаторов доступа.

```c#


IMovable tom = new Person("Tom");

// подписываемся на событие

tom.MoveEvent += () => Console.WriteLine($"{tom.Name} is moving");

tom.Move();



delegate void MoveHandler();    // делегат перемещения

interface IMovable

{

    protected internal void Move();

    protected internal string Name { get;}

    protected internal event MoveHandler MoveEvent;

}

class Person : IMovable

{

    string name;

    // явная реализация события - дополнительно создается переменная

    MoveHandler? moveEvent;

    event MoveHandler IMovable.MoveEvent

    {

        add => moveEvent += value;

        remove => moveEvent -= value;

    }

    // явная реализация свойства - в виде автосвойства

    string IMovable.Name { get => name; }

    public Person(string name) => this.name = name;

    // явная реализация метода

    void IMovable.Move()

    {

        Console.WriteLine($"{name} is walking");

        moveEvent?.Invoke();

    }

}
```

к таким методам, свойствам и событиям обращаются через переменную интерфейса, но не через переменную класса.

альтернатива: неявная реализация с модификатором **public**.

```c#


Person tom = new Person("Tom");

// подписываемся на событие

tom.MoveEvent += () => Console.WriteLine($"{tom.Name} is moving");

tom.Move();



delegate void MoveHandler();



interface IMovable

{

    protected internal void Move();

    protected internal string Name { get;}

    protected internal event MoveHandler MoveEvent;

}

class Person : IMovable

{

    string name;

    // явная реализация события - дополнительно создается переменная

    MoveHandler? moveEvent;

    // неявная реализация события с модификатором public

    public event MoveHandler MoveEvent

    {

        add => moveEvent += value;

        remove => moveEvent -= value;

    }

    // неявная реализация свойства - в виде автосвойства, но с модификатором public

    public string Name { get => name; }

    public Person(string name) => this.name = name;

    // неявная реализация метода, но с модификатором public 

    public void Move()

    {

        Console.WriteLine($"{name} is walking");

        moveEvent?.Invoke();

    }

}
```

в этом варианте к методам, свойствам и событиям интерфейса обращаются через переменную класса.
