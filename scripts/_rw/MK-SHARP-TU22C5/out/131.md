### вложенные задачи

одна задача может запустить другую. без дополнительного флага у вложенной задачи собственный жизненный цикл: завершение внешней её не ждёт, исключения наружу к родителю сами не переносятся.

```c#


var outer = Task.Factory.StartNew(() =>      // внешняя задача

{

    Console.WriteLine("Outer task starting...");

    var inner = Task.Factory.StartNew(() =>  // вложенная задача

    {

        Console.WriteLine("Inner task starting...");

        Thread.Sleep(2000);

        Console.WriteLine("Inner task finished.");

    });

});

outer.Wait(); // ожидаем выполнения внешней задачи

Console.WriteLine("End of Main");
```

`outer.Wait()` ждёт только внешнюю задачу. вложенная поставлена в пул отдельно и может закончиться уже после выхода из `Main`. возможный вывод, в котором строки внутренней задачи не успевают появиться:

```consoletext


Outer task starting...

End of Main
```

к моменту завершения основного потока внутренняя задача может ещё не начать выполнение. внешняя и вложенная здесь независимы.

чтобы вложенная задача исполнялась как часть внешней, в `StartNew` передаётся **TaskCreationOptions.AttachedToParent**:

```c#


var outer = Task.Factory.StartNew(() =>      // внешняя задача

{

    Console.WriteLine("Outer task starting...");

    var inner = Task.Factory.StartNew(() =>  // вложенная задача

    {

        Console.WriteLine("Inner task starting...");

        Thread.Sleep(2000);

        Console.WriteLine("Inner task finished.");

    }, TaskCreationOptions.AttachedToParent);

});

outer.Wait(); // ожидаем выполнения внешней задачи

Console.WriteLine("End of Main");
```

консольный вывод:

```consoletext


Outer task starting...

Inner task starting...

Inner task finished.

End of Main
```

прикреплённая задача входит в завершение родителя. родитель не переходит в `RanToCompletion`, пока не закончатся все такие дочерние задачи, поэтому `outer.Wait()` возвращает управление после строки `Inner task finished.`. исключение дочерней задачи переносится родителю и читается из `outer.Exception` как `AggregateException`. флаг действует для `StartNew` и для конструктора `Task` с последующим `Start`. `Task.Run` создаёт задачу с `DenyChildAttach`, и прикрепить к ней дочернюю через этот флаг нельзя.

### массив задач

набор задач можно хранить в массиве, по той же схеме, что и набор потоков. объекты `Task` создаются заранее и запускаются циклом:

```c#


Task[] tasks1 = new Task[3]

{

	new Task(() => Console.WriteLine("First Task")),

	new Task(() => Console.WriteLine("Second Task")),

	new Task(() => Console.WriteLine("Third Task"))

};

// запуск задач в массиве

foreach (var t in tasks1)

	t.Start();
```

либо элемент сразу запускается через `Task.Factory.StartNew` или `Task.Run`:

```c#


Task[] tasks2 = new Task[3];

int j = 1;

for (int i = 0; i < tasks2.Length; i++)

	tasks2[i] = Task.Factory.StartNew(() => Console.WriteLine($"Task {j++}"));
```

лямбда захватывает переменную `j` и увеличивает её в момент исполнения. к этому моменту другие задачи могут уже изменить `j`, а одновременный `j++` с нескольких потоков является гонкой по данным. номер итерации для печати копируют в отдельную локальную переменную до создания делегата.

задачи массива могут закончиться после метода `Main`. потоки пула фоновые, процесс их не ждёт:

```c#


Task[] tasks = new Task[3];

for(var i = 0; i < tasks.Length; i++)

{

    tasks[i] = new Task(() =>

    {

        Thread.Sleep(1000); // эмуляция долгой работы

        Console.WriteLine($"Task{i} finished");

    });

    tasks[i].Start();   // запускаем задачу

}

Console.WriteLine("Завершение метода Main");
```

один из возможных выводов, когда делегаты не успевают выполниться до выхода из процесса:

```consoletext


Завершение метода Main
```

код, которому нужны результаты всех задач, ставится после барьера **Task.WaitAll(tasks)**. метод блокирует вызывающий поток, пока каждая задача не перейдёт в конечное состояние:

```c#


Task[] tasks = new Task[3];

for(var i = 0; i < tasks.Length; i++)

{

    tasks[i] = new Task(() =>

    {

        Thread.Sleep(1000); // эмуляция долгой работы

        Console.WriteLine($"Task{i} finished");

    });

    tasks[i].Start();   // запускаем задачу

}

Console.WriteLine("Завершение метода Main");



Task.WaitAll(tasks); // ожидаем завершения всех задач
```

строка `Завершение метода Main` расположена до `WaitAll` и выполняется сразу, ещё до окончания делегатов. `WaitAll` затем удерживает основной поток. операторы, записанные после `WaitAll`, выполняются только когда все задачи завершены. вывод программы:

```consoletext


Завершение метода Main

Task3 finished

Task3 finished

Task3 finished
```

три строки `Task3 finished` дают замыкание на переменную цикла. в `for` переменная `i` одна на все итерации, лямбда захватывает саму переменную. к старту делегатов цикл уже закончился, `i` равно 3, и каждая задача печатает `Task3`. `WaitAll` порядок исполнения не задаёт. он задаёт только точку, в которой все элементы уже в конечном состоянии. порядок самих задач остаётся недетерминированным.

**Task.WaitAny(tasks)** блокирует вызывающий поток, пока не завершится хотя бы одна задача массива, и возвращает её индекс.

### возвращение результатов из задач

задача может вернуть значение. тип такой задачи закрывается типом результата: `Task<TResult>`.

```c#


int n1 =4, n2 = 5;

Task<int> sumTask = new Task<int>(() => Sum(n1, n2));

sumTask.Start();



int result = sumTask.Result;

Console.WriteLine($"{n1} + {n2} = {result}"); // 4 + 5 = 9



int Sum(int a, int b) => a + b;
```

чтобы получить из задачи значение, объект типизируется этим значением. здесь ожидается число `int`, поэтому тип записывается как `Task<int>`.

делегат обязан возвращать значение того же типа. метод `Sum` принимает два числа и возвращает их сумму типа `int`.

результат лежит в свойстве `Result`:

```c#
int result = sumTask.Result;
```

приведение к `int` не нужно: у `Task<int>` свойство `Result` уже имеет тип `int`. чтение `Result` блокирует текущий поток до завершения задачи, как и `Wait`. если задача завершилась исключением, обращение к `Result` выбрасывает `AggregateException`, и исходное исключение лежит внутри этой обёртки.

задачей может быть и ссылочный результат:

```c#


Task<Person> defaultPersonTask = new Task<Person>(() => new Person("Tom", 37));

defaultPersonTask.Start();



Person defaultPerson = defaultPersonTask.Result;

Console.WriteLine($"{defaultPerson.Name} - {defaultPerson.Age}"); // Tom - 37



record class Person(string Name, int Age);
```

`defaultPersonTask` возвращает объект типа `Person`. этот объект читается из свойства `Result` после завершения задачи.
