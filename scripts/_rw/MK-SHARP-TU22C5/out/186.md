при запуске приложения, написанного на c#, операционная система создаёт процесс, а среда clr создаёт внутри этого процесса логический контейнер. он называется доменом приложения, и запущенное приложение работает внутри него. в .net framework домен был границей изоляции: в одном процессе могли сосуществовать несколько доменов, и отдельный домен можно было выгрузить. в .net 5 и новее дополнительные домены не создаются. `AppDomain.CurrentDomain` остаётся представлением текущего приложения, а выгрузка отдельных сборок выполняется контекстом загрузки, а не выгрузкой домена.

для обращения к домену платформа .net предоставляет класс `AppDomain`. основные члены:

- свойство `BaseDirectory` возвращает базовый каталог, из которого подгружаются сборки. как правило, это каталог самого приложения

- свойство `CurrentDomain` возвращает домен текущего приложения

- свойство `FriendlyName` возвращает имя домена приложения

- свойство `SetupInformation` возвращает объект `AppDomainSetup` и хранит конфигурацию домена приложения

- метод `ExecuteAssembly()` запускает сборку exe в рамках текущего домена приложения. в .net 5 и новее этот метод не поддерживается и завершается `PlatformNotSupportedException`. создание доменов через `CreateDomain` относится к той же модели .net framework

- метод `GetAssemblies()` возвращает набор сборок .net, загруженных в домен приложения

имя и базовый каталог текущего домена, а также все загруженные в домен сборки, читаются так:

```c#


using System.Reflection;



AppDomain domain = AppDomain.CurrentDomain;

Console.WriteLine($"Name: {domain.FriendlyName}");

Console.WriteLine($"Base Directory: {domain.BaseDirectory}");

Console.WriteLine();



Assembly[] assemblies = domain.GetAssemblies();

foreach (Assembly asm in assemblies)

    Console.WriteLine(asm.GetName().Name);
```

`AppDomain.CurrentDomain` даёт домен текущего процесса. `FriendlyName` в выводе совпадает с именем приложения, `BaseDirectory` указывает на каталог сборки, включая целевой моникер вроде каталога `net6.0`. `GetAssemblies` возвращает уже загруженные сборки. в их число входят и сборки, которые среда подтянула по мере обращения к типам, а не только сборка, указанная при запуске. имя каждой сборки берётся из `AssemblyName` через `GetName().Name`.
