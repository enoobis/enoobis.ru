### выполнение программы

весь код программы на языке c# помещается в файлы с расширением **.cs**. по умолчанию в проекте, который создаётся в visual studio, а также при использовании .net cli, уже есть один файл с кодом c#, файл **Program.cs**, со следующим содержимым:

```c#


// See https://aka.ms/new-console-template for more information

Console.WriteLine("Hello, World!");
```

![выполнение программы на языке программирования c#](/uploads/course-lectures/1513bf28afb1250d63d0f66335de201271e534d0.png)

именно код файла **Program.cs** выполняется по умолчанию, если запустить проект на выполнение. при необходимости добавляются и другие файлы с кодом c#. точка входа в шаблоне с операторами верхнего уровня синтезируется компилятором: операторы этого файла попадают в метод, с которого clr начинает выполнение сборки.

### инструкции

базовым строительным блоком программы являются **инструкции** (statement). инструкция представляет некоторое действие, например арифметическую операцию, вызов метода, объявление переменной и присвоение ей значения. в конце каждой инструкции в c# ставится точка с запятой (;). этот знак указывает компилятору на конец инструкции. грамматика языка отделяет инструкции именно этим терминатором, а не концом строки: перевод строки для компилятора является пробельным символом. например, в проекте консольного приложения, который создаётся по умолчанию, есть такая строка:

```c#
Console.WriteLine("Hello, World!");
```

эта строка представляет вызов метода `Console.WriteLine`, который выводит на консоль строку. вызов метода является инструкцией и поэтому завершается точкой с запятой.

набор инструкций может объединяться в блок кода. блок кода заключается в фигурные скобки, а инструкции помещаются между открывающей и закрывающей фигурными скобками. блок задаёт область, в которой группируются инструкции, и одновременно является границей области видимости локальных объявлений. например, код файла **Program.cs** заменяется на следующий:

```c#


{

    Console.WriteLine("Привет");

    Console.WriteLine("Добро пожаловать в C#");

}
```

![блок кода на языке программирования c#](/uploads/course-lectures/15f888ade0b8cfc721680195edf47a894a149bc4.png)

здесь блок кода содержит две инструкции. при выполнении этого кода консоль выведет две строки:

```consoletext


Привет

Добро пожаловать в C#
```

в этом блоке кода две инструкции, которые выводят на консоль определённую строку. порядок вывода совпадает с порядком инструкций: выполнение внутри блока идёт сверху вниз, если нет операторов передачи управления.

одни блоки кода могут содержать другие блоки:

```c#


{

	Console.WriteLine("Первый блок");

	{

		Console.WriteLine("Второй блок");

	}

}
```

вложенный блок является отдельной областью видимости. имя, объявленное во внутреннем блоке, не видно снаружи, а имя внешнего блока во внутреннем видно, если оно не скрыто новым объявлением.

### регистрозависимость

c# является регистрозависимым языком. это значит, что в зависимости от регистра символов одни и те же буквы могут представлять разные классы, методы, переменные. например, для вывода на консоль используется метод **WriteLine**: его имя начинается именно с большой буквы, "WriteLine". если вместо "Console.WriteLine" написать "Console.writeline", программа не скомпилируется, так как данный метод обязательно должен называться "WriteLine", а не "writeline" или "WRITELINE" или как-то иначе. сравнение идентификаторов выполняется по точной последовательности символов юникода, без свёртки регистра, которая принята в некоторых других языках.

### комментарии

важной частью программного кода являются комментарии. они не являются собственно частью программы, при компиляции они игнорируются. тем не менее комментарии делают код программы более понятным, помогая понять те или иные его части. лексический анализатор удаляет комментарии до построения синтаксического дерева, поэтому комментарий не влияет ни на типы, ни на генерируемый cil.

есть два типа комментариев: однострочный и многострочный. однострочный комментарий размещается на одной строке после двойного слеша //. многострочный комментарий заключается между символами /* текст комментария */. он может размещаться на нескольких строках. например:

```c#


/*

       первая программа на C#,

       которая выводит приветствие на консоль

*/

Console.WriteLine("Привет");				// Выводим строку "Привет"

Console.WriteLine("Добро пожаловать в C#");	// Выводим строку "Добро пожаловать в C#"
```

однострочный комментарий действует до конца строки. многострочный не вкладывается: первая последовательность */ завершает комментарий, открытый /*.

### файл проекта

в каждом проекте c# есть файл, который отвечает за общую конфигурацию проекта. по умолчанию этот файл называется **Название_проекта.csproj**. файл открывается двойным щелчком левой кнопкой мыши по названию проекта либо щелчком правой кнопкой мыши по названию проекта и выбором в появившемся меню пункта **Edit Project File**.

![файл проекта в c# в visual studio](/uploads/course-lectures/38f4e04bfa812770fff94079542bf4f1bbfafdc3.png)

после этого visual studio открывает файл проекта, который выглядит следующим образом:

```xml


<Project Sdk="Microsoft.NET.Sdk">



  <PropertyGroup>

    <OutputType>Exe</OutputType>

    <TargetFramework>net6.0</TargetFramework>

    <ImplicitUsings>enable</ImplicitUsings>

    <Nullable>enable</Nullable>

  </PropertyGroup>



</Project>
```

этот файл в виде кода xml определяет конфигурацию проекта и может содержать множество элементов. ниже рассматриваются два основных:

- OutputType : определяет выходной тип проекта. это может быть выполняемое приложение в виде файла с расширением exe, которое запускается по нажатию. и также это может быть файл с расширением .dll, некоторый набор функциональностей, который используется другими проектами. по умолчанию здесь установлено значение "Exe", что значит, что создаётся исполняемое приложение. значение `Exe` заставляет sdk порождать точку входа. значение библиотеки порождает сборку без обязательной точки входа, предназначенную для ссылки из других проектов.

- TargetFramework : определяет применяемую для компиляции версию фреймворка .net. здесь это значение "net6.0", то есть применяется .net 6.0. идентификатор целевой платформы выбирает ссылочные сборки, относительно которых проверяются типы, и среду, на которой приложение рассчитывает выполняться.

на самых ранних этапах этот файл может не понадобиться, однако впоследствии может потребоваться внести некоторые изменения в конфигурацию, и тогда возникает потребность в обращении к этому файлу. sdk читает его при каждой сборке: смена `TargetFramework` меняет набор доступных api без правки исходных файлов .cs.
