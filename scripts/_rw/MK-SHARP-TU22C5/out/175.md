помимо классов, которые читают и пишут файл как есть, в .net есть классы сжатия. они упаковывают поток байтов и затем восстанавливают исходную последовательность. это `ZipFile`, `DeflateStream` и `GZipStream`. все три лежат в пространстве имён `System.IO.Compression`.

`DeflateStream` реализует алгоритм deflate: сжатый поток без собственного контейнера. `GZipStream` пишет тот же deflate внутри формата gzip, с заголовком и контрольной суммой в конце. набор конструкторов и методов у двух классов совпадает, поэтому замена одного типа на другой в программе не требует другой схемы вызовов. байты при этом различны: поток, записанный `GZipStream`, `DeflateStream` не разбирает, и обратно тоже.

### `GZipStream` и `DeflateStream`

экземпляр `GZipStream` создаётся одним из конструкторов:

- `GZipStream(Stream stream, CompressionLevel level)`: `stream` принимает уже сжатые байты, `level` задаёт уровень сжатия. этот конструктор открывает режим сжатия
- `GZipStream(Stream stream, CompressionMode mode)`: `mode` выбирает направление. `CompressionMode.Compress` сжимает данные, `CompressionMode.Decompress` восстанавливает их

направление определяет, чем является аргумент `stream`. при сжатии в него пишутся сжатые байты, а несжатые данные программа записывает в сам `GZipStream`. при восстановлении из `stream` читаются сжатые байты, а восстановленные данные программа читает из `GZipStream`.

- `GZipStream(Stream stream, CompressionLevel level, bool leaveOpen)`: `leaveOpen` решает, закрывать ли `stream` вместе с объектом `GZipStream`. при `true` базовый поток остаётся открытым после `Dispose`
- `GZipStream(Stream stream, CompressionMode mode, bool leaveOpen)`: та же пара режима и признака `leaveOpen`

сжатием и восстановлением управляют методы, унаследованные от `Stream`. основные из них:

- `void CopyTo(Stream destination)`: копирует данные в поток `destination`
- `Task CopyToAsync(Stream destination)`: асинхронная версия `CopyTo`
- `void Flush()`: очищает буфер и записывает его данные в базовый поток
- `Task FlushAsync()`: асинхронная версия `Flush`
- `int Read(byte[] array, int offset, int count)`: читает данные в массив байтов и возвращает число реально прочитанных байтов. `array` принимает данные
- `offset` задаёт смещение в байтах внутри `array`, с которого прочитанные байты туда помещаются
- `count` задаёт наибольшее число байтов чтения. если данных меньше, возвращаются все оставшиеся
- `Task<int> ReadAsync(byte[] array, int offset, int count)`: асинхронная версия `Read`
- `long Seek(long offset, SeekOrigin origin)`: у базового класса `Stream` метод ставит позицию со смещением `offset`. у потока сжатия произвольный доступ закрыт: `CanSeek` равен `false`, и вызов `Seek` завершается `NotSupportedException`. читать и писать такой поток можно только последовательно
- `void Write(byte[] array, int offset, int count)`: записывает в поток байты из массива. `array` задаёт источник
- `offset` задаёт смещение в `array`, с которого байты берутся
- `count` задаёт наибольшее число записываемых байтов
- `Task WriteAsync(byte[] array, int offset, int count)`: асинхронная версия `Write`

в режиме `CompressionMode.Compress` поток принимает запись и отвергает чтение. в режиме `CompressionMode.Decompress` поток отдаёт чтение и отвергает запись. `DeflateStream` подчиняется тем же правилам.

применение `GZipStream`:

```c#


using System.IO.Compression;



string sourceFile = "book.pdf"; // исходный файл

string compressedFile = "book.gz"; // сжатый файл

string targetFile = "book_new.pdf"; // восстановленный файл



// создание сжатого файла

await CompressAsync(sourceFile, compressedFile);

// чтение из сжатого файла

await DecompressAsync(compressedFile, targetFile);



async Task CompressAsync(string sourceFile, string compressedFile)

{

    // поток для чтения исходного файла

    using FileStream sourceStream = new FileStream(sourceFile, FileMode.OpenOrCreate);

    // поток для записи сжатого файла

    using FileStream targetStream = File.Create(compressedFile);



    // поток архивации

    using GZipStream compressionStream = new GZipStream(targetStream, CompressionMode.Compress);

    await sourceStream.CopyToAsync(compressionStream); // копируем байты из одного потока в другой



    Console.WriteLine($"Сжатие файла {sourceFile} завершено.");

    Console.WriteLine($"Исходный размер: {sourceStream.Length}  сжатый размер: {targetStream.Length}");

}



async Task DecompressAsync(string compressedFile, string targetFile)

{

    // поток для чтения из сжатого файла

    using FileStream sourceStream = new FileStream(compressedFile, FileMode.OpenOrCreate);

    // поток для записи восстановленного файла

    using FileStream targetStream = File.Create(targetFile);

    // поток разархивации

    using GZipStream decompressionStream = new GZipStream(sourceStream, CompressionMode.Decompress);

    await decompressionStream.CopyToAsync(targetStream);

    Console.WriteLine($"Восстановлен файл: {targetFile}");

}
```

предполагается, что рядом с программой, в текущем каталоге процесса, лежит `book.pdf`. его и сжимает фрагмент.

`CompressAsync` получает имя исходного файла и имя будущего сжатого файла. сначала открывается поток чтения исходного файла, `FileStream sourceStream`. затем открывается поток записи сжатого файла, `FileStream targetStream`, через `File.Create`. поток архивации `GZipStream compressionStream` связывается с `targetStream` и режимом `CompressionMode.Compress`. `CopyToAsync` переносит байты из `sourceStream` в `compressionStream`: на входе gzip-потока ещё несжатый pdf, на выходе в `targetStream` ложатся байты gzip.

`DecompressAsync` выполняет обратное восстановление. аргументы суть путь сжатого файла и путь восстановленного файла. сначала открывается чтение сжатого файла, `FileStream sourceStream`. затем создаётся файл для восстановленных данных, `FileStream targetStream`. `GZipStream decompressionStream` связывается с `sourceStream` и режимом `CompressionMode.Decompress`. `CopyToAsync` читает из gzip-потока уже восстановленные байты и пишет их в `targetStream`.

режим передаётся в конструктор значением `CompressionMode`: `Compress` для сжатия и `Decompress` для восстановления. отдельного признака в методах копирования нет, направление зафиксировано при создании потока.

пример вывода:

```bash


Сжатие файла book.pdf завершено.

Исходный размер: 3235353  сжатый размер: 2574401

Восстановлен файл: book_new.pdf
```

числа суть длины потоков в байтах для конкретного `book.pdf`. сжатый размер зависит от содержимого: уже сжатый внутри pdf почти не уменьшается, текст уменьшается сильнее.

чтобы сжать тем же сценарием через `DeflateStream`, в фрагменте достаточно заменить тип `GZipStream` на `DeflateStream`. вызовы `CopyToAsync`, режимы и `using` остаются прежними. меняется контейнер: у результата не будет заголовка gzip, и прежний `.gz` этим потоком уже не прочитать.

ограничение обоих потоковых классов одно: они сжимают один непрерывный поток и не хранят имена файлов. каталог из нескольких файлов в такой поток сам не раскладывается. для архива из многих файлов берётся `ZipFile`.

### `ZipFile`

статический класс `ZipFile` из `System.IO.Compression` строит архив zip, внутри которого у каждого файла своя запись. основной сценарий класса есть архивация каталога. методы:

- `void CreateFromDirectory(string sourceDirectoryName, string destinationFileName)`: упаковывает каталог `sourceDirectoryName` в файл `destinationFileName`
- `void ExtractToDirectory(string sourceFileName, string destinationDirectoryName)`: извлекает все записи zip-файла `sourceFileName` в каталог `destinationDirectoryName`

у `CreateFromDirectory` есть перегрузки с уровнем сжатия, с кодировкой имён записей и с признаком, попадает ли в архив сам корневой каталог. у `ExtractToDirectory` есть перегрузки с кодировкой имён и с заменой файлов, которые в каталоге назначения уже лежат. ниже базовая пара без этих аргументов.

```c#


using System.IO.Compression;



string sourceFolder = "D://test/"; // исходная папка

string zipFile = "D://test.zip"; // сжатый файл

string targetFolder = "D://newtest"; // папка, куда распаковывается файл



ZipFile.CreateFromDirectory(sourceFolder, zipFile);

Console.WriteLine($"Папка {sourceFolder} архивирована в файл {zipFile}");

ZipFile.ExtractToDirectory(zipFile, targetFolder);



Console.WriteLine($"Файл {zipFile} распакован в папку {targetFolder}");
```

каталог `D://test/` методом `ZipFile.CreateFromDirectory` упаковывается в `test.zip`. затем `ZipFile.ExtractToDirectory` извлекает этот архив в каталог `D://newtest`. если каталога назначения нет, он создаётся. если файл архива по пути `zipFile` уже существует, `CreateFromDirectory` завершается исключением и старый архив не заменяет.
