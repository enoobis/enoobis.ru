кроме стандартных классов коллекций, таких как списки, очереди, словари и стеки, платформа .net предоставляет класс **ObservableCollection**. в отличие от ранее рассмотренных коллекций он определён в пространстве имён **System.Collections.ObjectModel**. по набору операций `ObservableCollection<T>` близок к `List<T>`: оба типа задают индексируемую изменяемую последовательность. отдельный контракт этого класса связан с наблюдением. `ObservableCollection<T>` реализует `INotifyCollectionChanged` и после каждого изменения содержимого вызывает обработчики события `CollectionChanged`. на этом контракте держится привязка данных: подписчик узнаёт о вставке, удалении, замене, перемещении и сбросе и обновляет своё состояние без опроса коллекции.

### создание и инициализация ObservableCollection

для создания экземпляра класс предоставляет несколько конструкторов. пустая коллекция создаётся конструктором без параметров:

```c#


using System.Collections.ObjectModel;



ObservableCollection<string> people = new ObservableCollection<string>();
```

параметр типа `string` фиксирует тип элементов, поэтому коллекция people хранит только строки. подстановка значения другого типа отвергается при компиляции: коллекция обобщённая, и согласование типов выполняется статически.

другой конструктор принимает готовую последовательность `IEnumerable<T>` и копирует из неё элементы. источником может служить массив или любая другая коллекция:

```c#


var people = new ObservableCollection<string>( new string[] {"Tom", "Bob", "Sam"});
```

элементы задаются и инициализатором коллекции. для каждого значения в фигурных скобках компилятор порождает вызов `Add`:

```c#


var people = new ObservableCollection<string>

{

    "Tom", "Bob", "Sam"

};
```

оба способа сочетаются. конструктор сначала копирует элементы источника, затем инициализатор добавляет следующие значения:

```c#


var people = new ObservableCollection<string>( new string[] {"Mike", "Alice", "Kate" })

{

    "Tom", "Bob", "Sam"

};
```

итоговый порядок совпадает с порядком копирования и последующих вызовов `Add`: сначала Mike, Alice, Kate, затем Tom, Bob, Sam.

### обращение к элементам коллекции

чтение и запись по индексу устроены так же, как у массива и у `List<T>`. индексатор обращается к элементу по смещению от начала, нумерация начинается с нуля. запись в уже существующую позицию заменяет элемент и публикует уведомление о замене:

```c#


var people = new ObservableCollection<string>

{

    "Tom", "Bob", "Sam"

};



// получаем первый элемент

Console.WriteLine(people[0]);   // Tom

// изменяем первый элемент

people[0] = "Tomas";

Console.WriteLine(people[0]);   // Tomas
```

чтение `people[0]` возвращает первую строку Tom. присваивание `people[0] = "Tomas"` помещает на это место новую строку. индекс вне полуинтервала `[0, Count)` приводит к `ArgumentOutOfRangeException`.

### перебор коллекции

перебор выполняется обычными циклами. `foreach` получает перечислитель и двигается по последовательности, `for` идёт по индексам от нуля до `Count - 1`:

```c#


using System.Collections.ObjectModel;



var people = new ObservableCollection<string>

{

    "Tom", "Bob", "Sam"

};



foreach(var person in people)

{

    Console.WriteLine(person);

}

for (int i =0; i < people.Count; i++)

{

    Console.WriteLine(people[i]);

}
```

свойство **Count** возвращает текущее число элементов. допустимые индексы лежат в полуинтервале от 0 до `Count`.

### методы ObservableCollection

операции изменения повторяют список и добавляют перенос элемента между позициями:

- `void Add(T item)`: добавление нового элемента в конец коллекции

- `void CopyTo(T[] array, int index)`: копирует элементы коллекции в массив array, начиная с индекса index

- `bool Contains(T item)`: возвращает `true`, если элемент item есть в коллекции

- `void Clear()`: удаляет из коллекции все элементы

- `int IndexOf(T item)`: возвращает индекс первого вхождения элемента в коллекции

- `void Insert(int index, T item)`: вставляет элемент item в коллекцию по индексу index. если такого индекса в коллекции нет, генерируется исключение

- `bool Remove(T item)`: удаляет элемент item из коллекции и при успешном удалении возвращает true. если одинаковых элементов несколько, удаляется только первый

- `void RemoveAt(int index)`: удаляет элемент по индексу index. если такого индекса нет, генерируется исключение

- `void Move(int oldIndex, int newIndex)`: перемещает элемент с индекса oldIndex на позицию newIndex

применение основных методов:

```c#


using System.Collections.ObjectModel;



var people = new ObservableCollection<string>();



// добавляем элемент

people.Add("Bob");

// вставляем элемент по индексу 0

people.Insert(0, "Tom");



// проверка наличия элемента 

bool bobExists = people.Contains("Bob");     // true

Console.WriteLine($"Bob exists: {bobExists}");

bool mikeExists = people.Contains("Mike");   // false

Console.WriteLine($"Mike exists: {mikeExists}");



// удаляем элемент

people.Remove("Tom");

// удаляем элемент по индексу 0

people.RemoveAt(0);
```

`Add` увеличивает `Count` на единицу и ставит элемент в конец. `Insert(0, "Tom")` сдвигает уже хранимые элементы вправо и занимает нулевую позицию. `Contains` ищет значение по равенству элементов: для Bob результат true, для Mike результат false. `Remove` удаляет первое найденное вхождение, `RemoveAt` удаляет элемент по уже известному индексу и значение не ищет.

### уведомление об изменении коллекции

любое изменение содержимого публикуется событием **CollectionChanged**. подписка на него даёт обработку добавления, удаления, замены, перемещения и сброса. событие имеет тип делегата **NotifyCollectionChangedEventHandler**:

```c#
void NotifyCollectionChangedEventHandler(object? sender, NotifyCollectionChangedEventArgs e);
```

второй параметр, объект **NotifyCollectionChangedEventArgs**, хранит описание произошедшего изменения. свойство `Action` принадлежит перечислению NotifyCollectionChangedAction и различает характер операции:

- `NotifyCollectionChangedAction.Add`: добавление

- `NotifyCollectionChangedAction.Remove`: удаление

- `NotifyCollectionChangedAction.Replace`: замена

- `NotifyCollectionChangedAction.Move`: перемещение объекта внутри коллекции на новую позицию

- `NotifyCollectionChangedAction.Reset`: сброс содержимого коллекции, в том числе при очистке методом `Clear()`

свойства `NewItems` и `OldItems` возвращают соответственно добавленные и удалённые объекты. индексы начала затронутого участка лежат в `NewStartingIndex` и `OldStartingIndex`. по `Action` вместе с этими списками восстанавливается полная картина операции: какие объекты добавлены, какие удалены и какой объект каким заменён. уведомление рассылается после обновления внутреннего хранилища, поэтому к моменту входа в обработчик коллекция уже находится в новом состоянии.

для предметной модели берётся класс Person с неизменяемым именем:

```c#


class Person

{

    public string Name { get; }

    public Person(string name) => Name = name;

}
```

программа, которая ведёт коллекцию объектов Person и подписывается на её изменения:

```c#


using System.Collections.ObjectModel;

using System.Collections.Specialized;



var people = new ObservableCollection<Person>() 

{ 

    new Person("Tom"), 

    new Person("Sam") 

};

// подписываемся на событие изменения коллекции

people.CollectionChanged += People_CollectionChanged;



people.Add(new Person("Bob"));  // добавляем новый элемент



people.RemoveAt(1);                 // удаляем элемент

people[0] = new Person("Eugene");   // заменяем элемент



Console.WriteLine("\nСписок пользователей:");

foreach (var person in people)

{

    Console.WriteLine(person.Name);

}

// обработчик изменения коллекции

void People_CollectionChanged(object? sender, NotifyCollectionChangedEventArgs e)

{

    switch (e.Action)

    {

        case NotifyCollectionChangedAction.Add: // если добавление

            if(e.NewItems?[0] is Person newPerson)

                Console.WriteLine($"Добавлен новый объект: {newPerson.Name}");

            break;

        case NotifyCollectionChangedAction.Remove: // если удаление

            if (e.OldItems?[0] is Person oldPerson)

                Console.WriteLine($"Удален объект: {oldPerson.Name}");

            break;

        case NotifyCollectionChangedAction.Replace: // если замена

            if ((e.NewItems?[0] is Person replacingPerson)  && 

                (e.OldItems?[0] is Person replacedPerson))

                Console.WriteLine($"Объект {replacedPerson.Name} заменен объектом {replacingPerson.Name}");

            break;

    }

}
```

обработчиком служит метод `People_CollectionChanged`. параметр NotifyCollectionChangedEventArgs передаёт вид операции и затронутые объекты. при добавлении новый объект читается из `e.NewItems`, при удалении прежний объект читается из `e.OldItems`, при замене заполнены оба списка. оператор `is` проверяет, что элемент имеет тип Person, и сразу связывает его с локальной переменной. оператор `?.` учитывает, что список элементов у части действий отсутствует. консольный вывод программы:

```consoletext


Добавлен новый объект: Bob

Удален объект: Sam

Объект Tom заменен объектом Eugene



Список пользователей:

Eugene

Bob
```

вывод совпадает с порядком вызовов. `Add` порождает действие Add и печатает имя Bob. `RemoveAt(1)` удаляет элемент с индексом 1, это Sam, и порождает действие Remove. присваивание индексатора `people[0] = new Person("Eugene")` порождает действие Replace: объект Tom заменён объектом Eugene. после этих трёх операций в коллекции остаются Eugene и Bob, их и печатает завершающий цикл.

действие Reset, которым сопровождается `Clear`, в показанный `switch` не входит: при сбросе списки новых и старых элементов не заполняются, и обработчик, читающий только Add, Remove и Replace, такое событие не печатает. `Move` публикует действие Move и точно так же остаётся за пределами этого разбора. экземпляр коллекции не синхронизирует доступ сам: одновременное изменение из нескольких потоков ломает внутренний инвариант, а подписчики интерфейса обычно ожидают уведомление в том потоке, где коллекция создана.
