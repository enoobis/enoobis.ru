интерфейс описывает тип: набор компонентов, которые тип данных должен иметь. объект интерфейса нельзя создать конструктором напрямую, как объект класса. у интерфейса нет собственного конструктора:

```c#


IMovable m = new IMovable(); // ! Ошибка, так сделать нельзя



interface IMovable

{

	void Move();

}
```

интерфейс предназначен для реализации в классах и структурах. реализация `IMovable`:

```c#


// применение интерфейса в классе

class Person : IMovable

{

	public void Move()

	{

		Console.WriteLine("Человек идет");

	}

}

// применение интерфейса в структуре

struct Car : IMovable

{

	public void Move()

	{

		Console.WriteLine("Машина едет");

	}

}
```

при применении интерфейса, как и при наследовании, после имени класса или структуры ставят двоеточие и далее имена интерфейсов. класс обязан реализовать все методы и свойства применённых интерфейсов, если у этих методов и свойств нет реализации по умолчанию.

если методы и свойства интерфейса не имеют модификатора доступа, по умолчанию они публичные. при реализации в классе и структуре к ним применяют только модификатор `public`.

применение интерфейса в программе:

```c#


Person person = new Person();

Car car = new Car();

DoAction(person);

DoAction(car);



void DoAction(IMovable movable) => movable.Move();



interface IMovable

{

    void Move();

}

class Person : IMovable

{

    public void Move() => Console.WriteLine("Человек идет");

}

struct Car : IMovable

{

    public void Move() => Console.WriteLine("Машина едет");

}
```

метод `DoAction()` принимает объект интерфейса `IMovable`. на момент написания кода конкретный вид объекта, класс или структура, может быть неизвестен. известно одно: объект реализует метод `Move`, и этот метод можно вызвать.

интерфейс здесь выступает контрактом: определённый тип обязан реализовать указанную функциональность.

консольный вывод программы:

```bash


Человек идет

Машина едет
```

### реализация интерфейсов по умолчанию

начиная с версии c# 8.0 интерфейсы поддерживают реализацию методов и свойств по умолчанию. если в интерфейс, который уже реализуют многие классы, добавить новый метод, каждый такой класс обязан этот метод реализовать, иначе он не компилируется. тело по умолчанию снимает обязанность: класс, который метод не объявил, получает реализацию из интерфейса.

```c#


IMovable tom = new Person();

Car tesla = new Car();

tom.Move();     // Walking

tesla.Move();   // Driving

interface IMovable

{

    void Move() => Console.WriteLine("Walking");

}

class Person : IMovable { }

class Car : IMovable

{

    public void Move() => Console.WriteLine("Driving");

}
```

интерфейс `IMovable` задаёт реализацию по умолчанию для метода `Move`. класс `Person` этот метод не реализует и получает тело интерфейса. класс `Car` определяет собственную реализацию `Move`.

для объекта класса `Person` метод `Move` вызывается через ссылку на `IMovable`: класс применяет интерфейс, и вызов идёт по карте интерфейса. через переменную самого класса метод недоступен, в `Person` он не объявлен:

```c#


Person tom = new Person();

tom.Move();     // Ошибка - метод Move не определен в классе Person
```

### множественная реализация интерфейсов

у интерфейсов есть ещё одна роль. в c# нет множественного наследования классов: класс наследует только от одного класса, в отличие от c++, где множественное наследование разрешено. интерфейсы частично обходят это ограничение. класс и структура реализуют сразу несколько интерфейсов, имена перечисляют через запятую:

```c#


class myClass: myInterface1, myInterface2, myInterface3, ...

{

	

}
```

пример двух контрактов:

```c#


Message hello = new Message("Hello World");

hello.Print();	// Hello World



interface IMessage

{

    string Text { get; set; }

}

interface IPrintable

{

    void Print();

}

class Message : IMessage, IPrintable

{

    public string Text { get; set; }

    public Message(string text) => Text = text;

    public void Print()=> Console.WriteLine(Text);

}
```

здесь определены два интерфейса. `IMessage` определяет свойство `Text`, текст сообщения. `IPrintable` определяет метод `Print`. класс `Message` реализует оба интерфейса и затем используется в программе.

### интерфейсы в преобразованиях типов

правила преобразования типов переносятся на интерфейсы. поскольку класс `Message` реализует интерфейс `IMessage`, переменная типа `IMessage` может хранить ссылку на объект типа `Message`:

```c#


// Все объекты Message являются объектами IMessage

IMessage hello = new Message("Hello METANIT.COM");

Console.WriteLine(hello.Text); // Hello METANIT.COM



// Не все объекты IMessage являются объектами Message, необходимо явное приведение

// Message someMessage = hello; // ! Ошибка



// Интерфейс IMessage не имеет свойства Print, необходимо явное приведение

// hello.Print();  // ! Ошибка



// если hello представляет класс Message, выполняем преобразование

if (hello is Message someMessage) someMessage.Print();
```

преобразование от класса к его интерфейсу выполняется автоматически, как преобразование от производного типа к базовому: любой объект `Message` реализует `IMessage`. в отношении подтипирования реализующий класс есть подтип интерфейса.

обратное преобразование, от интерфейса к реализующему классу, аналогично преобразованию от базового класса к производному. не каждый объект `IMessage` является объектом `Message`: интерфейс `IMessage` могут реализовать и другие классы, поэтому нужна операция приведения. чтобы обратиться к методам класса `Message`, которые не определены в интерфейсе `IMessage`, но входят в класс `Message`, преобразование выполняют явно:

```c#
if (hello is Message someMessage) someMessage.Print();
```
