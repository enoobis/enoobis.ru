при запуске приложения операционная система создаёт для него отдельный процесс. процессу выделяется собственное адресное пространство, и от других процессов он изолирован: указатель, полученный в одном процессе, не адресует память другого. у процесса есть хотя бы один поток, главный. в программе на c# точкой входа служит метод `Main`. среда выполнения создаёт процесс и его главный поток и вызывает `Main` уже на этом потоке. вторичные потоки запускаются из главного потока или из пула.

в .net процесс представлен классом `Process` из пространства имён `System.Diagnostics`. класс управляет уже запущенными процессами и запускает новые. у него определены свойства и методы для сведений о процессе и для управления им:

- свойство `Handle` возвращает дескриптор процесса

- свойство `Id` возвращает уникальный идентификатор процесса в рамках текущего сеанса ос

- свойство `MachineName` возвращает имя компьютера, на котором запущен процесс

- свойство `MainModule` представляет основной модуль, исполняемый файл программы, объектом типа `ProcessModule`

- свойство `Modules` открывает коллекцию `ProcessModuleCollection`. она хранит набор модулей, загруженных в процесс, в том числе файлы dll и exe, объектами `ProcessModule`

- свойство `ProcessName` возвращает имя процесса. оно часто совпадает с именем приложения

- свойство `StartTime` возвращает время запуска процесса

- свойство `PagedMemorySize64` возвращает объём памяти в байтах, выделенный данному процессу. в источнике имя записано как pagememorysize64, в библиотеке свойство называется `PagedMemorySize64`

- свойство `VirtualMemorySize64` возвращает объём виртуальной памяти в байтах, выделенный данному процессу

- метод `CloseMainWindow()` закрывает окно процесса, у которого есть графический интерфейс: процессу посылается запрос на закрытие главного окна

- метод `GetProcesses()` возвращает массив всех запущенных процессов

- метод `GetProcessesByName()` возвращает процессы с заданным именем. несколько копий одного приложения имеют общее имя, поэтому результат является массивом

- метод `GetProcessById()` возвращает один процесс по идентификатору. идентификатор уникален в сеансе, поэтому несколько копий одного приложения различаются разными значениями `Id`, а не массивом из одного вызова

- метод `Kill()` останавливает процесс

- метод `Start()` запускает новый процесс

сведения о текущем процессе:

```c#


using System.Diagnostics;



var process = Process.GetCurrentProcess();

Console.WriteLine($"Id: {process.Id}");

Console.WriteLine($"Name: {process.ProcessName}");

Console.WriteLine($"VirtualMemory: {process.VirtualMemorySize64}");
```

`GetCurrentProcess` возвращает `Process` самого выполняющегося приложения. печатаются идентификатор, имя и размер виртуальной памяти.

все запущенные процессы:

```c#


using System.Diagnostics;



foreach(Process process in Process.GetProcesses())

{

	// выводим id и имя процесса

    Console.WriteLine($"ID: {process.Id}  Name: {process.ProcessName}");

}
```

для каждого процесса печатаются `Id` и `ProcessName`.

идентификаторы процессов, которые соответствуют запущенным экземплярам visual studio:

```c#


using System.Diagnostics;



Process[] vsProcs = Process.GetProcessesByName("devenv");   // для Windows

// Process[] vsProcs = Process.GetProcessesByName("VisualStudio"); //  для MacOS

foreach (var proc in vsProcs)

    Console.WriteLine($"ID: {proc.Id}");
```

на windows имя процесса среды равно `devenv`, на macos в комментарии к тому же вызову указано имя `VisualStudio`. `GetProcessesByName` возвращает массив всех таких экземпляров.

### потоки процесса

свойство `Threads` представляет коллекцию потоков процесса, объект `ProcessThreadCollection`. каждый поток в ней является объектом `ProcessThread`. у этого класса выделяются свойства:

- `CurrentPriority` возвращает текущий приоритет потока

- `Id` является идентификатором потока

- `IdealProcessor` задаёт процессор, предпочтительный для обработки потока

- `PriorityLevel` задаёт уровень приоритета потока

- `StartAddress` возвращает адрес в памяти функции, запустившей поток

- `StartTime` возвращает время запуска потока. чтение поддерживается только на windows и linux

все потоки процесса visual studio:

```c#


using System.Diagnostics;



Process proc = Process.GetProcessesByName("devenv")[0];  // Windows

// Process proc = Process.GetProcessesByName("VisualStudio")[0];  // MacOS

ProcessThreadCollection processThreads = proc.Threads;



foreach(ProcessThread thread in processThreads)

{

    Console.WriteLine($"ThreadId: {thread.Id}");

}
```

выражение индексирует массив с нуля и поэтому предполагает, что хотя бы один экземпляр visual studio уже запущен. дальше перечисляется `Threads`, и для каждого `ProcessThread` печатается идентификатор.

### модули процесса

одно приложение может загружать набор сторонних библиотек и модулей. для их получения у класса `Process` есть свойство `Modules`. оно представляет объект `ProcessModuleCollection`. отдельный модуль представлен классом `ProcessModule`. у него выделяются свойства:

- `BaseAddress` возвращает адрес модуля в памяти

- `FileName` возвращает полный путь к файлу модуля

- `EntryPointAddress` возвращает адрес функции в памяти, которая запустила модуль

- `ModuleName` возвращает название модуля, краткое имя файла

- `ModuleMemorySize` возвращает объём памяти, необходимый для загрузки модуля

модули, загруженные в visual studio:

```c#


using System.Diagnostics;



Process proc = Process.GetProcessesByName("devenv")[0]; // для Windows

// Process proc = Process.GetProcessesByName("VisualStudio")[0]; // для MacOS

ProcessModuleCollection modules = proc.Modules;



foreach(ProcessModule module in modules)

{

    Console.WriteLine($"Name: {module.ModuleName}  FileName: {module.FileName}");

}
```

как и в примере с потоками, берётся первый процесс с именем `devenv` на windows или `VisualStudio` на macos. для каждого `ProcessModule` печатаются краткое имя и полный путь к файлу.

### запуск нового процесса

статический метод `Process.Start()` запускает новый процесс:

```c#


// обращение к исполняемой программе

Process.Start(@"C:\Program Files\Google\Chrome\Application\chrome");



// Process.Start("/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"); // на MacOS
```

здесь запускается браузер google chrome. путь к исполняемому файлу на windows и отдельный путь на macos заданы в самом вызове. обращение к исполняемому файлу передаётся операционной системе, и .net запускает соответствующее приложение.

ряду программ при запуске нужны параметры командной строки. для этого используется перегрузка `Start`, во втором аргументе которой передаются параметры:

```c#


Process.Start(@"C:\Program Files\Google\Chrome\Application\chrome", "https://metanit.com");
```

вторым аргументом здесь указан адрес, который браузер открывает при старте.

настройку параметров запуска можно отделить от самого вызова. для этого служит класс `ProcessStartInfo`:

```c#


ProcessStartInfo procInfo = new ProcessStartInfo();

// исполняемый файл программы - браузер хром

procInfo.FileName = @"C:\Program Files\Google\Chrome\Application\chrome";

// аргументы запуска - адрес интернет-ресурса

procInfo.Arguments = "https://metanit.com";

Process.Start(procInfo);
```

`FileName` задаёт исполняемый файл, в примере это браузер chrome. `Arguments` задаёт аргументы запуска, в примере адрес ресурса. `Process.Start` принимает уже заполненный `ProcessStartInfo` и создаёт процесс с этими параметрами.
