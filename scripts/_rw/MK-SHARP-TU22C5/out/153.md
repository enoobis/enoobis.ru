при выполнении параллельного запроса порядок данных в результирующей выборке может быть непредсказуем.

```c#


int[] numbers = new int[] { -2, -1, 0, 1, 2, 3, 4, 5, 6, 7, 8, };

var squares = from n in numbers.AsParallel()

                 where n > 0

                 select Square(n);



foreach (var n in squares)

    Console.WriteLine(n);



int Square(int n) => n * n;
```

программа вычисляет квадраты чисел, которые больше 0. в результате работы программы вывод может оказаться неупорядоченным:

```consoletext


1

16

49

4

25

64

9

36
```

данные склеиваются в общий набор неупорядоченно. слияние разделов plinq по умолчанию не восстанавливает позиции элементов в источнике.

если в запросе применяются операторы или методы сортировки, данные автоматически упорядочиваются:

```c#


var squares = from n in numbers.AsParallel()

                 where n > 0

                 orderby n  // сортировка

                 select Square(n);
```

оператор `orderby` и метод `OrderBy` упорядочивают результирующую выборку по ключу сортировки, то есть по результатам, которые этот ключ задаёт. совпадение с исходной последовательностью получается только тогда, когда сам ключ повторяет её порядок. если в запросе сортировки нет, а сохранить расположение элементов источника всё же нужно, применяется метод **AsOrdered()**:

```c#


var squares = from n in numbers.AsParallel().AsOrdered()

              where n > 0

              select Square(n);
```

результат упорядочен в соответствии с тем, как элементы располагаются в исходной последовательности:

```consoletext


1

4

9

16

25

36

49

64
```

упорядочивание в параллельной операции приводит к увеличению издержек: при слиянии разделов приходится учитывать исходные позиции. подобный запрос выполняется медленнее неупорядоченного. если задача не требует возвращения упорядоченного набора, метод `AsOrdered` лучше не применять.

если с полученным набором дальше предстоят какие-нибудь манипуляции, а упорядочивание больше не требуется, применяется метод **AsUnordered()**. он снимает требование порядка с последующей части запроса, и сохранять исходные позиции дальше не нужно:

```c#


int[] numbers = new int[] { -2, -1, 0, 1, 2, 3, 4, 5, 6, 7, 8, };

var squares = from n in numbers.AsParallel().AsOrdered()

              where n > 0

              select Square(n);



// выбираем числа больще 4 без упорядочивания результата

var query = from n in squares.AsUnordered()

            where n > 4

            select n;



foreach (var n in query)

    Console.WriteLine(n);



int Square(int n) => n * n;
```
