### специальное поле field

ключевое слово `field` в аксессоре свойства обозначает поле, которое компилятор порождает для этого свойства. отдельное поле в тексте типа больше не нужно: хранение значения остаётся, но имя поля в исходном коде не появляется. до c# 14 то же хранение записывали явно.

```c#


class Person

{

    string? name;

 

    public string? Name

    {

        get

        {

            return name;    // возвращаем значение свойства

        }

        set

        {

            name = value;   // устанавливаем новое значение свойства

        }

    }

}
```

аксессор `get` возвращает поле `name`, аксессор `set` записывает в него `value`. имя поля выбрано автором типа и входит в область видимости класса.

с c# 14 ту же пару аксессоров пишут через контекстное слово `field`. оно видно только внутри аксессоров данного свойства и ссылается на синтезированное поле того же типа, что и свойство.

```c#


class Person

{

    // string? name;  это поле больше не нужно

 

    public string? Name

    {

        get

        {

            return field;    // возвращаем значение свойства

        }

        set

        {

            field = value;   // устанавливаем новое значение свойства

        }

    }

}
```

при миграции на c# 14 возникает ломкое место, если в типе уже есть поле или другая переменная с именем `field`. неквалифицированное `field` внутри аксессора связывается с ключевым словом, и старый идентификатор оказывается в тени. чтобы обратиться именно к члену, пишут `@field` или `this.field`. `@` снимает контекстный смысл слова и возвращает его в разряд обычных идентификаторов. другой выход состоит в том, чтобы переименовать член `field` и убрать столкновение имён.

### определение составных операторов присваивания

с c# 14 тип может задать составное присваивание так, чтобы менялось состояние существующего объекта, а переменная слева сохраняла ту же ссылку. раньше для этого хватало обычного бинарного оператора. если определён `+`, выражение с `+=` компилятор переписывает через этот оператор и последующее присваивание результата.

```c#


Counter counter1 = new Counter { Value = 23 };

counter1 += 45;

Console.WriteLine($"counter1.Value: {counter1.Value}");  // 68



class Counter

{

    public int Value { get; set; } 

    public static Counter operator +(Counter c, int n)

    {

        return new Counter { Value = c.Value + n };

    }

}
```

у `Counter` объявлен только `operator +`. он возвращает новый экземпляр, в `Value` которого лежит сумма прежнего значения и аргумента. запись `counter1 += 45` при этом допустима, отдельный оператор `+=` не объявлен. после выполнения `Value` печатается как 68.

инструкция

```c#
counter1 += 45;
```

по правилам переписывания совпадает со следующей.

```c#
counter1 = counter1 + 45;
```

при сложении создаётся новый объект `Counter`, и в переменную записывается ссылка на него. прежний экземпляр для этой переменной теряется. если построение объекта дорого или на старую ссылку ещё смотрят другие переменные, такая семантика расходится с ожиданием «изменить на месте».

в c# 14, в составе .net 10, составное присваивание можно определить отдельно. это метод экземпляра с возвращаемым типом `void`, с одним параметром и со специальным именем оператора. `void` здесь существенен: метод ничего не возвращает, и компилятору нечем подменить левую переменную. меняется только состояние получателя.

```c#


Counter counter1 = new Counter { Value = 23 };

counter1 += 45;

Console.WriteLine($"counter1.Value: {counter1.Value}");  // 68



class Counter

{

    public int Value { get; set; }



    public void operator +=(int n)

    {

        Value += n;

    }

}
```

`operator +=` прибавляет `n` к `Value`. свойство имеет тип `int`, поэтому внутреннее `Value += n` разрешается как встроенное сложение целых и к пользовательскому оператору повторно не приходит. после вызова переменная `counter1` указывает на тот же экземпляр, а `Value` равен 68.

подробнее определение составных операторов присваивания разобрано в соответствующей статье.

### блоки расширений

с c# 14 члены расширения можно объявлять блоком `extension`. дальше такой блок называется блоком расширений. им к уже существующему типу добавляют свойства, методы и операторы, не меняя исходный текст типа. классический метод расширения с модификатором `this` остаётся частным случаем той же идеи. блок нужен там, где расширениями становятся ещё и свойства с операторами.

блоками задаются два вида расширений:

- расширения экземпляров: расширяют экземпляр типа

- статические расширения: расширяют сам тип

ниже к `string` добавляются свойство, метод и операторы. статический класс `StringExtension` только вмещает блоки. сам он в вызовах не фигурирует: поиск идёт от расширяемого типа.

```c#


string s = "Привет мир";

Console.WriteLine(s.CharCount('и'));   // 2

Console.WriteLine("123".IsNumber);   // true

Console.WriteLine("abc".IsNumber);   // false



Console.WriteLine("hello" > "ello");  // true

Console.WriteLine("hello" < "ello");  // false



Console.WriteLine(string.Default);   // Hello World



static class StringExtension

{

    // нестатический блок расширений

    extension(string str)

    {

        public bool IsNumber

        {

            get

            {

                for (int i = 0; i < str.Length; i++)

                {

                    if (str[i] < '0' || str[i] > '9') return false;

                }

                return true;

            }

        }

        public int CharCount(char c)

        {

            int counter = 0;

            for (int i = 0; i < str.Length; i++)

            {

                if (str[i] == c) counter++;

            }

            return counter;

        }

    }

    // статический блок расширений

    extension(string)

    {

        // операторы

        public static bool operator >(string str1, string str2) => str1.Length > str2.Length;

        public static bool operator <(string str1, string str2) => str1.Length < str2.Length;



        // статическое свойство

        public static string Default => "Hello World";

    }

}
```

нестатический блок `extension(string str)` получает получателя в параметре `str`. свойство `IsNumber` истинно, когда каждый символ лежит в диапазоне от `'0'` до `'9'`. пустая строка по этому циклу тоже даёт истину: проверять нечего, до `return false` выполнение не доходит. `"123"` поэтому печатает `true`, `"abc"` печатает `false`. метод `CharCount` считает вхождения символа. в строке `"Привет мир"` буква `и` встречается дважды, и вызов возвращает 2.

статический блок `extension(string)` не именует получателя: члены относятся к типу. операторы `>` и `<` сравнивают длины. у `"hello"` длина 5, у `"ello"` длина 4, поэтому первое сравнение печатает `true`, второе `false`. статическое свойство `Default` возвращает литерал `"Hello World"` и читается как `string.Default`.

подробнее блоки расширений разобраны в соответствующей статье.

### параметры лямбда-выражения с модификаторами

до c# 14 модификатор параметра лямбды (`scoped`, `ref`, `in`, `out` или `ref readonly`) допускался только вместе с явным типом этого параметра. тип был нужен сразу, потому что из одной лямбды компилятору больше неоткуда было взять ни тип, ни способ передачи. с c# 14 модификатор можно указать и без типа параметра, если тип выводится из целевого типа делегата.

раньше параметр с `ref` записывали так.

```c#


var changeAge = (ref int age, int new_value) => {if(new_value > 0) age = new_value;};
```

с c# 14 тип у параметров лямбды опускают. его поставляет делегат, к которому лямбда приводится.

```c#


delegate void ChangeInt(ref int old_value, int new_value);



ChangeInt changeAge = (ref age, new_value) => {if(new_value > 0) age = new_value;};
```

делегат `ChangeInt` фиксирует сигнатуру: первый параметр передаётся по ссылке и имеет тип `int`, второй передаётся по значению и тоже `int`. у лямбды остаются модификатор `ref` и имена `age` и `new_value`. отдельное объявление делегата в этом месте обязательно. без целевого типа опущенные типы параметров вывести не из чего.

применение то же: лямбда пишет в переменную по ссылке, если новое значение больше нуля.

```c#


ChangeInt changeAge = (ref age, new_value) => {if(new_value > 0) age = new_value;};



int userAge = 34;

changeAge(ref userAge, 41);

Console.WriteLine(userAge); // 41



delegate void ChangeInt(ref int old_value, int new_value);
```

`userAge` начинается с 34. вызов передаёт 41, условие `new_value > 0` истинно, и в переменную записывается 41. печать показывает уже новое значение.

### присваивание с проверкой на null

операторы `?.` и `?[]` с c# 14 допустимы в левой части обычного и составного присваивания. до этой версии перед записью в член ссылки приходилось отдельно проверять, что ссылка не равна `null`, иначе обращение к члену завершалось бы исключением.

```c#


Person? person = null;



if(person is not null)

{

    person.Name = "Tom";

}



Console.WriteLine(person?.Name);   // ничего не выводит 



class Person

{

    public string? Name {get; set;} 

}
```

при `person`, равном `null`, ветвь с присваиванием не выполняется. последующее чтение `person?.Name` тоже не доходит до свойства, и имя на консоль не попадает.

с c# 14 проверка встраивается в левую часть присваивания.

```c#


Person? person = null;



// присваивание, если только person не равно null

person?.Name = "Tom";



Console.WriteLine(person?.Name);   // ничего не выводит 



class Person

{

    public string? Name {get; set;} 

}
```

в выражении `person?.Name = "Tom"` правая часть оператора `=` вычисляется только если левая часть имеет получателя, отличного от `null`. если `person` равен `null`, присваивания нет, правая часть не выполняется, исключения нет. в примере `person` как раз `null`, поэтому строка имени снова не печатается.

та же проверка действует для составных операторов присваивания: `+=`, `-=` и остальных. инкремент и декремент (`++` и `--`) в этой позиции не допускаются.

### приложения на основе файлов

с c# 14 и .net 10 программу можно собрать как приложение на основе файла (file-based app). отдельный файл проекта для такого запуска не требуется: исходный файл передаётся команде `dotnet run`, а sdk подставляет проект на время сборки. сборка и запуск короткой программы сводятся к одному файлу.

достаточно создать файл с текстом программы и указать его в команде. файл `hello.cs` содержит одну печать.

```c#
Console.WriteLine("Hello METANIT.COM");
```

в консоли переходят в каталог, где лежит этот файл, и выполняют `dotnet run hello.cs`.

```bash


eugene@Eugene:/dotnet/scripts$ dotnet run hello.cs

Hello METANIT.COM

eugene@Eugene:/dotnet/scripts$
```

команда печатает `Hello METANIT.COM` и возвращает управление оболочке.
