часть операций длится заметное время: обращение к сети, чтение и запись файлов, запрос к базе данных. синхронный вызов такой операции на основном потоке блокирует этот поток на всё время работы. в программе с графическим интерфейсом, настольной или мобильной, блокируется поток сообщений, и окно перестаёт принимать ввод. в серверном коде поток, занятый ожиданием, не берёт следующий запрос, и при большом числе одновременных запросов пропускная способность падает. чтобы ожидание не держало поток, в c# используется асинхронность.

**асинхронность** выносит ожидание из постоянного владения потоком. долгая операция описывается асинхронным методом: на время незавершённого ожидания поток возвращается в пул и обслуживает другие задачи, а когда операция завершается, методу снова выделяется поток, и выполнение продолжается с места остановки. компилятор реализует это конечным автоматом. локальные переменные метода становятся полями состояния, а каждый `await` является точкой, в которой метод может вернуть управление и позже продолжиться.

с асинхронными методами связаны два слова: **async** и **await**. они пишутся вместе в том смысле, что `await` разрешён только там, где метод помечен `async`. модификатор `async` сам по себе метод на другой поток не отправляет и параллельным его не делает. он сообщает компилятору, что в теле допустимы выражения `await`, и включает генерацию автомата.

**асинхронный метод** распознаётся по трём признакам:

- в заголовке стоит модификатор `async`

- в теле есть одно или несколько выражений `await`

- возвращаемый тип один из следующих: `void`

- `Task`

- `Task<TResult>`

- `ValueTask<TResult>`

параметров может быть сколько угодно, в том числе ни одного. параметры с модификаторами **out**, **ref** и **in** у такого метода запрещены: продолжение выполняется позже, уже не в том кадре стека, где метод был вызван.

простейшие определение и вызов:

```c#


await PrintAsync();   // вызов асинхронного метода

Console.WriteLine("Некоторые действия в методе Main");



void Print()

{

    Thread.Sleep(3000);     // имитация продолжительной работы

    Console.WriteLine("Hello  enoobis.COM");

}



// определение асинхронного метода

async Task PrintAsync()

{

    Console.WriteLine("Начало метода PrintAsync"); // выполняется синхронно

    await Task.Run(Print);                // выполняется асинхронно

    Console.WriteLine("Конец метода PrintAsync");

}
```

`Print` выводит строку и перед этим занимает поток на три секунды через `Thread.Sleep()`. в примере это замена долгой операции. на её месте в программе могли бы быть запись файла или запрос к базе, для разбора порядка достаточно задержки и одной строки на консоль.

`PrintAsync` является асинхронным: перед возвращаемым типом стоит **async**, тип результата `Task`, в теле есть **await**.

явного `return` с объектом `Task` в `PrintAsync` нет. объект строит компилятор. раз в теле есть `await`, тип `Task` означает операцию без отдельного значения, которая завершается вместе с методом.

оператор **await** стоит перед операцией, которая может идти асинхронно. здесь это постановка `Print` в пул:

```c#
await Task.Run(Print);
```

по соглашению имя заканчивается суффиксом **Async**, как `PrintAsync()`. компилятор этого не требует.

вызов из метода `Main`:

```c#
await PrintAsync();   // вызов асинхронного метода
```

консольный вывод:

```bash


Начало метода PrintAsync

Hello  enoobis.COM

Конец метода PrintAsync

Некоторые действия в методе Main
```

порядок строк складывается так:

- запускается `Main` и вызывает `PrintAsync`.

- `PrintAsync` идёт синхронно на вызывающем потоке до первого `await`.

```c#
Console.WriteLine("Начало метода PrintAsync"); // выполняется синхронно
```

- выражение `await` запускает асинхронную операцию `Task.Run(Print)`. в комментарии к разбору тот же запуск записывают лямбдой `Task.Run(()=>Print())`. `Task.Run` возвращает `Task`, на этот момент ещё не завершённый. `Print` выполняется на потоке пула, и `Thread.Sleep` внутри него этот поток занимает: учебная пауза здесь блокирующая. неблокирующая пауза задаётся через `Task.Delay` и разобрана ниже.

- пока `Task.Run(Print)` выполняется, а в примере это около трёх секунд, `await` запоминает продолжение `PrintAsync` и возвращает незавершённый `Task` вызывающему методу, то есть в `Main`. вызов записан как `await PrintAsync()`, поэтому `Main` тоже останавливается на своём `await` и не печатает следующую строку, пока `PrintAsync` не завершится.

- когда операция заканчивается и строка `Hello  enoobis.COM` уже выведена, продолжает работу `PrintAsync` и печатает `Конец метода PrintAsync`.

- после завершения `PrintAsync` продолжает работу `Main` и печатает `Некоторые действия в методе Main`.

этот порядок совпадает с выводом: строка `Main` последняя. если сохранить задачу и вызвать `await` позже, операторы между запуском и ожиданием выполнятся, пока операция ещё идёт. такой вариант показан ниже, в разделе про последовательный и одновременный запуск.

### асинхронный метод Main

оператор **await** допустим только в методе с модификатором **async**. если `await` стоит в `Main`, точка входа тоже объявляется асинхронной. предыдущий фрагмент в полной записи выглядит так:

```c#


class Program

{

    async static Task Main(string[] args)

    {

        await PrintAsync();   // вызов асинхронного метода

        Console.WriteLine("Некоторые действия в методе Main");





        void Print()

        {

            Thread.Sleep(3000);     // имитация продолжительной работы

            Console.WriteLine("Hello  enoobis.COM");

        }



        // определение асинхронного метода

        async Task PrintAsync()

        {

            Console.WriteLine("Начало метода PrintAsync"); // выполняется синхронно

            await Task.Run(Print);                // выполняется асинхронно

            Console.WriteLine("Конец метода PrintAsync");

        }

    }

}
```

компилятор порождает служебную точку входа, которая вызывает этот `Main` и ожидает возвращённый `Task`. процесс не завершается, пока цепочка от `Main` не закончится, поэтому `await` внутри `async Main` удерживает программу до конца асинхронных операций.

### задержка асинхронной операции и Task.Delay

в асинхронном методе пауза задаётся методом **Task.Delay()**. аргумент является числом миллисекунд типа `int` либо значением `TimeSpan`:

```c#


await PrintAsync();   // вызов асинхронного метода

Console.WriteLine("Некоторые действия в методе Main");



// определение асинхронного метода

async Task PrintAsync()

{

    await Task.Delay(3000);     // имитация продолжительной работы

    // или так

    //await Task.Delay(TimeSpan.FromMilliseconds(3000));

    Console.WriteLine("Hello  enoobis.COM");

}
```

`Task.Delay` сам является асинхронной операцией: метод регистрирует таймер и возвращает `Task`, который завершится по срабатыванию таймера. поток пула на время паузы не занимается. перед вызовом ставится `await`. `Thread.Sleep` на том же интервале держал бы текущий поток.

### преимущества асинхронности

предыдущие фрагменты устроены просто и служат схемой вызова. следующий код синхронный и трижды вызывает долгий метод:

```c#


PrintName("Tom");

PrintName("Bob");

PrintName("Sam");



void PrintName(string name)

{

    Thread.Sleep(3000);     // имитация продолжительной работы

    Console.WriteLine(name);

}
```

три вызова `PrintName` идут последовательно. каждый следующий ждёт, пока закончится предыдущий. задержка внутри метода равна трём секундам, поэтому программа занимает не меньше 9 секунд.

тот же метод в асинхронной форме, с ожиданием каждого вызова отдельно:

```c#


await PrintNameAsync("Tom");

await PrintNameAsync("Bob");

await PrintNameAsync("Sam");



// определение асинхронного метода

async Task PrintNameAsync(string name)

{

    await Task.Delay(3000);     // имитация продолжительной работы

    Console.WriteLine(name);

}
```

вместо `PrintName` три раза вызывается `PrintNameAsync`. пауза записана как `Task.Delay(3000)`. поток на время таймера свободен, и долгое ожидание не блокирует основной поток так, как это делал `Thread.Sleep`. оператор `await` перед каждым вызовом останавливает вызывающий метод до конца данного вызова, поэтому порядок остаётся строгим, и нижняя оценка снова 9 секунд.

запуск всех трёх операций до какого-либо ожидания:

```c#


var tomTask = PrintNameAsync("Tom");

var bobTask = PrintNameAsync("Bob");

var samTask = PrintNameAsync("Sam");



await tomTask;

await bobTask;

await samTask;

// определение асинхронного метода

async Task PrintNameAsync(string name)

{

    await Task.Delay(3000);     // имитация продолжительной работы

    Console.WriteLine(name);

}
```

задачи фактически стартуют в момент вызова `PrintNameAsync`: каждый метод доходит до `await Task.Delay` и возвращает незавершённый `Task`. три таймера идут одновременно. оператор `await` стоит там, где результаты нужно дождаться, в конце программы. нижняя оценка времени составляет 3 секунды, то есть время одной паузы, и заведомо меньше 9 секунд.

### определение асинхронного лямбда-выражения

асинхронная операция записывается не только отдельным методом, но и лямбдой. у лямбды тот же модификатор `async`, а тип результата выводится как `Task` или `Task<TResult>`:

```c#


// асинхронное лямбда-выражение

Func<string, Task> printer = async (message) =>

{

    await Task.Delay(1000);

    Console.WriteLine(message);

};



await printer("Hello World");

await printer("Hello  enoobis.COM");
```

переменная `printer` имеет тип `Func<string, Task>`: на входе `string`, на выходе `Task`. вызов возвращает задачу, `await` её ожидает. до первого `await` тело выполняется синхронно в вызывающем потоке, затем вызывающий получает незавершённый `Task` и может продолжать свою работу либо сразу ожидать, как в этих двух строках.
