одна из возможностей dlr состоит в том, что на clr исполняются динамические языки **IronPython** и **IronRuby**. отдельный язык внутри процесса c# работает как вложенная среда рядом с основным кодом. динамические языки применяют реже статически типизированных, но у них есть свои области. одна из них называется клиентскими сценариями: пользователь программы добавляет поведение, не пересобирая основную сборку. так устроены редакторы, средства автоматизации и игры, которые подгружают сценарии на внешнем языке. вторая область появляется, когда нужная библиотека существует на python и не имеет аналога в .net. ironpython в этом случае исполняет python-код в том же процессе, что и программа на c#.

ниже ironpython подключается к консольному проекту. сначала в проект добавляются пакеты через nuget. в окне проекта на узле **Dependencies** выполняется щелчок правой кнопкой мыши, и в списке выбирается пункт **Manage NuGet Packages...** (управление nuget-пакетами):

![пакетный менеджер nuget в visual studio](/uploads/course-lectures/b40e975f30f2789b6baa0de9d3cac4422659056b.png)

открывается окно диспетчера пакетов. в поле поиска вводится `DLR`. среди результатов первый пакет называется **DynamicLanguageRuntime**, его и устанавливают:

![пакет dynamiclanguageruntime в nuget](/uploads/course-lectures/0e63fde60a5e5ba169319e52c154bca5aab07d32.png)

после установки в узел **Dependencies** попадает библиотека **Microsoft.Scripting**. это хостинг dlr: общие типы движка сценариев, не привязанные к одному языку.

затем добавляется пакет **IronPython**. в поле поиска вводится `IronPython`, и устанавливается одноимённый пакет:

![пакет ironpython в nuget](/uploads/course-lectures/5c040a29407f10e8cf001bd45f1be20b361f634c.png)

после установки в узле **Dependencies** появляется библиотека **IronPython**. она содержит реализацию языка и фабрику движка `Python`.

минимальная программа, которая исполняет строку python, выглядит так:

```c#


using IronPython.Hosting;

using Microsoft.Scripting.Hosting;



ScriptEngine engine = Python.CreateEngine();

engine.Execute("print('hello, world')");
```

консольный вывод:

```consoletext


hello, world
```

строка `print('hello, world')` является кодом python и печатает текст на консоль. движок, который этот код исполняет, представлен классом **ScriptEngine**. экземпляр создаётся фабрикой `Python.CreateEngine()`. метод `Execute()` компилирует переданный фрагмент и тут же его выполняет. отдельного объекта области видимости в этом вызове нет: фрагмент исполняется в области, которую движок создаёт сам.

тот же текст можно вынести в файл **hello.py**, обычный текстовый файл с кодом python:

```c#


print ("hello,  enoobis.com")
```

запуск файла:

```c#


using IronPython.Hosting;

using Microsoft.Scripting.Hosting;



ScriptEngine engine = Python.CreateEngine();

engine.ExecuteFile("hello.py");
```

предполагается, что файл скрипта лежит в каталоге проекта и попадает в рабочий каталог процесса, откуда `ExecuteFile` читает относительный путь:

![файл с кодом python в проекте на c#](/uploads/course-lectures/ac3d55ede816fa41473845514ef1da6c27b52809.png)

годится и абсолютный путь. если скрипт расположен по пути `D://hello.py`, вызов такой:

```c#


ScriptEngine engine = Python.CreateEngine();

engine.ExecuteFile("D://hello.py");
```

`ExecuteFile` отличается от `Execute` источником текста: метод читает файл и исполняет его содержимое тем же движком.

### scriptscope

объект `ScriptScope` связывает программу на c# со скриптом. через него в скрипт передают переменные, из скрипта читают переменные и получают ссылки на функции. скрипт **hello2.py** использует внешнюю переменную `y`:

```python


x = 10

z = x + y

print(z)
```

переменная `x` задаётся внутри скрипта, `y` должна уже лежать в области видимости, `z` вычисляется как сумма, и `print` выводит `z`.

программа, которая подставляет `y` и забирает результат:

```c#


using IronPython.Hosting;

using Microsoft.Scripting.Hosting;



int y = 22;



ScriptEngine engine = Python.CreateEngine();

ScriptScope scope = engine.CreateScope();

scope.SetVariable("y", y);

engine.ExecuteFile("hello.py", scope);

dynamic x = scope.GetVariable("x");

dynamic z = scope.GetVariable("z");

Console.WriteLine($"{x} + {y} = {z}");
```

`ScriptScope` создаётся методом `CreateScope` у движка. `SetVariable` записывает в область пару имя-значение: здесь имя `"y"` получает целое `22` из программы на c#. `ExecuteFile` исполняет файл в этой области, а не в пустой области по умолчанию. `GetVariable` читает значение обратно по имени. результаты сохраняются в переменных типа `dynamic`, потому что статический тип объекта python вызывающей программе заранее неизвестен.

в листинге файл скрипта выше назван **hello2.py**, а `ExecuteFile` открывает `"hello.py"`. исполняется тот файл, путь к которому передан в метод: в нём должны быть присваивания `x` и `z`, иначе `GetVariable` эти имена не найдёт.

`SetVariable` передаёт значения в скрипт, `GetVariable()` забирает их из скрипта.

консольный вывод:

```consoletext


32

10 + 22 = 32
```

первая строка, `32`, напечатана самим скриптом: `z = 10 + 22`. вторая строка напечатана уже из c#: `x` прочитан как `10`, локальное `y` равно `22`, `z` прочитан как `32`.

### вызов функций из ironpython

в файле **hello.py** определяется функция квадрата числа:

```c#


def square(n):

   return n * n
```

обращение к ней из c#:

```c#


using IronPython.Hosting;

using Microsoft.Scripting.Hosting;



int number = 5;



ScriptEngine engine = Python.CreateEngine();

ScriptScope scope = engine.CreateScope();



engine.ExecuteFile("hello.py", scope);

dynamic square = scope.GetVariable("square");

// вызываем функцию и получаем результат

dynamic result = square(number);

Console.WriteLine(result);      // 25
```

функция достаётся из области так же, как переменная: `scope.GetVariable("square");`. объект, который возвращает ironpython, вызывается как метод. в `square` передаётся `number`, равное `5`, и результат равен `25`. связывание аргументов выполняет dlr: на этапе компиляции c# у переменной `square` нет статической сигнатуры, проверка числа и типов аргументов происходит в момент вызова.
