если класс применяет интерфейс, он реализует все методы и свойства интерфейса, у которых нет реализации по умолчанию. реализацию можно отложить: члены объявляют абстрактными и переносят обязанность на производные классы.

```c#


interface IMovable

{

	void Move();

}

abstract class Person : IMovable

{

	public abstract void Move();

}

class Driver : Person

{

	public override void Move() => Console.WriteLine("Шофер ведет машину");

}
```

при реализации интерфейса учитываются и методы и свойства, унаследованные от базового класса.

```c#


IAction action = new HeroAction();

action.Move();  // Move in BaseAction



interface IAction

{

    void Move();

}

class BaseAction

{

    public void Move() => Console.WriteLine("Move in BaseAction");

}

class HeroAction : BaseAction, IAction{ }
```

класс `HeroAction` реализует интерфейс `IAction`, но для метода `Move` из интерфейса используется `Move`, унаследованный от базового класса `BaseAction`. объявлять `Move` в `HeroAction` не нужно: сигнатура уже есть в `BaseAction`, и компилятор берёт её в карту интерфейса.

если класс одновременно наследует другой класс и реализует интерфейс, как `HeroAction` в примере выше, имя базового класса указывают до реализуемых интерфейсов:

```b
class HeroAction : BaseAction, IAction
```

### изменение реализации интерфейсов в производных классах

базовый класс уже реализовал интерфейс, а в классе-наследнике реализацию нужно изменить. для этого член интерфейса либо переопределяют, либо скрывают.

первый вариант: переопределение виртуальных и абстрактных методов.

```c#


interface IAction

{

    void Move();

}

class BaseAction : IAction

{

    public virtual void Move() => Console.WriteLine("Move in BaseAction");

}

class HeroAction : BaseAction

{

    public override void Move() => Console.WriteLine("Move in HeroAction");

}
```

в базовом классе `BaseAction` реализованный метод интерфейса объявлен виртуальным (его можно сделать и абстрактным), а в производном классе он переопределён.

вызов через переменную интерфейса, если она ссылается на объект производного класса, использует реализацию производного класса. диспетчеризация виртуального метода идёт по фактическому типу объекта:

```c#


BaseAction action1 = new HeroAction();

action1.Move();            // Move in HeroAction



IAction action2 = new HeroAction();

action2.Move();             // Move in HeroAction
```

второй вариант: сокрытие метода в производном классе.

```c#


interface IAction

{

    void Move();

}

class BaseAction : IAction

{

    public void Move() => Console.WriteLine("Move in BaseAction");



}

class HeroAction : BaseAction

{

    public new void Move() => Console.WriteLine("Move in HeroAction");

}
```

те же классы при сокрытии:

```c#


BaseAction action1 = new HeroAction();

action1.Move();            // Move in BaseAction



IAction action2 = new HeroAction();

action2.Move();           // Move in BaseAction
```

интерфейс реализован именно в классе `BaseAction`, поэтому через переменную `action2` доступна только реализация `Move` из `BaseAction`. слово `new` меняет вызов по статическому типу производного класса и не перестраивает карту интерфейса.

третий вариант: повторная реализация интерфейса в классе-наследнике.

```c#


interface IAction

{

    void Move();

}

class BaseAction : IAction

{

    public void Move() => Console.WriteLine("Move in BaseAction");

}

class HeroAction : BaseAction, IAction

{

    public new void Move() =>  Console.WriteLine("Move in HeroAction");

}
```

повторное указание `IAction` в списке базовых типов заставляет заново построить карту интерфейса для `HeroAction`. реализация этого метода из базового класса при вызове через интерфейс игнорируется:

```c#


BaseAction action1 = new HeroAction();

action1.Move();            // Move in BaseAction



IAction action2 = new HeroAction();

action2.Move();             // Move in HeroAction



HeroAction action3 = new HeroAction();

action3.Move();             // Move in HeroAction
```

для переменной `action1` по-прежнему действует раннее связывание. статический тип ссылки есть `BaseAction`, метод там не виртуальный, поэтому через эту переменную вызывается реализация `Move` только из базового класса, который переменная представляет.

четвёртый вариант: явная реализация интерфейса.

```c#


interface IAction

{

    void Move();

}

class BaseAction : IAction

{

    public void Move() => Console.WriteLine("Move in BaseAction");

}

class HeroAction : BaseAction, IAction

{

    public new void Move() => Console.WriteLine("Move in HeroAction");

    // явная реализация интерфейса

    void IAction.Move() => Console.WriteLine("Move in IAction");

}
```

для переменной типа `IAction` используется явная реализация интерфейса `IAction`. для переменной `HeroAction` по-прежнему используется неявная реализация:

```c#


BaseAction action1 = new HeroAction();

action1.Move();            // Move in BaseAction



IAction action2 = new HeroAction();

action2.Move();             // Move in IAction



HeroAction action3 = new HeroAction();

action3.Move();             // Move in HeroAction
```
