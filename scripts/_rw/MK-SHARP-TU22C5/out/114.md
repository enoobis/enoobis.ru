классы `StringBuilder` и `String` покрывают обычные операции над строками: конкатенацию, поиск подстроки, замену, разбиение. когда структура фрагмента задаётся не фиксированной подстрокой, а образцом, в .net используется механизм регулярных выражений. регулярное выражение описывает множество строк. на практике язык .net шире строго регулярных грамматик: в нём есть обратные ссылки и просмотр вперёд и назад (lookaround), поэтому отдельное выражение может требовать памяти сверх конечного автомата. движок `Regex` сопоставляет образец со входом и возвращает совпадения. тот же разбор, записанный циклами, `IndexOf` и `Substring`, занимает больше кода, а правило поиска в варианте с регулярным выражением собрано в одном шаблоне.

основная функциональность сосредоточена в пространстве имён `System.Text.RegularExpressions`. центральный тип этого пространства: класс `Regex`. он принимает образец и применяет его к строке. в примере ниже в тексте находятся все словоформы с корнем "туп".

```c#


using System.Text.RegularExpressions;



string s = "Бык тупогуб, тупогубенький бычок, у быка губа бела была тупа";

Regex regex = new Regex(@"туп(\w*)");

MatchCollection matches = regex.Matches(s);

if (matches.Count > 0)

{

    foreach (Match match in matches)

        Console.WriteLine(match.Value);

}

else

{

    Console.WriteLine("Совпадений не найдено");

}
```

шаблон `туп(\w*)` задаёт литеральный корень "туп" и сразу за ним захватывающую группу `(\w*)`. метасимвол `\w` совпадает с символом категории "буква, десятичная цифра или соединитель". в режиме по умолчанию класс юникодный. при `RegexOptions.ECMAScript` класс сужается до набора ecmascript. квантификатор `*` означает повтор предыдущего атома ноль или более раз: после корня может не быть ни одного символа, а может стоять последовательность любой длины. скобки запоминают совпавший фрагмент группы. в этом примере читается полное совпадение `Match.Value`, группа 1 не извлекается.

метод `Matches` применяет выражение ко всей строке и возвращает `MatchCollection`: все неперекрывающиеся совпадения. поиск идёт слева направо, следующее сопоставление начинается после конца предыдущего.

элемент коллекции имеет тип `Match`. свойство `Value` возвращает подстроку, совпавшую с шаблоном целиком, то есть группу 0.

для скороговорки из примера вывод такой:

```bash


тупогуб

тупогубенький

тупа
```

### параметр regexoptions

у `Regex` несколько конструкторов. две перегрузки принимают перечисление `RegexOptions`: набор флагов, меняющих компиляцию образца и семантику сопоставления. отдельные значения:

- `Compiled`: выражение компилируется в il. повторные сопоставления выполняются быстрее ценой времени первой компиляции и дополнительной памяти. флаг оправдан, когда один и тот же образец применяется многократно
- `CultureInvariant`: сравнения, зависящие от культуры, выполняются в инвариантной культуре, региональные различия игнорируются
- `IgnoreCase`: сопоставление без учёта регистра. для юникода это свёртка регистра (case folding), а не только приведение символов к нижнему регистру текущей культуры
- `IgnorePatternWhitespace`: из образца убираются пробельные символы, которые не экранированы и не стоят внутри класса символов, и разрешаются комментарии от `#` до конца строки. пробел как часть искомого текста в этом режиме записывается явно, например через `\s` или экранирование
- `Multiline`: текст обрабатывается построчно. якоря `^` и `$` совпадают с началом и концом каждой строки. без этого флага те же якоря относятся ко всему входу
- `RightToLeft`: сопоставление идёт справа налево. направление поиска определяет, какое из нескольких возможных совпадений будет найдено первым
- `Singleline`: точка `.` совпадает с любым символом, включая перевод строки `\n`. без этого флага `.` не совпадает с `\n`

пример с игнорированием регистра:

```c#


Regex regex = new Regex(@"туп(\w*)", RegexOptions.IgnoreCase);
```

несколько флагов соединяются операцией побитового или: `RegexOptions` помечено атрибутом `[Flags]`, значения занимают независимые биты.

```c#


Regex regex = new Regex(@"туп(\w*)", RegexOptions.Compiled | RegexOptions.IgnoreCase);
```

### синтаксис регулярных выражений

часть синтаксиса, на которую опираются дальнейшие примеры:

- `^`: якорь начала строки. образец `@"^пр\w*"` в строке "привет мир" совпадает со словом "привет": совпадение обязано начинаться в начале строки. в однострочном режиме это начало всего текста
- `$`: якорь конца строки. образец `@"\w*ир$"` в строке "привет мир" совпадает со словом "мир": фрагмент "ир" стоит в конце
- `.`: любой одиночный символ, кроме `\n`, пока не задан `RegexOptions.Singleline`. образец `"м.р"` совпадает и с "мир", и с "мор"
- `*`: предыдущий атом повторяется 0 и более раз
- `+`: предыдущий атом повторяется 1 и более раз
- `?`: предыдущий атом повторяется 0 или 1 раз
- `\s`: любой пробельный символ
- `\S`: любой символ вне класса пробельных
- `\w`: любой алфавитно-цифровой символ. в режиме unicode это буква, цифра или соединитель
- `\W`: любой символ вне класса `\w`
- `\d`: любая десятичная цифра. в режиме unicode сюда входят и десятичные цифры других письменностей. класс `[0-9]` ограничен кодовыми пунктами от `0` до `9`
- `\D`: любой символ, не являющийся десятичной цифрой

это небольшая часть языка. полный перечень приведён в кратком справочнике на msdn: [элементы языка регулярных выражений: краткий справочник](https://docs.microsoft.com/en-us/dotnet/standard/base-types/regular-expression-language-quick-reference).

на скороговорке `Бык тупогуб, тупогубенький бычок, у быка губа бела была тупа` дальше ищутся все слова, в которых встречается корень "губ":

```c#


string s = "Бык тупогуб, тупогубенький бычок, у быка губа бела была тупа";

Regex regex = new Regex(@"\w*губ\w*");
```

`\w*` совпадает с последовательностью алфавитно-цифровых символов любой длины, включая пустую. шаблон `\w*губ\w*` находит непрерывную последовательность `\w`, внутри которой есть подстрока "губ". запятая и пробел в `\w` не входят, поэтому совпадение останавливается на границе слова: после "тупогуб" запятая в совпадение не попадает.

следующий образец описывает телефонный номер в форме 111-111-1111:

```c#


string s = "456-435-2318";

Regex regex = new Regex(@"\d{3}-\d{3}-\d{4}");
```

когда длина известна точно, её задают квантификатором в фигурных скобках. `\d{3}` означает ровно три цифры. общая форма: `{n}` это ровно n повторов, `{n,m}` это от n до m, `{n,}` это не меньше n. в образце три группы цифр, между ними литеральные дефисы.

ограничение можно задать не готовым классом (`\d`, `\s`), а явным перечнем символов:

```c#


string s = "456-435-2318";

Regex regex = new Regex("[0-9]{3}-[0-9]{3}-[0-9]{4}");
```

квадратные скобки задают символьный класс: ровно один символ из перечисления или диапазона. для номера из обычных десятичных цифр шаблон `[0-9]{3}-[0-9]{3}-[0-9]{4}` принимает те же строки, что и предыдущий образец с `\d` и дефисами.

диапазон задаётся и для букв. выражение `Regex regex = new Regex("[a-v]{5}");` совпадает с любой последовательностью из пяти символов, каждый из которых лежит в диапазоне кодов от `a` до `v` включительно. сравнение в классе идёт по кодам символов. без `IgnoreCase` регистр различается: `A` в диапазон `a-v` не входит.

в том же классе можно перечислить отдельные символы: `Regex regex = new Regex(@"[2]*-[0-9]{3}-\d{4}");`. `[2]*` означает ноль или более символов `2`. под образец подходит, в частности, номер "222-222-2222": участок до первого дефиса состоит из двоек.

операция `|` задаёт альтернативу: левая ветвь или правая. приоритет `|` ниже квантификаторов и конкатенации, поэтому альтернативу заключают в группу.

```c#
Regex regex = new Regex(@"(2|3){3}-[0-9]{3}-\d{4}");
```

`(2|3){3}` означает три раза подряд выбор между символами `2` и `3`. под шаблон попадают "222-222-2222" и "323-435-2318". строка "235-435-2318" не совпадает: среди первых трёх цифр есть `5`, а альтернатива допускает только `2` и `3`.

символы `*`, `+`, `.`, `?`, скобки, `|` и ряд других в языке регулярных выражений имеют специальную семантику. литеральное вхождение такого символа записывается с экранированием обратной косой чертой. в дословной строке c# (`@"..."`) одна обратная косая уже попадает в образец: escape-последовательность c# здесь не обрабатывается.

```c#


Regex regex = new Regex(@"(2|3){3}\.[0-9]{3}\.\d{4}");

// этому выражению будет соответствовать строка "222.222.2222"
```

`\.` совпадает с точкой как с обычным символом. комментарий в примере фиксирует строку "222.222.2222". без экранирования точка совпала бы с любым символом на этом месте, и под шаблон попала бы, например, строка "222x222y2222".

### проверка на соответствие строки формату

проверка формата входной строки сводится к сопоставлению с образцом. так проверяют электронный адрес, номер телефона, код. класс `Regex` предоставляет статический метод `IsMatch`: он сопоставляет строку с образцом и возвращает логическое значение, не строя коллекцию совпадений.

```c#


using System.Text.RegularExpressions;



string pattern = @"^(?("")(""[^""]+?""@)|(([0-9a-z]((\.(?!\.))|[-!#\$%&'\*\+/=\?\^`\{\}\|~\w])*)(?<=[0-9a-z])@))" +

                @"(?(\[)(\[(\d{1,3}\.){3}\d{1,3}\])|(([0-9a-z][-\w]*[0-9a-z]*\.)+[a-z0-9]{2,17}))$";

var data = new string[]

{

    "tom@gmail.com",

    "+12345678999",

    "bob@yahoo.com",

    "+13435465566",

    "sam@yandex.ru",

    "+43743989393"

};



Console.WriteLine("Email List");

for(int i = 0; i < data.Length; i++)

{

    if (Regex.IsMatch(data[i], pattern, RegexOptions.IgnoreCase))

    {

        Console.WriteLine(data[i]);

    }

}
```

переменная `pattern` содержит образец адреса электронной почты. этот образец опубликован microsoft на страницах msdn. в нём есть условные конструкции `(?(...)...)`, просмотр назад `(?<=...)`, отрицательный просмотр вперёд `(?!\.)` и альтернатива между адресом в кавычках и обычным локальным именем. здесь образец используется как готовый предикат формата.

цикл проходит массив строк и отбирает те, которые соответствуют образцу, то есть распознаются как допустимый адрес электронной почты. проверка записывается вызовом `Regex.IsMatch(data[i], pattern, RegexOptions.IgnoreCase)`. третий аргумент задаёт сопоставление без учёта регистра. при успехе метод возвращает `true`, и строка выводится. телефонные номера из того же массива под образец не попадают.

### замена и метод replace

метод `Replace` заменяет каждый фрагмент, совпавший с образцом, заданной строкой. ниже используется перегрузка экземпляра.

```c#


string text = "Мама  мыла  раму. ";

string pattern = @"\s+";

string target = " ";

Regex regex = new Regex(pattern);

string result = regex.Replace(text, target);

Console.WriteLine(result);
```

эта перегрузка принимает исходный текст и строку замены. образец `\s+` означает один или более пробельных символов подряд. метод проходит по всему тексту и заменяет каждую такую последовательность одним пробелом: несколько пробелов между словами схлопываются в один. в коде образец задан дословной строкой `@"\s+"`.

второй пример оставляет в телефонном номере произвольного формата только цифры:

```c#


string phoneNumber = "+1(876)-234-12-98";

string pattern = @"\D";

string target = "";

Regex regex = new Regex(pattern);

string result = regex.Replace(phoneNumber, target);

Console.WriteLine(result);	// 18762341298
```

шаблон `\D` совпадает с любым символом, который не является десятичной цифрой. каждый такой символ заменяется пустой строкой `""` и тем самым удаляется. из строки "+1(876)-234-12-98" получается строка "18762341298".
