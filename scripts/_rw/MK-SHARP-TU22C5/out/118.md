приложение создаёт много объектов, и часть из них за время работы так и не используется. на больших графах объектов цена видна сразу. в примере читатель хранит библиотеку, хотя ветка чтения бумажной книги может ни разу не выполниться.

```c#


class Reader

{

    Library library = new Library();

    public void ReadBook()

    {

        library.GetBook();

        Console.WriteLine("Читаем бумажную книгу");

    }



    public void ReadEbook()

    {

        Console.WriteLine("Читаем книгу на компьютере");

    }

}



class Library

{

    private string[] books = new string[99];



    public void GetBook()

    {

        Console.WriteLine("Выдаем книгу читателю");

    }

}
```

класс `Library` изображает библиотеку и хранит набор книг в массиве. класс `Reader` хранит ссылку на объект библиотеки, в которой записан читатель. у читателя два метода: чтение электронной книги и чтение обычной. для обычной книги нужен вызов метода `Library`, который эту книгу выдаёт.

если выполняется только чтение электронных книг, объект библиотеки не участвует в вычислении:

```c#


Reader reader = new Reader();

reader.ReadEbook();
```

поле `library` при этом всё равно инициализируется в момент создания `Reader`: конструктор `Library` выделяет массив из 99 ссылок. объект занимает память, хотя обращения к нему нет.

для отложенной инициализации в .net есть класс `Lazy<T>`. поле читателя заменяется так:

```c#


class Reader

{

    Lazy<Library> library = new Lazy<Library>();

    public void ReadBook()

    {

        library.Value.GetBook();

        Console.WriteLine("Читаем бумажную книгу");

    }



    public void ReadEbook()

    {

        Console.WriteLine("Читаем книгу на компьютере");

    }

}
```

класс `Library` остаётся прежним. у читателя поле имеет тип `Lazy<Library>`, а не `Library`. обращение к самой библиотеке идёт через свойство `Value`: выражение `library.Value` имеет тип `Library` и даёт тот экземпляр, к методам которого относится вызов `GetBook`. конструктор `Lazy<T>` без фабрики создаёт значение конструктором `T` без параметров. у `Library` такой конструктор есть, он объявлен неявно.

замена меняет момент выделения `Library`. последовательность вызовов:

```c#


Reader reader = new Reader();

reader.ReadEbook();

reader.ReadBook();
```

экземпляр `Library` требуется только в `reader.ReadBook()`, где вызывается `library.Value.GetBook()`. до первого чтения `Value` конструктор `Library` не выполняется. если `ReadBook` в программе не вызывается, объект библиотеки не создаётся, и массив книг не выделяется. сам объект `Lazy<Library>` создаётся сразу: он хранит фабрику и кэш, но не библиотеку.

по умолчанию инициализация потокобезопасна. режим `LazyThreadSafetyMode.ExecutionAndPublication` гарантирует однократный запуск фабрики даже при одновременном чтении `Value` из нескольких потоков. после создания экземпляр кэшируется, и следующие обращения к `Value` возвращают тот же объект.

`Lazy<T>` откладывает создание `T` до первого обращения, в котором значение действительно нужно.
