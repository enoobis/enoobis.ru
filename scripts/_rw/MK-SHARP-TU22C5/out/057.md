один обобщённый класс может быть унаследован от другого обобщённого. при этом используются различные варианты наследования: параметр типа можно передать дальше, закрыть конкретным типом или заменить собственным параметром производного класса.

базовый класс `Person` задаётся так:

```c#


class Person<T>

{

	public T Id { get;}

	public Person(T id)

	{

		Id = id;

	}

}
```

первый вариант состоит в создании класса-наследника, который типизирован тем же типом, что и базовый:

```c#


class UniversalPerson<T> : Person<T>

{

	public UniversalPerson(T id) : base(id) { }

}
```

применение класса:

```c#


Person<string> person1 = new Person<string>("34");

Person<int> person3 = new UniversalPerson<int>(45);

UniversalPerson<int> person2 = new UniversalPerson<int>(33);

Console.WriteLine(person1.Id);

Console.WriteLine(person2.Id);

Console.WriteLine(person3.Id);
```

здесь `UniversalPerson<T>` есть открытый тип, производный от открытого `Person<T>`. аргумент типа один и тот же на обоих уровнях: подстановка `int` одновременно закрывает и наследника, и базовый класс. поэтому `UniversalPerson<int>` является подтипом `Person<int>`, и ссылке `Person<int>` можно присвоить объект `UniversalPerson<int>`. ссылке `Person<string>` такой объект не присваивается: это другое конструирование того же открытого типа.

второй вариант представляет создание обычного необобщённого класса-наследника. при наследовании у базового класса нужно явно определить используемый тип:

```c#


class StringPerson : Person<string>

{

    public StringPerson(string id) : base(id) { }

}
```

в производном классе в качестве типа используется тип `string`. применение класса:

```c#


StringPerson person4 = new StringPerson("438767");

Person<string> person5 = new StringPerson("43875");

// так нельзя написать

//Person<int> person6 = new StringPerson("45545");

Console.WriteLine(person4.Id);

Console.WriteLine(person5.Id);
```

`StringPerson` закрывает параметр базового класса типом `string` и сам параметров типа не имеет. он является подтипом только `Person<string>`. присваивание объекту типа `Person<int>` невозможно: `Person<int>` и `Person<string>` суть разные сконструированные типы, и обобщённые классы в c# инвариантны. отношение наследования между `StringPerson` и `Person<string>` не переносится на другие подстановки `T`.

третий вариант представляет типизацию производного класса параметром совсем другого типа, отличного от универсального параметра базового класса. для базового класса при этом тоже указывается используемый тип:

```c#


class IntPerson<T> : Person<int>

{

    public T Code { get; set; }

    public IntPerson(int id, T code) : base(id) 

    {

        Code = code;

    }

}
```

тип `IntPerson` типизирован ещё одним типом, и этот тип может не совпадать с типом, который использует базовый класс. параметр `T` у `IntPerson<T>` не есть параметр `T` класса `Person`: у базового класса параметр уже закрыт типом `int`, а `T` наследника описывает отдельное свойство `Code`. применение класса:

```c#


IntPerson<string> person7 = new IntPerson<string>(5, "r4556");

Person<int> person8 = new IntPerson<long>(7, 4587);

Console.WriteLine(person7.Id);

Console.WriteLine(person8.Id);
```

`IntPerson<string>` и `IntPerson<long>` оба являются подтипами `Person<int>`, потому что базовая часть у них закрыта одним и тем же `int`. чем закрыт их собственный параметр, на отношение к `Person<int>` не влияет.

в классах-наследниках использование универсального параметра базового класса сочетается с собственными параметрами:

```c#


class MixedPerson<T, K> : Person<T>

    where K : struct

{

    public K Code { get; set; }

    public MixedPerson(T id, K code) : base(id)

    {

        Code = code;

    }

}
```

в дополнение к унаследованному от базового класса параметру `T` добавляется новый параметр `K`. если при этом нужно задать ограничения, они указываются после названия базового класса. применение класса:

```c#


MixedPerson<string, int> person9 = new MixedPerson<string, int>("456", 356);

Person<string> person10 = new MixedPerson<string, int>("9867", 35678);

Console.WriteLine(person9.Id);

Console.WriteLine(person10.Id);
```

`MixedPerson<T, K>` передаёт `T` в `Person<T>` и добавляет `K` с ограничением `struct`: в `Code` попадает только значимый тип. `MixedPerson<string, int>` есть подтип `Person<string>`. второй аргумент типа в это отношение не входит.

если на уровне базового класса для универсального параметра установлено ограничение, такое же ограничение должно быть определено и в производных классах, которые этот параметр используют:

```c#


class Person<T> where T : class

{

	public T Id { get;}

	public Person(T id) => Id = id;

}

class UniversalPerson<T> : Person<T> where T: class

{

	public UniversalPerson(T id) : base(id) { }

}
```

если в базовом классе в качестве ограничения указано `class`, то есть любой класс, то в производном классе в качестве ограничения тоже указывается `class` либо какой-то конкретный класс. ограничение наследника обязано влечь ограничение базового класса: иначе подстановка, законная для наследника, оказалась бы незаконной для базовой части. компилятор проверяет это при объявлении производного класса, а не в каждом месте создания экземпляра.
