многопоточность позволяет выполнять в одном процессе несколько потоков управления. поток здесь единица планирования: у него собственный стек и собственная точка выполнения, куча процесса общая. код, который поток исполняет, это тело делегата или метода, переданного при запуске. планировщик операционной системы выделяет потоку квант процессорного времени и вытесняет его по истечении кванта или при блокировке. за счёт вытеснения несколько потоков продвигаются вперемежку и для прикладной программы выглядят одновременными. на одном ядре это чередование квантов, на нескольких ядрах участки действительно исполняются параллельно.

типичный повод разнести работу по потокам: длительная операция не должна останавливать остальной код. в графическом приложении запрос к серверу или чтение и обработка большого файла, выполненные в потоке интерфейса, оставляют окно без обработки сообщений на всё время операции. вынос запроса или другой долгой работы в отдельный поток оставляет интерфейс отзывчивым. клиент-серверные программы, и многие другие, строятся на этом разделении: ожидание сети и вычисления не занимают поток, который обязан продолжать цикл обработки.

основной api потоков находится в пространстве имён `System.Threading`. отдельный поток представлен классом `Thread`.

у `Thread` есть свойства, через которые поток идентифицируют и которыми управляют его режим. основные:

- `ExecutionContext`: контекст, в котором выполняется поток. вместе с переходом на другой поток контекст переносит данные окружения, в том числе значения `AsyncLocal<T>`
- `IsAlive`: признак того, что поток уже запущен и ещё не завершился
- `IsBackground`: признак фонового потока. процесс продолжает работу, пока жив хотя бы один поток переднего плана. после их завершения фоновые потоки останавливаются вместе с процессом
- `Name`: имя потока. его задают для диагностики, в отладчике и в журналах имя читается легче числового идентификатора
- `ManagedThreadId`: числовой идентификатор потока внутри clr. на время жизни потока он не меняется
- `Priority`: приоритет потока, значение перечисления `ThreadPriority`: `Lowest`
- `BelowNormal`
- `Normal`
- `AboveNormal`
- `Highest`

по умолчанию потоку назначается `Normal`. приоритет можно сменить во время работы, в том числе поднять его до `Highest`. clr передаёт приоритет планировщику, и тот на его основании выдаёт потоку процессорное время чаще или реже. приоритет не задаёт длину кванта числом и не гарантирует порядок запуска.

состояние потока читается через `ThreadState`. значение принадлежит перечислению `ThreadState`:

- `Aborted`: поток остановлен, но ещё не завершён окончательно
- `AbortRequested`: для потока вызван метод `Abort`, остановка ещё не произошла
- `Background`: поток выполняется в фоновом режиме
- `Running`: поток запущен и работает, он не приостановлен
- `Stopped`: поток завершён
- `StopRequested`: поток получил запрос на остановку
- `Suspended`: поток приостановлен
- `SuspendRequested`: поток получил запрос на приостановку
- `Unstarted`: поток создан и ещё не запущен
- `WaitSleepJoin`: поток заблокирован вызовом `Sleep` или `Join`

`Thread.Abort`, к которому относятся состояния `Aborted` и `AbortRequested`, в современных реализациях .net не поддерживается: на .net 5 и новее вызов завершается `PlatformNotSupportedException`. значения перечисления сохранены. приостановка через `Suspend` также относится к устаревшей модели управления потоком. актуальные состояния из этого списка, с которыми имеет дело обычный код: `Unstarted`, `Running`, `WaitSleepJoin`, `Stopped`, `Background`.

за время работы статус меняется многократно, вслед за методами. до вызова `Start` статус равен `Unstarted`. после запуска он становится `Running`. вызов `Sleep` переводит поток в `WaitSleepJoin` на время ожидания. флаги `ThreadState` могут сочетаться: фоновый работающий поток несёт и `Background`, и `Running`.

статическое свойство `CurrentThread` класса `Thread` возвращает поток, который выполняет текущий код.

в программе на c# всегда есть хотя бы один поток: главный. в классической записи программы в нём выполняется метод `Main`. код верхнего уровня, как в примерах ниже, тоже выполняется в главном потоке.

свойства текущего потока читаются так:

```c#


using System.Threading;



// получаем текущий поток

Thread currentThread = Thread.CurrentThread;



//получаем имя потока

Console.WriteLine($"Имя потока: {currentThread.Name}");

currentThread.Name = "Метод Main";

Console.WriteLine($"Имя потока: {currentThread.Name}");



Console.WriteLine($"Запущен ли поток: {currentThread.IsAlive}");

Console.WriteLine($"Id потока: {currentThread.ManagedThreadId}");

Console.WriteLine($"Приоритет потока: {currentThread.Priority}");

Console.WriteLine($"Статус потока: {currentThread.ThreadState}");
```

вывод имеет примерно такой вид:

```consoletext


Имя потока:

Имя потока: Метод Main

Запущен ли поток: True

Id потока: 1

Приоритет потока: Normal

Статус потока: Running
```

свойство `Name` у нового `Thread` не задано, поэтому первая печать показывает пустую строку. после присваивания `"Метод Main"` то же свойство возвращает это имя.

для управления потоком у `Thread` есть методы. основные:

- статический `GetDomain` возвращает ссылку на домен приложения. в современном .net у процесса один домен по умолчанию, метод возвращает его
- статический `GetDomainID` возвращает идентификатор домена приложения, в котором выполняется текущий поток
- статический `Sleep` приостанавливает вызывающий поток на заданное число миллисекунд. квант при этом потоку не выделяется, планировщик может исполнять другие потоки
- `Interrupt` прерывает поток, находящийся в состоянии `WaitSleepJoin`: ожидание завершается исключением `ThreadInterruptedException`
- `Join` блокирует вызывающий поток до завершения того потока, у которого метод вызван. есть перегрузки с таймаутом
- `Start` переводит поток из `Unstarted` в планирование и начинает выполнение его делегата

задержка выполнения через `Sleep`:

```c#


using System.Threading;



for(int i = 0; i < 10; i++)

{

    Thread.Sleep(500);      // задержка выполнения на 500 миллисекунд

    Console.WriteLine(i);

}
```
