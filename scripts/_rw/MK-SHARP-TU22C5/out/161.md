c# относится к языкам со статической типизацией, однако в язык добавлены и динамические средства. начиная с .net 4.0 в среду исполнения входит dlr, dynamic language runtime. dlr является средой выполнения динамических языков на clr. на ней, в частности, работают ironpython и ironruby.

в языке со статической типизацией типы выражений и наличие членов устанавливаются на этапе компиляции. в языке с динамической типизацией набор свойств и методов объекта до начала выполнения неизвестен: связывание имени с членом происходит в момент вызова. dlr переносит эту модель в c#. программа создаёт динамические объекты, члены которых определяются во время выполнения, и использует их рядом с обычными объектами, типы которых проверены компилятором.

опорная конструкция dlr в c# называется **dynamic**. это служебное слово отключает статическую проверку операций над переменной. объект, объявленный как `dynamic`, по ходу выполнения может хранить значения разных типов:

```c#


dynamic obj = 3;            // здесь obj - целочисленное int

Console.WriteLine(obj);     // 3



obj = "Hello world";        // obj - строка

Console.WriteLine(obj);     // Hello world



obj = new Person("Tom", 37); // obj - объект Person

Console.WriteLine(obj);      // Person { Name = Tom, Age = 37 }



record class Person(string Name, int Age);
```

переменная `obj` по очереди хранит `int`, строку и экземпляр `Person`. компилятор эти присваивания не отвергает: проверка операции отложена до выполнения. в этом `dynamic` расходится со служебным словом **var**. для переменной, объявленной через `var`, тип выводится один раз на этапе компиляции и на время выполнения уже не меняется.

на уровне clr хранилище `dynamic` представляется как `object`, а места вызова помечаются так, чтобы связыватель dlr обработал их при выполнении. результат связывания кэшируется в точке вызова, поэтому повтор той же операции не разбирает члены заново.

у `dynamic` есть внешнее сходство с `object`. если в предыдущем примере заменить `dynamic` на `object` (`object x = 3;`), присваивания разных значений останутся допустимыми: `object` является корнем иерархии ссылочных типов, и упаковка значения в `object` стирает статический тип. операции над значением при этом ведут себя по-разному:

```c#


object obj = 24;

dynamic dyn = 24;

obj += 4; // так нельзя

dyn += 4; // а так можно
```

строка `obj += 4;` не компилируется. операция `+=` не определена для пары типов `object` и `int`: статический тип левого операнда не содержит такого оператора. для переменной, объявленной как `dynamic`, та же операция проходит компиляцию. фактический тип становится известен только во время выполнения, и уже тогда связыватель либо находит операцию, либо завершает вызов исключением `RuntimeBinderException`.

служебное слово `dynamic` ставится не только на локальные переменные. им помечаются свойства, параметры и возвращаемые значения методов:

```c#


class Person

{

    public string Name { get;}

    public dynamic Age { get; set; }

    public Person(string name, dynamic age)

    {

        Name = name; Age = age;

    }



    // выводим зарплату в зависимости от переданного формата

    public dynamic GetSalary(dynamic value, string format)

    {

        if (format == "string") return $"{value} euro";

        else if (format == "int") return value;

        else return 0.0;

    }



    public override string ToString() => $"Name: {Name}  Age: {Age}";

}
```

у класса `Person` свойство `Age` имеет тип `dynamic`. присваивания `person.Age=22` и `person.Age="twenty-two"` оба допустимы: статическая проверка типа правой части не выполняется. через параметр `age` конструктора в это свойство передаётся любое значение, которое вызывающий код сочтёт возрастом.

метод `GetSalary` возвращает `dynamic`. ветка выбирается по строке `format`. при `"string"` метод возвращает строковое представление суммы с суффиксом `euro`, при `"int"` возвращает переданное значение как есть, в остальных случаях возвращает `0.0`. параметр `value` тоже объявлен как `dynamic`, поэтому на место дохода можно передать целое число, дробное число или строку. конкретное применение выглядит так:

```c#


dynamic tom = new Person("Tom", 22);

Console.WriteLine(tom);

Console.WriteLine(tom.GetSalary(28, "int"));



dynamic bob = new Person("Bob", "twenty-two");

Console.WriteLine(bob);

Console.WriteLine(bob.GetSalary("twenty-eight", "string"));
```

консольный вывод программы:

```consoletext


Name: Tom  Age: 22

28

Name: Bob  Age: twenty-two

twenty-eight euro
```

для `tom` возраст хранится как целое `22`, а `GetSalary(28, "int")` возвращает число `28`. для `bob` возраст хранится как строка `twenty-two`, а `GetSalary("twenty-eight", "string")` возвращает строку `twenty-eight euro`. тип результата на стороне вызова остаётся `dynamic`, и компилятор не сопоставляет его со строкой формата.
