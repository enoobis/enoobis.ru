в статье "динамическая загрузка сборок и позднее связывание" разбирается, как загрузить сборку в уже работающее приложение и вызвать её код через рефлексию. фреймворк .net позволяет и обратное: выгрузить сборку и тем самым уменьшить объём занятой памяти. для этого служит класс `AssemblyLoadContext` из пространства имён `System.Runtime.Loader`. он представляет контекст загрузки и выгрузки сборок. в .net 5 и новее это замена выгрузке домена приложений: сборки, загруженные в собираемый контекст, можно выгрузить, сборки контекста по умолчанию остаются до завершения процесса.

исходный консольный проект называется `MyApp`, его файл `Program.cs` содержит:

```c#


namespace MyApp

{

    class Program

    {

        static void Main(string[] args)

        {

            var number = 5;

            var result = Square(number);

            Console.WriteLine($"Квадрат {number} равен {result}");

        }

        static int Square(int n) => n * n;

    }

}
```

у программы есть метод `Square`, он считает квадрат числа. по умолчанию проект компилируется в сборку `MyApp.dll`. дальше эта сборка загружается из другого приложения, чтобы вызвать `Square`.

объект `AssemblyLoadContext` создаётся конструктором:

```c#
public AssemblyLoadContext (string? name, bool isCollectible = false);
```

первый параметр задаёт имя контекста. это произвольная строка, на алгоритм загрузки она не влияет и нужна чтобы отличать контексты. второй параметр, `isCollectible`, определяет, можно ли выгрузить загруженные сборки. значение `true` разрешает выгрузку. значение по умолчанию, `false`, создаёт контекст, который нельзя собрать. вызов `Unload` у такого контекста завершается исключением.

для загрузки сборок у `AssemblyLoadContext` есть несколько методов:

- `Assembly LoadFromAssemblyName (AssemblyName assemblyName)` загружает сборку по имени, представленному типом `System.Reflection.AssemblyName`

- `Assembly LoadFromAssemblyPath (string assemblyPath)` загружает сборку по пути. путь должен быть абсолютным

- `Assembly LoadFromStream (System.IO.Stream stream)` загружает сборку из потока `Stream`

после любого из этих вызовов сборка доступна как объект `Assembly`, и к её типам обращаются через рефлексию.

когда работа со сборкой закончена, у `AssemblyLoadContext` вызывается метод `Unload()`. он запускает выгрузку контекста вместе со всеми сборками, которые были загружены в этот контекст. память, занятая этими сборками, после сборки мусора освобождается.

полный пример:

```c#


using System.Reflection;

using System.Runtime.Loader;



Square(8);

// очистка памяти

GC.Collect();

GC.WaitForPendingFinalizers();



Console.WriteLine();

// смотрим, какие сборки после выгрузки

foreach (Assembly asm in AppDomain.CurrentDomain.GetAssemblies())

    Console.WriteLine(asm.GetName().Name);





void Square(int number)

{

    var context = new AssemblyLoadContext(name: "Square", isCollectible: true);

    // установка обработчика выгрузки

    context.Unloading += Context_Unloading;



    // получаем путь к сборке MyApp

    var assemblyPath = Path.Combine(Directory.GetCurrentDirectory(), "MyApp.dll");

    // загружаем сборку

    Assembly assembly = context.LoadFromAssemblyPath(assemblyPath);



    // получаем тип Program из сборки MyApp.dll

    var type = assembly.GetType("MyApp.Program");

    if (type != null)

    {

        // получаем его метод Square

        var squareMethod = type.GetMethod("Square", BindingFlags.Static | BindingFlags.NonPublic);

        // вызываем метод

        var result = squareMethod?.Invoke(null, new object[] { number });

        if (result is int)

        {

            // выводим результат метода на консоль

            Console.WriteLine($"Квадрат числа {number} равен {result}");

        }

    }



    // смотим, какие сборки у нас загружены

    foreach (Assembly asm in AppDomain.CurrentDomain.GetAssemblies())

        Console.WriteLine(asm.GetName().Name);



    // выгружаем контекст

    context.Unload();

}



// обработчик выгрузки контекста

void Context_Unloading(AssemblyLoadContext obj)

{

    Console.WriteLine("Библиотека MyApp выгружена");

}
```

все шаги собраны в локальной функции `Square`. аргументом она принимает число, квадрат которого нужно вычислить. точка входа сгенерированного метода `Main` вызывает эту функцию напрямую, отдельный класс `Program` во внешней программе не объявлен.

сначала создаётся контекст:

```c#
var context = new AssemblyLoadContext(name: "Square", isCollectible: true);
```

параметру `isCollectible` передаётся `true`, иначе ранее загруженные сборки выгрузить нельзя.

у `AssemblyLoadContext` есть событие `Unloading`. обработчик на нём наблюдает момент, когда выгрузка контекста началась:

```c#
context.Unloading += Context_Unloading;
```

в источнике имя события записано как unloadig. у класса событие называется `Unloading`.

дальше `LoadFromAssemblyPath` загружает `MyApp.dll` по абсолютному пути. лекция исходит из того, что файл сборки лежит в текущем каталоге процесса, рядом с запускаемым приложением. `Path.Combine` с `Directory.GetCurrentDirectory()` даёт абсолютный путь. относительный путь этот метод не принимает.

```c#
Assembly assembly = context.LoadFromAssemblyPath(assemblyPath);
```

получив сборку, рефлексия находит метод `Square` и вызывает его. `GetType("MyApp.Program")` ищет тип по отображаемому имени. `GetMethod` вызывается с флагами `BindingFlags.Static` и `BindingFlags.NonPublic`, потому что `Square` в исходном проекте объявлен закрытым статическим методом и в открытую поверхность типа не входит. `Invoke` получает первым аргументом `null`: экземпляр не нужен, метод статический. вторым аргументом идёт массив параметров из одного числа. результат проверяется шаблоном `is int`, и на консоль печатается квадрат.

затем выводится список сборок, загруженных в текущий домен. среди них есть и `MyApp`. в конце контекст выгружается:

```c#
context.Unload();
```

функция `Square` вызывается из точки входа:

```c#


Square(8);

// очистка

GC.Collect();

GC.WaitForPendingFinalizers();
```

сам по себе вызов `Unload` не освобождает память немедленно. он только запускает выгрузку. фактическое освобождение происходит, когда сборщик мусора уничтожает объекты контекста и на загруженные типы не остаётся ссылок. если ссылка на тип, экземпляр или сам контекст ещё жива, выгрузка не завершается. для более быстрой очистки после вызова выполняются `GC.Collect()` и `GC.WaitForPendingFinalizers()`. финализаторы могут отпустить последние ссылки уже после первого прохода, поэтому для собираемого контекста нередко нужен ещё один `GC.Collect()` после ожидания финализаторов.
