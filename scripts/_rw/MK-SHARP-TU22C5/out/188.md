по умолчанию программа на c# компилируется в код промежуточного языка msil. чтобы запустить такую программу, на компьютере устанавливается фреймворк .net: во время выполнения jit переводит il в машинные инструкции текущего процесса. .net sdk умеет компилировать проект на c# и иначе, сразу в нативное приложение. такой образ не использует jit и запускается на компьютере, где .net не установлен: нужные части среды уже входят в сам файл. эта модель называется native aot. она доступна начиная с .net 7 для консольных проектов. поддержка asp.net core и macos добавлена в .net 8.0.

для native aot заранее ставится дополнительный инструментарий. компилятор заранее порождает машинный код и вызывает системный компоновщик, поэтому на машине сборки нужен набор инструментов c++. на windows через установщик visual studio устанавливается нагрузка `Desktop development with C++` (`Разработка классических приложений на C++`).

![native aot в .net и c#](/uploads/course-lectures/eb3b4f9d22a482ebb1e8273d72602535721c5cc8.png)

на ubuntu ставятся пакеты `clang` и `zlib1g-dev`:

```bash
sudo apt-get install clang zlib1g-dev
```

на macos ставятся `Command Line Tools for XCode`.

чтобы проект публиковался в модели native aot, в файл проекта, внутрь элемента `PropertyGroup`, добавляется элемент `<PublishAot>true</PublishAot>`:

```xml


<PropertyGroup>

    <PublishAot>true</PublishAot>

</PropertyGroup>
```

компиляция через .net cli выполняется командой:

```bash
dotnet publish -r <RID>
```

аргумент `-r` задаёт rid, runtime identifier: целевую операционную систему и архитектуру. нативный образ привязан к ним и на другую пару ос и процессора не переносится. часть распространённых идентификаторов:

- для windows: `win-x64`

- `win-x86`

- `win-arm64`

- для linux: `linux-x64`

- `linux-arm64`

- для macos: `osx-x64`

- `osx-arm64`

полный список идентификаторов приведён на странице [https://github.com/dotnet/runtime/blob/main/src/libraries/Microsoft.NETCore.Platforms/src/runtime.json](https://github.com/dotnet/runtime/blob/main/src/libraries/Microsoft.NETCore.Platforms/src/runtime.json)

для 64-разрядной windows команда такая:

```bash
dotnet publish -r win-x64 -c Release
```

для 64-разрядной linux на архитектуре arm (`AArch64`) используется команда

```bash
dotnet publish -r linux-arm64 -c Release
```

ключ `-c Release` выбирает конфигурацию release.

дальше берётся обычный проект консольного приложения. в файл проекта csproj добавляется параметр

```xml
<PublishAot>true</PublishAot>
```

![компиляция в нативный код и native aot в .net и c#](/uploads/course-lectures/2a4a0a5cb41b6782649f67c5dfb8d050b7694efd.png)

```bash

```

полученный файл exe запускается на 64-разрядных windows и там, где .net не установлен.

главный недостаток нативной публикации состоит в размере файла. на снимке простое консольное приложение, которое печатает одну строку, после компиляции с .net 8.0 preview занимает 1793 кб. по сравнению с .net 7.0 в .net 8.0 размер нативного приложения заметно меньше, и разработчики .net продолжают эту работу, так что в следующих версиях размер может уменьшиться ещё. дополнительно применяются отдельные оптимизации. самая простая из них включает инвариантный режим глобализации. в файл проекта добавляется настройка

```xml
<InvariantGlobalization>true</InvariantGlobalization>
```

одной этой настройки достаточно, чтобы размер уменьшился с 1793 кб до 1567 кб: из образа уходят данные культур, и форматирование остаётся инвариантным.

помимо размера у модели есть и другие ограничения. она доступна не для всех типов проектов, библиотек и сред. консольные приложения поддерживаются с самого начала, с .net 7.0. для asp.net core модель доступна начиная с .net 8.0. поддержка macos добавлена только в .net 8.0, тогда как для windows и linux она есть уже в .net 7.

для таких нативных приложений недоступна динамическая загрузка библиотек, в том числе через `Assembly.LoadFile`. публикация оставляет в образе только код, достижимый статическим анализом, а jit во время выполнения нет, поэтому сборку, выбранную уже в рантайме, загрузить некуда.
