### проверка на null. null guard

если используется переменная или параметр, которые допускают `null`, то есть имеют nullable-тип, значимый или ссылочный, перед обращением к членам значение проверяется на `null`. иначе разыменование пустой ссылки завершится `NullReferenceException`:

```c#


void PrintUpper(string? text)

{

    if (text!=null)

    {

        Console.WriteLine(text.ToUpper());

    }    

}
```

если параметр `text` не равен `null`, у строки вызывается метод `ToUpper()`, который переводит символы в верхний регистр. для анализатора такая проверка является сужением состояния: в ветке, где сравнение с `null` ложно, `text` считается непустой ссылкой, и вызов `ToUpper()` предупреждения не даёт.

проверку даёт и оператор `is`:

```c#
объект is значение
```

если объект слева от оператора `is` имеет значение справа от оператора, `is` возвращает `true`, иначе возвращается `false`. сравнение с `null` записано константным шаблоном и проверяет отсутствие значения.

проверка параметра или переменной на `null` выглядит так:

```c#


void PrintUpper(string? text)

{

    if (text is  null) return;

    Console.WriteLine(text.ToUpper());

}
```

обратная проверка, отсутствие значения `null`, записывается через `is not`:

```c#


void PrintUpper(string? text)

{

    if (text is not null) 

		Console.WriteLine(text.ToUpper());

}
```

можно проверить и соответствие типу, значение которого далее используется:

```c#


void PrintUpper(string? text)

{

    if (text is string)

        Console.WriteLine(text.ToUpper());

    else 

        Console.WriteLine("NULL");

}
```

шаблон типа успешен только для ненулевой ссылки нужного типа. `null` типу `string` не соответствует, поэтому ветка `is string` одновременно исключает `null` и даёт в этой ветке статическое знание, что `text` имеет тип `string`.

такие проверки называют **null guard**, то есть защитой от `null`.

### оператор `??`

оператор `??` называется оператором null-объединения. он задаёт значение по умолчанию для типов, которые допускают `null`:

```c#
левый_операнд ?? правый_операнд
```

оператор `??` возвращает левый операнд, если этот операнд не равен `null`. иначе возвращается правый операнд. левый операнд обязан допускать `null`. правый операнд вычисляется только при пустом левом: если значение уже есть, выражение справа не выполняется. тип результата совпадает с типом операндов после снятия `null`. если правый операнд сам `null` не допускает, результат получает этот ненулевой тип:

```c#


string? text = null;

string name = text ?? "Tom";  // равно Tom, так как text равен null

Console.WriteLine(name);	// Tom



int? id = 200;

int personid = id ?? 1; // равно 200, так как id не равен null

Console.WriteLine(personid);	// 200
```

значимый тип без nullable-пометки левым операндом `??` быть не может:

```c#


int x = 44;

int y = x ?? 100;
```

переменная `x` имеет значимый тип `int` и значения `null` не принимает, поэтому в левой части операции `??` она недопустима. у типа `int` нет отдельного состояния «значение отсутствует», и оператору нечего проверять.

существует производный оператор `??=`:

```c#


string? text = null;

text ??= "Sam";

// аналогично

// text = text ?? "Sam";

Console.WriteLine(text);    // Sam



int? id = 100;

id ??= 1;

// аналогично

//id = id ?? 1;

Console.WriteLine(id); // 100
```

`??=` записывает правый операнд в левый только тогда, когда левый равен `null`. если значение уже есть, присваивания не происходит и правая часть не вычисляется. запись `text ??= "Sam"` равносильна присваиванию `text = text ?? "Sam"`.

### оператор условного null

при работе с объектами, которые принимают `null`, обращение к члену пустой ссылки завершается ошибкой. пусть задана следующая система классов:

```c#


class Person

{

    public Company? Company { get; set; }   // место работы

}

class Company

{

    public string? WebSite { get; set; }    // веб-сайт компании

}
```

объект `Person` представляет человека. свойство `Company` представляет компанию, где человек работает. человек может не работать, поэтому свойство имеет тип `Company?` и может иметь значение `null`.

класс `Company` содержит свойство `WebSite`, веб-сайт компании. собственного сайта у компании может не быть, поэтому свойство имеет тип `string?` и тоже допускает `null`.

требуется вывести на консоль заглавными буквами веб-сайт компании, где работает человек, если человек работает и если у компании есть сайт. прямая запись последовательных обращений выглядит так:

```c#


void PrintWebSite(Person? person)

{

    if (person != null)

    {

        if(person.Company != null)

        {

            if(person.Company.WebSite != null)

            {

                Console.WriteLine(person.Company.WebSite.ToUpper());

            }

        }

    }

}

class Person

{

    public Company? Company { get; set; }   // место работы

}

class Company

{

    public string? WebSite { get; set; }    // веб-сайт компании

}
```

метод `PrintWebSite()` принимает объект `Person?`. чтобы избежать исключения `NullReferenceException`, все используемые значения по очереди проверяются на `null`, и только затем метод `ToUpper()` выводит название сайта заглавными буквами.

способ корректен, но для вывода одной строки получается глубоко вложенная конструкция. её сокращают до одной конъюнкции:

```c#


void PrintWebSite(Person? person)

{

    if (person != null && person.Company != null && person.Company.WebSite != null)

    {

        Console.WriteLine(person.Company.WebSite.ToUpper());

    }

}
```

запись короче, однако условий по-прежнему несколько. в c# для той же схемы есть оператор условного null (null-conditional operator), оператор `?.`:

```c#


объект?.компонент
```

если объект не равен `null`, выполняется обращение к компоненту объекта: полю, свойству или методу. если объект равен `null`, обращение к компоненту не происходит, оставшаяся цепочка не вычисляется, а результат всего выражения равен `null`. тип такого выражения сам допускает `null`.

тот же пример с этим оператором:

```c#


void PrintWebSite(Person? person)

{

    Console.WriteLine(person?.Company?.WebSite?.ToUpper());

}
```

если `person` не равен `null`, выполняется обращение к свойству `Company`. если `Company` не равно `null`, выполняется обращение к свойству `WebSite` объекта `Company`. если `WebSite` не равно `null`, вызывается метод `ToUpper()`. на любом пустом звене цепочка останавливается, и `ToUpper()` не вызывается.

### присваивание с проверкой на null

операторы доступа с проверкой на `null`, `?.` и `?[]`, можно использовать в левой части присваивания или составного присваивания. `?[]` относится к индексатору и к элементу по индексу и подчиняется тому же правилу: при пустом получателе обращение не выполняется. до c# 14 перед присваиванием свойству переменную требовалось проверить на `null`:

```c#


Person? person = null;



if(person is not null)

{

    person.Name = "Tom";

}



Console.WriteLine(person?.Name);   // ничего не выводит 



class Person

{

    public string? Name {get; set;} 

}
```

начиная с c# 14 тот же код сокращается оператором `?.`:

```c#


Person? person = null;



// присваивание, если только person не равно null

person?.Name = "Tom";



Console.WriteLine(person?.Name);   // ничего не выводит 



class Person

{

    public string? Name {get; set;} 

}
```

в выражении `person?.Name = "Tom"` правая часть оператора присваивания `=` вычисляется только тогда, когда левая часть не равна `null`. если переменная `person` равна `null`, присваивания не будет и исключения не возникнет: свойство просто не получает значение, что и показывает последующий вывод.

та же логика присваивания с проверкой на `null` применяется к составным операторам присваивания (`+=`, `-=` и другим). инкремент и декремент (`++` и `--`) в этой форме не допускаются.
