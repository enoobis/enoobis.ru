наследование (inheritance) входит в число основных механизмов ооп. при наследовании один класс получает функциональность другого класса: члены базового типа становятся членами производного, с ограничениями доступа, которые разобраны ниже.

пусть есть класс `Person`, описывающий отдельного человека:

```c#


class Person

{

    private string _name = "";



	public string Name

	{

		get { return _name; }

		set { _name = value; }

	}

	public void Print()

	{

		Console.WriteLine(Name);

	}

}
```

далее понадобился класс сотрудника предприятия, `Employee`. сотрудник является человеком, поэтому класс реализует тот же функционал, что и `Person`. рационально сделать `Employee` производным классом (наследником, подклассом) от `Person`. `Person` в этой паре называется базовым классом, родителем или суперклассом:

```c#


class Employee : Person

{

	

}
```

после двоеточия указывается базовый класс. для `Employee` базовым является `Person`, поэтому `Employee` наследует свойства, методы и поля `Person`. конструкторы при наследовании не переходят к производному классу как его собственные члены. это особенно заметно на конструкторах с параметрами: их приходится вызывать явно. если ни в базовом, ни в производном классе конструктор не объявлен, компилятор создаёт обоим неявный конструктор без параметров, и пустой производный класс можно создать. как только в базовом классе появляется собственный конструктор, неявный конструктор без параметров исчезает, и производный класс обязан согласовать вызов, о чём сказано ниже.

наследование реализует отношение **is-a** (является): объект класса `Employee` одновременно является объектом класса `Person`.

```c#


Person person = new Person { Name = "Tom" };

person.Print();   // Tom

person = new Employee { Name = "Sam" };

person.Print();   // Sam
```

поскольку объект `Employee` является и объектом `Person`, допустимо определение `Person p = new Employee()`. восходящее присваивание меняет статический тип ссылки. динамический тип объекта остаётся `Employee`.

по умолчанию все классы наследуются от базового класса `Object`, даже если наследование не записано явно. поэтому классы `Person` и `Employee`, помимо собственных методов, имеют методы класса `Object`: `ToString()`, `Equals()`, `GetHashCode()` и `GetType()`.

все классы по умолчанию могут выступать базовыми. на это наложен ряд ограничений:

- множественное наследование классов не поддерживается: класс наследуется только от одного класса. в этом c# расходится с c++, где базовых классов может быть несколько. реализовать несколько интерфейсов класс при этом может

- при создании производного класса учитывается доступность базового. доступность производного класса должна быть такой же, как у базового, или более узкой. если базовый класс имеет доступ `internal`, производный может иметь доступ `internal` или `private`, но не `public`. модификатор `private` у класса возможен для вложенного типа: класс верхнего уровня бывает лишь `public` или `internal`. если базовый и производный классы находятся в разных сборках (проектах), производный класс наследует только от класса с модификатором `public`. тип `internal` из другой сборки просто не виден

- если класс объявлен с модификатором `sealed`, наследовать от него и создавать производные классы нельзя. следующий класс наследников не допускает:

```c#


sealed class Admin

{

}
```

- нельзя унаследовать класс от статического класса. статический класс неявно помечен `sealed`, экземпляров не имеет, и наследовать от него нечего

### доступ к членам базового класса из класса-наследника

вернёмся к классам `Person` и `Employee`. хотя `Employee` наследует функционал `Person`, следующий фрагмент не компилируется:

```c#


class Employee : Person

{

    public void PrintName()

    {

        Console.WriteLine(_name);

    }

}
```

код выдаёт ошибку: переменная `_name` объявлена с модификатором `private`, и доступ к ней имеет только класс `Person`. в `Person` при этом определено общедоступное свойство `Name`, и следующий код работает:

```c#


class Employee : Person

{

    public void PrintName()

    {

        Console.WriteLine(Name);

    }

}
```

производный класс имеет доступ лишь к тем членам базового класса, которые определены с модификаторами `private protected` (если базовый и производный класс находятся в одной сборке), `public`, `internal` (если базовый и производный класс находятся в одной сборке), `protected` и `protected internal`. член `private` в наследнике не виден. `protected` открывает член производным классам в любой сборке. `private protected` открывает его только производным классам той же сборки. `internal` открывает член любому коду той же сборки. `protected internal` открывает член коду той же сборки и производным классам, в том числе в другой сборке. `public` ограничений по доступу не ставит.

### ключевое слово base

в классы добавляются конструкторы:

```c#


class Person

{

    public string Name { get; set;}

    public Person(string name)

    {

        Name = name;

    }

    public void Print()

    {

        Console.WriteLine(Name);

    }

}



class Employee : Person

{

    public string Company { get; set; }

    public Employee(string name, string company)

        : base(name)

    {

        Company = company;

    }

}
```

класс `Person` имеет конструктор, который устанавливает свойство `Name`. класс `Employee` наследует это свойство и тоже должен его установить. повторять код установки в каждом наследнике незачем: соответствующий код уже есть в `Person`. свойств и параметров у конструктора базового класса может быть заметно больше, чем в этом примере.

ключевое слово `base` обращается к базовому классу. в конструкторе `Employee` нужно установить имя и компанию. имя передаётся в конструктор базового класса, то есть в конструктор `Person`, выражением `base(name)`. такой вызов является инициализатором конструктора: он выполняется до тела конструктора производного класса.

```c#


Person person = new Person("Bob");

person.Print();     // Bob

Employee employee = new Employee("Tom", "Microsoft");

employee.Print();   // Tom
```

### конструкторы в производных классах

конструкторы не передаются производному классу при наследовании. если в базовом классе не определён конструктор по умолчанию без параметров, а определены только конструкторы с параметрами, как у класса `Person`, производный класс обязан вызвать один из этих конструкторов через ключевое слово `base`. из класса `Employee` убирается определение конструктора:

```c#


class Employee : Person

{

    public string Company { get; set; } = "";

}
```

возникает ошибка: класс `Employee` не согласован с классом `Person`, потому что не вызывает конструктор базового класса. компилятор не подставляет вызов сам, раз беспараметрического конструктора у базы нет. ошибка сохранится и после добавления конструктора, который устанавливает те же свойства, если вызов базы не указан:

```c#


class Employee : Person

{

    public string Company { get; set; } = "";

    public Employee(string name, string company)	// ! Ошибка

    {

        Name = name;

        Company = company;

    }

}
```

в классе `Employee` через ключевое слово `base` нужно явно вызвать конструктор класса `Person`:

```c#


class Employee : Person

{

    public string Company { get; set; } = "";

    public Employee(string name, string company)

        : base(name)

    {

        Company = company;

    }

}
```

в качестве альтернативы в базовом классе определяется конструктор без параметров:

```c#


class Person

{

    public string Name { get; set; }

    // конструктор без параметров

    public Person()

    {

        Name = "Tom";

        Console.WriteLine("Вызов конструктора без параметров");

    }

    public Person(string name)

    {

        Name = name;

    }

    public void Print()

    {

        Console.WriteLine(Name);

    }

}
```

тогда в любом конструкторе производного класса, где нет обращения к конструктору базового класса, всё равно неявно вызывается этот конструктор по умолчанию. объявление собственного конструктора в базе отменяет конструктор, который компилятор создал бы сам. беспараметрический конструктор появляется снова только если его написали явно, как в примере. следующий конструктор

```c#


public Employee(string company)

{

    Company = company;

}
```

фактически эквивалентен такому конструктору:

```c#


public Employee(string company)

	:base()

{

    Company = company;

}
```

### порядок вызова конструкторов

при вызове конструктора класса сначала отрабатывают конструкторы базовых классов и только затем конструкторы производных. берутся следующие классы:

```c#


class Person

{

	string name;

	int age;



	public Person(string name)

	{

		this.name = name;

		Console.WriteLine("Person(string name)");

	}

	public Person(string name, int age) : this(name)

	{

		this.age = age;

		Console.WriteLine("Person(string name, int age)");

	}

}

class Employee : Person

{

	string company;



	public Employee(string name, int age, string company) : base(name, age)

	{

		this.company = company;

		Console.WriteLine("Employee(string name, int age, string company)");

	}

}
```

при создании объекта `Employee`

```c#
Employee tom = new Employee("Tom", 22, "Microsoft");
```

консольный вывод таков:

```consoletext


Person(string name)

Person(string name, int age)

Employee(string name, int age, string company)
```

получается следующая цепь выполнений.

- вначале вызывается конструктор `Employee(string name, int age, string company)`. он делегирует выполнение конструктору `Person(string name, int age)`

- вызывается конструктор `Person(string name, int age)`, который сам пока не выполняется и передаёт выполнение конструктору `Person(string name)`

- вызывается конструктор `Person(string name)`, который передаёт выполнение конструктору класса `System.Object`, поскольку это базовый по умолчанию класс для `Person`

- выполняется конструктор `System.Object.Object()`, затем выполнение возвращается конструктору `Person(string name)`

- выполняется тело конструктора `Person(string name)`, затем выполнение возвращается конструктору `Person(string name, int age)`

- выполняется тело конструктора `Person(string name, int age)`, затем выполнение возвращается конструктору `Employee(string name, int age, string company)`

- выполняется тело конструктора `Employee(string name, int age, string company)`. в итоге создаётся объект `Employee`

инициализаторы полей экземпляра входят в эту цепь отдельно от тел конструкторов. они выполняются при входе в конструктор, до вызова базового конструктора. конструктор с инициализатором `this(...)` поля не инициализирует: инициализаторы стоят в том конструкторе класса, который обращается к базе, и срабатывают один раз. в примере сначала выполняются инициализаторы полей `Employee`, затем управление входит в `Person(string name, int age)` и сразу передаётся в `Person(string name)`. там сначала выполняются инициализаторы полей `Person`, затем конструктор `System.Object.Object()`, и только после него тело `Person(string name)`. дальше тела идут в порядке списка выше. вызов виртуального метода из конструктора базы застаёт объект на полпути: инициализаторы полей наследника уже выполнены, тело его конструктора ещё нет, и поля, которым значение присваивается только в этом теле, по-прежнему хранят значения по умолчанию.
