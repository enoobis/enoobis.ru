потоки часто работают с ресурсами, общими для всей программы: с переменными, файлами, другими объектами в общей куче. каждый поток видит одну и ту же память, а операции над ней чередуются. пример запускает пять потоков на общей переменной `x`:

```c#


int x = 0;



// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Thread myThread = new(Print);

    myThread.Name = $"Поток {i}";   // устанавливаем имя для каждого потока

    myThread.Start();

}



void Print()

{

    x = 1;

    for (int i = 1; i < 6; i++)

    {

        Console.WriteLine($"{Thread.CurrentThread.Name}: {x}");

        x++;

        Thread.Sleep(100);

    }

}
```

пять потоков вызывают `Print` и работают с одной переменной `x`. по тексту метода ожидается, что каждый поток напечатает значения `x` от 1 до 5: он записывает 1 и пять раз печатает и увеличивает `x`. при выполнении планировщик переключается между потоками в произвольных точках, в том числе между чтением, записью и `x++`. инкремент сам по себе не атомарен: он читает значение, прибавляет единицу и записывает результат. чужая запись между этими шагами теряется. итоговое значение `x` от запуска к запуску разное. один из наблюдавшихся выводов, при другом запуске порядок и числа будут другими:

Поток 3: 1

Поток 1: 6

Поток 5: 7

Поток 1: 11

Поток 4: 11

Поток 2: 11

Поток 3: 16

такое чередование называется состоянием гонки: результат зависит от порядка, в котором потоки выполняют шаги, а этот порядок программа не фиксирует.

доступ к общему ресурсу на время использования одним потоком ограничивается синхронизацией. оператор `lock` задаёт блок, в который входит только один поток. пока этот поток не выйдет из блока, остальные потоки, дошедшие до того же `lock`, стоят в очереди на монитор объекта. для примера выше блок выглядит так:

```c#


int x = 0;

object locker = new();  // объект-заглушка

// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Thread myThread = new(Print);

    myThread.Name = $"Поток {i}";

    myThread.Start();

}





void Print()

{

    lock (locker)

    {

        x = 1;

        for (int i = 1; i < 6; i++)

        {

            Console.WriteLine($"{Thread.CurrentThread.Name}: {x}");

            x++;

            Thread.Sleep(100);

        }

    }

}
```

для `lock` нужен объект-заглушка, здесь это переменная `locker`. обычно её тип `object`. блокируется монитор этого объекта, а не сама переменная `x`: взаимное исключение возникает только у участков, которые захватывают один и тот же экземпляр. когда выполнение доходит до `lock`, поток захватывает `locker`. на время захвата монопольный доступ к блоку есть только у него. после выхода из блока, в том числе из-за исключения, захват снимается, и `locker` доступен следующему потоку из очереди. `Thread.Sleep` внутри `lock` монитор не отпускает: пауза тоже входит в критическую секцию, остальные потоки ждут и её.

оператор `lock` по ссылке на обычный объект раскрывается в захват и освобождение монитора (`Monitor.Enter` / `Monitor.Exit`) с освобождением в `finally`. связь с классом `Monitor` разбирается отдельно. объект синхронизации оставляют закрытым внутри типа: внешний код, получивший ту же ссылку, входит в тот же монитор и может занять секцию неожиданно для владельца.

при таком захвате вывод упорядочен. каждый поток печатает свою последовательность от 1 до 5 целиком, и только потом в секцию входит другой. порядок потоков по-прежнему выбирает планировщик, порядок строк внутри одного захвата фиксирован:
