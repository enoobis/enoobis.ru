если пространство имён используется в нескольких файлах проекта, директиву `using` по умолчанию повторяют в каждом файле, где нужны его типы. директива действует на одну единицу компиляции, то есть на один файл исходного текста.

пусть в проекте три файла.

![глобальные пространства имен в c# и .net](/uploads/course-lectures/3428011345a948686df18ae73007ec394e3e0f4b.png)

в файле `Base.cs` класс `Company` объявлен в пространстве `Base`.

```c#


namespace Base;

class Company

{

    string title;

    public Company(string title) => this.title = title;

    public void Print() => Console.WriteLine($"Компания: {title}");

}
```

в файле `Person.cs` класс `Person` использует `Company`.

```c#


using Base;



class Person

{

    string name;

    Company company;

    public Person(string name, Company company)

    {

        this.name = name;

        this.company = company;

    }

    public void Print()

    {

        Console.WriteLine($"Имя: {name}");

        company.Print();

    }

}
```

чтобы имя `Company` разрешилось, подключают его пространство: `using Base;`.

в `Program.cs` используются и `Person`, и `Company`.

```c#


using Base;



Company microsoft = new("Microsoft");

Person tom = new("Tom", microsoft);

tom.Print();
```

для `Company` снова нужна та же директива `using Base;`.

файлов, куда приходится подключать `Base` или любое другое пространство, может быть много. повторять одну и ту же директиву в каждом файле трудно сопровождать: при смене импорта правку приходится разносить по всему проекту. в .net 6 для этого введены глобальные пространства имён. одна директива подключает пространство сразу ко всем файлам кода проекта. достаточно записать её в одном файле.

```c#
global using подключаемое_пространство_имен;
```

файл `Program.cs` тогда выглядит так.

```c#


global using Base;



Company microsoft = new("Microsoft");

Person tom = new("Tom", microsoft);

tom.Print();
```

пространство `Base` подключается ко всем файлам кода проекта. из `Person.cs` строку с локальной директивой удаляют.

```c#
using Base;
```

### определение глобальных пространств в отдельном файле

держать `global using` в `Program.cs` тоже не всегда удачно: набор импортов проекта проще собрать в одном месте. в visual studio 2022 в проект добавляют отдельный файл c# и записывают в нём подключаемые пространства. имя `GlobalUsings.cs` компилятор не требует. это соглашение о том, где лежат глобальные импорты. директива `global using` в любой единице компиляции распространяется на весь проект.

```c#


global using System.Text;

global using System.Reflection;

global using Base;
```

этот набор автоматически подключается ко всем файлам кода проекта. `global using` остаётся действием времени компиляции: оно дописывает импорт к каждой единице компиляции и не создаёт отдельной сущности во время выполнения.
