отдельный поток может получать аргументы. для метода без параметров достаточно `ThreadStart`. один аргумент произвольного типа передаётся делегатом `ParameterizedThreadStart`, его конструктор `Thread` принимает наравне с `ThreadStart`.

```c#
public delegate void ParameterizedThreadStart(object? obj);
```

применение `ParameterizedThreadStart` устроено так же, как `ThreadStart`: делегат задаёт тело потока, `Start` ставит поток в планирование. отличие в сигнатуре. у `ParameterizedThreadStart` ровно один параметр типа `object?`, возвращаемого значения нет.

```c#


using System.Threading;



// создаем новые потоки

Thread myThread1 = new Thread(new ParameterizedThreadStart(Print));

Thread myThread2 = new Thread(Print);

Thread myThread3 = new Thread(message => Console.WriteLine(message));



// запускаем потоки

myThread1.Start("Hello");

myThread2.Start("Привет");

myThread3.Start("Salut");





void Print(object? message) => Console.WriteLine(message);
```

в конструктор `Thread` передаётся либо явный делегат `new ParameterizedThreadStart(Print)`, либо метод, совместимый с этим делегатом, в форме группы методов `new Thread(Print)`, либо лямбда той же сигнатуры `new Thread(message => Console.WriteLine(message))`. группа методов приводится к делегату по сигнатуре `void (object?)`.

в `Start()` передаётся значение, и оно становится аргументом `Print`. три потока получают строки `Hello`, `Привет` и `Salut`. порядок строк на консоли зависит от планировщика. исходный пример фиксирует один из наблюдавшихся порядков:

```consoletext


Salut

Hello

Привет
```

ограничение `ParameterizedThreadStart` жёсткое: тело потока это метод с единственным параметром типа `object?`. значение другого типа приводится внутри метода. значимый тип при передаче в `Start(object?)` упаковывается в объект, а в методе распаковывается. для `int` это делает сопоставление с образцом `is int n`: при успехе `n` имеет тип `int` и годится для арифметики.

```c#


using System.Threading;



int number = 4;

// создаем новый поток

Thread myThread = new Thread(Print);

myThread.Start(number);    // n * n = 16





// действия, выполняемые во втором потокке

void Print(object? obj)

{

    // здесь мы ожидаем получить число

    if (obj is int n)

    {

        Console.WriteLine($"n * n = {n * n}");

    }

}
```

переданное значение приводится к `int`, и только после этого участвует в вычислении. если объект другого типа, ветка `is int` не выполняется и метод ничего не печатает. ошибки приведения через `is` нет: несовпадение типа это обычный ложный результат проверки.

несколько параметров разных типов одним `object?` не описать без упаковки. их собирают в собственный тип и передают один объект этого типа:

```c#


using System.Threading;



Person tom = new Person("Tom", 37);

// создаем новый поток

Thread myThread = new Thread(Print);

myThread.Start(tom);



void Print(object? obj)

{

    // здесь мы ожидаем получить объект Person

    if (obj is Person person)

    {

        Console.WriteLine($"Name = {person.Name}");

        Console.WriteLine($"Age = {person.Age}");

    }

}



record class Person(string Name, int Age);
```

сначала объявляется тип `Person`. его экземпляр и передаётся во второй поток. в `Main` (в этих примерах это код верхнего уровня главного потока) объект попадает в `Start`, а `Print` проверяет тип через `is Person person` и читает уже типизированные свойства `Name` и `Age`.

у этого приёма остаётся ограничение сигнатуры: `Thread.Start(object?)` не является типобезопасным. компилятор принимает аргумент любого типа, а соответствие типу `Person` проверяется уже при выполнении, в теле `Print`. если передать строку или число, ветка `is Person` молча не сработает.

типобезопасный вариант переносит и данные, и метод в один тип и запускает поток через `ThreadStart`, без параметра. поля экземпляра уже имеют нужные типы, приведение `object` не требуется. лямбда, захватывающая локальные переменные нужных типов, даёт тот же эффект за счёт замыкания. исходный пример использует метод экземпляра:

```c#


using System.Threading;



Person tom = new Person("Tom", 37);

// создаем новый поток

Thread myThread = new Thread(tom.Print);

myThread.Start();



record class Person(string Name, int Age)

{

    public void Print()

    {

        Console.WriteLine($"Name = {Name}");

        Console.WriteLine($"Age = {Age}");

    }

}
```

`tom.Print` совместим с `ThreadStart`: у метода нет параметров. поток вызывает его на том же экземпляре, чьи `Name` и `Age` были заданы в конструкторе записи. неверный тип в `Start` передать нельзя, потому что вызывается перегрузка `Start()` без аргумента.
