в c# с xml работают несколькими независимыми моделями. в первых версиях фреймворка основной api находился в пространстве имён `System.Xml`. это классическая дом-модель: документ после разбора становится деревом узлов в памяти. в пространстве имён заданы такие типы:

- `XmlNode` представляет узел xml. узлом может быть как документ целиком, так и отдельный элемент

- `XmlDocument` представляет весь xml-документ

- `XmlElement` представляет отдельный элемент и наследуется от `XmlNode`

- `XmlAttribute` представляет атрибут элемента

- `XmlText` представляет текстовое значение элемента, то есть текст между открывающим и закрывающим тегами

- `XmlComment` представляет комментарий

- `XmlNodeList` представляет список узлов

общий контракт узла задаёт `XmlNode`. от него наследуют не только `XmlElement`, но и `XmlDocument`, `XmlAttribute`, `XmlText` и `XmlComment`, поэтому обход, чтение имени и работа с потомками у этих узлов устроены одинаково. ниже основные члены `XmlNode`, через которые читается дерево:

- свойство `Attributes` возвращает объект `XmlAttributeCollection`, коллекцию атрибутов

- свойство `ChildNodes` возвращает коллекцию дочерних узлов

- свойство `HasChildNodes` возвращает `true`, если у текущего узла есть дочерние узлы

- свойство `FirstChild` возвращает первый дочерний узел

- свойство `LastChild` возвращает последний дочерний узел

- свойство `InnerText` возвращает текстовое значение узла

- свойство `InnerXml` возвращает всю внутреннюю разметку узла

- свойство `Name` возвращает имя узла. у элемента `<user>` значение `Name` равно "user"

- свойство `ParentNode` возвращает родительский узел

эти типы применяются к конкретному файлу. файл называется `people.xml` и содержит следующий документ:

```xml


<?xml version="1.0" encoding="utf-8" ?>

<people>

  <person name="Tom">

    <company>Microsoft</company>

    <age>37</age>

  </person>

  <person name="Bob">

    <company>Google</company>

    <age>41</age>

  </person>

</people>
```

обход документа печатает его данные на консоль:

```c#


using System.Xml;



XmlDocument xDoc = new XmlDocument();

xDoc.Load("people.xml");

// получим корневой элемент

XmlElement? xRoot = xDoc.DocumentElement;

if (xRoot != null)

{

    // обход всех узлов в корневом элементе

    foreach (XmlElement xnode in xRoot)

    {

        // получаем атрибут name

        XmlNode? attr = xnode.Attributes.GetNamedItem("name");

        Console.WriteLine(attr?.Value);



        // обходим все дочерние узлы элемента user

        foreach (XmlNode childnode in xnode.ChildNodes)

        {

            // если узел - company

            if (childnode.Name == "company")

            {

                Console.WriteLine($"Company: {childnode.InnerText}");

            }

            // если узел age

            if (childnode.Name == "age")

            {

                Console.WriteLine($"Age: {childnode.InnerText}");

            }

        }

        Console.WriteLine();

    }

}
```

вывод программы:

```consoletext


Tom

Company: Microsoft

Age: 37



Bob

Company: Google

Age: 41
```

работа начинается с объекта `XmlDocument` и загрузки файла вызовом `xDoc.Load("people.xml");`. разбор идёт от корня: свойство `xDoc.DocumentElement` возвращает корневой элемент, и уже от него перечисляются дочерние узлы. при `PreserveWhitespace` равном `false`, а это значение по умолчанию, пробельные текстовые узлы в дерево не попадают, и детьми корня остаются элементы.

цикл `foreach(XmlNode xnode in xRoot)` проходит по всем дочерним узлам корня. в этом документе такие узлы являются элементами `<person>`, поэтому у них читаются атрибуты, `XmlNode attr = xnode.Attributes.GetNamedItem("name");`, и вложенные элементы, `foreach(XmlNode childnode in xnode.ChildNodes)`. в самом листинге переменная цикла объявлена как `XmlElement`: в неё попадают узлы, приводимые к элементу. если атрибут `name` отсутствует, `GetNamedItem` возвращает `null`, и оператор `?.` не обращается к `Value`.

какой именно узел встретился, определяется сравнением имени: `if(childnode.Name=="company")`. имя `company` даёт текст компании через `InnerText`, имя `age` даёт текст возраста.

тем же обходом по данным xml строятся объекты классов и структур:

```c#


using System.Xml;



var people = new List<Person>();



XmlDocument xDoc = new XmlDocument();

xDoc.Load("people.xml");

// получим корневой элемент

XmlElement? xRoot = xDoc.DocumentElement;

if (xRoot != null)

{

    foreach (XmlElement xnode in xRoot)

    {

        Person person = new Person();

        XmlNode? attr = xnode.Attributes.GetNamedItem("name");

        person.Name = attr?.Value;



        foreach (XmlNode childnode in xnode.ChildNodes)

        {

            if (childnode.Name == "company")

                person.Company = childnode.InnerText;



            if (childnode.Name == "age")

                person.Age = int.Parse(childnode.InnerText);

        }

        people.Add(person);

    }

    foreach (var person in people)

        Console.WriteLine($"{person.Name} ({person.Company}) - {person.Age}");

}



class Person

{

    public string? Name { get; set; }

    public int Age { get; set; }

    public string? Company { get; set; }

}
```

здесь у `Person` три свойства. при переборе узлов значения атрибутов и вложенных элементов записываются в экземпляр `Person`, после чего список печатается. для возраста вызывается `int.Parse` без явной культуры, то есть разбор идёт по правилам текущей культуры процесса.

консольный вывод программы:

```consoletext


Tom (Microsoft) - 37

Bob (Google) - 41
```
