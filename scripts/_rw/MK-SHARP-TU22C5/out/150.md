у запроса linq два режима выполнения: **отложенное** (deferred) и **немедленное** (immediate).

при отложенном выполнении выражение linq не запускает перечисление в точке, где записан запрос. перечисление начинается позже, когда по выборке идут итератором, например в цикле `foreach`. такие операторы возвращают объект `IEnumerable<T>` или `IOrderedEnumerable<T>`. запрос хранит цепочку операторов над источником. элементы в момент создания запроса ещё не посчитаны. полный список отложенных операций linq:

- AsEnumerable
- Cast
- Concat
- DefaultIfEmpty
- Distinct
- Except
- GroupBy
- GroupJoin
- Intersect
- Join
- OfType
- OrderBy
- OrderByDescending
- Range
- Repeat
- Reverse
- Select
- SelectMany
- Skip
- SkipWhile
- Take
- TakeWhile
- ThenBy
- ThenByDescending
- Union
- Where

отложенное выполнение на конкретной цепочке:

```c#


string[] people = { "Tom", "Sam", "Bob" };



var selectedPeople = people.Where(s=>s.Length == 3).OrderBy(s=>s);



// выполнение LINQ-запроса

foreach (string s in selectedPeople)

    Console.WriteLine(s);
```

фактическое выполнение происходит не в строке определения `var selectedPeople = people.Where...`, а при переборе в цикле `foreach`. до входа в цикл предикат `Where` и ключ `OrderBy` не вызываются. каждое новое перечисление запускает запрос заново, поэтому повторный `foreach` по той же переменной снова читает источник.

запрос linq распадается на три этапа:

- получение источника данных
- создание запроса
- выполнение запроса и получение его результатов

в этом примере этапы выглядят так.

получение источника данных, определение массива `people`:

```c#
string[] people = { "Tom", "Sam", "Bob" };
```

создание запроса, определение переменной `selectedPeople`:

```c#
var selectedPeople = people.Where(s=>s.Length == 3).OrderBy(s=>s);
```

выполнение запроса и получение результатов:

```c#


foreach (string s in selectedPeople)

    Console.WriteLine(s);
```

после определения запрос можно выполнить много раз. до выполнения источник ещё можно изменить, и ближайшее перечисление увидит уже новое состояние. элемент массива меняется до перебора выборки:

```c#


string[] people = { "Tom", "Sam", "Bob" };



var selectedPeople = people.Where(s=>s.Length == 3).OrderBy(s=>s);



people[2] = "Mike";

// выполнение LINQ-запроса

foreach (string s in selectedPeople)

    Console.WriteLine(s);
```

выборка содержит два элемента. до присваивания их было три: последний элемент после `people[2] = "Mike"` имеет длину 4 и не проходит условие `s.Length == 3`. переменная запроса сама не выполняет действий и не возвращает данные. она хранит набор команд, по которым результат будет получен позже. получение результата производится при переборе в цикле `foreach`. отсюда ограничение: если тело запроса читает изменяемое разделяемое состояние, результат зависит от того, в какой момент начато перечисление.

### немедленное выполнение запроса

часть методов выполняет запрос немедленно. это методы, которые возвращают одно атомарное значение, один элемент или материализованную коллекцию типов `Array`, `List<T>` и `Dictionary<TKey, TValue>`. полный список таких операций в linq:

- Aggregate
- All
- Any
- Average
- Contains
- Count
- ElementAt
- ElementAtOrDefault
- Empty
- First
- FirstOrDefault
- Last
- LastOrDefault
- LongCount
- Max
- Min
- SequenceEqual
- Single
- SingleOrDefault
- Sum
- ToArray
- ToDictionary
- ToList
- ToLookup

пример с методом `Count()`, который возвращает число элементов последовательности:

```c#


string[] people = { "Tom", "Sam", "Bob" };

// определение и выполнение LINQ-запроса

var count = people.Where(s=>s.Length == 3).OrderBy(s=>s).Count();



Console.WriteLine(count);   // 3 - до изменения коллекции



people[2] = "Mike";

Console.WriteLine(count);   // 3 - после изменения коллекции
```

результат `Count` имеет тип `int`, поэтому выполнение немедленное. число уже лежит в переменной `count`. последующее присваивание `people[2] = "Mike"` эту переменную не меняет, оба вызова `Console.WriteLine` печатают 3.

сначала строится запрос `people.Where(s=>s.Length == 3).OrderBy(s=>s)`. затем к нему применяется `Count()`. метод выполняет запрос, перебирает последовательность, которую этот запрос генерирует, и возвращает число её элементов. сортировка `OrderBy` на результат `Count` не влияет: метод считает элементы, не сохраняя их порядок в выходном значении.

`Count()` можно отделить от определения запроса. тогда каждый вызов заново перечисляет источник и видит изменения:

```c#


string[] people = { "Tom", "Sam", "Bob" };

// определение LINQ-запроса

var selectedPeople = people.Where(s=>s.Length == 3).OrderBy(s=>s);

// выполнение запроса

Console.WriteLine(selectedPeople.Count());   // 3 - до изменения коллекции



people[2] = "Mike";

// выполнение запроса

Console.WriteLine(selectedPeople.Count());   // 2 - после изменения коллекции
```

до изменения массива перечисление даёт 3. после замены "Bob" на "Mike" второе перечисление даёт 2: элемент больше не удовлетворяет предикату длины.

для немедленного выполнения и кэширования результата применяются методы преобразования `ToArray()`, `ToList()`, `ToDictionary()` и `ToLookup()`. они получают результат запроса в виде массива, `List<T>`, словаря и объекта `ILookup<TKey, TElement>` соответственно. после материализации повторное чтение идёт по копии и источник больше не трогает:

```c#


string[] people = { "Tom", "Sam", "Bob" };



// определение и выполнение LINQ-запроса

var selectedPeople = people.Where(s=>s.Length == 3).OrderBy(s=>s).ToList();



// изменение массива никак не затронет список selectedPeople

people[2] = "Mike";



// выполнение запроса

foreach (string s in selectedPeople)

    Console.WriteLine(s);
```

`ToList()` в момент вызова перечисляет запрос и заполняет список. присваивание `people[2] = "Mike"` на список `selectedPeople` не влияет. цикл `foreach` печатает три имени, отобранные до изменения массива. если нужен снимок на текущий момент, материализация как раз фиксирует его. если нужно видеть последующие правки источника, оставляют отложенный `IEnumerable<T>` и перечисляют его позже.
