наряду с оператором `lock` потоки синхронизирует монитор, класс `System.Threading.Monitor`. монитор связан с объектом в куче: у объекта есть служебный блок синхронизации, и методы `Monitor` захватывают и отпускают именно его. класс управляет синхронизацией статическими методами:

- `Enter(object obj)` получает объект в исключительное владение текущего потока. перегрузка `Enter(object obj, ref bool lockTaken)` дополнительно принимает флаг результата. в исходном перечне второй параметр назван `acquiredLock` и описан как логическое значение того, получено ли владение объектом. в коде ниже аргумент передаётся с `ref`: сигнатура этой перегрузки `Enter(object, ref bool)`. перед вызовом флаг равен `false`, после успешного захвата метод записывает в него `true`. если `Enter` завершился исключением до захвата, флаг остаётся `false`, и освобождать монитор нельзя
- `Exit(object obj)` освобождает ранее захваченный объект. вызов без соответствующего `Enter` у текущего потока порождает `SynchronizationLockException`. монитор реентерабелен: один и тот же поток может войти в него повторно, и тогда `Exit` нужен столько раз, сколько было успешных `Enter`
- `IsEntered(object obj)` возвращает `true`, если монитор объекта `obj` захвачен текущим потоком
- `Pulse(object obj)` уведомляет один поток из очереди ожидания, что состояние изменилось и монитор можно будет захватить после того, как текущий владелец его отпустит. сам `Pulse` монитор не освобождает: он переводит один ожидающий поток в очередь готовых к захвату
- `PulseAll(object obj)` уведомляет все потоки из очереди ожидания. после того как текущий поток освободит `obj`, один из потоков очереди готовности захватывает объект
- `TryEnter(object obj)` пытается захватить объект `obj`. если владение получено, возвращается `true`. если монитор занят, метод возвращает `false` и не блокирует вызывающий поток. есть перегрузки с ограничением времени ожидания
- `Wait(object obj)` освобождает блокировку и переводит вызывающий поток в очередь ожидания. следующий поток из очереди готовности захватывает объект. потоки, вызвавшие `Wait`, остаются в очереди ожидания, пока владелец блокировки не вызовет `Monitor.Pulse` или `Monitor.PulseAll`. после сигнала поток заново захватывает монитор, и только потом `Wait` возвращает управление. `Wait`, `Pulse` и `PulseAll` допустимы только у потока, который уже владеет монитором `obj`, иначе выбрасывается `SynchronizationLockException`

оператор `lock` инкапсулирует вызовы монитора. в предыдущей теме синхронизация записывалась так:

```c#


int x = 0;

object locker = new();  // объект-заглушка

// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Thread myThread = new(Print);

    myThread.Name = $"Поток {i}";

    myThread.Start();

}





void Print()

{

    lock (locker)

    {

        x = 1;

        for (int i = 1; i < 6; i++)

        {

            Console.WriteLine($"{Thread.CurrentThread.Name}: {x}");

            x++;

            Thread.Sleep(100);

        }

    }

}
```

тот же протокол, записанный методами `Monitor`, выглядит так:

```c#


int x = 0;

object locker = new();  // объект-заглушка

// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Thread myThread = new(Print);

    myThread.Name = $"Поток {i}";

    myThread.Start();

}



void Print()

{

    bool acquiredLock = false;

    try

    {

        Monitor.Enter(locker, ref acquiredLock);

        x = 1;

        for (int i = 1; i < 6; i++)

        {

            Console.WriteLine($"{Thread.CurrentThread.Name}: {x}");

            x++;

            Thread.Sleep(100);

        }

    }

    finally

    {

        if (acquiredLock) Monitor.Exit(locker);

    }

}
```

`Monitor.Enter` принимает объект блокировки и флаг `bool`. флаг сообщает, выполнен ли захват: `true` означает, что монитор получен. метод блокирует `locker` с той же взаимной исключительностью, что и оператор `lock`. в блоке `try`/`finally` метод `Monitor.Exit` освобождает `locker`, если захват состоялся, и объект становится доступен другим потокам. `finally` выполняется и при исключении из критической секции, поэтому монитор не остаётся занятым у потока, который уже вышел по ошибке. проверка `acquiredLock` отделяет успешный захват от случая, когда `Enter` не взял монитор: `Exit` тогда не вызывается.

для обычного объекта, как `locker` типа `object`, оператор `lock` раскрывается в эту схему. отдельный тип `System.Threading.Lock`, появившийся в .net 9, оператор `lock` обрабатывает другим api, без монитора объекта.
