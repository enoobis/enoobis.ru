делегаты поддерживают ковариантность и контравариантность при присваивании метода или другого делегата. **ковариантность** относится к возвращаемому типу: методу разрешено вернуть тип, производный от возвращаемого типа делегата. **контравариантность** относится к параметрам: методу разрешено принять тип, более общий, чем тип параметра делегата. оба правила сохраняют безопасность вызова. код, который пользуется делегатом, по-прежнему соблюдает объявленную сигнатуру, а подставленный метод способен принять то, что ему реально передадут, и вернуть то, что от него реально ожидают.

ниже одни и те же классы сообщений используются и для возвращаемого типа, и для параметра.

```c#

class Message
{
    public string Text { get; }
    public Message(string text) => Text = text;
    public virtual void Print() => Console.WriteLine($"Message: {Text}");
}
class EmailMessage: Message
{
    public EmailMessage(string text): base(text) { }
    public override void Print() => Console.WriteLine($"Email: {Text}");
}
class SmsMessage : Message
{
    public SmsMessage(string text) : base(text) { }
    public override void Print() => Console.WriteLine($"Sms: {Text}");
}
```

класс Message хранит текст в свойстве Text. текст задаётся в конструкторе и в дальнейшем не меняется. метод Print выводит сообщение на консоль и объявлен виртуальным, поэтому производный класс подменяет текст метки. EmailMessage представляет сообщение электронной почты, SmsMessage представляет sms-сообщение. оба класса производны от Message и переопределяют Print.

### ковариантность

ковариантность позволяет присвоить делегату метод, возвращаемый тип которого производный от возвращаемого типа делегата. если делегат объявлен как возвращающий Message, метод может возвращать EmailMessage:

```c#

// делегату с базовым типом передаем метод с производным типом
MessageBuilder messageBuilder = WriteEmailMessage; // ковариантность
Message message = messageBuilder("Hello");
message.Print();    // Email: Hello

EmailMessage WriteEmailMessage(string text) => new EmailMessage(text);

delegate Message MessageBuilder(string text);
```

делегат MessageBuilder объявлен с возвращаемым типом Message. благодаря ковариантности тот же делегат ссылается на метод WriteEmailMessage, который возвращает EmailMessage. вызов messageBuilder обязан по контракту дать объект Message. EmailMessage является Message, поэтому подстановка метода не нарушает ожидания вызывающего кода. направление совпадает с обычной ковариантностью результата: фактический тип является подтипом объявленного.

### контравариантность

контравариантность позволяет присвоить делегату метод, тип параметра которого более общий, чем тип параметра делегата. для классов Message и EmailMessage это выглядит так:

```c#

// делегату с производным типом передаем метод с базовым типом
EmailReceiver emailBox = ReceiveMessage; // контравариантность
emailBox(new EmailMessage("Welcome"));  // Email: Welcome

void ReceiveMessage(Message message) => message.Print();

delegate void EmailReceiver(EmailMessage message);
```

делегат EmailReceiver по контракту принимает только EmailMessage. ему присваивается метод ReceiveMessage, параметр которого имеет тип Message. безопасность держится на направлении передачи аргумента. при вызове делегата в метод может попасть только EmailMessage, а каждый объект EmailMessage является объектом Message, который ReceiveMessage готов принять. присваивание в обратную сторону компилятор отвергает: метод, требующий именно EmailMessage, нельзя подставить туда, где делегат обещает принять произвольный Message, потому что вызывающий код вправе передать экземпляр базового класса.

### ковариантность и контравариантность в обобщенных делегатах

те же отношения записываются на самом обобщённом делегате модификаторами **out** и **in**. закрытые конструируемые типы тогда преобразуются друг в друга без обёртки и без нового метода.

#### ковариантность

ковариантный обобщённый делегат объявляется и используется так:

```c#

// возвращает EmailMessage - более конкретный тип
MessageBuilder<EmailMessage> EmailMessageWriter = (string text) => new EmailMessage(text);
// возвращает более общий тип Message
MessageBuilder<Message> messageBuilder = EmailMessageWriter;     // ковариантность
Message message = messageBuilder("hello Tom"); // вызов делегата
message.Print(); // Email: hello Tom

delegate T MessageBuilder<out T>(string text);
```

модификатор **out** стоит у параметра типа, который встречается только в возвращаемой позиции. поэтому делегату типа `MessageBuilder<Message>` (аргумент типа более общий) можно присвоить делегат типа `MessageBuilder<EmailMessage>` (аргумент типа более конкретный). вызывающий код переменной messageBuilder ожидает Message и получает EmailMessage, то есть подтип объявленного результата.

#### контравариантность

контравариантный обобщённый делегат устроен симметрично, но по параметру:

```c#

// принимает объект более общего типа
MessageReceiver<Message> messageReceiver = (Message message) => message.Print();
// принимает объект более конкретного типа
MessageReceiver<EmailMessage> emailMessageReceiver = messageReceiver; // контравариантность

messageReceiver(new Message("Hello World!"));       // Message: Hello World!
messageReceiver(new EmailMessage("Hello World!"));  // Email: Hello World!

delegate void MessageReceiver<in T>(T message);
```

ключевое слово **in** разрешает присваивание делегату с производным аргументом типа (`MessageReceiver<EmailMessage>`) делегата с базовым аргументом типа (`MessageReceiver<Message>`). вызов через emailMessageReceiver передаёт только EmailMessage. метод, принятый в messageReceiver, рассчитан на любой Message и потому принимает и этот аргумент. тот же экземпляр messageReceiver по-прежнему можно вызвать и с Message, и с EmailMessage: его собственный контракт шире.

как и у обобщённых интерфейсов, ковариантный параметр типа допускается только там, где значение производится делегатом, то есть в возвращаемом типе. контравариантный параметр типа допускается только там, где значение потребляется, то есть в параметрах делегата. если один и тот же параметр типа стоит и во входной, и в выходной позиции, пометить его **in** или **out** нельзя: для одной из позиций преобразование вышло бы за контракт вызывающего кода.

по направлению преобразования самого делегата **ковариантность** идёт от более производного аргумента типа к более общему (EmailMessage переходит в Message), а **контравариантность** от более общего к более производному (Message переходит в EmailMessage).

#### совмещение ковариантности и контрвариантности

один делегат может нести оба модификатора сразу: **in** у входного параметра типа и **out** у выходного.

```c#

MessageConverter<Message, EmailMessage> toEmailConverter = (Message message) => new EmailMessage(message.Text);

MessageConverter<SmsMessage, Message> converter = toEmailConverter;
Message message = converter(new SmsMessage("Hello work"));
message.Print();    // Email: Hello work

delegate E MessageConverter<in M, out E>(M message);
```

делегат MessageConverter описывает преобразование объекта типа M в объект типа E. параметр M помечен **in**, параметр E помечен **out**, потому что M только входит в делегат, а E только выходит из него.

переменная converter имеет тип `MessageConverter<SmsMessage, Message>`: по этому контракту на вход подаётся SmsMessage, а на выходе ожидается Message. ей присваивается toEmailConverter типа `MessageConverter<Message, EmailMessage>`. для входного параметра срабатывает контравариантность: вместо производного SmsMessage метод принимает базовый Message и тем самым способен принять SmsMessage. для результата срабатывает ковариантность: вместо Message метод возвращает производный EmailMessage, который вызывающий код может использовать как Message. оба условия контракта converter выполнены, поэтому присваивание законно, а вызов с SmsMessage печатает строку email-сообщения.
