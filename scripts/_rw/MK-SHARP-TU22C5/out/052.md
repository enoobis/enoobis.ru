ранее рассмотрены два способа изменить функциональность метода, унаследованного от базового класса: скрытие и переопределение. различие между ними состоит в правиле связывания вызова с реализацией. при переопределении выбор метода откладывается до времени выполнения и зависит от динамического типа объекта. при скрытии вызов связывается со статическим типом ссылки ещё на этапе компиляции.

### переопределение

ниже пример переопределения виртуального метода:

```c#


class Person

{

	public string Name { get; set; }

	public Person(string name)

	{

		Name = name;

	}

	public virtual void Print()

	{

		Console.WriteLine(Name);

	}

}

class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company)

		: base(name)

	{

		Company = company;

	}



	public override void Print()

	{

		Console.WriteLine($"{Name} работает в {Company}");

	}

}
```

эти классы используются так:

```c#


Person tom = new Employee("Tom", "Microsoft");

tom.Print();		// Tom работает в Microsoft
```

вызов `tom.Print()` выполняет реализацию `Print` из класса `Employee`, хотя статический тип переменной `tom` есть `Person`. действует полиморфизм подтипов: реализация выбирается по динамическому типу объекта, на который ссылается переменная, а не по типу, записанному в объявлении переменной.

для виртуальных методов компилятор формирует таблицу виртуальных методов (virtual method table, **vmt**). в неё записываются адреса виртуальных методов. для каждого класса создаётся своя таблица. в clr эта таблица входит в таблицу методов типа: в заголовке каждого объекта хранится указатель на таблицу методов его точного типа, а слот виртуального метода содержит адрес реализации, действующей для этого типа.

когда создаётся объект класса, компилятор передаёт в конструктор объекта специальный код, который связывает объект и таблицу vmt.

при вызове виртуального метода из объекта берётся адрес его таблицы vmt. затем из vmt извлекается адрес метода, и этому адресу передаётся управление. выбор реализации производится во время выполнения программы. именно так выполняется виртуальный метод. поскольку среде выполнения сначала нужно получить из таблицы vmt адрес нужного метода, такой вызов немного замедляет выполнение программы: это косвенный вызов через слот таблицы. jit способен встроить его, если точный тип получателя установлен статически или по профилю выполнения: такая оптимизация называется девиртуализацией.

в c# методы экземпляра по умолчанию невиртуальные. динамическая диспетчеризация включается модификатором `virtual`, а замена реализации в производном классе записывается модификатором `override`. в java методы экземпляра виртуальны по умолчанию, в c++ виртуальность, как и в c#, объявляется явно.

### скрытие

те же классы `Person` и `Employee`, но вместо переопределения используется сокрытие:

```c#


class Person

{

	public string Name { get; set; }

	public Person(string name)

	{

		Name = name;

	}



	public void Print()

	{

		Console.WriteLine(Name);

	}

}



class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company)

			: base(name)

	{

		Company = company;

	}

	public new void Print()

	{

		Console.WriteLine($"{Name} работает в {Company}");

	}

}
```

результат следующего фрагмента другой:

```c#


Person tom = new Employee("Tom", "Microsoft");

tom.Print();		// Tom
```

переменная `tom` имеет тип `Person`, но хранит ссылку на объект `Employee`. при вызове метода `Print` выполняется та версия метода, которая определена в классе `Person`, а не в классе `Employee`. класс `Employee` не переопределяет метод `Print`, унаследованный от базового класса, а объявляет новый метод. модификатор `new` создаёт отдельный метод с тем же именем и не подменяет слот в таблице виртуальных методов базового класса. связывание идёт по статическому типу ссылки, поэтому `tom.Print()` вызывает метод `Print` из класса `Person`. если вызвать `Print` через ссылку статического типа `Employee`, выполнится уже новая версия, объявленная в `Employee`.
