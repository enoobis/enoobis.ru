класс `FileStream` читает файл и пишет в файл на уровне байтов. через него проходят и данные, которые программа считает текстом, и данные, которые остаются двоичными: для потока это одна последовательность байтов.

### создание `FileStream`

экземпляр создаётся конструктором `FileStream` или статическим методом класса `File`. у конструктора много перегрузок. базовая передаёт путь и режим открытия:

```c#
FileStream(string filename, FileMode mode)
```

второй аргумент имеет тип `FileMode`. перечисление задаёт, как открыть файл и что сделать, если он уже есть или если его ещё нет:

- `Append`: если файл есть, запись идёт в конец. если файла нет, он создаётся. поток открыт только для записи, чтение из него недоступно
- `Create`: создаётся новый файл. если файл с таким именем уже есть, его содержимое заменяется
- `CreateNew`: создаётся новый файл. если файл уже есть, вызов выбрасывает исключение
- `Open`: открывает существующий файл. если файла нет, выбрасывается исключение
- `OpenOrCreate`: существующий файл открывается без усечения, отсутствующий создаётся
- `Truncate`: существующий файл открывается и усекается до нулевой длины. поток предназначен только для записи. отсутствующий файл этот режим не создаёт

второй способ получить `FileStream` дают статические методы `File`:

```c#


FileStream File.Open(string file, FileMode mode);

FileStream File.OpenRead(string file);

FileStream File.OpenWrite(string file);
```

`File.Open` открывает файл в указанном режиме `FileMode` и возвращает поток `FileStream`. у метода есть перегрузки с дополнительными аргументами доступа и совместного использования. `File.OpenRead` открывает поток только для чтения. `File.OpenWrite` открывает поток для записи.

### закрытие потока

`FileStream` владеет дескриптором файла и буфером. класс реализует `IDisposable`: после работы дескриптор нужно освободить вызовом `Dispose`. метод `Close()` делает то же самое, потому что внутри вызывает `Dispose`. вместе с закрытием буфер сбрасывается на устройство, иначе хвост записи останется только в памяти процесса.

явная схема держит поток в переменной, выполняет операции и закрывает его в `finally`, в том числе когда тело выбросило исключение. тип переменной обнуляемый: если конструктор не выполнился, вызывать `Close` не у чего.

```c#


FileStream? fstream = null;

try

{

    fstream = new FileStream("note3.dat", FileMode.OpenOrCreate);

    // операции с fstream

}

catch(Exception ex)

{  }

finally

{

    fstream?.Close();

}
```

пустой `catch` в этом фрагменте поглощает исключение. `finally` при этом всё равно выполняется и закрывает поток, если он был создан.

конструкция `using` разворачивается в ту же пару `try`/`finally` и вызывает `Dispose` при выходе из блока, нормальном или по исключению:

```c#


using (FileStream fstream = new FileStream("note3.dat", FileMode.OpenOrCreate))

{

    // операции с fstream

}
```

### свойства и методы `FileStream`

состояние открытого потока читается из свойств класса `FileStream`:

- свойство `Length`: длина потока в байтах
- свойство `Position`: текущая позиция курсора в потоке, в байтах от начала
- свойство `Name`: абсолютный путь файла, открытого этим `FileStream`. даже если конструктор получил относительный путь, свойство возвращает абсолютный

чтение и запись идут методами того же класса. часть из них унаследована от `Stream`:

- `void CopyTo(Stream destination)`: копирует данные из текущего потока в поток `destination`
- `Task CopyToAsync(Stream destination)`: асинхронная версия `CopyTo`
- `void Flush()`: сбрасывает буфер потока в файл
- `Task FlushAsync()`: асинхронная версия `Flush`
- `int Read(byte[] array, int offset, int count)`: читает байты файла в массив и возвращает число реально прочитанных байтов. аргумент `array` задаёт массив, куда помещаются данные
- `offset` задаёт смещение в байтах внутри `array`, начиная с которого прочитанные байты записываются в массив
- `count` задаёт наибольшее число байтов, которое запрашивается у файла. если в файле байтов меньше, возвращаются все оставшиеся. возвращённое число может быть меньше `count` и равно нулю, когда данных больше нет: контракт `Stream.Read` не обещает заполнить буфер за один вызов
- `Task<int> ReadAsync(byte[] array, int offset, int count)`: асинхронная версия `Read`. возвращает то же число прочитанных байтов, обёрнутое в `Task<int>`
- `long Seek(long offset, SeekOrigin origin)`: ставит позицию потока со смещением `offset` относительно точки `origin`
- `void Write(byte[] array, int offset, int count)`: записывает в файл байты из массива. `array` задаёт источник
- `offset` задаёт смещение в байтах внутри `array`, с которого начинается запись в поток
- `count` задаёт наибольшее число байтов, которое берётся из массива
- `Task WriteAsync(byte[] array, int offset, int count)`: асинхронная версия `Write`

позиция после успешного `Read` или `Write` сдвигается на число обработанных байтов. следующий вызов продолжает файл с новой позиции, если её не переставить методом `Seek`.

### чтение и запись файлов

`FileStream` видит файл как массив байтов. строка в этот массив сама не превращается: её нужно закодировать, а при чтении декодировать. поэтому текст обычно пишут классами, которые держат кодировку сами. для двоичного файла с известной раскладкой байтов `FileStream` достаточен: из потока берётся нужный участок и обрабатывается отдельно от остального файла.

запись и чтение текстовой строки через байтовый поток:

```c#


using System.Text;



string path = @"C:\app\note.txt";   // путь к файлу



string text = "Hello  enoobis.COM"; // строка для записи



// запись в файл

using (FileStream fstream = new FileStream(path, FileMode.OpenOrCreate))

{

    // преобразуем строку в байты

    byte[] buffer = Encoding.Default.GetBytes(text);

    // запись массива байтов в файл

    await fstream.WriteAsync(buffer, 0, buffer.Length);

    Console.WriteLine("Текст записан в файл");

}



// чтение из файла

using (FileStream fstream = File.OpenRead(path))

{

    // выделяем массив для считывания данных из файла

    byte[] buffer = new byte[fstream.Length];

    // считываем данные

    await fstream.ReadAsync(buffer, 0, buffer.Length);

    // декодируем байты в строку

    string textFromFile = Encoding.Default.GetString(buffer);

    Console.WriteLine($"Текст из файла: {textFromFile}");

}
```

сначала задаются путь и текст. и при записи, и при чтении `FileStream` создаётся внутри `using`. на выходе из блока у экземпляра вызывается `Dispose`, дескриптор закрывается, буфер записи сбрасывается.

файловая операция ждёт устройство и на это время занимает поток, если вызвана синхронно. поэтому здесь стоят асинхронные `WriteAsync` и `ReadAsync`: вызывающий код получает `Task` и не блокируется на всё время обмена. и запись, и чтение пользуются `Encoding.Default` из `System.Text`. в актуальной платформе .net это свойство возвращает utf-8. в .net framework то же свойство возвращало ansi-кодировку операционной системы. `GetBytes` строит массив байтов из строки, `GetString` восстанавливает строку из массива байтов.

буфер чтения выделен размером `fstream.Length`, то есть на всю текущую длину файла, и один `ReadAsync` запрашивает её целиком. строка попадает в файл `note.txt`. вывод программы:

```consoletext


Текст записан в файл

Текст из файла: Hello  enoobis.COM
```

с точки зрения файловой системы записанный файл остаётся последовательностью байтов. если в него легла только закодированная строка, текстовый редактор показывает её в читаемом виде, подобрав ту же кодировку. произвольные байты такую интерпретацию ломают:

```c#


fstream.WriteByte(13);

fstream.WriteByte(103);
```

`WriteByte` кладёт в поток один байт и сдвигает позицию на единицу. байт 13 в ascii есть возврат каретки, байт 103 есть латинская `g`, но рядом с текстом в другой кодировке эта пара уже не обязана быть осмысленной строкой. для текста, где единица обмена есть символ, а не байт, предназначены `StreamReader` и `StreamWriter`.

### произвольный доступ к файлам

у многих двоичных форматов фиксированная раскладка. зная её, программа читает нужный участок или записывает байты в заданную позицию, не разбирая файл с начала. в wav-файле с каноническим pcm-заголовком звуковые кадры начинаются с байта 44, а предыдущие байты занимают метаданные: число каналов, частоту дискретизации и размер кадра. у файла с дополнительными фрагментами заголовка смещение данных другое, и цифра 44 относится именно к этому каноническому заголовку.

позицию курсора задаёт `Seek`. первый аргумент есть смещение в байтах, второй есть точка отсчёта:

- `SeekOrigin.Begin`: начало файла
- `SeekOrigin.End`: конец файла
- `SeekOrigin.Current`: текущая позиция

курсор сдвигается на `offset` относительно выбранной точки. отрицательное смещение ведёт назад, положительное вперёд.

пример чтения хвоста файла:

```c#


using System.Text;



string path = "note.dat";



string text = "hello world";



using (FileStream fstream = new FileStream(path, FileMode.OpenOrCreate))

{

    // преобразуем строку в байты

    byte[] input = Encoding.Default.GetBytes(text);

    // запись массива байтов в файл

    fstream.Write(input, 0, input.Length);

    Console.WriteLine("Текст записан в файл");

}

// чтение части файла

using (FileStream fstream = new FileStream(path, FileMode.OpenOrCreate))

{ 

    // перемещаем указатель в конец файла, до конца файла- пять байт

    fstream.Seek(-5, SeekOrigin.End); // минус 5 символов с конца потока



    // считываем четыре символов с текущей позиции

    byte[] output = new byte[5];

    await fstream.ReadAsync(output, 0, output.Length);

    // декодируем байты в строку

    string textFromFile = Encoding.Default.GetString(output);

    Console.WriteLine($"Текст из файла: {textFromFile}"); // world

}
```

сначала в файл записывается текст `hello world`. затем файл открывается снова, и курсор ставится на пять байт раньше конца:

```c#
fstream.Seek(-5, SeekOrigin.End)
```

после этого вызова курсор стоит на символе `w`.

дальше читаются пять байтов начиная с `w`. строка `hello world` состоит из символов ascii. и в utf-8, которым является `Encoding.Default` в текущей .net, и в однобайтовой кодировке каждый такой символ занимает один байт, поэтому пять байтов совпадают с пятью символами `world`. для символа вне ascii равенство байта и символа уже не выполняется, и тот же приём сдвинул бы курсор на середину символа.

вывод программы:

```consoletext


Текст записан в файл

Текст из файла: world
```

следующий пример пишет не в конец файла, а поверх уже лежащих байтов:

```c#


using System.Text;



string path = "note2.dat";



string text = "hello world";



// запись в файл

using (FileStream fstream = new FileStream(path, FileMode.OpenOrCreate))

{

    // преобразуем строку в байты

    byte[] input = Encoding.Default.GetBytes(text);

    // запись массива байтов в файл

    fstream.Write(input, 0, input.Length);

    Console.WriteLine("Текст записан в файл");

}

using (FileStream fstream = new FileStream(path, FileMode.OpenOrCreate))

{ 

    // заменим в файле слово world на слово house

    string replaceText = "house";

    fstream.Seek(-5, SeekOrigin.End); // минус 5 символов с конца потока

    byte[] input = Encoding.Default.GetBytes(replaceText);

    await fstream.WriteAsync(input, 0, input.Length);



    // считываем весь файл

    // возвращаем указатель в начало файла

    fstream.Seek(0, SeekOrigin.Begin);

    byte[] output = new byte[fstream.Length];

    await fstream.ReadAsync(output, 0, output.Length);

    // декодируем байты в строку

    string textFromFile = Encoding.Default.GetString(output);

    Console.WriteLine($"Текст из файла: {textFromFile}"); // hello house

}
```

снова сначала записывается `hello world`. файл открывается ещё раз, курсор снова встаёт за пять байтов до конца, на ту же позицию символа `w`, и с этой позиции пишется строка `house`. длины совпадают, по пять байтов, поэтому `house` занимает ровно место `world`: хвост файла не остаётся, и файл не растёт. другая длина замены оставила бы хвост прежних байтов или удлинила файл.

чтобы прочитать файл целиком после этой записи, курсор возвращается в начало. `Seek` с нулевым смещением от `SeekOrigin.Begin` ставит позицию 0:

```c#
fstream.Seek(0, SeekOrigin.Begin);
```

вывод программы:

```consoletext


Текст записан в файл

Текст из файла: hello house
```
