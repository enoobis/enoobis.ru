кроме обычных типов фреймворк .net поддерживает обобщённые типы (generics) и создание обобщённых методов. чтобы разобрать устройство этого механизма, сначала фиксируется проблема, которая возникала до появления обобщённых типов. класс для хранения данных пользователя задаётся так:

```c#


class Person

{

	public int Id { get;}

	public string Name { get;}

    public Person(int id, string name)

    {

        Id = id; 

        Name = name;

    }

}
```

класс `Person` определяет два свойства: `Id`, уникальный идентификатор пользователя, и `Name`, имя пользователя.

идентификатор задан как числовое значение: 1, 2, 3, 4 и так далее.

нередко для идентификатора используют и строковые значения. у числовых и у строковых значений есть свои плюсы и минусы. в момент написания класса может быть ещё не известно, что лучше выбрать для хранения идентификатора, строки или числа. класс могут использовать и другие разработчики со своим решением этой задачи, например с отдельным классом, созданным специально для представления идентификатора.

первый выход из этой ситуации состоит в том, чтобы определить свойство `Id` как свойство типа `object`. тип `object` является универсальным типом, от которого наследуются все типы, и в свойстве такого типа сохраняются и строки, и числа:

```c#


class Person

{

	public object Id { get;}

	public string Name { get;}

    public Person(object id, string name)

    {

        Id = id; 

        Name = name;

    }

}
```

затем класс используется для создания пользователей:

```c#


Person tom = new Person(546, "Tom");

Person bob = new Person("abc123", "Bob");



int tomId = (int)tom.Id;

string bobId = (string) bob.Id;



Console.WriteLine(tomId);   // 546

Console.WriteLine(bobId);   // abc123
```

программа компилируется и печатает оба идентификатора, но решение не оптимально. здесь возникают упаковка (boxing) и распаковка (unboxing).

при передаче в конструктор значения типа `int` это значение упаковывается в тип `object`:

```c#


Person tom = new Person(546, "Tom");	// упаковка в значения int в тип Object
```

чтобы снова получить данные в переменную типа `int`, нужна распаковка:

```c#


int tomId = (int)tom.Id;		// Распаковка в тип int
```

упаковка (boxing) есть преобразование значения значимого типа, например типа `int`, к типу `object`. при упаковке общеязыковая среда clr обертывает значение в объект и сохраняет его в управляемой куче. точный тип этого объекта-упаковки совпадает с исходным значимым типом: для `int` это `System.Int32`, а переменная типа `object` хранит ссылку на него. распаковка (unboxing) выполняет обратное преобразование: из объекта типа `object` извлекается значимый тип, и среда проверяет, что динамический тип упаковки совпадает с типом приведения. упаковка и распаковка снижают производительность, потому что системе нужно выделить объект в куче и выполнить эти преобразования.

существует и вторая проблема, безопасность типов. ошибка во время выполнения возникает при такой записи:

```c#


Person tom = new Person(546, "Tom");

string tomId = (string)tom.Id;  // !Ошибка  - Исключение InvalidCastException

Console.WriteLine(tomId);   // 546
```

какой именно объект представляет `Id`, по статическому типу `object` не видно. попытка прочитать число там, где лежит строка, или строку там, где лежит упакованное число, завершается исключением `InvalidCastException`. исключение возникает на этапе выполнения программы, компилятор эту ошибку не ловит.

для решения обеих проблем в язык c# добавлена поддержка **обобщённых типов** (их также называют универсальными). обобщённые типы позволяют указать конкретный тип, который будет использоваться. класс `Person` определяется как обобщённый:

```c#


class Person<T>

{

	public T Id { get; set; }

    public string Name { get; set; }

    public Person(T id, string name)

    {

        Id = id; 

        Name = name;

    }

}
```

угловые скобки в описании `class Person<T>` указывают, что класс является обобщённым, а тип `T`, заключённый в угловые скобки, будет использоваться этим классом. буква `T` не обязательна: на её месте может стоять любая другая буква или набор символов. на этапе написания класса конкретный тип неизвестен, им может оказаться любой тип. параметр `T` в угловых скобках называется универсальным параметром, или параметром типа: вместо него подставляется любой тип.

вместо параметра `T` можно подставить `int`, числовой номер пользователя. это может быть и `string`, и любой другой класс или структура:

```c#


Person<int> tom = new Person<int>(546, "Tom");  // упаковка не нужна

Person<string> bob = new Person<string>("abc123", "Bob");



int tomId = tom.Id;      // распаковка не нужна

string bobId = bob.Id;  // преобразование типов не нужно



Console.WriteLine(tomId);   // 546

Console.WriteLine(bobId);   // abc123
```

поскольку класс `Person` является обобщённым, при определении переменной после названия типа в угловых скобках указывается тип, который подставляется вместо универсального параметра `T`. объекты `Person` типизируются типами `int` и `string`:

```c#


Person<int> tom = new Person<int>(546, "Tom");  // упаковка не нужна

Person<string> bob = new Person<string>("abc123", "Bob");
```

у объекта `tom` свойство `Id` имеет тип `int`, у объекта `bob` тип `string`. для типа `int` упаковка не происходит: значение значимого типа хранится в поле объекта как часть его раскладки, а не как отдельный объект в куче.

в clr обобщения реифицированы. `Person<T>` есть открытый тип, а `Person<int>` и `Person<string>` есть два разных сконструированных типа со своими таблицами методов. это отличается от java, где параметр типа стирается и значение значимого типа в обобщённой коллекции всё равно упаковывается. отдельная специализация для `Person<int>` как раз и убирает упаковку.

попытка передать для параметра `id` значение другого типа даёт ошибку компиляции:

```c#


Person<int> tom = new Person<int>("546", "Tom");  // ошибка компиляции
```

при получении значения из `Id` операция приведения типов больше не нужна, и распаковка тоже не применяется:

```c#
int tomId = tom.Id;      // распаковка не нужна
```

проверка типа переносится со времени выполнения на время компиляции. обобщённый вариант класса сокращает время выполнения и уменьшает число ошибок, которые иначе обнаруживаются только при запуске.

универсальный параметр сам может быть обобщённым типом:

```c#


// класс компании

class Company<P>

{

    public P CEO { get; set; }  // президент компании

    public Company(P ceo)

    {

        CEO = ceo;

    }

}

class Person<T>

{

    public T Id { get;}

    public string Name { get;}

    public Person(T id, string name)

    {

        Id = id; 

        Name = name;

    }

}
```

класс компании определяет свойство `CEO`, которое хранит президента компании. в это свойство передаётся значение типа `Person`, типизированного каким-либо типом:

```c#


Person<int> tom = new Person<int>(546, "Tom");

Company<Person<int>> microsoft =  new Company<Person<int>>(tom);



Console.WriteLine(microsoft.CEO.Id);  // 546

Console.WriteLine(microsoft.CEO.Name);  // Tom
```

запись `Company<Person<int>>` есть вложенное конструирование типа: внешний параметр закрыт типом `Person<int>`, а тот в свою очередь закрыт типом `int`.

### статические поля обобщённых классов

при типизации обобщённого класса определённым типом создаётся свой набор статических членов. в классе `Person` определено такое статическое поле:

```c#


class Person<T>

{

    public static T? code;

    public T Id { get; set; }

    public string Name { get; set; }

    public Person(T id, string name)

    {

        Id = id; 

        Name = name;

    }

}
```

класс типизируется двумя типами, `int` и `string`:

```c#


Person<int> tom = new Person<int>(546, "Tom");

Person<int>.code = 1234;



Person<string> bob = new Person<string>("abc", "Bob");

Person<string>.code = "meta";



Console.WriteLine(Person<int>.code);       // 1234

Console.WriteLine(Person<string>.code);   // meta
```

в итоге для `Person<int>` и для `Person<string>` создаётся своя переменная `code`. статические поля принадлежат сконструированному типу, а не открытому шаблону: у `Person<int>` и `Person<string>` разные статические состояния, и присваивание одному не видно в другом.

### использование нескольких универсальных параметров

обобщения могут использовать несколько универсальных параметров одновременно. эти параметры представляют одинаковые или различные типы:

```c#


class Person<T, K>

{

    public T Id { get;}

    public K Password { get; set; }

    public string Name { get;}

    public Person(T id, K password, string name)

    {

        Id = id; 

        Name = name;

        Password = password;

    }

}
```

класс `Person` использует два универсальных параметра: один для идентификатора, другой для свойства-пароля. применение класса:

```c#


Person<int, string> tom = new Person<int, string>(546, "qwerty", "Tom");

Console.WriteLine(tom.Id);  // 546

Console.WriteLine(tom.Password);// qwerty
```

объект `Person` типизируется типами `int` и `string`. в качестве универсального параметра `T` используется тип `int`, для параметра `K` используется тип `string`. порядок аргументов типа соответствует порядку параметров в объявлении `Person<T, K>`.

### обобщённые методы

кроме обобщённых классов создаются обобщённые методы, которые точно так же используют универсальные параметры:

```c#


int x = 7;

int y = 25;

Swap<int>(ref x, ref y); // или так Swap(ref x, ref y);

Console.WriteLine($"x={x}    y={y}");   // x=25   y=7



string s1 = "hello";

string s2 = "bye";

Swap<string>(ref s1, ref s2); // или так Swap(ref s1, ref s2);

Console.WriteLine($"s1={s1}    s2={s2}"); // s1=bye   s2=hello



void Swap<T>(ref T x, ref T y)

{

    T temp = x;

    x = y;

    y = temp;

}
```

метод `Swap` обобщённый: он принимает параметры по ссылке и меняет их значения. какой тип представляют эти параметры, для тела метода не важно. тело написано один раз для открытого `T`, а компилятор подставляет конкретный тип в месте вызова.

при вызове метод `Swap` типизируется определённым типом, и ему передаются значения этого типа. аргумент типа можно указать явно, `Swap<int>`, либо опустить: по типам аргументов компилятор выводит `T` сам. такой вывод делается для обобщённых методов. в выражении `new Person<int>(...)` аргументы типа у класса записываются явно: по одним только аргументам конструктора компилятор их не восстанавливает.
