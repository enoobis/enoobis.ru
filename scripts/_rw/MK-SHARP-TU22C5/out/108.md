тип **Span** обозначает непрерывный участок памяти. он введён для того, чтобы операции над последовательностями обходились без дополнительных выделений. сам `Span<T>` является ref-структурой: значение span размещается на стеке либо встраивается в другую ref-структуру и не может оказаться в куче. память, на которую span указывает, при этом может лежать где угодно: в массиве в куче, в блоке `stackalloc` или в неуправляемом буфере. внутри span хранит управляемую ссылку на начало участка и длину. отсюда стоимость `Slice`: меняются только смещение и длина, копии элементов нет.

### создание Span

экземпляр строится одним из конструкторов:

- `Span()`: создаёт пустой Span

- `Span(T item)`: создаёт Span из одного элемента item

- `Span(T[] array)`: создаёт Span по всему массиву array

- `Span(void* pointer, int length)`: создаёт Span из length элементов типа T, начиная с адреса pointer

- `Span(T[] array, int start, int length)`: создаёт Span из length элементов массива array, начиная с индекса start

простейшая запись использует выражение коллекции и получает span из трёх строк:

```c#


Span<string> people = ["Tom", "Bob", "Sam"];
```

такой span хранит ссылки на три строки. сами строки по-прежнему лежат в куче, span лишь задаёт окно из трёх ссылок.

часто span строится поверх уже существующего набора:

```c#


string[] people =  { "Tom", "Alice", "Bob" };

Span<string> peopleSpan = new Span<string>(people);
```

массив может быть преобразован в span неявно, отдельный вызов конструктора тогда не пишется:

```c#


string[] people = { "Tom", "Alice", "Bob" };

Span<string> peopleSpan = people;
```

чтение, запись и перебор выглядят так же, как у массива. индексатор, длина и `foreach` работают по хранимому окну:

```c#


string[] people = { "Tom", "Alice", "Bob" };

Span<string> peopleSpan = people;

peopleSpan[1] = "Ann";              // переустановка значения элемента

Console.WriteLine(peopleSpan[2]);   // получение элемента

Console.WriteLine(peopleSpan.Length);   // получение длины Span



// перебор Span

foreach (var s in peopleSpan)

{

	Console.WriteLine(s);

}
```

присваивание `peopleSpan[1] = "Ann"` меняет вторую ячейку исходного массива people. `Length` здесь равен трём. цикл foreach перебирает окно по порядку.

назначение типа видно на задаче, где из одного массива нужны два окна. пусть temperatures хранит дневные температуры за месяц, и требуются первая и последняя декады. на одних массивах это делается копированием:

```c#


int[] temperatures =

{

	10, 12, 13, 14, 15, 11, 13, 15, 16, 17,

	18, 16, 15, 16, 17, 14,  9,  8, 10, 11,

	12, 14, 15, 15, 16, 15, 13, 12, 12, 11

};

int[] firstDecade = new int[10];	// выделяем память для первой декады

int[] lastDecade = new int[10];		// выделяем память для второй декады

Array.Copy(temperatures, 0, firstDecade, 0, 10);	// копируем данные в первый массив

Array.Copy(temperatures, 20, lastDecade, 0, 10);	// копируем данные во второй массив
```

для каждой декады выделяется собственный массив из десяти int, затем `Array.Copy` переносит в него десять значений. оба новых массива повторяют данные, которые уже лежат в temperatures, и занимают отдельные участки кучи.

span даёт те же два окна без копирования и без нового буфера под числа:

```c#


int[] temperatures =

{

	10, 12, 13, 14, 15, 11, 13, 15, 16, 17,

	18, 16, 15, 16, 17, 14,  9,  8, 10, 11,

	12, 14, 15, 15, 16, 15, 13, 12, 12, 11

};

Span<int> temperaturesSpan = temperatures;



Span<int> firstDecade = temperaturesSpan.Slice(0, 10);	// нет выделения памяти под данные

Span<int> lastDecade = temperaturesSpan.Slice(20, 10);	// нет выделения памяти под данные
```

метод Slice выделяет из span подпоследовательность и возвращает её новым объектом span. firstDecade смотрит на элементы `[0, 10)`, lastDecade смотрит на элементы `[20, 10)` того же массива temperatures. дополнительная память под сами температуры не выделяется: три значения span описывают один и тот же массив разными смещениями и длинами.

запись через одно окно видна через другое, потому что оба окна адресуют одни и те же ячейки:

```c#


int[] temperatures =

{

	10, 12, 13, 14, 15, 11, 13, 15, 16, 17,

	18, 16, 15, 16, 17, 14,  9,  8, 10, 11,

	12, 14, 15, 15, 16, 15, 13, 12, 12, 11

};

Span<int> temperaturesSpan = temperatures;



Span<int> firstDecade = temperaturesSpan.Slice(0, 10);



temperaturesSpan[0] = 25; // меняем в temperatureSpan

Console.WriteLine(firstDecade[0]); //25
```

`temperaturesSpan[0] = 25` записывает 25 в нулевой элемент массива. `firstDecade[0]` читает ту же ячейку и печатает 25.

устройство индексатора видно по открытому контракту типа:

```c#


public readonly ref struct Span<T>

{

	//....

	public ref T this[int index] { get { ... } }

	//....

}
```

индексатор возвращает `ref T`, управляемую ссылку на сам элемент. присваивание через такую ссылку меняет память исходного массива. на коротком примере выигрыш от отсутствующего копирования мал. при многократных разрезах больших буферов копирование участков начало бы доминировать и по времени, и по числу выделений в куче, тогда как `Slice` остаётся операцией над парой полей.

### методы Span

основные методы span:

- `void Fill(T value)`: заполняет все элементы span значением value

- `T[] ToArray()`: копирует элементы span в новый массив

- `Span<T> Slice(int start, int length)`: выделяет из span участок из length элементов, начиная с индекса start, и возвращает его как другой span

- `void Clear()`: очищает span, записывая в элементы значение по умолчанию

- `void CopyTo(Span<T> destination)`: копирует элементы текущего span в другой span

- `bool TryCopyTo(Span<T> destination)`: копирует элементы текущего span в другой span и возвращает bool: true, если копирование выполнено

`ToArray` и `CopyTo` как раз выполняют то выделение и копирование, которого `Slice` избегает. `CopyTo` требует, чтобы приёмник был не короче источника, иначе операция завершается исключением. `TryCopyTo` в той же ситуации возвращает false и приёмник не меняет. `Fill` и `Clear` пишут в исходную память через окно.

### ReadOnlySpan

структура **ReadOnlySpan** повторяет устройство span для данных, которые через это окно менять нельзя:

```c#


string text = "hello, world";

string worldString = text.Substring(startIndex: 7, length: 5); 			 // есть выделение памяти под символы

ReadOnlySpan<char> worldSpan = text.AsSpan().Slice(start: 7, length: 5); // нет выделения памяти под символы

//worldSpan[0] = 'a'; // Нельзя изменить

Console.WriteLine(worldSpan[0]); // выводим первый символ



// перебор символов

foreach(var c in worldSpan)

{

	Console.Write(c);

}
```

метод **AsSpan()** строит по строке `ReadOnlySpan<char>` на её внутренний буфер. последующий `Slice(start: 7, length: 5)` выделяет символы слова world. `Substring` на том же участке создаёт новую строку и копирует в неё символы. окно ReadOnlySpan тех же пяти единиц utf-16 отдельной строки не выделяет. индексатор окна доступен для чтения, запись `worldSpan[0] = 'a'` отвергается компилятором, что и зафиксировано в закомментированной строке. перебор `foreach` читает символы по одному. в остальном протокол совпадает со span: есть длина, срез, копирование в массив и проверка границ.

строка в .net неизменяема, поэтому тип окна над ней только для чтения. изменяемый `Span<char>` по всей строке построить нельзя: это оставило бы открытой запись в буфер, который контракт `System.String` считает постоянным.

### ограничения Span

модификатор ref у структуры накладывает ограничения, и все они следуют из запрета размещать значение в куче. span нельзя присвоить переменной типа `Object`, `dynamic` или переменной интерфейсного типа: такое присваивание упаковывало бы значение. span нельзя объявить полем объекта ссылочного типа. поле другого ref-структурного типа допустимо. span нельзя переносить через точку `await` и нельзя использовать в блоке итератора с `yield`: обе конструкции сохраняют локальное состояние в объекте кучи. ref-структура в такой объект не помещается. по той же причине span не захватывается лямбдой, которая переживает создавший её кадр стека.
