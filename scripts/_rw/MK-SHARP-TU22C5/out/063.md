если код, породивший исключение, не входит в блок try либо входит в конструкцию try..catch без блока catch, совместимого с типом исключения, среда выполнения ищет обработчик по стеку вызовов. поиск начинается в кадре, где исключение возникло, и идёт к более ранним кадрам, то есть к вызывающим методам.

в clr этот поиск устроен двумя проходами. на первом проходе выбирается кадр, чей catch принимает тип исключения: тип параметра catch должен совпадать с типом исключения или быть его базовым типом. блоки finally на первом проходе не выполняются. когда обработчик найден, второй проход раскручивает стек от места генерации до этого кадра и в каждом покидаемом кадре выполняет finally. после раскрутки выполняется сам catch, а затем finally той конструкции, в которой обработчик стоит. операторы после try в кадрах, не перехвативших исключение, не выполняются: управление в эти кадры не возвращается.

следующая программа собирает такую цепочку вызовов.

```c#

try
{
    TestClass.Method1();
}
catch (DivideByZeroException ex)
{
    Console.WriteLine($"Catch в Main : {ex.Message}");
}
finally
{
    Console.WriteLine("Блок finally в Main");
}
Console.WriteLine("Конец метода Main");

class TestClass
{
    public static void Method1()
    {
        try
        {
            Method2();
        }
        catch (IndexOutOfRangeException ex)
        {
            Console.WriteLine($"Catch в Method1 : {ex.Message}");
        }
        finally
        {
            Console.WriteLine("Блок finally в Method1");
        }
        Console.WriteLine("Конец метода Method1");
    }
    static void Method2()
    {
        try
        {
            int x = 8;
            int y = x / 0;
        }
        finally
        {
            Console.WriteLine("Блок finally в Method2");
        }
        Console.WriteLine("Конец метода Method2");
    }
}
```

стек вызовов здесь линейный: метод Main вызывает Method1, Method1 вызывает Method2. исключение DivideByZeroException возникает в Method2 при делении на нуль. тип DivideByZeroException входит в ветвь ArithmeticException и не является подтипом IndexOutOfRangeException, поэтому catch с параметром IndexOutOfRangeException его не принимает.

внизу стека находится метод Main, с которого началось выполнение. наверху находится Method2.

при генерации исключения обработка идёт в таком порядке.

- метод Main вызывает метод Method1, а тот вызывает метод Method2. в Method2 генерируется исключение DivideByZeroException.

- код, породивший исключение, стоит в конструкции try с блоком finally и без catch. среда ищет в этой конструкции catch для DivideByZeroException и не находит его. finally этого кадра ещё не выполняется: его очередь наступает на проходе раскрутки.

```c#

try
{
	int x = 8;
	int y = x / 0;
}
finally
{
	Console.WriteLine("Блок finally в Method2");
}
```

- поиск спускается по стеку в метод Method1, из которого вызван Method2. вызов Method2 стоит в конструкции try..catch. catch в этом кадре принимает IndexOutOfRangeException и для DivideByZeroException не подходит, поэтому обработчик здесь тоже не выбран.

```c#

try
{
	Method2();
}
catch (IndexOutOfRangeException ex)
{
	Console.WriteLine($"Catch в Method1 : {ex.Message}");
}
finally
{
	Console.WriteLine("Блок finally в Method1");
}
```

- поиск спускается в метод Main, из которого вызван Method1. вызов Method1 стоит в конструкции try..catch, и catch (DivideByZeroException) совместим с типом исключения. нужный обработчик найден. первый проход на этом заканчивается, а сам блок catch пока не выполняется.

```c#

try
{
	TestClass.Method1();
}
catch (DivideByZeroException ex)
{
	Console.WriteLine($"Catch в Main : {ex.Message}");
}
finally
{
	Console.WriteLine("Блок finally в Main");
}
```

- второй проход поднимается к вершине стека, в метод Method2, где исключение возникло непосредственно, и выполняет там finally.

```c#

finally
{
	Console.WriteLine("Блок finally в Method2");
}
```

- затем раскрутка доходит до метода Method1 и выполняет его finally.

```c#

finally
{
	Console.WriteLine("Блок finally в Method1");
}
```

- после этого управление переходит в метод Main. выполняется найденный catch, а следом finally той же конструкции. порядок внутри кадра-обработчика фиксирован: сначала catch, затем finally.

```c#

catch (DivideByZeroException ex)
{
	Console.WriteLine($"Catch в Main : {ex.Message}");
}
finally
{
	Console.WriteLine("Блок finally в Main");
}
```

- дальше выполняется код метода Main, стоящий после конструкции try..catch. код после конструкции try в Method1 и Method2 не выполняется: обработчик выбран в Main, эти кадры уже покинуты, и продолжения в них нет.

```c#

Console.WriteLine("Конец метода Main");
```

консольный вывод программы:

```consoletext

Блок finally в Method2
Блок finally в Method1
Catch в Main: Attempted to divide by zero
Блок finally в Main
Конец метода Main
```

порядок строк совпадает с раскруткой. сначала печатает finally метода Method2, затем finally метода Method1. после этого catch в Main выводит сообщение исключения, затем выполняется finally в Main, и только потом оператор, стоящий за конструкцией в Main.
