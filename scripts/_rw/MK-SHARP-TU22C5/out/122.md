язык c# выполняет в одном приложении несколько потоков одновременно: на одном ядре за счёт чередования квантов, на нескольких ядрах параллельно. новый поток создаётся конструктором класса `Thread`. перегрузки различаются делегатом тела потока и необязательным размером стека:

- `Thread(ThreadStart)`: аргумент это делегат `ThreadStart`, он задаёт действие потока
- `Thread(ThreadStart, Int32)`: кроме `ThreadStart` принимается размер стека этого потока в байтах. 0 означает стек по умолчанию для среды выполнения
- `Thread(ParameterizedThreadStart)`: аргумент это делегат `ParameterizedThreadStart`, действие с одним параметром типа `object?`
- `Thread(ParameterizedThreadStart, Int32)`: вместе с `ParameterizedThreadStart` принимается размер стека в байтах

при любом конструкторе нужно определить действие, которое поток будет выполнять. здесь используется делегат `ThreadStart`. его сигнатура не принимает параметров и не возвращает значения:

```c#
public delegate void ThreadStart();
```

под этот делегат подходит метод с типом результата `void` без параметров. три способа передать такое действие: группа методов, явный экземпляр `ThreadStart` и лямбда без параметров. группа методов `Print` приводится к `ThreadStart` по сигнатуре. запись `new ThreadStart(Print)` делает то же преобразование явно. лямбда `() => Console.WriteLine("Hello Threads")` совместима с `ThreadStart`, потому что тоже ничего не принимает и ничего не возвращает.

```c#


Thread myThread1 = new Thread(Print); 

Thread myThread2 = new Thread(new ThreadStart(Print));

Thread myThread3 = new Thread(()=>Console.WriteLine("Hello Threads"));



void Print() => Console.WriteLine("Hello Threads");
```

запуск выполняет метод `Start` класса `Thread`. до `Start` поток остаётся в состоянии `Unstarted`, его делегат не вызывается. каждый `Start` планирует свой поток. порядок, в котором три строки появятся на консоли, определяет планировщик.

```c#


using System.Threading;



// создаем новый поток

Thread myThread1 = new Thread(Print); 

Thread myThread2 = new Thread(new ThreadStart(Print));

Thread myThread3 = new Thread(()=>Console.WriteLine("Hello Threads"));



myThread1.Start();  // запускаем поток myThread1

myThread2.Start();  // запускаем поток myThread2

myThread3.Start();  // запускаем поток myThread3



void Print() => Console.WriteLine("Hello Threads");
```

потоки продвигаются одновременно. в следующем примере главный поток и второй поток печатают свои последовательности, каждый со своей паузой:

```c#


using System.Threading;



// создаем новый поток

Thread myThread = new Thread(Print);

// запускаем поток myThread

myThread.Start();



// действия, выполняемые в главном потоке

for (int i = 0; i < 5; i++)

{

    Console.WriteLine($"Главный поток: {i}");

    Thread.Sleep(300);

}



// действия, выполняемые во втором потокке

void Print()

{

    for (int i = 0; i < 5; i++)

    {

        Console.WriteLine($"Второй поток: {i}");

        Thread.Sleep(400);

    }

}
```

новый поток выполняет метод `Print`: печатает числа от 0 до 4 и после каждого вывода ждёт 400 миллисекунд. `Thread.Sleep` блокирует только вызывающий поток. второй поток спит, главный в это время может получить квант, и наоборот.

в главном потоке, в классической записи это метод `Main`, создаётся и запускается поток с методом `Print`:

```c#


Thread myThread = new Thread(Print);

myThread.Start();
```

главный поток делает ту же работу у себя: печатает числа от 0 до 4 с паузой 300 миллисекунд. паузы разные, поэтому шаги двух циклов смещаются друг относительно друга.

одновременно работают главный поток и второй поток с методом `Print`. процесс завершается, когда завершились все потоки переднего плана. по умолчанию новый `Thread` является потоком переднего плана, поэтому завершение метода верхнего уровня само по себе программу не заканчивает: среда ждёт и второй поток. один из допустимых вариантов чередования, его и показывает исходный пример, такой. главный поток спит 300 мс, второй 400 мс, и при типичном планировании их печати идут через одну. другой порядок тоже возможен: `Sleep` задаёт нижнюю границу ожидания, а не расписание.

```consoletext


Главный поток: 0

Второй поток: 0

Главный поток: 1

Второй поток: 1

Главный поток: 2

Второй поток: 2

Главный поток: 3

Второй поток: 3

Главный поток: 4

Второй поток: 4
```

тем же конструктором создаются три, четыре и любой другой набор потоков, каждому со своим делегатом. число потоков ограничено ресурсами процесса, в первую очередь памятью под стеки и тем, сколько потоков операционная система готова планировать. для большого числа коротких задач обычно берут пул потоков, а `Thread` оставляют для долгой работы с собственным временем жизни. в примерах этой лекции потоки создаются напрямую.
