кроме обычных методов в c# есть специальные методы доступа, которые называют свойствами. свойство даёт доступ к полю класса или структуры: через него читают значение или записывают новое. для клиентского кода свойство выглядит как поле, но компилятор превращает его в методы. у свойства `Name` это методы чтения `get_Name` и записи `set_Name`. хранилища у самого свойства нет, если только его не добавит компилятор у автосвойства.

### определение свойств

обычное объявление свойства имеет такой синтаксис.

```c#


[модификаторы] тип_свойства название_свойства

{

	get { действия, выполняемые при получении значения свойства}

	set { действия, выполняемые при установке значения свойства}

}
```

в начале определения могут стоять модификаторы, в том числе модификаторы доступа. затем идут тип свойства и его имя. полное определение содержит два блока: `get` и `set`.

блок `get` выполняется при чтении свойства. оператор `return` возвращает значение.

блок `set` выполняется при записи. параметр `value` принимает значение, переданное свойству. тип `value` совпадает с типом свойства, объявлять этот параметр не нужно: он входит в сигнатуру аксессора записи.

блоки `get` и `set` называют аксессорами, или методами доступа к значению свойства, а также геттером и сеттером.

пример:

```c#


Person person = new Person();



// Устанавливаем свойство - срабатывает блок Set

// значение "Tom" и есть передаваемое в свойство value

person.Name = "Tom";



// Получаем значение свойства и присваиваем его переменной - срабатывает блок Get

string personName = person.Name;

Console.WriteLine(personName);  // Tom



class Person

{

    private string name = "Undefined";



    public string Name

    {

        get

        {

            return name;	// возвращаем значение свойства

        }

        set

        {

            name = value;	// устанавливаем новое значение свойства

        }

    }

}
```

в классе `Person` закрытое поле `name` хранит имя, открытое свойство `Name` открывает к нему доступ. совпадение имён с точностью до регистра является соглашением об именовании. имена поля и свойства могут быть любыми и могут не совпадать.

через свойство внешний код управляет доступом к `name`. блок `get` возвращает значение поля.

```c#
get { return name; }
```

блок `set` записывает в `name` переданное значение. параметр `value` и есть это значение.

```c#
set { name = value; }
```

к свойству обращаются как к полю. присваивание запускает блок `set`, и правая часть попадает в `value`.

```c#


person.Name = "Tom";
```

чтение запускает блок `get`, который возвращает значение переменной `name`.

```c#


string personName = person.Name;
```

свойство `Name` само значения не хранит. оно стоит между внешним кодом и переменной `name`: чтение и запись проходят через аксессоры, и именно там можно поставить проверку.

свойство нужно там, где при чтении или записи требуется дополнительная логика. поле такой логики не выполняет: присваивание сразу меняет хранилище. проверка возраста показывает, зачем нужен аксессор.

```c#


Person person = new Person();



Console.WriteLine(person.Age);  // 1

// изменяем значение свойства

person.Age = 37;

Console.WriteLine(person.Age);  // 37

// пробуем передать недопустимое значение

person.Age = -23;               // Возраст должен быть в диапазоне от 1 до 120

Console.WriteLine(person.Age);  // 37 - возраст не изменился



class Person

{

    int age = 1;

    public int Age

    {

        set

        {

            if (value < 1 || value > 120)

                Console.WriteLine("Возраст должен быть в диапазоне от 1 до 120");

            else 

                age = value;

        }

        get { return age; }

    }

}
```

поле `age` хранит возраст и снаружи напрямую недоступно. чтение и запись идут через свойство `Age`. в блоке `set` значение принимается только из диапазона от 1 до 120. число вне диапазона поле не меняет, вместо записи метод выводит сообщение.

```c#
person.Age = -23; </pre

<p>Консольный вывод программы:</p>

<pre class="sh">

1

37

Возраст должен быть в диапазоне от 1 до 120

37
```

вызов `person.Age = -23` попадает в сеттер с `value`, равным -23. условие диапазона не выполнено, поэтому в `age` ничего не пишется. след в этом фрагменте такой: сначала печатается исходный возраст 1, после допустимого присваивания печатается 37, затем строка о диапазоне, и снова 37, потому что отклонённая запись оставила прежнее значение.

свойство опосредует доступ к данным объекта и проверяет значение до того, как оно попадёт в поле.

### свойства только для чтения и записи

блоки `set` и `get` не обязаны присутствовать вместе. если у свойства есть только `get`, оно доступно только для чтения: значение можно получить и нельзя установить.

если есть только `set`, свойство доступно только для записи: значение можно установить и нельзя прочитать.

```c#


Person person = new Person();



// свойство для чтения - можно получить значение

Console.WriteLine(person.Name);  // Tom

// но нельзя установить

// person.Name = "Bob";    // ! Ошибка



// свойство для записи - можно устновить значение

person.Age = 37;

// но нелзя получить

// Console.WriteLine(person.Age);  // ! Ошибка



person.Print();



class Person

{

    string name = "Tom";

    int age = 1;

    // свойство только для записи

    public int Age

    {

        set { age = value; }

    }

    // свойство только для чтения

    public string Name

    {

        get { return name; }

    }



    public void Print()=> Console.WriteLine($"Name: {name}  Age: {age}");

}
```

свойство `Name` доступно только для чтения, потому что у него один блок `get`.

```c#


public string Name

{

	get { return name; }

}
```

его значение получают, установить его нельзя.

```c#


Console.WriteLine(person.Name);  // получить можно

person.Name = "Bob";    // ! Ошибка - установить нельзя
```

свойство `Age`, напротив, доступно только для записи: у него один блок `set`.

```c#


public int Age

{

	set { age = value; }

}
```

значение устанавливают, прочитать его через свойство нельзя.

```c#


person.Age = 37; // установить можно

Console.WriteLine(person.Age);  // ! Ошибка - получить значение нельзя
```

метод `Print` по-прежнему видит оба поля, потому что он находится внутри класса. ограничение относится к коду вне класса. свойство только для записи оставляет значение в закрытом поле и не отдаёт его наружу через этот аксессор.

### вычисляемые свойства

свойство не обязано быть связано с отдельной переменной. его значение может вычисляться по выражению при каждом чтении.

```c#


Person tom = new("Tom", "Smith");

Console.WriteLine(tom.Name);    // Tom Smith

class Person

{

    string firstName;

    string lastName;

    public string Name

    {

        get { return  $"{firstName} {lastName}"; }

    }

    public Person(string firstName, string lastName)

    {

        this.firstName = firstName; 

        this.lastName = lastName;

    }

}
```

у `Person` свойство `Name` только для чтения. оно возвращает строку, собранную из `firstName` и `lastName`. отдельного поля под полное имя нет: значение возникает в момент вызова геттера. повторное чтение снова вычислит строку, поэтому изменение `firstName` или `lastName`, если бы оно было возможно снаружи, отразилось бы на `Name`. в этом классе оба поля задаются только в конструкторе.

### модификаторы доступа

модификатор доступа ставят не только на всё свойство, но и на отдельный блок `get` или `set`.

```c#


Person tom = new("Tom");



// Ошибка - set объявлен с модификатором private

//tom.Name = "Bob";

Console.WriteLine(tom.Name);    // Tom

class Person

{

    string name = "";

    public string Name

    {

        get { return name; }



        private set { name = value; }

    }

    public Person(string name) => Name = name;

}
```

закрытый блок `set` доступен только внутри класса: в его методах, свойствах и конструкторе. из другого класса присваивание `tom.Name = "Bob"` не компилируется. чтение остаётся открытым, потому что модификатор `public` относится к свойству в целом, а `private` сужает только сеттер. конструктор записывает имя через `Name = name` и тем самым проходит через тот же сеттер, уже изнутри класса, где `private` его разрешает.

у модификаторов аксессоров есть ограничения.

- модификатор для блока `set` или `get` можно поставить, только если у свойства есть оба блока

- модификатор доступа может иметь только один из блоков, `set` или `get`, но не оба сразу

- модификатор доступа блока должен быть более ограничивающим, чем модификатор самого свойства. если свойство помечено `public`, блоку `set` или `get` доступны только `protected internal`, `internal`, `protected`, `private protected` и `private`

более широкий доступ у аксессора, чем у свойства, язык не принимает: аксессор не может открыть член шире, чем объявлено у свойства.

### автоматические свойства

свойство управляет доступом к полю. если полей много, писать для каждого поле и однотипную пару аксессоров долго. в .net для этого добавлены автоматические свойства, у них сокращённое объявление.

```c#


class Person

{

    public string Name { get; set; }

    public int Age { get; set; }

		

	public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

поля для таких свойств в исходном тексте нет. их создаёт компилятор: у каждого автосвойства появляется скрытое поле, имя которого в исходнике не записано. геттер возвращает это поле, сеттер его записывает.

смысл автосвойства в том, что его в любой момент можно развернуть в обычное свойство и добавить логику, сохранив имя, тип и способ вызова у клиентского кода. вызов `person.Name` при этом не меняется. имя скрытого поля выбирает компилятор, и это имя может стать другим, если автосвойство заменить полным свойством с явно объявленным полем. код, который через рефлексию читал именно сгенерированное поле, на такую замену не рассчитан.

автоматическое свойство только для записи, в отличие от обычного свойства с одним блоком `set`, объявить нельзя. у автосвойства должен быть аксессор чтения: компилятору нужно знать, откуда возвращать значение скрытого поля.

автосвойству можно задать значение по умолчанию, это инициализация автосвойства.

```c#


Person tom = new();



Console.WriteLine(tom.Name);    // Tom

Console.WriteLine(tom.Age);    // 37



class Person

{

    public string Name { get; set; } = "Tom";

    public int Age { get; set; } = 37;

}
```

если при создании объекта `Person` свойства `Name` и `Age` не задают ни конструктор, ни инициализатор объекта, действуют значения по умолчанию `"Tom"` и 37. инициализатор свойства выполняется при создании объекта раньше тела конструктора, когда конструктор есть.

у автосвойств тоже бывают модификаторы доступа аксессоров.

```c#


class Person

{

    public string Name { private set; get;}

    public Person(string name) => Name = name;

}
```

блок `set` помечен `private`, поэтому записать `Name` можно внутри класса. конструктор делает это присваиванием `Name = name`.

блок `set` можно убрать и оставить автосвойство только для чтения. для хранения значения компилятор создаёт поле с модификатором `readonly`. такое свойство задают либо из конструктора, либо в инициализаторе самого свойства.

```c#


class Person

{

	// через инициализацию свойства

	public string Name { get; } = "Tom";

	// через конструктор

	public Person(string name) => Name = name;

}
```

в примере показаны оба места. инициализатор свойства записывает `"Tom"`. конструктор тоже имеет право присвоить `Name`, потому что выполнение конструктора ещё входит в инициализацию объекта. после завершения конструктора присваивание из внешнего кода для свойства только с `get` уже не компилируется: поле `readonly` получает значение один раз.

### блок init

начиная с c# 9.0 сеттер можно объявить оператором `init` (от initialization, инициализация). блок `init` как раз инициализирует свойство. значение свойства с `init` задают инициализатором объекта, конструктором или значением при объявлении. после инициализации изменить его нельзя, дальше свойство ведёт себя как доступное только для чтения. от свойства только с `get` его отличает инициализатор объекта: свойство только для чтения в инициализаторе объекта не задаётся, свойство с `init` задаётся.

```c#


Person person = new();

//person.Name = "Bob";    //! Ошибка - после инициализации изменить значение нельзя



Console.WriteLine(person.Name); // Undefined

public class Person

{

    public string Name { get; init; } = "Undefined";

}
```

у свойства `Name` вместо сеттера стоит `init`. строка

```c#
Person person = new();
```

создаёт объект и инициализирует его свойства. `Name` получает `"Undefined"` из инициализатора свойства. инициализация на этом уже закончена, поэтому строка

```c#
person.Name = "Bob";	// Ошибка
```

даёт ошибку компиляции. присваивание после создания объекта в аксессор `init` не попадает.

задать такое свойство можно несколькими способами. первый способ уже показан: значение при объявлении свойства. второй способ проходит через конструктор.

```c#


Person person = new("Tom");

Console.WriteLine(person.Name); // Tom

public class Person

{

    public Person(string name) => Name = name;

    public string Name { get; init; }

}
```

конструктор присваивает `Name`, и для `init` это законно: тело конструктора выполняется во время инициализации. вызов `new("Tom")` печатает `Tom`.

третий способ использует инициализатор объекта.

```c#


Person person = new() { Name = "Bob"};

Console.WriteLine(person.Name); // Bob



public class Person

{

    public string Name { get; init; } = "";

}
```

инициализатор `{ Name = "Bob" }` записывает свойство после конструктора, но ещё в фазе инициализации. начальное значение `""` из объявления свойства при этом заменяется.

четвёртый способ состоит в записи через другое свойство с модификатором `init`.

```c#


var person = new Person() { Name = "Sam" };

Console.WriteLine(person.Name);     // Sam

Console.WriteLine(person.Email);    // Sam@gmail.com

public class Person

{

    string name = "";

    public string Name

    {

        get { return name; }

        init

        {

            name = value;

            Email = $"{value}@gmail.com";

        }

    }

    public string Email { get; init; } = "";

}
```

свойство `Name` управляет полем `name`. перед записью в аксессоре `init` можно выполнить подготовку значения. в том же блоке устанавливается другое init-свойство, `Email`: из имени собирается адрес `value@gmail.com`. присваивание `Email` из аксессора `Name` законно, потому что оба свойства ещё инициализируются. когда инициализация объекта завершится, ни `Name`, ни `Email` снаружи изменить будет нельзя.

если при объявлении свойства указано значение, конструктор может его заменить. значение, установленное в конструкторе, может заменить инициализатор объекта. на этом инициализация заканчивается, и дальнейшее изменение значения не компилируется. порядок фиксирован: инициализатор свойства, затем тело конструктора, затем инициализатор объекта в выражении создания.

### сокращённая запись свойств

определение свойства сокращают так же, как метод. блоки `get` и `set` являются методами. если в аксессоре одна инструкция, его записывают через `=>`.

```c#


class Person

{

	string name;

	public string Name 

	{ 

		get => name;

		set => name = value; 

	}

}
```

всё свойство целиком тоже можно сократить, если оно только читает значение.

```c#


class Person

{

	string name;

	

	// эквивалентно public string Name { get { return name; } }

	public string Name => name;

}
```

запись `public string Name => name` эквивалентна свойству только для чтения, геттер которого возвращает `name`. сеттера у такой формы нет, и добавить его в ту же стрелочную запись нельзя: для пары аксессоров используют форму с двумя блоками, как в предыдущем примере.

### модификатор required

модификатор `required` добавлен в c# 11. поле или свойство с этим модификатором обязательно инициализируют при создании объекта. следующий пример не компилируется.

```c#


Person tom = new Person();  // ошибка - свойства Name и Age не инициализированы

public class Person

{

    public required string Name { get; set; }

    public required int Age { get; set; }

}
```

`Name` и `Age` отмечены `required`, поэтому их задают в инициализаторе объекта.

```c#
Person tom = new Person { Name = "Tom", Age = 38 }; // ошибки нет
```

присваивание в конструкторе и значение при объявлении это требование не снимают. инициализатор на месте вызова всё равно нужен. следующий пример тоже даёт ошибку.

```c#


Person bob = new Person("Bob"); // ошибка - свойства Name и Age все равно надо установить в инициализаторе



public class Person

{

    public Person(string name)

    {

        Name = name;

    }

    public required string Name { get; set; }

    public required int Age { get; set; } = 22;

}
```

конструктор записывает `Name`, а `Age` имеет значение 22 при объявлении, но вызов `new Person("Bob")` без инициализатора объекта не проходит проверку `required`. компилятор помечает такие члены атрибутом обязательности и проверяет каждую точку создания. исключение задают явно: конструктор с атрибутом `SetsRequiredMembers` считается установившим все обязательные члены, и тогда на месте вызова инициализатор объекта можно не писать. без этого атрибута, как в примере, инициализатор обязателен.

### специальное поле field

специальное поле `field` генерирует компилятор. внутри свойства оно обозначает хранилище значения этого свойства, и отдельное поле в исходнике объявлять не нужно.

```c#


Person person = new Person() {Name = "Tom"};

// првоеряем работу field

Console.WriteLine(person.Name);  // Tom

person.Name = "Tomas";

Console.WriteLine(person.Name);  // Tomas

 

class Person

{

    public required string Name

    {

        get

        {

            return field;    // возвращаем значение свойства

        }

        set

        {

            field = value;   // устанавливаем новое значение свойства

        }

    }

}
```

геттер возвращает `field`, сеттер записывает в `field` параметр `value`. для клиентского кода это по-прежнему свойство `Name`. слово `field` здесь контекстное: оно имеет особый смысл внутри аксессоров свойства.

при чтении кода возможна путаница, если у типа уже есть свой член, поле или переменная, с именем `field`. риск выше при переносе проекта на c# 14 с более ранней версии языка, где идентификатор `field` был обычным именем. тогда `@field` или `this.field` снимают неоднозначность между служебным словом `field` и идентификатором. член `field` можно и переименовать, чтобы имя хранилища и имя аксессорного поля не совпадали.
