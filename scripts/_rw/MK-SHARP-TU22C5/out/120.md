### методы parse и tryparse

у примитивных числовых типов и у ряда других типов есть два метода разбора строки: `Parse()` и `TryParse()`. оба переводят текстовое представление в значение этого типа. различие в обработке ошибки: `Parse` сообщает о ней исключением, `TryParse` сообщает логическим результатом.

`Parse()` принимает строку и возвращает значение текущего типа. для целых и дробных типов вызов выглядит так:

```c#


int a = int.Parse("10");

double b = double.Parse("23,56");

decimal c = decimal.Parse("12,45");

byte d = byte.Parse("4");

Console.WriteLine($"a={a}  b={b}  c={c}  d={d}");
```

разбор дробных чисел зависит от текущей культуры потока, `CultureInfo.CurrentCulture`. в культуре, где десятичный разделитель это запятая, строка "23,56" читается как 23 целых и 56 сотых. точка в роли десятичного разделителя в такой культуре не принимается, и `double.Parse` завершается исключением `FormatException`. в культуре, где десятичный разделитель это точка, запятая на том же месте тоже приводит к ошибке разбора. поэтому один и тот же литерал нельзя переносить между локалями, не зафиксировав формат.

разделитель задаётся явно через `NumberFormatInfo` и его свойство `NumberDecimalSeparator`. `NumberFormatInfo` реализует `IFormatProvider`. конструктор без аргументов создаёт формат инвариантной культуры, а присваивание `NumberDecimalSeparator` фиксирует десятичный разделитель. в примере это точка, поэтому строка "23.56" разбирается одинаково при любой культуре потока. объект передаётся вторым аргументом `Parse`:

```c#


using System.Globalization;



IFormatProvider formatter = new NumberFormatInfo { NumberDecimalSeparator = "." };

double number = double.Parse("23.56", formatter);

Console.WriteLine(number);   // 23,56
```

здесь десятичным разделителем назначена точка, и строка "23.56" разбирается независимо от того, какая культура у потока. комментарий вывода `23,56` относится уже к печати: `Console.WriteLine` форматирует `double` по текущей культуре, и в русскоязычной локали та же величина снова показывается с запятой.

`Parse` по-прежнему выбрасывает `FormatException`, если в строке оказываются символы, не входящие в запись числа, например буквы. для ввода, который может быть некорректным, подходит `TryParse()`. метод пытается выполнить то же преобразование. при успехе он возвращает `true` и записывает значение в выходной параметр. при неудаче возвращает `false`:

```c#


Console.WriteLine("Введите строку:");

string? input = Console.ReadLine();



bool result = int.TryParse(input, out var number);

if (result == true)

	Console.WriteLine($"Преобразование прошло успешно. Число: {number}");

else

	Console.WriteLine("Преобразование завершилось неудачно");
```

неудачный разбор исключения не порождает. `TryParse` возвращает `false`, а переменная `number` получает значение по умолчанию для целевого типа. для `int` это 0. проверять нужно именно логический результат: ноль может быть и успешным разбором строки "0".

### convert

класс `Convert` задаёт второй путь преобразования значений, уже не только из строки. у него набор статических методов, по одному на целевой тип:

- `ToBoolean(value)`
- `ToByte(value)`
- `ToChar(value)`
- `ToDateTime(value)`
- `ToDecimal(value)`
- `ToDouble(value)`
- `ToInt16(value)`
- `ToInt32(value)`
- `ToInt64(value)`
- `ToSByte(value)`
- `ToSingle(value)`
- `ToUInt16(value)`
- `ToUInt32(value)`
- `ToUInt64(value)`

аргументом может быть значение любого поддерживаемого примитивного типа, строка для этого не обязательна. преобразование `true` в `double` даёт 1, `false` даёт 0: логическое значение отображается на числа соглашением `Convert`, а не разбором текста.

```c#


int n = Convert.ToInt32("23");

bool b = true;

double d = Convert.ToDouble(b);

Console.WriteLine($"n={n}  d={d}");
```

если преобразовать значение в целевой тип нельзя из-за формата строки, метод выбрасывает `FormatException`, как и `Parse`. выход за диапазон целевого типа, например при переносе слишком большого числа в `byte`, даёт `OverflowException`.
