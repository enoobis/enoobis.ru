преобразования объектов простых типов уже разобраны. здесь рассматривается преобразование объектов классов. пусть задана следующая иерархия:

```c#


class Person

{

	public string Name { get; set; }

	public Person(string name)

	{

		Name = name;

	}

	public void Print()

	{

		Console.WriteLine($"Person {Name}");

	}

}



class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company) : base(name)

	{

		Company = company;

	}

}



class Client : Person

{

	public string Bank { get; set; }

	public Client(string name, string bank) : base(name)

	{

		Bank = bank;

	}

}
```

в этой иерархии прослеживается цепь наследования: `Object` (все классы неявно наследуются от типа `Object`) -> `Person` -> `Employee`|`Client`.

![иерархия наследования в языке c#](/uploads/course-lectures/02e17a5eb95aac79bfee8d0c6fe25639c3fd6ff5.png)

в этой иерархии базовые типы находятся вверху, а производные типы внизу.

### восходящие преобразования. upcasting

объект производного типа, который находится внизу иерархии, одновременно представляет и базовый тип. объект `Employee` является объектом класса `Person`: каждый сотрудник является человеком. поэтому допустима такая запись:

```c#


Employee employee = new Employee("Tom", "Microsoft");

Person person = employee;   // преобразование от Employee к Person



Console.WriteLine(person.Name);
```

переменной `person` типа `Person` присваивается ссылка на объект `Employee`. чтобы сохранить ссылку на объект одного класса в переменную другого класса, выполняется преобразование типов, здесь от `Employee` к `Person`. поскольку `Employee` наследуется от `Person`, преобразование неявное и восходящее: к типу, который находится выше в иерархии, то есть к базовому классу. для ссылочного типа такое преобразование не создаёт новый объект и не упаковывает значение. упаковка относится к значимым типам. обе переменные после присваивания обозначают один и тот же объект в памяти.

в итоге переменные `employee` и `person` указывают на один и тот же объект, но через переменную `person` доступна только та часть, которая представляет функционал типа `Person`. статический тип ссылки ограничивает набор видимых членов. динамический тип объекта остаётся `Employee`, поэтому виртуальный вызов через ссылку `Person` попадёт в переопределение `Employee`, если оно есть.

![преобразование типов в c#](/uploads/course-lectures/672356057385dd2d1987702c94bc228aef7926a4.png)

так же производятся и другие восходящие преобразования:

```c#


Person bob = new Client("Bob", "ContosoBank");   // преобразование от Client к Person
```

переменная `bob` типа `Person` хранит ссылку на объект `Client`, поэтому выполняется восходящее неявное преобразование от производного класса `Client` к базовому типу `Person`.

восходящее неявное преобразование происходит и в следующем случае:

```c#


object person1 = new Employee("Tom", "Microsoft");	// от Employee к object

object person2 = new Client("Bob", "ContosoBank");	// от Client к object

object person3 = new Person("Sam");					// от Person к object
```

тип `object` является базовым для всех остальных типов, поэтому преобразование к нему выполняется автоматически. отдельного оператора приведения для этого не требуется: отношение наследования уже задаёт неявное преобразование вверх по иерархии.

### нисходящие преобразования. downcasting

помимо восходящих преобразований от производного типа к базовому есть нисходящие преобразования, downcasting, от базового типа к производному. в следующем коде переменная `person` хранит ссылку на объект `Employee`:

```c#


Employee employee = new Employee("Tom", "Microsoft");

Person person = employee;   // преобразование от Employee к Person
```

функционал типа `Employee` через переменную типа `Person` сам по себе недоступен: нисходящее преобразование автоматически не выполняется. объект `Person` может и не быть сотрудником предприятия, то есть объектом `Employee`. для нисходящего преобразования нужно явное приведение: в скобках указывается тип, к которому выполняется преобразование. компилятор разрешает такое приведение, если типы лежат в одной иерархии. проверку фактического типа выполняет среда во время выполнения. если динамический тип не совместим с запрошенным, возникает исключение `InvalidCastException`.

```c#


Employee employee1 = new Employee("Tom", "Microsoft");

Person person = employee1;   // преобразование от Employee к Person



//Employee employee2 = person;    // так нельзя, нужно явное преобразование

Employee employee2 = (Employee)person;  // преобразование от Person к Employee
```

несколько примеров преобразований:

```c#


// Объект Employee также представляет тип object

object obj = new Employee("Bill", "Microsoft");



// чтобы обратиться к возможностям типа Employee, приводим объект к типу Employee

Employee employee = (Employee) obj;



// объект Client также представляет тип Person

Person person = new Client("Sam", "ContosoBank");

// преобразование от типа Person к Client

Client client = (Client)person;
```

в первом случае переменной `obj` присвоена ссылка на объект `Employee`, поэтому объект `obj` можно преобразовать к любому типу, который располагается в иерархии между `object` и `Employee`.

если нужно обратиться к отдельным свойствам или методам объекта, преобразованный объект необязательно сохранять в переменной. приведение можно записать прямо в выражении:

```c#


// Объект Employee также представляет тип object

object obj = new Employee("Bill", "Microsoft");



// преобразование к типу Person для вызова метода Print

((Person)obj).Print();

// либо так

// ((Employee)obj).Print();



// преобразование к типу Employee, чтобы получить свойство Company

string company = ((Employee)obj).Company;
```

при подобных преобразованиях нужна осторожность. следующий фрагмент показывает несовместимое приведение:

```c#


// Объект Employee также представляет тип object

object obj = new Employee("Bill", "Microsoft");



// преобразование к типу Client, чтобы получить свойство Bank

string bank = ((Client)obj).Bank;
```

здесь возникает ошибка: переменная `obj` хранит ссылку на объект `Employee`. этот объект является также объектом типов `object` и `Person`, поэтому преобразование к этим типам допустимо. к типу `Client` его преобразовать нельзя. `Employee` и `Client` лежат на соседних ветвях одного базового класса. отношения предок-потомок между ними нет, поэтому приведение отвергается.

другой пример:

```c#


Employee employee1 = new Person("Tom");	// ! Ошибка



Person person = new Person("Bob");

Employee employee2 = (Employee) person;	// ! Ошибка
```

здесь объект типа `Person` преобразуется к типу `Employee`, тогда как объект `Person` объектом `Employee` не является. в первой строке ошибка видна уже компилятору: неявного преобразования от `Person` к `Employee` нет. в последней строке visual studio ошибку не подсказывает, строка нормально компилируется, но во время выполнения программа получает ошибку, `InvalidCastException`. в этом и состоит риск явных преобразований: статическая проверка подтверждает лишь правдоподобие приведения внутри иерархии, а фактический тип объекта известен только при выполнении. в таких ситуациях нужна осторожность.

существует ряд способов избежать подобных ошибок преобразования.

### способы преобразований

первый способ использует ключевое слово `as`. программа пытается преобразовать выражение к определённому типу и не выбрасывает исключение. при неудачном преобразовании результат содержит `null`:

```c#


Person person = new Person("Tom");

Employee? employee = person as Employee;

if (employee == null)

{

    Console.WriteLine("Преобразование прошло неудачно");

}

else

{

    Console.WriteLine(employee.Company);

}
```

переменная `employee` определяется здесь как `Employee?`: после названия типа стоит вопросительный знак. переменная может хранить как `null`, так и значение `Employee`. тип с `?` необходим потому, что неудача `as` кодируется именно `null`, а в nullable-контексте обычная ссылка `Employee` пустое значение не принимает.

второй способ проверяет допустимость преобразования ключевым словом `is`:

```c#
значение is тип
```

если значение слева от оператора представляет тип, указанный справа, оператор `is` возвращает `true`, иначе возвращается `false`. проверка смотрит динамический тип объекта и по иерархии: экземпляр производного класса успешно проходит проверку на базовый тип.

оператор `is` умеет заодно преобразовать значение к типу, если значение этот тип представляет:

```c#


Person person = new Person("Tom");

if (person is Employee employee)

{

    Console.WriteLine(employee.Company);

}

else

{

    Console.WriteLine("Преобразование не допустимо");

}
```

выражение `if (person is Employee employee)` проверяет, является ли переменная `person` объектом типа `Employee`. если является, значение `person` преобразуется к типу `Employee`, и преобразованное значение сохраняется в переменную `employee`. далее в блоке `if` объект `employee` используется как значение типа `Employee`. переменная шаблона доступна в ветке, где проверка истинна.

если `person` не является объектом `Employee`, как в данном фрагменте, проверка возвращает `false`, и преобразование не выполняется.

оператор `is` применяется и без преобразования, когда нужно только проверить соответствие типу:

```c#


Person person = new Person("Tom");

if (person is Employee)

{

    Console.WriteLine("Представляет тип Employee");

}

else

{

    Console.WriteLine("НЕ является объектом типа Employee");

}
```
