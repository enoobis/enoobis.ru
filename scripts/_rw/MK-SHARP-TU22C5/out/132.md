задача продолжения, continuation task, планируется по завершении другой задачи. одной задаче сопоставляют несколько продолжений, ограничивают запуск её конечным статусом и передают в следующую задачу результат или исключение. продолжение само является объектом `Task`: его ожидают, отменяют и продолжают дальше. в курсе эта конструкция сопоставлена с обратным вызовом, потому что момент запуска привязан к завершению предыдущей операции.

```c#


Task task1 = new Task(() =>

{

    Console.WriteLine($"Id задачи: {Task.CurrentId}");

});



// задача продолжения - task2 выполняется после task1

Task task2 = task1.ContinueWith(PrintTask);



task1.Start();



// ждем окончания второй задачи

task2.Wait();

Console.WriteLine("Конец метода Main");



 

void PrintTask(Task t)

{

    Console.WriteLine($"Id задачи: {Task.CurrentId}");

    Console.WriteLine($"Id предыдущей задачи: {t.Id}");

    Thread.Sleep(3000);

}
```

первая задача задана лямбдой и печатает свой идентификатор. вторая создаётся методом **ContinueWith**. в показанной перегрузке аргумент имеет тип `Action<Task>`: метод `PrintTask` принимает параметр типа `Task`. через этот параметр читаются свойства предшественника, в примере это `Id`.

после завершения `task1` планировщик ставит `task2` в очередь. вывод программы:

```consoletext


Id задачи: 1

Id задачи: 2

Id предыдущей задачи: 1

Конец метода Main
```

`ContinueWith` без `TaskContinuationOptions` ставит продолжение при любом конечном статусе предшественника: успешном завершении, сбое и отмене. отбор по статусу задаётся флагами того же перечисления, среди них `OnlyOnRanToCompletion`, `OnlyOnFaulted` и `NotOnCanceled`.

в продолжение передаётся и конкретный результат предшественника:

```c#


Task<int> sumTask = new Task<int>(() => Sum(4, 5));



// задача продолжения

Task printTask = sumTask.ContinueWith(task => PrintResult(task.Result));



sumTask.Start();



// ждем окончания второй задачи

printTask.Wait();

Console.WriteLine("Конец метода Main");



int Sum(int a, int b) => a + b;

void PrintResult(int sum) => Console.WriteLine($"Sum: {sum}");
```

`sumTask` выполняет `Sum` и возвращает `int`. `printTask` является продолжением, запускается после `sumTask` и получает результат. вызов:

```c#
Task printTask = sumTask.ContinueWith(task => PrintResult(task.Result));
```

параметр `task` в лямбде является предшественником `sumTask`, из него берётся `Result`. к моменту тела продолжения предшественник уже завершён, поэтому чтение `Result` не ждёт ещё не выполненную работу. если предшественник завершился сбоем, `Result` выбрасывает `AggregateException`.

так собирается цепочка задач, каждая из которых ждёт предыдущую:

```c#


Task task1 = new Task(() => Console.WriteLine($"Current Task: {Task.CurrentId}"));



// задача продолжения

Task task2 = task1.ContinueWith(t =>

    Console.WriteLine($"Current Task: {Task.CurrentId}  Previous Task: {t.Id}"));



Task task3 = task2.ContinueWith(t =>

    Console.WriteLine($"Current Task: {Task.CurrentId}  Previous Task: {t.Id}"));





Task task4 = task3.ContinueWith(t =>

    Console.WriteLine($"Current Task: {Task.CurrentId}  Previous Task: {t.Id}"));



task1.Start();



task4.Wait();   //  ждем завершения последней задачи

Console.WriteLine("Конец метода Main");
```

друг за другом исполняются `task1`, `task2`, `task3` и `task4`. вывод программы:

```consoletext


Current Task: 1

Current Task: 2  Previous Task: 1

Current Task: 3  Previous Task: 2

Current Task: 4  Previous Task: 3

Конец метода Main
```

`task4.Wait()` ждёт последнюю задачу. каждая следующая поставлена продолжением предыдущей, поэтому завершение `task4` означает, что вся цепочка уже выполнилась. номера 1, 2, 3, 4 в выводе совпадают с порядком исполнения: идентификатор выдаётся при первом чтении `Id` или `CurrentId`, а каждое тело начинает с такого чтения.
