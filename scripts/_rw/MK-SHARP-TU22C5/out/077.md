### интерфейсы как ограничения обобщений

интерфейсы могут выступать ограничениями обобщений. в одной секции `where` классовое ограничение не больше одного. интерфейсных ограничений может быть несколько: аргумент типа обязан быть подтипом каждого из них.

исходные интерфейсы и класс, который их реализует:

```c#


interface IMessage

{

    string Text { get; } // текст сообщения

}

interface IPrintable

{

    void Print();

}

class Message : IMessage, IPrintable

{

    public string Text { get; }

    public Message(string text) => Text = text;



    public void Print() => Console.WriteLine(Text);

}
```

интерфейс `IMessage` представляет сообщение и определяет свойство `Text` для хранения текста сообщения. интерфейс `IPrintable` определяет метод `Print` для условной печати сообщения. класс сообщения `Message` реализует эти интерфейсы.

перечисленные интерфейсы используются как ограничения обобщённого класса:

```c#


class Messenger<T> where T: IMessage, IPrintable

{

    public void Send(T message)

    {

        Console.WriteLine("Отправка сообщения:");

        message.Print();

    }

}
```

класс условного мессенджера параметризован типом `T`, который реализует сразу два интерфейса, `IMessage` и `IPrintable`. внутри `Send` доступны только члены этих контрактов: конкретный тип компилятору неизвестен, известны ограничения. класс `Message`, определённый выше, реализует оба интерфейса, поэтому им типизируют объекты `Messenger`:

```c#


// создаем мессенджер

var telegram = new Messenger<Message>();

// создаем сообщение

var message = new Message("Hello World!");

// отправляем сообщение

telegram.Send(message);
```

параметр `T` может представлять и интерфейс, который наследует оба интерфейса. такой тип является подтипом каждого ограничения:

```c#


interface IPrintableMessage: IPrintable, IMessage { }

class PrintableMessage : IPrintableMessage

{

    public string Text { get; }

    public PrintableMessage(string text) => Text = text;

    public void Print() => Console.WriteLine(Text);

}
```

тогда объекты `Messenger` типизируют типом `IPrintableMessage`:

```c#


var telegram = new Messenger<IPrintableMessage>();

var message = new PrintableMessage("Hello World!");

telegram.Send(message);
```

### обобщенные интерфейсы

как и классы, интерфейсы могут быть обобщёнными:

```c#


interface IUser<T>

{

    T Id { get; }

}

class User<T> : IUser<T>

{

    public T Id { get; }

    public User(T id) => Id = id;

}
```

интерфейс `IUser` типизирован параметром `T`, и при реализации тот же параметр используется в классе `User`. свойство `Id` имеет тип `T`, поэтому идентификатор задают разными типами.

```c#


IUser<int> user1 = new User<int>(6789);

Console.WriteLine(user1.Id);    // 6789



IUser<string> user2 = new User<string>("12345");

Console.WriteLine(user2.Id);    // 12345
```

две реализации закрывают параметр по-разному: одна использует тип `int`, другая тип `string`. закрытые типы `IUser<int>` и `IUser<string>` между собой не совместимы:

```c#


class IntUser : IUser<int>

{

	public int Id { get; }

    public IntUser(int id) => Id = id;

}
```

при реализации интерфейса можно явно указать, какой тип будет использован для параметра `T`, и не оставлять параметр открытым:

```c#


IUser<int> user1 = new IntUser(2345);

Console.WriteLine(user1.Id);    // 2345



IntUser user2 = new IntUser(9840);

Console.WriteLine(user2.Id);    // 9840
```
