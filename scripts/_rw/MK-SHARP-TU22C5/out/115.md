структура `DateTime` представляет дату и время от 00:00:00 1 января 0001 года до 23:59:59 31 декабря 9999 года. единица хранения: тик, 100 наносекунд. вместе с числом тиков значение несёт поле `DateTimeKind` со значениями `Unspecified`, `Utc` и `Local`: одни и те же компоненты календаря могут обозначать локальное время, время utc или время без указанной зоны. арифметика `DateTime` сдвигает тики и не применяет правила часового пояса и перехода на летнее время, пока явно не вызваны методы преобразования зоны.

новый экземпляр создаётся конструктором. конструктор без параметров даёт начальную дату, она совпадает с `DateTime.MinValue`:

```c#


DateTime dateTime = new DateTime();

Console.WriteLine(dateTime); // 01.01.0001 0:00:00
```

то же минимальное значение доступно как статическое поле:

```c#


Console.WriteLine(DateTime.MinValue);
```

конкретная дата задаётся конструктором с компонентами календаря. перегрузка с тремя аргументами принимает год, месяц и день. время устанавливается в 00:00:00, `Kind` остаётся `Unspecified`:

```c#


DateTime date1 = new DateTime(2015, 7, 20); // год - месяц - день

Console.WriteLine(date1); // 20.07.2015 0:00:00
```

время задаётся перегрузкой с шестью аргументами: год, месяц, день, час, минута, секунда. аргумент вне допустимого диапазона (месяц 13, час 25, 31 февраля невисокосного года) приводит к `ArgumentOutOfRangeException` в конструкторе. конструктор не нормализует такие компоненты в соседний месяц или сутки.

```c#


DateTime date1 = new DateTime(2015, 7, 20, 18, 30, 25); // год - месяц - день - час - минута - секунда

Console.WriteLine(date1); // 20.07.2015 18:30:25
```

текущие дата и время читаются из статических свойств:

```c#


Console.WriteLine(DateTime.Now);

Console.WriteLine(DateTime.UtcNow);

Console.WriteLine(DateTime.Today);
```

консольный вывод зависит от момента запуска и от часового пояса машины. в исходном примере он такой:

```consoletext


20.07.2015 11:43:33

20.07.2015 8:43:33

20.07.2015 0:00:00
```

`DateTime.Now` возвращает локальные дату и время с `Kind = Local`. `DateTime.UtcNow` возвращает то же мгновение в шкале utc с `Kind = Utc`. utc это всемирное координированное время. в исходном тексте шкала названа временем по гринвичу (gmt): для гражданского показа часов gmt и utc совпадают, при этом `DateTime` не хранит високосные секунды utc. `DateTime.Today` возвращает текущую локальную дату со временем 00:00:00.

по умолчанию календарные вычисления `DateTime` ведутся по пролептическому григорианскому календарю: правила календаря распространены и на даты до григорианской реформы. день недели для 5 октября 1582 года запрашивается так:

```c#


DateTime someDate = new DateTime(1582, 10, 5);

Console.WriteLine(someDate.DayOfWeek);
```

консоль выводит `Tuesday`, то есть вторник. исторически переход с юлианского календаря на григорианский впервые произошёл в октябре 1582 года: после 4 октября (четверг) по юлианскому календарю следующим днём стало 15 октября (пятница) по григорианскому. десять календарных дат были пропущены, после 4 октября шло 15 октября. дата перехода зависит от страны: в ряде католических стран это октябрь 1582 года, в других странах реформа проведена позже. `DateTime` пропуск дат не воспроизводит. для него 5 октября 1582 года существует, и день недели вычислен по пролептическому григорианскому календарю. на расчётах в современном диапазоне это не сказывается. для дат xvi века и раньше календарь выбирается явно: типы, производные от `System.Globalization.Calendar`, в том числе `JulianCalendar`.

### операции с datetime

основные операции над `DateTime`: сложение и вычитание интервалов. структура неизменяема. методы не меняют исходное значение и возвращают новый экземпляр. к дате добавляют или вычитают дни, часы, месяцы.

методы добавления:

- `Add(TimeSpan value)`: добавляет к дате значение `TimeSpan`
- `AddDays(double value)`: добавляет дни. дробная часть переводится в часы, минуты и доли секунды
- `AddHours(double value)`: добавляет часы
- `AddMinutes(double value)`: добавляет минуты
- `AddMonths(int value)`: добавляет месяцы. день месяца сохраняется. если в целевом месяце такого дня нет, берётся последний день этого месяца. так 31 января плюс один месяц даёт 28 или 29 февраля
- `AddYears(int value)`: добавляет годы. 29 февраля при попадании в невисокосный год сдвигается на 28 февраля

пример: к дате прибавляются 3 часа.

```c#


DateTime date1 = new DateTime(2015, 7, 20, 18, 30, 25); // 20.07.2015 18:30:25

Console.WriteLine(date1.AddHours(3)); // 20.07.2015 21:30:25
```

разность двух дат вычисляет метод `Subtract(DateTime date)`:

```c#


DateTime date1 = new DateTime(2015, 7, 20, 18, 30, 25); // 20.07.2015 18:30:25

DateTime date2 = new DateTime(2015, 7, 20, 15, 30, 25); // 20.07.2015 15:30:25

Console.WriteLine(date1.Subtract(date2)); // 03:00:00
```

даты различаются на три часа, результат имеет тип `TimeSpan` и при выводе выглядит как "03:00:00". перегрузка `Subtract(TimeSpan)` и операторы `+` и `-` задают ту же арифметику над тиками.

отдельных методов для вычитания дней, часов и остальных компонентов у `DateTime` нет. отрицательный аргумент `AddDays`, `AddHours` и остальных методов добавления смещает значение назад на ту же величину.

```c#


// вычтем три часа

DateTime date1 = new DateTime(2015, 7, 20, 18, 30, 25);  // 20.07.2015 18:30:25

Console.WriteLine(date1.AddHours(-3)); // 20.07.2015 15:30:25
```

помимо арифметики есть методы форматирования. текст зависит от текущей культуры потока (`CultureInfo.CurrentCulture`): из неё берутся названия месяцев, порядок компонентов и разделители. числа в примере соответствуют русскоязычной локали и смещению utc+3, как в исходном выводе.

```c#


DateTime date1 = new DateTime(2015, 7, 20, 18, 30, 25);

Console.WriteLine(date1.ToLocalTime()); // 20.07.2015 21:30:25

Console.WriteLine(date1.ToUniversalTime()); // 20.07.2015 15:30:25

Console.WriteLine(date1.ToLongDateString()); // 20 июля 2015 г.

Console.WriteLine(date1.ToShortDateString()); // 20.07.2015

Console.WriteLine(date1.ToLongTimeString()); // 18:30:25

Console.WriteLine(date1.ToShortTimeString()); // 18:30
```

`ToLocalTime()` переводит значение utc в локальное время и прибавляет смещение относительно utc. `ToUniversalTime()` переводит локальное время в utc и вычитает это смещение. если `Kind` равен `Unspecified`, `ToLocalTime` считает значение временем utc, а `ToUniversalTime` считает его локальным. поэтому одно и то же показание 18:30:25 в примере сдвигается в обе стороны: плюс три часа и минус три часа при смещении utc+3. если `Kind` уже совпадает с целевой шкалой, повторный вызов сохраняет показания часов и выставляет соответствующий `Kind`. остальные методы примера форматируют значение: длинная и короткая дата, длинное и короткое время. их шаблоны задаёт культура, они совпадают со стандартными описателями `D`, `d`, `T` и `t`.
