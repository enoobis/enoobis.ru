внешнюю библиотеку не обязательно собирать в том же решении. ранее написанный код подключается к проекту готовым пакетом. для управления такими пакетами microsoft предоставляет менеджер пакетов **nuget**.

физически пакет nuget является одним архивным файлом с расширением .nupkg. в нём лежит скомпилированный код в виде библиотек dll и остальные файлы, которые использует программа, а также описание: номер версии и сопроводительные сведения. формат .nupkg устроен как zip-архив. сборки разложены по каталогам целевых платформ, а идентификатор, версия и зависимости записаны в манифесте пакета.

чтобы пакеты можно было публиковать и находить, microsoft поддерживает глобальный репозиторий **nuget.org**. автор помещает библиотеку в этот репозиторий в виде пакета nuget, другой проект скачивает пакет и ссылается на него. ниже показаны установка пакета и обращение к его коду. способов установки несколько, здесь разобраны .net cli и visual studio. в обоих случаях в проект попадает ссылка на конкретную версию, а загрузку пакета и транзитивных зависимостей выполняет восстановление nuget.

### установка nuget-пакетов с помощью .net cli

если приложение собирается непосредственно через .net cli, без среды разработки вроде visual studio, достаточно инструментов, входящих в .net sdk.

проект консольного приложения создаётся командой:

```bash
dotnet new console
```

в качестве примера берётся распространённый пакет `Newtonsoft.Json`, предназначенный для работы с json. в каталоге проекта выполняется команда:

```bash
dotnet add package Newtonsoft.Json
```

после `dotnet add package` указывается имя пакета. если номер версии не задан отдельно, выбирается последняя устойчивая версия, и ссылка на неё дописывается в файл проекта. при сборке nuget восстанавливает пакет в глобальный кэш и передаёт компилятору соответствующие сборки.

![установка пакета nuget в проект на c# с помощью .net cli](/uploads/course-lectures/c3ac22a0c873278054ac226780e13ff12f8bea7d.png)

после этого в файле конфигурации проекта с расширением csproj появляется элемент `PackageReference`. он и представляет добавленный пакет:

```xml


<ItemGroup>

	<PackageReference Include="Newtonsoft.Json" Version="13.0.1" />

</ItemGroup>
```

атрибут `Include` задаёт имя пакета, включаемого в проект, атрибут `Version` фиксирует версию. в проекте sdk-стиля `PackageReference` является единицей зависимости: по нему строится граф версий.

пакет подключён, далее его типы используются в программе:

```c#


using Newtonsoft.Json;  // подключаем пространство имен из пакета Newtonsoft.Json



Person tom = new Person("Tom", 38);

// сериализуем объект tom в код json

string json = JsonConvert.SerializeObject(tom);

Console.WriteLine(json);





class Person

{

    public string Name {get;set;}

    public int Age {get;set;}

    public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

вызов статического метода `JsonConvert.SerializeObject(tom)` сериализует объект `tom` в текст json. метод читает открытые свойства объекта и записывает их в объект json, после чего полученный текст выводится на консоль.

проект запускается командой `dotnet run`, результат программы таков:

```bash
{"Name":"Tom","Age":38}
```

пакет nuget установлен в проект, и программа вызывает его код. если впоследствии пакет не нужен, его удаляют командой:

```bash
dotnet remove package Newtonsoft.Json
```

после `dotnet remove package` указывается имя удаляемого пакета. соответствующий элемент `PackageReference` исчезает из файла проекта.

### установка пакета в visual studio

visual studio предоставляет отдельный интерфейс для пакетов nuget. в простейший проект консольного приложения добавляется тот же пакет `Newtonsoft.Json`. правый щелчок по имени проекта открывает контекстное меню, в нём выбирается пункт **Manage NuGet Packages...**:

![добавление nuget пакетов в проект на c# в visual studio](/uploads/course-lectures/baa25c9f1a0adec320d784df00139559df32c7a0.png)

открывается встроенный менеджер пакетов nuget:

![добавление nuget пакетов в проект в visual studio](/uploads/course-lectures/57c155d3351e6e9fe68b91a62bc81247a75568f2.png)

для поиска имя пакета вводится в поле поиска, после чего список обновляется. обычно первым в списке оказывается нужный пакет. в правой части окна выводятся сведения о нём: описание, доступные версии, зависимости.

установка запускается кнопкой `Install`. затем может появиться дополнительное окно со списком пакетов, которые будут установлены фактически, включая зависимости выбранного пакета:

![установка nuget пакетов в проект на c# в visual studio](/uploads/course-lectures/8d50543b03375739e5740f3db10b789b72054468.png)

после установки в структуре проекта появляется узел `Packages` с установленным пакетом, а в файл конфигурации проекта вносится запись `PackageReference`:

![установка nuget пакета в проект на c# в visual studio](/uploads/course-lectures/38c91ab5dcb35e4aacdb3168281050b7c2780665.png)

функциональность пакета после этого доступна в программе так же, как при установке через .net cli.

другой способ добавления даёт консоль **Package Manager Console**. в меню visual studio выбирается пункт **Tools -> NuGet Package Manager -> Package Manager Console**. в открывшемся внизу окне **Package Manager Console** вводится команда:

```c#
Install-Package Newtonsoft.Json
```

после `Install-Package` указывается имя устанавливаемого пакета. консоль выполняет ту же операцию, что и `dotnet add package`: в проект добавляется ссылка на пакет, а файл проекта получает `PackageReference`.

![install-package и установка пакета nuget в c# в visual studio](/uploads/course-lectures/fe5ebd969b26f480204cf23f88cf27edf0dd438f.png)
