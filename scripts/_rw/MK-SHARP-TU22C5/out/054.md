все классы в .net, в том числе классы, определяемые в программе, а также базовые типы вроде `System.Int32`, неявно входят в иерархию с корнем `Object`. даже если `Object` не указан в качестве базового класса, он всё равно стоит на вершине иерархии наследования. поэтому любой тип располагает методами, определёнными в `System.Object`. у типов-значений цепочка чуть длиннее: `System.Int32` является структурой и наследует `System.ValueType`, а `ValueType` уже наследует `Object`. ниже рассматриваются методы, которые эта иерархия делает общими для всех объектов.

### tostring

метод `ToString` служит для получения строкового представления данного объекта. для базовых типов выводится их строковое значение:

```c#


int i = 5;

Console.WriteLine(i.ToString()); // выведет число 5



double d = 3.5;

Console.WriteLine(d.ToString()); // выведет число 3,5
```

для классов реализация по умолчанию выводит полное название класса с указанием пространства имён, в котором класс определён. метод можно переопределить:

```c#


Person person = new Person { Name = "Tom" };

Console.WriteLine(person.ToString()); // выведет название класса Person



Clock clock = new Clock { Hours = 15, Minutes = 34, Seconds = 53 };

Console.WriteLine(clock.ToString()); // выведет 15:34:53



class Clock

{

    public int Hours { get; set; }

    public int Minutes { get; set; }

    public int Seconds { get; set; }

    public override string ToString()

    {

        return $"{Hours}:{Minutes}:{Seconds}";

    }

}

class Person

{

    public string Name { get; set; } = "";

}
```

для переопределения метода `ToString()` в классе `Clock`, который представляет часы, используется ключевое слово **override**, как и при обычном переопределении виртуальных или абстрактных методов. метод `ToString()` выводит в строке значения свойств `Hours`, `Minutes`, `Seconds`.

класс `Person` не переопределяет метод `ToString`, поэтому для этого класса срабатывает стандартная реализация, которая выводит название класса.

обе реализации можно совместить в одном методе:

```c#


Person tom = new Person { Name = "Tom" };

Console.WriteLine(tom.ToString()); // Tom



Person undefined = new Person();

Console.WriteLine(undefined.ToString()); // Person



class Person

{

    public string Name { get; set; } = "";



    public override string? ToString()

    {

        if (string.IsNullOrEmpty(Name))

            return base.ToString();

        return Name;

    }

}
```

если имя, свойство `Name`, не имеет значения и представляет пустую строку, возвращается базовая реализация, то есть название класса. базовая реализация возвращает не просто строку, а объект `string?`: это может быть строка `string` либо значение `null`, которое указывает на отсутствие значения. в качестве возвращаемого типа метода допустимы и `string`, и `string?`. аннотация `string?` относится к проверке ссылок на null во время компиляции и не создаёт отдельного типа во время выполнения: в обоих случаях значение есть либо ссылка на `System.String`, либо пустая ссылка.

если имя у объекта `Person` установлено, возвращается значение свойства `Name`. для проверки строки на наличие значения применяется метод `String.IsNullOrEmpty()`.

различные технологии на платформе .net используют метод `ToString` для своих целей. метод `Console.WriteLine()` по умолчанию выводит именно строковое представление объекта. чтобы вывести строковое представление объекта на консоль, при передаче объекта в метод `Console.WriteLine` вызывать `ToString()` явно не требуется: он вызывается неявно.

```c#


Person person = new Person { Name = "Tom" };

Console.WriteLine(person);	// Tom



Clock clock = new Clock { Hours = 15, Minutes = 34, Seconds = 53 };

Console.WriteLine(clock); // выведет 15:34:53
```

### метод `GetHashCode`

метод `GetHashCode` позволяет возвратить некоторое числовое значение, которое соответствует данному объекту, его хеш-код. по этому числу объекты сопоставляют, в частности, когда их размещают в хеш-таблицах. алгоритм генерации числа может быть любым, либо берётся реализация базового типа:

```c#


class Person

{

    public string Name { get; set; } = "";



    public override int GetHashCode()

    {

		return Name.GetHashCode();

    }

}
```

метод `GetHashCode` возвращает хеш-код значения свойства `Name`. два объекта `Person` с одним и тем же именем возвращают один и тот же хеш-код. сам алгоритм при необходимости может быть другим.

контракт, который ожидают коллекции вроде `Dictionary` и `HashSet`, такой: если `Equals` признаёт два объекта равными, их хеш-коды обязаны совпадать. обратное не требуется. одинаковый хеш-код ещё не означает равенство объектов, он только помещает их в одну корзину.

### получение типа объекта и метод `GetType`

метод `GetType` позволяет получить тип данного объекта:

```c#


Person person = new Person { Name = "Tom" };

Console.WriteLine(person.GetType());	// Person
```

этот метод возвращает объект `Type`, то есть тип объекта. `GetType()` не является виртуальным: подменить его в производном классе нельзя, тип сообщает сама среда выполнения по указателю на таблицу методов объекта.

ключевое слово **typeof** получает тип класса, и этот тип сравнивается с типом объекта. если объект представляет тип `Person`, выполняются соответствующие действия:

```c#


object person = new Person { Name = "Tom" };

if (person.GetType() == typeof(Person))

	Console.WriteLine("Это реально класс Person");
```

поскольку класс `Object` является базовым типом для всех классов, переменной типа `object` можно присвоить объект любого типа. для этой переменной метод `GetType` всё равно вернёт тот тип, на объект которого ссылается переменная. в примере это объект типа `Person`.

ту же проверку точного типа в примере выше можно записать короче оператором **is**:

```c#


object person = new Person { Name = "Tom" };

if (person is Person)

    Console.WriteLine("Это реально класс Person");
```

для объекта, который создан именно как `Person`, оба варианта дают один результат. семантика у них разная. сравнение `GetType()` с `typeof(Person)` проверяет тождество динамического типа. оператор `is` истинен и для подтипов `Person`, и для типов, реализующих интерфейс, если справа указан интерфейс.

в отличие от методов `ToString`, `Equals`, `GetHashCode` метод `GetType()` не переопределяется.

### метод equals

метод `Equals` позволяет сравнить два объекта на равенство. в качестве параметра он принимает объект для сравнения в виде типа `object` и возвращает `true`, если оба объекта равны:

```c#
public override bool Equals(object? obj) {......}
```

реализация в классе `Person`:

```c#


class Person

{

	public string Name { get; set; } = "";

    public override bool Equals(object? obj)

    {

        // если параметр метода представляет тип Person

        // то возвращаем true, если имена совпадают

        if (obj is Person person) return Name == person.Name;

        return false;

    }

    // вместе с методом Equals следует реализовать метод GetHashCode

    public override int GetHashCode() => Name.GetHashCode();

}
```

метод `Equals` принимает объект любого типа, который затем приводится к текущему классу, классу `Person`. конструкция `obj is Person person` одновременно проверяет динамический тип и, при успехе, связывает объект с переменной `person`.

если переданный объект представляет тип `Person`, возвращается результат сравнения имён двух объектов `Person`. если объект представляет другой тип, возвращается `false`.

для примера применяется простой алгоритм сравнения. при необходимости реализацию делают более сложной, например сравнивают несколько свойств, если они есть.

вместе с методом `Equals` следует реализовать метод `GetHashCode`. иначе нарушается контракт хеш-коллекций: равные по `Equals` объекты могут попасть в разные корзины и перестанут находиться.

применение метода:

```c#


var person1 = new Person { Name = "Tom" };

var person2 = new Person { Name = "Bob" };

var person3 = new Person { Name = "Tom" };



bool person1EqualsPerson2 = person1.Equals(person2);   // false

bool person1EqualsPerson3 = person1.Equals(person3);   // true



Console.WriteLine(person1EqualsPerson2);    // false

Console.WriteLine(person1EqualsPerson3);    // true
```

если сравниваются два сложных объекта, как в этом примере, используется метод `Equals`, а не стандартная операция `==`. для классов операция `==` по умолчанию сравнивает ссылки, то есть тождество объектов в памяти. переопределённый `Equals` сравнивает состояние, в примере это имя. операция `==` меняется только явной перегрузкой оператора, переопределение `Equals` её само по себе не заменяет.
