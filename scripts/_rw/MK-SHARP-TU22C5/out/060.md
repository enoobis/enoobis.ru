базовым для всех типов исключений является тип `Exception`. этот тип определяет ряд свойств, с помощью которых получается информация об исключении.

- `InnerException`: хранит информацию об исключении, которое послужило причиной текущего исключения

- `Message`: хранит сообщение об исключении, текст ошибки

- `Source`: хранит имя объекта или сборки, которое вызвало исключение

- `StackTrace`: возвращает строковое представление стека вызовов, которые привели к возникновению исключения

- `TargetSite`: возвращает метод, в котором и было вызвано исключение

`InnerException` связывает исключения в цепочку причин: внешнее исключение описывает сбой на своём уровне, внутреннее сохраняет исходную причину. `StackTrace` есть строка, собранная при проходе по стеку. `TargetSite` возвращает метод как объект отражения, `MethodBase`. `Source` хранит имя объекта или сборки, из которых исключение пришло.

обработка исключения типа `Exception`:

```c#


try

{

    int x = 5;

    int y = x / 0;

    Console.WriteLine($"Результат: {y}");

}

catch (Exception ex)

{

    Console.WriteLine($"Исключение: {ex.Message}");

    Console.WriteLine($"Метод: {ex.TargetSite}");

    Console.WriteLine($"Трассировка стека: {ex.StackTrace}");

}
```

поскольку тип `Exception` является базовым типом для всех исключений, выражение `catch (Exception ex)` обрабатывает все исключения, которые могут возникнуть.

есть и более специализированные типы исключений, предназначенные для отдельных видов сбоев. таких типов много, ниже перечислены некоторые из них:

- `DivideByZeroException`: представляет исключение, которое генерируется при делении на ноль

- `ArgumentOutOfRangeException`: генерируется, если значение аргумента находится вне диапазона допустимых значений

- `ArgumentException`: генерируется, если в метод для параметра передаётся некорректное значение

- `IndexOutOfRangeException`: генерируется, если индекс элемента массива или коллекции находится вне диапазона допустимых значений

- `InvalidCastException`: генерируется при попытке произвести недопустимые преобразования типов

- `NullReferenceException`: генерируется при попытке обращения к объекту, который равен `null` (то есть по сути не определён)

при необходимости обработка различных типов исключений разграничивается дополнительными блоками `catch`:

```c#


static void Main(string[] args)

{

	try

	{

		int[] numbers = new int[4];

		numbers[7] = 9;     // IndexOutOfRangeException



		int x = 5;

		int y = x / 0;  // DivideByZeroException

		Console.WriteLine($"Результат: {y}");

	}

	catch (DivideByZeroException)

	{

		Console.WriteLine("Возникло исключение DivideByZeroException");

	}

	catch (IndexOutOfRangeException ex)

	{

		Console.WriteLine(ex.Message);

	}

            

	Console.Read();

}
```

блоки `catch` обрабатывают исключения типов `IndexOutOfRangeException` и `DivideByZeroException`. когда в блоке `try` возникает исключение, clr ищет нужный блок `catch` для его обработки. на строке

```c#
numbers[7] = 9;
```

происходит обращение к элементу массива с индексом 7. в массиве только 4 элемента, допустимые индексы равны 0, 1, 2 и 3, поэтому возникает исключение типа `IndexOutOfRangeException`. clr находит блок `catch`, который обрабатывает данное исключение, и передаёт ему управление.

в блоке `try` есть и вторая ситуация, способная породить исключение: деление на ноль. после генерации `IndexOutOfRangeException` управление переходит в соответствующий блок `catch`, поэтому деление на ноль `int y = x / 0` не выполняется, и исключение типа `DivideByZeroException` не генерируется. из одного `try` в этот обработчик попадает только первое возникшее исключение. последующие выражения того же блока уже не исполняются.

другая ситуация:

```c#


try

{

    object obj = "you";

    int num = (int)obj;     // System.InvalidCastException

    Console.WriteLine($"Результат: {num}");

}

catch (DivideByZeroException)

{

    Console.WriteLine("Возникло исключение DivideByZeroException");

}

catch (IndexOutOfRangeException)

{

    Console.WriteLine("Возникло исключение IndexOutOfRangeException");

}
```

в блоке `try` генерируется исключение типа `InvalidCastException`: строка приводится к `int` через ссылку типа `object`, и проверка типа во время выполнения не проходит. соответствующего блока `catch` для этого исключения нет. программа аварийно завершает своё выполнение.

для `InvalidCastException` можно определить свой блок `catch`. теоретически в коде генерируются самые разные типы исключений. определять блок `catch` для каждого типа, если обработка у них однотипна, не требуется. тогда определяется блок `catch` для базового типа `Exception`:

```c#


try

{

    object obj = "you";

    int num = (int)obj;     // System.InvalidCastException

    Console.WriteLine($"Результат: {num}");

}

catch (DivideByZeroException)

{

    Console.WriteLine("Возникло исключение DivideByZeroException");

}

catch (IndexOutOfRangeException)

{

    Console.WriteLine("Возникло исключение IndexOutOfRangeException");

}

catch (Exception ex)

{

    Console.WriteLine($"Исключение: {ex.Message}");

}
```

блок `catch (Exception ex){}` обрабатывает все исключения кроме `DivideByZeroException` и `IndexOutOfRangeException`. блоки `catch` для более общих, более базовых исключений помещаются в конце, после блоков `catch` для более конкретных, специализированных типов. clr выбирает для обработки исключения первый блок `catch`, который соответствует типу сгенерированного исключения. поэтому сначала обрабатываются `DivideByZeroException` и `IndexOutOfRangeException`, и только потом `Exception`: `DivideByZeroException` и `IndexOutOfRangeException` наследуются от класса `Exception`, и более ранний общий обработчик забрал бы и их тоже.

если блок для базового типа поставить раньше блока для производного, производный блок становится недостижимым. компилятор c# такую расстановку отвергает: более специфичный `catch` после `catch` базового типа, уже покрывающего этот случай, до выполнения программы не доходит.
