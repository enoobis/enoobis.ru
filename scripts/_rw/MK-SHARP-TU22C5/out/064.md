делегат представляет собой объект, который ссылается на метод. тип делегата задаёт контракт вызова: возвращаемый тип и список параметров. экземпляр хранит цель вызова и указывает на конкретный метод, поэтому через делегат этот метод можно вызвать. в clr тип, объявленный служебным словом delegate, порождается от System.MulticastDelegate. даже когда в списке вызова один метод, объект остаётся делегатом с тем же устройством списка. для статического метода цель пуста, для метода экземпляра в делегате сохраняется ссылка на объект, у которого метод вызывается.

### определение делегатов

объявление начинается со служебного слова **delegate**, далее идут возвращаемый тип, имя делегата и параметры. пример объявления без параметров и без результата:

```c#

delegate void Message();
```

делегат Message имеет возвращаемый тип void и пустой список параметров. к нему приводится любой метод, который ничего не принимает и ничего не возвращает.

применение строится в четыре шага: объявление типа, переменная, присваивание метода, вызов.

```c#

Message mes;            // 2. Создаем переменную делегата
mes = Hello;            // 3. Присваиваем этой переменной адрес метода
mes();                  // 4. Вызываем метод

void Hello() => Console.WriteLine("Hello METANIT.COM");

delegate void Message(); // 1. Объявляем делегат
```

сначала объявляется сам тип делегата:

```c#
delegate void Message(); // 1. Объявляем делегат
```

затем объявляется переменная этого типа:

```c#
Message mes; // 2. Создаем переменную делегата
```

переменной присваивается метод Hello. метод имеет тот же возвращаемый тип и тот же список параметров, здесь пустой, поэтому группа методов преобразуется в экземпляр делегата:

```c#
mes = Hello; // 3. Присваиваем этой переменной адрес метода
```

вызов переменной передаёт управление методу, на который делегат ссылается:

```c#
mes(); // 4. Вызываем метод
```

синтаксис вызова совпадает с вызовом метода: скобки после имени переменной.

метод не обязан быть объявлен в том же классе, где стоит переменная делегата. целью может быть метод другого класса или структуры, статический или метод экземпляра.

```c#

Message message1 = Welcome.Print;
Message message2 = new Hello().Display;

message1(); // Welcome
message2(); // Привет

delegate void Message();

class Welcome
{
    public static void Print() => Console.WriteLine("Welcome");
}
class Hello
{
    public void Display() => Console.WriteLine("Привет");
}
```

message1 связывается со статическим методом Welcome.Print, и цель у этого делегата отсутствует. message2 связывается с методом экземпляра Display. объект, созданный выражением `new Hello()`, сохраняется в делегате как цель вызова, поэтому message2() выполняет Display именно у этого экземпляра. оба метода подходят делегату Message: возвращаемый тип void, параметров нет.

### место определения делегата

в программе верхнего уровня (top-level program), которую по умолчанию представляет файл Program.cs начиная с c# 10, делегат, как и другие типы, объявляется в конце файла. тот же тип можно объявить и внутри класса:

```c#

class Program
{
    delegate void Message(); // 1. Объявляем делегат
    static void Main()
    {
        Message mes;            // 2. Создаем переменную делегата
        mes = Hello;            // 3. Присваиваем этой переменной адрес метода
        mes();                  // 4. Вызываем метод

        void Hello() => Console.WriteLine("Hello METANIT.COM");
    }
}
```

либо вне класса, на уровне пространства имён:

```c#

delegate void Message(); // 1. Объявляем делегат
class Program
{
    static void Main()
    {
        Message mes;            // 2. Создаем переменную делегата
        mes = Hello;            // 3. Присваиваем этой переменной адрес метода
        mes();                  // 4. Вызываем метод

        void Hello() => Console.WriteLine("Hello METANIT.COM");
    }
}
```

от места объявления зависит область видимости имени делегата. делегат внутри класса виден как вложенный тип, делегат вне класса виден как самостоятельный тип. правила присваивания метода и вызова от этого места не меняются.

### параметры и результат делегата

делегат может принимать параметры и возвращать результат. сигнатура тогда целиком входит в тип:

```c#

Operation operation = Add;      // делегат указывает на метод Add
int result = operation(4, 5);   // фактически Add(4, 5)
Console.WriteLine(result);      // 9
    
operation = Multiply;           // теперь делегат указывает на метод Multiply
result = operation(4, 5);       // фактически Multiply(4, 5)
Console.WriteLine(result);      // 20

int Add(int x, int y) => x + y;

int Multiply(int x, int y) => x * y;

delegate int Operation(int x, int y);
```

делегат Operation возвращает int и принимает два параметра типа int. ему соответствует любой метод с тем же возвращаемым типом и тем же списком параметров. методы Add и Multiply выполняют это условие, поэтому переменной operation можно присвоить любой из них. после присваивания вызов operation идёт в тот метод, который сейчас находится в списке вызова: сначала Add, затем, после второго присваивания, Multiply. прежнее присваивание заменяется целиком, а не дополняется.

поскольку делегат принимает два параметра типа int, при вызове нужно передать значения этих параметров: `operation(4,5)`. аргументы попадают в x и y выбранного метода.

### присвоение ссылки на метод

выше метод присваивался переменной напрямую. второй способ создаёт объект делегата конструктором и передаёт в конструктор нужный метод:

```c#

Operation operation1 = Add;
Operation operation2 = new Operation(Add);

int Add(int x, int y) => x + y;

delegate int Operation(int x, int y);
```

обе формы эквивалентны. прямое присваивание является преобразованием группы методов и приводит к созданию экземпляра Operation, ссылающегося на Add. конструктор делает то же создание явно. в обоих случаях operation1 и operation2 вызывают Add.

### соответствие методов делегату

метод соответствует делегату при совпадении возвращаемого типа и всего списка параметров. в список входят не только типы, но и модификаторы **ref**, **in** и **out**: они задают способ передачи аргумента и потому входят в сигнатуру.

делегат для сравнения:

```c#
delegate void SomeDel(int a, double b);
```

следующий метод этому делегату соответствует. имена параметров роли не играют, важны позиция, тип и отсутствие модификатора передачи:

```c#
void SomeMethod1(int g, double n) { }
```

следующие методы не соответствуют:

```c#

double SomeMethod2(int g, double n) { return g + n; }
void SomeMethod3(double n, int g) { }
void SomeMethod4(ref int g, double n) { }
void SomeMethod5(out int g, double n) { g = 6; }
```

SomeMethod2 возвращает double, тогда как делегат возвращает void. SomeMethod3 принимает те же типы, но в другом порядке, поэтому список параметров другой. у SomeMethod4 первый параметр передаётся с модификатором ref, у SomeMethod5 с модификатором out. для делегата SomeDel оба параметра передаются по значению, и отличие способа передачи делает преобразование невозможным.

### добавление методов в делегат

в предыдущих примерах переменная ссылалась на один метод. экземпляр может ссылаться на несколько методов с той же сигнатурой и тем же возвращаемым типом. все они входят в список вызова (invocation list). при вызове делегата методы из списка выполняются последовательно, в порядке следования в списке. добавить метод можно операцией **+=**:

```c#

Message message = Hello;
message += HowAreYou;  // теперь message указывает на два метода
message();              // вызываются оба метода - Hello и HowAreYou

void Hello() => Console.WriteLine("Hello");
void HowAreYou() => Console.WriteLine("How are you?");

delegate void Message();
```

в список вызова message входят Hello и HowAreYou. вызов message выполняет оба метода.

операция += не дописывает метод в уже существующий экземпляр. делегат неизменяем: создаётся новый объект, его список вызова содержит методы прежней копии и добавляемый метод, и этот новый объект присваивается переменной message.

одну и ту же ссылку на метод можно добавить несколько раз. в списке вызова тогда несколько вхождений одного метода, и при вызове метод выполняется столько раз, сколько раз был добавлен:

```c#

Message message = Hello;
message += HowAreYou;
message += Hello;
message += Hello;

message();
```

консольный вывод:

```consoletext

Hello
How are you?
Hello
Hello
```

Hello входит в список трижды, HowAreYou один раз, и печать повторяет этот порядок.

удаление из списка записывается операцией **-=**:

```c#

Message? message = Hello; 
message += HowAreYou;
message();	// вызываются все методы из message
message -= HowAreYou;	// удаляем метод HowAreYou
if (message != null) message();	// вызывается метод Hello
```

удаление тоже не меняет старый экземпляр. создаётся новый делегат, в списке вызова которого на один метод меньше, и он присваивается переменной.

если снят последний метод, переменная получает значение null. поэтому тип объявлен как **Message?**. значением может быть и делегат Message, и null. перед вторым вызовом переменная проверяется на null, иначе вызов пустого делегата завершится исключением.

если один и тот же метод входит в список несколько раз, операция -= ищет вхождение с конца списка и удаляет только первое найденное, то есть последнее по порядку добавления. остальные вхождения остаются. если такого метода в списке нет, -= ничего не меняет.

#### объединение делегатов

делегаты объединяются в новый делегат операцией +. список вызова результата составляется из списков операндов, сначала левый, затем правый:

```c#

Message mes1 = Hello;
Message mes2 = HowAreYou;
Message mes3 = mes1 + mes2; // объединяем делегаты
mes3(); // вызываются все методы из mes1 и mes2

void Hello() => Console.WriteLine("Hello");
void HowAreYou() => Console.WriteLine("How are you?");

delegate void Message();
```

объект mes3 является объединением mes1 и mes2. в его список вызова попадают все методы обоих делегатов. вызов mes3 выполняет эти методы один за другим. исходные mes1 и mes2 при этом не меняются: сложение, как и +=, даёт новый экземпляр.

### вызов делегата

в примерах выше делегат вызывался скобками, как метод. если у делегата есть параметры, в скобки передаются аргументы:

```c#

Message mes = Hello;
mes();
Operation op = Add;
int n = op(3, 4);
Console.WriteLine(n);

void Hello() => Console.WriteLine("Hello");
int Add(int x, int y) => x + y;

delegate int Operation(int x, int y);
delegate void Message();
```

второй способ вызова, метод **Invoke()**. аргументы, если они есть, передаются в Invoke:

```c#

Message mes = Hello;
mes.Invoke(); // Hello
Operation op = Add;
int n = op.Invoke(3, 4);
Console.WriteLine(n);   // 7

void Hello() => Console.WriteLine("Hello");
int Add(int x, int y) => x + y;

delegate int Operation(int x, int y);
delegate void Message();
```

если список вызова пуст и делегат равен null, вызов порождает исключение. оба следующих вызова к этому и приводят:

```c#

Message? mes;
//mes();        // ! Ошибка: делегат равен null

Operation? op = Add;
op -= Add;      // делегат op пуст
int n = op(3, 4);       // !Ошибка: делегат равен null
```

перед вызовом переменную проверяют на null. ту же проверку выполняет условный оператор `?.` вместе с Invoke: при null метод не вызывается, и исключения нет.

```c#

Message? mes = null;
mes?.Invoke();        // ошибки нет, делегат просто не вызывается

Operation? op = Add;
op -= Add;      	// делегат op пуст
int? n = op?.Invoke(3, 4);   // ошибки нет, делегат просто не вызывается, а n = null
```

если делегат возвращает значение, а в списке вызова несколько методов, результатом выражения становится значение последнего метода. предыдущие методы при этом всё равно выполняются, их результаты отбрасываются:

```c#

Operation op = Subtract;
op += Multiply;
op += Add;
Console.WriteLine(op(7, 2));    // Add(7,2) = 9

int Add(int x, int y) => x + y;
int Subtract(int x, int y) => x - y;
int Multiply(int x, int y) => x * y;

delegate int Operation(int x, int y);
```

в списке сначала Subtract, затем Multiply, затем Add. вызов op(7, 2) выполняет все три метода и возвращает результат Add, то есть 9. если один из методов списка выбрасывает исключение, последующие методы этого вызова уже не выполняются: обход списка идёт последовательно и прерывается исключением.

### обобщенные делегаты

делегат, как и другой тип, может быть обобщённым. параметры типа входят в сигнатуру и фиксируются при создании переменной:

```c#

Operation<decimal, int> squareOperation = Square;
decimal result1 = squareOperation(5);
Console.WriteLine(result1);  // 25

Operation<int, int> doubleOperation = Double;
int result2 = doubleOperation(5);
Console.WriteLine(result2);  // 10

decimal Square(int n) => n * n;
int Double(int n) => n + n;

delegate T Operation<T, K>(K val);
```

у делегата Operation два параметра типа. T задаёт возвращаемый тип, K задаёт тип аргумента. закрытый тип `Operation<decimal, int>` соответствует методу, который принимает int и возвращает decimal: это Square. закрытый тип `Operation<int, int>` соответствует методу, который принимает int и возвращает int: это Double. открытое объявление само по себе не создаёт один делегат на произвольные типы. каждый закрытый тип обладает собственной сигнатурой, и метод приводится только к тому закрытому типу, с которым совпадает.

### делегаты как параметры методов

делегат может быть параметром метода. метод тогда принимает не только данные, но и действие, которое с этими данными нужно выполнить:

```c#

DoOperation(5, 4, Add);         // 9
DoOperation(5, 4, Subtract);    // 1
DoOperation(5, 4, Multiply);    // 20

void DoOperation(int a, int b, Operation op)
{
    Console.WriteLine(op(a,b));
}
int Add(int x, int y) => x + y;
int Subtract(int x, int y) => x - y;
int Multiply(int x, int y) => x * y;

delegate int Operation(int x, int y);
```

метод **DoOperation** принимает два числа и действие типа Operation. внутри метода делегат вызывается с этими числами, и на консоль выводится его результат. при вызове DoOperation третьим аргументом передаётся метод, совместимый с Operation: Add, Subtract или Multiply. выбор действия остаётся у вызывающего кода, а DoOperation отвечает только за применение переданного делегата.

### возвращение делегатов из метода

метод может вернуть делегат, то есть вернуть действие в виде ссылки на другой метод:

```c#

Operation operation = SelectOperation(OperationType.Add);
Console.WriteLine(operation(10, 4));    // 14

operation = SelectOperation(OperationType.Subtract);
Console.WriteLine(operation(10, 4));    // 6

operation = SelectOperation(OperationType.Multiply);
Console.WriteLine(operation(10, 4));    // 40

Operation SelectOperation(OperationType opType)
{
    switch (opType)
    {
        case OperationType.Add: return Add;
        case OperationType.Subtract: return Subtract;
        default: return Multiply;
    }
}

int Add(int x, int y) => x + y;
int Subtract(int x, int y) => x - y;
int Multiply(int x, int y) => x * y;

enum OperationType
{
    Add, Subtract, Multiply
}
delegate int Operation(int x, int y);
```

метод `SelectOperation()` принимает перечисление OperationType. в перечислении три константы, и каждая обозначает арифметическую операцию. по значению параметра метод возвращает соответствующий метод. возвращаемый тип SelectOperation является делегатом Operation, поэтому вернуть можно только метод, совместимый с этим делегатом. здесь это Add, Subtract и Multiply. если параметр равен `OperationType.Add`, возвращается Add:

```c#
case OperationType.Add: return Add;
```

ветвь default возвращает Multiply, поэтому и константа Multiply, и любое значение, не разобранное отдельной ветвью, дают умножение.

вызов SelectOperation записывает полученное действие в переменную operation:

```c#
Operation operation = SelectOperation(OperationType.Add);
```

вызов operation выполняет тот метод, который SelectOperation вернул. при OperationType.Add переменная ссылается на Add, и operation(10, 4) вычисляет сумму:

```c#

Operation operation = SelectOperation(OperationType.Add);	// Здесь operation = Add
Console.WriteLine(operation(10, 4));    // 14
```

для Subtract и Multiply схема та же: меняется возвращённый метод, вызов переменной остаётся вызовом делегата.

### возвращение делегатом делегата

делегат может возвращать делегат, в том числе собственный тип. сигнатура тогда ссылается сама на себя: результат вызова снова можно вызвать.

```c#

Eat(5)(6)(7);

Hungry Eat(int val)
{
    Console.WriteLine($"Съели число {val}"); 
    return Eat;
};

delegate Hungry Hungry(int value);
```

делегат Hungry принимает число и возвращает Hungry. метод `Eat()` с этой сигнатурой совместим: параметр имеет тип `int`, возвращаемый тип является делегатом Hungry. из метода, совместимого с Hungry, можно вернуть сам этот метод. тело печатает переданное число и возвращает Eat.

цепочка `Eat(5)(6)(7)` состоит из трёх вызовов. первый вызов получает 5 и возвращает делегат, второй вызывает этот делегат с аргументом 6, третий вызывает результат второго вызова с аргументом 7. каждый вызов снова возвращает Eat, поэтому цепочка не обрывается.

```bash

Съели число 5
Съели число 6
Съели число 7
```
