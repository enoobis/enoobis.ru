универсальным параметром обобщённый класс типизируется любым типом. иногда тип требуется сузить. класс `Message` представляет некоторое сообщение:

```c#


class Message

{

    public string Text { get; } // текст сообщения

    public Message(string text)

    {

        Text = text;

    }

}
```

метод отправки сообщений в виде объектов `Message` на первый взгляд определяется так:

```c#


SendMessage(new Message("Hello World"));



void SendMessage(Message message)

{

    Console.WriteLine($"Отправляется сообщение: {message.Text}");

}
```

метод `SendMessage` принимает в параметре `message` объект `Message` и эмулирует его отправку. у класса `Message` при этом могут быть классы-наследники. класс `EmailMessage` предназначен для email-сообщений, `SmsMessage` для sms-сообщений, и далее по тому же принципу:

```c#


class EmailMessage : Message

{

    public EmailMessage(string text) : base(text) { }

}

class SmsMessage : Message

{

    public SmsMessage(string text) : base(text) { }

}
```

сообщения этих классов тоже нужно отправлять. метод `SendMessage` принимает объект `Message`, а значит принимает и объекты производных классов: они подставляются по отношению подтипа.

```c#


SendMessage(new EmailMessage("Hello World"));



void SendMessage(Message message)

{

    Console.WriteLine($"Отправляется сообщение: {message.Text}");

}
```

здесь происходит преобразование типов от `EmailMessage` к `Message`. если затем понадобится преобразовать объект `message` обратно к производному классу, снова возникает проблема типобезопасности: статическому типу `Message` неизвестно, какой именно наследник был передан. чтобы избежать этих преобразований, применяются обобщения:

```c#


void SendMessage<T>(T message)

{

    Console.WriteLine($"Отправляется сообщение: {message.Text}");	// ! Ошибка - свойство Text

}
```

обобщение убирает преобразование к базовому классу, но появляется другая проблема. универсальный параметр `T` означает любой тип, а свойство `Text` есть не у любого типа. для объекта типа `T` свойство `Text` не определено, и обратиться к нему нельзя. более того, у объекта `T` по умолчанию доступны только методы типа `object`: компилятор проверяет тело обобщения по тем членам, которые гарантированы ограничением, а без ограничения гарантирован только контракт `object`.

нужно одновременно избежать преобразований типов, то есть остаться в обобщении, и обращаться внутри метода к функционалу класса `Message`. эту пару требований закрывают ограничения обобщений.

### ограничения методов

ограничения методов указываются после списка параметров, после оператора **where**:

```c#
имя_метода<T>(параметры) where T: тип_ограничения
```

после оператора **where** указывается универсальный параметр, к которому применяется ограничение. через двоеточие указывается тип ограничения. обычно в качестве ограничения выступает конкретный тип, и это ограничение есть верхняя граница: аргумент типа обязан быть этим типом или его подтипом.

ограничение применяется к методу `SendMessage`, который отправляет объекты `Message`:

```c#


SendMessage(new Message("Hello World"));

SendMessage(new EmailMessage("Bye World"));



void SendMessage<T>(T message) where T: Message

{

    Console.WriteLine($"Отправляется сообщение: {message.Text}");

}

class Message

{

    public string Text { get; } // текст сообщения

    public Message(string text)

    {

        Text = text;

    }

}

class EmailMessage : Message

{

    public EmailMessage(string text) : base(text) { }

}
```

выражение `where T: Message` в определении метода `SendMessage` говорит, что через универсальный параметр `T` передаются объекты класса `Message` и производных классов. компилятор знает, что у `T` есть функционал класса `Message`, и к методам и свойствам класса `Message` внутри метода можно обращаться без приведения. подставить тип, который не является `Message` и не наследует `Message`, нельзя: ошибка будет на этапе компиляции, а не при чтении свойства.

при вызове метода тип в угловых скобках указывать не обязательно. компилятор по переданному значению сам определяет, каким типом типизируется метод:

```c#
SendMessage(new EmailMessage("Bye World"));
```

то же самое можно записать явно:

```c#
SendMessage<EmailMessage>(new EmailMessage("Bye World"));
```

вывод аргумента типа выполняется для обобщённого метода по типам аргументов вызова. ограничение при выводе не подменяет аргумент, а только проверяет, что выведенный тип ему удовлетворяет.

### ограничения обобщений в типах

тем же способом задаются ограничения обобщённых типов, в том числе обобщённых классов:

```c#
class имя_класса<T> where T: тип_ограничения
```

класс мессенджера отправляет сообщения в виде объектов `Message`:

```c#


class Messenger<T> where T : Message

{

    public void SendMessage(T message)

    {

        Console.WriteLine($"Отправляется сообщение: {message.Text}");

    }

}



class Message

{

    public string Text { get; } // текст сообщения

    public Message(string text)

    {

        Text = text;

    }

}

class EmailMessage : Message

{

    public EmailMessage(string text) : base(text) { }

}
```

для класса `Messenger` установлено ограничение `where T : Message`. внутри класса `Messenger` любой объект типа `T` используется как объект `Message`. в методе `SendMessage` снова эмулируется отправка сообщений. обращение к `message.Text` законно, потому что ограничение гарантирует это свойство у любого типа, подставленного вместо `T`.

применение класса:

```c#


Messenger<Message> telegram = new Messenger<Message>(); 

telegram.SendMessage(new Message("Hello World"));



Messenger<EmailMessage> outlook = new Messenger<EmailMessage>();

outlook.SendMessage(new EmailMessage("Bye World"));
```

`Messenger<Message>` принимает любой `Message` и его подтипы. `Messenger<EmailMessage>` уже: в `SendMessage` этого экземпляра передаётся только `EmailMessage`. обобщённые классы в c# инвариантны, поэтому `Messenger<EmailMessage>` не является подтипом `Messenger<Message>`.

### типы ограничений и стандартные ограничения

в качестве ограничений используются следующие типы:

- классы

- интерфейсы

- `class`: универсальный параметр должен представлять класс

- `struct`: универсальный параметр должен представлять структуру

- `new()`: универсальный параметр должен представлять тип, который имеет общедоступный (`public`) конструктор без параметров

есть ряд стандартных ограничений. можно потребовать, чтобы использовались только структуры или другие типы значений:

```c#


class Messenger<T> where T : struct

{}
```

конкретную структуру, в отличие от класса, указать как ограничение нельзя. структура не бывает базовым типом другого типа, она фактически герметична, и ограничение «параметр есть данная структура» не описывает семейство подтипов. язык такое ограничение запрещает. класс в качестве границы как раз описывает все его подтипы, поэтому имя класса в `where` допустимо.

ограничение ссылочными типами:

```c#


class Messenger<T> where T : class

{}
```

словом **new** задаётся ограничение: тип, класс или структура, должен иметь общедоступный конструктор без параметров.

```c#


class Messenger<T> where T : new()

{}
```

ограничение `new()` нужно затем, что внутри обобщённого определения выражение `new T()` законно только если у `T` гарантирован публичный конструктор без параметров. без этого ограничения компилятор не знает, как создать значение `T`.

если для универсального параметра задано несколько ограничений, они идут в определённом порядке:

- название класса, `class`, `struct`. одновременно допустимо только одно из этих ограничений

- название интерфейса

- `new()`

```c#


class Smartphone<T> where T: Messenger, new()

{

 

}
```

в контексте аннотаций nullable ограничение `class` требует ссылочный тип без null, а `class?` разрешает пустую ссылку. ограничение `struct` требует значимый тип, не допускающий `null`: `Nullable<T>` этому ограничению не удовлетворяет. в более поздних версиях языка к стандартным ограничениям добавлены `notnull`, `unmanaged`, `Enum` и `Delegate`. при вызове метода на значении параметра типа компилятор порождает в il префикс `constrained`. если параметр ограничен `struct`, этот вызов не упаковывает значение.

### использование нескольких универсальных параметров

если класс использует несколько универсальных параметров, ограничения задаются последовательно к каждому из них:

```c#


class Messenger<T, P> 

    where T : Message

    where P: Person

{

    public void SendMessage(P sender, P receiver, T message)

    {

        Console.WriteLine($"Отправитель: {sender.Name}");

        Console.WriteLine($"Получатель: {receiver.Name}");

        Console.WriteLine($"Сообщение: {message.Text}");

    }

}

class Person

{

    public string Name { get;}

    public Person(string name) => Name = name;

}



class Message

{

    public string Text { get; } // текст сообщения

    public Message(string text) =>  Text = text;

}
```

для параметра `P` передаются объекты типа `Person`, для параметра `T` объекты `Message`. у каждого параметра своё предложение `where`. ограничение одного параметра не распространяется на другой.

применение классов:

```c#


Messenger<Message, Person> telegram = new Messenger<Message, Person>();

Person tom = new Person("Tom");

Person bob = new Person("Bob");

Message hello = new Message("Hello, Bob!");

telegram.SendMessage(tom, bob, hello);
```

консольный вывод:

```consoletext


Отправитель: Tom

Получатель: Bob

Сообщение: Hello, Bob!
```
