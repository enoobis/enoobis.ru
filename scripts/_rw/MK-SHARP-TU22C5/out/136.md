возвращаемый тип асинхронного метода является одним из следующих: **void**, **Task**, `Task<TResult>` или `ValueTask<TResult>`.

### void

при типе `void` метод не отдаёт вызывающему ни значения, ни объекта задачи:

```c#


PrintAsync("Hello World");

PrintAsync("Hello METANIT.COM");



Console.WriteLine("Main End");

await Task.Delay(3000); // ждем завершения задач



// определение асинхронного метода

async void PrintAsync(string message)

{

    await Task.Delay(1000);     // имитация продолжительной работы

    Console.WriteLine(message);

}
```

асинхронных методов с типом `void` избегают и оставляют их там, где другая подпись невозможна. к такому методу нельзя применить `await`: вызов не возвращает `Task`. исключения из него не перехватываются снаружи метода. они уходят в контекст синхронизации, а если контекста нет, остаются необработанными. по той же причине метод трудно тестировать: у теста нет задачи, по которой видны завершение и ошибка.

такая подпись нужна, когда её требует делегат события:

```c#


Account account = new Account();

account.Added += PrintAsync;



account.Put(500);



await Task.Delay(2000); // ждем завершения



// определение асинхронного метода

async void PrintAsync(object? obj, string message)

{

    await Task.Delay(1000);     // имитация продолжительной работы

    Console.WriteLine(message);

}



class Account

{

    int sum = 0;

    public event EventHandler<string>? Added;

    public void Put(int sum)

    {

        this.sum += sum;

        Added?.Invoke(this, $"На счет поступило {sum} $");

    }

}
```

событие `Added` в классе `Account` имеет тип `EventHandler<string>`. этот делегат возвращает `void`, поэтому обработчиком может быть только метод с типом `void`. `Put` синхронно вызывает подписчиков. `PrintAsync` доходит до `await Task.Delay` и возвращает управление в `Put`, печать происходит позже, уже после паузы. `await Task.Delay(2000)` в вызывающем коде лишь не даёт процессу завершиться раньше печати. саму задачу обработчика этот оператор не наблюдает, наблюдать её нечего: `async void` задачу наружу не отдаёт.

### Task

метод может возвращать объект `Task` и при этом не возвращать отдельного значения:

```c#


await PrintAsync("Hello Metanit.com");



// определение асинхронного метода

async Task PrintAsync(string message)

{

    await Task.Delay(1000);     // имитация продолжительной работы

    Console.WriteLine(message);

}
```

формально `PrintAsync` не использует `return`, чтобы отдать результат. если в выражении `await` выполняется асинхронная операция, возвращаемым типом метода может быть `Task`: компилятор завершит этот объект, когда метод дойдёт до конца.

для ожидания применяется оператор **await**. ставить его прямо в строке вызова не обязательно. вызов запускает метод, `await` пишется там, где нужно гарантированно дождаться конца задачи:

```c#


var task = PrintAsync("Hello Metanit.com"); // задача начинает выполняться

Console.WriteLine("Main Works");



await task; // ожидаем завершения задачи



// определение асинхронного метода

async Task PrintAsync(string message)

{

    await Task.Delay(0);

    Console.WriteLine(message);

}
```

между созданием задачи и `await` выполняется синхронный код, здесь это печать `Main Works`. `Task.Delay(0)` задаёт нулевую паузу. реализация может завершить такую задачу сразу или поставить продолжение в очередь, поэтому к строке `await` задача бывает уже готова, и тогда ожидание не приостанавливает метод.

### Task с результатом

метод может вернуть значение. значение хранится внутри задачи, а возвращаемый тип имеет вид `Task<TResult>`. для квадрата числа параметр типа равен `int`:

```c#


int n1 = await SquareAsync(5);

int n2 = await SquareAsync(6);

Console.WriteLine($"n1={n1}  n2={n2}"); // n1=25  n2=36



async Task<int> SquareAsync(int n)

{

    await Task.Delay(0);

    return n * n;

}
```

`SquareAsync` возвращает `int`, квадрат аргумента. тип метода при этом `Task<int>`.

чтобы получить само число, вызов пишется с `await`:

```c#
int n1 = await SquareAsync(5);
```

`await` снимает с `Task<int>` значение типа `int`. так же читаются результаты других типов, в том числе ссылочных:

```c#


Person person = await GetPersonAsync("Tom");

Console.WriteLine(person.Name); // Tom

// определение асинхронного метода

async Task<Person> GetPersonAsync(string name)

{

    await Task.Delay(0);

    return new Person(name);

}

record class Person(string Name);
```

непосредственный результат можно забрать позже, в той точке, где он нужен. до этого вызовы уже запущены:

```c#


var square5 = SquareAsync(5);

var square6 = SquareAsync(6);



Console.WriteLine("Остальные действия в методе Main");



int n1 = await square5;

int n2 = await square6;

Console.WriteLine($"n1={n1}  n2={n2}"); // n1=25  n2=36



async Task<int> SquareAsync(int n)

{

    await Task.Delay(0);

    var result = n * n;

    Console.WriteLine($"Квадрат числа {n} равен {result}");

    return result;

}
```

пример работы программы (вывод недетерминирован):

```consoletext


Квадрат числа 5 равен 25

Квадрат числа 6 равен 36

Остальные действия в методе Main

n1=25  n2=36
```

оба вызова `SquareAsync` доходят до `await Task.Delay(0)` и дальше печатают квадрат, когда продолжение получает поток. строка `Остальные действия в методе Main` выполняется на вызывающем потоке сразу после запуска, без ожидания этих задач. взаимный порядок этой строки и двух печатей квадратов зависит от того, завершился ли `Delay(0)` синхронно. числа `n1` и `n2` читаются уже после `await`, когда результаты точно есть.

### ValueTask

`ValueTask<TResult>` стоит в тех же местах, что `Task<TResult>`, и отличается представлением. `ValueTask<TResult>` является структурой и поэтому копируется при передаче. полей у неё больше, чем нужно, чтобы хранить один только готовый результат или одну ссылку: внутри лежит либо значение `TResult`, либо задача. копирование этой структуры дороже копирования ссылки на `Task<TResult>`. экономия выделения появляется на пути, где результат уже готов. `Task<TResult>` является классом, и даже мгновенно готовый результат обычно означает объект в куче. структура позволяет вернуть уже известное значение без такого объекта.

синхронный возврат суммы через `Task`:

```c#


var result = await AddAsync(4, 5);

Console.WriteLine(result);



Task<int> AddAsync(int a, int b)

{

    return Task.FromResult(a + b);

}
```

`AddAsync` сразу знает сумму двух чисел. статический метод **Task.FromResult** синхронно возвращает завершённый `Task<int>`. это отдельная задача со своим выделением памяти в куче. `ValueTask<TResult>` в том же месте объект задачи не создаёт:

```c#


var result = await AddAsync(4, 5);

Console.WriteLine(result);



ValueTask<int> AddAsync(int a, int b)

{

    return new ValueTask<int>(a + b);

}
```

дополнительный `Task` не выделяется, и отдельной памяти под него нет. `ValueTask<TResult>` применяют, когда результат асинхронной операции уже есть и выделять задачу не для чего. структуру ожидают один раз: повторный `await` по той же копируемой операции и несколько одновременных ожиданий контрактом типа не предусмотрены.

при необходимости `ValueTask<TResult>` превращается в `Task` методом **AsTask()**:

```c#


var getMessage = GetMessageAsync();

string message = await getMessage.AsTask();

Console.WriteLine(message); // Hello



async ValueTask<string> GetMessageAsync()

{

    await Task.Delay(0);

    return "Hello";

}
```

дальше ожидают уже обычный `Task<string>`, его можно сохранить и отдать нескольким потребителям. исходную структуру после `AsTask` ещё раз не ожидают: потребителем становится возвращённый объект `Task`.
