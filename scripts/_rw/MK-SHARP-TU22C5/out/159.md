для приложения фиксируется набор сборок, к функциональности которых оно обращается. ссылки на эти сборки записываются в проекте, и во время выполнения clr подгружает сборку при первом обращении к её типам. имя сборки в этом сценарии известно уже на этапе компиляции: это раннее связывание.

приложение может загрузить и сборку, ссылки на которую в проекте нет. загрузка тогда выполняется программно во время выполнения и называется динамической.

работа со сборками сосредоточена в пространстве имён `System.Reflection`, в классе **Assembly**. через него сборку загружают и читают метаданные: отображаемое имя, версию, перечень определённых в ней типов.

динамическая загрузка выполняется статическими методами **Assembly.LoadFrom()** и **Assembly.Load()**.

метод `LoadFrom()` принимает путь к файлу сборки.

ниже два проекта, между которыми сборка передаётся файлом, а не ссылкой проекта.

![загрузка сборок в c# и .net](/uploads/course-lectures/b196de13b33254bcb69417e3b98c014f84173bb6.png)

проект MyApp компилируется в сборку MyApp.dll. файл Program.cs содержит такой текст:

```c#


Person tom = new Person("Tom");

Console.WriteLine($"Hello, {tom.Name}");



class Person

{

    public string Name { get; }

    public Person(string name) => Name = name;

}
```

инструкции верхнего уровня компилятор помещает в неявно объявленный класс `Program`. тип `Person` объявлен в том же файле явно: у него есть свойство `Name` и конструктор, который это свойство инициализирует.

второй проект загружает MyApp.dll и перечисляет типы этой сборки:

```c#


using System.Reflection;



Assembly asm = Assembly.LoadFrom("MyApp.dll");



Console.WriteLine(asm.FullName);

// получаем все типы из сборки MyApp.dll

Type[] types = asm.GetTypes();

foreach (Type t in types)

{

    Console.WriteLine(t.Name);

}
```

в `LoadFrom` передан относительный путь. файл MyApp.dll лежит в том же каталоге, что и запускаемое приложение, то есть в выходном каталоге проекта `bin/Debug/net6.x`. на место пути можно подставить и сборку текущего приложения: программа тогда читает собственные метаданные. для загрузки, по крайней мере в .net 6.0, подходит файл с расширением dll. файл exe в этой роли не принимается. у sdk-проекта управляемый код приложения находится в dll, а соседний exe является нативным хостом, который эту dll запускает.

консольный вывод примера:

```bash


MyApp, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null

EmbeddedAttribute

NullableAttribute

NullableContextAttribute

Program

Person
```

полное отображаемое имя сборки выглядит так: `MyApp, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null`. в нём записаны простое имя, версия, культура и маркер открытого ключа. значение `null` у `PublicKeyToken` означает, что сборка не подписана строгим именем.

`GetTypes()` возвращает пять типов. по исходному тексту ожидаются два: неявный класс `Program` и класс `Person`. ещё три типа, `EmbeddedAttribute`, `NullableAttribute` и `NullableContextAttribute`, выпускает компилятор. они кодируют метаданные контекста обнуляемых ссылочных типов. `NullableContextAttribute` задаёт контекст для участка кода, `NullableAttribute` помечает обнуляемость конкретного элемента, `EmbeddedAttribute` показывает, что определение атрибута вложено в саму сборку, а не взято из отдельной библиотеки.

метод `Load()` загружает сборку по отображаемому имени, а не по пути к файлу. это имя часто совпадает с именем приложения: `Assembly asm = Assembly.Load("MyApp");`. среда ищет сборку по идентичности среди сборок, доступных контексту загрузки, тогда как `LoadFrom` открывает конкретный файл.

к каждому объекту `Type`, полученному из `GetTypes()`, применяются те же операции отражения, что и в предыдущей теме: чтение конструкторов, полей, свойств, методов и атрибутов.

### позднее связывание

динамическая загрузка служит основанием позднего связывания. **позднее связывание** создаёт экземпляры некоторого типа и вызывает его члены во время выполнения, когда конкретный тип не зафиксирован в исходном тексте вызывающей программы.

при раннем связывании типы записаны в коде напрямую, и компилятор проверяет наличие членов и совместимость сигнатур. при позднем связывании эта проверка сдвигается на время выполнения: неверное имя типа, отсутствие метода или несовпадение аргументов проявляются как исключение отражения. за счёт этого программу можно расширять сборками, которых на момент компиляции ещё нет и которые поставляет другой разработчик.

в создании экземпляров при позднем связывании участвует класс **System.Activator**. статический метод **Activator.CreateInstance()** строит экземпляр по объекту `Type`. вызов уже известного метода выполняет другая операция отражения, `MethodInfo.Invoke`. в следующем примере используется именно она.

загружаемая сборка, в тексте лекции обозначенная как MyApp.exe, соответствует такой программе:

```c#


class Program

{

    static void Main(string[] args)

    {

        var number = 5;

        var result = Square(number);

        Console.WriteLine($"Квадрат {number} равен {result}");

    }

    static int Square(int n) => n * n;

}
```

класс `Program` объявлен явно и содержит метод `Main`. в том же классе определён статический метод `Square`: параметр `n` типа `int`, результат равен `n * n`. модификатор доступа у метода не указан, значит член закрытый и виден только внутри типа.

основная программа подключает сборку и вызывает эти методы:

```c#


using System.Reflection;



Assembly asm = Assembly.LoadFrom("MyApp.dll");



Type? t = asm.GetType("Program");

if (t is not null)

{

    // получаем метод Square

    MethodInfo? square = t.GetMethod("Square", BindingFlags.NonPublic | BindingFlags.Static);



    // вызываем метод, передаем ему значения для параметров и получаем результат

    object? result = square?.Invoke(null, new object[] { 7 });

    Console.WriteLine(result); // 49

}
```

ссылка на исследуемую сборку сохраняется в переменной `asm`:

```c#
Assembly asm = Assembly.LoadFrom("MyApp.dll")
```

метод `GetType` ищет в MyApp.dll тип по имени `Program`. если тип не найден, возвращается `null`, поэтому результат имеет тип `Type?`:

```c#
Type? t = asm.GetType("Program");
```

затем из типа извлекается метод:

```c#
MethodInfo? square = t.GetMethod("Square", BindingFlags.NonPublic | BindingFlags.Static);
```

перегрузка `GetMethod` без флагов ищет открытый метод экземпляра. `Square` закрытый и статический, поэтому вторым аргументом передаётся маска `BindingFlags.NonPublic | BindingFlags.Static`. это битовое объединение: `NonPublic` включает члены без модификатора `public`, `Static` включает статические члены. вместе маска отбирает закрытый статический метод.

сам вызов выполняет `Invoke`:

```c#


object? result = square?.Invoke(null, new object[] { 7 });
```

первый аргумент `Invoke` задаёт получателя, то есть объект, для которого вызывается метод экземпляра. второй аргумент задаёт фактические параметры массивом `object[]`. `Square` статический и к экземпляру не привязан, поэтому получатель равен `null`, а в массив помещается аргумент `7`. возвращаемое значение приходит как `object`: на этапе компиляции статический тип результата вызова неизвестен. для входа `7` метод печатает `49`.

если метод параметров не принимает, на место массива передаётся `null`: `method.Invoke(null, null)`.

у класса `Program` в той же сборке есть и метод `Main`. его вызов устроен так:

```c#


using System.Reflection;



Assembly asm = Assembly.LoadFrom("MyApp.dll");



Type? program = asm.GetType("Program");

if (program is not null)

{

    // получаем метод Main

    MethodInfo? main = program.GetMethod("Main", BindingFlags.NonPublic | BindingFlags.Static);



    // вызываем метод Main

    main?.Invoke(null, new object[] { new string[] { } });   // Квадрат 5 равен 25

}
```

`Main` тоже статический и закрытый, поэтому маска снова `BindingFlags.NonPublic | BindingFlags.Static`. параметр имеет тип массива строк, и в `Invoke` передаётся соответствующее значение: `main.Invoke(null, new object[]{new string[]{}})`. внешний массив `object[]` является списком аргументов `Invoke`, его единственный элемент и есть тот массив строк, который получит `Main`. тело `Main` берёт число `5`, вызывает `Square` и выводит строку `Квадрат 5 равен 25`.
