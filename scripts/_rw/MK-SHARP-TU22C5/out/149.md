ряд методов linq проверяет наличие элементов в последовательности и извлекает отдельный элемент. кванторы обходят источник до тех пор, пока ответ ещё не определён, методы выбора элемента либо возвращают один объект, либо сигнализируют об отсутствии через исключение или через значение по умолчанию.

### All

метод **All()** проверяет, удовлетворяют ли условию все элементы. если все элементы удовлетворяют условию, возвращается `true`. на пустой последовательности результат тоже `true`: утверждение «для каждого элемента» не опровергается ни одним контрпримером.

```c#


string[] people = { "Tom", "Tim", "Bob", "Sam" };



// проверяем, все ли элементы имеют длину в 3 символа

bool allHas3Chars = people.All(s => s.Length == 3);     // true

Console.WriteLine(allHas3Chars);



// проверяем, все ли строки начинаются на T

bool allStartsWithT = people.All(s => s.StartsWith("T"));   // false

Console.WriteLine(allStartsWithT);
```

в первом вызове проверяется, что каждая строка массива `people` имеет длину 3. условие выполняется для всех четырёх строк, `All` возвращает `true`. во втором вызове проверяется, что каждая строка начинается с буквы "T". строки "Bob" и "Sam" на "T" не начинаются, условие ложно, `All` возвращает `false`. обход прекращается на первом неподходящем элементе.

### Any

метод **Any()** возвращает `true`, если хотя бы один элемент удовлетворяет условию. на пустой последовательности и при отсутствии подходящих элементов результат `false`. перегрузка без предиката отвечает на другой вопрос: есть ли в последовательности хотя бы один элемент.

```c#


string[] people = { "Tom", "Tim", "Bob", "Sam" };



// проверяем, есть ли хоть один элемент с длиной больше 3 символов

bool allHasMore3Chars = people.Any(s => s.Length > 3);     // false

Console.WriteLine(allHasMore3Chars);



// проверяем, есть ли хоть одна строка, начинающаяся на T

bool allStartsWithT = people.Any(s => s.StartsWith("T"));   // true

Console.WriteLine(allStartsWithT);
```

первое выражение возвращает `false`: все строки имеют длину 3, строки длиннее 3 нет. второе выражение возвращает `true`: в коллекции есть строки, которые начинаются на букву `T`. имя переменной `allHasMore3Chars` в коде относится к вызову `Any`. предикат при этом остаётся `s.Length > 3`.

### Contains

метод **Contains()** возвращает `true`, если последовательность содержит указанный элемент.

```c#


string[] people = { "Tom", "Tim", "Bob", "Sam" };



// проверяем, есть ли строка Tom

bool hasTom = people.Contains("Tom");     // true

Console.WriteLine(hasTom);



// проверяем, есть ли строка Mike

bool hasMike = people.Contains("Mike");     // false

Console.WriteLine(hasMike);
```

сравнение идёт через реализацию `Equals` у компаратора по умолчанию, то есть через `EqualityComparer<T>.Default`. для собственных типов равенство задаётся переопределением `Equals`. вместе с `Equals` переопределяется `GetHashCode`: контракт требует, чтобы равные объекты имели одинаковый хеш-код. сам линейный поиск в `Enumerable.Contains` опирается на `Equals`, а согласованный хеш нужен коллекциям вроде словаря и множества, куда обычно передают ту же модель равенства.

```c#


Person[] people = { new Person("Tom"), new Person("Sam"), new Person("Bob")};



var tom = new Person("Tom");

var mike = new Person("Mike");



// проверяем, есть ли Tom

bool hasTom = people.Contains(tom);     // true

Console.WriteLine(hasTom);



// проверяем, есть ли строка Mike

bool hasMike = people.Contains(mike);     // false

Console.WriteLine(hasMike);



class Person

{

    public string Name { get;}

    public Person(string name) => Name = name;



    public override bool Equals(object? obj)

    {

        if (obj is Person person) return Name == person.Name;

        return false;

    }

    public override int GetHashCode() => Name.GetHashCode();

}
```

у `Person` равенство определено по свойству `Name`. поэтому `people.Contains(tom)` возвращает `true` для нового экземпляра с именем "Tom", хотя это другой объект в памяти. `people.Contains(mike)` возвращает `false`: имени "Mike" в массиве нет.

ожидаемый ответ `Contains` зависит от того, какое равенство подставлено. регистр символов в равенстве `string` по умолчанию учитывается:

```c#


string[] people = { "tom", "Tim", "bOb", "Sam" };



// проверяем, есть ли строка Tom

bool hasTom = people.Contains("Tom");     // false

Console.WriteLine(hasTom);



// проверяем, есть ли строка Bob

bool hasMike = people.Contains("Bob");     // false

Console.WriteLine(hasMike);
```

в массиве нет строки "Tom", есть строка "tom". вызов `people.Contains("Tom")` возвращает `false`. строки "Bob" в массиве тоже нет, есть "bOb", поэтому `people.Contains("Bob")` возвращает `false` (результат записан в переменную `hasMike`). такое сравнение ординальное. когда нужен другой критерий, в `Contains` передаётся второй аргумент: реализация `IEqualityComparer<T>`. этот интерфейс задаёт равенство и хеш. интерфейс `IComparer<T>` задаёт порядок и к данной перегрузке не подходит.

```c#


using System.Diagnostics.CodeAnalysis;



string[] people = { "tom", "Tim", "bOb", "Sam" };



// проверяем, есть ли строка Tom

bool hasTom = people.Contains("Tom", new CustomStringComparer());     // true

Console.WriteLine(hasTom);



// проверяем, есть ли строка Bob

bool hasMike = people.Contains("Bob", new CustomStringComparer());     // true

Console.WriteLine(hasMike);



class CustomStringComparer : IEqualityComparer<string>

{

    public bool Equals(string? x, string? y)

    {

        if (x is null || y is null) return false;

        return x.ToLower() == y.ToLower();



    }



    public int GetHashCode(string obj) => obj.ToLower().GetHashCode();

}
```

`IEqualityComparer<string>` типизирован типом сравниваемых данных. для реализации нужны методы `Equals` и `GetHashCode`. в `Equals` строки сравниваются в нижнем регистре, в `GetHashCode` возвращается хеш-код строки в нижнем регистре. обе стороны проходят через одну и ту же нормализацию, иначе равные с точки зрения `Equals` строки получили бы разные хеш-коды. `ToLower()` без явной культуры использует текущую культуру процесса, поэтому результат зависит от локали. ординальное сравнение без учёта регистра в библиотеке уже есть: `StringComparer.OrdinalIgnoreCase`. после подстановки компаратора оба вызова, `Contains("Tom")` и `Contains("Bob")`, возвращают `true`.

### First

метод **First()** возвращает первый элемент последовательности:

```c#


string[] people = { "Tom", "Bob", "Tim", "Sam" };



// проверяем, есть ли строка Tom

var first = people.First();  // Tom

Console.WriteLine(first);
```

в `First` можно передать предикат. тогда метод возвращает первый элемент, который удовлетворяет условию, и пропускает предыдущие:

```c#


string[] people = { "Tom", "Bob", "Kate", "Tim", "Mike", "Sam" };



// первая строка, длина которой равна 4 символам

var firstWith4Chars = people.First(s=> s.Length == 4);  // Kate

Console.WriteLine(firstWith4Chars);
```

здесь выбирается первый элемент, длина которого равна 4 символам. в массиве это строка "Kate": у "Tom" и "Bob" длина 3.

если последовательность пуста или в ней нет элемента, который удовлетворяет условию, генерируется исключение `InvalidOperationException`:

```c#


string[] people = { "Tom", "Bob", "Kate", "Tim", "Mike", "Sam" };



// первая строка, длина которой равна 5 символам

var firstWith5Chars = people.First(s => s.Length == 5);  // ! исключение

Console.WriteLine(firstWith5Chars);



var first = new string[] {}.First();  // ! исключение

Console.WriteLine(first);
```

предикат `s.Length == 5` не подходит ни одной строке. вызов `First` на массиве без элементов тоже не имеет первого элемента. оба вызова завершаются исключением, до `Console.WriteLine` выполнение не доходит.

### FirstOrDefault

метод **FirstOrDefault()** тоже возвращает первый элемент и тоже принимает условие. если последовательность пуста или подходящих элементов нет, метод возвращает значение по умолчанию:

```c#


string[] people = { "Tom", "Bob", "Kate", "Tim", "Mike", "Sam" };



// первый элемент

var first = people.FirstOrDefault();  // Tom

Console.WriteLine(first);



// первая строка, длина которой равна 4 символам

var firstWith4Chars = people.FirstOrDefault(s => s.Length == 4);  // Kate

Console.WriteLine(firstWith4Chars);



// первый элемент из пустой коллекции

var firstOrDefault = new string[] {}.FirstOrDefault();

Console.WriteLine(firstOrDefault);  // null
```

для последовательностей ссылочных типов возвращаемое значение имеет тип `T?` (в примере это `string?`), то есть допускает `null`, и значение по умолчанию равно `null`. для последовательностей числовых типов возвращается само значение типа `T`, а значение по умолчанию равно 0. в обоих случаях это `default(T)`: у ссылочного типа `null`, у `int` ноль.

значение по умолчанию задаётся явно одним из аргументов. такая перегрузка есть с .net 6:

```c#


string[] people = { "Tom", "Bob", "Kate", "Tim", "Mike", "Sam" };



string? firstWith5Chars = people.FirstOrDefault(s => s.Length == 5, "Undefined");

Console.WriteLine(firstWith5Chars); // Undefined



// первый элемент из пустой коллекции строк

string? firstOrDefault = new string[] {}.FirstOrDefault("hello"); // hello - значение по умолчанию

Console.WriteLine(firstOrDefault);  // hello



// первый элемент из пустой коллекции int

int firstNumber = new int[] {}.FirstOrDefault(100); // 100 - значение по умолчанию

Console.WriteLine(firstNumber); // 100
```

предикат длины 5 не находит строку, поэтому возвращается переданная строка "Undefined". пустой массив строк с аргументом "hello" даёт "hello". пустой массив `int` с аргументом 100 даёт 100.

### Last и LastOrDefault

метод **Last()** устроен так же, как `First`, но возвращает последний подходящий элемент. если последовательность пуста или не содержит элемента, который удовлетворяет условию, метод генерирует `InvalidOperationException`. на последовательности без произвольного доступа метод доходит до конца. если источник реализует `IList<T>`, реализация может взять последний индекс сразу.

```c#


string[] people = { "Tom", "Bob", "Kate", "Tim", "Mike", "Sam" };



string last = people.Last();

Console.WriteLine(last); // Sam



string lastWith4Chars = people.Last(s => s.Length == 4);

Console.WriteLine(lastWith4Chars); // Mike
```

без предиката результатом становится последний элемент, строка "Sam". предикат длины 4 отбирает "Kate", "Tim" и "Mike", последним из них идёт "Mike".

метод **LastOrDefault()** возвращает последний элемент или значение по умолчанию, если подходящего элемента нет или последовательность пуста:

```c#


string[] people = { "Tom", "Bob", "Kate", "Tim", "Mike", "Sam" };



string? last = people.LastOrDefault();

Console.WriteLine(last); // Sam



string? lastWith4Chars = people.LastOrDefault(s => s.Length == 4);

Console.WriteLine(lastWith4Chars); // Mike



string? lastWith5Chars = people.LastOrDefault(s => s.Length == 5);

Console.WriteLine(lastWith5Chars); // null



string? lastWith5CharsOrDefault = people.LastOrDefault(s => s.Length == 5, "Undefined");

Console.WriteLine(lastWith5CharsOrDefault); // Undefined



// первый элемент из пустой коллекции строк

string? lastOrDefault = new string[] {}.LastOrDefault("hello");

Console.WriteLine(lastOrDefault);  // hello
```

правила значения по умолчанию те же, что у `FirstOrDefault`: `null` для ссылочного типа, явное значение из перегрузки с дополнительным аргументом, если оно передано. вызов на пустом массиве строк с аргументом "hello" возвращает "hello". комментарий в коде говорит про первый элемент, сам вызов при этом является `LastOrDefault`.
