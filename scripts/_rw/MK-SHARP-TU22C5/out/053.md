### абстрактные классы

помимо обычных классов в c# есть **абстрактные классы**. класс обычно задаёт план определённого рода объектов: класс `Car` описывает машины, класс `Person` описывает людей, и в эти классы вкладываются свойства, поля и методы, которые описывают состояние и поведение таких объектов. часть сущностей, которые требуется выразить в языке, не имеет конкретного воплощения. геометрической фигуры как таковой не существует: есть круг, прямоугольник, квадрат, но отдельного объекта «просто фигура» нет. при этом круг и прямоугольник имеют общие операции и оба являются фигурами. для описания сущностей без конкретного воплощения и предназначены абстрактные классы.

абстрактный класс устроен как обычный класс. он может иметь переменные, методы, конструкторы и свойства. при определении используется ключевое слово **abstract**:

```c#


abstract class Transport

{

	public void Move()

    {

		Console.WriteLine("Транспортное средство движется");

    }

}
```

транспортное средство здесь есть абстракция без конкретного воплощения. существуют легковые и грузовые машины, самолёты, морские суда, космические корабли, но объекта «транспортное средство вообще» нет. общее у всех этих сущностей то, что они перемещаются. метод `Move` эмулирует это перемещение.

главное отличие абстрактного класса от обычного в том, что конструктор абстрактного класса нельзя использовать для создания экземпляра. такая запись отвергается компилятором:

```c#
Transport tesla = new Transport();
```

запрет статический: тип, помеченный `abstract`, считается незавершённым как значение, даже если в нём нет абстрактных членов. экземпляр создаётся только для конкретного производного класса, а конструктор абстрактного класса участвует лишь в цепочке инициализации базовой части.

при этом абстрактный класс полезен как носитель общего функционала, который производные классы наследуют и используют:

```c#


Transport car = new Car();

Transport ship = new Ship();

Transport aircraft = new Aircraft();



car.Move();

ship.Move();

aircraft.Move();

abstract class Transport

{

	public void Move()

    {

		Console.WriteLine("Транспортное средство движется");

    }

}

// класс корабля

class Ship : Transport { }

// класс самолета

class Aircraft : Transport { }

// класс машины

class Car : Transport { }
```

от класса `Transport` наследуются три класса, представляющие различные типы транспортных средств. общая черта этих классов в том, что они перемещаются с помощью метода `Move()`.

выше зафиксировано, что конструктор абстрактного класса нельзя вызвать, чтобы получить экземпляр этого класса. сам конструктор абстрактный класс определять может:

```c#


Transport car = new Car("машина");

Transport ship = new Ship("корабль");

Transport aircraft = new Aircraft("самолет");



car.Move();			// машина движется

ship.Move();		// корабль движется

aircraft.Move();	// самолет движется

abstract class Transport

{

    public string Name { get; }

    // конструктор абстрактного класса Transport

    public Transport(string name)

    {

		Name = name;

    }

    public void Move() =>Console.WriteLine($"{Name} движется");

}

// класс корабля

class Ship : Transport 

{

	// вызываем конструктор базового класса

	public Ship(string name) : base(name) { }

}

// класс самолета

class Aircraft : Transport

{

	public Aircraft(string name) : base(name) { }

}

// класс машины

class Car : Transport

{

	public Car(string name) : base(name) { }

}
```

в абстрактном классе `Transport` определён конструктор. через параметр он устанавливает значение свойства `Name`, которое хранит название транспортного средства. производные классы обязаны в своих конструкторах вызвать этот конструктор: инициализация базовой части объекта идёт только через цепочку `base(...)`, потому что отдельного экземпляра `Transport` не существует.

### абстрактные члены классов

кроме обычных свойств и методов абстрактный класс может иметь абстрактные члены. они определяются ключевым словом **abstract** и не содержат реализации. абстрактными могут быть:

- методы

- свойства

- индексаторы

- события

абстрактные члены класса не должны иметь модификатор `private`: производный класс не смог бы обратиться к закрытому члену, чтобы его реализовать. производный класс обязан переопределить и реализовать все абстрактные методы и свойства базового абстрактного класса. при переопределении такой метод или свойство объявляется с модификатором **override**, как и при обычном переопределении виртуальных методов и свойств. если класс имеет хотя бы один абстрактный метод, абстрактное свойство, индексатор или событие, сам класс должен быть определён как **абстрактный**.

абстрактные члены, как и виртуальные, входят в полиморфный интерфейс типа. виртуальный метод передаёт наследнику готовую реализацию, которую тот может заменить. абстрактный метод передаёт наследнику только контракт: сигнатуру и слот в таблице виртуальных методов. реализация в базовом классе отсутствует, слот заполняется в конкретном производном классе. абстрактный метод неявно виртуален: модификатор `virtual` вместе с `abstract` не записывается.

#### абстрактные методы

в примере с транспортными средствами метод `Move` описывает передвижение. различные типы транспорта перемещаются по-разному: ездят по земле, летят по воздуху, плывут по воде. метод `Move` можно сделать абстрактным и переложить реализацию на производные классы:

```c#


abstract class Transport

{

    public abstract void Move();

}

// класс корабля

class Ship : Transport 

{

	// мы должны реализовать все абстрактные методы и свойства базового класса

	public override void Move()

    {

		Console.WriteLine("Корабль плывет");

    }

}

// класс самолета

class Aircraft : Transport

{

	public override void Move()

	{

		Console.WriteLine("Самолет летит");

	}

}

// класс машины

class Car : Transport

{

	public override void Move()

	{

		Console.WriteLine("Машина едет");

	}

}
```

применение классов:

```c#


Transport car = new Car();

Transport ship = new Ship();

Transport aircraft = new Aircraft();



car.Move();			// машина едет

ship.Move();		// корабль плывет

aircraft.Move();	// самолет летит
```

вызов через ссылку статического типа `Transport` попадает в реализацию динамического типа. это та же диспетчеризация через таблицу виртуальных методов, что и у `override`, только базовой реализации, которую можно было бы вызвать, у абстрактного метода нет.

#### абстрактные свойства

абстрактные свойства определяются похоже на автосвойства:

```c#


abstract class Transport

{

	// абстрактное свойство для хранения скорости

    public abstract int Speed { get; set; }	

}

// класс корабля

class Ship: Transport

{

	int speed;

    public override int Speed 

	{ 

		get => speed; 

		set => speed = value; 

	}

}



class Aircraft : Transport

{

	public override int Speed { get; set; }

}
```

в классе `Transport` определено абстрактное свойство `Speed`, которое должно хранить скорость транспортного средства. запись похожа на автосвойство, но автосвойством не является. у объявления нет реализации, поэтому у него только пустые блоки `get` и `set`, и компилятор не создаёт для него поле. в производных классах свойство переопределяется либо как полноценное свойство с явным полем, как в классе `Ship`, либо как автоматическое, как в классе `Aircraft`. хранение значения появляется только в той реализации, которая закрывает абстрактный слот.

#### отказ от реализации абстрактных членов

производный класс обязан реализовать все абстрактные члены базового класса. от реализации можно отказаться, но тогда производный класс тоже должен быть определён как абстрактный:

```c#


Transport tesla = new Auto();

tesla.Move();			// легковая машина едет

abstract class Transport

{

    public abstract void Move();

}

// класс машины

abstract class Car : Transport{}



class Auto: Car

{

	public override void Move()

	{

		Console.WriteLine("легковая машина едет");

	}

}
```

класс `Car` не реализует абстрактный метод `Move` базового класса `Transport` и поэтому тоже определён как абстрактный. абстрактность распространяется вниз по иерархии, пока конкретный класс не закроет все унаследованные абстрактные слоты. любые неабстрактные классы, производные от `Car`, всё равно должны реализовать все унаследованные абстрактные методы и свойства.

### пример абстрактного класса

стандартный пример такой иерархии составляет система геометрических фигур. геометрической фигуры как таковой не существует. есть круг, прямоугольник, квадрат, но просто фигуры нет. круг и прямоугольник имеют общие операции, периметр и площадь, и оба являются фигурами:

```c#


// абстрактный класс фигуры

abstract class Shape

{

    // абстрактный метод для получения периметра

    public abstract double GetPerimeter();

    // абстрактный метод для получения площади

    public abstract double GetArea();

}

// производный класс прямоугольника

class Rectangle : Shape

{

    public float Width { get; set; }

    public float Height { get; set; }



    // переопределение получения периметра

    public override double GetPerimeter() => Width * 2 + Height * 2;

    // переопрелеление получения площади

    public override double GetArea() => Width * Height;

}

// производный класс окружности

class Circle : Shape

{

	public double Radius { get; set; }



	// переопределение получения периметра

	public override double GetPerimeter() => Radius * 2 * 3.14;

	// переопрелеление получения площади

	public override double GetArea() => Radius * Radius * 3.14;

}
```

применение классов:

```c#


var rectanle = new Rectangle { Width = 20, Height = 20 };

var circle = new Circle { Radius = 200 };

PrintShape(rectanle); // Perimeter: 80   Area: 400

PrintShape(circle);	// Perimeter: 1256  Area: 125600



void PrintShape(Shape shape)

{

	Console.WriteLine($"Perimeter: {shape.GetPerimeter()}  Area: {shape.GetArea()}");

}
```

метод `PrintShape` принимает ссылку на абстрактный тип `Shape`. периметр и площадь вычисляются реализацией того конкретного класса, объект которого передан. добавить новую фигуру означает добавить новый конкретный класс с теми же двумя методами, не меняя код, который уже работает через `Shape`.

от интерфейса абстрактный класс отличается тем, что может хранить состояние и готовые методы, а класс в c# наследует только один класс. интерфейсов у типа может быть несколько. абстрактный класс выбирают, когда у семейства типов есть общая реализация или общие поля. интерфейс выбирают, когда нужно задать только контракт.
