**событие** сообщает, что в объекте произошло определённое действие. подписка на событие позволяет выполнить внешний код в ответ на это действие. по устройству событие опирается на делегат, но снаружи доступны только подписка и отписка. вызвать событие может код того класса, в котором событие объявлено. этим событие отличается от поля делегата, которое внешний код мог бы вызвать или заменить целиком.

пример, класс банковского счёта:

```c#

class Account
{
    // сумма на счете
    public int Sum { get; private set; }
    // в конструкторе устанавливаем начальную сумму на счете
    public Account(int sum) => Sum = sum;
    // добавление средств на счет
    public void Put(int sum) => Sum += sum;
    // списание средств со счета
    public void Take(int sum)
    {
        if (Sum >= sum)
        {
            Sum -= sum;
        }
    }
}
```

конструктор записывает начальную сумму в свойство Sum. метод Put увеличивает Sum, метод Take уменьшает Sum, если на счёте достаточно средств. при нехватке средств Take состояние не меняет. использование класса в программе, пополнение и два снятия:

```c#

Account account = new Account(100);
account.Put(20);    // добавляем на счет 20
Console.WriteLine($"Сумма на счете: {account.Sum}");
account.Take(70);   // пытаемся снять со счета 70
Console.WriteLine($"Сумма на счете: {account.Sum}");
account.Take(180);  // пытаемся снять со счета 180
Console.WriteLine($"Сумма на счете: {account.Sum}");
```

консольный вывод:

```bash

Сумма на счете: 120
Сумма на счете: 50
Сумма на счете: 50
```

арифметика счёта выполняется, как задано методами: 100 + 20 даёт 120, снятие 70 оставляет 50, снятие 180 не проходит, и сумма остаётся 50. уведомления о результате операции в этом варианте нет.

если уведомление вписать в сам метод, Put можно переписать так:

```c#

public void Put(int sum)    
{
	Sum += sum;
	Console.WriteLine($"На счет поступило: {sum}");
}
```

после этого консоль покажет факт зачисления. на момент определения класса конкретное действие в ответ на зачисление часто ещё неизвестно. это может быть вывод на консоль, письмо по электронной почте или sms. класс Account может лежать в отдельной библиотеке и подключаться к разным проектам. в графическом приложении сообщение нужно показать в окне, а не в консоли. другой разработчик той же библиотеки может выбрать иное действие. все эти варианты сводятся к одному приёму: класс сообщает о факте операции, а реакция задаётся снаружи. для этого и объявляется событие.

### определение и вызов событий

событие объявляется в классе служебным словом **event**. после него указывается тип делегата, который задаёт сигнатуру обработчиков:

```c#

delegate void AccountHandler(string message);
event AccountHandler Notify;
```

сначала объявлен делегат AccountHandler с одним параметром типа string. затем служебным словом **event** объявлено событие Notify, представляющее этот делегат. имя события выбирается свободно, но тип события обязан быть типом делегата: именно делегат определяет, какие обработчики можно подписать и какие аргументы получат при вызове.

объявленное событие вызывается по имени, как метод:

```c#

Notify("Произошло действие");
```

Notify представляет AccountHandler и потому принимает одну строку. при вызове эта строка передаётся всем подписанным обработчикам.

если обработчик не подписан, событие равно null. вызов null даёт исключение. перед вызовом событие проверяют. явная проверка:

```c#
if(Notify !=null) Notify("Произошло действие");
```

та же проверка через условный вызов:

```c#
Notify?.Invoke("Произошло действие");
```

событие является делегатом, поэтому его можно вызвать методом **Invoke()**, передав аргументы параметров. оператор `?.` пропускает вызов, когда событие равно null.

объявление, изменение суммы и вызов собираются в одном классе:

```c#

class Account
{
    public delegate void AccountHandler(string message);
    public event AccountHandler? Notify;              // 1.Определение события
    public Account(int sum) => Sum = sum;
    public int Sum { get; private set; }
    public void Put(int sum)
    {
        Sum += sum;
        Notify?.Invoke($"На счет поступило: {sum}");   // 2.Вызов события 
    }
    public void Take(int sum)
    {
        if (Sum >= sum)
        {
            Sum -= sum;
            Notify?.Invoke($"Со счета снято: {sum}");   // 2.Вызов события
        }
        else
        {
            Notify?.Invoke($"Недостаточно денег на счете. Текущий баланс: {Sum}"); ;
        }
    }
}
```

событие Notify сообщает о трёх исходах: средства зачислены, средства сняты, на счёте недостаточно денег. текст исхода передаётся аргументом. вызов стоит после изменения Sum в успешных ветвях и вместо изменения в ветви нехватки средств. тип события допускает null, что соответствует отсутствию подписчиков.

### добавление обработчика события

с событием связывают один или несколько обработчиков. обработчик и есть код, который выполняется при вызове события. чаще всего обработчик является методом. список параметров и возвращаемый тип обработчика должны совпадать с делегатом события. подписка записывается операцией **+=**:

```c#
Notify += обработчик события;
```

обработчик для Notify в программе пополнения и снятия:

```c#

Account account = new Account(100);
account.Notify += DisplayMessage;   // Добавляем обработчик для события Notify
account.Put(20);    // добавляем на счет 20
Console.WriteLine($"Сумма на счете: {account.Sum}");
account.Take(70);   // пытаемся снять со счета 70
Console.WriteLine($"Сумма на счете: {account.Sum}");
account.Take(180);  // пытаемся снять со счета 180
Console.WriteLine($"Сумма на счете: {account.Sum}");

void DisplayMessage(string message) => Console.WriteLine(message);
```

обработчиком назначен метод DisplayMessage. его сигнатура совпадает с AccountHandler: один параметр типа string, возвращаемый тип void. при вызове `Notify?.Invoke()` выполняется DisplayMessage, и в параметр message попадает строка, переданная в `Notify?.Invoke()`. в этом методе строка печатается. на месте печати может стоять любая другая логика с тем же параметром.

если обработчик не подписан, `Notify?.Invoke()` ничего не выполняет: событие Notify равно null, и условный вызов на этом заканчивается.

консольный вывод программы:

```consoletext

На счет поступило: 20
Сумма на счете: 120
Со счета снято: 70
Сумма на счете: 50
Недостаточно денег на счете. Текущий баланс: 50
Сумма на счете: 50
```

класс Account с событием можно вынести в отдельную библиотеку и подключить к любому проекту. проект задаёт собственные обработчики, класс счёта при этом не меняется.

### добавление и удаление обработчиков

на одно событие подписывают несколько обработчиков и снимают их в любой момент. снятие записывается операцией **-=**:

```c#

Account account = new Account(100);
account.Notify += DisplayMessage;       // добавляем обработчик DisplayMessage
account.Notify += DisplayRedMessage;    // добавляем обработчик DisplayRedMessage
account.Put(20);    // добавляем на счет 20
account.Notify -= DisplayRedMessage;     // удаляем обработчик DisplayRedMessage
account.Put(50);    // добавляем на счет 50

void DisplayMessage(string message) => Console.WriteLine(message);
void DisplayRedMessage(string message)
{
    // Устанавливаем красный цвет символов
    Console.ForegroundColor = ConsoleColor.Red;
    Console.WriteLine(message);
    // Сбрасываем настройки цвета
    Console.ResetColor();
}
```

консольный вывод:

```consoletext

На счет поступило: 20
На счет поступило: 20
На счет поступило: 50
```

на первое зачисление подписаны оба метода, поэтому сообщение печатается дважды, второй раз красным: DisplayRedMessage перед печатью ставит Console.ForegroundColor в ConsoleColor.Red и после печати вызывает Console.ResetColor. затем DisplayRedMessage снимается. второе зачисление, Put(50), выполняет только оставшийся DisplayMessage, и строка одна.

обработчиком может быть не только обычный метод, но и делегат, анонимный метод или лямбда-выражение. подписка методом и подписка явно созданным делегатом:

```c#

Account acc = new Account(100);
// установка делегата, который указывает на метод DisplayMessage
acc.Notify += new Account.AccountHandler(DisplayMessage);
// установка в качестве обработчика метода DisplayMessage
acc.Notify += DisplayMessage;       // добавляем обработчик DisplayMessage

acc.Put(20);    // добавляем на счет 20

void DisplayMessage(string message) => Console.WriteLine(message);
```

обе подписки добавляют в список вызова один и тот же метод DisplayMessage. разницы в том, какой код выполнится при вызове, нет: конструктор делегата и преобразование группы методов дают экземпляр, ссылающийся на DisplayMessage. в списке при этом два вхождения, поэтому одно зачисление вызовет печать дважды.

анонимный метод в роли обработчика:

```c#

Account acc = new Account(100);
acc.Notify += delegate (string mes)
{
    Console.WriteLine(mes);
};
acc.Put(20);
```

лямбда-выражение в роли обработчика:

```c#

Account account = new Account(100);
account.Notify += message => Console.WriteLine(message);
account.Put(20);
```

во всех трёх формах в список вызова попадает делегат, совместимый с AccountHandler. различается только синтаксис, которым задано тело.

### управление обработчиками

аксессоры **add** и **remove** перехватывают подписку и отписку. нужна такая форма редко: обычные += и -= достаточны, пока классу не требуется собственная реакция на изменение списка. форма с аксессорами выглядит так:

```c#

class Account
{
    public delegate void AccountHandler(string message);
    AccountHandler? notify;
    public event AccountHandler Notify
    {
        add
        {
            notify += value;
            Console.WriteLine($"{value.Method.Name} добавлен");
        }
        remove
        {
            notify -= value;
            Console.WriteLine($"{value.Method.Name} удален");
        }
    }
    public Account(int sum) => Sum = sum;
    public int Sum { get; private set; }
    public void Put(int sum)
    {
        Sum += sum;
        notify?.Invoke($"На счет поступило: {sum}");   // 2.Вызов события 
    }
    public void Take(int sum)
    {
        if (Sum >= sum)
        {
            Sum -= sum;
            notify?.Invoke($"Со счета снято: {sum}");   // 2.Вызов события
        }
        else
        {
            notify?.Invoke($"Недостаточно денег на счете. Текущий баланс: {Sum}"); ;
        }
    }
}
```

при собственных аксессорах компилятор не создаёт скрытое поле делегата. событие разделяется на две части. первая часть, поле делегата, через которое класс вызывает обработчики:

```c#
AccountHandler notify;
```

в полном объявлении класса поле названо notify и допускает null. фрагмент выше показывает роль этого поля: оно хранит список вызова. имя Notify с аксессорами само по себе список не хранит.

вторая часть задаёт аксессоры. аксессор **add** выполняется при операции +=. добавляемый обработчик доступен как **value**. у него можно прочитать сведения о методе, например имя через value.Method.Name, и выполнить дополнительное действие. здесь действие сводится к печати и к добавлению value в список:

```c#

add
{
	notify += value;
	Console.WriteLine($"{value.Method.Name} добавлен");
}
```

аксессор **remove** выполняется при операции -=. дополнительная логика записывается здесь так же:

```c#

remove
{
	notify -= value;
	Console.WriteLine($"{value.Method.Name} удален");
}
```

внутри класса событие вызывается через поле notify. снаружи для подписки и отписки используется имя Notify. внешний код не может вызвать Notify как метод: при объявленных аксессорах вызов остаётся привилегией класса и идёт через поле.

```c#

Account acc = new Account(100);
acc.Notify += DisplayMessage;       // добавляем обработчик DisplayMessage
acc.Put(20);    // добавляем на счет 20
acc.Notify -= DisplayMessage;     // удаляем обработчик DisplayMessage
acc.Put(20);    // добавляем на счет 20

void DisplayMessage(string message) => Console.WriteLine(message);
```

консольный вывод программы:

```consoletext

DisplayMessage добавлен
На счет поступило: 20
DisplayMessage удален
```

первая строка печатается аксессором add в момент подписки DisplayMessage. Put(20) вызывает notify, и обработчик печатает сообщение о зачислении. снятие подписки печатает строку аксессора remove. второй вызов Put(20) по-прежнему увеличивает Sum, но строку уведомления уже не печатает: список вызова пуст, и `notify?.Invoke` ничего не вызывает.

### передача данных события

обработчику часто нужны сведения о произошедшем, а не один готовый текст. для этого рядом со счётом объявляется класс **AccountEventArgs**:

```c#

class AccountEventArgs
{
    // Сообщение
    public string Message{get;}
    // Сумма, на которую изменился счет
    public int Sum {get;}
    public AccountEventArgs(string message, int sum)
    {
        Message = message;
        Sum = sum;
    }
}
```

у класса два свойства. Message хранит текст сообщения, Sum хранит сумму, на которую изменился счёт. оба значения задаются конструктором и далее только читаются.

класс Account переводится на этот носитель данных: делегат принимает отправителя и объект AccountEventArgs.

```c#

class Account
{
    public delegate void AccountHandler(Account sender, AccountEventArgs e);
    public event AccountHandler? Notify;
	
    public int Sum { get; private set; }
	
    public Account(int sum) => Sum = sum;
	
    public void Put(int sum)
    {
        Sum += sum;
        Notify?.Invoke(this, new AccountEventArgs($"На счет поступило {sum}", sum));
    }
    public void Take(int sum)
    {
        if (Sum >= sum)
        {
            Sum -= sum;
            Notify?.Invoke(this, new AccountEventArgs($"Сумма {sum} снята со счета", sum));
        }
        else
        {
            Notify?.Invoke(this, new AccountEventArgs("Недостаточно денег на счете", sum));
        }
    }
}
```

относительно предыдущей версии Account изменились число параметров делегата и число аргументов в вызове события. первый параметр AccountHandler принимает объект, который вызвал событие, то есть текущий экземпляр Account, и в вызов передаётся this. второй параметр принимает AccountEventArgs. объект создаётся в точке вызова, и в конструктор входят текст исхода и сумма операции. при нехватке средств сумма в объекте события является запрошенной суммой, а баланс счёта через этот объект не передаётся: его обработчик читает у отправителя.

основная программа подстраивается под новую сигнатуру:

```c#

Account acc = new Account(100);
acc.Notify += DisplayMessage;
acc.Put(20);
acc.Take(70);
acc.Take(150);

void DisplayMessage(Account sender, AccountEventArgs e)
{
    Console.WriteLine($"Сумма транзакции: {e.Sum}");
    Console.WriteLine(e.Message);
    Console.WriteLine($"Текущая сумма на счете: {sender.Sum}");
}
```

в обработчике DisplayMessage меняются число параметров и то, как они используются. первый параметр даёт отправителя, счёт, над которым выполнена операция, поэтому текущая сумма читается как sender.Sum. второй параметр даёт состояние операции: текст в e.Message и сумму транзакции в e.Sum. форма сигнатуры, отправитель и отдельный объект с данными, совпадает с обычным для библиотеки .net образцом `(object sender, EventArgs e)`. класс AccountEventArgs при этом объявлен самостоятельно и от EventArgs не наследует: он несёт только сообщение и сумму, которые нужны этому примеру. способ уведомления, консоль, файл или окно, задаётся обработчиком и в методы Put и Take не входит.
