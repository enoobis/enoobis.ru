ранее разбирались элементарные типы: `int`, `byte`, `double`, `string`, `object` и другие. есть и составные типы: структуры, перечисления, классы. все эти типы делятся на типы значений, их же называют значимыми типами (value types), и ссылочные типы (reference types). различие задаётся тем, что именно хранит переменная: само значение или ссылку на значение.

типы значений:

- целочисленные типы (`byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`)
- типы с плавающей запятой (`float`, `double`)
- тип `decimal`
- тип `bool`
- тип `char`
- перечисления `enum`
- структуры (`struct`)

ссылочные типы:

- тип `object`
- тип `string`
- классы (`class`)
- интерфейсы (`interface`)
- делегаты (`delegate`)

чтобы увидеть различие, нужна организация памяти в .net. память делится на стек и кучу (heap). параметры и локальные переменные метода, которые имеют тип значений, размещают само значение в стеке. стек есть структура данных, растущая снизу вверх: каждый новый элемент помещается поверх предыдущего. время жизни переменных таких типов ограничено их контекстом. физически стек есть область памяти в адресном пространстве процесса.

когда программа запускается, в конце блока, зарезервированного под стек, устанавливается указатель стека. при помещении данных указатель переставляется так, чтобы снова указывать на свободное место. при вызове каждого метода в стеке выделяется область, фрейм стека, и в ней хранятся значения параметров и локальных переменных этого вызова.

например:

```c#


class Program

{

	static void Main(string[] args)

    {

		Calculate(5);

    }



	static void Calculate(int t)

    {

		int x = 6;

        int y = 7;

        int z = y + t;

	}

}
```

при запуске такой программы в стеке определяются два фрейма: для метода `Main`, потому что он вызывается при старте, и для метода `Calculate`.

![структура стека в языке программирования c#](/uploads/course-lectures/f43581924ba5a226c95ca6c06712b068e54a7f86.png)

при вызове `Calculate` в его фрейм помещаются значения `t`, `x`, `y` и `z`. они существуют в контексте этого метода. когда метод завершается, память кадра может быть использована другими вызовами.

если параметр или локальная переменная имеет тип значений, в стеке хранится само значение. параметр и локальные переменные `Calculate` имеют тип `int`, поэтому в кадре лежат числа, а не адреса.

ссылочные типы хранятся в куче, её же называют хипом. кучу можно представить как неупорядоченный набор разнородных объектов. физически это остальная память, доступная процессу.

при создании объекта ссылочного типа в стек помещается ссылка на адрес в куче. когда объект больше не используется, вступает сборщик мусора. он видит, что ссылок на объект в куче не осталось, условно удаляет объект и освобождает память: фактически помечает участок как пригодный для других данных. немедленного обнуления байт модель не обещает.

если изменить метод `Calculate`:

```c#


static void Calculate(int t)

{

	object x = 6;

    int y = 7;

    int z = y + t;

}
```

значение, связанное с `x`, хранится в куче, потому что `object` есть ссылочный тип, а в стеке хранится ссылка. литерал 6 имеет тип `int`. присваивание его в переменную типа `object` выполняет упаковку: число копируется в отдельный объект в куче, и `x` ссылается на этот объект. `y` и `z` по-прежнему лежат в кадре как значения `int`.

![ссылочные типы в куче в языке программирования c#](/uploads/course-lectures/4c52fba806e2df541c6ce75771efce322bdc0aa7.png)

### составные типы

дальше случай, когда тип значений и ссылочный тип составные: структура и класс.

```c#


State state1 = new State(); // State - структура, ее данные размещены в стеке

Country country1 = new Country(); // Country - класс, в стек помещается ссылка на адрес в хипе

                                  // а в хипе располагаются все данные объекта country1

struct State

{

    public int x;

    public int y;

}

class Country

{

    public int x;

    public int y;

}
```

в методе `Main` в стеке выделяется память под значение `state1`. затем в стеке создаётся ссылка `country1` (`Country country1`), а вызов конструктора с `new` выделяет место в куче (`new Country()`). ссылка в стеке хранит адрес того места в куче, где размещён объект.

![ссылычные типы и типы значений в c#](/uploads/course-lectures/0bd7c238161eb11f4daf829c11e073e905283eb6.png)

в стеке оказываются все поля структуры `state1` и ссылка на объект `country1` в куче. поля `x` и `y` структуры лежат прямо в кадре. поля класса лежат в объекте в куче, а в кадре только адрес.

если в структуре `State` объявлено ещё и поле ссылочного типа `Country`, хранение распадается на две части: где лежит ссылка и где лежит объект, на который она указывает.

```c#


State state1 = new State();

Country country1 = new Country();



struct State

{

    public int x;

    public int y;

    public Country country;

    public State()

    {

        x = 0;

        y = 0;

        country = new Country();

    }

}

class Country

{

    public int x;

    public int y;

}
```

значение `state1.country` есть ссылка на область кучи и хранится в стеке, внутри значения структуры. поля этого объекта `Country` хранятся в куче, потому что `state1.country` имеет ссылочный тип.

![стек и куча в языке программирования c#](/uploads/course-lectures/bfcf20821dcc283820458bd72c96db9baa3f606d.png)

та же граница видна и в другую сторону. если структура является полем класса, само значение структуры лежит внутри объекта в куче, а не в кадре стека. правило «значимое в стеке» относится к локальным переменным и параметрам, а не к любому вхождению значимого типа в программе.

### копирование значений

тип данных учитывают при копировании. присваивание объекту значимого типа передаёт копию данных. присваивание объекту ссылочного типа передаёт не копию объекта, а ссылку на этот объект в куче.

```c#


State state1 = new State(); // Структура State

State state2 = new State();

state2.x = 1;

state2.y = 2;

state1 = state2;

state2.x = 5; // state1.x=1 по-прежнему

Console.WriteLine(state1.x); // 1

Console.WriteLine(state2.x); // 5



Country country1 = new Country(); // Класс Country

Country country2 = new Country();

country2.x = 1;

country2.y = 4;

country1 = country2;

country2.x = 7; // теперь и country1.x = 7, так как обе ссылки и country1 и country2 

                // указывают на один объект в хипе

Console.WriteLine(country1.x); // 7

Console.WriteLine(country2.x); // 7
```

`state1` есть структура, поэтому присваивание `state1 = state2` копирует значение `state2`. после этого изменение `state2.x` не затрагивает копию: `state1.x` остаётся равным 1, а `state2.x` становится равным 5. вывод подтверждает, что это два независимых значения.

объект класса `country1` при присваивании `country1 = country2` получает ссылку на тот же объект, на который указывает `country2`. с изменением `country2` меняется и `country1`: обе переменные наблюдают одно состояние в куче, и обе печатают 7. скопирована ссылка, объект один.

### ссылочные типы внутри типов значений

внутри структуры может быть поле ссылочного типа, например поле класса.

```c#


State state1 = new State();

State state2 = new State();



state2.country.x = 5;

state1 = state2;

state2.country.x = 8; // теперь и state1.country.x=8, так как state1.country и state2.country

                      // указывают на один объект в хипе

Console.WriteLine(state1.country.x); // 8

Console.WriteLine(state2.country.x); // 8



struct State

{

    public int x;

    public int y;

    public Country country;

    public State()

    {

        x = 0;

        y = 0;

        country = new Country(); // выделение памяти для объекта Country

    }

}

class Country

{

    public int x;

    public int y;

}
```

поле ссылочного типа в структуре хранит в стеке ссылку на объект в куче. присваивание `state1 = state2` копирует структуру, и вместе с ней копируется ссылка `country`. `state1` получает ссылку на тот же объект `Country` в куче. изменение `state2.country` поэтому меняет и `state1.country`: оба поля указывают на один объект, и чтение `x` даёт 8. копирование структуры поверхностное. вложенный объект заново не создаётся, клонируется только ссылка. поля `x` и `y` самой структуры при этом копируются как числа и дальше живут независимо.

### объекты классов как параметры методов

расположение объектов в памяти нужно учитывать при передаче параметров по значению и по ссылке. если параметр есть объект класса, у передачи появляются отдельные следствия. метод принимает объект `Person`:

```c#


Person p = new Person { name = "Tom", age = 23 };

ChangePerson(p);



Console.WriteLine(p.name); // Alice

Console.WriteLine(p.age); // 23



void ChangePerson(Person person)

{

    // сработает

    person.name = "Alice";

    // сработает только в рамках данного метода

    person = new Person { name = "Bill", age = 45 };

    Console.WriteLine(person.name); // Bill

}



class Person

{

    public string name = "";

    public int age;

}
```

при передаче объекта класса по значению в метод попадает копия ссылки. копия указывает на тот же объект, что и исходная ссылка, поэтому через неё можно изменить отдельные поля и свойства. подменить сам объект, который видит вызывающий код, нельзя. в примере выполняется `person.name = "Alice"`: меняется поле общего объекта, и после возврата `p.name` равно `"Alice"`. возраст остаётся 23, метод его не записывал.

другая строка, `person = new Person { name = "Bill", age = 45 }`, создаёт новый объект в куче, и параметр `person` начинает ссылаться на него. присваивание меняет локальную копию ссылки. даже если после этого менять новый объект, ссылка `p` в `Main` не затрагивается: `p` по-прежнему указывает на прежний объект. внутри метода печать показывает `"Bill"`, а `p.name` после вызова остаётся `"Alice"`.

при передаче параметра по ссылке, с ключевым словом `ref`, в метод передаётся сама переменная со ссылкой на объект. можно изменить и поля объекта, и то, какой объект наблюдает вызывающий код:

```c#


Person p = new Person { name = "Tom", age = 23 };

ChangePerson(ref p);



Console.WriteLine(p.name); // Bill

Console.WriteLine(p.age); // 45



void ChangePerson(ref Person person)

{

    // сработает

    person.name = "Alice";

    // сработает

    person = new Person { name = "Bill", age = 45 };

}



class Person

{

    public string name = "";

    public int age;

}
```

операция `new` создаёт новый объект в куче, и ссылка `person` указывает на него. это та же переменная, что `p` в `Main`: параметр `ref` не копирует ссылку в отдельную локальную ячейку, а даёт имя исходной ячейке. после возврата `p.name` равно `"Bill"`, а `p.age` равно 45. прежний объект с именем `"Tom"` остаётся без ссылки из `p` и может быть собран сборщиком мусора, если других ссылок на него нет.
