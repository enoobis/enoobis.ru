помимо параметров с модификатором **ref**, которые передают в метод ссылку на уже существующую переменную, c# позволяет вернуть ссылку из метода и завести локальную переменную, которая эту ссылку хранит. такая ссылка именует область памяти, и присваивание по ней пишет в исходную переменную.

### переменная-ссылка

локальная переменная-ссылка (ref local) объявляется ключевым словом **ref** перед типом:

```c#

int x = 5;
ref int xRef = ref x;
```

`xRef` именует ту же область памяти, в которой лежит `x`. поэтому **ref** стоит и перед инициализатором.

объявить ссылку без инициализатора нельзя. ссылка обязана сразу именовать существующую область. следующий фрагмент не компилируется:

```c#

ref int xRef;	// ошибка
```

через полученную ссылку значение меняется в обе стороны. запись в ссылку меняет исходную переменную, запись в исходную переменную видна по ссылке:

```c#

int x = 5;
ref int xRef = ref x;
Console.WriteLine(x); // 5
xRef = 125;
Console.WriteLine(x); // 125
x = 625;
Console.WriteLine(xRef); // 625
```

### ссылка как результат функции

чтобы функция вернула ссылку, **ref** ставится в сигнатуре перед типом результата и в теле после **return**:

```c#

int[] numbers = { 1, 2, 3, 4, 5, 6, 7 };
ref int numberRef = ref Find(4, numbers); // ищем число 4 в массиве
numberRef = 9; // заменяем 4 на 9
Console.WriteLine(numbers[3]); // 9

ref int Find(int number, int[] numbers)
{
    for (int i = 0; i < numbers.Length; i++)
    {
        if (numbers[i] == number)
        {
            return ref numbers[i]; // возвращаем ссылку на адрес, а не само значение
        }
    }
    throw new IndexOutOfRangeException("число не найдено");
}
```

`Find` ищет число в массиве и возвращает ссылку на его элемент. тип результата поэтому записан как **ref int**. в точке возврата то же слово стоит после `return`:

```c#
return ref numbers[i];
```

результатом становится адрес элемента. присваивание `numberRef = 9` записывает 9 в этот элемент, и `numbers[3]` меняется.

локальная переменная, которая принимает ссылку, тоже объявляется с **ref**, и вызов метода пишется с **ref**:

```c#
ref int numberRef = ref Find(7, numbers);
```

`numberRef` после этого именует тот же `int`, что и найденный элемент, и последующая запись через переменную меняет его.

другой пример возвращает ссылку на большее из двух чисел:

```c#

int a = 5;
int b = 8;
ref int pointer = ref Max(ref a, ref b);
pointer = 34;   // меняем значением максимального числа
Console.WriteLine($"a: {a}  b: {b}"); // a: 5   b: 34

ref int Max(ref int n1, ref int n2)
{
    if (n1 > n2)
		return ref n1;

    else
        return ref n2;
}
```

параметры здесь тоже объявлены с **ref**. это необходимое условие возврата: `return ref n1` отдаёт область памяти вызывающего. если параметр передан по значению, ссылаться на него из возврата нельзя: копия параметра исчезнет вместе со стековым кадром.

у метода, который возвращает ссылку, тип результата не бывает `void`: ссылке не на что указывать, если значения нет. кроме того, такой метод не возвращает:

- значение `null`

- константу

- значение перечисления `enum`

- свойство класса или структуры

- поле для чтения, помеченное как read-only

во всех этих случаях нет изменяемой области памяти, которая пережила бы вызов. `null` не именует ячейку. константа и значение `enum` существуют как готовые значения, изменяемой переменной за ними нет. обычное свойство читается и пишется методами. отдельной ячейки, которую можно отдать наружу, у него нет. поле read-only нельзя открыть на запись через возвращаемую ссылку: иначе ограничение обходилось бы присваиванием по ссылке. вернуть ссылку можно на элемент массива, на параметр `ref` и на другое хранилище, время жизни которого не короче вызова.
