класс System.String покрывает чтение, поиск и сборку текста, но строка, которую он представляет, неизменяема. любая операция, меняющая содержимое, выделяет новый объект и копирует в него символы. удаление одного символа само по себе дёшево. когда таких операций много, а текст длинный, повторное копирование растущего префикса даёт суммарную стоимость порядка квадрата длины: каждая конкатенация в цикле заново переписывает уже накопленный текст. для этой ситуации в .net есть класс **StringBuilder** из пространства имён `System.Text`. он хранит изменяемый буфер символов и дописывает данные в уже выделенную память, пока в ней остаётся место.

### создание StringBuilder

у класса несколько конструкторов. пустой построитель создаётся конструктором без параметров:

```c#


using System.Text;



StringBuilder sb = new StringBuilder();
```

начальное содержимое можно передать сразу:

```c#


StringBuilder sb = new StringBuilder("Привет мир");
```

строка, накопленная в буфере, извлекается методом `ToString()`. метод копирует символы буфера в новый неизменяемый объект string:

```c#


var sb = new StringBuilder("Hello World");

Console.WriteLine(sb.ToString());    //  Hello World
```

тот же текст печатается и при передаче объекта StringBuilder в `Console.WriteLine`. перегрузка для `object` вызывает `ToString`:

```c#


var sb = new StringBuilder("Hello World");

Console.WriteLine(sb);    //  Hello World
```

### длина и ёмкость StringBuilder

число уже записанных символов хранит свойство **Length**. отдельно хранится ёмкость выделенного буфера, свойство `Capacity`. ёмкость является размером памяти, зарезервированной под символы. если задать её заранее, повторные расширения буфера не выполняются, и сборка длинной строки обходится меньшим числом выделений.

правило начальной ёмкости такое. когда строка, переданная в конструктор, содержит не больше 16 символов, начальная ёмкость равна 16. когда начальная строка длиннее 16 символов, начальной ёмкостью становится длина этой строки.

проверка обоих свойств на короткой строке:

```c#


using System.Text;



StringBuilder sb = new StringBuilder("Привет мир");

Console.WriteLine($"Длина: {sb.Length}");		// Длина: 10

Console.WriteLine($"Емкость: {sb.Capacity}");	// Емкость: 16
```

длина равна 10, а ёмкость по умолчанию равна 16. построитель резервирует памяти больше, чем занимает текущий текст. когда при дальнейшем добавлении число символов превышает ёмкость, буфер перераспределяется. новая ёмкость как минимум покрывает требуемую длину и в типичном случае удваивается, то есть растёт в два и более раз.

если верхняя граница размера известна до начала сборки, ёмкость задаётся конструктором сразу, и последующие расширения не нужны:

```c#


var sb = new StringBuilder(32);
```

строка и ёмкость задаются вместе. второй аргумент является начальной ёмкостью, первый аргумент копируется в буфер:

```c#
var sb = new StringBuilder("Привет мир", 32);
```

если запрошенная ёмкость меньше длины переданной строки, конструктор поднимает ёмкость до длины строки: буфер не может быть короче уже размещённого текста.

### операции со строками в StringBuilder

для изменения буфера класс определяет методы:

- `Append`: добавляет подстроку в конец объекта StringBuilder

- `Insert`: вставляет подстроку в объект StringBuilder, начиная с заданного индекса

- `Remove`: удаляет заданное число символов, начиная с заданного индекса

- `Replace`: заменяет все вхождения символа или подстроки другим символом или подстрокой

- `AppendFormat`: добавляет в конец объекта StringBuilder подстроку, собранную по форматному шаблону, с теми же полями подстановки, что у `string.Format`

эти методы меняют текущий буфер и возвращают тот же экземпляр StringBuilder, поэтому вызовы можно ставить цепочкой. новый объект string на каждом шаге не создаётся. `ToString` в конце цепочки выполняет единственное копирование в неизменяемую строку.

рост буфера виден на методе **Append()**:

```c#


using System.Text;



var sb = new StringBuilder("Название: ");

Console.WriteLine(sb);   // Название: 

Console.WriteLine($"Длина: {sb.Length}"); // 10

Console.WriteLine($"Емкость: {sb.Capacity}"); // 16



sb.Append(" Руководство");

Console.WriteLine(sb);   // Название: Руководство

Console.WriteLine($"Длина: {sb.Length}"); // 22

Console.WriteLine($"Емкость: {sb.Capacity}"); // 32



sb.Append(" по C#");

Console.WriteLine(sb);   // Название: Руководство по C#

Console.WriteLine($"Длина: {sb.Length}"); // 28

Console.WriteLine($"Емкость: {sb.Capacity}"); // 32
```

при создании под строку короче 16 символов резервируется ёмкость 16. начальный текст `"Название: "` имеет длину 10, что и печатает первое чтение `Length`.

метод `Append` дописывает подстроку в конец. после первого добавления комментарий примера фиксирует длину 22. это больше начальной ёмкости 16, поэтому ёмкость удваивается до 32. если бы требуемая длина превысила и 32, ёмкость выросла бы так, чтобы вместить всю строку.

следующий `Append` доводит длину до 28. 28 не превосходит 32, нового выделения нет, `Capacity` остаётся 32. цена этого шага пропорциональна длине добавленного фрагмента. уже накопленный текст повторно не копируется.

остальные методы на одном и том же экземпляре:

```c#


var sb = new StringBuilder("Привет мир");

sb.Append("!");

sb.Insert(7, "компьютерный ");

Console.WriteLine(sb);	// Привет компьютерный мир!



// заменяем слово

sb.Replace("мир", "world");

Console.WriteLine(sb);	// Привет компьютерный world!



// удаляем 13 символов, начиная с 7-го

sb.Remove(7, 13);

Console.WriteLine(sb);	// Привет world!



// получаем строку из объекта StringBuilder

string text = sb.ToString();

Console.WriteLine(text);	// Привет world!
```

`Append("!")` дописывает восклицательный знак к `"Привет мир"`. `Insert(7, "компьютерный ")` вставляет текст, начиная с индекса 7, то есть перед словом "мир", и сдвигает хвост вправо. получается строка, которую комментарий показывает как `"Привет компьютерный мир!"`. `Replace("мир", "world")` заменяет все вхождения "мир" и даёт `"Привет компьютерный world!"`. `Remove(7, 13)` удаляет 13 символов, начиная с индекса 7. участок "компьютерный " как раз имеет такую длину, после удаления остаётся `"Привет world!"`. `ToString` копирует буфер в отдельную строку text. сам StringBuilder после этого сохраняет своё содержимое: извлечение строки буфер не очищает.

выбор между string и StringBuilder определяется числом изменений текста во время выполнения.

microsoft рекомендует класс String в следующих случаях:

- при небольшом числе операций и изменений над строками

- при фиксированном числе операций объединения. в этом случае компилятор может свести все объединения в одну операцию

- когда при сборке строки нужны операции поиска вроде `IndexOf` или `StartsWith`. у класса StringBuilder таких методов нет

класс StringBuilder рекомендуется в следующих случаях:

- когда число операций и изменений над строками к моменту компиляции неизвестно и выясняется во время выполнения

- когда таких операций ожидается много

к этому разделению добавляется оценка сложности. цепочка из фиксированного числа конкатенаций в одном выражении превращается в один вызов соединения, и квадратичного копирования нет. цикл вида `s = s + fragment` на каждой итерации копирует растущую строку, суммарно порядка n в квадрате по числу символов. `Append` при геометрическом росте ёмкости копирует каждый символ ограниченное число раз и в сумме линеен по длине результата. построитель при этом не предоставляет поиска по содержимому: чтобы найти подстроку, буфер сначала превращают в string. экземпляр StringBuilder не синхронизирован, одновременные вызовы методов из разных потоков его инвариант не сохраняют.
