классы и структуры часто оформляют отдельной библиотекой. библиотека компилируется в файл dll, и эту сборку затем подключают к другим проектам. один и тот же набор типов определяют один раз и либо ссылаются на него из нескольких проектов, либо передают другим разработчикам. граница видимости здесь совпадает со сборкой: типы с модификатором `public` образуют внешнюю поверхность библиотеки, типы без модификатора остаются `internal` и снаружи сборки не видны. поэтому класс, которым должна пользоваться другая программа, объявляют открытым.

ниже библиотеку классов создают и подключают к консольному приложению.

берётся уже существующий проект консольного приложения c#, например созданный в предыдущих темах. в структуре решения правой кнопкой нажимают имя решения и в контекстном меню выбирают `Add -> New Project...` (добавить новый проект).

![создание библиотеки классов в c#](/uploads/course-lectures/22676d9d0a3c592d543a37e5c52535f12661b5b5.png)

в списке шаблонов находят пункт `Class Library`.

![библиотека классов в c# и .net](/uploads/course-lectures/ffa423d1cf0825b19207ba14c35cc4455c6b5c13.png)

новому проекту задают имя, в примере это `MyLib`.

![class library in .net](/uploads/course-lectures/296f86974141d8c1d86c8dfad1744332ee1830cd.png)

после создания в решение добавлен новый проект. в примере он называется `MyLib`.

![добавление нового проекта в c# и .net](/uploads/course-lectures/73a93721b958c5386f3059d6b3f53856ffbe1f3d.png)

по умолчанию в проекте один пустой класс `Class1` в файле `Class1.cs`. файл можно удалить или переименовать.

файл `Class1.cs` переименовывают в `Person.cs`, а класс `Class1` в `Person`. в классе `Person` достаточно такого кода.

```c#


namespace MyLib

{

    public class Person

    {

        string name;

        public Person(string name) 

        {

            this.name = name;

        }

        public void Print() => Console.WriteLine($"Name: {name}");

    }

}
```

![новый проект в c# и .net core](/uploads/course-lectures/75ebf1a798fffd261c198af8de1857422a88d8e7.png)

библиотеку компилируют: правая кнопка по проекту библиотеки, в контекстном меню пункт `Rebuild`.

![компиляция библиотеки классов в c# и .net core](/uploads/course-lectures/d82200aac0c3a21a7696cb76af71a8f522eebcda.png)

после компиляции в каталоге проекта `bin/Debug/net6.0` лежит файл dll, в примере `MyLib.dll`. его подключают к основному проекту. в основном проекте правой кнопкой нажимают узел `Dependencies` и выбирают `Add Project Reference...`.

![добавление библиотеки классов в проекте на c# и .net core](/uploads/course-lectures/bb98ef085efc5ea146818e5753bc4bc5f5b40ac9.png)

открывается окно добавления библиотек. пункт `Solution` показывает библиотеки классов из проектов текущего решения. отметку ставят у нужной библиотеки и нажимают `OK`.

![](/uploads/course-lectures/472cc33367a191ad72785317713a0f4888b48b6a.png)

если библиотека является файлом dll и не входит ни в один проект решения, кнопка `Browse` позволяет указать расположение dll и подключить файл напрямую. ссылка на проект и ссылка на готовый dll различаются для системы сборки: ссылка на проект заставляет сначала собрать зависимость и подставляет её выходной файл, ссылка через `Browse` указывает на уже существующую сборку.

после подключения библиотеки в главном проекте меняют `Program.cs`, чтобы он использовал класс `Person` из библиотеки.

```c#


using MyLib;    // подключение пространства имен из библиотеки классов



Person tom = new("Tom");

tom.Print();    // Name: Tom
```

директива `using MyLib` импортирует пространство, объявленное в сборке. простое имя `Person` разрешается в `MyLib.Person`, потому что класс открытый. внутренний класс той же сборки из главного проекта был бы не виден.
