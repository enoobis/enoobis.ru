на многоядерной машине одних объектов `Thread` мало для повседневного параллелизма: на каждую операцию пришлось бы вручную создавать поток, решать, когда его присоединять, и следить за общим числом. в .net для этого добавлена библиотека параллельных задач tpl (task parallel library). её api расположен в пространстве имён **System.Threading.Tasks**. библиотека описывает работу как задачи, а планировщик ставит их в пул потоков. явный `Thread` по-прежнему нужен, когда требуется собственный поток с заданным приоритетом, локальным хранилищем потока или долгим циклом, который не следует занимать у пула.

единица библиотеки называется задачей и описывает отдельную операцию, в том числе долгую. в библиотеке классов ей соответствует класс **Task**. задача асинхронно исполняется на потоке пула. её можно выполнить и синхронно на текущем потоке. задача описывает единицу работы планировщика. один поток пула по очереди обслуживает много задач, а продолжение одной задачи может быть поставлено уже на другой поток. число потоков пула не совпадает с числом задач.

завести и запустить задачу можно тремя способами.

- первый способ: создать объект `Task` и вызвать у него `Start`. конструктор принимает делегат `Action`, то есть метод без параметров и без результата: лямбда-выражение или группу методов. в примере лямбда выводит строку `Hello Task!`. `Start()` ставит задачу в очередь планировщика по умолчанию, а это пул потоков.

```c#


Task task = new Task(() => Console.WriteLine("Hello Task!"));

task.Start();
```

- второй способ: статический метод `Task.Factory.StartNew()`. аргумент снова `Action`. метод создаёт задачу и сразу ставит её на выполнение, возвращая уже запущенный `Task`. у `StartNew` есть перегрузки с `TaskCreationOptions` и отдельным `TaskScheduler`, поэтому им пользуются, когда нужно прикрепление к родителю, признак долгой работы или свой планировщик.

```c#


Task task = Task.Factory.StartNew(() => Console.WriteLine("Hello Task!"));
```

- третий способ: статический метод `Task.Run()`. он тоже принимает `Action` и возвращает `Task`. это сокращение над `StartNew` для обычной работы в пуле: задача создаётся с запретом прикрепления дочерних (`DenyChildAttach`), чтобы случайный вложенный `StartNew` не стал частью вызывающего.

```c#


Task task = Task.Run(() => Console.WriteLine("Hello Task!"));
```

все три способа в одной программе:

```c#


Task task1 = new Task(() => Console.WriteLine("Task1 is executed"));

task1.Start();



Task task2 = Task.Factory.StartNew(() => Console.WriteLine("Task2 is executed"));



Task task3 = Task.Run(() => Console.WriteLine("Task3 is executed"));
```

задачи создаются и запускаются, но консоль может остаться пустой. делегат берёт поток из пула уже после выхода из конструктора и `Start`. поток пула является фоновым. когда основной поток покидает `Main` и других приоритетных потоков нет, процесс завершается и обрывает фоновые потоки, даже если делегат ещё не начал выполнение. чтобы процесс дождался задач, их завершение ожидается явно.

### ожидание завершения задачи

метод **Wait()** объекта `Task` блокирует вызывающий поток, пока задача не перейдёт в конечное состояние:

```c#


Task task1 = new Task(() => Console.WriteLine("Task1 is executed"));

task1.Start();



Task task2 = Task.Factory.StartNew(() => Console.WriteLine("Task2 is executed"));



Task task3 = Task.Run(() => Console.WriteLine("Task3 is executed"));



task1.Wait();   // ожидаем завершения задачи task1

task2.Wait();   // ожидаем завершения задачи task2

task3.Wait();   // ожидаем завершения задачи task3
```

возможный консольный вывод:

```bash


Task3 is executed

Task2 is executed

Task1 is executed
```

порядок строк не детерминирован. задачи независимы, планировщик пула не обещает порядок старта и завершения. задача, поставленная первой, может закончиться последней.

**Wait()** блокирует вызывающий поток. пока задача не завершится, следующий оператор этого потока не выполняется. на потоке пула такой вызов удерживает работника пула в ожидании другой работы того же пула. цепочка подобных ожиданий исчерпывает пул.

```c#


Console.WriteLine("Main Starts");

// создаем задачу

Task task1 = new Task(() =>

{

    Console.WriteLine("Task Starts");

    Thread.Sleep(1000);     // задержка на 1 секунду - имитация долгой работы

    Console.WriteLine("Task Ends");

 });

task1.Start();  // запускаем задачу

task1.Wait();   // ожидаем выполнения задачи

Console.WriteLine("Main Ends");
```

`Thread.Sleep(1000)` внутри делегата имитирует долгую работу. на `task1.Wait()` основной поток останавливается и не печатает `Main Ends`, пока делегат не закончится. вывод:

```bash


Main Starts

Task Starts

Task Ends

Main Ends
```

если остальной синхронный код основного потока не должен ждать задачу, вызов `Wait` переносится в конец `Main`:

```c#


Console.WriteLine("Main Starts");

// создаем задачу

Task task1 = new Task(() =>

{

    Console.WriteLine("Task Starts");

    Thread.Sleep(1000);     // задержка на 1 секунду - имитация долгой работы

    Console.WriteLine("Task Ends");

 });

task1.Start();  // запускаем задачу

Console.WriteLine("Main Ends");

task1.Wait();   // ожидаем выполнения задачи
```

процесс всё равно не завершится раньше задачи: `Wait` стоит до выхода из `Main`. операторы между `Start` и `Wait` выполняются сразу. строка `Main Ends` может появиться раньше `Task Ends`.

### синхронный запуск задачи

`Start` и `Task.Run` планируют задачу асинхронно. метод **RunSynchronously()** просит текущий планировщик выполнить задачу синхронно и возвращает управление после её завершения, поэтому отдельный `Wait` не нужен. при планировщике по умолчанию делегат исполняется на вызывающем потоке, если задача ещё не была запущена:

```c#


Console.WriteLine("Main Starts");

// создаем задачу

Task task1 = new Task(() =>

{

    Console.WriteLine("Task Starts");

    Thread.Sleep(1000); 

    Console.WriteLine("Task Ends");

 });

task1.RunSynchronously(); // запускаем задачу синхронно

Console.WriteLine("Main Ends"); // этот вызов ждет завершения задачи task1
```

### свойства класса Task

по свойствам `Task` читается состояние объекта. часть из них:

- `AsyncState` : объект состояния, переданный при создании, либо отсутствие значения.

- `CurrentId` : идентификатор задачи, которая исполняется на текущем потоке. статическое свойство типа `int?`. вне задачи значение пустое.

- `Id` : идентификатор этой задачи. число назначается при первом обращении к свойству. конструктор сам по себе номер не выдаёт, и номер не служит порядком создания.

- `Exception` : `AggregateException`, из-за которого задача перешла в сбой, либо пустое значение, если сбоя не было. чтение не блокирует вызывающий поток и не ждёт завершения. обращение к свойству помечает исключение как просмотренное.

- `Status` : статус, значение перечисления `System.Threading.Tasks.TaskStatus`:

- `Canceled` : задача отменена.

- `Created` : задача создана и ещё не запущена.

- `Faulted` : во время выполнения возникло необработанное исключение.

- `RanToCompletion` : задача завершилась успешно.

- `Running` : задача выполняется.

- `WaitingForActivation` : задача ждёт активации. в этом состоянии находятся, в частности, обещания `TaskCompletionSource` до установки результата.

- `WaitingForChildrenToComplete` : собственный делегат уже закончился, задача ждёт прикреплённых дочерних задач.

- `WaitingToRun` : задача стоит в очереди и ещё не начала выполнение.

- `IsCompleted` : `true`, если статус конечный: `RanToCompletion`, `Faulted` или `Canceled`.

- `IsCanceled` : `true`, если задача отменена.

- `IsFaulted` : `true`, если задача завершилась из-за исключения.

- `IsCompletedSuccessfully` : `true`, если статус равен `RanToCompletion`.

чтение нескольких свойств до и вокруг ожидания:

```c#


Task task1 = new Task(() =>

{

    Console.WriteLine($"Task{Task.CurrentId} Starts");

    Thread.Sleep(1000);

    Console.WriteLine($"Task{Task.CurrentId} Ends");

 });

task1.Start(); //запускаем задачу



// получаем информацию о задаче

Console.WriteLine($"task1 Id: {task1.Id}");

Console.WriteLine($"task1 is Completed: {task1.IsCompleted}");

Console.WriteLine($"task1 Status: {task1.Status}");



task1.Wait(); // ожидаем завершения задачи
```

пример консольного вывода:

```bash


task1 Id: 1

Task1 Starts

task1 is Completed: False

task1 Status: Running

Task1 Ends
```

`task1.Id` и `Task.CurrentId` внутри делегата относятся к одной задаче. `IsCompleted` в точке печати ещё `false`, `Status` равен `Running`: свойства читаются до `Wait`, пока делегат стоит в `Sleep`. после возврата из `Wait` статус был бы `RanToCompletion`.
