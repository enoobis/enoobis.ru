ранее разобраны объявление и переопределение виртуальных методов. другой способ изменить функциональность метода, унаследованного от базового класса, состоит в **скрытии** (shadowing / hiding).

скрытие метода или свойства представляет собой объявление в классе-наследнике метода или свойства с тем же именем и тем же набором параметров, что у члена базового класса. для скрытия применяется ключевое слово `new`:

```c#


class Person

{

	public string Name { get; set; }

	public Person(string name)

    {

        Name = name;

    }

	public void Print()

	{

		Console.WriteLine($"Name: {Name}");

	}

}

class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company)

				: base(name)

	{

		Company = company;

	}

	public new void Print()

	{

		Console.WriteLine($"Name: {Name}   Company: {Company}");

	}

}
```

здесь объявлены класс `Person`, представляющий человека, и класс `Employee`, представляющий работника предприятия. `Employee` наследует от `Person` свойства и методы. помимо унаследованных свойств в `Employee` есть собственное свойство `Company`, оно хранит название компании. метод `Print` должен выводить на консоль сведения о компании вместе с именем. для этого объявляется метод `Print` с ключевым словом `new`. он скрывает реализацию этого метода из базового класса.

скрытие уместно, когда метод `Print` базового класса не является виртуальным и переопределить его нельзя, а реализация для производного класса не подходит. сокрытие задаёт нужный функционал под тем же именем. механизм при этом другой, чем у `override`. `new` не подменяет слот диспетчеризации, а объявляет отдельный член. вызов выбирается по статическому типу ссылки во время компиляции. если ссылка имеет статический тип `Person` и указывает на объект `Employee`, вызов `Print()` выполнит версию `Person`, даже когда в `Employee` метод скрыт. если ключевое слово `new` опустить, сокрытие всё равно произойдёт, но компилятор выдаст предупреждение: имя скрывает унаследованный член. `new` фиксирует, что это сделано намеренно.

эти классы используются в программе в методе `Main`:

```c#


Person bob = new Person("Bob");

bob.Print();	// Name: Bob



Employee tom = new Employee("Tom", "Microsoft");

tom.Print();	// Name: Tom  Company: Microsoft
```

консольный вывод программы:

```consoletext


Name: Bob

Name: Tom  Company: Microsoft
```

если нужна именно реализация свойства или метода базового класса, снова используется ключевое слово `base`: через него вызывается функциональность базового класса, без учёта скрывающего члена.

```c#


class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company)

				: base(name)

	{

		Company = company;

	}

	public new void Print()

	{

		base.Print();	// вызываем метод Print из базового класса Person

		Console.WriteLine($"Company: {Company}");

	}

}
```

### скрытие свойств

тем же способом организуется скрытие свойств:

```c#


Person bob = new Person("Bob");

Console.WriteLine(bob.Name);	// Bob



Employee tom = new Employee("Tom", "Microsoft");

Console.WriteLine(tom.Name);    // Mr./Ms. Tom



class Person

{

	public string Name { get; set; }

	public Person(string name)

    {

        Name = name;

    }

}

class Employee : Person

{

	// скрываем свойство Name базового класса

	public new string Name

	{

		get => $"Mr./Ms. {base.Name}";

		set => base.Name = value;



	}

	public string Company { get; set; }

	public Employee(string name, string company)

				: base(name)

	{

		Company = company;

	}

}
```

в классе `Employee` скрыто свойство `Name`. в блоке `get` берётся значение свойства базового класса `Person` и к нему присоединяется префикс `"Mr./Ms."`. в блоке `set` полученное значение передаётся в реализацию свойства `Name` базового класса `Person`. обращение `base.Name` необходимо: имя `Name` внутри `Employee` уже обозначает скрывающее свойство, и без `base` чтение зациклилось бы на нём самом.

как и у скрытого метода, выбор свойства определяется статическим типом выражения. через ссылку статического типа `Person` читается и записывается свойство базового класса, даже если динамический тип объекта есть `Employee`. префикс `"Mr./Ms."` появляется, когда статическим типом выражения является `Employee`. хранится при этом одно значение, в базовом свойстве. производный геттер только иначе его показывает.

### скрытие переменных и констант

в отличие от переопределения, c# позволяет применять скрытие к переменным, как к статическим, так и к нестатическим, и к константам. для этого тоже используется ключевое слово `new`. поля и константы не участвуют в виртуальной диспетчеризации, поэтому модификатор `override` к ним неприменим. связывание остаётся статическим:

```c#


Console.WriteLine(Person.minAge);	  // 1

Console.WriteLine(Person.typeName);   // Person



Console.WriteLine(Employee.minAge);		// 18

Console.WriteLine(Employee.typeName);   // Employee



class Person

{

	public readonly static int minAge = 1;

	public const string typeName = "Person";

}

class Employee : Person

{

	// скрываем поля и константы базового класса

	public new readonly static int minAge = 18;

	public new const string typeName = "Employee";

}
```

`Person.minAge` и `Employee.minAge` являются двумя разными статическими полями. скрытие не затирает поле базового класса, а добавляет одноимённый член в производном. константа `typeName` неявно статическая, и в место использования подставляется значение той константы, которая видна по статическому типу. `new` у константы скрывает имя базовой константы в производном классе.
