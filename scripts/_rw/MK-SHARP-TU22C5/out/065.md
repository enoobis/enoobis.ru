предыдущая тема разобрала объявление делегата, список вызова и вызов через переменную. в тех примерах целевой метод известен в той же области видимости, и его можно было вызвать напрямую. отдельный смысл делегата в том, что вызов отделяется от выбора метода. на момент компиляции класса конкретное тело может быть ещё неизвестно. известна только сигнатура. код класса вызывает делегат, а какой метод войдёт в список вызова, решает внешний код позже. это обратный вызов: библиотечный код передаёт управление методу, который подставил клиент.

пример строится на классе счёта.

```c#

public class Account
{
    int sum; // Переменная для хранения суммы
    // через конструктор устанавливается начальная сумма на счете
    public Account(int sum) => this.sum = sum;
    // добавить средства на счет
    public void Add(int sum) => this.sum += sum;
    // взять деньги с счета
    public void Take(int sum)
    {
        // берем деньги, если на счете достаточно средств
        if (this.sum >=sum) this.sum -= sum;
    }
}
```

в поле sum хранится сумма на счёте. конструктор записывает начальную сумму. метод `Add()` увеличивает сумму, метод `Take` уменьшает её, если остатка достаточно.

при снятии средств через `Take` требуется уведомить владельца счёта и, возможно, другие объекты. если класс применяется в той же консольной программе, где он объявлен, уведомление можно вписать прямо в метод:

```c#

public class Account
{
    int sum;
    public Account(int sum) => this.sum = sum;
    public void Add(int sum) => this.sum += sum;
    public void Take(int sum)
    {
        if (this.sum >= sum)
        {
            this.sum -= sum;
            Console.WriteLine($"Со счета списано {sum} у.е.");
        }
    }
}
```

вызов

```c#
Console.WriteLine($"Со счета списано {sum} у.е.");
```

привязан к консоли. в другом проекте, графическом приложении windows forms или wpf, в мобильном приложении, в веб-приложении, запись в стандартный вывод не сообщает о событии тому, кто работает с интерфейсом.

класс Account к тому же предполагается как отдельная библиотека. код, который будет на него ссылаться, на момент написания класса неизвестен, и способ уведомления тоже неизвестен. жёстко встроенный вызов

```c#
Console.WriteLine($"Со счета списано {sum} у.е.");
```

связывает операцию списания с одним каналом вывода. заменить канал можно только правкой самого класса. делегат переносит определение действия из класса во внешний код, который этим классом пользуется.

класс с делегатом выглядит так:

```c#

// Объявляем делегат
public delegate void AccountHandler(string message);
public class Account
{
    int sum;
    // Создаем переменную делегата
    AccountHandler? taken;
    public Account(int sum) => this.sum = sum;
    // Регистрируем делегат
    public void RegisterHandler(AccountHandler del)
    {
        taken = del;
    }
    public void Add(int sum) => this.sum += sum;
    public void Take(int sum)
    {
        if (this.sum >= sum)
        {
            this.sum -= sum;
            // вызываем делегат, передавая ему сообщение
            taken?.Invoke($"Со счета списано {sum} у.е.");
        }
        else
        {
            taken?.Invoke($"Недостаточно средств. Баланс: {this.sum} у.е.");
        }
    }
}
```

для обратного вызова объявлен делегат **AccountHandler**. ему соответствует любой метод с возвращаемым типом **void** и одним параметром типа **string**.

```c#
public delegate void AccountHandler(string message);
```

в классе Account поле `taken` хранит экземпляр этого делегата. тип поля допускает null: обработчик может быть ещё не зарегистрирован.

```c#
AccountHandler? taken;
```

поле нужно связать с конкретным действием. способов передать делегат в объект несколько. здесь для этого служит метод RegisterHandler: он записывает переданный делегат в `taken`.

```c#

public void RegisterHandler(AccountHandler del)
{
	taken = del;
}
```

после регистрации делегат можно вызывать. вызов стоит в методе Take.

```c#

public void Take(int sum)
{
    if (this.sum >= sum)
    {
        this.sum -= sum;
        // вызываем делегат, передавая ему сообщение
        taken?.Invoke($"Со счета списано {sum} у.е.");
    }
	else
	{
		taken?.Invoke($"Недостаточно средств. Баланс: {this.sum} у.е.");
	}
}
```

поскольку AccountHandler принимает строку, в вызов передаётся текст сообщения. при успешном списании и при нехватке средств тексты разные. оператор `taken?.Invoke` не вызывает делегат, если поле равно null, и исключение из-за пустого списка вызова не возникает.

фактически выполняются действия, которые внешний код передал в RegisterHandler. в точке вызова внутри Take эти действия неизвестны. метод только передаёт сообщение об успешном или неудачном снятии.

проверка класса в основной программе:

```c#

// создаем банковский счет
Account account = new Account(200);
// Добавляем в делегат ссылку на метод PrintSimpleMessage
account.RegisterHandler(PrintSimpleMessage);
// Два раза подряд пытаемся снять деньги
account.Take(100);
account.Take(150);

void PrintSimpleMessage(string message) => Console.WriteLine(message);
```

RegisterHandler передаёт в `taken` ссылку на метод `PrintSimpleMessage`. сигнатура метода совпадает с AccountHandler, поэтому преобразование в делегат законно. там, где Account вызывает `taken`, выполняется PrintSimpleMessage.

параметр `message` получает строку, переданную из Take, и метод печатает её на консоль:

```bash

Со счета списано 100 у.е.
Недостаточно средств. Баланс: 100 у.е.
```

получился механизм обратного вызова: снятие денег в Account приводит к вызову внешнего метода. в этом прогоне метод печатает строку на консоль. ту же печать можно было бы записать в Take напрямую, без делегата. разница в зависимости. Account не задаёт способ показа сообщения и не знает, какое действие последует за списанием. объект только рассылает уведомление через делегат.

отсюда выбор обработчика остаётся за программой, которая создаёт счёт. консольное приложение выводит текст на консоль. приложение windows forms или wpf показывает графическое окно. обработчик может записать факт списания в файл или отправить уведомление по электронной почте. способ обработки не входит в класс Account и от него не зависит.

### добавление и удаление методов в делегате

в предыдущем варианте поле хранило ссылку на один метод: RegisterHandler присваивал делегат операцией `=`, и новая регистрация заменяла предыдущую. список вызова делегата способен содержать несколько методов одной сигнатуры. ссылку можно и снять, чтобы метод больше не вызывался. для накопления служит `+=`, для снятия `-=`. метод RegisterHandler переписывается на добавление, рядом появляется UnregisterHandler:

```c#

public delegate void AccountHandler(string message);
public class Account
{
    int sum;
    AccountHandler? taken;
    public Account(int sum) => this.sum = sum;
    // Регистрируем делегат
    public void RegisterHandler(AccountHandler del)
    {
        taken += del;
    }
    // Отмена регистрации делегата
    public void UnregisterHandler(AccountHandler del)
    {
        taken -= del; // удаляем делегат
    }
    public void Add(int sum) => this.sum += sum;
    public void Take(int sum)
    {
        if (this.sum >= sum)
        {
            this.sum -= sum;
            taken?.Invoke($"Со счета списано {sum} у.е.");
        }
        else 
            taken?.Invoke($"Недостаточно средств. Баланс: {this.sum} у.е.");
    }
}
```

RegisterHandler объединяет текущее значение `taken` и аргумент `del`. результат объединения, новый делегат со списком вызова из обоих операндов, записывается обратно в `taken`. UnregisterHandler удаляет из `taken` методы, которые входят в `del`. обе операции создают новый экземпляр делегата, а не меняют старый список на месте. если удаление снимает последний метод, поле получает значение null.

новые методы используются так:

```c#

Account account = new Account(200);
// Добавляем в делегат ссылку на методы
account.RegisterHandler(PrintSimpleMessage);
account.RegisterHandler(PrintColorMessage);
// Два раза подряд пытаемся снять деньги
account.Take(100);
account.Take(150);

// Удаляем делегат
account.UnregisterHandler(PrintColorMessage);
// снова пытаемся снять деньги
account.Take(50);

void PrintSimpleMessage(string message) => Console.WriteLine(message);
void PrintColorMessage(string message)
{
    // Устанавливаем красный цвет символов
    Console.ForegroundColor = ConsoleColor.Red;
    Console.WriteLine(message);
    // Сбрасываем настройки цвета
    Console.ResetColor();
}
```

для проверки добавлен второй метод, PrintColorMessage. он выводит то же сообщение красным цветом: перед печатью свойству Console.ForegroundColor присваивается ConsoleColor.Red, после печати Console.ResetColor возвращает цвет по умолчанию. ссылка на PrintColorMessage тоже передаётся в RegisterHandler и попадает в список вызова `taken`.

пока в списке оба метода, каждый вызов Take печатает сообщение дважды. строка `account.UnregisterHandler(PrintColorMessage);` удаляет PrintColorMessage из списка вызова, и дальше срабатывает только PrintSimpleMessage. консольный вывод:

```consoletext

Со счета списано 100 у.е.
Со счета списано 100 у.е.
Недостаточно средств. Баланс: 100 у.е.
Недостаточно средств. Баланс: 100 у.е.
Со счета списано 50 у.е.
```

первые две строки относятся к успешному снятию 100 при двух зарегистрированных обработчиках. следующие две строки относятся к неудачной попытке снять 150: остаток 100 меньше запрошенной суммы, и оба обработчика получают сообщение о нехватке средств. последняя строка относится к снятию 50 уже после отмены регистрации PrintColorMessage, поэтому сообщение одно.
