c# является компилируемым языком. обычный путь от текста программы до запуска делится на два этапа:

- компиляция в бинарный пакет командой `dotnet build`

- запуск ранее скомпилированной программы командой `dotnet run`

даже у самого простого приложения на c# была обязательная структура: файл проекта с расширением `.csproj`, а у решения из нескольких проектов ещё и файл `.sln`, и исходный код в файлах с расширением `.cs`. без файла проекта `.csproj` код не компилировался.

начиная с c# 14 и .net 10 можно создавать приложения на основе файлов, file-based app. сборка и запуск программы на c# при этом упрощаются. такая форма позволяет использовать c# как скриптовый язык для небольших утилит, автоматизации и быстрого прототипирования.

для создания и запуска достаточно одного файла с кодом на c#, передаваемого команде `dotnet run`. файловое приложение остаётся обычной программой на c# и использует синтаксис инструкций верхнего уровня, top-level statements. класс `Program` и метод `Main` в тексте не объявляются: компилятор синтезирует их вокруг инструкций файла.

файл `hello.cs` с коротким содержимым:

```c#
Console.WriteLine("Hello METANIT.COM");
```

в консоли выполняется переход в папку этого файла и команда `dotnet run hello.cs`:

```bash


eugene@Eugene:/dotnet/scripts$ dotnet run hello.cs

Hello METANIT.COM

eugene@Eugene:/dotnet/scripts$
```

файловое приложение снижает порог запуска для тех, кто только начинает c#: код пишется и выполняется без отдельной структуры проекта. тот же механизм подходит для короткого сценария или небольшой утилиты командной строки, когда заводить полноценный проект незачем.

в будущих версиях .net ожидается расширение поддержки на сценарии из нескольких файлов. это увеличит гибкость файловых приложений. лекция фиксирует именно ожидание, а не уже включённую многофайловую модель.

### развитие

когда сценарий на основе файла разрастается и требует обычной структуры проекта, он преобразуется в стандартный проект c# командой:

```bash


dotnet project convert app.cs
```

аргументом указан файл `app.cs`. команда `dotnet project convert` строит по нему файл проекта, после чего программа собирается уже как обычный проект sdk.

### особенности и директивы

то, что раньше задавалось в файле csproj, для файлового приложения записывается специальными директивами прямо в файле. директива начинается с `#:` и обрабатывается до компиляции самого c#.

- `#:package <id>[@<version>]` подключает пакет nuget. запись ниже подключает пакет `Microsoft.EntityFrameworkCore.Sqlite` версии 10.0.0

```c#
#:package Microsoft.EntityFrameworkCore.Sqlite@10.0.0
```

- `#:sdk <name>` указывает нужный sdk, в том числе sdk веб-приложений

```c#
#:sdk Microsoft.NET.Sdk.Web
```

- `#:property <name>=<value>` задаёт свойство msbuild

минимальное веб-приложение, minimal api, целиком помещается в один файл `app.cs`:

```c#


#:sdk Microsoft.NET.Sdk.Web



var builder = WebApplication.CreateBuilder();

var app = builder.Build();

 

app.MapGet("/", () => "Hello METANIT.COM!");

 

app.Run();
```

разбор самого веб-приложения здесь не нужен. устройство первого приложения на asp.net core с .net cli изложено в отдельном руководстве, в статье "первое приложение на asp.net core с .net cli". в этом файле существенна первая строка:

```c#
#:sdk Microsoft.NET.Sdk.Web
```

она подключает функциональность sdk `Microsoft.NET.Sdk.Web`, без которой типы веб-приложения в файловом проекте недоступны. запуск выполняется командой `dotnet run app.cs`:

```bash


eugene@Eugene:/dotnet/scripts$ dotnet run app.cs

info: Microsoft.Hosting.Lifetime[14]

      Now listening on: http://localhost:5000

info: Microsoft.Hosting.Lifetime[0]

      Application started. Press Ctrl+C to shut down.

info: Microsoft.Hosting.Lifetime[0]

      Hosting environment: Production

info: Microsoft.Hosting.Lifetime[0]

      Content root path: /dotnet/scripts
```

из вывода следует, что приложение запущено. обратиться к нему можно по адресу "http://localhost:5000" (адрес по умолчанию). открытие этого адреса в браузере даёт ответ, который показывает снимок:

### сценарии использования

файловые приложения подходят для таких задач:

- скриптинг и автоматизация: замена сценариев на bash, powershell или python для операционных задач и автоматизации

- прототипирование: быстрая проверка идеи или api

- обучение: более низкий порог входа в c#, код пишется и запускается без сложной структуры проекта и без необходимости сначала понимать эту структуру

- утилиты cli: простые самодостаточные утилиты консоли и командной строки
