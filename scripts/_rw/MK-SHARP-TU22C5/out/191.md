### выражения коллекций

в c# 12 создание массивов и других коллекций сведено к выражению коллекции (collection expression). это единый синтаксис, тип которого определяется целью присваивания: одна и та же запись порождает массив, список или span в зависимости от типа слева. раньше массив задавался инициализатором в фигурных скобках, а пустой массив требовал явного `new` с типом элемента.

```c#


int[] nums1 = { 1, 2, 3, 4 };

int[] nums2 = new int[] { };   // пустой массив
```

та же пара значений записывается квадратными скобками. пустое выражение `[]` даёт пустую коллекцию целевого типа, без отдельного указания `int` в конструкции создания.

```c#


int[] nums1 = [ 1, 2, 3, 4 ];

int[] nums2 = [];   // пустой массив
```

выражение коллекции работает и для других типов, которые компилятор умеет строить из последовательности элементов. в примерах это `List<int>` и `Span<int>`. для span буфер при известной длине может быть размещён на стеке, без отдельного массива в куче. пустой список задаётся тем же `[]`.

```c#


List<int> list1 = [1, 2, 3, 4];

List<int> list2 = []; //  пустой список

Span<int> span1 = [1, 2, 3, 4];
```

### первичные конструкторы

первичный конструктор (primary constructor) добавляет параметры прямо в заголовок класса или структуры. эти параметры входят в область видимости всего тела типа и доступны в инициализаторах, методах и свойствах.

```c#


var tom = new Person("Tom", 38);

Console.WriteLine(tom);



public class Person(string name, int age)

{

    public Person(string name) : this(name, 18) { }

    public string Name => name;

    public int Age => age;



    public override string ToString() => $"name: {name}, age: {age}";

}
```

у `Person` первичный конструктор принимает `name` и `age`. свойства `Name` и `Age` читают эти параметры, и их же подставляет `ToString`. если параметр читается из члена экземпляра, компилятор захватывает его в скрытое поле: время жизни параметра конструктора само по себе короче времени жизни объекта. дополнительный конструктор классу определять можно, как в примере с одним аргументом `name`. любой такой конструктор обязан вызвать первичный через `this(...)`. цепочка фиксирует, что захват параметров и инициализация базового состояния проходят через одну точку.

```c#
public Person(string name) : this(name, 18) { }
```

вызов `this(name, 18)` передаёт первичному конструктору имя и возраст по умолчанию 18.

### псевдонимы типов

в c# 12 директива `using` вводит псевдоним любого типа. псевдоним действует в текущем файле компиляции и снаружи не экспортируется. целью может быть сконструированный обобщённый тип, кортеж или тип делегата.

```c#


using People = System.Collections.Generic.List<Person>;



People people = new(){ new ("Tom", 38), new ("Bob", 42) };

people.ForEach(Console.WriteLine);



public record Person(string Name, int Age);
```

имя `People` здесь является псевдонимом закрытого типа `List<Person>`. дальше список создаётся уже под этим именем, а элементы конструируются как записи `Person`.

```c#


using user = (string, int);

user tom = ("Tom", 38);

Console.WriteLine(tom);     // (Tom, 38)
```

имя `user` является псевдонимом анонимной по составу пары `(string, int)`. переменная `tom` имеет этот тип кортежа, и печать показывает оба элемента.

элементам кортежа в псевдониме можно задать имена. имена становятся частью типа для кода, который пользуется псевдонимом, и к ним обращаются как к полям.

```c#


using user = (string name, int age);

user tom = ("Tom", 38);

Console.WriteLine(tom.name);     // Tom

Console.WriteLine(tom.age);     // 38
```

у пары появляются поля `name` и `age`. печать читает их по отдельности и получает `Tom` и 38.

ещё один частый случай: псевдоним функционального типа.

```c#


using BinaryOp = System.Func<int, int, int>;



BinaryOp sum = (a, b) => a + b;

BinaryOp subtract = (a, b) => a - b;



DoOperation(10, 6, sum);        // 16

DoOperation(10, 6, subtract);   // 4



void DoOperation(int a, int b, BinaryOp op)

{

    Console.WriteLine(op(a, b));

}
```

делегату `System.Func<int, int, int>` назначен псевдоним `BinaryOp`. обе лямбды совместимы с этим типом, а `DoOperation` принимает операцию как значение и применяет её к двум аргументам. вызовы дают 16 и 4.

### значения по умолчанию для параметров лямбда-выражений

начиная с c# 12 у параметров лямбда-выражения могут быть значения по умолчанию, по тем же правилам, что у параметров метода. если аргумент в вызове опущен, подставляется значение из объявления параметра.

```c#


var welcome = (string message = "hello")=> Console.WriteLine(message);



welcome("hello world"); // hello world

welcome();              // hello
```

прямой вызов `welcome("hello world")` передаёт аргумент. вызов `welcome()` аргумент опускает, и параметр `message` получает `"hello"`.

### ref-параметры только для чтения

модификатор `ref readonly`, доступный с c# 12, передаёт аргумент по ссылке и запрещает присваивание этому параметру в теле метода. вызывающий код обязан передать переменную, как для обычного `ref`. временное значение здесь не подходит, и компилятор не вставляет защитную копию, которой иногда сопровождается параметр `in`. крупная структура поэтому не копируется ни на входе, ни из-за попытки записи.

```c#


void Increment(ref readonly int n)

{

    // n++; // нельзя, иначе будет очишка компиляции

    Console.WriteLine($"Число в методе Increment: {n}");

}

 

int number = 5;

Increment(ref number);

Console.WriteLine($"Число после метода Increment: {number}");
```

в `Increment` параметр `n` связан ссылкой с переменной `number` и доступен только для чтения. выражение `n++` не компилируется. метод печатает текущее значение, после возврата `number` остаётся равным 5.

### упрощение определения типов

начиная с c# 12 у класса, структуры и интерфейса с пустым телом фигурные скобки можно заменить точкой с запятой. пустое определение означает, что в типе нет полей, свойств и методов. семантика типа от формы записи не меняется: это по-прежнему отдельный тип, просто без членов.

```c#


class Person;

struct User;

interface Human;
```
