**семафор** ограничивает число потоков, которым одновременно разрешён доступ к ресурсу. это считающий семафор: внутренний счётчик хранит число свободных разрешений. поток, входящий в участок, забирает разрешение и уменьшает счётчик. поток, покидающий участок, разрешение возвращает. в .net семафор представлен классом **Semaphore** из `System.Threading`.

экземпляр создаётся одним из конструкторов:

- `Semaphore(int initialCount, int maximumCount)` : `initialCount` задаёт начальное число свободных разрешений, `maximumCount` задаёт верхнюю границу счётчика, то есть наибольшее число разрешений, которое семафор вообще выдаёт.

- `Semaphore(int initialCount, int maximumCount, string? name)` : дополнительно задаёт имя. именованный семафор, как и именованный мьютекс, один на всю систему для данного имени и доступен нескольким процессам.

- `Semaphore(int initialCount, int maximumCount, string? name, out bool createdNew)` : выходной параметр `createdNew` равен `true`, если создан новый семафор, и `false`, если семафор с таким именем уже был и метод вернул его.

для работы с потоками используются два метода:

- `WaitOne()` : ждёт свободное разрешение и уменьшает счётчик на единицу. при нулевом счётчике поток блокируется.

- `Release()` : возвращает одно разрешение и увеличивает счётчик. перегрузка с аргументом `int` возвращает сразу несколько. если новый счётчик превысил бы `maximumCount`, выбрасывается `SemaphoreFullException`.

модель для этого примитива: читатели приходят в библиотеку три раза в день, и одновременно в зале не больше трёх. ёмкость семафора прямо кодирует это ограничение.

```c#


// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Reader reader = new Reader(i);

}

class Reader

{

    // создаем семафор

    static Semaphore sem = new Semaphore(3, 3);

    Thread myThread;

    int count = 3;// счетчик чтения



    public Reader(int i)

    {

        myThread = new Thread(Read);

        myThread.Name = $"Читатель {i}";

        myThread.Start();

    }



    public void Read()

    {

        while (count > 0)

        {

            sem.WaitOne();  // ожидаем, когда освободиться место



            Console.WriteLine($"{Thread.CurrentThread.Name} входит в библиотеку");



            Console.WriteLine($"{Thread.CurrentThread.Name} читает");

            Thread.Sleep(1000);



            Console.WriteLine($"{Thread.CurrentThread.Name} покидает библиотеку");



            sem.Release();  // освобождаем место



            count--;

            Thread.Sleep(1000);

        }

    }

}
```

читатель описан классом `Reader`. поток хранится в поле `Thread myThread`. счётчик визитов `count` принадлежит экземпляру, начальное значение 3 соответствует трём посещениям. семафор объявлен статическим полем `sem`, поэтому все экземпляры делят один счётчик разрешений.

```c#
static Semaphore sem = new Semaphore(3, 3);
```

первый аргумент конструктора задаёт, сколько разрешений доступно сразу, второй задаёт максимум. `Semaphore(3, 3)` означает три свободных места при старте и запрет иметь их больше трёх. в модели библиотеки это три читателя в зале одновременно.

работа сосредоточена в методе `Read`, он и является телом потока. в начале итерации поток ждёт место:

```c#
sem.WaitOne();  // ожидаем, когда освободиться место
```

когда `WaitOne` возвращает управление, счётчик уже уменьшен, текущий поток занимает место и читает. `Thread.Sleep(1000)` имитирует время в зале.

по окончании чтения место возвращается:

```c#
sem.Release();  // освобождаем место
```

счётчик растёт на единицу, и один из потоков, стоящих в `WaitOne`, может войти. затем экземпляр уменьшает собственный `count` и ждёт секунду уже вне библиотеки. цикл повторяется, пока `count` больше нуля. пять читателей при трёх разрешениях постоянно конкурируют за вход: часть печатает сообщение о входе сразу, остальные блокируются до ближайшего `Release`.
