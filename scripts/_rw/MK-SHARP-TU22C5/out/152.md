по умолчанию все элементы коллекции в linq обрабатываются последовательно. начиная с .net 4.0 в пространство имён `System.Linq` добавлен класс **ParallelEnumerable**. он инкапсулирует функциональность plinq (parallel linq) и позволяет выполнять обращения к коллекции в параллельном режиме.

при обработке коллекции plinq использует возможности всех процессоров в системе. источник данных разделяется на сегменты, и каждый сегмент обрабатывается в отдельном потоке. на многоядерной машине запрос за счёт этого выполняется быстрее, если полезная работа перекрывает накладные расходы на разделение и объединение.

по умолчанию plinq выбирает последовательную обработку данных. переход к параллельной обработке выполняется в том случае, если он приведёт к ускорению. при параллельных операциях возрастают дополнительные издержки: деление источника на разделы, постановка работы в планировщик, слияние частичных результатов. если параллельная обработка потенциально требует больших затрат, остаётся последовательная обработка, у которой этих затрат нет.

смысл применения plinq есть преимущественно на больших коллекциях или при сложных операциях, где выгода от распараллеливания запросов перекрывает возникающие издержки.

при доступе к общему разделяемому состоянию параллельные операции неявно используют синхронизацию, чтобы избежать взаимоблокировки доступа к этим общим ресурсам. затраты на синхронизацию ведут к снижению производительности, поэтому в параллельных операциях разделяемые ресурсы лучше исключать или ограничивать их применение.

### метод asparallel

метод **AsParallel()** позволяет распараллелить запрос к источнику данных. он реализован как метод расширения linq у массивов и коллекций. при вызове источник данных разделяется на части, если это возможно, и над каждой частью операции производятся отдельно. метод возвращает `ParallelQuery<T>`. дальнейшие операторы такого запроса предоставляет `ParallelEnumerable`.

простейший пример, нахождение квадратов чисел:

```c#


int[] numbers = new int[] { 1, 2, 3, 4, 5, 6, 7, 8, };

var squares = from n in numbers.AsParallel()

                 select Square(n);



foreach (var n in squares)

    Console.WriteLine(n);



int Square(int n) => n * n;
```

фактически это обычный запрос linq, только к источнику данных применяется метод `AsParallel`.

результат работы программы показывает, что данные для нахождения квадратов выбирались не последовательно. произошло распараллеливание работы программы. порядок в таком выводе не зафиксирован контрактом запроса и при другом запуске может быть иным. один из возможных выводов:

```consoletext


49

1

9

25

64

4

16

36
```

аналогичная операция с помощью методов расширения:

```c#


var squares = numbers.AsParallel().Select(x => Square(x));
```

### метод forall

приведённый код вычисления квадрата числа можно дополнительно оптимизировать с точки зрения параллелизации. для вывода результата параллельной операции там используется цикл `foreach`. его использование увеличивает издержки: данные, полученные в разных потоках, нужно склеить в один набор и затем перебрать в цикле. в этом месте уместнее метод **ForAll()**. он выполняет действие в том же потоке, в котором элемент обрабатывается, и не собирает перед действием единую последовательность:

```c#


int[] numbers = new int[] { 1, 2, 3, 4, 5, 6, 7, 8, };



// с помощью операторов LINQ

(from n in numbers.AsParallel() select Square(n)).ForAll(Console.WriteLine);



// с помощью методов расширения LINQ

numbers.AsParallel().Select(n => Square(n)).ForAll(Console.WriteLine);



int Square(int n) => n * n;
```

метод `ForAll()` в качестве параметра принимает делегат `Action<T>`, который указывает на выполняемое действие.
