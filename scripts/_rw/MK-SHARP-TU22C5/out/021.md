в c# аргумент передают в метод двумя способами: по значению и по ссылке.

### передача параметров по значению

передача по значению является обычным способом. параметр становится отдельной локальной переменной и получает копию аргумента:

```c#


void Increment(int n)

{

    n++;

    Console.WriteLine($"Число в методе Increment: {n}");

}



int number = 5;

Console.WriteLine($"Число до метода Increment: {number}");

Increment(number);

Console.WriteLine($"Число после метода Increment: {number}");
```

консольный вывод:

```bash


Число до метода Increment: 5

Число в методе Increment: 6

Число после метода Increment: 5
```

при передаче по значению параметр получает копию аргумента и дальше работает с копией. сама переменная вызывающего кода остается прежней.

`Increment` получает копию `number` и увеличивает копию. внутри метода `n` равно 6. после возврата `number` по-прежнему равно 5: запись шла в копию.

если аргумент имеет ссылочный тип, копируется ссылка, а не объект в куче. изменение полей объекта через эту ссылку видно вызывающему коду. присваивание самому параметру подменяет только локальную копию ссылки.

### передача параметров по ссылке и модификатор ref

передача по ссылке записывается модификатором `ref`:

```c#


void Increment(ref int n)

{

    n++;

    Console.WriteLine($"Число в методе Increment: {n}");

}



int number = 5;

Console.WriteLine($"Число до метода Increment: {number}");

Increment(ref number);

Console.WriteLine($"Число после метода Increment: {number}");
```

консольный вывод:

```bash


Число до метода Increment: 5

Число в методе Increment: 6

Число после метода Increment: 6
```

при передаче по ссылке параметр обозначает ту же ячейку памяти, что и переменная-аргумент. запись в параметр меняет эту ячейку, поэтому после возврата меняется и переменная вызывающего кода.

в `Increment` передается ссылка на `number`. параметр `n` и переменная `number` именуют один адрес. увеличение `n` меняет `number`, после метода там стоит 6.

модификатор `ref` пишут и перед параметром в объявлении, и перед аргументом в вызове. аргумент должен быть переменной с ячейкой памяти, уже присвоенной до вызова: литерал и невычисленное выражение передать через `ref` нельзя.

### выходные параметры. модификатор out

предыдущие параметры были входными: метод читает полученное значение. выходной параметр предназначен для записи результата наружу. его помечают модификатором `out`:

```c#


void Sum(int x, int y, out int result)

{

    result = x + y;

}
```

сумма покидает метод не через `return`, а через выходной параметр `result`. вызов:

```c#


void Sum(int x, int y, out int result)

{

    result = x + y;

}



int number;



Sum(10, 15, out number);



Console.WriteLine(number);   // 25
```

служебное слово `out`, как и `ref`, стоит и в объявлении параметра, и в вызове. передача тоже идет по ссылке, но правила присваивания другие. аргумент `out` можно не инициализировать до вызова: в примере `number` объявлена без начального значения. метод обязан присвоить выходному параметру значение на каждом пути, который завершает метод нормально. до этого присваивания параметр внутри метода читать нельзя. фрагмент ниже недопустим: `result` не получает значения.

```c#


void Sum(int x, int y, out int result)

{

    Console.WriteLine(x + y);

}
```

через несколько выходных параметров метод отдает несколько результатов за один вызов:

```c#


void GetRectangleData(int width, int height, out int rectArea, out int rectPerimetr)

{

    rectArea = width * height;       // площадь прямоугольника - произведение ширины на высоту

    rectPerimetr = (width + height) * 2; // периметр прямоугольника - сумма длин всех сторон  

}



int area;

int perimetr;



GetRectangleData(10, 20, out area, out perimetr);



Console.WriteLine($"Площадь прямоугольника: {area}");       // 200

Console.WriteLine($"Периметр прямоугольника: {perimetr}");   // 60
```

`GetRectangleData` принимает ширину и высоту, параметры `width` и `height`. два выходных параметра получают площадь и периметр. площадь равна произведению сторон, периметр равен сумме длин сторон, то есть `(width + height) * 2`.

переменные для `out`-аргументов можно объявить прямо в вызове. предыдущий фрагмент сокращается так:

```c#


void GetRectangleData(int width, int height, out int rectArea, out int rectPerimetr)

{

    rectArea = width * height;  

    rectPerimetr = (width + height) * 2; 

}



GetRectangleData(10, 20, out int area, out int perimetr);



Console.WriteLine($"Площадь прямоугольника: {area}");       // 200

Console.WriteLine($"Периметр прямоугольника: {perimetr}");   // 60
```

если тип заранее не выписывают, на месте объявления ставят `var`. компилятор выводит тип из типа параметра:

```c#


GetRectangleData(10, 20, out var area, out var perimetr);



Console.WriteLine($"Площадь прямоугольника: {area}");       // 200

Console.WriteLine($"Периметр прямоугольника: {perimetr}");   // 60
```

### входные параметры. модификатор in

кроме выходных параметров с `out` у метода бывают входные параметры с модификатором `in`. аргумент передается по ссылке, а присваивание параметру внутри метода запрещено:

```c#


void GetRectangleData(in int width, in int height, out int rectArea, out int rectPerimetr)

{

    //width = 25; // нельзя изменить, так как width - входной параметр

    rectArea = width * height;      

    rectPerimetr = (width + height) * 2;

}



int w = 10;

int h = 20;

GetRectangleData(w, h, out var area, out var perimetr);



Console.WriteLine($"Площадь прямоугольника: {area}");       // 200

Console.WriteLine($"Периметр прямоугольника: {perimetr}");   // 60
```

через `width` и `height` в метод входят значения, и тело не может им ничего присвоить: параметры помечены `in`. в вызове модификатор перед аргументом опущен, язык это допускает.

передача по ссылке устраняет копирование значения. для крупной структуры это сокращает работу, для `int` копия и так дешева. модификатор `in` при этом фиксирует, что метод не изменит переменные, переданные этими параметрами.

### ref-параметры только для чтения

обычный `ref`-параметр внутри метода можно изменять. если запись нужно запретить, начиная с c# 12 параметр объявляют как `ref readonly`:

```c#


void Increment(ref readonly int n)

{

    // n++; // нельзя, иначе будет очишка компиляции

    Console.WriteLine($"Число в методе Increment: {n}");

}

 

int number = 5;

Increment(ref number);

Console.WriteLine($"Число после метода Increment: {number}");
```

параметр `n` входит в `Increment` по ссылке и доступен только для чтения. в вызове аргумент передается с `ref`. присваивание параметру отвергается на этапе компиляции, переменная вызывающего кода через этот параметр не меняется.
