соединение в linq строит одну последовательность из двух последовательностей, типы элементов которых могут различаться. в синтаксисе запросов соединение записывается оператором **join**, в синтаксисе методов вызывается **Join()**. обе формы сопоставляют элементы по общему критерию.

### оператор join

формальный синтаксис оператора **join**:

```c#


from объект1 in набор1

join объект2 in набор2 on объект2.свойство2 equals объект1.свойство1
```

после `join` идёт выборка объектов из второй коллекции. после `on` указывается ключ объекта второй выборки, после `equals` ключ объекта первой выборки. части `equals` вычисляются по отдельности и сравниваются компаратором `EqualityComparer<TKey>.Default`: в этой позиции допустимо равенство ключей. если ключи равны, оба объекта входят в элемент результата. соединение внутреннее: объект без пары в выходную последовательность не попадает. реализация linq to objects сначала складывает внутреннюю последовательность в таблицу по ключу (`Lookup<TKey, TElement>`), затем каждый внешний элемент ищет в ней совпадения, поэтому ожидаемая стоимость линейна по сумме длин последовательностей.

например, заданы два типа:

```c#


record class Person(string Name, string Company);

record class Company(string Title, string Language);
```

`Person` представляет пользователя и хранит два свойства: `Name` (имя) и `Company` (компания пользователя). `Company` представляет компанию и хранит `Title` (название компании) и `Language` (основной язык программирования в компании). оба типа объявлены как позиционные record-классы. в соединение попадают выбранные свойства, запись целиком при этом не сравнивается.

у объектов обоих классов один общий критерий: название компании. по нему соединяются два набора:

```c#


Person[] people =

{

    new Person("Tom", "Microsoft"), new Person("Sam", "Google"),

    new Person("Bob", "JetBrains"), new Person("Mike", "Microsoft"),

};

Company[] companies =

{

    new Company("Microsoft", "C#"),

    new Company("Google", "Go"),

    new Company("Oracle", "Java")

};

var employees = from p in people

             join c in companies on p.Company equals c.Title

             select new { Name = p.Name, Company = c.Title, Language = c.Language };



foreach (var emp in employees)

    Console.WriteLine($"{emp.Name} - {emp.Company} ({emp.Language})");



record class Person(string Name, string Company);

record class Company(string Title, string Language);
```

роль оператора видна в отдельной строке запроса:

```c#
join c in companies on p.Company equals c.Title
```

объект `p` из списка `people` (элемент типа `Person`) соединяется с объектом `c` из списка `companies` (элемент типа `Company`), если значение `p.Company` совпадает со значением `c.Title`. для `string` такое равенство ординальное и чувствительно к регистру. результатом соединения становится объект анонимного типа с тремя свойствами. пары выходят в порядке элементов `people`. когда одному внешнему элементу соответствует несколько внутренних, эти внутренние элементы идут в порядке `companies`. программа печатает:

```bash


Tom - Microsoft (C#)

Sam - Google (Go)

Mike - Microsoft (C#)
```

в массиве `people` есть объект `new Person("Bob", "JetBrains")`. в массиве компаний нет компании с именем "JetBrains", поэтому этот человек в результат не попадает. симметрично, в `people` нет объектов `Person`, у которых `Company` равен значению из `new Company("Oracle", "Java")`, и элемент `"Oracle"` не даёт ни одной пары.

### метод Join

ту же операцию задаёт метод `Join()`:

```c#


Join(IEnumerable<TInner> inner, 

    Func<TOuter,TKey> outerKeySelector, 

    Func<TInner,TKey> innerKeySelector, 

    Func<TOuter,TInner,TResult> resultSelector);
```

`Join()` принимает четыре параметра:

- вторая последовательность, которая соединяется с текущей
- делегат, который выбирает свойство объекта текущей последовательности, по которому идёт соединение
- делегат, который выбирает свойство объекта второй последовательности, по которому идёт соединение
- делегат, который строит новый объект результата из пары сопоставленных объектов

параметр типа `TOuter` относится к текущей последовательности, `TInner` ко второй, `TKey` к типу ключа, `TResult` к типу элемента результата. предыдущий пример на методе `Join`:

```c#


Person[] people =

{

    new Person("Tom", "Microsoft"), new Person("Sam", "Google"),

    new Person("Bob", "JetBrains"), new Person("Mike", "Microsoft"),

};

Company[] companies =

{

    new Company("Microsoft", "C#"),

    new Company("Google", "Go"),

    new Company("Oracle", "Java")

};

var employees = people.Join(companies, // второй набор

             p => p.Company, // свойство-селектор объекта из первого набора

             c => c.Title, // свойство-селектор объекта из второго набора

             (p, c) => new { Name = p.Name, Company = c.Title, Language = c.Language }); // результат



foreach (var emp in employees)

    Console.WriteLine($"{emp.Name} - {emp.Company} ({emp.Language})");



record class Person(string Name, string Company);

record class Company(string Title, string Language);
```

первый делегат читает `p.Company`, второй читает `c.Title`, третий собирает анонимный тип с `Name`, `Company` и `Language`. смысл критериев совпадает с запросом, где стояли `on` и `equals`.

### GroupJoin

метод **GroupJoin()** соединяет последовательности и тут же группирует совпадения. элемент внешней последовательности сохраняется и тогда, когда совпадений нет: группа в этом случае пуста. это левое внешнее соединение с группировкой по внешнему ключу.

```c#


GroupJoin(IEnumerable<TInner> inner, 

        Func<TOuter,TKey> outerKeySelector, 

        Func<TInner,TKey> innerKeySelector, 

        Func<TOuter, IEnumerable<TInner>,TResult> resultSelector);
```

`GroupJoin()` принимает четыре параметра:

- вторая последовательность, которая соединяется с текущей
- делегат, который выбирает свойство объекта текущей коллекции. по этому свойству идёт и соединение, и группировка
- делегат, который выбирает свойство объекта второй коллекции, по которому идёт соединение
- делегат, который строит объект результата. делегат получает объект текущей коллекции, по которому шла группировка, и набор объектов второй коллекции, составляющих группу (`IEnumerable<TInner>`)

те же массивы `people` и `companies`. внешняя последовательность здесь компании, пользователи собираются в группы по названию компании:

```c#


Person[] people =

{

    new Person("Tom", "Microsoft"), new Person("Sam", "Google"),

    new Person("Bob", "JetBrains"), new Person("Mike", "Microsoft"),

};

Company[] companies =

{

    new Company("Microsoft", "C#"),

    new Company("Google", "Go"),

    new Company("Oracle", "Java")

};

var personnel = companies.GroupJoin(people, // второй набор

             c => c.Title, // свойство-селектор объекта из первого набора

             p => p.Company, // свойство-селектор объекта из второго набора

             (c, employees) => new   // результат

             {

                 Title = c.Title,

                 Employees = employees

            });



foreach (var company in personnel)

{

    Console.WriteLine(company.Title);

    foreach(var emp in company.Employees)

    {

        Console.WriteLine(emp.Name);

    }

    Console.WriteLine();

}



record class Person(string Name, string Company);

record class Company(string Title, string Language);
```

выполнение программы даёт такой вывод:

```consoletext


Microsoft

Tom

Mike



Google

Sam



Oracle
```

набор параметров тот же, что у `Join`. в последний делегат приходят объект компании и набор пользователей этой компании. группа целиком становится полем `Employees` анонимного типа, ключ компании переносится в `Title`.

для компании "Oracle" в массиве `people` пользователей нет, однако группа для неё создаётся. внутренний цикл по `Employees` для этой группы не печатает имён, на консоли остаётся заголовок `"Oracle"`.

тот же результат даёт оператор `join` с продолжением `into`. имя после `into` обозначает группу совпадений, и такая форма запроса транслируется в `GroupJoin`:

```c#


var personnel = from c in companies

                join p in people on c.Title equals p.Company into g

                select new   // результат

                {

                    Title = c.Title,

                    Employees = g

                };
```

### метод Zip

метод **Zip()** последовательно соединяет элементы текущей последовательности с элементами второй по позиции: индекс в первой последовательности совпадает с индексом во второй. первый элемент первой последовательности объединяется с первым элементом второй, второй со вторым, и так далее. длина результата равна меньшей из двух длин: перечисление останавливается, когда заканчивается короткая последовательность. перегрузка без селектора результата, появившаяся в .net 6, возвращает последовательность кортежей, где каждый кортеж хранит пару соответствующих элементов:

```c#


var courses = new List<Course> { new Course("C#"), new Course("Java") };

var students = new List<Student> { new Student("Tom"), new Student("Bob") };



var enrollments = courses.Zip(students);



foreach (var enrollment in enrollments)

    Console.WriteLine($"{enrollment.First} - {enrollment.Second}");



record class Course(string Title);  // учебный курс

record class Student(string Name);  // студент
```

здесь `Zip` объединяет соответствующие элементы списков `courses` и `students`. получается коллекция кортежей. у кортежа два поля: `First` хранит объект текущей коллекции (в примере это `Course`), `Second` хранит объект второй последовательности (в примере это `Student`). консольный вывод:

```consoletext


Course { Title = C# } - Student { Name = Tom }

Course { Title = Java } - Student { Name = Bob }
```
