чтобы пользоваться классом, подключают его пространство имён либо пишут полное имя класса. начиная с visual studio 2022, .net 6 и c# 10 в файле программы допустима такая запись.

```c#
Console.WriteLine("Hello");
```

пространство `System`, в котором лежит класс `Console`, явно не подключено, однако простое имя `Console` доступно в любом файле c# проекта. с .net 6 sdk проекта сам подключает набор часто используемых пространств имён, и повторять `using` для них не нужно. настройка действует на весь проект.

файл проекта открывают двойным щелчком левой кнопки по проекту либо правой кнопкой и пунктом `Edit Project File`.

![implicitusings в c# в visual studio](/uploads/course-lectures/38f4e04bfa812770fff94079542bf4f1bbfafdc3.png)

visual studio открывает файл проекта. это файл msbuild. для консольного приложения он выглядит примерно так.

```xml


<Project Sdk="Microsoft.NET.Sdk">



  <PropertyGroup>

    <OutputType>Exe</OutputType>

    <TargetFramework>net6.0</TargetFramework>

    <ImplicitUsings>enable</ImplicitUsings>

    <Nullable>enable</Nullable>

  </PropertyGroup>



</Project>
```

строка со свойством `ImplicitUsings` задаёт подключение набора пространств имён по умолчанию.

```xml
<ImplicitUsings>enable</ImplicitUsings>
```

элемент `ImplicitUsings` со значением `enable` включает эту настройку. sdk читает свойство и при компиляции порождает исходный файл с директивами `global using`.

после компиляции в каталоге `obj/Debug/net6.0` появляется файл `[имя_проекта].GlobalUsings.g.cs`. если проект называется `HelloApp`, файл называется `HelloApp.GlobalUsings.g.cs`. его содержимое таково.

```c#


global using global::System;

global using global::System.Collections.Generic;

global using global::System.IO;

global using global::System.Linq;

global using global::System.Net.Http;

global using global::System.Threading;

global using global::System.Threading.Tasks;
```

здесь перечислены пространства, которые проект получает по умолчанию. префикс `global::` привязывает имя к корню иерархии пространств, поэтому локальный псевдоним или тип с именем `System` внутри проекта не перехватывает этот импорт.

те же имена без префиксов:

```c#


System

System.Collections.Generic

System.IO

System.Linq

System.Net.Http

System.Threading

System.Threading.Tasks
```

этот набор относится к консольному приложению на sdk `Microsoft.NET.Sdk`. у других типов проектов набор другой: его определяет sdk, указанный в корневом элементе `Project`. библиотека классов и веб-проект получают свои списки.

### отключение пространств по умолчанию

в проектах, которые visual studio 2022 создаёт для .net 6 и c# 10, неявные импорты включены сразу. настройку можно выключить.

```xml
<ImplicitUsings>disable</ImplicitUsings>
```

после этого visual studio 2022 подчёркивает класс `Console`: простое имя нигде в проекте не объявлено, а пространство `System` больше не импортировано.

![implicitusings в .net 6 и c# 10 в visual studio 2022](/uploads/course-lectures/e3c45c04ead3c1789ebf1d80333e85ca2057b1cc.png)

дальше либо подключают `System`, где расположен `Console`, либо пишут полное имя класса.

```c#


using System;   // или подключить пространство System

Console.WriteLine("Hello world");



// или использовать полное имя класса

System.Console.WriteLine("Hello work");
```

первая строка вывода использует импорт `System`. вторая обращается к тому же методу по квалифицированному имени `System.Console`.

### подключение и отключение пространств по отдельности

вместо готового набора пространства можно включать и исключать по одному. файл проекта меняют так.

```xml


<Project Sdk="Microsoft.NET.Sdk">



  <PropertyGroup>

    <OutputType>Exe</OutputType>

    <TargetFramework>net6.0</TargetFramework>

    <ImplicitUsings>disable</ImplicitUsings>

    <Nullable>enable</Nullable>

  </PropertyGroup>

  

  <ItemGroup>

    <Using Include="System" />

    <Using Include="System.Threading.Tasks" />

  </ItemGroup>

  

</Project>
```

атрибут `Include` элемента `Using` подключает пространство глобально, на весь проект.

```c#
<Using Include="System" />
```

эта запись подключает `System`. в файлах кода проекта отдельная директива `using System` уже не нужна. при `ImplicitUsings` со значением `disable` в проект попадают только те пространства, которые перечислены элементами `Using`.

обратная операция убирает отдельные пространства из набора по умолчанию. для неё у элемента `Using` задают атрибут `Remove`.

```xml


<Project Sdk="Microsoft.NET.Sdk">



  <PropertyGroup>

    <OutputType>Exe</OutputType>

    <TargetFramework>net6.0</TargetFramework>

    <ImplicitUsings>enable</ImplicitUsings>

    <Nullable>enable</Nullable>

  </PropertyGroup>

  

  <ItemGroup>

    <Using Remove="System" />

    <Using Remove="System.Threading.Tasks"/>

  </ItemGroup>

  

</Project>
```

здесь при включённых неявных импортах из набора исключаются `System` и `System.Threading.Tasks`. остальные пространства sdk по-прежнему импортируются. `Include` и `Remove` являются элементами msbuild: компилятор c# видит уже готовый список директив `global using`, который sdk собрал из свойства `ImplicitUsings` и из этих элементов.
