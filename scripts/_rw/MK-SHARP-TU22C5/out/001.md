первая программа на языке c# собирается из двух частей: исходного текста и компилятора. для записи исходного текста нужен текстовый редактор. подойдёт любой редактор, в том числе встроенный в windows блокнот. в этом курсе используется редактор **visual studio code**. он доступен для основных операционных систем: windows, macos, linux. дистрибутив размещён по ссылке [загрузить visual studio code](https://code.visualstudio.com/Download)

![c# в visual studio code](/uploads/course-lectures/2db6096eea5aa4235f9b9892b11d9d06702a2f0c.png)

второй необходимый компонент для создания программ: компилятор. для компиляции, построения, запуска и ряда других задач microsoft предоставляет набор инструментов, который называется **.net sdk**. .net sdk является кроссплатформенным и доступен для основных операционных систем и основных архитектур. sdk объединяет компилятор c# (он переводит исходный текст в сборку на cil), среду выполнения и утилиту `dotnet`, через которую вызываются шаблоны проектов, восстановление зависимостей и запуск.

для установки .net sdk под различные системы, windows, macos и linux, используются пакеты установки, которые загружаются с официального сайта по ссылке [https://dotnet.microsoft.com/en-us/download](https://dotnet.microsoft.com/en-us/download).

![загрузка sdk .net](/uploads/course-lectures/f657e611f7bd19bfbaac005ad9b4c4d616a04659.png)

страница автоматически отображает варианты sdk под текущую операционную систему. на данный момент страница загрузок предоставляет последнюю версию .net sdk, 10-ю версию. для изучения используется самая последняя версия, на данный момент это .net 10, которая включает последние возможности и улучшения. при необходимости устанавливаются и другие версии .net. на странице [https://dotnet.microsoft.com/en-us/download](https://dotnet.microsoft.com/en-us/download) при необходимости находятся все варианты sdk под различные архитектуры и системы. несколько sdk на одной машине сосуществуют: утилита `dotnet` выбирает версию по файлу проекта и по глобальному или локальному файлу конфигурации.

### установка на linux

для операционных систем на базе linux применяются разные методы установки: через пакетный менеджер, вручную или с помощью скрипта. самый простой способ: установка через пакетный менеджер. для установки .net sdk 10.0 на ос ubuntu и debian через пакетный менеджер apt выполняется следующая команда:

```bash


sudo apt-get update &&  sudo apt-get install -y dotnet-sdk-10.0
```

более ранние версии ubuntu и debian могут не иметь в репозиториях пакета с самой последней версией .net. например, в официальных репозиториях ubuntu для более ранних версий пакет .net 10.0 недоступен. он доступен в репозиториях компании microsoft. поэтому перед загрузкой .net 10 добавляются соответствующие репозитории microsoft командой:

```bash


sudo add-apt-repository ppa:dotnet/backports
```

и затем устанавливается .net sdk 10.0. пакетный менеджер после этого разрешает зависимость `dotnet-sdk-10.0` уже из добавленного источника, а не из архива дистрибутива.

для установки на fedora через пакетный менеджер dnf применяется команда

```bash
sudo dnf install dotnet-sdk-10.0
```

на других системах на базе linux применяются другие пакетные менеджеры. имя пакета и команда различаются, состав sdk при этом тот же: компилятор, среда выполнения и утилита `dotnet`.

в качестве альтернативы можно загрузить пакет бинарных файлов для определённой системы со страницы [https://dotnet.microsoft.com/en-us/download/dotnet/10.0](https://dotnet.microsoft.com/en-us/download/dotnet/10.0), распаковать его в определённое место на диске и добавить путь к папке с утилитой dotnet внутри этого распакованного пакета в переменную окружения `PATH`. например, если пакет файлов фреймворка распакован в папку "/home/[имя_пользователя]/dotnet-sdk-10.0.100", то для текущей сессии терминала путь к фреймворку добавляется следующим образом:

```bash
export PATH=$HOME/dotnet-sdk-10.0.100:$PATH
```

переменная `PATH` задаёт список каталогов, в которых оболочка ищет исполняемые файлы. добавление каталога sdk в начало списка делает команду `dotnet` видимой в текущем сеансе, не меняя системную установку. после закрытия терминала такое присваивание исчезает, если его не записать в файл инициализации оболочки.

### проверка установки .net

после установки, чтобы убедиться, что всё установлено и настроено правильно, проверяется версия .net. в командной строке или консоли выполняется команда **dotnet --version**:

```bash


C:\Users\eugen>dotnet --version

10.0.100



C:\Users\eugen>
```

на одной машине может быть установлено одновременно несколько версий .net sdk. для проверки установленных версий используется команда **dotnet --list-sdks**:

```bash


C:\Users\eugen>dotnet --list-sdks

8.0.110 [C:\Program Files\dotnet\sdk]

9.0.101 [C:\Program Files\dotnet\sdk]

10.0.100 [C:\Program Files\dotnet\sdk]



C:\Users\eugen>
```

каждая строка вывода содержит номер sdk и каталог, в котором этот sdk расположен. компилятор конкретного проекта выбирается по идентификатору целевой платформы в файле проекта, а не по максимальному установленному номеру.

### создание первой программы на c#

после установки .net sdk создаётся первый проект. для этого используется набор консольных утилит .net cli.

сначала создаётся каталог для проектов на .net (вручную или командой **mkdir**). каталог называется **dotnet** и располагается в текущей папке пользователя. в терминале выполняется переход в этот каталог командой **cd**.

```bash


C:\Users\eugen>mkdir dotnet



C:\Users\eugen>cd dotnet



C:\Users\eugen\dotnet>
```

для создания проекта в .net cli применяется команда **dotnet new**, которой передаётся тип проекта. создаётся консольное приложение, поэтому используется тип `console`. в терминале вводится следующая команда:

```bash


dotnet new console -o helloapp
```

здесь создаваемый проект представляет консольное приложение (console), а опция `-o` задаёт название проекта. проект будет называться helloapp. при выполнении команды консоль отображает базовую информацию:

```bash


C:\Users\eugen\dotnet>dotnet new console -o helloapp

Шаблон "Консольное приложение" успешно создан.



Идет обработка действий после создания...

Восстановление C:\Users\eugen\dotnet\helloapp\helloapp.csproj:

  Определение проектов для восстановления...

  Восстановлен C:\Users\eugen\dotnet\helloapp\helloapp.csproj (за 1,01 sec).

Восстановление выполнено.







C:\Users\eugen\dotnet>
```

после выполнения этой команды в папке helloapp создаётся проект с минимальным набором стандартных файлов и папок. шаблон одновременно порождает файл проекта и запускает восстановление: подтягиваются целевые пакеты платформы, без которых сборка не находит базовую библиотеку.

![.net cli создание проекта](/uploads/course-lectures/1a105fd681fa6e760aacea15c6fe73f994851b04.png)

в папке проекта находится файл **helloapp.csproj**. это главный файл проекта, который определяет его конфигурацию. его можно открыть в любом текстовом редакторе, просмотреть и при необходимости изменить. файл проекта записан в формате xml и задаёт, в частности, вид выходной сборки и версию целевой платформы.

кроме того, по умолчанию создаётся главный файл программы **Program.cs** со следующим содержимым:

```c#


// See https://aka.ms/new-console-template for more information

Console.WriteLine("Hello, World!");
```

если нужно внести изменения в исходный код программы, изменяется содержимое именно этого файла. в современных шаблонах консольного приложения операторы верхнего уровня допускаются непосредственно в файле: компилятор сам помещает их в синтезированный метод точки входа. отдельное объявление класса и метода `Main` в таком шаблоне не обязательно.

этот минимальный проект уже можно запускать. для запуска выполняется переход в консоли в папку проекта helloapp, и для выполнения программы вводится команда **dotnet run**:

```bash


C:\Users\eugen\dotnet> cd helloapp

C:\Users\eugen\dotnet\helloapp>dotnet run

Hello, World!



C:\Users\eugen\dotnet\helloapp>
```

команда `dotnet run` восстанавливает зависимости, если это ещё не сделано, компилирует проект и запускает полученную сборку. после выполнения команды в проекте в папке `bin\Debug\net9.0` появляются файлы программы (на windows это файлы helloapp.dll и helloapp.exe), которые можно вручную запустить на компьютере, где установлен .net 9. каталог `Debug` соответствует конфигурации отладочной сборки, а `net9.0` является идентификатором целевой платформы, записанным в файле проекта.

![компиляция программы c# с помощью .net cli](/uploads/course-lectures/7ea18ba2ad344fa241da99ee0ec1d5006e1a2cd5.png)

затем весь код программы заменяется. файл **Program.cs** открывается в текстовом редакторе, и его код заменяется на следующий:

```c#


Console.Write("Введите свое имя: ");

var name = Console.ReadLine();       // вводим имя

Console.WriteLine($"Привет {name}");    // выводим имя на консоль
```

![изменение кода программы на c# и .net](/uploads/course-lectures/a6344099d81981834cbdf380a6b0a305f992f000.png)

по сравнению с автоматически сгенерированным кодом изменено несколько мест. теперь первой строкой выводится приглашение к вводу.

```c#
Console.Write("Введите свое имя: ");
```

метод **Console.Write()** выводит на консоль строку. здесь это строка `"Введите свое имя: "`. в отличие от `Console.WriteLine`, этот метод не добавляет перевод строки, поэтому курсор остаётся на той же строке, и ввод продолжается сразу за приглашением.

на второй строке определяется строковая переменная name, в которую пользователь вводит информацию с консоли:

```c#
var name = Console.ReadLine();
```

ключевое слово **var** указывает на определение переменной. здесь переменная называется `name`. ей присваивается результат метода **Console.ReadLine()**, который считывает с консоли введённую строку. в консоли вводится строка (имя), и эта строка оказывается в переменной `name`. `var` не отменяет статическую типизацию: компилятор выводит тип по правой части, и далее переменная имеет этот тип на всём протяжении области видимости. метод `Console.ReadLine` возвращает строку, поэтому тип `name` фиксируется как строковый.

затем введённое имя выводится на консоль:

```c#
Console.WriteLine($"Привет {name}");
```

чтобы ввести значение переменной name внутрь выводимой на консоль строки, применяются фигурные скобки {}. при выводе строки на консоль выражение `{name}` заменяется на значение переменной name, введённое имя.

чтобы таким образом вводить значения переменных внутрь строки, перед строкой указывается знак доллара $. такая строка называется интерполированной: компилятор превращает её в вызов форматирования, а выражения в фигурных скобках вычисляются во время выполнения и подставляются в результат.

затем проект проверяется запуском командой **dotnet run**:

```bash


C:\Users\eugen\dotnet\helloapp>dotnet run

Введите свое имя: Евгений

Привет Евгений



C:\Users\eugen\dotnet\helloapp>
```
