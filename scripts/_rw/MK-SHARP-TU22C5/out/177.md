xml остаётся распространённым текстовым форматом документов для данных со сложной иерархией. в базовой библиотеке .net для этого формата предусмотрено несколько api чтения и записи. прежде чем переходить к файлам, фиксируется устройство xml-документа и способ, которым в нём представляется объект программы на c#.

исходный тип выглядит так:

```c#


class Person

{

    public string Name { get;}

    public int Age { get; set; }

    public string Company { get; set; }

    public Person(string name, int age, string company)

    {

        Name = name;

        Age = age;

        Company = company;

    }

}
```

список экземпляров `Person` строится обычным выражением:

```c#


var employees = new List<Person>

{

    new Person ("Tom", 37, "Microsoft"),

    new Person ("Bob", 41, "Google")

};
```

тот же список можно сохранить документом xml:

```xml


<?xml version="1.0" encoding="utf-8" ?>

<people>

  <person name="Tom">

    <company>Microsoft</company>

    <age>37</age>

  </person>

  <person name="Bob">

    <company>Google</company>

    <age>41</age>

  </person>

</people>
```

документ открывает объявление `<?xml version="1.0" encoding="utf-8" ?>`. оно задаёт версию xml, здесь 1.0, и кодировку октетов, здесь utf-8. после объявления идёт тело документа.

у документа ровно один корневой элемент, и вся остальная разметка помещается внутрь него. в примере такой корень записан тегом `<people>`. внутри `<people>` расположен набор элементов `<person>`. вынести `person` за пределы корня нельзя: второй элемент верхнего уровня нарушает синтаксис xml и в дерево документа не входит.

элемент задаётся парой тегов, открывающего и закрывающего, например `<person>` и `</person>`. между ними стоит значение или вложенная разметка. применяется и пустая запись `<person />`: косая черта перед закрывающей угловой скобкой показывает, что содержимого нет.

у элемента могут быть вложенные элементы и атрибуты. у каждого `person` в примере два вложенных элемента, `company` и `age`, и атрибут `name`.

атрибут записывается в открывающем теге в форме `название="значение"`. во фрагменте `<person name="Bill Gates">` атрибут называется `name` и имеет значение `Bill Gates`.

у простого элемента значением служит его текст. во фрагменте `<company> Google </company>` элемент `company` имеет значение `Google`. пробелы, стоящие в разметке вокруг текста, входят в текстовый узел.

имена элементов чувствительны к регистру, поэтому `<person>` и `<Person>` обозначают разные элементы.

список объектов, в источнике названный `Users`, сопоставляется с корневым элементом `<people>`, каждый объект `Person` сопоставляется с элементом `<person>`, а каждое свойство объекта сопоставляется с атрибутом либо с вложенным элементом этого `<person>`.

для свойства одинаково законны и атрибут, и вложенный элемент: различие относится к схеме документа. вместо атрибута `name` можно записать одноимённый дочерний элемент:

```xml


<?xml version="1.0" encoding="utf-8" ?>

<people>

  <person>

	<name>Tom</name>

    <company>Microsoft</company>

    <age>37</age>

  </person>

  <person>

	<name>Bob</name>

    <company>Google</company>

    <age>41</age>

  </person>

</people>
```

дальше рассматриваются основные модели работы с xml, которые есть в c#.
