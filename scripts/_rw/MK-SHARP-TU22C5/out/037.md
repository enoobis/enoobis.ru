в предыдущей теме библиотека классов создавалась в visual studio и подключалась к другому проекту того же решения. те же шаги выполняются без visual studio, через .net cli.

для создания проекта библиотеки команде `dotnet new` передают шаблон `classlib`.

```consoletext
dotnet new classlib
```

проект библиотеки в примере располагается в папке `C:\dotnet\console\mylib`. его создают так.

```consoletext


C:\Users\eugen>cd C:\dotnet\console\mylib



C:\dotnet\console\mylib>dotnet new classlib

Шаблон "Библиотека классов" успешно создан.



Идет обработка действий после создания...

Восстановление C:\dotnet\console\mylib\mylib.csproj:

  Определение проектов для восстановления...

  Восстановлен C:\dotnet\console\mylib\mylib.csproj (за 79 ms).

Восстановление выполнено.



C:\dotnet\console\mylib>
```

команда создаёт проект с файлом `Class1.cs`.

![создание библиотеки классов c# с помощью .net cli](/uploads/course-lectures/a9e5dcda6398b79606c20b996bd2d8de6af04ab5.png)

это тот же вид проекта, который создаёт visual studio по шаблону библиотеки классов. файл `Class1.cs` переименовывают в `Person.cs`, класс `Class1` в `Person` и записывают в нём такой код.

```c#


namespace MyLib

{

    public class Person

    {

        string name;

        public Person(string name) 

        {

            this.name = name;

        }

        public void Print() => Console.WriteLine($"Name: {name}");

    }

}
```

библиотеку строят командой

```consoletext
dotnet build
```

после построения в каталоге проекта `\bin\Debug\net7.0\` появляется файл `mylib.dll`. каталог целевой платформы зависит от `TargetFramework` в файле проекта: в этой теме sdk создаёт проект под `net7.0`, поэтому сборка лежит именно в `net7.0`.

библиотеку подключают к другому проекту. для проверки новый консольный проект создают в папке `C:\dotnet\console\helloapp`, то есть в соседней папке относительно `mylib`.

```consoletext
dotnet new console
```

![подключение библиотеки классов в проект на c# через .net cli](/uploads/course-lectures/e3328c3eaef22447a923a75d12129d1636a65a87.png)

ссылку одного проекта на другой добавляет команда `dotnet add reference`. общий формат такой.

```c#


dotnet add путь_к_файлу_csproj_главного_проекта reference путь_к_файлу_csproj_подключаемого_проекта
```

если текущая папка является папкой проекта `helloapp`, подключение библиотеки записывается так.

```consoletext


dotnet add helloapp.csproj reference ..\mylib\mylib.csproj
```

![подключение библиотеки классов в консольный проект на c# через .net cli](/uploads/course-lectures/c82a39eb3d56597460b4d4daecb75843c08dad71.png)

команда дописывает в `helloapp.csproj` элемент `ProjectReference` на `mylib.csproj`. при сборке `helloapp` система сборки сначала строит библиотеку и передаёт компилятору полученный dll. членство проектов в одном решении само по себе такой ссылки не создаёт: ссылка и решение являются разными отношениями между проектами.

после подключения в главном проекте меняют `Program.cs`, чтобы он использовал класс `Person`.

```c#


using MyLib;    // подключение пространства имен из библиотеки классов



Person tom = new("Tom");

tom.Print();    // Name: Tom
```

#### удаление ссылки на проект

ссылку удаляют симметричной командой.

```c#


dotnet remove путь_к_файлу_csproj_главного_проекта reference путь_к_файлу_csproj_подключаемого_проекта
```

команда убирает соответствующий `ProjectReference` из файла проекта, который указан первым путём.

### создание решения

решение создаёт команда `dotnet new sln`. по умолчанию она пишет файл решения в текущую папку. в терминале переходят в папку консольного проекта и выполняют команду.

```consoletext


dotnet new sln
```

в текущей папке появляется файл с расширением `.sln`. имя файла по умолчанию совпадает с именем текущей папки.

ранее созданные проекты добавляют в решение командой `dotnet sln add`. обобщённый формат такой.

```c#
dotnet sln [путь_к_файлу_решения.sln] add путь_к_файлу_csproj_добавляемого_проекта
```

если файл решения лежит в текущей папке, путь к нему можно не указывать. из папки консольного проекта `helloapp` последовательно выполняют две команды.

```consoletext


dotnet sln add helloapp.csproj

dotnet sln add ..\mylib\mylib.csproj
```

![добавление проектов на c# в решение через .net cli](/uploads/course-lectures/eb0f0820608bdb906f10b405ccd5baff1c7c0ced.png)

первая команда добавляет в решение сам `helloapp.csproj`, вторая добавляет `..\mylib\mylib.csproj`. чтобы убрать проект из решения, применяют команду

```c#
dotnet sln [путь_к_файлу_решения.sln] remove путь_к_файлу_csproj_удаляемого_проекта
```

удаление из решения не удаляет каталог проекта и не снимает ссылку `ProjectReference`, если она была добавлена отдельно. ссылку по-прежнему снимают командой `dotnet remove ... reference`.
