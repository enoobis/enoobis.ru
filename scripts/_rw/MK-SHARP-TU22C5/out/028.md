### создание конструкторов

в предыдущей лекции объект создавался конструктором по умолчанию. конструкторы можно объявить и самостоятельно. обычно конструктор инициализирует объект. если в классе объявлен хотя бы один собственный конструктор, автоматический конструктор по умолчанию больше не генерируется. вызов `new Person()` тогда компилируется только когда среди объявленных конструкторов есть вариант без параметров.

в коде конструктор выглядит как метод с именем класса. параметры у него допустимы, возвращаемый тип не указывается. простейший конструктор в классе `Person`:

```c#


Person tom = new Person();  // Создание объекта класса Person



tom.Print();    // Имя: Tom  Возраст: 37



class Person 

{

    public string name;

    public int age;

    public Person()

    {

        Console.WriteLine("Создание объекта Person");

        name = "Tom";

        age = 37;

    }

    public void Print()

    {

        Console.WriteLine($"Имя: {name}  Возраст: {age}");

    }

}
```

конструктор выводит на консоль сообщение и инициализирует поля класса.

```c#


public Person()

{

	Console.WriteLine("Создание объекта Person");

	name = "Tom";

	age = 37;

}
```

у конструктора бывают модификаторы доступа, их пишут перед именем. чтобы конструктор можно было вызвать вне `Person`, ему указан `public`. закрытый конструктор оставил бы создание экземпляров внутри типа.

после объявления конструктор вызывается при создании объекта `Person`:

```c#
Person tom = new Person();  // Создание объекта Person
```

выражение `Person()` здесь есть вызов конструктора, объявленного в классе. автоматического конструктора по умолчанию у класса уже нет. при выполнении на консоль выводится строка `"Создание объекта Person"`, а поля `name` и `age` получают значения `"Tom"` и 37.

в классе можно объявить несколько конструкторов. класс `Person` с тремя конструкторами:

```c#


Person tom = new Person();          // вызов 1-ого конструктора без параметров

Person bob = new Person("Bob");     //вызов 2-ого конструктора с одним параметром

Person sam = new Person("Sam", 25); // вызов 3-его конструктора с двумя параметрами



tom.Print();          // Имя: Неизвестно  Возраст: 18

bob.Print();          // Имя: Bob  Возраст: 18

sam.Print();          // Имя: Sam  Возраст: 25



class Person 

{

    public string name;

    public int age;

    public Person() { name = "Неизвестно"; age = 18; }      // 1 конструктор

    public Person(string n) { name = n; age = 18; }         // 2 конструктор

    public Person(string n, int a) { name = n; age = a; }   // 3 конструктор



    public void Print()

    {

        Console.WriteLine($"Имя: {name}  Возраст: {age}");

    }

}
```

три конструктора различаются числом параметров и по-разному заполняют поля. для создания объекта вызывается ровно один из них: компилятор выбирает перегрузку по числу и типам аргументов. конструктор без параметров ставит имя `"Неизвестно"` и возраст 18. конструктор с одним аргументом типа `string` записывает переданное имя и тот же возраст 18. конструктор с двумя аргументами записывает и имя, и возраст.

консольный вывод программы:

```bash


Имя: Неизвестно  Возраст: 18

Имя: Bob  Возраст: 18

Имя: Sam  Возраст: 25
```

начиная с c# 9 вызов конструктора можно записать без повторения имени типа, если тип выводится из левой части объявления:

```c#


Person tom = new ();			// аналогично new Person();

Person bob = new ("Bob");		// аналогично new Person("Bob");

Person sam = new ("Sam", 25);	// аналогично new Person("Sam", 25);
```

запись `new ()`, `new ("Bob")` и `new ("Sam", 25)` означает те же вызовы `new Person()`, `new Person("Bob")` и `new Person("Sam", 25)`. тип берётся из типа переменной. это целевая типизация `new`: аргументы по-прежнему выбирают перегрузку, меняется только синтаксис.

### ключевое слово this

ключевое слово `this` обозначает ссылку на текущий экземпляр класса. оно требуется, когда имя параметра совпадает с именем поля и скрывает его.

```c#


Person sam = new("Sam", 25); 

sam.Print();          // Имя: Sam  Возраст: 25



class Person 

{

    public string name;

    public int age;

    public Person() { name = "Неизвестно"; age = 18; }

    public Person(string name) { this.name = name; age = 18; }

    public Person(string name, int age) 

	{ 

		this.name = name; 

		this.age = age; 

	}

    public void Print() => Console.WriteLine($"Имя: {name}  Возраст: {age}");

}
```

во втором и третьем конструкторах параметры названы так же, как поля. чтобы отличить поле от параметра, к полю обращаются через `this`. в выражении

```b
this.name = name;
```

левая часть `this.name` есть поле текущего экземпляра, а правая часть `name` есть параметр. если бы имена различались, `this` было бы необязательно: простое имя поля и так обозначает член экземпляра. через `this` можно обратиться к любому полю или методу этого объекта. внутри статического члена `this` нет: статический член не связан с конкретным экземпляром.

### цепочка вызова конструкторов

три конструктора выше выполняют одно и то же действие: записывают `name` и `age`. повторяющихся присваиваний может быть больше. дублировать тело не обязательно: один конструктор вызывает другой через `this`, передавая нужные аргументы.

```c#


class Person 

{

    public string name;

    public int age;

    public Person() : this("Неизвестно")    // первый конструктор

    { }

    public Person(string name) : this(name, 18) // второй конструктор

    { }

    public Person(string name, int age)     // третий конструктор

    {

        this.name = name;

        this.age = age;

    }

    public void Print() => Console.WriteLine($"Имя: {name}  Возраст: {age}");

}
```

первый конструктор вызывает второй, второй вызывает третий. какой конструктор вызывается, компилятор определяет по числу и типам аргументов в `this(...)`. во втором конструкторе:

```c#


public Person(string name) : this(name, 18)

{ }
```

идёт обращение к третьему конструктору, ему передаются два значения. сначала выполняется тело третьего конструктора, и только потом тело второго. инициализатор `this(...)` отрабатывает до тела того конструктора, в котором записан. тела первого и второго конструкторов в примере пусты: вся запись полей сосредоточена в третьем.

в этом примере конструкторы не делают ничего, кроме передачи значений третьему. проще оставить один конструктор и задать параметрам значения по умолчанию:

```c#


Person tom = new();

Person bob = new("Bob");

Person sam = new("Sam", 25);



tom.Print();          // Имя: Неизвестно  Возраст: 18

bob.Print();          // Имя: Bob  Возраст: 18

sam.Print();          // Имя: Sam  Возраст: 25



class Person 

{

    public string name;

    public int age;

    public Person(string name = "Неизвестно", int age = 18)

    {

        this.name = name;

        this.age = age;

    }

    public void Print() => Console.WriteLine($"Имя: {name}  Возраст: {age}");

}
```

если при вызове аргумент для параметра не передан, подставляется значение по умолчанию. `new()` соответствует имени `"Неизвестно"` и возрасту 18, `new("Bob")` подставляет возраст 18, `new("Sam", 25)` задаёт оба аргумента. значения по умолчанию стоят в конце списка параметров, иначе вызов был бы неоднозначен.

### первичные конструкторы

начиная с c# 12 у класса могут быть первичные конструкторы. параметры записываются прямо в объявлении класса и доступны в его теле:

```c#


var tom = new Person("Tom", 38);

Console.WriteLine(tom);



public class Person(string name, int age)

{

    public Person(string name) : this(name, 18) { }

    public void Print() => Console.WriteLine($"name: {name}, age: {age}");

}
```

у класса `Person` первичный конструктор имеет параметры `name` и `age`. они используются в методе `Print`.

для каждого параметра первичного конструктора, к которому обращаются из тела класса, компилятор создаёт закрытое поле и хранит в нём значение параметра. поэтому параметр виден не только в момент вызова конструктора, но и в методах экземпляра. параметр, который нигде в теле не читается, такого поля не получает.

помимо первичного, класс может объявлять дополнительные конструкторы, как в примере выше. дополнительный конструктор обязан вызвать первичный:

```c#
public Person(string name) : this(name, 18) { }
```

инициализатор `this(name, 18)` передаёт управление первичному конструктору. обойти его нельзя: состояние, захваченное первичными параметрами, должно быть инициализировано.

### инициализаторы объектов

поля и свойства объекта можно задать инициализатором: в фигурных скобках после создания перечисляются присваивания доступным членам.

```c#


Person tom = new Person { name = "Tom", age = 31 };

// или так

// Person tom = new() { name = "Tom", age = 31 };

tom.Print();          // Имя: Tom  Возраст: 31
```

инициализатор присваивает значения доступным полям и свойствам в момент создания. действуют два правила:

- инициализатор задаёт только те поля и свойства, которые доступны снаружи класса. в примере `name` и `age` имеют модификатор `public`, поэтому они доступны из любой части программы. закрытое поле в инициализаторе снаружи записать нельзя.
- инициализатор выполняется после конструктора. если одно и то же поле задано и в конструкторе, и в инициализаторе, значение из конструктора заменяется значением из инициализатора.

инициализатор уместен, когда поле или свойство само имеет тип класса:

```c#


Person tom = new Person{ name = "Tom", company = { title = "Microsoft"} };

tom.Print();          // Имя: Tom  Компания: Microsoft



class Person

{

    public string name;

    public Company company;

    public Person() 

    { 

        name = "Undefined";

        company = new Company();

    }

    public void Print() => Console.WriteLine($"Имя: {name}  Компания: {company.title}");

}



class Company

{

    public string title = "Unknown";

}
```

поле `company` задаётся так:

```c#
company = { title = "Microsoft"}
```

такая запись не создаёт новый объект `Company`. она меняет поля уже существующего объекта, который конструктор `Person` заранее поместил в `company`. если бы поле осталось `null`, обращение к `title` внутри инициализатора было бы невозможным. поэтому конструктор выполняет `company = new Company()` до инициализатора.

### деконструкторы

деконструктор, его не смешивают с деструктором, раскладывает объект на отдельные части. деструктор связан с завершением жизни объекта, деконструктор только читает состояние и отдаёт его наружу через выходные параметры.

класс `Person`:

```c#


class Person

{

    string name;

    int age;

    public Person(string name, int age)

    {

        this.name = name;

        this.age = age;

    }



    public void Deconstruct(out string personName, out int personAge)

    {

        personName = name;

        personAge = age;

    }

}
```

декомпозиция объекта `Person`:

```c#


Person person = new Person("Tom", 33);



(string name, int age) = person;



Console.WriteLine(name);    // Tom

Console.WriteLine(age);     // 33
```

значения из деконструктора передаются по позиции. первый выходной параметр `personName` попадает в первую переменную `name`, второй параметр `personAge` попадает в переменную `age`. имена переменных слева с именами параметров `Deconstruct` не сравниваются.

по существу деконструктор есть позиционный способ разобрать объект на компоненты. тот же эффект даёт прямой вызов:

```c#


Person person = new Person("Tom", 33);



string name; int age;

person.Deconstruct(out name, out age);
```

при разборе нужно объявить столько переменных, сколько значений возвращает деконструктор. если часть значений не нужна, на их месте пишут прочерк `_`. чтобы получить только возраст:

```c#


Person person = new Person("Tom", 33);



(_, int age) = person;



Console.WriteLine(age);    // 33
```

первое возвращаемое значение есть имя, оно здесь не используется, поэтому вместо переменной стоит `_`. прочерк не создаёт переменную и не обязывает далее к этому значению обращаться.
