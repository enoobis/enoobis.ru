точка входа в программу на c# есть метод `Main`. выполнение начинается с него, и программа обязана иметь метод `Main`.

возникает вопрос, где этот метод, если visual studio 2022 по умолчанию создаёт консольное приложение с таким текстом:

```c#


// See https://aka.ms/new-console-template for more information

Console.WriteLine("Hello, World!");
```

явного метода `Main` в файле нет, но программа выполняется и выводит на консоль строку `"Hello, World!"`. это программа верхнего уровня (top-level program). вызов `Console.WriteLine("Hello, World!")` есть инструкция верхнего уровня (top-level statement).

компилятор помещает эти инструкции в метод `Main`, а метод помещает в класс. имя класса может быть любым. обычно генерируется класс `Program`, поэтому файл кода по умолчанию называется `Program.cs`. метод `Main` остаётся обязательной частью консольного приложения: среда выполнения ищет его как точку входа. приведённый текст эквивалентен программе:

```c#


class Program

{

	static void Main(string[] args)

	{

		// See https://aka.ms/new-console-template for more information

		Console.WriteLine("Hello, World!");

	}

}
```

объявление `Main` начинается с модификатора `static`. метод статический: он вызывается без экземпляра. к моменту старта процесса экземпляр ещё некому создать, поэтому точка входа не может быть обычным методом объекта. что именно означает `static` для остальных членов, разбирается отдельно.

в этой форме возвращаемый тип `Main` есть `void`. параметром метод принимает массив строк `string[] args`. при запуске из консоли в этот массив попадают аргументы командной строки. внутри метода располагаются действия программы. язык допускает и другие сигнатуры точки входа, в том числе возврат `int` как код завершения процесса. шаблон, который порождают инструкции верхнего уровня, использует именно `void` и `string[] args`.

до visual studio 2022 предыдущие версии среды создавали по умолчанию примерно такой явный класс и метод. начиная с visual studio 2022 класс `Program` и метод `Main` можно не писать вручную: их генерирует компилятор.

переменные, константы и методы, к которым обращаются на верхнем уровне, помещаются внутрь сгенерированного `Main`. программа верхнего уровня

```c#


string hello = "Hello  enoobis.COM";



Print(hello);



void Print(string message)

{

	Console.WriteLine(message);

}
```

эквивалентна программе

```c#


class Program

{

	static void Main(string[] args)

	{

		string hello = "Hello  enoobis.COM";



		Print(hello);



		void Print(string message)

        {

			Console.WriteLine(message);

        }

	}

}
```

локальная функция `Print` оказалась внутри `Main`. на верхнем уровне она не становится методом класса: у инструкций верхнего уровня нет собственного типа, и функция остаётся локальной для сгенерированного метода.

новые типы, например классы, помещаются вне класса `Program`. код

```c#


Person tom = new();

tom.SayHello();



class Person

{ 

    public void SayHello() =>Console.WriteLine("Hello");

}
```

эквивалентен следующему:

```c#


class Program

{

	static void Main(string[] args)

	{

		Person tom = new();

		tom.SayHello();

	}

}

class Person

{

	public void SayHello() => Console.WriteLine("Hello");

}
```

объявления типов, в частности классов, должны стоять в конце файла, после инструкций верхнего уровня:

```c#


// инструкции верхнего уровня (top-level statements)

Person tom = new();

tom.SayHello();



// определение класса идет после инструкций верхнего уровня

class Person

{

    public void SayHello() => Console.WriteLine("Hello");

}
```

порядок в файле фиксирован. сначала идут исполняемые инструкции, затем объявления типов. тип, записанный выше инструкции верхнего уровня, не компилируется: компилятору нужно отделить тело будущего `Main` от типов, которые в это тело не входят.

программы верхнего уровня можно писать и дальше, без явного метода `Main`. можно и явно объявить класс `Program` и метод `Main`:
