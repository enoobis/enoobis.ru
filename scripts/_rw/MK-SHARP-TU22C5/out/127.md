класс **AutoResetEvent** задаёт событие синхронизации потоков и лежит в пространстве имён `System.Threading`. объект находится в одном из двух состояний, сигнальном или несигнальном. вызов ожидания, заставший сигнальное состояние, атомарно переводит объект в несигнальное и отпускает ровно один поток: сигнал потребляется. в этом устройство автосброса. соседний примитив `ManualResetEvent` после сигнала остаётся сигнальным, пока состояние не сбросят явно, и тогда проходят все ожидающие.

управление состоянием дают три метода:

- `Reset()` : переводит объект в несигнальное состояние. последующие `WaitOne` блокируются, пока сигнал не будет выставлен снова.

- `Set()` : переводит объект в сигнальное состояние. если потоки уже ждут на этом событии, продолжить работу может один из них, после чего событие само возвращается в несигнальное состояние. если очередь пуста, сигнал сохраняется до первого `WaitOne`. формулировка «один или несколько потоков» относится к паре событий целиком: несколько ожидающих одновременно отпускает `ManualResetEvent`, потому что его `Set` сигнал не снимает.

- `WaitOne()` : ждёт сигнальное состояние и по успешному завершению оставляет объект несигнальным. если событие уже сигнальное, поток не блокируется: сброс и возврат из вызова происходят сразу. если событие несигнальное, текущий поток блокируется, пока другой поток не вызовет `Set`.

пока событие несигнальное, поток, вызвавший `WaitOne`, стоит. метод `Set` задаёт сигнальное состояние и тем самым даёт ожиданию завершиться.

в одной из предыдущих тем взаимное исключение записывалось оператором `lock`. он разворачивается в пару `Monitor.Enter` / `Monitor.Exit` и привязывает владение монитором к потоку:

```c#


int x = 0;

object locker = new();  // объект-заглушка

// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Thread myThread = new(Print);

    myThread.Name = $"Поток {i}";

    myThread.Start();

}





void Print()

{

    lock (locker)

    {

        x = 1;

        for (int i = 1; i < 6; i++)

        {

            Console.WriteLine($"{Thread.CurrentThread.Name}: {x}");

            x++;

            Thread.Sleep(100);

        }

    }

}
```

тот же сценарий на **AutoResetEvent**:

```c#


int x = 0;  // общий ресурс



AutoResetEvent waitHandler = new AutoResetEvent(true);  // объект-событие



// запускаем пять потоков

for (int i = 1; i < 6; i++)

{

    Thread myThread = new(Print);

    myThread.Name = $"Поток {i}";

    myThread.Start();

}





void Print()

{

    waitHandler.WaitOne();  // ожидаем сигнала

    x = 1;

    for (int i = 1; i < 6; i++)

    {

        Console.WriteLine($"{Thread.CurrentThread.Name}: {x}");

        x++;

        Thread.Sleep(100);

    }

    waitHandler.Set();  //  сигнализируем, что waitHandler в сигнальном состоянии

}
```

переменная типа `AutoResetEvent` создаётся с аргументом `true`. этот аргумент задаёт начальное состояние: `true` означает сигнальное, и один `WaitOne` проходит сразу. значение `false` создало бы событие несигнальным.

поток, вошедший в `Print`, первым делом вызывает `waitHandler.WaitOne()`. вызов либо потребляет уже выставленный сигнал и сбрасывает событие, либо переводит поток в ожидание, пока объект не станет сигнальным. из нескольких потоков, дошедших до этой строки, критический участок занимает один: после его прохода событие уже несигнальное, остальные остаются в очереди.

после цикла поток вызывает `waitHandler.Set` и сообщает, что объект снова сигнальный. один из ожидающих забирает сигнал, переводит событие в несигнальное состояние и выполняет своё тело. прочие продолжают ждать следующего `Set`. владение здесь не привязано к потоку. `WaitOne` и `Set` могут вызывать разные потоки. у `Monitor` освобождение делает тот же поток, который захватил монитор.

при начальном `true` первый поток, успевший вызвать `WaitOne`, входит в участок без предварительного `Set` из пользовательского кода.

запись `AutoResetEvent waitHandler = new AutoResetEvent(false)` оставляет объект несигнальным с самого начала. все пять потоков блокируются в `waitHandler.WaitOne()`, и ни один не доходит до `Set`. получается взаимная блокировка: программа не продвигается.

если объектов `AutoResetEvent` несколько, их совместно ждут статическими методами `WaitAll` и `WaitAny`. оба принимают массив `WaitHandle`, базового класса для `AutoResetEvent`, а также для `Mutex`, `Semaphore` и `ManualResetEvent`. `WaitAll` возвращает управление, когда сигнал есть у каждого элемента. `WaitAny` возвращает управление, когда сигнал есть хотя бы у одного, и даёт индекс этого элемента.

в примере выше строка

```c#
waitHandler.WaitOne();
```

заменяется на

```c#


AutoResetEvent.WaitAll(new WaitHandle[] {waitHandler});
```

массив из одного `waitHandler` задаёт то же условие пробуждения, что и одиночный `WaitOne`: поток не входит в критический участок, пока событие несигнальное. при успешном ожидании событие с автосбросом снова оказывается несигнальным, и следующий поток проходит только после нового `Set`.
