чтобы облегчить написание, тестирование и отладку программного кода, нередко используют специальные среды разработки, в частности visual studio. ниже рассматривается создание приложений на c# с помощью бесплатной и полнофункциональной среды visual studio community 2026, которую можно загрузить по следующему адресу: [microsoft visual studio 2026](https://visualstudio.microsoft.com/ru/downloads/)

![установка visual studio 2026](/uploads/course-lectures/25aa2bb696ada58e80eab416133eb5a1c22eeabb.png)

после загрузки запускается программа установщика. в открывшемся окне предлагается выбрать компоненты, которые устанавливаются вместе с visual studio. visual studio является функциональной средой разработки и позволяет разрабатывать приложения с помощью множества языков и платформ. в этом курсе интерес представляют прежде всего c# и .net. среда объединяет редактор, отладчик, дизайнер проектов и вызов того же sdk, который используется из командной строки: сборка по-прежнему порождает сборку на cil.

чтобы добавить в visual studio поддержку проектов для c# и .net, в программе установки среди рабочих нагрузок можно выбрать только пункт **asp.net и разработка веб-приложений**. можно выбрать и больше опций или вообще все опции, однако нужно учитывать свободный размер на жёстком диске: чем больше опций выбрано, тем больше места на диске занято. рабочая нагрузка asp.net тянет за собой sdk .net и шаблоны, достаточные и для консольного приложения.

![установка visual studio 2026](/uploads/course-lectures/63d22bc4a9aadc242d8c4dbe879f6c7d0785e8c1.png)

при инсталляции visual studio на компьютер устанавливаются все необходимые инструменты для разработки программ, в том числе фреймворк .net.

после завершения установки создаётся первая программа. она невелика. сначала открывается visual studio. на стартовом экране выбирается **Create a new project** (создать новый проект). имя пункта меню сохраняется в том виде, в каком его показывает среда.

![создание первого проекта в visual studio 2026](/uploads/course-lectures/1249513ccbd8f18919812b7893fa37174bcd4dcf.png)

на следующем окне в качестве типа проекта выбирается **Console App**, то есть создаётся консольное приложение на языке c#.

![проект консольного приложения на c# и .net в visual studio 2026](/uploads/course-lectures/adf8767f7de2eaaf149725d8be776fe237446f6d.png)

чтобы проще было найти нужный тип проекта, в поле языков можно выбрать **C#**, а в поле типа проектов выбрать **Console**.

далее на следующем этапе предлагается указать имя проекта и каталог, где будет располагаться проект.

![создание первого приложения на c#](/uploads/course-lectures/a98d9b779c5c072639d3e0b91b2d14b17e9ac996.png)

в поле **Project Name** проекту даётся название. в примере это **HelloApp**.

на следующем окне visual studio предлагает выбрать версию .net, которая будет использоваться для проекта. выбирается последняя на данный момент версия, .net 9.0:

![установка c# и .net в visual studio](/uploads/course-lectures/54e17c9ad42ce0d8e5e7e8382543e779c0bce4b7.png)

нажимается кнопка Create (создать) для создания проекта, и после этого visual studio создаёт и открывает проект. выбранная версия записывается в файл проекта как идентификатор целевой платформы и определяет, какой ссылочный набор библиотек увидит компилятор.

![первый проект на c#](/uploads/course-lectures/4e913ebdd1375e844eca56c6d1c41a92d370b83e.png)

в большом поле в центре, которое представляет собой текстовый редактор, находится сгенерированный по умолчанию код c#. впоследствии он заменяется на собственный.

справа находится окно Solution Explorer, в котором видна структура проекта. здесь сгенерирована структура по умолчанию: узел **Dependencies** содержит сборки dll, которые добавлены в проект по умолчанию. эти сборки содержат классы библиотеки .net, которые использует c#. не всегда все сборки нужны. ненужные потом можно удалить, в то же время если понадобится добавить нужную библиотеку, она добавляется именно в этот узел. зависимости бывают двух видов: неявные ссылки на платформу, которые подтягивает sdk, и явные пакеты, которые добавляются в проект отдельно.

далее идёт непосредственно сам файл кода программы **Program.cs**, который по умолчанию открыт в центральном окне и который имеет всего две строки:

```c#


// See https://aka.ms/new-console-template for more information

Console.WriteLine("Hello, World!");
```

первая строка предваряется символами `//` и представляет комментарии, пояснения к коду. комментарий не попадает в cil: лексический анализатор отбрасывает его до синтаксического разбора.

вторая строка представляет собой код программы: `Console.WriteLine("Hello World!");`. эта строка выводит на консоль строку "Hello World!".

несмотря на то, что программа содержит только одну строку кода, это уже программа, которую можно запустить. проект запускается клавишей F5 или с панели инструментов, нажатием на зелёную стрелку. при запуске приложения на консоль выводится строка "Hello World!". среда перед запуском выполняет сборку, и если компилятор сообщает об ошибке, процесс останавливается до старта.

```bash


Hello, World!



C:\Users\eugen\source\repos\HelloApp\HelloApp\bin\Debug\net10.0\HelloApp.exe (process 16120) exited with code 0 (0x0).

Press any key to close this window . . .
```

затем весь этот код заменяется на следующий:

```c#


Console.Write("Введите свое имя: ");

var name = Console.ReadLine();       // вводим имя

Console.WriteLine($"Привет {name}");    // выводим имя на консоль
```

по сравнению с автоматически сгенерированным кодом изменено несколько мест. теперь первой строкой выводится приглашение к вводу.

```c#
Console.Write("Введите свое имя: ");
```

метод **Console.Write()** выводит на консоль некоторую строку. здесь это строка `"Введите свое имя: "`.

на второй строке определяется строковая переменная name, в которую пользователь вводит информацию с консоли:

```c#
var name = Console.ReadLine();
```

ключевое слово **var** указывает на определение переменной. здесь переменная называется `name`. ей присваивается результат метода **Console.ReadLine()**, который позволяет считать с консоли введённую строку. в консоли вводится строка (имя), и эта строка оказывается в переменной `name`. тип выводится компилятором из правой части и далее не меняется: это по-прежнему статическая типизация, а не динамическая.

затем введённое имя выводится на консоль:

```c#
Console.WriteLine($"Привет {name}");
```

чтобы ввести значение переменной name внутрь выводимой на консоль строки, применяются фигурные скобки {}. при выводе строки на консоль выражение `{name}` заменяется на значение переменной name, введённое имя.

чтобы можно было вводить таким образом значения переменных внутрь строки, перед строкой указывается знак доллара $. интерполированная строка вычисляется во время выполнения: литеральный текст остаётся как есть, а каждое выражение в скобках приводится к строке и вставляется в результат.

затем проект проверяется запуском, также нажатием на F5 или зелёную стрелку.

```bash


Введите свое имя: Евгений

Привет Евгений



C:\Users\eugen\source\repos\HelloApp\HelloApp\bin\Debug\net10.0\HelloApp.exe (process 16120) exited with code 0 (0x0).

Press any key to close this window . . .
```

скомпилированное приложение можно найти в папке проекта в каталоге **bin\Debug\net10.0**. оно называется по имени проекта и имеет расширение exe. затем этот файл можно запускать без visual studio, а также переносить его на другие компьютеры, где установлен .net 10. рядом с exe в этой конфигурации лежит dll со сборкой на cil: запуск exe передаёт управление среде, а исполняемый код метода порождается jit-компиляцией уже на целевой машине.
