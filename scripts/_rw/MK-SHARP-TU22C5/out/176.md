json, javascript object notation, есть текстовый формат обмена данными: объект, массив, строка, число, логическое значение и `null`. платформа .net читает и пишет этот формат средствами пространства имён `System.Text.Json`. основной тип пространства есть класс `JsonSerializer`. он переводит объект c# в текст json и восстанавливает объект из такого текста.

для записи в классе определены статический метод `Serialize` и асинхронный `SerializeAsync`. у обоих много перегрузок. часть из них:

- `string Serialize(Object obj, Type type, JsonSerializerOptions options)`: сериализует объект `obj` как экземпляр типа `type` и возвращает json строкой. последний аргумент `options` необязателен и задаёт параметры сериализации
- `string Serialize<T>(T obj, JsonSerializerOptions options)`: обобщённая версия. тип выводится из `obj`, результат снова строка json
- `Task SerializeAsync(Stream utf8Json, Object obj, Type type, JsonSerializerOptions options)`: сериализует `obj` типа `type` и пишет байты в поток `utf8Json`. аргумент `options` необязателен. байты в потоке кодируются utf-8, на что указывает и имя параметра
- `Task SerializeAsync<T>(Stream utf8Json, T obj, JsonSerializerOptions options)`: обобщённая версия пишет объект типа `T` в поток `utf8Json`

для восстановления служат `Deserialize` и `DeserializeAsync`:

- `object? Deserialize(string json, Type type, JsonSerializerOptions options)`: разбирает строку json в объект типа `type`. аргумент `options` необязателен. если json есть значение `null`, ссылочный результат тоже пуст, отсюда обнуляемый тип возврата
- `T? Deserialize<T>(string json, JsonSerializerOptions options)`: разбирает строку json в значение типа `T`
- `ValueTask<object?> DeserializeAsync(Stream utf8Json, Type type, JsonSerializerOptions options, CancellationToken token)`: читает json из потока `utf8Json` в объект типа `type`. `options` и `token` необязательны. `token` отменяет ожидание. результат обёрнут в `ValueTask`: если данные уже прочитаны, задача завершается без отдельного объекта `Task`
- `ValueTask<T?> DeserializeAsync<T>(Stream utf8Json, JsonSerializerOptions options, CancellationToken token)`: обобщённая версия возвращает значение типа `T` внутри `ValueTask<T?>`

базовый пример сериализует и тут же восстанавливает один объект:

```c#


using System.Text.Json;



Person tom = new Person("Tom", 37);

string json = JsonSerializer.Serialize(tom);

Console.WriteLine(json);

Person? restoredPerson = JsonSerializer.Deserialize<Person>(json);

Console.WriteLine(restoredPerson?.Name); // Tom



class Person

{

    public string Name { get;}

    public int Age { get; set; }

    public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

`JsonSerializer.Serialize` превращает экземпляр `Person` в строку json. `JsonSerializer.Deserialize<Person>` собирает из этой строки новый `Person`. имя восстановленного объекта печатается через `?.`: если разбор вернул пустую ссылку, обращения к `Name` нет.

вывод программы:

```bash


{"Name":"Tom","Age": 37}

Tom
```

тот же вызов применим к структуре. сериализатор читает открытые свойства значения и для класса, и для структуры.

### некоторые замечания по сериализации и десериализации

тип, который восстанавливается из json, должен предоставить конструктор, которым сериализатор умеет создать экземпляр. годится конструктор без параметров. годится и конструктор с параметрами, если каждому параметру в json находится свойство с тем же именем. параметры конструктора сопоставляются со свойствами json без учёта регистра. имена свойств при обычном сравнении с ключами json учитывают регистр. отключить эту чувствительность можно свойством `PropertyNameCaseInsensitive` у параметров сериализации.

в json попадают только открытые свойства, то есть свойства с модификатором `public`. закрытые свойства и поля в этот контракт не входят, если их не включить отдельной настройкой.

класс `Person` из фрагмента выше этому правилу удовлетворяет. конструктор принимает `name` и `age`, свойства называются `Name` и `Age`, регистр параметра и свойства различается, и для конструктора это допустимо. у `Name` есть только геттер, значение приходит через параметр конструктора. у `Age` есть сеттер.

### запись и чтение файла

`SerializeAsync` и `DeserializeAsync` принимают `Stream`, поэтому файл подставляется как `FileStream`. сериализатор пишет в него байты utf-8 и читает их обратно:

```c#


using System.Text.Json;



// сохранение данных

using (FileStream fs = new FileStream("user.json", FileMode.OpenOrCreate))

{

    Person tom = new Person("Tom", 37);

    await JsonSerializer.SerializeAsync<Person>(fs, tom);

    Console.WriteLine("Data has been saved to file");

}



// чтение данных

using (FileStream fs = new FileStream("user.json", FileMode.OpenOrCreate))

{

    Person? person = await JsonSerializer.DeserializeAsync<Person>(fs);

    Console.WriteLine($"Name: {person?.Name}  Age: {person?.Age}");

}



class Person

{

    public string Name { get;}

    public int Age { get; set; }

    public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

сначала объект сохраняется в `user.json`, затем новый `FileStream` открывает тот же файл, и `DeserializeAsync<Person>` восстанавливает `Person`. режим `FileMode.OpenOrCreate` при чтении оставляет уже записанные байты. позиция второго потока начинается с нуля, поэтому разбор идёт с начала файла.

### настройка сериализации через `JsonSerializerOptions`

по умолчанию `JsonSerializer` пишет плотный json: без отступов и лишних пробелов. параметры сериализации и разбора собирает объект `JsonSerializerOptions`. часть свойств:

- `AllowTrailingCommas`: разрешает ли разбор висячую запятую после последнего элемента объекта или массива. при `true` такая запятая в читаемом json допустима и игнорируется. при `false`, это значение по умолчанию, висячая запятая есть синтаксическая ошибка. свойство относится к чтению, при записи запятую сериализатор сам не добавляет
- `DefaultIgnoreCondition`: задаёт условие `JsonIgnoreCondition`, по которому свойство опускается. значение `WhenWritingDefault` исключает из записи свойства, чьё значение совпадает со значением типа по умолчанию
- `IgnoreReadOnlyProperties`: при `true` свойства только для чтения в json не попадают. значение по умолчанию `false`, поэтому геттер без сеттера, как `Name` в примере, сериализуется
- `WriteIndented`: при `true` в json добавляются переводы строк и отступы. при `false` текст остаётся плотным
- `Encoder`: кодировщик `JavaScriptEncoder`, которым экранируются строки. `null` оставляет кодировщик по умолчанию

применение `WriteIndented`:

```c#


using System.Text.Json;



Person tom = new Person("Tom", 37);



var options = new JsonSerializerOptions

{

    WriteIndented = true

};

string json = JsonSerializer.Serialize<Person>(tom, options);

Console.WriteLine(json);

Person? restoredPerson = JsonSerializer.Deserialize<Person>(json);

Console.WriteLine(restoredPerson?.Name);
```

вывод программы:

```bash


{

	"Name": "Tom",

	"Age":  37

}

Tom
```

`WriteIndented` меняет только записанный текст. `Deserialize` принимает и плотную, и разобранную по строкам форму: пробелы между лексем для json не значимы.

отдельного внимания требует `Encoder`. кодировщик по умолчанию оставляет как есть символы базовой латиницы, а прочие кодовые точки пишет escape-последовательностями `\uXXXX`. так строка остаётся чистым ascii и безопасна при вставке json в html. для файла, который должны читать люди, такой вид часто нежелателен.

тот же приём с `WriteIndented`, но имя задано кириллицей. запись параметров во фрагменте синтаксически неполна: после типа нет открывающей скобки инициализатора. по смыслу текста включён `WriteIndented`, остальное совпадает с предыдущим примером.

```c#


using System.Text.Json;



Person tom = new Person("Евгений", 41);



var options = new JsonSerializerOptions WriteIndented = true};

string json = JsonSerializer.Serialize<Person>(tom, options);

Console.WriteLine(json);

Person? restoredPerson = JsonSerializer.Deserialize<Person>(json);

Console.WriteLine(restoredPerson?.Name);
```

вывод программы:

```bash


{

  "Name": "\u0415\u0432\u0433\u0435\u043D\u0438\u0439",

  "Age": 41

}

Евгений
```

имя восстанавливается: последовательность `\u0415\u0432\u0433\u0435\u043D\u0438\u0439` есть те же символы, что и `Евгений`, записанные кодами utf-16. разбор json раскрывает такие последовательности обратно в символы. в файле при этом лежат escape-коды, а не сами буквы. то же происходит при сериализации в поток.

нужный набор символов задаётся свойством `Encoder`. у `JavaScriptEncoder` есть фабрика `Create`. она принимает допустимые диапазоны юникода и возвращает кодировщик, который не экранирует символы из этих диапазонов:

```c#


public static JavaScriptEncoder Create(params System.Text.Unicode.UnicodeRange[] allowedRanges);
```

тип аргумента есть `params`-массив `System.Text.Unicode.UnicodeRange`.

подстановка латиницы и кириллицы:

```c#


using System.Text.Json;

using System.Text.Unicode;

using System.Text.Encodings.Web;



Person tom = new Person("Евгений", 41);



var options = new JsonSerializerOptions

{

    Encoder = JavaScriptEncoder.Create(UnicodeRanges.BasicLatin, UnicodeRanges.Cyrillic),

    WriteIndented = true

};

string json = JsonSerializer.Serialize<Person>(tom, options);

Console.WriteLine(json);

Person? restoredPerson = JsonSerializer.Deserialize<Person>(json);

Console.WriteLine(restoredPerson?.Name);
```

здесь разрешены два диапазона, `UnicodeRanges.BasicLatin` и `UnicodeRanges.Cyrillic`. символы имени попадают во второй диапазон и записываются буквами. вывод программы:

```bash


{

  "Name": "Евгений",

  "Age": 41

}

Евгений
```

### настройка сериализации атрибутами

по умолчанию сериализуются все открытые свойства, и имя свойства в json совпадает с именем свойства в c#. атрибуты `JsonIgnore` и `JsonPropertyName` меняют это правило для отдельных свойств.

`JsonIgnore` исключает свойство и из записи, и из чтения. `JsonPropertyName` подставляет в json другое имя. имя свойства в c# при этом не меняется, меняется только ключ в тексте:

```c#


using System.Text.Json;

using System.Text.Json.Serialization;



Person tom = new Person("Tom", 37);



string json = JsonSerializer.Serialize<Person>(tom);

Console.WriteLine(json);

Person? person = JsonSerializer.Deserialize<Person>(json);

Console.WriteLine($"Name: {person?.Name}  Age: {person?.Age}");





class Person

{

    [JsonPropertyName("firstname")]

    public string Name { get;}

    [JsonIgnore]

    public int Age { get; set; }

    public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

свойство `Age` помечено `JsonIgnore` и в json не входит. свойство `Name` в json называется `firstname`. при разборе ключ `firstname` снова заполняет `Name`. вывод программы:

```consoletext


{"firstname":"Tom"}

Name: Tom   Age: 0
```

поскольку `Age` в json не записывалось, при разборе ему достаётся значение по умолчанию для `int`, то есть 0. в выводе это видно по возрасту. имя при этом восстановлено из псевдонима.
