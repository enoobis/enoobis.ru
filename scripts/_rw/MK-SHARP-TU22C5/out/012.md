у каждого примитивного числового типа есть диапазон значений и фиксированный размер в памяти. арифметические операции из предыдущей темы применяются к операндам разных типов, и тип результата определяется правилами преобразования, а не только ожидаемым числом.

```c#


byte a = 4;

int b = a + 70;
```

результат сложения равен 74: значение `byte` расширяется до `int`, и сложение выполняется в `int`.

если оба операнда узкие, а приемник имеет тип `byte`, та же арифметика уже не компилируется:

```c#


byte a = 4;

byte b = a + 70;  // ошибка
```

изменился только тип переменной, которая принимает результат: `int` заменен на `byte`. программа отвергается на этапе компиляции. в visual studio диагностика помечает вторую строку.

диапазон `byte` вмещает 74, однако ошибка возникает раньше, чем компилятор смотрит, помещается ли конкретное число. дело в статическом типе выражения.

сложение и вычитание целочисленных операндов, разрядность которых не выше `int` (`byte`, `short`, `int`), дают результат типа `int`. перед операцией действует бинарное числовое продвижение: `byte`, `sbyte`, `short`, `ushort` и `char` приводятся к `int`. выражение `a + 70` имеет тип `int` и занимает 4 байта. присвоить его переменной `b` типа `byte` (1 байт) без явного преобразования нельзя: такое присваивание было бы сужающим, а сужающее преобразование компилятор сам не вставляет.

нужна операция преобразования. в скобках перед значением указывается тип, к которому значение приводится:

```c#


(тип_данных_в_который_надо_преобразовать)значение_для_преобразования;
```

предыдущий пример с явным приведением:

```c#


byte a = 4;

byte b = (byte)(a + 70);
```

### сужающие и расширяющие преобразования

преобразования делятся на сужающие (narrowing) и расширяющие (widening). расширяющее преобразование увеличивает размер значения в памяти и сохраняет его для всех представимых исходным типом чисел.

```c#


byte a = 4;				// 0000100

ushort b = a;	// 000000000000100
```

переменной типа `ushort` присваивается значение типа `byte`. `byte` занимает 1 байт (8 бит). двоичное представление значения `a` имеет вид:

```c#
00000100
```

`ushort` занимает 2 байта (16 бит). при присваивании представление `a` расширяется до 2 байт:

```c#
0000000000000100
```

значение шириной 8 бит расширяется до 16 бит. старшие биты заполняются нулями, число не меняется.

сужающее преобразование, напротив, переводит значение к типу меньшей разрядности. явное приведение `ushort` к `byte` как раз сужает значение:

```c#


ushort a = 4;

byte b = (byte) a;
```

переменная `b` занимает 8 бит и получает значение `ushort`, которое занимает 16 бит. из `0000000000000100` остается `00000100`: отбрасываются старшие 8 бит. значение сужается с 16 бит (2 байта) до 8 бит (1 байт). если старшие биты были ненулевыми, число меняется.

### явные и неявные преобразования

#### неявные преобразования

расширяющее преобразование компилятор выполняет сам. это неявное преобразование (implicit conversion). оно безопасно относительно диапазона: любое значение источника представимо в приемнике.

преобразование беззнакового типа меньшей разрядности к беззнаковому типу большей разрядности дописывает старшие биты со значением 0. это дополнение нулями, zero extension.

```c#


byte a = 4;				// 0000100

ushort b = a;	// 000000000000100
```

преобразование к знаковому типу копирует знаковый бит в добавленные разряды. в дополнительном коде старший бит равен 0 у неотрицательного числа и 1 у отрицательного. если число неотрицательное, старшие биты заполняются нулями. если число отрицательное, они заполняются единицами. это знаковое расширение, sign extension.

преобразование положительного числа:

```c#


sbyte a = 4;			// 0000100

short b = a;	// 000000000000100
```

преобразование отрицательного числа:

```c#


sbyte a = -4;			// 1111100

short b = a;	// 111111111111100
```

#### явные преобразования

явное преобразование (explicit conversion) программист записывает сам операцией `()`. перед значением в скобках стоит тип, к которому значение приводится:

```c#


int a = 4;

int b = 6;

byte c = (byte)(a+b);
```

расширяющие преобразования от меньшей разрядности к большей компилятор выполняет неявно. среди них такие цепочки:

`byte` -> `short` -> `int` -> `long` -> `decimal`

`int` -> `double`

`short` -> `float` -> `double`

`char` -> `int`

`char` хранит кодовую единицу utf-16 и в преобразованиях ведет себя как беззнаковое 16-битное число: он расширяется до целых типов, но не сужается неявно до `byte`.

все безопасные неявные преобразования собраны в таблице. беззнаковый приемник не стоит в строке знакового источника, если отрицательные значения источника в него не входят: у `sbyte` нет неявного преобразования к `ushort`, `uint` и `ulong`.

| тип | в какие типы безопасно преобразуется |
| --- | --- |
| byte | short, ushort, int, uint, long, ulong, float, double, decimal |
| sbyte | short, int, long, float, double, decimal |
| short | int, long, float, double, decimal |
| ushort | int, uint, long, ulong, float, double, decimal |
| int | long, float, double, decimal |
| uint | long, ulong, float, double, decimal |
| long | float, double, decimal |
| ulong | float, double, decimal |
| float | double |
| char | ushort, int, uint, long, ulong, float, double, decimal |

![преобразования типов в c#](/uploads/course-lectures/148febc3561a8d4dfe82fa09ba37b0ba4117c5ca.png)

во всех остальных направлениях нужно явное преобразование.

`double` и `decimal` оба хранят дробные значения, и у `decimal` больше десятичных значащих цифр, чем у `double`. тем не менее `double` приводится к `decimal` только явно:

```c#


double a = 4.0;

decimal b = (decimal)a;
```

причина в представлении. `double` хранит двоичную мантиссу, `decimal` десятичную. не каждое значение `double` точно представимо в `decimal`, а значения вне диапазона `decimal` при приведении дают переполнение. поэтому преобразование не входит в множество неявных.

### потеря точности данных

сужающее приведение может изменить число. следующий фрагмент компилируется, потому что приведение записано явно:

```c#


int a = 33;

int b = 600;

byte c = (byte)(a+b);

Console.WriteLine(c);   // 121
```

на консоль выводится 121. сумма `a + b` равна 633, а диапазон `byte` ограничен 255. в unchecked-контексте, который действует по умолчанию, остаются младшие 8 бит: `633 % 256` равно 121, старшие биты отбрасываются. в checked-контексте то же приведение выбрасывает `OverflowException`. при выборе приведения это учитывают: либо операнды подбирают так, чтобы сумма не превышала 255, либо вместо `byte` берут тип, который вмещает результат, например `int`.
