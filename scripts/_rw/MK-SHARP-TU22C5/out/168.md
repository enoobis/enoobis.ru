### указатели на типы и операция ->

помимо указателей на примитивные типы объявляют указатели на структуры. поле структуры, на которую ссылается указатель, читается и записывается операцией `->`:

```c#


unsafe

{

    Point point = new Point(0, 0);

    Console.WriteLine(point);   // X: 0  Y: 0

    Point* p = &point;



    p->X = 30;

    Console.WriteLine(p->X);    // 30



    // разыменовывание указателя

    (*p).Y = 180;

    Console.WriteLine((*p).Y);  // 180



    Console.WriteLine(point);   // X: 30  Y: 180

}

struct Point

{

    public int X { get; set; }

    public int Y { get; set; }

    public Point(int x, int y)

    {

        X = x; Y = y;

    }

    public override string ToString() => $"X: {X}  Y: {Y}";

}
```

запись `p->X = 30` читает или устанавливает свойство той структуры, на которую указывает `p`. форма `p.X=30` здесь не компилируется: `p` имеет тип указателя на `Point`, а не тип самой структуры, и оператор `.` к указателю не применяется.

равносильная запись проходит через разыменование: `(*p).X = 30`. скобки обязательны, потому что операция `.` связывается теснее, чем `*`. без скобок выражение читалось бы как `*(p.X)`.

указатель ставится только на такую структуру, у которой нет полей ссылочных типов. в этот запрет входят и поля, которые компилятор порождает сам для автоматических свойств. если автоматическое свойство имеет ссылочный тип, его скрытое поле тоже ссылочное, и структура перестаёт быть неуправляемой. у `Point` в примере оба свойства имеют тип `int`, их скрытые поля тоже целочисленные, поэтому структура остаётся допустимой целью указателя. операция `&` берёт адрес локальной переменной `point`, которая лежит в кадре метода и сборщиком не перемещается.

### указатели на массивы и stackalloc

служебное слово **stackalloc** выделяет память под массив в стеке. смысл такого размещения в том, что выделение сводится к сдвигу указателя стека и не проходит через управляемую кучу. ниже так считаются квадраты чисел:

```c#


unsafe

{

    const int size = 7;

    int* square = stackalloc int[size]; // выделяем память в стеке под семь объектов int

    int* p = square;

    // вычисляем квадраты чисел от 1 до 7 включая

    for (int i = 1; i <= size; i++, p++)

    {

        // считаем квадрат числа

        *p = i * i;

    }

    for (int i = 0; i < size; i++)

    {

        Console.WriteLine(square[i]);

    }

}
```

оператор `stackalloc` стоит перед типом массива, на который будет указывать указатель: `int* square = stackalloc int[size];`. память живёт в кадре текущего метода и освобождается вместе с выходом из него. инициализатора у этого `stackalloc` нет, поэтому пример сам записывает каждую ячейку, прежде чем её читать.

для прохода по массиву заводится второй указатель `int* p = square;`. он указывает на первый из семи элементов. сдвиг `p` перемещает его по массиву `square`.

цикл считает квадраты чисел от 1 до 7 включительно. квадрат числа `i * i` записывается по адресу, который сейчас хранит указатель:

```c#
*p = i * i;
```

затем указатель увеличивается: `p++`. арифметика указателя сдвигает адрес на размер одного `int`, то есть на следующий элемент `square`, а не на соседний байт.

чуть более плотный пример считает факториал:

```c#


unsafe

{

    const int size = 7;

    int* factorial = stackalloc int[size]; // выделяем память в стеке под семь объектов int

    int* p = factorial;



    *(p++) = 1; // присваиваем первой ячейке значение 1 и

    // увеличиваем указатель на 1

    for (int i = 2; i <= size; i++, p++)

    {

        // считаем факториал числа

        *p = p[-1] * i;

    }

    for (int i = 0; i < size; i++)

    {

        Console.WriteLine(factorial[i]);

    }

}
```

`stackalloc` снова резервирует память под 7 элементов `int`. указатель для прохода объявляется так: `int* p = factorial;`. в начале он ссылается на первый элемент массива из семи ячеек.

факториал числа 1 равен 1, поэтому первой ячейке присваивается единица, и указатель сразу сдвигается: `*(p++)= 1;`.

запись значения по адресу указателя сама по себе выглядит как `*p=1`. в том же выражении есть и инкремент `p++`. постфиксный инкремент выполняется после разыменования: сначала в текущую ячейку пишется 1, затем `p` переходит на второй элемент. то же самое двумя операторами:

```c#


*p= 1;

p++;
```

чтобы получить предыдущий элемент и сдвинуться назад, применяется декремент: `Console.WriteLine(*(--p));`. выражения `*(--p)` и `*(p--)` различаются порядком. в первом указатель сначала сдвигается, и разыменование читает уже новую ячейку. во втором сначала читается текущая ячейка, и только потом указатель сдвигается.

факториалы остальных чисел считаются так: `*p = p[-1] *i;`. обращение к указателю как к массиву заменяет разыменование со сдвигом. `p[-1]` означает ячейку на один элемент позади текущего адреса, то есть `*(p - 1)`. в ней лежит уже посчитанный факториал предыдущего числа, и умножение на `i` даёт следующее значение. индекс `-1` здесь не выход за массив в смысле нумерации с нуля у `factorial`: он отсчитывается от текущего `p`, который к этой итерации уже сдвинут вперёд.

в конце по указателю `factorial`, который по-прежнему ссылается на начало блока, печатаются факториалы всех семи чисел. указатель `p` к этому моменту ушёл вперёд, а базовый адрес `factorial` цикл не менял.

### оператор fixed и закрепление указателей

предыдущие указатели ссылались на типы значений: на `int` и на структуру в кадре метода. класс устроен иначе. его поля лежат в куче вместе с объектом, а сборщик мусора в любой момент может передвинуть объект при уплотнении. адрес поля, взятый один раз, после такого сдвига указывает не туда. на время работы с адресом объект закрепляют оператором `fixed`.

класс `Point` с открытыми полями:

```c#


class Point

{

    public int x;

    public int y;

    public override string ToString() => $"x: {x}  y: {y}";

}
```

закрепление указателя:

```c#


unsafe

{

    Point point = new Point();



    // блок фиксации указателя

    fixed (int* pX = &point.x)

    {

        *pX = 30;

    }

    fixed (int* pY = &point.y)

    {

        *pY = 150;

    }

    // можно совместить оба блока

    /*fixed (int* pX = &point.x, pY = &point.y)

    {

        *pX = 30;

        *pY = 150;

    }*/

    Console.WriteLine(point); // x: 30  y: 150

}
```

оператор `fixed` открывает блок, внутри которого указатель на поле объекта остаётся действительным. сборщик может собирать мусор в это время, но данный объект он не перемещает. в примере сначала закрепляется адрес поля `x`, и по нему записывается `30`, затем отдельно закрепляется адрес поля `y`, и по нему записывается `150`. в комментарии показана форма с двумя указателями в одном `fixed`: оба поля закреплены на протяжении одного блока. после закрытия блока закрепление снимается, и объект снова можно перемещать.

инициализатором указателя в `fixed` служит не только адрес поля. туда же передают массив, строку или буфер фиксированного размера:

```c#


unsafe 

{

    int[] nums = { 0, 1, 2, 3, 7, 88 };

    string str = "Привет мир";

    fixed(int* p = nums)

    {

		int third = *(p+2);     // получим третий элемент

		Console.WriteLine(third); // 2

    }

    fixed(char* p = str)

    {

		char forth = *(p + 3);     // получим четвертый элемент

		Console.WriteLine(forth); // в

    }

}
```

при закреплении строки тип указателя обязан быть `char*`. строка в clr хранится как последовательность кодовых единиц utf-16, и `char` как раз занимает одну такую единицу. `p` после `fixed(char* p = str)` указывает на первый символ. `*(p + 3)` читает четвёртый: в строке `Привет мир` это символ `в`. аналогично `*(p+2)` у массива `nums` читает третий элемент, значение `2`. пример только читает память. запись по `char*`, полученному из строки, ломала бы неизменяемость строки, и такой указатель для изменения текста не используется.
