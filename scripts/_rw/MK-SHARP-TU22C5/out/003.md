**wsl**, или **windows subsystem for linux**, позволяет запускать окружение gnu/linux и ряд приложений linux непосредственно на windows без виртуальной машины. это полезно при создании и тестировании приложений для linux без переключения между операционными системами. подсистема предоставляет ядро linux и дистрибутив как процесс windows: файловая система дистрибутива доступна из windows, а процессы linux исполняются рядом с процессами windows, а не внутри отдельной гостевой ос.

### установка wsl

перед установкой учитывается, что текущая версия wsl поддерживается на windows 10 версии 2004 и выше (build 19041 и выше) и на windows 11.

для установки открывается оболочка powershell или командная строка от имени администратора, и в ней выполняется следующая команда:

```bash
wsl --install
```

эта команда подключает функции wsl и устанавливает дистрибутив linux по умолчанию, которым является ubuntu (дистрибутив по умолчанию можно изменить). включение компонента требует прав администратора, потому что подсистема регистрируется как необязательный компонент windows.

![установка windows subsystem for linux](/uploads/course-lectures/a2995528c25ce453fd6a9eed90165af8fa736b16.png)

после установки и перезагрузки системы откроется консоль, где задаются имя пользователя и пароль:

![установка имени пользователя для windows subsystem for linux](/uploads/course-lectures/029426df8bd15aa92cf943e6834e30b4d4bc6400.png)

затем в терминале нажимается стрелка вниз, и в появившемся списке выбирается "ubuntu":

![запуск ubuntu в windows subsystem for linux](/uploads/course-lectures/4a6839212ad69a26459819238b8aaea584181ef9.png)

для установки текущей в этом разделе версии .net 8 сначала добавляется репозиторий пакетов microsoft последовательным выполнением следующих команд:

```bash


wget https://packages.microsoft.com/config/ubuntu/22.04/packages-microsoft-prod.deb -O packages-microsoft-prod.deb

sudo dpkg -i packages-microsoft-prod.deb

rm packages-microsoft-prod.deb
```

в первой команде указаны цифры "22.04". если используется другая версия ubuntu, вместо них указывается соответствующая версия. пакет `packages-microsoft-prod` добавляет источник пакетов microsoft в список apt, после чего пакеты sdk разрешаются уже из этого источника. файл `.deb` после установки удаляется, потому что он нужен только как носитель конфигурации репозитория.

![установка .net 8 sdk на ubuntu в windows subsystem for linux](/uploads/course-lectures/6a50d0f8595f3d4f2540ca0da076181081d42512.png)

затем для установки 8-й версии .net sdk выполняются команды:

```bash


sudo apt-get update

sudo apt-get install -y dotnet-sdk-8.0
```

для проверки установленных .net sdk выполняется следующая команда:

```bash


dotnet --list-sdks
```

вывод перечисляет установленные sdk и каталоги, в которых они лежат. наличие строки с версией 8 подтверждает, что компилятор и среда выполнения доступны внутри дистрибутива, а не только в windows.

### первый проект в wsl

создаётся первый проект. для этого открывается консоль ubuntu, и сначала создаётся каталог для проекта следующей командой:

```bash


mkdir dotnet
```

затем выполняется переход в эту папку командой:

```bash


cd dotnet
```

затем для создания проекта выполняется следующая команда:

```bash


dotnet new console
```

шаблон `console` без опции имени создаёт проект в текущем каталоге: файл проекта и `Program.cs` появляются там, где была запущена команда.

![создание проекта на c# и .net 8 на ubuntu в wsl](/uploads/course-lectures/d069b0fa84896d61a865447aa99f11cab0c03d7f.png)

далее можно использовать базовые команды linux для управления и навигации по файлам и каталогам в проекте и вообще в wsl. например, команда **ll** отображает список файлов и каталогов в текущем каталоге. если нужно открыть файл в проекте и изменить его содержимое, используются встроенные в ubuntu текстовые редакторы, например vim. можно использовать и редакторы из текущей системы windows. если установлен visual studio code и нужно открыть в нём файл `Program.cs`, как и в windows достаточно ввести команду **code Program.cs**. команда `code` ставится расширением visual studio code и запускает редактор windows, передавая ему путь внутри файловой системы дистрибутива.

![управление проектом на c# и .net 8 на ubuntu в wsl](/uploads/course-lectures/f55278d5fe58c004f5afbdaf4a7c055da6891984.png)

либо весь проект открывается в visual studio code командой **code .** (при нахождении в папке проекта). точка обозначает текущий каталог.

для запуска проекта, построения и конфигурации используются те же команды .net cli, которые применяются на windows и в полноценном linux. например, проект запускается командой:

```bash


dotnet run
```

`dotnet run` внутри wsl компилирует проект компилятором linux-версии sdk и запускает его в среде дистрибутива. это уже исполнение под linux, а не под windows, хотя окно терминала встроено в windows.

![запуск проекта на c# и .net 8 на ubuntu в wsl](/uploads/course-lectures/8f8d2d42edac6f0d39298eff2dcd823570800bf2.png)

поскольку работа идёт в windows, содержимое проекта можно посмотреть в стандартном проводнике windows. для этого выполняется следующая команда:

```bash


explorer.exe .
```

в этом вызове открывается текущая папка, поэтому передаётся точка. ту же папку можно открыть напрямую в проводнике windows. `explorer.exe` является программой windows: подсистема позволяет запустить её из сеанса linux и передать путь файловой системы дистрибутива.

![просмотр проекта на c# и .net 8 на ubuntu в wsl в проводнике windows](/uploads/course-lectures/83d77f7d74111deceb444cf1314de829c18f8343.png)
