ковариантность и контравариантность связаны с возможностью использовать вместо некоторого типа другой тип, который находится ниже или выше в иерархии наследования.

возможны три варианта поведения:

- ковариантность: позволяет использовать более конкретный тип, чем заданный изначально

- контравариантность: позволяет использовать более универсальный тип, чем заданный изначально

- инвариантность: позволяет использовать только заданный тип

c# позволяет создавать ковариантные и контравариантные обобщённые интерфейсы. это расширяет допустимые подстановки при использовании обобщённых интерфейсов. по умолчанию все обобщённые интерфейсы инвариантны: наследование `EmailMessage` от `Message` само по себе не создаёт отношения подтипа между `I<EmailMessage>` и `I<Message>`.

для ковариантных и контравариантных интерфейсов ниже используются такие классы:

```c#


class Message

{

    public string Text { get; set; }

    public Message(string text) => Text = text;

}

class EmailMessage : Message

{

    public EmailMessage(string text): base(text) { }

}
```

класс `Message` получает через конструктор текст и сохраняет его в свойство `Text`. класс `EmailMessage` представляет условное email-сообщение и вызывает конструктор базового класса, передавая ему текст сообщения.

### ковариантные интерфейсы

обобщённые интерфейсы ковариантны, если к универсальному параметру применяется служебное слово **out**. такой параметр представляет тип объекта, который возвращается из метода.

```c#


interface IMessenger<out T>

{

    T WriteMessage(string text);

}

class EmailMessenger : IMessenger<EmailMessage>

{

    public EmailMessage WriteMessage(string text)

    {

        return new EmailMessage($"Email: {text}");

    }

}
```

обобщённый интерфейс `IMessenger` представляет интерфейс мессенджера и определяет метод `WriteMessage()` для создания сообщения. на момент определения интерфейса неизвестно, объект какого типа будет возвращать этот метод. служебное слово **out** в определении интерфейса указывает, что интерфейс ковариантен: если `EmailMessage` подтип `Message`, то `IMessenger<EmailMessage>` подтип `IMessenger<Message>`.

класс `EmailMessenger`, условная программа для отправки email-сообщений, реализует этот интерфейс и возвращает из метода `WriteMessage()` объект `EmailMessage`.

применение этих типов:

```c#


IMessenger<Message> outlook = new EmailMessenger();

Message message = outlook.WriteMessage("Hello World");

Console.WriteLine(message.Text);    // Email: Hello World





IMessenger<EmailMessage> emailClient = new EmailMessenger();

IMessenger<Message> messenger = emailClient;

Message emailMessage = messenger.WriteMessage("Hi!");

Console.WriteLine(emailMessage.Text);    // Email: Hi!
```

более общему типу `IMessenger<Message>` можно присвоить объект более конкретного типа `EmailMessenger` или `IMessenger<EmailMessage>`. направление подстановки совпадает с направлением наследования аргумента типа.

без служебного слова `out` интерфейс инвариантен:

```c#
interface IMessenger<T>
```

тогда строки присваивания не компилируются:

```c#


IMessenger<Message> outlook = new EmailMessenger();  // ! Ошибка



IMessenger<EmailMessage> emailClient = new EmailMessenger();

IMessenger<Message> messenger = emailClient;	// ! Ошибка
```

привести объект `IMessenger<EmailMessage>` к типу `IMessenger<Message>` в инвариантном интерфейсе нельзя.

при создании ковариантного интерфейса универсальный параметр используется только как тип значения, возвращаемого методами интерфейса. его нельзя использовать как тип аргументов метода или как ограничение методов интерфейса: входная позиция позволила бы передать значение неверного типа.

### контравариантные интерфейсы

для контравариантного интерфейса используют служебное слово **in**. те же классы `Message` и `EmailMessage`:

```c#


interface IMessenger<in T>

{

    void SendMessage(T message);

}

class SimpleMessenger : IMessenger<Message>

{

    public void SendMessage(Message message)

    {

        Console.WriteLine($"Отправляется сообщение: {message.Text}");

    }

}
```

интерфейс `IMessenger` снова представляет интерфейс мессенджера и определяет метод `SendMessage()` для отправки условного сообщения. служебное слово **in** в определении интерфейса указывает, что этот интерфейс **контравариантный**: отношение подтипов по параметру обращается.

класс `SimpleMessenger` представляет условную программу отправки сообщений и реализует этот интерфейс. в качестве типа он использует `Message`, то есть `SimpleMessenger` фактически представляет тип `IMessenger<Message>`.

применение этих типов:

```c#


IMessenger<EmailMessage> outlook = new SimpleMessenger();

outlook.SendMessage(new EmailMessage("Hi!"));



IMessenger<Message> telegram = new SimpleMessenger();

IMessenger<EmailMessage> emailClient = telegram;

emailClient.SendMessage(new EmailMessage("Hello"));
```

поскольку интерфейс `IMessenger` использует универсальный параметр со служебным словом **in**, он контравариантен, и переменной типа `IMessenger<EmailMessage>` можно передать объект `IMessenger<Message>` или `SimpleMessenger`. отправитель, который принимает любой `Message`, принимает и `EmailMessage`.

если служебное слово **in** не используется, такое присваивание запрещено. объект интерфейса с более универсальным типом приводится к объекту интерфейса с более конкретным типом только при контравариантности.

при создании контравариантного интерфейса универсальный параметр применяется только к аргументам метода и не применяется к возвращаемому результату метода.

### совмещение ковариантности и контравариантности

ковариантность и контравариантность совмещаются в одном интерфейсе, на разных параметрах:

```c#


interface IMessenger<in T, out K>

{

    void SendMessage(T message);

    K WriteMessage(string text);

}

class SimpleMessenger : IMessenger<Message, EmailMessage>

{

    public void SendMessage(Message message)

    {

        Console.WriteLine($"Отправляется сообщение: {message.Text}");

    }

    public EmailMessage WriteMessage(string text)

    {

        return new EmailMessage($"Email: {text}");

    }

}
```

фактически здесь объединены два предыдущих примера. благодаря ковариантности и контравариантности объект класса `SimpleMessenger` (`IMessenger<Message, EmailMessage>`) может представлять типы `IMessenger<Message, EmailMessage>`, `IMessenger<EmailMessage, EmailMessage>`, `IMessenger<Message, Message>` и `IMessenger<EmailMessage, Message>`. по контравариантному параметру аргумент сужают, по ковариантному результат расширяют до базового типа. применение классов:

```c#


IMessenger<EmailMessage, Message> messenger = new SimpleMessenger();

Message message = messenger.WriteMessage("Hello World");

Console.WriteLine(message.Text);

messenger.SendMessage(new EmailMessage("Test"));



IMessenger<EmailMessage, EmailMessage> outlook = new SimpleMessenger();

EmailMessage emailMessage = outlook.WriteMessage("Message from Outlook");

outlook.SendMessage(emailMessage);



IMessenger<Message, Message> telegram = new SimpleMessenger();

Message simpleMessage = telegram.WriteMessage("Message from Telegram");

telegram.SendMessage(simpleMessage);
```
