в c и c++ есть **указатели**. указатель хранит адрес ячейки памяти и через этот адрес читает либо записывает значение, которое в ячейке лежит.

в c# указатели применяются редко. к ним обращаются, когда нужно обойти проверки clr и сократить накладные расходы на конкретном участке. код с указателями называется небезопасным, unsafe. смысл термина в правилах среды: все действия с адресами, включая освобождение памяти, выполняет сама программа, а не clr. среда такой код не верифицирует, поэтому растёт вероятность ошибок адресации, порчи памяти и обхода инвариантов типов.

чтобы проект допустил небезопасный код, в настройках включается флаг

```xml
<AllowUnsafeBlocks>true</AllowUnsafeBlocks>
```

флаг ставится в файл проекта с расширением `.csproj`:

```xml


<Project Sdk="Microsoft.NET.Sdk">



  <PropertyGroup>

    <OutputType>Exe</OutputType>

    <TargetFramework>net9.0</TargetFramework>

    <ImplicitUsings>enable</ImplicitUsings>

    <Nullable>enable</Nullable>



    <AllowUnsafeBlocks>true</AllowUnsafeBlocks>  <!-- нужная опция -->



  </PropertyGroup>



</Project>
```

после этой настройки в проекте разрешены небезопасные блоки и указатели. без флага компилятор отвергает служебное слово `unsafe`.

### служебное слово unsafe

блок или метод, в котором есть указатели, помечается служебным словом **unsafe**:

```c#


// блок кода, использующий указатели

unsafe 

{

	

}
```

метод с указателями объявляется так:

```c#


unsafe void Test()

{



}
```

тем же словом помечаются структура и класс, если указатель входит в их члены:

```c#


unsafe struct State

{ 



}



unsafe class Person

{



}
```

метка на типе означает, что его объявление содержит неверифицируемые элементы, например поле-указатель. вызов такого типа снаружи всё равно проходит через обычные правила языка, а небезопасные операции остаются внутри помеченного участка.

### операции * и &

основная операция над указателем называется разыменованием и записывается знаком `*`. разыменование читает или записывает значение по адресу, который хранит указатель. адрес переменной даёт операция `&`:

```c#


unsafe

{

    int* x; // определение указателя

    int y = 10; // определяем переменную



    x = &y; // указатель x теперь указывает на адрес переменной y

    Console.WriteLine(*x); // 10



    y = y + 20;     // меняем значение

    Console.WriteLine(*x);// 30



    *x = 50;

    Console.WriteLine(y); // переменная y=50

}
```

при объявлении указателя указывается тип ячейки, на которую он ссылается: `int* x;` объявляет указатель на целое. помимо `int` допускаются `sbyte, byte, short, ushort, int, uint, long, ulong, char, float, double, decimal или bool`. указатель объявляют и на `enum`, на структуру из полей неуправляемых типов и на другой указатель. общий признак этих типов в том, что их размер и представление известны без участия сборщика мусора. ссылочный тип в этот список не входит: объект в куче может быть перемещён, и голый адрес на него без закрепления недействителен.

выражение `x = &y;` записывает в `x` адрес переменной `y`. до этого присваивания указатель `x` ни на какую переменную не ссылается. операция `&` заставляет компилятор поместить `y` в адресуемую ячейку, а не только в регистр.

дальше `x` и `y` обозначают одну и ту же ячейку. изменение `y` видно через `*x`, а запись в `*x` меняет `y`. в примере `y` увеличивается на `20`, и разыменование показывает `30`. затем `*x = 50` записывает `50` в ту же ячейку, и чтение `y` даёт `50`.

значение по адресу, на который указывает `x`, получается выражением `*x`.

### получение адреса

адрес, хранимый указателем, можно прочитать как целое число, преобразовав указатель к целочисленному типу:

```c#


int* x; // определение указателя

int y = 10; // определяем переменную



x = &y; // указатель x теперь указывает на адрес переменной y



// получим адрес переменной y

ulong addr = (ulong)x;

Console.WriteLine($"Адрес переменной y: {addr}");
```

для такого преобразования годятся `uint`, `long` и `ulong`. адрес является целым без знака. на 32-разрядной системе диапазон адресов идёт от 0 до 4 000 000 000, и его вмещает `uint`. знаковый `int` на верхней половине этого диапазона переполняется, поэтому для 32-разрядного адреса надёжнее `uint`. на 64-разрядной системе адрес шире 32 бит, и его сохраняют в `ulong`, чтобы преобразование не потеряло старшие разряды.

### указатель на другой указатель

указатель может ссылаться не на значение, а на другой указатель:

```c#


unsafe

{

    int* x; // определение указателя

    int y = 10; // определяем переменную



    x = &y; // указатель x теперь указывает на адрес переменной y

    int** z = &x; // указатель z теперь указывает на адрес, указателя x

    **z = **z + 40; // изменение указателя z повлечет изменение переменной y

    Console.WriteLine(y); // переменная y=50

    Console.WriteLine(**z); // переменная **z=50

}
```

`x` имеет тип `int*` и хранит адрес `y`. `z` имеет тип `int**` и хранит адрес самого `x`. запись `**z` дважды разыменовывает `z`: первое разыменование даёт указатель `x`, второе даёт ячейку `y`. поэтому `**z = **z + 40` прибавляет `40` к `y`. и чтение `y`, и чтение `**z` после этого дают `50`.
