параллельная задача может выполняться долго, и её бывает нужно остановить. для кооперативной отмены .net даёт структуру **CancellationToken** из пространства имён `System.Threading`. токен не снимает поток с процессора. он переносит запрос отмены, а код задачи читает этот запрос в выбранных точках и сам решает, как выйти.

обычный порядок такой:

- создаётся `CancellationTokenSource`. источник владеет состоянием отмены и рассылает уведомление связанным токенам.

- свойство `CancellationTokenSource.Token` возвращает сам токен, значение структуры `CancellationToken`. токен передаётся в задачу. для этого у `Task` есть конструктор с отдельным аргументом токена. связь с конструктором нужна статусу: при согласованной отмене задача переходит в `Canceled`. тот же выход по исключению без токена в конструкторе даёт статус `Faulted`.

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource(); 

CancellationToken token = cancelTokenSource.Token;
```

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource(); 

CancellationToken token = cancelTokenSource.Token;

Task task = new Task(() => { выполняемые_действия}, token); //
```

- в теле задачи задаётся реакция на отмену.

- вызывается `CancellationTokenSource.Cancel()`. метод ставит `CancellationToken.IsCancellationRequested` в `true` и вызывает зарегистрированные обработчики. сам `Cancel()` делегат не прерывает: способ выхода выбирает автор задачи.

- класс `CancellationTokenSource` реализует `IDisposable`. когда работа с источником закончена, у него вызывают `Dispose` и освобождают связанные ресурсы, в том числе примитив ожидания отмены. явный `Dispose` заменяется конструкцией `using`: освобождение происходит при выходе из блока.

чем именно закончить задачу, решает автор делегата. общих вариантов два.

- при сигнале отмены выйти из метода, например оператором `return`, или построить условие цикла так, чтобы оно стало ложным. статус тогда будет `TaskStatus.RanToCompletion`. статус `TaskStatus.Canceled` при таком выходе не выставляется: для планировщика делегат завершился штатно.

- при сигнале отмены выбросить `OperationCanceledException`, вызвав у токена `ThrowIfCancellationRequested()`. если в конструктор `Task` передан тот же токен, статус становится `TaskStatus.Canceled`.

### мягкий выход из задачи без исключения OperationCanceledException

первый вариант обходится без исключения:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();

CancellationToken token = cancelTokenSource.Token;



// задача вычисляет квадраты чисел

Task task = new Task(() =>

{

    for (int i = 1; i < 10; i++)

    {

        if (token.IsCancellationRequested)  // проверяем наличие сигнала отмены задачи

        {

            Console.WriteLine("Операция прервана");

            return;     //  выходим из метода и тем самым завершаем задачу

        }

        Console.WriteLine($"Квадрат числа {i} равен {i * i}");

        Thread.Sleep(200);

    }

}, token);

task.Start();



Thread.Sleep(1000);

// после задержки по времени отменяем выполнение задачи

cancelTokenSource.Cancel();

// ожидаем завершения задачи

Thread.Sleep(1000);

//  проверяем статус задачи

Console.WriteLine($"Task Status: {task.Status}");

cancelTokenSource.Dispose(); // освобождаем ресурсы
```

задача `task` считает квадраты чисел от 1 до 9 и печатает их. для отмены создаётся источник:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();
```

из источника берётся токен и передаётся в конструктор задачи:

```c#


CancellationToken token = cancelTokenSource.Token;
```

запрос отмены посылается методом `Cancel()`:

```c#


cancelTokenSource.Cancel();
```

в примере `Cancel` вызывается через секунду после старта, чтобы цикл успел выполнить несколько итераций. паузы `Thread.Sleep(1000)` на основном потоке и `Thread.Sleep(200)` в задаче задают это окно.

сигнал в цикле читается по свойству `token.IsCancellationRequested`:

```c#


if (token.IsCancellationRequested)

{

    Console.WriteLine("Операция прервана");

    return;

}
```

после `cancelTokenSource.Cancel()` выражение `token.IsCancellationRequested` даёт `true`. цикл печатает `Операция прервана` и выходит по `return`. делегат завершается обычным образом.

статус после этого:

```c#
Console.WriteLine($"Task Status: {task.Status}");
```

штатный выход оставляет статус `RanToCompletion`.

в конце источник освобождается:

```c#
cancelTokenSource.Dispose();
```

консольный вывод:

```bash


Квадрат числа 1 равен 1

Квадрат числа 2 равен 4

Квадрат числа 3 равен 9

Квадрат числа 4 равен 16

Квадрат числа 5 равен 25

Операция прервана

Task Status: RanToCompletion
```

за секунду при шаге 200 мс успевают напечататься пять квадратов, затем цикл видит отмену.

### отмена задачи с помощью генерации исключения

второй способ завершает задачу исключением **OperationCanceledException**. его бросает метод **ThrowIfCancellationRequested()** токена:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();

CancellationToken token = cancelTokenSource.Token;



Task task = new Task(() =>

{

    for (int i = 1; i < 10; i++)

    {

        if (token.IsCancellationRequested)

            token.ThrowIfCancellationRequested(); // генерируем исключение



        Console.WriteLine($"Квадрат числа {i} равен {i * i}");

        Thread.Sleep(200);

    }

}, token);

try

{

    task.Start();

    Thread.Sleep(1000);

    // после задержки по времени отменяем выполнение задачи

    cancelTokenSource.Cancel();



    task.Wait(); // ожидаем завершения задачи

}

catch (AggregateException ae)

{

    foreach (Exception e in ae.InnerExceptions)

    {

        if (e is TaskCanceledException)

            Console.WriteLine("Операция прервана");

        else

            Console.WriteLine(e.Message);

    }

}

finally

{

    cancelTokenSource.Dispose();

}



//  проверяем статус задачи

Console.WriteLine($"Task Status: {task.Status}");
```

в цикле снова проверяется `IsCancellationRequested`, и при значении `true` исключение генерируется явно:

```c#


if (token.IsCancellationRequested)

    token.ThrowIfCancellationRequested(); // генерируем исключение
```

`ThrowIfCancellationRequested` сам читает токен и бросает `OperationCanceledException`, если отмена уже запрошена. предшествующая проверка свойства повторяет то же условие в теле задачи.

весь код работы с задачей стоит в `try..catch`. вызов `cancelTokenSource.Cancel()` посылает отмену, `task.Wait()` блокирует основной поток до конечного состояния. исключение, которым закончилась задача, при ожидании через `Wait` приходит внутри `AggregateException`, то есть внутри набора исключений. если причина в отмене, среди `InnerExceptions` есть **TaskCanceledException**:

```c#


catch (AggregateException ae)

{

    foreach (Exception e in ae.InnerExceptions)

    {

        if (e is TaskCanceledException)

            Console.WriteLine("Операция прервана");

        else

            Console.WriteLine(e.Message);

    }

}
```

`TaskCanceledException` является производным от `OperationCanceledException`. такое исключение соответствует задаче, которой выставили статус `Canceled`.

консольный вывод:

```consoletext


Квадрат числа 1 равен 1

Квадрат числа 2 равен 4

Квадрат числа 3 равен 9

Квадрат числа 4 равен 16

Квадрат числа 5 равен 25

Операция прервана

Task Status: Canceled
```

исключение доходит до вызывающего потока, когда тот останавливается и ждёт задачу через `Wait` или `WaitAll` (либо читает `Result` у `Task<TResult>`). без ожидания исключение остаётся записанным в задаче, а снаружи у неё статус `Canceled`. в следующем фрагменте вместо `Wait` стоит `Sleep`, обработчик `catch` не выполняется, отдельной строки об отмене нет:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();

CancellationToken token = cancelTokenSource.Token;



Task task = new Task(() =>

{

    for (int i = 1; i < 10; i++)

    {

        if (token.IsCancellationRequested)

            token.ThrowIfCancellationRequested(); // генерируем исключение



        Console.WriteLine($"Квадрат числа {i} равен {i * i}");

        Thread.Sleep(200);

    }

}, token);

try

{

    task.Start();

    Thread.Sleep(1000);

    // после задержки по времени отменяем выполнение задачи

    cancelTokenSource.Cancel();



    // ожидаем завершения задачи

    Thread.Sleep(1000);

}

catch (AggregateException ae)

{

    foreach (Exception e in ae.InnerExceptions)

    {

        if (e is TaskCanceledException)

            Console.WriteLine("Операция прервана");

        else

            Console.WriteLine(e.Message);

    }

}

finally

{

    cancelTokenSource.Dispose();

}



//  проверяем статус задачи

Console.WriteLine($"Task Status: {task.Status}");
```

консольный вывод:

```consoletext


Квадрат числа 1 равен 1

Квадрат числа 2 равен 4

Квадрат числа 3 равен 9

Квадрат числа 4 равен 16

Квадрат числа 5 равен 25

Task Status: Canceled
```

### регистрация обработчика отмены задачи

сигнал можно не только опрашивать через `IsCancellationRequested`. метод **Register()** записывает обработчик отмены, делегат `Action`, и источник вызывает его из `Cancel`:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();

CancellationToken token = cancelTokenSource.Token;



// задача вычисляет квадраты чисел

Task task = new Task(() =>

{

    int i = 1;

    token.Register(() => 

    { 

        Console.WriteLine("Операция прервана"); 

        i = 10; 

    });

    for (; i < 10; i++)

    {

        Console.WriteLine($"Квадрат числа {i} равен {i * i}");

        Thread.Sleep(400);

    }

}, token);

task.Start();



Thread.Sleep(1000);

// после задержки по времени отменяем выполнение задачи

cancelTokenSource.Cancel();

// ожидаем завершения задачи

Thread.Sleep(1000);

//  проверяем статус задачи

Console.WriteLine($"Task Status: {task.Status}");

cancelTokenSource.Dispose(); // освобождаем ресурсы
```

обработчик задан лямбдой:

```c#


token.Register(() => 

{ 

    Console.WriteLine("Операция прервана"); 

    i = 10; 

});
```

цикл идёт, пока `i` меньше 10. присваивание `i = 10` в обработчике делает условие ложным, и задача выходит из цикла. по умолчанию обработчик `Register` выполняется синхронно на потоке, который вызвал `Cancel`, в примере это основной поток. тело задачи в это время на потоке пула, так что запись в `i` идёт из другого потока. пример опирается на паузу `Sleep`: отмена приходит во время ожидания, и следующая проверка условия видит уже новое `i`.

### передача токена во внешний метод

если операция вынесена во внешний метод, токен передаётся ему одним из параметров. конструктор `Task` получает тот же токен, чтобы планировщик мог выставить статус отмены:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();

CancellationToken token = cancelTokenSource.Token;



Task task = new Task(() =>PrintSquares(token), token);

try

{

    task.Start();

    Thread.Sleep(1000);

    // после задержки по времени отменяем выполнение задачи

    cancelTokenSource.Cancel();



    // ожидаем завершения задачи

    task.Wait();

}

catch (AggregateException ae)

{

    foreach (Exception e in ae.InnerExceptions)

    {

        if (e is TaskCanceledException)

            Console.WriteLine("Операция прервана");

        else

            Console.WriteLine(e.Message);

    }

}

finally

{

    cancelTokenSource.Dispose();

}



//  проверяем статус задачи

Console.WriteLine($"Task Status: {task.Status}");





void PrintSquares(CancellationToken token)

{

    for (int i = 1; i < 10; i++)

    {

        if (token.IsCancellationRequested)

            token.ThrowIfCancellationRequested(); // генерируем исключение



        Console.WriteLine($"Квадрат числа {i} равен {i * i}");

        Thread.Sleep(200);

    }

}
```

`PrintSquares` на каждой итерации проверяет токен и при отмене вызывает `ThrowIfCancellationRequested`. дальше схема совпадает с вариантом исключения: `Wait`, разбор `AggregateException`, `Dispose` в `finally`, печать `task.Status`.

### отмена параллельных операций Parallel

у `Parallel.For()` и `Parallel.ForEach()` есть перегрузки с объектом **ParallelOptions**. через него в цикл передаётся токен:

```c#


CancellationTokenSource cancelTokenSource = new CancellationTokenSource();

CancellationToken token = cancelTokenSource.Token;



// в другой задаче посылаем сигнал отмены

new Task(() =>

{

    Thread.Sleep(400);

    cancelTokenSource.Cancel();

}).Start();



try

{

    Parallel.ForEach<int>(new List<int>() { 1, 2, 3, 4, 5},

                                new ParallelOptions { CancellationToken = token }, Square);

    // или так

    //Parallel.For(1, 5, new ParallelOptions { CancellationToken = token }, Square);

}

catch (OperationCanceledException)

{

    Console.WriteLine("Операция прервана");

}

finally

{

    cancelTokenSource.Dispose();

}



void Square(int n)

{

    Thread.Sleep(3000);

    Console.WriteLine($"Квадрат числа {n} равен {n * n}");

}
```

отдельная задача через 400 мс вызывает `cancelTokenSource.Cancel()`. методы `Parallel` проверяют токен между итерациями и при отмене выбрасывают `OperationCanceledException`, выполнение параллельного цикла прекращается. уже начатое тело, здесь это `Square` с паузой 3000 мс, дорабатывает до конца: инфраструктура не прерывает его на середине. исключение ловится в `catch`, источник освобождается в `finally`.
