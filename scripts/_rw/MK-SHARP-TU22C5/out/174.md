двоичный файл с значениями примитивных типов в машинном представлении читают и пишут классы `BinaryWriter` и `BinaryReader`. текстовая запись тех же значений в этот файл не входит. целое `37` занимает в файле четыре байта. символы `3` и `7` при такой записи не появляются. порядок байтов целых чисел в этих классах little-endian.

### `BinaryWriter`

у `BinaryWriter` несколько конструкторов. базовый принимает поток:

```c#
BinaryWriter(Stream stream)
```

аргумент имеет тип `Stream`. обычно это `FileStream`, полученный из `File.Open`. писатель кодирует значения и передаёт байты в этот поток. по умолчанию строки кодируются в utf-8.

основные методы:

- `Close()`: закрывает поток и освобождает ресурсы
- `Flush()`: сбрасывает буфер и дописывает оставшиеся данные в файл
- `Seek()`: устанавливает позицию во внутреннем потоке
- `Write()`: записывает значение. аргументом служит примитив: `Write(bool)`
- `Write(byte)`
- `Write(char)`
- `Write(decimal)`
- `Write(double)`
- `Write(Half)`
- `Write(short)`
- `Write(int)`
- `Write(long)`
- `Write(sbyte)`
- `Write(float)`
- `Write(string)`
- `Write(ushort)`
- `Write(uint)`
- `Write(ulong)`

массивы передаются отдельными перегрузками `Write(byte[])` и `Write(char[])`, а также срезами:

- `Write(ReadOnlySpan<byte>)`
- `Write(ReadOnlySpan<char>)`

при записи массива можно указать, с какого элемента начинать и сколько элементов брать:

- `Write(byte[], int, int)`
- `Write(char[], int, int)`

`Write(string)` пишет перед байтами строки длину. длина кодируется 7-битным целым переменной ширины: в каждом байте семь бит значения, старший бит отмечает, есть ли следующий байт длины. затем идут байты самой строки в кодировке писателя.

простейшая запись:

```c#


string path = "person.dat";



// создаем объект BinaryWriter

using (BinaryWriter writer = new BinaryWriter(File.Open(path, FileMode.OpenOrCreate)))

{

    // записываем в файл строку

    writer.Write("Tom");

    // записываем в файл число int

    writer.Write(37);

    Console.WriteLine("File has been written");

}
```

в файл `person.dat` попадают два значения: строка `Tom` и число `37` типа `int`. экземпляр строится вызовом `new BinaryWriter(File.Open(path, FileMode.OpenOrCreate))`. `using` закрывает писатель и вместе с ним внутренний поток.

тем же порядком сохраняется массив объектов. `BinaryWriter` не обходит граф объекта и не пишет тип: в файл попадает только то, что явно передано в `Write`. схему, то есть порядок и типы полей, хранит программа.

```c#


string path = "people.dat";



// массив для записи

Person[] people =

{

    new Person("Tom", 37),

    new Person("Bob", 41)

};



using (BinaryWriter writer = new BinaryWriter(File.Open(path, FileMode.OpenOrCreate)))

{

    // записываем в файл значение каждого свойства объекта

    foreach (Person person in people)

    {

        writer.Write(person.Name);

        writer.Write(person.Age);

    }

    Console.WriteLine("File has been written");

}



class Person

{

    public string Name { get; set; }

    public int Age { get; set; }

    public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

для каждого `Person` из массива `people` в файл `people.dat` последовательно пишутся `Name` и `Age`.

### `BinaryReader`

у `BinaryReader` тоже несколько конструкторов. базовая форма принимает поток. во фрагменте ниже конструктор записан так, как он приведён в материале:

```c#
Reader(Stream stream)
```

аргумент снова имеет тип `Stream`, обычно это `FileStream`. читатель забирает из потока столько байтов, сколько занимает запрошенный тип, и сдвигает позицию на это число.

основные методы:

- `Close()`: закрывает поток и освобождает ресурсы
- `ReadBoolean()`: читает `bool` и сдвигает позицию на один байт
- `ReadByte()`: читает один байт и сдвигает позицию на один байт
- `ReadChar()`: читает `char`, один символ, и сдвигает позицию на число байтов, которое символ занимает в текущей кодировке
- `ReadDecimal()`: читает `decimal` и сдвигает позицию на 16 байт
- `ReadDouble()`: читает `double` и сдвигает позицию на 8 байт
- `ReadInt16()`: читает `short` и сдвигает позицию на 2 байта
- `ReadInt32()`: читает `int` и сдвигает позицию на 4 байта
- `ReadInt64()`: читает `long` и сдвигает позицию на 8 байт
- `ReadSingle()`: читает `float` и сдвигает позицию на 4 байта
- `ReadString()`: читает `string`. перед символами лежит длина, записанная тем же 7-битным целым, которым её писал `BinaryWriter`

каждый метод читает ровно свой тип и сдвигает курсор на размер этого типа. `int` занимает 4 байта, поэтому `ReadInt32` забирает 4 байта и оставляет курсор сразу за ними. вызов не того метода, чем при записи, читает чужие байты и сдвигает курсор на чужую величину: дальше весь файл разбирается со смещением.

выше в `person.dat` легли строка и число. чтение повторяет этот порядок:

```c#


using (BinaryReader reader = new BinaryReader(File.Open("person.dat", FileMode.Open)))

{

    // считываем из файла строку

    string name = reader.ReadString();

    // считываем из файла число 

    int age = reader.ReadInt32();

    Console.WriteLine($"Name: {name}  Age: {age}");

}
```

конструктор `BinaryReader` тоже получает поток. режим открытия здесь `FileMode.Open`: файл должен уже существовать. вызов имеет вид `new BinaryReader(File.Open("person.dat", FileMode.Open))`.

порядок чтения совпадает с порядком записи. если сначала писалась строка, а затем число, в том же порядке они и читаются. в файле нет меток типов, только последовательность байтов, которую читатель интерпретирует выбранными методами.

данные `people.dat` читаются тем же правилом. файл содержит значения свойств `Person` в том порядке, в каком их писал предыдущий фрагмент:

```c#


// список для считываемых данных

List<Person> people = new List<Person>();



// создаем объект BinaryWriter

using (BinaryReader reader = new BinaryReader(File.Open("people.dat", FileMode.Open)))

{

    // пока не достигнут конец файла

    // считываем каждое значение из файла

    while (reader.PeekChar() > -1)

    {

        string name = reader.ReadString();

        int age = reader.ReadInt32();

        // по считанным данным создаем объект Person и добавляем в список

        people.Add(new Person(name, age));

    }

}

// выводим содержимое списка people на консоль

foreach(Person person in people)

{

    Console.WriteLine($"Name: {person.Name}  Age: {person.Age}");

}



class Person

{

    public string Name { get; set; }

    public int Age { get; set; }

    public Person(string name, int age)

    {

        Name = name;

        Age = age;

    }

}
```

цикл `while` продолжается, пока `PeekChar()` возвращает значение больше -1. метод заглядывает в следующий символ и возвращает его числовой код, не забирая байты строки окончательно для последующего `ReadString`. если символа нет, возвращается -1, и это трактуется как конец файла. для произвольного двоичного хвоста -1 возможен и тогда, когда байты не образуют символ в кодировке читателя. надёжнее сравнивать `BaseStream.Position` с `BaseStream.Length`. в этом файле очередное значение начинается со строки, и условие отмечает именно конец.

внутри цикла строка и `int` читаются в том же порядке, в каком писались `Name` и `Age`. из них собирается `Person` и добавляется в список `people`. комментарий фрагмента называет создаваемый объект `BinaryWriter`, по коду создаётся `BinaryReader`.
