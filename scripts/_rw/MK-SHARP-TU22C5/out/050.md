при наследовании нередко нужно изменить в классе-наследнике поведение метода, унаследованного от базового класса. тогда класс-наследник переопределяет методы и свойства базового класса.

методы и свойства, которые должны быть доступны для переопределения, в базовом классе помечаются модификатором `virtual`. такие методы и свойства называются виртуальными. модификатор выделяет члену слот диспетчеризации. вызов виртуального члена разрешается по динамическому типу объекта. статический тип ссылки определяет, какой слот вызывается, а реализацию в этом слоте выбирает фактический тип.

чтобы переопределить метод в классе-наследнике, метод объявляется с модификатором `override`. переопределённый метод должен иметь то же имя и тот же набор параметров, что и виртуальный метод в базовом классе. `override` подменяет реализацию в уже существующем слоте и не объявляет отдельный метод. тип возвращаемого значения в примерах совпадает с базовым. начиная с c# 9 у переопределения ссылочного типа допускается ковариантный возврат: тип результата может быть производным от типа результата в базе.

рассматриваются следующие классы:

```c#


class Person

{

	public string Name { get; set; }

	public Person(string name)

	{

		Name = name;

	}

	public virtual void Print()

	{

		Console.WriteLine(Name);

	}

}

class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company) : base(name)

	{

		Company = company;

	}

}
```

класс `Person` представляет человека. класс `Employee` наследуется от `Person` и представляет сотрудника предприятия. помимо унаследованного свойства `Name` у него есть свойство `Company`.

чтобы метод `Print` был доступен для переопределения, он объявлен с модификатором `virtual`. переопределить его можно, но не обязательно. если реализация базового класса устраивает, объекты `Employee` используют метод `Print` из класса `Person`:

```c#


Person bob = new Person("Bob");

bob.Print(); // вызов метода Print из класса Person



Employee tom = new Employee("Tom", "Microsoft");

tom.Print(); // вызов метода Print из класса Person
```

консольный вывод:

```bash


Bob

Tom
```

виртуальный метод можно и переопределить. в классе-наследнике объявляется метод с модификатором `override`, с тем же именем и тем же набором параметров:

```c#


class Employee : Person

{

	public string Company { get; set; }

	public Employee(string name, string company)

		: base(name)

	{

		Company = company;

	}

	public override void Print()

	{

		Console.WriteLine($"{Name} работает в {Company}");

	}

}
```

те же объекты дают уже другой результат для `Employee`, потому что слот `Print` у динамического типа `Employee` указывает на новую реализацию:

```c#


Person bob = new Person("Bob");

bob.Print(); // вызов метода Print из класса Person



Employee tom = new Employee("Tom", "Microsoft");

tom.Print(); // вызов метода Print из класса Employee
```

консольный вывод:

```bash


Bob

Tom работает в Microsoft
```

виртуальные методы базового класса задают интерфейс всей иерархии. переопределить их можно на любой глубине наследования. класс `Manager`, производный от `Employee`, тоже может переопределить метод `Print`, если выше по иерархии метод не закрыт модификатором `sealed`.

при переопределении виртуальных методов действуют ограничения:

- виртуальный и переопределённый методы должны иметь один и тот же модификатор доступа. если виртуальный метод объявлен как `public`, переопределённый метод тоже должен быть `public`. сузить или расширить доступ нельзя: у слота одна доступность на всю иерархию

- нельзя переопределить статический метод класса и нельзя объявить статический метод класса виртуальным. статический член не вызывается у экземпляра и не занимает слот диспетчеризации объекта. вызов связывается во время компиляции по имени типа. статические виртуальные члены, появившиеся в c# 11, объявляются в интерфейсах и к наследованию классов не относятся

### ключевое слово base

помимо конструкторов, ключевое слово `base` обращается и к другим членам базового класса. вызов `base.Print()` обращается к методу `Print()` класса `Person`:

```c#


class Employee : Person

{

    public string Company { get; set; }

 

    public Employee(string name, string company)

			:base(name)

    {

        Company = company;

    }

 

    public override void Print()

    {

        base.Print();

        Console.WriteLine($"работает в {Company}");

    }

}
```

вызов через `base` не отправляется снова в переопределение производного класса. связывание начинается с реализации базового типа, поэтому из `Employee.Print` можно дописать поведение, не зацикливая вызов на самом себе.

### переопределение свойств

свойства переопределяются так же, как методы:

```c#


class Person

{

	int age = 1;

	public virtual int Age

	{

		get => age;

		set{ if(value > 0 && value < 110) age = value; }

	}

	public string Name { get; set; }

	public Person(string name)

    {

        Name = name;

    }

	public virtual void Print() => Console.WriteLine(Name);

}

class Employee : Person

{

	public override int Age

	{

		get => base.Age;

		set { if (value > 17 && value < 110) base.Age = value; }

	}

	public string Company { get; set; }

	public Employee(string name, string company)

		: base(name)

	{

		Company = company;

		base.Age = 18; // возраст для работников по умолчанию

	}

}
```

в классе `Person` определено виртуальное свойство `Age`. значение записывается, если оно больше 0 и меньше 110. в классе `Employee` свойство переопределено: возраст работника должен быть не меньше 18, верхняя граница по-прежнему меньше 110. в конструкторе `base.Age = 18` обращается к сеттеру базового класса напрямую, минуя виртуальную диспетчеризацию, и проходит проверку `Person`.

```c#


Person bob = new Person("Bob");

Console.WriteLine(bob.Age); // 1



Employee tom = new Employee("Tom", "Microsoft");

Console.WriteLine(tom.Age); // 18

tom.Age = 22;

Console.WriteLine(tom.Age); // 22

tom.Age = 12;

Console.WriteLine(tom.Age); // 22
```

переопределение сеттера сужает множество допустимых значений по сравнению с базовым классом. поскольку свойство виртуальное, присваивание выполняет сеттер динамического типа. инвариант работника сохраняется: значение 12, показанное в примере, не записывается, и возраст остаётся прежним. подстановка объекта `Employee` туда, где ожидается произвольный `Person`, уже не гарантирует запись любого возраста, который принял бы базовый сеттер.

### запрет переопределения методов

переопределение методов и свойств можно запретить. для этого их объявляют с модификатором `sealed`:

```c#


class Employee : Person

{

    public string Company { get; set; }

 

    public Employee(string name, string company)

                : base(name)

	{

		Company = company;

	}



	public override sealed void Print()

	{

		Console.WriteLine($"{Name} работает в {Company}");

	}

}
```

модификатор `sealed` применяется в паре с `override`, то есть только к уже переопределяемым методам. закрывается конкретная реализация в иерархии: метод остаётся виртуальным для вызывающего кода, но ниже этого класса слот больше не подменяется.

после такого объявления метод `Print` нельзя переопределить в классе, унаследованном от `Employee`.
