в предыдущей теме метод `Dispose` вызывался вручную, через конструкцию `try...finally`:

```c#


Test();



void Test()

{

    Person? tom = null;

    try

    {

        tom = new Person("Tom");

    }

    finally

    {

        tom?.Dispose();

    }

}

public class Person : IDisposable

{

    public string Name { get;}

    public Person(string name) => Name = name;



    public void Dispose() => Console.WriteLine($"{Name} has been disposed");

}
```

в c# для того же сценария есть отдельная конструкция **using**. она разворачивается компилятором в `try...finally` и сама вызывает `Dispose` при выходе из области:

```c#


using (Person tom = new Person("Tom"))

{

}
```

конструкция оформляет блок и объявляет объект типа, у которого есть метод `Dispose`. для обычного класса это тип, реализующий интерфейс `IDisposable`. при завершении блока, и при нормальном выходе, и при исключении, у объекта вызывается `Dispose`.

применение к тому же классу `Person`:

```c#


Test();



void Test()

{

    using (Person tom = new Person("Tom"))

    {

        // переменная tom доступна только в блоке using

        // некоторые действия с объектом Person

        Console.WriteLine($"Name: {tom.Name}");

    }

    Console.WriteLine("Конец метода Test");

}

public class Person : IDisposable

{

    public string Name { get;}

    public Person(string name) => Name = name;



    public void Dispose() => Console.WriteLine($"{Name} has been disposed");

}
```

консольный вывод:

```bash


Name: Tom

Tom has been disposed

Конец метода Test
```

по завершении блока `using` у объекта `Person` вызывается `Dispose`, и только потом выполняется оператор, стоящий после блока. переменная `tom` объявлена внутри блока, поэтому за его пределами её нет: область видимости имени совпадает с областью, в конце которой выполняется освобождение.

начиная с версии c# 8.0 областью действия `using` может быть вся окружающая область видимости, например метод:

```c#


Test();



void Test()

{

    using Person tom = new Person("Tom");

    

    // переменная tom доступна только в блоке using

    // некоторые действия с объектом Person

    Console.WriteLine($"Name: {tom.Name}");

    Console.WriteLine("Конец метода Test");

}

public class Person : IDisposable

{

    public string Name { get;}

    public Person(string name) => Name = name;



    public void Dispose() => Console.WriteLine($"{Name} has been disposed");

}
```

такая форма называется объявлением `using`. компилятор понимает её так: переменная удаляется в конце области видимости, то есть в конце метода `Test`. `Dispose` выполняется после остальных операторов метода. консольный вывод из-за этого меняет порядок относительно блочной формы:

```bash


Name: Tom

Конец метода Test

Tom has been disposed
```

строка `Конец метода Test` печатается раньше сообщения из `Dispose`. ресурс живёт до конца метода, а не до конца вложенного блока.

### освобождение множества ресурсов

несколько ресурсов освобождают вложенными конструкциями `using`:

```c#


void Test()

{

	using (Person tom = new Person("Tom"))

	{

		using (Person bob = new Person("Bob"))

		{

			Console.WriteLine($"Person1: {tom.Name}    Person2: {bob.Name}");

		}// вызов метода Dispose для объекта bob

	} // вызов метода Dispose для объекта tom

	Console.WriteLine("Конец метода Test");

}
```

обе конструкции в примере создают объекты одного типа. типы могут и различаться. условие одно: у каждого типа есть `Dispose`, для класса это реализация `IDisposable`. внутренний блок завершается раньше внешнего, поэтому `Dispose` у `bob` вызывается раньше, чем у `tom`.

то же вложение записывается без лишней пары скобок. вторая конструкция `using` становится заголовком того же блока:

```c#


void Test()

{

	using (Person tom = new Person("Tom"))

	using(Person bob = new Person("Bob"))

	{

		Console.WriteLine($"Person1: {tom.Name}    Person2: {bob.Name}");

	} // вызов метода Dispose для объектов bob и tom

	Console.WriteLine("Конец метода Test");

}
```

комментарий в листинге фиксирует порядок: при выходе из общего блока `Dispose` вызывается и для `bob`, и для `tom`. первым освобождается объект, объявленный позже, то есть `bob`.

в c# область действия объектов, созданных объявлением `using`, может совпадать со всем методом:

```c#


private static void Test()

{

	using Person tom = new Person { Name = "Tom" };

	using Person bob = new Person { Name = "Bob" };

	

	Console.WriteLine($"Person1: {tom.Name}    Person2: {bob.Name}");

	

	Console.WriteLine("Конец метода Test");

} // вызов метода Dispose для объектов bob и tom
```

оба объекта доживают до закрывающей скобки `Test`. освобождение идёт в порядке, обратном объявлению: сначала `bob`, затем `tom`. в этом листинге `Person` создаётся инициализатором объекта, со свойством `Name` в фигурных скобках.

другой пример моделирует сетевое подключение:

```c#


// создаем подключение

using (var con = new Connection())

con.Open(new Socket()); // открываем условный сокет для взаимодействия по сети



// класс сокета

class Socket

{

    public bool IsOpened {get;set;}     // открыт ли сокет

}

// класс сетевого подключения

class Connection : IDisposable

{

    Socket? activeSocket = null;



    // для открытия сетевого подключения передаем сокет

    public void Open(Socket? socket)

    {

        if(activeSocket != socket)  // проверяем сокет

        {

            Close();    // закрываем сокет, если ранее был установлен другой сокет

            activeSocket = socket;

            activeSocket?.IsOpened = true;  // открываем новый сокет

            Console.WriteLine("Подключение открыто. Можно посылать пакеты по сети");

        }

    }

    // закрываем сокет

    public void Close()

    {

        if(activeSocket is not null)

        {

            activeSocket?.IsOpened = false;

            Console.WriteLine("Подключение закрыто...");

        }

    }

    public void Dispose()

    {

        Close();

    }

}
```

подключение представлено классом `Connection`. обмен по сети обычно идёт через сокет: компонент, который привязан к порту и отправляет либо принимает данные. сокет, как правило, является ресурсом операционной системы, и его нужно закрыть после работы, иначе дескриптор останется занятым. в примере сокет сведён к классу `Socket` с одним свойством `IsOpened`. оно показывает, открыт ли сокет.

метод `Open()` принимает сокет и открывает его для обмена. если в `activeSocket` уже лежит другой сокет, сначала вызывается `Close()`, затем новый сокет запоминается и помечается открытым. метод `Close()` сбрасывает `IsOpened` у текущего сокета. `Dispose` вызывает `Close`, потому что вместе с подключением сокет больше не нужен.

в основной части программы объект подключения создаётся и сразу открывается:

```c#


using (var con = new Connection())

con.Open(new Socket()); // открываем условный сокет для взаимодействия по сети
```

конструкция `using` без собственного блока действует до конца текущего метода, здесь это `Main`. при выходе из метода автоматически вызывается `Dispose` у `Connection`, тот вызывает `Close`, и сокет закрывается. объект `Connection` тем самым освобождает сокет. консольный вывод:

```bash


Подключение открыто. Можно посылать пакеты по сети

Подключение закрыто...
```

первая строка печатается из `Open`, вторая из `Close`, который запущен уже из `Dispose` на выходе из метода.

### абстрагирование завершения using

при выходе из `using` вызывается `Dispose()`. в примерах выше метод принадлежал тому же классу, который держит ресурс. вызов нужных действий можно отдать отдельному объекту и не привязывать `Dispose` к классу подключения:

```c#


// создаем подключение

var con = new Connection();



using var closeSocket = new ScopeExit(() => 

{

    con.Close();

    Console.WriteLine("Сокет свободен");

});





con.Open(new Socket()); // открываем условный сокет для взаимодействия по сети



// класс сокета

class Socket

{

    public bool IsOpened {get;set;}     // открыт ли сокет

}

// класс сетевого подключения

class Connection

{

    Socket? activeSocket = null;



    // для открытия сетевого подключения передаем сокет

    public void Open(Socket? socket)

    {

        if(activeSocket != socket)  // проверяем сокет

        {

            Close();    // закрываем сокет, если ранее был установлен другой сокет

            activeSocket = socket;

            activeSocket?.IsOpened = true;  // открываем новый сокет

            Console.WriteLine("Подключение открыто. Можно посылать пакеты по сети");

        }

    }

    // закрываем сокет

    public void Close()

    {

        if(activeSocket is not null)

        {

            activeSocket?.IsOpened = false;

            Console.WriteLine("Подключение закрыто...");

        }

    }

}



public ref struct ScopeExit

{

    public ScopeExit(Action action)

    {

        this.action = action;

    }



    public void Dispose()

    {

        action.Invoke();

    }



    Action action;

}
```

классы `Connection` и `Socket` те же, и после работы `Connection` по-прежнему должен закрыть сокет. сам `Connection` метод `Dispose` больше не реализует и интерфейс `IDisposable` не наследует. ресурсом конструкции `using` служит ссылочная структура `ScopeExit`. через конструктор она принимает действие типа `Action` и вызывает его в своём `Dispose()`.

`ref struct` не может реализовать интерфейс: интерфейс предполагает упаковку, а ссылочная структура существует только на стеке. компилятор для `using` начиная с c# 8.0 принимает тип и по образцу. достаточно доступного метода `Dispose()` без интерфейса `IDisposable`. `ScopeExit` как раз такой тип.

при объявлении `using` создаётся экземпляр `ScopeExit`, и в конструктор передаётся действие. в действии `Connection` вызывает `Close` и тем самым закрывает сокет, после чего печатается отдельная строка. порядок на консоли такой:

```bash


Подключение открыто. Можно посылать пакеты по сети

Подключение закрыто...

Сокет свободен
```

сначала выполняется `Open`, который стоит в теле метода после объявления `using`. `Dispose` у `ScopeExit` запускается в конце области, вызывает `Close` и затем печатает сообщение о свободном сокете. момент освобождения задан границей области видимости, а состав действий задан делегатом, а не классом подключения.
