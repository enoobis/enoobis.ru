переменной и параметру значимого типа напрямую присвоить `null` нельзя. значение значимого типа всегда содержит данные: пустой ссылки, как у ссылочного типа, у него нет. тем не менее часто требуется, чтобы значимый тип мог выразить отсутствие значения. типичный случай представляет число, прочитанное из базы данных: если значение в базе есть, получается число, если значения нет, получается `null`.

чтобы переменной или параметру значимого типа можно было присвоить `null`, их тип должен быть nullable-типом. после названия типа ставится знак `?`:

```c#


int? val = null;

Console.WriteLine(val);
```

переменная `val` имеет тип `int?`. такой тип принимает и значения `int`, и значение `null`. в примере переменной передаётся `null`. передать можно и обычное значение `int`:

```c#


int? val = null;

IsNull(val);    // null

val = 22;

IsNull(val);    // 22



void IsNull(int? obj)

{

    if (obj == null) Console.WriteLine("null");

    else Console.WriteLine(obj);

}
```

если переменная или параметр имеет значимый тип без nullable-пометки, присвоить `null` не удастся. компилятор отвергает такое присваивание, потому что у значения нет состояния «данные отсутствуют»:

```c#
int val = null;  // ! ошибка, переменная val НЕ представляет тип nullable
```

запись `?` у значимого типа является сокращением структуры `System.Nullable<T>`. параметр `T` в угловых скобках представляет универсальный параметр, вместо которого подставляется конкретный тип данных. `Nullable<T>` является структурой, то есть само остаётся значимым типом: внутри хранятся значение `T` и признак наличия этого значения. `null` для `int?` означает сброшенный признак наличия значения. сама переменная при этом остаётся структурой `Nullable<T>`. следующие определения эквивалентны:

```c#


int? number1 = 5;

Nullable<int> number2 = 5;
```

#### свойства Value и HasValue и метод GetValueOrDefault

структура `Nullable<T>` имеет два свойства.

- `Value` хранит значение объекта. чтение `Value` при отсутствии значения завершается исключением `InvalidOperationException`

- `HasValue` возвращает `true`, если объект хранит некоторое значение, и `false`, если объект равен `null`

эти свойства используются для проверки наличия значения и для его получения:

```c#


PrintNullable(5);       // 5

PrintNullable(null);    // параметр равен null



void PrintNullable(int? number)

{

    if (number.HasValue)

    {

        Console.WriteLine(number.Value);

        // аналогично

        Console.WriteLine(number);

    }

    else

    {

        Console.WriteLine("параметр равен null");

    }

}
```

если через свойство `Value` прочитать переменную, которая равна `null`, возникает ошибка. вывод самой nullable-переменной при этом исключения не даёт: преобразование в строку для пустого `Nullable<T>` даёт пустую строку, и на консоль ничего не попадает:

```c#


int? number = null;

Console.WriteLine(number.Value);	// ! Ошибка

Console.WriteLine(number);			// Ошибки нет - просто ничего не выведет
```

у структуры `Nullable<T>` есть метод `GetValueOrDefault()`. он возвращает значение переменной или параметра, если они не равны `null`. если они равны `null`, возвращается значение по умолчанию. это значение можно передать в метод аргументом. если аргумент не передан, возвращается значение по умолчанию для данного типа данных. для числовых типов это число 0:

```c#


int? number = null; // если значения нет, метод возвращает значение по умолчанию

Console.WriteLine(number.GetValueOrDefault());      // 0  - значение по умолчанию для числовых типов

Console.WriteLine(number.GetValueOrDefault(10));    // 10



number = 15;    // если значение задано, оно возвращается методом

Console.WriteLine(number.GetValueOrDefault());    // 15

Console.WriteLine(number.GetValueOrDefault(10));  // 15
```

### преобразование значимых nullable-типов

возможны такие преобразования.

- явное преобразование от `T?` к `T`. преобразование законно только при наличии значения, поэтому перед приведением проверяется `HasValue`. приведение пустого `T?` к `T` во время выполнения даёт `InvalidOperationException`: извлекать нечего

```c#


int? x1 = null;

if(x1.HasValue)

{

    int x2 = (int)x1;

    Console.WriteLine(x2);

}
```

- неявное преобразование от `T` к `T?`. оно всегда успешно и даёт nullable-значение с установленным `HasValue`

```c#


int x1 = 4;

int? x2 = x1;

Console.WriteLine(x2);
```

- неявные расширяющие преобразования от `V` к `T?` и явные сужающие преобразования от `V` к `T?`. если `V` неявно приводится к `T`, то `V` неявно приводится и к `T?`: сначала выполняется расширяющее преобразование, затем результат заворачивается в nullable-тип. сужающее преобразование, наоборот, требует явного приведения. к значению применяются те же правила, что и при сужении `V` к `T`, после чего результат получает тип `T?`

```c#


int x1 = 4;

long? x2 = x1;

Console.WriteLine(x2);
```

```c#


long x1 = 4;

int? x2 = (int?)x1;
```

- явные сужающие преобразования от `V?` к `T?` устроены так же. если исходное значение пусто, результат тоже пуст и исключения нет. если значение есть, оно сужается от `V` к `T` и снова заворачивается в nullable-тип

```c#


long? x1 = 4;

int? x2 = (int?)x1;
```

- явные сужающие преобразования от `V?` к `T` требуют и сужения, и снятия nullable-оболочки. пустое значение приводить нельзя, поэтому в коде снова проверяется `HasValue`. без проверки пустой `V?` при приведении к `T` даёт `InvalidOperationException`

```c#


long? x1 = null;

if (x1.HasValue) 

{ 

    int x2 = (int)x1; 

}
```

### операции с nullable-типами

nullable-типы поддерживают тот же набор операций, что и их не-nullable двойники. операции базового типа поднимаются на nullable-тип: компилятор порождает вариант оператора, который сначала проверяет наличие значений. если в операции участвует nullable-тип, результат тоже имеет nullable-тип. присвоить такой результат переменной базового типа нельзя, пока значение не извлечено через `Value` или явное приведение:

```c#


int? x = 5;

int z = x + 7;          // нельзя

int? w = x + 7;         // можно

int d = x.Value + 7;    // можно
```

в арифметической операции, если один из операндов равен `null`, результат операции тоже равен `null`. второе слагаемое в этом случае не образует числа, и сумма не определена:

```c#


int? x = null;

int? w = x + 7;         // w = null
```

в операциях отношения `>`, `<`, `>=` и `<=`, если хотя бы один из операндов равен `null`, возвращается `false`. сравнение с отсутствующим значением не считается ни большим, ни меньшим. операция `!=` к этому правилу не относится и рассматривается вместе с `==`:

```c#


int? x = null;

int? y = 5;     

int? z = null;  

Console.WriteLine($"x > y is {x > y}");     // false

Console.WriteLine($"x < y is {x < y}");     // false 

Console.WriteLine($"x >= y is {x >= y}");   // false

Console.WriteLine($"x <= y is {x <= y}");   // false



Console.WriteLine($"x > z is {x > z}");     // false

Console.WriteLine($"x < z is {x < z}");     // false 

Console.WriteLine($"x >= z is {x >= z}");   // false

Console.WriteLine($"x <= z is {x <= z}");   // false
```

в операциях `==` и `!=` выполняется обычное сравнение с учётом отсутствия значения. два операнда, равные `null`, считаются равными между собой. `null` и число равными не считаются, поэтому `!=` в таком случае даёт `true`:

```c#


int? x = null;

int? y = 5;     

int? z = null;  



Console.WriteLine($"x == y is {x == y}");   // false

Console.WriteLine($"x != y is {x != y}");   // true



Console.WriteLine($"x == z is {x == z}");   // true

Console.WriteLine($"x != z is {x != z}");   // false
```
