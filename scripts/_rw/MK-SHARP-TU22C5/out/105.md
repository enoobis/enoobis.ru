для большинства коллекций платформы базовым контрактом перебора служит пара интерфейсов IEnumerable и IEnumerator. реализация этой пары позволяет обходить объекты циклом `foreach`:

```c#


foreach(var item in перечислимый_объект)

{

	

}
```

перебираемая коллекция предоставляет интерфейс IEnumerable либо, как будет видно дальше, публичный метод с тем же именем и подходящей сигнатурой.

интерфейс IEnumerable содержит один метод. он возвращает ссылку на другой интерфейс, перечислитель:

```c#


public interface IEnumerable

{

	IEnumerator GetEnumerator();

}
```

интерфейс IEnumerator задаёт протокол обхода внутренних объектов контейнера:

```c#


public interface IEnumerator

{

	bool MoveNext(); // перемещение на одну позицию вперед в контейнере элементов

	object Current {get;}  // текущий элемент в контейнере

	void Reset(); // перемещение в начало контейнера

}
```

метод **MoveNext()** сдвигает указатель текущего элемента на следующую позицию последовательности. пока элементы ещё есть, метод возвращает true. когда последовательность исчерпана, возвращается false.

свойство **Current** возвращает объект, на который указатель установлен сейчас.

метод **Reset()** возвращает указатель в начальное положение, то есть в позицию перед первым элементом.

конкретный способ сдвига указателя и извлечения элемента определяется реализацией. разные контейнеры строят эту логику по-разному: массив хранит индекс, связный список хранит ссылку на узел, дерево может обходить вершины в выбранном порядке. сам цикл от этой разницы не зависит и видит только три операции протокола.

тот же обход массива записывается через IEnumerator явно, без цикла foreach:

```c#


using System.Collections;



string[] people = {"Tom", "Sam", "Bob"};



IEnumerator peopleEnumerator = people.GetEnumerator(); // получаем IEnumerator

while (peopleEnumerator.MoveNext())   // пока не будет возвращено false

{

    string item = (string)peopleEnumerator.Current; // получаем элемент на текущей позиции

    Console.WriteLine(item);

}

peopleEnumerator.Reset(); // сбрасываем указатель в начало массива
```

`GetEnumerator` выдаёт перечислитель, стоящий перед первым элементом. цикл вызывает `MoveNext`, и только после возврата true читает `Current`. у необобщённого свойства `Current` тип `object`, поэтому значение приводится к `string`. после исчерпания массива `Reset` снова ставит указатель в начало, и тот же экземпляр перечислителя можно пройти заново. цикл `foreach` так не делает: он каждый раз запрашивает новый перечислитель и `Reset` не вызывает.

### реализация IEnumerable и IEnumerator

простейшая реализация **IEnumerable** делегирует обход уже готовому перечислителю массива:

```c#


using System.Collections;



Week week = new Week();

foreach (var day in week)

{

    Console.WriteLine(day);

}



class Week : IEnumerable

{

    string[] days = { "Monday", "Tuesday", "Wednesday", "Thursday",

                         "Friday", "Saturday", "Sunday" };

    public IEnumerator GetEnumerator() => days.GetEnumerator();

}
```

класс Week изображает неделю и хранит названия дней в массиве. метод `GetEnumerator` не строит собственный автомат обхода, а возвращает перечислитель массива `days`:

```c#


public IEnumerator GetEnumerator() => days.GetEnumerator();
```

этого достаточно, чтобы цикл foreach перебрал все дни. перечислитель массива представляет собой структуру. возврат её через тип интерфейса IEnumerator упаковывает структуру в объект на куче. для учебного примера цена упаковки незаметна, при частом обходе больших массивов она уже входит в стоимость перебора.

циклу foreach достаточно публичного метода **GetEnumerator**, который возвращает объект IEnumerator. компилятор ищет этот метод по образцу, включая метод расширения. реализация интерфейса IEnumerable требуется, когда объект передаётся дальше как значение типа IEnumerable. класс с одним только методом выглядит так:

```c#


class Week

{

	string[] days = { "Monday", "Tuesday", "Wednesday", "Thursday", 

						"Friday", "Saturday", "Sunday" };

	public IEnumerator GetEnumerator() =>days.GetEnumerator();

}
```

в предыдущих вариантах использовался готовый перечислитель массива. собственный порядок обхода задаётся реализацией интерфейса **IEnumerator**:

```c#


using System.Collections;



class WeekEnumerator : IEnumerator

{

    string[] days;

    int position = -1;

    public WeekEnumerator(string[] days) => this.days = days;

    public object Current

    {

        get

        {

            if (position == -1 || position >= days.Length)

                throw new ArgumentException();

            return days[position];

        }

    }

    public bool MoveNext()

    {

        if (position < days.Length - 1)

        {

            position++;

            return true;

        }

        else

            return false;

    }

    public void Reset() => position = -1;

}

class Week

{

    string[] days = { "Monday", "Tuesday", "Wednesday", "Thursday",

                            "Friday", "Saturday", "Sunday" };

    public IEnumerator GetEnumerator() => new WeekEnumerator(days);

}
```

класс Week больше не вызывает перечислитель массива. он создаёт WeekEnumerator и передаёт ему тот же массив дней. указатель позиции хранится в поле position. в исходном состоянии перечислитель обязан стоять перед первым элементом, поэтому начальное значение равно -1. цикл foreach сначала вызывает `MoveNext` и тем самым сдвигает указатель на одну позицию вперёд, и только затем читает `Current`. обращение к `Current` в позиции -1 или за последним элементом в этом примере завершается `ArgumentException`. контракт интерфейса для обращения вне допустимой позиции задаёт `InvalidOperationException`.

`MoveNext` увеличивает position, пока индекс остаётся внутри массива, и возвращает true. на последнем элементе следующий вызов возвращает false и позицию не сдвигает за границу чтения. `Reset` снова записывает -1, возвращая перечислитель в состояние, которое было сразу после конструктора.

объект Week после этого обходится тем же циклом foreach:

```c#


Week week = new Week();

foreach(var day in week)

{

	Console.WriteLine(day);

}
```

цикл получает перечислитель из `GetEnumerator`, последовательно вызывает `MoveNext` и печатает `Current`, пока `MoveNext` не вернёт false. если перечислитель реализует `IDisposable`, цикл по завершении вызывает `Dispose`. в этой реализации освобождать нечего, но сам протокол такой вызов предусматривает.

### обобщённая версия IEnumerator

выше использовались необобщённые интерфейсы из пространства `System.Collections`. у них есть обобщённые двойники `IEnumerable<T>` и `IEnumerator<T>` в пространстве `System.Collections.Generic`. обобщённый перечислитель возвращает элемент статически известного типа и наследует `IDisposable`:

```c#


using System.Collections;



class WeekEnumerator : IEnumerator<string>

{

    string[] days;

    int position = -1;

    public WeekEnumerator(string[] days) => this.days = days;

    public string Current

    {

        get

        {

            if (position == -1 || position >= days.Length)

                throw new ArgumentException();

            return days[position];

        }

    }

    object IEnumerator.Current => Current;

    public bool MoveNext()

    {

        if (position < days.Length - 1)

        {

            position++;

            return true;

        }

        else

            return false;

    }

    public void Reset() => position = -1;

    public void Dispose() { }

}

class Week

{

    string[] days = { "Monday", "Tuesday", "Wednesday", "Thursday",

                            "Friday", "Saturday", "Sunday" };

    public IEnumerator<string> GetEnumerator() => new WeekEnumerator(days);

}
```

реализуется интерфейс `IEnumerator<string>`, поэтому свойство Current возвращает `string`. необобщённый член `IEnumerator.Current` обязан остаться: его тип `object`, и он реализован явно через уже типизированное свойство. для ссылочного типа string упаковки при таком перенаправлении нет. метод `Dispose` присутствует из-за наследования `IEnumerator<T>` от `IDisposable` и в примере пуст.

при обходе в цикле foreach элементы сразу имеют тип **string**, отдельное приведение не требуется:

```c#


Week week = new Week();

foreach (string day in week)

{

    Console.WriteLine(day);

}
```

обобщённый протокол убирает приведение и связанную с ним возможность ошибки типов во время выполнения. необобщённый обход всякий раз получает `object` и восстанавливает тип вручную. для значимых типов разница ещё и в размещениях: необобщённый `Current` упаковывает значение, обобщённый возвращает его по объявленному типу `T`.
