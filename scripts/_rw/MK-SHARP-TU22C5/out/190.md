### паттерны списков

паттерн списка (list pattern) относится к сопоставлению с образцом: выражение сравнивается с последовательностью, у которой компилятор видит длину и индексатор. сюда попадают массивы и списки, а также другие типы той же формы, в частности `Span<T>`. шаблон фиксированной длины задаёт элемент на каждой позиции. четыре константы соответствуют только той последовательности, которая поэлементно равна этим значениям.

```c#


[2, 3, 4, 5] // этот паттерн соответствует любому массиву/списку, 

            // который равен [2, 3, 4, 5]
```

паттерн `_` занимает ровно одну позицию и принимает любое значение. имя при этом не вводится, значение просто отбрасывается. шаблон из двух позиций, во второй из которых стоит 5, подходит для любой пары с таким хвостом, в том числе для `[1, 5]` и `[25, 5]`.

```c#


[_, 5] // этот паттерн соответствует любому массиву/списку из двух элементов

        // где второй элемент равен 5 (например, [1, 5] или [25, 5])
```

slice-паттерн `..` обозначает подряд идущий фрагмент произвольной длины, включая пустой. в одном паттерне списка такой фрагмент допустим один раз: иначе разбиение последовательности на части было бы неоднозначным. шаблон с 2 в начале, 5 в конце и `..` между ними покрывает и `[2, 5]`, где середина пуста, и `[2, 3, 9, 5]`.

```c#


[2, .., 5] // этот паттерн соответствует любому массиву/списку, где первый элемент равен 2

        // а последний элемент равен 5, а между 2 и 5 может быть произвольное количество произвольных элементов

        // (например, [2, 5] или [2, 3, 9, 5])
```

в выражении `switch` ветви проверяются сверху вниз, срабатывает первая подходящая. более частный шаблон поэтому записывают выше более общего, иначе общий перехватит значения, которые должны были попасть в частный. локальная функция `GetNumber` разбирает `int[]` именно в таком порядке.

```c#


Console.WriteLine(GetNumber(new[] { 2, 3, 5 }));        // 1

Console.WriteLine(GetNumber(new[] { 2, 4, 5 }));        // 2

Console.WriteLine(GetNumber(new[] { 2, 3, 4, 5 }));     // 3

Console.WriteLine(GetNumber(new[] { 1, 2, 3 }));        // 4

Console.WriteLine(GetNumber(new int[] { }));            // 4



int GetNumber(int[] values) => values switch

{

    [2, 3, 5] => 1,

    [2, _, 5] => 2,

    [2, .., 5] => 3,

    [..] => 4

};
```

ветвь `[2, 3, 5]` возвращает 1 и забирает только эту тройку. ветвь `[2, _, 5]` возвращает 2: длина ровно три, края фиксированы, средний элемент произволен, поэтому массив `{2, 4, 5}` останавливается здесь. ветвь `[2, .., 5]` возвращает 3. массив `{2, 3, 4, 5}` длиннее трёх элементов и с шаблонами фиксированной длины не совпадает. края равны 2 и 5, поэтому срабатывает эта ветвь. ветвь `[..]` возвращает 4 и принимает любую оставшуюся последовательность, включая `{1, 2, 3}` и массив нулевой длины. значение `null` паттерн списка не принимает: `null` не является последовательностью элементов.

### обобщения в атрибутах

в c# 11 класс атрибута может быть обобщённым. аргумент типа указывается в месте применения и обязан быть закрытым: в метаданные атрибута он записывается на тех же основаниях, что и аргумент оператора `typeof`. класс по-прежнему наследует `Attribute`. суффикс `Attribute` в месте применения можно опустить, поэтому тип `ReaderAttribute<T>` на методе записывается как `Reader<int>`.

```c#


class C

{

    [Reader<int>]

    public void M() 

    {

    }

}



class ReaderAttribute<T> : Attribute

{

}
```

атрибут стоит на методе `M`. параметр типа `T` подставлен как `int` и тем самым зафиксирован для этого применения.

### многострочные строки

многострочный текст, в том числе с интерполяцией, записывается сырым строковым литералом. его открывает и закрывает одна и та же последовательность символов двойной кавычки. в примере их три. грамматика допускает и более длинную последовательность, лишь бы открывающая и закрывающая совпали. кавычки внутри текста экранировать не нужно: они не завершают литерал, пока не встретится последовательность той же длины. если перед открывающей последовательностью стоит `$`, литерал интерполируется, и фигурные скобки обозначают дырку подстановки. колонка закрывающей последовательности задаёт общий отступ: он вычитается из каждой строки содержимого, поэтому в вывод не попадают ведущие пробелы, которыми пример выровнен в исходном тексте.

```c#


Print();

PrintValue("hello");



void Print()

{

    string text = """

              <element attr="content">

                <body>

                </body>

              </element>

              """;

    Console.WriteLine(text);

}



void PrintValue(string val)

{

    string text = $"""

              <element attr="content">

                <body>

                {val}

                </body>

              </element>

              """;

    Console.WriteLine(text);

}
```

`Print` выводит фрагмент разметки без подстановок. `PrintValue` строит такой же фрагмент, но в дырку `{val}` попадает аргумент метода.

### строковые литералы utf-8

литерал с суффиксом `u8` имеет тип `ReadOnlySpan<byte>`. содержимое span представляет собой байты той же строки в кодировке utf-8. перекодирование выполняется во время компиляции, байты размещаются в сборке. отдельный объект `string` для такого литерала не строится, и на границе с api, которые принимают utf-8, повторно кодировать текст не нужно.

```c#


ReadOnlySpan<byte> span2 = "hello"u8;
```

суффикс `u8` сообщает компилятору, что литерал кодируется в utf-8. обычный строковый литерал при этом остаётся последовательностью utf-16.

### файл как область видимости

в c# 11 появился модификатор доступности `file`. он применяется к классам, структурам, делегатам, перечислениям и интерфейсам. тип с этим модификатором входит в область видимости только текущего файла компиляции. другие файлы той же сборки его не видят, поэтому в каждом файле может быть свой file-локальный тип с тем же именем. этим пользуются генераторы исходного кода: служебный тип не попадает во внутреннюю область сборки и не сталкивается с типом из другого генератора.

```c#


file class Person

{

}
```

модификатор `file` не комбинируется с `public`, `internal`, `private` и остальными модификаторами доступности. видимость такого типа задаётся одним этим словом.

### модификатор required

модификатор `required`, добавленный в c# 11, помечает поле или свойство, которое вызывающий код обязан инициализировать при создании экземпляра. проверка статическая: пропуск обязательного члена является ошибкой компиляции. у `Person` обязательны `Name` и `Age`, поэтому вызов конструктора без инициализатора объекта отвергается.

```c#


Person tom = new Person();  // ошибка - свойства Name и Age не инициализированы

public class Person

{

    public required string Name { get; set; }

    public required int Age { get; set; }

}
```

значения задаются инициализатором объекта. он выполняется после конструктора и в этой точке компилятор видит, что оба обязательных свойства установлены.

```c#
Person tom = new Person { Name = "Tom", Age = 38 }; // ошибки нет
```

присваивание в теле конструктора и инициализатор при объявлении поля сами по себе обязательность не снимают. компилятор не анализирует тело конструктора и не доказывает, что все required-члены там записаны. такое обещание даёт только атрибут `System.Diagnostics.CodeAnalysis.SetsRequiredMembersAttribute` на конструкторе. пока атрибута нет, вызов `new Person("Bob")` остаётся ошибкой, хотя конструктор пишет в `Name`, а у `Age` уже стоит начальное значение 22. вызывающий код всё равно обязан пройти через инициализатор объекта.

```c#


Person bob = new Person("Bob"); // ошибка - свойства Name и Age все равно надо установить в инициализаторе



public class Person

{

    public Person(string name)

    {

        Name = name;

    }

    public required string Name { get; set; }

    public required int Age { get; set; } = 22;

}
```
