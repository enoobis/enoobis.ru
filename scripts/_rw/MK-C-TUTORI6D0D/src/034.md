**Storage class** или класс хранения — это модификатор, который определяет жизненный цикл и область видимости переменных и функций. Он сообщает компилятору, где и как хранить переменную, ее начальное значение по умолчанию и кто может к ней обращаться.



В Си существует четыре основных класса хранения:





- auto

- extern

- static

- register



В принципе в предыдущих статьях мы уже частично рассматривали эти классы хранения. Теперь суммируем/обобщим их использование.




Класс хранения auto является классом по умолчанию для всех локальных переменных. Это означает, что если вы объявляете переменную внутри функции или блока без указания класса хранения, она автоматически принимает тип хранения auto . Основные характеристики класса:





- Область видимости : действие переменной ограничена блоком, в котором она объявлена (локальная видимость).

- Жизненный цикл : переменная создается при входе в блок и уничтожается при выходе из него.

- Начальное значение : если переменная не инициализирована явно, то она содержит "мусорное" неопределенное значение.



Пример:



```c

void myFunction() {
  int a; // То же самое, что и "auto int a;""
  a = 10;
  // a доступна только внутри myFunction
}
```



Поскольку auto используется по умолчанию для локальных переменных, его редко указывают в коде явно.



## extern



Ключевое слово extern (от англ. "external" — внешний) используется для **объявления** глобальной переменной или функции, которая **определена** в другом файле. Это позволяет использовать одну и ту же глобальную переменную в нескольких исходных файлах. Основные характеристики:





- Область видимости : глобальная (доступна во всем проекте).

- Жизненный цикл : существует в течение всего времени выполнения программы.

- Начальное значение : определяется в месте ее инициализации. Если глобальная переменная не инициализирована явно, она получает значение 0.



Пример. Файл **file1.c** (Определение переменной):



```c

#include <stdio.h>

int globalVar = 100; // Определение и инициализация

void printGlobal() {
    printf("globalVar из file1.c: %d\n", globalVar);
}
```



Файл **file2.c** (Использование внешней переменной):



```c

#include <stdio.h>

extern int globalVar; // Объявление, что переменная определена где-то еще

void displayGlobal() {
    printf("globalVar из file2.c: %d\n", globalVar);
}

int main() {
    displayGlobal();
    // printGlobal(); // Предупреждение или ошибка
    return 0;
}
```



При компиляции этих двух файлов extern сообщает file2.c , что `globalVar` существует и будет доступна на этапе компоновки (linking). Компиляция:



```bash

eugene@Eugene:/workspace/c$ gcc file1.c file2.c -o app && ./app
globalVar из file2.c: 100
```



Возьмем закомментрированную строку



```c
// printGlobal(); // Предупреждение или ошибка
```



В примере выше функция `printGlobal()` определена в файле file1.c , однако в файле file2.c не объявлена с помощью extern . Если мы расскомментируем эту строку, то в зависимости от компилятора мы можем столкнуться либо с предупреждением (как в случае с GCC):



```bash

eugene@Eugene:/workspace/c$ gcc file1.c file2.c -o app && ./app
file2.c: In function ‘main’:
file2.c:11:5: warning: implicit declaration of function ‘printGlobal’ [-Wimplicit-function-declaration]
   11 |     printGlobal(); // Ошибка компиляции, если не объявлена
      |     ^~~~~~~~~~~
globalVar из file2.c: 100
globalVar из file1.c: 100
```



Либо с ошибкой (как в случае с Clang):



```bash

eugene@Eugene:/workspace/c$ clang file1.c file2.c -o app && ./app
file2.c:11:5: error: call to undeclared function 'printGlobal'; ISO C99 and later do not support implicit function declarations [-Wimplicit-function-declaration]
   11 |     printGlobal(); // Ошибка компиляции, если не объявлена
      |     ^
1 error generated.
```




## static




Ключевое слово static имеет два основных применения в зависимости от контекста: для локальных переменных и для глобальных переменных/функций.



### Локальные static-переменные



Когда static применяется к локальной переменной, он изменяет ее жизненный цикл, сохраняя ее значение между вызовами функции. Основные характеристики:





- Область видимости : Локальная, как у `auto` переменных.

- Жизненный цикл : Существует в течение всего времени выполнения программы, а не только внутри функции.

- Начальное значение : Инициализируется только один раз при первом вызове функции. Если не инициализирована явно, получает значение 0.



```c

#include <stdio.h>

void counter() {
    static int count = 0; // Инициализируется только один раз
    count++;
    printf("Count: %d\n", count);
}

int main() {
    counter(); // Count: 1
    counter(); // Count: 2
    counter(); // Count: 3
    return 0;
}
```



### Глобальные переменные и функции со static



Когда static применяется к глобальной переменной или функции, он ограничивает их **область видимости текущим файлом**. Это означает, что к такой переменной или функции нельзя будет обратиться из другого файла с помощью `extern`. В этом случае действуют следующие характеристики:





- Область видимости : действие переменной/функции ограничено файлом, в котором они объявлены.

- Жизненный цикл : переменная/функция существует в течение всего времени выполнения программы.



Пример, пусть у нас есть файл file1.c :



```c

// Файл file1.c
static int secret = 42; // Доступна только в file1.c

static void secretFunction() { // Доступна только в file1.c
    // ...
}
```



Такая инкапсуляция полезна для сокрытия деталей реализации модуля.



## register



Класс хранения register является рекомендацией для компилятора поместить переменную не в оперативную память, а в регистр процессора. Доступ к регистрам значительно быстрее, чем к памяти, поэтому это может оптимизировать производительность. Однако в современных компиляторах register почти не используется, так как они самостоятельно выполняют очень сложную оптимизацию и часто лучше программиста решают, какие переменные стоит помещать в регистры.



Пример применения:



```c

void fastLoop() {
    register int i; // Просьба к компилятору использовать регистр для i
    for (i = 0; i < 1000000; i++) {
        // ... какая-то быстрая операция
    }
}
```




Основные характеристики этого класса хранения:





- Область видимости : Локальная.

- Жизненный цикл : Локальный.

- К `register` -переменной нельзя применить оператор взятия адреса `&` , так как у нее нет адреса в памяти.

```c

#include <stdio.h>

int main() {

    register int i = 0; // Просьба к компилятору использовать регистр для i
    printf("i addr: %p\n", &i);   // здесь будет ошибка
    return 0;
}
```



- Компилятор может проигнорировать это указание, если нет свободных регистров или если тип данных не подходит для хранения в регистре.
