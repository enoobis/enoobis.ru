Для создания многопоточных приложений, которые выполняют некоторые действия параллельно, в языке Си обычно используются потоки `pthreads`, но это не единственный способ добиться параллелизма в C. Для этой цели мы также можем использовать библиотеку OpenMP .



Для применения OpenMP нам не нужно включать какие-либо файлы заголовков (если мы сами не используем функции OpenMP). Вместо этого применяютчя прагмы (директивы `pragma`). Сначала посмотрим на небольшом примере:



```c

#include <unistd.h<
#include <stdio.h>

int main(void)
{
  static const char str[] = "Hello enoobis.ru\n";

  // Используются все доступные процессоры
  #pragma omp parallel
  write(STDOUT_FILENO, str, sizeof str - 1);
}
```



Разберем этот код. Сначала определяется строка, которую, для примера мы будем выводить на консоль:



```c
static const char str[] = "Hello enoobis.ru\n";
```



Далее используем прагму:



```c
#pragma omp parallel
```



Эта директива создает параллельную область — каждый поток исполняет одну и ту же инструкцию, расположенную сразу после директивы.



Далее идет низкоуровневый системный вызов для вывода ранее опредеденной строки в стандартный вывод (stdout).



```c
write(STDOUT_FILENO, str, sizeof str - 1)
```



Запустим код на выполнение, например, с помощью компилятора GCC (предполагается, что код расположен в файле app.c ):



```bash

eugene@Eugene:/workspace/c$ gcc -fopenmp app.c -o app && ./app
Hello enoobis.ru
Hello enoobis.ru
Hello enoobis.ru
Hello enoobis.ru
..................
Hello enoobis.ru
eugene@Eugene:/workspace/c$
```



При использовании компиляторов GCC или Clang, нужно явно указать флаг -fopenmp .



При выполнении создаётся несколько потоков (обычно столько, сколько ядер у процессора). Каждый поток одновременно вызывает функцию `write` и выводит строку "Hello enoobis.ru\n" на консоль. Таким образом, в результате на экране появится несколько строк, выведенных параллельно.



Сразу отмечу важную деталь, что для вывод на консоль здесь применяется не стандартный `printf`, а прямой вызов в системный буфер вывода через `write`. Поскольку write — небуферизованный, он работает атомарно на уровне системных вызовов (в отличие от printf), поэтому каждая строка скорее всего будет выведена полностью, без перемешивания символов. Если бы использовался `printf`, вывод мог бы перемешиваться, потому что `printf` использует буферизацию и не потокобезопасен.




### Директивы OpenMP



При работе с OpenMP применяется ряд директив. Отмечу некоторые из них:



```c

#pragma omp parallel
#pragma omp simd
#pragma omp for
```



При использовании директив OpenMP после `#pragma` сначала идет omp , а затем собственно указывается директива OpenMP:





- `#pragma omp parallel` Эта директива создает параллельную область: несколько потоков начинают выполнение кода внутри этой области. Каждый поток исполняет одну и ту же копию кода.


- `#pragma omp simd` Эта директива указывает компилятору векторизовать (SIMD — Single Instruction, Multiple Data) следующий цикл: выполнять одну инструкцию одновременно над множеством данных, используя векторные инструкции CPU (например, SSE/AVX).


- `#pragma omp for` Обозначает, что итерации следующего за директивой цикла должны быть распределены между потоками. Обычно используется внутри parallel.




Директивы можно сочетать, например, `parallel` и `for`:



```c
#pragma omp parallel for
```




Рассмотрим некоторые сценарии применения директив OpenMP



### Параллельная обработка циклов



Директива for предназначена для использования с `parallel` и используется для разветвления текущего потока на дополнительные N-1 потоков, где N — это количество итераций цикла. Правда, если N больше количества логических процессоров, то N будет соответствовать этому значению, и тогда у нас будет M групп по N потоков в последовательности, где M — это количество итераций, деленное на максимальное количество потоков. Например:



```c

#include <stdio.h>

int main( void )
{
  int i;

  // Используем 8 процессоров (создаст 7 новых потоков + основной)
  #pragma omp parallel for
  for ( i = 0; i < 8; i++ )
    printf( "%d\n", i );
}
```



Директива OpenMP `parallel for` делит итерации цикла for между несколькими потоками. Каждый поток получает свое значение счетчика i в диапазоне от 0 до 7. OpenMP по умолчанию использует число потоков, равное количеству логических ядер, либо значение, заданное в OMP_NUM_THREADS. ПРимер консольного вывода:



```bash

eugene@Eugene:/workspace/c$ gcc -fopenmp app.c -o app && ./app
1
3
2
4
7
5
0
6
eugene@Eugene:/workspace/c$
```



Обратите внимание, что порядок, в котором потоки выполняются, не гарантируется. Если нужен правильный порядок, необходимо использовать директиву ordered :



```c

#include <stdio.h>

int main( void )
{
  int i;

  // упорядоченный вывод
  #pragma omp parallel for ordered
  for (i = 0; i < 8; i++ )
    #pragma omp ordered
    printf( "%d\n", i );
}
```



С помощью первой директивы `#pragma` мы сообщаем OpenMP, что цикл for распараллелен и внутри блока цикла есть выражения (в данном случае вызов функции `printf()`), которые должны быть выполнены по порядку. А чтобы указать, какие выражение должны быть упорядочены, к ним применяется второая дилектива `#pragma` - `#pragma omp ordered`. Это подразумевает, что вполне возможно иметь выражения внутри блока цикла, которые выполняются не по порядку, а другие — по порядку.



```bash

eugene@Eugene:/workspace/c$ gcc -fopenmp app.c -o app && ./app
0
1
2
3
4
5
6
7
```






### Векторизация и SIMD



Директива `#pragma omp simd` применяется для векторизации цикла. Она указывает компилятору векторизовать цикл, используя SIMD-инструкции процессора (например, AVX, SSE). Она **не создает потоки**, как `#pragma omp parallel`, а применяет одну инструкцию к множеству данных одновременно. Например, применим эту директиву для операции сложения массивов:



```c

#include <stdio.h>
#include <omp.h>

int main(void)
{
    const int N = 8;
    float a[N], b[N], c[N];

    // Инициализация
    for (int i = 0; i < N; i++) {
        a[i] = i;
        b[i] = i * 2;
    }

    // Векторизуемый цикл сложения
    #pragma omp simd
    for (int i = 0; i < N; i++) {
        c[i] = a[i] + b[i];
    }

    // Вывод результата
    for (int i = 0; i < N; i++) {
        printf("c[%d] = %.1f\n", i, c[i]);
    }

    return 0;
}
```



Для компиляции применяется флаг -O2 или выше, чтобы компилятор действительно применил векторизацию:



```bash

eugene@Eugene:/workspace/c$ gcc -O2 -fopenmp app.c -o app && ./app
c[0] = 0.0
c[1] = 3.0
c[2] = 6.0
c[3] = 9.0
c[4] = 12.0
c[5] = 15.0
c[6] = 18.0
c[7] = 21.0
eugene@Eugene:/workspace/c$
```




Вобщем, директива `omp simd` применяется, когда есть простые циклы над массивами (арифметика, копирование и т.п.), либо когда надо ускорить код за счёт векторизации, без параллельных потоков.




### Функции OpenMP



Если нам надо использовать какие-то специфические функции OpenMP, то необходимо подключить заголовочный файл omp.h . Например, используем встроенную функцию omp_get_thread_num() , которая возвращает номер текущего потока:



```c

#include <stdio.h>
#include <omp.h>

int main( void )
{
  #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        printf("Thread %d: Hello\n", tid);
    }
}
```

### Критическая секция



При паралельном выполнении следует помнить, что некоторые стандартные функции, как, например, функции вывода `printf()` или `puts()` **не потокобезопасны**. Так, `printf/puts` используют буферизацию, и их вызовы не синхронизируются между потоками по умолчанию. Это может привести к перемешиванию вывода, поврежденным строкам (например, "HeHlellollo") или даже потере части вывода в редких случаях.



Чтобы решить эту проблемиу мы можем применить еще одну директиву - `#pragma omp critical`. Она используется для **синхронизации потоков** и гарантирует, что **только один поток заходит в критическую секцию в каждый момент времени**:



```c

#pragma omp critical
{
    // Этот блок выполняется ОДНИМ потоком за раз
}
```



Использование этой директивы позволяет **предотвратить одновременный доступ** к общим ресурсам, таким как файлы, переменные, буферы вывода (printf, puts) и т.п.



Пример - конкурентный доступ к `puts`:



```c

#include <stdio.h>

int main(void)
{
    const char str[] = "Hello";
    #pragma omp parallel for
    for (int i = 0; i < 8; i++) {
        #pragma omp critical
        {
            puts(str);
        }
    }
    return 0;
}
```



Без директивы `critical` вызовы `puts()` из разных потоков могут перемешиваться, т.к. stdout не потокобезопасен.



С `critical` потоки выводят по очереди. `puts()` выполняется атомарно (одним потоком за раз).



При всех плюсах есть и минусы: это замедляет производительность, если использовать слишком часто - потоки начинают ждать друг друга. Поэтому лучше сужать критическую секцию до минимально необходимого кода.
