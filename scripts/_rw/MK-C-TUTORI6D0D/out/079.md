в зависимости от архитектуры размер базовых типов, таких как `int` или `long`, может меняться. например, для типа **int** стандартом языка си устанавливается минимальный размер в 2 байта (16 бит), а для типа **long** : минимальный размер в 4 байта (32 бита). на большинстве современных архитектур **int** занимает 4 байта, но тем не менее это не обязательное требование. стандарт фиксирует только нижние границы и отношения `sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)`, а также что `char` не меньше 8 бит. конкретную ширину выбирает abi платформы. возьмём следующую простейшую программу:

```c


#include <stdio.h>



int main(void)

{

    printf("sizeof(long) = %zu \n", sizeof(long));

     

    return 0;

}
```

даже если взять только 64-разрядные системы, окажется, что на windows long занимает 4 байта, тогда как на linux : 8 байт.

для описания применяемых размеров в языке си используется специальный набор характеристик, который называют **модель данных** или **data model**. существует множество моделей данных, ниже перечислены распространённые:

- LP32 : модель 2/4/4 (int : 2 байта, long и указатели по 4 байта). применяется для 32-разрядных систем в win16 api

- ILP32 : модель 4/4/4 (int, long и указатели по 4 байта). применяется для 32-разрядных систем в win32 api, unix и unix-подобных системах (linux, macos)

- LLP64 : модель 4/4/8 (int и long по 4 байта, указатель : 8 байт). применяется для 64-разрядных систем arm (aarch64) и x86-64 (x64) в win32 api (также называемом windows api), то есть в современном windows

- LP64 : модель 4/8/8 (int : 4 байта, long и указатели по 8 байт). применяется для 64-разрядных unix и unix-подобных систем (linux, macos), то есть в современных linux и macos

буквы в имени модели: l для `long`, p для указателя, i для `int`; цифра 64 означает 64 бита у соответствующих типов. различие lp64 и llp64 как раз в ширине `long`: код, хранящий указатель в `unsigned long`, переносим на linux и ломается на windows x64, где указатель шире `long`.

размеры в битах для разных типов в соответствии с выше перечисленными моделями:

| тип данных | стандарт c | LP32 | ILP32 | LLP64 | LP64 |
| --- | --- | --- | --- | --- | --- |
| char/unsigned char | как минимум 8 | 8 | 8 | 8 | 8 |
| short/unsigned short int | как минимум 16 | 16 | 16 | 16 | 16 |
| int / unsigned int | как минимум 16 | 16 | 32 | 32 | 32 |
| long/unsigned long | как минимум 32 | 32 | 32 | 32 | 64 |
| long long/unsigned long long | как минимум 64 | 64 | 64 | 64 | 64 |

чтобы уйти от платформенной зависимости, начиная со стандарта c99 в язык была добавлена поддержка платформо-независимых числовых типов. они определены в заголовочном файле **stdint.h** и имеют названия по следующему шаблону `uint|int[размер]_t`. в качестве размера указывается количество бит : 8, 16, 32 или 64:

- int8_t

- int16_t

- int32_t

- int64_t

- intptr_t (для хранения указателей)

беззнаковые типы предваряются приставкой **u**

- uint8_t

- uint16_t

- uint32_t

- uint64_t

- uintptr_t (для хранения указателей)

типы точной ширины `intN_t` / `uintN_t` необязательны: реализация предоставляет их, только если есть целочисленный тип без заполнения (padding) ровно в N бит. обязательны типы наименьшей достаточной ширины `int_leastN_t` и «быстрые» `int_fastN_t`. `intptr_t` / `uintptr_t` тоже необязательны; они способны хранить значение указателя на объект, преобразованное в целое, с обратным преобразованием без потери.

пример применения:

```c


#include <stdio.h>

#include <stdint.h>





int main(void)

{

    int8_t i8 = -8;

    uint8_t u8 = 8;



    int16_t i16 = -16;

    uint16_t u16 = 16;



    int32_t i32 = -32;

    uint32_t u32 = 32;



    int64_t i64 = -64;

    uint64_t u64 = 64;





    printf("i8 = %d \n", i8);

    printf("u8 = %u \n", u8);



    printf("i16 = %d \n", i16);

    printf("u16 = %u \n", u16);



    printf("i32 = %d \n", i32);

    printf("u32 = %u \n", u32);



    printf("i64 = %lld \n", i64);

    printf("u64 = %llu \n", u64);

     

    return 0;

}
```

в примере выше для вывода на консоль применяются стандартные встроенные спецификаторы типа `%d` или `%lld`. однако специально для этих типов в заголовочном файле **inttypes.h** также определены дополнительные макросы:

- PRI для форматированного вывода (с помощью printf, fprintf и т.д.)

- SCN для форматированного ввода (scanf, fscanf и т.д.).

вместе с этими макросами применяются спецификаторы типов:

- d : для вывода чисел в десятичном формате

- x : в шестнадцатеричном формате

- o : в восьмеричном формате

- u : для беззнаковых чисел

- i : для целых чисел со знаком

макросы раскрываются в строковые литералы (`"lld"`, `"I64d"` и т.п. в зависимости от модели данных), поэтому их склеивают с соседними литералами на этапе трансляции: `"%" PRIi64 "\n"`. так формат остаётся согласованным с фактической шириной типа. **inttypes.h** включает **stdint.h**, отдельный `#include <stdint.h>` при их использовании не обязателен.

применение

```c


#include <stdio.h>

#include <inttypes.h>





int main(void)

{

    int64_t int64;

    uint64_t uint64;



    printf("Enter signed number: ");

    scanf("%"SCNi64, &int64);



    printf("Enter unsigned number: ");

    scanf("%"SCNu64, &uint64);



    printf("int64 = %" PRIi64 "\n", int64);

    printf("uint64 = %" PRIu64 "\n", uint64);

     

    return 0;

}
```

пример ввода:

```bash


Enter signed number: -34

Enter unsigned number: 56

int64 = -34

uint64 = 56
```

стандартные операции, например арифметика, производятся так же, как и со встроенными типами:

```c


#include <stdio.h>

#include <inttypes.h>





int main(void)

{

    int64_t a = 5;

    int64_t b = 6;



    int64_t c = a + b * a;  // c = 35

    printf("c = %" PRIi64 "\n", c);

     

    return 0;

}
```

переполнение знакового `int64_t` по-прежнему даёт неопределённое поведение: фиксированная ширина не меняет правила обычной целочисленной арифметики си. для беззнаковых типов арифметика выполняется по модулю 2^N.
