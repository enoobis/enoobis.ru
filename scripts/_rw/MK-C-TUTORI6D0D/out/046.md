различные архитектуры, операционные системы и компиляторы могут определять ряд макросов, которые используются для определения особенностей окружения. с помощью предопределённых макросов компилируют отдельные части программы только под linux или только под windows, узнают, какой компилятор применяется, и так далее. такие макросы задаёт реализация, а не стандарт языка: набор и точные значения зависят от конкретной цепочки компиляции.

### предопределённые макросы версии компилятора

| компилятор | макрос |
| --- | --- |
| borland | __BORLANDC__ |
| clang | __clang__ |
| codeplay vectorc | __VECTORC__ |
| digital mars | __DMC__ |
| gnu | __GNUC__ |
| intel legacy "classic" | __INTEL_COMPILER |
| intel llvm based | __INTEL_LLVM_COMPILER |
| microsoft | _MSC_VER |
| pathscale | __PATHSCALE__ |
| symantec | __SYMANTECC__ |
| watcom | __WATCOMC__ |

например, выясним, какой компилятор применяется для компиляции программы:

```c
#include <stdio.h>

int main(void){

#ifdef __clang__
    puts("Clang compiler");
#elif __GNUC__
    puts("GCC compiler");
#else
    puts("Undefined compiler");
#endif

    return 0;
}
```

в функции main с помощью выражения

```c
#ifdef __clang__
```

проверяем, применяется ли компилятор clang. если он применяется, то компилируется строка `puts("Clang compiler");`. clang ради совместимости часто определяет также `__GNUC__`, поэтому проверку clang ставят раньше gnu.

с помощью второго выражения

```c
#elif __GNUC__
```

проверяем, что компилятор gcc. если применяется компилятор gcc, то компилируется строка кода `puts("GCC compiler")`.

далее с помощью выражения `#else` задаётся код, который компилируется, если компилятор не clang и не gcc.

не все компиляторы имеют хорошо документированные макросы, которые сообщают текущую аппаратную платформу и операционную систему. следующие макросы могут быть определены или не определены: переносимый код обязан предусматривать ветвь `#else`.

#### макросы архитектур

| архитектура | макрос |
| --- | --- |
| x86 | _M_IX86, __INTEL__, __i386__ |
| x86-64 | _M_X64, __x86_64__, __amd64 |
| IA64 | __IA64__ |
| dec alpha | __ALPHA__ |
| motorola power pc | __POWERPC__ |

применение макросов

```c
#include <stdio.h>

int main(void){

#ifdef __x86_64__
    puts("Intel x86 64bit");
#elif __i386__
    puts("Intel x86 32bit");
#else
    puts("Undefined hardware");
#endif

    return 0;
}
```

здесь определяется разрядность системы на платформе intel. `__x86_64__` соответствует 64-разрядному режиму, `__i386__` 32-разрядному. на microsoft visual c для тех же целей обычно смотрят `_M_X64` и `_M_IX86`.

#### порядок байтов

для определения порядка байтов (endianness, индианность) в общем случае можно применять следующие макросы:

| архитектура | макрос |
| --- | --- |
| any little endian | __LITTLE_ENDIAN__ |
| any big endian | __BIG_ENDIAN__ |

```c
#include <stdio.h>

int main(void){

#ifdef __LITTLE_ENDIAN__
    puts("__LITTLE_ENDIAN__");
#elif __BIG_ENDIAN__
    puts("__BIG_ENDIAN__");
#else
    puts("Undefined order of bytes");
#endif

    return 0;
}
```

однако в gcc для определения порядка байтов применяется предопределённый макрос BYTE_ORDER, который сравнивается с двумя константами: LITTLE_ENDIAN и BIG_ENDIAN. little-endian хранит младший байт по меньшему адресу, big-endian наоборот. порядок байтов влияет на сериализацию целых чисел и на совместимость двоичных форматов между платформами.

```c
#include <stdio.h>

int main(void){

#if BYTE_ORDER == LITTLE_ENDIAN
    puts("__LITTLE_ENDIAN__ on GCC");
#elif BYTE_ORDER == BIG_ENDIAN
    puts("__BIG_ENDIAN__ on GCC");
#endif

    return 0;
}
```

данный код также будет работать и на clang, поскольку clang в этой части повторяет модель gcc.

#### макросы операционных систем

| операционная система | макрос |
| --- | --- |
| dos 16 bit | __MSDOS__, _MSDOS |
| windows 16 bit | _WIN16 |
| windows 32 bit | _WIN32, __WINDOWS__ |
| windows 64 bit | _WIN64, _WIN32 |
| cygwin | __CYGWIN__ |
| mingw | __MINGW32__, __MINGW64__ |
| linux 32 bit | __unix__, __linux__ |
| linux 64 bit | __unix__, __linux__, __LP64__, __amd64 |
| bsd | __unix__, __BSD__, __FREEBSD__ |
| mac os | __APPLE__, (__DARWIN__, __MACH__) |
| os/2 | __OS2__ |

`_WIN32` определён и в 64-разрядной windows, поэтому его недостаточно, чтобы отличить 32- и 64-разрядные сборки: для 64-разрядной дополнительно проверяют `_WIN64`.

пример применения:

```c
#include <stdio.h>

int main(void){

#ifdef __WINDOWS__
    puts("Windows");
#elif __APPLE__
    puts("Mac OS");
#elif __linux__
    puts("Linux");
#else
    puts("Undefined operation system");
#endif

    return 0;
}
```

порядок проверок здесь существенен: сначала windows, затем mac os, затем linux. ветвь `#else` покрывает остальные системы, для которых ни один из перечисленных макросов не задан.
