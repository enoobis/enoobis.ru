память программы на c организована вполне определённым образом: данные разных видов и код размещаются в отдельных сегментах адресного пространства процесса. каждый **сегмент** выполняет свою функцию и обладает собственными характеристиками, от которых зависит, как память распределяется, как к ней осуществляется доступ и как она управляется во время выполнения. строго говоря, стандарт c не описывает сегменты, он оперирует продолжительностью хранения объектов (автоматической, статической, выделенной), а приведённая ниже схема отражает типичную реализацию в распространённых операционных системах. сегментация памяти разбирается на примере следующей программы:

```c
#include <stdio.h>
double f(int[]);

int size = 3;

int main(void) {
    int x[3] = {1, 7, 3};
    double result = f(x);
    return 0;
}

double f(int list[]) {
    double q = 7.0;
    return q;
}
```

**сегмент стека** расположен в верхней части адресного пространства и растёт вниз по мере вызова функций и создания локальных переменных. в нём хранятся все **локальные переменные**, **параметры функций** и **адреса возврата**. каждый вызов функции порождает новый фрейм стека с её локальными данными.

в рассматриваемом примере стек содержит локальный массив x со значениями {1, 7, 3}, а также переменные result, f и q, существующие в области видимости соответствующих функций.

стек работает по дисциплине last-in-first-out (последним пришёл, первым ушёл) и автоматически выделяет и освобождает память при вызове функции и возврате из неё. во время выполнения main отводится место под массив x и переменную result, а функция f создаёт собственный фрейм стека с локальной переменной q, инициализированной значением 7.0.

выделение во фрейме сводится к смещению указателя стека, то есть выполняется за постоянное время, поэтому стек эффективен для временных данных, однако время жизни переменных в нём ограничено их областью видимости.

**сегмент динамической памяти** (heap) обеспечивает динамическое распределение памяти, хотя в этом простом примере не задействован. heap располагается между стеком и нижними сегментами, растёт вверх и позволяет программе запрашивать память во время выполнения с помощью функций malloc() и free().

**сегмент констант и глобальных переменных** хранит объекты, существующие на протяжении всего выполнения программы, например глобальную переменную size со значением 3. обычно сюда попадают инициализированные глобальные переменные, статические переменные и строковые литералы, которые должны быть доступны из нескольких функций или в течение всего времени жизни программы. в типичных реализациях инициализированные данные размещаются в секции .data, неинициализированные в .bss, а литералы и константы в секции только для чтения.

**сегмент кода** находится в нижней части адресного пространства и содержит скомпилированные машинные инструкции всех функций программы. как правило, он доступен только для чтения, что защищает программный код от случайного изменения во время выполнения.

функция f реализована тривиально и всегда возвращает 7.0 через локальную переменную q, тогда как main управляет ходом программы: инициализирует массив, вызывает f и сохраняет возвращённое значение.

такая организация памяти помещает данные каждого вида в сегмент, соответствующий их области видимости, времени жизни и характеру использования, что обеспечивает эффективность и безопасность выполнения программы.
