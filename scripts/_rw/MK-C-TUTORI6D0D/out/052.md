при работе со структурами необходимо представлять, как они располагаются в памяти во время выполнения. от этого зависит размер программы и обрабатываемых данных, а также ряд других аспектов. в частности, чтобы скомпилированный код мог взаимодействовать с другим кодом, использующим те же структуры (библиотеками, модулями, собранными другим компилятором, системными вызовами), структуры должны размещаться строго так, как предписывают соответствующие стандарты. для unix-подобных систем, в том числе для linux, размещение структур частично определено стандартом c и частично двоичным интерфейсом system v abi. сам стандарт c фиксирует лишь порядок полей и отсутствие отступа перед первым полем, а конкретные величины выравнивания и размеры типов задаёт abi платформы.

поля структуры располагаются в памяти в том же порядке, в каком они перечислены в объявлении структуры. первое поле имеет тот же адрес, что и структура в целом. каждое последующее поле размещается после предыдущего с учётом выравнивания.

выравнивание означает, что поле должно располагаться по адресу, кратному (делящемуся без остатка) величине выравнивания. для примитивных типов и указателей в system v abi выравнивание совпадает с размером типа. например, размер типа int составляет 4 байта, поэтому поле age должно находиться по адресу, кратному 4. размер типа char равен 1 байту, поэтому его выравнивание тоже равно 1 байту, и поле типа char может располагаться по любому адресу. размер типа long составляет 8 байт, поэтому его выравнивание равно 8 (это верно для модели lp64, принятой в linux и macos, тогда как в 64-разрядной windows long занимает 4 байта). указатели занимают 8 байт на 64-разрядных системах и 4 байта на 32-разрядных архитектурах, соответственно выравнивание указателей составляет 8 или 4 байта в зависимости от разрядности системы.

рассмотрим следующий пример.

```c


#include <stdio.h>



struct person {

    int age;

    char* name;

};



int main(void){



    struct person tom = {.age = 40, .name ="Tom"};

    // получаем размер структуры person

    printf("sizeof(struct person): %lu\n", sizeof(struct person));

    // получаем адрес переменной tom

    printf("tom address: %p\n", &tom);

    // получаем адрес поля age в переменной tom

    printf("age address: %p\n", &tom.age);

    // получаем адрес поля name в переменной tom

    printf("name address: %p\n", &tom.name);

    return 0;

}
```

здесь определена структура person, а в функции main определена переменная этой структуры tom. затем программа выводит размер структуры person, а также адреса самой переменной tom и её полей. для значения типа size_t, которое возвращает sizeof, строго говоря, предназначен спецификатор `%zu`, а `%lu` совпадает с ним лишь на платформах, где size_t определён как unsigned long. консольный вывод программы может выглядеть, например, так:

```bash


sizeof(struct person): 16

tom address: 0x7ffde016cdb0

age: 0x7ffde016cdb0

name address: 0x7ffde016cdb8
```

из вывода видно, что структура person занимает 16 байт. адрес первого поля age совпадает с адресом структуры, а поле name находится на 8 байт дальше поля age. схематически это можно изобразить так:

```


  Поле  |  age  |  отступ |  name  |

------------------------------------

  Байты |  0-3  |   4-7   |  8-15  |
```

первым идёт поле age. оно имеет тип int и поэтому занимает 4 байта. однако следующее поле name располагается не сразу после поля age, а после отступа (padding) в 4 байта. причина в том, что при размещении полей структуры учитывается их выравнивание: поле должно располагаться по адресу, кратному (делящемуся без остатка) величине его выравнивания. для примитивных типов и указателей выравнивание совпадает с размером типа. например, размер типа int составляет 4 байта, поэтому поле age должно находиться по адресу, кратному 4.

размер поля name, то есть размер указателя, составляет 8 байт на 64-разрядных системах и 4 байта на 32-разрядных архитектурах. поэтому поле name должно располагаться по адресу, кратному 8. в приведённом выше выводе сразу за полем age следует адрес 0x7ffde016cdb4, но он не кратен 8, поэтому добавляется необходимое смещение в 4 байта.

в итоге вся структура занимает 16 байт: размер поля age, отступ и размер поля name. содержимое байтов отступа не определено, поэтому сравнивать структуры побайтово через memcmp в общем случае некорректно.

### выравнивание структуры

как уже упоминалось, выравнивание примитивных типов и указателей совпадает с их размером. выравнивание самой структуры определяется так: согласно system v abi, структура получает выравнивание своего наиболее строго выровненного поля, а её размер должен быть кратен этому выравниванию. в примере выше наибольшее выравнивание у поля name, оно занимает 8 байт. следовательно, вся структура выравнивается по 8 байтам, и её размер должен быть кратен 8. требование кратности размера нужно для массивов: только при нём каждый следующий элемент массива структур окажется правильно выровненным. рассмотрим следующий пример:

```c


#include <stdio.h>



struct person {

    char* name;

    int age;

};



int main(void){



    struct person tom = {.age = 40, .name ="Tom"};

    // получаем размер структуры person

    printf("sizeof(struct person): %lu\n", sizeof(struct person));

    // получаем адрес переменной tom

    printf("tom address: %p\n", &tom);

    // получаем адрес поля name в переменной tom

    printf("name address: %p\n", &tom.name);

    // получаем адрес поля age в переменной tom

    printf("age address: %p\n", &tom.age);

    return 0;

}
```

в отличие от предыдущего примера, здесь поля name и age просто поменяны местами. можно было бы ожидать, что отступ между полями name и age исчезнет. действительно, адрес, следующий за полем name, кратен 8 и, следовательно, кратен 4, поэтому между полями name и age отступов нет. однако размер структуры person по-прежнему составляет 16 байт. консольный вывод может быть, например, таким:

```bash


sizeof(struct person): 16

tom address: 0x7ffd22dfd830

name address: 0x7ffd22dfd830

age address: 0x7ffd22dfd838
```

поскольку согласно abi размер структуры должен быть кратен выравниванию её наибольшего поля, структура person имеет выравнивание 8 и размер 16. совокупный размер полей name и age равен 12 байтам (8 байт поля name и 4 байта поля age), поэтому в конце структуры добавляется хвостовой отступ в 4 байта:

```


  Поле  |  name  |  age   |  отступ |

-------------------------------------

  Байты |  0 -7  |  8-11  |   12-15 |
```

### выравнивание массивов

если поле является массивом, для него используется выравнивание типа его элементов. например:

```c


#include <stdio.h>



struct example {

    char field1;

    int field2[2];

    char field3[5];

};



int main(void){



    struct example exmp;

    printf("sizeof(struct example): %lu\n", sizeof(struct example));

    printf("exmp address: %p\n", &exmp);



    printf("field1 (char) address: %p\n", &exmp.field1);

    printf("field2 (int[2]) address: %p\n", &exmp.field2);

    printf("field3 (char[5]) address: %p\n", &exmp.field3);

    return 0;

}
```

здесь определена структура example, которая имеет три поля:

- поле field1 имеет тип char, поэтому занимает 1 байт и имеет выравнивание 1

- поле field2 является массивом int[2], который занимает 8 байт. поскольку тип элементов массива int, его выравнивание равно 4

- поле field3 имеет тип char[5], занимает 5 байт и имеет выравнивание 1 (так как хранит элементы типа `char`), соответственно для него никаких отступов не требуется

адрес, следующий сразу за первым полем field1, не кратен 4, поэтому между полями field1 и field2 добавляется отступ в 3 байта.

кроме того, наибольшее выравнивание среди полей имеет field2, оно равно 4, поэтому вся структура в целом также имеет выравнивание 4, и её размер должен быть кратен 4. сумма размеров всех полей и отступа между field1 и field2 даёт:

```browser
1 (размер field1) + 3 (отступ между field1 и field1) + 8 (размер field2) + 5 (размер field3) = 17 байт
```

однако размер структуры должен быть кратен 4, поэтому в конец структуры добавляются ещё 3 байта, и вся структура в целом занимает 20 байт.

```


  Поле  | field1  |  отступ  |  field2  |  field3  |  отступ |

-----------------------------------------------------------

  Байты |    0    |   1-3    |   4-11   |   12-17  |  18-19  |
```

возможный консольный вывод:

```bash


sizeof(struct example): 20

exmp address: 0x7ffe27226560

field1 (char) address: 0x7ffe27226560

field2 (int[2]) address: 0x7ffe27226564

field3 (char[5]) address: 0x7ffe2722656c
```

### оптимизация расположения

знание того, как поля структуры располагаются в памяти, позволяет оптимизировать её и уменьшить размер. возьмём, например, следующую программу:

```c


#include <stdio.h>



struct person{

    int age;

    char* name;

    int salary;

};



int main(void){



    struct person tom = {.age = 40, .name = "Tom", .salary = 125};

    printf("sizeof(struct person): %lu\n", sizeof(struct person));



    printf("age address: %p\n", &tom.age);

    printf("name address: %p\n", &tom.name);

    printf("salary address: %p\n", &tom.salary);

    return 0;

}
```

здесь поля в структуре person располагаются следующим образом:

```


  Поле  |  age  |  отступ |  name  |  salary  |  отступ | 

---------------------------------------------------------

  Байты |  0-3  |   4-7   |  8-15  |  16-19   |  20-23  |
```

поле с наибольшим выравниванием здесь name, его выравнивание и размер равны 8. соответственно вся структура имеет выравнивание 8 и размер, кратный 8, то есть 24 байта. такое расположение не оптимально: в нём есть лишний отступ между полями age и name, а также отступ после поля salary, необходимый для обеспечения кратности размера структуры. компилятор c не вправе переставлять поля самостоятельно, поскольку порядок полей закреплён стандартом, поэтому оптимизация возлагается на программиста. поля можно переупорядочить следующим образом:

```c


#include <stdio.h>



struct person{

    char* name;

    int age;

    int salary;

};



int main(void){



    struct person tom = {.age = 40, .name = "Tom", .salary = 125};

    printf("sizeof(struct person): %lu\n", sizeof(struct person));



    printf("age address: %p\n", &tom.age);

    printf("name address: %p\n", &tom.name);

    printf("salary address: %p\n", &tom.salary);

    return 0;

}
```

теперь поле с наибольшим выравниванием располагается в самом начале, а поля размещаются так:

| поле | name | age | salary |
| --- | --- | --- | --- |
| байты | 0-7 | 8-11 | 12-15 |

```


  Поле  |  name  |  age   |  salary  |

--------------------------------------

  Байты |  0-7   |  8-11  |  12-15  |
```

в итоге общий размер структуры составит 16 байт.

распространённое правило упорядочивания полей структуры состоит в следующем: в начале располагаются поля с наибольшим выравниванием, а за ними поля с меньшим выравниванием. это позволяет экономнее распределять память и уменьшить размер структуры. при этом такая перестановка может ухудшить читаемость и локальность доступа к логически связанным полям, а для структур, входящих в публичный двоичный интерфейс, порядок полей изменять нельзя без нарушения совместимости.
