при использовании кириллицы возможна ситуация, когда вместо кириллических символов отображаются непонятные знаки. особенно это характерно для windows. причина в несовпадении кодировок: байты строки в исходном файле интерпретируются консолью по иной кодовой странице. в этом случае необходимо явно задать текущую локаль (культуру) для вывода символов. в c это делается функцией **setlocale()**, объявленной в заголовочном файле **locale.h**.

код из прошлых тем изменяется следующим образом:

```c
#include <stdio.h>

int main(void)
{
	printf("Привет мир! \n");
	return 0;
}
```

компиляция и запуск в windows могут выглядеть так:

```bash
c:\C>gcc hello.c -o hello & hello
╧ЁштхЄ ьшЁ!

c:\C>
```

вместо русских слов выводятся непонятные символы, что не соответствует ожиданиям. текст был сохранён в windows-1251, а консоль по умолчанию использует кодовую страницу 866, поэтому каждый байт отображается символом другой таблицы. теперь код изменяется с применением функции setlocale:

```c
#include <stdio.h>
#include <locale.h>

int main(void)
{
	char *locale = setlocale(LC_ALL, "");
	
	printf("Привет мир! \n");
	return 0;
}
```

поскольку функция setlocale объявлена в файле locale.h, он подключается директивой `#include `.

вызов `setlocale(LC_ALL, "")` устанавливает для всех категорий локали (LC_CTYPE, LC_NUMERIC, LC_TIME и др.) значения из окружения пользователя вместо локали "C", действующей при старте любой программы. функция возвращает строку с именем установленной локали или нулевой указатель в случае ошибки.

приложение повторно компилируется и запускается:

```bash
c:\C>gcc hello.c -o hello & hello
Привет мир!

c:\C>
```

в качестве кодировки текстового файла в этом случае должна использоваться ansi, то есть windows-1251, но не utf-8.

на некоторых платформах, например ubuntu или macos, такой проблемы может не возникнуть, поскольку и исходные файлы, и терминал там обычно работают в utf-8. в этом случае вызов функции setlocale на вывод никак не повлияет.
