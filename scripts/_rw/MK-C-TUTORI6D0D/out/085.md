**семафор** представляет разделяемую целочисленную переменную, которая ограничивает число потоков, одновременно имеющих доступ к некоторому коду или ресурсу. семафоры допускают к участку кода только заданное количество потоков. тем же примитивом один поток заставляют ждать, пока другой не выполнит определённое действие, и тем самым упорядочивают действия потоков. в отличие от мьютекса семафор не имеет владельца: увеличить счётчик может любой поток, не только тот, который его уменьшал. семантически это счётчик разрешений с атомарными операциями захвата и освобождения, восходящий к операциям p и v дейкстры.

в языке c основной функционал posix-семафоров объявлен в заголовочном файле **semaphore.h**. сам семафор представлен типом **sem_t**. для работы с семафорами предусмотрен ряд функций. основные из них:

- `int sem_init(sem_t *sem, int pshared, unsigned value)` : инициализирует семафор. параметры функции: `*sem` - указатель на инициализируемый семафор

- `pshared` - указывает, будет ли семафор общим для потоков или процессов. если равен 0, семафор общий для потоков одного процесса, при ненулевом значении семафор общий для процессов и должен размещаться в разделяемой памяти

- `value` - начальное значение семафора

при успешной инициализации функция возвращает 0, иначе возвращается -1.

- `int sem_destroy(sem_t *sem)` : удаляет семафор

- `int sem_wait(sem_t *sem)` : уменьшает (блокирует) семафор. если значение семафора больше нуля, выполняется уменьшение, и поток продолжает работу. если значение семафора равно нулю, поток блокируется до тех пор, пока уменьшение не станет возможным. проверка и изменение счётчика выполняются атомарно.

- `int sem_post(sem_t *sem)` : увеличивает (разблокирует) семафор. если значение семафора после этого становится больше нуля, другой поток, который ожидает получение семафора и заблокирован вызовом sem_wait(), проснётся и заблокирует семафор.

- `sem_destroy(sem_t *sem)` : удаляет семафор

применение семафоров на небольшом примере:

```c


#include <semaphore.h>

#include <pthread.h>

#include <stdio.h>

#include <unistd.h>



sem_t sem;              // семафор

int result1 = 0;

int result2 = 0;



// Функция Потока 1

void* thread1_work(void* args) 

{

    result1 = 1;        // условная работа потока - установка переменной

    puts("Thread1 works");

    sem_post(&sem);     // увеличиваем значение семафора

    return NULL;

}

// Функция Потока 2

void* thread2_work(void* args) 

{

    result2 = 2;        // условная работа потока - установка переменной

    puts("Thread2 works");

    sem_post(&sem);     // увеличиваем значение семафора

    return NULL;

}

// Функция Потока 3

void* thread3_work(void* arg) 

{

    puts("Thread3 waits");

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    printf("result1 = %d result2 = %d\n", result1, result2);

    return NULL;

}

int main(void) 

{

    sem_init(&sem, 0, 0);       // инициализируем семафор



    pthread_t thread1, thread2, thread3;

    pthread_create(&thread3, NULL, thread3_work, NULL);

    sleep(2);   // чтобы Поток 3 начал выполняться раньше

    pthread_create(&thread1, NULL, thread1_work, NULL);

    pthread_create(&thread2, NULL, thread2_work, NULL);



    sem_destroy(&sem);      // удаляем семафор

    

    pthread_join(thread1, NULL);

    pthread_join(thread2, NULL);

    pthread_join(thread3, NULL);



    return 0;

}
```

сначала программа запускается, её консольный вывод:

```bash


Thread3 waits

Thread1 does work

Thread2 does work

result1 = 1     result2 = 2
```

разбор программы. здесь семафор задаёт очередность действий потоков: третий поток читает результаты только после того, как первые два их записали. сначала определяется сам семафор:

```c
sem_t sem;      // семафор
```

для демонстрации определяются две глобальные переменные, значения которых вычисляются в двух потоках и которые по умолчанию равны 0:

```c


int result1 = 0;

int result2 = 0;
```

в функции main семафор инициализируется числом 0. нулевое начальное значение означает, что разрешений ещё нет, и любой `sem_wait` сразу блокирует вызывающий поток:

```c
sem_init(&sem, 0, 0);
```

далее запускаются три потока. поток thread3 запускается первым и выполняет функцию thread3_work:

```c


void* thread3_work(void* arg) 

{

    puts("Thread3 waits");

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    printf("result1 = %d \tresult2 = %d\n", result1, result2);

    return NULL;

}
```

поток thread3 вызывает `sem_wait()` и тем самым проверяет значение семафора: если оно больше 0, поток уменьшает значение семафора и продолжает работу. поскольку при инициализации семафору назначено число 0, данный поток начинает ждать, пока семафор не станет больше 0. поскольку `sem_wait()` вызывается два раза, во внешнем коде семафор надо увеличить дважды, чтобы поток thread3 перешёл к выводу на консоль переменных result1 и result2. два последовательных ожидания здесь эквивалентны барьеру «дождаться двух независимых событий», без требования, какой из потоков 1 и 2 завершится раньше.

после потока thread3 запускаются потоки thread1 и thread2, которые выполняют однотипные функции thread1_work и thread2_work соответственно. поток thread1:

```c


void* thread1_work(void* args) 

{

    result1 = 1;        // условная работа потока - установка переменной

    puts("Thread1 works");

    sem_post(&sem);     // увеличиваем значение семафора

    return NULL;

}
```

поток thread1 выполняет работу: устанавливает переменную result1 и затем функцией `sem_post()` увеличивает значение семафора. аналогично действует поток thread2, который устанавливает переменную result2 и увеличивает значение семафора.

только после того, как потоки thread1 и thread2 увеличат семафор по одному разу, поток thread3 сможет уменьшить это значение до 0 и перейти к выводу значений переменных result1 и result2 на консоль. в итоге сначала выполняются оба потока thread1 и thread2, и только потом thread3.

после завершения работы семафор удаляется:

```c
sem_destroy(&sem);
```

вызов `sem_destroy` освобождает ресурсы безымянного семафора. уничтожать семафор, на котором ещё ждут потоки, нельзя: поведение в этом случае не определено. в примере `sem_destroy` стоит до `pthread_join`, то есть формально до завершения потоков; корректный порядок: дождаться join, затем уничтожить семафор.

### упорядочивание действий потоков

ещё один пример. есть повар, который готовит еду, и человек, который её потребляет. чтобы поесть еду, её надо сначала приготовить. программа:

```c


#include <semaphore.h>

#include <pthread.h>

#include <stdio.h>

#include <unistd.h>



sem_t sem;              // семафор



// Функция Повара

void* cook(void* args) 

{

    puts("Breakfast is ready");  // повар готовит завтрак

    sem_post(&sem);     // увеличиваем значение семафора

    sleep(2);

    puts("Lunch is ready");  // повар готовит обед

    sem_post(&sem);     // увеличиваем значение семафора

    sleep(2);

    puts("Dinner is ready");  // повар готовит ужин

    sem_post(&sem);     // увеличиваем значение семафора

    return NULL;

} 

// Функция уничтожителя еды

void* eat(void* arg) 

{

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    puts("Having breakfast");  // едим завтрак

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    puts("Having lunch");  // едим обед

    sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

    puts("Having dinner");  // едим ужин

    

    return NULL;

}

int main(void) 

{

    sem_init(&sem, 0, 0);       // инициализируем семафор

    pthread_t chief, eater;

    pthread_create(&eater, NULL, eat, NULL);

    sleep(2);   // аппетит приходит вовремя, а еду опять задерживают на 2 секунды

    pthread_create(&chief, NULL, cook, NULL);



    sem_destroy(&sem);      // удаляем семафор

    

    pthread_join(chief, NULL);

    pthread_join(eater, NULL);



    return 0;

}
```

за повара отвечает поток chief, который запускает функцию cook. в этой функции повар последовательно готовит завтрак, обед и ужин, при этом увеличивая значение семафора. каждый `sem_post` публикует одно готовое блюдо как единицу ресурса:

```c


puts("Breakfast is ready");  // повар готовит завтрак

sem_post(&sem);     // увеличиваем значение семафора

sleep(2);

puts("Lunch is ready");  // повар готовит обед

sem_post(&sem);     // увеличиваем значение семафора

sleep(2);

puts("Dinner is ready");  // повар готовит ужин

sem_post(&sem);     // увеличиваем значение семафора
```

за потребителя еды отвечает поток eater, который запускает функцию eat. в этой функции вызовом sem_wait ожидается, когда семафор станет больше 0 (когда повар увеличит значение семафора), после чего значение уменьшается, что условно означает потребление пищи:

```c


sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

puts("Having breakfast");  // едим завтрак

sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

puts("Having lunch");  // едим обед

sem_wait(&sem);     // ожидаем, когда семафор станет больше 0 и уменьшаем его

puts("Having dinner");  // едим ужин
```

консольный вывод программы:

```bash


Breakfast is ready

Having breakfast

Lunch is ready

Having lunch

Dinner is ready

Having dinner
```

последовательность блюд сохраняется, потому что потребитель каждый раз ждёт очередного `sem_post`. если бы повар публиковал все три сигнала подряд без пауз, а потребитель был бы медленнее, семафор накопил бы счётчик, и несколько приёмов пищи могли бы пройти подряд: семафор помнит число сигналов, в отличие от условной переменной pthread, которая сигнал не хранит.

### ограничение количества потоков

распространённая функция семафоров: ограничение количества потоков, имеющих доступ к некоторому участку кода. в обоих примерах выше семафор по умолчанию не ограничивал число потоков, а служил счётчиком событий. теперь задача: есть некоторое число читателей, которые приходят в библиотеку два раза в день и что-то там читают. единовременно в библиотеке не может находиться больше трёх читателей. задачу решают семафором с ненулевым начальным значением, трактуемым как число свободных мест:

```c


#include <semaphore.h>

#include <pthread.h>

#include <stdio.h>

#include <unistd.h>



sem_t sem;              // семафор



void* read_books(void* arg)

{

    char* reader = (char*) arg; // идентификатор читателя

    int count = 2;// счетчик чтения

    while (count > 0)

    {

        sem_wait(&sem);  // ожидаем, когда освободиться место

 

        printf("%s enters the library \n", reader);



        printf("%s reads \n", reader);

        sleep(1);

 

        printf("%s leaves the library \n", reader);

 

        sem_post(&sem);  // освобождаем место

 

        count--;

        sleep(1);

    }

    return NULL;

}



int main(void) 

{

    sem_init(&sem, 0, 3);       // инициализируем семафор

    pthread_t readers[5];

    pthread_create(&readers[0], NULL, read_books, "Reader 1");

    pthread_create(&readers[1], NULL, read_books, "Reader 2");

    pthread_create(&readers[2], NULL, read_books, "Reader 3");

    pthread_create(&readers[3], NULL, read_books, "Reader 4");

    pthread_create(&readers[4], NULL, read_books, "Reader 5");



    sem_destroy(&sem);      // удаляем семафор

    

    pthread_exit(NULL); // ждем завершения всех потоков и завершаем текущий поток



    return 0;

}
```

при инициализации семафора начальное значение равно 3:

```c
sem_init(&sem, 0, 3);
```

одновременно доступ к коду могут иметь не более 3 потоков, иначе говоря в библиотеке одновременно могут находиться только 3 читателя. это классический counting semaphore: начальное значение задаёт ёмкость критического ресурса.

массив readers из 5 потоков представляет 5 читателей, больше ограничения семафора, числа 3. при запуске каждого потока выполняется функция read_books, в которую передаётся строковой идентификатор читателя в виде "ReaderN".

в начале функции read_books для ожидания получения семафора используется функция `sem_wait()`:

```c


void* read_books(void* arg)

{

    char* reader = (char*) arg; // идентификатор читателя

    int count = 2;// счетчик чтения

    while (count > 0)

    {

        sem_wait(&sem);  // ожидаем, когда освободиться место
```

после того как в семафоре освободится место (семафор станет больше 0), данный поток вычитает из семафора 1: читатель занимает свободное место и выполняет все дальнейшие действия.

```c


printf("%s enters the library \n", reader);



printf("%s reads \n", reader);

sleep(1);

 

printf("%s leaves the library \n", reader);
```

после окончания чтения семафор высвобождается функцией `sem_post` (значение семафора увеличивается: читатель покидает библиотеку):

```c
sem_post(&sem);  // освобождаем место
```

после этого в семафоре освобождается одно место, которое заполняет другой поток. пример консольного вывода:
