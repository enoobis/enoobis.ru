переменные, используемые в программе, могут быть не только глобальными, локальными или статическими, но также могут представлять внешние объекты. такие объекты определены в какой-то внешней единице трансляции, то есть в другом исходном файле. функции тоже могут быть внешними по отношению к другим функциям: их определения располагаются в других файлах. тогда возникает задача согласовать имена между единицами трансляции, чтобы линкер смог разрешить ссылки на объекты и функции, определённые вне текущего файла.

пусть в программе будут два файла: главный файл **app.c** и вспомогательный файл **main.c**.

![внешние объекты в языке программирования си](/uploads/course-lectures/ac6fcc41ca3ef80b606b4f7ab4ece9bd724c9cb6.png)

файл **main.c** содержит следующий код:

```c
#include <stdio.h>

char message[] = "Hello enoobis.ru";

void print()
{
    printf("Hello from extern function\n");
}
int sum(int x, int y)
{
    return x + y;
}
```

здесь определены одна переменная `message` и две функции: `print()` и `sum()`. определения находятся на уровне файла, поэтому соответствующие имена по умолчанию получают внешнее связывание (external linkage): линкер сможет сопоставить их с объявлениями в других единицах трансляции.

этот функционал используется в файле **app.c**, который представляет главный файл программы:

```c
#include <stdio.h>

extern char message[];		// переменная message из файла main.c
void print(void);			// функция print из main.c
int sum(int, int);			// функция sum из main.c

int main(void)
{
    // выводим на консоль внешнюю переменную message
    printf("%s \n", message);
    // вызываем внешнюю функцию print
    print();
    // вызываем другую внешнюю функцию - sum
    printf("4 + 5 = %d \n", sum(5, 4));
    return 0;
}
```

если переменная определена во внешнем файле, то перед её использованием должно идти её описание с ключевым словом **extern**. в файле **main.c** определена переменная `message`. чтобы к ней обращаться, в файл **app.c** помещается её описание с ключевым словом **extern**:

```c
extern char message[];
```

описание переменной в принципе совпадает с её определением, только при описании ей нельзя присваивать какое-либо значение. семантически `extern` без инициализатора есть объявление, а не определение: оно сообщает компилятору тип и связывание имени, но не резервирует память. определение, выделяющее объект, находится в **main.c**. правило одной определения (one definition rule) требует, чтобы определение существовало ровно в одной единице трансляции, а объявления могли повторяться.

если требуется использовать внешние функции, то перед их использованием надо задать их прототип. в файле **main.c** определены функции `print()` и `sum()`, поэтому в файле **app.c** перед вызовом этих функций помещается их прототип:

```c
void print(void);			// функция print из main.c
int sum(int, int);			// функция sum из main.c
```

для функций спецификатор `extern` подразумевается по умолчанию, поэтому прототип без `extern` всё равно описывает функцию с внешним связыванием. то же самое касается использования любых других переменных и функций, которые определены во внешних файлах.

при компиляции через gcc компилятору надо последовательно через пробел передать имена файлов:

```consoletext
gcc app.c main.c -o app.exe
```

здесь файлы **app.c** и **main.c** будут компилироваться в один файл **app.exe**. фактически gcc сначала транслирует каждый исходник в объектный файл, после чего линкер объединяет их и разрешает внешние ссылки: обращение к `message`, `print` и `sum` из **app.c** связывается с определениями из **main.c**.

в некоторых средах разработки (например, в visual studio) среда разработки автоматически скомпилирует оба файла в одну программу, если оба входят в один проект.

### статические объекты

по умолчанию любая глобальная переменная, константа или функция из одного файла доступна в другом файле при совместной компиляции, как в примере выше. иногда возникает необходимость, наоборот, скрыть переменную или функцию, чтобы внешние файлы не могли их использовать. в этом случае к подобным переменным и функциям применяют спецификатор **static**, задавая им внутреннее связывание (internal linkage). например, определим следующий файл **main.c**:

```c
#include <stdio.h>

static char message[] = "Hello enoobis.ru";

static void print()
{
    printf("%s\n", message);
}
void hello()
{
    print();
}
```

теперь ни переменная `message`, ни функция `print()` не доступны из внешних файлов, потому что они определены как статические: их имена видны только внутри данной единицы трансляции. функция `hello()` сохраняет внешнее связывание, и только её можно использовать в других файлах, например в файле **app.c**:

```c
#include <stdio.h>

//extern char message[];	-  переменная message из файла main.c недоступна
// void print(void);		- функция print из main.c недоступна
void hello(void);			// функция hello из main.c доступна

int main(void)
{
    // вызываем другую внешнюю функцию - hello
    hello();
    return 0;
}
```

попытка объявить `message` как `extern` или вызвать `print` из **app.c** приведёт к ошибке линковки: символов с внешним связыванием для этих имён нет. функция `hello` остаётся единственной точкой входа во внутреннее состояние файла **main.c**. такое разделение соответствует сокрытию реализации: статическая функция `print` и статическая переменная `message` образуют закрытый интерфейс единицы трансляции, а `hello` экспортирует его наружу.
