потоки нередко обращаются к разделяемым ресурсам, общим для всей программы: глобальным переменным, файлам, другим объектам процесса. для разграничения доступа к таким ресурсам применяются **мьютексы** (**mutex**, сокращение от "mutual exclusion", взаимное исключение). мьютекс представляет объект с двумя состояниями: заблокированным и разблокированным. в c при использовании библиотеки posix threads мьютекс представлен типом **pthread_mutex_t**.



переход мьютекса из одного состояния в другое выполняют две функции:




- pthread_mutex_lock() : переводит мьютекс из разблокированного состояния в заблокированное. если мьютекс уже заблокирован, поток, запросивший его, приостанавливается до тех пор, пока владеющий поток не освободит (не разблокирует) мьютекс.

- pthread_mutex_unlock() : переводит мьютекс из заблокированного состояния в разблокированное, после чего мьютекс может быть захвачен другими потоками.



общая схема работы с мьютексом такова. поток, которому нужен общий ресурс, захватывает мьютекс вызовом **pthread_mutex_lock()**, остальные потоки, претендующие на тот же мьютекс, в это время ожидают. закончив работу с ресурсом, поток-владелец освобождает мьютекс вызовом **pthread_mutex_unlock()**. с этого момента мьютекс, а вместе с ним и защищаемый ресурс, свободен, пока его не захватит другой поток. участок кода между захватом и освобождением называют критической секцией: мьютекс гарантирует, что в каждый момент времени внутри неё находится не более одного потока.



сначала рассмотрим проблему, которая возникает при работе с общими ресурсами в многопоточном приложении без синхронизации. возьмём следующую программу:



```c


#include <pthread.h>

#include <stdio.h>

#include <unistd.h>



int value = 0;  // общий ресурс





void* do_work(void* thread_id)

{

    value = 1;

    int id = *(int*)thread_id;     // получаем id потока

    for (int n = 0; n < 5; n++) 

    {

        printf("Thread %d: %d\n", id, value );

        value += 1;

        sleep(1);

    }

    return NULL;

}

int main(void) 

{

    pthread_t t1, t2;       // два потока для демонстрации

    int t1_id = 1, t2_id = 2;  // идентификаторы потоков

    pthread_create(&t1, NULL, do_work, &t1_id);

    pthread_create(&t2, NULL, do_work, &t2_id);



    pthread_join(t1, NULL);

    pthread_join(t2, NULL);

    

    return 0;

}
```



здесь запускаются два потока, оба вызывают функцию do_work и работают с общей переменной value. чтобы различать потоки, в do_work передаётся числовой идентификатор потока. ожидаемое поведение: каждый поток выводит значения value от 1 до 5. на деле планировщик переключает потоки произвольно, и значение value становится непредсказуемым. с точки зрения модели памяти c11 одновременный неатомарный доступ к одной переменной из разных потоков, хотя бы один из которых пишет, является гонкой данных (data race) и ведёт к неопределённому поведению. один из возможных вариантов консольного вывода (от запуска к запуску он различается):

изменим программу, применив мьютекс:



```c


#include <pthread.h>

#include <stdio.h>

#include <unistd.h>



int value = 0;  // общий ресурс



pthread_mutex_t m; // мьютекс для разграничения доступа



void* do_work(void* thread_id)

{

    int id = *(int*)thread_id;

    pthread_mutex_lock( &m );   // поток блокирует мьютекс

    value = 1;                  // начало работы с обшим ресурсом

    for (int n = 0; n < 5; n++) 

    {

        printf("Thread %d: %d\n", id, value );

        value += 1;

        sleep(1);

    }

    pthread_mutex_unlock( &m );     // поток освобождает мьютекс

    return NULL;

}

int main(void) 

{

    pthread_t t1, t2;

    int t1_id = 1, t2_id = 2; 

    pthread_mutex_init(&m, NULL); //  инициализация мьютекса

    pthread_create(&t1, NULL, do_work, &t1_id);

    pthread_create(&t2, NULL, do_work, &t2_id);



    pthread_join(t1, NULL);

    pthread_join(t2, NULL);

    

    pthread_mutex_destroy(&m);  // удаление мьютекса

    return 0;

}
```



программа совпадает с предыдущей, за исключением мьютекса. сам мьютекс объявлен как глобальная переменная, видимая обоим потокам:



```c
pthread_mutex_t m;
```



в функции main мьютекс инициализируется функцией **pthread_mutex_init()**. первый параметр: адрес мьютекса, второй: указатель на атрибуты. здесь атрибуты по умолчанию устраивают, поэтому передаётся NULL. для статически размещённого мьютекса допустима и инициализация макросом `PTHREAD_MUTEX_INITIALIZER`:



```c
pthread_mutex_init(&m, NULL);
```



каждый поток по-прежнему выполняет do_work, но теперь участок кода, где используется общий ресурс, переменная value, защищён мьютексом:



```c


void* do_work(void* thread_id)

{

    int id = *(int*)thread_id;

    pthread_mutex_lock(&m);   // поток блокирует мьютекс

    

    // критическая секция - работа с ресурсом value



    pthread_mutex_unlock(&m);     // поток освобождает мьютекс

    return NULL;

}
```



один из потоков первым захватывает мьютекс вызовом `pthread_mutex_lock(&m)` и начинает работать с переменной value. второй поток в это время блокируется в ожидании освобождения мьютекса.



закончив работу, первый поток вызывает `pthread_mutex_unlock(&m)` и освобождает мьютекс. тогда второй поток захватывает его и получает доступ к value. помимо взаимного исключения, пара lock и unlock задаёт отношение синхронизации: все записи, сделанные потоком до unlock, гарантированно видны потоку, который затем выполнит lock того же мьютекса.



когда мьютекс больше не нужен, он уничтожается функцией **pthread_mutex_destroy()**. уничтожать допустимо только разблокированный мьютекс, которого не ожидает ни один поток:



```c
pthread_mutex_destroy(&m);  // удаление мьютекса
```

### взаимоблокировка



механизм мьютексов прост, однако неаккуратное использование нескольких мьютексов приводит к взаимоблокировке (deadlock). рассмотрим следующую ситуацию:



```c


pthread_mutex_t A;

pthread_mutex_t B;

void* thread1(void* arg)

{

    pthread_mutex_lock(&A);

    pthread_mutex_lock(&B);

    // ........................

    pthread_mutex_unlock(&B);

    pthread_mutex_unlock(&A);

    return NULL;

}



void* thread2(void* arg)

{

    pthread_mutex_lock(&B);

    pthread_mutex_lock(&A);

    // ........................

    pthread_mutex_unlock(&A);

    pthread_mutex_unlock(&B);

    return NULL;

}
```



пусть первый поток выполняет функцию thread1, а второй поток функцию thread2. тогда возможна взаимоблокировка: первый поток захватил мьютекс A и для продолжения ждёт мьютекс B, а второй поток захватил B и ждёт A. ни один из них не может продвинуться, поскольку образовался цикл ожидания. чтобы исключить такую ситуацию, во всех потоках мьютексы следует захватывать в одном и том же глобальном порядке и освобождать в обратном: при фиксированном порядке захвата цикл ожидания возникнуть не может.
