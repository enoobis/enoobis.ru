одна из типичных задач при разработке программ состоит в безопасной обработке ошибок. ряд современных языков программирования (например, rust) предоставляет специальные типы результата, значение которых представляет либо успешное завершение операции вместе с её результатом, либо ошибку. это так называемый шаблон result, предполагающий явную обработку ошибок. операция возвращает единственный объект result, который находится в одном из двух состояний: ok (успех) или error (сбой). с точки зрения теории типов result есть тип-сумма (размеченное объединение), и шаблон вынуждает разработчика явно проверять, какой из вариантов получен, благодаря чему поток выполнения и потенциальные точки отказа становятся явными, а число ошибок времени выполнения сокращается. объект result обычно инкапсулирует результат, если операция выполнена успешно, или подробную информацию об ошибке (например, код и описание), если операция завершилась неудачей. такой подход делает код более предсказуемым и тестируемым.



в c нет ни параметрического полиморфизма, ни алгебраических типов данных, однако подобный механизм несложно реализовать средствами препроцессора. рассмотрим следующие макросы:



```c

typedef enum {OK=1, ERR=0} result_type;

#define DEFINE_RESULT(T) \
typedef struct { \
    result_type type;\
    T* data; \
} Result_##T;\
\
Result_##T Ok_##T(T* data) { \
    Result_##T v = { .data = data, .type = OK}; \
    return v; \
}; \
\
Result_##T Err_##T() { \
    Result_##T v = { .data = 0, .type = ERR};\
    return v; \
};

#define RESULT(T)  Result_##T
#define Ok(T)  Ok_##T
#define Err(T)  Err_##T
```



вначале определяется перечисление `result_type`, задающее вид результата. вариантов два: успех или ошибка (OK или ERR). поле этого типа играет роль дискриминанта (тега) размеченного объединения.



затем определяется макрос `DEFINE_RESULT(T)`, который разворачивается в структуру с именем `Result_##T`. структура содержит вид результата (поле `type`) и указатель data на сами данные, то есть макрос `DEFINE_RESULT(T)` создаёт "обёртку" над данными типа T. оператор `##` соединяет два фрагмента текста в один идентификатор на этапе препроцессирования: встретив `Result_##T`, препроцессор подставляет вместо `T` аргумент макроса и удаляет `##`.



например, при вызове `DEFINE_RESULT(Person)` параметр `T` равен Person, а `Result_##T` превращается в `Result_Person`. если же `T` есть `int`, получится `Result_int`.



в итоге компилятор c видит уникальное имя структуры или функции, хотя шаблон определён в макросе лишь один раз. по сути это ручная мономорфизация: для каждого типа порождается отдельная копия кода, подобно тому как это делают шаблоны c++ или обобщения rust, только без проверки шаблона до подстановки.



далее определены вспомогательные функции `Ok_T` и `Err_T`, создающие соответственно успешный или ошибочный результат. благодаря им функция возвращает не просто "указатель или NULL", а явный статус операции вместе с данными.



есть нюанс: если передать в такой макрос тип из нескольких лексем (например, `unsigned int`) или тип-указатель, компиляция завершится ошибкой, так как идентификатор `Result_unsigned int` недопустим (содержит пробел). в таких случаях сначала вводят псевдоним через `typedef`. кроме того, поскольку `DEFINE_RESULT` порождает определения функций с внешним связыванием, его нельзя вызывать для одного типа в нескольких единицах трансляции без конфликта символов при компоновке; на практике функции объявляют `static inline`.




рассмотрим применение этих макросов на примере:



```c

#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <assert.h>

typedef enum {OK=1, ERR=0} result_type;
#define DEFINE_RESULT(T) \
typedef struct { \
    result_type type;\
    T* data; \
} Result_##T;\
\
Result_##T Ok_##T(T* data) { \
    Result_##T v = { .data = data, .type = OK}; \
    return v; \
}; \
\
Result_##T Err_##T() { \
    Result_##T v = { .data = 0, .type = ERR};\
    return v; \
};

#define RESULT(T)  Result_##T
#define Ok(T)  Ok_##T
#define Err(T)  Err_##T


typedef struct{
    char* name;
    unsigned age;
} Person;


DEFINE_RESULT(Person)

// создание Person
RESULT(Person) Person_new(char* person_name, unsigned person_age) {
    // если нереальный возраст
    if(person_age > 110) {
        printf("Error: invalide age `%u`\n", person_age);
        return Err(Person)();
    }
    // если пустое имя 
    if(!person_name){
        puts("Error: name is NULL");
        return Err(Person)();
    }

    Person* p = malloc(sizeof(*p));

    if(!p){
        printf("Unable to locate a memory for a Person\n");
        return Err(Person)();
    }
    p->name = strdup(person_name);
    if(!p->name){
        printf("Unable to locate a memory for a Person name\n");
        return Err(Person)();
    }
    p->age = person_age;

    return Ok(Person)(p);
}
// удаляем объект Person
void Person_delete(Person* p){
    if(!p) return;
    if(p->name) free(p->name);
    free(p);
}
// тестируем успешное создание объекта Person
void test_create_person_ok(){

    // Arrange
    char* name = "Tom";
    unsigned age = 22;

    // Act
    RESULT(Person) result = Person_new(name, age);

    // Assert
    assert((result.type ==OK) && "Unable to create person");
    assert((result.data !=0) && "Null result after creating person");
    // проверяем результат
    Person* p = result.data;
    assert((!strcmp(p->name, name) && "Invalid person name"));
    assert((p->age == age) && "Invalid person age");

    puts("test_create_person_ok() PASSED!");

    if(p) Person_delete(p);
}

// тестируем некорректное имя
void test_create_person_failed_name(){

    // Arrange
    char* name = NULL;
    unsigned age = 22;

    // Act
    RESULT(Person) result = Person_new(name, age);

    // Assert
    assert((result.type ==ERR) && "test_create_person_failed_name() FAILED");

    puts("test_create_person_failed_name() PASSED!");
}

// тестируем некорректный возраст
void test_create_person_failed_age(){

    // Arrange
    char* name = "Tom";
    unsigned age = 122;

    // Act
    RESULT(Person) result = Person_new(name, age);

    // Assert
    assert((result.type ==ERR) && "test_create_person_failed_age() FAILED");

    puts("test_create_person_failed_age() PASSED!");
}

int main(void){

    test_create_person_ok();
    test_create_person_failed_age();
    test_create_person_failed_name();
    return 0;
}
```



для проверки макросов здесь определена структура Person, хранящая имя (динамически выделенную строку) и возраст.



при вызове `DEFINE_RESULT(Person)` препроцессор порождает:



```c

typedef struct {
    result_type type;
    Person* data;
} Result_Person; // Склеилось в одно слово
```



то же самое происходит с функциями:





- `Ok_##T` становится `Ok_Person`

- `Err_##T` становится `Err_Person`



для создания экземпляра структуры определена функция `Person_new()`, своего рода конструктор с валидацией. если возраст больше 110 или имя отсутствует, возвращается `Err(Person)`:



```c

// если нереальный возраст
if(person_age > 110) {
    printf("Error: invalide age `%u`\n", person_age);
    return Err(Person)();
}
// если пустое имя 
if(!person_name){
    puts("Error: name is NULL");
    return Err(Person)();
}
```



в случае успеха выделяется память под структуру и копируется строка (strdup). функция `strdup` долгое время входила только в posix и включена в стандарт c лишь начиная с c23. в итоге возвращается созданный объект:



```c

return Ok(Person)(p);
```



заметим, что в ветке, где `strdup` возвращает NULL, ранее выделенная под `p` память не освобождается, что приводит к утечке; в корректной реализации перед возвратом ошибки следует вызвать `free(p)`.



функция `Person_delete()` выполняет роль деструктора и освобождает память в порядке, обратном выделению: сначала имя, затем саму структуру.



в функции `main` запускаются три теста на основе стандартного макроса `assert`, который проверяет условие во время выполнения и отключается при определении `NDEBUG`:




- `test_create_person_ok` : проверяет создание корректного объекта.

- `test_create_person_failed_name` : проверяет реакцию на NULL вместо имени.

- `test_create_person_failed_age` : проверяет валидацию возраста (граница 110 лет).



при запуске программы отработают все три теста, и программа выведет:



```bash

test_create_person_ok() PASSED!
Error: invalide age `122`
test_create_person_failed_age() PASSED!
Error: name is NULL
test_create_person_failed_name() PASSED!
```
