если в арифметической операции участвуют значения разных типов, компилятор неявно приводит их к общему типу. кроме того, при присваивании значение всегда преобразуется к типу переменной, в которую оно записывается. например:

```c
char c = 6;
int d = c;
```

переменная d имеет тип int, а присваиваемое ей значение имеет тип char, поэтому компилятор выполняет преобразование значения из типа char в тип int.

при этом преобразования не всегда безопасны: разные типы имеют разное внутреннее представление и разный диапазон значений, и переход от одного представления к другому без потери точности возможен далеко не всегда.

при арифметических операциях компилятор применяет следующие правила преобразования (стандарт называет их обычными арифметическими преобразованиями):

- если один из операндов имеет тип long double , второй операнд тоже преобразуется в тип long double

- если предыдущее условие не выполняется и один из операндов имеет тип double , второй операнд тоже преобразуется к типу double

- если предыдущее условие не выполняется и один из операндов имеет тип float , второй операнд тоже преобразуется к типу float

- если предыдущее условие не выполняется и один из операндов имеет тип unsigned long int , второй операнд тоже преобразуется к типу unsigned long int

- если предыдущее условие не выполняется и один из операндов имеет тип long , второй операнд тоже преобразуется к типу long

- если предыдущее условие не выполняется и один из операндов имеет тип unsigned , второй операнд тоже преобразуется к типу unsigned

- если ни одно из предыдущих условий не выполняется, оба операнда приводятся к типу int

этот перечень представляет упрощённую картину. в действующем стандарте целочисленная часть правил сформулирована через ранг преобразования типов: сначала к обоим операндам применяется целочисленное повышение (char, short и битовые поля превращаются в int или unsigned int), затем операнд меньшего ранга приводится к типу операнда большего ранга, а при смешении знакового и беззнакового типов одного ранга результат становится беззнаковым. отсюда известный эффект: выражение -1 < 0u ложно, поскольку -1 преобразуется в очень большое беззнаковое значение.

например:

```c
int a = 10;
#include <stdio.h>
 
int main(void)
{
    int number1 = 10;
    double number2 = 4;
    double result = number1 + number2;   // 14.000000
    printf("result = %f \n", result);     // result = 14.000000
    return 0;
}
```

в выражении `number1 + number2` операнд `number2` имеет тип **double**, поэтому значение `number1` автоматически преобразуется к double. результат операции сложения также имеет тип **double**.

### операция преобразования

специальная операция преобразования (приведение типа, cast) позволяет явно привести значение к нужному типу. например:

```c
int a = 10;
int b = 4;
int c = a / b;                     // 2
double d = a / b;				// 2.00000
double e = (double)a / (double)b;	// 2.50000
printf("c = %d \n", c);
printf("d = %f \n", d);
printf("e = %f \n", e);
```

в выражении `int c = a / b;` результатом деления будет целое число 2: оба операнда целые, поэтому выполняется целочисленное деление и дробная часть отбрасывается.

в выражении `double d = a / b;` переменная получает вещественное значение 2.00000, однако оба операнда деления по-прежнему целые, поэтому результатом самой операции снова будет целое число 2. только после выполнения деления происходит присваивание результата переменной d с преобразованием значения 2 из типа int в тип double. тип выражения в c определяется его операндами и не зависит от контекста, в который результат затем записывается.

в выражении `double e = (double)a / (double)b` операнды явно приводятся к типу double, поэтому и результат деления является вещественным числом 2.50000. для получения того же эффекта достаточно привести один операнд, второй будет преобразован неявно по правилам выше.

в операции приведения в круглых скобках указывается тип, к которому требуется привести значение:

```c
int number = 70;
char symbol = (char) number;
printf("symbol = %c \n", symbol);			//	F
printf("symbol (int code) = %d \n", symbol);	// 70
```

в ряде случаев преобразование сопровождается потерей информации, например когда значение типа большей разрядности (скажем, размером 4 байта) записывается в тип меньшей разрядности (например, 2 байта). без потери информации выполняются следующие цепочки преобразований:

**char -> short -> int -> long**

**unsigned char -> unsigned short -> unsigned int -> unsigned long**

**float -> double -> long double**

все остальные преобразования, не входящие в эти цепочки, могут приводить к потере точности. так, в примере выше преобразование из int в char небезопасно, и к подобным преобразованиям следует относиться с осторожностью. например:

```c
#include <stdio.h>
 
int main(void)
{
    
    int number1 = 300;
    char code = number1;    // потеря точности - число number1 усекается до 1 байта
    printf("code = %d \n", code);     // code = 44
    return 0;

    short number2 = 100000;    // потеря точности - число 100000 усекается до 2 байт
    printf("number2 = %d \n", number2);     // number2 = -31072

}
```

здесь показаны две ситуации небезопасного преобразования. в первом случае число 300 типа `int` присваивается переменной типа `char`, и в итоге переменная `code` оказывается равна 44. причина видна из двоичной записи числа 300:

```c
0000000100101100
```

сохраняется только младший байт:

```c
00101100
```

что в десятичной системе даёт число 44.

во втором случае число 100000, которое по умолчанию имеет тип `int`, усекается до разрядности типа `short`, то есть до двух байт.

```c
short number = 100000;
```

в итоге переменная `number` фактически получает значение -31072. для беззнаковых типов такое поведение гарантировано стандартом (результат берётся по модулю 2 в степени n), тогда как результат преобразования значения, не помещающегося в знаковый целевой тип, определяется реализацией. на распространённых платформах с дополнительным кодом он сводится к отбрасыванию старших байтов, что и дает показанные значения.
