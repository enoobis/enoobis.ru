битовые поля дают доступ к отдельным битам данных. они позволяют формировать объекты, длина которых не кратна байту, и за счёт этого плотнее размещать данные, экономя память. взятие адреса битового поля запрещено: у поля нет самостоятельного объекта в смысле оператора `&`.

битовое поле не существует само по себе. оно может быть только элементом структуры или объединения. в рамках структуры битовые поля имеют следующую форму определений:

```c
struct имя_структуры
{
	тип1 имя_поля1 : ширина_поля1;
	тип2 имя_поля2 : ширина_поля2;
	//..............
	типi имя_поляi : ширина_поляi;
}
```

в качестве типа поля в классической формулировке используется **int**, допустимы модификаторы signed и unsigned. стандарт c99 дополнительно разрешает `_Bool`; реализации часто принимают и другие целочисленные типы, однако это уже расширение конкретной реализации. имя_поля представляет произвольный идентификатор, а ширина_поля: положительное целое число, которое не должно превышать ширину выбранного типа и на практике ограничено длиной машинного слова платформы (машинное слово измеряется в битах или байтах и совпадает с разрядностью регистров процессора; для 64-разрядной архитектуры длина равна 64 битам). соседние битовые поля обычно упаковываются в одну единицу размещения, пока суммарная ширина не превышает её размер; нулевая ширина безымянного поля принудительно начинает новую единицу. порядок битов внутри единицы размещения зависит от реализации.

ниже определяется структура с битовыми полями:

```c
struct point
{
	unsigned int x:5;	// 0-31
	unsigned int y:3;	// 0-7
};
```

структура point содержит два битовых поля. первое поле `x` имеет ширину 5 бит, то есть принимает значения от 0 до 31. второе поле `y` имеет ширину 3 бита и принимает значения от 0 до 7.

далее со структурой и её элементами работают так же, как с любой структурой:

```c
#include <stdio.h>

struct point
{
	unsigned int x:5;	// 0-31
	unsigned int y:3;	// 0-7
};

int main(void)
{
	struct point center = {0, 5};
	center.x = 2;
	printf("x=%d	y=%d \n", center.x, center.y);	// x=2	y=5
	
	return 0;
}
```

в зависимости от платформы расположение полей структуры в памяти может отличаться. в частности, на windows порядок такой: поля в начале структуры имеют младшие адреса, поля в конце структуры имеют старшие адреса. если взять из примера выше поля x и y структуры point с итоговыми значениями x=2 и y=5, на windows получается следующее размещение битов в памяти:

![битовые поля в языке программирования си](/uploads/course-lectures/38ea40e6be0d5e081c2957eeea2cd9bda38063f2.png)

поля x и y вместе занимают 8 бит, поэтому на рисунке 8 ячеек. биты изображены слева направо от старших к младшим. на трёх левых битах размещено поле point.y: значение 5 в двоичной системе есть 101. на следующих 5 битах помещается поле point.x со значением 2 (10 в двоичной системе). такое расположение согласуется с типичной для msvc упаковкой: первое объявленное поле занимает младшие биты единицы размещения, а на рисунке младшие биты находятся справа.

размещение полей в памяти можно выяснить программно. для этого используются объединения:

```c
#include <stdio.h>

struct point
{
	unsigned int x:5;	// 0-31
	unsigned int y:3;	// 0-7
};

union code
{
	struct point p;
	struct{
		unsigned a0:1;
		unsigned a1:1;
		unsigned a2:1;
		unsigned a3:1;
		unsigned a4:1;
		unsigned a5:1;
		unsigned a6:1;
		unsigned a7:1;
	} byte;
};


int main(void)
{
	struct point center = {2, 5};
	union code c;
	c.p = center;
	printf("7 \t 6 \t 5 \t 4 \t 3 \t 2 \t 1 \t 0 \n");
	printf("%d \t %d \t %d \t %d \t %d \t %d \t %d \t %d \n", 
			c.byte.a7, c.byte.a6, c.byte.a5, c.byte.a4, 
			c.byte.a3, c.byte.a2, c.byte.a1, c.byte.a0);
	return 0;
}
```

объединение code содержит два элемента: структуру point и безымянную структуру byte. элементы объединения занимают одну и ту же область в памяти, точнее начинаются с одного и того же адреса. чтобы выяснить, какие биты заняты, безымянная структура byte имеет 8 полей, каждое шириной 1 бит. запись в `c.p` и последующее чтение `c.byte` переинтерпретирует те же биты побитово.

при запуске программы размещение значений в памяти видно непосредственно:

```consoletext
7	6	5	4	3	2	1	0
1	0	1	0	0	0	1	0
```
