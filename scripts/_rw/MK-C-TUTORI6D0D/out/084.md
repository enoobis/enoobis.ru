условные переменные позволяют дополнить синхронизацию потоков ожиданием некоторого условия. такие переменные имеют тип **pthread_cond_t** и всегда используются совместно с мьютексом. принцип условной синхронизации следующий. один поток активен, остальные находятся в состоянии ожидания и ждут выполнения некоторого условия. в определённый момент активный поток посылает сигнал, его получает ожидающий поток и возобновляет выполнение. сама условная переменная не хранит никакого значения: она служит только очередью ожидающих потоков, а условие задаётся отдельными данными, защищёнными мьютексом.

для отправки и ожидания сигнала применяются две функции:

- pthread_cond_signal() : отправляет сигнал через условную переменную

- pthread_cond_wait() : переводит поток в состояние ожидания до получения сигнала через условную переменную

обе функции следует вызывать только внутри участка кода между захватом и освобождением одного и того же мьютекса. кроме того, сигнал, отправленный через `pthread_cond_signal()` до того, как другой поток вызвал `pthread_cond_wait()`, теряется: условная переменная не запоминает сигналов, и такой порядок вызовов является ошибкой, способной привести к зависанию программы.

применение условных переменных рассмотрим на примере следующей программы:

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

pthread_cond_t condvar = PTHREAD_COND_INITIALIZER;  // условная переменная
pthread_mutex_t mutex;      // мьютекс

// функция первого потока
void* thread1_work(void* arg) 
{
    pthread_mutex_lock(&mutex);             // Поток 1 блокирует мьютекс
    puts("Thread1 starts and waits for signal");

    pthread_cond_wait(&condvar, &mutex);    // Поток 1 ожидает сигнала

    puts("Thread1 received a signal");
    pthread_mutex_unlock(&mutex);         // Поток 1 освобождает мьютекс
    return NULL;
}
// функция второго потока
void* thread2_work(void* arg) 
{
    pthread_mutex_lock(&mutex);                 // Поток 2 блокирует мьютекс
    puts("Thread2 starts and does some work"); // Поток 2 выполняет условную работу
    puts("Thread2 is sending a signal");

    pthread_cond_signal(&condvar);      // ПОток 2 посылает сигнал
    puts("Thread2 sent a signal");
    pthread_mutex_unlock( &mutex );         // Поток 2 освобождает мьютекс
    return NULL;
}
int main(void) 
{
    pthread_t thread1, thread2;
    pthread_mutex_init(&mutex, NULL);

    pthread_create(&thread1, NULL, thread1_work, NULL);
    sleep(2);   // ждем, чтобы Поток 1 гарантировано начал выполняться первым
    pthread_create(&thread2, NULL, thread2_work, NULL);

    pthread_join(thread1, NULL);
    pthread_join(thread2, NULL);

    pthread_mutex_destroy(&mutex);
    return 0;
}
```

программа выводит на консоль следующее:

```bash
eugene@Eugene:~/Documents/enoobis$ ./main
Thread1 starts and waits for signal
Thread2 starts and does some work
Thread2 is sending a signal
Thread2 sent a signal
Thread1 received a signal
eugene@Eugene:~/Documents/enoobis$
```

разберём программу. среди глобальных переменных определена условная переменная:

```c
pthread_cond_t condvar = PTHREAD_COND_INITIALIZER;  // условная переменная
```

перед использованием условную переменную необходимо инициализировать. это делается двумя способами: присваиванием встроенного макроса `PTHREAD_COND_INITIALIZER` либо вызовом функции **pthread_cond_init()**. в примере выше применён первый способ, он подходит для переменных со статическим временем жизни. второй способ выглядел бы так:

```c
pthread_cond_t condvar;
....................
// в функции main
pthread_cond_init(&condvar, NULL);  // второй параметр - атрибуты условной переменной
```

в программе участвуют два потока. первый выполняет функцию thread1_work, второй функцию thread2_work. первый поток захватывает мьютекс mutex, затем вызывает `pthread_cond_wait()` и начинает ожидать сигнал, передаваемый через условную переменную condvar. функция pthread_cond_wait принимает также адрес захваченного ранее мьютекса:

```c
void* thread1_work(void* arg) 
{
    pthread_mutex_lock(&mutex);             // Поток 1 блокирует мьютекс
    puts("Thread1 starts and waits for signal");

    pthread_cond_wait(&condvar, &mutex);    // Поток 1 ожидает сигнала
```

в результате первый поток переходит в состояние ожидания сигнала, а мьютекс mutex **разблокируется**. освобождение мьютекса и постановка потока в очередь ожидания выполняются атомарно, поэтому между ними другой поток не может вклиниться и отправить сигнал, который был бы потерян. получив сигнал, первый поток автоматически снова захватывает мьютекс и продолжает выполнение с оператора, следующего за вызовом pthread_cond_wait.

второй поток захватывает тот же мьютекс mutex, выполняет некоторую работу (здесь только выводит строку на консоль) и отправляет сигнал через condvar функцией **pthread_cond_signal()**:

```c
void* thread2_work(void* arg) 
{
    pthread_mutex_lock(&mutex);             // Поток 2 блокирует мьютекс
    puts("Thread2 starts and does some work"); // Поток 2 выполняет условную работу
    puts("Thread2 is sending a signal");

    pthread_cond_signal(&condvar);      // ПОток 2 посылает сигнал
```

отправка сигнала разблокирует как минимум один из потоков, ожидающих на условной переменной condvar (здесь это первый поток). чтобы разбудить все ожидающие потоки, используется функция pthread_cond_broadcast(). при этом проснувшийся поток фактически продолжит работу лишь после того, как второй поток освободит мьютекс.

так один поток сигнализирует другому о завершении некоторой работы, и тот продолжает выполнение.

стандарт posix допускает ложные пробуждения (spurious wakeups): поток может выйти из pthread_cond_wait, не получив сигнала. поэтому условие проверяется через дополнительную разделяемую переменную, причём в цикле:

```c
int signal_sent = 0;   // условие - общий ресурс

// функция первого потока
void* thread1_work(void* arg) 
{
    pthread_mutex_lock(&mutex); 
    puts("Thread1 starts and waits for signal");

    
    while (!signal_sent)       // пока не будет удовлетворять условие
    { 
        pthread_cond_wait(&condvar, &mutex);    // Поток 1 ожидает сигнала
    }
    // pthread_cond_wait(&condvar, &mutex);
    puts("Thread1 received a signal");
    pthread_mutex_unlock(&mutex); 
    return NULL;
}
// функция второго потока
void* thread2_work(void* arg) 
{
    pthread_mutex_lock(&mutex); 
    puts("Thread2 starts and does some work");
    puts("Thread2 is sending a signal");
    signal_sent = 1;                           // Поток 2 изменяет общую переменную

    pthread_cond_signal(&condvar); 
    puts("Thread2 sent a signal");
    pthread_mutex_unlock( &mutex ); 
    return NULL;
}
```

первый поток дополнительно проверяет значение общей переменной signal_sent:

```c
while (!signal_sent)  { ....... }
```

даже если первый поток проснётся без сигнала, проверка значения signal_sent заставит его снова перейти к ожиданию. второй поток перед отправкой сигнала устанавливает эту переменную. такой цикл решает и проблему потерянного сигнала: если второй поток успеет выставить signal_sent и отправить сигнал раньше, чем первый поток дойдёт до ожидания, первый поток увидит выполненное условие и вовсе не станет вызывать pthread_cond_wait.
