### параметры компилятора gcc

по умолчанию при компиляции выводится лишь ограниченный набор предупреждений. между тем предупреждения компилятора указывают на потенциальные проблемы в коде, даже если он успешно компилируется. простейший пример: в программе определена переменная, которая нигде не используется. компилятор может сообщить о такой ситуации, что позволяет разработчику сразу выявить и устранить проблему. предупреждения отражают результаты статического анализа, который компилятор и так выполняет в ходе семантической проверки и оптимизации, поэтому их включение почти ничего не стоит.

для компиляции с предупреждениями применяется флаг `-Wall`:

```bash
gcc -Wall source.c
```

название флага обманчиво: `-Wall` включает не все предупреждения, а широкий набор наиболее полезных. дополнительные проверки включаются, например, флагом `-Wextra`.

существуют разные версии стандарта языка c, и каждая может добавлять возможности, которые потребуются в программе. флагом **-std=** указывается конкретный стандарт: `c99`, `c11` или `c17`. например, для компиляции по стандарту `c99`:

```bash
gcc -std=c99 source.c
```

аналогично для компиляции по стандарту `c11` используется команда:

```bash
gcc -std=c11 source.c
```

без флага `-std` gcc использует собственный диалект с расширениями gnu (например, `gnu17` в gcc 8-14 и `gnu23` начиная с gcc 15), а не строгий iso c.

чтобы гарантировать строгое соответствие программы определённому стандарту, указывается флаг `-pedantic`

```bash
gcc -std=c99 -Wall -pedantic source.c
gcc -std=c11 -Wall -pedantic source.c
gcc -std=c17 -Wall -pedantic source.c
gcc -std=c23 -Wall -pedantic source.c
```

в этом случае компилятор выдаёт предупреждения, если код не соответствует правилам стандарта. флаг `-pedantic-errors` превращает такие предупреждения в ошибки компиляции.

для автоматического запуска приложения сразу после компиляции можно использовать следующую команду:

```bash
gcc source.c & ./a.out
```

различные опции можно объединить в одной команде:

```bash
gcc -std=c17 -Wall -pedantic app.c -o app.exe & app
```

опция **-S** позволяет сгенерировать файл с ассемблерным кодом:

```bash
gcc app.c -S
```

по содержимому app.c будет сгенерирован файл с тем же именем, что и исходный, но с расширением `.s`, то есть app.s. он содержит код на ассемблере в синтаксисе ассемблера gas (ассемблера gnu), для x86 по умолчанию это синтаксис at&t. компиляция останавливается после этапа генерации кода, ассемблирование и компоновка не выполняются. анализ такого вывода полезен для изучения того, как конструкции языка отображаются на машинные инструкции и как на это влияют уровни оптимизации `-O1`, `-O2` и т.д.

### параметры компилятора clang

основные параметры компилятора clang во многом повторяют параметры gcc, поскольку clang проектировался как совместимая по интерфейсу командной строки замена gcc. например, компиляция с помощью clang по определённому стандарту с выводом предупреждений:

```bash
clang -std=c17 -Wall -pedantic app.c -o app.exe & app.exe
```
