как было показано ранее, строка в c представляет собой последовательность символов, завершённую нулевым символом '\0'. отдельного строкового типа в языке нет, и строку можно представить в виде массива:



```c


char hello[] = "Hello";
```



здесь из символов строки формируется массив из 6 элементов типа char. эквивалентная запись:



```c


 char hello[] = {'H', 'e', 'l', 'l', 'o', '\0'};
```



в строке 5 видимых символов, а массив содержит 6. строковый литерал всегда завершается нулевым байтом, поэтому последний элемент массива хранит нулевой байт, и общая длина массива равна 6.



в примере выше длина массива выводилась автоматически из инициализатора. если же длина задана явно, ситуация сложнее: массиву можно присвоить при инициализации строку, в которой символов меньше или больше, чем ожидает массив. рассмотрим варианты.



если размер массива совпадает с количеством символов строки:



```c


char abc[4] = "abc";
```



массив имеет длину 4 и инициализируется строкой из 4 символов с учётом завершающего нулевого байта. фактически получается:



```c
char abc[4] = {'a', 'b', 'c', '\0'};
```



если длина массива равна длине строки без учёта нулевого байта:



```c


char abc[3] = "abc";
```



массив имеет длину 3, и завершающий нулевой байт в него НЕ помещается. стандарт явно разрешает этот случай. фактически получается:



```c
char abc[3] = {'a', 'b', 'c'};
```



такой массив уже не является строкой в смысле c, и передавать его функциям, ожидающим нуль-терминированную строку (printf с `%s`, strlen), нельзя: они выйдут за его границы. в c++ такая инициализация запрещена.



если размер массива больше длины строки, оставшиеся элементы заполняются нулевыми байтами. например:



```c


char abc[5] = "abc";

// эквивалентно

char abc[4] = {'a', 'b', 'c', '\0', '\0'};
```



в эквивалентной записи размер, разумеется, должен быть 5, по числу инициализаторов.



если же строка длиннее массива даже без учёта завершающего нулевого байта, например:



```c
char abc[2] = "abc";
```



стандарт трактует это как нарушение ограничения на инициализатор и требует диагностики, а дальнейшее поведение зависит от реализации. gcc успешно компилирует этот пример, создаёт массив из первых двух символов строки "abc" и выводит предупреждение.



### указатель на char



строки в c можно представлять и через указатели на тип **char**:



```c


#include <stdio.h>

 

int main(void)

{

	char *hello = "Hello enoobis.ru!";	// указатель на char - фактически строка

	printf("%s", hello);

	return 0;

}
```



с точки зрения чтения символов оба определения, через массив и через указатель, равнозначны. различие между ними всё же есть, и для его понимания сначала нужно разобрать механизм интернирования строк.




### string interning



при работе со строковыми литералами в c применяется механизм **string interning**, или **интернирование строк**. строковые литералы имеют статическое время хранения и в типичных реализациях размещаются в секции **.rodata** (read-only data), предназначенной для данных только для чтения, а сами литералы рассматриваются как неизменяемые данные. возьмём следующую программу:



```c


#include <stdio.h>



char* str1 = "Hello";

char* str2 = "World";



int main(void)

{

    printf("str1 = %p \n", &str1[0]);

    printf("str2 = %p \n", &str2[0]);

     

    return 0;

}
```



здесь определены две строки, str1 и str2, а функция main выводит адрес первого символа каждой из них. пример вывода:



```bash


str1 = 00007FF75E674000

str2 = 00007FF75E674006
```



первый символ второй строки расположен через 6 байт от начала первой строки, то есть строки лежат в памяти рядом.



теперь сделаем строки одинаковыми:


```c


#include <stdio.h>



char* str1 = "Hello World";

char* str2 = "Hello World";



int main(void)

{

    printf("str1 = %p \n", &str1[0]);

    printf("str2 = %p \n", &str2[0]);

     

    return 0;

}
```



вывод изменится:



```bash


str1 = 00007FF75F674000

str2 = 00007FF75F674000
```



адреса совпадают, поскольку обе переменные на самом деле указывают на одну и ту же строку. интернирование устраняет дублирование одинаковых литералов и экономит память. стандарт оставляет неуточнённым, будут ли одинаковые литералы различными объектами, так что слияние является оптимизацией реализации (в gcc и clang она включена по умолчанию), а не гарантией языка. то, что переменные глобальные, значения не имеет: локальные переменные точно так же будут указывать на один и тот же адрес в **.rodata**.



```c


#include <stdio.h>



int main(void)

{

    char* str1 = "Hello World";

    char* str2 = "Hello World";

    printf("str1 = %p \n", &str1[0]);

    printf("str2 = %p \n", &str2[0]);

     

    return 0;

}
```



адрес, по которому располагается строка, можно получить и непосредственно из литерала:



```c


#include <stdio.h>



int main(void)

{

    char* str1 = "Hello World";

    char (*str2)[] = &"Hello World";

    printf("str1 = %p \n", &str1[0]);

    printf("str2 = %p \n", str2);

     

    return 0;

}
```



здесь str2 является указателем на массив символов и хранит адрес литерала "Hello World". это возможно потому, что строковый литерал есть lvalue типа «массив char», к которому применим оператор &. значения `&str1[0]` и `str2` снова совпадают.



### изменение строк



размещение строки, на которую ссылается указатель, в секции rodata означает, что изменить её нельзя. например:



```c


#include <stdio.h>



int main(void)

{

    char* text = "Hello";

    text[1] = 'a';

    printf("New text: %s\n", text);

    return 0;

}
```



здесь предпринимается попытка заменить второй символ (символ с индексом 1) на "a". программа компилируется, но при запуске завершается с ошибкой; в случае gcc на linux это segmentation fault. по стандарту попытка модифицировать строковый литерал есть неопределённое поведение. исторически литералы в c имеют тип `char[N]`, а не `const char[N]`, как в c++, поэтому компилятор такую запись пропускает; флаг gcc `-Wwrite-strings` позволяет получать предупреждения, а для указателей на литералы рекомендуется тип `const char *`.



то же касается изменения строки через синтаксис указателей:



```c


char* text = "Hello";

*text = 'a';  // Ошибка
```



теперь вместо указателя используем массив:


```c


#include <stdio.h>



int main(void)

{

    

    char text[] = "Hello";

    text[1] = 'a';

    *text = 'B';

    *(text+2) = 'b';

    printf("%s\n", text); // Bablo

    return 0;

}
```



теперь программа выполняется корректно и выводит на консоль строку "Bablo". массив является отдельным изменяемым объектом, который при инициализации получает копию символов литерала. для изменения элементов, как видно из примера, подходит и синтаксис массивов, и синтаксис указателей.



### пустая строка и null



указателю на символы, как и любому другому указателю, можно присвоить значение NULL:


```c


char* text = NULL;

if(!text) puts("text is null");
```



этот случай нужно отличать от пустой строки. пустая строка содержит один символ, нулевой байт, и указатель на неё является валидным:



```c


char* text1= NULL; // строка не инициализирована

char* text2= "\0"; // пустая строка

char text3[5]; // строка формально неинициализирована, но содержит мусор

char text4[5] = {'\0'}; // пустая строка
```
