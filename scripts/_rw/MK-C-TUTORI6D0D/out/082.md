функция **pthread_join()** позволяет перевести текущий поток (объект pthread_t ) в состояние ожидания, пока не завершится другой поток. эта функция имеет следующий прототип:

```c
int pthread_join(pthread_t thread, void **value_ptr);
```

первый параметр представляет поток, завершения которого надо подождать. второй параметр : указатель, через который можно получить результат потока.

при успешном выполнении эта функция возвращает 0, при возникновении ошибки : числовой код ошибки.

join : операция рандеву. вызывающий поток блокируется, пока целевой не завершится (через `return` из `routine` или `pthread_exit`). после успешного join идентификатор потока больше нельзя использовать: повторный join к тому же `pthread_t` даёт неопределённое поведение. поток, который никто не ждёт, следует либо явно отсоединить (`pthread_detach`), либо дождаться, иначе он остаётся в состоянии zombie и удерживает результат.

используем функцию `pthread_join()` для ожидания завершения потока:

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h> 

void* some_work(void* arg) 
{
    for(int i = 0; i < 3; ++i) 
    {
        puts(arg);
        sleep(1);
    }
    return NULL;
}
int main(void) 
{ 
    pthread_t thread;
    pthread_create(&thread, NULL, some_work, "Hello World" );
    pthread_join(thread, NULL);     // ждем завершения потока thread
    printf("End...\n");
    return 0;
}
```

в этом примере ожидается завершение потока thread, который выполняет функцию some_work. результат потока не важен (тем более он возвращает NULL), поэтому в `pthread_join()` второму параметру передаётся значение NULL. в итоге получается следующий консольный вывод:

```bash
eugene@Eugene:~/Documents/enoobis$ ./main
Hello World
Hello World
Hello World
End...
eugene@Eugene:~/Documents/enoobis$
```

возврат из `main` после join безопасен: к этому моменту единственный рабочий поток уже закончен, процесс не уничтожит чужую работу.

теперь используем результат:

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h> 

void* some_work(void* arg) 
{
    for(int i = 0; i < 3; ++i) 
    {
        puts(arg);
        sleep(1);
    }
    return "Bye, World";
}
int main(void) 
{
    pthread_t thread;
    void* thread_result;    // для получения результата потока
    pthread_create(&thread, NULL, some_work, "Hello World" );
    pthread_join(thread, &thread_result);     // ждем завершения потока thread
    puts(thread_result);
    return 0;
}
```

здесь поток возвращает строку (значение `char*`). для получения этого результата в функции main определён указатель thread_result. а в функцию `pthread_join()` вторым аргументом передаётся адрес этого указателя. в конце функции main выводится полученное значение:

```bash
eugene@Eugene:~/Documents/enoobis$ ./main
Hello World
Hello World
Hello World
Bye, World
eugene@Eugene:~/Documents/enoobis$
```

тип второго аргумента : `void **`. функция записывает по этому адресу то `void*`, которое вернула `routine`. строковый литерал `"Bye, World"` имеет статическую продолжительность жизни, поэтому указатель валиден после завершения потока. указатель на локальный объект внутри `some_work` после join был бы висячим.

если несколько потоков, завершения которых надо подождать, то для всех этих потоков можно вызвать `pthread_join()`:

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h> 

void* some_work(void* arg) 
{
    for(int i = 0; i < 3; ++i) 
    {
        puts(arg);
        sleep(1);
    }
    return "Bye, World";
}
int main(void) 
{
    pthread_t thread1, thread2;
    pthread_create(&thread1, NULL, some_work, "Hello World" );
    pthread_create(&thread2, NULL, some_work, "Hello enoobis.ru" );

    pthread_join(thread1, NULL);     // ждем завершения потока thread1
    pthread_join(thread2, NULL);     // ждем завершения потока thread2
    puts("End...");
    return 0;
}
```

порядок вызовов join задаёт порядок ожидания, а не порядок завершения: `thread2` мог закончиться раньше `thread1`, но main всё равно сначала дождётся `thread1`. результат обоих потоков здесь отбрасывается (`NULL` во втором аргументе), хотя `some_work` по-прежнему возвращает `"Bye, World"`.
