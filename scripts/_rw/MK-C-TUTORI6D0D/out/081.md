многопоточность является одним из центральных аспектов в современном программировании. основным понятием при работе с многопоточностью является поток. поток представляет некоторую часть кода программы. при выполнении программы каждому потоку выделяется определённый квант времени. при помощи многопоточности в приложении выделяют несколько потоков, которые выполняют различные задачи одновременно. если графическое приложение посылает запрос к серверу или считывает и обрабатывает огромный файл, то без многопоточности графический интерфейс блокировался бы на время выполнения задачи. благодаря потокам отправку запроса или любую другую задачу, которая может долго обрабатываться, выделяют в отдельный поток. поэтому, например, клиент-серверные приложения (и не только они) практически немыслимы без многопоточности.

на unix-подобных системах потоки уровня пользователя реализует posix threads (pthreads): это не часть iso c, а интерфейс posix. стандарт c11 добавил `<threads.h>`, но на практике на linux по-прежнему используют **pthread.h**. планировщик ос распределяет кванты между потоками процесса; истинный параллелизм возможен при нескольких ядрах, иначе наблюдается квазипараллельное чередование.

в языке си поток представляет объект типа **pthread_t**, который определён в заголовочном файле **pthread.h**. а для создания потока применяется функция **pthread_create()**, которая имеет следующий прототип:

```c


int pthread_create(

  pthread_t *thread,

  const pthread_attr_t *attr,

  void *(*routine) (void *),

  void *arg);
```

эта функция принимает следующие параметры:

- `*thread` : указатель на объект pthread_t , который инициализируется.

- `*attr` : указатель на набор атрибутов потока в виде объекта pthread_attr_t . если атрибуты не нужны, можно передать `NULL`

- `*routine` : указатель на функцию, которая запускается в потоке. подобная функция должна принимать в качестве параметра указатель `void*` , вместо которого можно передать указатель на любой объект. однако допускается только один аргумент. соответственно если надо передать несколько значений, то можно оформить их в массив или структуру. возвращаемое значение функции также должно представлять указатель `void*` . соответственно также можно возвратить указатель на любой объект. данное возвращаемое значение будет выступать в качестве результата потока. опять же здесь можно возвратить значение `NULL` , если оно не нужно.

- `*arg` : указатель void* , через который передаётся значение в запускаемую функцию.

при успехе **pthread_create** возвращает 0, иначе код ошибки (не через `errno` в обязательном порядке). новый поток начинает выполнение `routine(arg)` параллельно с вызывающим. объект `pthread_t` становится идентификатором потока; его нельзя копировать как произвольные данные между реализациями, сравнивать допустимо через `pthread_equal`.

например, определим следующую программу:

```c


#include <pthread.h>

#include <stdio.h>



void* some_work(void* arg) 

{

    for(int i = 0; i < 5; ++i) 

    {

        puts(arg);

    }

    return NULL;

}

int main(void) 

{ 

    pthread_t thread1, thread2;

    // создаем потоки

    pthread_create(&thread1, NULL, some_work, "Hello World" );

    pthread_create(&thread2, NULL, some_work, "Hello enoobis.ru" );



    printf("End...\n");

    return 0;

}
```

в функции main сначала объявляются две переменные, которые будут представлять потоки:

```c


pthread_t thread1, thread2;
```

затем они инициализируются:

```c


pthread_create(&thread1, NULL, some_work, "Hello World" );

pthread_create(&thread2, NULL, some_work, "Hello enoobis.ru" );
```

инициализация обоих потоков аналогична. в качестве первого параметра в функцию передаётся адрес переменной. атрибуты потока сейчас не важны, поэтому вторым аргументом передаётся значение NULL. в качестве выполняемой функции передаётся функция some_work, которая определена выше. четвёртое значение : аргумент для функции, здесь это две разных строки.

функция some_work просто в цикле выводит пять раз переданную в качестве параметра строку:

```c


void* some_work(void* arg) 

{

    for(int i = 0; i < 5; ++i) 

    {

        puts(arg);

    }

    return NULL;

}
```

результат функции здесь не важен, поэтому возвращается NULL. строковые литералы имеют статическую продолжительность жизни, поэтому передавать их в поток как `void*` безопасно; указатель на локальный объект `main` после возврата из `main` был бы висячим.

компиляция и запуск программы:

```bash


eugene@Eugene:~/Documents/enoobis$ gcc -Wall -pedantic -std=c2x main.c -o main

eugene@Eugene:~/Documents/enoobis$ ./main

End...

eugene@Eugene:~/Documents/enoobis$
```

на этом выводе видно, что потоки не отработали до конца: ни один из них не вывел переданную в него строку. в реальности вывод недетерминирован. например, он мог бы быть следующим:

```bash


eugene@Eugene:~/Documents/enoobis$ ./main

End...

Hello World

Hello World

Hello World

Hello World

Hello World

eugene@Eugene:~/Documents/enoobis$
```

в любом случае возникает проблема: потоки не отрабатывают полностью, а программа завершается. дело в том, что оператор return в функции main приводит к завершению программы и соответственно процесса программы и всех её потоков. если поток не успел отработать до завершения процесса, то он тоже завершается.

`exit` и возврат из `main` завершают процесс целиком. компоновка с pthreads обычно требует флага `-pthread` (он задаёт и макросы, и библиотеку); в показанной команде gcc он не указан и на части систем может потребоваться отдельно.

### функция pthread_exit

функция **pthread_exit()** позволяет подождать, пока не завершатся все потоки, и после их завершения завершает вызывающий поток (главный поток программы, в котором запущена функция main) и позволяет выполниться всем другим потокам. эта функция принимает один параметр : возвращаемый результат. если он не важен, то можно передать NULL. далее видно, где это значение может пригодиться.

точнее, **pthread_exit** завершает только вызывающий поток. если это главный поток, процесс не уничтожается возвратом из `main`: остальные потоки продолжают работу, и процесс живёт, пока жив последний не-отсоединённый поток. join при этом не выполняется, значение, переданное в **pthread_exit** из main, доступно тому, кто позже сделает `pthread_join` к главному потоку, что на практике почти не используют.

код программы с функцией **pthread_exit()**:

```c


#include <pthread.h>

#include <stdio.h>



void* some_work(void* arg) 

{

    for(int i = 0; i < 5; ++i) 

    {

        puts(arg);

    }

    return NULL;

}

int main(void) 

{ 

    pthread_t thread1, thread2;

    // создаем потоки

    pthread_create(&thread1, NULL, some_work, "Hello World" );

    pthread_create(&thread2, NULL, some_work, "Hello enoobis.ru" );



    pthread_exit(NULL);



    printf("End...\n");

    return 0;

}
```

теперь оба потока будут выполняться полностью:

```bash


eugene@Eugene:~/Documents/enoobis$ ./main

Hello World

Hello World

Hello World

Hello World

Hello World

Hello enoobis.ru

Hello enoobis.ru

Hello enoobis.ru

Hello enoobis.ru

Hello enoobis.ru

eugene@Eugene:~/Documents/enoobis$
```

однако, поскольку функция **pthread_exit()** завершает вызывающий поток (поток функции main), то консоль не выведет строку "End...".

порядок строк на выводе не гарантирован: планировщик волен чередовать потоки как угодно. даже пять одинаковых строк подряд от одного потока : допустимое расписание, а не ошибка.

### функция sleep

чтобы сделать более показательной одновременную работу потоков, используется функция **sleep()**. она определена в заголовочном файле "unistd.h" и позволяет приостановить текущий поток на определённое количество секунд. код программы принимает следующий вид:

```c


#include <pthread.h>

#include <stdio.h>

#include <unistd.h>



void* some_work(void* arg) 

{

    for(int i = 0; i < 5; ++i) 

    {

        puts(arg);

        sleep(1);   // задержка в 1 секунду

    }

    return NULL;

}

int main(void) 

{ 

    pthread_t thread1, thread2;

    pthread_create(&thread1, NULL, some_work, "Hello World" );

    pthread_create(&thread2, NULL, some_work, "Hello enoobis.ru" );



    pthread_exit(NULL);

    printf("End...\n");

    return 0;

}
```

`sleep` : функция posix, она приостанавливает текущий поток, а не весь процесс с точки зрения остальных потоков того же процесса. на windows в стандартной библиотеке си такого имени нет.

задержка составляет 1 секунду, благодаря чему потоки могут выводить строку на консоль почти попеременно. например:

```bash


eugene@Eugene:~/Documents/enoobis$ ./main

Hello World

Hello enoobis.ru

Hello enoobis.ru

Hello World

Hello World

Hello enoobis.ru

Hello World

Hello enoobis.ru

Hello World

Hello enoobis.ru

eugene@Eugene:~/Documents/enoobis$
```

точный вывод, какой поток начнёт первым выводить строку на консоль, опять же неопределён. гонки по общему `stdout` тоже возможны: `puts` не обязан быть атомарным относительно других потоков, поэтому на реальной системе строки иногда смешиваются посимвольно, если не синхронизировать вывод.
