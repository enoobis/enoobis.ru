компиляторы gcc и clang поддерживают встраивание ассемблерного кода в произвольные места программы на c. для этого служит конструкция **asm()**: внутри скобок записывается ассемблерный шаблон, который через операнды напрямую связывается с объектами программы на c. конструкция не входит в стандарт iso c (стандарт лишь упоминает `asm` как распространённое расширение), поэтому её синтаксис и семантика определяются конкретным компилятором. в общем виде инструкция **asm()** имеет следующий синтаксис:



```c

asm asm-qualifiers ( AssemblerTemplate
 : OutputOperands
 [ : InputOperands]
 [ : Clobbers ] ]
 [ : GotoLabels])
```



инструкция принимает следующие параметры:




- `AssemblerTemplate` : собственно ассемблерный код. шаблон может содержать подстановки, начинающиеся с символа %, на место которых компилятор c подставляет входные и выходные операнды.

- `OutputOperands:` : выходные операнды, то есть список переменных или регистров, через которые ассемблерный код возвращает результат.

- `InputOperands` : входные операнды, то есть список переменных или регистров, через которые в ассемблерный код передаются значения.

- `Clobbers` : список регистров (а также специальных значений вроде `"memory"` и `"cc"`), которые ассемблерный код использует и чьё содержимое в ходе его выполнения будет затёрто. по этому списку компилятор узнаёт, какие регистры нельзя считать сохранёнными после вставки.

- `GotoLabelsr` : список меток в коде c, на которые допустим переход из ассемблерного кода.




### ассемблерный код



ассемблерный код состоит из обычных команд ассемблера целевой архитектуры. компилятор не анализирует их смысл: шаблон после подстановки операндов передаётся ассемблеру как текст. простейший пример:



```c

asm(
    "mov $12, %rax"
);
```



эта вставка помещает в регистр rax число 12. используется синтаксис ассемблера gas (синтаксис at&t, родной для gcc), в котором имена регистров записываются с префиксом `%` (например, `%eax`), непосредственные значения с префиксом `$`, а порядок операндов обратный по сравнению с синтаксисом intel: сначала источник, затем приёмник.



вставка может содержать несколько операций:



```c

asm(
    "mov $12, %rax\n"
    "mov $13, %rcx\n"
    "add %rcx, %rax"
);
```



здесь в регистр rax помещается 12, в rcx помещается 13, после чего значения складываются и сумма записывается в rax. все строковые литералы по правилам c конкатенируются в одну строку на этапе трансляции, поэтому, чтобы ассемблер воспринимал операции как отдельные инструкции, каждая строка завершается символом перевода строки \n.




рассмотрим простейшую программу на c для linux:



```c

#include <stdio.h>

int main (void)
{
    puts("Hello enoobis.ru");

    asm(
        "movq $22, %rdi  # в RDI код статуса результата\n"
        "movq $60, %rax  # в RAX номер системной функции\n"
        "syscall         # выполняем системную функцию"
    );
}
```



внутри шаблона допустимы комментарии ассемблера, начинающиеся с символа `#`. программа сначала выводит на консоль произвольную строку, затем ассемблерная вставка выполняет системный вызов linux с номером 60 (`exit` в соглашении x86-64). по соглашению о системных вызовах в регистр rdi помещается код возврата, в регистр rax помещается номер вызова (60), после чего выполняется инструкция `syscall`. в результате процесс завершится с кодом 22, что по наблюдаемому эффекту эквивалентно явному `return 22;` из `main` (с той разницей, что прямой вызов `exit` минует сброс буферов стандартной библиотеки и обработчики `atexit`). код возврата после выполнения программы проверяется командой "echo $?":



```bash

eugene@Eugene:$ gcc app.c -o app && ./app
Hello enoobis.ru
eugene@Eugene:$ echo $?
22
eugene@Eugene:$
```



### выходные параметры



выходные параметры представляют собой список переменных или регистров, через которые ассемблерный код возвращает результат. рассмотрим простейшую программу:



```c

#include <stdio.h>

int main (void)
{
    
    int x = 1;
    printf("Initial X value: %d\n", x);

    asm(
        "mov $12, %%rax\n"
        "mov $13, %%rdx\n"
        "add %%rdx, %%rax"
        : "=a" (x)
    );

    printf("Final X value: %d\n", x);

   return 0;
}
```



ассемблерный код складывает значения регистров rax и rdx. поскольку вставка содержит операнды (так называемая расширенная форма asm), символ `%` в шаблоне служит маркером подстановки, и имена регистров приходится экранировать: как и в строке формата функции printf, **%%** обозначает один литеральный `%`. в базовой форме без операндов, как в предыдущих примерах, такого экранирования не требуется.



в качестве выходного операнда используется переменная x:



```c
: "=a" (x)
```



в этом выражении `"=a"` является ограничением (constraint): модификатор `=` означает, что операнд только записывается, а буква `a` привязывает его к регистру rax. выражение `x` в скобках указывает, что значение этого регистра после выполнения вставки будет записано в переменную `x`. для проверки результата значение x выводится дважды, до и после вставки. консольный вывод:



```bash

Initial X value: 1
Final X value: 25
```




### дескрипторы аргументов



в примере выше для получения результата в выходной операнд, переменную x, применялось ограничение `"=a"`. для архитектуры x86 определены специальные буквенные обозначения: "a" (rax), "b" (rbx), "c" (rcx), "d" (rdx), "D" (rdi), "S" (rsi). для rip и rflags таких дескрипторов нет, нет их и для регистров r8~r15. помимо них существуют более общие дескрипторы: "r" обозначает произвольный регистр общего назначения, конкретный регистр выбирает компилятор при распределении регистров, а "m" обозначает операнд в памяти, который транслируется в эффективный адрес.



например, в примере выше можно забирать результат из регистра rdx:



```c

asm(
    "mov $12, %%rax\n"
    "mov $13, %%rdx\n"
    "add %%rdx, %%rax"
    : "=d" (x)
);
```



в этом случае в переменную x будет записано число 13, поскольку сумма остаётся в rax, а rdx хранит второе слагаемое.



кроме того, ключевое слово `asm` вместе с классом хранения `register` (storage class) позволяет потребовать от компилятора разместить объект в конкретном регистре (расширение gcc, explicit register variables). например:



```c

#include <stdio.h>

int main (void)
{
    register int x asm ("r8");
    x = 1;
    printf("Initial X value: %d\n", x);  // 1

    asm(
        "mov $15, %%r8\n"
        : "=r" (x)
    );

    printf("Final X value: %d\n", x);  // 15

   return 0;
}
```



здесь переменная x связывается с регистром r8. поэтому в определении выходного операнда допустимо записать `: "=r" (x)`: общий дескриптор "r" в этом случае будет соответствовать именно регистру r8. документация gcc гарантирует такую привязку локальной регистровой переменной только в момент её использования как операнда asm, в остальном коде компилятор вправе держать значение где угодно.



### обновляемые параметры



выходной операнд можно одновременно использовать как входной, то есть обновлять его значение. для этого вместо модификатора "=" указывается модификатор "+" (плюс). например:



```c

#include <stdio.h>

int main (void)
{
    int x = 11;
    printf("Initial X value: %d\n", x);

    asm(
        "add %%rax, %%rax"
        : "+a" (x)
    );

    printf("Final X value: %d\n", x);

   return 0;
}
```



благодаря ограничению "+a" значение переменной x перед выполнением вставки загружается в регистр rax, а после её завершения записывается оттуда обратно. при выполнении программы получим следующий консольный вывод:



```bash

Initial X value: 11
Final X value: 22
```



следующий пример использует несколько операндов:



```c

#include <stdio.h>

int main (void)
{
    
    int x = 11;
    int y = 0;
    printf("Initial X value: %d\n", x);
    printf("Initial Y value: %d\n", y);

    asm(
        "mov $12, %%rdx\n"
        "add %%rdx, %%rax"
        : "+a" (x), "=d" (y)
    );

    printf("Final X value: %d\n", x);
    printf("Final Y value: %d\n", y);

   return 0;
}
```



здесь два выходных операнда, представленных переменными x и y. переменная x и загружается в регистр rax, и обновляется из него, тогда как переменная y только получает значение из регистра rdx.




### входные параметры



входные параметры представляют собой список переменных или регистров, через которые в ассемблерный код передаются значения. например:



```c

#include <stdio.h>

int main (void)
{
    long x = 11;
    long y = 5;
    long z = 0;

    printf("Initial z value: %ld\n", z);

    asm(
        "add %%rdx, %%rax"
        : "=a" (z)
        : "a" (x), "d" (y)
    );

    printf("Final z value: %ld\n", z);

   return 0;
}
```



входные операнды заданы следующим образом:



```c
: "a" (x), "d" (y)
```



значение переменной x помещается в регистр rax, значение переменной y помещается в регистр rdx, всего два входных операнда. входные операнды компилятор считает неизменяемыми: если ассемблерный код всё же модифицирует такой регистр, это нужно отразить через "+" или список clobbers, иначе поведение некорректно.



результат сложения (`"add %%rdx, %%rax"`) передаётся в переменную z, которая выступает выходным операндом (`: "=a" (z)`). консольный вывод:



```c

Initial z value: 0
Final z value: 16
```




### индексы параметров



к операндам также можно обращаться по индексу в общем списке, где сначала нумеруются выходные, а затем входные операнды. используется форма `%N`, где N лежит в диапазоне от 0 до 9 (в современных версиях gcc допускается до 30 операндов, кроме того, доступны символические имена вида `%[name]`). например:



```c

asm (
  "add %0,%0"
  : "+a" (x)
);
```



в этом случае операнд один, x, и его индекс равен 0, поэтому выражение `%0` ссылается именно на него.



другой пример:



```c

#include <stdio.h>

int main (void)
{
    
    long x = 11;
    long y = 3;
    long z = 0;

    //printf("Initial z value: %ld\n", z);

    asm(
        "add %2, %1"
        : "=a" (z)
        : "a" (x), "d" (y)
    );

    //printf("Final z value: %ld\n", z);

   return 0;
}
```



здесь всего три операнда: выходной `z`, связанный с регистром rax, и два входных, из которых `x` загружается в регистр rax, а `y` загружается в регистр rdx. нумерация следует порядку перечисления, сначала выходные, затем входные:




- `%0` : `z`

- `%1` : `x`

- `%2` : `y`




таким образом, вставка прибавляет третий операнд ко второму, результат остаётся в rax, откуда его забирает первый операнд z.



входной операнд x размещается в том же регистре, что и выходной z, поэтому вместо буквы регистра для него можно указать индекс выходного операнда (так называемое совпадающее ограничение, matching constraint):



```c

asm(
    "add %2, %1"
    : "=a" (z)
    : "0" (x), "d" (y)
);
```



в этой записи x и z гарантированно используют один и тот же регистр.



ассемблерный код, сгенерированный компилятором для этой программы без оптимизаций, выглядит следующим образом:



```asm

main:
        pushq   %rbp
        movq    %rsp, %rbp
        movq    $11, -8(%rbp)
        movq    $3, -16(%rbp)
        movq    $0, -24(%rbp)
        movq    -8(%rbp), %rax
        movq    -16(%rbp), %rdx
        add %rdx, %rax
        movq    %rax, -24(%rbp)
        movl    $0, %eax
        popq    %rbp
        ret
```



в листинге видно, что компилятор сам загрузил входные операнды в rax и rdx перед вставкой и сохранил rax в z после неё, а текст шаблона вошёл в результат дословно с подставленными именами регистров.



ещё один пример: вычисление длины строки.



```c

#include <stdio.h>

int main (void)
{
    char* text = "hello";
    size_t len = 0;

    asm (
      "mov %%rdi, %%rsi\n"
      "repne scasb\n"
      "sub %%rsi, %%rdi\n"
      "sub $1, %%rdi\n"
      : "=D" (len)
      : "a" (0), "D" (text), "c" (-1)
    );
    
    printf("len: %lu\n", len);  // len: 5
    return 0;
}
```



в регистр rdi загружается адрес строки, длину которой требуется найти. в регистр rcx загружается максимальное число просматриваемых символов: значение -1 в беззнаковой интерпретации даёт наибольшее возможное число, то есть ограничение фактически снимается. в регистр al (младший байт rax) загружается искомый символ. строка в c завершается нулевым байтом, поэтому искать нужно символ с кодом 0.



поиск нулевого байта выполняет инструкция `repne scasb`: она сравнивает al с байтом по адресу из rdi, увеличивает rdi и уменьшает rcx, повторяя это, пока байты не совпадут или rcx не обнулится. по завершении rdi указывает на байт, следующий за найденным нулём. поэтому из этого адреса вычитается адрес начала строки, предварительно скопированный в rsi, и ещё 1 байт. полученная длина попадает в выходной операнд, переменную len. строго говоря, вставка модифицирует rsi и rcx, не объявляя их, и полагается на сброшенный флаг направления df, поэтому в рабочем коде rsi следует указать в списке clobbers, а rcx сделать операндом "+c".




### asm и volatile



обычно к блоку `asm` добавляют квалификатор **volatile**. в контексте asm он означает, что вставка имеет побочные эффекты, не выраженные через операнды, поэтому оптимизатор не должен её удалять, даже если результаты не используются, и не должен выносить её из цикла как инвариантное выражение. без этого квалификатора компилятор рассматривает вставку с выходными операндами как чистую функцию от входов и вправе «оптимизировать» её. вставки без выходных операндов gcc неявно считает volatile:



```c

#include <stdio.h>

int main (void)
{
    int x = 11;

    asm volatile(
        "add %%rax, %%rax"
        : "+a" (x)
    );

    printf("Final X value: %d\n", x);

   return 0;
}
```
