### memset



функция **memset** из заголовочного файла `string.h` заполняет блок памяти заданным значением. типичное применение: инициализация начальными значениями блока динамической памяти, полученного от malloc, содержимое которого неопределено. прототип функции:



```c
void *memset(void *destination, int value, size_t N);
```



параметры




- `destination`: указатель на блок памяти

- `value`: значение, которым заполняется блок; перед записью оно преобразуется к unsigned char

- `N`: размер заполняемого блока в байтах



например, выделим блок памяти для 5 чисел типа `int` и заполним все его байты нулями:



```c


#include <stdio.h>

#include <stdlib.h>

#include <string.h>



int main(void)

{

	// выделяем блок памяти для 5 чисел int

	int m = 5; 					// количество элементов

	int n = m * sizeof(int);	// размер выделяемой памяти

	int *ptr = malloc(n);

	if (ptr)

	{

		// иницилизируем все байты нулями

		memset(ptr, 0, n);

		// проверяем инициализацию

		for (int i = 0; i < m; i++)

		{

 			printf("%d ", ptr[i]);

 		}

 	}

 	free(ptr);

	return 0;

}
```



memset работает на уровне представления объектов: инициализируются не числа int, составляющие массив ptr, а каждый байт блока памяти. для нуля это даёт ожидаемый результат, поскольку целое число из нулевых байтов равно 0. вызов `memset(ptr, 1, n)` записал бы в каждый int не 1, а значение 0x01010101, то есть 16843009 при 32-битном int. для типов с плавающей точкой и указателей нулевое представление совпадает с 0.0 и NULL на распространённых платформах, но стандарт этого не гарантирует. для выделения уже обнулённой памяти существует функция calloc.



### memcpy



функция **memcpy** копирует заданное количество байт из одного блока памяти в другой. её прототип:



```c
void* memcpy(void *destination, const void *source, size_t N );
```



параметры





- `destination`: указатель на блок памяти, в который выполняется копирование

- `source`: указатель на блок памяти, из которого выполняется копирование

- `N`: количество копируемых байтов



блоки не должны перекрываться, иначе поведение не определено; для перекрывающихся областей предназначена функция memmove. в c99 параметры memcpy объявлены с квалификатором restrict, который и выражает это требование для компилятора.



например, скопируем 5 байт из одного блока памяти в другой:



```c


#include <stdio.h>

#include <string.h>



int main(void)

{

 	char source[] = "Hello World";

	// копируем 5 байт

 	char destination[5];

 	memcpy(destination, source, sizeof destination);



 	// выводим скопированные байты

 	for (int i = 0; i < sizeof destination; i++)

 	{

 		printf("%c", destination[i]);

 	}

	return 0;

}
```



в массив destination попадают символы "Hello" без завершающего нулевого байта, поэтому он не является строкой и выводится посимвольно. выражение `sizeof destination` записано без скобок: для выражения, в отличие от имени типа, скобки у оператора sizeof не обязательны.



указатель на блок, в который копируются байты, может указывать и на динамически выделенную память:



```c


#include <stdio.h>

#include <string.h>

#include <stdlib.h>



int main(void)

{

 	char source[] = "Hello World";

	// копируем 5 байт

	int n = 5;

 	char *destination = malloc(n);

 	memcpy(destination, source, n);



 	for (int i = 0; i < n; i++)

 	{

 		printf("%c", destination[i]);

 	}

	free(destination);

	return 0;

}
```



блоки памяти, между которыми копируются данные, не обязаны содержать объекты типа `char`. благодаря параметрам типа void * функция не зависит от типа данных и оперирует только байтами, поэтому подходит для объектов любого типа, например `int`:



```c


#include <stdio.h>

#include <string.h>

#include <stdlib.h>



int main(void)

{

	// копируем 5 объектов типа int

	const int n = 5;

 	int numbers[] = {1, 2, 3, 4, 5};

 	int *destination = malloc(n * sizeof(int));

 	memcpy(destination, numbers, n * sizeof(int));



 	for (int i = 0; i < n; i++)

 	{

 		printf("%d ", destination[i]);

 	}

	free(destination);

	return 0;

}
```



размер в этом случае задаётся в байтах, поэтому количество элементов умножается на `sizeof(int)`.



другой пример: копирование структур.



```c


#include <stdio.h>

#include <string.h>



struct person

{

	char name[20];

	int age;

};



int main(void)

{

	struct person tom = {"Tom", 38};	// структура, которую копируем

	struct person someperson;	// структура, в которую копируем



 	memcpy(&someperson, &tom, sizeof(struct person));



 	printf("Name: %s\n", someperson.name);

 	printf("Age: %d\n", someperson.age);

	return 0;

}
```



поскольку функция `memcpy` принимает указатели, в неё передаются адреса структур. для структур одного типа тот же результат даёт обычное присваивание `someperson = tom`, которое в c выполняет побайтовое копирование всего объекта; memcpy полезна, когда тип источника и приёмника формально различается или размер известен только во время выполнения.



### сравнение объектов. memcmp



функция **memcmp** сравнивает заданное количество байт двух объектов. её прототип:



```c
int memcmp( const void* p1, const void* p2, size_t N );
```



первый и второй параметры являются указателями на сравниваемые блоки памяти. последний параметр задаёт количество сравниваемых байт блоков p1 и p2.



функция возвращает 0, если N байтов обоих объектов совпадают.



если первый несовпадающий байт первого блока, интерпретируемый как unsigned char, больше соответствующего байта второго блока, возвращается число больше 0.



если первый несовпадающий байт первого блока меньше соответствующего байта второго блока, возвращается число меньше 0.



например, сравним два объекта структуры:



```c


#include <stdio.h>

#include <string.h>



struct person

{

	char name[20];

	int age;

};



int main(void)

{

	struct person tom = {"Tom", 38};

	struct person tomas = {"Tom", 38};



 	int result = memcmp(&tom, &tomas, sizeof(struct person));

	if(result == 0)

	{

		printf("tom and tomas are equal \n");

	}

	else	

	{

		printf("tom and tomas are not equal \n");

	}

	return 0;

}
```



здесь сравниваются все байты обеих структур. поскольку их значения равны, функция `memcmp` возвращает 0. в общем случае побайтовое сравнение структур ненадёжно: между элементами и в конце структуры компилятор может вставлять байты выравнивания (padding), значения которых не определены, и две структуры с равными элементами могут различаться в этих байтах. в данном примере выравнивание не требуется, так как размер массива name кратен размеру int, а неиспользованные элементы name при инициализации обнуляются. по этой причине в c нет встроенного оператора `==` для структур.



поскольку функция последовательно сравнивает соответствующие байты обоих объектов, а элементы структуры располагаются в памяти в порядке их объявления, равными могут оказаться и объекты разных структурных типов:



```c


#include <stdio.h>

#include <string.h>



struct person

{

	char name[20];

	int age;

};



struct employee

{

	char name[20];

	int age;

};



int main(void)

{

	struct person tom = {"Tom", 38};

	struct employee tomas = {"Tom", 38};



 	int result = memcmp(&tom, &tomas, sizeof(struct person));

	if(result == 0)

	{

		printf("tom and tomas are equal \n");

	}

	else	

	{

		printf("tom and tomas are not equal \n");

	}

	return 0;

}
```



объекты структур person и employee имеют одинаковые элементы с одинаковыми значениями, поэтому memcmp возвращает 0, несмотря на то, что типы структур разные. функция работает с нетипизированными указателями и не имеет сведений о типах объектов: сравнивается только представление в памяти.



ещё один пример: сравнение массивов.



```c


#include <stdio.h>

#include <string.h>



int main(void)

{

	int numbers1[] = {1, 2, 3, 4, 5};

	int numbers2[] = {2, 1, 3, 4, 5}; 



 	int result = memcmp(numbers1, numbers2, sizeof(numbers1));

	if(!result)

	{

		printf("arrays are equal \n");

	}

	else	

	{

		printf("arrays are not equal \n");

	}

	return 0;

}
```



массивы не равны, поэтому функция возвращает ненулевое число. знак результата для массивов многобайтовых целых зависит от порядка байтов платформы (little-endian или big-endian) и в общем случае не совпадает с результатом сравнения самих чисел, поэтому для упорядочивания таких данных memcmp не подходит, а для проверки равенства подходит.
