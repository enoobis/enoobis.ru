к указателям применим ограниченный набор арифметических операций: сложение, вычитание, инкремент и декремент. семантика этих операций отличается от целочисленной арифметики и определяется типом указателя, точнее размером объекта, на который он указывает. к указателю можно прибавить целое число, из указателя можно вычесть целое число, а также можно вычесть один указатель из другого. стандарт c определяет результат такой арифметики только в пределах одного массива (включая позицию сразу за последним элементом), а одиночный объект трактуется как массив из одного элемента.



начнём с инкремента и декремента на примере указателя на объект типа **int**:



```c


#include <stdio.h>



int main(void)

{

	int n = 10;

	

	int *ptr = &n;

	printf("address=%p \t value=%d \n", (void*)ptr, *ptr);

	

	ptr++;

	printf("address=%p \t value=%d \n", (void*)ptr, *ptr);

	

	ptr--;

	printf("address=%p \t value=%d \n", (void*)ptr, *ptr);

	

	return 0;

}
```



операция инкремента ++ увеличивает значение операнда на единицу. для указателя это означает увеличение хранимого адреса на размер указываемого типа, то есть на `sizeof(*ptr)` байт. здесь указатель имеет тип `int *`, а объект int на большинстве современных архитектур занимает 4 байта, поэтому инкремент такого указателя увеличивает адрес на 4.



на тестовой машине консольный вывод выглядит так:


 

```consoletext


address=0060FEA8	value=10

address=0060FEAC	value=6356652

address=0060FEA8	value=10
```


 

видно, что после инкремента значение указателя выросло на 4: с 0060FEA8 до 0060FEAC. после декремента, то есть уменьшения на единицу, указатель снова содержит прежний адрес.



по смыслу увеличение на единицу означает переход к следующему объекту того же типа, расположенному в памяти сразу за текущим. уменьшение на единицу означает переход к предыдущему объекту.



после смены адреса можно прочитать значение по новому адресу, однако оно может оказаться неопределённым, как во второй строке вывода выше. формально разыменование указателя, вышедшего за пределы объекта n, является неопределённым поведением: сформировать адрес «сразу за концом» разрешено, читать по нему нельзя.



для указателя на **int** изменение на единицу сдвигает адрес на 4. по той же логике для указателя на **short** эти операции сдвигали бы адрес на 2, а для указателя на **char** на 1, поскольку `sizeof(char)` по определению равен 1.



```c


#include <stdio.h>



int main(void)

{

	double d = 10.6;

	double *pd = &d;

	printf("Pointer pd: address=%p \n", (void*)pd);

	pd++;

	printf("Pointer pd: address=%p \n", (void*)pd);

		

	char c = 'N';

	char *pc = &c;

	printf("Pointer pc: address=%p \n", (void*)pc);

	pc++;

	printf("Pointer pc: address=%p \n", (void*)pc);

	

	return 0;

}
```



пример консольного вывода:



```bash


Pointer pd: address=0060FEA0

Pointer pd: address=0060FEA8

Pointer pc: address=0060FE9F

Pointer pc: address=0060FEA0
```



инкремент указателя на double увеличил хранимый адрес на 8 (объект double занимает 8 байт), а инкремент указателя на char увеличил адрес на 1 (тип char занимает 1 байт).



так же указатель изменяется при прибавлении или вычитании произвольного целого числа: смещение в байтах равно числу, умноженному на размер указываемого типа.


```c


#include <stdio.h>



int main(void)

{

	double d = 10.6;

	double *pd = &d;

	printf("Pointer pd: address=%p \n", (void*)pd);

	pd = pd + 2;	// перемещаем указатель вперед на 2 значения double (2 * 8 = 16 байт)

	printf("Pointer pd: address=%p \n", (void*)pd);

	

	

	char c = 'N';

	char *pc = &c;

	printf("Pointer pc: address=%p \n", (void*)pc);

	pc = pc - 3;		// перемещаем указатель назад на 3 значения char (3 * 1 = 3 байта)

	printf("Pointer pc: address=%p \n", (void*)pc);

	

	return 0;

}
```



прибавление к указателю на **double** числа 2


```c
pd = pd + 2;
```



означает переход на два объекта double вперёд, то есть изменение адреса на 2 * 8 = 16 байт.



вычитание из указателя на **char** числа 3



```c
pc = pc - 3;
```



означает переход на три объекта char назад, то есть изменение адреса на 3 * 1 = 3 байта.



получаемый консольный вывод:



```bash


Pointer pd: address=0060FEA0

Pointer pd: address=0060FEB0

Pointer pc: address=0060FE9F

Pointer pc: address=0060FE9C
```



в отличие от сложения, вычитание допускается не только между указателем и целым числом, но и между двумя указателями одного типа:



```c


#include <stdio.h>



int main(void)

{

	int a = 10;

	int b = 23;

	int *pa = &a;

	int *pb = &b;

	ptrdiff_t c = pa - pb;	// разница между адресами

	

	printf("pa=%p \n", (void*)pa);

	printf("pb=%p \n", (void*)pb);

	printf("c=%lld \n", c);

	

	return 0;

}
```



консольный вывод:



```bash


pa=0060FEA0

pb=0060FE9C

c=1
```



результат разности двух указателей есть «расстояние» между ними, выраженное в количестве объектов указываемого типа (здесь int), а не в байтах. в примере адрес в первом указателе на 4 больше адреса во втором (0x0060FE9C + 4 = 0x0060FEA0). поскольку **один** объект int занимает 4 байта, расстояние равно (0x0060FEA0 - 0x0060FE9C)/4 = 1. строго говоря, стандарт определяет разность только для указателей на элементы одного и того же массива. a и b являются независимыми переменными, их взаимное расположение на стеке выбирает компилятор, поэтому этот пример иллюстрирует механику, но формально даёт неопределённое поведение.



расстояние между указателями имеет тип **ptrdiff_t**, объявленный в заголовке `<stddef.h>`. это знаковый целочисленный тип, на 64-разрядных платформах обычно являющийся псевдонимом **long long** (или long) размером 8 байт. переносимый спецификатор формата для него в printf: `%td`.



ещё один пример:


```c


#include <stdio.h>

 

int main(void)

{

    int arr[64];

    int* ptr1 = &arr[10];

    int* ptr2 = &arr[40];

    ptrdiff_t dist = ptr2 - ptr1; // 30

     

    printf("dist=%lld \n", dist);

     

    return 0;

}
```



здесь вычисляется разность указателей на 10-й и 40-й элементы массива. расстояние равно 30, то есть 30 элементам int. это корректный случай: оба указателя относятся к одному массиву. для получения расстояния в байтах результат нужно умножить на размер указываемого типа.



### особенности операций



при работе с указателями следует различать операции над самим указателем и операции над значением по адресу, который он хранит.


```c


int a = 10;

int *pa = &a;

int b = *pa + 20;	// операция со значением, на который указывает указатель

pa++; 				// операция с самим указателем

	

printf("b=%d \n", b);	// 30
```



выражение разыменования `*pa` даёт значение, на которое указывает pa, то есть число 10, и к нему применяется сложение. здесь выполняется обычное сложение двух целых чисел, поскольку `*pa` является lvalue типа int.



особого внимания требуют инкремент и декремент. префиксные операции ++ и --, как и разыменование *, относятся к унарным операциям одного приоритета и группируются справа налево. постфиксные ++ и -- имеют более высокий приоритет, чем унарная *, поэтому в выражении `*pa++` инкремент также связывается с указателем, а не со значением.



рассмотрим постфиксный инкремент:



```c


int a = 10;

int *pa = &a;

printf("pa: address=%p \t value=%d \n", (void*)pa, *pa);

int b = *pa++;		// инкремент адреса указателя

	

printf("b: value=%d \n", b);

printf("pa: address=%p \t value=%d \n", (void*)pa, *pa);
```



в выражении `b = *pa++;` инкремент применяется к указателю: адрес увеличивается на 4, поскольку указатель имеет тип **int**. результатом постфиксного инкремента является прежнее значение указателя, поэтому разыменование возвращает значение по старому адресу, то есть число 10, и оно присваивается переменной b. результат работы:


 

```consoletext


pa: address=0060FEA4	value=10

b: value=10

pa: address=0060FEA8	value=6356648
```


 

изменим выражение:



```c
b = (*pa)++;
```



скобки меняют порядок вычисления. сначала выполняется разыменование, затем полученное значение увеличивается на 1, и по адресу в указателе теперь хранится 11. поскольку инкремент постфиксный, переменная b получает значение до инкремента, то есть снова 10. в отличие от предыдущего случая, все операции выполняются над значением по адресу, а сам указатель не меняется. соответственно меняется и вывод:


 

```consoletext


pa: address=0060FEA4	value=10

b: value=10

pa: address=0060FEA4	value=11
```


 

аналогично работает префиксный инкремент:


```c
b = ++*pa;
```



здесь разыменование даёт значение по адресу из pa, к нему прибавляется единица, и значение по этому адресу становится равным 11. результат операции присваивается переменной b:


 

```consoletext


pa: address=0060FEA4	value=10

b: value=11

pa: address=0060FEA4	value=11
```


 

изменим выражение:



```c
b = *++pa;
```



теперь сначала меняется адрес в указателе, затем по новому адресу читается значение и присваивается переменной b. полученное значение может быть неопределённым:



```bash


pa: address=0060FEA4	value=10

b: value=6356648

pa: address=0060FEA8	value=6356648
```



### указатели на void



отдельного рассмотрения заслуживают указатели на тип void. void является неполным типом (incomplete type), который невозможно сделать полным, поэтому компилятор не знает его размера. за указателем на `void` может скрываться объект любого типа. пример:



```c


#include <stdio.h>



int main(void)

{

    int num1 = 11;

    int num2 = 12;

    int num3 = 13;

    int num4 = 14;

    void* p_num = &num1;

    printf("*p_num: %d\n", *(int*)(p_num+8)); 



    return 0;

}
```



здесь определены 4 числа типа int. значения размещаются в стеке и в типичной реализации располагаются в памяти последовательно, примерно так:



| Переменная | Условный адрес в памяти |
| --- | --- |
| int num1 = 11; | 0xff00 |
| int num2 = 12; | 0xff04 |
| int num3 = 13; | 0xff08 |
| int num4 = 14; | 0xff0c |



адреса условны, существенно лишь то, что значения идут по порядку, и адрес каждого следующего отличается от предыдущего на 4 (размер типа int). при этом стандарт такого расположения не гарантирует: порядок и выравнивание локальных переменных остаются на усмотрение компилятора. переменная p_num является указателем на `void` и хранит адрес переменной num1.


```c
void* p_num = &num1;
```



при выводе на консоль к указателю прибавляется 8, результат преобразуется в указатель на `int` и разыменовывается:


```c
printf("*p_num: %d\n", *(int*)(p_num+8));
```



результат программы зависит от компилятора. gcc и clang в качестве расширения считают размер `void` равным 1, поэтому выражение `p_num+8` увеличивает значение указателя на 8, то есть сдвигает его на 8 байт вперёд, к адресу переменной num3. при компиляции свежими версиями gcc получается следующий вывод:


```bash


gcc test.c -o test && ./test

*p_num: 13
```



программа отрабатывает без ошибок. однако формально `void` остаётся неполным типом без размера, и арифметика над `void *` стандартом c запрещена. если скомпилировать ту же программу с флагом **-pedantic**, который включает диагностику отступлений от стандарта, вывод будет другим:


```bash


gcc -pedantic test.c -o test && ./test

test.c: In function ‘main’:

test.c:11:43: warning: pointer of type ‘void *’ used in arithmetic [-Wpointer-arith]

   11 |     printf("*p_num: %d\n", *(int*)(p_num+8));

      |                                           ^

result1: 13
```



программа по-прежнему работает, но появляется предупреждение. это поведение конкретной версии gcc (здесь gcc 13), и как поведёт себя другой компилятор или другая его версия, заранее неизвестно: msvc, например, отвергает такую арифметику. поэтому при необходимости выполнять арифметику над указателем на void его следует сначала привести к указателю на фактический тип данных:



```c
printf("*p_num: %d\n", *(((int*)p_num)+2));
```



здесь p_num сначала преобразуется в указатель на int, а затем к нему прибавляется 2, что означает смещение на два значения int вперёд.
