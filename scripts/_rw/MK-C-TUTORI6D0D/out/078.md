кроме типа `char` для работы с символами в си есть тип **wchar_t** (или "широкий символ"/ "wide character"), который определён в заголовочном файле **stddef.h**. для работы с ним предназначены символьные литералы, которые предваряются префиксом **L**. например:

```c
#include <stdio.h>
#include <stddef.h>
 
int main(void)
{
    wchar_t c = L'A';
    printf("%c - %d \n", c, c); // A - 65
    return 0;
}
```

здесь константа `L'A'` имеет тип wchar_t. и с этим символом также связан некоторый числовой код.

поддержка этого типа определяется реализацией. на linux широкий символ имеет длину 32 бита, что эквивалентно беззнаковому целому числу типа `unsigned int`, и соответственно имеет достаточно места для размещения кодовой точки unicode. но в windows исторически широкий символ имеет длину 16 бит, а не 32, поэтому для этой системы `wchar_t` эквивалентен `unsigned short int`.

это следствие того, что windows приняла utf-16 до расширения unicode за пределы bmp: `wchar_t` там кодирует 16-битные кодовые единицы, а не обязательно одну кодовую точку. стандарт iso c требует лишь, чтобы `wchar_t` мог представить любой широкий символ поддерживаемой реализации; фиксированного размера он не задаёт. заголовок **stddef.h** задаёт сам тип; широкий ввод-вывод объявлен в **wchar.h**.

аналогичным образом можно определять строки из широких символов. для их вывода на консоль применяется спецификатор %ls :

```c
#include <stdio.h>
#include <stddef.h>

int main(void)
{
    wchar_t str[] = L"Hello";
    printf("str: %ls\n", str);
    return 0;
}
```

строковый литерал с префиксом `L` имеет тип `wchar_t[]` и завершается широким нулём `L'\0'`. спецификатор `%ls` в `printf` ожидает указатель на такую последовательность; расхождение размера `wchar_t` между платформами делает двоичную совместимость широких строк между windows и linux невозможной без перекодирования.

### поддержка для utf-8, utf-16 и utf-32

стандарт c11 добавил поддержку символов в кодировках utf-16 и utf-32. начиная со стандарта c23 также добавлена поддержка для кодировки utf-8. для этого в заголовочном файле **uchar.h** были определены соответственно типы **char8_t**, **char16_t** и **char32_t**, которые занимают 1, 2 и 4 байта соответственно.

эти типы, в отличие от `wchar_t`, имеют фиксированную ширину: `char16_t` и `char32_t` совпадают с `uint_least16_t` и `uint_least32_t`. они описывают кодовые единицы соответствующей кодировки, а не «символ» в пользовательском смысле: кодовая точка вне bmp в utf-16 занимает две единицы (суррогатная пара).

при определении символов типа `char16_t` перед символьным литералом указывается префикс **u**, для символов типа `char32_t*` : префикс **U**, а для **char8_t** : префикс **u8**:

```c
#include <stdio.h>
//#include <stddef.h>
#include <uchar.h>
 
int main(void)
{
    char8_t letter8 = u8'N';
    char16_t letter16 = u'Ы';
    char32_t letter32 = U'Ю';
    printf("%c - %d\n", letter8, letter8);
    printf("%c - %d\n", letter16, letter16);
    printf("%c - %d\n", letter32, letter32);
    return 0;
}
```

также можно определять и строки символов этих типов:

```c
#include <stdio.h>
#include <uchar.h>

int main(void)
{
	char16_t utf16_str[] = u"UTF-16 string";
	
	printf("%ls \n", utf16_str);

 	char32_t utf32_str[] = U"UTF-32 string";
	// определяем размер строки utf-32
	int n = sizeof(utf32_str)/4;
	for(int i=0; i < n; i++)
	{
		printf("%lc", utf32_str[i]);
	}

	return 0;
}
```

для вывода строки типа `char16_t` применяется спецификатор `%ls`. а для вывода отдельного символа : спецификатор `%lc.`. но опять же поддержка этих типов определяется конкретной реализацией.

`%ls` и `%lc` исторически рассчитаны на `wchar_t`, а не на `char16_t`/`char32_t`. на linux, где `wchar_t` 32-битный, печать `char16_t[]` через `%ls` даёт неверный результат; на windows, где `wchar_t` 16-битный, `%ls` совпадает с utf-16. переносимый вывод требует преобразования в `wchar_t` или в utf-8 и уже затем узких спецификаторов.

при этом можно использовать числовые коды символов в соответствующей кодировке. например:

```c
#include <stdio.h>
#include <uchar.h>
#include <locale.h>     // для локализации на Windows
 
int main(void)
{
    setlocale(LC_ALL, "");  // для локализации на Windows
    char16_t utf16_str[] = u"\u043F\u0440\u0438\u0432\u0435\u0442"; //u"привет";
     
    printf("%ls \n", utf16_str);    // привет

    char16_t s = u'\u044F';
    printf("%lc\n", s);            // я

    return 0;
}
```

escape-последовательность `\uXXXX` задаёт кодовую точку из bmp (ровно четыре шестнадцатеричные цифры), `\UXXXXXXXX` : из всего пространства unicode. вызов `setlocale(LC_ALL, "")` подключает локаль окружения: без этого широкая печать на windows часто не отображает кириллицу, потому что стартовая локаль "c" не содержит соответствующих многобайтовых преобразований.
