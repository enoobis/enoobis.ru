стек (stack) есть структура данных, подчиняющаяся дисциплине доступа "последним пришёл, первым ушёл" (lifo, last in, first out): единственной доступной позицией для чтения и записи служит вершина. реализаций стека существует много, и значительная часть из них опирается на указатели. препроцессорные макросы c дают ещё один способ: операции над стеком записываются как текстовые подстановки, которые раскрываются до компиляции и не порождают накладных расходов на вызов функции. рассмотрим следующую программу:

```c
#include <stdio.h>

#define SIZE 8  // размер стека

int stack[SIZE];

int* sp = &stack[-1];  // указатель на верхушку стека (на позицию перед стеком)

#define STACK_FULL()  (((sp-stack) + 1) >= SIZE)    // полный стек
#define STACK_EMPTY()  (((sp-stack) + 1) == 0)    // пустой стек

#define STACK_USED() ((sp-stack) + 1)  // сколько мест в стеке использовано
#define CLEAR_STACK (sp = stack - 1)    // сбрасываем стек
#define PUSH(n) (*++sp = (n))   // добавляем в стек
#define POP() (*sp--)       // получаем значение из стека


int main (void)
{
    // добавляем в стек в стек числа от 0 до  10 или до SIZE
    int i = 10; 
    while(!STACK_FULL()){
        PUSH(i);
        i++;
    }
    // выводим содержимое стека
    for(size_t i = 0; i < SIZE; ++i){
        printf("stack[%lu]: %d\n", i, stack[i]);
    }
    // извлекаем данные из стека
    while(!STACK_EMPTY()){
        printf("%d\n", POP());
    }

   return 0;
}
```

стек здесь представлен массивом и указателем на вершину, а операции над ним заданы макросами. разберём основные элементы реализации.

сначала описываются базовые компоненты:

```c
#define SIZE 8
int stack[SIZE];
int* sp = &stack[-1];
```

- константа `SIZE` задаёт ёмкость стека, то есть не более 8 элементов. поскольку это макрос, значение подставляется на этапе препроцессирования и может использоваться как размер массива со статической продолжительностью хранения.

- `stack` представляет массив, в котором хранятся элементы стека.

- `sp` (stack pointer) указывает на текущую вершину стека. в начальном состоянии он указывает на позицию перед первым элементом массива, что кодирует пустой стек. инвариант реализации: число занятых ячеек всегда равно `(sp - stack) + 1`.

далее определяются макросы для работы со стеком:

- `STACK_FULL()` : проверяет, заполнен ли стек

- `STACK_EMPTY()` : проверяет, пуст ли стек

- `STACK_USED()` : возвращает количество элементов в стеке

- `CLEAR_STACK` : очищает стек, возвращая `sp` в начальное состояние; содержимое массива при этом не затирается, меняется лишь логическая граница

- `PUSH(n)` : добавляет элемент в стек, сначала сдвигая указатель (префиксный инкремент), затем записывая значение

- `POP()` : извлекает элемент с вершины стека, сначала читая значение, затем сдвигая указатель (постфиксный декремент)

аргумент `n` в `PUSH` заключён в скобки, чтобы выражение-аргумент не нарушило приоритет операций после подстановки. при этом макрос, в отличие от функции, не защищён от побочных эффектов: аргумент вроде `i++` подставится текстуально, и количество его вычислений определяется телом макроса.

логика функции `main()` распадается на три части:

- заполнение стека: в цикле добавляются числа начиная с 10, пока стек не заполнится (не более 8 элементов).

```c
   int i = 10;
   while(!STACK_FULL()){
       PUSH(i);
       i++;
   }
```

- вывод содержимого стека как массива: здесь просто просматривается массив `stack`, который к этому моменту содержит 8 элементов. такой обход нарушает абстракцию стека, но наглядно показывает физическое расположение данных.

```c
   for(size_t i = 0; i < SIZE; ++i){
       printf("stack[%lu]: %d\n", i, stack[i]);
   }
```

- извлечение из стека: значения последовательно извлекаются и печатаются в порядке, обратном порядку добавления, что и составляет семантику lifo.

```c
   while(!STACK_EMPTY()){
       printf("%d\n", POP());
   }
```

```bash
stack[5]: 15
stack[6]: 16
stack[7]: 17
17

15
14

```

стек, следовательно, можно определить через указатели и макросы без структур и динамической памяти. такой подход полезен для понимания работы с памятью на низком уровне и самого принципа стека. вместе с тем манипуляции с указателями за границами массива, как `&stack[-1]`, потенциально опасны: по стандарту c арифметика указателей определена лишь в пределах массива и позиции сразу за его последним элементом, поэтому формирование адреса перед началом массива формально является неопределённым поведением, даже если по нему не выполняется обращение. на практике распространённые компиляторы обрабатывают такой код ожидаемо, но полагаться на это допустимо лишь при особом контроле, как в данном примере. переносимая альтернатива: хранить индекс вершины, равный `-1` для пустого стека, или указатель на первую свободную ячейку. отметим также, что спецификатор `%lu` для `size_t` переносим не везде; стандартным с c99 является `%zu`.
