обобщения (generics) представляют собой функции или типы, определённые независимо от конкретных типов данных, с которыми они работают; в теории типов эта возможность называется параметрическим полиморфизмом. язык c не поддерживает обобщения на уровне системы типов, в отличие от шаблонов c++ или generics в java и rust. однако средствами препроцессора такую функциональность можно в некоторой степени имитировать. кроме того, в стандарте c11 появилась конструкция **_Generic** (выражение обобщённого выбора), которая упрощает определение обобщённых интерфейсов.



сначала рассмотрим, как с помощью обычных макросов построить подобие универсальных функций и структурных типов. простейший пример: сложение чисел разных типов.



```c


#include <stdio.h>



#define define_sum(T) T sum_##T(T a, T b) {\

 return a + b; \

}



#define sum(T) sum_##T



define_sum(int)

define_sum(float)



int main(void)

{

    printf("float: %f\n", sum(float)(3.0, 2.0));

    printf("int: %d\n", sum(int)(3, 2));

    return 0;

}
```



здесь определены два макроса. первый, `define_sum(T)`, предназначен для определения функции сложения:



```c


#define define_sum(T) T sum_##T(T a, T b) {\

 return a + b; \

}
```



через параметр T передаётся тип данных. оператор препроцессора **##** (конкатенация лексем) присоединяет имя типа к имени функции sum: если в макрос передаётся тип "int", определяется функция "sum_int". для продолжения определения макроса на следующих строках применяется обратная косая черта \, поскольку директива препроцессора по определению занимает одну логическую строку. этот подход работает только для типов, имя которых является одним идентификатором: для `unsigned int` или `char*` конкатенация не даст корректного имени, и такие типы приходится предварительно обозначать через typedef.



второй макрос формирует вызов конкретной функции



```c


#define sum(T) sum_##T
```



например, первый вызов макроса define_sum



```c


define_sum(int)
```



разворачивается в следующий код:



```c


int sum_int(int a, int b) {

 return a + b;

}
```



при обращении ко второму макросу, "sum(T)", выполняется вызов функции:



```c
printf("int: %d\n", sum(int)(3, 2));
```



то есть фактически после препроцессирования получается код:



```c
printf("int: %d\n", sum_int(3, 2));
```



по сути это ручная мономорфизация: для каждого типа порождается отдельная копия функции, как это делают компиляторы c++ и rust при инстанцировании шаблонов, но без проверки типов на уровне обобщённого определения. ошибки обнаруживаются только после подстановки, в развёрнутом коде.



аналогично можно создавать псевдоуниверсальные структуры:



```c


#include <stdio.h>



#define DEFINE_PERSON(T, N) struct Person_##N{\

    T id;\

    char name[20];\

};



DEFINE_PERSON(int, int)

DEFINE_PERSON(char*, char)



#define person(N) struct Person_##N





int main(void)

{

    person(char) tom = {.id="regjh12345", .name="Tom"};

    person(int) bob = {.id=12344, .name="Bob"};



    printf("id: %s  name: %s\n", tom.id, tom.name);

    printf("id: %d  name: %s\n", bob.id, bob.name);

    return 0;

}
```



макрос DEFINE_PERSON разворачивается в определение структуры, в которой тип поля id задаётся параметром макроса. первый параметр задаёт тип поля id, второй служит для формирования уникального имени структуры; отдельный параметр для имени нужен как раз потому, что тип вроде `char*` нельзя напрямую склеить с идентификатором. например, вызов `DEFINE_PERSON(char*, char)` даёт определение следующей структуры:



```c


struct Person_char{

    chr* id;

    char name[20];

};
```



при инициализации в main используются назначенные инициализаторы (`.id=`, `.name=`), введённые в c99.



### конструкция _Generic



в стандарт c11 была добавлена конструкция **_Generic**, которая в ряде случаев позволяет уйти от жёсткой привязки выражений к типам данных. формально это не макрос, а ключевое слово и первичное выражение языка, но применяется оно обычно внутри макросов. выбор нужной ветви выполняется во время компиляции на основании типа выражения, то есть это статическая диспетчеризация без затрат во время выполнения. синтаксис:



```c


_Generic (контролирующее_выражение, список_ассоциаций)
```



первый операнд, `контролирующее_выражение`, задаёт выражение, тип которого сравнивается с типами из второго операнда, `списка ассоциаций`. само контролирующее выражение не вычисляется, используется только его тип, причём после преобразования lvalue и снятия квалификаторов, поэтому `const int` сопоставляется с `int`, а массив с указателем.



второй операнд, `список_ассоциаций`, является списком разделённых запятыми сопоставлений типов и выражений в следующем виде:



```c


тип1 : выражение1,

тип2 : выражение2,

default : выражение по умолчанию
```



тип контролирующего выражения сравнивается с типами из списка ассоциаций, и при совпадении результатом всей конструкции становится соответствующее выражение. остальные выражения не вычисляются. если совпадения нет, выбирается ветвь default, а при её отсутствии возникает ошибка компиляции.



в качестве примера определим функцию, которая складывает два числа, причём числа могут иметь различные типы:



```c


#include <stdio.h>



// определение обобщенной функции sum

#define sum(a, b) _Generic((a), \

	int : sum_int, \

	float : sum_float, \

	default : sum_double \

)(a, b)



// отдельные реализации функции

void sum_int(int a, int b)

{

	printf("Sum of ints: %d\n", a + b);

}

void sum_float(float a, float b)

{

 	printf("Sum of floats: %f\n", a + b);

}

void sum_double(double a, double b)

{

 	printf("Sum of numbers: %lf\n", a + b);

}

int main(void)

{

	int int_num1 = 4;

	int int_num2 = 5;



	float float_num1 = 5.6f;

	float float_num2 = 6.5f;



	double double_num1 = 2.3l;

	double double_num2 = 3.7l;



	sum(int_num1, int_num2);

	sum(float_num1, float_num2);

	sum(double_num1, double_num2);

	

	return 0;

}
```



сначала определяется обобщённая функция `sum()`, не привязанная к конкретным типам:



```c


#define sum(a, b) _Generic((a), \

	int : sum_int, \

	float : sum_float, \

	default : sum_double \

)(a, b)
```



запись `sum(a, b)` означает, что макрос называется "sum" и принимает два параметра.



далее применяется `_Generic`. контролирующим выражением служит `(a)`, то есть выбор определяется типом аргумента `a`, переданного в `sum`.



затем задаётся список ассоциаций: `int : sum_int, float : sum_float, default : sum_double`. если аргумент `a` имеет тип `int`, в качестве реализации `sum()` фактически используется функция `sum_int()`. если тип аргумента `float`, выбирается функция `sum_float`. во всех остальных случаях выбирается функция `sum_double()`.



результатом `_Generic` здесь является обозначение функции, и сразу за ним в скобках указываются аргументы для вызова выбранной функции: `(a, b)`. тип второго аргумента в выборе не участвует: он лишь неявно преобразуется к типу параметра выбранной функции.



после определения обобщённой функции `sum()` определяются конкретные реализации, используемые в зависимости от типа данных:



```c


void sum_int(int a, int b)

{

	printf("Sum of ints: %d\n", a + b);

}

void sum_float(float a, float b)

{

 	printf("Sum of floats: %f\n", a + b);

}

void sum_double(double a, double b)

{

 	printf("Sum of numbers: %lf\n", a + b);

}
```



в функции main вызывается `sum()` с аргументами определённых типов, и по типу первого аргумента выбирается конкретная реализация:



```c


sum(int_num1, int_num2);

sum(float_num1, float_num2);

sum(double_num1, double_num2);
```



в исходном тексте вызывается `sum()`, но после компиляции на каждом месте вызова стоит обращение к функции, предназначенной для соответствующего типа. по сути это перегрузка функций, реализованная средствами языка c; на том же механизме построены обобщённые макросы tgmath.h.



консольный вывод:



```bash


Sum of ints: 9

Sum of floats: 12.100000

Sum of numbers: 6.000000
```
