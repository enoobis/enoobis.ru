**storage class**, или класс хранения, представляет собой спецификатор объявления, задающий время жизни (storage duration) и связывание (linkage) переменных и функций, а через них и доступность имени из разных частей программы. класс хранения сообщает компилятору, где и как размещать объект, каким будет его начальное значение по умолчанию и из каких единиц трансляции к нему можно обратиться.



в c различают четыре основных класса хранения:





- auto

- extern

- static

- register



в предыдущих лекциях эти классы уже частично встречались. здесь их семантика сводится воедино.




класс хранения auto принимается по умолчанию для всех локальных переменных: переменная, объявленная внутри функции или блока без явного спецификатора, получает автоматическую длительность хранения. на практике такие объекты обычно размещаются в кадре стека или в регистрах, хотя стандарт языка конкретного механизма не предписывает. характеристики класса:





- область видимости: имя доступно только в пределах блока, где оно объявлено (блочная область видимости).

- жизненный цикл: объект создаётся при входе в блок и прекращает существование при выходе из него.

- начальное значение: без явной инициализации объект содержит неопределённое ("мусорное") значение, и чтение такого значения до присваивания ведёт к неопределённому или как минимум непредсказуемому поведению.



пример:



```c

void myFunction() {
  int a; // То же самое, что и "auto int a;""
  a = 10;
  // a доступна только внутри myFunction
}
```



поскольку auto для локальных переменных подразумевается, явно его почти не пишут. следует помнить и о расхождении с c++: начиная с c++11 там `auto` означает вывод типа, а в c23 ключевое слово также получило роль вывода типа при объявлении с инициализатором.



## extern



ключевое слово extern (от англ. "external", внешний) служит для **объявления** глобальной переменной или функции, **определение** которой находится в другом месте, как правило в другой единице трансляции. объявление вводит имя и тип, не выделяя память, а определение существует ровно одно на всю программу (правило одного определения). благодаря этому одна и та же глобальная переменная используется в нескольких исходных файлах. характеристики:





- область видимости: глобальная, с внешним связыванием (имя доступно во всём проекте).

- жизненный цикл: статическая длительность хранения, объект существует всё время выполнения программы.

- начальное значение: задаётся в месте определения. если глобальная переменная явно не инициализирована, она получает значение 0, поскольку объекты со статической длительностью хранения инициализируются нулём до начала выполнения.



пример. файл **file1.c** (определение переменной):



```c

#include <stdio.h>

int globalVar = 100; // Определение и инициализация

void printGlobal() {
    printf("globalVar из file1.c: %d\n", globalVar);
}
```



файл **file2.c** (использование внешней переменной):



```c

#include <stdio.h>

extern int globalVar; // Объявление, что переменная определена где-то еще

void displayGlobal() {
    printf("globalVar из file2.c: %d\n", globalVar);
}

int main() {
    displayGlobal();
    // printGlobal(); // Предупреждение или ошибка
    return 0;
}
```



при раздельной компиляции extern сообщает file2.c, что `globalVar` существует, а разрешение ссылки на конкретный адрес откладывается до этапа компоновки (linking). компиляция:



```bash

eugene@Eugene:/workspace/c$ gcc file1.c file2.c -o app && ./app
globalVar из file2.c: 100
```



рассмотрим закомментированную строку:



```c
// printGlobal(); // Предупреждение или ошибка
```



функция `printGlobal()` определена в файле file1.c, однако в file2.c её объявления нет: ни прототипа, ни объявления с extern (для функций extern подразумевается по умолчанию, поэтому достаточно обычного прототипа). если раскомментировать эту строку, результат зависит от компилятора. gcc выдаёт предупреждение:



```bash

eugene@Eugene:/workspace/c$ gcc file1.c file2.c -o app && ./app
file2.c: In function ‘main’:
file2.c:11:5: warning: implicit declaration of function ‘printGlobal’ [-Wimplicit-function-declaration]
   11 |     printGlobal(); // Ошибка компиляции, если не объявлена
      |     ^~~~~~~~~~~
globalVar из file2.c: 100
globalVar из file1.c: 100
```



clang выдаёт ошибку:



```bash

eugene@Eugene:/workspace/c$ clang file1.c file2.c -o app && ./app
file2.c:11:5: error: call to undeclared function 'printGlobal'; ISO C99 and later do not support implicit function declarations [-Wimplicit-function-declaration]
   11 |     printGlobal(); // Ошибка компиляции, если не объявлена
      |     ^
1 error generated.
```



различие объясняется историей стандарта: в c89 вызов необъявленной функции неявно объявлял её как возвращающую `int`, а c99 это правило упразднил. gcc из соображений совместимости по умолчанию ограничивается предупреждением, clang считает такой код ошибкой.



## static




ключевое слово static имеет два применения, и его смысл зависит от контекста: для локальных переменных оно меняет длительность хранения, для глобальных переменных и функций меняет связывание.



### локальные static-переменные



применённый к локальной переменной, static переводит её в статическую длительность хранения, так что значение сохраняется между вызовами функции. характеристики:





- область видимости: локальная, как у `auto` переменных.

- жизненный цикл: объект существует всё время выполнения программы, а не только во время работы функции.

- начальное значение: инициализация выполняется один раз (фактически до запуска программы, поэтому инициализатор должен быть константным выражением). без явной инициализации объект получает значение 0.



```c

#include <stdio.h>

void counter() {
    static int count = 0; // Инициализируется только один раз
    count++;
    printf("Count: %d\n", count);
}

int main() {
    counter(); // Count: 1
    counter(); // Count: 2
    counter(); // Count: 3
    return 0;
}
```



### глобальные переменные и функции со static



применённый к глобальной переменной или функции, static даёт им внутреннее связывание и тем самым ограничивает **область видимости текущим файлом**, точнее текущей единицей трансляции. обратиться к такой переменной или функции из другого файла через `extern` невозможно: компоновщик её имени снаружи не видит. характеристики:





- область видимости: имя переменной или функции доступно только в файле, где оно объявлено.

- жизненный цикл: объект существует всё время выполнения программы.



пример, файл file1.c:



```c

// Файл file1.c
static int secret = 42; // Доступна только в file1.c

static void secretFunction() { // Доступна только в file1.c
    // ...
}
```



такой приём служит средством инкапсуляции на уровне модуля: детали реализации скрываются, а в глобальное пространство имён компоновщика попадает только интерфейс.



## register



класс хранения register представляет собой подсказку компилятору разместить переменную не в оперативной памяти, а в регистре процессора. доступ к регистрам значительно быстрее доступа к памяти, поэтому подсказка в принципе может улучшить производительность. однако современные компиляторы распределяют регистры самостоятельно, выполняя сложный анализ времени жизни значений, и обычно справляются с этим лучше программиста, так что register практически не используется. в c++17 ключевое слово register вообще удалено из языка, в c оно сохраняется.



пример применения:



```c

void fastLoop() {
    register int i; // Просьба к компилятору использовать регистр для i
    for (i = 0; i < 1000000; i++) {
        // ... какая-то быстрая операция
    }
}
```




характеристики этого класса хранения:





- область видимости: локальная.

- жизненный цикл: локальный.

- к `register` -переменной нельзя применить оператор взятия адреса `&`: язык запрещает это независимо от того, оказалась ли переменная фактически в регистре, поскольку у регистра нет адреса в памяти.

```c

#include <stdio.h>

int main() {

    register int i = 0; // Просьба к компилятору использовать регистр для i
    printf("i addr: %p\n", &i);   // здесь будет ошибка
    return 0;
}
```



- компилятор вправе проигнорировать указание, если свободных регистров нет или тип данных не подходит для хранения в регистре.
