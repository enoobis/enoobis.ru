все идентификаторы, определяемые с помощью директив #define, которые предполагают замену на определённую последовательность символов, ещё называют **макросами**. макрос в c есть текстуальная подстановка на этапе препроцессора, а не сущность времени компиляции или выполнения: у него нет типа, области видимости языка и стекового кадра.

макросы позволяют определять замену не только для отдельных символов, но и для целых выражений:

```c


#include <stdio.h>



#define HELLO printf("Hello World! \n")

#define FOR for(int i=0; i<4; i++)



int main(void)

{

	FOR HELLO;

	return 0;

}
```

макрос HELLO определяет вывод на консоль строки "Hello World! \n". макрос FOR определяет цикл, который отрабатывает 4 раза. в итоге после обработки препроцессора функция main будет выглядеть следующим образом:

```c


int main(void)

{

	for(int i=0; i<4; i++) printf("Hello World! \n");

	return 0;

}
```

то есть данный код 4 раза выведет на консоль строку "Hello World! \n". подстановка выполняется до синтаксического анализа компилятором, поэтому макрос FOR сливается с вызовом HELLO в одну инструкцию `for(...) printf(...)`.

подобные определения директивы #define имеют один недостаток: последовательность символов, которая используется директивой, фиксирована. например, здесь везде, где в исходном коде встретится идентификатор HELLO, выводится строка "Hello World!". если требуется динамически передавать строку, то есть строка может быть любой, задаётся макроопределение с параметрами в следующей форме:

```c
#define имя_макроса(список_параметров) последовательность_символов
```

список_параметров здесь это список идентификаторов, разделённых запятыми. между именем макроса и открывающей скобкой не должно быть пробелов: пробел превратил бы конструкцию в объектный макрос, а скобки остались бы частью тела подстановки.

для обращения к макросу применяется конструкция:

```c
имя_макроса(список_аргументов)
```

список_аргументов это набор значений, которые передаются для каждого параметра макроса. в отличие от вызова функции аргументы не приводятся к типам и не вычисляются заранее: они подставляются как последовательность лексем столько раз, сколько параметр встречается в теле.

например, возьмём банальную операцию по выводу чисел на консоль и сократим её с помощью макросов:

```c
#define print(a) printf("%d \n", a)
```

здесь `print` это имя макроса, или идентификатор, после которого в скобках указан параметр `a`. этот параметр будет представлять любое целое число. любой вызов макроса print будет заменяться на строку `printf("%d \n", a)`. на примере это выглядит так:

```c


#include <stdio.h>

#define print(a) printf("%d \n", a)



int main(void)

{

	int x = 10;

	print(x);

	int y =20;

	print(y);

	print(22);

	return 0;

}
```

или более сложный пример: определим макрос `swap(t,x,y)`, который обменивает местами значения двух аргументов типа `t`:

```c


#include <stdio.h>



#define t int

#define swap(t, x, y) { t temp = x; x = y; y=temp;}



int main(void)

{

	t x = 4;

	t y = 10;

	swap(t, x, y)

	printf("x=%d \t y=%d", x, y);

	return 0;

}
```

макрос swap применяет блок для обмена значениями. причём данный макрос фактически универсален: неважно, какой тип у переменных x и y, поскольку `t` тоже подставляется как текст и становится спецификатором типа временной переменной `temp`. фигурные скобки делают тело одной составной инструкцией, чтобы вызов можно было записывать в контексте statement.

или ещё один пример: нахождение минимального значения:

```c


#include <stdio.h>

#define min(a,b) (a < b ? a : b)



int main(void)

{

	int x = 23;

	int y = 14;

	int z = min(x,y);

	printf("min = %d", z);	// min = 14

	return 0;

}
```

то есть после работы препроцессора вместо строки `int z = min(x,y);` получится строка:

```c
int z = (x < y ? x : y);
```

при определении макроса его параметры следует заключать в скобки. иначе подстановка подчиняется приоритету операций языка, а не намерению автора макроса. например, следующая программа:

```c


#include <stdio.h>



#define SQUARE(n) n*n



int main(void)

{

    int x = SQUARE(4+2);



    printf("x = %d\n", x);      // x = 14

    return 0;

}
```

здесь макрос SQUARE принимает один параметр и возводит его в квадрат. однако при вызове макроса

```c
int x = SQUARE(4+2);
```

получится некорректный результат, а именно число 14, а не 36, как ожидалось. потому что данный вызов макроса будет разворачиваться в выражение

```c
int x = 4+2*4+2;
```

умножение имеет более высокий приоритет, чем сложение, поэтому вычисляется `2*4`, а не квадрат суммы. чтобы получить нужный результат, поместим параметры макроса в скобки:

```c


#include <stdio.h>



#define SQUARE(n) (n)*(n)	// параметры в скобках



int main(void)

{

    int x = SQUARE(4+2);



    printf("x = %d\n", x);      // x = 36

    return 0;

}
```

полная форма тела обычно записывается как `((n)*(n))`: внешние скобки защищают макрос как операнд в окружающем выражении, внутренние защищают сам аргумент. даже при скобках аргумент с побочным эффектом, например `SQUARE(i++)`, вычислится дважды.

### препроцессорные операции

при обработке исходного кода препроцессор может выполнять две операции: **#** и **##**.

операция **#** позволяет заключать текст параметра, который следует после операции, в кавычки (stringification): из лексем аргумента формируется строковый литерал.

```c


#include <stdio.h>

#define print_int(n) printf(#n"=%d \n",n);



int main(void)

{

	int x = 23;

	print_int(x);		// x=23

	int y = 14;

	print_int(y);		// y=14

	int number = 203;

	print_int(number);	// number=203

	return 0;

}
```

директива **##** позволяет объединять две лексемы (token pasting): соседние аргументы склеиваются в одну лексему до компиляции.

```c


#include <stdio.h>

#define print(a,b,c) printf("%d", a##b##c);



int main(void)

{

	print(2, 81, 34);	// 28134

	return 0;

}
```

здесь склеиваются три числа, которые передаются в макрос print. или аналогичный пример:

```c


#include <stdio.h>

#define unite(a,b,c) a##b##c;



int main(void)

{

	int x = unite(2, 81, 34);	// 28134

	printf("%d \n", x);

	return 0;

}
```

результат `a##b##c` должен быть допустимой лексемой языка: идентификатором, числом и т.д. некорректная склейка даёт ошибку на этапе препроцессора или компиляции.
