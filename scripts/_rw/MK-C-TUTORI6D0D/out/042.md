препроцессор является обязательной составной частью реализации языка c. в целом процесс построения программы на c разбивается на три этапа:

- препроцессор

- компиляция

- линковка

препроцессор обрабатывает исходный текст программы до собственно компиляции. он работает на уровне лексем и строк текста и ничего не знает о типах, областях видимости и прочей семантике языка. результатом его работы является полный текст единицы трансляции, который передаётся компилятору. в gcc и clang этот промежуточный текст можно получить с помощью флага `-E`.

затем компилятор транслирует обработанный препроцессором исходный код в объектные файлы.

на последнем этапе линкер (компоновщик) объединяет объектные файлы в один исполняемый файл или файл динамической библиотеки, разрешая ссылки на внешние имена между ними.

препроцессором управляют директивы, каждая из которых начинается с символа решётки # и располагается на отдельной строке. препроцессор просматривает текст программы, находит эти директивы и обрабатывает их.

доступны следующие директивы:

- #define : определяет макрос или препроцессорный идентификатор

- #undef : отменяет определение макроса или идентификатора

- #ifdef : проверяет, определён ли идентификатор

- #ifndef : проверяет, что идентификатор не определён

- #include : включает текст из файла

- #if : проверяет условное выражение (аналогично условной конструкции if)

- #else : задаёт альтернативную ветвь для #if

- #endif : завершает условную директиву #if

- #elif : задаёт альтернативное условие для #if

- #line : меняет номер следующей строки, сообщаемый компилятором

- #error : формирует текст сообщения об ошибке трансляции

- #pragma : задаёт действия, зависящие от конкретной реализации компилятора

- # : пустая директива, по сути ничего не делает

далее рассматриваются основные из этих директив.

директива **#include** уже встречалась ранее. она текстуально подставляет в исходный код содержимое указанного файла и имеет следующие формы:

```c
#include <имя_файла> 	// имя файла в угловых скобках
#include "имя_файла"		// имя файла в кавычках
```

например, для консольного ввода-вывода с помощью функций `printf()` или `scanf()` необходимо подключить файл "stdio.h", содержащий объявления этих функций:

```c
#include <stdio.h>
```

при выполнении этой директивы препроцессор вставляет текст файла `stdio.h`. такой файл называется заголовочным. заголовочные файлы содержат прототипы функций, определения и описания типов и констант и имеют расширение **.h**.

файл в угловых скобках ищется в стандартных системных каталогах, а файл в кавычках обычно сначала ищется относительно текущего исходного файла, а затем в тех же системных каталогах (точный порядок поиска определяется реализацией). стандарт языка определяет набор встроенных заголовочных файлов, доступных в любой соответствующей реализации:

- assert.h : отвечает за диагностику программ

- complex.h : для работы с комплексными числами

- ctype.h : отвечает за преобразование и проверку символов

- errno.h : отвечает за проверку ошибок

- fenv.h : для доступа к окружению, которое управляет операциями с числами с плавающей точкой

- float.h : отвечает за характеристики чисел с плавающей точкой

- inttypes.h : для работы с целыми числами фиксированной и максимальной ширины, в том числе макросы форматирования для printf и scanf

- iso646.h : содержит макросы, задающие альтернативные словесные обозначения логических и побитовых операций (and, or, not и т.п.)

- limits.h : содержит предельные значения целочисленных типов

- locale.h : отвечает за работу с локальной культурой

- math.h : для работы с математическими функциями

- setjmp.h : определяет возможности нелокальных переходов

- signal.h : для обработки сигналов, то есть асинхронных событий и исключительных ситуаций

- stdalign.h : для выравнивания типов

- stdarg.h : обеспечивает поддержку переменного числа параметров

- stdatomic.h : для выполнения атомарных операций над данными, разделяемыми между потоками

- stdbool.h : для работы с типом _Bool

- stddef.h : содержит ряд вспомогательных определений

- stdint.h : для работы с целыми числами фиксированной ширины

- stdio.h : для работы со средствами ввода-вывода

- stdlib.h : содержит определения и прототипы функций общего пользования

- stdnoreturn.h : содержит макрос noreturn

- string.h : для работы со строками

- tgmath.h : подключает math.h и complex.h и добавляет типонезависимые (type-generic) макросы для математических вычислений

- threads.h : для работы с потоками

- time.h : для работы с датами и временем

- uchar.h : для работы с символами в кодировке unicode

- wchar.h : для работы с расширенными символами

- wctype.h : содержит дополнительные возможности для классификации и преобразования расширенных символов

в различных средах к этому набору могут добавляться дополнительные заголовочные файлы для тех или иных целей, например для работы с графикой или с интерфейсами операционной системы.

### определение заголовочных файлов

помимо стандартных заголовочных файлов можно подключать и собственные. например, в той же папке, где находится главный файл программы, определим ещё один файл с именем **numbers.c**.

![препроцессор в программе на языке c и подключение файлов с помощью директивы include](/uploads/course-lectures/3cf76c015c709173ca6b9b59257621cab1303f8f.png)

поместим в него следующий код:

```c
int number = 5;
```

здесь определена всего одна переменная. подключим этот файл в главный файл программы, пусть он называется **app.c**:

```c
#include <stdio.h>
#include "numbers.c"
 
int main(void)
{
    printf("Number: %d", number);   // Number: 5
    return 0;
}
```

при подключении собственных файлов их имя указывается в кавычках. хотя в самой программе переменная number не определена, она берётся из подключённого файла **numbers.c**, поскольку препроцессор буквально вставил его текст. в этом примере существенно, что файл numbers.c расположен в одной папке с главным файлом программы.

### определение заголовочных файлов

такой способ работает в gcc, однако в разных средах разработки подключение файлов может вести себя по-разному. в visual studio, например, будет получена ошибка: среда компилирует numbers.c ещё и как отдельную единицу трансляции, и переменная оказывается определена дважды. более правильный подход состоит в том, чтобы поместить объявление объекта (переменной или константы) или функции в отдельный заголовочный файл, а определение объекта или функции оставить в обычном файле с расширением **.c**. так соблюдается правило одного определения, а интерфейс модуля отделяется от реализации.

в файле **numbers.c** уже есть определение переменной number. добавим в ту же папку новый файл **numbers.h**, с тем же именем, но другим расширением.

![подключение заголовочных файлов с помощью директивы include в программе на языке c](/uploads/course-lectures/9bb35e17fbefce3d746cbd03635ff8833ad45a08.png)

поместим в **numbers.h** следующий код:

```c
extern int number;
```

ключевое слово **extern** указывает, что объект является внешним, то есть здесь он только объявляется, а определён в другой единице трансляции. такой заголовок можно подключить в файл исходного кода:

```c
#include <stdio.h>
#include "numbers.h"		// объявление или описание объекта

int main(void)
{
	printf("%d", number);
	return 0;
}
```

чтобы скомпилировать эту программу, компилятору gcc передаются оба файла с исходным кодом, **app.c** и **numbers.c**:

```consoletext
gcc app.c numbers.c -o app.exe && app
```

файлы перечисляются через пробел, каждый компилируется отдельно, а затем все они компонуются в один исполняемый файл.

#### примечание для visual studio

при разработке в **visual studio** файл с исходным кодом (`numbers.c`) подключать не нужно, однако чтобы среда видела функциональность файла в процессе разработки, может потребоваться подключить заголовочный файл (`numbers.h`). при этом заголовочный файл `numbers.h` помещается в папку **Headers Files**.
