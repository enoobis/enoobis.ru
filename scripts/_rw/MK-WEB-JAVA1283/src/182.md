В прошлой статье мы рассмотрели выполнение запросов к модели с помощью метода `promt()`. Однако у этого способа есть недостаток - `prompt()` отдает весь текст ответа целиком лишь после завершения генерации, а генерация ответа модели может занять некоторое время. Но Prompt API также позволяет отображать токены ответа по мере их генерации. Для этого применяется метод **promptStreaming()**, который сразу же возвращает объект потока. Далее, используя этот поток, можно обрабатывать токены ответа по мере их генерации. В общем случае это выглядит так:



```javascript

// Вызываем стриминг
const stream = session.promptStreaming("текст запроса");
            
// Читаем поток отдельными порциями в реальном времени
for await (const chunk of stream) {
    
    console.log(chunk);  // некоторая обработка порций ответа 
}
```



В данном случае `chunk` это отдельная порция ответа в виде строки, которую мы можем как-нибудь обработать. И если планируется разработка приложения как чат-интерфейса, то `promptStreaming()` предпочтительнее из-за удобства для пользователя. Посмотрим на более полном примере:



```xml

<head>

        textarea { width: 100%; height: 80px; margin-bottom: 10px; padding: 8px; box-sizing: border-box; }
        button { padding: 10px 20px; }
        #output { margin-top: 20px; padding: 15px; background: #f5f5f5; border-radius: 5px; white-space: pre-wrap; min-height: 50px; }
    </style>
</head>
<body>
<h2>Тест Prompt API</h2>
    
<textarea id="promptInput" placeholder="Введите ваш запрос к модели..."></textarea>

// Получаем элементы интерфейса
const promptInput = document.getElementById("promptInput");
const sendBtn = document.getElementById("sendBtn");
const output = document.getElementById("output");

async function start(){
    
    // проверяем доступность Prompt API
    if (typeof LanguageModel === "undefined") {
        output.textContent = "Ошибка: Prompt API не поддерживается вашим браузером.";
        return;
    }

    // проверяем доступность модели для выбранных языков
    const availability = await LanguageModel.availability({ languages: ["en", "ru"] });
    if (availability === "unavailable") {
        output.textContent = "Ошибка: Модель для Prompt API не доступна.";
        return;
    }

    // Устанавливаем обработчик клика на кнопку
    sendBtn.addEventListener("click", async () => {

        const text = promptInput.value.trim(); // получаем введенный текст
        if (!text) return;

        // Подготовка интерфейса к загрузке

        // Создаем сессию
        const session = await LanguageModel.create();

        // Вызываем стриминг
        const stream = session.promptStreaming(text);
            
        // Очищаем поле перед выводом
        output.textContent = "";
```

### prompt() или promptStreaming()



Сравним оба способа отправки запроса к модели, поскольку ни один из них не является "лучшим" во всех ситуациях - выбор зависит от конкретной задачи интерфейса. - Метод `session.promptStreaming(text)` Возвращает асинхронный поток (ReadableStream), который вы читаете с помощью цикла `for await...of` . Преимущества: Мгновенный отклик: пользователь видит первые буквы ответа почти сразу. Это создает ощущение быстрой работы приложения. - Улучшенный пользовательский опыт (UX) для чатов: эффект "печатающегося текста" характерен для современных ИИ-интерфейсов. - Контроль над длинной генерацией: чтение потока можно прервать в любой момент, если модель генерирует не то, что нужно. Недостатки:





- Сложность кода: требуется использовать асинхронные циклы, следить за частым обновлением интерфейса (DOM) и корректно обрабатывать обрывы связи внутри потока.

- Трудности с форматированием на ходу: парсинг незаконченных кусков текста в реальном времени сложнее, если требуется преобразовать ответ из Markdown в HTML.


 

- Метод `session.prompt(text)` Возвращает обычный Promise, который переходит в состояние выполненного (resolved) только тогда, когда модель полностью закончила генерацию. Преимущества: Простота реализации: код легко читать и поддерживать.

- Готовый результат: получается полная строка текста. Ее можно сразу отдать обычному Markdown-парсеру, сохранить в базу данных или отправить по API.

- Идеально для фоновых задач: подходит, если интерфейс не важен (например, автоматический перевод текста, классификация писем, генерация тегов).



К недостаткам можно отнести плохой плохой пользовательский опыт при длинных ответах: пользователь будет видеть статичный экран несколько секунд, пока модель генерирует код или статью.


 
 



Принципы выбора того или иного метода можно суммировать в следующей таблице:



| Критерий | prompt() | promptStreaming() |
| --- | --- | --- |
| Для чего лучше подходит Анализ текста, классификация, фоновая обработка, API. Интерактивные чаты, ассистенты, генерация длинных текстов. |  |  |
| Скорость появления первых букв Медленная (нужно ждать весь ответ). Очень быстрая (миллисекунды). |  |  |
| Сложность интеграции Низкая (обычный Promise). Средняя (асинхронный итератор). |  |  |
| Итоговое качество ответа Одинаковое (модель работает одинаково). Одинаковое (модель работает одинаково). |  |  |
