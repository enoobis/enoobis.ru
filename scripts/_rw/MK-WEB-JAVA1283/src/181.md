Prompt API - это экспериментальный API браузера, который позволяет с помощью кода JavaScript делать запросы к встроенной в браузер небольшой локальной языковой модели. Можно применять Prompt API для генерации и анализа текста, создания логики приложения на основе пользовательского ввода, каких-то других задач. Причем сам ввод теоретически может быть реализован как в виде текста, так и в графическом виде с помощью изображений, либо это может быть звуковой ввод. А применяемый API позволяет возвратить результат в структурированном виде, удобном для разбора и анализа. Некоторые сценарии применения Prompt API:





- Поиск на основе ИИ: отвеьы на вопросы на основе содержимого веб-страницы.

- Персонализированные новостные ленты: создание ленты, которая динамически классифицирует статьи по категориям и позволяет пользователям фильтровать контент.

- Настраиваемые фильтры контента. Анализ новостных статей и выделение основных мест на основе заданных пользователем тем.

- Создание событий календаря. К примеру, можно разработать расширение для Chrome, которое автоматически извлекает информацию о событиях с веб-страниц, чтобы пользователи могли создавать записи в календаре всего за несколько шагов.

- Удобное извлечение контактной информации. Создать расширение, которое извлекает контактную информацию с веб-сайтов, упрощая пользователям связь с компанией или добавление информации в список контактов.



Ключевым ограничением Prompt API является то, что пока данная технология находится в экспериментальной стадии. На момент написания текущей статьи ее внедрение ограничивается браузерами на платформе Chromium. В частности, Prompt API уже можно использовать в Google Chrome и Microsoft Edge (по крайней мере в последних версиях). Однако для ее подключения необходимо вручную включить пару флагов в браузере.



Кроме того, Prompt API работает не сам по себе, а использует локальные языковые модели, которые загружает браузер. Для Google Chrome - это Gemini Nano , а для Microsoft Edge - это Phi-4-mini



В третьих, для работы с Prompt API требуются соответствующие аппаратные ресурсы (в зависимости от браузера могут отличаться), и, к примеру, на момент написания текущей статьи работа с моделями поддерживается только в десктопных версиях браузеров.



### Google Chrome и Gemini Nano



Рассмотрим использование Gemini Nano в Google Chrome. Прежде всего, надо отметить требования к оборудованию:





- Поддерживается только десктопная версия браузера. На мобильных устройствах не работает.

- Операционная система: Windows 10 или 11; macOS 13+ (Ventura и выше); Linux; или ChromeOS (начиная с платформы 16389.0.0 и выше) на устройствах Chromebook Plus.

- Хранилище: не менее 22 ГБ свободного места на томе, где находится текущий профиль Chrome. Это формальные требования. В реальности встроенные модели должны быть значительно меньше. Точный размер может незначительно меняться после обновлений. Но, к примеру, Gemini Nano занимает 4 ГБ

- GPU или CPU: Встроенные модели могут работать как с GPU, так и с CPU. GPU: Строго более 4 ГБ видеопамяти. CPU: 16 ГБ оперативной памяти или больше и 4 ядра CPU или больше. API Prompt с аудиовходом требует GPU. Сеть: безлимитный трафик или безлимитное подключение для загрузки (обновления) самой модели и браузера. После загрузки модели подключение не требуется. Сама модель загружается автоматически и устанавливается в виде файла "weights.bin" в подкаталог OptGuideOnDeviceModel: Windows : папка `AppData/Local/Google/Chrome/User Data/OptGuideOnDeviceModel/`

- Linux : папка `$HOME/.config/google-chrome/OptGuideOnDeviceModel/`

- MacOS : папка `~/Library/Application Support/Google/Chrome/OnDeviceHeadSuggestModel`



#### Подлкючение Prompt API



Чтобы задействовать Prompt API, надо включить ряд флагов. Для этого перейдем в браузере по адресу `chrome://flags/` и установим в **Enabled** три флага:





- Enables optimization guide on device

- Prompt API for Gemini Nano

- Prompt API for Gemini Nano with Multimodal Input

После включения данных флагов мы сможем использовать Prompt API в Google Chrome.



### Проверка доступности API



Prompt API доступно через глобальный объект **LanguageModek**. И перед использованием Prompt API в коде веб-страницы или расширения, мы можем проверить доступность API стандартными способами:



```javascript

if (typeof LanguageModel === "undefined") {
    console.log("Prompt API недоступно");
} else {
    console.log("Prompt API доступно");
}
```



Либо так:



```javascript

if (window.hasOwnProperty("LanguageModel")){
    console.log("Prompt API доступно");
}
else{
    console.log("Prompt API недоступно");
}
```



### Проверка доступности модели



API Prompt можно использовать только в том случае, если устройство поддерживает запуск модели, и после того, как языковая модель и среда выполнения модели будут загружены в браузере. Чтобы определить, готова ли модель к использованию, применяется метод **LanguageModel.availability()**. Этот метод возвращает строковое значение, которое указывает на текущий статус готовности локальной модели на устройстве пользователя:





- `"available"` : модель полностью готова к работе

- `"downloadable"` : устройство технически поддерживает ИИ, но файлы языковой модели еще не загружены в браузер. Создание сессии с помощью вызова `LanguageModel.create()` автоматически инициирует скачивание

- `"downloading"` : модель прямо сейчас находится в процессе загрузки на устройство. Использовать ее можно будет сразу после окончания скачивания.

- `"unavailable"` : локальный ИИ недоступен. Это происходит, если железо пользователя не соответствует системным требованиям (мало ОЗУ, нет места на диске), модель не поддерживается для запрошенных языков или функция отключена в настройках браузера



Пример обработки статусов в коде:



```javascript

const availability = await LanguageModel.availability();

console.log(availability);

if (availability == "unavailable") {
    console.log("Модель недоступна");
}
else if (availability == "downloadable" || availability == "downloading") {
    console.log("Модель необходимо загрузить перед использованием");
}
else if (availability == "available") {
    console.log("Модель доступна и может использоваться");
}
```



Но при использовании локальных языковых моделей, даже если они поддерживаются, мы можем столкнуться с проблемой поддержки языков. Для проверки доступности конкретных языков в Prompt API необходимо передавать объект конфигурации с массивом `languages` в качестве аргумента методу `LanguageModel.availability()`:



```javascript

const availability = await ai.languageModel.availability({
  languages: ["en", "ru"] // Проверяем поддержку английского и русского
});
if (availability === "available") {
  // Модель поддерживает и локально хранит указанные языки
}
else{
    ...................
}
```



В массив `languages` передаются коды языков (в формате ISO 639-1). Что касается **Gemini Nano**, то изначально API поддерживал только английский язык ("en"). В последних версиях добавлена поддержка и других распространенных языков, в том числе и русского.



### Создание и завершение сессии



Создание сессии указывает браузеру загрузить языковую модель в память, чтобы ее можно было использовать. Собственно запросы к языковой модели в Prompt API производятся в рамках сессии. Для создания новой сессии применяется метод **LanguageModel.create()**:



```javascript

const session = await LanguageModel.create();
```




### Выполнение запросов к модели



Для выполнения запросов к модели после создания сессии используются методы **session.prompt()** или **session.promptStreaming()**. Вначале посмотрим, как работает `session.prompt()`. В последующих статье отдельно посмотрим на работу `session.promptStreaming()`



Метод **prompt()** возвращает ответ модели, как только он станет доступен. Запрос передается в метод в виде строки через параметр:



```javascript

const result = await session.prompt("Напиши функцию вычисления факториала на языке Rust");

// выводим ответ модели на консоль
console.log(result);
```



### Полный пример



Теперь объединим все вместе и выполним запрос на веб-странице:



```xml

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="utf-8" />
    <title>enoobis.ru</title>
</head>
<body>
<script>
async function start(){

    // проверяем доступность Prompt API
    if (typeof LanguageModel === "undefined") {
        console.log("Prompt API недоступно");
        return;
    }

    // проверяем доступность модели для выбранных языков
    const availability = await LanguageModel.availability({
        languages: ["en", "ru"] // Проверяем поддержку английского и русского
    });
    if (availability == "unavailable") {
        console.log("Модель недоступна");
        return;
    }
    // создаем сессию
    const session = await LanguageModel.create();

    const result = await session.prompt("Напиши функцию вычисления факториала на языке Rust");

    // выводим ответ модели на консоль
    console.log(result);
}

start();
</script>
</body>
</html>
```



Поскольку здесь мы имеем дело с асинхронным кодом, то весь код оформлен в виде отдельной асинхронной функции, которая запускается при запуске веб-страницы. В итоге после запуска веб-страницы в браузере через некоторое время консоль браузера покажет ответ модели:



![prompt api в google chrome](/uploads/course-lectures/ccf2bf2eac9de8b28d13d4cce931d20089e3b831.png)



Стоит отметить, что между отправкой запроса и получением ответа может пройти некоторое время. В этом минус метода **prompt()** Чтобы иметь понимание, что запрос все еще выполняется можно добавить некоторую индикацию, например, с помощью таймера:



```javascript

// перед запросом создаем таймер
const timerId = setInterval(()=>console.log("Модель обрабатывает запрос..."), 5000);

const result = await session.prompt("Напиши функцию вычисления факториала на языке JavaScript");
    
// после выполнения запроса освобождаем ресурсы таймера
clearTimeout(timerId);
```



Однако этот недостаток устраняет другой метод - **promptStreaming()**, который мы далее рассмотрим.




### Завершение сессии



Завершение сессии сообщает браузеру, что языковая модель больше не нужна, и ее можно выгрузить из памяти. Завершить сессию можно двумя способами:





- С помощью метода destroy() :

```javascript

// создаем сессию
const session = await LanguageModel.create();

// некоторая работа с сессией, например, выполнение запросов

// завершаем сессию
session.destroy();
```





- с помощью объекта AbortController :

```javascript

// Создаем объект AbortController
const controller = new AbortController();

// Создаем сессию LanguageModel и передаем объект AbortController, используя опцию signal.
const session = await LanguageModel.create({ signal: controller.signal });

// Позже, возможно, когда пользователь будет взаимодействовать с пользовательским интерфейсом, уничтожаем сессию,
// вызывая функцию abort() объекта AbortController
controller.abort();
```





### Графическое приложение



Добавим завершение сессии. Только теперь вместо простого консольного приложения сделаем графическое, чтобы пользователь мог бы взаимодействовать с моделью через элементы графического интерфейса:



```xml

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="utf-8" />
    <title>enoobis.ru</title>
    <style>
        body { font-family: Arial; max-width: 600px; margin: 20px auto; padding: 0 10px; }
        textarea { width: 100%; height: 80px; margin-bottom: 10px; padding: 8px; box-sizing: border-box; }
        button { padding: 10px 20px; }
        #output { margin-top: 20px; padding: 15px; background: #f5f5f5; border-radius: 5px; white-space: pre-wrap; min-height: 50px; }
    </style>
</head>
<body>
<h2>Тест Prompt API</h2>
    
<textarea id="promptInput" placeholder="Введите ваш запрос к модели..."></textarea>
<button id="sendBtn" disabled="true">Отправить запрос</button>

<h3>Ответ модели:</h3>
<div id="output">Здесь появится ответ...</div>

<script>
// Получаем элементы интерфейса
const promptInput = document.getElementById("promptInput");
const sendBtn = document.getElementById("sendBtn");
const output = document.getElementById("output");

async function start(){
    
    // проверяем доступность Prompt API
    if (typeof LanguageModel === "undefined") {
        output.textContent = "Ошибка: Prompt API не поддерживается вашим браузером.";
        return;
    }

    // проверяем доступность модели для выбранных языков
    const availability = await LanguageModel.availability({ languages: ["en", "ru"] });
    if (availability === "unavailable") {
        output.textContent = "Ошибка: Модель для Prompt API не доступна.";
        return;
    }

    // Устанавливаем обработчик клика на кнопку
    sendBtn.addEventListener("click", async () => {

        const text = promptInput.value.trim(); // получаем введенный текст
        if (!text) return;

        // Подготовка интерфейса к загрузке
        output.textContent = "Думаю...";
        sendBtn.disabled = true;    // на время получения ответа блокируем кнопку

        // Создаем сессию
        const session = await LanguageModel.create();

        // Выполняем запрос к модели
        const result = await session.prompt(text);
            
        // Устанавливаем текст ответа
        output.textContent = result; 

        // Обязательно закрываем сессию и возвращаем кнопку в рабочее состояние
        session.destroy();
        sendBtn.disabled = false;
    });
    sendBtn.disabled = false; // кнопка доступна - можно отправлять запросы
}

start();
</script>
</body>
</html>
```



Здесь используется все те функции, которые были рассмотрены выше. Только теперь пользователь вводит запрос в текстовое поле и отправляет его нажатием кнопки. Когда ответ будет готов, он отобразится во втором - нижнем текстовом поле:
