Объект Temporal.ZonedDateTime представляет дату и время с указанием временной зоны. По сути, он представляет собой комбинацию момента времени, временной зоны и календарной системы. Это единственный класс в Temporal API, который учитывает временные зоны. Добавление временной зоны приводит к существенным отличиям в поведении объектов `ZonedDateTime` от объектов `Temporal.PlainDateTime`.



Временные зоны хранятся в базе данных часовых поясов IANA. Каждая временная зона IANA состоит из нескольких компонентов:

(.+)



- Основной идентификатор временной зоны , который однозначно идентифицирует временную зону. Обычно он относится к географической области, привязанной к городу, например, `Europe/Moscow` (временная зона города Москва), но может также обозначать временнын зоны с одним смещением, такие как UTC (постоянное смещение +00:00) или Etc/GMT+5 (которое по историческим причинам является отрицательным смещением -05:00).

- Определение временной зоны в виде таблицы, которая сопоставляет диапазоны дат/времени UTC с определенными смещениями.

- Вспомогательные идентификаторы временной зоны , которые являются псевдонимами для основного идентификатора. Обычно это исторические названия, которые больше не используются, но сохраняются для совместимости



Temporal API также принимает идентификатор смещения временной зоны, который имеет тот же формат, что и смещение, например, `+05:30, -08, +0600` - все это допустимые идентификаторы смещения. Внутри системы идентификаторы смещения хранятся в формате `±HH:mm`.



Общий формат объектов `ZonedDateTime` в виде строки выглядит следующим образом (результат метода `toString()`):



```browser
YYYY-MM-DD T HH:mm:ss.sssssssss Z/±HH:mm [time_zone_id] [u-ca=calendar_id]
```



Здесь используются следующие компоненты:





- `YYYY` : год - четырехзначное или шестизначное число со знаком + или -.

- `MM` : месяц - двузначное число от 01 до 12.

- `DD` : день - двузначное число от 01 до 31

- `T` (необязательно): разделитель даты и времени, который может быть T, t или пробелом. Присутствует только при наличии `HH` .

- `HH` (необязательно): часы - двузначное число от 00 до 23. По умолчанию 00.


- `mm` (необязательно): минуты -двузначное число от 00 до 59. По умолчанию 00.


- `ss.sssssssss` (необязательно): секунды - двузначное число от 00 до 59. Может дополнительно сопровождаться точкой или точкой и одной-девятью цифрами. По умолчанию - 00. Можно опустить только ss или оба параметра - ss и mm, поэтому время может быть представлено в одном из трех форматов: `HH, HH:mm` или `HH:mm:ss.ssssssss` .


- `Z/±HH:mm` (необязательно): символ `Z` / `z` , либо смещение относительно UTC со знаком + или -, за которым следует тот же формат, что и у компонента времени. Если смещение опущено, оно определяется идентификатором временной зоны. Если оно присутствует, то время также должно быть указано. Причем символ `Z` / `z` означает, что время указано в формате UTC независимо от идентификатора временной зоны, а смещение в формате `±HH:mm` означает, что время указано в местном времени, которое совпадает с UTC+0, и будет проверено на соответствие идентификатору временной зоны.

- `[time_zone_id]` : идентификатор временной зоны (именованный или смещение). Может иметь критический флаг, если перед идентификатором стоит префикс `!` , например, `[!America/New_York]` . Этот флаг обычно сообщает другим системам, что его нельзя игнорировать, если они его не поддерживают.


- `[u-ca=calendar_id]` (необязательно): используемый календарь. По умолчанию используется `[u-ca=iso8601]` . Для получения всех доступных календарей можно использовать выражение `Intl.supportedValuesOf("calendar")` Также может иметь критический флаг ( `!` ), например, `[!u-ca=iso8601]` , который сообщает другим системам, что его нельзя игнорировать, если они его не поддерживают. При этом дата в формате `YYYY-MM-DD` всегда интерпретируется как дата календаря ISO 8601, а затем преобразуется в указанный календарь.



### Определение ZonedDateTime



Можно выделить три основных способа определения/получения объекта `ZonedDateTime`:





- Конструкторы

- Статический метод `Temporal.Now.ZonedDateTimeISO()` , который возвращает текущую дату и время

- Статический метод `Temporal.ZonedDateTime.from()` , который создает объект ZonedDateTime из другого объекта или строки



#### Конструкторы



Для создания `ZonedDateTime` Temporal API предоставляет две функции-конструкторы:



```javascript

new Temporal.ZonedDateTime(epochNanoseconds, timeZone)
new Temporal.ZonedDateTime(epochNanoseconds, timeZone, calendar)
```



Параметры конструкторов:





- `epochNanoseconds` : количество наносекунд, прошедших с начала эпохи Unix (1 января 1970 года, 00:00:00 UTC). Представляет значение `BigInt` (например, `16725312000n` ), так как стандартное число Number в JS не обладает достаточной точностью для наносекунд на больших отрезках времени.

- `timeZone` : идентификатор временной зоны (именованным или смещением)

- `calendar` (необязательный): cтрока, обозначающая используемый календарь (по умолчанию `"iso8601"` ). Для получения всех доступных календарей можно использовать выражение `Intl.supportedValuesOf("calendar")`



Пример определения объекта `ZonedDateTime`:



```javascript

const zdt = new Temporal.ZonedDateTime(1672531200000000000n, "Europe/Volgograd");
console.log(zdt.toString());        // 2023-01-01T03:00:00+03:00[Europe/Volgograd]
```



#### Получение текущих даты и времени



Для получения текущих значений даты и времени в виде объекта `ZonedDateTime` применяется статический метод `Temporal.Now.zonedDateTimeISO()`:



```javascript

const dateTime = Temporal.Now.zonedDateTimeISO();
console.log(dateTime.toString());   // например, 2026-03-19T20:11:14.820209961+03:00[Europe/Volgograd]
```



#### Temporal.ZonedDateTime.from()



Статический метод `Temporal.ZonedDateTime.from()` создает новый объект `ZonedDateTime` из другого объекта `ZonedDateTime`, объекта со свойствами даты и времени или строки RFC 9557.



```javascript

Temporal.ZonedDateTime.from(info)
Temporal.ZonedDateTime.from(info, options)
```



Здесь параметр `info` представляет либо экземпляр `ZonedDateTime`, на основе которого создается новый объект, либо строку в формате RFC 9557 с датой (дополнительно, но необязательно может содержать время и календарь), либо это объект с такими параметрами дат и времени (`calendar, era, eraYear, year, month, monthCode, day, hour, minute, second, millisecond, microsecond, nanosecond`), а также `timeZone` (временная зона) и `offset` (смещение). Как минимум, необходимо явно указывать год (в формате year или era и eraYear), месяц (в формате month или monthCode) и день, а также временную зону, а остальные параметры являются необязательными и будут установлены на значения по умолчанию.




Рассмотрим различные варианты создания `ZonedDateTime`. Создание на основе другого `ZonedDateTime`:



```javascript

const dt = Temporal.ZonedDateTime.from(new Temporal.ZonedDateTime(1672531200000000000n, "Europe/Volgograd"));
console.log(dt.toString()); // 2023-01-01T03:00:00+03:00[Europe/Volgograd]
```



При создании на основе произвольного объекта, в метод передается обычный объект JS, у которого названия свойств соответствуют выше указанным параметрам:



```javascript

const dt = Temporal.ZonedDateTime.from({
    year: 2026,
    month: 3,
    day: 17,
    timeZone: "Europe/Volgograd"
});
console.log(dt.toString()); // 2026-03-17T00:00:00+03:00[Europe/Volgograd]
```



Третий способ - передача строки в формате RFC 9557 - `YYYY-MM-DD T HH:mm:ss.sssssssss Z/±HH:mm [time_zone_id] [u-ca=calendar_id]`, где обязательными являются только три первых компонента (YYYY год, MM - месяц, DD - день) и временная зона:



```javascript

const dt = Temporal.ZonedDateTime.from("2026-03-06T07:40:56[Europe/Volgograd]");
console.log(dt.toString()); // 2026-03-06T07:40:56+03:00[Europe/Volgograd]
```




### Свойства и получение компонентов даты



Для хранения различных компонентов даты и времени объект определяет ряд свойств:





- `calendarId` : строка, которая представляет календарь

- `day` : день месяца (обычно начинается с 1)

- `dayOfWeek` : день недели (начиная с 1). Дни недели нумеруются последовательно от 1 до daysInWeek и зависят от календаря. 1 обычно обозначает понедельник в календаре, даже если в локалях, использующих этот календарь, первым днем ​​недели может считаться другой день

- `dayOfYear` : номер дня в году, начиная с 1. Первый день этого года - 1, а последний день - daysInYear. Зависит от календаря.

- `daysInMonth` : количество дней в месяце

- `daysInWeek` : количество дней в неделе

- `daysInYear` : количество дней в году. Зависит от календаря. Для календаря ISO 8601 это 365, или 366 в високосном году.

- `era` : эра этой даты, или undefined, если календарь не использует эры (например, ISO 8601)

- `eraYear` : год в рамках эры, или undefined, если календарь не использует эры. Индекс года обычно начинается с 1 (более распространенный) или 0, а годы в эре могут уменьшаться со временем (например, григорианский до н.э.)

- `epochMilliseconds` : количество миллисекунд, прошедших с начала эпохи Unix (полночь начала 1 января 1970 г., UTC) до настоящего момента. Эквивалентно делению epochNanoseconds на 1e6 и округлению результата до целого числа.


- `epochNanoseconds` : количество наносекунд (значение типа `BigInt` ), прошедших с начала эпохи Unix до настоящего момента.


- `hour` : час (целое число от 0 до 23)

- `hoursInDay` : количество часов в сутках для данной даты в часовом поясе. В случае изменений смещения, таких как переход на летнее время, оно может быть больше или меньше 24


- `inLeapYear` : логическое значение, которое указывает, находится ли эта дата в високосном году

- `microsecond` : микросекунды даты (число от 0 до 999)

- `millisecond` : миллисекунды даты (число от 0 до 999)

- `minute` : минуты (число от 0 до 59)

- `month` : индекс месяца в году. Первый месяц этого года равен 1, а последний месяц - monthsInYear

- `monthCode` : строка, которая представляет месяц этой даты. Зависит от календаря. Обычно это M плюс двузначный номер месяца

- `monthsInYear` : количество месяцев в году этой даты. Зависит от календаря. Для календаря ISO 8601 это всегда 12, но в других календарных системах это может отличаться.

- `nanosecond` : наносекунды даты (число от 0 до 999)

- `offset` : смещение, используемое для интерпретации внутреннего момента времени, в формате `±HH:mm` (или `±HH:mm:ss.sssssssss` с необходимой точностью до долей минуты)

- `offsetNanoseconds` : смещение в виде количества наносекунд (положительное или отрицательное)


- `second` : секунды даты (число от 0 до 59)

- `timeZoneId` : идентификатор временной зоны

- `weekOfYear` : Виндекс недели (начиная с 1) в yearOfWeek для этой даты, или undefined, если календарь не имеет четко определенной системы недель. Первая неделя года равна 1. Зависит от календаря

- `year` : количество лет этой даты

- `yearOfWeek` : год, который будет сопоставлен с weekOfYear этой даты, или undefined, если календарь не имеет четко определенной системы недель



Например, получим некоторые компоненты текущей даты:



```javascript

const dateTime = Temporal.Now.zonedDateTimeISO();
console.log(dateTime.toString());   // например, 2026-03-19T20:54:44.062655029+04:00[Europe/Volgograd]
console.log(dateTime.day);          // 19
console.log(dateTime.month);        // 3
console.log(dateTime.year);         // 2026
console.log(dateTime.hour);         // 20
console.log(dateTime.minute);       // 54
console.log(dateTime.timeZoneId);   // Europe/Volgograd
console.log(dateTime.offset);       // +04:00
```



### Управление датами и временем



Для управления датами и временем объект `ZonedDateTime` определяет ряд методов:





- `equals()` : возвращает `true` , если эта дата и время эквивалентны по значению другой дате и времени, и `false` в противном случае. При этом учитываются и календари и часовые пояса

- `compare(dateTime1, dateTime2)` (статический метод): возвращает возвращает -1, если dateTime1 предшествует dateTime2, 0, если они совпадают, и 1, если dateTime1 следует за dateTime2. Сравнение производится по исходным значениям даты и времени, без учета календарей, но с учетом временных зон.


- `add()` : сдвигает дату/время вперед на заданную длительность (прибавляет) и результат возвращает в виде нового объекта `ZonedDateTime`

- `subtract()` : сдвигает дату/время на заданную длительность назад (вычитает) и результат возвращает в виде нового объекта `ZonedDateTime`


- `since()` : возвращает новый объект `Temporal.Duration` , который представляет продолжительность от другой даты до текущей. Продолжительность положительна, если другая дата и время предшествует текущей, и отрицательна, если идет после.

- `until()` : возвращает новый объект `Temporal.Duration` , который представляет продолжительность от текущей даты до другой. Продолжительность положительна, если другая дата позже текущей, и отрицательна, если идет раньше.


- `round()` : возвращает объект `ZonedDateTime` , представляющий эту дату и время, округленную до заданной единицы.


- `getTimeZoneTransition()` : возвращает объект `ZonedDateTime` , представляющий ближайщий (как после, так и до) момент перехода, когда изменяется смещение UTC временной зоны, или null, если такого перехода нет. Например, это может быть переход на летнее время.

- `startOfDay()` : возвращает объект `ZonedDateTime` , представляющий первый момент времени этой даты в часовом поясе. Обычно это время 00:00:00, но оно может отличаться, если полночь отсутствует из-за изменений смещения, в этом случае возвращается первое существующее время.



- `with()` : возвращает объект `ZonedDateTime` , в котором некоторые поля текущего объекта заменены новыми значениями.

- `withCalendar()` : возвращает объект `ZonedDateTime` , в котором применяется новая календарная система

- `withTimeZone()` : возвращает объект `ZonedDateTime` , в котором применяется новая временная зона

- `withPlainTime()` : возвращает объект `ZonedDateTime` , в котором часть времени текущего объекта полностью заменена новым временем


- `toInstant()` : возвращает объект `Temporal.Instant` , представляющий текущие дату и время

- `toLocaleString()` : возвращает строку с представлением даты и времени с учетом языка.

- `toPlainDate()` : возвращает объект `Temporal.PlainDate` , представляющий часть даты (год, месяц, день) этой даты и времени в той же календарной системе.

- `toPlainTime()` : возвращает объект `Temporal.PlainTime` , представляющий часть времени (час, минута, секунда и доля секунды).

- `toPlainDateTime()` : возвращает новый экземпляр `Temporal.PlainDateTime` , представляющий ту же дату и время с удалением временной зоны.



### Сравнение даты и времени



Метод `equals()` возвращает `true`, если два объекта эквивалентны с учетом календарей и временных зон, и `false`, если объекты не эквивалентны:



```javascript

const dt1 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 17, timeZone: "Europe/Volgograd"});
const dt2 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 17, hour: 0, minute:0, timeZone: "Europe/Volgograd"});
const dt3 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 17, timeZone: "Europe/Moscow"});

console.log(dt1.equals(dt2));       // true
console.log(dt1.equals(dt3));       // false - разные временные зона (даже при том, что Москва и Волгоград сейчас в одной временной зоне)
```



Статический метод `compare()` позволяет определить, предшествует ли одна дата другой или наоборот - следует за ней. Он возвращает возвращает -1, если первая дата предшествует второй, и 1, если первая дата следует за второй. При равестве двух дат возвращается 0, при этом в отличие от `equals()` календари не учитываются:



```javascript

const dt1 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 17, timeZone: "Europe/Volgograd"});
const dt2 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 17, hour:0, timeZone: "Europe/Volgograd"});

const dt3 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 20, timeZone: "Europe/Volgograd"});
const dt4 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 15, timeZone: "Europe/Volgograd"});
const dt5 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 17, timeZone: "Europe/Belgrade"});

console.log(Temporal.ZonedDateTime.compare(dt1, dt2));  // 0  - даты равны
console.log(Temporal.ZonedDateTime.compare(dt1, dt3));  // -1 - дата dt1 идет перед dt3
console.log(Temporal.ZonedDateTime.compare(dt1, dt4));  // 1  - дата dt1 идет после dt4
console.log(Temporal.ZonedDateTime.compare(dt1, dt5));  // -1 - дата dt1 идет перед dt5 (разные часовые пояса)
```



### Арифметика с датами/временем



Метод `add()` позволяет прибавить к дате некоторую продолжительность времени, а метод `subtract()` - вычесть из дату некоторый временной отрезок. В качестве параметра эти методы принимают объект **Temporal.Duration** или объект со свойствами `years, months, weeks, days, hours, minutes, seconds, milliseconds, microseconds, nanoseconds`, которые представляют продолжительность для добавления или вычитания из текущей даты:



```javascript

const dateTime = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 19, timeZone: "Europe/Volgograd"});

const tomorrow = dateTime.add({days:1});    // добавляем один день
console.log(tomorrow.toString());           // 2026-03-20T00:00:00+03:00[Europe/Volgograd]

const yesterday = dateTime.subtract({days:1});  // вычитаем один день
console.log(yesterday.toString());              // 2026-03-18T00:00:00+03:00[Europe/Volgograd]
```



### Продолжительность между двумя датами



Метод `since()` позволяет узнать, сколько времени пройдет от другой даты до текущей, а метод `until()` - сколько пройдет времени от текущей даты до другой. Оба метода возвращают результат в виде объекта `Temporal.Duration`, который представляет продолжительность между двумя датами:



```javascript

const current = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 19, timeZone: "Europe/Volgograd"});

const date1 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 15, timeZone: "Europe/Volgograd"});
const date2 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 25, timeZone: "Europe/Volgograd"});

// сколько времени от даты date1 до current
const since_date1 = current.since(date1);
console.log(since_date1.toString());        // PT96H - 96 часов (4 дня)

// сколько времени от даты current до date2
const until_date2 = current.until(date2);
console.log(until_date2.toString());        // PT144H - 144 часа (6 дней)
```



По консольному выводу мы видим, что по умолчанию возвращается объект `Duration`, который хранит все время в виде часов. Это может быть неудобно, поскольку в случае выше все часы можно преобразовать без остатка в целое число дней. И с помощью дополнительного необязательного параметра методов мы можем это настроить - мы можем передать вторым параметром объект, в котором свойство `largestUnit` представляет название наибольшего типа единиц измерения. Например, нам надо рассчитать в днях:



```javascript

const current = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 19, timeZone: "Europe/Volgograd"});

const date1 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 15, timeZone: "Europe/Volgograd"});
const date2 = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 25, timeZone: "Europe/Volgograd"});

// сколько времени от даты date1 до current
const since_date1 = current.since(date1, { largestUnit: "days" });
console.log(since_date1.toString());        // P4D - 4 дня

// сколько времени от даты current до date2
const until_date2 = current.until(date2,  { largestUnit: "days" });
console.log(until_date2.toString());        // P6D - 6 дней
```



Стоит отметить, что для этих методов требуется, чтобы оба объекта ZonedDateTime имели одинаковые временные зоны.



### with



Метод `with()` позволяет определить новый объект `ZonedDateTime` на основе текущего, у которого заменены отдельные поля. Это полезно, когда нам надо создать один объект на основе другого, заменив лишь пару свойств. В метод передается объект, свойства которого соответствуют свойствам `ZonedDateTime`:



```javascript

const current = Temporal.ZonedDateTime.from({ year: 2026, month: 3, day: 19, timeZone: "Europe/Volgograd"});

const new_date = current.with({day: 24, month:4});   // меняем день и месяц

console.log(current.toString());      // 2026-03-19T00:00:00+03:00[Europe/Volgograd]
console.log(new_date.toString());     // 2026-04-24T00:00:00+03:00[Europe/Volgograd]
```
