Иногда одна функция в качестве параметра принимает другую функцию - функцию обратного вызова или callback и в процессе своей работы вызывает ее. Например, возьмем функцию быстрой сортировки `qsort`, которая есть в стандартной библиотеке языка C:



```java

void qsort(void *base, size_t nmemb, size_t size, int (*compare)(const void *, const void *));
```



При вызове этой функции ей передаются:





- `base` : массив сортируемых элементов

- `nmemb` : длина массива

- `size` : размер каждого элемента

- `compar` : ​​адрес функции обратного вызова, которая собственно сравнивает два элемента



Последний параметр представляет указатель на функцию, которая вызывается при сравнении двух элементов. С точки зрения API FFM, как и любой указатель, указатель на функцию передается через значение `ValueLayout.ADDRESS`. Однако может возникнуть вопрос, как определить подобную функцию и как передать ее в вызов. Рассмотрим на примере следующей программы:



```java

import java.lang.foreign.*;
import java.lang.invoke.*;
import java.util.Arrays;
import static java.lang.foreign.ValueLayout.*;

public class Program {

    public static void main(String[] args) throws Throwable{

        // получаем линкер/компоновщик 
        Linker linker = Linker.nativeLinker();
        // получаем стандартную библиотеку
        SymbolLookup stdlib = linker.defaultLookup();

        // получаем адрес функции sqort
        MemorySegment qsortAddr = stdlib.findOrThrow("qsort");
        // определяем дескриптор функции
        FunctionDescriptor qsortDesc = FunctionDescriptor.ofVoid(ADDRESS, JAVA_LONG, JAVA_LONG, ADDRESS);
        // void qsort(void*, size_t, size_t, int (*)(const void *, const void *))
        MethodHandle qsort = linker.downcallHandle(qsortAddr, qsortDesc);

        // получаем тип метода
        MethodType compareType = MethodType.methodType(int.class, MemorySegment.class, MemorySegment.class);
        // получаем дескриптор статического метода
        MethodHandle compareHandle = MethodHandles.lookup().findStatic(Program.class, "compareInt", compareType);

        // определяем заглушку для функции
        MemorySegment compareStub = linker.upcallStub(
            compareHandle,
            FunctionDescriptor.of(JAVA_INT,
                ADDRESS.withTargetLayout(JAVA_INT),
                ADDRESS.withTargetLayout(JAVA_INT)),
            Arena.ofAuto());

        // данные для сортировки 
        int[] numbers = {3, 5, 1, 8, 0, 5, 2};

        try (Arena arena = Arena.ofConfined()) {

            // определяем для чисел numbers сегмент памяти
            MemorySegment numbers_seg = arena.allocateFrom(JAVA_INT, numbers);
            qsort.invoke(numbers_seg, numbers.length, JAVA_INT.byteSize(), compareStub);

            // преобразуем сегмент памяти в массив
            numbers = numbers_seg.toArray(JAVA_INT);
            System.out.println(Arrays.toString(numbers));   // [0, 1, 2, 3, 5, 5, 8]
        }
    }

    static int compareInt(MemorySegment a, MemorySegment b) {

        return Integer.compare(a.get(JAVA_INT, 0), b.get(JAVA_INT, 0));
    }
}
```



Рассмотрим поэтапно программный код:





- Допустим, мы хотим, чтобы нативная функция `qsort` для сортировки использовала следующий метод Java: Обратите внимание, что метод предназначен для сортировки целочисленных значений типа `int` , однако параметры представляют значения `MemorySegment`

```java

static int compareInt(MemorySegment a, MemorySegment b) {

    return Integer.compare(a.get(JAVA_INT, 0), b.get(JAVA_INT, 0));
}
```




- Для начала нам нам, как и в общем случае, надо получить дескриптор метода внешней функции:

```java

// получаем линкер/компоновщик 
Linker linker = Linker.nativeLinker();
// получаем стандартную библиотеку
SymbolLookup stdlib = linker.defaultLookup();

// получаем адрес функции sqort
MemorySegment qsortAddr = stdlib.findOrThrow("qsort");
// определяем дескриптор функции
FunctionDescriptor qsortDesc = FunctionDescriptor.of(ADDRESS, JAVA_LONG, JAVA_LONG, ADDRESS);
// void qsort(void*, size_t, size_t, int (*)(const void *, const void *))
MethodHandle qsort = linker.downcallHandle(qsortAddr, qsortDesc);
```




- Чтобы получить адрес этого метода, сначала получаем объект `MemoryHandle` для статического метода Java: Метод `MethodType.methodType` принимает тип возвращаемого значения и далее типы параметров метода. В нашем случае метод сортировки `compareInt` возвращает значение `int` и принимает два значения `MemorySegment`

```java

// получаем тип метода
MethodType compareType = MethodType.methodType(int.class, MemorySegment.class, MemorySegment.class);

// получаем дескриптор статического метода (Program - текущий класс, где располагается метод)
MethodHandle compareHandle = MethodHandles.lookup().findStatic(Program.class, "compareInt", compareType);
```




- С помощью метода `upcallStub()` линкера сгенерируем заглушку для функции C, которая затем вызывает дескриптор метода обратного вызова: Метод `upcallStub()` создает заглушку вызова, которую можно передать другим внешним функциям в виде указателя на функцию. Вызов такого указателя на функцию из внешнего кода приведет к выполнению предоставленного дескриптора метода: Метод принимает до 4 параметров: `target` : дескриптор целевого метода

```java

MemorySegment compareStub = linker.upcallStub(
    compareHandle,
    FunctionDescriptor.of(JAVA_INT,
        ADDRESS.withTargetLayout(JAVA_INT),
        ADDRESS.withTargetLayout(JAVA_INT)),
    Arena.ofAuto());
```

```java

MemorySegment upcallStub(MethodHandle target,
 FunctionDescriptor function,
 Arena arena,
 Linker.Option... options)
```



- `function` : дескриптор функции-заглушки вызываемой функции

- `arena` : арена, связанная с возвращаемым сегментом-заглушкой вызываемой функции

- `options` : параметры линкера, связанные с этим запросом на компоновку



Обратите внимание на вызовы `withTargetLayout()`. Они настраивают структуру памяти, чтобы линкер мог сгенерировать код для настройки экземпляров MemorySegment, которые получает обратный вызов Java. Если этого не сделать, вызовы `a.get(JAVA_INT, 0)` и `b.get(JAVA_INT, 0)` в Java-коллбэке завершатся ошибкой, поскольку сегменты памяти a и b будут иметь нулевой размер.

 


- И в конце можно вызвать внешнюю функцию с адресом коллбэка:

```java

float[] samples = . . .;
MemorySegment csamples = arena.allocateFrom(JAVA_FLOAT, samples);

qsort.invoke(csamples, samples.length, JAVA_FLOAT.byteSize(), compStub);
```






При выполнении программы на вход функции `qsort` передаем массив `{3, 5, 1, 8, 0, 5, 2}` и после выполнения мы увидим консольный вывод отсортированного массива:



```bash
[0, 1, 2, 3, 5, 5, 8]
```
