чтение и запись массива байтов выполняют `ByteArrayInputStream` и `ByteArrayOutputStream`. источником и приёмником служит участок кучи, а не файл и не сокет, поэтому операция сводится к копированию байтов внутри виртуальной машины.

### чтение массива байтов и класс `ByteArrayInputStream`

`ByteArrayInputStream` представляет входной поток, у которого источник данных это массив байтов. конструкторы:

```java


ByteArrayInputStream(byte[] buf) 

ByteArrayInputStream(byte[] buf, int offset, int length)
```

`buf` задаёт массив, из которого идёт чтение. `offset` задаёт смещение от начала массива, `length` задаёт, сколько байтов разрешено прочитать. конструктор с одним аргументом читает переданный массив с начала и до конца и не копирует его: поток и вызывающий код смотрят на один и тот же объект массива. когда доступный диапазон исчерпан, `read` возвращает `-1`, по тому же соглашению, что и конец любого `InputStream`.

чтение массива и вывод на консоль:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        byte[] array1 = new byte[]{1, 3, 5, 7};

        ByteArrayInputStream byteStream1 = new ByteArrayInputStream(array1);

        int b;

        while((b=byteStream1.read())!=-1){

        

            System.out.println(b);

        }

        

        String text = "Hello world!";

        byte[] array2 = text.getBytes();

		// считываем 5 символов

        ByteArrayInputStream byteStream2 = new ByteArrayInputStream(array2, 0, 5);

        int c;

        while((c=byteStream2.read())!=-1){

        

            System.out.println((char)c);

		}

    } 

}
```

первый поток обходит массив `{1, 3, 5, 7}` и печатает байты как числа. второй получает байты строки `"Hello world!"` через `getBytes()` в кодировке платформы по умолчанию и ограничен пятью байтами, начиная со смещения 0. эти байты печатаются приведением к `char`. для кодов 0..127, то есть для ascii этого примера, один байт совпадает с одним символом. в многобайтовой кодировке такое приведение режет символ на части.

потокам с внешним ресурсом `close()` нужен, чтобы отдать дескриптор. `ByteArrayInputStream` внешнего ресурса не держит: массив принадлежит вызывающему коду. метод `close()` у класса есть из-за наследования от `InputStream`, но он не освобождает массив и не запрещает дальнейшее чтение.

### запись массива байт и класс `ByteArrayOutputStream`

`ByteArrayOutputStream` представляет поток вывода, у которого место записи это массив байтов.

объект создаётся одним из конструкторов:

```java


ByteArrayOutputStream() 

ByteArrayOutputStream(int size)
```

конструктор без аргументов выделяет внутренний буфер на 32 байта. конструктор с аргументом выделяет буфер длиной `size`. это начальная ёмкость, а не верхняя граница записи. когда места не хватает, буфер заменяется массивом большей длины, уже записанные байты копируются, а логическая длина потока хранится отдельно от ёмкости и растёт с каждой записью.

применение класса:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        ByteArrayOutputStream baos = new ByteArrayOutputStream();

        String text = "Hello Wolrd!";

        byte[] buffer = text.getBytes();

        try{

            baos.write(buffer);

        }

        catch(Exception ex){

        

            System.out.println(ex.getMessage());

        }

        // превращаем массив байтов в строку

        System.out.println(baos.toString());

        

        // получаем массив байтов и выводим по символьно

        byte[] array = baos.toByteArray();

        for(byte b: array){

        

            System.out.print((char)b);

        }

        System.out.println();

    } 

}
```

у `ByteArrayOutputStream`, как и у других потоков вывода, есть метод `write`. в примере в поток уходит массив байтов строки `"Hello Wolrd!"`. байты ложатся в защищённое поле `buf` типа `protected byte[] buf`. модификатор `protected` открывает буфер наследнику и закрывает его для кода из другого пакета. внешний код забирает данные методами ниже, а не чтением поля.

`write` унаследован от `OutputStream` и объявлен с возможным `IOException`, поэтому вызов стоит в `try..catch`. запись в память у этой реализации исключение не порождает, но сигнатура его декларирует, и компилятор требует обработчик.

`toString()` и `toByteArray()` отдают накопленные байты текстом или массивом. `toByteArray()` копирует в новый массив ровно записанную длину, без незаполненного хвоста ёмкости. `toString()` декодирует те же байты кодировкой платформы по умолчанию. в примере она совпадает с кодировкой `getBytes()`, и исходная строка собирается обратно.

`writeTo` копирует накопленные байты в другой поток. параметр имеет тип `OutputStream`:

```java


ByteArrayOutputStream baos = new ByteArrayOutputStream();

String text = "Hello Wolrd!";

byte[] buffer = text.getBytes();

try{

    baos.write(buffer);

}

catch(Exception ex){

        

    System.out.println(ex.getMessage());

}

try(FileOutputStream fos = new FileOutputStream("hello.txt")){

    

	baos.writeTo(fos);

}

catch(IOException e){

            

    System.out.println(e.getMessage());

}
```

после выполнения в каталоге программы появляется файл `hello.txt`, и в нём строка `Hello Wolrd!`. в файл попадают те байты, которые лежали в `ByteArrayOutputStream`, без отдельного преобразования текста.

для `ByteArrayOutputStream`, как и для `ByteArrayInputStream`, явный `close()` не нужен. закрывать в этом классе нечего: буфер остаётся на месте, а `write`, `toString` и `toByteArray` после `close()` по-прежнему допустимы и `IOException` из-за закрытия не дают.
