### лямбды как параметры методов

лямбда-выражение в java является значением и передаётся в метод наравне с обычными аргументами. тип этого значения задаёт функциональный интерфейс: у такого интерфейса один абстрактный метод, и компилятор приводит лямбду к этому целевому типу. метод ниже принимает не только числа, но и операцию над ними.

```java


public class Program {



    public static void main(String[] args) {

         

        doOperation(10, 4, (a, b) -> a + b);  // 14

        doOperation(10, 4, (a, b) -> a - b);  // 6

        doOperation(10, 4, (a, b) -> a * b);  // 40

    } 



    static void doOperation(int a, int b, Operation op)

    {

        System.out.println(op.execute(a, b));

    }

}

interface Operation{

    int execute(int a, int b);

}
```

для представления лямбд объявлен функциональный интерфейс `Operation`. единственный абстрактный метод `execute()` принимает два числа, выполняет над ними вычисление и возвращает число, то есть результат.

```java


interface Operation{

    int execute(int a, int b);

}
```

метод `doOperation` принимает два числа и ссылку типа `Operation`, то есть некоторую операцию над парой чисел.

```java


static void doOperation(int a, int b, Operation op)

{

    System.out.println(op.execute(a, b));

}
```

в точке объявления `doOperation` конкретная операция ещё не зафиксирована. известна только сигнатура: два аргумента типа `int` и результат типа `int`. какая функция будет вызвана, определяется в месте вызова, когда лямбда приводится к `Operation`. на уровне виртуальной машины вызов связывается через `invokedynamic` и фабрику `LambdaMetafactory`: у полученного экземпляра функционального интерфейса вызывается `execute`, а отдельный именованный класс для каждой операции в исходном тексте не пишется.

в `main` метод `doOperation` вызывается несколько раз, и третьим аргументом каждый раз передаётся своя лямбда. переменную типа `Operation` объявлять не требуется: целевой тип выводится из типа параметра.

```java


doOperation(10, 4, (a, b) -> a + b);  // 14

doOperation(10, 4, (a, b) -> a - b);  // 6

doOperation(10, 4, (a, b) -> a * b);  // 40
```

отдельная переменная не нужна, если выражение участвует в одном вызове. если та же операция нужна повторно, лямбду сохраняют в переменной типа `Operation` и передают уже эту переменную.

следующий пример связывает условие с обходом массива.

```java


public class Program {



    public static void main(String[] args) {

        

        Expression func = (n)-> n%2==0;

        int[] nums = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

        System.out.println(sum(nums, func)); // 20

    } 

    static int sum (int[] numbers, Expression func)

    {

        int result = 0;

        for(int i : numbers)

        {

            if (func.isEqual(i))

                result += i;

        }

        return result;

    }

}



interface Expression{

    boolean isEqual(int n);

}
```

функциональный интерфейс `Expression` задаёт метод `isEqual()`, который возвращает `true`, если для числа `n` выполняется заданное условие. имя метода говорит о равенстве, контракт при этом шире: это любой предикат над `int` с результатом `boolean`.

в классе `Program` метод `sum()` складывает те элементы массива, для которых условие истинно. само условие приходит параметром `Expression func`. при написании `sum` конкретный предикат неизвестен: метод зависит только от контракта `isEqual`. для массива `{1, 2, 3, 4, 5, 6, 7, 8, 9}` и предиката чётности сумма равна 20, что печатает вызов в `main`. само условие записывается лямбдой:

```java
Expression func = (n)-> n%2==0;
```

условие требует чётности: остаток от деления числа на 2 равен 0. выражение сохраняется в `func` и передаётся в `sum`.

тот же метод `sum` принимает и другое условие, записанное прямо в аргументе вызова:

```java


int[] nums = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

int x = sum(nums, (n)-> n > 5); // сумма чисел, которые больше 5

System.out.println(x);	// 30
```

предикат отбирает числа больше 5. сумма `6 + 7 + 8 + 9` равна 30.

### лямбды как результат методов

метод может не только принимать лямбду, но и возвращать её. формальный тип результата снова является функциональным интерфейсом, а лямбда в инструкции `return` приводится к этому типу.

```java


interface Operation{

    int execute(int a, int b);

}



public class Program {

 

    public static void main(String[] args) {

         

        Operation func = action(1);

		int a = func.execute(6, 5);

		System.out.println(a);			// 11

		

		int b = action(2).execute(8, 2);

        System.out.println(b); 			// 6

    } 

	

	private static Operation action(int number){

		switch(number){

			case 1: return (x, y) -> x + y; 

			case 2: return (x, y) -> x - y; 

			case 3: return (x, y) -> x * y; 

			default: return (x,y) -> 0;

		}

	}

}
```

интерфейс `Operation` сохраняет прежний контракт: `execute` принимает два значения типа `int` и возвращает `int`.

метод `action` принимает число-селектор и по нему выбирает лямбду. значение 1 соответствует сложению, 2 вычитанию, 3 умножению. любая другая величина даёт лямбду, которая возвращает 0. возвращаемый тип `action` формально есть `Operation`, поэтому каждая ветвь `switch` возвращает лямбду, совместимую с `execute(int, int)`.

в `main` результат `action` можно сохранить в переменной типа `Operation` и затем вызвать `execute`:

```java


Operation func = action(1);

int a = func.execute(6, 5);

System.out.println(a);			// 11
```

вызов `action(1)` даёт сложение, `execute(6, 5)` возвращает 11.

лямбду можно получить и сразу применить, без промежуточной переменной:

```java


int b = action(2).execute(8, 2);

System.out.println(b); 			// 6
```
