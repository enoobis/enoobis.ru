утверждение (assertion): распространённый защитный приём. в контрольной точке проверяется условие, которое программа считает инвариантом. в java для этого есть оператор `assert`. им отмечают нарушения, при которых продолжать выполнение бессмысленно: сломан внутренний инвариант. внешний ввод, который ещё можно отклонить обычным исключением, этим оператором не разбирают. на практике `assert` оставляют для разработки и тестирования, когда нужно локализовать внутреннюю ошибку. в обычном запуске проверки выключены, и оператор не меняет наблюдаемое поведение.

### оператор assert

у оператора две формы:

```java


assert условие;

assert условие : выражение;
```

в обеих после `assert` стоит булево условие. если поддержка утверждений включена, среда вычисляет условие. ложное условие означает нарушение инварианта, и среда порождает `AssertionError`. этот класс наследует `Error`, то есть относится к непроверяемым исключениям и по смыслу ближе к сбою программы, чем к отказу, который вызывающий код обязан обработать по контракту метода.

во второй форме после двоеточия записывается выражение. его значение передаётся в конструктор `AssertionError` и становится текстом сообщения. если условие истинно, выражение не вычисляется, и побочный эффект в нём не выполнится. то же верно для самого условия, когда утверждения выключены: соответствующий байткод пропускается. полагаться на побочные эффекты внутри `assert` нельзя, иначе поведение при включённых и выключенных проверках разойдётся.

первая форма:

```java


assert n > 0;
```

здесь проверяется, что `n` больше 0. значение 0 и отрицательные значения делают условие ложным и при включённых утверждениях дают `AssertionError` без дополнительного сообщения.

вторая форма:

```java


assert n > 0 : n;
```

условие то же. значение `n` уходит в конструктор `AssertionError` и попадает в сообщение, так что по трассировке видно фактический аргумент.

### включение поддержки assert

по умолчанию оператор `assert` на выполнение не влияет: условие не проверяется и `AssertionError` не возникает. ошибка порождается только если поддержка включена явно в момент запуска. компилятор `javac` сохраняет инструкции `assert` в байткоде всегда, а виртуальная машина решает, исполнять ли их. это решение принимается при старте. на время компиляции оно не влияет. для включения утилите `java` передаётся опция `-enableassertions` или краткая форма `-ea`:

```bash
java -enableassertions Program
```

поддержку можно ограничить отдельными классами и пакетами:

```bash
java -ea:SomeClass -ea:com.mycompany.somelib... Program
```

запись `-ea:SomeClass` включает `assert` в классе `SomeClass`. запись `-ea:com.mycompany.somelib...` включает его в пакете `com.mycompany.somelib` и, за счёт завершающего `...`, во вложенных пакетах.

у пакета по умолчанию имени нет. для него служит отдельная форма:

```bash
-ea:...
```

точечная настройка возможна и в обратную сторону. опции `-disableassertions` и `-da` выключают `assert` в указанных классах и пакетах. распространённое сочетание: включить утверждения широко, затем выключить их в отдельном классе.

```bash
java -ea:... -da: SomeClass Program
```

### пример использования assert

ниже `assert` проверяет предусловие метода, который считает факториал. в примере аргумент обязан быть положительным:

```java


class Program {



    public static void main(String[] args) {

        

        int f1 = factorial(4);

        System.out.println("f1: " + f1);



        int f2 = factorial(-4);

        System.out.println("f2: " + f2);

    } 



    static int factorial(int n){



        assert n > 0;



        int result = 1;

        while(n > 1) result *= n--;

        return result;

    }

}
```

метод `factorial` получает `n` и накапливает произведение в цикле. по принятому в примере предусловию число должно быть больше 0, и это условие записано оператором `assert`:

```java


static int factorial(int n){



    assert n > 0;

    .................
```

в `main` метод вызывается дважды: с допустимым аргументом и с недопустимым.

```java


int f1 = factorial(4);



int f2 = factorial(-4);
```

после компиляции программа запускается с флагом `-enableassertions`:

```bash


eugene@Eugene:/workspace/java$ javac Program.java && java -enableassertions Program

f1: 24

Exception in thread "main" java.lang.AssertionError

	at Program.factorial(Program.java:14)

	at Program.main(Program.java:8)



eugene@Eugene:/workspace/java$
```

первый вызов с аргументом 4 завершается обычным возвратом, в консоль попадает значение 24. второй вызов передаёт -4, условие `n > 0` ложно, и на строке с `assert` (в показанной трассировке это строка 14 метода `factorial`) возникает `AssertionError`. кадр `Program.main` указывает место вызова. такая ошибка на тестировании означает, что данные, попадающие в `factorial`, заранее не проверяются. на стороне вызова тогда добавляют проверку аргумента или иной контроль, чтобы нарушение предусловия не доходило до утверждения.

та же проверка во второй форме передаёт в сообщение значение аргумента. метод меняется так:

```java


static int factorial(int n){



    assert n > 0 : n;



    int result = 1;

    while(n > 1) result *= n--;

    return result;

}
```

выражение `assert n > 0 : n` по-прежнему требует положительный аргумент, а при нарушении помещает фактическое `n` в `AssertionError`. запуск даёт другое сообщение:

```bash


eugene@Eugene:/workspace/java$ javac Program.java && java -enableassertions Program

f1: 24

Exception in thread "main" java.lang.AssertionError: -4

	at Program.factorial(Program.java:14)

	at Program.main(Program.java:8)



eugene@Eugene:/workspace/java$
```

из строки `AssertionError: -4` видно значение, из-за которого условие не выполнилось. текст сообщения может быть и подробнее. строковый операнд после двоеточия попадает в исключение без изменений:

```java
assert n > 0 : "Параметр меньше 1";
```

при включённых утверждениях ложное условие даст `AssertionError` с текстом из этой строки. при выключенных, то есть в запуске без `-ea`, оба вызова пройдут оператор молча. цикл `while (n > 1)` при отрицательном аргументе не выполняется ни разу, и метод вернёт 1, что уже не является факториалом переданного числа. `assert` обнаруживает нарушение инварианта в тестовом запуске и не заменяет проверку внешнего ввода в рабочей программе.
