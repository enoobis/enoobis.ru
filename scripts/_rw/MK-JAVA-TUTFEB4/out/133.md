при компиляции программа на java превращается в набор классов. классы должны лежать в каталогах, которые повторяют пакеты. такое дерево неудобно передавать и подключать. для распространения сделаны файлы jar (java archive, архив java). jar содержит и файлы классов, и другие файлы, например изображения и звук, которые программа затем читает как ресурсы.

jar собирает много файлов в один, и этот один файл проще распространять и подключать к проекту. в jar упаковывают библиотеки, приложения и плагины.

формат jar основан на zip: внутри лежат файлы классов и подкаталоги в сжатом виде, это уменьшает размер. по устройству jar является zip-архивом, и его открывает любая утилита zip. внешняя библиотека с нужной функциональностью обычно поставляется именно файлом jar.

с jar работает утилита `jar`. она ставится вместе с jdk и лежит в каталоге `jdk/bin`. общий вид команды:
```bash

jar options file1 file2 ... fileN
```
команде `jar` сначала передаются опции (options). они задают действие. затем через пробел идут файлы, над которыми действие выполняется. набор параметров совпадает с параметрами команды tar в unix:

- `c`: создаёт новый или пустой архив и добавляет в него файлы. если среди имён есть каталоги, `jar` обходит их рекурсивно

- `C`: временно меняет каталог. следующая команда переходит в подкаталог `classdir` и добавляет оттуда файлы классов
```bash

jar cvf jarFileName.jar -C classdir *.class
```
- `e`: записывает точку входа в манифест, то есть главный класс

- `f`: задаёт имя jar-файла. имя передаётся следующим аргументом командной строки

- `i`: строит индексный файл, чтобы ускорить поиск класса в большом архиве

- `m`: добавляет в jar указанный манифест. у архива есть манифест по умолчанию, этой опцией его заменяют своим

- `M`: запрещает создание файла манифеста

- `t`: показывает оглавление

- `u`: обновляет уже существующий jar-файл

- `v`: включает подробный вывод

- `x`: извлекает файлы. если после опций названы конкретные имена, извлекаются только они. иначе извлекается всё содержимое

- `0`: сохраняет записи без сжатия zip. данные лежат в архиве как есть, распаковка обходится без inflate

### создание jar-файлов

самая частая команда создания нового jar-файла имеет такой синтаксис:
```bash

jar cvf jarFileName file1 file2 ... fileN
```
например, есть файл `Program.java` с коротким кодом:
```java

class Program{

    public static void main(String[] args) {
        
       System.out.println("Hello enoobis.ru");
    }
}
```
сначала файл компилируется компилятором `javac`:
```bash

javac Program.java
```
в результате появляется файл `Program.class`. из этого класса собирается jar-файл:
```bash

jar cvf app.jar Program.class
```
опция `cvf` складывается из трёх флагов: `c` создаёт архив, `v` печатает подробности, `f` берёт имя файла из следующего аргумента. имя результата здесь `app.jar`. полный вывод команды:
```bash

eugene@Eugene:/workspace/java$ jar cvf app.jar Program.class
added manifest
adding: Program.class(in = 425) (out= 292)(deflated 31%)
eugene@Eugene:/workspace/java$
```
после команды в текущем каталоге лежит файл `app.jar`. строка `deflated 31%` в выводе означает степень сжатия zip: запись `Program.class` стала меньше исходного файла класса.

в архив можно передать и конкретный список файлов классов:
```bash

jar cvf app.jar Program.class Person.class Employee.class
```
если нужны все классы из определённого каталога, используется подстановка `*`. в bash, как в примерах этой лекции, оболочка раскрывает звёздочку в список имён до запуска `jar`, и в архив попадает тот набор `.class`, который лежит в каталоге в этот момент:
```bash

jar cvf app.jar *.class
```
в архив попадают все классы текущего каталога. если классы лежат в каталоге пакета, например в `com/enoobis`, в команду входит путь к классам. внутри архива этот путь сохраняется: виртуальная машина ищет класс по имени пакета, и каталоги в jar должны это имя повторять.
```bash

jar cvf app.jar com/enoobis/Program.class com/enoobis/Person.class com/enoobis/Employee.class

// или так 
jar cvf app.jar com/enoobis/*.class
```
### содержимое jar-файла

архив распаковывается любой программой для zip. в linux обычно уже есть утилита unzip:
```bash

eugene@Eugene:/workspace/java$ unzip -l app.jar
Archive:  app.jar
  Length      Date    Time    Name
---------  ---------- -----   ----
        0  2025-09-19 14:23   META-INF/
       62  2025-09-19 14:23   META-INF/MANIFEST.MF
      425  2025-09-19 14:21   Program.class
---------                     -------
      487                     3 files
eugene@Eugene:/workspace/java$
```
опция `-l` говорит утилите `unzip` вывести содержимое архива на консоль и не распаковывать файлы. у архива уже есть структура:

- каталог `META-INF` и файл `MANIFEST.MF`: файл манифеста

- файл `Program.class`: файл основного класса программы

распакованный jar содержит не только классы, но и манифест. каталог `META-INF` зарезервирован форматом: кроме манифеста там лежат подписи и, у многорелизного архива, классы отдельных версий платформы.

### запуск jar-файлов

java запускает jar-файл как программу. утилите `java` передаётся параметр `-jar` и путь к архиву. запуск созданного `app.jar`:
```bash

eugene@Eugene:/workspace/java$ java -jar app.jar
no main manifest attribute, in app.jar
eugene@Eugene:/workspace/java$
```
java файл не запустила. в манифесте архива нет атрибута `Main-Class`, о чём говорит сообщение `no main manifest attribute`. без этого атрибута виртуальная машина не знает, в каком классе лежит точка входа `main`.

исполняемый jar собирается и без ручного файла манифеста. опция `e` команды `jar` сама записывает главный класс:
```bash

jar cvfe app.jar Program Program.class
```
после имени jar-файла передаётся имя класса без расширения `.class`. здесь это `Program`. получается исполняемый jar, его запускает команда `java -jar app.jar`:
```bash

eugene@Eugene:/workspace/java$ java -jar app.jar
Hello enoobis.ru
eugene@Eugene:/workspace/java$
```
имя класса указывается вместе со всеми пакетами, в которых класс лежит. если бы `Program` находился в пакете `com.enoobis`, полное имя было бы `com.enoobis.Program`, и главным классом передавалось бы оно. путь к файлу класса при этом пишется через `/`, а имя класса в аргументе `e` пишется через `.`: это разные записи одного и того же типа.
```bash

jar cvfe app.jar com.enoobis.Program com/enoobis/Program.class
```
в зависимости от настройки операционной системы приложение запускают и двойным щелчком по значку jar-файла.

в windows установщик java создаёт ассоциацию расширения `.jar` с командой `javaw -jar`. команда `javaw` не открывает окно консоли. графической программе отдельное консольное окно обычно не нужно, поэтому ассоциация файлов указывает на `javaw`.

в mac os расширение `.jar` узнаётся системой. двойной щелчок запускает программу java, а та уже открывает jar-файл.

## манифест jar-файла

манифест описывает содержимое архива. он есть у каждого архива. свой файл манифеста можно передать при сборке. если его не передали, манифест создаётся по умолчанию и содержит минимум полей, нужных формату.

файл называется `MANIFEST.MF` и лежит в jar в подкаталоге `META-INF`. это текст. в минимальном виде он содержит версию манифеста в параметре `Manifest-Version`:
```javascript

Manifest-Version: 1.0
```
записей может быть больше. при сборке в создаваемый манифест обычно попадает и версия использованного jdk:
```javascript

Manifest-Version: 1.0
Created-By: 25 (Oracle Corporation)
```
записи манифеста группируются в разделы. первый раздел называется основным и относится ко всему файлу. последующие разделы, если они есть, относятся к отдельным записям архива, например к подписанным файлам. у основного раздела атрибутов больше, чем в минимальном примере. полный перечень приведён в [документации](https://docs.oracle.com/en/java/javase/21/docs/specs/jar/jar.html#jar-manifest). основные из них:

- `Manifest-Version`: версия файла манифеста. значение является допустимым номером версии

- `Created-By`: версия и поставщик реализации java, которой сгенерирован этот файл манифеста. атрибут записывает сама утилита `jar`

- `Signature-Version`: версия подписи jar-файла. значение должно быть допустимой строкой с номером версии

- `Class-Path`: относительные url библиотек, нужных этому приложению. адреса разделяются одним или несколькими пробелами. загрузчик классов приложения строит по значению атрибута свой внутренний путь поиска. адреса разрешаются относительно расположения самого jar. текущий каталог процесса на эти адреса не влияет. подробнее это разобрано в документации, в разделе атрибута `Class-Path`

- `Multi-Release`: определяет, является ли этот jar многорелизным. если значение равно `true`, регистр символов не учитывается, и среда выполнения java вместе с инструментами обрабатывает архив как многорелизный jar. если значение отлично от `true`, атрибут игнорируется. классы конкретных версий платформы лежат в `META-INF/versions`, в подкаталоге с номером версии

- `Main-Class`: имя основного класса приложения. это класс, который загрузчик будет загружать при запуске. имя указывается без расширения `.class`

атрибут `Main-Class` называет класс, с которого начинается программа. один из способов сделать jar исполняемым состоит в том, чтобы записать этот атрибут в файл манифеста. опция `e`, показанная выше, пишет тот же атрибут во время сборки.

### создание и добавление манифеста

простая программа лежит в файле `Program.java`:
```java

class Program{

    public static void main(String[] args) {
        
       System.out.println("Hello enoobis.ru");
    }
}
```
программа компилируется:
```bash

javac Program.java
```
в результате компилируется файл `Program.class`.

затем в той же папке создаётся текстовый файл `manifest.mf`. он служит файлом манифеста и содержит следующее:
```javascript

Manifest-Version: 1.0
Main-Class: Program
```
атрибуту `Main-Class` передаётся имя класса `Program`, без расширения `.class`. имя указывается с учётом всех пакетов, в которых класс расположен. если бы класс `Program` лежал в пакете `com.enoobis`, полное имя класса было бы `com.enoobis.Program`, и в манифесте стояла бы строка `Main-Class: com.enoobis.Program`.

в конце последней строки манифеста нужен перевод строки. без завершающего перевода строка форматом может быть отброшена, и атрибут `Main-Class` до виртуальной машины не дойдёт.

дальше из класса `Program.class` и манифеста `manifest.mf` собирается jar-файл:
```bash

jar cfm app.jar manifest.mf Program.class
```
в итоге получается файл `app.jar`. в манифесте указан главный класс программы, поэтому архив запускается командой `java -jar app.jar`:
```bash

eugene@Eugene:/workspace/java$ java -jar app.jar
Hello enoobis.ru
eugene@Eugene:/workspace/java$
```
### обновление манифеста

манифест существующего jar-файла можно обновить. дополнения помещают в текстовый файл и передают его следующей командой. флаги `ufm` читаются по отдельности: `u` обновляет архив, `f` берёт имя архива из следующего аргумента, `m` берёт манифест из файла. существующие записи манифеста при этом дополняются, архив заново из классов не собирается.
```bash

jar ufm app.jar manifest.mf
```
