обобщения в java дают статическую проверку типов и позволяют писать код, общий для разных аргументов типа. при сочетании наследования и обобщений возникает отдельная трудность: параметризованные типы инвариантны. подстановочный знак (wildcard, метасимвол) задает неизвестный аргумент типа и описывает целое семейство параметризаций там, где конкретный аргумент не нужен.

в обобщениях wildcard обозначает неизвестный тип и записывается вопросительным знаком `?`. он нужен там, где один и тот же код должен принимать разные аргументы типа, не называя их.

существует три вида подстановочных знаков:

- неограниченный wildcard (`?`)

- wildcard с верхней границей, ограниченный базовым классом (`? extends Type`)

- wildcard с нижней границей, ограниченный производным классом (`? super Type`)

разбор идет на классе `Person`.

```java

class Person<T>{

    private T id;
    private String name;

    T getId(){ return id; }
    void setId(T id){ this.id = id; }

    String getName() { return name; }

    Person(T id, String name){

        this.id = id;
        this.name = name;
    }
}
```

тип `Person` обобщенный. параметр `T` задает тип поля `id` и одновременно типы результата `getId` и параметра `setId`. имя хранится отдельно и имеет конкретный тип `String`.

перед введением подстановочного знака разбирается ситуация, в которой программа без него не компилируется.

```java

public class Program{
       
    public static void main(String[] args) {
           
        Person<Object> bob = new Person<>(2.0, "Bob");
        Person<Integer> tom = new Person<>(1, "Tom");
        Person<String> sam = new Person<>("F-456", "Sam");

        printPersonInfo(bob);
        printPersonInfo(tom); // ! ОШибка:  tom - НЕ представляет тип Person<Object>
        printPersonInfo(sam); // ! ОШибка:  sam - НЕ представляет тип Person<Object>
    }

    static void printPersonInfo(Person<Object> person) {

        System.out.print("Name: " + person.getName());
        Object id = person.getId();
        System.out.println(";  Id: " + id);
    }
}
```

компиляция этой программы завершается ошибками в двух вызовах. метод `printPersonInfo` принимает `Person<Object>`. аргумент `Object` кажется достаточным для любого `id`, включая `Integer` и `String`, поскольку оба типа являются подтипами `Object`. инвариантность обобщений устроена иначе. `Person<Integer>` не является подтипом `Person<Object>`, и `Person<String>` тоже не является подтипом `Person<Object>`. отношение подтипа по самому аргументу на параметризованный тип само по себе не переносится. в метод со статическим типом параметра `Person<Object>` можно передать только объект, параметризованный именно `Object`. объект `bob` этому требованию удовлетворяет. объекты `tom` и `sam` этому требованию не удовлетворяют.

фрагмент, который компилятор отвергает:

```java

Person<Integer> tom = new Person<>(1, "Tom");
Person<String> sam = new Person<>("F-456", "Sam");

printPersonInfo(tom); // ! ОШибка:  tom - НЕ представляет тип Person<Object>
printPersonInfo(sam); // ! ОШибка:  sam - НЕ представляет тип Person<Object>
```

подстановочный знак описывает неизвестный аргумент и снимает это ограничение в тех методах, где конкретный тип поля `id` не используется.

массивы в java, для сравнения устройства, ковариантны: `Integer[]` является подтипом `Object[]`, а ошибка несовместимой записи обнаруживается во время выполнения (`ArrayStoreException`). обобщения выбрали инвариантность и вынесли вариантность в место использования, в wildcard, чтобы аналогичная ошибка отвергалась при компиляции.

### неограниченный wildcard (?)

неограниченный wildcard (unbounded wildcard) применяется, когда обобщенный тип нужен, а конкретный аргумент неизвестен или в логике метода не участвует. знак `?` здесь означает любой тип. он уместен, если тело метода не вызывает операцию, зависящую от аргумента типа.

пример:

```java

public class Program{
       
    public static void main(String[] args) {
           
        // Пример использования:
        Person<Integer> tom = new Person<>(123, "Tom");
        Person<String> bob = new Person<>("A-456", "Bob");

        printPersonInfo(tom);   // Name: Tom;  Id: 123
        System.out.println();
        printPersonInfo(bob);   // Name: Bob;  Id: A-456
    }
    static void printPersonInfo(Person<?> person) {
        // Мы можем безопасно вызывать методы, не связанные с дженериком
        System.out.print("Name: " + person.getName());
        
        // Мы можем получить id, но компилятор будет рассматривать его как Object
        Object id = person.getId();
        System.out.println(";  Id: " + id);
    }
}
```

метод `printPersonInfo` выводит сведения об объекте `Person`. тип параметра:

```java
Person<?> person
```

параметр `person` имеет тип `Person` с неизвестным аргументом. какой именно тип скрыт за `?`, методу не важно. поле `id` выводится на консоль через строковое представление, то есть через `toString()`, и конкретный аргумент для этого не нужен. поэтому в метод передается и `Person<Integer>`, и `Person<String>`.

вызовы:

```java

Person<Integer> tom = new Person<>(123, "Tom");
Person<String> bob = new Person<>("A-456", "Bob");

printPersonInfo(tom);   // Name: Tom;  Id: 123
printPersonInfo(bob);   // Name: Bob;  Id: A-456
```

первый вызов печатает имя `Tom` и идентификатор `123`, второй печатает имя `Bob` и идентификатор `A-456`. оба вызова корректны, потому что параметр объявлен как `Person<?>`, а не как `Person<Object>`.

компилятор не знает аргумент типа у `Person<?>`. операции, которые требуют конкретного `T`, для такого значения запрещены. в частности, нельзя вызвать `setId` с обычным аргументом.

```java

public class Program{
       
    public static void main(String[] args) {
           
        // Пример использования:
        Person<Integer> tom = new Person<>(123, "Tom");
        changePerson(tom, 25);
    }
    static void changePerson(Person<?> person, Object id) {

        person.setId(id); // ! ошибка
    }
}
```

вызов `person.setId(id)` отвергается во время компиляции. неограниченный wildcard по правилам чтения и записи близок к верхней границе `? extends Object`. прочитать `getId()` можно только как `Object`. записать в `setId` допустимо лишь `null`, потому что `null` является значением любого ссылочного типа. конкретный `Object` мог бы не совпасть с фактическим аргументом (`Integer`, `String` или любым другим), и компилятор такую запись блокирует.

### wildcard, ограниченный базовым классом (? extends Type)

wildcard с верхней границей, его же называют ограничением сверху или ограничением базовым классом, означает любой тип, который является указанным базовым типом или его подтипом. форма записи:

```java
? extends Type
```

аргумент должен быть самим `Type` или подтипом `Type`.

такая граница нужна, когда значение извлекается из обобщения и дальше используется как базовый тип. по правилу producer extends объект здесь выступает поставщиком данных: из него читают, а не записывают в него значение неизвестного типа.

название "сверху" связано с тем, как обычно рисуют иерархию типов: базовые типы помещают выше производных. `Type` задает верхнюю, крайнюю границу. типы, расположенные строго выше `Type` (базовые по отношению к нему, например `Object`), в множество не входят.

метод ниже принимает только такие объекты `Person`, у которых поле `id` является числом, например `Integer` или `Double`. встроенные числовые типы java наследуют класс `Number`, поэтому верхней границей ставится `Number`.

```java

public class Program{
       
    public static void main(String[] args) {
           
        Person<Integer> tom = new Person<>(10, "Tom");
        Person<Double> bob = new Person<>(25.5, "Bob");

        processNumericId(tom);      // Id as double: 10.0
        processNumericId(bob);      // Id as double: 25.5
    }

    static void processNumericId(Person<? extends Number> person) {
        // Мы можем безопасно "прочитать" id как Number
        Number id = person.getId();
        System.out.println("Id as double: " + id.doubleValue());
    }
}
```

метод `processNumericId` принимает `Person`, параметризованный типом `Number` или подтипом `Number`:

```java
void processNumericId(Person<? extends Number> person)
```

внутри метода компилятор рассматривает `id`, поле типа `T`, как значение с верхней границей `Number`. с ним работают как с `Number`, в том числе вызывают `doubleValue()` и получают `double`. для `Integer` 10 метод печатает `10.0`, для `Double` 25.5 печатает `25.5`. приведение к `Number` не требуется: оно следует из границы wildcard.

следующая пара вызовов некорректна:

```java

public static void main(String[] args) {
           
    Person<String> sam = new Person<>("A-456", "Sam");
    Person<Object> alice = new Person<>(123, "Alice");

    processNumericId(sam);      // ! Ошибка
    processNumericId(alice);    // ! Ошибка
}
```

в вызове `processNumericId(sam)` объект `Person` параметризован типом `String`. `String` не входит в иерархию `Number`, компилятор сообщает об ошибке.

в вызове `processNumericId(alice)` объект параметризован типом `Object`. в иерархии `Object` расположен выше `Number` и является его базовым классом, поэтому `Object` границе `? extends Number` не удовлетворяет. этот вызов также отвергается, хотя фактическое значение идентификатора в листинге и является числом. проверяется статический аргумент типа, а не динамический класс значения.

установить `id` нельзя и тогда, когда передаваемое значение само имеет тип `Number`:

```java

static void setNumericId(Person<? extends Number> person, Number id) {
        
    person.setId(id);  // ! Ошибка
}
```

компилятор не знает, какой именно подтип ожидает объект: `Integer`, `Double` или иной наследник `Number`. значение типа `Number` нельзя безопасно записать ни в одну из этих параметризаций, поэтому вызов `setId` запрещен. единственное ссылочное значение, которое подошло бы любому подтипу, это `null`.

### wildcard с ограничением производным типом (? super Type)

wildcard с нижней границей, его же называют ограничением снизу или ограничением производным типом, означает любой тип, который является указанным типом или его базовым типом. базовым считается тип, расположенный выше по иерархии. для `Integer` прямой базовый тип это `Number`, косвенный базовый тип это `Object`. форма записи:

```java
? super Type
```

аргумент должен быть самим `Type` или его супертипом. подтипы самого `Type` в множество не входят и границей отсекаются.

если нужен метод, который записывает в `id` значение типа `Integer` и при этом принимает и `Person<Integer>`, и `Person` с базовым аргументом (`Number` или `Object`), нижняя граница задается типом `Integer`.

```java

public class Program{
       
    public static void main(String[] args) {
           
        Person<Integer> pInt = new Person<>(1, "Tom");
        Person<Number> pNum = new Person<>(2.0, "Bob");
        Person<Object> pObj = new Person<>("F-456", "Sam");

        setIntegerId(pInt, 100); // OK
        setIntegerId(pNum, 200); // OK
        setIntegerId(pObj, 300); // OK

        // проверка
        System.out.println("pInt Id: " + pInt.getId()); // pInt Id: 100
        System.out.println("pNum Id: " + pNum.getId()); // pNum Id: 200
        System.out.println("pObj Id: " + pObj.getId()); // pObj Id: 300
    }
    static void setIntegerId(Person<? super Integer> person, int newId) {
        // Мы можем безопасно "записать" Integer,
        // так как любой супертип Integer сможет его принять.
        person.setId(newId);
    }
}
```

метод `setIntegerId` получает объект `Person` и новое значение `id` типа `int`. оно упаковывается в `Integer` и передается в `setId`. метод применим к `Person<Integer>`, `Person<Number>` и `Person<Object>`: каждый из этих аргументов типа является супертипом `Integer` либо самим `Integer`, поэтому способен принять значение `Integer`. после трех вызовов идентификаторы равны 100, 200 и 300 соответственно, что и печатает проверка в `main`.

при чтении, например при вызове `getId()`, гарантирован только `Object`. фактический супертип неизвестен и может оказаться `Integer`, `Number` или `Object`, а общий для них всех статический тип, который компилятор может выдать наружу, это `Object`.

```java

public class Program{
       
    public static void main(String[] args) {
           
        Person<Integer> pInt = new Person<>(1, "Tom");
        Person<Number> pNum = new Person<>(2.0, "Bob");
        Person<Object> pObj = new Person<>("F-456", "Sam");

        printPersonId(pInt);
        printPersonId(pNum);
        printPersonId(pObj);
    }

    static void printPersonId(Person<? super Integer> person) {

        // Здесь id - это Object
        Object id = person.getId();

        // Integer id = person.getId();  // так мы не можем написать

        System.out.println(id); 
    }
}
```

присваивание результата `getId()` переменной `Integer` компилятор отвергает, что и отмечено закомментированной строкой в листинге. чтение из `? super Integer` не восстанавливает `Integer`: нижняя граница описывает, что можно записать, а не что будет прочитано.

### принцип pecs

принцип pecs (producer extends, consumer super) фиксирует, какой wildcard выбирать:

- producer extends: объект поставляет данные (операции чтения, как в `getId()`). применяется `? extends Type`

- consumer super: объект потребляет данные (операции записи, как в `setId()`). применяется `? super Type`

чтение через `? extends Type` безопасно, потому что любой подтип границы можно использовать как саму границу. запись через `? super Type` безопасна, потому что значение типа `Type` можно передать в параметр любого супертипа `Type`. одна и та же позиция не может одновременно быть и поставщиком конкретного типа, и его потребителем через wildcard: для чтения и записи одним и тем же конкретным типом нужен именованный аргумент, а не неизвестный.
