**область действия (scope)** и **время жизни (lifetime)** переменных определяют, где к переменным можно получить доступ и как долго они хранятся в памяти. **область действия** переменной представляет собой область кода, где переменная видима и может быть использована. **время жизни** переменной представляет собой период, в течение которого она находится в памяти. локальные переменные существуют только во время выполнения блока или метода, в котором они объявлены, и уничтожаются после завершения блока или метода. переменные экземпляра класса существуют, пока объект, которому они принадлежат, находится в памяти. статические переменные существуют в течение всего времени существования программы. ниже эти различия разобраны по отдельности.

**область действия**, или scope, представляет собой область программы, в которой переменная доступна или видима.

в java переменные получают разные области действия в зависимости от места объявления.

### локальная область действия

переменные, объявленные внутри блока кода, то есть между фигурными скобками `{}`, имеют **локальную область действия** и доступны только внутри этого блока. их используют для временного хранения, и при выходе из блока они уничтожаются:

```java


class Program{

    // метод образует локальную область видимости

    public static void main(String[] args) {  



        // Определяем локальную переменную

        int x = 5;

        // используем переменную x

        System.out.println("x: " + x); 



        // блок образует другую локальную область видимости

        {

            // Еще одна локальная переменная

            int y = 10;

            System.out.println("y: " + y);

        }  // здесь область действия переменной y завершается



        // System.out.println("y: " + y);  // здесь использовать переменную y нельзя



    }   // здесь область действия переменной x завершается



    // метод test образует новую локальную область видимости

    public static void test() {  

        // System.out.println("x: " + x); // здесь использовать переменную x нельзя

    }

}
```

переменная `x` определена как локальная внутри метода `main`. область её действия ограничена этим методом. в другом методе, методе `test`, она недоступна: у вызова `test` собственный кадр и собственный набор локальных имён.

переменная `y` также является локальной, но объявлена внутри вложенного блока, и её область действия ограничена этим блоком. попытка доступа к `y` вне блока приводит к ошибке компиляции, поскольку переменная в этом месте находится вне своей области действия. память под локальные переменные выделяется в кадре вызова метода и освобождается, когда выполнение блока или метода заканчивается.

### область действия класса и переменные экземпляра

переменные, объявленные **на уровне класса**, вне любого метода, в этой лекции называются глобальными. они доступны всем методам и конструкторам класса и потому имеют область действия класса:

```java


class Person{

    // Глобальая переменная (область действия класса)

    String name;

    // Конструктор

    public Person(String name) {

        this.name = name;

    }



    public void print() {

        System.out.println("Name: " + name);

    }

}
```

на уровне класса `Person` определена переменная `name`. к этой переменной обращаются внутри любого метода класса, в любом месте класса, где имя видимо. в java такое имя не является глобальным в том смысле, в каком глобальная переменная языка c видна всей программе. это поле класса. снаружи класса видимость поля задают модификаторы доступа, а внутри класса поле доступно методам и конструкторам.

## время жизни

в java время жизни переменной определяется временем, в течение которого она находится в памяти. локальные переменные, объявленные внутри метода или блока, имеют время жизни, ограниченное выполнением этого метода или блока, и уничтожаются после его завершения.

у переменных, названных здесь глобальными, бывает два типа времени жизни:

- нестатические глобальные переменные, иначе переменные экземпляра или объекта, имеют время жизни, соответствующее времени жизни объекта, которому они принадлежат. такие переменные создаются при создании объекта и уничтожаются при сборке мусора
- статические переменные, объявленные на уровне класса со служебным словом `static`, имеют время жизни на всю программу. они создаются при инициализации класса после его первой загрузки и уничтожаются при завершении программы

пример, где видны оба режима и локальный блок:

```java


class Program{



    public static void main(String[] args) {  



        Person.printCount();    // Count: 0



        Person bob = new Person("Bob");



        {

            Person tom = new Person("Tom");

            tom.printName();    // Name: Tom

        } // здесь формально завершается время жизни объекта tom и его переменной name

        // чуть позже сборщик мусора удалит переменную tom и ее переменную name



        bob.printName();        // Name: Bob





        Person.printCount();    // Count: 2

    } // здесь формально завершается время жизни объекта bob и его переменной name



}  // здесь завершается время жизни статической переменной count



class Person{

    

    String name;  // время жизни - время жизни объекта

    static int count = 0;  // время жизни - время жизни программы



    public Person(String name) {

        this.name = name;

        count++;        // для теста увеличиваем счетчик объектов

    }



    public void printName() {

        System.out.println("Name: " + name);

    }



    public static void printCount() {

        System.out.println("Count: " + count);

    }

}
```

в классе `Person` определены две переменные уровня класса: `name` и `count`. переменная `name` принадлежит объекту, поэтому создаётся отдельно для каждого объекта при создании этого объекта и уничтожается при уничтожении объекта. переменная `count` является статической, поэтому уничтожается при завершении программы.

в `main` формальное время жизни ссылки `tom` заканчивается вместе с блоком. объект, на который она ссылалась, после выхода из блока становится доступен сборщику мусора, но момент самой сборки язык не назначает: комментарий в примере говорит, что сборщик удалит `tom` и её поле `name` чуть позже. поле `name` живёт ровно столько, сколько живёт объект. ссылка `bob` и поле `name` этого объекта доживают до конца `main`. статический `count` увеличивается в конструкторе каждого созданного объекта, поэтому второй вызов `printCount` печатает 2, хотя имя `tom` уже вышло из области действия. счётчик относится к классу и не исчезает вместе с локальной переменной.
