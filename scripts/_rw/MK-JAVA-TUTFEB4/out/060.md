**паттерн типов** (**type pattern**) сопоставляет значение или результат выражения с заданным типом и при успехе связывает это значение с новой переменной уже приведённого типа. шаблон применяется в операторе **instanceof** и в конструкциях **switch**. сопоставление с `instanceof` стало постоянной частью языка в java 16 (jep 394), шаблоны в `switch` в java 21 (jep 441).

### instanceof

в прежней семантике `instanceof` только проверял, принадлежит ли объект указанному типу. в нынешней форме та же проверка при успехе сразу приводит ссылку к сопоставленному типу и записывает её в переменную шаблона. отдельное приведение после проверки не нужно, и переменная видна только на тех путях, где шаблон точно совпал (область видимости по потоку управления). система типов для примеров:

```java


// класс человека

class Person {

     

    private String name;

    String getName() {return name;}

    

    Person(String name){ this.name=name;  }

}





// служащий некоторой компании 

class Employee extends Person{

 

    private String company;  // компания, где работает человек

    String getCompany(){return company;}

     

    Employee(String name, String company) {

     

        super(name);

        this.company = company;

    }

}

// класс клиента банка

class Client extends Person{

       

    private String bank; // банк клиента

    String getBank(){ return bank; }

       

    Client(String name, String bank) {

       

        super(name);

        this.bank = bank;

    }

}
```

применение паттерна типов в `instanceof`:

```java


class Program{

      

    public static void main(String[] args) {

          

        Person tom = new Person("Tom");

        Person bob = new Employee("Bob", "Google");

        Person sam = new Client("Sam", "Sberbank");



        printPerson(tom);       // Person Tom

        printPerson(bob);       // Bob works in Google

        printPerson(sam);       // Sam is client of Sberbank

    }



    static void printPerson(Person person){

        if(person instanceof Employee empl){

        

            System.out.printf("%s works in %s\n", empl.getName(), empl.getCompany());

        }

        else if(person instanceof Client cl){

        

            System.out.printf("%s is client of %s\n", cl.getName(), cl.getBank());

        }

        else{

                                

            System.out.println("Person " + person.getName());

        }

    }

}
```

статический метод `printPerson` получает объект `Person` и оператором `instanceof` проверяет, какому динамическому типу принадлежит ссылка. проверяемое выражение:

```java
person instanceof Employee empl
```

выражение истинно, если `person` является экземпляром `Employee` (включая подтипы, если бы они были). при истинном результате ссылка передаётся переменной `empl` типа `Employee`, и дальше по этой переменной доступны `getName()` и `getCompany()` без приведения. если результат ложен, переменная `empl` в этой ветви не существует. ветвь `Client` устроена так же. если ссылка не подошла ни под `Employee`, ни под `Client`, печатается имя как у обычного `Person`.

тот же шаблон допустим в условии тернарного оператора. переменная шаблона видна только в ветви, которая выполняется при успешном сопоставлении:

```java


class Program{

      

    public static void main(String[] args) {

             

        Person kate = new Client("Kate", "Sberbank");

        printEmplCompany(kate);  // ничего



        Person sam = new Employee("Sam", "Yandex");

        printEmplCompany(sam);  // Yandex



        Person bob = new Employee("Bob", "VK");

        printEmplCompany(bob);  // VK

    }



    static void printEmplCompany(Person p){



        String company = (p instanceof Employee empl) ?  empl.getCompany() : "";

        

        System.out.println(company);

    }

}
```

для `kate` типа `Client` условие ложно, и в `company` попадает пустая строка: метод ничего содержательного не печатает. для `sam` и `bob` ссылка приводится к `Employee`, и печатается компания, `Yandex` и `VK`.

### выражения/конструкции switch

конструкция и выражение **switch** собирают ту же проверку типов в один перебор ветвей, без цепочки `if` и `else if`.

```java


class Program{

      

    public static void main(String[] args) {

          

        Person tom = new Person("Tom");

        Person bob = new Employee("Bob", "Google");

        Person sam = new Client("Sam", "Sberbank");



        printPerson(tom);       // Person Tom

        printPerson(bob);       // Bob works in Google

        printPerson(sam);       // Sam is client of Sberbank

    }



    static void printPerson(Person person){

        switch(person){

            case Employee empl ->

                System.out.printf("%s works in %s\n", empl.getName(), empl.getCompany());

            case Client cl ->

                System.out.printf("%s is client of %s\n", cl.getName(), cl.getBank());

            default ->

                System.out.println("Person " + person.getName());

        }

    }

}
```

ветвь `case Employee empl` делает то же, что оператор `instanceof`: проверяет принадлежность значения типу `Employee` и при успехе кладёт ссылку в переменную `empl`. порядок ветвей существенен. шаблон более общего типа доминирует над шаблоном подтипа: если поставить `case Person` выше `case Employee`, ветвь `Employee` станет недостижимой, и компилятор это отвергнет. в примере сначала идут конкретные подтипы, общий случай остаётся в `default`.

при сопоставлении с типом переменную шаблона указать обязательно. следующая запись незаконна:

```java


switch(person){

    case Employee ->

        System.out.println("Person is Employee");
```

после типа `Employee` нужна переменная. в этой ветви переменная нигде не читается: даже если её объявить, использования нет. тогда на её месте пишут прочерк `_`, безымянную переменную шаблона. безымянные шаблоны и переменные стандартизованы в java 22 (jep 456), в java 21 та же форма доступна как preview.

```java


static void printPerson(Person person){

    switch(person){

        case Employee _ ->

            System.out.println("Person is Employee");

        

        case Client _ ->

            System.out.println("Person is Client");

        

        default ->

            System.out.println("Person " + person.getName());

    }

}
```

ветви `Employee` и `Client` здесь только различают тип и печатают фиксированную строку. имя человека по-прежнему берётся из исходного параметра `person`, потому что безымянный шаблон значение не связывает.

### обработка null

переменная ссылочного типа может хранить `null`. оператор `instanceof` на нулевой ссылке исключение не бросает и возвращает `false`: и проверка типа, и связывание переменной происходят только для ненулевой ссылки подходящего типа. поэтому нулевая ссылка проваливается в последнюю ветвь `else`.

```java


class Program{

      

    public static void main(String[] args) {

          

        Person tom = null;

        Person bob = new Employee("Bob", "Google");

        Person sam = new Client("Sam", "Sberbank");



        printPerson(tom);       // Person is Undefined

        printPerson(bob);       // Employee Bob

        printPerson(sam);       // Person Sam

    }

    static void printPerson(Person person){

        if(person instanceof Employee){

        

            System.out.println("Employee " + person.getName());

        }

        else if(person instanceof Person){

        

            System.out.println("Person " + person.getName());

        }

        else{       // обрабатываем null

                                

            System.out.println("Person Undefined");

        }

    }

}
```

явная проверка на `null` записывается и отдельным сравнением:

```java


else if(person == null){

    System.out.println("Person Undefined");

}
```

даже когда статический тип выражения уже есть `Person`, сравнение с тем же типом через `instanceof` отсекает нулевую ссылку: `null instanceof Person` ложно, и тело ветви для живого объекта `Person` не выполняется.

```java
else if(person instanceof Person){ ....
```

#### switch

классический оператор `switch` по ссылке выбрасывает `NullPointerException`, если выражение селектора равно `null`. в switch с шаблонами нулевая ссылка обрабатывается отдельной меткой `case null`. без этой метки селектор `null` по-прежнему завершает выполнение исключением, а не попадает в `default`.

```java


class Program{

      

    public static void main(String[] args) {

          

        Person tom = null;

        Person bob = new Employee("Bob", "Google");

        Person sam = new Client("Sam", "Sberbank");



        printPerson(tom);       // Person is Undefined

        printPerson(bob);       // Employee Bob

        printPerson(sam);       // Person Sam

    }



    static void printPerson(Person person){

        switch(person){



            case null ->     // обрабатываем null

                System.out.println("Person is Undefined");



            case Employee _ ->

                System.out.println("Employee " + person.getName());



            default ->

                System.out.println("Person " + person.getName());

        }

    }

}
```

метка `case null` печатает, что человек не задан. `Employee` печатает имя служащего. любая другая ненулевая ссылка, в примере это `Client` и простой `Person`, попадает в `default`.

### защитные условия паттерна или guards

к шаблону добавляют дополнительное условие, **guard**. ветвь выбирается, только если совпал и тип, и это условие.

#### instanceof

при `instanceof` охрана записывается дальше по конъюнкции. переменная шаблона уже видна справа от `&&`, потому что до этого места шаблон обязан был совпасть:

```java


class Program{

      

    public static void main(String[] args) {

          

        Person bob = new Employee("Bob", "Yandex");

        Person sam = new Employee("Sam", "Sberbank");

        Person tom = new Person("Tom");



        printPerson(bob);       // Employee Bob works in Yandex

        printPerson(sam);       // Employee Sam

        printPerson(tom);       // Person Tom

    }

    static void printPerson(Person person){



        // по цепочке используем переменную empl

        if(person instanceof Employee empl && empl.getCompany() == "Yandex"){

        

            System.out.println("Employee " + empl.getName() + " works in Yandex");

        }

        else if(person instanceof Employee){

        

            System.out.println("Employee " + person.getName());

        }

        else if(person instanceof Person){

                                

            System.out.println("Person " + person.getName());

        }

    }

}
```

разбираемое выражение:

```java


if(person instanceof Employee empl && empl.getCompany() == "Yandex"){



    System.out.println("Employee " + empl.getName() + " works in Yandex");

}
```

объект `person` должен иметь тип `Employee`, и компания этого служащего должна быть `"Yandex"`. подвыражение `empl.getCompany() == "Yandex"` и есть guard, условие шаблона. блок `if` выполняется, когда условие истинно. оператор `==` сравнивает ссылки на строки. равенство содержимого задаёт метод `equals`. во фрагменте оба операнда являются литералом `"Yandex"` либо значением, которое в этих примерах тоже задано литералом, поэтому сравнение ссылок совпадает с ожидаемым текстом. если условие ложно, выполняется следующая ветвь, уже без охраны:

```java


else if(person instanceof Employee){

        

    System.out.println("Employee " + person.getName());

}
```

сюда попадает любой `Employee`, чья компания не совпала с `"Yandex"`, в примере это `Sam` из `Sberbank`. `Tom` типа `Person` до этой ветви не доходит и печатается последней ветвью как обычный человек.

#### switch

в `switch` охрана вводится ключевым словом **when**:

```java


class Program{

      

    public static void main(String[] args) {

          

        Person bob = new Employee("Bob", "Yandex");

        Person sam = new Employee("Sam", "Sberbank");

        Person tom = new Person("Tom");



        printPerson(bob);       // Employee Bob works in Yandex

        printPerson(sam);       // Employee Sam

        printPerson(tom);       // Person Tom

    }



    static void printPerson(Person person){

        switch(person){



            case Employee empl when empl.getCompany() == "Yandex" ->

                System.out.println("Employee " + empl.getName() + " works in Yandex");



            case Employee _ ->

                System.out.println("Employee " + person.getName());



            case Person _ ->

                System.out.println("Person " + person.getName());

        }

    }

}
```

условие шаблона здесь записано так:

```java
when empl.getCompany() == "Yandex"
```

это та же защита, что и конъюнкция при `instanceof`: тип `Employee` и компания `"Yandex"`.

охрана может соединять несколько подусловий:

```java


switch(person){

    case Employee empl 

        when empl.getCompany() == "Yandex" && empl.name == "Bob" ->

            System.out.println("Bob works in Yandex");
```

ветвь `case` выполняется, если `person` имеет тип `Employee`, имя равно `"Bob"` и компания равна `"Yandex"`. во фрагменте поле `name` читается как `empl.name`. в объявлении `Person` поле `name` закрыто, поэтому такой доступ компилируется только из кода, которому закрытое поле видно. смысл охраны от этого не меняется: совпасть должны оба компонента состояния.
