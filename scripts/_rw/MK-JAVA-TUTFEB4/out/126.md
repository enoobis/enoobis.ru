с выходом jdk 9 в java появилась модульность. код делится на модули: модуль собирает пакеты и ресурсы в одну единицу и адресуется по имени. поддержку даёт подсистема java platform module system, она входит и в язык, и в виртуальную машину. компилятор и загрузчик классов строят граф модулей и проверяют его и при компиляции, и при запуске.

до java 9 инкапсуляция держалась на двух уровнях. класс закрывает поля и методы модификаторами доступа. пакет собирает классы, но почти не ограничивает внешний доступ: член без модификатора виден только внутри пакета, а тип с модификатором `public` виден любому коду с пути классов. для платформы и крупных библиотек этого стало мало: нельзя было объявить, какой пакет входит в контракт, а какой остаётся деталью реализации. модуль добавил следующий уровень и объединяет несколько пакетов.

### определение модуля

модуль состоит из группы пакетов. в дескрипторе перечисляются пакеты, которые модуль отдаёт наружу, и модули, от которых он зависит. дополнительно, уже без обязательности, модуль может содержать файлы ресурсов и нативные библиотеки. принадлежность пакета модулю определяется тем, что пакет скомпилирован в этот модуль. пакеты без директивы `exports` в модуле остаются, но в его публичный контракт не входят.

имя модуля задаётся идентификатором из букв, цифр и знаков подчёркивания. по соглашению берут обратное доменное имя (reverse domain name), как и для пакетов. желательно, чтобы имя модуля совпадало с префиксом имён его пакетов: так реже сталкиваются имена пакетов из разных модулей. один и тот же пакет размещается только в одном модуле. размещение одного пакета сразу в двух модулях запрещено, такой конфликт называется split package. при уникальных именах модулей и общем префиксе имена пакетов тоже остаются уникальными.

простейший модуль собирается так. исходные файлы помещаются в каталог `C:\java` или `Home/java`, либо в другой каталог на диске. в нём создаётся каталог `demo`. по соглашению имя корневого каталога совпадает с именем модуля.

в каталоге `demo` создаётся файл `module-info.java`:
```java
module demo {
}
```
этот файл является дескриптором модуля (module descriptor) и содержит только объявление модуля.

ключевое слово `module` объявляет модуль `demo`, с тем же именем, что и каталог, в котором лежит файл. фигурные скобки задают тело модуля. в этом дескрипторе тело пустое: нет ни зависимостей, ни экспорта. код самого модуля своими пакетами пользуется и без `exports`. другим модулям такие пакеты не видны.

дальше в каталоге `demo` создаётся каталог `com`, в нём каталог `enoobis`, в нём каталог `hello`. путь к исходному файлу получается `com/enoobis/hello`.

в каталоге `com/enoobis/hello` создаётся файл `Hello.java`:
```java
package com.enoobis.hello;
 
public class Hello{
     
    public static void main(String[] args){
        System.out.println("Hello enoobis.ru!");
    }
}
```
имя пакета `com.enoobis.hello` повторяет цепочку каталогов. класс `Hello` в методе `main` выводит на консоль строку.

компиляция начинается с перехода в терминале в каталог, внутри которого лежит модуль `demo`.

команда компиляции:
```bash
javac demo/module-info.java demo/com/enoobis/hello/Hello.java
```
после компиляции модуль `demo` запускается так:
```bash
java  --module-path demo --module demo/com.enoobis.hello.Hello
```
параметр `--module-path` задаёт путь к каталогу модуля, параметр `--module` задаёт главный класс в форме `имя-модуля/имя-класса`. у `--module-path` есть краткая форма `-p`, у `--module` есть краткая форма `-m`.

на консоли появляется строка из `main`:
```bash
eugene@Eugene:~$ cd java
eugene@Eugene:/java$ javac demo/module-info.java demo/com/enoobis/hello/Hello.java
eugene@Eugene:/java$ java  --module-path demo --module demo/com.enoobis.hello.Hello
Hello enoobis.ru!
eugene@Eugene:/java$
```
