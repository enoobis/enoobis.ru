код, который подключают к разным проектам или передают другим разработчикам, оформляют библиотекой. в java распространённый формат поставки библиотеки: файл jar (java archive). ниже разобраны компиляция классов такой библиотеки, упаковка в jar и подключение архива к отдельной программе через путь к классам.

### компиляция классов

библиотека в примере состоит из одного класса со статическими арифметическими операциями. на диске заводится каталог проекта, например `workspace/java/mathlib`. внутри него создаётся каталог `math`, а в этом каталоге файл `Operation.java`. класс `Operation` принадлежит пакету `math`, поэтому исходник лежит в каталоге с именем пакета: и компилятор, и виртуальная машина отображают составное имя пакета на путь в файловой системе.

в файле `Operation.java` определяется следующий код:

```java


package math;



public class Operation {

    public static int add(int a, int b) {

        return a + b;

    }



    public static int subtract(int a, int b) {

        return a - b;

    }

}
```

исходник компилируется в файл класса с расширением `.class`. в консоли выполняется переход в корневой каталог проекта, например `workspace/java`, и запускается команда:

```bash


javac -d . math/Operation.java
```

опция `-d` задаёт корень дерева выходных файлов. аргумент `.` означает текущий каталог: файлы `.class` помещаются в него, а подкаталоги повторяют пакеты. при таком корне класс `math.Operation` оказывается в файле `math/Operation.class`.

### создание jar-файла

скомпилированные классы упаковываются утилитой `jar` из состава jdk:

```bash


jar -cvf mathlib.jar math/
```

параметры утилиты `jar`:

- `-c`: создаёт новый jar-файл
- `-v`: включает подробный вывод (verbose)
- `-f`: задаёт имя создаваемого файла, в команде это `mathlib.jar`
- `math/`: каталог, который добавляется в архив и содержит скомпилированные классы

после команды в каталоге появляется файл `mathlib.jar` со скомпилированными классами, в том числе с классом `Operation`. полный вывод команды:

```bash


eugene@Eugene:/workspace/java/mathlib$ jar -cvf mathlib.jar math/

added manifest

adding: math/(in = 0) (out= 0)(stored 0%)

adding: math/Operation.class(in = 306) (out= 217)(deflated 29%)

adding: math/Operation.java(in = 187) (out= 101)(deflated 45%)

eugene@Eugene:/workspace/java/mathlib$
```

утилита записывает манифест и содержимое каталога `math`. в этот прогон в архив попал и исходник `Operation.java`: каталог упаковывается целиком, поэтому рядом с `Operation.class` в архиве оказывается и `.java`. для виртуальной машины jar выступает корнем дерева пакетов, по устройству архив совпадает с zip.

### подключение jar-файла к программе на java

библиотека `mathlib.jar` подключается к отдельному проекту. для проекта создаётся новый каталог и файл `Program.java` со следующим кодом:

```java


import math.Operation;   // подключаем класс из библиотеки



class Program{



    public static void main(String[] args) {

        

        int sum = Operation.add(5, 3);

        System.out.println("Sum: " + sum); // Sum: 8

    }

}
```

директива импорта задаёт квалифицированное имя `math.Operation`: класс `Operation` объявлен в пакете `math`. дальше программа вызывает статический метод `add`. компилятор разрешает это имя по пути к классам.

файл `mathlib.jar` копируется в каталог проекта, чтобы в командах не писать абсолютный путь. в каталоге проекта два файла:

- `Program.java`
- `mathlib.jar`

компилятору нужно указать место класса `Operation`. при компиляции для этого служит опция `-cp`:

```bash


javac -cp mathlib.jar Program.java
```

параметр `-cp mathlib.jar` добавляет архив к пути поиска классов. jar здесь занимает место каталога: относительный путь `math/Operation.class` внутри архива соответствует бинарному имени `math.Operation`. файл `Program.java` указан аргументом командной строки и читается из текущего каталога.

после компиляции программа запускается с тем же архивом в пути к классам:

```bash


// для Linux

java -cp mathlib.jar:. Program



// для Windows

java -cp mathlib.jar;. Program
```

для запуска задаётся `-cp mathlib.jar:.` в linux и `-cp mathlib.jar;.` в windows. путь включает `mathlib.jar` и текущий каталог `.`. разделитель элементов зависит от системы: в linux это двоеточие, в windows точка с запятой, потому что двоеточие в windows уже входит в имя диска. виртуальной машине нужны оба корня: `Program.class` лежит в текущем каталоге, `Operation.class` лежит в архиве `mathlib.jar`. если точку из пути убрать, загрузчик не находит класс главной программы.

после запуска на консоли печатается результат:

```bash


eugene@Eugene:/workspace/java/hello$ java -cp mathlib.jar:. Program

Sum: 8

eugene@Eugene:/workspace/java/hello$
```

в интегрированных средах подключение jar сводится к той же записи в пути к классам. среда передаёт этот путь и компилятору, и виртуальной машине.

установка в intellij idea:

- пункт меню `File -> Project Structure...`
- раздел `Modules` и нужный модуль
- вкладка `Dependencies`
- кнопка `+` и пункт `JARs or directories...`
- файл jar-библиотеки и кнопка `OK`

установка в eclipse:

- правый щелчок по проекту в `Package Explorer`
- пункт `Build Path -> Configure Build Path...`
- вкладка `Libraries`
- кнопка `Add External JARs...`
- файл jar-библиотеки и кнопка `Open`

после этих шагов среда добавляет jar и в путь компиляции, и в путь запуска.
