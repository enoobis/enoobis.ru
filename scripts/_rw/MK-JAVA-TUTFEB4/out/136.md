программа на java ссылается на классы. часть из них объявлена в самой программе, часть поставляется другими разработчиками в виде файлов `.class` или архивов `jar`. компилятор и виртуальная машина ищут эти файлы по пути к классам. среды разработки ведут такой путь своими средствами. тот же путь можно задать вручную: из чего складывается запись, как записать её в переменную окружения и в параметр командной строки, в каком порядке затем идёт поиск.

### расположение классов и формат пути

подключаемые классы распространяются отдельными файлами `.class` или библиотекой в виде jar-файла.

#### файлы классов

путь к файлам `.class` указывает на каталог-корень. сами файлы лежат ниже этого корня по каталогам пакета. в примере корень называется `/home/user/classdir` в linux и `c:\classdir` в windows.

класс `Person`:

```java


package com.enoobis;



public class Person 

{

    String name; 



    public Person(String name){



        this.name = name;

    }



    public void print() {



        System.out.printf("Person %s\n", name);

    }

}
```

этот исходник компилируется в файл `Person.class`. класс принадлежит пакету `com.enoobis`, бинарное имя `com.enoobis.Person`. файл поэтому помещается в `/home/user/classdir/com/enoobis/Person.class` в linux и в `c:\classdir\com\enoobis\Person.class` в windows. каждый сегмент пакета становится каталогом: точки бинарного имени заменяются разделителем каталогов, к имени класса добавляется расширение `.class`.

#### jar-файлы

для классов внутри `.jar` путём к классам считается путь к самому файлу `.jar`. в примере каталог для архива называется `/home/user/jardir` в linux и `c:\jardir` в windows.

если в этом каталоге лежит библиотека `mathlib.jar`, путь к её классам такой:

- `/home/user/jardir/mathlib.jar` (linux)
- `c:\jardir\mathlib.jar` (windows)

внутри архива относительный путь пакета тот же, что и в обычном каталоге. архив является ещё одним корнем поиска.

#### формат пути

путь к классам есть совокупность всех корней, где могут находиться файлы классов. один корень, например каталог `classdir`, хранит отдельно лежащие скомпилированные классы:

```browser


// Linux

/home/user/classdir



// Windows

c:\classdir
```

jar-библиотеки могут лежать по другому пути. библиотека `mathlib.jar`:

```browser


// Linux

/home/user/jardir/mathlib.jar



// Windows

c:\jardir\mathlib.jar
```

общий путь содержит оба этих корня. формат записи:

```browser


// Linux

путь1:путь2:путь3:путьN



// Windows

путь1;путь2;путь3;путьN
```

элементы перечисляются подряд и отделяются друг от друга разделителем. в linux разделитель двоеточие `:`, в windows точка с запятой `;`. в windows двоеточие уже занято именем диска, поэтому разделителем пути к классам выбран другой знак.

кроме конкретных корней допустимы относительные пути. точка `.` обозначает текущий каталог, две точки `..` обозначают родительский каталог.

для классов из примера путь собирается так:

```bash


// Для Linux

/home/user/classdir:.:/home/user/jardir/mathlib.jar



// Windows

c:\classdir;.;c:\jardir\mathlib.jar
```

в этой записи три элемента:

- базовый каталог `/home/user/classdir` или `c:\classdir`
- текущий каталог, его обозначение `.`
- путь к jar: `/home/user/jardir/mathlib.jar` или `c:\jardir\mathlib.jar`

если нужны все jar-файлы одного каталога, в элементе пути ставится подстановка `*`. она раскрывается в список jar-файлов этого каталога, без вложенных каталогов и без отдельных файлов `.class`. раскрывает подстановку виртуальная машина. в оболочке unix символ `*` экранируют, иначе оболочка подставит имена файлов раньше, чем аргумент дойдёт до `java` или `javac`:

```browser


// Unix/Linux - символ * необходимо экранировать, чтобы предотвратить расширение командной оболочкой

/home/user/classdir:.:/home/user/jardir/'*'



// Windows

c:\classdir;.;c:\jardir\*
```

дальше показано, как этот путь передаётся компиляции и запуску.

### переменная окружения classpath

путь к классам хранится в переменной окружения `CLASSPATH`. её обычно добавляют в систему при установке jdk. значение переменной выводится на консоль так:

```bash


eugene@Eugene:~$  echo $CLASSPATH

.:..

eugene@Eugene:~$
```

вывод в примере равен `.:..`. точка `.` обозначает текущий каталог, `..` обозначает родительский каталог, двоеточие между ними служит разделителем. переменная `CLASSPATH` в этом выводе содержит два корня: текущий каталог и родительский.

при таком значении файл, положенный в текущий или в родительский каталог, компилятор и виртуальная машина находят без дополнительной опции в команде.

### настройка переменной окружения classpath

постоянные глобальные настройки ради одного запуска лучше не менять. на время сеанса оболочки переменную задают командой, и команда зависит от оболочки и системы:

```bash


// Для Linux (bash)

export CLASSPATH=/home/user/classdir:.:/home/user/jardir/mathlib.jar



// Windows

set CLASSPATH=c:\classdir;.;c:\jardir\mathlib.jar
```

значение живёт до завершения оболочки и не переписывает постоянную настройку системы. начальное значение `CLASSPATH` поэтому сохраняется за пределами сеанса. в следующем сеансе работы с java переменную устанавливают снова, если этот путь ещё нужен.

когда переменная `CLASSPATH` задана, она подменяет путь по умолчанию. пока переменная не задана, путь по умолчанию состоит из текущего каталога.

### параметр -classpath

путь к классам на одну команду задаётся параметром `-classpath`. короткая форма параметра `-cp`, длинная форма `--class-path`. параметр действует и при компиляции `javac`, и при запуске `java` и на время команды перекрывает переменную `CLASSPATH`:

```bash


// Для Linux

javac -classpath /home/user/classdir:.:/home/user/jardir/mathlib.jar Program.java

java -classpath /home/user/classdir:.:/home/user/jardir/mathlib.jar Program



// Windows

javac -classpath c:\classdir;.;c:\jardir\mathlib.jar  Program.java

java -classpath c:\classdir;.;c:\jardir\mathlib.jar Program
```

вся команда набирается одной строкой.

### поиск классов

поиск сопоставляет бинарное имя файла относительному пути и проверяет этот путь в каждом корне.

#### поиск компилятора

если в коде написано простое имя класса, без пакета, компилятор сначала подбирает пакет. источниками служат директивы импорта. ниже класс `Person` используется в программе, и компилятор ищет тип при компиляции такого исходника:

```java


import java.util.*;

import com.enoobis.*;



class Program{



    public static void main(String[] args) {

        

        Person tom = new Person("Tom");

        tom.print();

    }

}
```

в исходнике две директивы импорта:

```java


import java.util.*;

import com.enoobis.*;
```

компилятор рассматривает имена `java.lang.Person` (пакет `java.lang` импортируется всегда, по умолчанию), `java.util.Person`, `com.enoobis.Person` и имя `Person` в текущем пакете. каждое из этих имён ищется во всех корнях пути к классам, в том числе в корнях из переменной `CLASSPATH` и из параметра `-classpath`. порядок директив импорта на результат не влияет: простое имя должно указывать на один тип. если под это имя подходят два класса, компиляция завершается ошибкой.

дополнительно компилятор сравнивает исходный файл и файл класса. если исходник новее файла класса, исходник компилируется заново.

#### поиск виртуальной машины

виртуальная машина ищет файл класса `com.enoobis.Person`. сначала просматриваются классы стандартного api java. там этого класса нет, и поиск переходит на путь к классам. в примере путь равен `/home/user/classdir:.:/home/user/jardir/mathlib.jar`.

по этим корням проверяются такие файлы:

- `/home/user/classdir/com/enoobis/Person.class`
- `com/enoobis/Person.class` в текущем каталоге
- `com/enoobis/Person.class` в архиве `/home/user/jardir/mathlib.jar`

компилятор `javac` просматривает текущий каталог всегда. загрузчик виртуальной машины просматривает текущий каталог только если каталог `.` присутствует в пути к классам.
