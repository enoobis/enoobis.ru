в jdk 8 класс `Arrays` получил методы параллельной обработки массива. к stream api эти методы не относятся. по устройству они близки к параллельным потокам: диапазон индексов делится на части, части исполняются задачами общего пула `ForkJoinPool`, массив меняется на месте.

- `parallelPrefix()`: записывает в каждый элемент результат бинарной операции по префиксу массива, например сумму или произведение

- `parallelSetAll()`: заполняет элементы функцией от индекса

- `parallelSort()`: сортирует массив

ниже `parallelSetAll()` заполняет массив:
```java

import java.util.Arrays;
public class Program {

    public static void main(String[] args) {
		
        int[] numbers = initializeArray(6);
        for(int i: numbers)
            System.out.println(i);
        
    } 
    public static int[] initializeArray(int size) {
        int[] values = new int[size];
        Arrays.parallelSetAll(values, i -> i*10);
        return values;
    }
}
```
в `Arrays.parallelSetAll` передаются изменяемый массив и функция, которая задаёт элементы. функция обходит индексы и получает индекс текущего элемента. выражение `i -> i*10` записывает по индексу `i` число `i * 10`. индексация начинается с нуля, поэтому массив длины 6 печатается так:
```consoletext

0
10
20
30
40
50
```
следующий пример опирается на класс `Phone`:
```java

class Phone{
    
    private String name;
    private int price;
    
    public Phone(String name, int price){
        this.name=name;
        this.price = price;
    }
    
    public String getName() {
        return name;
    }
    public void setName(String val) {
        this.name=val;
    }
    public int getPrice() {
        return price;
    }
    public void setPrice(int val) {
        this.price=val;
    }
}
```
тот же метод применяется к массиву объектов `Phone`:
```java

Phone[] phones = new Phone[]{new Phone("iPhone 8", 54000), 
    new Phone("Pixel 2", 45000),
    new Phone("Samsung Galaxy S9", 40000),
    new Phone("Nokia 9", 32000)};
        
Arrays.parallelSetAll(phones, i -> {
    phones[i].setPrice(phones[i].getPrice()-10000); 
    return phones[i];
});
        
for(Phone p: phones)
    System.out.printf("%s - %d \n", p.getName(), p.getPrice());
```
здесь лямбда-выражение в `Arrays.parallelSetAll` записано блоком. функция обязана вернуть объект того же типа, что и элемент массива, поэтому в блоке стоит оператор `return`. параметром снова служит индекс, и по этому индексу код обращается к элементу и меняет его состояние. в примере цена уменьшается на 10000. генератор для разных индексов может выполняться параллельно, поэтому тело затрагивает только `phones[i]`: объекты массива различны, и записи в разные индексы не пересекаются. консольный вывод:
```consoletext

iPhone 8 - 44000 
Pixel 2 - 35000 
Samsung Galaxy S9 - 30000 
Nokia 9 - 22000
```
### сортировка

массив чисел сортируется в параллельном режиме:
```java

int[] nums = {30, -4, 5, 29, 7, -8};
Arrays.parallelSort(nums);
for(int i: nums)
    System.out.println(i);
```
`Arrays.parallelSort()` принимает массив и упорядочивает его по возрастанию. на коротком массиве реализация остаётся последовательной. когда элементов достаточно много, диапазон делится между задачами, части сортируются отдельно и затем сливаются:
```consoletext

-8
-4
5
7
29
30
```
иной порядок, например сравнение по модулю или разбор объектов без естественного порядка, задаётся компаратором во втором аргументе `Arrays.parallelSort()`. для класса `Phone` компаратор сравнивает имена без учёта регистра. `toUpperCase()` строит временные строки только для сравнения и поле `name` не переписывает, после чего `compareTo` задаёт лексикографический порядок. контракт `Comparator` требует транзитивное и согласованное отношение, иначе результат сортировки не определён. для массива объектов параллельная сортировка не является устойчивой: элементы, равные по компаратору, могут поменять взаимный порядок.
```java

import java.util.Arrays;
import java.util.Comparator;
public class Program {
 
    public static void main(String[] args) {
         
        Phone[] phones = new Phone[]{new Phone("iPhone 8", 54000), 
		new Phone("Pixel 2", 45000),
		new Phone("Samsung Galaxy S9", 40000),
		new Phone("Nokia 9", 32000)};
        
        Arrays.parallelSort(phones,new PhoneComparator());
        
         for(Phone p: phones)
            System.out.println(p.getName());
    }
}
class PhoneComparator implements Comparator<Phone>{
 
    public int compare(Phone a, Phone b){
     
        return a.getName().toUpperCase().compareTo(b.getName().toUpperCase());
    }
}
```
### метод `parallelPrefix`

`parallelPrefix()` применяется, когда на месте каждого элемента нужно значение того же типа, собранное по префиксу массива: максимум, минимум, сумма, произведение. ниже считается произведение:
```java

int[] numbers = {1, 2, 3, 4, 5, 6};
Arrays.parallelPrefix(numbers, (x, y) -> x * y);

for(int i: numbers)
    System.out.println(i);
```
результат:
```consoletext

1
2
6
24
120
720
```
лямбда-выражение в `Arrays.parallelPrefix` является бинарной функцией. она получает уже накопленное значение и следующий элемент, выполняет операцию, записывает результат на позицию этого элемента и передаёт его в следующий вызов. для исходного массива `1, 2, 3, 4, 5, 6` произведение префиксов даёт `1, 2, 6, 24, 120, 720`: первый элемент остаётся собой, каждый следующий равен произведению всех элементов от начала до этой позиции включительно. параллельное вычисление совпадает с последовательным, когда операция ассоциативна, то есть `(a op b) op c` совпадает с `a op (b op c)`. умножение целых чисел ассоциативно. если ассоциативности нет, разные разбиения массива могут записать разный результат.
