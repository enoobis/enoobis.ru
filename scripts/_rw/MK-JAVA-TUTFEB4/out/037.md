полиморфизм является одной из основных концепций объектно-ориентированного программирования и подразумевает, что сущность может принимать различные формы. в языке java переменные ссылочного типа являются полиморфными. это значит, что переменная базового класса может ссылаться на объект производного класса. такое отношение называют подтипным полиморфизмом: статический тип переменной задаёт видимый контракт, динамический тип объекта задаёт реализацию. пример:

```java


public class Program{

     

	public static void main(String[] args) {

			

		Person tom = new Person("Tom");

		tom.print();



        System.out.println();



		Person sam = new Employee("Sam", "Oracle");

		sam.print();

	}

}

class Person {

    

    private String name;

   

    Person(String name){ this.name = name; }

 

    void print(){

		

		System.out.println("Name: " + name);

	}

}



class Employee extends Person{



    private String company;

    

    Employee(String name, String company) {

    

        super(name);

        this.company = company;

    }

    @Override

    void print(){

        

        super.print();

        System.out.println("Company: " + company);

    }

}
```

так как `Employee` наследуется от `Person`, объект `Employee` является в то же время и объектом `Person`. любой работник предприятия одновременно является человеком. поэтому переменной типа `Person` можно присвоить ссылку на объект типа `Employee`:

```java
Person sam = new Employee("Sam", "Oracle");
```

несмотря на то, что статический тип переменной есть `Person`, виртуальная машина видит, что в реальности ссылка указывает на объект `Employee`. при вызове методов у этого объекта вызывается версия, определённая в классе `Employee`. пример:

```java


Person sam = new Employee("Sam", "Oracle");

sam.print();  // вызов реализации метода print из класса Employee
```

при вызове переопределённого метода виртуальная машина динамически находит и вызывает именно ту версию метода, которая определена в подклассе. данный процесс ещё называется dynamic method lookup, или динамический поиск метода, или динамическая диспетчеризация методов. установка точной версии метода называется динамическим связыванием (dynamic binding).

для ускорения поиска виртуальная машина заранее вычисляет таблицу методов для каждого класса (method table). в таблице методов перечисляются все сигнатуры методов (названия методов и типы их параметров) и сами вызываемые методы. виртуальная машина может построить таблицу методов после загрузки класса, объединив методы, найденные в файле класса, с таблицей методов базового класса. при фактическом вызове метода виртуальная машина просто выполняет поиск в таблице. обычный вызов метода экземпляра, который разрешено переопределять, соответствует инструкции `invokevirtual`.

если же метод определён с модификаторами `private`, `static`, `final` или является конструктором, компилятор точно знает, какой метод вызывать. это называется статическим связыванием (static binding). такие методы в подклассе не подменяются.

консольный вывод данной программы:

```bash


Name: Tom



Name: Sam

Company: Oracle
```

присваивание в обратную сторону компилятор отвергает. переменной производного класса не дают ссылку на объект базового класса, например следующим образом:

```java


Employee sam = new Person("Sam");
```

это согласовано с типами. не все люди работают и являются работниками некоторого предприятия. статический тип `Employee` уже, чем `Person`, и объект суперкласса контракт подкласса не выполняет.

### полиморфизм в параметрах и возвращаемых типах

то обстоятельство, что любой объект производного класса также рассматривается как объект базового класса, позволяет параметру базового типа передавать объекты производных классов. пример:

```java


public class Program{

     

	public static void main(String[] args) {

			

		Person tom = new Person("Tom");

		printPerson(tom);



        System.out.println();



		Employee sam = new Employee("Sam", "Oracle");

		printPerson(sam);

	}



    static void printPerson(Person person){



        person.print();

    }

}

class Person {

    

    private String name;

   

    Person(String name){ this.name = name; }

 

    void print(){

		

		System.out.println("Name: " + name);

	}

}



class Employee extends Person{



    private String company;

    

    Employee(String name, String company) {

    

        super(name);

        this.company = company;

    }

    @Override

    void print(){

        

        super.print();

        System.out.println("Company: " + company);

    }

}
```

в классе `Program` метод `printPerson` принимает объект типа `Person`:

```java


static void printPerson(Person person){



    person.print();

}
```

поскольку объекты производного типа `Employee` также являются объектами типа `Person`, эти объекты можно передать в данный метод:

```java


Employee sam = new Employee("Sam", "Oracle");

printPerson(sam); // параметру типа Person передаем объект Employee
```

вызов `person.print()` внутри метода диспетчеризуется по динамическому типу аргумента. для экземпляра `Employee` выполняется переопределённый `print`, хотя статический тип параметра равен `Person`.

то же самое относится к возвращению объекта из метода. если возвращаемый тип представляет базовый класс, из метода можно вернуть объект производного класса. пример:

```java


public class Program{

     

	public static void main(String[] args) {

			

		Person person1 = defaultPerson(0);

		person1.print();



        System.out.println();



		Person person2 = defaultPerson(1);

		person2.print();

	}



    static Person defaultPerson(int type){



        if(type == 0){

            return new Person("Tom");

        }

        return new Employee("Tom", "OOO Undefined");

    }

}

class Person {

    

    private String name;

   

    Person(String name){ this.name = name; }

 

    void print(){

		

		System.out.println("Name: " + name);

	}

}



class Employee extends Person{



    private String company;

    

    Employee(String name, String company) {

    

        super(name);

        this.company = company;

    }

    @Override

    void print(){

        

        super.print();

        System.out.println("Company: " + company);

    }

}
```

в классе `Program` статический метод `defaultPerson` возвращает значение типа `Person`:

```java


static Person defaultPerson(int type){



    if(type == 0){

        return new Person("Tom");

    }

    return new Employee("Tom", "OOO Undefined");

}
```

в зависимости от переданного параметра это может быть как объект типа `Person`, так и объект типа `Employee`, который также является объектом типа `Person`. вызывающий код видит статический тип `Person` и пользуется контрактом суперкласса, не различая ветки возврата.
