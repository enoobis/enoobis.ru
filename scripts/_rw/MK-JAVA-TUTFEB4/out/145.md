### создание собственных аннотаций

в самой java и во фреймворках на этом языке уже есть аннотации для разных задач. язык при этом позволяет объявлять собственные аннотации. каждая аннотация задаётся **интерфейсом аннотации**: после ключевого слова `@interface` указывается имя. конструкция `@interface` вводит особый вид интерфейса java:

```java


// объявление аннотации под названием MyAnnotation

@interface MyAnnotation {



}
```

после имени, как и у обычного интерфейса, идут фигурные скобки. внутри них располагаются элементы аннотации. в примере имя `MyAnnotation`, элементов нет. такая аннотация является маркером: у места применения нет параметров, важен сам факт пометки.

всякий интерфейс аннотации неявно расширяет `java.lang.annotation.Annotation`. это обычный интерфейс с методом `annotationType()`, но расширять интерфейс аннотации другим интерфейсом или реализовать его в своём классе нельзя. тип аннотации не бывает обобщённым, и в его заголовке нельзя написать `extends`. классы-прокси и экземпляры, которые ведут себя как этот интерфейс, при необходимости строят обработчики исходного кода и виртуальная машина. экземпляр, который возвращает рефлексия, как раз такой прокси: вызов элемента аннотации читает значение, сохранённое в месте применения.

при объявлении аннотации обычно ставят **мета-аннотации**, то есть аннотации, применимые к типам аннотаций:

- `@Retention`: задаёт политику хранения, то есть до какой стадии обработки аннотация сохраняется
- `@Target`: задаёт элементы кода, к которым аннотацию разрешено применять (класс, метод, поле, параметр и другие)
- `@Documented`: включает аннотацию в генерируемую документацию javadoc. без этой мета-аннотации javadoc по умолчанию не показывает аннотацию на документируемом элементе
- `@Inherited`: аннотация, поставленная на класс, видна и на подклассах при рефлексивном поиске. наследование касается только классов и только запроса аннотации через рефлексию. на интерфейсы оно не распространяется, и в байткод подкласса аннотация заново не копируется
- `@Repeatable`: разрешает поставить одну и ту же аннотацию на один элемент несколько раз. в class-файле повторы хранятся во вмещающей аннотации, у которой элемент имеет тип массива

ниже разобраны `@Target` и `@Retention`. сначала показано само применение пользовательской аннотации:

```java


@interface MyAnnotation{}



@MyAnnotation

class Thing{

    @MyAnnotation String name;

}
```

`MyAnnotation` стоит на объявлениях: на классе `Thing` и на поле `name`. ни объявление аннотации, ни эти пометки сами по себе поведения не добавляют. класс используется как обычный класс:

```java


// объявляем аннотацию

@interface MyAnnotation{}



// применяем аннотацию к классу Thing

@MyAnnotation

class Thing{ }



class Program{

 

    public static void main(String[] args) throws Exception{

          

        Thing thing = new Thing();

        System.out.println(thing);

    }

}
```

по умолчанию, если `@Target` не указан, аннотация допустима на любых объявлениях, кроме параметров типа в обобщениях, и недопустима на использованиях типа. более точный набор мест задаёт мета-аннотация `@Target`.

### `@Target`

мета-аннотация `@Target` перечисляет, к каким элементам кода применяется аннотация. значение задаёт массив констант перечисления `ElementType`:

- `ElementType.ANNOTATION_TYPE`: объявления типов аннотаций
- `ElementType.MODULE`: модули
- `ElementType.PACKAGE`: пакеты
- `ElementType.TYPE`: классы, включая перечисления, и интерфейсы, включая типы аннотаций
- `ElementType.METHOD`: методы
- `ElementType.CONSTRUCTOR`: конструкторы
- `ElementType.FIELD`: поля, включая константы перечисления
- `ElementType.PARAMETER`: параметры метода или конструктора
- `ElementType.RECORD_COMPONENT`: компоненты классов `record`
- `ElementType.LOCAL_VARIABLE`: локальные переменные
- `ElementType.TYPE_PARAMETER`: параметры типов
- `ElementType.TYPE_USE`: использование типа

константы соответствуют тем местам, которые различают аннотации объявлений и аннотации использования типов. `TYPE_PARAMETER` открывает параметр обобщения, `TYPE_USE` открывает вхождения типа. без явного указания этих двух констант аннотация туда не попадает, даже если кажется, что «все объявления» уже покрыты.

пример ограничения:

```java


@Target({ElementType.FIELD, ElementType.RECORD_COMPONENT, ElementType.TYPE})

@interface MyAnnotation
```

здесь `MyAnnotation` разрешена на полях, на компонентах `record` и на типах, то есть на классах и интерфейсах. применение к классу и к полю согласовано с этим списком:

```java


@MyAnnotation

class Thing{

    @MyAnnotation String name;

}
```

к методам и к остальным элементам, не перечисленным в `@Target`, такая аннотация неприменима: компилятор отвергает место применения, которое не входит в массив `ElementType`. проверка выполняется во время компиляции, виртуальная машина повторно её не проводит.

если элемент `@Target` один, фигурные скобки массива можно опустить. несколько констант записываются массивом, как в примере. аннотация без `@Target` по-прежнему допустима на любых объявлениях, кроме параметров типа, и недопустима на использованиях типа.

### элементы аннотаций

у аннотации бывают элементы. синтаксически это методы, но вызываются они как чтение сохранённого значения, а не как вычисление с побочным эффектом. у такого метода не может быть параметров, он не может быть обобщённым, и в объявлении нельзя указать `throws`. тип результата ограничен: примитив, `String`, `Class`, перечисление, тип аннотации либо массив из этих типов. произвольный класс, в том числе `Object`, типом элемента быть не может: значение элемента должно сериализоваться в атрибут class-файла как константа.

```java


@interface MyAnnotation {



    // элементы аннотации

    String value();

    int count();

}
```

у `MyAnnotation` два элемента: `value` типа `String` и `count` типа `int`. имя `value` особое. если в месте применения задаётся только этот элемент, имя можно опустить и оставить одно значение в скобках. в примерах ниже имя указано явно.

при применении элементам передаются значения:

```java


@interface MyAnnotation {



    // элементы аннотации

    String value();

    int count();

}



@MyAnnotation(value="Thing", count=1)

class Thing{ }
```

значения пишутся после имени аннотации в круглых скобках, через запятую, в виде `имя_элемента = значение`. порядок имён не обязан повторять порядок объявления элементов. по форме запись похожа на вызов конструктора, но конструктора у типа аннотации нет: это литерал аннотации, и компилятор кладёт пары «имя, значение» в атрибут аннотаций того элемента, на котором стоит пометка. значение обязано быть константой времени компиляции. выражение с вызовом метода здесь недопустимо.

#### значения по умолчанию для элементов аннотаций

у элемента может быть значение по умолчанию. после заголовка метода ставится ключевое слово `default` и константа:

```java


@interface MyAnnotation {



    // элементы аннотации со значениями по умолчанию

    String value() default "default value";

    int count() default 0;

}
```

если у элемента есть значение по умолчанию, в месте применения его можно не указывать. компилятор примет аннотацию, у которой задано любое подмножество таких элементов, включая пустые скобки и полное отсутствие скобок:

```java


@interface MyAnnotation {



    // элементы аннотации со значениями по умолчанию

    String value() default "DefaultValue";

    int count() default 0;

}



@MyAnnotation(value="Type A", count=2)

class TypeA{ }



@MyAnnotation(value="Type B")  // count = 0

class TypeB{ }



@MyAnnotation(count=1)      // value = DefaultValue

class TypeC{ }



@MyAnnotation               // value = DefaultValue, count = 0

class TypeD{ }
```

`TypeA` задаёт оба элемента. `TypeB` оставляет `count` равным 0. `TypeC` оставляет `value` равным `DefaultValue`. `TypeD` не задаёт ничего, и оба элемента читаются как значения по умолчанию. пропущенное значение не записывается в атрибут конкретного места применения. оно хранится в типе аннотации, в атрибуте значения по умолчанию у метода-элемента, и подставляется при чтении: рефлексией или обработчиком. поэтому смена `default` в типе аннотации меняет результат чтения старых мест применения, где элемент был опущен, без перекомпиляции этих мест. явно записанное значение так не меняется.

если элемент имеет тип массива, значение по умолчанию записывается в фигурных скобках. пустой массив тоже допустим:

```java


@interface MyAnnotation {

    String[] addresses() default {"address1@humail.com", "address2@humail.com"};

    String[] posts() default {};    // пустой массив

}
```

значение по умолчанию не сохраняется вместе с каждой применённой аннотацией. оно вычисляется при обращении к элементу.

### `@Retention`

мета-аннотация `@Retention` задаёт, где аннотация ещё доступна, то есть насколько долго она сохраняется. аргумент выбирается из трёх констант перечисления `RetentionPolicy`:

- `RetentionPolicy.SOURCE`: аннотация существует только в исходном коде и отбрасывается компилятором. так устроены пометки для анализа текста и для генерации кода на этапе компиляции. процессор аннотаций ещё видит их, в class-файле их уже нет. `@Override` и `@SuppressWarnings` хранятся именно так
- `RetentionPolicy.CLASS`: аннотация записывается в файл `.class`, в байткод, но рефлексия во время выполнения её не видит. это значение по умолчанию, если `@Retention` не указана. атрибут рассчитан на инструменты, которые читают байткод, а не на `getAnnotation`
- `RetentionPolicy.RUNTIME`: аннотация записывается в файл `.class` и остаётся доступной во время выполнения через рефлексию. этот вариант нужен фреймворкам вроде spring и junit, которые смотрят на классы уже работающей программы. в байткоде такие аннотации лежат в атрибуте, видимом виртуальной машине, и `getAnnotation` возвращает прокси с записанными значениями элементов

политика хранения не меняет синтаксис применения. она определяет, переживёт ли метаданное компиляцию и загрузку класса.

пример двух мета-аннотаций вместе:

```java


@Retention(RetentionPolicy.RUNTIME)     // Аннотация доступна во время выполнения

@Target(ElementType.TYPE)             // Аннотация применяется к типам

@interface MyAnnotation {



    String value() default "DefaultValue";

}
```

`@Retention(RetentionPolicy.RUNTIME)` оставляет `MyAnnotation` доступной во время выполнения. `@Target(ElementType.TYPE)` разрешает её только на типах. элемент `value` имеет значение по умолчанию `DefaultValue`, поэтому скобки в месте применения можно не писать, а рефлексия при отсутствии явного значения вернёт эту строку.
