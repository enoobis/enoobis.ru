аннотации в java представляют специальную форму **метаданных**, то есть данных о самом коде. аннотация добавляется в исходный текст и сообщает компилятору, инструменту сборки, фреймворку или коду времени выполнения дополнительный факт об элементе программы. конфигурация и метаданные за счёт этого отделяются от основной логики: правило записано декларативно у того объявления, к которому относится, а не спрятано в отдельном участке императивного кода. на аннотациях держатся многие современные библиотеки java: веб-фреймворки, средства тестирования, проверка ограничений на данные.

сама аннотация действий не выполняет. она помечает класс, метод, поле или другой элемент. отдельный код, обработчик аннотаций, ищет эти пометки и исполняет свою логику. обработчик может работать на этапе компиляции, как процессор аннотаций, либо во время выполнения, через рефлексию. пока обработчика нет, аннотация остаётся записью в исходнике или в атрибутах class-файла.

синтаксически аннотация начинается с символа `@`, за которым следует имя, например `@Override`. имя обозначает тип аннотации. аргументы, если они есть, записываются в круглых скобках после имени.

в java есть встроенные аннотации для стандартных проверок компилятора. чаще всего встречаются такие:

- `@Override`: сообщает компилятору, что метод переопределяет метод супертипа. если сигнатура в супертипе не найдена, компиляция завершается ошибкой
- `@Deprecated`: помечает элемент (класс, метод, поле и ряд других объявлений) как устаревший. использование такого элемента даёт предупреждение компилятора
- `@SuppressWarnings`: отключает выбранные предупреждения компилятора для аннотированного элемента
- `@FunctionalInterface`: помечает интерфейс как функциональный, то есть требующий ровно один абстрактный метод, не считая методов `Object`

у `@Override` и `@SuppressWarnings` политика хранения `source`: компилятор учитывает их и в class-файл не записывает. `@Deprecated` и `@FunctionalInterface` сохраняются до времени выполнения, их можно прочитать рефлексией. у `@Deprecated` с java 9 есть элементы `since` и `forRemoval`: первый фиксирует версию, с которой элемент устарел, второй сообщает, что элемент намечены к удалению.

### применение аннотаций

аннотации объявлений применимы ко многим конструкциям языка. по месту записи аннотации делятся на две группы:

- аннотации объявлений (declaration annotation)
- аннотации использования типов (type use annotation)

различие семантическое. аннотация объявления относится к самому объявлению: к классу, методу, полю, параметру. аннотация использования типа относится к вхождению типа в конкретном месте программы: к аргументу обобщения, к одному уровню массива, к приведению. компилятор и внешние средства анализа читают эти две группы по разным правилам, и на поведение байткода приведения или `instanceof` аннотация использования типа не влияет.

### аннотации объявлений

аннотация объявления несёт сведения об объявляемом элементе. её ставят на такие объявления:

- на классы, включая перечисления, и на интерфейсы, включая типы аннотаций
- на методы
- на конструкторы
- на поля, включая константы перечислений и компоненты классов `record`
- на локальные переменные, в том числе объявленные в `for` и в `try-with-resources`
- на параметры методов
- на параметры типов
- на пакеты и модули

у класса, интерфейса и модуля аннотация стоит перед ключевым словом `class`, `interface` или `module` и перед модификаторами, если они есть:

```java
@MyAnnotation public class Person { }
```

у переменной, параметра и компонента `record` аннотация стоит перед типом:

```java


@MyAnnotation String name = "Tom";

public User getUser(@MyAnnotation int userId)

record Person(@MyAnnotation String name) {}
```

перед параметром типа в обобщённом классе или методе аннотация пишется так же, перед именем параметра:

```java


class Person<@MyAnnotation T> { }
```

параметр типа есть объявление переменной типа. использованием типа в выражении он не является. поэтому здесь нужна аннотация, которой разрешены параметры типов. одной аннотации использования типа для этого места мало.

### аннотации использования типов

аннотация использования типа может стоять в следующих местах:

- у аргумента обобщённого типа:

```java
Person<@MyAnnotation String>
```

здесь метаданные относятся к конкретному аргументу `String` в применении `Person`, а не к объявлению класса `Person`.

- перед скобками массива. аннотация непосредственно перед парой скобок относится к тому уровню массива, который эти скобки задают. от такой записи отличают аннотацию, стоящую перед типом элемента:

```java


String[] @MyAnnotation [] data // Применяется к String[]

String @MyAnnotation [][] data // Применяется к String[][]
```

```java
@MyAnnotation String[][] data
```

в двух первых строках аннотация стоит перед скобками и относится к типу массива: к `String[]` и к `String[][]` соответственно. в последней строке аннотация стоит перед `String` и относится к типу элемента.

- у суперкласса и у реализованных интерфейсов:

```java
class Employee extends @MyAnnotation Person.
```

аннотация относится к вхождению типа `Person` в секции `extends`, а не к объявлению класса `Employee`.

- у вызова конструктора:

```java
 new @MyAnnotation Person();
```

- у вложенных типов, между именем объемлющего типа и именем вложенного:

```java
 Map.@MyAnnotation Entry
```

запись `Map.@MyAnnotation Entry` аннотирует тип `Entry` в квалифицированном имени, а не тип `Map`.

- у приведений и у проверок `instanceof`. такие аннотации рассчитаны на внешние инструменты. они не меняют семантику приведения и не меняют результат `instanceof`:

```java


(@MyAnnotation String) text

if (text instanceof @MyAnnotation String)
```

- у спецификации генерируемых исключений:

```java
void print() throws @MyAnnotation Exception.
```

- у подстановочных типов и у границ типов:

```java


List<@MyAnnotation ? extends Person>

List<? extends @MyAnnotation Person>
```

в первой строке аннотация относится к подстановочному типу, во второй относится к границе `Person`. это разные вхождения типа, и средство проверки может трактовать их по-разному.

- у ссылок на метод и на конструктор:

```java
@MyAnnotation Person::getName
```

аннотацию можно ставить и до других модификаторов, и после них, в том числе рядом со `static` и `public`. обычно аннотацию использования типа пишут после остальных модификаторов, а аннотацию объявления ставят перед ними:

```java


private @MyAnnotation String name;   // Аннотация использования типа

@MyAnnotation private int age;      // Аннотация переменной / поля класса
```

в первой строке аннотация стоит между модификатором и типом, это аннотация использования типа `String`. во второй аннотация стоит перед модификатором и относится к объявлению поля.

### `@Override`

аннотация `@Override` сообщает компилятору, что метод переопределяет метод супертипа. если метода с той же сигнатурой в супертипе нет, компилятор выдаёт ошибку. проверка ловит опечатку в имени и расхождение в параметрах, которые иначе дали бы новый метод, а не переопределение. та же проверка покрывает реализацию метода интерфейса: аннотация требует совпадения с методом супертипа, класс это или интерфейс.

при переопределении аннотация не обязательна. без неё язык принимает и настоящее переопределение, и случайно объявленный новый метод. разницу показывает следующая программа:

```java


class Animal {

    void makeSound() {

        System.out.println("Некий звук");

    }

}

class Cat extends Animal {

    

    void makeSounds() {

        System.out.println("Мяу");

    }

}



class Program{

 

    public static void main(String[] args) throws Exception{

          

        Cat barsik = new Cat();

        barsik.makeSound(); // Некий звук

    }

}
```

класс `Animal` задаёт животное и метод `makeSound()` для звука. класс `Cat` по замыслу переопределяет этот метод. в `main` метод вызывается у экземпляра `Cat`. консольный вывод:

```bash
Некий звук
```

напечатан текст суперкласса. причина в имени: в `Cat` объявлен `makeSounds`, с лишней буквой относительно `makeSound`. это отдельный метод. он ничего не переопределяет, виртуальный вызов `makeSound` остаётся в `Animal`, программа компилируется и выполняется. как раз против такого расхождения поставлена `@Override`. та же программа с аннотацией:

```java


class Animal {

    void makeSound() {

        System.out.println("Некий звук");

    }

}

class Cat extends Animal {

    

    @Override

    void makeSounds() {

        System.out.println("Мяу");

    }

}
```

в `Cat` по-прежнему имя с опечаткой, `makeSounds` вместо `makeSound`. аннотация утверждает, что в супертипе есть метод с этой сигнатурой и что его нужно переопределить. метода `makeSounds` в `Animal` нет, поэтому компиляция останавливается:

```bash


Program.java:8: error: method does not override or implement a method from a supertype

    @Override

    ^

1 error

error: compilation failed
```

сообщение компилятора прямо говорит, что метод не переопределяет и не реализует метод супертипа. ошибка видна до запуска, и имя можно привести к сигнатуре суперкласса:

```java


class Cat extends Animal {

    

    @Override

    void makeSound() {

        System.out.println("Мяу");

    }

}
```

после исправления вызов `barsik.makeSound()` диспетчеризуется в `Cat` и печатает текст подкласса.

### `@Deprecated`

аннотация `@Deprecated` помечает элемент (класс, метод, поле) как устаревший. это нужно после изменения api класса или пакета, когда отдельные компоненты больше не следует вызывать, но удалить их сразу нельзя: существующий код должен по-прежнему компилироваться. компилятор выдаёт предупреждение при каждом использовании такого элемента:

```java


class Cat{

    

    @Deprecated

    void makeSound() {

        System.out.println("Мяу");

    }



    void say() {

        System.out.println("Мяу");

    }

}



class Program{

 

    public static void main(String[] args) throws Exception{

          

        Cat barsik = new Cat();

        barsik.makeSound();

    }

}
```

в классе `Cat` метод `makeSound()` помечен `@Deprecated` как устаревший. рядом объявлен `say()` с той же печатью, и дальнейший код предполагается переводить на него. программа компилируется и выполняется, при компиляции выдаётся предупреждение:

```java


eugene@Eugene:/workspace/java$ java Program.java

Program.java:18: warning: [deprecation] makeSound() in Cat has been deprecated

        barsik.makeSound();

              ^

1 warning

Мяу
```

предупреждение `deprecation` указывает файл, строку и имя устаревшего метода. выполнение при этом не прерывается: аннотация не вставляет проверку времени выполнения, она только сообщает компилятору о статусе элемента. строка `Мяу` печатается уже как результат работы метода.

### `@SuppressWarnings`

аннотация `@SuppressWarnings` отключает выбранные предупреждения компилятора для аннотированного элемента и для того, что вложено в него. элемент аннотации имеет тип массива строк: каждый элемент массива задаёт имя категории предупреждений. одна строка записывается без фигурных скобок, несколько имён записывают в скобках как массив.

программа ниже компилируется и выполняется, но обращение к сырому типу порождает предупреждение:

```java


import java.util.ArrayList;

import java.util.List;



class Program{

 

    public static void main(String[] args) throws Exception{

          

        methodWithRawType();

    }



    public static void methodWithRawType() {

        List names = new ArrayList();

        names.add("Tom");

        System.out.println(names);

    }

}
```

вывод компилятора:

```bash


eugene@Eugene:/workspace/java$ java Program.java

Program.java:13: warning: [unchecked] unchecked call to add(E) as a member of the raw type List

        names.add("Tom");

                 ^

  where E is a type-variable:

    E extends Object declared in interface List

1 warning

[Tom]
```

предупреждение `unchecked` возникает из-за сырого типа `List`. параметр типа стёрт, и компилятор не может проверить, что в `add` передаётся допустимый элемент. в сообщении `E` обозначена переменная типа интерфейса `List`, её граница равна `Object`. корректная запись фиксирует аргумент типа:

```java
List<String> names = new ArrayList<String>();
```

если сырой тип сохранён намеренно, то же предупреждение отключают аннотацией. в скобках передаётся имя категории. в примере это `unchecked`:

```java


@SuppressWarnings("unchecked")

public static void methodWithRawType() {



    List names = new ArrayList();

    names.add("Tom");

    System.out.println(names);

}
```

аннотация стоит на методе, поэтому подавление касается предупреждений внутри этого метода, а не всего компилируемого файла. неизвестное имя категории компилятор может сопроводить отдельным предупреждением: строка не проверяется системой типов, это договорённость с конкретным компилятором.

### `@FunctionalInterface`

аннотация `@FunctionalInterface` сообщает, что интерфейс предназначен для использования как функциональный интерфейс: в нём ровно один абстрактный метод. компилятор проверяет это условие. методы `Object`, а также методы с реализацией `default` и `static`, в этот единственный абстрактный метод не входят. если абстрактных методов нет или их больше одного, компиляция интерфейса с такой аннотацией завершается ошибкой.

```java


@FunctionalInterface

interface MyComparator {

    int compare(String a, String b);

}
```

без аннотации интерфейс с одним абстрактным методом всё равно может быть целью лямбда-выражения или ссылки на метод. аннотация не включает эту возможность, она фиксирует намерение и просит компилятор отвергнуть интерфейс, который условию больше не соответствует. это проверка времени компиляции, аналогичная `@Override` для сигнатуры.
