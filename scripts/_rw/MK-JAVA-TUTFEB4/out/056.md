для лямбда-выражений нужен функциональный интерфейс, то есть тип с одним абстрактным методом. собственный интерфейс объявлять не обязательно: jdk уже содержит набор таких типов в пакете `java.util.function` (с java 8). эти типы покрывают наиболее частые формы функций и подставляются в разные api. основные из них:

- `Predicate`

- `Consumer`

- `Function`

- `BiFunction`

- `Supplier`

- `UnaryOperator`

- `BinaryOperator`

у части типов есть примитивные специализации (`IntPredicate`, `ToIntFunction` и другие), чтобы не упаковывать `int`, `long` и `double` в объектные оболочки. `BinaryOperator<T>` в библиотеке является частным случаем `BiFunction<T, T, T>`, а `UnaryOperator<T>` частным случаем `Function<T, T>`.

### predicate

функциональный интерфейс `Predicate<T>` проверяет условие над объектом типа `T`. если условие выполнено, метод `test` возвращает `true`.

```java


public interface Predicate<T> {

	boolean test(T t);

}
```

пример:

```java


import java.util.function.Predicate;



public class Program {



    public static void main(String[] args) {

        

        Predicate<Integer> isPositive = x -> x > 0;

        

        System.out.println(isPositive.test(5)); // true

        System.out.println(isPositive.test(-7)); // false

	}

}
```

предикат `isPositive` истинен для положительного `Integer`. вызов `test(5)` даёт `true`, `test(-7)` даёт `false`.

### binaryoperator

`BinaryOperator<T>` принимает два объекта типа `T`, выполняет над ними бинарную операцию и возвращает результат того же типа `T`.

```java


public interface BinaryOperator<T> {

	T apply(T t1, T t2);

}
```

пример:

```java


import java.util.function.BinaryOperator;



public class Program {



    public static void main(String[] args) {

        

        BinaryOperator<Integer> multiply = (x, y) -> x*y;

		

        System.out.println(multiply.apply(3, 5)); // 15

        System.out.println(multiply.apply(10, -2)); // -20

	}

}
```

операция `multiply` перемножает два `Integer`. `apply(3, 5)` возвращает 15, `apply(10, -2)` возвращает -20.

### unaryoperator

`UnaryOperator<T>` принимает один объект типа `T`, выполняет над ним операцию и возвращает результат типа `T`.

```java


public interface UnaryOperator<T> {

	T apply(T t);

}
```

пример:

```java


import java.util.function.UnaryOperator;



public class Program {



    public static void main(String[] args) {

        

        UnaryOperator<Integer> square = x -> x*x;

        System.out.println(square.apply(5)); // 25

	}

}
```

операция `square` возводит аргумент в квадрат. `apply(5)` возвращает 25.

### function

функциональный интерфейс `Function<T, R>` задаёт отображение объекта типа `T` в объект типа `R`. тип аргумента и тип результата независимы.

```java


public interface Function<T, R> {

	R apply(T t);

}
```

пример:

```java


import java.util.function.Function;



public class Program {



    public static void main(String[] args) {

        

        Function<Integer, String> convert = x-> String.valueOf(x) + " долларов";

        System.out.println(convert.apply(5)); // 5 долларов

	}

}
```

функция `convert` переводит `Integer` в `String`: число переводится в текст методом `String.valueOf`, и к нему дописывается суффикс «долларов». `apply(5)` возвращает строку `5 долларов`.

### bifunction

функциональный интерфейс `BiFunction<T, U, R>` задаёт функцию двух параметров, типов `T` и `U`, с результатом типа `R`. в пакете `java.util.function` интерфейс называется именно `BiFunction`. во фрагменте ниже объявление записано под именем `Function` с тремя параметрами типа: это расходится с библиотечным именем, сигнатура `apply` при этом та же.

```java


public interface Function<T, U, R> {

	R apply(T t, U u);

}
```

пример:

```java


import java.util.function.BiFunction;



public class Program {



    public static void main(String[] args) {

         

        BiFunction<Integer, Integer, Integer> sum = (x, y) -> x + y;

         

        System.out.println(sum.apply(3, 5)); // 8

        System.out.println(sum.apply(10, -2)); // 8

    } 

}
```

функция `sum` складывает два `Integer` и возвращает `Integer`. `apply(3, 5)` даёт 8, `apply(10, -2)` тоже даёт 8, потому что `10 + (-2)` равно 8.

### consumer

`Consumer<T>` выполняет действие над объектом типа `T` и не возвращает значения: метод `accept` имеет тип результата `void`. это сторона эффекта, а не отображения.

```java


public interface Consumer<T> {

	void accept(T t);

}
```

пример:

```java


import java.util.function.Consumer;



public class Program {



    public static void main(String[] args) {

        

        Consumer<Integer> printer = x-> System.out.printf("%d долларов \n", x);

        printer.accept(600); // 600 долларов

	}

}
```

`printer` печатает число в формате «n долларов». `accept(600)` выводит строку `600 долларов`.

### supplier

`Supplier<T>` не принимает аргументов и возвращает объект типа `T`. метод называется `get`.

```java


public interface Supplier<T> {

	T get();

}
```

этот интерфейс используют для ленивого, то есть отложенного, вычисления: результат может понадобиться не в момент создания поставщика, а позже, и до вызова `get` тело лямбды не выполняется.

пример:

```java


import java.util.function.Supplier;



public class Program {



    public static void main(String[] args) {

         

        Supplier<Integer> randomValue = ()-> (int)(Math.random() * 10) + 1;

         

        System.out.println("Случайное значение");

        System.out.println(randomValue.get());  // реальные вычисления происходят тут

    } 

}
```

переменная `randomValue` хранит выражение для случайного целого от 1 до 10, но само выражение ещё не вычислено. вычисление происходит в момент вызова `get()`, когда значение действительно запрашивается. повторный `get()` выполнит лямбду ещё раз и может вернуть другое число: поставщик не запоминает предыдущий результат.
