интерфейс `Set` расширяет `Collection` и задает набор уникальных элементов. новых операций он почти не вводит и меняет контракт унаследованных. метод `add` добавляет элемент и возвращает `true`, только если равного элемента в наборе еще нет. равенство определяется методом `equals`. если элемент уже присутствует, `add` возвращает `false` и набор не меняется.

из методов, добавленных самим `Set`, для построения набора используются два статических:

- `static <E> Set<E> of(E... elements)`: возвращает неизменяемый набор из переданных элементов

- `static <E> Set<E> copyOf(Collection<? extends E> col)`: возвращает неизменяемый набор и копирует в него все элементы коллекции col

оба запрещают `null`: нулевой аргумент дает `NullPointerException`. повтор элемента в `of` дает `IllegalArgumentException`. попытка потом вызвать `add` или `remove` дает `UnsupportedOperationException`, потому что набор немодифицируемый. порядок обхода у результата `of` контрактом не зафиксирован.

создание набора методом `of`:

```java


import java.util.Set;

 

public class Program{

      

    public static void main(String[] args) {

          

        Set<String> people = Set.<String>of("Tom", "Bob", "Sam");



        System.out.println(people); // [Tom, Sam, Bob]

    }

}
```
вызов с тремя строками возвращает неизменяемый набор, конкретный класс которого в этой реализации есть `java.util.ImmutableCollections$SetN`. это вложенный класс пакета и деталь реализации. код программы на это имя не опирается. печать показывает элементы без гарантии порядка вставки.

уникальность проверяется через `equals`, который есть у любого объекта. два одинаковых значения в `of` до выполнения тела не доходят: фабрика отвергает повтор.

```java


import java.util.Set;

 

public class Program{

      

    public static void main(String[] args) {

          

        Set<String> people = Set.<String>of("Tom", "Bob", "Sam", "Tom");  // Ошибка! duplicate element: Tom



        System.out.println(people);

    }

}
```
распространенная реализация `Set` есть обобщенный класс `HashSet`. он хранит элементы в хеш-таблице. класс наследует `AbstractSet`, а `AbstractSet` реализует `Set`. внутри `HashSet` это `HashMap`, где элементы набора служат ключами, а значением стоит один и тот же служебный объект.

в хеш-таблице у каждого объекта есть хеш-код, целое число. по нему выбирается корзина, и внутри корзины объект отличают от остальных вызовом `equals`. код считает метод `hashCode` самого объекта, обычно по тем полям, которые участвуют в равенстве. разным состояниям нужны по возможности разные коды, иначе много элементов сваливается в одну корзину и поиск из среднего `O(1)` скатывается к просмотру списка. код должен считаться быстро и зависеть только от того состояния, которое учитывает `equals`. контракт языка требует: если `equals` возвращает `true`, `hashCode` у обоих объектов обязан совпадать. иначе `HashSet` не найдет элемент, который по равенству в наборе уже есть.

у `HashSet` четыре конструктора:

- `HashSet()`: создает пустой набор. начальная емкость таблицы по умолчанию 16, коэффициент заполнения 0.75

- `HashSet(Collection<? extends E> col)`: создает хеш-таблицу и добавляет в нее все элементы коллекции col

- `HashSet(int capacity)`: параметр capacity задает начальную емкость таблицы. значение по умолчанию, если емкость не передана, равно 16

- `HashSet(int capacity, float koef)`: параметр koef, коэффициент заполнения, лежит в пределах от 0.0 до 1.0. он задает, при какой доле занятых корзин таблица расширяется. в jdk тот же параметр называется `loadFactor`. коэффициент 0.75 означает расширение, когда число элементов превышает три четверти емкости. при расширении емкость удваивается, и элементы раскладываются по новым корзинам заново

пустая хеш-таблица:

```java


import java.util.HashSet;



public class Program{

     

	public static void main(String[] args) {

         

        HashSet<String> langs = new HashSet<String>();

    }

}
```
хеш-таблица по уже готовой коллекции, здесь по неизменяемому набору:

```java


import java.util.Set;

import java.util.HashSet;

 

public class Program{

      

    public static void main(String[] args) {

          

        Set<String> data = Set.<String>of("Java", "JavaScript", "C#");



        HashSet<String> langs = new HashSet<String>(data);



        System.out.println(langs); // [C#, Java, JavaScript]

    }

}
```
конструктор копирования обходит исходную коллекцию и вызывает `add` для каждого элемента. повторы при этом схлопываются, порядок обхода `HashSet` по-прежнему не совпадает с порядком вставки. строки `Java`, `JavaScript` и `C#` оказываются в наборе, а печать выстраивает их по корзинам, не по алфавиту.

`HashSet` в основном реализует методы родительских классов и интерфейсов. основные из них:

- `boolean add(E e)`: добавляет указанный элемент в этот набор, если его еще нет

- `void clear()`: удаляет все элементы из этого набора

- `Object clone()`: возвращает поверхностную копию данного экземпляра `HashSet`. сами элементы не клонируются, в новую таблицу копируются ссылки

- `boolean contains(Object o)`: возвращает `true`, если этот набор содержит указанный элемент

- `boolean isEmpty()`: возвращает `true`, если этот набор не содержит элементов

- `Iterator<E> iterator()`: возвращает итератор по элементам этого набора

- `static <E> HashSet<E> newHashSet(int numElements)`: создает новый пустой `HashSet`, емкость которого рассчитана на ожидаемое число элементов, чтобы при их добавлении таблица не расширялась. метод есть в jdk с выпуска 19

- `boolean remove(Object o)`: удаляет указанный элемент из этого набора, если он присутствует

- `int size()`: возвращает количество элементов в этом наборе

- `Object[] toArray()`: возвращает массив, содержащий все элементы этой коллекции

`add` кладет объект в таблицу, если равного еще нет, и тогда возвращает `true`. если элемент уже есть, таблица не меняется, а метод возвращает `false`:

```java


import java.util.HashSet;

 

public class Program{

      

    public static void main(String[] args) {



        HashSet<String> langs = new HashSet<String>();

        // добавим ряд объектов

        langs.add("Java");

        langs.add("C++");

        langs.add("C#");

        // пытаемся добавить элемент, который уже есть в коллекции

        boolean isAdded = langs.add("Java");

        System.out.println(isAdded);    // false

        

        System.out.printf("langs size: %d \n", langs.size());    // langs size: 3

          

        System.out.println(langs); // [C#, Java, C++]

    }

}
```
повторная вставка `Java` отвергается, размер остается равным 3. порядок в выводе снова не является порядком вызовов `add`.

`remove` удаляет объект из таблицы и при успехе возвращает `true`. если объекта нет, набор не меняется, а метод возвращает `false`. полное удаление делает `clear`:

```java


import java.util.Set;

import java.util.HashSet;

 

public class Program{

      

    public static void main(String[] args) {

          

        Set<String> data = Set.<String>of("Java", "JavaScript", "C#", "Python");

        HashSet<String> langs = new HashSet<String>(data);

        // удаляем язык JavaScript

        boolean isRemoved = langs.remove("JavaScript");

        System.out.println("JavaScript removed: " + isRemoved);    // true



        // удаляем язык OCalm

        isRemoved = langs.remove("OCalm");

        System.out.println("OCalm removed: " + isRemoved);    // false

          

        System.out.println(langs); // [C#, Java, Python]



        // удаляем все

        langs.clear();

        System.out.println(langs); // []

    }

}
```
`JavaScript` в наборе есть, поэтому первое удаление возвращает `true`. `OCalm` нет, второе возвращает `false`. `clear` оставляет пустой набор, его печать есть `[]`.
