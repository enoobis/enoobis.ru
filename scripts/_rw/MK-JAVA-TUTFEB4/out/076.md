интерфейс `Iterator` задает односторонний обход коллекции. его определение:

```java


public interface Iterator <E>{

    

   boolean hasNext();

   E next();

   default void remove();

   default void forEachRemaining(Consumer<? super E> action);

}
```
`next` возвращает следующий элемент и сдвигает курсор. `hasNext` сообщает, остался ли элемент, и в конце коллекции возвращает `false`. `hasNext` вызывают до `next`: когда элементов больше нет, `next` выбрасывает `NoSuchElementException`. `remove` удаляет элемент, который вернул последний вызов `next`. это необязательная операция. у итератора `ArrayList` она поддерживается, а вызов без предшествующего `next` или второй `remove` подряд дает `IllegalStateException`. реализация по умолчанию в интерфейсе бросает `UnsupportedOperationException`. `forEachRemaining` применяет действие к оставшимся элементам.

итераторы коллекций вроде `ArrayList` устроены как fail-fast. структурное изменение коллекции в обход этого итератора, например прямой `add` или `remove` у списка, помечает обход недействительным, и следующий вызов итератора выбрасывает `ConcurrentModificationException`. удалять текущий элемент во время обхода нужно методом самого итератора.

обход `ArrayList` итератором:

```java


import java.util.Collection;

import java.util.ArrayList;

import java.util.Iterator;

 

public class Program{

      

    public static void main(String[] args) {

          

        Collection<String> people = new ArrayList<String>();

        people.add("Tom");

        people.add("Bob");

        people.add("Sam");

         

        // получаем интератор коллекции people

        Iterator<String> iter = people.iterator();

        // используя итератор, перебираем коллекцию

        while(iter.hasNext()){

         

            System.out.println(iter.next());

        }

    }

}
```
`iterator` возвращает итератор, поставленный перед первым элементом. цикл печатает элементы в порядке списка:

```bash


Tom

Bob

Sam
```
для такого просмотра короче цикл for-each:

```java


import java.util.Collection;

import java.util.ArrayList;

 

public class Program{

      

    public static void main(String[] args) {

          

        Collection<String> people = new ArrayList<String>();

        people.add("Tom");

        people.add("Bob");

        people.add("Sam");

         

        for(var p : people){

            System.out.println(p);

        }

    }

}
```
для объекта `Iterable` компилятор разворачивает for-each в тот же протокол: получить `iterator`, пока `hasNext` возвращает `true`, вызывать `next`. у массива развертка другая, по индексу. семантика обхода коллекции от выбора записи не меняется.

### встроенные реализации итераторов

`Iterator` умеет только идти вперед и удалять текущий элемент. для отдельных видов коллекций в jdk есть расширения. `ListIterator` используют классы списков, `LinkedList`, `ArrayList` и другие реализации `List`.

`ListIterator` расширяет `Iterator`. курсор стоит между элементами, поэтому у списка есть движение в обе стороны и вставка в позицию курсора. дополнительные и уточненные методы:

- `void add(E obj)`: вставляет obj перед элементом, который вернул бы следующий `next`. после вставки `previous` вернулся бы к вставленному элементу

- `boolean hasNext()`: возвращает `true`, если дальше по направлению к концу есть элемент, иначе `false`

- `boolean hasPrevious()`: возвращает `true`, если по направлению к началу есть элемент, иначе `false`

- `E next()`: возвращает элемент за курсором и переносит курсор вперед. если элемента нет, выбрасывает `NoSuchElementException`

- `E previous()`: возвращает элемент перед курсором и переносит курсор назад. если элемента нет, выбрасывает `NoSuchElementException`

- `int nextIndex()`: возвращает индекс элемента, который вернул бы `next`. если курсор стоит в конце, возвращает размер списка

- `int previousIndex()`: возвращает индекс элемента, который вернул бы `previous`. если курсор стоит в начале, возвращает -1

- `void remove()`: удаляет из списка элемент, который вернул последний `next` или `previous`. метод вызывают после `next` или `previous`. без такого вызова, либо после `add` или повторного `remove`, выбрасывается `IllegalStateException`

- `void set(E obj)`: заменяет элемент, который вернул последний `next` или `previous`, ссылкой на obj

обход списочным итератором:

```java


import java.util.ListIterator;

import java.util.ArrayList;

 

public class Program{

      

    public static void main(String[] args) {

          

        var people = new ArrayList<String>();

        people.add("Tom");

        people.add("Bob");

        people.add("Sam"); 

         

        ListIterator<String> listIter = people.listIterator();

         

        while(listIter.hasNext()){

         

            System.out.println(listIter.next());

        }

        // сейчас текущий элемент - Sam

        // изменим значение этого элемента

        listIter.set("Sammy");

        // пройдемся по элементам в обратном порядке

        while(listIter.hasPrevious()){

         

            System.out.println(listIter.previous());

        }  

    }

}
```
прямой проход печатает `Tom`, `Bob`, `Sam` и оставляет курсор за последним элементом. последним возвращенным был `Sam`, поэтому `set("Sammy")` заменяет именно его. обратный проход вызывает `previous`, пока `hasPrevious` истинен, и печатает уже замененный список с хвоста:

```bash


Tom

Bob

Sam

Sammy

Bob

Tom
```
### интерфейс `Iterable`

цикл for-each применим к любому объекту, который реализует `Iterable` и его метод `iterator`:

```java


public interface Iterable<E>

{

    Iterator<E> iterator();

    ....

}
```
метод возвращает итератор, объект с интерфейсом `Iterator`. им и выполняется обход экземпляра класса, реализующего `Iterable`.

`Collection` расширяет `Iterable`, поэтому все коллекции наследуют `iterator`:

```java


public interface Collection<E>

{

    Iterator<E> iterator();

    ................
```
цикл for-each из-за этого работает с любой коллекцией java collections framework. помимо `iterator`, в `Iterable` есть методы по умолчанию `forEach` и `spliterator`. фрагмент интерфейса в листинге показывает только метод, который нужен циклу.

### собственная реализация итераторов

`Iterable` и `Iterator` не привязаны к коллекциям jdk. любой класс можно представить как конечную последовательность объектов и отдать ее тому же циклу. ниже интерфейсы реализованы для обхода свойств собственного класса.

```java


import java.util.Iterator;

 

public class Program{

      

    public static void main(String[] args) {

          

        Person tom = new Person(22, "Tom", 41);

        for(var prop : tom){

            System.out.println(prop);

        }

    }

}



class PersonIterator implements Iterator<String>{



    int currentProp = 0;

    Person person;



    PersonIterator(Person person){ this.person = person; }



    public boolean hasNext(){ return currentProp < 3; }



    public String next(){

        return switch(currentProp++){



            case 0 -> String.valueOf(person.getId());

            case 1 -> person.getName();

            case 2 -> String.valueOf(person.getAge());

            default -> null;

        };

    }

}



class Person implements Iterable{



    private int id;

    private String name;

    private int age;



    int getId() { return id;}

    String getName() { return name;}

    int getAge() { return age;}



    private PersonIterator iter = null;





    Person(int id, String name, int age){



        this.id = id;

        this.age = age;

        this.name = name;

    }



    public PersonIterator iterator(){

        if(iter == null){

            iter = new PersonIterator(this);

        }

        return iter;

    }

}
```
задача этого кода: сделать экземпляр перечислимым в цикле for-each. перебирается объект класса `Person`, описание человека.

```java


class Person implements Iterable{

    // ... поля и конструктор ...



    public PersonIterator iterator(){

        if(iter == null){

            iter = new PersonIterator(this);

        }

        return iter;

    }

}
```
устройство класса:

- `implements Iterable`: класс берет на себя обязательство предоставить `iterator`. цикл for-each вызывает этот метод сам, в исходном тексте вызов не написан

- `public PersonIterator iterator()`: метод возвращает объект, который реализует `Iterator`. здесь это экземпляр `PersonIterator`

класс объявлен как сырой `Iterable`, без аргумента типа. возвращается конкретный `PersonIterator`, а не тип `Iterator<String>`. для цикла этого достаточно: у возвращенного объекта есть `hasNext` и `next`.

логика обхода собрана в `PersonIterator`:

```java


class PersonIterator implements Iterator<String>{

    // ... поля и конструктор ...



    public boolean hasNext(){ return currentProp < 3; }



    public String next(){

        return switch(currentProp++){

            // ...

        };

    }

}
```
- `implements Iterator<String>`: итератор выдает значения типа `String`

- `boolean hasNext()`: цикл for-each вызывает метод перед каждой итерацией. `true` означает, что следующий элемент есть, `false` означает конец. у `Person` три свойства, и метод возвращает `true`, пока счетчик `currentProp` меньше 3

- `String next()`: возвращает следующий элемент и вызывается, только если `hasNext` уже вернул `true`. выражение `switch` по текущему `currentProp` последовательно отдает поля id, name и age строками. постфиксный `currentProp++` увеличивает счетчик после выбора ветви

`PersonIterator` и есть описание того, в каком порядке читать свойства `Person`. с классом его связывает `Iterable`: `Person.iterator` отдает этот объект циклу.

итератор сохранен в поле и создается один раз. `currentProp` нигде не обнуляется. повторный for-each по тому же экземпляру застает счетчик равным 3, `hasNext` сразу возвращает `false`, и второй обход пуст. чтобы обходить объект многократно, `iterator` должен создавать новый итератор или сбрасывать счетчик.

в `main` создается `Person`, и его свойства читает цикл:

```java


public static void main(String[] args) {

      

    Person tom = new Person(22, "Tom", 41);

    for(var prop : tom){

        System.out.println(prop);

    }

}
```
результат программы:

```bash


22

Tom

41
```
сначала печатается идентификатор 22, затем имя `Tom`, затем возраст 41. это порядок ветвей `switch`, а не порядок полей в памяти и не алфавит имен.

### метод `forEach`

вместо цикла for-each коллекцию обходят методом `forEach`, а остаток итератора методом `forEachRemaining`. обоим передается лямбда, то есть `Consumer`, и она применяется к элементу. `forEach` проходит все элементы. `forEachRemaining` проходит только те, до которых курсор еще не дошел:

```java


coll.forEach(element -> действия с element);

iter.forEachRemaining(element -> действия с element);
```
`forEach` объявлен в `Iterable` как метод по умолчанию, с java 8, и коллекции получают его оттуда. имя `Collection.forEach` есть тот же метод.

пример:

```java


import java.util.ArrayList;

 

public class Program{

      

    public static void main(String[] args) {

          

        var people = new ArrayList<String>();

        people.add("Tom");

        people.add("Bob");

        people.add("Sam"); 

         

        // p представляет каждый объект в people

        people.forEach(p -> System.out.println(p) );

    }

}
```
параметр `p` есть очередной элемент `people`. лямбда печатает его. порядок совпадает с порядком итератора списка, от первого индекса к последнему.
