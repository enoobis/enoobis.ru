сортировка задаёт на элементах коллекции полный порядок и расставляет их в соответствии с ним. в java у списков и у ряда других структур методы сортировки уже есть, но сам порядок произвольный класс не несёт. его описывают два интерфейса: `Comparator` и `Comparable`. первый сравнивает пару объектов снаружи, второй встраивает сравнение в сам класс элемента.

базовые операции списка собраны в `List`. среди них есть сортировка:

```java


default void sort(Comparator<? super E> c)
```

в `sort` передаётся компаратор, и параметр типа согласован с типом элементов. запись `Comparator<? super E>` разрешает компаратор, объявленный и на `E`, и на супертипе `E`: метод только читает элементы. по знаку, который вернёт компаратор, алгоритм решает, какой из двух элементов поставить раньше.

у `Comparator` несколько операций. порядок задаёт `compare`:

```java
   

public interface Comparator<T> {



	int compare(T a, T b);

	// остальные методы

}
```

`compare` принимает два объекта и возвращает `int`. смысл знака фиксирован контрактом:

- если a предшествует b, возвращается отрицательное число
- если b предшествует a, возвращается положительное число
- если a и b совпадают в этом порядке, возвращается ноль

ноль здесь означает совпадение в заданном порядке. для `List.sort` этого достаточно. в деревьях поиска (`TreeSet`, `TreeMap`) тот же ноль означает равенство ключей: если `compare` возвращает 0 для объектов, которые `equals` различает, инвариант множества расходится с равенством. интерфейс функциональный, абстрактный метод один, поэтому реализацией может быть и отдельный класс, и лямбда. остальные методы `Comparator` имеют тело по умолчанию и строят новые порядки из уже заданных. ниже для этого используется `thenComparing`.

для своего типа объявляют класс компаратора. элемент в примерах: `Person`, имя и возраст.

```java


class Person{



    private String name;

    private int age;



    String getName(){ return name; }

    int getAge(){ return age;}



    Person(String name, int age){

        this.name = name;

        this.age = age;

    }



    void print(){

        System.out.printf("Person Name: %s;  Age: %d;\n", name, age);

    }

}
```

порядок на паре объектов `Person` и есть правило сортировки. его выносят в отдельный класс:

```java


class PersonNameComparator implements Comparator<Person>{

 

    public int compare(Person a, Person b){

     

        return a.getName().compareTo(b.getName());

    }

}
```

сравнение идёт по полю `name`. у `String` уже есть `compareTo`, посимвольное сравнение заново не пишут. если `a.getName()` лексикографически раньше `b.getName()`, `compareTo` возвращает отрицательное число. если позже, положительное. если строки равны, возвращается 0. этот порядок сравнивает коды utf-16. регистр и диакритика с правилами конкретного языка не отождествляются.

ту же точку расширения занимает другая формула. ниже компаратор сравнивает длины имён:

```java


class PersonNameComparator implements Comparator<Person>{

 

    public int compare(Person a, Person b){

     

        return a.getName().length()-p.getName().length();

    }

}
```

из длины имени первого объекта вычитается длина имени второго. отрицательная разность ставит более короткое имя раньше. во фрагменте второй вызов записан как `p.getName()`, а параметр метода называется `b`, поэтому в таком виде фрагмент не компилируется. сама формула: разность длин.

та же схема в одной программе, сортировка по имени:

```java


import java.util.ArrayList; 

import java.util.Comparator; 



public class Program{

      

    public static void main(String[] args) {

         

        var people = new ArrayList<Person>();

        people.add(new Person("Tom", 41));

        people.add(new Person("Bob", 46));

        people.add(new Person("Sam", 28));



        people.sort(new PersonNameComparator());



        for(var p : people){

            p.print();

        }

    }

}

class PersonNameComparator implements Comparator<Person>{

 

    public int compare(Person a, Person b){

     

        return a.getName().compareTo(b.getName());

    }

}



class Person{



    private String name;

    private int age;



    String getName(){ return name; }

    int getAge(){ return age;}



    Person(String name, int age){

        this.name = name;

        this.age = age;

    }



    void print(){

        System.out.printf("Person Name: %s;  Age: %d;\n", name, age);

    }

}
```

`var` выводит тип списка из конструктора: `ArrayList` с аргументом `Person`. в список попадают три объекта, в `sort` передаётся экземпляр `PersonNameComparator`. цикл for-each обходит уже переставленные ссылки и печатает их через `print`.

вызов сортировки в тексте записан так:

```java
people.sort(new PersonComparator());
```

в полной программе класс называется `PersonNameComparator`. короткий фрагмент использует имя `PersonComparator`. после упорядочивания по `name` консоль показывает:

```bash


Person Name: Bob;  Age: 46;

Person Name: Sam;  Age: 28;

Person Name: Tom;  Age: 41;
```

имена идут bob, sam, tom. это лексикографический порядок строк. возраст в нём не участвует.

аналогично строится компаратор по полю `age`:

```java


import java.util.ArrayList; 

import java.util.Comparator; 



public class Program{

      

    public static void main(String[] args) {

         

        var people = new ArrayList<Person>();

        people.add(new Person("Tom", 41));

        people.add(new Person("Bob", 46));

        people.add(new Person("Sam", 28));



        people.sort(new PersonAgeComparator());



        for(var p : people){

            p.print();

        }

    }

}

class PersonAgeComparator implements Comparator<Person>{

  

    public int compare(Person a, Person b){



        return a.getAge() - b.getAge();

    }

}



class Person{



    private String name;

    private int age;



    String getName(){ return name; }

    int getAge(){ return age;}



    Person(String name, int age){

        this.name = name;

        this.age = age;

    }



    void print(){

        System.out.printf("Person Name: %s;  Age: %d;\n", name, age);

    }

}
```

`PersonAgeComparator` возвращает `a.getAge() - b.getAge()`. та же развилка, расписанная по веткам:

```java


class PersonAgeComparator implements Comparator<Person>{

  

    public int compare(Person a, Person b){

      

        if(a.getAge() > b.getAge())

            return 1;

        else if(a.getAge() < b.getAge())

            return -1;

        else

            return 0;

    }

}
```

вычитание короче условной конструкции: ветвлений меньше, а знак разности для возрастов из примера совпадает со знаком сравнения. у `int` та же разность вблизи границ диапазона переполняется, и знак становится неверным. `Integer.compare` вычисляет знак без этого переполнения. пример опирается на вычитание, значения возраста здесь малы, и переполнение не наступает.

после сортировки по `age` вывод другой:

```bash


Person Name: Sam;  Age: 28;

Person Name: Tom;  Age: 41;

Person Name: Bob;  Age: 46;
```

первым оказывается младший: sam с возрастом 28, затем tom с возрастом 41, затем bob с возрастом 46.

### сочетание компараторов

компараторы соединяют по приоритету. сначала порядок задаёт `name`. если имена равны и первый компаратор вернул 0, применяется порядок по `age`.

для такой цепочки у `Comparator` есть `thenComparing`. метод возвращает новый компаратор: композицию текущего и переданного. второй вызывается только тогда, когда первый вернул ноль. получается лексикографическое произведение двух порядков.

```java


import java.util.ArrayList; 

import java.util.Comparator; 



public class Program{

      

    public static void main(String[] args) {

         

        var people = new ArrayList<Person>();

        people.add(new Person("Tom", 22));

        people.add(new Person("Tom", 41));

        people.add(new Person("Bob", 46));

        people.add(new Person("Bob", 37));

        people.add(new Person("Sam", 28));



        Comparator<Person> totalComparator = new PersonNameComparator().thenComparing(new PersonAgeComparator());

        people.sort(totalComparator);



        for(var p : people){

            p.print();

        }

    }

}
```

короткий фрагмент сборки цепочки:

```java
PersonNameComparator().thenComparing(new PersonAgeComparator());
```

в программе результат сохраняется в `totalComparator` и передаётся в `people.sort`. там вызов записан как `new PersonNameComparator().thenComparing(new PersonAgeComparator())`. составной компаратор элементы не двигает: он отвечает, кто из двоих раньше. перестановку выполняет `sort`. контракт метода требует устойчивость: при нулевом сравнении прежний относительный порядок элементов сохраняется. в этом примере ничья по имени снимается вторым компаратором, поэтому возраст внутри одинаковых имён задан явно.

консольный вывод:

```bash


Person Name: Bob;  Age: 37;

Person Name: Bob;  Age: 46;

Person Name: Sam;  Age: 28;

Person Name: Tom;  Age: 22;

Person Name: Tom;  Age: 41;
```

сначала оба bob, внутри пары возраст по возрастанию: 37, затем 46. дальше sam. затем оба tom: 22, затем 41.

## интерфейс comparable

второй способ задать порядок: интерфейс `Comparable`. сравнение становится частью класса элемента. интерфейс объявляет один метод, `compareTo`:

```java


public interface Comparable

{

   int compareTo(Object other);

}
```

роль та же, что у `compare` в `Comparator`. сравнивается текущий объект с аргументом. у `compare` оба объекта приходят параметрами. фрагмент показывает сырую форму без параметра типа: аргумент имеет тип `Object`. в jdk интерфейс обобщён, `Comparable<T>`, и `compareTo` принимает `T`. знак результата:

- если текущий объект меньше other, возвращается отрицательное число
- если текущий объект больше other, возвращается положительное число
- если объекты равны в этом порядке, возвращается ноль

ряд классов jdk уже реализует `Comparable`. в `PersonNameComparator` строки сравнивались так:

```java
return a.getName().compareTo(b.getName());
```

это естественный порядок `String`, реализация `Comparable<String>`. его же берёт сортировка списка, когда элементы сами умеют сравниваться:

```java


import java.util.ArrayList; 



public class Program{

      

    public static void main(String[] args) {

         

        var people = new ArrayList<String>();

        people.add("Tom");

        people.add("Bob");

        people.add("Sam");



        people.sort(null);



        for(var p : people){

            System.out.println(p);

        }



    }

}
```

список строк сортируется. консольный вывод:

```bash


Bob

Sam

Tom
```

сортировка проходит, потому что в `sort` передан `null`. нулевой компаратор означает естественный порядок: каждый элемент обязан реализовать `Comparable`, и алгоритм вызывает `compareTo`. для `String` это снова лексикографический порядок кодов utf-16. если элемент интерфейс не реализует, приведение во время сравнения заканчивается `ClassCastException`. компилятор вызов `sort(null)` сам по себе не отвергает: проверка откладывается до выполнения.

тот же интерфейс реализуют и собственные классы:

```java


class Person implements Comparable<Person>{



    private String name;

    private int age;



    String getName(){ return name; }

    int getAge(){ return age;}



    Person(String name, int age){

        this.name = name;

        this.age = age;

    }



    void print(){

        System.out.printf("Person Name: %s;  Age: %d;\n", name, age);

    }



    public int compareTo(Person p){

     

        return name.compareTo(p.getName());

    }

}
```

пороги 1, -1 и 0 в теле не записаны. `compareTo` возвращает результат `name.compareTo`, то есть естественный порядок поля `name`. порядок `Person` тем самым совпадает с порядком имён.

применение в программе:

```java


import java.util.ArrayList; 



public class Program{

      

    public static void main(String[] args) {

         

        var people = new ArrayList<Person>();

        people.add(new Person("Tom", 41));

        people.add(new Person("Bob", 46));

        people.add(new Person("Sam", 28));



        people.sort(null); // сортировка на основе реализации Comparable



        for(var p : people){

            p.print();

        }



    }

}



class Person implements Comparable<Person>{



    private String name;

    private int age;



    String getName(){ return name; }

    int getAge(){ return age;}



    Person(String name, int age){

        this.name = name;

        this.age = age;

    }



    void print(){

        System.out.printf("Person Name: %s;  Age: %d;\n", name, age);

    }



    public int compareTo(Person p){

     

        return name.compareTo(p.getName());

    }

}
```

`people.sort(null)` берёт порядок из `Comparable`, который реализован классом `Person`. комментарий в вызове фиксирует именно это. консольный вывод:

```bash


Person Name: Bob;  Age: 46;

Person Name: Sam;  Age: 28;

Person Name: Tom;  Age: 41;
```

имена стоят в порядке bob, sam, tom. возраст в сравнение не входит: `compareTo` читает только `name`. у класса один естественный порядок. внешний `Comparator`, переданный в `sort` вместо `null`, задаёт другой порядок на время одной операции и класс элемента не меняет. `Comparable` фиксирует порядок по умолчанию, `Comparator` задаёт порядок снаружи.
