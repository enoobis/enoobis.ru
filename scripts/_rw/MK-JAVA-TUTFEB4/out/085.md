### запись текста через буфер и `BufferedWriter`

`BufferedWriter` пишет текст в символьный поток и предварительно складывает символы в буфер. число обращений к физическому носителю падает: в файл уходит пачка символов, а не отдельный системный вызов на каждый `char`.

конструкторы:

```java


BufferedWriter(Writer out) 

BufferedWriter(Writer out, int sz)
```

первый аргумент это поток вывода `Writer`, в который выполняется запись. второй аргумент `sz` задаёт размер буфера в символах. без явного размера берётся буфер на 8192 символа.

запись в файл:

```java


import java.io.*;



public class Program {

 

    public static void main(String[] args) {

         

		try(BufferedWriter bw = new BufferedWriter(new FileWriter("notes4.txt")))

        {

			String text = "Hello  World!\nHey! Teachers! Leave the kids alone.";

			bw.write(text);

        }

        catch(IOException ex){

             

            System.out.println(ex.getMessage());

        } 

    } 

}
```

`FileWriter` открывает `notes4.txt`, `BufferedWriter` его оборачивает. `write` принимает строку с уже расставленными переводами строки `\n`. пока буфер не заполнен, байты могут ещё не лежать на диске. выход из try-with-resources вызывает `close()`, тот сбрасывает буфер и закрывает `FileWriter`. для короткой строки этого сброса достаточно, отдельный `flush` в теле не вызван.

### чтение текста и `BufferedReader`

`BufferedReader` читает текст из символьного потока ввода и буферизует прочитанные символы. буфер повышает производительность: вложенный `Reader` вызывается реже, чем число символов, которые забирает программа.

конструкторы:

```java


BufferedReader(Reader in) 

BufferedReader(Reader in, int sz)
```

второй конструктор, помимо потока ввода, задаёт размер буфера, в который читаются символы. размер по умолчанию снова 8192.

`BufferedReader` наследует `Reader` и может вызывать все методы чтения, определённые в `Reader`. сверх того у него есть `readLine()`. метод читает поток построчно: возвращает содержимое строки без завершающего перевода (`\n`, `\r` или `\r\n`) и возвращает `null`, когда строк больше нет. признак конца здесь `null`, а не `-1`, потому что тип результата `String`.

применение `BufferedReader`:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

       

        try(BufferedReader br = new BufferedReader (new FileReader("notes4.txt")))

        {

           // чтение посимвольно

            int c;

            while((c=br.read())!=-1){

                

                System.out.print((char)c);

            }

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        } 

    } 

}
```

`FileReader` открывает `notes4.txt`, буфер сидит поверх него. цикл вызывает `read()` по одному символу, приводит код к `char` и печатает, пока не получит `-1`. буфер при этом заполняется крупными порциями из файла, а цикл этого не видит: для него `read()` по-прежнему отдаёт один символ.

тот же текст можно забрать построчно:

```java


try(BufferedReader br = new BufferedReader(new FileReader("notes4.txt")))

{

    //чтение построчно

    String s;

    while((s=br.readLine())!=null){

                

        System.out.println(s);

    }

}

 catch(IOException ex){

            

    System.out.println(ex.getMessage());

}
```

`readLine()` в условии цикла читает очередную строку. пока результат не `null`, строка печатается через `println`, который добавляет свой перевод строки. исходные разделители строк метод уже снял, поэтому пустая строка файла приходит как пустой `String`, а конец файла как `null`. пустую строку и конец файла путать нельзя: у пустой строки `equals("")` истинно, у `null` вызов метода недопустим.

### считывание с консоли в файл

оба класса соединяются, чтобы читать консоль и писать файл:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        try(BufferedReader br = new BufferedReader (new InputStreamReader(System.in)); 

                BufferedWriter bw = new BufferedWriter(new FileWriter("notes5.txt")))

        {

           // чтение построчно

            String text;

            while(!(text=br.readLine()).equals("ESC")){

                 

                bw.write(text + "\n");

                bw.flush();

            }

        }

        catch(IOException ex){

             

            System.out.println(ex.getMessage());

        } 

    }   

}
```

`BufferedReader` читает консоль через `new InputStreamReader(System.in)`. `InputStreamReader` декодирует байты стандартного ввода в символы кодировкой платформы по умолчанию, `BufferedReader` добавляет построчное чтение. `BufferedWriter` пишет в `notes5.txt` через `FileWriter`.

в цикле `while` читается введённая строка. пока она не равна `"ESC"` сравнением `equals`, текст вместе с `\n` уходит в файл. сравнение чувствительно к регистру: строка `esc` условие выхода не выполняет. `flush()` после каждой строки сбрасывает буфер на диск до следующей итерации, иначе введённые строки лежали бы в буфере до закрытия потока. когда пользователь вводит `ESC`, тело цикла не выполняется, блок заканчивается, и try-with-resources закрывает оба ресурса. закрытие идёт в обратном порядке объявления: сначала `BufferedWriter`, затем `BufferedReader`.
