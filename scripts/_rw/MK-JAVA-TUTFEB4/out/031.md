классы в java группируются в пакеты. пакет задаёт пространство имён: простое имя класса однозначно только внутри пакета, а полное имя складывается из имени пакета и простого имени. одинаковые простые имена, выбранные разными авторами, не конфликтуют, пока классы лежат в разных пакетах.

в платформе java уже есть стандартные пакеты, среди них `java.lang`, `java.util`, `java.io`. пакеты могут быть вложенными, и имя вложенного пакета записывается через точку. для вывода в консоль применяется класс `System`, расположенный в пакете `java.lang`.

### импорт пакетов и классов

чтобы пользоваться классами другого пакета, их подключают директивой импорта. исключение составляют классы пакета `java.lang` (например, `System`): этот пакет импортируется в каждую единицу компиляции неявно, отдельно его подключать не нужно.

класс `Date`, предназначенный для работы с датами, находится в пакете `java.util`. без импорта к нему обращаются по полному имени:

```java


java.util.Date
```

такое полное имя и есть имя типа, по которому компилятор и виртуальная машина опознают класс. программа с явным именем выглядит так:

```java


class Program {

  

    public static void main(String[] args) {

        

        java.util.Date curDate = new java.util.Date();

        System.out.println(curDate);

    }

}
```

при создании объекта указан полный путь к классу внутри пакета. длинная цепочка имён неудобна при каждом вхождении, поэтому пакеты и классы импортируют директивой `import`:

```java


import пакет.класс;
```

`import` стоит в начале единицы компиляции и вводит простое имя. директива разрешает это имя на этапе компиляции: в байткоде остаётся символическая ссылка на полное имя типа, текст пакета в файл не подставляется. ниже импортируется класс `Date`, и с его помощью на консоль выводятся текущие дата и время:

```java


import java.util.Date;



class Program {

  

    public static void main(String[] args) {

        

        Date curDate = new Date();

        System.out.println(curDate);

    }

}
```

после `import` указано имя подключаемого класса, здесь класса `Date`.

классы пакета `java.lang` подключаются автоматически, поэтому класс `System` для вывода на консоль отдельно не импортируют.

в примере выше подключён один класс, тогда как пакет `java.util` содержит и другие классы. чтобы не перечислять каждый, импортируют весь пакет, то есть выполняют импорт по требованию:

```java


import java.util.*; // импорт всех классов из пакета java.util
```

после такой директивы простое имя, не найденное среди типов текущей единицы компиляции, ищется среди типов `java.util`. доступен любой класс этого пакета.

возможна коллизия простых имён. класс `Date` есть и в пакете `java.util`, и в пакете `java.sql`. если нужны оба типа сразу, простое имя `Date` неоднозначно, и для каждого указывают полный путь:

```java


java.util.Date utilDate = new java.util.Date();

java.sql.Date sqlDate = new java.sql.Date();
```

одновременный импорт обоих классов `Date` неоднозначность простого имени не снимает: компилятору не из чего выбрать один тип. в такой ситуации остаются полные имена.

### статический импорт

в java есть отдельная форма импорта, статический импорт. вместе с директивой `import` пишется модификатор `static`:

```java


import static java.lang.System.*;

import static java.lang.Math.*;



class Program {



    public static void main(String[] args) {

        

        double result = sqrt(20);

        out.println(result);

    } 

}
```

здесь статически импортируются члены классов `System` и `Math`. директива `import static` вводит простые имена статических членов. имя самого класса как типа эта директива не объявляет. у `System` и `Math` есть статические методы, и после статического импорта их вызывают без квалификатора класса. вместо `Math.sqrt(20)` пишут `sqrt(20)`, потому что метод `sqrt()`, возвращающий квадратный корень числа, является статическим. статические члены класса разбираются в курсе дальше.

то же относится к классу `System`: в нём объявлен статический объект `out`, и после статического импорта к этому объекту обращаются без указания класса.

### безымянные пакеты

класс не обязан входить в именованный пакет. если директивы `package` нет, класс попадает в пакет по умолчанию, у которого нет имени. пусть исходный файл содержит такой код:

```java


class Program {

  

    public static void main(String[] args) {

        

        Person tom = new Person("Tom");

        tom.print();

    }

}



class Person 

{

    String name; 



    Person(String name){



        this.name = name;

    }



    void print() {



        System.out.printf("Person %s\n", name);

    }

}
```

в файле объявлены два класса, `Program` и `Person`, и оба находятся в безымянном пакете. все классы предыдущих материалов курса, для которых пакет не задавался, тоже определялись в безымянном пакете.

у типа из безымянного пакета нет канонического имени, поэтому класс именованного пакета не может его импортировать. безымянный пакет годится для коротких примеров и не служит способом публикации библиотеки.

### установка пакета

принадлежность класса определённому пакету задаётся директивой `package`, после которой указывается имя пакета:

```java
package название_пакета;
```

имена пакетов, как правило, совпадают с физической структурой проекта, то есть с деревом каталогов, где лежат файлы исходного кода. путь к файлам внутри проекта соответствует имени пакета этих файлов. если классы принадлежат пакету `mypack`, их помещают в папку `mypack`. если классы принадлежат пакету `com.mypack`, их помещают в каталог `com/mypack`: каждая компонента имени становится уровнем каталога.

пусть структура проекта такова:

- файл `Program.java`

- папка `types`, файл `Person.java`

в корневой папке лежит файл `Program.java` и папка `types`, в которой находится файл `Person.java`.

файл `Person.java` устроен так:

```java


package types;



public class Person 

{

    String name; 



    public Person(String name){



        this.name = name;

    }



    public String getName() {



        return this.name;

    }

}
```

первая строка (`package types`) объявляет, что класс `Person` принадлежит пакету `types`. принадлежность класса пакету указывается в самом начале файла, до импорта и объявления типов. перед директивой `package` допустимы пробелы и комментарии.

отдельное требование касается модификатора `public`. если поле, метод или конструктор должны быть доступны из других пакетов, объявление предваряют словом `public`, как в этом файле конструктор класса и метод `getName()`. чтобы сам класс был доступен из других пакетов, его тоже определяют с `public`. тип верхнего уровня без `public` имеет пакетный доступ и извне пакета не виден.

далее файл `Program.java` использует класс `Person` из пакета `types`:

```java


import types.Person;  // испортируем класс Person из пакета types



class Program {

  

    public static void main(String[] args) {

        

        Person tom = new Person("Tom");

        System.out.println(tom.getName());   // Tom

    }

}
```

в начале кода подключается класс `Person` из пакета `types` (`import types.Person`). после этого доступен функционал класса, объявленный с `public`.

#### создание вложенных пакетов

в папку `types` добавляется каталог `test`, а в него новый файл `PersonTest`. структура проекта становится такой:

- файл `Program.java`

- папка `types`, файл `Person.java`

- папка `test`, файл `PersonTest.java`

в файле `PersonTest.java` записано следующее содержимое:

```java


package types.test;  // класс PersonTest находится в пакете types.test



import types.Person;  // импортируем класс Person из пакета types



public class PersonTest

{



    public static void personNameTest(){



        String name = "Bob";

        Person bob = new Person(name);

        if(name == bob.getName()){

            System.out.println("personNameTest passed!");

        }

        else{

            System.out.println("personNameTest failed...");

        }

    }

}
```

первая строка помещает класс `PersonTest` в пакет `types.test`. имя пакета снова соответствует структуре каталогов: класс `PersonTest` находится в папке `types/test` и в пакете `types.test`.

точка в имени пакета не создаёт иерархии доступа. для компилятора `types` и `types.test` являются разными пакетами: пакетный доступ одного на другой не распространяется. общий префикс нужен для раскладки каталогов и для уникальности имён.

вторая строка импортирует класс `Person` из пакета `types`.

далее объявлен класс с единственным статическим методом `personNameTest()`, который проверяет имя, пользуясь функционалом класса `Person`. чтобы метод `personNameTest()` был доступен из других пакетов, он определён с модификатором `public`.

в теле проверки локальная переменная `name` и результат `bob.getName()` сравниваются оператором `==`. для ссылочных типов этот оператор сравнивает тождественность ссылок. в конструктор передаётся та же переменная, которая хранит литерал `"Bob"`, а `getName` возвращает поле, записанное из неё, поэтому обе ссылки совпадают и выполняется ветка с текстом `personNameTest passed!`. посимвольное равенство строк устанавливает метод `equals`.

далее изменяется файл `Program.java`:

```java


import types.test.PersonTest;  // испортируем класс PersonTest из пакета types.test



class Program {

  

    public static void main(String[] args) {

        

        PersonTest.personNameTest();  // personNameTest passed!

    }

}
```

первая строка импортирует класс `PersonTest` из пакета `types.test`. в методе `main` вызывается `PersonTest.personNameTest()`, и тем самым проверяется, что функционал класса `Person` работает как задумано.

#### главный файл в отдельном пакете

до этого главный файл программы с методом `main` располагался в безымянном пакете по умолчанию. его можно поместить и в именованный пакет. в текущую папку проекта добавляется папка `enoobis`, и в неё помещается файл `Program.java`. структура получается такой:

- папка `enoobis`, файл `Program.java`

- папка `types`, файл `Person.java`

- папка `test`, файл `PersonTest.java`

в файле `Program.java` определён следующий код:

```java


package  enoobis;



import types.test.PersonTest;  // испортируем класс PersonTest из пакета types.test



class Program {

  

    public static void main(String[] args) {

        

        PersonTest.personNameTest();  // personNameTest passed!

    }

}
```

первая строка относит класс к пакету `enoobis`.

дальше программу компилируют и запускают. в консоли переходят в корневой каталог, где располагаются папки `enoobis` и `types`. компиляция выполняется командой:

```bash
javac  enoobis/Program.java
```

запуск выполняется командой:

```bash
java  enoobis.Program
```

полный сеанс работы:

```bash


eugene@Eugene:/workspace/java$ javac  enoobis/Program.java

eugene@Eugene:/workspace/java$ java  enoobis.Program

personNameTest passed!

eugene@Eugene:/workspace/java$
```

`javac` компилирует `enoobis/Program.java` и по ссылкам на типы находит `types.test.PersonTest` и `types.Person`, если исходные файлы лежат в каталогах, соответствующих пакетам. команда `java` получает полное имя запускаемого класса: пакет `enoobis` и класс `Program`. путь к файлу `.java` этой команде не передают.

#### предосторожности

при работе с пакетами учитывают, что компилятор не проверяет структуру каталогов при компиляции исходных файлов. пусть исходный файл начинается с директивы

```java
package com.mycompany;
```

`javac` может скомпилировать файл, даже если тот не находится в подкаталоге `com/mycompany`. исходный файл скомпилируется без ошибок, если он не обращается к другим невстроенным пакетам. скомпилированная программа при этом не запустится, пока файлы классов не будут перемещены на нужное место. виртуальная машина ищет класс по полному имени, превращая компоненты пакета в путь относительно classpath, и не обнаруживает классы, если пакеты не соответствуют каталогам.
