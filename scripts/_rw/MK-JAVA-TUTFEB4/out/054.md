лямбда-выражение в java задает набор инструкций, который можно сохранить в переменной и затем многократно вызвать в разных местах программы. само выражение является значением и имеет целевой тип, функциональный интерфейс.

### определение лямбда-выражения и функциональные интерфейсы

лямбда-выражение строится лямбда-оператором, стрелкой `->`. оператор делит запись на две части:

```java
 (параметры) -> действия
```

слева от стрелки параметры перечисляются через запятую, справа записываются выполняемые действия.

само по себе лямбда-выражение не запускается. оно образует реализацию метода, объявленного в функциональном интерфейсе, и вызывается уже как этот метод. пример:

```java

public class Program {

    public static void main(String[] args) {
        
        Operationable op;
        op = (x,y)->x+y;
        
        int result = op.execute(10, 20);
        System.out.println(result); //30
    }   
}
interface Operationable{
    int execute(int x, int y);
}
```

роль функционального интерфейса играет `Operationable`. в нем один метод без реализации, `execute`. метод принимает два параметра типа `int` и возвращает некоторое значение типа `int`.

объявление и использование лямбда-выражения разбивается на три шага.

- определение ссылки на функциональный интерфейс:

```java
Operationable op;
```

переменная `op` имеет тип `Operationable` и еще не связана с реализацией.

- создание лямбда-выражения. параметры лямбды соответствуют параметрам единственного метода интерфейса `Operationable`, а результат выражения соответствует результату этого метода. ключевое слово `return` для тела-выражения не пишется: значением лямбды становится значение выражения справа от стрелки. оба параметра метода имеют тип `int`, поэтому в теле допустимо сложение. сумма тоже имеет тип `int`, и этот тип совпадает с результатом метода интерфейса.

```java
op = (x,y)->x+y;
```

параметры в этой записи не типизированы явно. их типы выводятся из целевого типа `Operationable`. имена `x` и `y` выбираются в самой лямбде и с именами параметров `execute` совпадать не обязаны.

- использование лямбда-выражения в виде вызова метода интерфейса. в лямбде задано сложение параметров, поэтому результатом метода будет сумма чисел 10 и 20.

```java
int result = operation.execute(10, 20);
```

вызов идет через имя метода интерфейса. аргументы 10 и 20 попадают в параметры лямбды, выражение `x + y` дает 30, и это значение возвращается из `execute`.

лямбда-выражение является сокращенной формой внутреннего анонимного класса, которым раньше в java пользовались для той же цели: реализовать интерфейс прямо в месте вызова. предыдущий пример в такой форме выглядит так:

```java

public class Program {

    public static void main(String[] args) {
        
        Operationable op = new Operationable(){
        
            public int execute(int x, int y){
            
				return x + y;
            }
        };
         int z = op.execute(20, 10);
         System.out.println(z); // 30
    }   
}
interface Operationable{
    int execute(int x, int y);
}
```

анонимный класс реализует `Operationable`, переопределяет `execute` и возвращает сумму через явный `return`. вызов `op.execute(20, 10)` дает 30, как и лямбда. совпадает результат вызова. отличается представление. у анонимного класса есть собственный экземпляр, и `this` внутри него указывает на этот экземпляр. в лямбде `this` указывает на экземпляр объемлющего класса, а если лямбда записана в статическом контексте, своего `this` у нее нет. локальные переменные объемлющего метода лямбда не затеняет. на уровне байткода лямбда, как и ссылка на метод, связывается через `invokedynamic`, а не через отдельный class-файл, который компилятор порождал бы для каждого анонимного класса.

для одного функционального интерфейса задают сколько угодно лямбда-выражений. каждая переменная получает свою реализацию `execute`:

```java

Operationable sum = (int x, int y)-> x + y;
Operationable sub = (int x, int y)-> x - y;
Operationable mul = (int x, int y)-> x * y;
        
System.out.println(sum.execute(20, 10)); //30
System.out.println(sub.execute(20, 10)); //10
System.out.println(mul.execute(20, 10)); //200
```

`sum` складывает, `sub` вычитает, `mul` умножает. вызовы с аргументами 20 и 10 печатают 30, 10 и 200. в этой записи типы параметров указаны явно (`int x`, `int y`). для целевого типа `Operationable` явное указание не обязательно и должно совпадать с типами метода интерфейса.

если лямбда принимает один параметр, скобки вокруг него можно опустить:

```java

public class Program {

    public static void main(String[] args) {
        
        Printable printer = message -> System.out.println(message);

        printer.print("Hello World");
        printer.print("Hello Work");
    }   
}
interface Printable{
    void print(String message);
}
```

лямбда, записанная в `printer`, реализует функциональный интерфейс `Printable`. единственный метод этого интерфейса, `print`, принимает один параметр типа `String`. тело вызывает `System.out.println` с этим параметром. первый вызов печатает `Hello World`, второй печатает `Hello Work`.

другая ситуация: параметр у метода функционального интерфейса есть, но лямбда его не использует. тогда на месте параметра ставят прочерк `_`:

```java

public class Program {

    public static void main(String[] args) {
        
        Printable printer = _ -> System.out.println("Test");

        // при вызове параметру все равно надо передать значение
        // но оно не имеет значения, так как не будет использоваться
        printer.print(null);    // Test
        printer.print("brr");   // Test
    }   
}
interface Printable{
    void print(String message);
}
```

при вызове аргумент передать все равно нужно, этого требует сигнатура `print(String)`. значение в тело не попадает, поэтому и `null`, и строка `"brr"` приводят к одной и той же печати `Test`. неименованный параметр `_` в лямбде допустим начиная с java 22. с java 9 одиночный символ `_` запрещен в роли имени переменной, и только с java 22 он снова разрешен именно как неименованный параметр, а не как имя, к которому можно обратиться.

если метод интерфейса не принимает параметров, в лямбде пишутся пустые скобки:

```java

public class Program {

    public static void main(String[] args) {
        
        Hello speaker = () -> System.out.println("Привед");

        speaker.sayHello();
    }   
}
interface Hello{
    void sayHello();
}
```

пустые скобки обязательны: опустить их, как скобки единственного параметра, нельзя, иначе запись нельзя отличить от других конструкций. вызов `speaker.sayHello()` выполняет тело и печатает `Привед`.

### отложенное выполнение

практика лямбд опирается на отложенное выполнение (deferred execution). выражение описывают в одном месте программы, а вызывают позже, столько раз и в тех точках, где оно требуется. отложенное выполнение нужно, в частности, в следующих случаях:

- выполнение кода в отдельном потоке

- выполнение одного и того же кода несколько раз

- выполнение кода в результате некоторого события

- выполнение кода только в том случае, когда он действительно необходим и если он необходим

во всех этих ситуациях лямбда передается как значение. код справа от стрелки в момент создания выражения не исполняется. исполнение начинается в вызове единственного абстрактного метода функционального интерфейса.

### лямбды и локальные переменные

лямбда-выражение может использовать переменные, объявленные во внешней, более широкой области видимости: на уровне класса или на уровне метода, в котором выражение записано. способ использования зависит от того, где переменная объявлена. первый пример читает и меняет поля класса:

```java

public class Program {

    static int x = 10;
    static int y = 20;
    public static void main(String[] args) {
        
        Operation op = ()->{ 
            
            x=30;
            return x+y;
        };
        System.out.println(op.execute()); // 50
        System.out.println(x); // 30 - значение x изменилось
    }
}
interface Operation{
    int execute();
}
```

поля `x` и `y` объявлены на уровне класса и являются статическими. лямбда их читает и может изменить. в теле `x` присваивается 30, затем возвращается сумма `x + y`, то есть 50. после вызова `execute` поле `x` равно 30, что и печатает второй `println`. доступ к статическому полю идет через класс, а не через захваченную локальную копию, поэтому присваивание полю разрешено. то же верно для поля экземпляра: оно читается и пишется через захваченный `this`.

локальные переменные метода подчиняются другому правилу:

```java

public static void main(String[] args) {
        
    int n = 70;
    int m = 30;
    Operation op = ()->{ 
            
        //n = 100; - так нельзя сделать
        return m+n;
    };
	// n=100;  - так тоже нельзя
    System.out.println(op.execute()); // 100
}
```

локальные переменные метода в лямбде читать можно, присваивать им нельзя. закомментированная строка `n = 100` внутри лямбды некорректна. среда netbeans в такой ситуации показывает ошибку и указывает, что переменную надо пометить ключевым словом `final`, то есть сделать константой: `final int n = 70`. модификатор при этом не обязателен.

более того, переменную, которую лямбда использует, нельзя изменить и снаружи выражения. присваивание `n = 100` после создания лямбды, тоже показанное в комментарии, отвергается компилятором. даже без модификатора `final` такая переменная по сути константа. в спецификации языка это называется effectively final: после инициализации у переменной нет других присваиваний. требование связано с захватом. лямбда сохраняет значение локальной переменной, и это значение должно быть однозначным. если бы присваивание было разрешено и внутри лямбды, и в методе, у захваченного состояния не было бы единственного значения. поле класса этому ограничению не подчиняется, что и показывает предыдущий пример с `x` и `y`.

### блоки кода в лямбда-выражениях

у лямбда-выражения две формы тела: однострочное выражение и блок кода. однострочные тела показаны выше. блок обрамляется фигурными скобками. внутри блока допустимы вложенные блоки, циклы, конструкции `if` и `switch`, локальные переменные. если блок должен вернуть значение, результат передается явным оператором `return`. в теле-выражении `return` как раз не пишется, в теле-блоке без `return` вернуть значение нельзя.

```java

Operationable operation = (int x, int y)-> {
        
    if(y==0)
        return 0;
    return x/y;
};
        
System.out.println(operation.execute(20, 10)); //2
System.out.println(operation.execute(20, 0)); //0
```

при `y`, равном 0, блок возвращает 0 и деления не выполняет. иначе возвращается частное `x / y`. вызов с аргументами 20 и 10 печатает 2, вызов с аргументами 20 и 0 печатает 0. оба `return` обязательны: это тело-блок, и каждый путь, который покидает лямбду со значением, указывает это значение через `return`.

### обобщенный функциональный интерфейс

функциональный интерфейс может быть обобщенным. в самой лямбде параметры типа объявлять нельзя. аргумент типа задается у переменной интерфейса, и уже этот целевой тип применяется в лямбда-выражении.

```java

public class Program {

    public static void main(String[] args) {
        
        Operationable<Integer> operation1 = (x, y)-> x + y;
        Operationable<String> operation2 = (x, y) -> x + y;
        
        System.out.println(operation1.execute(20, 10)); //30
        System.out.println(operation2.execute("20", "10")); //2010
    } 
}
interface Operationable<T>{
    T execute(T x, T y);
}
```

к моменту проверки лямбды целевой тип известен, поэтому известны и типы параметров, и тип результата. у `operation1` параметр `T` равен `Integer`, сложение целочисленное, `execute(20, 10)` возвращает 30. у `operation2` параметр `T` равен `String`, оператор `+` означает конкатенацию, и `execute("20", "10")` возвращает строку `2010`. одна и та же запись `(x, y) -> x + y` получает разный смысл из целевого типа, а не из текста лямбды. объявить собственный параметр типа непосредственно у лямбда-выражения нельзя: обобщение принадлежит функциональному интерфейсу, который служит целью присваивания.
