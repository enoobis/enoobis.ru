когда у обобщения указывается параметр типа, по умолчанию аргументом может быть любой ссылочный тип. если параметр должен принадлежать только некоторому множеству типов, на него накладывают ограничение (type bound): в заголовке параметра задается тип, которому аргумент обязан соответствовать. проверка выполняется во время компиляции.

в качестве исходного примера берется класс `Message`, представляющий сообщение, и два его подкласса: `EmailMessage` для сообщения электронной почты и `SmsMessage` для sms.

```java

// Класс сообщения
class Message {
    private String text;

    String getText() { return text;  }

    Message(String text) { this.text = text; }
}
// класс сообщения по email
class EmailMessage extends Message {

    private String address;  // адрес электронной почты
    String getAddress(){ return address; }

    EmailMessage(String text, String address) {

        super(text);
        this.address = address;
    }
}
// класс сообщения по sms
class SmsMessage extends Message {

    private String number;  // номер телефона
    String getNumber(){ return number; }

    SmsMessage(String text, String number) {
        super(text);
        this.number = number;
    }
}
```

для отправки сообщений вводится класс `Messenger`.

```java

class Messenger {

    private Message message;
    Message getMessage() { return this.message; }

    Messenger(Message message) { this.message = message;  }

    void send() {
        System.out.println("Отправляется сообщение: " + message.getText());
    }
}
```

конструктор `Messenger` принимает сообщение, метод `send()` выполняет условную отправку, метод `getMessage()` возвращает принятое сообщение. чтобы класс оставался общим для разных видов сообщений, в роли типа сообщения используется базовый тип `Message`.

далее те же классы собираются в программу.

```java

class Program {

    public static void main(String[] args) {
        //  Создаем сообщения
        Message message1 = new EmailMessage("Привет, ты спишь?", "someaddress@hmail.com");
        Message message2 = new SmsMessage("Не, ты скажи, ты спишь?", "+71234567890");

        // Отправляем сообщения
        Messenger simpleMessenger = new Messenger(message1);
        simpleMessenger.send();

        simpleMessenger = new Messenger(message2);
        simpleMessenger.send();
    }
}
```

программа компилируется и выполняется. `Messenger` объявлен с параметром типа `Message`, а объект подкласса допустим там, где ожидается объект базового класса: подстановка опирается на обычное отношение подтипа, без параметризации. ниже разобраны две трудности, которые при такой схеме остаются.

#### преобразования типов

при извлечении сообщения из `Messenger` статический тип результата равен `Message`. чтобы вызвать члены, объявленные только в `EmailMessage`, требуется нисходящее приведение.

```java

class Program {

    public static void main(String[] args) {

        Message message = new EmailMessage("Привет, ты спишь?", "someaddress@hmail.com");

        Messenger simpleMessenger = new Messenger(message);
        simpleMessenger.send(); // Отправляется сообщение: Привет, ты спишь?

        // получаем отправленное сообщение
        EmailMessage email = (EmailMessage) simpleMessenger.getMessage();
        System.out.println("Address: " + email.getAddress());  // Address: someaddress@hmail.com
    }
}
```

вызов `simpleMessenger.getMessage()` возвращает значение статического типа `Message`. приведение к `EmailMessage` открывает метод `getAddress()`. нисходящее приведение проверяется во время выполнения: jvm сравнивает фактический класс объекта с целевым типом и при несовпадении выбрасывает `ClassCastException`.

#### типобезопасность

вторая трудность в том, что статический тип `Message` не хранит сведения о фактическом подклассе. приведение к несовместимому типу проходит компиляцию и завершается ошибкой уже при запуске.

```java

class Program {

    public static void main(String[] args) {

        Message message = new EmailMessage("Привет, ты спишь?", "someaddress@hmail.com");
        Messenger simpleMessenger = new Messenger(message);

        // получаем сообщение
        SmsMessage sms = (SmsMessage) simpleMessenger.getMessage();  // Сюрпрайз - java.lang.ClassCastException!
        System.out.println("Phone number: " + sms.getNumber());
    }
}
```

объект создан как `EmailMessage`. приведение к `SmsMessage` выбрасывает `java.lang.ClassCastException`. диагностика появляется только во время выполнения, компиляция такого фрагмента завершается успешно. обобщения переносят часть этих проверок на время компиляции, пока аргумент типа еще присутствует в исходном тексте.

#### использование обобщений

чтобы убрать ручные приведения и получить проверку при компиляции, класс `Messenger` параметризуют.

```java

class Messenger<T> {

    private T message;
    T getMessage() { return this.message; }

    Messenger(T message) { this.message = message;  }

    void send() {
        System.out.println("Отправляется сообщение: " + message.getText());
    }
}
```

в `Messenger<T>` передается значение некоторого типа, и поле, конструктор и `getMessage()` согласованы с этим аргументом. приведение вниз для восстановления исходного типа не требуется, несовместимое присваивание отклоняет компилятор. возникает другое ограничение. параметр `T` без границы означает произвольный ссылочный тип, а метод `getText()` есть у `Message` и его подклассов. для неограниченного `T` компилятор допускает лишь члены `Object`, поэтому вызов `message.getText()` в `send()` некорректен.

#### определение ограничений обобщений

нужно одновременно сохранить параметризацию, чтобы не приводить типы вручную, и вызывать внутри `Messenger` члены класса `Message`. ограничение параметра типа связывает эти два требования.

после имени параметра ставится ключевое слово `extends` и тип границы:

```java
<T extends тип_ограничения>
```

слово `extends` в границе используется и для класса, и для интерфейса: отдельной формы `implements` у параметра типа нет. граница проверяется в каждом месте, где обобщение инстанцируется.

### ограничения обобщений в типах

ограничение задается и в заголовке типа:

```java
class имя_класса<T extends тип_ограничения>
```

класс мессенджера с границей записывается так:

```java

class Messenger<T extends Message> {

    private T message;
    T getMessage() { return this.message; }

    Messenger(T message) { this.message = message;  }

    void send() {
        System.out.println("Отправляется сообщение: " + message.getText());
    }
}
```

запись `T extends Message` означает, что аргументом `T` служит `Message` или его подтип. компилятор относит к значениям типа `T` члены `Message`, и вызов `getText()` внутри `Messenger` корректен. при стирании типов на месте `T` остается граница `Message`, поэтому обращение к `getText()` в байткоде идет уже к методу `Message`.

применение класса к двум видам сообщений:

```java


class Program {

    public static void main(String[] args) {

        EmailMessage email = new EmailMessage("Привет, ты спишь?", "someaddress@hmail.com");
        Messenger<EmailMessage> mailClient = new Messenger<EmailMessage>(email);
        mailClient.send();  // Отправляется сообщение: Привет, ты спишь?

        SmsMessage sms = new SmsMessage("Hello World", "+71234567890");
        Messenger<SmsMessage> phone = new Messenger<SmsMessage>(sms);
        phone.send();   // Отправляется сообщение: Hello World
    }
}
```

при объявлении локальной переменной запись типа можно сократить. вывод типа `var` (java 10) берет тип из инициализатора, и справа аргумент типа указан явно:

```java
var mailClient = new Messenger<EmailMessage>(email);
```

либо тип указан слева, а справа применяется ромбовидный оператор (diamond, java 7): аргументы типа конструктора выводятся из целевого типа переменной.

```java
Messenger<EmailMessage> mailClient = new Messenger<>(email);
```

если из мессенджера, параметризованного `EmailMessage`, прочитать результат в переменную несовместимого типа, компилятор останавливает сборку:

```java

EmailMessage email = new EmailMessage("Привет", "someaddress@hmail.com");
var mailClient = new Messenger<EmailMessage>(email);

SmsMessage sms = mailClient.getMessage();  // Ошибка компиляции
```

присваивание результата `getMessage()` переменной типа `SmsMessage` отвергается во время компиляции. аргумент `EmailMessage` зафиксирован в типе `Messenger<EmailMessage>`, и возвращаемый тип `getMessage()` равен `EmailMessage`. ошибка `ClassCastException` из предыдущего примера в этой записи не возникает, потому что несовместимое приведение до запуска не доходит.

### использование нескольких универсальных параметров

если у класса несколько параметров типа, граница указывается у каждого отдельно:

```java

class Messenger<T extends Message, P extends Person> {

    void sendMessage(P sender, P receiver, T message)
    {
        System.out.println("Отправитель: " + sender.getName());
        System.out.println("Получатель: " + receiver.getName());
        System.out.println("Сообщение: " + message.getText());
    }
}

class Person{

    private String name;
    String getName(){ return name;}

    Person(String name) {this.name = name; }
}

class Message{

    private String text; // текст сообщения
    String getText(){ return text; }

    Message(String text)
    {
        this.text = text;
    }
}
```

для параметра `P` допускаются `Person` и его подтипы, для параметра `T` допускаются `Message` и его подтипы. оба аргумента `sendMessage`, отправитель и получатель, имеют один и тот же параметр `P`, поэтому их статические типы совпадают: передать отправителя и получателя разных несвязанных типов в этот метод нельзя.

применение классов:

```java

public class Program{
      
    public static void main(String[] args) {
          
        Messenger<Message, Person> telegram = new Messenger<Message, Person>();
        Person tom = new Person("Tom");
        Person bob = new Person("Bob");
        Message hello = new Message("Hello, Bob!");
        telegram.sendMessage(tom, bob, hello);
    }
}
```

консольный вывод:

```bash

Отправитель: Tom
Получатель: Bob
Сообщение: Hello, Bob!
```

вызов печатает имя отправителя, имя получателя и текст сообщения. имена берутся из `Person.getName()`, текст из `Message.getText()`. оба обращения законны именно из-за границ `P extends Person` и `T extends Message`.

### множественные ограничения

для одного параметра можно задать несколько границ сразу. границы соединяются оператором `&` и образуют тип-пересечение: аргумент должен быть подтипом каждой границы.

```java

public class Program{
      
    public static void main(String[] args) {
          
        var icq = new Messenger<PrintedMessage>();
        var hello = new PrintedMessage("Hello enoobis.ru");
        icq.sendMessage(hello);     // Текст сообщения: Hello enoobis.ru
    }
}
class Messenger<T extends Message & Printable> {

    void sendMessage(T message){

        message.print();
    }
}
interface Printable{

    void print();
}

class Message{

    private String text; // текст сообщения
    String getText(){ return text; }

    Message(String text)
    {
        this.text = text;
    }
}

class PrintedMessage 
        extends Message 
        implements Printable{

    PrintedMessage(String text) { super(text); }

    public void print(){
        System.out.println("Текст сообщения: " + getText());
    }
}
```

параметр `T` класса `Messenger` одновременно ограничен классом `Message` и интерфейсом `Printable`. если среди границ есть класс, он записывается первым. стирание подставляет первую границу, а к членам остальных границ компилятор обращается через приведение. двух классов в списке границ быть не может: у параметра одна классовая граница, дальше идут только интерфейсы.

```java
class Messenger<T extends Message & Printable> {
```

в роли такого аргумента определен класс `PrintedMessage`: он наследует `Message` и реализует `Printable`. объект этого класса передается в `sendMessage`, и метод вызывает `print()`, объявленный в интерфейсе.

```java

var icq = new Messenger<PrintedMessage>();
var hello = new PrintedMessage("Hello enoobis.ru");
icq.sendMessage(hello);     // Текст сообщения: Hello enoobis.ru
```

вызов печатает строку `Текст сообщения: Hello enoobis.ru`. аргумент `PrintedMessage` удовлетворяет обеим границам, поэтому и создание `Messenger<PrintedMessage>`, и вызов `print()` принимаются компилятором.

### ограничения методов

та же форма границы применяется к параметру типа метода, а не только класса.

```java

public class Program{
      
    public static void main(String[] args) {
          
        sendMessage(new Message("Hello World"));
        sendMessage(new EmailMessage("Bye World"));
    }
    static <T extends Message> void sendMessage(T message){

        System.out.println("Отправляется сообщение: " + message.getText());
    }
}
class EmailMessage extends Message{

    EmailMessage(String text) {  super(text); }
}
class SmsMessage extends Message{

    SmsMessage(String text)  { super(text); }
}
class Message{

    private String text; // текст сообщения
    String getText(){ return text; }

    Message(String text){

        this.text = text;
    }
}
```

метод `sendMessage` обобщенный. параметр `T` ограничен `Message`, поэтому и `Message`, и `EmailMessage` допустимы как аргумент, а вызов `getText()` внутри метода корректен. класс `SmsMessage` в том же листинге объявлен как еще один подкласс `Message` и подчиняется той же границе, хотя из `main` он не передается. аргумент типа метода выводится из фактического параметра вызова, явно указывать `sendMessage` с аргументом типа в угловых скобках не требуется.
