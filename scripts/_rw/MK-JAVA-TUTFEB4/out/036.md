наследование применимо не в каждой ситуации, и тогда его требуется запретить. запрет записывается ключевым словом `final`. пример:

```java


final class Person { }
```

если класс `Person` объявлен с модификатором `final`, следующий код ошибочен и не компилируется: наследовать `Person` запрещено.

```java


class Employee extends Person{ }  // ! Ошибка - унаследовать от класса Person нельзя
```

кроме запрета наследования можно также запретить переопределение отдельных методов. метод `print()`, который выше переопределялся в производном классе, закрывают так:

```java


class Person {

     

    private String name;



    Person(String name){ this.name = name;  }



    // запрет переопределения

    final void print(){

         

        System.out.println("Name: " + name);

    }

}
```

в этом случае класс-наследник не сможет переопределить метод `print`:

```java


class Employee extends Person{



    private String company;



    Employee(String name, String company){

        super(name); 

        this.company = company;

    }

    // ! Ошибка - переопределить метод нельзя

    void print(){

        super.print();

        System.out.println("Company: " + company);

    }

}
```

запрет наследования класса или переопределения метода с помощью `final` полезен, когда нужно гарантировать, что семантика класса или метода не будет изменена в производном классе: класс или метод действует ровно так, как был изначально определён. если внутри базового класса вызываются его методы, переопределение этих методов в производном классе может нарушить стандартную и ожидаемую работу этого класса. небольшой пример:

```java


public class Program{ 

       

    public static void main (String args[]){



        Employee bob = new Employee("Bob", "Google");

    }

}

class Person {

     

    private String name;



    Person(String name){ 



        this.name = name;  

        print();

    }



    void print(){

         

        System.out.println("Name: " + name);

    }

}



class Employee extends Person{



    private String company;



    Employee(String name, String company){



        super(name); 

        this.company = company;

    }

    @Override

    void print(){

        super.print();

        System.out.println("Company: " + company);

    }

}
```

в конструкторе класса `Person` вызывается метод `print()` для вывода информации о созданном объекте. в классе `Employee` этот метод переопределён, чтобы также вывести значение поля `company`.

поскольку в конструкторе `Employee` уже вызывается конструктор базового класса `Person`, второй раз вызывать метод `print` не нужно:

```java


Employee(String name, String company){



    super(name);   // здесь вызывается метод print

    this.company = company;

}
```

консольный вывод программы при этом выглядит так:

```bash


Name: Bob

Company: null
```

конструктор базового класса `Person`, где вызывается метод `print`, отработал до установки поля `company`. поле ссылочного типа до присваивания хранит значение по умолчанию `null`, поэтому на консоль выходит некорректная информация `Company: null`. вызов `print()` в конструкторе суперкласса уже диспетчеризуется в переопределение `Employee`, хотя инструкции конструктора `Employee` после `super(name)` ещё не выполнялись.

вызов метода базового класса в конструкторе составляет одну из распространённых причин запрета переопределения метода. метод печати данных `Person` определяют как `final`:

```java


public class Program{ 

       

    public static void main (String args[]){



        Employee bob = new Employee("Bob", "Google");

    }

}

class Person {

     

    private String name;



    Person(String name){ 

        this.name = name;  

        printPerson();

    }

    // запрет переопределения

    final void printPerson(){

         

        System.out.println("Name: " + name);

    }

}



class Employee extends Person{



    private String company;



    Employee(String name, String company){



        super(name);  // в этой точке в базовом классе вызывается метод printPerson 



        this.company = company;

        printEmployee();

    }



    void printEmployee(){

        System.out.println("Company: " + company);

    }

}
```

в этом случае вывод корректен:

```bash


Name: Bob

Company: Google
```

метод `printPerson` помечен `final`, и подкласс его не подменяет. сведения о компании печатает отдельный метод `printEmployee`, вызванный уже после присваивания `this.company`.

проблема выше была связана прежде всего с тем, что вызов конструктора базового класса выполнялся до остального кода, то есть до установки поля `company`. до версии java 25 конструктор базового класса можно было вызывать только в самом начале конструктора производного класса, до всего остального кода:

```java


Employee(String name, String company){



    super(name); 

    this.company = company;

}
```

начиная с java 25 конструктор базового класса можно вызывать в другом месте конструктора производного класса. до вызова `super` спецификация jep 513 разрешает инициализировать поля самого производного класса и запрещает пользоваться ещё не построенным экземпляром суперкласса:

```java


Employee(String name, String company){



    this.company = company;

    super(name); 

}
```

конкретно эта перестановка решила бы проблему примера: поле `company` получило бы значение до того, как конструктор `Person` вызовет печать. в более сложных программах приходится учитывать все зависимости, которые могут повлиять на создание объекта базового класса. поэтому в конструкторе лучше вызывать только методы с модификаторами `final` или `private`. метод с `private` не участвует в переопределении и связывается статически, так что вызов не попадает в реализацию подкласса.
