### класс `PrintStream`

`PrintStream` это тот класс, через который идёт вывод на консоль. вызов `System.out.println()` работает с `PrintStream`: поле `out` класса `System` имеет именно этот тип, а `println()` определён у `PrintStream`.

тем же классом пишут не только в консоль. он садится поверх любого потока вывода. для этого объявлен ряд конструкторов:

```java


PrintStream(OutputStream outputStream)

PrintStream(OutputStream outputStream, boolean autoFlushingOn)

PrintStream(OutputStream outputStream, boolean autoFlushingOn, String charSet) throws UnsupportedEncodingException

PrintStream(File outputFile) throws FileNotFoundException

PrintStream(File outputFile, String charSet) throws FileNotFoundException, UnsupportedEncodingException

PrintStream(String outputFileName) throws FileNotFoundException

PrintStream(String outputFileName, String charSet) throws FileNotFoundException, UnsupportedEncodingException
```

`outputStream` это `OutputStream`, в который идёт запись. `autoFlushingOn` при `true` включает автоматический сброс буфера. по умолчанию флаг равен `false`, и буфер уходит в поток по явному `flush` или по `close`. при `true` сброс выполняется, когда записан массив байтов, когда вызван `println`, либо когда в поток попал символ перевода строки `\n`. при том же флаге `printf` и `format` сбрасывают буфер, только если в записанный текст попал `\n`. параметр `charSet` задаёт кодировку символов. неизвестное имя кодировки даёт `UnsupportedEncodingException`, что видно по спецификации соответствующих конструкторов. если кодировка не указана, берётся кодировка платформы по умолчанию.

вместо `OutputStream` источником приёмника может быть объект `File` или строковый путь. файл по этому пути создаётся, а если открыть его нельзя, конструктор выбрасывает `FileNotFoundException`.

для вывода `PrintStream` даёт три основные операции:

- `println()`: вывод строковой информации с переводом строки
- `print()`: вывод строковой информации без перевода строки
- `printf()`: форматированный вывод

методы `print` и `println` не пробрасывают `IOException` наружу. ошибка нижележащего потока запоминается во внутреннем флаге, его читают методом `checkError()`. из-за этого сбой записи легко пропустить, если флаг не проверять. это отличие байтового `PrintStream` от обычного `OutputStream`, у которого ошибка приходит исключением.

запись строки в файл:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        String text = "Привет мир!"; // строка для записи

        try(FileOutputStream fos=new FileOutputStream("C://SomeDir//notes3.txt");

                PrintStream printStream = new PrintStream(fos))

        {

            printStream.println(text);

            System.out.println("Запись в файл произведена");

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        }  

    } 

}
```

здесь взята форма `PrintStream(OutputStream)`, аргумент это поток вывода. рядом в списке конструкторов есть форма с именем файла, `PrintStream(String outputFileName)`.

поток вывода в примере это `FileOutputStream` на путь `C://SomeDir//notes3.txt`. `println()` пишет текст в этот поток, то есть в файл. при выводе на консоль через `System.out.println()` приёмником того же метода выступает консоль. строка `Привет мир!` уходит в файл, а сообщение о том, что запись выполнена, печатается уже в `System.out`, не в файл.

как наследник `OutputStream`, `PrintStream` имеет и метод `write`:

```java


import java.io.*;



public class Program {

 

    public static void main(String[] args) {

         

        try(PrintStream printStream = new PrintStream("notes3.txt"))

        {

            printStream.print("Hello World!");

            printStream.println("Welcome to Java!");

			

            printStream.printf("Name: %s Age: %d \n", "Tom", 34);

			

			String message = "PrintStream";

            byte[] message_toBytes = message.getBytes();

            printStream.write(message_toBytes);

			

            System.out.println("The file has been written");

        }

        catch(IOException ex){

             

            System.out.println(ex.getMessage());

        }  

    } 

}
```

`print` пишет текст без перевода строки, `println` добавляет перевод, `printf` подставляет аргументы по форматной строке: `%s` для строки, `%d` для целого, `\n` для перевода. `write` принимает уже готовые байты, полученные `getBytes()`, и кладёт их в тот же поток без форматного разбора.

после выполнения программы файл содержит:

```


Hello World!Welcome to Java!

Name: Tom Age: 34 

PrintStream
```

перевод строки стоит только там, где его поставил `println` или `\n` внутри `printf`. `print("Hello World!")` и следующий `println` склеиваются в одну строку. байты `write` дописываются сразу после этой строки.

### `PrintWriter`

рядом с `PrintStream` стоит `PrintWriter`. им пишут и на консоль, и в файл, и в любой другой поток вывода. класс символьный: он работает с `char` и с `Writer`, тогда как `PrintStream` пишет байты. конструкторы:

- `PrintWriter(File file)`: запись в указанный файл
- `PrintWriter(File file, String csn)`: запись в указанный файл в кодировке `csn`
- `PrintWriter(OutputStream out)`: вывод в уже существующий `OutputStream`, без автоматического сброса буфера
- `PrintWriter(OutputStream out, boolean autoFlush)`: тот же `OutputStream`. второй параметр задаёт, сбрасывать ли буфер автоматически
- `PrintWriter(String fileName)`: запись в файл по указанному имени
- `PrintWriter(String fileName, String csn)`: запись в файл по указанному имени в кодировке `csn`
- `PrintWriter(Writer out)`: вывод в уже существующий `Writer`
- `PrintWriter(Writer out, boolean autoFlush)`: тот же `Writer`. второй параметр задаёт, сбрасывать ли буфер автоматически

при `autoFlush == true` буфер сбрасывается вызовами `println`, `printf` и `format`, а не каждым `print`. конструктор без этого флага автоматический сброс не включает.

`PrintWriter` реализует `Appendable`, `Closeable` и `Flushable`. раз поток закрываемый, после работы его закрывают: `close()` сбрасывает буфер и закрывает нижележащий приёмник. ошибку записи методы `print` и `println` наружу не бросают, её тоже читают через `checkError()`.

для записи служат `printf()` и `println()`.

вывод на консоль:

```java


try(PrintWriter pw = new PrintWriter(System.out))

{

    pw.println("Hello world!");

}
```

приёмником здесь передан `System.out`. на консоль уходит строка `Hello world!`. объект обёрнут в try-with-resources, поэтому по выходу из блока вызывается `close()`. `close()` закрывает вложенный `Writer`, а тот закрывает переданный `OutputStream`. если приёмником был `System.out`, стандартный поток вывода после этого закрыт.
