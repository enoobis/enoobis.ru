сериализация записывает состояние объекта в поток. извлечение этого состояния обратно, то есть восстановление объекта, называется десериализацией. для сложного графа объектов протокол обходит ссылки сам. каждое поле вручную, как в `DataOutputStream`, раскладывать не приходится.

### интерфейс `Serializable`

сериализовать можно только объект класса, который реализует `Serializable`. интерфейс не объявляет методов. это маркер: по нему механизм сериализации отличает класс, чей экземпляр разрешено писать в поток. если маркер не реализован, `writeObject` завершается `NotSerializableException`. проверка выполняется во время выполнения, компилятор отсутствие интерфейса не ловит.

### сериализация. класс `ObjectOutputStream`

для записи объекта в поток служит `ObjectOutputStream`. он пишет байты протокола сериализации java во вложенный поток.

конструктор получает поток, в который идёт запись:

```java


ObjectOutputStream(OutputStream out)
```

у `ObjectOutputStream` много методов записи. основные:

- `void close()`: закрывает поток
- `void flush()`: очищает буфер и сбрасывает его содержимое в выходной поток
- `void write(byte[] buf)`: записывает в поток массив байтов
- `void write(int val)`: записывает в поток один младший байт из `val`
- `void writeBoolean(boolean val)`: записывает в поток значение `boolean`
- `void writeByte(int val)`: записывает в поток один младший байт из `val`
- `void writeChar(int val)`: записывает в поток значение типа `char`, представленное целочисленным значением
- `void writeDouble(double val)`: записывает в поток значение типа `double`
- `void writeFloat(float val)`: записывает в поток значение типа `float`
- `void writeInt(int val)`: записывает целочисленное значение `int`
- `void writeLong(long val)`: записывает значение типа `long`
- `void writeShort(int val)`: записывает значение типа `short`
- `void writeUTF(String str)`: записывает в поток строку в кодировке utf-8
- `void writeObject(Object obj)`: записывает в поток отдельный объект

эти методы покрывают набор данных, которые протокол умеет сериализовать: примитивы, строки и объекты. `writeObject` пишет не только переданный объект, но и объекты, достижимые из его полей. в начале потока лежит заголовок протокола, затем описание класса и значения полей. в файл попадают поля экземпляра, а не результат вызова геттеров. статические поля к состоянию экземпляра не относятся и в эту запись не входят.

сохранение одного объекта `Person`:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        try(ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("person.dat")))

        {

			Person p = new Person("Sam", 33, 178, true);

            oos.writeObject(p);

        }

        catch(Exception ex){

            

            System.out.println(ex.getMessage());

        } 

    } 

}

class Person implements Serializable{

     

    private String name;

    private int age;

    private double height;

    private boolean married;

     

    Person(String n, int a, double h, boolean m){

         

        name=n;

        age=a;

        height=h;

        married=m;

    }

	String getName() {return name;}

	int getAge(){ return age;}

	double getHeight(){return height;}

	boolean getMarried(){return married;}

}
```

`FileOutputStream` открывает `person.dat`, `ObjectOutputStream` пишет в него. `Person` реализует `Serializable`, поэтому `writeObject` принимает экземпляр. поля `name`, `age`, `height` и `married` приватные, но протокол читает их средствами сериализации, без вызова `getName` и остальных геттеров. try-with-resources закрывает поток и тем самым дописывает буфер в файл.

### десериализация. класс `ObjectInputStream`

`ObjectInputStream` выполняет обратный проход: читает ранее сериализованные данные из потока. конструктор принимает поток ввода:

```java


ObjectInputStream(InputStream in)
```

методы класса читают те же типы, которые писались парными методами. основные:

- `void close()`: закрывает поток
- `int skipBytes(int len)`: пропускает при чтении несколько байт, число которых равно `len`
- `int available()`: возвращает количество байт, доступных для чтения
- `int read()`: считывает из потока один байт и возвращает его целочисленное представление
- `boolean readBoolean()`: считывает из потока одно значение `boolean`
- `byte readByte()`: считывает из потока один байт
- `char readChar()`: считывает из потока один символ `char`
- `double readDouble()`: считывает значение типа `double`
- `float readFloat()`: считывает из потока значение типа `float`
- `int readInt()`: считывает целочисленное значение `int`
- `long readLong()`: считывает значение типа `long`
- `short readShort()`: считывает значение типа `short`
- `String readUTF()`: считывает строку в кодировке utf-8
- `Object readObject()`: считывает из потока объект

`readObject` возвращает статически тип `Object`. фактический класс восстанавливается по описанию, записанному в поток, и ссылку приводят к ожидаемому типу. класс при чтении должен быть доступен загрузчику и должен быть совместим с описанием в потоке. если совместимого описания нет, чтение завершается `InvalidClassException` или `ClassNotFoundException`.

извлечение сохранённого `Person`:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

       

        try(ObjectInputStream ois = new ObjectInputStream(new FileInputStream("person.dat")))

        {

            Person p=(Person)ois.readObject();

			System.out.printf("Name: %s \t Age: %d \n", p.getName(), p.getAge());

        }

        catch(Exception ex){

            

            System.out.println(ex.getMessage());

        }

    } 

}
```

`ObjectInputStream` открывает тот же `person.dat`. `readObject` возвращает объект, ссылка приводится к `Person`, затем печатаются имя и возраст через геттеры. поля, которые не печатаются, в объекте тоже восстановлены: протокол заполняет экземпляр целиком, а не только запрошенные геттеры.

сохранение и восстановление списка объектов совмещаются так:

```java


import java.io.*;

import java.util.ArrayList;

 

public class Program {

	

	//@SuppressWarnings("unchecked")

    public static void main(String[] args) {

        

        String filename = "people.dat";

        // создадим список объектов, которые будем записывать

        ArrayList<Person> people = new ArrayList<Person>();

        people.add(new Person("Tom", 30, 175, false));

        people.add(new Person("Sam", 33, 178, true));

         

        try(ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream(filename)))

        {

            oos.writeObject(people);

            System.out.println("File has been written");

        }

        catch(Exception ex){

             

            System.out.println(ex.getMessage());

        } 

         

        // десериализация в новый список

        ArrayList<Person> newPeople= new ArrayList<Person>();

        try(ObjectInputStream ois = new ObjectInputStream(new FileInputStream(filename)))

        {

			

			newPeople=((ArrayList<Person>)ois.readObject());

        }

        catch(Exception ex){

             

            System.out.println(ex.getMessage());

        } 

         

        for(Person p : newPeople)

            System.out.printf("Name: %s \t Age: %d \n", p.getName(), p.getAge());

    } 

}

class Person implements Serializable{

     

    private String name;

    private int age;

    private double height;

    private boolean married;

     

    Person(String n, int a, double h, boolean m){

         

        name=n;

        age=a;

        height=h;

        married=m;

    }

	String getName() {return name;}

	int getAge(){ return age;}

	double getHeight(){return height;}

	boolean getMarried(){return married;}

}
```

сначала строится `ArrayList` с двумя объектами `Person` и целиком передаётся в `writeObject`. `ArrayList` сам реализует `Serializable`, а элементы сериализуются вместе со списком, потому что достижимы из его состояния. если бы элемент не реализовывал `Serializable`, запись оборвалась бы на `NotSerializableException`.

чтение идёт в другой список. `readObject` снова возвращает `Object`, и ссылка приводится к `ArrayList<Person>`. приведение непроверяемое: параметр типа стирается, во время выполнения в потоке лежит `ArrayList` без аргумента `Person`. комментарий `SuppressWarnings("unchecked")` в исходнике как раз про это предупреждение компилятора. дальше цикл печатает имя и возраст каждого восстановленного элемента.

идентификатор версии класса, поле `serialVersionUID`, в этих примерах не объявлен. тогда реализация вычисляет его по структуре класса. смена полей, которая меняет вычисленный идентификатор, делает старый поток несовместимым с новым классом.

### исключение данных из сериализации

по умолчанию сериализуются все нестатические поля объекта. поле, которое в поток попасть не должно, объявляют с модификатором `transient`. у `Person` из сериализации исключаются `height` и `married`:

```java


class Person implements Serializable{

     

    private String name;

    private int age;

    private transient double height;

    private transient boolean married;

     

    Person(String n, int a, double h, boolean m){

         

        name=n;

        age=a;

        height=h;

        married=m;

    }

	String getName() {return name;}

	int getAge(){ return age;}

	double getHeight(){return height;}

	boolean getMarried(){return married;}

}
```

`transient` убирает поле из записи. при десериализации такое поле получает начальное значение типа: `0.0` для `double`, `false` для `boolean`, `null` для ссылки. значение, которое было у объекта в момент `writeObject`, для этих полей не восстанавливается. имя и возраст модификатора не имеют и пишутся как раньше.
