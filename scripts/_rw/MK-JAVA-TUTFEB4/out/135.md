упаковка пакетов в один jar служит и для распространения модулей java. jar, в котором лежит скомпилированный модуль вместе с дескриптором, называется модульным jar-файлом.

модульный jar собирает та же утилита `jar`. если в модуле несколько пакетов, исходники компилируют с опцией `-d`: она складывает файлы классов в отдельный каталог и создаёт его, если каталога ещё нет. при упаковке переход в этот каталог выполняет опция `-C`. разбор идёт на примере.

### определение модуля

на диске, например в каталоге `workspace/java`, создаётся каталог `demo`. этот каталог и есть одноимённый модуль. в `demo` помещается файл дескриптора `module-info.java`:

```java


module demo {

}
```

пустое тело модуля означает, что модуль ничего не экспортирует и не объявляет зависимостей. модуль `java.base` остаётся требуемым неявно: его читает любой именованный модуль.

далее в `demo` создаётся каталог `com`, в нём каталог `enoobis`, в `com/enoobis` каталог `hello`.

в каталоге `com/enoobis/hello` создаётся файл `Hello.java`:

```java


package com.enoobis.hello;

 

public class Hello{

     

    public static void main(String[] args){

        System.out.println("Hello enoobis.ru!");

    }

}
```

имя пакета `com.enoobis.hello` повторяет цепочку каталогов, в которых лежит файл. класс `Hello` в методе `main` печатает на консоль строку.

дальше модуль компилируется и упаковывается в jar.

### создание jar

в командной строке выполняется переход в каталог, где лежит каталог модуля `demo`, в примере это `workspace/java`. компиляция модуля:

```bash


javac --module-source-path . -d mods demo/module-info.java demo/com/enoobis/hello/Hello.java
```

опция `--module-source-path .` сообщает компилятору, что корни исходников модулей являются подкаталогами текущего каталога: имя подкаталога совпадает с именем модуля. опция `-d mods` задаёт корень выходных файлов. после компиляции появляется каталог `mods`, и в нём дерево классов модуля `demo`:

```browser


mods

|_demo

    |_module-info.class

    |_com

        |_enoobis

            |_hello

                |_Hello.class
```

в корне модуля лежит `module-info.class`, дальше каталоги повторяют пакет `com.enoobis.hello`. упаковка в jar:

```bash


jar -c -v -f demo.jar -C mods/demo .
```

параметры команды:

- `-c`: создаёт новый архив
- `-v`: включает подробный вывод выполнения
- `-f demo.jar`: задаёт имя jar-файла, создаваемый файл называется `demo.jar`
- `-C mods/demo .`: переходит в каталог скомпилированных классов и добавляет в архив всё его содержимое, обозначенное точкой. первый компонент, `mods`, имя произвольное и совпадает с аргументом `-d`. подкаталог `demo` называется по имени модуля из `module-info.java`. в примере модуль называется `demo`, поэтому классы лежат в `mods/demo`

опция `-C` нужна, чтобы `module-info.class` оказался в корне архива. система модулей читает дескриптор именно из корня модульного jar. если упаковать каталог снаружи, без смены каталога, в архиве появится лишний префикс пути.

полный консольный вывод:

```bash


eugene@Eugene:~$ cd workspace/java

eugene@Eugene:/workspace/java$ javac --module-source-path . -d mods demo/module-info.java demo/com/enoobis/hello/Hello.java

eugene@Eugene:/workspace/java$ jar -c -v -f demo.jar -C mods/demo .

added manifest

added module-info: module-info.class

adding: com/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/hello/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/hello/Hello.class(in = 440) (out= 305)(deflated 30%)

```

в выводе видны манифест, дескриптор `module-info.class`, пустые каталоги пакета и файл `Hello.class`.

### создание исполняемого jar

класс `Hello` является точкой входа: в нём есть метод `main`, и его можно запустить. в модульном jar, как и в обычном, можно записать главный класс. для этого служит опция `-e`, её полная форма `--main-class`. опции передаётся бинарное имя главного класса, с пакетом:

```bash


jar -c -v -f demo.jar -e com.enoobis.hello.Hello -C mods/demo .
```

класс `Hello` объявлен в пакете `com.enoobis.hello`, поэтому бинарное имя `com.enoobis.hello.Hello`. опция сохраняет это имя как точку входа модуля.

собранный модульный jar запускается командой `java`:

```bash
java --module-path demo.jar --module demo
```

`--module-path demo.jar` задаёт путь модулей: по нему система модулей находит именованные модули. `--module demo` выбирает начальный модуль. главный класс берётся из записи, сделанной опцией `-e`.

полный консольный вывод:

```bash


eugene@Eugene:/workspace/java$ javac --module-source-path . -d mods demo/module-info.java demo/com/enoobis/hello/Hello.java

eugene@Eugene:/workspace/java$ jar -c -v -f demo.jar -e com.enoobis.hello.Hello -C mods/demo .

added manifest

added module-info: module-info.class

adding: com/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/hello/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/hello/Hello.class(in = 440) (out= 305)(deflated 30%)

eugene@Eugene:/workspace/java$ java --module-path demo.jar --module demo

Hello enoobis.ru!

eugene@Eugene:/workspace/java$
```

после запуска на консоли печатается строка `Hello enoobis.ru!`.

### компиляция взаимодействующих модулей

следующий пример сложнее: несколько модулей, и один из них пользуется пакетом другого. структура проектов:

![взаимодействие модулей в java](/uploads/course-lectures/724cda24c966eb21d3559fd3f2b17ae51cfd0d0c.png)

здесь два модуля, `demo` и `operations`. каждый лежит в своём одноимённом каталоге.

в каталоге `operations/com/enoobis/factorial` находится файл `Factorial.java`:

```java


package com.enoobis.factorial;



public class Factorial{

	

	public static int calculate(int n){

		if (n < 1) return -1;

        int result = 1;

        while (n > 1) result *= n--;

        return result;

	}

}
```

класс `Factorial` принадлежит пакету `com.enoobis.factorial` и считает факториал. при аргументе меньше 1 метод `calculate` возвращает `-1`. при большем аргументе метод возвращает произведение чисел от 1 до этого аргумента.

чтобы класс и весь пакет были доступны другим модулям, в каталоге `operations` задаётся `module-info.java`:

```java


module operations {

    exports com.enoobis.factorial;

}
```

директива `exports` открывает пакет `com.enoobis.factorial`. открытые типы этого пакета становятся доступны модулям, которые читают `operations`. без `exports` модификатор `public` у класса за пределы модуля не действует: система модулей инкапсулирует пакет.

в каталоге `demo` задаётся свой `module-info.java`:

```java


module demo {

    requires operations;

}
```

директива `requires` объявляет зависимость: модуль `demo` читает модуль `operations`. зависимость разрешается при запуске по пути модулей. слова `transitive` в директиве нет. чтение модуля `demo` поэтому на модуль `operations` не распространяется.

в каталоге `demo/com/enoobis/hello` находится файл `Hello.java`:

```java


package com.enoobis.hello;



import com.enoobis.factorial.Factorial;



public class Hello{

	

	public static void main(String[] args){

		

		int a = 5;

		int b = Factorial.calculate(a);

		System.out.printf("Factorial of %d is equal to %d \n", a, b);

	}

}
```

исходник импортирует `Factorial` из пакета `com.enoobis.factorial` и вычисляет факториал числа. для этого вызова нужны обе директивы: `requires` со стороны `demo` и `exports` со стороны `operations`.

оба модуля упаковываются в jar. обычный порядок такой: каждый модуль собирается в свой архив. в консоли выполняется переход в каталог, где лежат оба модуля, в примере это `/workspace/java`, и запускается компиляция:

```bash
javac --module-source-path . -d mods demo/module-info.java demo/com/enoobis/hello/Hello.java
```

в команде перечислены исходники одного модуля, `demo`. модуль `operations` компилируется вместе с ним: он указан в `requires`, а его исходники лежат на `--module-source-path`. оба результата помещаются в каталог `mods`. дерево такое:

```browser


mods

|_demo

|   |_module-info.class

|   |_com

|       |_enoobis

|           |_hello

|                |_Hello.class

|_factorial

    |_module-info.class

    |_com

        |_enoobis

            |_factorial

                |_Factorial.class
```

имя выходного каталога совпадает с именем модуля в дескрипторе. упаковка модуля `operations` поэтому читает каталог `mods/operations`:

```bash
jar -c -v -f libs/operations.jar -C mods/operations .
```

файл `operations.jar` помещается в каталог `libs`. затем упаковывается модуль `demo`, и опция `-e` снова записывает главный класс:

```bash
jar -c -v -f libs/demo.jar -e com.enoobis.hello.Hello -C mods/demo .
```

в каталоге `libs` после этого лежат оба модульных jar. запуск передаёт в путь модулей весь каталог `libs` и явно называет главный класс:

```bash
java --module-path libs --module demo/com.enoobis.hello.Hello
```

форма `--module demo/com.enoobis.hello.Hello` задаёт начальный модуль и бинарное имя класса с методом `main`. путь `--module-path libs` покрывает оба архива, поэтому зависимость `operations` находится рядом с `demo`.

```bash

eugene@Eugene:/workspace/java$ jar -c -v -f libs/operations.jar -C mods/operations .

added manifest

added module-info: module-info.class

adding: com/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/factorial/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/factorial/Factorial.class(in = 339) (out= 266)(deflated 21%)

eugene@Eugene:/workspace/java$ jar -c -v -f libs/demo.jar -e com.enoobis.hello.Hello -C mods/demo .

added manifest

added module-info: module-info.class

adding: com/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/(in = 0) (out= 0)(stored 0%)

adding: com/enoobis/hello/(in = 0) (out= 0)(stored 0%)

```
