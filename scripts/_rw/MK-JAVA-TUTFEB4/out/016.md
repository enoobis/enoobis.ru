каждый примитивный тип занимает фиксированное число байт. от этого зависит, какие операции над значениями разных типов компилятор принимает без явного указания. следующий фрагмент не компилируется:

```java


int a = 4;

byte b = a;	// ! Ошибка
```

ошибка возникает на этапе компиляции. и `byte`, и `int` представляют целые числа, а значение переменной `a` входит в диапазон `byte` (от -128 до 127). компилятор смотрит на типы, а не доказывает, что конкретное значение поместится в более узкий тип. выражение `a` имеет тип `int` и занимает 4 байта, переменная слева занимает 1 байт. сужающее присваивание без явного приведения запрещено.

когда преобразование всё же нужно, его задают операцией приведения типа. синтаксически это скобки с именем целевого типа:

```java


int a = 4;

byte b = (byte)a;  // преобразование типов: от типа int к типу byte

System.out.println(b); // 4
```

в скобках указан тип, к которому преобразуется значение. `(byte)a` переводит значение типа `int` в тип `byte`. результат выражения имеет тип `byte` и в этом примере равен 4.

### явные и неявные преобразования

если в одной операции участвуют данные разных типов, приведение не всегда записывают в исходном тексте. часть преобразований компилятор выполняет сам.

#### автоматические преобразования

![преобразования типов в языке java](/uploads/course-lectures/3b062bafa05096db7c84502162e2cb4dd7905d40.png)

сплошные стрелки на схеме показывают преобразования, которые выполняются автоматически и сохраняют значение. пунктирные стрелки показывают автоматические преобразования, при которых точность может потеряться.

без потери значения проходят расширяющие преобразования (widening). представление в памяти становится шире, исходная информация сохраняется:

```java


byte b = 7;

int d = b;	// преобразование от byte к int
```

значение типа `byte` занимает 1 байт и расширяется до типа `int`, который занимает 4 байта. старшие разряды заполняются копией знакового бита, поэтому сохраняются и положительные, и отрицательные значения.

расширяющие автоматические преобразования идут по цепочкам:

**byte** -> **short** -> **int** -> **long**

**int** -> **double**

**short** -> **float** -> **double**

**char** -> **int**

`char` беззнаковый, поэтому расширение до `int` дополняет значение нулями, а не знаковым битом. коды от 0 до 65535 остаются неотрицательными.

#### автоматические преобразования с потерей точности

некоторые преобразования компилятор выполняет сам и между типами одинаковой разрядности, и даже от типа с большей разрядностью к типу с меньшей. это цепочки `int -> float`, `long -> float` и `long -> double`. ошибки компиляции нет. мантисса `float` хранит 23 бита, мантисса `double` хранит 52 бита, и в них помещаются не все целые значения широких целых типов. младшие разряды могут округлиться.

```java


int a = 2147483647;

float b = a;			// от типа int к типу float

System.out.println(b);	// 2.14748365E9
```

`2147483647` точно представимо как `int` и не представимо точно как `float`. в выводе `2.14748365E9` младшие разряды уже округлены. для `long -> double` точность теряется у целых, которым не хватает 53 значащих бит мантиссы вместе со скрытой единицей.

#### явные преобразования

во всех остальных преобразованиях примитивных типов приведение записывают явно. обычно это сужающие преобразования (narrowing), от типа с большей разрядностью к типу с меньшей:

```java


long a = 4;

int b = (int) a;
```

### потеря данных при преобразовании

явное сужение может отбросить старшие разряды. если значение входит в диапазон целевого типа, результат совпадает с исходным числом:

```java


int a = 5;

byte b = (byte) a;

System.out.println(b);		// 5
```

число 5 входит в диапазон `byte`, поэтому после преобразования `b` равно 5. если значение в диапазон не входит, остаётся младший байт:

```java


int a = 258;

byte b = (byte) a;

System.out.println(b);		// 2
```

результат равен 2. число 258 лежит вне диапазона `byte` (от -128 до 127), и старшие разряды отбрасываются.

число 258 как `int` в двоичной записи равно `00000000 00000000 00000001 00000010`. тип `byte` хранит 8 бит, поэтому от записи остаётся правый октет `00000010`, то есть 2. эти 8 бит читаются как знаковый `byte` в дополнительном коде. если бы старший из них был равен 1, результат был бы отрицательным.

### усечение рациональных чисел до целых

при преобразовании значения с плавающей точкой к целому типу дробная часть отбрасывается. округления до ближайшего целого нет, усечение идёт к нулю:

```java


double a = 56.9898;

int b = (int)a;
```

значение `b` равно 56, хотя 57 ближе к 56.9898. ближайшее целое даёт `Math.round` из математической библиотеки java:

```java


import java.lang.Math;  // для Math.round



public class Program {

  

    public static void main(String[] args) {

          

        double a = 56.9898;

        int b = (int)Math.round(a);

        System.out.println(b);  // 57

    }

}
```

`Math.round` для аргумента `double` возвращает `long`, поэтому результат ещё приводят к `int`. импорт `java.lang.Math` на разбор программы не влияет: пакет `java.lang` импортируется всегда. в примере импорт записан явно.

### преобразования при операциях

в бинарных числовых операциях типы операндов выравниваются по правилам продвижения (binary numeric promotion). правила применяются по порядку, срабатывает первое подходящее:

- если один из операндов операции относится к типу `double`, то и второй операнд преобразуется к типу `double`
- если предыдущее условие не соблюдено, а один из операндов операции относится к типу `float`, то и второй операнд преобразуется к типу `float`
- если предыдущие условия не соблюдены и один из операндов операции относится к типу `long`, то и второй операнд преобразуется к типу `long`
- иначе все операнды операции преобразуются к типу `int`

примеры преобразований:

```java


int a = 3;

double b = 4.6;

double c = a+b;
```

в операции участвует значение типа `double`, поэтому второе значение приводится к `double`, и сумма `a+b` имеет тип `double`.

другой пример:

```java


byte a = 3;

short b = 4;

byte c = (byte)(a+b);
```

операнды имеют типы `byte` и `short`. правила для `double`, `float` и `long` здесь не срабатывают, поэтому оба преобразуются к `int`, и сумма `a+b` имеет тип `int`. присвоить `int` переменной типа `byte` без приведения нельзя, поэтому сумма явно приводится к `byte`. скобки вокруг `a+b` нужны по приоритету: приведение выполняется раньше сложения, и запись `(byte) a + b` привела бы только `a`, после чего сложение снова дало бы `int`.

если в операции участвует `char`, он преобразуется к `int`. код символа складывается как целое:

```java


int d = 'a' + 5;

System.out.println(d);	// 102
```

код `'a'` в unicode равен 97, поэтому `'a' + 5` равно 102. `println` получает уже `int` и печатает число, а не символ.
