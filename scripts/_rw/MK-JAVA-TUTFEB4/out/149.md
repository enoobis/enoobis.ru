при вызове нативных функций код java работает с памятью вне кучи. эта память выделена не оператором `new`, сборщик мусора её не перемещает, и у блока есть стабильный адрес на всё время жизни. жизненным циклом таких блоков управляет **арена** (`arena`). арена выделяет сегменты и освобождает их вместе, одной операцией закрытия, а не по отдельному `free` на каждый указатель.

### создание и закрытие арены

на платформе java арена представлена классом `Arena`. экземпляр получают одним из статических методов. методы задают разные области видимости по потокам и разный способ освобождения:

- `global()` возвращает глобальную арену. сегменты, выделенные в ней, доступны любому потоку. глобальная арена одна на виртуальную машину, это одиночка: повторный вызов отдаёт тот же экземпляр
- `ofAuto()` создаёт арену, временем жизни которой управляет сборщик мусора. сегменты доступны любому потоку. закрыть такую арену явно нельзя
- `ofConfined()` возвращает ограниченную арену. сегменты доступны только потоку, который арену создал, то есть потоку-владельцу. чужой поток не может ни читать сегмент, ни закрывать арену
- `ofShared()` возвращает общую арену. сегменты доступны любому потоку, и закрыть арену тоже может любой поток

для закрытия есть метод `close()`. правило закрытия зависит от вида арены:

- ограниченная арена (`ofConfined()`) закрывается в том же потоке, в котором создана. закрытие из другого потока завершается исключением `WrongThreadException`. то же исключение получает чужой поток при обращении к сегменту
- глобальная арена (`global()`) не закрывается. выделенные ею сегменты не освобождаются до конца работы виртуальной машины. вызов `close()` завершается `UnsupportedOperationException`
- автоматическая арена (`ofAuto()`) закрытию не подлежит. сборщик мусора освободит сегменты, когда и арена, и сегменты станут недостижимы. момент освобождения программа не назначает: он зависит от цикла сборки. вызов `close()` тоже завершается `UnsupportedOperationException`
- общая арена (`ofShared()`) живёт, пока `close` не вызван из какого-либо потока. после успешного закрытия сегменты недоступны всем потокам

явный `close()` нужен только ограниченной и общей аренам. для глобальной и автоматической этот вызов порождает исключение, а не освобождение. повторное закрытие уже закрытой ограниченной или общей арены тоже завершается исключением: область памяти больше не жива.

после успешного `close()` обращение к любому сегменту этой арены невозможно, а область вне кучи, связанная с ареной, освобождена. отдельные сегменты при этом не выбирают: закрытие гасит их все.

```java


Arena arena = Arena.ofConfined();   // создаем арену

// неокторая работа с ареной

arena.close();  // закрываем арену
```

класс арены реализует `AutoCloseable`, и метод этого интерфейса совпадает с `close()`. поэтому арену открывают конструкцией `try` с ресурсами. выход из блока, обычный или по исключению, вызывает `close` в том потоке, который вошёл в блок. для `ofConfined()` это как раз поток-владелец, и ограничение «закрывать там же, где создали» выполняется само:

```java


try (Arena arena = Arena.ofConfined()) {



    // работа с ареной



} // Арена закрыта
```

общая арена тоже годится для `try` с ресурсами, если закрывать её должен тот же структурный блок. глобальную и автоматическую в такое `try` ставить нельзя: их `close` всегда отвергается.

## сегменты памяти `MemorySegment`

сегмент памяти представляет непрерывный блок байтов. на уровне java его задаёт интерфейс `MemorySegment`. сегмент может лежать в куче java, которой управляет сборщик мусора, или быть выделенным вне кучи. у сегмента вне кучи физический адрес фиксирован, пока жива арена. сегмент кучи, как и любой объект java, достижим по ссылке, но постоянного адреса не имеет: сборщик вправе переместить его при уплотнении. нативной функции нужен адрес, который не изменится на время вызова, поэтому для внешних функций выделяют сегменты вне кучи. адрес сегмента кучи в `printf` не передают: сборщик мусора может сдвинуть объект.

выделение собрано в методах `Arena`. большая их часть реализует интерфейс `java.lang.foreign.SegmentAllocator`: арена выступает распределителем, а способ освобождения остаётся свойством арены, не свойством отдельного вызова. часть перегрузок:

- `allocate(long byteSize, long byteAlignment)` принимает два параметра. `byteSize` задаёт размер выделяемой памяти в байтах. `byteAlignment` задаёт выравнивание в байтах. выравнивание обязано быть степенью двойки, иначе метод бросает `IllegalArgumentException`. адрес возвращённого сегмента кратен выравниванию: остаток от деления адреса на `byteAlignment` равен нулю. размер сегмента равен `byteSize`

метод возвращает сегмент заданного размера. выделенные байты обнуляются.

- `allocateFrom(String str)` переводит строку java в строку c, завершённую нулевым байтом, в кодировке utf-8 и кладёт байты в новый сегмент. длина сегмента на один байт больше длины utf-8, этот лишний байт служит терминатором
- `allocateFrom(ValueLayout elementLayout, ...)` выделяет память под элементы примитивного типа и сразу копирует значения. в исходном описании перегрузка записана как `ValueLayout` элемента и массив значений `Type`. на практике тип раскладки конкретный: `ValueLayout.OfInt`, `ValueLayout.OfFloat` и остальные раскладки примитивов. `Type` в этой записи обозначает соответствующий примитив, `int`, `float` и так далее
- перегрузка с одним значением делает то же для одного элемента: выделяет сегмент под одну единицу типа и записывает в него переданное значение
- `allocate(MemoryLayout layout)` выделяет память вне кучи по макету `layout`. макет описывает размер, выравнивание и взаимный порядок полей. так задают структуру c или последовательность, не перечисляя байты вручную. размер и выравнивание сегмента берутся из макета
- `allocate(MemoryLayout layout, long count)` выделяет память вне кучи под `count` элементов одного макета, то есть под массив структур или значений с этой раскладкой

все эти методы возвращают `MemorySegment`. пример `allocate` с явными размером и выравниванием:

```java


import java.lang.foreign.*;



public class Program {



    public static void main(String[] args) {



        try (Arena arena = Arena.ofConfined()) {



            // выделяем сегмент памяти - в 16 байт с выравниванием по 8 байтам

            MemorySegment segment1 = arena.allocate(16, 8);

            // можем выделить еще один сегмент

            MemorySegment segment2 = arena.allocate(32, 4);



            // просто выведем информацию на экран

            System.out.println(segment1);   // MemorySegment{ kind: native, address: 0x772c881780e0, byteSize: 16 }

            System.out.println(segment2);   // MemorySegment{ kind: native, address: 0x772c881783d0, byteSize: 32 }

        } 

    }

}
```

первый сегмент занимает 16 байт и выровнен по 8, второй занимает 32 байта и выровнен по 4. печать `MemorySegment` показывает вид `native`, адрес и `byteSize`. адреса в комментарии относятся к одному прогону: при следующем запуске они другие, размеры 16 и 32 сохраняются. оба сегмента закрываются вместе с ареной в конце `try`, по отдельности их не освобождают.

`allocateFrom` с аргументом `String` даёт прямой способ положить строку в сегмент вне кучи:

```java


import java.lang.foreign.*;



public class Program {



    public static void main(String[] args) {



        try (Arena arena = Arena.ofConfined()) {



            String str = "Hello enoobis.ru";



            MemorySegment str_seg = arena.allocateFrom(str);



            System.out.println(str_seg);   // MemorySegment{ kind: native, address: 0x7aa79c1802d0, byteSize: 18 }

        } 

    }

}
```

строка java кодируется в utf-8, и под результат выделяется сегмент. в нём лежат байты текста и нулевой терминатор. у литерала `Hello enoobis.ru` 17 байт ascii, вместе с терминатором получается 18. это значение `byteSize` в комментарии к печати. адрес снова зависит от прогона.

### освобождение памяти

сегмент ограниченной или общей арены освобождается закрытием этой арены, методом `close()`. пока арена жива, сегмент жив, даже если переменная `MemorySegment` уже перезаписана: сама арена держит область. после `close` недействительны все сегменты, которые арена выдала.

у автоматической арены сегмент освобождает сборщик мусора. чтобы сегмент и арена стали недостижимы, ссылку сбрасывают в `null`. освобождение происходит позже, в каком-то цикле сборки, а не в строке присваивания:

```java


MemorySegment segment = Arena.ofAuto().allocate(...);



...

segment = null; // Память в конечном итоге освобождается
```

в этом фрагменте арену не сохраняют в отдельную переменную. единственная достижимая ссылка на выделенное хранится в переменной `segment`. присваивание `null` убирает её. когда сборщик признает объект недостижимым, он освободит память арены. до этого момента байты ещё заняты, и рассчитывать на немедленный возврат памяти нельзя.

сегменты глобальной арены за время работы программы не освобождаются. туда кладут данные, которые должны пережить весь процесс: таблицу, которую нативный код читает до выхода из виртуальной машины. для временной строки, как в вызове `printf`, глобальная арена оставляет байты до конца процесса, поэтому для таких буферов берут ограниченную арену и `try` с ресурсами.

освободить один сегмент, оставив остальные сегменты той же арены, нельзя. единица освобождения: арена целиком. так устроен жизненный цикл ffm: проверка «сегмент ещё жив» привязана к области арены. у отдельного указателя своего счётчика ссылок нет. ошибка использования после освобождения обнаруживается при обращении к сегменту: виртуальная машина бросает исключение.
