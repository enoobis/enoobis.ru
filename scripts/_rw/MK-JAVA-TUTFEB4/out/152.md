поиск библиотечной функции языка c и подготовка её к вызову в foreign function and memory api сосредоточены в классе **Linker**, полное имя `java.lang.foreign.Linker`. в комментариях примеров тот же объект назван компоновщиком: речь о связывании вызова с машинным соглашением, а не о статическом редакторе связей. линкер текущей нативной платформы, то есть вызывающего соглашения процесса, возвращает статический метод **Linker.nativeLinker()**:

```java
Linker linker = Linker.nativeLinker();
```

поиск символа по имени этот объект не выполняет. поиск делегирован экземпляру **SymbolLookup**, который даёт метод `defaultLookup()` линкера:

```java


Linker linker = Linker.nativeLinker();

SymbolLookup stdlib = linker.defaultLookup();
```

библиотеки, видимые поиску по умолчанию, зависят от платформы. в linux это libc и libm. такого поиска достаточно для известных функций `printf` и `malloc`. результат поиска является адресом символа. дескриптор вызова из него ещё предстоит собрать.

отдельную библиотеку, системную или свою, подключают через `SymbolLookup.libraryLookup()`. в метод передают путь к файлу библиотеки, строкой или объектом `Path`, и арену:

```java


SymbolLookup somelib = SymbolLookup.libraryLookup("/lib/x86_64-linux-gnu/libsxxx.so", arena);
```

`libraryLookup` загружает библиотеку на время жизни арены. когда арена закрывается, библиотека выгружается. адреса, полученные из этого поиска, после выгрузки не используют: отображение могло быть снято.

### поиск функций

получив `SymbolLookup`, по нему ищут функцию. для этого есть два метода:

- `Optional find(String name)` : возвращает адрес символа с заданным именем. пустой результат означает, что в этом поиске символа нет

- `MemorySegment findOrThrow(String name)` : возвращает адрес символа с заданным именем или генерирует исключение, если функция не найдена

в обоих случаях указатель на функцию приходит объектом `MemorySegment`, тем же видом сегмента, что и при работе с памятью. длина такого сегмента нулевая: размер кода символа поиску неизвестен, и читать сегмент как данные нельзя. сегмент несёт адрес, который дальше передают в связывание вызова. поиск `printf`:

```java


Linker linker = Linker.nativeLinker();

SymbolLookup stdlib = linker.defaultLookup();

MemorySegment printf_addr = stdlib.findOrThrow("printf");
```

### дескриптор функции/метода

адреса функции ещё недостаточно для вызова: нужно соглашение о регистрах, стеке и возвращаемом значении. **дескриптор метода** это объект, через который передают аргументы, вызывают метод и получают возвращаемое значение. его тип в java называется `MethodHandle`.

дескриптор внешнего вызова создаёт линкер, объект `Linker`, методом **downcallHandle()**. две формы:

- `downcallHandle(FunctionDescriptor function, Linker.Option... options)` создаёт дескриптор метода для вызова внешней функции с заданной сигнатурой. адрес функции в дескриптор не вшит, его передают отдельным аргументом в момент вызова

- `downcallHandle(MemorySegment address, FunctionDescriptor function, Linker.Option... options)` создаёт дескриптор метода для вызова внешней функции с заданной сигнатурой и адресом

у этих форм до трёх параметров:

- `address` : сегмент памяти, базовый адрес которого совпадает с адресом вызываемой внешней функции

- `function` : дескриптор вызываемой внешней функции, то есть описание её сигнатуры

- `options` : параметры линкера, связанные с этим запросом на связывание. через них задают особенности соглашения, которых нет в самой сигнатуре

сигнатуру описывает интерфейс **FunctionDescriptor**. обычно объект получают статическим методом `FunctionDescriptor.of`:

```java
FunctionDescriptor.of(MemoryLayout resLayout, MemoryLayout... argLayouts)
```

первый параметр задаёт компоновку памяти результата функции. второй параметр, переменной длины, задаёт компоновки памяти параметров функции, слева направо, как в объявлении c.

дескриптор метода для функции `printf` собирается целиком так:

```java


import java.lang.foreign.*;

import java.lang.invoke.*;



public class Program {



    public static void main(String[] args) {



        // получаем линкер/компоновщик 

        Linker linker = Linker.nativeLinker();

        // получаем стандартную библиотеку

        SymbolLookup stdlib = linker.defaultLookup();

        // получаем адрес функции printf

        MemorySegment printf_addr = stdlib.findOrThrow("printf");

        // дескриптор функции printf

        FunctionDescriptor printf_desc = FunctionDescriptor.of(ValueLayout.JAVA_INT, ValueLayout.ADDRESS);

        // дескриптор метода для функции printf

        MethodHandle printf = linker.downcallHandle(printf_addr, printf_desc);

        System.out.println(printf);     // MethodHandle(MemorySegment)int

    }

}
```

при передаче указателя в функцию c и при получении указателя в результате используют `ValueLayout.ADDRESS`. размер сегмента на стороне java для значения указателя роли не играет: в вызов уходит адрес. тип возвращаемого значения и типы параметров нужно указать точно. линкер по этому описанию выбирает соглашение вызова и не сверяет его с заголовком библиотеки. неверное описание может завершить работу виртуальной машины.

функция `printf` в c возвращает целое `int` и принимает строку как указатель на символы. её дескриптор имеет форму:

```java
FunctionDescriptor.of(ValueLayout.JAVA_INT, ValueLayout.ADDRESS)
```

`printf` в c объявлен с переменным числом аргументов. индекс первой вариативной компоновки при таком соглашении задают опцией `Linker.Option.firstVariadicArg`. дескриптор в примере описывает результат `JAVA_INT` и обязательный параметр `ADDRESS`: вызов передаёт одну строку формата. печать дескриптора показывает носители java, `MethodHandle(MemorySegment)int`: компоновка `ADDRESS` стала типом `MemorySegment`, компоновка `JAVA_INT` стала типом `int`.

### вызов функции

когда дескриптор метода получен, функцию вызывают методом **invoke()** типа `MethodHandle`:

```java
public final Object invoke(Object... args) throws Throwable
```

аргументы `invoke` являются значениями параметров внешней функции. передавать нужно носители компоновок, которыми описана сигнатура c. прямой вызов со строкой java сигнатуре не соответствует:

```java
printf.invoke("Hello");
```

`printf` принимает строку c, то есть указатель на байты с завершающим нулём. строку java для этого вызова сначала записывают в сегмент как utf-8. полный вызов:

```java


import java.lang.foreign.*;

import java.lang.invoke.*;



public class Program {



    public static void main(String[] args) throws Throwable{



        // получаем линкер/компоновщик 

        Linker linker = Linker.nativeLinker();

        // получаем стандартную библиотеку

        SymbolLookup stdlib = linker.defaultLookup();



        // получаем адрес функции printf

        MemorySegment printf_addr = stdlib.findOrThrow("printf");

        // дескриптор функции printf

        FunctionDescriptor printf_desc = FunctionDescriptor.of(ValueLayout.JAVA_INT, ValueLayout.ADDRESS);

        // дескриптор метода для функции printf

        MethodHandle printf = linker.downcallHandle(printf_addr, printf_desc);



        // создаем арену

        try (Arena arena = Arena.ofConfined()) {

            

            // строка для вывода

            String str = "Hello enoobis.ru\n";

            // преобразуем строку Java в строку UTF-8

            MemorySegment str_seg = arena.allocateFrom(str);



            // вызываем функцию printf и получаем результат

            int char_count = (int) printf.invoke(str_seg);  // Hello enoobis.ru

            

            System.out.println("Длина строки: " + char_count + " символов");  // Длина строки: 18 символов

        }

    }

}
```

`allocateFrom` кодирует строку java в utf-8 и дописывает нулевой байт. в `invoke` уходит сегмент `str_seg`. метод `invoke` принимает аргументы как `Object` и возвращает `Object`, поэтому результат приводят к `int`. объявление бросает `Throwable`: через него проходят и ошибки самого дескриптора, в том числе несовпадение типа аргумента с носителем. возвращённое число у `printf` равно количеству записанных символов. арена confined после блока освобождает сегмент строки. к этому моменту функция c байты уже прочитала.

#### возвращаемый тип void

функция, которая возвращает `void`, описывается методом **FunctionDescriptor.ofVoid**:

```java


FunctionDescriptor ofVoid(MemoryLayout... argLayouts)
```

параметры метода являются компоновками аргументов вызываемой внешней функции. компоновки результата нет, и у дескриптора метода результат `void`. указатель на `void` (`void*`), как и все указатели, представляет тип `ValueLayout.ADDRESS`. дескрипторы методов для `malloc` (выделение памяти) и `free` (освобождение памяти):

```java


import java.lang.foreign.*;

import java.lang.invoke.*;



public class Program {



    public static void main(String[] args) throws Throwable{



        // получаем линкер/компоновщик 

        Linker linker = Linker.nativeLinker();

        // получаем стандартную библиотеку

        SymbolLookup stdlib = linker.defaultLookup();



        // получаем адрес функции malloc

        MemorySegment mallocAddr = stdlib.findOrThrow("malloc");

        // void* malloc(size_t)

        MethodHandle mallocHandle = linker.downcallHandle(mallocAddr, FunctionDescriptor.of(ValueLayout.ADDRESS, ValueLayout.JAVA_LONG));

        System.out.println(mallocHandle);   // MethodHandle(long)MemorySegment





        // получаем адрес функции free

        MemorySegment freeAddr = stdlib.findOrThrow("free");

        // void free(void *ptr)

        MethodHandle freeHandle = linker.downcallHandle(freeAddr, FunctionDescriptor.ofVoid(ValueLayout.ADDRESS));

        System.out.println(freeHandle);     // MethodHandle(MemorySegment)void



    }

}
```

`malloc` в c имеет вид `void* malloc(size_t)`. на 64-разрядной платформе `size_t` занимает 8 байт, поэтому аргумент описан компоновкой `JAVA_LONG`, а результат компоновкой `ADDRESS`. печать даёт `MethodHandle(long)MemorySegment`. `free` имеет вид `void free(void*)`, поэтому дескриптор построен через `ofVoid` с одним параметром `ADDRESS`. печать даёт `MethodHandle(MemorySegment)void`. область, полученную от `malloc`, освобождает `free`. арена java эту область не ведёт: выделение выполнила библиотека c, и время жизни области задаёт пара `malloc` и `free`, а не закрытие арены.
