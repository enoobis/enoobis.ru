среда выполнения java порождает исключения сама, когда операция не может завершиться по семантике языка. типичный случай: деление целого на ноль, возникает `ArithmeticException`. наряду с этим язык позволяет возбудить исключение явно, оператором `throw`. явная генерация нужна там, где нарушено предметное ограничение. правило виртуальной машины такое ограничение не описывает. если программа принимает имя и считает допустимым лишь имя длиной не меньше двух символов, строка из одного символа для неё ошибочна, хотя с точки зрения типа `String` она корректна. на имя можно наложить и другие ограничения. при нарушении `throw` создаёт исключительную ситуацию: управление переходит к совместимому обработчику либо поток завершается, если обработчика нет.

общая форма оператора:

```java


throw объект_исключения;
```

после `throw` записывается ссылка на объект исключения, экземпляр класса из иерархии `Throwable`. объект строится через `new` из стандартных классов, в том числе из базовых `Throwable` и `Exception`. один из конструкторов `Throwable` принимает сообщение об ошибке:

```java


Throwable(String message)
```

это сообщение затем возвращает `getMessage()`. если исключение остаётся необработанным, тот же текст попадает в диагностику на консоли. прочие типы исключений, как правило, объявляют такой же конструктор и передают строку выше по иерархии, в `super`.

генерация исключения на конкретном вводе выглядит так:

```java


import java.util.Scanner;



class Program{

     

	public static void main(String[] args) {

         

        Scanner in = new Scanner(System.in);

        System.out.print("Введите имя: ");

        String name = in.nextLine(); // считываем введенную строку



        // если строка имеет имеет меньше 2-х символов, генерируем исключение

        if(name.length() < 2) throw new Throwable("Малобукоф");



        System.out.println("Привет, " + name);

    }

}
```

класс `Scanner`, связанный с `System.in`, читает строку методом `nextLine()`. длина запрашивается у `length()`. если она меньше 2, выполняется

```java
if(name.length() < 2) throw new Throwable("Малобукоф");
```

в конструктор `Throwable` передаётся текст ошибки. строка становится состоянием объекта и доступна обработчику через `getMessage()`.

компиляция этого фрагмента завершается ошибкой:

```bash


Program.java:12: error: unreported exception Throwable; must be caught or declared to be thrown

        if(name.length() < 2) throw new Throwable("Малобукоф");

                              ^

1 error
```

диагностика `unreported exception Throwable; must be caught or declared to be thrown` фиксирует статическое требование. метод, в теле которого возникает проверяемое исключение, обязан либо перехватить его, либо объявить его в сигнатуре. показанный `main` не делает ни того, ни другого.

### проверяемые и непроверяемые исключения

исключения java делятся на проверяемые (checked) и непроверяемые (unchecked). к непроверяемым относятся `Error`, `RuntimeException` и все их подтипы. проверяемыми считаются остальные классы иерархии `Throwable`. для `throw` различие существенно: оно проводится во время компиляции по статическому типу выражения. фактический тип объекта во время выполнения в этой проверке не участвует. при генерации проверяемого исключения метод либо указывает этот тип в секции `throws`, либо обрабатывает его в `try..catch`. непроверяемое исключение компилятор не требует ни объявлять, ни перехватывать: контроль остаётся на семантике программы.

в примере выше статическим типом объекта является сам `Throwable`. компилятор считает его проверяемым, хотя `Error` и `RuntimeException` наследуют `Throwable`. правило такое: тип проверяем, если он не является подтипом `RuntimeException` или `Error`. `Throwable` не подтип ни одного из этих двух классов, поэтому объявление `throw new Throwable(...)` без обработки и без `throws` отвергается.

исправление состоит в том, чтобы перехватить исключение конструкцией `try..catch`:

```java


import java.util.Scanner;



class Program{

     

	public static void main(String[] args) {

         

        Scanner in = new Scanner(System.in);

        System.out.print("Введите имя: ");

        String name = in.nextLine(); // считываем введенную строку



        try{



            // если строка имеет имеет меньше 2-х символов, генерируем исключение

            if(name.length() < 2) throw new Throwable("Малобукоф");

            System.out.println("Привет, " + name);

        }

        catch(Throwable ex){

            System.out.println("Возникла ошибка: " + ex.getMessage());

        }

    }

}
```

участок, который проверяет `name` и может выполнить `throw`, помещён в блок `try`. если исключение порождено, оставшиеся операторы блока не выполняются, объект передаётся в совместимый `catch`, и там печатается сообщение. вызов с приветствием достижим только при длине имени не меньше 2: после успешной проверки выполнение идёт дальше по `try` и блок `catch` пропускается.

пример запуска:

```bash


Введите имя: e

Возникла ошибка: Малобукоф
```

### обработка других типов исключений

`throw` допустим всюду, где разрешён оператор: в методе, в конструкторе, внутри ветки. тип объекта может быть любым подтипом `Throwable`, не только самим базовым классом. для аргумента, который не удовлетворяет контракту метода, в стандартной библиотеке есть `IllegalArgumentException`. класс наследует `RuntimeException` и потому относится к непроверяемым исключениям. ниже он применяется в конструкторе `Person`: возраст должен лежать в заданном диапазоне.

```java


class Program{

     

	public static void main(String[] args) {

         

        var tom = new Person("Tom", -20);

        tom.print();

    }

}



class Person{

    

    private String name;

    private int age;



    Person(String name, int age){



        if(age < 1 || age > 110) throw new IllegalArgumentException("Некорректный возраст: " + age);

        this.name = name; 

        this.age = age;

    }



    void print(){ System.out.printf("Name: %s; Age: %d\n", name, age); }

}
```

через параметр `age` в конструктор передаётся возраст. тип параметра, `int`, и множество его значений шире множества осмысленных возрастов: отрицательное число возрастом не является, как и слишком большое. конструктор сопоставляет `age` с диапазоном от 1 до 110 включительно. при выходе за диапазон выполняется

```java


if(age < 1 || age > 110) 

    throw new IllegalArgumentException("Некорректный возраст: " + age);
```

в `main` в конструктор передаётся заведомо недопустимое значение:

```java
var tom = new Person("Tom", -20);
```

создание экземпляра доходит до проверки, `throw` порождает исключение, и при отсутствии обработчика поток `main` завершается:

```bash


Exception in thread "main" java.lang.IllegalArgumentException: Некорректный возраст: -20

	at Person.<init>(Program.java:20)

	at Program.main(Program.java:7)
```

в трассировке указаны тип `IllegalArgumentException`, сообщение из конструктора и кадры стека: конструктор `Person.<init>` и вызывающий `Program.main`. компилятор при этом ошибку не сообщает. `IllegalArgumentException` непроверяемое, и ни `throws`, ни `try..catch` для него не требуются. если аварийное завершение с трассировкой приемлемо, исключение можно не перехватывать. перехват нужен, когда текст ошибки обрабатывается внутри программы и выполнение продолжается:

```java


class Program{

     

	public static void main(String[] args) {

         

        try{



            var tom = new Person("Tom", -20);

            tom.print();

        }

        catch(IllegalArgumentException ex){

            System.out.println(ex.getMessage());

        }

    }

}



class Person{

    

    private String name;

    private int age;



    Person(String name, int age){



        if(age < 1 || age > 110) throw new IllegalArgumentException("Некорректный возраст: " + age);

        this.name = name; 

        this.age = age;

    }



    void print(){ System.out.printf("Name: %s; Age: %d\n", name, age); }

}
```

## оператор throws

если метод порождает проверяемое исключение и не перехватывает его, компилятору нужно объявление: метод выпускает это исключение наружу. обработка внутри метода: один из двух способов удовлетворить проверке. часто метод не располагает правильной реакцией на ошибку и оставляет решение вызывающему коду. тогда в объявлении метода перечисляются типы проверяемых исключений. для этого служит секция `throws`:

```java


возвращаемый_тип имя_метода(параметры) throws тип_исключения_1, тип_исключения_2,... тип_исключения_N  {



}
```

секция записывается после списка параметров и до открывающей фигурной скобки тела. дальше через запятую идут типы. в следующем примере чтение имени вынесено в отдельный метод:

```java


import java.util.Scanner;



class Program{

     

	public static void main(String[] args) {

         

        try{

            printName();  // здесь генерируется исключение

        }

        catch(Throwable ex){

            System.out.println(ex.getMessage());

        }

    }



    static void printName() throws Throwable {



        Scanner in = new Scanner(System.in);

        System.out.print("Введите имя: ");

        String name = in.nextLine(); // считываем введенную строку



        // если строка имеет имеет меньше 2-х символов, генерируем исключение

        if(name.length() < 2) throw new Throwable("Недостаточная длина имени: " + name.length());

        System.out.println("Привет, " + name);

    }

}
```

`printName` читает строку с консоли и при длине меньше 2 выполняет `throw` с объектом `Throwable`. сам метод исключение не перехватывает, поэтому в его сигнатуре указано

```java
static void printName() throws Throwable {
```

вызывающий `main` перехватывает возможное исключение конструкцией `try..catch` и печатает `getMessage()`.

если вызываемый метод не обрабатывает проверяемое исключение, вызывающий обязан либо обработать его, как в предыдущем фрагменте, либо тоже объявить этот тип в `throws`. второй вариант переносит обязанность ещё выше по стеку:

```java


import java.util.Scanner;



class Program{

     

	public static void main(String[] args) throws Throwable {

         

        printName(); // здесь возникает исключение, но его никто не обрабатывает

    }



    static void printName() throws Throwable{



        Scanner in = new Scanner(System.in);

        System.out.print("Введите имя: ");

        String name = in.nextLine(); // считываем введенную строку



        // если строка имеет имеет меньше 2-х символов, генерируем исключение

        if(name.length() < 2) throw new Throwable("Недостаточная длина имени: " + name.length());

        System.out.println("Привет, " + name);

    }

}
```

фрагмент компилируется, потому что в заголовке `main` есть

```java


public static void main(String[] args) throws Throwable {
```

при недопустимом вводе исключение не перехватывается ни на одном кадре. поток завершается, и среда печатает трассировку. тип в сообщении: `java.lang.Throwable`. текст взят из конструктора, кадры указывают `printName` и `main`.

```bash


Введите имя: r

Exception in thread "main" java.lang.Throwable: Недостаточная длина имени: 1

	at Program.printName(Program.java:22)

	at Program.main(Program.java:7)
```

один метод может выпускать несколько проверяемых типов. они перечисляются в `throws` через запятую:

```java


public static void main(String[] args) throws FileNotFoundException, EOFException {
```

непроверяемые исключения, в том числе `IllegalArgumentException`, в `throws` указывать не требуется: компилятор их не учитывает. секция `throws` описывает контракт проверяемых исключений. он входит в сигнатуру и проверяется у каждого вызывающего метода. непроверяемое исключение в этот контракт не входит, даже если метод фактически его порождает.
