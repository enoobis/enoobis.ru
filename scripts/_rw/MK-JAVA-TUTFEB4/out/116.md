коллекции, на основе которых нередко создаются потоки, уже имеют специальные методы для сортировки содержимого. класс `Stream` также включает возможность сортировки. её задействуют, когда набор промежуточных операций с потоком создаёт новые наборы данных и сортировать надо уже эти наборы, а не исходную коллекцию.

для простой сортировки по возрастанию применяется метод `sorted()`:

```java


import java.util.ArrayList;

import java.util.Collections;

import java.util.List;



public class Program {

 

    public static void main(String[] args) {

         

        List<String> phones = new ArrayList<String>();

		Collections.addAll(phones, "iPhone X", "Nokia 9", "Huawei Nexus 6P",

                "Samsung Galaxy S8", "LG G6", "Xiaomi MI6",

                "ASUS Zenfone 3", "Sony Xperia Z5", "Meizu Pro 6",

                "Pixel 2");

         

        phones.stream()

                .filter(p->p.length()<12)

                .sorted() // сортировка по возрастанию

                .forEach(s->System.out.println(s));

    } 

}
```

`filter` оставляет названия короче 12 символов. из исходного списка при таком условии выпадают `Huawei Nexus 6P`, `Samsung Galaxy S8`, `ASUS Zenfone 3` и `Sony Xperia Z5`: их длины больше либо равны 12. `sorted()` сортирует оставшиеся по возрастанию, `forEach` печатает результат. консольный вывод после сортировки объектов:

```consoletext


LG G6

Meizu Pro 6

Nokia 9

Pixel 2

Xiaomi MI6

iPhone X
```

метод сортирует объекты по возрастанию. порядок совпадает с естественным порядком `String`: сравнение идёт по кодовым единицам utf-16. коды заглавных латинских букв меньше кодов строчных, поэтому `LG G6`, `Meizu Pro 6`, `Nokia 9`, `Pixel 2` и `Xiaomi MI6` оказываются раньше `iPhone X`, у которого первая буква строчная. заглавные и строчные буквы рассматриваются отдельно и не склеиваются в одну и ту же букву.

кроме того, `sorted()` без аргументов подходит только для сортировки тех объектов, которые реализуют интерфейс `Comparable`. если элемент этот интерфейс не реализует, при выполнении возникает `ClassCastException`: стадия приводит элемент к `Comparable`.

если классы объектов не реализуют этот интерфейс или нужна своя логика сортировки, используется другая версия метода `sorted()`, которая в качестве параметра принимает компаратор.

класс `Phone` для такого примера:

```java


class Phone{

    

    private String name;

    private String company;

    private int price;

    

    public Phone(String name, String comp, int price){

        this.name=name;

        this.company=comp;

        this.price = price;

    }

    

    public String getName() { return name; }

    public int getPrice() { return price; }

    public String getCompany() { return company; }

}
```

отсортируем поток объектов `Phone`:

```java


import java.util.Comparator;

import java.util.stream.Stream;



public class Program {



    public static void main(String[] args) {



        Stream<Phone> phoneStream = Stream.of(new Phone("iPhone X", "Apple", 600), 

            new Phone("Pixel 2", "Google", 500),

            new Phone("iPhone 8", "Apple",450),

            new Phone("Nokia 9", "HMD Global",150),

            new Phone("Galaxy S9", "Samsung", 300));

        

        phoneStream.sorted(new PhoneComparator())

                .forEach(p->System.out.printf("%s (%s) - %d \n", 

                        p.getName(), p.getCompany(), p.getPrice()));

        

    } 

}

class PhoneComparator implements Comparator<Phone>{

 

    public int compare(Phone a, Phone b){

     

        return a.getName().toUpperCase().compareTo(b.getName().toUpperCase());

    }

}
```

здесь определён класс компаратора `PhoneComparator`, который реализует `Comparator<Phone>` и сортирует объекты по полю `name`. `compare` приводит оба имени к верхнему регистру через `toUpperCase()` и сравнивает полученные строки методом `compareTo`. отрицательное число означает, что первое имя меньше второго, ноль означает равенство в этом порядке, положительное означает, что первое больше. `toUpperCase()` без явной локали берёт локаль по умолчанию. для латиницы этого набора порядок от локали не зависит. контракт `Comparator` соблюдён: равные в верхнем регистре имена дают ноль, и знак `compare(a, b)` противоположен знаку `compare(b, a)`.

в итоге получается следующий вывод:

```consoletext


Galaxy S9 (Samsung) - 300 

iPhone 8 (Apple) - 450 

iPhone X (Apple) - 600

Nokia 9 (HMD Global) - 150 

Pixel 2 (Google) - 500
```

имена идут без учёта регистра: `Galaxy S9`, `iPhone 8`, `iPhone X`, `Nokia 9`, `Pixel 2`. цена и компания в сравнение не входят, они только печатаются вместе с именем.
