для хранения набора однотипных значений в java есть массивы. длина массива фиксирована: она записывается в объект при создании и дальше не меняется, потому что элементы лежат в непрерывном блоке памяти. чтобы увеличить набор, нужно выделить новый массив и скопировать в него старые элементы. эту задачу, вместе с выбором структуры данных, берёт на себя java collections framework, подсистема стандартной библиотеки для коллекций. дело не только в том, что размер набора может расти. классы коллекций реализуют разные структуры и алгоритмы: список, множество, стек, очередь, дерево и другие.

типы коллекций объявлены в пакете `java.util`. перед использованием соответствующий тип импортируют.

иерархия устроена так, что контракт отделён от реализации. в основе лежит интерфейс: он задаёт операции и их смысл, а класс даёт конкретное представление в памяти. основные интерфейсы:

- `Collection`: базовый интерфейс коллекций и общий предок остальных интерфейсов коллекций, кроме `Map`

- `Queue`: наследует `Collection` и задаёт операции очереди

- `Deque`: наследует `Queue` и задаёт двунаправленную очередь, у которой оба конца доступны для вставки и удаления

- `List`: наследует `Collection` и задаёт список: порядок элементов сохраняется, доступ идёт по индексу, повторы допустимы

- `Set`: наследует `Collection` и задаёт множество. элемент входит в него не более одного раза, сравнение ведётся через `equals`

- `SortedSet`: расширяет `Set` и хранит элементы в порядке сортировки, естественном или заданном компаратором

- `NavigableSet`: расширяет `SortedSet` и добавляет поиск ближайшего элемента относительно заданного значения: методы вроде `lower`, `floor`, `ceiling`, `higher`

- `Map`: словарь, в котором у каждого элемента есть ключ и значение. от `Collection` этот интерфейс не наследует: пара «ключ-значение» не сводится к одному элементу коллекции, поэтому ассоциативный массив стоит в иерархии рядом с `Collection`

часть контракта уже реализована абстрактными классами. конкретный класс доопределяет хранение, а общую механику наследует:

- `AbstractCollection`: базовая реализация для коллекций, применяющих `Collection`

- `AbstractList`: расширяет `AbstractCollection` и применяет `List`, основа списков с доступом по индексу

- `AbstractSet`: расширяет `AbstractCollection` и применяет `Set`, основа множеств

- `AbstractQueue`: расширяет `AbstractCollection` и применяет `Queue`, основа очередей и стеков

- `AbstractSequentialList`: расширяет `AbstractList` и реализует `List` через последовательный доступ. от него строят связные списки

- `AbstractMap`: применяет `Map` и служит основой словарей с парами «ключ-значение»

на этих интерфейсах и абстрактных классах собраны основные реализации:

- `ArrayList`: список на динамическом массиве

- `LinkedList`: двусвязный список. вставка и удаление у известного узла обходятся без сдвига остальных элементов, доступ по индексу линеен

- `ArrayDeque`: двунаправленная очередь на кольцевом массиве. вставка и удаление возможны и в начале, и в конце

- `HashSet`: множество на хеш-таблице. бакет выбирается по хеш-коду, а равенство элементов определяется `equals`. одинаковый хеш-код у разных объектов допустим: коллизия допустима и вставке не мешает

- `TreeSet`: упорядоченное множество на дереве поиска. в jdk реализация опирается на красно-чёрное дерево

- `LinkedHashSet`: хеш-множество, которое дополнительно помнит порядок вставки

- `PriorityQueue`: очередь с приоритетом. из головы извлекается наименьший в заданном порядке элемент. момент вставки сам по себе порядок не задаёт

- `HashMap`: словарь на хеш-таблице. у каждой записи уникальный ключ и связанное с ним значение

- `TreeMap`: словарь на дереве поиска. ключи упорядочены, каждому ключу соответствует значение

### интерфейс collection

`Collection` задаёт операции, общие для списков, множеств и очередей:

```java
public interface Collection<E> extends Iterable<E>{

	// определения методов
}
```

интерфейс обобщённый: параметр типа `E` задаёт тип элемента. он расширяет `Iterable`, поэтому любую коллекцию можно обойти циклом `for-each`. цикл разворачивается в получение `Iterator` и последовательные вызовы `hasNext` и `next`.

у `Collection` в частности есть такие методы:

- `boolean add(E item)`: добавляет в коллекцию объект item. при успехе возвращает true, при отказе возвращает false. множество возвращает false, если равный элемент уже есть

- `boolean addAll(Collection col)`: добавляет все элементы коллекции col. при изменении текущей коллекции возвращает true, иначе false

- `void clear()`: удаляет все элементы

- `boolean contains(Object item)`: возвращает true, если item содержится в коллекции, иначе false. поиск опирается на `equals`

- `boolean containsAll(Collection col)`: возвращает true, если в коллекции есть все элементы col, иначе false

- `boolean isEmpty()`: возвращает true, если коллекция пуста, иначе false

- `Iterator iterator()`: возвращает `Iterator` для обхода элементов

- `boolean remove(Object item)`: удаляет один объект, равный item. при успехе возвращает true, иначе false

- `boolean removeAll(Collection col)`: удаляет из текущей коллекции все объекты, которые есть в col. если коллекция изменилась, возвращает true, иначе false

- `boolean removeIf(Predicate filter)`: удаляет элементы, для которых предикат filter возвращает true

- `boolean retainAll(Collection col)`: оставляет в текущей коллекции только те объекты, которые содержатся в col, остальные удаляет. если коллекция изменилась, возвращает true, иначе false

- `int size()`: возвращает число элементов

- `Object[] toArray()`: возвращает массив со всеми элементами коллекции

эти операции реализует каждая коллекция, поэтому добавление, удаление, очистка и запрос размера выглядят одинаково у списка, множества и очереди. элемент добавляется методом `add`, удаляется методом `remove`, коллекция очищается методом `clear`, число элементов даёт `size`. различия реализаций лежат в сложности, в допустимости повторов и в порядке обхода. имена базовых операций при этом общие. единый контракт позволяет писать код от интерфейса `Collection` и подставлять конкретный класс там, где известны требования к структуре данных.
