в предыдущей главе разбирались преобразования значений простых типов. с объектами классов семантика иная: меняется статический тип ссылки, а сам объект в памяти остаётся тем же экземпляром. ниже иерархия классов.

```java


public class Program{

      

    public static void main(String[] args) {

             

        Person tom = new Person("Tom");

        tom.print();        // Person Tom

        Person sam = new Employee("Sam", "Yandex");

        sam.print();        // Employee Sam works in Yandex

        Person bob = new Client("Bob", "SberBank");

        bob.print();    // Client Bob has account in SberBank

    }

}

// класс человека

class Person {

     

    private String name;

    String getName() {return name;}

    

    Person(String name){

     

        this.name=name;

    }

  

    void print(){

         

        System.out.printf("Person %s \n", name);

    }

}

// служащий некоторой компании 

class Employee extends Person{

 

    private String company;

    String getCompany(){return company;}

     

    Employee(String name, String company) {

     

        super(name);

        this.company = company;

    }

     

    void print(){

         

        System.out.printf("Employee %s works in %s \n", getName(), company);

    }

}

// класс клиента банка

class Client extends Person{

       

    private String bank;

    String getBank(){return bank;}

       

    Client(String name, String bank) {

       

        super(name);

        this.bank=bank;

    }

       

    void print(){

           

        System.out.printf("Client %s has account in %s \n", getName(), bank);

    }

}
```

в этой иерархии прослеживается цепь наследования: `Object` (все классы неявно наследуются от `Object`, если не указан другой прямой суперкласс) -> `Person` -> `Employee` | `Client`.

суперклассы обычно размещают выше подклассов, поэтому на вершине наследования находится класс `Object`, а в самом низу: `Employee` и `Client`.

### upcasting, восходящее преобразование

объект подкласса одновременно является объектом суперкласса: отношение подтипа идёт вверх по иерархии. поэтому ссылку на экземпляр подкласса записывают в переменную типа суперкласса.

```java


public class Program{

      

    public static void main(String[] args) {

             

        Object tom = new Person("Tom");                     // преобразование от Person к Object

        Object sam = new Employee("Sam", "Yandex");         // от Employee к Object

        Object kate = new Client("Kate", "SberBank");       // от Client к Object

        Person bob = new Client("Bob", "VTB");              // от Client к Person

        Person alice = new Employee("Alice", "VK");         // от Employee к Person

    }

}
```

это восходящее преобразование (от подкласса внизу к суперклассу вверху иерархии), или upcasting. оно безопасно и выполняется автоматически, без оператора приведения. компилятор принимает его, потому что любой `Employee` и любой `Client` удовлетворяют контракту `Person` и контракту `Object`.

### downcasting, нисходящее преобразование

обратное верно не всегда. объект `Person` не всегда является объектом `Employee` или `Client`. поэтому нисходящее преобразование, или downcasting, от суперкласса к подклассу автоматически не выполняется. нужна явная операция приведения типов.

```java


Object sam = new Employee("Sam", "Yandex");

sam.print(); // ! Ошибка
```

переменная `sam` хранит ссылку на объект типа `Employee`, но сама имеет статический тип `Object`. на этапе компиляции доступен только контракт `Object`. метод `print()` в этот контракт не входит, поэтому программа не компилируется: объект типа `Object` не обязательно представляет `Employee` или `Person` и может не иметь метода `print()`. чтобы добраться до метода подтипа, применяют нисходящее преобразование от `Object` к `Employee` или к `Person`.

```java


Object sam = new Employee("Sam", "Yandex");



// нисходящее преобразование от Object к типу Employee

Employee emp = (Employee)sam;

emp.print();

System.out.println(emp.getCompany());
```

здесь переменная `sam` приводится к типу `Employee`. затем через объект `emp` доступен функционал `Employee`, в том числе метод `getCompany()`.

объект `Employee` можно провести по всей прямой линии наследования от `Object` к `Employee`. приведение поперёк ветвей, от `Client` к `Employee` или обратно, этой линии не принадлежит.

примеры нисходящих преобразований:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Object kate = new Client("Kate", "Sberbank");

        ((Person)kate).print();

                

        Object sam = new Employee("Sam", "Yandex");

        ((Employee)sam).print();

    }

}
```

ещё одна ситуация:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Person kate = new Client("Kate", "Sberbank");

        Employee emp = (Employee) kate;   // ! Ошибка - java.lang.ClassCastException

        emp.print();



        // или так

        ((Employee)kate).print();

    }

}
```

переменная `kate` имеет тип `Person` и хранит ссылку на объект `Client`. приведение этого объекта к типу `Client` проходит без ошибки: динамический тип совместим с целевым. попытка преобразования к типу `Employee` даёт ошибку во время выполнения, `java.lang.ClassCastException`. `kate` не ссылается на объект типа `Employee`. классы `Client` и `Employee` находятся в соседних ветвях и не состоят в отношении подтипа.

### оператор instanceof

в примере выше по тексту видно, что `kate` есть ссылка на объект `Client`, а тип `Employee` ей не соответствует. нередко данные приходят извне, и точный динамический тип заранее неизвестен. тогда вероятность ошибки приведения велика. перед преобразованием типов совместимость проверяют оператором `instanceof`.

```java


public class Program{

      

    public static void main(String[] args) {

             

        Person kate = new Client("Kate", "Sberbank");

        printPerson(kate);  // Person is not an employee



        Person sam = new Employee("Sam", "Yandex");

        printPerson(sam);  // Employee works in Yandex

    }



    static void printPerson(Person person){

        if(person instanceof Employee){

     

            Employee empl = (Employee) person;

            System.out.println("Employee works in " + empl.getCompany());

        }

        else{

                            

            System.out.println("Person is not an employee");

        }

    }

}
```

в методе `printPerson` выражение `person instanceof Employee` проверяет, является ли динамический тип параметра `person` типом `Employee` или подтипом `Employee`. для ссылки `null` результат ложен: приводить нечего. если объект не является `Employee`, проверка возвращает `false`, преобразование не выполняется, и работает блок `else`:

```java


else{

                            

    System.out.println("Person is not an employee");

}
```

если параметр `person` представляет тип `Employee`, выполняется блок `if`: ссылка преобразуется к типу `Employee`, и на консоль выводится информация об объекте.

```java


if(person instanceof Employee){

     

    Employee empl = (Employee) person;

    System.out.println("Employee works in " + empl.getCompany());

}
```
