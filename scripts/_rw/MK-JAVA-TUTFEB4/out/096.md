у `Thread` есть методы управления уже созданным потоком. ниже разобраны приостановка текущего потока и ожидание завершения другого.

### метод sleep

статический метод `Thread.sleep` приостанавливает текущий поток на заданный срок и переводит его в `TIMED_WAITING`. приостановить можно только тот поток, который выполняет вызов: ссылка на чужой `Thread` для этого метода не нужна. три перегрузки:

```java


static void sleep(long millis)

static void sleep(long millis, int nanos)

static void sleep(Duration duration)
```

первая принимает миллисекунды, вторая добавляет к ним наносекунды, третья принимает `Duration`. перегрузка с `Duration` появилась в java 19. отрицательная длительность даёт `IllegalArgumentException`. аргумент `nanos` обязан лежать в диапазоне от 0 до 999999 включительно.

`sleep` объявляет проверяемое исключение `InterruptedException`. его обрабатывают в теле метода или перечисляют в `throws`. если за время ожидания у потока выставлен флаг прерывания, `sleep` сбрасывает флаг и выбрасывает это исключение. монитор, который поток уже держит, за ним и остаётся: остановка внутри `synchronized` блокировку не отпускает. срок задаёт нижнюю границу паузы. по её истечении поток переходит в `RUNNABLE`, а когда он реально продолжится, решает планировщик.

первая перегрузка в задаче:

```java


class MyTask implements Runnable {



    public void run(){

         

        String name = Thread.currentThread().getName();  // получаем имя текущего потока



        System.out.println(name + " started...");



        System.out.println(name + " works"); 

        

        try{

            Thread.sleep(1000); // приостанавливаем поток на 1000 миллисекунд

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        System.out.println(name + " finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        var task = new MyTask();

        new Thread(task, "MyTask").start();



        System.out.println("Main thread finished...");

    }

}
```

в `run()` класса `MyTask`, то есть в теле потока, задержка стоит в `try`/`catch` на 1000 миллисекунд, это 1 секунда:

```java


try{

    Thread.sleep(1000); // приостанавливаем поток на 1000 миллисекунд

}

catch(InterruptedException ex){

    System.out.println(ex.getMessage());

}
```

когда исполнение доходит до `Thread.sleep(1000)`, поток переходит в `TIMED_WAITING` и возвращается к следующей инструкции не раньше чем через секунду. возможный вывод:

```bash


Main thread started...

Main thread finished...

MyTask started...

MyTask works

MyTask finished...
```

главный поток печатает своё завершение раньше дочернего. `join` здесь не вызывается, и `main` секундную паузу в `MyTask` не ждёт.

### ожидание завершения потока и метод join

в предыдущих примерах главный поток завершался раньше дочернего. если продолжать `main` нужно только после конца дочернего потока, на объекте этого потока вызывают `join`:

```java


void join()

void join(long millis)

void join(long millis, int nanos)

boolean join(Duration duration)
```

перегрузок несколько. без ограничения по времени `join` ждёт перехода целевого потока в `TERMINATED`. перегрузки с миллисекундами, наносекундами и `Duration` возвращают управление и в том случае, когда срок истёк, а поток ещё жив. вариант с `Duration` возвращает `boolean`: `true`, если поток успел завершиться, `false`, если истёк тайм-аут. остальные перегрузки возвращают `void`. все варианты объявляют `InterruptedException`.

`join` на потоке в состоянии `NEW` возвращается сразу: `isAlive()` для ещё не запущенного потока ложен, ждать в цикле ожидания нечего. осмысленно ждать поток, для которого уже вызван `start()`.

реализация ждёт на мониторе самого объекта `Thread`, а завершающийся поток уведомляет ждущих. отсюда два следствия. действия дочернего потока до выхода из `run()` становятся видимы вызывающему после возврата из `join`: между ними есть отношение happens-before. вызов `join` под чужим монитором, которого ждёт целевой поток, способен привести к взаимной блокировке.

главный поток дожидается дочернего:

```java


class MyTask implements Runnable {



    public void run(){

         

        String name = Thread.currentThread().getName();  // получаем имя текущего потока



        System.out.println(name + " started...");



        System.out.println(name + " works");

        

        try{

            Thread.sleep(1000); // приостанавливаем поток на 1000 миллисекунд

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        System.out.println(name + " finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        var task = new MyTask();

        var t = new Thread(task, "MyTask");

        t.start();



        try{

            t.join();  // текущий поток Main thread ожидает завершения потока t

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        

        System.out.println("Main thread finished...");

    }

}
```

`join()` тоже выбрасывает `InterruptedException`, поэтому вызов стоит в `try`/`catch`:

```java


var task = new MyTask();

var t = new Thread(task, "MyTask");

t.start();



try{

    t.join();  // текущий поток Main thread ожидает завершения потока t

}

catch(InterruptedException ex){

    System.out.println(ex.getMessage());

}
```

теперь `"Main thread finished..."` печатается после `"MyTask finished..."`:

```bash


Main thread started...

MyTask started...

MyTask works

MyTask finished...

Main thread finished...
```

ожидание без срока опасно, если в дочернем потоке цикл без выхода. срок ограничивают. ниже предел равен 500 миллисекундам, а `MyTask` спит 1000:

```java


var task = new MyTask();

var t = new Thread(task, "MyTask");

t.start();



try{

    t.join(500);  // ждем завершения потока t не более 500 миллисекунд

}

catch(InterruptedException ex){

    System.out.println(ex.getMessage());

}
```

`MyTask` выполняется дольше секунды, ожидание обрывается через 500 миллисекунд. главный поток печатает завершение, пока `MyTask` ещё в `sleep`:

```bash


Main thread started...

MyTask started...

MyTask works

Main thread finished...

MyTask finished...
```

#### ожидание группы потоков

если дочерних потоков несколько и главный поток должен продолжиться после каждого из них, `join()` вызывают на каждом. ссылки удобно держать в массиве:

```java


class MyTask implements Runnable {



    public void run(){

         

        String name = Thread.currentThread().getName();  // получаем имя текущего потока



        System.out.println(name + " started...");



        System.out.println(name + " works");

        

        try{

            Thread.sleep(1000); // приостанавливаем поток на 1000 миллисекунд

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        System.out.println(name + " finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        // определяем и запускаем 4 потока

        Thread[] tasks = new Thread[4];

        for(int i = 0; i < tasks.length; i++) {



            tasks[i] = new Thread(new MyTask(), "MyTask_" + i);

            tasks[i].start();

        }   



        //  ждем завершения 4 потоков

        try{

            

            for(int i = 0; i < tasks.length; i++)  tasks[i].join();

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        

        System.out.println("Main thread finished...");

    }

}
```

цикл создаёт и запускает четыре потока с именами `MyTask_0` ... `MyTask_3`. второй цикл вызывает `join` по очереди. если какой-то поток к этой строке уже завершился, соответствующий `join` возвращается сразу. последняя строка главного потока печатается после всех четырёх дочерних:

```bash


Main thread started...

MyTask_2 started...

MyTask_1 started...

MyTask_2 works

MyTask_1 works

MyTask_3 started...

MyTask_3 works

MyTask_0 started...

MyTask_0 works

MyTask_1 finished...

MyTask_2 finished...

MyTask_3 finished...

MyTask_0 finished...

Main thread finished...
```

порядок строк дочерних потоков между собой по-прежнему задаёт планировщик. фиксировано положение `"Main thread finished..."` после них. этот порядок держится на `join`. приоритет потока на него не влияет.
