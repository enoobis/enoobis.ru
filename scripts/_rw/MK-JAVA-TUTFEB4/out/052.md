начиная с java 16 в язык входят records (записи). окончательно они оформлены в jep 395, а в java 14 и java 15 существовали как preview. record представляет класс, состояние которого неизменяемо (immutable), а компоненты доступны внешнему коду для чтения. объявление record короче равносильного обычного класса: конструктор, методы доступа, `equals`, `hashCode` и `toString` порождает компилятор. по роли record является компактной формой контейнера неизменяемых данных.

для объявления применяется ключевое слово `record`. после имени в круглых скобках перечисляются компоненты:

```java
record название (поле1, поле2,...полеN){
	// тело record
}
```

ниже тот же набор данных сначала записан обычным классом.

```java

import java.util.Objects;

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom", 36);
        System.out.println(tom.toString());
    }
}

class Person {
    private final String name;
    private final int age;

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    String name() { return name; }
    int age() { return age; }

    public boolean equals(Object o) {
        if (!(o instanceof Person)) return false;
        Person other = (Person) o;
        return other.name == name && other.age == age;
    }

    public int hashCode() {
        return Objects.hash(name, age);
    }

    public String toString() {
        return String.format("Person[name=%s, age=%d]", name, age);
    }
}
```

класс `Person` хранит две константы, `name` и `age`:

```java

private final String name;
private final int age;
```

значения задаются в конструкторе. другого присваивания этим полям нет: модификатор `final` запрещает запись после инициализации. после создания объекта `Person` имя и возраст не меняются.

для чтения предусмотрены одноименные методы:

```java

String name() { return name; }
int age() { return age; }
```

дополнительно переопределены методы `equals()`, `hashCode()` и `toString()`, унаследованные от `Object`. `equals` проверяет тип оператором `instanceof`, приводит аргумент к `Person` и сравнивает компоненты. `hashCode` строится через `Objects.hash`. `toString` собирает строку формата `Person[name=%s, age=%d]`.

в `main` создается один объект `Person`, и на консоль выводится его текстовое представление:

```java

Person tom = new Person("Tom", 36);
 System.out.println(tom.toString());
```

консоль выводит:

```bash
Person[name=Tom, age=36]
```

тот же тип, записанный как record, занимает объявление без тела:

```java

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom", 36);
        System.out.println(tom.toString());
    }
}
record Person(String name, int age) { }
```

запись начинается с ключевого слова `record`, затем следует имя и список компонентов. здесь компоненты `name` и `age`. компилятор объявляет их `private final`.

одновременно создается канонический конструктор с параметрами `name` и `age`. для каждого компонента создается открытый метод доступа с тем же именем. для поля `name` это метод `name()`, возвращающий значение компонента. имена методов доступа совпадают с именами компонентов и не следуют схеме java beans вида `getName`: так задан контракт record.

автоматически создаются и методы `equals`, `hashCode` и `toString`. полученный record по набору членов соответствует классу выше, а исходный текст короче. есть расхождение в равенстве. рукописный `equals` сравнивает `name` оператором `==`, то есть по ссылке. метод, порожденный для record, сравнивает ссылочные компоненты через `Objects.equals`, а примитивные компоненты через `==`. два record с одинаковым содержимым строк `name` равны и тогда, когда это разные объекты `String`.

имеющиеся методы можно вызывать явно:

```java

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom",  36);
		
        System.out.println(tom.name());		// Tom
        System.out.println(tom.age());		// 36
        System.out.println(tom.hashCode());
		
		Person bob = new Person("Bob", 21);
		Person tomas = new Person("Tom", 36);
		System.out.println(tom.equals(bob));	// false
		System.out.println(tom.equals(tomas));	// true
    }
}
record Person(String name, int age){ }
```

`name()` возвращает `Tom`, `age()` возвращает `36`. `hashCode()` дает целое, вычисленное по компонентам. `equals` для `tom` и `bob` возвращает `false`, потому что различается имя. `equals` для `tom` и `tomas` возвращает `true`: оба компонента совпадают, хотя это два разных объекта.

### конструктор record

в примере выше применялась форма без тела:

```java

record Person(String name, int age) { }
```

она порождает конструктор:

```java

Person(String name, int age) { 
	this.name = name;
	this.age = age;
}
```

этот конструктор называется каноническим. его параметры называются так же, как компоненты record, и значения параметров записываются в соответствующие поля. других действий у порожденного конструктора нет.

логику инициализации можно изменить. если при создании передан возраст вне допустимого диапазона, компактный конструктор подставляет значение по умолчанию:

```java

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom", -116);
        System.out.println(tom.toString());
    }
}
record Person(String name, int age) { 

	Person{
		
		if(age<1 || age > 110){
			age = 18;
		}
	}
}
```

если переданное значение меньше 1 или больше 110, параметру `age` присваивается 18. в примере в конструктор передается `-116`, поэтому в объект попадает 18. компактный конструктор записывается без списка параметров: параметры канонического конструктора доступны в теле неявно, под теми же именами. присваивать компоненты через `this` в компактном конструкторе нельзя, меняются только параметры. по завершении тела компилятор сам выполняет присваивания полей из уже, возможно, измененных параметров. фактически получается конструктор:

```java

Person(String name, int age) { 
	if(age<1 || age > 110){
		age = 18;
	}
	this.name = name;
	this.age = age;
}
```

присваивания `this.name` и `this.age` дописываются после пользовательской проверки. программа выводит:

```bash
Person[name=Tom, age=18]
```

канонический конструктор можно переопределить полностью, уже с явным списком параметров и явными присваиваниями полей:

```java

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom",  36);
        System.out.println(tom.toString());
        System.out.println(tom.name());
    }
}
record Person(String name, int age) { 

	Person(String name, int age){
		
		if(age < 0 || age > 120) age = 18;
		
		this.name = name;
		this.age = age;
	}
}
```

в этой форме проверка диапазона и запись в `this.name` и `this.age` находятся в теле конструктора. неявных присваиваний компилятор не добавляет: раз конструктор написан целиком, инициализировать обязан он сам, и каждый компонент должен получить значение на всех путях выполнения. диапазон здесь немного другой, чем в компактной форме: недопустимым считается возраст меньше 0 или больше 120, и тогда тоже подставляется 18.

допустимы и другие конструкторы. каждый из них обязан вызвать канонический конструктор через `this(...)`. присвоить компоненты напрямую в таком конструкторе нельзя: состояние record инициализирует только канонический конструктор, альтернативный лишь готовит для него аргументы.

```java

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom", "Smith",  36);
        System.out.println(tom.toString());
    }
}
record Person(String name, int age) { 

	Person(String firstName, String lastName, int age){
		
		this(firstName + " " + lastName, age);
		
	}
}
```

этот конструктор принимает имя, фамилию и возраст. он вызывает канонический конструктор и передает ему значения компонентов `name` и `age` выражением `this(firstName + " " + lastName, age)`. имя и фамилия склеиваются в одну строку через пробел.

консольный вывод программы:

```bash
Person[name=Tom Smith, age=36]
```

в `name` оказывается строка `Tom Smith`, в `age` число 36. отдельного компонента для фамилии у record нет: фамилия существует только как часть аргумента канонического конструктора.

### переопределение методов

методы, которые record получает по умолчанию, можно переопределить. это `equals()`, `hashCode()`, `toString()` и методы доступа. методы доступа называются так же, как компоненты, и возвращают значения этих компонентов.

для записи `Person` ниже переопределены `toString()` и `name()`:

```java

public class Program{ 
      
    public static void main (String args[]){
          
		Person tom = new Person("Tom", 36);
        System.out.println(tom.toString());
        System.out.println(tom.name());
    }
}
record Person(String name, int age) { 

	public String name() { return "Mister " + name; }
	
    public String toString() {
        return String.format("Person %s, Age: %d", name, age);
    }
}
```

консольный вывод программы:

```bash

Person Tom, Age: 36
Mister Tom
```

`toString()` больше не использует порожденный формат `Person[name=..., age=...]` и собирает строку `Person Tom, Age: 36`. переопределенный `name()` возвращает строку с префиксом `Mister`. явный аксессор заменяет порожденный. контракт неизменяемости при этом сохраняется: метода, который записывал бы новое имя или новый возраст, у record по-прежнему нет. внутри `toString()` имя читается напрямую из компонента, поэтому префикс из переопределенного `name()` в эту строку не попадает.

### ограничения records

record нельзя объявить наследником другого класса. у записи фиксированный базовый класс `java.lang.Record`, и второй суперкласс в java невозможен. обычный класс нельзя наследовать от record: record неявно объявлен как `final`. реализовать интерфейсы record может. абстрактным record быть не может, потому что абстрактный класс рассчитан на наследование, а наследовать record запрещено.

явно объявлять нестатические поля и инициализаторы экземпляра в record нельзя. состояние исчерпывается компонентами заголовка, дополнительное поле экземпляра нарушило бы этот контракт. статические поля, статические инициализаторы, статические и нестатические методы допустимы.

```java

record Person(String name, int age){ 

	static int minAge;
	static{
        minAge = 18;
        System.out.println("Static initializer");
    }
}
```

статическое поле `minAge` и статический инициализатор относятся к классу, а не к экземпляру. инициализатор выполняется один раз при инициализации класса, записывает в `minAge` значение 18 и печатает `Static initializer`. экземпляры `Person` этого поля не копируют: оно одно на весь класс.
