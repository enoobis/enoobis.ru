**прокси** (`proxy`) в языке java нужен тогда, когда объект должен иметь тип одного или нескольких интерфейсов, а реализация методов не задаётся исходным текстом класса. механизм собран в классе `java.lang.reflect.Proxy`. обращаются к нему нечасто: обычная область, системное программирование, в том числе инфраструктура плагинов. во время выполнения прокси порождает новый класс, который реализует заданный набор интерфейсов, хотя этого класса нет в исходниках программы. такой класс направляет вызовы методов на удалённые серверы, связывает события пользовательского интерфейса с действиями и протоколирует вызовы при отладке. с точки зрения системы типов экземпляр прокси является подтипом каждого переданного интерфейса, поэтому ссылку на него можно привести к любому из этих интерфейсов. сгенерированный класс финальный, расширяет `java.lang.reflect.Proxy`, и виртуальная машина переиспользует его для того же загрузчика и того же набора интерфейсов.

прокси-класс, как и любой класс java, наследует методы `Object`, в том числе `toString()`, `equals()` и `hashCode()`. помимо них в тип входят методы всех интерфейсов, переданных при создании. методы `equals`, `hashCode` и `toString` диспетчеризуются в обработчик вызовов наравне с методами интерфейсов. остальные открытые методы `Object` прокси-класс не переопределяет, и их семантика остаётся семантикой `Object`.

### обработчик вызовов (invocation handler)

отличие от обычной реализации интерфейса в том, что во время выполнения нельзя подставить отдельное тело для каждого метода интерфейса. вместо тел методов задаётся **обработчик вызовов** (invocation handler). обработчик является экземпляром произвольного класса, который реализует интерфейс `InvocationHandler`. у интерфейса один метод:

```java


Object invoke(Object proxy, Method method, Object[] args) throws Throwable
```

параметры метода:

- `proxy`: объект прокси-класса, на котором вызван метод. это сам прокси. целевой объект, если он нужен, обработчик хранит отдельно
- `method`: экземпляр `Method`, соответствующий вызванному методу интерфейса. по нему доступны имя, типы параметров и класс, в котором метод объявлен
- `args`: массив аргументов вызова либо `null`, если метод интерфейса не принимает аргументов. аргументы примитивных типов упаковываются в классы-обёртки: `int` приходит как `java.lang.Integer`, `boolean` как `java.lang.Boolean`

значение, которое вернёт `invoke`, становится результатом вызова на прокси и тем значением, которое видит вызывающий код. если метод интерфейса имеет тип `void`, обработчик возвращает `null`. если метод возвращает примитив, возврат обработчика распаковывается. возврат `null` для примитивного типа приводит к `NullPointerException` при распаковке. проверяемое исключение, не объявленное методом интерфейса, прокси оборачивает в `UndeclaredThrowableException`.

каждый вызов метода прокси передаёт управление в `invoke`. туда попадают объект `Method` и аргументы. отдельной реализации в таблице методов целевого класса прокси не выбирает: для методов интерфейсов точка входа одна, обработчик.

ниже обработчик, который протоколирует вызовы. цель примера: увидеть имя метода и аргументы до того, как вызов дойдёт до настоящего объекта:

```java


import java.lang.reflect.InvocationHandler;

import java.lang.reflect.Method;



class DebugHandler implements InvocationHandler{



   private Object target;



   DebugHandler(Object target){



      this.target = target;

   }



   public Object invoke(Object proxy, Method m, Object[] args) throws Throwable {



      // выводим имя аргумента

      System.out.print(target);

      // выводим имя метода

      System.out.print("." + m.getName() + "(");

      // выводим аргументы

      if (args != null) {



         for (int i = 0; i < args.length; i++){



            if (i != args.length - 1) System.out.print(", ");

            System.out.print(args[i]);

         }

      }

      System.out.println(")");



      // вызываем метод интерфейса

      return m.invoke(target, args);

   }

}
```

класс `DebugHandler` реализует `InvocationHandler`. через конструктор он получает объект, на котором следует вызвать метод интерфейса, и сохраняет его в поле `target`. метод `invoke` печатает данные вызова и затем выполняет сам метод, передавая в рефлексивный вызов цель и аргументы.

первая печать выводит строковое представление `target`. у класса точки это результат `toString`. комментарий в исходнике говорит про имя аргумента, на консоль при этом уходит сам объект цели. далее печатаются точка, имя метода из `m.getName()` и круглая скобка. цикл выводит аргументы. запятая печатается перед аргументом, если он не последний. при одном аргументе, как у `move`, запятая не появляется. закрывающая скобка завершает строку протокола.

строка `m.invoke(target, args)` выполняет метод рефлексией на цели. вызов того же метода на `proxy` снова вошёл бы в `invoke` и зациклил бы диспетчеризацию. возвращаемое значение рефлексивного вызова возвращается из обработчика и становится результатом исходного вызова на прокси.

### создание прокси-объекта

прокси-объект создаёт статический метод `Proxy.newProxyInstance()`:

```java


static Object newProxyInstance (ClassLoader loader, Class<?>[] interfaces, InvocationHandler h)
```

у метода три параметра:

- `loader`: загрузчик, который определяет прокси-класс. подходит системный загрузчик, его даёт `ClassLoader.getSystemClassLoader()`. загрузчик должен видеть все переданные интерфейсы: прокси-класс будет их реализовывать, и ссылки на них войдут в его байткод
- `interfaces`: массив интерфейсов, которые реализует прокси-класс. элементы массива обязаны быть интерфейсами. порядок входит в идентичность класса: тот же загрузчик и та же последовательность интерфейсов дают уже созданный класс, а не новый
- `h`: обработчик вызовов, через который идёт диспетчеризация методов

создание и использование прокси собраны в одной программе:

```java


import java.lang.reflect.InvocationHandler;

import java.lang.reflect.Method;

import java.lang.reflect.Proxy;



class Program{

     

	public static void main(String[] args) {

         

        Object start = new Point(10, 15);

        var handler = new DebugHandler(start);

        Movable proxy = (Movable) Proxy.newProxyInstance(ClassLoader.getSystemClassLoader(), new Class[] { Movable.class }, handler);



        proxy.move(25);

        proxy.move(15);

        proxy.move(10);

    }

}



class Point implements Movable{



    private int x;

    private int y;



    Point(int x, int y){



        this.x = x;

        this.y = y;

    }

    @Override

    public String toString(){ return "(" + x + ", " + y + ")";}



    public void move(int distance){



        System.out.printf("Перемещаем точку (%d, %d) на %d пикселей\n\n", x, y, distance);

        x += distance;

        y += distance;

    }

}



interface Movable{

    void move(int distance);

}



class DebugHandler implements InvocationHandler{



   private Object target;



   public DebugHandler(Object target){



      this.target = target;

   }



   public Object invoke(Object proxy, Method m, Object[] args) throws Throwable {



      // выводим имя аргумента

      System.out.print(target);

      // выводим имя метода

      System.out.print("." + m.getName() + "(");

      // выводим аргументы

      if (args != null) {



         for (int i = 0; i < args.length; i++){



            if (i != args.length - 1) System.out.print(", ");

            System.out.print(args[i]);

         }

      }

      System.out.println(")");



      // вызываем метод интерфейса

      return m.invoke(target, args);

   }

}
```

в программе объявлен интерфейс `Movable` с одним методом `move()`:

```java


interface Movable{

    void move(int distance);

}
```

параметр `move()` задаёт расстояние, на которое перемещается объект. единицы условные: реализация сама решает, как прибавить это число к своему состоянию.

класс `Point` задаёт точку на плоскости и реализует этот интерфейс:

```java


class Point implements Movable{



    private int x;

    private int y;



    Point(int x, int y){



        this.x = x;

        this.y = y;

    }

    @Override

    public String toString(){ return "(" + x + ", " + y + ")";}



    public void move(int distance){



        System.out.printf("Перемещаем точку (%d, %d) на %d пикселей\n\n", x, y, distance);

        x += distance;

        y += distance;

    }

}
```

в `move` расстояние `distance` прибавляется к полям `x` и `y`, перед изменением состояния печатается диагностическая строка с прежними координатами. `toString` возвращает координаты в виде `(x, y)`. этот текст затем попадает в протокол обработчика, потому что обработчик печатает цель.

в `main` прокси строится в три шага. сначала создаётся точка, на которой позже будет вызван `move`:

```java


Object start = new Point(10, 15);
```

затем создаётся обработчик, и ему передаётся целевой объект:

```java


var handler = new DebugHandler(start);
```

после этого создаётся сам прокси:

```java


Movable proxy = (Movable) Proxy.newProxyInstance(ClassLoader.getSystemClassLoader(), new Class[] { Movable.class }, handler);
```

статический тип `newProxyInstance` есть `Object`, потому что конкретный прокси-класс на этапе компиляции ещё не существует. приведение к `Movable` проверяется во время выполнения. оно успешно: сгенерированный класс реализует `Movable`, и прокси можно использовать там, где ожидается этот интерфейс. подстановка прокси вместо `Point` возможна из-за общего супертипа `Movable`. экземпляром `Point` такой объект не является, поэтому `instanceof Point` для него ложен.

определяющим загрузчиком берётся системный, полученный из `ClassLoader.getSystemClassLoader()`.

второй аргумент: массив интерфейсов. здесь интерфейс один, `Movable`:

```java
new Class[] { Movable.class }
```

третий аргумент: обработчик `handler`. ссылка на него сохраняется в экземпляре прокси. все последующие вызовы интерфейсных методов этого экземпляра приходят в тот же объект.

полученный прокси имеет тип `Movable`, а обработчик перехватывает вызовы методов интерфейса. для демонстрации `move` вызывается трижды:

```java


proxy.move(25);

proxy.move(15);

proxy.move(10);
```

при каждом `proxy.move` виртуальная машина входит в `invoke`, передаёт вызванный метод и массив аргументов, обработчик печатает их и вызывает метод на объекте `Point`:

```java


m.invoke(target, args)
```

выражение

```java
proxy.move(25)
```

по наблюдаемому эффекту на состоянии точки совпадает с прямым вызовом

```java


start.move(25); // где start = new Point(10, 15)
```

разница в пути управления. прямой вызов сразу входит в `Point.move`. вызов через прокси сначала входит в `DebugHandler.invoke`, и только оттуда рефлексия доходит до `Point.move`. состояние меняет один и тот же экземпляр `start`: после первого сдвига координаты равны `(35, 40)`, после второго `(50, 55)`, третий вызов печатает уже эти координаты и сдвигает точку на 10. протокол печатает координаты до изменения, потому что `toString` цели вызывается в обработчике раньше, чем `m.invoke`.

консольный вывод:

```bash


(10, 15).move(25)

Перемещаем точку (10, 15) на 25 пикселей



(35, 40).move(15)

Перемещаем точку (35, 40) на 15 пикселей



(50, 55).move(10)

Перемещаем точку (50, 55) на 10 пикселей
```
