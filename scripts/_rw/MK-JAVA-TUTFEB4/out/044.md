один из распространённых способов применения интерфейсов в java: обратный вызов. обратный вызов устроен так, что одно действие регистрируют, а запускает его другое действие. одни действия вызываются из других. стандартный пример: нажатие кнопки. само нажатие есть одно действие, а в ответ на него запускаются другие. нажатие на значок принтера, например, запускает печать документа.

пример:

```java


public class EventsApp {



    public static void main(String[] args) {

        

        Button button = new Button(new ButtonClickHandler());

        button.click();

        button.click();

        button.click();

    }

}



class ButtonClickHandler implements EventHandler{

    

    public void execute(){

        

        System.out.println("Кнопка нажата!");

    }

}



interface EventHandler{

    

    void execute();

}



class Button{

    

    EventHandler handler;

    Button(EventHandler action){

        

        this.handler=action;

    }

    public void click(){

        

        handler.execute();

    }

}
```

класс `Button` в конструкторе принимает объект интерфейса `EventHandler`, а в методе `click` (имитация нажатия) вызывает метод `execute` этого объекта. кнопка зависит от контракта `EventHandler`. конкретную реакцию задаёт переданный объект. какое действие выполнится, решает этот объект. это инверсия управления: источник события не содержит прикладной код.

реализация `EventHandler` задана классом `ButtonClickHandler`. в основной программе объект этого класса передаётся в конструктор `Button`. через конструктор устанавливается обработчик нажатия. каждый вызов `button.click()` доходит до этого обработчика: `click` делегирует работу методу `execute`.

программа выводит на консоль следующий результат:

```consoletext


Кнопка нажата!

Кнопка нажата!

Кнопка нажата!
```

выносить действие в интерфейс и реализовывать его отдельно нужно потому, что в момент определения класса `Button` будущие действия ещё неизвестны. класс кнопки и класс основной программы могут лежать в разных пакетах и библиотеках и проектироваться разными разработчиками. кнопок, то есть объектов `Button`, может быть несколько, и каждому объекту нужно своё действие. если печатать текст прямо в `click`, все кнопки получат одну и ту же реакцию:

```java


class Button{

    

    public void click(){

        

        System.out.println("Кнопка нажата!");

    }

}
```

ниже главный класс задаёт две разные кнопки:

```java


public class EventsApp {



    public static void main(String[] args) {

        

        Button tvButton = new Button(new EventHandler(){

              

            private boolean on = false;

            public void execute(){

                

                if(on) {

                    System.out.println("Телевизор выключен..");

                    on=false;

                }   

                else {

                    System.out.println("Телевизор включен!");

                    on=true;

                }

            }

        });

        

        Button printButton = new Button(new EventHandler(){

              

            public void execute(){

                

                System.out.println("Запущена печать на принтере...");

            }

        });

        

        tvButton.click();

        printButton.click();

        tvButton.click();

    }

}
```

здесь две кнопки. одна включает и выключает телевизор, другая запускает печать на принтере. отдельные именованные классы, реализующие `EventHandler`, не создаются: обработчики заданы анонимными объектами, которые реализуют интерфейс `EventHandler`. обработчик кнопки телевизора хранит дополнительное состояние в поле `on` типа `boolean`. поле принадлежит экземпляру анонимного класса, поэтому значение сохраняется между вызовами `click` и переключается с `true` на `false` и обратно. локальная переменная метода `main` для такого переключения не годится: захваченную локальную переменную повторно присваивать нельзя. у интерфейса `EventHandler` один абстрактный метод, так что интерфейс функциональный. с java 8 реализацию без собственных полей можно записать лямбдой. обработчику телевизора нужно поле, поэтому в примере остаётся анонимный класс.

консоль выводит следующий результат:

```consoletext


Телевизор включен!

Запущена печать на принтере...

Телевизор выключен..
```

в этом качестве интерфейсы широко применяются в графических api: awt, swing, javafx. обработка событий элементов графического интерфейса там устроена тем же контрактом. компонент хранит ссылку на обработчик, а прикладной код подставляет реализацию.
