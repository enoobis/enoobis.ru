аннотация в java сама по себе действий не выполняет. чтобы она на что-то влияла, её нужно обработать. во время выполнения данные аннотации читаются рефлексией. в пакете `java.lang.reflect` для этого есть интерфейс `AnnotatedElement`. он объявляет операции доступа к аннотациям элемента программы:

```java


T getAnnotation(Class<T>)

T getDeclaredAnnotation(Class<T>)

T[] getAnnotationsByType(Class<T>)

T[] getDeclaredAnnotationsByType(Class<T>)    

Annotation[] getAnnotations()

Annotation[] getDeclaredAnnotations()

boolean isAnnotationPresent(Class<? extends Annotation> annotationClass)
```

у методов две независимые оси различия.

объявление и использование типа читаются разным api. аннотация объявления (declaration annotation) стоит на элементе: на классе, поле, методе. её отдают `getAnnotation`, `getDeclaredAnnotation`, `getAnnotations`, `getDeclaredAnnotations` и `isAnnotationPresent`. аннотация использования типа (type annotation) прикреплена к вхождению типа. к объявлению целиком она не относится. методы с суффиксом `ByType` её не возвращают: `getAnnotationsByType` и `getDeclaredAnnotationsByType` раскрывают повторяемые аннотации объявления, то есть собирают все аннотации одного типа на элементе, включая те, что лежат во вмещающей аннотации. вхождение типа читается отдельным зеркалом `java.lang.reflect.AnnotatedType`, через методы вроде `getAnnotatedSuperclass` и `getAnnotatedReturnType`.

вторая ось: наследование против аннотаций, записанных непосредственно на элементе. вариант с `Declared` в имени не поднимается по `@Inherited` к суперклассу. вариант без `Declared` для класса учитывает унаследованную аннотацию, если она сама помечена `@Inherited` и на классе не перекрыта. `isAnnotationPresent` отвечает на вопрос наличия и следует тем же правилам, что и `getAnnotation`: отсутствующая аннотация даёт `null` у `getAnnotation` и `false` у `isAnnotationPresent`.

`getAnnotations` и `getDeclaredAnnotations` возвращают все аннотации элемента массивом объектов `Annotation`. `Annotation` является интерфейсом. среди его методов выделяется `annotationType()`: он возвращает класс конкретной аннотации, то есть объект `Class` её интерфейса.

```java


Class<? extends Annotation> annotationType()
```

интерфейс `AnnotatedElement` реализуют `Class`, `Field`, `Parameter`, `Method`, `Constructor` и `Package`. получив рефлексией компонент программы, у него читают аннотации тем же набором методов. небольшой пример читает аннотацию класса. сначала берётся экземпляр класса, на котором аннотация стоит:

```java


import java.lang.annotation.ElementType;

import java.lang.annotation.Retention;

import java.lang.annotation.RetentionPolicy;

import java.lang.annotation.Target;



@Retention(RetentionPolicy.RUNTIME)     // Аннотация доступна во время выполнения

@Target(ElementType.TYPE)             // Аннотация применяется к типам

@interface MyAnnotation {



    String value();

}



// применяем аннотацию

@MyAnnotation(value="Thing")

class Thing{

    String name;

}



class Program{

 

    public static void main(String[] args) throws Exception{

          

        var obj = new Thing();

        var cl = obj.getClass();

        // получаем аннотацию MyAnnotation

        MyAnnotation annot = cl.getAnnotation(MyAnnotation.class);

        System.out.println(annot);  // @MyAnnotation("Thing")



        if (annot != null){



            System.out.println(annot.value());  // Thing

        }

    }

}
```

переменная объекта, к которому относится аннотация:

```java
var obj = new Thing();
```

класс этой переменной:

```java
var cl = obj.getClass();
```

дальше читается `MyAnnotation`. в метод передаётся объект класса аннотации, здесь `MyAnnotation.class`. результат является прокси, реализующим интерфейс `MyAnnotation`. у прокси вызываются элементы аннотации как методы:

```java
MyAnnotation annot = cl.getAnnotation(MyAnnotation.class);
```

если такой аннотации у класса нет, `getAnnotation` возвращает `null`. перед вызовом элементов ссылку проверяют:

```java


if (annot != null){



    System.out.println(annot.value());  // Thing

}
```

`getAnnotation` возвращает один объект аннотации данного типа. когда на типе или на его элементе несколько разных аннотаций и нужны все, вызывают `getAnnotations`. метод возвращает массив `Annotation`:

```java


import java.lang.annotation.ElementType;

import java.lang.annotation.Retention;

import java.lang.annotation.RetentionPolicy;

import java.lang.annotation.Target;

import java.lang.annotation.Annotation;



@Retention(RetentionPolicy.RUNTIME) 

@Target({ElementType.TYPE, ElementType.FIELD, ElementType.METHOD}) 

@interface Description {



    String data();

}



@Retention(RetentionPolicy.RUNTIME) 

@Target({ElementType.TYPE, ElementType.FIELD, ElementType.METHOD}) 

@interface Name {



    String value();

}



@Name(value="Thing")

@Description(data="Represents some object with a name")

class Thing{

    String name;

}



class Program{

 

    public static void main(String[] args) throws Exception{

          

        var obj = new Thing();

        var cl = obj.getClass();



        // получаем все аннотации

        Annotation[] annotations = cl.getAnnotations();

        for(var annot: annotations){



             System.out.println(annot);

            // получаем конкретный тип аннотации

            System.out.println(annot.annotationType());





        }

    }

}
```

на классе `Thing` стоят две аннотации, `@Name` и `@Description`. цикл печатает сам объект аннотации, его строковая форма похожа на литерал в исходнике, и затем класс, который вернул `annotationType()`. консольный вывод:

```bash


@Name("Thing")

interface Name

@Description(data="Represents some object with a name")

interface Description
```

сначала идёт `@Name("Thing")` и интерфейс `Name`, затем `@Description(...)` и интерфейс `Description`. порядок в этом прогоне совпадает с порядком литералов на классе.

#### практический пример

более прикладной пример собирает из тех же операций проверку объекта. программа задаёт правила для полей декларативно, аннотацией, и во время выполнения проверяет, укладываются ли значения живого экземпляра в эти правила. правило кодирует аннотация `@Range`. у неё два элемента, `min` и `max`: они хранят допустимый диапазон целочисленного поля.

```java


import java.lang.annotation.ElementType;

import java.lang.annotation.Retention;

import java.lang.annotation.RetentionPolicy;

import java.lang.annotation.Target;

import java.lang.reflect.Field;





@Retention(RetentionPolicy.RUNTIME) 

@Target(ElementType.FIELD) 

@interface Range {



    int min();

    int max();

}





class Person{



    String name;



    @Range(min=1, max=110)

    int age;



    Person(String name, int age){

        this.name = name;

        this.age = age;

    }



    String getName(){ return name; }

    int getAge(){ return age; }

}





class RangeValidator{



    public static boolean validate(Object obj) throws Exception{

        // Получаем класс объекта 

        var cl = obj.getClass();



        // Проверяем аннотации на уровне полей

        for (Field field : cl.getDeclaredFields()) {

            // если к полю применяется аннотация Range

            if (field.isAnnotationPresent(Range.class) && field.getType()==int.class) {

                // получаем аннотацию

                Range range = field.getAnnotation(Range.class);

                // делаем поле доступным для получения его значения

                field.setAccessible(true);

                // получаем значение поля

                int age = (int)field.get(obj);

                // проверяем значение поля

                if(age > range.max() || age < range.min()) return false;

            }

        }



        return true;

    }

}



class Program{

 

    public static void main(String[] args) throws Exception{

          

        Person tom = new Person("Tom", 41);

        validatePerson(tom);                // Person Tom is valid



        Person bob = new Person("Bob", 141);

        validatePerson(bob);                // Person Bob is invalid!!!

    }

    static void validatePerson(Person p) throws Exception {



        if(RangeValidator.validate(p)) System.out.printf("Person %s is valid\n", p.getName());

        else System.out.printf("Person %s is invalid!!!\n", p.getName());

    }

}
```

объявление аннотации отдельно:

```java


@Retention(RetentionPolicy.RUNTIME) 

@Target(ElementType.FIELD) 

@interface Range {



    int min();

    int max();

}
```

хранение `runtime` нужно потому, что `RangeValidator` читает аннотацию рефлексией уже после запуска. цель `field` ограничивает аннотацию полями: на метод или на класс её поставить нельзя, и валидатор ищет её только среди полей.

- у класса `Person` поле `age` помечено этой аннотацией. правило означает, что допустимый возраст `Person` лежит в диапазоне от 1 до 110 включительно: условие в валидаторе строгое, равенство границам проходит.

```java


class Person{



    String name;



    @Range(min=1, max=110)

    int age;

    ......................

}
```

- класс `RangeValidator` проверяет произвольный объект. метод `validate` принимает `obj` и возвращает `true`, если объект укладывается в правила, и `false`, если нет. рефлексия получает описание класса переданного объекта, для экземпляра `Person` это класс `Person`. `getDeclaredFields` возвращает поля, объявленные в этом классе, без полей суперкласса. цикл `for (Field field : cl.getDeclaredFields())` перебирает их. наличие `@Range` проверяет `isAnnotationPresent(Range.class)`. дополнительное сравнение `field.getType()==int.class` отбирает только примитив `int`: поле типа `Integer` в эту ветку не попадёт, потому что его `Class` другой. если аннотация найдена, читается она сама и её элементы, в примере это `min=1` и `max=110`:

`Range range = field.getAnnotation(Range.class);`

`setAccessible(true)` снимает языковую проверку доступа, в том числе если бы поле было `private`. в примере у `age` доступ пакета, вызов всё равно оставлен, чтобы то же правило работало для закрытого поля:

`field.setAccessible(true);`

значение поля читается рефлексией из конкретного объекта. `Field.get` возвращает `Object`, примитив приходит упакованным, приведение к `int` его распаковывает:

`int age = (int)field.get(obj);`

дальше значение сравнивается с границами из аннотации. выход за диапазон сразу даёт `false`, объект считается невалидным, остальные поля уже не смотрятся:

`if(age > range.max() || age < range.min()) return false;`

если ни одно размеченное поле не нарушило границы, метод возвращает `true`, и объект считается валидным. отсутствие аннотации `@Range` на поле ошибкой не является: такое поле цикл пропускает. сигнатура бросает `Exception`, потому что доступ к полю и снятие проверки доступа объявляют проверяемые исключения.

```java


public static boolean validate(Object obj) throws Exception{

        // Получаем класс объекта 

        var cl = obj.getClass();



        // Проверяем аннотации на уровне полей

        for (Field field : cl.getDeclaredFields()) {

            // если к полю применяется аннотация Range

            if (field.isAnnotationPresent(Range.class) && field.getType()==int.class) {

                // получаем аннотацию

                Range range = field.getAnnotation(Range.class);

                // делаем поле доступным для получения его значения

                field.setAccessible(true);

                // получаем значение поля

                int age = (int)field.get(obj);

                // проверяем значение поля

                if(age > range.max() || age < range.min()) return false;

            }

        }



        return true;

    }
```

- в классе `Program` для краткости проверки введён вспомогательный метод `validatePerson`. он вызывается для двух типовых объектов: `Tom` с возрастом 41 и `Bob` с возрастом 141.

консольный вывод программы:

```bash


Person Tom is valid

Person Bob is invalid!!!
```

`Tom` попадает в диапазон 1..110, `Bob` выходит за верхнюю границу, и валидатор возвращает `false` на поле `age`.
