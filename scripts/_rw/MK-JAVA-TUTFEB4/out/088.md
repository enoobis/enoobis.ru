помимо общего доступа к файлам java умеет читать и писать zip-архивы. в пакете `java.util.zip` для этого есть два класса, `ZipInputStream` и `ZipOutputStream`. оба работают поверх обычного байтового потока: архив для них это последовательность записей, а не отдельная файловая система.

### `ZipOutputStream`. запись архивов

архив создаёт `ZipOutputStream`. в конструктор передаётся поток вывода, куда лягут байты архива:

```java
ZipOutputStream(OutputStream out)
```

для каждого файла в архиве создаётся `ZipEntry`. конструктор записи принимает имя, под которым файл ляжет в архив. имя это путь внутри архива, оно не обязано совпадать с путём на диске. `putNextEntry()` делает эту запись текущей: следующие `write` пишут уже тело файла, а не заголовок следующей записи.

сжатие по умолчанию это метод deflate. запись можно пометить как хранимую без сжатия, но в примере оставлен режим по умолчанию.

сборка архива:

```java
import java.io.*;
import java.util.zip.*;
 
public class Program {
 
    public static void main(String[] args) {
        
        String filename = "notes.txt";
        try(ZipOutputStream zout = new ZipOutputStream(new FileOutputStream("output.zip"));
                FileInputStream fis= new FileInputStream(filename);)
        {
            ZipEntry entry1=new ZipEntry("notes.txt");
            zout.putNextEntry(entry1);
            // считываем содержимое файла в массив byte
            byte[] buffer = new byte[fis.available()];
            fis.read(buffer);
            // добавляем содержимое к архиву
            zout.write(buffer);
            // закрываем текущую запись для новой записи
            zout.closeEntry();
        }
        catch(Exception ex){
             
            System.out.println(ex.getMessage());
        } 
    } 
}
```

`ZipOutputStream` пишет в `output.zip`, `FileInputStream` читает `notes.txt`. объект `ZipEntry` создаётся с именем `notes.txt`, `putNextEntry` открывает эту запись. содержимое файла читается в массив `byte`: размер массива берётся из `fis.available()`, для ещё не читавшегося файлового потока это оставшиеся байты файла. `read` заполняет массив, `write` дописывает его к архиву.

после тела текущую запись закрывают методом `closeEntry()`. после этого в тот же архив можно положить следующий файл, повторив цикл: новый `ZipEntry`, `putNextEntry`, байты тела, `closeEntry`. если `closeEntry` не вызван, следующий `putNextEntry` закрывает предыдущую запись сам. try-with-resources в конце закрывает оба потока. `close()` у `ZipOutputStream` дописывает завершение архива, в том числе центральный каталог.

### чтение архивов. `ZipInputStream`

архив читает `ZipInputStream`. конструктор принимает поток, указывающий на zip:

```java
ZipInputStream(InputStream in)
```

записи достаются методом `getNextEntry()`. он возвращает `ZipEntry` очередной записи либо `null`, когда записей больше нет. `ZipEntry` это одна позиция в архиве: имя, метод сжатия, размеры. обход архива:

```java
import java.io.*;
import java.util.zip.*;
 
public class Program {
 
    public static void main(String[] args) {
        
        try(ZipInputStream zin = new ZipInputStream(new FileInputStream("output.zip")))
        {
            ZipEntry entry;
            String name;
            while((entry=zin.getNextEntry())!=null){
                 
                name = entry.getName(); // получим название файла
                System.out.printf("File name: %s \n", name);
				
				// распаковка
				FileOutputStream fout = new FileOutputStream("new" + name);
				for (int c = zin.read(); c != -1; c = zin.read()) {
					fout.write(c);
				}
				fout.flush();
				zin.closeEntry();
				fout.close();
            }
        }
        catch(Exception ex){
             
            System.out.println(ex.getMessage());
        } 
    } 
}
```

конструктор получает поток ввода на `output.zip`. цикл вызывает `getNextEntry`, пока тот не вернёт `null`. имя записи даёт `getName()`, и фрагмент печатает его. размер несжатых данных записи, в байтах, лежит в `getSize()`. если размер в заголовке неизвестен, метод возвращает `-1`. в показанном `printf` на консоль уходит имя.

затем байты записи читаются из того же `ZipInputStream`: после `getNextEntry` поток отдаёт уже распакованное тело, а не сырой deflate. цикл `read` забирает байты по одному, пока не получит `-1` в конце тела, и пишет их в новый файл. имя нового файла это `new`, склеенное с именем из архива, путь относительный, поэтому файл появляется в рабочем каталоге. `flush` сбрасывает буфер, `closeEntry` завершает текущую запись, `close` закрывает `FileOutputStream`. выходной файл создан вручную, не в заголовке try-with-resources, поэтому его закрывают явно на каждой итерации. следующая запись снова начинается с `getNextEntry`.
