одна функция c может принимать параметром другую функцию и вызывать её по ходу своей работы. принятую функцию называют функцией обратного вызова. в стандартной библиотеке c так устроена быстрая сортировка `qsort`:

```java


void qsort(void *base, size_t nmemb, size_t size, int (*compare)(const void *, const void *));
```

при вызове этой функции ей передают:

- `base` : массив сортируемых элементов, указатель на первый байт области

- `nmemb` : длина массива, число элементов

- `size` : размер каждого элемента в байтах

- `compar` : адрес функции обратного вызова, которая сравнивает два элемента

последний параметр является указателем на функцию. `qsort` вызывает её, когда сравнивает два элемента. от функции ждут соглашение c: отрицательное значение, если первый элемент меньше второго, нуль, если элементы равны, положительное значение, если первый больше. с точки зрения foreign function and memory api указатель на функцию передаётся значением `ValueLayout.ADDRESS`, как и любой другой указатель. саму функцию задают статическим методом java, а адрес для c получают как нативную заглушку. полная программа:

```java


import java.lang.foreign.*;

import java.lang.invoke.*;

import java.util.Arrays;

import static java.lang.foreign.ValueLayout.*;



public class Program {



    public static void main(String[] args) throws Throwable{



        // получаем линкер/компоновщик 

        Linker linker = Linker.nativeLinker();

        // получаем стандартную библиотеку

        SymbolLookup stdlib = linker.defaultLookup();



        // получаем адрес функции sqort

        MemorySegment qsortAddr = stdlib.findOrThrow("qsort");

        // определяем дескриптор функции

        FunctionDescriptor qsortDesc = FunctionDescriptor.ofVoid(ADDRESS, JAVA_LONG, JAVA_LONG, ADDRESS);

        // void qsort(void*, size_t, size_t, int (*)(const void *, const void *))

        MethodHandle qsort = linker.downcallHandle(qsortAddr, qsortDesc);



        // получаем тип метода

        MethodType compareType = MethodType.methodType(int.class, MemorySegment.class, MemorySegment.class);

        // получаем дескриптор статического метода

        MethodHandle compareHandle = MethodHandles.lookup().findStatic(Program.class, "compareInt", compareType);



        // определяем заглушку для функции

        MemorySegment compareStub = linker.upcallStub(

            compareHandle,

            FunctionDescriptor.of(JAVA_INT,

                ADDRESS.withTargetLayout(JAVA_INT),

                ADDRESS.withTargetLayout(JAVA_INT)),

            Arena.ofAuto());



        // данные для сортировки 

        int[] numbers = {3, 5, 1, 8, 0, 5, 2};



        try (Arena arena = Arena.ofConfined()) {



            // определяем для чисел numbers сегмент памяти

            MemorySegment numbers_seg = arena.allocateFrom(JAVA_INT, numbers);

            qsort.invoke(numbers_seg, numbers.length, JAVA_INT.byteSize(), compareStub);



            // преобразуем сегмент памяти в массив

            numbers = numbers_seg.toArray(JAVA_INT);

            System.out.println(Arrays.toString(numbers));   // [0, 1, 2, 3, 5, 5, 8]

        }

    }



    static int compareInt(MemorySegment a, MemorySegment b) {



        return Integer.compare(a.get(JAVA_INT, 0), b.get(JAVA_INT, 0));

    }

}
```

разбор программы по шагам:

- сравнивать элементы для `qsort` будет следующий метод java. метод предназначен для сортировки целочисленных значений типа `int`. параметры имеют тип `MemorySegment`: из c в обратный вызов приходят указатели, а значение `int` лежит в памяти по этим указателям. `Integer.compare` возвращает отрицательное число, нуль или положительное число и тем выполняет контракт сравнения `qsort`

```java


static int compareInt(MemorySegment a, MemorySegment b) {



    return Integer.compare(a.get(JAVA_INT, 0), b.get(JAVA_INT, 0));

}
```

- дескриптор метода внешней функции получают в том же порядке, что и для обычного downcall. берут линкер платформы, поиск стандартной библиотеки, адрес `qsort` и сигнатуру, затем связывают их через `downcallHandle`. в комментарии фрагмента сигнатура записана как `void qsort(void*, size_t, size_t, int (*)(const void *, const void *))`. в полной программе возвращаемый тип `void` задан через `FunctionDescriptor.ofVoid` с четырьмя аргументами: `ADDRESS`, `JAVA_LONG`, `JAVA_LONG`, `ADDRESS`. фрагмент ниже собирает дескриптор методом `FunctionDescriptor.of` и перечисляет те же четыре компоновки, ставя `ADDRESS` на место результата

```java


// получаем линкер/компоновщик 

Linker linker = Linker.nativeLinker();

// получаем стандартную библиотеку

SymbolLookup stdlib = linker.defaultLookup();



// получаем адрес функции sqort

MemorySegment qsortAddr = stdlib.findOrThrow("qsort");

// определяем дескриптор функции

FunctionDescriptor qsortDesc = FunctionDescriptor.of(ADDRESS, JAVA_LONG, JAVA_LONG, ADDRESS);

// void qsort(void*, size_t, size_t, int (*)(const void *, const void *))

MethodHandle qsort = linker.downcallHandle(qsortAddr, qsortDesc);
```

- чтобы получить адрес метода java, сначала строят объект `MethodHandle` для статического метода. `MethodType.methodType` принимает тип возвращаемого значения и далее типы параметров. метод сортировки `compareInt` возвращает `int` и принимает два значения `MemorySegment`. `MethodHandles.lookup().findStatic` ищет метод по классу, имени и этому типу. `Program` здесь текущий класс, в котором метод расположен

```java


// получаем тип метода

MethodType compareType = MethodType.methodType(int.class, MemorySegment.class, MemorySegment.class);



// получаем дескриптор статического метода (Program - текущий класс, где располагается метод)

MethodHandle compareHandle = MethodHandles.lookup().findStatic(Program.class, "compareInt", compareType);
```

- метод `upcallStub()` линкера строит заглушку функции c. заглушка является нативной точкой входа, а её вызов выполняет переданный дескриптор метода обратного вызова. полученный указатель передают другим внешним функциям как указатель на функцию. вызов такого указателя из внешнего кода приводит к выполнению дескриптора. у `upcallStub()` до 4 параметров. параметр `target` является дескриптором целевого метода. в примере опции линкера опущены, поэтому вызов передаёт три аргумента: дескриптор метода, дескриптор заглушки и арену

```java


MemorySegment compareStub = linker.upcallStub(

    compareHandle,

    FunctionDescriptor.of(JAVA_INT,

        ADDRESS.withTargetLayout(JAVA_INT),

        ADDRESS.withTargetLayout(JAVA_INT)),

    Arena.ofAuto());
```

объявление метода:

```java


MemorySegment upcallStub(MethodHandle target,

 FunctionDescriptor function,

 Arena arena,

 Linker.Option... options)
```

- `function` : дескриптор функции-заглушки вызываемой функции. это сигнатура, которую видит нативный код при вызове указателя

- `arena` : арена, связанная с возвращаемым сегментом-заглушкой. сегмент заглушки действителен, пока жива арена

- `options` : параметры линкера, связанные с этим запросом на связывание

вызовы `withTargetLayout()` настраивают компоновку памяти указателя, чтобы линкер собрал экземпляры `MemorySegment`, которые получит обратный вызов java. у такого сегмента появляются размер и выравнивание целевой компоновки. для `JAVA_INT` размер равен 4 байтам, и чтение `int` по смещению 0 попадает внутрь сегмента. если эту настройку опустить, сегменты `a` и `b` приходят с нулевой длиной, и вызовы `a.get(JAVA_INT, 0)` и `b.get(JAVA_INT, 0)` в обратном вызове java завершаются ошибкой: проверка границ не пропускает чтение при нулевом размере. арена заглушки в программе создана через `Arena.ofAuto()`. её забирает сборщик мусора, явного закрытия нет. вызов компаратора из `qsort` происходит синхронно внутри `invoke`, и на это время заглушка должна оставаться достижимой.

- в конце внешнюю функцию вызывают с адресом обратного вызова. фрагмент показывает вызов для массива `float`: в `invoke` уходят база, число элементов, размер одного элемента и указатель на заглушку сравнения

```java


float[] samples = . . .;

MemorySegment csamples = arena.allocateFrom(JAVA_FLOAT, samples);



qsort.invoke(csamples, samples.length, JAVA_FLOAT.byteSize(), compStub);
```

в полной программе на вход `qsort` передают массив `{3, 5, 1, 8, 0, 5, 2}`. сегмент чисел строится через `allocateFrom`, число элементов равно длине массива, размер элемента равен `JAVA_INT.byteSize()`. после возврата из `qsort` порядок байтов в сегменте уже соответствует сортировке, и `toArray` копирует его в массив java. консольный вывод отсортированного массива:

```bash
[0, 1, 2, 3, 5, 5, 8]
```
