механизм наследования повторно использует состояние и поведение, но ограничен одним суперклассом. класс наследует реализацию только от одного класса. в c++ доступно множественное наследование классов, в java его нет.

частично это ограничение снимают интерфейсы. интерфейс задаёт функционал без конкретной реализации. класс, который применяет интерфейс, эту реализацию даёт сам. один класс может применить несколько интерфейсов.

основной смысл интерфейса: набор требований, которым должен соответствовать класс. интерфейс определяет, **что** класс обязан делать. класс определяет, **как** он это делает.

### определение интерфейса

чтобы определить интерфейс, используется служебное слово `interface`:

```java


interface Movable{ }
```

интерфейс называется `Movable` и дальше представляет транспортное средство, нечто, что может перемещаться. по соглашениям java имя интерфейса начинается с большой буквы и обычно заканчивается суффиксом «-able». язык этого не требует. суффикс остаётся соглашением, компилятор его не проверяет.

### применение интерфейса

интерфейс задаёт набор требований к классу, а класс эти требования применяет. чтобы указать, что класс применяет, или реализует, интерфейс, после имени класса пишут служебное слово `implements`, а за ним имя интерфейса:

```java


interface Movable{ }

class Car implements Movable{ }
```

класс `Car` применяет, или реализует, интерфейс `Movable`. тем самым фиксируется, что машина (`Car`) есть транспортное средство: у неё должен появиться функционал перемещения.

### переменные интерфейса

интерфейс вводит новый тип. переменную этого типа объявляют так же, как переменную класса:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Movable obj;    // определяем интерфейс

    }

}

// определение интерфейса

interface Movable{ }
```

классом интерфейс не является. оператор `new` для создания экземпляра интерфейса неприменим: у интерфейса нет конструктора экземпляра и нет собственного состояния объекта.

```java


public class Program{

      

    public static void main(String[] args) {

        

        Movable obj = new Movable();        // ! Ошибка, так нельзя сделать

    }

}

interface Movable{ }
```

переменной интерфейса присваивают ссылку на объект класса, который этот интерфейс применяет:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Movable obj = new Car();

        System.out.println(obj);

    }

}



interface Movable{ }

class Car implements Movable{ }
```

поскольку класс `Car` применяет интерфейс `Movable`, переменной типа `Movable` присваивается объект `Car`. статический тип ссылки видит только контракт интерфейса, динамический тип остаётся `Car`.

объявленный выше интерфейс `Movable` пуст и ничего не определяет. пустой интерфейс работает как маркерный тип: методов нет, но тип уже можно использовать в объявлениях и в проверках. интерфейс может определять и ряд компонентов:

- методы без реализации

- методы по умолчанию (с реализацией)

- приватные методы

- статические методы (как приватные, так и публичные)

- константы

### определение методов в интерфейсе

интерфейс задаёт требования, или контракт, которому должен соответствовать класс. эти требования записываются методами. метод интерфейса может иметь реализацию, а может не иметь. если класс применяет интерфейс, он обязан реализовать все методы этого интерфейса. исключение: методы, для которых в интерфейсе уже задана реализация по умолчанию.

ниже в `Movable` добавлен метод:

```java


interface Movable{



    void move();

}
```

интерфейс `Movable` представляет функционал транспортного средства и определяет один метод без реализации, метод `move()`. условно он предназначен для передвижения. методы без реализации похожи на абстрактные методы абстрактных классов: сигнатура есть, тела нет. модификатор доступа в объявлении метода часто опущен. для метода интерфейса отсутствие модификатора означает `public`. цель интерфейса: определить функционал для реализации классом, поэтому этот функционал открыт для реализации. явный модификатор `public` допустим и смысла не меняет. более узкий доступ у метода контракта запрещён.

есть интерфейс `Movable`, который представляет транспортное средство без уточнения вида, и есть метод `move` для перемещения. как именно выполняется перемещение, интерфейсу неизвестно: это остаётся реализации класса.

класс, который применяет интерфейс, обязан реализовать все его методы без реализации. ниже реализация `Movable`:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Car car = new Car();

        car.move();     // Едем на машине

    }

}



interface Movable{



    void move();

}

// класс машины

class Car implements Movable{ 



    public void move(){



        System.out.println("Едем на машине");

    }

}
```

класс `Car` применяет интерфейс `Movable` и поэтому реализует метод `move()`. если класс не реализует какие-то методы интерфейса, его объявляют абстрактным. неабстрактные классы-наследники затем всё равно обязаны эти методы реализовать. правило то же, что для абстрактного метода абстрактного класса: экземпляр можно создать только у класса, где контракт закрыт полностью.

интерфейс `Movable` задаёт требование: реализовать метод перемещения `move`. класс `Car` принимает это требование и сам выбирает конкретную реализацию метода.

тем же способом интерфейс реализуют в серии классов. ниже добавлен класс самолёта:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Car car = new Car();

        car.move();     // Едем на машине



        Aircraft boing = new Aircraft();

        boing.move();   // Летим на самолете

    }

}



interface Movable{



    void move();

}

// класс машины

class Car implements Movable{ 



    public void move(){



        System.out.println("Едем на машине");

    }

}

class Aircraft implements Movable{ 



    public void move(){



        System.out.println("Летим на самолете");

    }

}
```

### методы по умолчанию

интерфейсы в java могут содержать методы по умолчанию (default methods): метод с реализацией, которая используется, если класс, реализующий интерфейс, сам этот метод не реализует.

методы по умолчанию нужны для эволюции уже опубликованного контракта. если интерфейс создан раньше и его уже реализовало множество классов, добавление нового метода без тела ломает все эти реализации: их пришлось бы менять вместе с интерфейсом. когда речь о паре классов в одном файле с интерфейсом, правка выглядит небольшой. когда интерфейс стандартной библиотеки java много лет реализуют разные разработчики, изменение контракта становится трудно устранимым: классы перестают компилироваться, потому что не реализуют новый метод.

при наличии метода по умолчанию класс по-прежнему загружается, даже если нового метода в нём нет. программа может создавать экземпляры таких классов: тело метода уже лежит в интерфейсе.

ниже к использованному ранее интерфейсу `Movable` добавлен новый метод, и этот метод объявлен методом по умолчанию:

```java


interface Movable{



    void move();

    default void stop() { 

        System.out.println("Останавливаемся"); 

    }

}
```

метод `stop()` определён как метод по умолчанию. это обычный метод без модификаторов доступа в тексте (формально у него модификатор `public`), помеченный служебным словом `default`. в примере `stop` выводит строку на консоль. тело может не делать ничего и состоять из пустых фигурных скобок: `default void stop() { }`.

в классе этот метод реализовывать необязательно. если своей версии нет, вызывается реализация интерфейса:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Car car = new Car();

        car.move();     // Едем на машине

        car.stop();     // Останавливаемся

    }

}



interface Movable{



    void move();

    default void stop() { 

        System.out.println("Останавливаемся"); 

    }

}

// класс машины

class Car implements Movable{ 



    public void move(){



        System.out.println("Едем на машине");

    }

}
```

метод по умолчанию можно и переопределить. тогда динамическая диспетчеризация выберет версию класса. реализация интерфейса при этом не вызывается:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Movable car = new Car();

        car.move();     // Едем на машине

        car.stop();     // Машина останавливается

    }

}



interface Movable{



    void move();

    default void stop() {  }

}

// класс машины

class Car implements Movable{ 



    public void move(){



        System.out.println("Едем на машине");

    }

    // переопределяем метод по умолчанию

    public void stop(){



        System.out.println("Машина останавливается");

    }

}
```

### статические методы

в интерфейсах определяют и статические методы. по роли они аналогичны статическим методам класса: принадлежат типу. для вызова экземпляр не нужен.

```java


interface Printable {

    

    void print();

	

    static void read(){

        

        System.out.println("Read printable");

    }

}
```

обращение к статическому методу интерфейса записывают так же, как к статическому методу класса: имя интерфейса и имя метода. вызов идёт через имя интерфейса. реализующий класс не наследует этот статический метод и не вызывает его через экземпляр.

```java


public static void main(String[] args) {

        

    Printable.read();

}
```

### приватные методы

по умолчанию методы интерфейса фактически имеют модификатор `public`. начиная с java 9 в интерфейсе можно объявлять методы с модификатором `private`. они бывают статическими и нестатическими. реализации по умолчанию, то есть модификатора `default`, у них нет: приватный метод не входит в контракт для классов и всегда имеет собственное тело. снаружи интерфейса реализовать или переопределить его нельзя, поэтому тела по умолчанию ему не требуется.

такие методы видны только внутри того интерфейса, где они определены. если в нескольких методах по умолчанию повторяется одна и та же работа, её выносят в приватный метод. в контракт класса этот метод не попадает.

```java


public class Program{

     

	public static void main(String[] args) {

         

		Operation c = new Operation(); 

		System.out.println(c.sum(1, 2));        // 3

		System.out.println(c.sum(1, 2, 4));     // 7

	}

}

class Operation implements Sumable{}



interface Sumable{



	default int sum(int a, int b){

		return sumAll(a, b);

	}

	default int sum(int a, int b, int c){

		return sumAll(a, b, c);

	}

	

    private int sumAll(int... values){

         int result = 0;

		 for(int n : values){

			 result += n;

		 }

		 return result;

    }

}
```

### константы в интерфейсах

кроме методов в интерфейсе определяют статические константы:

```java


interface Stateable{



	int OPEN = 1;

	int CLOSED = 0;

	

	void printState(int n);

}
```

у таких констант в тексте тоже может не быть модификаторов. по умолчанию они получают `public static final`. значение доступно из любого места программы, присвоить его заново нельзя. поле интерфейса неизменяемо и не хранит состояние экземпляра. у целочисленных констант из примера инициализатор является постоянным выражением, поэтому это константы времени компиляции.

применение констант:

```java


public class Program{

     

	public static void main(String[] args) {

         

		WaterPipe pipe = new WaterPipe();

		pipe.printState(1);

	}

}

class WaterPipe implements Stateable{

	

	public void printState(int n){

		if(n == OPEN)

			System.out.println("Water is opened");

		else if(n == CLOSED)

			System.out.println("Water is closed");

		else

			System.out.println("State is invalid");

	}

}

interface Stateable{



	int OPEN = 1;

	int CLOSED = 0;

	

	void printState(int n);

}
```

### вложенные интерфейсы

как и классы, интерфейсы бывают вложенными: их определяют внутри класса или внутри другого интерфейса. вложенный в класс интерфейс неявно статический, отдельного экземпляра внешнего класса ему не нужно.

```java


class Printer{

    interface Printable {

    

        void print();

    }

}
```

при применении такого интерфейса указывают полное имя вместе с именем класса:

```java


class Book implements Printer.Printable {



    public void print() {

        System.out.println("Печатаем книгу");

    }  

}
```

использование интерфейса дальше совпадает с предыдущими случаями: переменная имеет тип вложенного интерфейса, а ссылка указывает на объект класса, который этот интерфейс реализует.

```java


Printer.Printable printable = new Book();

printable.print();
```
