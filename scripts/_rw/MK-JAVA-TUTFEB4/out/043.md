в ряде языков доступно множественное наследование классов. в c++ один класс наследует сразу от нескольких базовых классов. в java множественное наследование классов недоступно: у класса один прямой суперкласс. при этом класс может применить сразу несколько интерфейсов. такую конструкцию называют множественной реализацией интерфейсов. поля и состояние по-прежнему приходят из одного суперкласса.

если классу нужно применить несколько интерфейсов, их перечисляют через запятую после служебного слова `implements`:

```java


public class Program{

      

    public static void main(String[] args) {

        

        TextFile file = new TextFile("content.txt", "Hello World");

        System.out.println("Печать файла " + file.getName());

        file.print();

    }

}



interface File{

    String getName();  // возвращает имя файла

}

interface Printable{

    void print();  // печать содержимого

}

class TextFile implements File, Printable{



    private String name;

    private String text;



    TextFile(String name, String text){



        this.name = name;

        this.text = text;

    }

    public String getName(){ return this.name; }

    public void print() { System.out.println(text); }

}
```

класс `TextFile` реализует два интерфейса, `File` и `Printable`, и поэтому обязан реализовать методы обоих. объект класса `TextFile` можно рассматривать и как объект `File`, и как объект `Printable`: у него два супертипа-интерфейса одновременно.

```java


public class Program{

      

    public static void main(String[] args) {

        

        TextFile file = new TextFile("content.txt", "Hello World");

        printFileName(file);

        printObj(file);

    }



    static void printFileName(File file){

        System.out.println("File name: " + file.getName());

    }



    static void printObj(Printable obj){

        obj.print();

    }

}
```

метод `printFileName` принимает объект интерфейса `File`. в метод передаётся объект любого класса, который этот интерфейс реализует. метод `printObj()` принимает объект интерфейса `Printable`. на его место передаётся объект класса `TextFile`, поскольку `TextFile` данный интерфейс реализует. статический тип параметра отсекает методы, которых в соответствующем контракте нет.

#### конфликты методов по умолчанию

один и тот же метод может быть методом по умолчанию в интерфейсе и одновременно конкретным методом суперкласса или методом другого интерфейса. правила такие:

- суперклассы имеют преимущество. если суперкласс предоставляет конкретный метод, методы по умолчанию с теми же именами и типами параметров игнорируются.

- конфликт интерфейсов. если интерфейс предоставляет метод по умолчанию, а другой интерфейс содержит метод с тем же именем и теми же типами параметров (с реализацией по умолчанию или без неё), конфликт нужно разрешить, переопределив этот метод.

первое правило следует из приоритета класса над интерфейсом: конкретный метод суперкласса перекрывает одноимённый метод по умолчанию, и класс-наследник получает версию суперкласса. ниже разобран второй случай, когда ни один суперкласс конфликт не снимает.

```java


public class Program{

      

    public static void main(String[] args) {

        

        EBook book = new EBook();

        book.print();

    }

}

// печать на принтере

interface Printable{

    default void print(){

        System.out.println("Печатаем на принтере");

    }

}

// работа с консолью

interface Console{

    default void print(){

        System.out.println("Выводим данные на консоль");

    }

}

class EBook implements Printable, Console{ }
```

класс `EBook` представляет электронную книгу. он реализует два интерфейса. `Printable` описывает печать на принтере методом `print`. `Console` описывает работу с консолью, в том числе вывод на консоль тем же методом `print`. оба интерфейса здесь уместны: книгу нужно и напечатать на принтере, и вывести её текст на консоль. поскольку в обоих интерфейсах объявлен метод с одним и тем же именем и той же сигнатурой, компиляция останавливается с ошибкой. интерфейсы не связаны наследованием, и компилятор не может выбрать одну из двух реализаций по умолчанию.

```bash


Program.java:20: error: types Printable and Console are incompatible;

class EBook implements Printable, Console{ }

^

  class EBook inherits unrelated defaults for print() from types Printable and Console

1 error
```

неоднозначность снимают двумя способами.

#### явное определение метода в классе

реализацию `print` можно задать прямо в классе `EBook`. этот метод перекрывает обе версии по умолчанию:

```java


class EBook implements Printable, Console{ 

    

    public void print(){

        System.out.println("Печатаем книгу");

    }

}
```

при любом взгляде на объект `EBook`, через тип `Printable` или через тип `Console`, вызывается одна и та же реализация `print` из класса. динамический тип один, поэтому выбор статического типа переменной метод класса не меняет.

```java


Console book = new EBook();

// или так 

// Printable book = new EBook();

book.print(); // Печатаем книгу
```

#### выбор реализации определённого интерфейса

вместо собственного тела можно явно выбрать реализацию одного из интерфейсов:

```java


public class Program{

      

    public static void main(String[] args) {

        

        Console book = new EBook();

        book.print();

    }

}

// печать на принтере

interface Printable{

    default void print(){

        System.out.println("Печатаем на принтере");

    }

}

// работа с консолью

interface Console{

    default void print(){

        System.out.println("Выводим данные на консоль");

    }

}

class EBook implements Printable, Console{ 

    

    public void print(){

        Printable.super.print();

    }

}
```

выражение `Printable.super.print()` в методе `print` класса `EBook` выбирает реализацию из интерфейса `Printable`. квалифицированный вызов `суперинтерфейс.super.метод` допустим в классе, который этот интерфейс реализует, и указывает конкретную ветвь контракта. вызов срабатывает при любом статическом типе переменной, в том числе если переменная имеет тип интерфейса `Console`.

```java


Console book = new EBook();

book.print();   // Печатаем на принтере
```

интерфейсы, как и классы, наследуются. интерфейс может расширить несколько интерфейсов сразу: для контрактов множественное наследование разрешено.

```java


interface Printable{

    void print();  // печать содержимого

}

interface File extends Printable{

    String getName();  // возвращает имя файла

}
```

интерфейс `File` наследует интерфейс `Printable`. класс, который реализует `File`, обязан реализовать и методы `File`, и методы базового интерфейса `Printable`. подтип интерфейса включает контракт супертипа целиком.

```java


public class Program{

      

    public static void main(String[] args) {

        

        TextFile file = new TextFile("content.txt", "Hello World");

        System.out.println("File name: " + file.getName());

        file.print();

    }

}



interface Printable{

    void print();  // печать содержимого

}

interface File extends Printable{

    String getName();  // возвращает имя файла

}

class TextFile implements File{



    private String name;

    private String text;



    TextFile(String name, String text){



        this.name = name;

        this.text = text;

    }

    public String getName(){ return this.name; }

    public void print() { System.out.println(text); }

}
```

консольный вывод:

```bash


File name: content.txt

Hello World
```
