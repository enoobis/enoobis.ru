когда поток может продолжить работу только после чужого результата, ему нужно извещение. для этого у класса `Object` есть три метода. все три вызываются из синхронизированного контекста, блока или метода: вызывающий поток уже владеет монитором данного объекта. вызов без владения завершается `IllegalMonitorStateException`.

- `wait()`: освобождает монитор и переводит вызывающий поток в ожидание, пока другой поток не вызовет на том же объекте `notify()` или `notifyAll()`. после пробуждения поток снова состязается за монитор и идёт дальше только захватив его

- `notify()`: возобновляет один поток, ранее вызвавший `wait()` на этом мониторе. какой из ожидающих будет выбран, спецификация оставляет реализации

- `notifyAll()`: возобновляет все потоки, ранее вызвавшие `wait()` на этом мониторе

ниже задача производитель-потребитель (producer-consumer). потребитель не забирает продукт, пока производитель его не положил. производитель создаёт 5 товаров, потребитель забирает все пять. одновременно на складе находится не больше 3 товаров. схема собрана на `wait()` и `notify()`:

```java


public class Program {

 

    public static void main(String[] args) {

         

        Store store=new Store();

        Producer producer = new Producer(store);

        Consumer consumer = new Consumer(store);

        new Thread(producer).start();

        new Thread(consumer).start();

    }

}

// Класс Магазин, хранящий произведенные товары

class Store{

   private int product=0;

   public synchronized void get() {

      while (product<1) {

         try {

            wait();

         }

         catch (InterruptedException e) {

         }

      }

      product--;

      System.out.println("Покупатель купил 1 товар");

      System.out.println("Товаров на складе: " + product);

      notify();

   }

   public synchronized void put() {

       while (product>=3) {

         try {

            wait();

         }

         catch (InterruptedException e) { 

         } 

      }

      product++;

      System.out.println("Производитель добавил 1 товар");

      System.out.println("Товаров на складе: " + product);

      notify();

   }

}

// класс Производитель

class Producer implements Runnable{

 

    Store store;

    Producer(Store store){

       this.store=store; 

    }

    public void run(){

        for (int i = 1; i < 6; i++) {

            store.put();

        }

    }

}

// Класс Потребитель

class Consumer implements Runnable{

     

     Store store;

    Consumer(Store store){

       this.store=store; 

    }

    public void run(){

        for (int i = 1; i < 6; i++) {

            store.get();

        }

    }

}
```

определены класс магазина `Store`, производитель `Producer` и потребитель `Consumer`. производитель в методе `run()` пять раз вызывает `put()` у объекта `Store` и тем добавляет 5 товаров. потребитель в `run()` в цикле обращается к `get` того же объекта и эти товары забирает. оба метода, `put` и `get`, синхронизированы, поэтому делят монитор экземпляра `Store` и не выполняются одновременно.

наличие товара отслеживает поле `product`. по умолчанию товара нет, переменная равна `0`. метод `get()`, получение товара, должен срабатывать только при хотя бы одном товаре. перед изъятием проверяется отсутствие товара:

```java
while (product<1)
```

если товара нет, вызывается `wait()`. метод освобождает монитор объекта `Store` и блокирует выполнение `get`, пока для этого же монитора не будет вызван `notify()`. условие записано циклом `while`. `wait()` может вернуться и без парного `notify()`, такое пробуждение называют ложным, поэтому предикат после пробуждения читают снова. кроме того, монитор мог достаться потоку, которому продолжать ещё рано, и тогда он опять вызывает `wait()`.

когда в методе `put()` добавляется товар и вызывается `notify()`, метод `get()` получает монитор и выходит из конструкции `while (product<1)`. затем `product` уменьшается, и склад печатает новый запас. один из допустимых порядков печати:

```consoletext


Производитель добавил 1 товар

Товаров на складе: 1

Производитель добавил 1 товар

Товаров на складе: 2

Производитель добавил 1 товар

Товаров на складе: 3

Покупатель купил 1 товар

Товаров на складе: 2

Покупатель купил 1 товар

Товаров на складе: 1

Покупатель купил 1 товар

Товаров на складе: 0

Производитель добавил 1 товар

Товаров на складе: 1

Производитель добавил 1 товар

Товаров на складе: 2

Покупатель купил 1 товар

Товаров на складе: 1

Покупатель купил 1 товар

Товаров на складе: 0
```

в методе `get()` вызов `wait()` удерживает потребителя до тех пор, пока производитель не добавит новый товар. после добавления вызывается `notify()`: на складе состояние изменилось, и если товар забрали, одно место освободилось, туда можно класть следующий.

в методе `put()` вызов `wait()` внутри `while (product>=3)` ждёт освобождения места. когда место есть, товар добавляется, и `notify()` уведомляет покупателя, что товар можно забирать.

при одном производителе и одном потребителе в ожидании не больше одного потока, и `notify()` возобновляет именно его. если на том же мониторе ждут потоки с разными предикатами, одного `notify()` мало. возобновиться может поток, чей предикат всё ещё ложен. он снова вызовет `wait()` и не пошлёт сигнал остальным. тогда на мониторе вызывают `notifyAll()`.
