регулярное выражение задаёт шаблон строк. с ним сопоставляют всю строку или подстроку. в java этот механизм собран в пакете `java.util.regex`, диалект близок к perl. шаблон компилируется в автомат с возвратами: доступны обратные ссылки и ленивые квантификаторы, а на отдельных шаблонах возвраты дают экспоненциальное время. часть методов `String` принимает такое выражение и применяет его к содержимому строки. синтаксически неверный шаблон компиляция отвергает исключением `PatternSyntaxException`.

### split

`String.split` делит строку на подстроки. аргумент компилируется как регулярное выражение. литеральное сравнение подстроки здесь не выполняется. совпавшие разделители в результат не входят. при лимите по умолчанию хвостовые пустые строки отбрасываются.

пример делит предложение на слова:

```java


String text = "FIFA will never regret it";

String[] words = text.split("\\s*(\\s|,|!|\\.)\\s*");

for(String word : words){

	System.out.println(word);

}
```

шаблон `"\\s*(\\s|,|!|\\.)\\s*"` читается так. метасимвол `\s` по умолчанию совпадает с пробельным символом ascii, класс `[ \t\n\x0B\f\r]`. квантификатор `*` задаёт повторение от нуля раз и выше, поэтому `\s*` описывает последовательность пробельных символов любой длины, включая пустую: между словами может быть сколько угодно пробелов, и их может не быть вовсе. круглые скобки выделяют группу. вертикальная черта внутри группы задаёт альтернативу, и подстрока должна совпасть с одной из ветвей. группа `\s|,|!|\.` совпадает с пробельным символом, запятой, восклицательным знаком или точкой. вне символьного класса точка обозначает любой символ, кроме ограничителя строки, поэтому литеральная точка экранируется: `\.`. в строковом литерале java обратный слеш сам требует экранирования, в исходном тексте это запись `"\\."`.

### соответствие строки. matches

`String.matches` компилирует выражение и проверяет всю строку. частичное вхождение метод не ищет: семантика совпадает с `Pattern.matches` и с `Matcher.matches`. результат имеет тип `boolean`.

проверка, похожа ли строка на номер телефона:

```java


String input = "+12343454556";

boolean result = input.matches("(\\+*)\\d{11}");

if(result){

	System.out.println("It is a phone number");

}

else{

	System.out.println("It is not a phone number!");	

}
```

шаблон `"(\\+*)\\d{11}"` читается слева направо. группа `(\+*)` задаёт литеральный плюс, повторённый от нуля раз: плюса может не быть, и плюсов может быть несколько. один необязательный плюс записывался бы квантификатором `?`, то есть `\+?`. дальше `\d` задаёт десятичную цифру ascii, класс `[0-9]`, а `{11}` требует ровно одиннадцать таких цифр. поскольку сопоставляется вся строка, вход `"+12343454556"` подходит: один плюс и одиннадцать цифр. лишний символ по краю делает результат ложным.

### класс `Pattern`

основная работа с регулярными выражениями сосредоточена в пакете `java.util.regex`.

само выражение есть шаблон поиска. класс `Pattern` хранит скомпилированный шаблон. класс `Matcher` хранит состояние конкретного поиска: вход, позицию, границы последнего совпадения и группы. `Pattern` неизменяем, его можно публиковать нескольким потокам. `Matcher` изменяем, один экземпляр одновременно из нескольких потоков не используют.

для полного совпадения у `Pattern` есть статический метод `boolean matches(String regex, CharSequence input)`. метод компилирует шаблон и требует, чтобы вся последовательность `input` ему соответствовала:

```java


import java.util.regex.Pattern;



public class StringsApp {



    public static void main(String[] args) {

        

        String input = "Hello";

        boolean found = Pattern.matches("Hello", input);

        if(found)

            System.out.println("Найдено");

        else

            System.out.println("Не найдено");

    }   

}
```

на входе `"Hello"` и шаблоне `"Hello"` совпадение есть, программа печатает `Найдено`. сравнение символов чувствительно к регистру: шаблон `"hello"` эту строку уже не принимает. для одноразовой проверки статического метода достаточно. если тот же шаблон применяется многократно, его компилируют один раз и дальше порождают сопоставители.

для повторного поиска держат `Matcher`. разовый статический вызов каждый раз компилирует шаблон заново.

### класс `Matcher`

основные методы `Matcher`:

- `boolean matches()`: возвращает `true`, если со всей текущей областью входа совпадает шаблон

- `boolean find()`: возвращает `true`, если в оставшейся части области есть подстрока, совпадающая с шаблоном, и переносит состояние сопоставителя на это совпадение

- `String group()`: возвращает подстроку текущего совпадения, полученного вызовом `find` или `matches`. если совпадения нет, метод выбрасывает `IllegalStateException`

- `int start()`: возвращает индекс начала текущего совпадения

- `int end()`: возвращает смещение первого символа после текущего совпадения. с этого смещения следующий вызов `find()` продолжает поиск

- `String replaceAll(String replacement)`: заменяет все совпадения строкой `replacement` и возвращает новую строку. исходный `String` неизменяем, сопоставитель читает его как `CharSequence`

сопоставитель получают из шаблона. сначала шаблон компилируют статическим методом `compile`:

```java
Pattern pattern = Pattern.compile("Hello");
```

шаблоном служит литерал `"Hello"`. `compile()` возвращает объект `Pattern`, дальше его используют для поиска.

метод `matcher(CharSequence input)` принимает последовательность, в которой ведут поиск, и возвращает `Matcher`. `String` подходит как реализация `CharSequence`:

```java


String input = "Hello world! Hello Java!";

Pattern pattern = Pattern.compile("hello");

Matcher matcher = pattern.matcher(input);
```

в этом фрагменте шаблон записан в нижнем регистре, `"hello"`, а во входе стоит `"Hello"`. дальше у сопоставителя вызывают `matches()`:

```java


import java.util.regex.Matcher;

import java.util.regex.Pattern;



public class StringsApp {



    public static void main(String[] args) {

        

        String input = "Hello";

        Pattern pattern = Pattern.compile("Hello");

        Matcher matcher = pattern.matcher(input);

        boolean found = matcher.matches();

        if(found)

            System.out.println("Найдено");

        else

            System.out.println("Не найдено");

    }   

}
```

здесь и шаблон, и вход равны `"Hello"`, поэтому `matches()` возвращает `true`. метод требует покрытия всей области и следующее вхождение не ищет. отдельные вхождения находит `find()`.

пример ищет в строке отдельные вхождения:

```java


import java.util.regex.Matcher;

import java.util.regex.Pattern;



public class StringsApp {



    public static void main(String[] args) {

        

        String input = "Hello Java! Hello JavaScript! JavaSE 25.";

        Pattern pattern = Pattern.compile("Java(\\w*)");

        Matcher matcher = pattern.matcher(input);

        while(matcher.find())

            System.out.println(matcher.group());

    }   

}
```

нужны все вхождения, которые начинаются с `Java`. во входе их три: `"Java"`, `"JavaScript"` и `"JavaSE"`. шаблон `"Java(\\w*)"` требует литерал `Java` в начале совпадения. группа `\w*` задаёт хвост. метасимвол `\w` по умолчанию совпадает с классом `[a-zA-Z0-9_]`: латинская буква, цифра или подчёркивание. `*` снова означает повтор от нуля раз, поэтому под шаблон попадают и `"Java"` без хвоста, и формы с хвостом. флаг `UNICODE_CHARACTER_CLASS` не включён, буквы вне ascii в `\w` не входят. чтобы компилятор java не воспринял `\w` как escape-последовательность строкового литерала вроде `\n`, в исходном тексте слеш удваивают.

`find()` переходит к следующему совпадению после уже найденного. первый вызов находит первое, второй находит следующее, и так до конца входа. цикл `while(matcher.find())` обходит все неперекрывающиеся вхождения. текст очередного совпадения даёт `group()`. программа печатает:

```bash


Java

JavaScript

JavaSE
```

### замена в строке

`Matcher.replaceAll` подставляет строку замены на место каждого совпадения и возвращает новый `String`:

```java


String input = "Hello Java! Hello JavaScript! JavaSE 25.";

Pattern pattern = Pattern.compile("Java(\\w*)");

Matcher matcher = pattern.matcher(input);

String newStr = matcher.replaceAll("HTML");

System.out.println(newStr); // Hello HTML! Hello HTML! HTML 8.
```

тот же приём есть у `String`. метод `replaceAll` компилирует шаблон и заменяет все совпадения. для одноразовой замены вызов на строке короче. при повторном применении того же шаблона компиляция через `Pattern.compile` выполняется один раз, а сопоставитель переиспользуют.

```java


String input = "Hello Java! Hello JavaScript! JavaSE 25.";

String myStr =input.replaceAll("Java(\\w*)", "HTML");

System.out.println(myStr); // Hello HTML! Hello HTML! HTML 8.
```

комментарий в обоих листингах записывает результат как `Hello HTML! Hello HTML! HTML 8.` во входе при этом стоит `"JavaSE 25"`. шаблон `Java(\w*)` поглощает `"JavaSE"` целиком, подстановка `"HTML"` оставляет число `25`, и строка получается `Hello HTML! Hello HTML! HTML 25.`

### разделение строки на лексемы

`String[] split(CharSequence input)` у `Pattern` делит строку на массив подстрок по совпадениям шаблона. так выделяют отдельные слова:

```java


import java.util.regex.Pattern;



public class StringsApp {



    public static void main(String[] args) {

        

        String input = "Hello Java! Hello JavaScript! JavaSE 25.";

        Pattern pattern = Pattern.compile("[ ,.!?]");

        String[] words = pattern.split(input);

        for(String word:words)

            System.out.println(word);

    }   

}
```

консоль печатает набор слов:

```bash


Hello

Java



Hello

JavaScript



JavaSE

25
```

символы-разделители в массив не попадают. разбиение этим шаблоном грубое: часть пробелов остаётся отдельными элементами массива, то есть отдельными лексемами. шаблон `[ ,.!?]` является символьным классом и совпадает с одним символом из набора: пробел, запятая, точка, восклицательный знак, вопросительный знак. внутри класса точка литеральна. там, где разделители стоят подряд, между ними возникает пустая строка. последовательность `"! "` это два совпадения подряд, и `split` вставляет между ними пустой элемент. хвостовые пустые строки реализация с лимитом по умолчанию отбрасывает.

для более точного разбиения в шаблон входят уже разобранные конструкции: необязательные пробелы вокруг одного разделителя.

```java
Pattern pattern = Pattern.compile("\\s*(\\s|,|!|\\.)\\s*");
```

после замены шаблона в массиве остаются только слова:

```bash


Hello

Java

Hello

JavaScript

JavaSE

25
```
