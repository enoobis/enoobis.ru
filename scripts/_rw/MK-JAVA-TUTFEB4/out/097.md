в предыдущих примерах поток выполнял конечную последовательность инструкций и завершался вместе с выходом из `run()`. другая организация тела: цикл без собственного условия выхода. так устроен поток сервера, который слушает порт и принимает данные. завершение тогда запрашивают извне.

### завершение потока

распространённый приём кооперативной остановки: на каждой итерации поток читает логическую переменную и выходит из цикла, когда она становится `false`.

класс задачи:

```java


class MyTask implements Runnable {

      

    private boolean isActive;

      

    void disable(){ isActive=false; }

      

    MyTask(){ isActive = true; }

      

    public void run(){

          

        String taskName = Thread.currentThread().getName();



        System.out.printf("%s started... \n", taskName);



        int counter = 1; // счетчик циклов



        while(isActive){



            System.out.println("Loop " + counter++);



            try{

                Thread.sleep(400);

            }

            catch(InterruptedException _){

                

                System.out.printf("%s interrupted... \n", taskName);

            }

        }

        System.out.printf("%s finished... \n", taskName);

    }

}
```

`isActive` означает, что циклу ещё работать. пока поле равно `true`, поток продолжает итерации. `disable()` записывает `false`. после очередной проверки условия цикл заканчивается, `run()` доходит до последней печати, и поток переходит в `TERMINATED`.

модель памяти требует оговорки. запись `isActive` выполняет главный поток, чтение выполняет поток задачи. без отношения happens-before запись может так и остаться невидимой другому потоку: компилятор вправе держать значение в регистре, и цикл условие не перечитает. флаг отмены объявляют `volatile` либо защищают одной и той же блокировкой. `volatile`-запись происходит раньше последующего `volatile`-чтения того же поля. в листинге модификатора нет, пример показывает только схему опроса.

тот же класс в программе:

```java


class Program{



    public static void main(String[] args) {

         

        System.out.println("Main thread started...");



        // создаем и запускаем поток

        var myTask = new MyTask();

        new Thread(myTask,"MyTask").start();

            

        try{

            Thread.sleep(1100);

                

            myTask.disable();  // завершаем поток

            

            Thread.sleep(1000);

        }

        catch(InterruptedException e){

            System.out.println("Main thread interrupted...");

        }

        System.out.println("Main thread finished...");

    }

}

class MyTask implements Runnable {

      

    private boolean isActive;

      

    void disable(){ isActive=false; }

      

    MyTask(){ isActive = true; }

      

    public void run(){

          

        String taskName = Thread.currentThread().getName();



        System.out.printf("%s started... \n", taskName);



        int counter=1; // счетчик циклов

        while(isActive){

            System.out.println("Loop " + counter++);

            try{

                Thread.sleep(400);

            }

            catch(InterruptedException _){

                

                System.out.printf("%s interrupted... \n", taskName);

            }

        }

        System.out.printf("%s finished... \n", taskName);

    }

}
```

сначала запускается дочерний поток:

```java


var myTask = new MyTask();

new Thread(myTask,"MyTask").start();
```

затем главный поток останавливается на 1100 миллисекунд, вызывает `disable()` и останавливается ещё на 1000 миллисекунд, чтобы дочерний поток успел увидеть флаг, выйти из цикла и напечатать завершение:

```java
myTask.disable();  // завершаем поток
```

1100 миллисекунд покрывают две паузы по 400 миллисекунд и часть третьей, поэтому в типичном прогоне видны три итерации:

```bash


Main thread started...

MyTask started... 

Loop 1

Loop 2

Loop 3

MyTask finished... 

Main thread finished...
```

точный набор строк зависит от планировщика. пауза `sleep(1100)` в главном потоке и пауза `sleep(400)` в задаче по одним и тем же границам кванта не выровнены.

### прерывание потока и метод interrupt

принудительно снять поток с исполнения api не умеет. `Thread.stop()` в современных jdk выбрасывает `UnsupportedOperationException` и к отмене непригоден: метод исторически отпускал мониторы в произвольной точке и ломал инварианты объектов. запрос на отмену выражает `interrupt()`. вызов выставляет булев флаг прерывания. отдельного значения `Thread.State` для прерванного потока нет. поток остаётся в `RUNNABLE`, `WAITING`, `TIMED_WAITING` или `BLOCKED`, а флаг хранится отдельно.

поток, который исполняет свой код, опрашивает флаг методом `isInterrupted()`. метод возвращает флаг и не сбрасывает его. статический `Thread.interrupted()` возвращает флаг текущего потока и сбрасывает его. цикл с такой проверкой:

```java


// пока поток не прерван

while (!Thread.currentThread().isInterrupted()){



    // делаем некоторую работу

}
```

поток, который стоит внутри блокирующего вызова, до своей проверки флага не доходит. `sleep`, `wait`, `join` и ряд методов `java.util.concurrent` на `interrupt()` отвечают сами: вызов завершается исключением `InterruptedException`, а флаг перед этим сбрасывается. после выхода в `catch` флаг уже ложен. если отмену нужно сохранить для вызывающего кода, в обработчике флаг ставят снова через `Thread.currentThread().interrupt()`.

блокирующий ввод-вывод устроен по-разному. классический `java.io` прерыванием не обрывается: `read` возвращается обычным путём, когда операция завершится, а флаг остаётся установленным, и поток проверяет его следом. канал `java.nio`, реализующий `InterruptibleChannel`, на прерывание закрывается, а операция завершается исключением `ClosedByInterruptException`.

каркас задачи, которая и опрашивает флаг, и ловит прерывание блокирующего вызова:

```java


Runnable r = () -> {   // действия потока

    try  {



        // если действия в цикле, в качестве условия проверяем isInterrupted()

        while (!Thread.currentThread().isInterrupted()) {

            

            // выполняемые действия

        }

    }

    catch (InterruptedException ex){



        // обрабатываем исключение прерывания потока

    }



    // какие-то завершающие действия при необходимости

};
```

прерывание остаётся запросом. поток вправе обработать исключение и продолжить работу. на практике флаг и `InterruptedException` читают как просьбу выйти из `run()`.

пример такой отмены:

```java


class MyTask implements Runnable {



    public void run(){

         

        String name = Thread.currentThread().getName();  // получаем имя текущего потока



        try{

            

            System.out.println(name + " started...");



            while(!Thread.currentThread().isInterrupted()){



                System.out.println(name + " works");



                Thread.sleep(1000); // приостанавливаем поток на 1000 миллисекунд

            }

        }

        catch(InterruptedException ex){



            System.out.println(ex.getMessage());

        }

        System.out.println(name + " finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        // определяем поток

        var t = new Thread(new MyTask(), "MyTask");

        // запускаем поток

        t.start();

        

        try{

            // делаем небольшую задержку, чтобы дочерний поток MyTask успел немного отработать

            Thread.sleep(2000);

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }



        // прерываем поток

        t.interrupt();

        

        System.out.println("Main thread finished...");

    }

}
```

в `run()` класса `MyTask` условие цикла вызывает `isInterrupted()`:

```java


try{

            

    .........................



    while(!Thread.currentThread().isInterrupted()){



        System.out.println(name + " works");

        Thread.sleep(1000); // приостанавливаем поток на 1000 миллисекунд

    }

}

catch(InterruptedException ex){



    System.out.println(ex.getMessage());

}
```

в цикле поток печатает строку и вызывает `Thread.sleep(1000)`. если за время сна другой поток вызовет `interrupt()`, `sleep` выбросит `InterruptedException`. управление перейдёт в `catch`, цикл на этом закончится, и после обработчика напечатается сообщение о завершении. текст исключения из `sleep` равен `sleep interrupted`.

в `main` поток запускают, дают ему около двух секунд и затем прерывают:

```java


var t = new Thread(new MyTask(), "MyTask");

t.start();

        

try{

    Thread.sleep(2000);

}

catch(InterruptedException ex){

    System.out.println(ex.getMessage());

}



// прерываем поток

t.interrupt();
```

за две секунды цикл успевает напечатать `"MyTask works"` дважды. прерывание приходится на очередной `sleep`, задача печатает текст исключения и завершает `run()`:

```bash


Main thread started...

MyTask started...

MyTask works

MyTask works

Main thread finished...

sleep interrupted

MyTask finished...
```

`"Main thread finished..."` может оказаться раньше последних строк `MyTask`: после `interrupt()` главный поток `join` не вызывает.
