с выходом jdk 21 появилась экспериментальная возможность: компактные исходные файлы и сокращённое объявление метода `main`. она упрощает программу на java. в jdk 25 эта возможность перестала быть экспериментальной и стала обычным средством языка (jep 512). суть в упрощении файла программы и метода `main`. код можно писать без объявления класса и с сокращённым определением `main`.

### компактный метод main

прежде всего можно определить более компактный метод `main`. стандартная программа, размещённая в файле `Program.java`, выглядит так:

```java


public class Program{ 

     

    public static void main (String args[]){

         

		    System.out.println("Hello enoobis.ru!");

    }

}
```

раньше для построения и запуска программы на java требовалось:

- объявить класс (`public class Program`)

- создать статический метод `main` с параметром-массивом строк (`public static void main (String args[])`)

теперь метод `main` можно определить без `public static` и без параметра `String args[]`:

```java


class Program{

    void main() {

        System.out.println("Hello enoobis.ru");

    }

}
```

версии jdk 21, 22, 23 и 24 поддерживали такое определение метода `main` как экспериментальное, и для компиляции программы нужно было указать дополнительные опции. для компиляции с помощью jdk 22 применялась команда:

```bash
javac --release 22 --enable-preview Program.java
```

здесь 22 указывает на версию jdk, и это число соответственно заменяют на 21, 23 или 24. для запуска программы тоже нужно было указать дополнительную опцию `--enable-preview`:

```bash
java --enable-preview Program
```

начиная с версии jdk 25 никаких дополнительных опций ни при компиляции, ни при запуске программы указывать не нужно:

```bash


eugene@Eugene:/workspace/java$ javac Program.java

eugene@Eugene:/workspace/java$ java Program

Hello enoobis.ru!

eugene@Eugene:/workspace/java$
```

общая механика вызова метода `main` такова. при запуске приложения лаунчер java (программа запуска приложения) выбирает и вызывает основной метод запущенного класса:

- если класс определяет или наследует метод `main` с параметром `String[]`, лаунчер выбирает этот метод

- в противном случае, если класс определяет или наследует метод `main` без параметров, лаунчер выбирает этот метод

- в противном случае лаунчер сообщает об ошибке и завершает работу

после выбора метода дальнейшие действия зависят от того, выбран статический или нестатический метод `main`:

- если выбранный метод статический, лаунчер вызывает его

- иначе класс должен иметь незакрытый (без модификатора `sealed`) конструктор без параметров. лаунчер вызывает этот конструктор, а затем у созданного объекта класса вызывает выбранный метод `main`. если же класс не имеет конструктора без параметров, лаунчер сообщает об ошибке и завершает работу

по jep 512 у этого конструктора нет параметров, и он не объявлен `private`: лаунчер создаёт экземпляр сам и должен иметь право вызвать конструктор.

для примера берётся файл программы со следующим кодом:

```java


public class Program{

    void main(String[] args) {  

        System.out.println("With args");  

    } 



    void main() {  

        System.out.println("Without args");  

    } 

}
```

здесь два определения метода `main`, оба нестатические, но один из них принимает параметр `String[]`. именно этот метод лаунчер выбирает для выполнения программы, и на консоль выходит строка `With args`.

### компактные файлы

если компилятор java обнаружит исходный файл с полями и методами, которые не заключены в объявление класса, он считает, что исходный файл неявно объявляет класс, членами которого являются эти поля и методы. такой исходный файл называется компактным исходным файлом.

раньше для построения и запуска программы на java требовалось:

- объявить класс (`public class Program`)

- создать статический метод `main` с параметром-массивом строк (`public static void main (String args[])`)

теперь в файле программы можно писать код без объявления класса:

```java


void main() {

    System.out.println("Hello enoobis.ru!");

}
```

для подобного файла неявно определяется класс верхнего уровня в неименованном пакете. весь код файла фактически представляет этот класс, который:

- расширяет `java.lang.Object` и не реализует никаких интерфейсов

- имеет конструктор по умолчанию без параметров и никаких других конструкторов

- имеет в качестве своих членов поля и методы компактного исходного файла

- должен иметь запускаемый метод `main`. в противном случае выдаётся ошибка времени компиляции

по jep 512 неявно объявленный класс ещё и финальный: объявить его подкласс нельзя. имя, которое генератор выбирает при компиляции, зависит от реализации.

поскольку поля и методы, объявленные в компактном исходном файле, интерпретируются как члены неявно объявленного класса, рядом с методом `main` можно определить и использовать другие методы и поля. они автоматически являются методами и полями этого класса. определение и вызов метода:

```java


String sayHello(){ 

    return "Hello";

}



void main(String[] args) {  



    System.out.println(sayHello()); 

}
```

определение и использование полей:

```java


String message = "Hello Work";



void main(String[] args) {  



    System.out.println(message); 

}
```

компактный исходный файл объявляет класс неявно, поэтому у класса нет имени, которое можно использовать в исходном коде. компилятор java генерирует имя класса при компиляции компактного исходного файла, но это имя зависит от реализации и не должно использоваться ни в каком исходном коде, включая исходный код самого компактного файла. на текущий экземпляр класса ссылаются через `this`, явно или, как в примерах выше, неявно. создать экземпляр класса оператором `new` нельзя: в исходном тексте нет имени, которое можно было бы записать после `new`.

### определение других типов в файле

в том же файле можно определять и другие типы, например классы:

```java


void main(String[] args) {  



    Person tom = new Person("Tom");

    System.out.println(tom.getName()); 

}



class Person{

     

    private String name;

 

    Person(String name){

        this.name = name;

    }

    public void setName(String name){

        this.name = name;

    }

    public String getName(){

     

        return this.name;

    }

}
```

это аналогично тому, что класс `Person` определён внутри класса, который представляет текущий файл: типы компактного файла оказываются вложенными в неявно объявленный класс.

если вложенность класса не устраивает, для метода `main` явным образом определяют конкретный класс, а рядом с ним остальные типы:

```java


class Program{

    void main(String[] args) {  



        Person bob = new Person("Bob");

        System.out.println(bob.getName()); 

    }

}



class Person{

     

    private String name;

 

    Person(String name){

        this.name = name;

    }

    public void setName(String name){

        this.name = name;

    }

    public String getName(){

     

        return this.name;

    }

}
```

в этом файле уже есть объявление класса верхнего уровня, поэтому файл не является компактным. `Person` оказывается соседним типом того же пакета. членом неявного класса он здесь уже не является.
