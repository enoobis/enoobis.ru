при работе с объектами классов учитывают, что переменная хранит ссылку на объект в куче. присваивание копирует ссылку. пример показывает, какие трудности из этого следуют.

```java

public class Program{
      
    public static void main(String[] args) {
          
        Person tom = new Person("Tom");
        tom.print();      // Person Tom
        Person bob = tom;
        bob.name = "Bob";
        tom.print();      // Person Bob
    }
}
class Person{

    String name;
     
    Person(String name){ this.name = name; }

    void print(){
        System.out.println("Person " + name);
    }
}
```

в программе создается один объект `Person`, и ссылка на него записывается во вторую переменную `bob`. изменение поля через `bob` видно и через `tom`. после присваивания обе переменные указывают на одну область памяти, где хранятся данные объекта и его поля. отдельного второго объекта операция `bob = tom` не создает, поэтому второй вызов `tom.print()` печатает `Person Bob`.

### метод clone

чтобы у переменной `bob` был собственный объект, объект копируют. стандартный механизм копирования в библиотеке java это метод `clone`.

```java

class Person implements Cloneable{  // применяем интерфейс  Cloneable

    String name;
     
    Person(String name){ this.name = name; }

    void print(){
        System.out.println("Person " + name);
    }

    public Person clone() throws CloneNotSupportedException{
      
        return (Person) super.clone();
    }
}
```

для клонирования класс `Person` реализует интерфейс `Cloneable`. это маркерный интерфейс: собственных методов он не объявляет, а лишь помечает класс как допускающий клонирование. метод `clone` определен в классе `Object` как защищенный (`protected`) и здесь переопределяется с ковариантным типом результата `Person`. такое переопределение допустимо с java 5: исходный результат `Object.clone()` имеет тип `Object`, наследник сужает его до `Person`. тело возвращает результат `super.clone()` с приведением к `Person`.

`Object.clone()` создает новый объект того же класса и копирует поля побитово, то есть копирует значения полей, а для ссылочных полей копирует сами ссылки. если класс не реализует `Cloneable`, `Object.clone()` выбрасывает проверяемое исключение `CloneNotSupportedException`.

в секции `throws` указано `CloneNotSupportedException`. тело вызывает `super.clone()`, а этот вызов объявляет проверяемое исключение, поэтому его либо перехватывают, либо оставляют в `throws`. в листинге выбран второй путь. само переопределение может сузить список исключений относительно `Object.clone()`, если новое тело исключение не выпускает. метод в листинге объявлен как `public`: `Object.clone()` был `protected`, и без расширения доступа класс `Program`, не являющийся наследником `Person`, вызвать его не смог бы.

копирование выполняется вызовом переопределенного метода:

```java

public class Program{
      
    public static void main(String[] args) {
          
        try{
            Person tom = new Person("Tom");
            Person bob = tom.clone();
            bob.name = "Bob";
            tom.print();        // Person Tom
            bob.print();        // Person Bob
        }
        catch(CloneNotSupportedException ex){
                        
            System.out.println("Clonable not implemented");
        }
    }
}
```

после `tom.clone()` переменные ссылаются на разные объекты. присваивание `bob.name = "Bob"` меняет только копию. `tom.print()` по-прежнему выводит `Person Tom`, `bob.print()` выводит `Person Bob`. если бы класс не реализовал `Cloneable`, `clone()` выбросил бы `CloneNotSupportedException`, и управление перешло бы в `catch`, который печатает `Clonable not implemented`. строка в `catch` повторяет текст листинга, включая написание `Clonable`.

### глубокое копирование

описанный способ дает неполное копирование (shallow copy). его достаточно, пока клонируемый объект не содержит ссылок на другие изменяемые объекты. пусть у `Person` есть поле со ссылкой на объект `Company`, условно место работы.

```java

class Company{
    
    String name;
     
    Company(String name){ this.name = name; }
}
class Person implements Cloneable{

    String name;
    Company company;
     
    Person(String name, Company company){ 

        this.name = name; 
        this.company = company;
    }

    void print(){
        System.out.printf("Person %s works in %s\n", name, company.name);
    }

    public Person clone() throws CloneNotSupportedException{
      
        return (Person) super.clone();
    }
}
```

класс `Person` по-прежнему реализует `clone()`. копирование самого объекта `Person` при этом выполняется, но поле `company` обрабатывается тем же побитовым правилом.

```java

public class Program{
      
    public static void main(String[] args) {
          
        try{
            Company yandex = new Company("Yandex");
            Person tom = new Person("Tom", yandex);

            Person bob = tom.clone();  //  копируем объект tom

            bob.name = "Bob";
            bob.company.name = "Google";

            tom.print();        // Person Tom works in Google
            bob.print();        // Person Bob works in Google
        }
        catch(CloneNotSupportedException ex){
                        
            System.out.println("Clonable not implemented");
        }
    }
}
```

консольный вывод программы:

```bash

Person Tom works in Google
Person Bob works in Google
```

переменные `tom` и `bob` ссылаются на разные объекты `Person`, однако поле `company` у обоих хранит ссылку на один и тот же объект `Company`. поверхностное копирование дублирует ссылку, а не объект по этой ссылке. поэтому присваивание `bob.company.name = "Google"` меняет имя компании и у исходного объекта, и `tom.print()` тоже показывает `Google`.

![неполное копирование объектов в java](/uploads/course-lectures/f71a5b0d802fdf983e3ee17a084782561799f85a.png)

здесь требуется полное копирование, его же называют глубоким (deep copy). для этого метод клонирования определяется и у класса `Company`.

```java

class Company implements Cloneable{
    
    String name;
     
    Company(String name){ this.name = name; }

    public Company clone() throws CloneNotSupportedException{
    
        return (Company) super.clone();
    }
}
```

`Company.clone()` устроен так же, как поверхностный `clone` у `Person`: новый объект `Company` и копия поля `name`. вложенных ссылок у `Company` в примере нет, поэтому поверхностного копирования компании достаточно.

затем `clone()` в классе `Person` после копирования самого `Person` отдельно клонирует `Company` и записывает в копию новую ссылку:

```java

class Person implements Cloneable{

    String name;
    Company company;
     
    Person(String name, Company company){ 

        this.name = name; 
        this.company = company;
    }

    void print(){
        System.out.printf("Person %s works in %s\n", name, company.name);
    }

    public Person clone() throws CloneNotSupportedException{
      
        Person person = (Person) super.clone();
        person.company =(Company) company.clone();
        return person;
    }
}
```

сначала `super.clone()` создает новый `Person` с теми же ссылками, что и у оригинала. следующая строка заменяет поле `company` у копии результатом `company.clone()`. наружу возвращается уже этот объект, а не исходный `tom`.

код класса `Program` остается прежним:

```java

public class Program{
      
    public static void main(String[] args) {
          
        try{
            Company yandex = new Company("Yandex");
            Person tom = new Person("Tom", yandex);

            Person bob = tom.clone();  //  копируем объект tom

            bob.name = "Bob";
            bob.company.name = "Google";

            tom.print();        // Person Tom works in Google
            bob.print();        // Person Bob works in Google
        }
        catch(CloneNotSupportedException ex){
                        
            System.out.println("Clonable not implemented");
        }
    }
}
```

комментарии в этом листинге оставлены от предыдущего запуска и по-прежнему упоминают `Google` для обоих объектов. фактический вывод после глубокого копирования другой:

```bash

Person Tom works in Yandex
Person Bob works in Google
```

`person.company = (Company) company.clone()` создает отдельный объект `Company`. изменение `bob.company.name` больше не затрагивает компанию, на которую ссылается `tom`. консоль показывает `Person Tom works in Yandex` и `Person Bob works in Google`.

глубокое копирование должно обойти весь граф ссылок, которые по смыслу принадлежат объекту. если в графе есть цикл, прямой рекурсивный вызов `clone` не завершится, и такой граф копируют с учетом уже посещенных объектов. в примере граф состоит из одного поля `company` и ацикличен, поэтому одного дополнительного вызова `clone` достаточно.
