после установки jdk собирается первое приложение. чтобы получить программу на java, нужны две вещи. исходный текст пишется в любом текстовом редакторе, например в notepad++. исполняемый вид этому тексту придаёт компилятор, он входит в состав jdk.

на диске создаётся каталог для исходных файлов. в этом курсе это каталог `C:/Java`. в нём создаётся текстовый файл `Program.java`. файл открывается в редакторе, и в него записывается программа:

```java
public class Program{ 
     
    public static void main (String args[]){
         
        System.out.println("Hello enoobis.ru!");
    }
}
```

java является объектно-ориентированным языком, поэтому программа оформляется как набор классов. здесь объявлен один класс `Program`.

объявление начинается с модификатора доступа `public`: тип доступен за пределами пакета, и средство запуска может взять его точкой входа из командной строки. имя открытого класса обязано совпадать с именем файла, поэтому класс `Program` лежит в `Program.java`. дальше стоит служебное слово `class` и имя класса. тело класса заключено в фигурные скобки.

класс содержит поля и методы. в этом файле объявлен один метод `main`. это точка входа: виртуальная машина начинает выполнение программы с вызова `main`. в программе, которую запускают как приложение, такой метод обязателен.

у метода тоже стоит модификатор `public`, иначе вызов снаружи пакета, в том числе со стороны средства запуска, недопустим. `static` означает, что метод принадлежит классу: машина вызывает его, не создавая объект. `void` означает, что метод не возвращает значение. полное описание заголовка `main` и допустимых вариантов сигнатуры даётся дальше в курсе.

в круглых скобках записан параметр `String args[]`. это массив `args` со значениями типа `String`, то есть строками. объявление вида `args[]` повторяет форму декларатора массива, унаследованную от c. равносильная запись выглядит как `String[] args`. в этой программе параметр не читается. при запуске из командной строки в него попадают аргументы, переданные после имени класса.

после списка параметров идёт тело метода: инструкции, которые метод выполняет. здесь инструкция одна, вывод строки на консоль. для вывода используется метод `System.out.println()`. `System.out` обозначает статический объект стандартного потока вывода, `println` записывает строку и перевод строки. каждая инструкция заканчивается точкой с запятой. точка с запятой завершает инструкцию.

дальше программа компилируется. открывается командная строка windows или терминал linux и macos. сначала оболочка переводится в каталог с файлом командой `cd`:

```bash
cd C:\Java
```

в этом примере файл лежит в каталоге `C:\Java`.

![первая программа на java на windows](/uploads/course-lectures/0a72f55ec8cd900c5a5a388485e3dda6f04ac684.png)

затем текст компилируется:

```bash
javac Program.java
```

компилятор java вызывается утилитой `javac`. через пробел передаётся имя файла, в котором лежит класс.

компилятор записывает байт-код. в каталоге `C:\Java` появляется файл `Program.class`. его запускает утилита `java`:

```bash
java Program
```

расширение у имени класса не указывается. аргумент `Program` задаёт имя класса. средство запуска ищет `Program.class`, загружает байт-код в jvm и вызывает `main`.

на windows вся последовательность выглядит так:

![первая программа на java](/uploads/course-lectures/a5620f7553b823aeb0f51769d4e538251286c378.png)

в этом примере выполнение разбито на два этапа:

- компилятор `javac` строит из исходного текста файл с расширением `*.class`. в нём байт-код для виртуальной машины java, jvm

- утилита `java` загружает байт-код из файла `*.class` и выполняет программу

в поздних выпусках java тот же исходный файл можно выполнить сразу, без отдельного шага `javac`:

```bash
C:\Java>java Program.java
Hello enoobis.ru!

C:\Java>
```

утилите `java` передаётся файл исходного текста. файл с расширением `*.class` при этом не создаётся. такой запуск одного файла (single-file source-code program, начиная с jdk 11) компилирует текст в памяти процесса и сразу вызывает `main`. отдельный артефакт класса на диск не пишется, поэтому каталог после запуска остаётся без `Program.class`.
