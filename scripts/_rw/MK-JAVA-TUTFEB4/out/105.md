применение условий в блокировках даёт контроль над тем, при каком состоянии ресурса поток вправе продолжать работу. условие блокировки представляет собой объект интерфейса `Condition` из пакета `java.util.concurrent.locks`.

применение `Condition` во многом аналогично методам `wait`, `notify` и `notifyAll` класса `Object`. у интерфейса используются такие методы:

- `await`: поток ожидает, пока не будет выполнено некоторое условие и пока другой поток не вызовет `signal` или `signalAll`. на время ожидания связанная блокировка освобождается, иначе сигналящий поток не захватил бы её и не дошёл бы до сигнала. перед возвратом поток захватывает блокировку снова. метод аналогичен `wait` класса `Object`

- `signalAll`: сигнализирует всем потокам, у которых ранее был вызван `await()`, что они могут продолжить работу. аналогичен `notifyAll()` класса `Object`

- `signal`: сигнализирует, что поток, у которого ранее был вызван `await()`, может продолжить работу. применение аналогично `notify` класса `Object`. поток для разблокировки выбирается из ожидающих случайным образом. разбудить один поток дешевле, чем все, но выбранный поток может обнаружить, что продолжить выполнение всё ещё нельзя, и снова блокируется. если ни один другой поток снова не вызовет сигнал, программа останется в ожидании

эти методы вызываются из блока, который выполняется при удержанной блокировке `ReentrantLock`. вызов без владения завершается `IllegalMonitorStateException`. сначала из блокировки получают объект `Condition`:

```java


ReentrantLock locker = new ReentrantLock();

Condition condition = locker.newCondition();
```

как правило, сначала проверяется условие доступа. если условие говорит, что продолжать рано, поток ожидает, пока состояние не изменится. предикат стоит в цикле `while`: `await` может вернуться без `signal`, и склад после пробуждения проверяют снова.

```java


while (условие)

    condition.await();
```

после выполнения действий другим потокам подаётся сигнал об изменении условия:

```java
condition.signalAll();
```

`signal` или `signalAll` вызывают до освобождения блокировки, в конце секции. без сигнала ожидающие не выходят из `await`, и взаимное ожидание производителя и потребителя превращается во взаимоблокировку. возобновлённый поток всё равно не пойдёт дальше раньше сигналящего: возврат из `await` требует повторно захватить блокировку, а её ещё держит тот, кто послал сигнал.

для примера взята задача производителей и потребителей. производитель должен произвести 5 товаров, покупатель должен эти товары купить. на складе одновременно можно разместить не больше 3 товаров. покупатель не может купить товар, если на складе ничего нет, и ждёт, пока производитель не произведёт хотя бы один. производитель ждёт, пока покупатель не купит хотя бы один товар, если на складе уже 3. задача решается блокировкой и условием:

```java


import java.util.concurrent.locks.ReentrantLock;

import java.util.concurrent.locks.Condition;



public class Program {

 

    public static void main(String[] args) {

         

        Store store=new Store();

        Producer producer = new Producer(store);

        Consumer consumer = new Consumer(store);

        new Thread(producer).start();

        new Thread(consumer).start();

    }

}

// Класс Магазин, хранящий произведенные товары

class Store{

   private int product=0;

   ReentrantLock locker;

   Condition condition;

   

   Store(){

       locker = new ReentrantLock(); // создаем блокировку

       condition = locker.newCondition(); // получаем условие, связанное с блокировкой

   }

   

   public void get() {

       

      locker.lock();

      try{

          // пока нет доступных товаров на складе, ожидаем

          while (product<1)

              condition.await();

          

          product--;

          System.out.println("Покупатель купил 1 товар");

          System.out.println("Товаров на складе: " + product);

          

          // сигнализируем

          condition.signalAll();

      }

      catch (InterruptedException e){

          System.out.println(e.getMessage());

      }

      finally{

          locker.unlock();

      }

   }

   public void put() {

       

       locker.lock();

       try{

          // пока на складе 3 товара, ждем освобождения места

          while (product>=3)

              condition.await();

          

          product++;

          System.out.println("Производитель добавил 1 товар");

          System.out.println("Товаров на складе: " + product);

          // сигнализируем

          condition.signalAll();

      }

      catch (InterruptedException e){

          System.out.println(e.getMessage());

      }

      finally{

          locker.unlock();

      }

   }

}

// класс Производитель

class Producer implements Runnable{

 

    Store store;

    Producer(Store store){

       this.store=store; 

    }

    public void run(){

        for (int i = 1; i < 6; i++) {

            store.put();

        }

    }

}

// Класс Потребитель

class Consumer implements Runnable{

     

     Store store;

    Consumer(Store store){

       this.store=store; 

    }

    public void run(){

        for (int i = 1; i < 6; i++) {

            store.get();

        }

    }

}
```

по шагам программа состоит из общего буфера и двух методов.

`Store`, магазин, это общий ресурс, буфер, к которому обращаются два потока. ограничение склада: не больше 3 товаров и не меньше 0. запись `product >= 3` означает, что склад полон.

метод `put()` производителя:

- поток захватывает блокировку вызовом `locker.lock()`. проверка заполненности выполняется уже под этой блокировкой

- `while (product >= 3)`: метод проверяет, полон ли склад

- `condition.await()`: если склад полон, три товара, производитель переходит в ожидание и освобождает блокировку. продолжение возможно, когда его возобновит потребитель

- `product++`: если склад не полон, товаров меньше 3, производитель добавляет 1 товар

- `condition.signalAll()`: производитель возобновляет все ожидающие потоки. так продолжается потребитель, если тот ждал из-за пустого склада

- `locker.unlock()`: производитель отпускает блокировку. в коде снятие стоит в `finally`, поэтому выполняется и при исключении

метод `get()` класса `Consumer`, потребитель, выполняет следующие действия:

- `locker.lock()`: поток потребителя захватывает блокировку

- `while (product < 1)`: проверяется, пуст ли склад

- `condition.await()`: если склад пуст, 0 товаров, потребитель ждёт и освобождает блокировку, пока его не возобновит производитель

- `product--`: если на складе есть товары, один или больше, потребитель забирает 1 товар

- `condition.signalAll()`: потребитель возобновляет все ожидающие потоки, в том числе производителя, если тот ждал из-за полного склада

- `locker.unlock()`: потребитель отпускает блокировку

выполнение программы:

- два потока, `Producer` и `Consumer`, запускаются одновременно

- они состязаются за блокировку `locker`

- `Producer` с большой вероятностью захватывает блокировку первым, добавляет 3 товара тремя вызовами `put()` и на четвёртой попытке ждёт, потому что `product` становится равен 3

- `Consumer` тем временем забирает товары. как только он заберёт хотя бы один, он вызовет `signalAll()`, и сигнал возобновит производителя, объект `Producer`

- `Producer` снова пытается добавить товар

- процесс повторяется. потоки поочерёдно производят и потребляют, число товаров на складе не бывает больше 3 и не бывает меньше 0: оба изменения стоят после своего цикла `while`

- в итоге `Producer` 5 раз добавляет товар, `Consumer` 5 раз его забирает, после чего оба потока завершают работу

вывод может быть таким:

```bash

Товаров на складе: 1

Производитель добавил 1 товар

Товаров на складе: 2

Производитель добавил 1 товар

Товаров на складе: 3

Покупатель купил 1 товар

Товаров на складе: 2

Покупатель купил 1 товар

Товаров на складе: 1

Покупатель купил 1 товар

Товаров на складе: 0

Производитель добавил 1 товар

Товаров на складе: 1

Производитель добавил 1 товар
```
