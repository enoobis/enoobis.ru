первая публичная версия языка java датируется 23 мая 1995 года и вышла в компании sun microsystems. язык разрабатывала группа под руководством джеймса гослинга (james gosling); внутри компании ему предшествовало имя oak. год спустя появился jdk (java development kit), комплект, в котором исходный текст переводится в форму, пригодную для выполнения. впоследствии sun microsystems была поглощена oracle, и развитие платформы перешло к ней.

java задумывалась как язык общего назначения, применимый к разным классам задач. выход версии, которую принято обозначать 1.0, зафиксировал несколько свойств, определивших дальнейшую практику разработки.

- платформенная независимость: в java сформулирована модель «пиши один раз, запускай везде» (write once, run anywhere, wora). компилятор порождает не машинный код конкретной архитектуры, а байт-код, спецификация которого не зависит от операционной системы и процессора. этот байт-код исполняет виртуальная машина java (jvm). одна и та же скомпилированная программа выполняется на любой платформе, где установлена jvm, и поставка приложения отделяется от конкретной ос.

- объектная модель: java закрепила в массовой практике программирование в классах, с наследованием и полиморфизмом. синтаксис опирается на c++, но из языка исключены указатели с произвольной арифметикой адресов и ручное освобождение памяти. вместо указателя используется ссылка: значение ссылочного типа обозначает объект, арифметика над адресом программисту недоступна. согласование типов проверяется статически, до запуска.

- надёжность и безопасность: автоматическое управление памятью (трассирующая сборка мусора), строгая статическая типизация и встроенные механизмы ограничения прав. для апплетов исторически применялась песочница: код, загруженный из сети, исполнялся с урезанным набором разрешений. api апплетов позднее удалён из платформы (jdk 11), сама же схема «загрузка кода плюс проверка прав» осталась частью архитектуры безопасности. перед исполнением байт-код проходит верификацию: виртуальная машина отклоняет файл класса, нарушающий ограничения типовой системы.

- широкое применение: язык быстро занял несколько ниш. веб-апплеты были первым массовым сценарием: интерактивный фрагмент на странице, что для веба середины 1990-х было новым приёмом.

- серверные приложения: со временем java стала обычной платформой серверного кода. спецификация java ee, ныне jakarta ee, и каркас spring задали типовой стек корпоративного сервера.

- мобильные и встраиваемые системы: профиль java me распространил ту же модель на мобильные устройства и встроенные системы с ограниченными ресурсами.

- экосистема: вместе с языком сложились стандартная библиотека (java api), комплект jdk и сообщество разработчиков. за счёт этого язык быстро расходился по отраслям, а недостающие средства закрывались библиотеками. ядро языка при этом оставляли компактным.

- влияние на другие языки: модель java (управление памятью виртуальной машиной, переносимый промежуточный код, статическая типизация с классами) заметна в c#, kotlin и ряде других языков. кроссплатформенность через виртуальную машину и отказ от ручного освобождения памяти стали ориентиром для последующих промышленных языков.

- корпоративное применение: банки, финансовые организации и телекоммуникации взяли java как основу систем, от которых требуют длительной эволюции и предсказуемой работы под нагрузкой. решающими свойствами здесь оказались масштабируемость и устойчивость уже работающего кода.

в долгой перспективе java задала для промышленной разработки три ориентира: переносимость на уровне бинарного байт-кода, ограничения, снижающие класс ошибок памяти, и расчёт на широкий круг задач одним языком. язык по-прежнему занимает заметное место в разработке android, серверных систем и обработки больших массивов данных.

к текущему моменту выпущено много редакций. актуальной версией курса считается java 27, вышедшая в сентябре 2026 года. за это время java перестала быть только языком и стала платформой: язык, виртуальная машина, стандартная библиотека и набор сопутствующих спецификаций. на этой платформе собирают настольные программы, крупные веб-порталы и сервисы, а также программное обеспечение обычных компьютеров, планшетов, смартфонов и бытовой техники. отдельный масштаб задала мобильная ос android: большой корпус приложений для неё по-прежнему написан на java.

### особенности java

- платформенная независимость и переносимость: исходный текст сначала транслируется в байт-код, не привязанный к платформе, после чего байт-код выполняет jvm (java virtual machine). трансляция устроена в два шага. компилятор `javac` порождает файл класса. jvm исполняет его: интерпретирует байт-код и может компилировать часто выполняемые участки в машинный код процессора (jit-компиляция). у php и perl исполняется непосредственно исходный текст, отдельного стабильного промежуточного представления, которое переносят между машинами, нет. у c и c++ компилятор сразу порождает машинный код целевой архитектуры, поэтому бинарный файл привязан к платформе. у java между этими полюсами лежит файл класса: его переносят без перекомпиляции, а машинный код возникает уже на целевой jvm. для windows, linux, mac os и других систем существуют свои реализации jvm, и каждая из них обязана исполнять один и тот же байт-код.

- объектная ориентация: java является объектно-ориентированным языком со статической типизацией. поддерживаются полиморфизм и наследование реализации (один суперкласс) наряду с множественным наследованием интерфейсов. вызов метода экземпляра диспетчеризуется динамически, по фактическому классу объекта. такая модель рассчитана на крупные программы, которые расширяют, не переписывая уже согласованные контракты типов.

- синтаксис, знакомый по c и c++: набор управляющих конструкций, объявлений и выражений восходит к c и c++. разработчик, уже писавший на этих языках, узнаёт форму `if`, циклов, блоков и объявлений. жёсткая структура файла (пакет, импорт, тип, члены типа) делает текст предсказуемым при чтении.

- автоматическое управление памятью: объекты размещаются в куче, а освобождение выполняет сборщик мусора jvm. достижимость определяется по ссылкам из корней (стеки потоков, статические поля). объект, до которого не осталось пути по ссылкам, может быть утилизирован. программист не пишет явного освобождения, и целый класс ошибок (повторное освобождение, использование после освобождения) из языка уходит. утечки при этом не исключены полностью: объект остаётся жив, пока на него сохраняется ссылка, в том числе забытая в коллекции или статическом поле.

- надёжность: статическая система типов отсекает несогласованные присваивания на этапе компиляции. исключения задают отдельный канал сигнализации об ошибке, который нельзя молча проигнорировать у проверяемых исключений: метод либо обрабатывает их, либо объявляет в спецификации. проверки времени выполнения (границы массивов, приведение типов, разыменование) останавливают программу в определённой точке. в c та же ситуация может дать неопределённое поведение.

- безопасность: платформа содержит средства, ограничивающие, какой код какие ресурсы может задействовать. исторически это песочница апплетов и политика разрешений: недоверенный код исполнялся без произвольного доступа к файлам, сети и окружению. ту же задачу изоляции по-прежнему решают загрузчики классов и граница процесса операционной системы вокруг jvm.

- многопоточность: создание потоков, примитивы взаимного исключения и библиотека параллельных коллекций входят в саму платформу. сторонний пакет для базовой многопоточности не требуется. модель памяти java фиксирует, какие записи одного потока обязаны стать видимыми другому и какие перестановки операций допустимы. на многоядерном процессоре программа может держать несколько потоков исполнения внутри одного процесса jvm.

- стандартная библиотека: java api покрывает ввод-вывод, сети, доступ к базам данных, графический интерфейс, коллекции, время, рефлексию и ряд других типовых задач. класс и метод для такой задачи ищутся в спецификации платформы раньше, чем в сторонней библиотеке.

- сообщество и экосистема: вокруг языка накопились библиотеки, каркасы, средства сборки и публикации. готовая реализация типовой задачи сокращает объём кода, который приходится писать под конкретную систему.

### роль java

в текущей практике java остаётся языком, на котором держатся сразу несколько разных классов систем.

- корпоративные приложения: организации берут java для систем, которые годами расширяют и от которых ждут предсказуемой работы под нагрузкой. банковские контуры, системы планирования ресурсов предприятия (erp) и системы управления клиентами (crm) часто собраны на каркасах и спецификациях этой платформы. решают масштабируемость, предсказуемость среды выполнения и уже сложившаяся экосистема.

- веб-разработка: на java пишут серверную логику и, реже, серверную генерацию интерфейса. spring boot, jakarta ee (прежнее имя java ee) и play framework задают разные способы собрать веб-приложение. javaserver pages (jsp) и javaserver faces (jsf) остаются вариантами порождения динамической разметки на сервере.

- мобильная разработка (android): значительная часть приложений android по-прежнему написана на java. android studio, официальная среда разработки android, принимает и java, и kotlin. байт-код для android проходит собственную цепочку (исторически dalvik, ныне art), но язык и большая доля библиотек остаются теми же.

- большие данные и аналитика: apache hadoop реализован на java и служит основой распределённого хранения и пакетной обработки. apache spark исполняется на jvm; ядро spark написано на scala, при этом api и существенная часть экосистемы доступны из java. встроенная многопоточность и средства параллелизма java используются там, где обработка идёт несколькими потоками над большим объёмом данных.

- облачные вычисления: сервисы на java упаковывают в контейнеры и разворачивают в оркестраторах. kubernetes, docker и openshift принимают такие образы наравне с другими и позволяют масштабировать число экземпляров. переносимость байт-кода здесь совпадает с переносимостью контейнера: один и тот же образ запускают на разных узлах кластера.

- интернет вещей: облегчённые среды java me (java micro edition) и java embedded применяют на устройствах с ограниченными ресурсами. один язык перекрывает разные архитектуры процессоров, а средства разграничения прав остаются теми же, что и на сервере.

- искусственный интеллект и машинное обучение: в исследовательском и прикладном контуре этих задач преобладает python. java остаётся там, где модель встраивают в уже существующую корпоративную систему. библиотеки deeplearning4j и weka дают средства строить и исполнять модели, apache mahout содержит реализации алгоритмов, рассчитанных на масштабирование.

универсальность платформы, ограничения, снижающие класс ошибок памяти, и накопленная экосистема удерживают java в проектах от корпоративных систем до мобильных приложений, iot и облачного развёртывания.

### oracle jdk, openjdk и прочие jdk

для разработки нужен комплект jdk (java development kit): компилятор, средство запуска, стандартная библиотека и служебные утилиты. реализации jdk несколько, язык при этом один. две самые распространённые: **oracle jdk** и **openjdk**.

oracle jdk развивает компания oracle. **openjdk** является открытым проектом: его ведут сообщество и ряд компаний, среди которых oracle, red hat и другие. openjdk служит эталонной реализацией платформы java se. расхождение между сборками лежит прежде всего в лицензии и в условиях сопровождения. синтаксис языка у сборок общий. по условиям лицензии oracle jdk допускается бесплатное применение для личных нужд, а также для разработки, тестирования и демонстрации приложений. в остальных случаях, в том числе когда требуется сопровождение от oracle, нужна коммерческая лицензия в форме подписки. openjdk распространяется свободно.

по набору языковых средств и по составу стандартной библиотеки oracle jdk и openjdk совпадают: обе сборки следуют одной спецификации. относительно производительности и устойчивости долго держалось мнение, что oracle jdk работает несколько быстрее и ведёт себя стабильнее. oracle обязуется выпускать обновления в течение определённого срока. обновления openjdk зависят от того, какой поставщик их собирает и как долго сопровождает конкретную ветку. долговременное сопровождение непосредственно от oracle предоставляется за отдельную, заметную плату, и часть организаций из-за этого перешла на сборки openjdk. для изучения языка различие между этими реализациями несущественно: компилятор, запуск и семантика программ совпадают.

существуют и другие сборки. microsoft поставляет собственную. на части выпусков windows она может оказаться установленной по умолчанию, и тогда её каталог находится в `C:\Program Files\Microsoft`.

для этого курса безразлично, взят openjdk, jdk oracle, сборка microsoft или комплект другого поставщика. примеры рассчитаны на язык и на стандартную библиотеку, общие для всех этих сборок.
