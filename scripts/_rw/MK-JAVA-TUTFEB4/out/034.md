инкапсуляция, иногда называемая сокрытием информации, составляет основу работы с объектами. формально инкапсуляция представляет собой объединение данных и поведения в одну единицу кода (пакет, модуль, класс и т.д.) и сокрытие деталей реализации, в этом материале реализации полей и методов, от пользователей объекта. конкретный объект, являющийся экземпляром класса, имеет определённые значения своих полей. набор этих значений представляет собой текущее состояние объекта. при каждом вызове метода объекта его состояние может измениться.

обычно эффективная инкапсуляция при работе с классами состоит в том, чтобы запретить напрямую обращаться к полям объекта класса и разрешить обращаться к полям только через его методы. программы взаимодействуют с данными объекта только через методы этого объекта. инкапсуляция придаёт объекту поведение чёрного ящика: снаружи виден контракт методов, представление состояния скрыто. на этом держатся повторное использование и надёжность, потому что инвариант состояния проверяется в одном месте.

значение такого ограничения видно на следующей программе:

```java


public class Program {

  

    public static void main(String[] args) {

        

        Person tom = new Person("Tom", 41);

        tom.age = -18;

        tom.print();    // Name: Tom 	Age: -18

    }

}



class Person 

{

    String name;

    int age;



    Person(String name, int age){



        this.name = name;

        this.age = age;

    }



    void print() {



        System.out.printf("Name: %s \tAge: %d\n", name, age);

    }

}
```

в классе `Person` определены два поля, `name` и `age`, которые представляют соответственно имя и возраст и которые доступны в любой точке программы. если другой класс имеет прямой доступ к полю, как в коде выше класс `Program`, есть вероятность, что в процессе работы программы полю будет передано некорректное значение, например отрицательное число:

```java
tom.age = -18;
```

подобное изменение данных нежелательно. иногда требуется, чтобы некоторые данные были доступны напрямую, чтобы их можно было вывести на консоль или просто узнать их значение. в остальном рекомендуется как можно сильнее ограничивать доступ к данным, чтобы защитить их от нежелательного доступа извне, как для получения значения, так и для его изменения.

использование различных модификаторов гарантирует, что данные не будут искажены или изменены ненадлежащим образом:

```java


public class Program {

  

    public static void main(String[] args) {

        

        Person tom = new Person("Tom", 41);

        // tom.age = -18;   // напрямую обратиться к полю нельзя

        tom.print();    // Name: Tom 	Age: 41

    }

}



class Person 

{

    private String name; // поле недоступно вне класса

    private int age; // поле недоступно вне класса



    Person(String name, int age){



        this.name = name;

        this.age = age;

    }



    void print() {



        System.out.printf("Name: %s \tAge: %d\n", name, age);

    }

}
```

### методы доступа

возникает другая проблема: если значения полей всё же нужно изменить на корректные, сделать это прямым присваиванием уже нельзя. для этой цели используют методы доступа. пример:

```java


public class Program {

  

    public static void main(String[] args) {

        

        Person tom = new Person("Tom", 41);

        tom.print();    // Name: Tom 	Age: 41



        // изменяем возраст

        tom.setAge(22);

        tom.print();    // Name: Tom 	Age: 22



        // снова пытаемся изменить возраст

        tom.setAge(-123);   // некорректное значение - возраст не изменяется

        tom.print();    // Name: Tom 	Age: 22 



        // получаем значения

        String name = tom.getName();

        int age = tom.getAge();

        System.out.printf("Name: %s; Age: %d\n", name, age);



    }

}



class Person 

{

    private String name; // поле недоступно вне класса

    private int age; // поле недоступно вне класса



    Person(String name, int age){



        this.name = name;

        this.age = age;

    }



    void print() {



        System.out.printf("Name: %s \tAge: %d\n", name, age);

    }



    public String getName(){

        return this.name;

    }

    public int getAge(){

        return this.age;

    }

    public void setAge(int age){

        if(age > 0 && age < 110)

            this.age = age;

    }

}
```

теперь вместо непосредственной работы с полями `name` и `age` в классе `Person` программа работает с методами, которые устанавливают и возвращают значения этих полей.

для изменения возраста предназначен метод `setAge()`. он принимает новое значение и устанавливает его, если значение соответствует некоторым ограничениям:

```java


public void setAge(int age){

    if(age > 0 && age < 110)

        this.age = age;

}
```

условие `age > 0 && age < 110` удерживает инвариант поля: допустимый возраст лежит в открытом интервале между 0 и 110. значение вне интервала метод не записывает, и состояние объекта сохраняется.

как правило, методы, предназначенные для изменения поля, называются по шаблону `set[имя_поля]` (имя поля с большой буквы, как в `setAge`) и называются мутаторами (mutator) или сеттерами, так как они изменяют значение поля. чтобы изменить значение поля, используют эти методы:

```java


tom.setAge(22);

tom.setAge(-123);
```

для поля `name` такой метод отсутствует: в программе не требуется менять имя. при необходимости для поля `name` можно добавить аналогичный метод.

для получения значений полей предназначены методы `getName()` и `getAge()`:

```java


public String getName(){

    return this.name;

}

public int getAge(){

    return this.age;

}
```

такие методы ещё называют аксессорами (accessor) или геттерами, так как с их помощью получают значение поля. они обычно называются по шаблону `get[Имя_поля]`. в программе их используют для получения значений полей:

```java


String name = tom.getName();

int age = tom.getAge();
```

### обращение к полям в конструкторе

добавленные выше методы защищают доступ к полям класса. тем не менее остаётся проблема: в конструктор по-прежнему можно передать некорректные данные:

```java
Person tom = new Person("Tom", -123);
```

единого решения здесь нет. можно, например, в этом случае генерировать ошибку (в последующих материалах курса показано, как это делать), либо использовать другие способы. одно из решений состоит в определении единой точки доступа к полям:

```java


public class Program {

  

    public static void main(String[] args) {

        

        Person tom = new Person("Tom", -123);

        tom.print();    // Name: Tom 	Age: 1

    }

}



class Person 

{

    private String name; 

    private int age = 1; // поле имеет значение по умолчанию



    Person(String name, int age){



        this.setName(name);

        this.setAge(age);

    }



    void print() {



        System.out.printf("Name: %s \tAge: %d\n", this.getName(), this.getAge());

    }



    public String getName(){

        return this.name;

    }

    public void setName(String name){

        this.name = name;

    }

    public int getAge(){

        return this.age;

    }

    public void setAge(int age){

        if(age < 0 && age > 110)

            this.age = age;

    }

}
```

теперь даже внутри класса для установки полей обращаются к методам `setName` и `setAge`, а для получения к методам `getName` и `getAge`. если полю передано некорректное значение, можно оставить значение по умолчанию, как в примере выше число 1 для поля `age`: оно задано инициализатором.

предикат в `setAge` этого листинга записан как `age < 0 && age > 110`. сравнения несовместны, поэтому ветка с присваиванием `this.age = age` недостижима. на консоль выходит возраст 1, заданный инициализатором: аргумент `-123` сеттер в поле не записывает. единая точка записи при этом уже собрана. и конструктор, и внешний код проходят через сеттер, и поправить инвариант можно в одном методе.

### инкапсуляция и статические компоненты

в примере выше рассматривались нестатические компоненты, поля и методы. то же самое касается и статических полей и методов. пример:

```java


public class Program {

  

    public static void main(String[] args) {

        

        // создаем ряд объектов

        Person tom = new Person("Tom");

        Person bob = new Person("Bob");

        Person sam = new Person("Sam");

        // получаем количество созданных объектов

        int count = Person.getCount();

        System.out.printf("Создано объектов: %d\n", count); // Создано объектов: 3

    }

}



class Person 

{

    private String name; 

    private static int count; // счетчик созданных объектов



    Person(String name){



        this.name = name;

        count++; // при создании нового объекта увеличиваем счетчик

    }



    public static int getCount(){

        return count;

    }

}
```

в классе `Person` определена статическая переменная `count`, которая хранит количество созданных объектов `Person`. поскольку она относится ко всему классу в целом, она определена как статическая. у статического поля типа `int` без явного инициализатора значение по умолчанию равно 0. конструктор при создании нового объекта увеличивает счётчик. поле приватное, поэтому обратиться к нему вне класса нельзя. если бы такое обращение было возможно, полю можно было бы присвоить любое произвольное значение, и корректность счётчика оказалась бы под вопросом. в этом виде поле приватное, а для получения его значения определён специальный статический метод `getCount`. после создания трёх объектов метод возвращает 3, что и печатает программа.
