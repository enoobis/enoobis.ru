класс `Phaser` позволяет синхронизировать потоки, которые представляют отдельную фазу или стадию общего действия. объект синхронизации ждёт, пока не завершится определённая фаза. затем `Phaser` переходит к следующей стадии и снова ожидает её завершения.

для создания объекта используется один из конструкторов:

```java


Phaser()

Phaser(int parties)

Phaser(Phaser parent)

Phaser(Phaser parent, int parties)
```

параметр `parties` указывает количество участников, которые должны выполнять все фазы действия. участник здесь регистрация, а не обязательно отдельный объект `Thread`: фаза считается завершённой по счётчику регистраций, и один поток может держать несколько из них. первый конструктор создаёт `Phaser` без участников. второй регистрирует переданное в конструктор количество. третий и четвёртый также устанавливают родительский объект `Phaser`. если родитель задан и число участников больше нуля, дочерний синхронизатор регистрируется у родителя. иерархия нужна, когда участников много: группы сходятся на своих узлах, родитель наблюдает продвижение групп, и ожидание не собирается на одном объекте.

основные методы класса `Phaser`:

- `int register()`: регистрирует участника, который выполняет фазы, и возвращает номер текущей фазы. обычно у нового объекта это фаза 0

- `int arrive()`: сообщает, что участник завершил фазу, и возвращает номер текущей фазы. поток при этом не ждёт остальных

- `int arriveAndAwaitAdvance()`: аналогичен `arrive` и дополнительно заставляет `Phaser` ждать завершения фазы всеми остальными участниками. после полного набора прибытий фаза продвигается

- `int arriveAndDeregister()`: сообщает о завершении всех фаз участником и снимает его с регистрации. возвращает номер текущей фазы или отрицательное число, если синхронизатор `Phaser` завершил свою работу

- `int getPhase()`: возвращает номер текущей фазы

при работе с классом обычно сначала создаётся его объект. далее регистрируются все участники. для каждого вызывается `register()`, либо нужное количество передаётся в конструктор, и отдельный вызов не требуется. затем каждый участник выполняет набор действий, составляющих фазу. синхронизатор ждёт, пока все участники не завершат фазу. чтобы сообщить о завершении, участник вызывает `arrive()` или `arriveAndAwaitAdvance()`. после этого синхронизатор переходит к следующей фазе.

применение в приложении:

```java


import java.util.concurrent.Phaser;



public class Program {



    public static void main(String[] args) {

        

        Phaser phaser = new Phaser(1);

        new Thread(new PhaseThread(phaser, "PhaseThread 1")).start();

        new Thread(new PhaseThread(phaser, "PhaseThread 2")).start();

        

        // ждем завершения фазы 0

        int phase = phaser.getPhase();

        phaser.arriveAndAwaitAdvance();

        System.out.println("Фаза " + phase + " завершена");

        // ждем завершения фазы 1

        phase = phaser.getPhase();

        phaser.arriveAndAwaitAdvance();

        System.out.println("Фаза " + phase + " завершена");

        

        // ждем завершения фазы 2

        phase = phaser.getPhase();

        phaser.arriveAndAwaitAdvance();

        System.out.println("Фаза " + phase + " завершена");

        

        phaser.arriveAndDeregister();

    }

}



class PhaseThread implements Runnable{

    

    Phaser phaser;

    String name;



    PhaseThread(Phaser p, String n){

        

        this.phaser=p;

        this.name=n;

        phaser.register();

    }

    public void run(){

        

        System.out.println(name + " выполняет фазу " + phaser.getPhase());

        phaser.arriveAndAwaitAdvance(); // сообщаем, что первая фаза достигнута

        

        System.out.println(name + " выполняет фазу " + phaser.getPhase());

        phaser.arriveAndAwaitAdvance(); // сообщаем, что вторая фаза достигнута



        System.out.println(name + " выполняет фазу " + phaser.getPhase());

        phaser.arriveAndDeregister(); // сообщаем о завершении фаз и удаляем с регистрации объекты 

    }

}
```

фазы выполняются тремя участниками: главным потоком и двумя потоками `PhaseThread`. при создании объекта передаётся число 1, регистрация главного потока. в конструкторе `PhaseThread` вызывается `register()`. вызов происходит ещё в главном потоке, до `start()`: регистрация увеличивает счётчик участников и не обязана выполняться в том потоке, который потом войдёт в `run()`. к началу работы сторон три. без `register()` тот же состав задаётся конструкцией `Phaser phaser = new Phaser(3)`.

фаза для каждого участника здесь минимальна. для потоков `PhaseThread` это вывод сообщения, для главного потока это чтение текущей фазы методом `getPhase()`. отсчёт фаз начинается с нуля. каждый участник завершает фазу вызовом `phaser.arriveAndAwaitAdvance()`. пока последний участник не завершит текущую фазу, все уже прибывшие заблокированы. когда прибытия собраны, номер фазы увеличивается, и ожидавшие продолжают.

после завершения последней фазы регистрация всех участников снимается методом `arriveAndDeregister()`. когда зарегистрированных не остаётся, срабатывает стандартное правило `Phaser`: синхронизатор завершает работу.

итог работы программы:

```consoletext


PhaseThread 1 выполняет фазу 0

PhaseThread 2 выполняет фазу 0

PhaseThread 1 выполняет фазу 1

PhaseThread 2 выполняет фазу 1

Фаза 0 завершена

Фаза 1 завершена

PhaseThread 1 выполняет фазу 2

PhaseThread 2 выполняет фазу 2

Фаза 2 завершена
```

вывод легко читается неверно: сообщение о выполнении фазы 1 может выйти после сообщения об окончании фазы 0, а может и раньше него. связь с многопоточностью прямая. фаза уже завершилась, но в одном потоке ещё не напечатано сообщение о завершении, тогда как другие потоки уже начали следующую фазу. барьер упорядочивает переход, а не последующие вызовы печати. чей `println` выполнится раньше, решает планировщик. всё это происходит уже после завершения фазы.

чтобы порядок строк был нагляднее, после продвижения фазы в потоках ставят паузу:

```java


public void run(){

        

        System.out.println(name + " выполняет фазу " + phaser.getPhase());

        phaser.arriveAndAwaitAdvance(); // сообщаем, что первая фаза достигнута

        try{

            Thread.sleep(200);

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        

        System.out.println(name + " выполняет фазу " + phaser.getPhase());

        phaser.arriveAndAwaitAdvance(); // сообщаем, что вторая фаза достигнута

        try{

            Thread.sleep(200);

        }

        catch(InterruptedException ex){

            System.out.println(ex.getMessage());

        }

        System.out.println(name + " выполняет фазу " + phaser.getPhase());

        phaser.arriveAndDeregister(); // сообщаем о завершении фаз и удаляем с регистрации объекты 

    }
```

пауза не меняет работу фаз. `Thread.sleep(200)` не участвует в подсчёте прибытий. она задерживает печать в `PhaseThread`, и сообщение главного потока о закрытой фазе успевает появиться раньше. вывод становится привычнее по порядку номеров:

```consoletext


PhaseThread 1 выполняет фазу 0

PhaseThread 2 выполняет фазу 0

Фаза 0 завершена

PhaseThread 2 выполняет фазу 1

PhaseThread 1 выполняет фазу 1

Фаза 1 завершена

PhaseThread 2 выполняет фазу 2

PhaseThread 1 выполняет фазу 2

Фаза 2 завершена
```

на правила продвижения фаз этот `sleep` не влияет.
