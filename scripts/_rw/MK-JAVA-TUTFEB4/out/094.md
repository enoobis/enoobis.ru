многопоточность выделяет в процессе несколько потоков исполнения. потоки платформы разделяют кучу и держат отдельные стеки вызовов. длительная работа в потоке, который обслуживает интерфейс, останавливает разбор событий на всё время этой работы. запрос к серверу или чтение и разбор большого файла в том же потоке замораживают отрисовку и ввод. перенос такой работы в отдельный поток оставляет поток интерфейса свободным. поэтому прикладные программы с сетью, диском и интерфейсом строятся на нескольких потоках.

с версии 21 в языке два вида потоков. поток платформы (platform thread) предоставляет операционная система, она же планирует его выполнение. виртуальный поток (virtual thread) выполняется на потоке платформы, а планирует его среда выполнения java.

сколько потоков платформы реально идёт параллельно, определяет аппаратура. ядро в каждый момент исполняет один аппаратный поток, а при одновременной многопоточности обычно два. если потоков платформы больше, чем таких контекстов, операционная система выделяет каждому квант времени. когда квант исчерпан, система вытесняет поток и даёт исполняться другому.

в java за потоки отвечает класс `Thread`. новый поток начинает существование как объект этого класса. создают его явно. при запуске программы виртуальная машина поднимает главный поток и вызывает в нём `main()`. остальные потоки порождаются уже из этого потока.

### получение текущего потока

статический метод `Thread.currentThread()` возвращает объект `Thread` того потока, который выполняет вызов:

```java


public class Program {

  

    public static void main(String[] args) {

          

        // получаем текущий поток

        Thread t = Thread.currentThread(); 

        System.out.println(t); // Thread[#3,main,5,main]

    }

}
```

вызов стоит в `main`, поэтому в `t` попадает главный поток. печать идёт через `toString()`. строка выглядит так:

```bash
Thread[#3,main,5,main]
```

формат этой строки задаёт `toString()`:

```java
идентификатор_потока, имя_потока, приоритет, группа потока
```

разбор вывода:

- идентификатор потока: 3

- имя потока: `main`

- приоритет потока: 5

- группа потока: `main`

число в первой позиции это `threadId()`. оно зависит от того, сколько потоков среда уже создала к моменту входа в `main`, и в другом запуске может быть иным. имя, приоритет и группа главного потока стабильны: `main`, значение `NORM_PRIORITY` (5) и группа `main`.

`Thread.getAllStackTraces()` возвращает `Map<Thread, StackTraceElement[]>`: ключ это активный поток, значение это снимок его стека. множество ключей перечисляет потоки, для которых виртуальная машина сняла трассировку, без разбора самих кадров.

```java


public class Program {

  

    public static void main(String[] args) {

          

        // получаем только потоки без трасировки стека

        var threads = Thread.getAllStackTraces().keySet(); 



        for(var thread : threads){

            System.out.println(thread); 

        }

    }

}
```

набор строк зависит от версии jdk и от того, какие подсистемы уже инициализированы. типичный вывод:

```bash


Thread[#3,main,5,main]

Thread[#15,Reference Handler,10,system]

Thread[#16,Finalizer,8,system]

Thread[#32,Notification Thread,9,system]

Thread[#17,Signal Dispatcher,9,system]

Thread[#33,Common-Cleaner,8,InnocuousThreadGroup]
```

рядом с `main` видны служебные потоки среды выполнения. спецификация их состав не фиксирует. для программы важен сам приём: ключи карты дают живые потоки на момент вызова.

### получение информации о потоках

у `Thread` есть методы чтения состояния и методы управления исполнением. чтение и установка свойств:

- `String getName()`: возвращает имя потока

- `void setName(String name)`: устанавливает имя потока

- `int getPriority()`: возвращает приоритет потока

- `void setPriority(int newPriority)`: устанавливает приоритет потока платформы. аргумент лежит в диапазоне от 1 до 10, иначе метод выбрасывает `IllegalArgumentException`. приоритет входит в эвристики планировщика и жёсткий порядок исполнения не задаёт. главному потоку при создании выставляется средний приоритет 5, константа `NORM_PRIORITY`

- `StackTraceElement[] getStackTrace()`: возвращает снимок стека потока, массив кадров `StackTraceElement`

- `void setDaemon(boolean on)`: помечает поток демоном. вызов допустим до `start()`. после запуска метод выбрасывает `IllegalThreadStateException`. демон не удерживает виртуальную машину: она завершает работу, когда не осталось живых потоков помимо демонов

- `boolean isAlive()`: возвращает `true`, если поток уже запущен и ещё не завершился. для состояний `NEW` и `TERMINATED` результат ложен

- `boolean isInterrupted()`: возвращает `true`, если у потока выставлен флаг прерывания. флаг метод не сбрасывает

- `boolean isDaemon()`: возвращает `true`, если поток демонический

- `boolean isVirtual()`: возвращает `true`, если поток виртуальный

- `long threadId()`: возвращает идентификатор потока. значение положительное и за время жизни объекта не меняется. метод заменяет устаревший `getId()`: `threadId()` финальный, переопределить его нельзя

управление исполнением:

- `void join()`: текущий поток ждёт завершения того потока, на котором метод вызван

- `void run()`: содержит код, который выполнит поток. прямой вызов `run()` исполняет тело в текущем потоке и новый поток не порождает

- `static void sleep(long millis)`: приостанавливает текущий поток не менее чем на заданное число миллисекунд

- `void start()`: переводит поток из `NEW` в очередь на исполнение, после чего `run()` выполняется уже в этом потоке. повторный `start()` выбрасывает `IllegalThreadStateException`

- `static Thread startVirtualThread(Runnable task)`: создаёт виртуальный поток с телом `task` и ставит его в очередь на запуск

свойства главного потока читаются так:

```java


public class Program {

  

    public static void main(String[] args) {

          

        // получаем текущий поток

        Thread t = Thread.currentThread(); 

        // получаем его свойства



        System.out.println("Id: " + t.threadId()); 

        System.out.println("Name: " + t.getName()); 

        System.out.println("Priority: " + t.getPriority()); 

        System.out.println("State: " + t.getState()); 

        System.out.println("isAlive: " + t.isAlive()); 

        System.out.println("isDaemon: " + t.isDaemon()); 

        System.out.println("isVirtual: " + t.isVirtual()); 

    }

}
```

консольный вывод:

```bash


Id: 3

Name: main

Priority: 5

State: RUNNABLE

isAlive: true

isDaemon: false

isVirtual: false
```

`getState()` возвращает `RUNNABLE`: с точки зрения виртуальной машины главный поток исполняется. `isAlive()` истинно. демоном поток не является, `isVirtual()` ложно, потому что `main` это поток платформы.

ниже разобраны состояние и приоритет.

### состояние потоков

перечисление `Thread.State` задаёт шесть состояний. в любой момент поток находится ровно в одном из них. это состояния виртуальной машины. набор грубее состояний планировщика операционной системы: готовность, исполнение на ядре и ожидание ввода-вывода система может различать внутри одного значения `RUNNABLE`.

- `NEW`: объект создан, `start()` ещё не вызывался

- `RUNNABLE`: с точки зрения виртуальной машины поток исполняется или готов к исполнению. отдельной константы для факта «сейчас занимает ядро» в перечислении нет, оба случая сведены сюда

- `BLOCKED`: поток ждёт монитор, чтобы войти в `synchronized` или войти в него снова после `Object.wait`

- `WAITING`: поток ждёт без предела по времени. так устроены `Object.wait()` без тайм-аута, `Thread.join()` без тайм-аута и `LockSupport.park`

- `TIMED_WAITING`: то же ожидание с предельным сроком. сюда попадают `Thread.sleep`, `Object.wait(long)`, `Thread.join(long)`, `LockSupport.parkNanos` и `LockSupport.parkUntil`

- `TERMINATED`: выполнение `run()` закончилось, обычным возвратом или исключением

### приоритеты потоков

у каждого потока есть приоритет, целое от 1 до 10. для границ и значения по умолчанию объявлены константы:

- `MIN_PRIORITY`: минимальный приоритет, число 1

- `MAX_PRIORITY`: максимальный приоритет, число 10

- `NORM_PRIORITY`: обычный приоритет, число 5

новый поток наследует приоритет создателя. у потока платформы приоритет меняют методом `setPriority`. аргумент лежит между `MIN_PRIORITY` и `MAX_PRIORITY` включительно.

когда планировщик операционной системы выбирает следующий поток платформы, более высокий приоритет повышает шанс получить квант. десять логических уровней java отображаются на уровни платформы, и это отображение зависит от системы. для потока платформы планировщиком остаётся операционная система, виртуальная машина только переводит логический приоритет в уровень этой системы.

в windows уровни, на которые опирается виртуальная машина, сводятся к семи относительным приоритетам win32, поэтому разные числа java могут попасть на один и тот же уровень системы. в openjdk для linux при политике по умолчанию приоритеты java игнорируются. класс планирования `SCHED_OTHER` не даёт непривилегированному процессу статически задать приоритет, и такие потоки остаются равноправными. в ранних виртуальных машинах, которые не сажались на потоки операционной системы, приоритеты влияли на планирование сильнее. в современном коде порядок исполнения потоков платформы приоритетами не регулируют.

виртуальные потоки для совместимости держат фиксированный приоритет `NORM_PRIORITY`. `setPriority` на виртуальном потоке эффекта не имеет. у главного потока приоритет по умолчанию тоже 5.
