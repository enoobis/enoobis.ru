очередь хранит элементы по дисциплине fifo (first in, first out). чем раньше элемент добавлен, тем раньше он из очереди удаляется. вставка идёт в хвост, изъятие идёт из головы. это модель однонаправленной очереди. двунаправленная очередь умеет больше: элемент добавляется и в начало, и в конец, а удаляется и с конца, и с начала.

классы очередей реализуют интерфейс `Queue` или интерфейс `Deque`.

### интерфейс queue

обобщённый интерфейс `Queue` расширяет `Collection` и фиксирует поведение однонаправленной очереди. операции такие:

- `E element()`: возвращает, но не удаляет элемент из начала очереди. если очередь пуста, генерирует `NoSuchElementException`

- `boolean offer(E obj)`: добавляет элемент obj в конец очереди. если элемент добавлен, возвращает true, иначе false

- `E peek()`: возвращает без удаления элемент из начала очереди. если очередь пуста, возвращает `null`

- `E poll()`: возвращает с удалением элемент из начала очереди. если очередь пуста, возвращает `null`

- `E remove()`: возвращает с удалением элемент из начала очереди. если очередь пуста, генерирует `NoSuchElementException`

у любой реализации есть `offer` для добавления в хвост, `poll` для извлечения с головы и пара `peek` и `element`, которая только читает голову.

одну и ту же операцию `Queue` выражает двумя методами. один при неудаче генерирует исключение, другой возвращает специальное значение: признак успеха или `null`. сводка:

|  | генерирует исключение | возвращает значение |
| --- | --- | --- |
| вставка | add(e) | offer(e) |
| удаление | remove() | poll() |
| получение | element() | peek() |

`add` описан ещё в `Collection`, а у `Queue` его контракт уточнён. если вместимость ограничена и место кончилось, `add` завершается `IllegalStateException`, а `offer` возвращает false. `remove` и `element` на пустой очереди бросают `NoSuchElementException`. `poll` и `peek` в той же ситуации возвращают `null`. поэтому `null` от этих двух методов означает пустую очередь. реализация, которая разрешает хранить `null` (так устроен `LinkedList`), делает ответ неоднозначным: пустая очередь и хранимый `null` выглядят одинаково. `ArrayDeque` и `PriorityQueue` элементы `null` не принимают.

### интерфейс deque

`Deque` (сокращение от double ended queue) расширяет `Queue` и задаёт двунаправленную очередь. та же структура работает как обычная однонаправленная очередь и как стек с дисциплиной lifo (last in, first out): последний вошедший выходит первым.

методы `Deque`:

- `void addFirst(E obj)`: добавляет элемент в начало очереди (унаследован от `SequencedCollection`)

- `void addLast(E obj)`: добавляет элемент obj в конец очереди (унаследован от `SequencedCollection`)

- `E getFirst()`: возвращает без удаления элемент из головы очереди. если очередь пуста, генерирует `NoSuchElementException` (унаследован от `SequencedCollection`)

- `E getLast()`: возвращает без удаления последний элемент очереди. если очередь пуста, генерирует `NoSuchElementException` (унаследован от `SequencedCollection`)

- `boolean offerFirst(E obj)`: добавляет элемент obj в самое начало очереди. если элемент добавлен, возвращает true, иначе false

- `boolean offerLast(E obj)`: добавляет элемент obj в конец очереди. если элемент добавлен, возвращает true, иначе false

- `E peekFirst()`: возвращает без удаления элемент из начала очереди. если очередь пуста, возвращает `null`

- `E peekLast()`: возвращает без удаления последний элемент очереди. если очередь пуста, возвращает `null`

- `E pollFirst()`: возвращает с удалением элемент из начала очереди. если очередь пуста, возвращает `null`

- `E pollLast()`: возвращает с удалением последний элемент очереди. если очередь пуста, возвращает `null`

- `E pop()`: возвращает с удалением элемент из начала очереди. если очередь пуста, генерирует `NoSuchElementException`

- `void push(E element)`: добавляет элемент в самое начало очереди

- `E removeFirst()`: возвращает с удалением элемент из начала очереди. если очередь пуста, генерирует `NoSuchElementException` (унаследован от `SequencedCollection`)

- `E removeLast()`: возвращает с удалением элемент из конца очереди. если очередь пуста, генерирует `NoSuchElementException` (унаследован от `SequencedCollection`)

- `boolean removeFirstOccurrence(Object obj)`: удаляет первый встреченный элемент obj из очереди. если удаление произошло, возвращает true, иначе false

- `boolean removeLastOccurrence(Object obj)`: удаляет последний встреченный элемент obj из очереди. если удаление произошло, возвращает true, иначе false

`push` и `pop` дают поведение стека. вершина стека совпадает с головой очереди: `push` вставляет в самое начало, `pop` снимает начало и на пустой очереди бросает `NoSuchElementException`. по контракту `push` совпадает с `addFirst`, `pop` совпадает с `removeFirst`. доступ к хвосту при этом сохраняется, поэтому класс, реализующий `Deque`, остаётся двунаправленной очередью и одновременно годится как стек. начиная с java 21 интерфейс расширяет и `Queue`, и `SequencedCollection`: методы концов последовательности на двунаправленной очереди и есть голова и хвост.

пары методов устроены так же, как у `Queue`. неудача операции либо генерирует исключение, либо возвращает специальное значение.

|  | первый элемент (head) | последний элемент (tail) |  |  |
| --- | --- | --- | --- | --- |
| генерация исключения | возвращение значения | генерация исключения | возвращение значения |  |
| вставка | addFirst(e) | offerFirst(e) | addLast(e) | offerLast(e) |
| удаление | removeFirst() | pollFirst() | removeLast() | pollLast() |
| получение | getFirst() | peekFirst() | getLast() | peekLast() |

методы `Queue` выражаются через методы `Deque`. вставка однонаправленной очереди пишет в хвост, удаление и чтение берут голову:

| метод `Queue` | метод `Deque` |
| --- | --- |
| add(e) | addLast(e) |
| offer(e) | offerLast(e) |
| remove() | removeFirst() |
| poll() | pollFirst() |
| element() | getFirst() |
| peek() | peekFirst() |

### класс arraydeque

очередь в java представлена несколькими классами. один из них: `ArrayDeque`. это обобщённая двунаправленная очередь. класс наследует `AbstractCollection` и реализует `Deque`.

конструкторы `ArrayDeque`:

- `ArrayDeque()`: создаёт пустую очередь

- `ArrayDeque(Collection col)`: создаёт очередь, наполненную элементами из коллекции col

- `ArrayDeque(int capacity)`: создаёт очередь с начальной ёмкостью capacity. если начальная ёмкость не указана, она равна 16

элементы лежат в кольцевом буфере. пока в массиве есть место, оба конца сдвигаются за постоянное время, поэтому очередь и стек на `ArrayDeque` обычно быстрее списка на ссылках. когда места не хватает, выделяется больший массив, и ссылки раскладываются заново. отдельного потолка вместимости нет: `offer` при успешной вставке возвращает true, а отказ по заполненности эта реализация не использует. `null` отклоняется, возникает `NullPointerException`: иначе `peek` и `poll` не отличали бы пустую очередь от элемента. класс не синхронизирован. общий экземпляр из нескольких потоков без внешней блокировки даёт гонку.

добавление в `ArrayDeque`:

```java


import java.util.ArrayDeque;

 

public class Program{

      

    public static void main(String[] args) {

          

        ArrayDeque<String> people = new ArrayDeque<String>();

        System.out.println(people);      // []

          

        // добавим ряд элементов

        people.add("Tom");              // [Tom]

        people.add("Bob");              // [Tom, Bob]

        // добавляем элемент в самое начало

        people.push("Sam");             // [Sam, Tom, Bob]

        // добавляем элемент в самое начало

        people.addFirst("Alice");       // [Alice, Sam, Tom, Bob]

        // добавляем элемент в конец коллекции

        people.addLast("Kate");         // [Alice, Sam, Tom, Bob, Kate]



        // добавляем элемент в самое начало

        people.offerFirst("Alex");       // [Alex, Alice, Sam, Tom, Bob]

        // добавляем элемент в конец коллекции

        people.offerLast("Bill");         // [Alex, Alice, Sam, Tom, Bob, Kate, Bill]

        // добавляем элемент в конец коллекции

        people.offer("Tim");            // [Alex, Alice, Sam, Tom, Bob, Kate, Bill, Tim]



        // выводим все

        System.out.println(people);      // [Alex, Alice, Sam, Tom, Bob, Kate, Bill, Tim]

    }

}
```

пример копит строки и после операций печатает очередь целиком. пустая очередь выглядит как `[]`. `add` и `addLast` ставят элемент в хвост. `push` и `addFirst` ставят элемент в голову. `offerFirst` тоже пишет в голову и возвращает признак успеха. `offerLast` и `offer` пишут в хвост. печать идёт от головы к хвосту, голова слева. комментарий у `offerFirst` теряет kate и показывает `[Alex, Alice, Sam, Tom, Bob]`, хотя вставка в голову хвост не стирает. следующая строка, `offerLast`, снова содержит kate. итоговая печать совпадает с фактическим составом: `[Alex, Alice, Sam, Tom, Bob, Kate, Bill, Tim]`.

удаление элементов из `ArrayDeque`:

```java


import java.util.ArrayDeque;

import java.util.Collections;

 

public class Program{

      

    public static void main(String[] args) {

          

        ArrayDeque<String> people = new ArrayDeque<String>();

        // добавляем ряд объектов

        Collections.addAll(people, new String[]{ "Alex", "Alice", "Sam", "Tom", "Bob", "Kate", "Bill", "Tim"});

        System.out.println(people);      // [Alex, Alice, Sam, Tom, Bob, Kate, Bill, Tim]



        // удаляем элемент из начала

        var person = people.poll();

        System.out.println(person);      // Alex



        // удаляем элемент из начала в [Alice, Sam, Tom, Bob, Kate, Bill, Tim]

        person = people.poll();

        System.out.println(person);      // Alice



        // удаляем элемент из конца в [Sam, Tom, Bob, Kate, Bill, Tim]

        person = people.pollLast();

        System.out.println(person);      // Tim



        // удаляем элемент из начала  в [Sam, Tom, Bob, Kate, Bill]

        person = people.remove();

        System.out.println(person);      // Sam



        // удаляем элемент из начала в [Tom, Bob, Kate, Bill]

        person = people.removeFirst();

        System.out.println(person);      // Tom



        // удаляем элемент из конца в [Bob, Kate, Bill]

        person = people.removeLast();

        System.out.println(person);      // Bill



        // удаление произвольного элемента из [Bob, Kate]

        boolean removed = people.remove("Kate");

        System.out.println("Kate is removed: " + removed);  // Kate is removed: true

        // удаление произвольного элемента из [Bob]

        removed = people.remove("Charl");

        System.out.println("Charl is removed: " + removed);  // Charl is removed: false



        

        // выводим оставшиеся

        System.out.println(people);      // [Bob]



        people.clear();

        // удаляем оставшиеся

        System.out.println(people);      // [Bob]

    }

}
```

`Collections.addAll` заполняет очередь тем же набором, с alex в голове и tim в хвосте. дальше концы снимаются по очереди. первый `poll` забирает голову и возвращает alex, второй `poll` возвращает alice. `pollLast` забирает хвост и возвращает tim. `remove` и `removeFirst` снова снимают голову: sam, затем tom. на пустой очереди оба бросили бы `NoSuchElementException`, `poll` в той же ситуации вернул бы `null`. `removeLast` снимает текущий хвост, bill. `remove(Object)` удаляет первое вхождение по `equals`: для kate результат true, для отсутствующего имени charl результат false. перед `clear` в очереди остаётся bob. `clear` удаляет оставшиеся элементы, очередь становится пустой. комментарий у печати после `clear` по-прежнему написан как `[Bob]`. фактическая печать пустой очереди: `[]`.

получение элементов из очереди:

```java


import java.util.ArrayDeque;

import java.util.Collections;

 

public class Program{

      

    public static void main(String[] args) {

          

        ArrayDeque<String> people = new ArrayDeque<String>();

        // добавляем ряд объектов

        Collections.addAll(people, new String[]{"Tom", "Bob", "Sam"});



        // получаем элемент из начала

        var first = people.element();

        System.out.println(first);      // Tom



        first = people.peek();

        System.out.println(first);      // Tom



        first = people.peekFirst();

        System.out.println(first);      // Tom



        first = people.getFirst();

        System.out.println(first);      // Tom





        // получаем элемент из конца

        var last = people.getLast();

        System.out.println(last);      // Sam



        last = people.peekLast();

        System.out.println(last);      // Sam



        // проверка наличия

        boolean available = people.contains("Tom");

        System.out.println("Tom is avalable: " + available);      // true

        available = people.contains("Alex");

        System.out.println("Alex is avalable: " + available);      // false







        // перебор без извлечения

        for(var p : people){

          

            System.out.println(p);

        }



        // перебор коллекции с извлечением      

        while(people.peek() != null){

            // извлечение c начала

            System.out.println(people.pop());

        }

    }

}
```

в очереди три строки: tom в голове, затем bob, sam в хвосте. голову без удаления читают четыре метода: `element`, `peek`, `peekFirst` и `getFirst`. на непустой очереди каждый возвращает tom. различие проявляется на пустой: `element` и `getFirst` бросают `NoSuchElementException`, `peek` и `peekFirst` возвращают `null`. хвост без удаления читают `getLast` и `peekLast`, оба возвращают sam. `contains` проверяет наличие по `equals`: true для tom, false для alex. цикл for-each обходит элементы от головы к хвосту и ничего не извлекает. цикл с условием `people.peek() != null` забирает элементы через `pop`, то есть снимает вершину стека, пока голова существует. порядок извлечения: tom, bob, sam. после цикла очередь пуста. условие завязано на `null`, который `peek` отдаёт у пустой очереди. хранимый `null` сделал бы тот же цикл двусмысленным, и `ArrayDeque` такие элементы отклоняет.

### очереди приоритетов priorityqueue

очередь приоритетов, класс `PriorityQueue`, отдаёт элементы по заданному порядку. при каждом чтении или удалении с головы приходит наименьший элемент этого порядка. остальные элементы очередь при этом целиком не сортирует. обход итератором и печать коллекции не дают отсортированный ряд: элементы могут лежать так, как их держит куча.

куча: самоорганизующееся двоичное дерево. вставка и удаление переставляют узлы так, чтобы наименьший элемент оказался в корне, и не выстраивают все элементы в отсортированный ряд. в `PriorityQueue` куча уложена в массив. у узла с индексом i левый ребёнок лежит в `2i + 1`, правый в `2i + 2`, корень имеет индекс 0. родитель в мин-куче не больше своих детей. `peek` читает корень за постоянное время. `offer` и `poll` восстанавливают свойство кучи. стоимость пропорциональна логарифму числа элементов, полная сортировка при каждой операции не выполняется.

часто такую очередь используют для планирования заданий. у каждого задания есть приоритет. задания поступают в произвольном порядке. когда можно запустить следующее задание, из очереди удаляется задание с наивысшим приоритетом. в `PriorityQueue` с головы уходит наименьший элемент, поэтому наивысший приоритет кодируют как наименьшее значение порядка. если более срочной должна быть большая величина, это записывают в `Comparator`: очередь по-прежнему снимает минимум, а минимумом становится самая срочная работа.

раз порядок строится сравнением, элементы либо принадлежат классу с интерфейсом `Comparable`, либо в конструктор передаётся `Comparator`. переданный компаратор заменяет естественный порядок. конструкторы `PriorityQueue`:

- `PriorityQueue()`: создаёт очередь с начальной вместимостью по умолчанию (11). элементы упорядочены естественным порядком

- `PriorityQueue(int initialCapacity)`: создаёт очередь с указанной начальной вместимостью. элементы упорядочены естественным порядком

- `PriorityQueue(int initialCapacity, Comparator comparator)`: создаёт очередь с указанной начальной вместимостью. элементы упорядочены указанным компаратором

- `PriorityQueue(Collection c)`: создаёт очередь, которая содержит элементы из указанной коллекции. если коллекция сама является `SortedSet` или другой `PriorityQueue`, новая очередь берёт тот же порядок

- `PriorityQueue(Comparator comparator)`: создаёт очередь с начальной вместимостью по умолчанию. элементы упорядочены указанным компаратором

- `PriorityQueue(PriorityQueue c)`: создаёт `PriorityQueue`, которая содержит элементы из другой `PriorityQueue`. вместе с элементами копируется и компаратор источника

- `PriorityQueue(SortedSet c)`: создаёт `PriorityQueue`, которая содержит элементы из `SortedSet`. порядок берётся из компаратора этого множества. если множество упорядочено естественно, компаратор источника пуст, и новая очередь тоже использует естественный порядок

`PriorityQueue` реализует `Collection` и `Queue`, поэтому доступны методы обоих интерфейсов. `add` и `offer` кладут элемент в кучу, `poll` и `remove` снимают корень, `peek` и `element` читают корень и оставляют его на месте. применение:

```java


import java.util.PriorityQueue;

 

public class Program{

      

    public static void main(String[] args) {

          

        var people = new PriorityQueue<String>();

        // добавляем ряд объектов

        people.add("Tom");

        people.add("Bob");

        people.add("Sam");



        System.out.println(people);      // [Bob, Tom, Sam]



        var numbers = new PriorityQueue<Integer>();

        // добавляем ряд объектов

        numbers.add(3);

        numbers.add(1);

        numbers.add(5);

        numbers.add(4);



        System.out.println(numbers);      // [1, 3, 5, 4]

    }

}
```

здесь две очереди приоритетов: для строк и для чисел. в обоих случаях наименьший элемент стоит в самом начале. для строк это bob, для чисел это 1. коллекция целиком при этом не сортируется. печать показывает массив кучи. у чисел вывод `[1, 3, 5, 4]`: в корне 1, её дети 3 и 5, а 4 лежит под 3. родитель не больше детей, но ряд 3, 5, 4 отсортированным не является. у строк вывод `[Bob, Tom, Sam]`: bob меньше и tom, и sam, поэтому bob стоит в корне, а tom и sam остаются его детьми. `null` в `PriorityQueue` недопустим. если у элементов нет ни `Comparable`, ни компаратора, первое сравнение завершается `ClassCastException`.
