метод `run()` интерфейса `Runnable` не возвращает значения: поток, который его выполняет, производит только побочный эффект. если вычисление должно вернуть результат, а вызывающий код получает этот результат после завершения, контракта `Runnable` недостаточно. для такой задачи в пакете `java.util.concurrent` определены интерфейсы `Callable` и `Future`.

`Callable` описывает вычисление с результатом. интерфейс параметризован типом результата и объявляет единственный абстрактный метод `call()`, возвращающий значение этого типа:

```java


public interface Callable<V>{



   V call() throws Exception;

}
```

единственный абстрактный метод делает `Callable` функциональным интерфейсом: реализацией может быть лямбда-выражение или ссылка на метод, и тело лямбды становится телом `call()`. объект `Callable` передаётся механизму исполнения (потоку, `FutureTask` или пулу). значение, возвращённое из `call()`, и есть результат, который затем читается через `Future`.

`Future` представляет результат асинхронного вычисления. к моменту получения ссылки на `Future` вычисление ещё может быть не закончено. через этот объект читается, в частности, результат `call()`. контракт отделяет постановку задачи от момента, когда результат становится доступен: вызывающий код продолжает свою работу и обращается к результату позже, когда тот готов.

интерфейс содержит операции отмены, проверки завершения, ожидания и извлечения результата:

- `boolean cancel(boolean mayInterruptIfRunning)` пытается отменить выполнение задачи

- `default Throwable exceptionNow()` возвращает исключение, сгенерированное задачей, без ожидания

- `V get()` при необходимости ожидает завершения задачи, а затем извлекает её результат

- `V get(long timeout, TimeUnit unit)` при необходимости ожидает завершения задачи не дольше заданного времени, а затем извлекает её результат, если он доступен

- `boolean isCancelled()` возвращает `true`, если задача была отменена до нормального завершения

- `boolean isDone()` возвращает `true`, если задача завершена

- `default V resultNow()` возвращает вычисленный результат без ожидания, это неблокирующий вариант метода `get()`

- `default Future.State state()` возвращает состояние задачи. состояние представлено перечислением `Future.State` со следующими константами: `CANCELLED`: задача отменена

- `FAILED`: задача завершилась неудачно и сгенерировала исключение

- `RUNNING`: задача ещё не завершена

- `SUCCESS`: задача успешно завершена

методы `exceptionNow()`, `resultNow()` и `state()` входят в `Future` начиная с java 19. `get()` без параметров блокирует вызывающий поток до завершения задачи. перегрузка с `timeout` ограничивает ожидание: по истечении интервала выбрасывается `TimeoutException`, а сама задача при этом продолжает выполняться. `resultNow()` не ждёт и выбрасывает `IllegalStateException`, если задача ещё не завершилась успешно. `exceptionNow()` требует, чтобы задача уже завершилась именно с исключением, иначе также выбрасывается `IllegalStateException`. `isDone()` истинен для нормального завершения, для завершения с исключением и для отмены. `isCancelled()` истинен только после отмены.

по контракту перечисления `Future.State` константа `RUNNING` означает, что задача ещё не завершена, в том числе если исполнение ещё не начато. `SUCCESS` и `FAILED` различают нормальное завершение и завершение с исключением. `CANCELLED` фиксирует отмену.

### futuretask

один из способов запустить асинхронное вычисление сразу и как задачу, и как дескриптор результата даёт класс `FutureTask`. объект класса представляет асинхронную задачу, которую можно отменить. класс содержит базовую реализацию `Future`: запуск и отмена вычисления, опрос завершения и получение результата.

`FutureTask` реализует `RunnableFuture`, а через него и `Runnable`, и `Future`. поэтому один и тот же объект передаётся конструктору `Thread` и используется как источник результата.

обычно `FutureTask` оборачивает `Callable` или `Runnable`, чтобы выполнить задачу позже, в момент вызова `run()`. для этого предусмотрены два конструктора:

- `FutureTask(Runnable runnable, V result)` создаёт `FutureTask`, который при запуске выполнит указанный `Runnable`. при успешном завершении `get` возвращает заранее переданный результат, потому что сам `Runnable` значения не производит

- `FutureTask(Callable callable)` создаёт `FutureTask`, который при запуске выполнит указанный `Callable`

поведение класса выражается следующими методами:

- `boolean cancel(boolean mayInterruptIfRunning)` пытается отменить выполнение задачи

- `Throwable exceptionNow()` возвращает исключение, сгенерированное задачей

- `V get()` при необходимости ожидает завершения задачи и возвращает её результат

- `V get(long timeout, TimeUnit unit)` при необходимости ожидает завершения задачи не дольше заданного времени, а затем извлекает результат, если он доступен

- `boolean isCancelled()` возвращает `true`, если задача была отменена до нормального завершения

- `boolean isDone()` возвращает `true`, если задача завершена

- `V resultNow()` возвращает результат задачи без ожидания её завершения

- `void run()` исполняет обёрнутое вычисление и записывает результат в этот объект `Future`, если задача не была отменена

- `Future.State state()` возвращает состояние задачи

чтение результата выполняет `get()`. если задача ещё не завершена, вызов блокирует текущий поток. после завершения метод возвращает результат либо завершается исключением. `run()` срабатывает один раз: повторный вызов не запускает вычисление заново. схема видна на вычислении факториала:

```java


import java.util.concurrent.*;



class Program{



    public static void main(String[] args) {

         

        System.out.println("Main thread started...");



        int number = 5;  // исходное число для вычисления факториала



        // определяем задачу, которая вычисляет факториал

        Callable<Integer> task = () -> {



            int n = number;     // копируем число, чтобы не изменять его

            int result = 1;

            while(n > 0) result *= n--;

            return result;  // возвращаем результат задачи

        };



        // определяем задачу, которая будет выполнена в будущем

        var futureTask = new FutureTask<Integer>(task);

        // создаем и запускаем поток

        var t = new Thread(futureTask); // futureTask - это объект Runnable

        t.start();



        // здесь могут быть какие-либо другие операции метода main

        // которые должны выполняться одновременно с futureTask

        System.out.println("Main thread works...");



        try{

            // ожидаем выполнения задачи

            Integer factorial = futureTask.get();

            System.out.printf("factorial of %d is %d\n", number, factorial);

        }

        catch(Exception ex){ 

            System.out.println(ex.getMessage()); 

        }



        System.out.println("Main thread finished...");

    }

}
```

консольный вывод программы:

```bash


Main thread started...

Main thread works...

factorial of 5 is 120

Main thread finished...
```

разбор начинается с задачи `Callable`. она задана лямбда-выражением. у `Callable` один абстрактный метод, поэтому лямбда однозначно сопоставляется с `call()`.

```java


Callable<Integer> task = () -> {



    int n = number;     // копируем число, чтобы не изменять его

    int result = 1;

    while(n > 0) result *= n--;

    return result;  // возвращаем результат задачи

};
```

тело считает факториал числа `number`, объявленного во внешнем методе. лямбда-выражение в java захватывает локальные переменные объемлющей области только если они эффективно финальны: после инициализации переменная не получает новое значение. `number` не переприсваивается, поэтому захват допустим. локальная копия `n` оставляет внешнее число неизменным, как и сказано в комментарии. уменьшать сам `number` внутри лямбды нельзя: присваивание нарушило бы правило захвата, и код не скомпилировался бы. цикл `while (n > 0) result *= n--` накапливает произведение и уменьшает копию. для значения 5 результат равен 120. в конце лямбда возвращает `result`. объявленный тип `Callable<Integer>` ссылочный, поэтому примитив `int` упаковывается в `Integer`. для этого примера переполнения нет: знаковое 32-битное `int` перестаёт вмещать факториал начиная с числа 13.

далее создаётся `FutureTask`, и в конструктор передаётся эта задача:

```java


var futureTask = new FutureTask<Integer>(task);
```

задача возвращает `int`, упаковываемый в `Integer`, поэтому и `Callable`, и `FutureTask` параметризованы типом `Integer`. параметр типа фиксирует значение, которое позже вернёт `get()`.

для исполнения создаётся и запускается поток:

```java


var t = new Thread(futureTask); // futureTask - это объект Runnable

t.start();
```

`FutureTask` реализует `Runnable`, поэтому ссылка принимается конструктором `Thread`. `start()` переводит поток в состояние готовности к планированию. вход в задачу идёт через `Thread.run()`, тот вызывает `FutureTask.run()`, а `run()` вызывает `call()`.

пока дочерний поток `t` считает факториал, поток метода `main` выполняет другие действия. в примере это вывод строки:

```java


System.out.println("Main thread works...");
```

затем результат читается методом `get()`:

```java


try{

    // ожидаем выполнения задачи

    Integer factorial = futureTask.get();

    System.out.printf("factorial of %d is %d\n", number, factorial);

}

catch(Exception ex){ 

    System.out.println(ex.getMessage()); 

}
```

`get()` объявляет проверяемые исключения, поэтому вызов стоит внутри `try`. эта перегрузка выбрасывает `InterruptedException`, если ожидающий поток прерван во время блокировки, и `ExecutionException`, если `call()` завершился с исключением. после отмены `get()` выбрасывает непроверяемое `CancellationException`. в примере любое из них попадает в `catch (Exception ex)`, печатается сообщение, и факториал на консоль не выводится. при нормальном завершении `get()` возвращает `Integer`, и `printf` печатает его.

блокирующий вызов сам по себе:

```java
Integer factorial = futureTask.get();
```

поток, в котором выполняется `main`, останавливается на `get()` и продолжает работу после появления результата либо после исключения из `get()`. порядок строк это подтверждает: `Main thread works...` печатается до факториала, а `Main thread finished...` только после возврата из `get()`.

### генерация и обработка ошибки

алгоритм выше на части входов возвращает 1 без всякого умножения. если число меньше 1, цикл не выполняется ни разу, и задача возвращает начальное значение 1. факториал положительного целого есть произведение чисел от 1 до n. факториал нуля по определению равен 1, отрицательный факториал на целых не определён. следующее условие `number < 1` отвергает и нуль, и отрицательные числа: так задана область примера. вызывающему коду об ошибке сообщают исключением. возврат 1 эту ошибку скрывает.

метод `call()` уже в объявлении допускает любое проверяемое исключение:

```java
V call() throws Exception;
```

сигнатура `throws Exception` позволяет реализации выбросить и проверяемое, и непроверяемое исключение. код, который вызывает `call()` напрямую, обязан это учитывать. `FutureTask.run()` перехватывает исключение из `call()` и переводит задачу в неуспешное завершение, сохраняя исходное исключение как исход вычисления.

при чтении через `get()` это исключение наружу приходит обёрнутым в `ExecutionException`. перехват `ExecutionException` отделяет сбой внутри `call()` от прерывания ожидающего потока (`InterruptedException`). исходная причина лежит в `getCause()`.

пример генерирует ошибку, если аргумент факториала меньше 1:

```java


import java.util.concurrent.*;



class Program{



    public static void main(String[] args) {

         

        System.out.println("Main thread started...");



        int number = -5;  // исходное число для вычисления факториала

        try{

            // определяем задачу, которая вычисляет факториал

            Callable<Integer> task = () -> {



                // если число меньше 1, генерируем исключение

                if(number < 1) throw new Exception("Number must be greater than 0");

                int n = number;     // копируем число, чтобы не изменять его

                int result = 1;

                while(n > 0) result *= n--;

                return result;  // возвращаем результат задачи

            };



            var futureTask = new FutureTask<Integer>(task);

            var t = new Thread(futureTask);

            t.start();



            System.out.println("Main thread works...");

       

            // ожидаем выполнения задачи

            Integer factorial = futureTask.get();

            System.out.printf("factorial of %d is %d\n", number, factorial);

        }

        // перехватываем ошибки выполнения FutureTask

        catch(ExecutionException ex){



            System.out.println("Factorial error: " + ex.getMessage());

        }

        // перехватываем все остальные ошибки

        catch(Exception ex){ 

            System.out.println(ex.getMessage()); 

        }



        System.out.println("Main thread finished...");

    }

}
```

перед вычислением число проверяется, и при нарушении условия выбрасывается исключение:

```java


if(number < 1) throw new Exception("Number must be greater than 0");
```

для сбоя внутри `FutureTask` выделен отдельный обработчик:

```java


catch(ExecutionException ex){



    System.out.println("Factorial error: " + ex.getMessage());

}
```

второй `catch (Exception)` принимает остальные исключения, в том числе прерывание ожидания. в пример передано недопустимое значение -5, поэтому срабатывает первый обработчик:

```bash


Main thread started...

Main thread works...

Factorial error: java.lang.Exception: Number must be greater than 0

Main thread finished...
```

текст `java.lang.Exception: Number must be greater than 0` совпадает с сообщением `ExecutionException`: конструктор сохраняет в сообщении результат `toString()` причины. само исключение задачи имеет тип `Exception`.

то же исключение задачи читается у `FutureTask` методом `exceptionNow()`, уже без обёртки `ExecutionException`:

```java


import java.util.concurrent.*;



class Program{



    public static void main(String[] args) {

         

        System.out.println("Main thread started...");



        int number = -5;  // исходное число для вычисления факториала



        FutureTask<Integer> futureTask = null;  // определяем задачу



        try{

            ..............................................



            futureTask = new FutureTask<Integer>(task);



            ..............................................

        }

        // перехватываем ошибки выполнения FutureTask

        catch(ExecutionException ex){



            var ex = futureTask.exceptionNow();  // получаем исключение

            System.out.println("Factorial error: " + ex.getMessage());

        }

        // перехватываем все остальные ошибки

        catch(Exception ex){ 

            System.out.println(ex.getMessage()); 

        }



        System.out.println("Main thread finished...");

    }

}
```

`exceptionNow()` не блокируется и возвращает исключение, сохранённое как исход задачи, то есть объект, выброшенный из `call()`. вызов законен, когда задача уже завершилась с исключением. в этом фрагменте `get()` только что выбросил `ExecutionException`, значит исход исключительный и `exceptionNow()` применим. фрагмент в записанном виде повторно объявляет имя `ex` внутри блока `catch`, где параметр `ex` уже находится в области видимости. компилятор java такое переобъявление отвергает, поэтому результату `exceptionNow()` нужно другое имя. вызов нужен, когда несколько объектов `FutureTask` завершаются разными исключениями. эти исключения читают у соответствующих задач. общий обработчик вокруг `get()` их не разделяет.

сообщение объекта из `exceptionNow()` короче сообщения `ExecutionException`: это текст, переданный в конструктор `Exception`, без префикса имени класса, который добавляет `toString()`.

### отмена задач

`Future` позволяет отменить задачу. для этого служит `cancel()`:

```java


boolean cancel(boolean mayInterruptIfRunning)
```

если выполнение уже началось, параметр `mayInterruptIfRunning` определяет, будет ли прерван поток задачи. реализация, которой поток известен, при значении `true` вызывает у этого потока `interrupt()`. прерывание в java кооперативно: у потока взводится флаг, а реакция зависит от кода задачи. `Thread.sleep` при взведённом флаге выбрасывает `InterruptedException` и сбрасывает статус прерывания. код, который флаг не проверяет, после `cancel(true)` может продолжать счёт.

возвращаемое значение равно `false`, если отменить задачу нельзя, обычно потому что она уже завершилась нормально, и `true`, если отмена зафиксирована. по контракту `Future` признак отмены после этого читают методом `isCancelled()`. после возврата из `cancel` повторные вызовы `isDone()` дают `true`. если `cancel` вернул `true`, последующие вызовы `isCancelled()` также дают `true`.

метод не меняет исход, если задача уже завершена, уже отменена или не может быть отменена по другой причине. если на момент вызова задача ещё не стартовала, она не должна быть запущена. уже выполненные побочные эффекты отмена не откатывает: контракт фиксирует отказ от нормального результата и, при `mayInterruptIfRunning == true`, попытку прерывания.

пример с наблюдаемой отменой:

```java


import java.util.concurrent.*;



class Program{



    public static void main(String[] args) {

         

        System.out.println("Main thread started...");



        int number = 5;  // исходное число для вычисления факториала



        try{

            // определяем задачу, которая вычисляет факториал

            Callable<Integer> task = () -> {



                if(number < 1) throw new Exception("Number must be greater than 0");

                int n = number;     // копируем число, чтобы не изменять его

                int result = 1;

                while(n > 0) {



                    result *= n--;

                    System.out.printf("[Factorial execution] result = %d   n = %d\n", result, n);

                    Thread.sleep(200);

                }

                return result;

            };



            var futureTask = new FutureTask<Integer>(task);

            // создаем и запускаем поток

            var t = new Thread(futureTask);

            t.start();



            System.out.println("Main thread works...");

            Thread.sleep(300); // имитируем работу, чтобы futureTask успела немного поработать



            // в конце отменяем задачу

            futureTask.cancel(true);



            // проверяем отмену задачи

            if(futureTask.isCancelled()) System.out.println("Factorial execution cancelled...");

        }

        catch(Exception ex){ 

            System.out.println(ex.getMessage()); 

        }



        System.out.println("Main thread finished...");

    }

}
```

чтобы отмена была видна на консоли, в цикле задачи стоит пауза 200 миллисекунд:

```java


while(n > 0) {



    result *= n--;

    System.out.printf("[Factorial execution] result = %d   n = %d\n", result, n);

    Thread.sleep(200);

}
```

поток `main` после паузы 300 миллисекунд отменяет задачу с прерыванием рабочего потока и проверяет статус:

```java


// отменяем задачу

futureTask.cancel(true);



// проверяем отмену задачи

if(futureTask.isCancelled()) System.out.println("Factorial execution cancelled...");
```

консольный вывод:

```bash


Main thread started...

Main thread works...

[Factorial execution] result = 5   n = 4

[Factorial execution] result = 20   n = 3

Factorial execution cancelled...

Main thread finished...
```

после двух итераций цикла нормальное выполнение прекращено. `sleep` в рабочем потоке получает прерывание, из `call()` выходит `InterruptedException`, а `FutureTask` к этому моменту уже переведён в отменённое состояние, поэтому `isCancelled()` печатает подтверждение. исключение рабочего потока в `catch` метода `main` не попадает: `call()` исполняется в другом потоке, и `FutureTask` хранит исход у себя. `get()` в примере не вызывается, поэтому `InterruptedException` из `sleep` на консоль не выводится. вызов `get()` после успешного `cancel(true)` завершился бы `CancellationException`.
