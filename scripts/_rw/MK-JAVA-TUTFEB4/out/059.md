**sealed-классы** (запечатанные классы) и **sealed-интерфейсы** (запечатанные интерфейсы) в java задают точный набор типов, которым разрешено расширять данный класс или интерфейс. иерархия наследования становится замкнутой и проверяется компилятором. до этой конструкции такой контроль давали только более жёсткие средства: модификатор `final`, который закрывает тип для любого наследования, и ограничение доступа, которое прячет тип, но не перечисляет наследников. конструкция вошла в язык как постоянная в java 17 (jep 409).

назначение запечатанного типа видно на фоне прежних режимов. до `sealed` иерархия была либо полностью открыта (наследоваться мог любой класс), либо полностью закрыта модификатором `final`. sealed-класс занимает промежуточный режим: автор явно перечисляет допустимые прямые подклассы и тем самым отсекает непредусмотренное наследование. тот же механизм моделирует алгебраический тип данных (adt): у базового типа фиксированный набор вариантов, и компилятор этот набор знает. вместе с сопоставлением шаблонов в `switch` замкнутый набор даёт проверку полноты ветвей: пропущенный разрешённый подтип является ошибкой компиляции.

класс или интерфейс объявляется запечатанным двумя ключевыми словами, `sealed` и `permits`:

```java


sealed class имя_класса permits подкласс_1, подкласс_2, ююю подкласс_N { 



    // содержимое класса

}
```

ключевое слово **sealed** ставится у суперкласса или интерфейса и объявляет тип запечатанным.

после имени класса идёт ключевое слово **permits** и список классов, которым разрешено быть прямыми наследниками. дальше эти классы называются разрешёнными.

пример:

```java


sealed class Operation

    permits Sum, Subtract, Multiply

{ }
```

классам `Sum`, `Subtract` и `Multiply` разрешено наследовать `Operation`. для любого другого класса наследование запрещено. попытка объявить лишнего наследника отвергается на этапе компиляции:

```java


sealed class Operation

    permits Sum, Subtract, Multiply

{ }

class Divide extends Operation   // Ошибка - для класса Divide не разрешено наследование

{ }
```

класс `Divide` в списке `permits` отсутствует, поэтому объявление `extends Operation` не компилируется.

### ограничения для разрешённых подклассов

классы, перечисленные после `permits`, подчиняются правилам расположения:

- разрешённый подкласс sealed-класса должен быть доступен из запечатанного типа. им не может быть приватный класс, вложенный в другой класс, и не может быть тип, видимый только внутри чужого пакета.

- разрешённые публичные подклассы располагаются в том же пакете, что и sealed-класс. если программа собрана в модули, разрешённые подклассы располагаются в том же модуле, что и запечатанный тип. уточнение правила модуля: в именованном модуле разрешённые подтипы могут лежать в разных пакетах этого модуля, в безымянном модуле они обязаны находиться в одном пакете с запечатанным типом.

- sealed-класс можно объявить без предложения `permits`. тогда все его прямые подклассы объявляются в том же файле, то есть в той же единице компиляции: компилятор сам собирает список по соседним объявлениям.

кроме расположения, разрешённый класс явно сообщает, как он продолжает или обрывает иерархию запечатанного типа. для этого к нему применяется один из трёх модификаторов:

- `final`: любое дальнейшее наследование запрещено, ветвь иерархии заканчивается на этом классе

```java


sealed class Operation

    permits Sum, Subtract, Multiply { }



final class Sum extends Operation { }

final class Subtract extends Operation {}

final class Multiply extends Operation {}
```

- `sealed`: дальнейшее наследование разрешено, но только классам из собственного списка `permits`

```java


sealed class Operation permits UnaryOp, BinaryOp{}



final class UnaryOp extends Operation { }



// разрешаем дальнейшее наследование, но только для классов Sum, Subtract, Multiply

sealed class BinaryOp extends Operation

    permits Sum, Subtract, Multiply { }



final class Sum extends BinaryOp {}

final class Subtract extends BinaryOp {}

final class Multiply extends BinaryOp {}
```

здесь `UnaryOp` закрыт модификатором `final`, а `BinaryOp` сам запечатан и пускает дальше только `Sum`, `Subtract` и `Multiply`.

- `non-sealed`: подкласс снова открыт для расширения любым классом, как обычный класс java, и ветвь иерархии перестаёт быть замкнутой

```java


sealed class Operation permits UnaryOp, BinaryOp{}



final class UnaryOp extends Operation { }



// открываем для наследования произвольным классами

non-sealed class BinaryOp extends Operation {}



class Sum extends BinaryOp {}

class Subtract extends BinaryOp {}

class Multiply extends BinaryOp {}
```

`BinaryOp` помечен `non-sealed`, поэтому `Sum`, `Subtract` и `Multiply` наследуют его уже без отдельного разрешения в `permits`.

### пример sealed-классов

простейший замкнутый набор арифметических операций:

```java


class Program{

      

    public static void main(String[] args) {

          

        Operation add = new Sum(5, 4);

        Operation sub = new Subtract(5, 4);



        System.out.println(add.execute());      // 9

        System.out.println(sub.execute());      // 1

    }

}



sealed abstract class Operation

    permits Sum, Subtract

{

    int op1;

    int op2;



    Operation(int op1, int op2){



        this.op1 = op1;

        this.op2 = op2;

    }

    abstract int execute();

}



final class Sum extends Operation{



    Sum(int op1, int op2){ super(op1, op2); }



    @Override int execute() { return op1 + op2;}

}

final class Subtract extends Operation{



    Subtract(int op1, int op2){ super(op1, op2); }



    @Override int execute() { return op1 - op2;}

}
```

абстрактный класс `Operation` объявлен запечатанным. он представляет арифметическую операцию: хранит два операнда в полях `op1` и `op2` и объявляет абстрактный метод `execute()` для выполнения операции. наследовать `Operation` могут только `Sum` и `Subtract`, оба перечислены в `permits`.

в `Sum` и `Subtract` метод `execute()` реализован для сложения и вычитания. оба класса помечены `final`, поэтому наследование от них запрещено: новых прямых вариантов операции за пределами этого файла не добавить.

### расширенный пример

тот же приём на иерархии из нескольких уровней:

```java


class Program{

      

    public static void main(String[] args) {

          

        Operation add = new Sum(5, 4);

        Operation sub = new Subtract(5, 4);

        Operation neg = new Negation(5);

        Operation if1 = new IfOperation(true, 3, 7);

        Operation if2 = new IfOperation(false, 3, 7);



        System.out.println(add.execute());      // 9

        System.out.println(sub.execute());      // 1

        System.out.println(neg.execute());      // -5

        System.out.println(if1.execute());      // 3

        System.out.println(if2.execute());      // 7

    }

}



sealed abstract class Operation permits BinaryOperation, IfOperation{



    abstract int execute();

}



// запрещаем дальнейшее наследование

// операция отрицания

final class IfOperation extends Operation { 



    boolean condition;

    int op1;  

    int op2; 

    IfOperation(boolean cond, int op1, int op2){ 

        

        this.condition = cond;

        this.op1 = op1; 

        this.op2 = op2; 

    }



    @Override int execute() { return condition ? op1 : op2; }

}



// разрешаем дальнейшее наследование для типов Sum, Subtract

sealed abstract class BinaryOperation extends Operation

    permits Sum, Subtract

{

    int op1;

    int op2;



    BinaryOperation(int op1, int op2){



        this.op1 = op1;

        this.op2 = op2;

    }

}



final class Sum extends BinaryOperation{



    Sum(int op1, int op2){ super(op1, op2); }



    @Override int execute() { return op1 + op2;}

}



non-sealed class Subtract extends BinaryOperation{



    Subtract(int op1, int op2){ super(op1, op2); }



    @Override int execute() { return op1 - op2;}

}



class Negation extends Subtract{



    Negation(int op){ super(0, op); }   // эквивалентно варажению 0 - op

}
```

единый sealed-класс `Operation` представляет операцию вообще. прямыми наследниками разрешены `BinaryOperation` (операция с двумя операндами) и `IfOperation` (операция с тремя операндами: условие и два альтернативных значения).

класс `IfOperation` объявлен как `final` и дальнейшее наследование закрывает. его `execute` реализует выбор, близкий к тернарной операции: при истинном условии возвращается `op1`, иначе `op2`.

класс `BinaryOperation` сам запечатан и разрешает наследование двум классам, `Sum` и `Subtract`. `Subtract` объявлен с модификатором `non-sealed`, поэтому от него может наследоваться произвольный класс. таким классом в примере является `Negation`: унарный минус записан как вычитание из нуля, конструктор вызывает `super(0, op)`, что соответствует выражению `0 - op`.

### sealed-интерфейсы

то же правило распространяется на интерфейсы. **sealed-интерфейс** реализуется или расширяется только теми классами и интерфейсами, которые перечислены в его предложении `permits`.

пример:

```java


public sealed interface Shape permits Rectangle, Circle {

    // Методы интерфейса

}
```
