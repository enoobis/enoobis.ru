по завершении работы с потоком его закрывают методом `close()`, объявленным в интерфейсе `Closeable`:

```java


void close() throws IOException
```

метод ничего не возвращает. если ресурс освободить не удаётся, выбрасывается `IOException`, и вызывающий код это исключение обрабатывает или объявляет в сигнатуре.

интерфейс `Closeable` уже реализован классами `InputStream` и `OutputStream`, а через наследование и всеми классами байтовых потоков. контракт закрытия поэтому один и тот же у файлового потока, сетевого потока и буферизованной обёртки.

`close()` освобождает ресурсы, закреплённые за потоком. у файлового потока это дескриптор операционной системы. незакрытый поток держит дескриптор до сборки мусора и финализации. пока ссылка на поток жива или пока финализатор не отработал, дескриптор занят: вместе с памятью виртуальной машины утекает и ограниченный ресурс процесса.

закрыть файл можно двумя способами. первый задаёт закрытие явно, блоком `try..catch..finally`. чтение байтов из файла выглядит так:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        FileInputStream fin=null;

        try

        {

            fin = new FileInputStream("notes.txt");

            

            int i=-1;

            while((i=fin.read())!=-1){

            

                System.out.print((char)i);

            }

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        } 

        finally{

            

            try{

            

                if(fin!=null)

                    fin.close();

            }

            catch(IOException ex){

            

                System.out.println(ex.getMessage());

            }

        }  

    } 

}
```

открытие и чтение способны завершиться ошибкой ввода-вывода, поэтому чтение помещено в `try`, а `catch` печатает текст `IOException`. закрытие обязано выполниться и при нормальном выходе, и при исключении, поэтому `close()` стоит в `finally`. семантика `finally` выполняет блок при любом выходе из `try`, кроме `System.exit` и аварийного завершения виртуальной машины. `Thread.interrupt` этот блок не пропускает. `close()` сам объявлен с `throws IOException`, и вложенный `try..catch` перехватывает ошибку закрытия отдельно от ошибки чтения. перед вызовом проверяется `fin != null`: если конструктор `FileInputStream` выбросил исключение, присваивания не было, переменная осталась `null`, и вызов метода по ней породил бы ещё одно исключение.

### try-with-resources

с java 7 то же закрытие записывается конструкцией try-with-resources. компилятор разворачивает её в `try..finally` и сам вызывает `close()`. ресурс в заголовке обязан реализовать `AutoCloseable`. `Closeable` расширяет `AutoCloseable` и сужает `close()` до `IOException`, поэтому любой байтовый поток в заголовке допустим.

синтаксис такой:

```java


try(Resource res = ...){



    // действия с ресурсом res

}
```

ресурс создаётся в круглых скобках. имя `res` существует только внутри блока: после закрывающей фигурной скобки оно не видно, а объект к этому моменту уже закрыт. переменная ресурса неявно финальная, повторное присваивание в неё не компилируется.

блок `catch` конструкция не отменяет. обработчик пишется после `try`, как у обычного оператора:

```java


try(Resource res = ...){



    // действия с ресурсом res

}

catch(исключение){

    // обработка исключения

}
```

чтение файла в этой форме:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

        

        try(FileInputStream fin = new FileInputStream("notes.txt"))

        {

            int i=-1;

            while((i = fin.read()) != -1){

            

                System.out.print((char)i);

            }   

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        } 

    } 

}
```

при выходе из `try` у объекта `FileInputStream` вызывается `close()`. вызов происходит и при нормальном завершении тела, и если `read` выбросил `IOException`: закрытие стоит в порождённом `finally`. если исключение выбросили и тело, и `close()`, наружу распространяется исключение тела, а исключение закрытия присоединяется к нему через `Throwable.addSuppressed` и остаётся доступным при разборе причины. несколько ресурсов в одном заголовке закрываются в порядке, обратном порядку объявления.

несколько потоков, которые нужно закрыть после работы, перечисляются в заголовке через точку с запятой:

```java


try(FileInputStream fin = new FileInputStream("hello.txt"); 

        FileOutputStream fos = new FileOutputStream("hello2.txt"))

{

	//..................

}
```

в примерах выше ресурс создаётся прямо в заголовке:

```java
try(FileInputStream fin = new FileInputStream("notes.txt"))
```

с java 9 в заголовок можно поставить уже объявленную переменную, если она эффективно финальная: после инициализации ей ничего не присваивается. по завершении конструкции такой ресурс всё равно закрывается:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) throws FileNotFoundException {

        

        FileInputStream fin = new FileInputStream("notes.txt");

        try(fin)

        {

            int i=-1;

            while((i = fin.read()) != -1){

            

                System.out.print((char)i);

            }   

        }  // здесь вызывается fin.close()

    } 

}
```

здесь `fin` создан до `try`, а в скобках указано только имя. комментарий на выходе из блока отмечает место вызова `fin.close()`. `FileNotFoundException` конструктора объявлен у `main` и в `catch` этой конструкции не попадает: к входу в `try` поток уже открыт, а ошибка открытия уходит вызывающему `main`.
