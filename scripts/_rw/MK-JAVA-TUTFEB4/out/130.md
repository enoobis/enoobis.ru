встроенные примитивные числовые типы подходят не для всякой программы. иногда нужно хранить числа, которые выходят за диапазон `long` и `double`. у формата с плавающей точкой есть и отдельные свойства, из-за которых точный денежный расчёт на `double` не сходится.

### особенности при вычислениях с числами с плавающей точкой

вычисления с плавающей точкой следуют спецификации ieee 754. помимо обычных конечных чисел формат содержит три особых значения. ими обозначают переполнение и ошибочную операцию:

- положительная бесконечность (positive infinity)

- отрицательная бесконечность (negative infinity)

- `NaN` (не число)

в java этим значениям соответствуют константы:

- `Double.POSITIVE_INFINITY` для типа `double` и `Float.POSITIVE_INFINITY` для типа `float`

- `Double.NEGATIVE_INFINITY` и `Float.NEGATIVE_INFINITY`

- `Double.NaN` и `Float.NaN`

деление положительного числа с плавающей точкой на ноль даёт положительную бесконечность. целочисленное деление на ноль бросает `ArithmeticException`. вещественное деление на ноль исключения не поднимает и возвращает особое значение формата:
```java

public class Program{
     
	public static void main(String[] args) {
        
        double d = 1.2;
        double result = d / 0;
        System.out.println(result); // Infinity
	}
}
```
деление на отрицательный ноль `-0.0` даёт отрицательную бесконечность. в исходном примере записано выражение `1.0 / -0`. литерал `0` имеет целый тип, унарный минус целый ноль не меняет, и после приведения к `double` частное равно положительной бесконечности. отрицательный ноль задаётся вещественным литералом `-0.0`, и уже `1.0 / -0.0` равно `Double.NEGATIVE_INFINITY`.

деление `0.0` на `0`, а также квадратный корень отрицательного числа, даёт `NaN`:
```java

public class Program{
     
	public static void main(String[] args) {
        
        double d = 0.0;
        double result = d / 0;
        System.out.println(result); // NaN
	}
}
```
теми же константами проверяют результат. сравнение с бесконечностью через `==` определено: бесконечность равна самой себе. сравнение с `NaN` через `==` всегда ложно, в том числе `Double.NaN == Double.NaN`. по ieee 754 нечисло не равно ни одному значению, включая себя. в примере ниже ветка с `Double.NaN` поэтому не выполняется, и управление уходит в печать значения. ветка с `Double.POSITIVE_INFINITY` выполняется, потому что положительная бесконечность сравнима сама с собой:
```java

public class Program{
     
	public static void main(String[] args) {
        
        double result1 = 0.0 / 0;
        if(result1 == Double.NaN)
            System.out.println("result1 is NaN"); 
        else 
            System.out.printf("result1 is %f\n", result1);

        double result2 = 1.0 / 0;
        if(result2 == Double.POSITIVE_INFINITY)
            System.out.println("result2 is Double.POSITIVE_INFINITY"); 
        else 
            System.out.printf("result2 is %f\n", result2);
	}
}
```
для проверки на `NaN` есть метод `Double.isNaN()`. тот же предикат есть у `Float`. полагаться на `==` здесь нельзя по правилу, разобранному выше:
```java

public class Program{
     
	public static void main(String[] args) {
        
        double result = 0.0 / 0;
        if(Double.isNaN(result))
            System.out.println("result is NaN"); 
        else 
            System.out.printf("result is %f\n", result);
	}
}
```
числа с плавающей точкой не годятся для финансовых вычислений, где ошибка округления недопустима. пример:
```java

public class Program{
     
	public static void main(String[] args) {
        
        System.out.println(2.0 - 1.1);
	}
}
```
программа печатает `0.8999999999999999`. точное десятичное значение разности равно `0.9`. причина в двоичном представлении. у дроби 1/10 нет конечной двоичной записи, как у 1/3 нет конечной десятичной. `double` хранит ближайшее представимое значение, и разность `2.0 - 1.1` показывает эту погрешность. когда нужно точное десятичное значение, берут класс `BigDecimal`.

### `BigDecimal`

`BigDecimal` хранит целое без масштаба и отдельно масштаб, то есть положение десятичной точки. объекты неизменяемы: арифметические методы возвращают новый экземпляр и исходный не меняют. основные методы:

- `BigDecimal add(BigDecimal other)`: возвращает сумму двух чисел

- `BigDecimal subtract(BigDecimal other)`: возвращает разность двух чисел

- `BigDecimal multiply(BigDecimal other)`: возвращает произведение двух чисел

- `BigDecimal divide(BigDecimal other)`: возвращает частное двух чисел. если десятичная запись частного бесконечна, метод бросает `ArithmeticException`

- `BigDecimal divide(BigDecimal other, RoundingMode mode)`: частное двух чисел, округлённое по режиму mode

- `int compareTo(BigDecimal other)`: сравнивает два числа по величине. возвращает -1, если текущий объект меньше other, 1, если текущий объект больше, и 0, если числа равны по значению. нулевой результат `compareTo` возможен и при разном масштабе: `1.0` и `1.00` для `compareTo` равны. `equals` считает их разными, потому что учитывает масштаб

- `static BigDecimal valueOf(double x)`: возвращает объект `BigDecimal`, значение которого равно переданному числу. эта перегрузка строится из `Double.toString`, то есть из короткой десятичной записи. конструктор `BigDecimal(double)` сохраняет точное двоичное приближение, и для десятичных величин обычно берут `valueOf`

- `double doubleValue()`: преобразует объект `BigDecimal` в `double`. при преобразовании снова появляется двоичное округление, если значение не представимо в `double`

- `float floatValue()`: преобразует объект `BigDecimal` в `float`

пример:
```java

import java.math.*;

public class Program {
  
    public static void main(String[] args) {
        
        BigDecimal c = BigDecimal.valueOf(2325.06);
        BigDecimal d = BigDecimal.valueOf(215.06);
        c = c.subtract(d.multiply(BigDecimal.valueOf(2.1)));
        System.out.println(c);      // 1873.434
        double y = c.doubleValue();
        System.out.println(y);      // 1873.434
    }
}
```
### `BigInteger`

для очень больших целых используется тип `BigInteger` из пакета `java.math`. величина ограничена только доступной памятью. объект неизменяем: знак и массив разрядов фиксируются при создании. основные методы:

- `BigInteger add(BigInteger other)`: возвращает сумму двух чисел

- `BigInteger subtract(BigInteger other)`: возвращает разность двух чисел

- `BigInteger multiply(BigInteger other)`: возвращает произведение двух чисел

- `BigInteger divide(BigInteger other)`: возвращает частное двух чисел. деление целочисленное, дробная часть отбрасывается к нулю

- `BigInteger mod(BigInteger other)`: возвращает остаток от целочисленного деления. остаток неотрицателен. этим `mod` отличается от `remainder`: у `remainder` знак совпадает со знаком делимого

- `BigInteger sqrt()`: возвращает целый квадратный корень, округлённый вниз. для отрицательного аргумента метод бросает `ArithmeticException`

- `int compareTo(BigInteger other)`: сравнивает два числа. возвращает -1, если текущий объект меньше other, 1, если текущий объект больше, и 0, если числа равны

- `static BigInteger valueOf(long x)`: возвращает объект `BigInteger` со значением переданного `long`. для чисел длиннее `long` объект собирают из десятичной строки

- `int intValue()`: переводит объект в `int`. если значение не помещается в 32 бита, сохраняются младшие биты, исключения нет

- `byte byteValue()`: переводит объект в `byte` по тому же сужению к младшим битам

- `short shortValue()`: переводит объект в `short`

- `long longValue()`: переводит объект в `long`. при выходе за диапазон `long` сохраняются младшие 64 бита

пример:
```java

import java.math.*;

public class Program {
  
    public static void main(String[] args) {
          
        BigInteger a = BigInteger.valueOf(2147483647);
        BigInteger b = BigInteger.valueOf(2147483641);
        //a = a * b;  // так нельзя
        a = a.multiply(b);
        System.out.println(a);  // 4611686001247518727
        long x = a.longValue();
        System.out.println(x);  // 4611686001247518727
    }
}
```
объекты `BigInteger` и `BigDecimal` представляют числа, но стандартные арифметические операторы к ним не применяются. в java операторы не перегружаются: запись `a * b` для этих типов не компилируется, что и показывает закомментированная строка примера. все математические действия идут через методы, и каждый метод возвращает новый объект. исходные экземпляры после вызова остаются прежними, поэтому результат нужно записывать обратно в переменную, как в примерах сделано с `c` и `a`.
