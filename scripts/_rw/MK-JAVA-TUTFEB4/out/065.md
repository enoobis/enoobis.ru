стандартная библиотека java покрывает большую часть типичных сбоев: ввод-вывод, приведение типов, выход индекса за границы, неверный аргумент. отдельный класс исключения нужен, когда ошибка принадлежит предметной области и её надо отличить от прочих `Exception` при обработке. собственный класс строится наследованием. наследование от `Exception` делает исключение проверяемым. компилятор требует, чтобы каждый метод на пути распространения либо перехватил его, либо объявил в `throws`. тот же приём применим к методу факториала, который должен отвергнуть аргумент меньше 1. ниже он разобран на классе `Person`, где проверяются имя и возраст.

```java


import java.util.Scanner;



class Program{

     

	public static void main(String[] args) throws Exception {

         

        createPerson("Tom", -10);

    }



    static void createPerson(String name, int age){



        try{



            var person = new Person(name, age);

            person.print();

        }

        catch(Exception ex){



            System.out.println(ex.getMessage());

        }

    }

}



class Person{

    

    private String name;

    private int age;



    Person(String name, int age) throws Exception{



        if(name.length() < 2) throw new Exception("Недостаточная длина имени: " + name.length());

        if(age < 1 || age > 110) throw new Exception("Некорректный возраст: " + age);

        this.name = name; 

        this.age = age;

    }



    void print(){ System.out.printf("Name: %s; Age: %d\n", name, age); }

}
```

конструктор `Person` получает имя и возраст и сопоставляет их с ограничениями. длина имени меньше 2 символов, а также возраст меньше 1 или больше 110, приводят к исключению. типом объекта служит базовый `Exception`, в конструктор которого передаётся текст ошибки:

```java


Person(String name, int age) throws Exception{



    if(name.length() < 2) throw new Exception("Недостаточная длина имени: " + name.length());

    if(age < 1 || age > 110) throw new Exception("Некорректный возраст: " + age);

    this.name = name; 

    this.age = age;

}
```

конструктор сам исключение не перехватывает, поэтому в его сигнатуре указано `throws Exception`. вызывающий код видит проверяемое исключение в контракте метода и обязан его учесть.

обработка сосредоточена в `createPerson`. вызов конструктора и последующий `print` стоят в `try`, а `catch` принимает `Exception` и печатает `getMessage()`:

```java


try{

    var person = new Person(name, age);

    person.print();

}

catch(Exception ex){



    System.out.println(ex.getMessage());

}
```

такой схемы достаточно, пока все ошибки обрабатываются одинаково. один `catch (Exception)` не отличает сбой `Person` от любого другого `Exception`, попавшего в ту же область. если реакция нужна только на ошибки этого типа, либо имя и возраст должны порождать разные исключения, объявляется собственный класс. минимальный вариант: `PersonException`.

```java


class PersonException extends Exception{



    PersonException(String message){

        

        super(message);

    }

}
```

у класса один конструктор. он принимает сообщение и передаёт его конструктору `Exception` через `super(message)`. собственного состояния, помимо унаследованного сообщения и трассировки, тип не хранит. его роль: выделить подтип в иерархии, чтобы обработчик мог назвать его в параметре `catch`. теперь `Person` порождает именно этот тип, а основная программа перехватывает его отдельно:

```java


class Program{

     

	public static void main(String[] args) throws Exception {

         

        createPerson("Tom", -10);

        createPerson("m", 20);

    }



    static void createPerson(String name, int age){



        try{



            var person = new Person(name, age);

            person.print();

        }

        catch(PersonException ex){



            System.out.println(ex.getMessage());

        }

    }

}



class PersonException extends Exception{



    PersonException(String message){

        

        super(message);

    }

}



class Person{

    

    private String name;

    private int age;



    Person(String name, int age) throws PersonException{



        if(name.length() < 2) throw new PersonException("Недостаточная длина имени: " + name.length());

        if(age > 1 || age > 110) throw new PersonException("Некорректный возраст: " + age);

        this.name = name; 

        this.age = age;

    }



    void print(){ System.out.printf("Name: %s; Age: %d\n", name, age); }

}
```

запуск даёт следующий консольный вывод:

```bash


Некорректный возраст: -10

Недостаточная длина имени: 1
```

тот же приём можно уточнить: отдельная ситуация получает отдельный тип. ошибка имени оформляется как `PersonNameException`, ошибка возраста оформляется как `PersonAgeException`. оба класса наследуют `Exception` и остаются проверяемыми. конструкторы принимают не готовую строку, а исходные данные и сами собирают сообщение: текущее значение, нижнюю и верхнюю границу. границы имени и возраста вынесены в статические поля `Person` (`nameMinLength`, `minAge`, `maxAge`), чтобы условие в конструкторе и текст исключения ссылались на одни и те же константы.

```java


class Program{

     

	public static void main(String[] args) throws Exception {

         

        createPerson("Tom", -10);

        createPerson("m", 20);

    }



    static void createPerson(String name, int age){



        try{



            var person = new Person(name, age);

            person.print();

        }

        catch(PersonNameException ex){



            System.out.println("Ошибка в имени:");

            System.out.println(ex.getMessage());

        }

        catch(PersonAgeException ex){



            System.out.println("Ошибка в возрасте:");

            System.out.println(ex.getMessage());

        }

    }

}



class PersonNameException extends Exception{



    PersonNameException(String name, int minLength){

        

        String message = "Недостаточная длина имени. Текущее значение: " + name + ". Минимальная длина имени: " + minLength; 

        super(message);

    }

}



class PersonAgeException extends Exception{



    PersonAgeException(int age, int minAge, int maxAge){

        

        String message = "Некорректный возраст. Текущее значение: " + age + 

                        ". Минимальный возраст: " + minAge + ". Максимальный возраст: " + maxAge; 

        super(message);

    }

}



class Person{

    

    private String name;

    private int age;

    private static int nameMinLength = 2;

    private static int minAge = 1;

    private static int maxAge = 110;



    Person(String name, int age) throws PersonNameException, PersonAgeException {



        if(name.length() < nameMinLength) throw new PersonNameException(name, nameMinLength);

        if(age < minAge || age > maxAge) throw new PersonAgeException(age, minAge, maxAge);

        this.name = name; 

        this.age = age;

    }



    void print(){ System.out.printf("Name: %s; Age: %d\n", name, age); }

}
```

конструктор `Person` объявляет оба типа. секция `throws` перечисляет их через запятую: каждый `throw` выпускает проверяемое исключение, а сам конструктор его не перехватывает.

```java


Person(String name, int age) throws PersonNameException, PersonAgeException {
```

в `createPerson` ветки `catch` разделены по типам. сначала обрабатывается `PersonNameException`, затем `PersonAgeException`. эти классы не состоят в отношении подтипа, поэтому порядок ветвей на выбор обработчика не влияет: среда выбирает первую ветвь, чей параметр совместим с фактическим типом объекта. общий префикс печатается до `getMessage()`, и по нему видно, какое ограничение нарушено.

```java


catch(PersonNameException ex){



    System.out.println("Ошибка в имени:");

    System.out.println(ex.getMessage());

}

catch(PersonAgeException ex){



    System.out.println("Ошибка в возрасте:");

    System.out.println(ex.getMessage());

}
```

консольный вывод:

```bash


Ошибка в возрасте:

Некорректный возраст. Текущее значение: -10. Минимальный возраст: 1. Максимальный возраст: 110

Ошибка в имени:

Недостаточная длина имени. Текущее значение: m. Минимальная длина имени: 2
```

разделение типов делает обработку выборочной. вызывающий код реагирует на имя и на возраст по-разному и не разбирает текст сообщения. сообщение остаётся данными для человека, а выбор ветви `catch` идёт по типу исключения, то есть по обычной диспетчеризации подтипов.
