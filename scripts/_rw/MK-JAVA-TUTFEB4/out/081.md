буферизованные потоки снижают число обращений к нижележащему источнику. к байтовому потоку добавляется буфер в памяти: чтение и запись идут блоками, а не отдельным вызовом на каждый байт.

### класс `BufferedInputStream`

`BufferedInputStream` копит входные данные в буфере и не ходит в источник на каждый `read` вызывающего кода. конструкторов два:

```java
BufferedInputStream(InputStream inputStream)
BufferedInputStream(InputStream inputStream, int bufSize)
```

первый аргумент это поток ввода, из которого байты читаются в буфер. второй аргумент это размер буфера в байтах. если размер не передан, берётся буфер на 8192 байта. `read` сначала отдаёт байты из уже заполненного буфера и только после его исчерпания запрашивает у вложенного потока следующую порцию.

чтение из `ByteArrayInputStream` через буфер:

```java
import java.io.*;

public class Program {

    public static void main(String[] args) {
        
         String text = "Hello world!";
         byte[] buffer = text.getBytes();
        ByteArrayInputStream in = new ByteArrayInputStream(buffer);
        
        try(BufferedInputStream bis = new BufferedInputStream(in)){
            
            int c;
            while((c=bis.read())!=-1){
        
                System.out.print((char)c);
            }
        }
        catch(Exception e){
            
            System.out.println(e.getMessage());
        }
        System.out.println();
    } 
}
```

конструктор `BufferedInputStream` принимает `InputStream`. в примере это `ByteArrayInputStream`, построенный по байтам строки `"Hello world!"`. метод `read()` общий для потоков ввода: он возвращает очередной байт как `int` в диапазоне 0..255 либо `-1` в конце потока. отдельное значение конца потока нужно потому, что байт `0xFF` тоже должен быть представим. если бы метод возвращал `byte`, этот код совпал бы с `-1` и конец потока нельзя было бы отличить от данных. цикл приводит каждый байт к `char` и печатает его.

тот же обход массива делает один `ByteArrayInputStream`. `BufferedInputStream` оставляет наблюдаемую последовательность байтов прежней и сокращает число вызовов `read` у вложенного потока: данные забираются пачкой в буфер. на массиве в куче вложенный `read` и так дёшев, выигрыш мал. на файле или сокете та же обёртка убирает системный вызов на каждый байт. на месте `ByteArrayInputStream` может стоять любой наследник `InputStream`: буферизация это декоратор над потоком, а не отдельный источник данных.

### класс `BufferedOutputStream`

`BufferedOutputStream` симметрично держит буфер для вывода. байты копятся в памяти и попадают во вложенный поток, когда буфер заполнен, когда вызван `flush()`, либо когда поток закрывают. закрытие в try-with-resources сначала сбрасывает буфер, затем закрывает вложенный поток. без этого сброса хвост, который ещё не заполнил буфер, в файл не попал бы.

если длина одной записи не меньше размера буфера, класс сбрасывает уже накопленное и пишет этот массив во вложенный поток напрямую, минуя побайтовое заполнение. так большой блок не копируется во внутренний массив дважды.

конструкторы:

```java
BufferedOutputStream(OutputStream outputStream)
BufferedOutputStream(OutputStream outputStream, int bufSize)
```

первый аргумент это поток вывода, наследник `OutputStream`. второй аргумент это размер буфера. размер по умолчанию тоже 8192 байта.

запись в файл:

```java
import java.io.*;

public class Program {

    public static void main(String[] args) {
        
        String text = "Hello world!"; // строка для записи
        try(FileOutputStream out=new FileOutputStream("notes.txt"); 
                BufferedOutputStream bos = new BufferedOutputStream(out))
        {
			// перевод строки в байты
            byte[] buffer = text.getBytes();
            bos.write(buffer, 0, buffer.length);
        }
        catch(IOException ex){
            
            System.out.println(ex.getMessage());
        } 
    } 
}
```

в конструктор передан `OutputStream`, здесь это `FileOutputStream` для файла `notes.txt`. строка переводится в байты методом `getBytes()`, и `write` копирует весь массив, от нулевого индекса до `buffer.length`. отдельного нового способа записать байт у `BufferedOutputStream` нет: те же байты принимает и сам `FileOutputStream`. класс сдвигает момент, в который байты достигают файла, и уменьшает число обращений к нему.
