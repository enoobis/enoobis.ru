одним из основных механизмов объектно-ориентированного программирования является наследование. с помощью наследования расширяют функционал уже имеющихся классов за счёт добавления нового функционала или изменения старого. пусть имеется следующий класс `Person`, описывающий отдельного человека:

```java


class Person {

     

    String name;

	

    void print(){

         

        System.out.println("Name: " + name);

    }

}
```

впоследствии может понадобиться ещё один класс, который описывает сотрудника предприятия, класс `Employee`:

```java


class Employee {

     

    String name;

	

    void print(){

         

        System.out.println("Name: " + name);

    }

}
```

этот класс реализует тот же функционал, что и класс `Person`, поскольку сотрудник является человеком. целесообразнее не определять повторно один и тот же функционал, а передать его из класса `Person` в класс `Employee`. для этого класс `Employee` наследуют от класса `Person`:

```java


class Employee extends Person { }
```

чтобы унаследовать один класс от другого, после имени класса-наследника используют ключевое слово `extends`, после которого идёт имя базового класса. для класса `Employee` базовым является `Person`, и поэтому класс `Employee` наследует все те же поля и методы, которые есть в классе `Person`.

наследование реализует отношение is-a (является). объект класса `Employee` также является объектом класса `Person`. в этом отношении класс `Employee` ещё называют производным классом (а также дочерним классом, классом-наследником, подклассом), а класс `Person` базовым классом (а также родительским классом или суперклассом).

в java у класса ровно один прямой суперкласс. если `extends` не записан, суперклассом считается `Object`. один класс не может расширять сразу два класса: множественное наследование реализации в языке отсутствует, его место занимают интерфейсы, которые разбираются отдельно.

затем функционал базового класса (`Person`) используют, обращаясь к объекту производного класса (`Employee`):

```java


public class Program{ 

       

    public static void main (String args[]){

           

        Person tom = new Person();

        tom.name = "Tom";

        tom.print();



        Employee bob = new Employee();

        bob.name = "Bob";

        bob.print();

    }

}



class Person {

     

    String name;



    void print(){

         

        System.out.println("Name: " + name);

    }

}



class Employee extends Person{}
```

благодаря наследованию у объекта класса `Employee` можно обратиться и к полю `name`, и к методу `print`, хотя они определены в классе `Person`.

### наследование конструкторов

если в базовом классе определены конструкторы, в конструкторе производного класса необходимо вызвать один из конструкторов базового класса с помощью ключевого слова `super`. в вызов передаются значения для параметров конструктора:

```java


super(аргументы);
```

конструкторы при этом не наследуются как обычные члены. подкласс объявляет собственный конструктор и сцепляет его с конструктором суперкласса. если в подклассе не объявлен ни один конструктор, компилятор добавляет конструктор без параметров, тело которого вызывает `super()`. такой вызов компилируется только при наличии у суперкласса доступного конструктора без параметров.

например, в классе `Person` определяется конструктор:

```java


class Person {

     

    private String name;



    Person(String name){



        this.name = name;

    }



    void print(){

         

        System.out.println("Name: " + name);

    }

}



class Employee extends Person{



    // надо вызвать конструктор базового класса

    Employee(String name){

        super(name);  // вызываем конструктор базового класса

    }

}
```

здесь конструктор класса `Person` принимает один параметр. поэтому в классе `Employee` в конструкторе нужно вызвать конструктор класса `Person`. вызов `super(name)` представляет собой вызов конструктора класса `Person`.

при вызове конструктора после слова `super` в скобках идёт перечисление передаваемых аргументов. установка имени сотрудника делегируется конструктору базового класса.

даже если производный класс никакой другой работы в конструкторе не производит, как в примере выше, всё равно необходимо вызвать конструктор базового класса. у `Person` объявлен только конструктор с параметром `String`, поэтому опустить `super(name)` нельзя: неявный вызов `super()` не нашёл бы подходящего конструктора.

использование классов:

```java


public class Program{ 

       

    public static void main (String args[]){

           

        Person tom = new Person("Tom");

        tom.print();



        Employee bob = new Employee("Bob");

        bob.print();

    }

}

class Person {

     

    private String name;



    Person(String name){



        this.name = name;

    }



    void print(){

         

        System.out.println("Name: " + name);

    }

}



class Employee extends Person{



    Employee(String name){

        super(name);

    }

}
```

при определении конструктора в производном классе до версии java 25 вызов конструктора суперкласса должен был выполняться до всех остальных инструкций. пример:

```java


Employee(String name){

    super(name);   // До Java 25 вызов конструктора мог быть только в самом начале



    // все остальные инструкции

    System.out.println("Employee created");

}
```

начиная с версии java 25 вызов конструктора суперкласса может располагаться не только в начале конструктора производного класса (jep 513, flexible constructor bodies). пример:

```java


Employee(String name){



    System.out.println("Employee creation started");



    super(name);   // Начиная с Java 25 можно поместить вызов конструктора в любое место

}
```

перед явным вызовом `super` или `this` по-прежнему нельзя использовать текущий экземпляр: читать его поля и вызывать методы экземпляра. разрешено присваивать поля, объявленные в этом же классе, и выполнять код, который к экземпляру не обращается. вызов `println` в листинге экземпляр не трогает, поэтому такая инструкция разрешена до `super`.

### расширение базового класса

производный класс не только наследует функционал от базового класса, но и может расширять его, добавляя свои поля и методы. класс `Employee` представляет работника некоторой компании, и соответственно в нём хранят данные об этой компании:

```java


public class Program{ 

       

    public static void main (String args[]){

           

        Employee bob = new Employee("Bob", "Google");

        bob.print();    // Name: Bob

        bob.work();     // Company: Google

    }

}



class Employee extends Person{



    private String company;



    Employee(String name, String company){

        super(name); 

        this.company = company;

    }



    // выводим данные о компании

    void work(){

        System.out.println("Company: " + company);

    }

}  



class Person {

     

    private String name;



    Person(String name){



        this.name = name;

    }



    void print(){

         

        System.out.println("Name: " + name);

    }

}
```

класс `Employee` добавляет поле `company`, которое хранит место работы сотрудника, а также метод `work` для вывода названия компании.

### доступ к функциональности базового класса

производный класс имеет доступ ко всем методам и полям базового класса (даже если базовый класс находится в другом пакете), которые определены с модификаторами `public` и `protected`. в примере выше поле `name` в классе `Person` сделано приватным (определённым с модификатором `private`). поэтому класс `Employee` не имеет к нему доступа:

```java


class Employee extends Person{



    private String company;



    Employee(String name, String company){

        super(name); 

        this.company = company;

    }



    // выводим данные о компании

    void work(){

        System.out.println("Name: " + name);  // ! Ошибка: так нельзя - переменная name - приватная

        System.out.println("Company: " + company);

    }

}
```

при попытке скомпилировать этот класс возникает ошибка: в методе `work` идёт обращение к переменной `name` базового класса `Person`, которая является приватной. модификатор `private` ограничивает область видимости телом класса, где член объявлен, и подкласс в эту область не входит.

определение полей приватными представляет стандартную практику: данные лучше инкапсулировать и защитить от некорректного вмешательства извне. бывают случаи, когда требуется открыть доступ к компоненту (полю или методу) базового класса только для производных классов. в этом случае компонент класса объявляется с помощью модификатора `protected`. если суперкласс `Person` объявляет поле `name` с модификатором `protected`, методы класса `Employee` обращаются к нему напрямую:

```java


public class Program{ 

       

    public static void main (String args[]){

           

        Employee bob = new Employee("Bob", "Google");

        bob.work();     // Name: Bob

                        // Company: Google

    }

}



class Employee extends Person{



    private String company;



    Employee(String name, String company){

        super(name); 

        this.company = company;

    }



    // выводим данные о компании

    void work(){

        System.out.println("Name: " + name);  // так можно - переменная name - protected

        System.out.println("Company: " + company);

    }

}  

class Person {

     

    protected String name;



    Person(String name){ this.name = name;  }



    void print(){

         

        System.out.println("Name: " + name);

    }

}
```

в java поле с модификатором `protected` доступно любому классу в том же пакете. поэтому для надлежащей инкапсуляции класс `Person` помещают в отдельный пакет. в этом случае поля и методы с модификатором `protected` будут доступны классу `Employee` и другим унаследованным классам, а классам чужого пакета, не входящим в иерархию, останутся недоступны. из другого пакета доступ подкласса к защищённому члену экземпляра разрешён, когда он выполняется в теле подкласса и тип ссылки является этим подклассом или его дальнейшим наследником.

### переопределение методов

производный класс может определять свои методы, а может переопределять методы, которые унаследованы от базового класса. при переопределении метод производного класса имеет то же имя и те же типы параметров, что и метод базового класса. пример:

```java


public class Program{ 

       

    public static void main (String args[]){

           

        Employee bob = new Employee("Bob", "Google");

        bob.print();

    }

}



class Employee extends Person{



    private String company;



    Employee(String name, String company){

        super(name); 

        this.company = company;

    }

    @Override

    void print(){

        System.out.println("Company: " + company);

    }

}  

class Person {

     

    private String name;



    Person(String name){ this.name = name;  }



    void print(){

         

        System.out.println("Name: " + name);

    }

}
```

производный класс `Employee` переопределяет метод `print` из базового класса. перед переопределяемым методом указывается аннотация `@Override`. данная аннотация в принципе необязательна. если она указана, компилятор проверяет, что метод действительно переопределяет член суперкласса: расхождение в сигнатуре становится ошибкой компиляции. при включённой аннотации отдельная перегрузка из-за опечатки не возникает.

при переопределении метод должен иметь уровень доступа не меньше, чем уровень доступа в базовом классе. например, если в базовом классе метод имеет модификатор `public`, то и в производном классе метод должен иметь модификатор `public`. сузить доступ до `protected`, пакетного или `private` нельзя. тип результата совпадает с типом в суперклассе или является его подтипом: ковариантное возвращаемое значение допустимо начиная с java 5.

в классе `Employee` реализация метода `print` выводит значение поля `company` на консоль. если переопределённый метод `print` должен выводить и значение поля `name` из базового класса, напрямую в классе `Employee` обращаться к полю `name` нельзя, потому что оно приватное. реализацию метода базового класса вызывают в производном классе с помощью слова `super`:

```java


super.метод(аргументы)
```

например:

```java


public class Program{ 

       

    public static void main (String args[]){

           

        Employee bob = new Employee("Bob", "Google");

        bob.print();        // Name: Bob

                            // Company: Google

    }

}



class Employee extends Person{



    private String company;



    Employee(String name, String company){

        super(name); 

        this.company = company;

    }

    @Override

    void print(){

        super.print();  // вызов реализации метожжа print из класса Person

        System.out.println("Company: " + company);

    }

}  

class Person {

     

    private String name;



    Person(String name){ this.name = name;  }



    void print(){

         

        System.out.println("Name: " + name);

    }

}
```

в методе `print` класса `Employee` с помощью ключевого слова `super` выполняется обращение к реализации метода `print` из базового класса, которая выводит имя:

```java
super.print();
```

вызов `super.print()` связывается с `Person.print` статически. динамическая диспетчеризация на этом вызове не выполняется, поэтому реализация `Employee` не вызывает сама себя.
