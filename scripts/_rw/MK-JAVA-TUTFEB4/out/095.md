поток платформы создают одним из двух способов:

- реализация интерфейса `Runnable`

- подкласс `Thread` с переопределённым `run()`

`Runnable` отделяет задачу от механизма исполнения: тот же объект передают и в `Thread`, и в пул `ExecutorService`, и в виртуальный поток. подкласс `Thread` связывает задачу с конкретным классом потока и занимает единственный слот наследования. в новом коде задачу задают реализацией `Runnable` или лямбдой.

оба способа ниже.

### реализация интерфейса `Runnable`

`Runnable` описывает операцию без результата и без проверяемых исключений. в интерфейсе один метод:

```java


interface Runnable{

	

	void run();

}
```

код, который выполнится при запуске потока, записывают в `run()`.

создание и запуск складываются из трёх шагов.

- `Runnable` функциональный интерфейс с одним абстрактным методом, поэтому реализацию можно задать лямбдой:

```java


Runnable task = ()->{



    // здесь действия потока

};
```

- объект `Thread` создаётся конструктором, который принимает `Runnable`. у класса есть и другие конструкторы. здесь используется одноаргументный:

```java


var t = new Thread(task);
```

- `start()` ставит поток в очередь на исполнение:

```java


t.start();
```

полный пример:

```java


public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        Runnable task = ()->{       // определяем действия потока

            System.out.println("Runnable started...");



            System.out.println("Runnable finished...");

        };



        var t = new Thread(task);  // определяем поток



        t.start();  // запускаем поток



        System.out.println("Main thread finished...");

    }

}
```

в созданном потоке печатаются два сообщения. возможный вывод:

```bash


Main thread started...

Main thread finished...

Runnable started...

Runnable finished...
```

`start()` вызывается раньше последней инструкции `main`, а строки дочернего потока оказываются после `"Main thread finished..."`. `start()` переводит поток в `RUNNABLE` и сам квант не гарантирует. планировщик может сначала доисполнить главный поток, и `main` успевает допечатать свою строку. возврат из `main` процесс не останавливает, пока жив другой поток, который не является демоном.

создание объекта отделено от запуска:

```java
var t = new Thread(task);
```

оператор `new` и конструктор выделяют объект и оставляют его в состоянии `NEW`. код задачи ещё не выполняется.

после `start()` состояние становится `RUNNABLE`. для виртуальной машины это готовность к исполнению: планировщик операционной системы решает, выдать ли квант сейчас. получив процессор, поток может быть вытеснен, чтобы исполнялись другие. политика вытеснения определяется операционной системой и видом потока, платформенный он или виртуальный.

вместо лямбды задачу оформляют отдельным классом, который реализует `Runnable`:

```java


class MyTask implements Runnable {

    

    public void run(){  // определяем действия потока

         

        System.out.println("Runnable started...");

        System.out.println("Runnable finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        Runnable task = new MyTask();



        var t = new Thread(task);  // определяем поток



        t.start();  // запускаем поток



        System.out.println("Main thread finished...");

    }

}
```

### наследование от класса `Thread`

второй способ: подкласс `Thread` переопределяет `run()`.

```java


class MyThread extends Thread {

     

    MyThread(){

        super();  // вызываем конструктор базового класса

    }

     

    public void run(){

         

        System.out.println("MyThread started...");

        System.out.println("MyThread finished...");

    }

}



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        var t = new MyThread();  // определяем поток



        t.start();  // запускаем поток



        System.out.println("Main thread finished...");

    }

}
```

класс потока называется `MyThread`. конструктор вызывает конструктор суперкласса `Thread`. переопределённый `run()` и есть тело потока. если `run()` не переопределить и в конструктор не передать `Runnable`, поток завершится сразу: реализация `Thread.run()` вызывает `run()` у переданной задачи, а при её отсутствии ничего не делает.

запуск в `main`:

```java


var t = new MyThread();  // определяем поток

t.start();  // запускаем поток
```

`start()` приводит к выполнению переопределённого `run()` в новом потоке. прямой вызов `t.run()` выполнил бы тот же текст в главном потоке.

консольный вывод:

```bash


Main thread started...

Main thread finished...

MyThread started... 

MyThread finished...
```

порядок строк зависит от планировщика. в показанном прогоне главный поток успевает завершить печать раньше, чем `MyThread` получает квант.

### запуск массива потоков

тем же способом запускают сразу несколько потоков:

```java


class MyTask implements Runnable {

    

    private String name;



    MyTask(String name) { this.name = name;}



    public void run(){  // определяем действия потока

         

        System.out.println(name + " started...");

        System.out.println(name + " finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        for(int i=1; i < 6; i++){



            var task = new MyTask("MyTask_" + i);

            new Thread(task).start();

        }



        System.out.println("Main thread finished...");

    }

}
```

чтобы строки разных потоков различались, в `MyTask` через конструктор передаётся имя. цикл берёт `i` от 1 включительно до 6 исключительно и запускает пять потоков с именами от `MyTask_1` до `MyTask_5`. имя собирается из номера итерации.

вывод недетерминирован. один из возможных прогонов:

```bash


Main thread started...

Main thread finished...

MyTask_2 started...

MyTask_1 started...

MyTask_1 finished...

MyTask_4 started...

MyTask_3 started...

MyTask_3 finished...

MyTask_2 finished...

MyTask_4 finished...

MyTask_5 started...

MyTask_5 finished...
```

сообщения разных задач перемешаны. каждый `start()` только публикует поток планировщику, дальнейший порядок квантов от номера цикла не зависит. перемежаемая печать показывает конкурентное выполнение: задачи продвигаются независимо друг от друга. одновременное исполнение на разных ядрах возможно, когда свободных ядер несколько и интервалы работы перекрываются.

### конструкторы `Thread`

у `Thread` несколько конструкторов. опорный вариант, к которому сводятся остальные:

```java


Thread(ThreadGroup group, Runnable task, String name)
```

параметры конструктора:

- `group`: группа `ThreadGroup`. при `null` группой становится группа текущего потока

- `task`: объект `Runnable`, его `run()` задаёт тело потока. при `null` вызывается `run()` самого объекта `Thread`, этим пользуются подклассы, которые переопределяют `run()`

- `name`: имя создаваемого потока

этот вариант удобно держать в голове, потому что остальные конструкторы неявно выходят на него. конструктор из задачи и имени:

```java
Thread(Runnable task, String name)
```

даёт тот же эффект, что и вызов

```java
Thread (null, task, name)
```

конструктор из одной задачи:

```java
Thread(Runnable task)
```

совпадает по эффекту с вызовом

```java
Thread (null, task, gname)
```

здесь `gname` это имя, которое виртуальная машина генерирует сама, в форме `"Thread-" + n`, где `n` целое число.

следующий пример читает имя у уже запущенного потока. в задаче отдельного поля для имени нет:

```java


class MyTask implements Runnable {



    public void run(){  // определяем действия потока

         

        // получаем имя текущего потока

        String name = Thread.currentThread().getName();

        System.out.println(name + " started...");

        System.out.println(name + " finished...");

    }

} 



public class Program {

  

    public static void main(String[] args) {

          

        System.out.println("Main thread started...");



        for(int i=1; i < 6; i++){



            var task = new MyTask();

            new Thread(task).start();

        }



        System.out.println("Main thread finished...");

    }

}
```

внутри `run()` вызов `Thread.currentThread().getName()` возвращает имя того потока, который исполняет тело. при конструкторе с одним `Runnable` это автоматически назначенное `"Thread-" + n`. возможный вывод:

```bash


Main thread started...

Main thread finished...

Thread-2 started...

Thread-0 started...

Thread-3 started...

Thread-4 started...

Thread-0 finished...

Thread-1 started...

Thread-2 finished...

Thread-3 finished...

Thread-4 finished...

Thread-1 finished...
```

номера в именах `Thread-0` ... `Thread-4` отражают порядок создания. порядок получения кванта другой: в прогоне первой печатается строка `Thread-2`.

такие имена плохо отличаются по смыслу. осмысленное имя передают вторым аргументом конструктора `Thread`:

```java


for(int i=1; i < 6; i++){



    var task = new MyTask();

    new Thread(task, "MyTask_" + i).start();

}
```

в выводе тогда стоят имена, заданные в цикле:

```bash


Main thread started...

Main thread finished...

MyTask_1 started...

MyTask_4 started...

MyTask_1 finished...

MyTask_3 started...

MyTask_4 finished...

MyTask_3 finished...

MyTask_5 started...

MyTask_5 finished...

MyTask_2 started...

MyTask_2 finished...
```
