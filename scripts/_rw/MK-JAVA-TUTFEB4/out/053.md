### функциональный интерфейс

в java выделен особый вид интерфейсов, функциональный интерфейс. функциональный интерфейс содержит ровно один абстрактный метод, то есть метод без реализации. методы `default` и `static`, у которых реализация уже есть, в этот подсчет не входят. простейший пример:

```java

interface Message{
    void print();
}
```

интерфейс `Message` с единственным абстрактным методом `print` удовлетворяет определению и считается функциональным. аннотация `@FunctionalInterface` для этого не обязательна. если ее поставить, компилятор проверит, что абстрактный метод действительно один, и отвергнет интерфейс при втором абстрактном методе.

как и у любого интерфейса, у функционального можно объявить переменную:

```java

Message mes;
```

переменная `mes` имеет тип `Message` и пока не ссылается на экземпляр. ниже экземпляр задается ссылкой на уже существующий метод.

### ссылки на метод

функциональный интерфейс служит целевым типом ссылки на метод (method reference). ссылка обозначает готовое действие, а не класс, в котором метод интерфейса написан вручную.

ссылка на метод записывается так:

```java

имя_класса::имя_статического_метода     // если метод статический

объект_класса::имя_метода       // если метод нестатический
```

перед `::` стоит либо имя класса, если метод статический, либо выражение, дающее объект, если метод нестатический. после `::` стоит имя метода без списка параметров и без скобок. аргументы появятся позже, в вызове метода интерфейса.

пример присваивания ссылки:

```java

public class Program {

    public static void main(String[] args) {
        
        Message mes;
        mes = Program::hello;
    }

    static void hello(){
        System.out.println("Hello enoobis.ru");
    }
}
interface Message{
    void print();
}
```

переменной `mes` присваивается ссылка на статический метод `hello` класса `Program`. ссылка выглядит так:

```java
Program::hello
```

метод, на который ведет ссылка, должен быть совместим с единственным абстрактным методом функционального интерфейса по параметрам и по результату. метод `print` в `Message` имеет тип результата `void` и не принимает параметров. статический метод `hello` устроен так же: параметров нет, результат `void`. при несовпадении арности или типов присваивание ссылки не компилируется.

далее метод вызывается через переменную интерфейса:

```java

public class Program {

    public static void main(String[] args) {
        
        Message mes;
        mes = Program::hello;

        mes.print(); // вызываем метод по ссылке
    }

    static void hello(){
        System.out.println("Hello enoobis.ru");
    }
}
interface Message{
    void print();
}
```

вызов

```java
mes.print();
```

выполняет метод `hello()` и печатает `Hello enoobis.ru`. в точке вызова написан `print`, а управление переходит в метод, который был связан с переменной.

ссылка на метод предписывает компилятору создать экземпляр функционального интерфейса и реализовать его единственный абстрактный метод вызовом указанного метода. в примере получается значение типа `Message`, в котором `hello()` служит телом `print()`. начиная с java 8 эта связка транслируется через инструкцию `invokedynamic` и фабрику `LambdaMetafactory`. отдельный исходный класс для такой реализации не пишется: фабрика связывается с целевым методом при первом исполнении участка.

если метод нестатический, в ссылке вместо имени класса стоит объект этого класса, приемник вызова:

```java

public class Program {

    public static void main(String[] args) {
        
        Program prog = new Program();
        Message mes = prog::hello;

        mes.print();    // Hello enoobis.ru
    }

    void hello(){
        System.out.println("Hello enoobis.ru");
    }
}
interface Message{
    void print();
}
```

метод `hello()` объявлен без `static`. для ссылки сначала создается объект `Program`, затем ссылка на его метод передается переменной `mes`:

```java

Program prog = new Program();
Message mes = prog::hello;
```

такая ссылка называется связанной (bound method reference). приемник `prog` фиксируется в момент создания ссылки. абстрактный метод интерфейса дополнительных аргументов под приемник не получает: `print()` по-прежнему вызывается без параметров, а `hello()` исполняется на уже захваченном объекте.

#### пример метода с параметрами

следующий пример ссылается на методы с параметрами и с возвращаемым значением.

```java

public class Program {

    public static void main(String[] args) {
        
        Operation op = Operations::add;
        System.out.println(op.execute(5, 4));       // 9

        op = Operations::sub;
        System.out.println(op.execute(5, 4));       // 1

        op = Operations::mul;
        System.out.println(op.execute(5, 4));       // 20
    }
}
interface Operation{
    int execute(int x, int y);
}
class Operations{

    static int add(int a, int b){ return a + b; }
    static int sub(int a, int b){ return a - b; }
    static int mul(int a, int b){ return a * b; }
}
```

функциональный интерфейс `Operation` объявляет один абстрактный метод `execute`:

```java

interface Operation{
    int execute(int x, int y);
}
```

метод принимает два `int` и возвращает `int`. класс `Operations` содержит три статических метода той же формы: `add`, `sub` и `mul`.

в `main` переменная `op` типа `Operation` получает ссылку на `Operations.add`:

```java

Operation op = Operations::add;
```

присваивание корректно. типы параметров и тип результата `Operations.add` совпадают с типами параметров и результата `execute`. имена параметров (`a`, `b` у метода и `x`, `y` у интерфейса) на совместимость не влияют, сопоставляются позиции и типы.

вызов через переменную `op` передает аргументы уже методу интерфейса:

```java

System.out.println(op.execute(5, 4));
```

`op.execute(5, 4)` выполняет `add` и печатает `9`.

затем переменной присваивается ссылка на другой метод, и тот же вызов с теми же аргументами дает другой результат:

```java

op = Operations::sub;
System.out.println(op.execute(5, 4));       // 1
```

после присваивания `Operations::sub` вызов `execute(5, 4)` печатает `1`. та же переменная далее может указывать и на `Operations::mul`, тогда результат равен `20`. тип переменной при этих присваиваниях не меняется: меняется метод, связанный с единственной реализацией `execute`.

### ссылки на метод как параметры методов

ссылку на метод можно передать туда, где параметр имеет тип функционального интерфейса. параметр обозначает действие, а конкретный метод выбирается в точке вызова.

```java

public class Program {

    public static void main(String[] args) {
         
        doOperation(10, 4, Operations::add);  // 14
        doOperation(10, 4, Operations::sub);  // 6
        doOperation(10, 4, Operations::mul);  // 40
    } 

    static void doOperation(int a, int b, Operation op)
    {
        System.out.println(op.execute(a, b));
    }
}
interface Operation{
    int execute(int x, int y);
}
class Operations{

    static int add(int a, int b){ return a + b; }
    static int sub(int a, int b){ return a - b; }
    static int mul(int a, int b){ return a * b; }
}
```

вычисления вынесены в класс `Operations` и представлены статическими методами `add`, `sub` и `mul`. в вызов `doOperation` они передаются выражениями вида `Operations::add`.

```java
doOperation(10, 4, Operations::add);  // 14
```

метод `doOperation` принимает два операнда и значение `Operation`. тело не знает, сложение это, вычитание или умножение: оно вызывает `op.execute(a, b)` и печатает результат. для аргументов 10 и 4 ссылка `Operations::add` дает 14, `Operations::sub` дает 6, `Operations::mul` дает 40.

если методы нестатические, вместо имени класса в ссылке стоит имя объекта:

```java

public class Program {

    public static void main(String[] args) {
         
        Operations ops = new Operations();
        doOperation(10, 4, ops::add);  // 14
        doOperation(10, 4, ops::sub);  // 6
        doOperation(10, 4, ops::mul);  // 40
    } 

    static void doOperation(int a, int b, Operation op)
    {
        System.out.println(op.execute(a, b));
    }
}
interface Operation{
    int execute(int x, int y);
}
class Operations{

    int add(int a, int b){ return a + b; }
    int sub(int a, int b){ return a - b; }
    int mul(int a, int b){ return a * b; }
}
```

объект `ops` создается один раз и служит приемником для `ops::add`, `ops::sub` и `ops::mul`. сигнатура `doOperation` при этом не меняется: параметр по-прежнему имеет тип `Operation`, а различие статического и нестатического метода остается по ту сторону ссылки. связанная ссылка сама хранит приемник.

### ссылки на метод как результаты методов

метод может возвращать ссылку на метод. тип результата тогда тоже является функциональным интерфейсом.

```java

import java.util.function.BiFunction;

public class Program {

    public static void main(String[] args) {
        
        Operation action = select(1);  // получаем ссылку на функцию Sum
        System.out.println(action.execute(8, 5)); // 13

        action = select(2);  // получаем ссылку на функцию Subtract
        System.out.println(action.execute(8, 5));// 3

        action = select(3);  // получаем ссылку на функцию Multiply
        System.out.println(action.execute(8, 5)); // 40
    }

    static Operation select(int choice){

        // возвращаем нужную функцию в зависимости от choice
        switch (choice)
        {
            case 2:
                return Program::subtract;
            case 3:
                return Program::multiply;
            default:
                return Program::sum;
        }
    }
    static int sum(int a, int b) { return a + b; }
    static int subtract(int a, int b) { return a - b; }
    static int multiply(int a, int b) { return a * b; }
}
// Operation представляет метод, который принимает два числа int и возвращает int
interface Operation {
    int execute(int a, int b);
}
```

метод `select` по значению параметра `choice` возвращает ссылку на один из трех методов: `sum`, `subtract` или `multiply`.

```java

static Operation select(int choice){

    switch (choice){

        case 2:
            return Program::subtract;
        case 3:
            return Program::multiply;
        default:
            return Program::sum;
    }
}
```

ветка `case 2` возвращает `Program::subtract`, ветка `case 3` возвращает `Program::multiply`, ветка `default` возвращает `Program::sum`. все три метода статические, принимают два `int` и возвращают `int`, поэтому каждый из них совместим с `Operation.execute`.

в `main` результат `select` сохраняется в переменную:

```java
Operation action = select(1);
```

вызов `select(1)` не попадает в ветки 2 и 3, срабатывает `default`, и переменная `action` обозначает ссылку `Program::sum`. последующий `action.execute(8, 5)` печатает 13. `select(2)` связывает `action` с `Program::subtract` и дает 3. `select(3)` связывает ее с `Program::multiply` и дает 40.

интерфейс `Operation` в конце листинга описывает метод, который принимает два `int` и возвращает `int`. импорт `java.util.function.BiFunction` в файле присутствует. в теле он не используется: для той же формы функции, два аргумента и результат, здесь объявлен собственный интерфейс `Operation`. стандартный `BiFunction<Integer, Integer, Integer>` описывает ту же арность, но пример обходится своим типом.

### ссылки на конструкторы

конструктор записывается ссылкой вида `название_класса::new`.

```java

public class Program {

    public static void main(String[] args) {
        
        UserBuilder userBuilder = User::new;
        User user = userBuilder.create("Tom");
        System.out.println(user.getName());
    }
}
interface UserBuilder{
    User create(String name);
}

class User{
    
    private String name;
    String getName(){
        return name;
    }
    
    User(String n){
        this.name=n;
    }
}
```

абстрактный метод функционального интерфейса должен принимать тот же список параметров, что и выбранный конструктор, и возвращать объект данного класса. в примере `UserBuilder.create(String)` соответствует конструктору `User(String)`. выражение `User::new` конструктор сразу не вызывает. вызов происходит в `userBuilder.create("Tom")`, и уже этот вызов выполняет `new` с аргументом `"Tom"`. `getName()` затем возвращает записанное имя.

аналогично выражение `Person[]::new` обозначает создание массива объектов `Person`. ссылка на конструктор массива сопоставляется с функциональным интерфейсом, чей метод принимает длину типа `int` и возвращает массив. элемент массива при этом получает значение по умолчанию. для ссылочного типа `Person` это `null`, конструктор `Person` для элементов не вызывается.
