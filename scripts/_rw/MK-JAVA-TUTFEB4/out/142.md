класс `java.lang.reflect.Method` описывает один метод класса или интерфейса и даёт к этому методу доступ во время выполнения: можно прочитать его объявление и вызвать его, не записывая вызов в исходном тексте. основные методы класса `Method`:

- `String getName()`: возвращает имя метода

- `Class[] getExceptionTypes()`: возвращает типы исключений из раздела `throws` в виде массива объектов `Class`

- `int getModifiers()`: возвращает целое число, в котором отдельные биты описывают модификаторы

- `int getParameterCount()`: возвращает количество формальных параметров

- `Class[] getParameterTypes()`: возвращает типы параметров метода в порядке объявления

- `Class getReturnType()`: возвращает тип возвращаемого значения. для метода `void` это `void.class`

- `Object invoke(Object obj, Object... args)`: вызывает метод, представленный этим объектом `Method`, у указанного объекта и с указанными аргументами

### получение методов

методы типа получают у объекта `Class`:

- `Method[] getMethods()`: возвращает массив объектов `Method` для открытых методов (с модификатором `public`) данного класса, его суперклассов и суперинтерфейсов. в выборку входят и публичные методы `Object`

- `Method[] getDeclaredMethods()`: возвращает массив объектов `Method` для всех методов, объявленных в данном классе, без унаследованных. если таких методов нет, а также если объект `Class` представляет примитивный тип или массив, метод возвращает массив нулевой длины. в массив могут попасть методы, которые породил компилятор: мосты, нужные из-за стирания обобщённых типов, и прочие синтетические методы

- `Method getMethod(String name, Class... parameterTypes)`: возвращает объект `Method` для публичного метода с заданным именем. второй параметр задаёт типы параметров и тем самым выбирает перегрузку. поиск идёт и среди публичных методов суперклассов. если такого публичного метода нет, метод генерирует исключение `NoSuchMethodException`

- `Method getDeclaredMethod(String name, Class... parameterTypes)`: возвращает объект `Method` для метода, объявленного в данном классе, с любым модификатором доступа. второй параметр задаёт типы параметров. унаследованные методы не просматриваются. если такого метода нет, генерируется исключение `NoSuchMethodException`

пример получает все объявленные методы класса `Operation`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Operation.class;

        Method[] methods = cl.getDeclaredMethods();

        for(Method m : methods){

            System.out.println(m);

        }

    }

}



class Operation{



    static int sum(int val1, int val2){

        return val1 + val2;

    }



    static double sum(double val1, double val2){

        return val1 + val2;

    }



    static int subtract(int val1, int val2){

        return val1 - val2;

    }

}
```

в `Operation` объявлены три статических метода: две перегрузки `sum` и метод `subtract`. `getDeclaredMethods()` возвращает все три. консольный вывод:

```bash


static int Operation.sum(int,int)

static double Operation.sum(double, double)

static int Operation.subtract(int,int)
```

строка метода содержит модификаторы, тип результата, квалифицированное имя и типы параметров. две перегрузки `sum` различаются типами параметров: `(int,int)` и `(double,double)`. порядок строк спецификация не фиксирует.

### исследование метода

разбор метода `sum` класса `Operation`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Operation.class;

        try{

            // получаем метод sum с двумя параметрами типа int

            Method m = cl.getDeclaredMethod("sum", int.class, int.class);

            // получаем имя метода

            String methodName = m.getName();

            // получаем модификаторы

            String modifiers = Modifier.toString(m.getModifiers());



            // получаем количество параметров

            int paramsCount = m.getParameterCount();

            // получаем возвращаемый тип

            Class retType = m.getReturnType();

            // получаем типы параметров

            Class[] paramTypes = m.getParameterTypes();



            // выводим информацию о методе

            System.out.print(modifiers + " " + retType.getName() + " " + methodName + "(");

            for (int j = 0; j < paramsCount; j++)

            {

                if (j > 0) System.out.print(", ");

                System.out.print(paramTypes[j].getName());

            }

            System.out.println(");");

        }

        catch(Exception ex){



            System.out.println(ex);

        }

    }

}



class Operation{



    static int sum(int val1, int val2){

        return val1 + val2;

    }



    static double sum(double val1, double val2){

        return val1 + val2;

    }



    static int subtract(int val1, int val2){

        return val1 - val2;

    }

}
```

выбирается перегрузка `sum` с двумя параметрами типа `int`. имя без типов параметров перегрузку не определяет:

```java
Method m = cl.getDeclaredMethod("sum", int.class, int.class);
```

дальше читаются имя, модификаторы через `Modifier.toString`, число параметров, тип результата и массив типов параметров. цикл печатает типы через запятую и не ставит запятую перед первым типом. консольный вывод:

```bash
static int sum(int, int);
```

вызов метода выполняет `invoke`:

```java


public Object invoke(Object obj, Object... args)

              throws IllegalAccessException, InvocationTargetException
```

первый параметр (`obj`) задаёт объект, у которого вызывается метод. если метод статический, ссылка `obj` игнорируется. обычное значение в этом месте есть `null`.

второй параметр (`args`) задаёт аргументы вызываемого метода. если у метода нет параметров, `args` опускают. форма `Object...` означает, что аргументы передаются списком переменной длины, как в вызове `m.invoke(null, val1, val2)`.

возвращаемое значение `invoke` есть результат вызываемого метода. примитив приходит упакованным, а вызов метода с типом `void` возвращает `null`. исключение, выброшенное самим методом, оборачивается в `InvocationTargetException`: исходная причина доступна через `getCause()`. отказ в доступе даёт `IllegalAccessException`.

### вызов статического метода

вызов статического метода `sum` класса `Operation`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Operation.class;

        try{

            // получаем метод sum с двумя параметрами типа int

            Method m = cl.getDeclaredMethod("sum", int.class, int.class);

            int val1 = 23;

            int val2 = 4;

            // вызываем метод и получаем результат

            int result = (int) m.invoke(null, val1, val2);



            System.out.printf("sum(%d, %d) = %d\n", val1, val2, result);        // sum(23, 4) = 27

        }       

        catch(Exception ex){



            System.out.println(ex);

        }

    }

}



class Operation{



    static int sum(int val1, int val2){

        return val1 + val2;

    }



    static int subtract(int val1, int val2){

        return val1 - val2;

    }

}
```

метод `sum` статический, поэтому первым аргументом `invoke` передаётся `null`:

```java
int result = (int) m.invoke(null, val1, val2);
```

результат приводят к `int`. выбранная перегрузка возвращает `int`, а `invoke` отдаёт это значение упакованным в `Integer`. приведение к примитиву выполняет распаковку. консольный вывод:

```bash
sum(23, 4) = 27
```

### вызов нестатического метода

вызов метода экземпляра выглядит так:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        // объект, для которого будет вызываться метод

        Person tom = new Person("Tom");

        Class cl = tom.getClass();

        try{

            // получаем метод setName с параметром типа String

            Method m = cl.getDeclaredMethod("setName", String.class);

            // новое имя

            String name = "Eugene";

            // вызываем метод

            m.invoke(tom, name);



            tom.print();        // Person Eugene

        }       

        catch(Exception ex){



            System.out.println(ex);

        }

    }

}

class Person {

     

    private String name;



    void setName(String name){ this.name = name; }



    Person(String name){  this.name = name; }

    

    void print(){

        System.out.println("Person " + name);

    }

}
```

у объекта `Person` вызывается `setName()`, и поле `name` получает новое значение. первым аргументом `invoke` передаётся экземпляр `tom`: для метода экземпляра это получатель, та же ссылка, которая внутри метода видна как `this`. `setName` объявлен без модификатора доступа, то есть доступен в пределах пакета. класс `Program` находится в том же пакете по умолчанию, поэтому вызов проходит без `setAccessible`. `print()` печатает строку `Person Eugene`.

### приватные методы

как и для полей и конструкторов, рефлексия по умолчанию запрещает вызов метода с модификатором `private`. доступ открывают методом `setAccessible()`, передав в него `true`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Person tom = new Person("Tom");

        Class cl = tom.getClass();



        try{

            Method m = cl.getDeclaredMethod("setName", String.class);

            m.setAccessible(true);      // открываем доступ к методу



            String name = "Eugene";



            m.invoke(tom, name);



            tom.print();        // Person Eugene

        }       

        catch(Exception ex){



            System.out.println(ex);

        }

    }

}

class Person {

     

    private String name;

    // приватный метод

    private void setName(String name){ this.name = name; }



    Person(String name){  this.name = name; }

    

    void print(){

        System.out.println("Person " + name);

    }

}
```

здесь `setName` объявлен как `private`. `getDeclaredMethod` такое объявление находит: поиск среди объявленных членов закрытые методы не отбрасывает. отбрасывает их последующий `invoke`, пока проверка доступа включена. после `setAccessible(true)` проверка снята, и `invoke(tom, name)` меняет поле. если модуль не открыл пакет, `setAccessible` завершается отказом, как и для закрытого поля. `print()` печатает строку `Person Eugene`.
