объекты `String` неизменяемы: операция, которая по смыслу меняет текст, выделяет новый объект и копирует в него символы. при многократной конкатенации в цикле стоимость каждого шага линейна по текущей длине, а сумма шагов квадратична. `StringBuffer` и `StringBuilder` задают изменяемую последовательность символов. содержимое меняется в том же объекте, внутренний массив растёт по мере надобности, и серия дозаписей остаётся амортизированно линейной.

публичный набор конструкторов и методов у классов один и тот же, общая реализация буфера в `java.lang` тоже одна. расходятся они моделью синхронизации. каждый метод `StringBuffer` захватывает монитор экземпляра, поэтому один объект допустимо публиковать нескольким потокам: освобождение монитора и следующий захват того же монитора образуют отношение happens-before. синхронизирован при этом отдельный вызов. несколько последовательных вызовов в одну атомарную операцию сами не складываются, для составного действия нужна внешняя блокировка. методы `StringBuilder` монитор не захватывают. если буфером владеет один поток, лишний захват только увеличивает стоимость, и берут `StringBuilder`. `StringBuffer` есть в библиотеке с java 1.0, `StringBuilder` добавлен в java 5 как вариант того же буфера без синхронизации.

`StringBuffer` определяет четыре конструктора:

```java


StringBuffer()

StringBuffer(int capacity)

StringBuffer(String str)

StringBuffer(CharSequence chars)
```

те же четыре конструктора определяет `StringBuilder`:

```java


StringBuilder()

StringBuilder(int capacity)

StringBuilder(String str)

StringBuilder(CharSequence chars)
```

дальше семантика показана на `StringBuilder`. у `StringBuffer` сигнатуры и наблюдаемый результат совпадают, отличие остаётся в синхронизации.

операция, которой не хватает текущего массива, перераспределяет память. чтобы копирование не случалось на каждый символ, буфер резервирует ёмкость сверх текущей длины. конструктор без параметров резервирует место под 16 символов. второй конструктор принимает начальную ёмкость явно. конструкторы от `String` и от `CharSequence` берут длину аргумента и добавляют к ней те же 16 символов.

начиная с java 9 компактные строки хранят данные в массиве `byte` и держат кодер `latin-1` либо `utf-16`. `capacity()` и `length()` при этом считаются в кодовых единицах `char`. длина массива `byte` зависит от кодера отдельно.

`capacity()` возвращает число символов, под которые зарезервирована память. `ensureCapacity(int minimumCapacity)` поднимает минимальную ёмкость. контракт метода такой: если запрошенный минимум больше текущей ёмкости, новая ёмкость равна большему из двух чисел, этого минимума и удвоенной старой ёмкости плюс 2. неположительный аргумент метод оставляет без изменений.

```java


String str = "Java";

StringBuilder strBuilder = new StringBuilder(str);

System.out.println("Емкость: " + strBuilder.capacity()); // 20

strBuilder.ensureCapacity(32);

System.out.println("Емкость: " + strBuilder.capacity()); // 42

System.out.println("Длина: " + strBuilder.length()); // 4
```

буфер создан из строки `"Java"` длины 4, поэтому начальная ёмкость равна 4 + 16 = 20. вызов `ensureCapacity(32)` запрашивает минимум 32. удвоенная старая ёмкость плюс 2 даёт 42, и поскольку 42 больше запрошенного минимума, итоговая ёмкость равна 42. длина, которую возвращает `length()`, остаётся 4: ёмкость описывает резерв, длина описывает значимое содержимое.

текущее содержимое буфера возвращает `toString()` уже как неизменяемый `String`. метод копирует значимые символы в новый объект. буфер после копирования остаётся изменяемым, и дальнейшие `append` на уже построенную строку не влияют.

```java


String str = "Java";

StringBuilder strBuilder = new StringBuilder(str);

System.out.println(strBuilder.toString()); // Java
```

набор операций у буфера близок к `String`. методы `append`, `insert`, `delete`, `replace` и `reverse` меняют сам объект и возвращают его, поэтому вызовы можно сцеплять. `substring` возвращает новый `String` и буфер не меняет.

### получение и установка символов

`charAt(int index)` читает символ по индексу, `setCharAt(int index, char ch)` записывает символ по индексу. нумерация с нуля, допустимый диапазон полуоткрытый: от 0 включительно до `length()` исключительно. индекс вне диапазона даёт `IndexOutOfBoundsException`.

```java


StringBuilder strBuilder = new StringBuilder("Java");

char c = strBuilder.charAt(0); // J

System.out.println(c);

strBuilder.setCharAt(0, 'c');

System.out.println(strBuilder.toString()); // cava
```

символ с индексом 0, то есть `'J'`, заменяется на `'c'`. содержимое становится `"cava"`.

`getChars(int srcBegin, int srcEnd, char[] dst, int dstBegin)` копирует символы полуоткрытого диапазона `[srcBegin, srcEnd)` в массив `dst`, начиная с позиции `dstBegin`. буфер при этом сохраняется.

```java


StringBuilder strBuilder = new StringBuilder("world");

int startIndex = 1;

int endIndex = 4;

char[] buffer = new char[endIndex-startIndex];

strBuilder.getChars(startIndex, endIndex, buffer, 0);

System.out.println(buffer); // orl
```

у `"world"` диапазон `[1, 4)` содержит `'o'`, `'r'`, `'l'`. массив `buffer` выделен ровно под эту длину.

### добавление в строку

`append` дописывает данные в конец и при нехватке ёмкости растит массив по той же формуле. перегрузки принимают примитивы, `char[]`, `CharSequence`, `String` и произвольный объект, который приводится через `String.valueOf`.

```java


StringBuilder strBuilder = new StringBuilder("hello");

strBuilder.append(" world");

System.out.println(strBuilder.toString()); // hello world
```

`insert(int offset, ...)` вставляет данные по индексу и сдвигает хвост вправо. индекс лежит в диапазоне от 0 до `length()` включительно: вставка в позицию `length()` совпадает с дозаписью в конец.

```java


StringBuilder strBuilder = new StringBuilder("word");

        

strBuilder.insert(3, 'l');

System.out.println(strBuilder.toString()); //world



strBuilder.insert(0, "s");

System.out.println(strBuilder.toString()); //sworld
```

вставка `'l'` по индексу 3 в `"word"` даёт `"world"`. следующая вставка строки `"s"` по индексу 0 даёт `"sworld"`.

### удаление символов

`delete(int start, int end)` удаляет символы полуоткрытого диапазона `[start, end)`. `deleteCharAt(int index)` удаляет один символ. хвост сдвигается влево, длина уменьшается, ёмкость обычно сохраняется.

```java


StringBuilder strBuilder = new StringBuilder("assembler");

strBuilder.delete(0,2);

System.out.println(strBuilder.toString()); //sembler

        

strBuilder.deleteCharAt(6);

System.out.println(strBuilder.toString()); //semble
```

`delete(0, 2)` снимает префикс `"as"` у `"assembler"`, остаётся `"sembler"`. символ с индексом 6 в `"sembler"` это `'r'`. после `deleteCharAt(6)` остаётся `"semble"`.

### обрезка строки

`substring(int start)` и `substring(int start, int end)` возвращают новый `String` с копией фрагмента. длина буфера сохраняется: метод общий по имени со `String` и так же только читает фрагмент.

```java


StringBuilder strBuilder = new StringBuilder("hello java!");

String str1 = strBuilder.substring(6); // обрезка строки с 6 символа до конца

System.out.println(str1); //java!

        

String str2 = strBuilder.substring(3, 9); // обрезка строки с 3 по 9 символ 

System.out.println(str2); //lo jav
```

у `"hello java!"` индекс 6 указывает на `'j'`, поэтому `substring(6)` равен `"java!"`. диапазон `[3, 9)` содержит `"lo jav"`.

### изменение длины

`setLength(int newLength)` меняет логическую длину. ёмкость буфера этот метод не трогает. если новая длина больше текущей, хвост дополняется кодовыми единицами `'\u0000'`. при печати такой символ не виден, и в комментарии примера хвост изображён пробелами. записывается при этом `U+0000`. если новая длина меньше текущей, хвост отбрасывается. ёмкость после уменьшения длины сохраняется.

```java


StringBuilder strBuilder = new StringBuilder("hello");

strBuilder.setLength(10);

System.out.println(strBuilder.toString()); //"hello     "

        

strBuilder.setLength(4);

System.out.println(strBuilder.toString()); //"hell"
```

после `setLength(10)` длина равна 10: пять символов `"hello"` и пять нулевых кодовых единиц. после `setLength(4)` значимыми остаются первые четыре символа, `"hell"`.

### замена в строке

`replace(int start, int end, String str)` заменяет полуоткрытый диапазон `[start, end)` строкой `str`. длина подстановки может отличаться от длины диапазона: хвост сдвигается, при нехватке места буфер растёт.

```java


StringBuilder strBuilder = new StringBuilder("hello world!");

strBuilder.replace(6,11,"java");

System.out.println(strBuilder.toString()); //hello java!
```

первый аргумент задаёт начало диапазона, второй задаёт позицию, которая в диапазон уже не входит, третий задаёт подставляемый текст. в `"hello world!"` диапазон `[6, 11)` это `"world"`. после замены на `"java"` получается `"hello java!"`.

### обратный порядок в строке

`reverse()` переставляет содержимое буфера в обратном порядке на месте. разворот учитывает суррогатные пары utf-16: символ вне базовой многоязычной плоскости остаётся одной парой и не распадается на два независимых значения `char`.

```java


StringBuilder strBuilder = new StringBuilder("assembler");

strBuilder.reverse();

System.out.println(strBuilder.toString()); //relbmessa
```

`"assembler"` после разворота читается как `"relbmessa"`.
