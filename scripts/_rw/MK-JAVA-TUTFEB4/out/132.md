иногда одной программе на java нужно запустить другую, произвольную программу. для этого в стандартной библиотеке есть класс `Process`. он представляет процесс операционной системы и даёт доступ к его стандартным потокам ввода, вывода и ошибок. через `Process` данные передают в процесс и читают из него, ждут завершения, проверяют статус и завершают процесс. сам объект описывает уже запущенный процесс. команда, которая ещё только готовится, задаётся в `ProcessBuilder`.

### создание процесса

объект `Process` через публичный конструктор не собирают. его создаёт и настраивает `ProcessBuilder`. у построителя два близких конструктора:
```java

ProcessBuilder(String... command)
ProcessBuilder(List<String> command)
```
оба конструктора принимают путь к программе и её аргументы строками. первый принимает переменное число строк, второй принимает уже собранный `List<String>`. разбиение на элементы делает вызывающий код: построитель не передаёт строку оболочке и пробелы сам не разбирает. пробел внутри одного элемента остаётся частью этого аргумента. пример:
```java
var builder = new ProcessBuilder("java", "--version");
```
первый аргумент, `"java"`, есть имя приложения, которое будет запущено. второй, `"--version"`, передаётся приложению как его аргумент. вместе это команда `java --version`, запрос версии java. поиск исполняемого файла идёт по правилам операционной системы, в том числе по `PATH`, если в строке нет каталога.

### запуск процесса

запуск выполняет метод `start()` класса `ProcessBuilder`:
```java
Process start()
```
метод возвращает объект уже запущенного процесса. если программу не удалось найти или операционная система отказала в запуске, `start()` бросает `IOException`:
```java

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        Process javac = builder.start();
    }
}
```
после компиляции и запуска этого варианта на консоли ничего не появляется. стандартный вывод дочернего процесса не связан с консолью родителя, его ещё нужно направить. настройка идёт методами `ProcessBuilder`. каждый из них возвращает тот же построитель, поэтому вызовы сцепляются в одну цепочку.

- `ProcessBuilder command(String... command)` / `command(List<String> command)`: задаёт запускаемую программу и аргументы

- `ProcessBuilder directory(File directory)`: задаёт рабочий каталог процесса

- `ProcessBuilder inheritIO()`: делает источником ввода и назначением вывода подпроцесса те же потоки, что у текущего процесса java

- `ProcessBuilder redirectError(File file)`: направляет ошибки в файл

- `ProcessBuilder redirectError(ProcessBuilder.Redirect destination)`: задаёт назначение стандартного вывода ошибок

- `ProcessBuilder redirectInput(File file)`: берёт файл как источник стандартного ввода

- `ProcessBuilder redirectInput(ProcessBuilder.Redirect source)`: задаёт источник стандартного ввода

- `ProcessBuilder redirectOutput(File file)`: берёт файл как стандартный вывод

- `ProcessBuilder redirectOutput(ProcessBuilder.Redirect destination)`: задаёт назначение стандартного вывода

- `ProcessBuilder redirectErrorStream(boolean redirectErrorStream)`: управляет свойством `redirectErrorStream`. при значении `true` стандартный вывод и поток ошибок сливаются в одно место

у подпроцесса три канала, и каждый настраивается отдельно:

- вывод: куда пишется стандартный вывод. метод `redirectOutput()`

- ввод: откуда читается стандартный ввод. метод `redirectInput()`

- вывод ошибок: куда пишется поток ошибок. методы `redirectError()` и `redirectErrorStream()`

текущие параметры читаются одноимёнными методами:

- `List<String> command()`: возвращает программу и аргументы запуска

- `File directory()`: возвращает рабочий каталог построителя

- `boolean redirectErrorStream()`: сообщает, сливает ли построитель стандартный вывод ошибок со стандартным выводом

- `ProcessBuilder.Redirect redirectError()`: возвращает текущее назначение потока ошибок

- `ProcessBuilder.Redirect redirectInput()`: возвращает текущий источник ввода

- `ProcessBuilder.Redirect redirectOutput()`: возвращает текущее назначение вывода

потоки ввода, вывода и ошибок нового процесса можно совместить с потоками jvm. если jvm запущена в консоли, ввод пользователя попадает в процесс, а вывод процесса виден в той же консоли. для этого вызывается `inheritIO()`. основная программа ниже сама запущена в консоли, и дочерний процесс должен печатать туда же:
```java

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        Process javac = builder
                            .inheritIO()    // запускаемый процесс наследует параметры ввода/вывода текущего процесса
                            .start();       // запускаем процесс
    }
}
```
при запуске видна версия java, то есть вывод запущенного подпроцесса:
```bash

eugene@Eugene:/workspace/java/hello$ javac Program.java && java Program
java 25 2025-09-16 LTS
Java(TM) SE Runtime Environment (build 25+37-LTS-3491)
Java HotSpot(TM) 64-Bit Server VM (build 25+37-LTS-3491, mixed mode, sharing)
```
потоки можно перенаправить и по отдельности на потоки текущей jvm. для одного канала служит константа `ProcessBuilder.Redirect.INHERIT`. в примере наследуется только стандартный вывод, поток ошибок остаётся при значении по умолчанию:
```java

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        builder
            .redirectOutput(ProcessBuilder.Redirect.INHERIT)
            .start();
    }
}
```
другой частый приём: вывод в файл. в `redirectOutput()` передаётся объект `File`:
```java

import java.nio.file.Path;

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        builder
            .redirectOutput(Path.of("output.txt").toFile())
            .start();
    }
}
```
путь строится через интерфейс `java.nio.file.Path`. статический метод `Path.of()` задаёт путь к файлу. здесь это `output.txt` в текущем каталоге. если файла нет, он создаётся. если файл уже есть, вывод процесса его переписывает. метод `toFile()` переводит `Path` в `File`: перегрузки `redirectOutput` принимают `File` или `ProcessBuilder.Redirect`. вывод команды `java --version` записывается в `output.txt`.

нередко поток вывода и поток ошибок должны попасть в одно место. для слияния вызывается:
```java
builder.redirectErrorStream(true);
```
#### рабочий каталог

у каждого процесса есть рабочий каталог (working directory). относительно него вычисляются относительные имена файлов. по умолчанию рабочий каталог подпроцесса совпадает с рабочим каталогом виртуальной машины, обычно это каталог текущей программы на java. метод `directory()` без аргумента возвращает этот каталог объектом `File`:
```java

var builder = new ProcessBuilder("java", "--version");
System.out.println(builder.directory());  // null - текущий каталог
```
если метод возвращает `null`, рабочим каталогом считается каталог текущей программы на java, то есть значение системного свойства `user.dir`. `null` здесь означает наследование каталога jvm.

рабочий каталог меняется одноимённым методом `directory()`, который принимает объект `File`. смена действует на дочерний процесс и каталог самого процесса jvm не трогает.

например, в текущем каталоге программы создаётся подкаталог `test`, а в нём файл `Main.java`:
```java

class Main{
 
    public static void main(String[] args) throws Exception{
          
        System.out.println("Hello enoobis.ru");
    }
}
```
файл `Main.java` в каталоге `test` содержит короткую программу на java. следующая программа запускает этот файл. с java 11 виртуальная машина умеет выполнить одиночный исходный файл командой `java` без отдельного предварительного `javac`. текст запуска:
```java

import java.nio.file.Path;

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "Main.java");
        builder
            .directory(Path.of("test").toFile())                // устанавливаем рабочий каталог на подкаталог "test"
            .redirectOutput(ProcessBuilder.Redirect.INHERIT)    // устанавливаем вывод на консоль
            .redirectErrorStream(true)                          // вывод ошибок также идет на консоль
            .start();
    }
}
```
фактически выполняется команда `java Main.java`. рабочим каталогом назначен подкаталог `test`, поэтому процесс находит `Main.java` по относительному имени. запуск основной программы выполняет эту команду в отдельном подпроцессе. `redirectErrorStream(true)` добавляет поток ошибок к тому же выводу, который уже направлен на консоль через `INHERIT`:
```bash

eugene@Eugene:/workspace/java$ java Program.java
Hello enoobis.ru
eugene@Eugene:/workspace/java$
```
класс `Process` даёт методы управления процессом.

- `abstract InputStream getErrorStream()`: возвращает входной поток, подключённый к потоку ошибок процесса

- `abstract InputStream getInputStream()`: возвращает поток ввода, подключённый к обычному выводу процесса

- `abstract OutputStream getOutputStream()`: возвращает поток вывода, подключённый к обычному вводу процесса

- `final BufferedReader errorReader()`: возвращает `BufferedReader`, подключённый к стандартному потоку ошибок процесса

- `final BufferedReader inputReader()`: возвращает `BufferedReader`, подключённый к стандартному выводу процесса

- `final BufferedWriter outputWriter()`: возвращает `BufferedWriter`, подключённый к обычному входу процесса, в собственной кодировке процесса

- `Stream<ProcessHandle> children()`: возвращает поток прямых дочерних процессов

- `Stream<ProcessHandle> descendants()`: возвращает поток потомков процесса, не только прямых детей

- `abstract void destroy()`: завершает процесс

- `Process destroyForcibly()`: завершает процесс принудительно

- `boolean isAlive()`: проверяет, жив ли запущенный процесс

- `long pid()`: возвращает идентификатор запущенного процесса в операционной системе

- `ProcessHandle toHandle()`: возвращает `ProcessHandle` этого процесса. через дескриптор доступны pid, потомки и завершение уже без удержания самих потоков `Process`

- `CompletableFuture<Process> onExit()`: возвращает `CompletableFuture`, который завершается вместе с процессом

- `boolean supportsNormalTermination()`: возвращает `true`, если `destroy()` завершает процесс штатно. возвращает `false`, если `destroy()` завершает процесс принудительно и сразу

- `abstract int waitFor()`: заставляет текущий поток ждать завершения запущенного процесса. перегрузки ограничивают ожидание по времени: `boolean waitFor(long timeout, TimeUnit unit)` и `boolean waitFor(Duration duration)`

имена `getInputStream` и `getOutputStream` смотрят со стороны родителя. `getInputStream` читает то, что дочерний процесс пишет в свой стандартный вывод. `getOutputStream` пишет в стандартный ввод дочернего процесса. путаница этих имён приводит к тому, что родитель читает не тот канал.

### получение потоков ввода-вывода процесса

те же потоки можно получить и разобрать вручную:

- `abstract InputStream getErrorStream()`: возвращает входной поток, подключённый к потоку ошибок процесса

- `abstract InputStream getInputStream()`: возвращает поток ввода, подключённый к обычному выводу процесса

- `abstract OutputStream getOutputStream()`: возвращает поток вывода, подключённый к обычному вводу процесса

- `final BufferedReader errorReader()`: возвращает `BufferedReader`, подключённый к стандартному потоку ошибок процесса

- `final BufferedReader inputReader()`: возвращает `BufferedReader`, подключённый к стандартному выводу процесса

- `final BufferedWriter outputWriter()`: возвращает `BufferedWriter`, подключённый к обычному входу процесса, в собственной кодировке процесса

поток вывода или ошибок можно целиком перенаправить в файл или на консоль методами построителя. потоки `Process` нужны, когда строки надо обработать в родительском процессе до печати. пример нумерует строки версии:
```java

import java.util.Scanner;

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        Process process = builder.start();
        try (var in = new Scanner(process.getInputStream()))
        {
            int i = 0;
            // проходим по каждой строке из потока
            while (in.hasNextLine()){
                // при выводе на консоль добавляем перед строкой ее номер
                System.out.println(++i + ". " + in.nextLine());
            }
        }
    }
}
```
запускается команда `java --version`. её вывод занимает несколько строк. родитель читает входной поток построчно и печатает номер перед каждой строкой. получается вывод такого вида:
```bash

1. java 25 2025-09-16 LTS
2. Java(TM) SE Runtime Environment (build 25+37-LTS-3491)
3. Java HotSpot(TM) 64-Bit Server VM (build 25+37-LTS-3491, mixed mode, sharing)
```
тот же поток читается методом `inputReader()`. `readLine()` возвращает `null` в конце потока, на этом цикл останавливается. `Scanner` из предыдущего примера прячет ту же границу за `hasNextLine()`:
```java

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        Process process = builder.start();
        try (var in = process.inputReader();)
        {
            int i = 0;
            String s;
            // считываем построчно
            while ((s = in.readLine())!=null){
                System.out.println(++i + ". " + s);
            }
        }
    }
}
```
буфер канала операционной системы конечен. если записать в процесс больше, чем он успевает прочитать, или не забирать его вывод, дочерний процесс блокируется на записи в заполненный буфер. родитель при этом может заблокироваться на своей записи ввода. вход поэтому не перегружают, а выход читают, не откладывая. взаимная блокировка родителя и потомка на полном буфере является обычной ошибкой работы с `Process`.

### завершение процесса

#### `destroy` и `destroyForcibly`

процесс завершают методом `destroy()` или `destroyForcibly()`:
```java

process.destroy();
// или
process.destroyForcibly();
```
разница зависит от платформы. в unix-подобных системах, в том числе в linux, `destroy()` посылает сигнал `SIGTERM`, а `destroyForcibly()` посылает `SIGKILL`. процесс может перехватить `SIGTERM` и завершиться сам. `SIGKILL` перехвату не подлежит. `supportsNormalTermination()` возвращает `true`, если `destroy()` способен завершить процесс штатно. в windows оба вызова обычно завершают процесс принудительно, и `supportsNormalTermination()` возвращает `false`: отдельного мягкого сигнала в этой модели нет.

завершение просит операционную систему остановить процесс и освободить его ресурсы. файловые дескрипторы закрываются. вместе с ними рвутся соединения с другими процессами.

#### ожидание завершения процесса и `waitFor`

дождаться завершения можно методом `waitFor()`:
```java
int result = process.waitFor();
```
метод возвращает числовой код завершения. по соглашению 0 означает успешное завершение, ненулевой код означает ошибку. смысл ненулевых кодов задаёт сама программа, операционная система его не унифицирует.

ожидание этой перегрузки не ограничено по времени: текущий поток блокируется, пока процесс не закончится. предел задаёт другая перегрузка, она принимает интервал:
```java

long delay = 10; // период ожидания
if (process.waitFor(delay, TimeUnit.SECONDS)){

    int result = process.exitValue();
}
else{

    process.destroyForcibly();
}
```
`process.waitFor(delay, TimeUnit.SECONDS)` возвращает `true`, если процесс успел завершиться в отведённое время. тогда `exitValue()` читает код завершения. если время вышло, метод возвращает `false`, и в примере процесс завершается через `destroyForcibly()`. `exitValue()` до фактического завершения бросает `IllegalThreadStateException`, поэтому его вызывают после успешного `waitFor` или после того, как `isAlive()` стал ложным.

#### асинхронное уведомление о завершении процесса и `onExit()`

`onExit()` даёт асинхронное уведомление о завершении и не блокирует вызывающий поток, в отличие от `waitFor()`. метод возвращает `CompletableFuture<Process>`. на будущее ставят действие, которое выполнится, когда процесс закончится. в примере вывод процесса наследуется консолью, а `thenAccept` печатает код завершения. `Thread.sleep(500)` удерживает главный поток, чтобы виртуальная машина не остановилась раньше колбэка: когда не остаётся живых нефоновых потоков, процесс jvm завершается, не дождавшись отложенного действия.
```java

class Program{
 
    public static void main(String[] args) throws Exception{
          
        var builder = new ProcessBuilder("java", "--version");
        Process process = builder.redirectOutput(ProcessBuilder.Redirect.INHERIT).start();
        process.onExit().thenAccept(p -> System.out.println("Процесс завершился с кодом: " + p.exitValue()));
        Thread.sleep(500); // задержка, что успел отработать
    }
}
```
