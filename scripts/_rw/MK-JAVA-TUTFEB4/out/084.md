классами байтовых потоков текст в файл записать можно, но устроены они для бинарного потока байтов. кодировки символов, посимвольного чтения и дозаписи текста в них нет. для текста служат другие классы, наследники абстрактных `Reader` и `Writer`. `Reader` и `Writer` оперируют значениями `char` и сами кодируют их в байты нижележащего потока. байтовый `InputStream` такой перекодировки не делает.

### запись файлов. класс `FileWriter`

`FileWriter` производный от `OutputStreamWriter`, а тот от `Writer`. класс пишет текстовые файлы: символы кодируются в байты и уходят в файл.

объект создаётся одним из конструкторов:

```java


FileWriter(File file)

FileWriter(File file, boolean append)

FileWriter(FileDescriptor fd)

FileWriter(String fileName)

FileWriter(String fileName, boolean append)
```

в конструктор передаётся либо путь к файлу строкой, либо объект `File`, указывающий на конкретный файл. `FileDescriptor` подключает писатель к уже открытому дескриптору. параметр `append` выбирает режим. при `true` данные дописываются в конец файла, при `false` файл перезаписывается с начала. если аргумента `append` нет, файл тоже открывается с перезаписью. кодировка в этих конструкторах это кодировка платформы по умолчанию. с java 11 есть перегрузки с явным `Charset`, в этом наборе конструкторов их нет.

запись текста:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

       

        try(FileWriter writer = new FileWriter("notes3.txt", false))

        {

           // запись всей строки

            String text = "Hello Gold!";

            writer.write(text);

            // запись по символам

            writer.append('\n');

            writer.append('E');

			

			writer.flush();

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        } 

    } 

}
```

в конструкторе `append` равен `false`, значит файл `notes3.txt` будет перезаписан. дальше работают методы базового класса `Writer`. `write(String)` записывает строку целиком, здесь это `Hello Gold!`. `append(char)` дописывает один символ: сначала перевод строки `\n`, затем символ `E`. `flush()` сбрасывает буфер в файл, не дожидаясь `close()`. закрытие всё равно выполнится само: объект создан в try-with-resources, и по выходу из блока `close()` вызовет сброс ещё раз и закроет файл.

### чтение файлов. класс `FileReader`

`FileReader` наследуется от `InputStreamReader` и через него от абстрактного `Reader`. класс читает текстовые файлы и декодирует байты в `char` той же кодировкой по умолчанию, если явный `Charset` не задан.

объект создаётся одним из конструкторов:

```java


FileReader(String fileName) 

FileReader(File file)

FileReader(FileDescriptor fd)
```

методы базового `Reader` читают файл. `read()` без аргументов возвращает один символ как `int` в диапазоне кодовой единицы utf-16 либо `-1`, когда символы кончились:

```java


import java.io.*;



public class Program {



    public static void main(String[] args) {

       

        try(FileReader reader = new FileReader("notes3.txt"))

        {

           // читаем посимвольно

            int c;

            while((c=reader.read())!=-1){

                

                System.out.print((char)c);

            } 

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        }   

    } 

}
```

цикл идёт, пока `read` не вернёт `-1`. возвращённое значение приводится к `char` и печатается. тип `int` у `read` нужен по той же причине, что и у байтового потока: кодовую единицу `0xFFFF` нельзя было бы отличить от признака конца, если бы метод возвращал `char`.

чтение можно вести через промежуточный буфер, массив символов:

```java


import java.io.*;

import java.util.Arrays;



public class Program {

 

    public static void main(String[] args) {

         

        try(FileReader reader = new FileReader("notes3.txt"))

        {

			char[] buf = new char[256];

            int c;

            while((c = reader.read(buf))>0){

                

				if(c < 256){

					buf = Arrays.copyOf(buf, c);

				}

                System.out.print(buf);

            } 

        }

        catch(IOException ex){

            

            System.out.println(ex.getMessage());

        }		

    }	  

}
```

символы читаются в массив на 256 элементов, пока файл не кончится. в конце файла `read` возвращает `-1`, и условие `c > 0` цикл останавливает. `read(char[])` возвращает не сам текст, а число символов, реально записанных в буфер. порция может быть короче 256, например в файле всего 73 символа. если число прочитанных символов меньше размера буфера, массив копируется через `Arrays.copyOf`: длина нового массива равна `c`, хвост старого буфера отбрасывается. в `buf` остаются только символы, прочитанные из файла, и `print` выводит массив этой длины. когда `c` равно 256, буфер заполнен целиком, копирование не нужно.
