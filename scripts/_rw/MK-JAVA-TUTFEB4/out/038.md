обычный класс можно объявить так, что в его заголовке нет явного базового класса. фактически все классы наследуются от класса `Object`. все остальные классы, даже те, которые добавляют в свой проект, являются неявно производными от класса `Object`, прямо или через цепочку суперклассов. сам `Object` суперкласса не имеет и замыкает иерархию.

переменную типа `Object` используют для ссылки на объекты любого ссылочного типа:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Object obj = "Some Object";

        System.out.println(obj);    // Some Object



        obj = 41;

        System.out.println(obj);    // 41



        obj = new Person("Tom");

        System.out.println(obj);    // Person@1dbd16a6

    }

}

class Person{

    private String name;



    Person(String name) { this.name = name; }



    void print(){  System.out.println("Person " + name); }

}
```

присваивание `obj = 41` выполняется за счёт автоупаковки: значение типа `int` превращается в объект `Integer`, а `Integer` является подтипом `Object`. `System.out.println` для аргумента `Object` печатает результат `toString`. у строки это её символы, у упакованного числа его десятичная запись, у `Person` без собственного `toString` строка вида `Person@1dbd16a6`: имя класса, разделитель `@` и шестнадцатеричный хеш-код.

поскольку все классы неявно наследуются от `Object`, все эти классы также наследуют методы класса `Object`. ниже разобраны эти методы.

### toString

метод `toString` служит для получения представления данного объекта в виде строки. при попытке вывести строковое представление какого-нибудь объекта, как правило, будет выводиться полное имя класса. пример:

```java


public class Program{

     

	public static void main(String[] args) {

			

		Person tom = new Person("Tom");

		System.out.println(tom.toString()); // Будет выводить что-то наподобие Person@7960847b

	}

}

class Person {

    

    private String name;

	

    public Person(String name){

    

        this.name=name;

    }

}
```

полученное значение (здесь это `Person@7960847b`) вряд ли может служить хорошим строковым описанием объекта. поэтому метод `toString()` нередко переопределяют. пример:

```java


public class Program{

     

	public static void main(String[] args) {

			

		Person tom = new Person("Tom");

		System.out.println(tom.toString()); // Person Tom

	}

}

class Person {

    

    private String name;

   

    public Person(String name){

    

        this.name=name;

    }

	

	@Override

	public String toString(){

         

        return "Person " + name;

    }

}
```

реализация в `Object` складывает имя класса, символ `@` и результат `Integer.toHexString(hashCode())`. переопределение подставляет вместо этой строки описание состояния. от `toString` не требуют уникального ключа объекта: метод рассчитан на отладку и журналы.

### метод hashCode

метод `hashCode` позволяет задать некоторое числовое значение, которое будет соответствовать данному объекту, или его хеш-код. по данному числу, например, можно сравнивать объекты. если `x` и `y` два разных объекта, то существует высокая вероятность того, что вызовы `x.hashCode()` и `y.hashCode()` дадут различные результаты.

например, вывод представления объекта, определённого выше:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Person tom = new Person("Tom");

        System.out.println(tom.hashCode()); // 498931366

    }

}

class Person{

    private String name;

    Person(String name) {  this.name = name; }

}
```

можно задать свой алгоритм определения хеш-кода объекта. существует много готовых алгоритмов хеширования. класс `String` применяет следующий алгоритм:

```java


int hash = 0;

for (int i = 0; i < length(); i++)

   hash = 31 * hash + charAt(i);
```

это полиномиальный хеш с основанием 31: накопленное значение умножается на 31, и к нему прибавляется код очередного символа. начиная с java 9 строка может храниться в компактном виде, но для той же последовательности символов `hashCode` остаётся значением этого полинома. вычисленный код кешируется в самом объекте `String`.

можно определить и свой алгоритм. алгоритм желательно подобрать такой, чтобы при вычислении кода для разных объектов их код также различался. пример:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Person tom = new Person("Tom");

        System.out.println(tom.hashCode()); // 842740





        Person tomas = new Person("Tom");

        System.out.println(tomas.hashCode()); // 842740



        Person tim = new Person("Tim");

        System.out.println(tim.hashCode()); // 840880

    }

}

class Person{

    private String name;



    Person(String name) {  this.name = name; }

    @Override

    public int hashCode(){

 

        return 10 * name.hashCode();

    }

}
```

в данном примере алгоритм хеширования выбран произвольно, только для демонстрации. он зависит от хеш-кода поля `name`. по консольному выводу видно, что объекты с одинаковым полем `name` получают один и тот же код, а объекты с разными именами различаются.

#### объединение хешей

обычно хеши вычисляются на основе полей объекта, как в примере выше, где для вычисления хеша применялось поле `name`. если класс содержит несколько полей, для общего хеша объекта можно использовать все эти поля, по крайней мере те, которые участвуют в равенстве. пример:

```java


class Person{

    private String name;

    private int age;



    Person(String name, int age) { 



        this.name = name;

        this.age = age;

    }

    @Override

    public int hashCode(){

 

        return 31* name.hashCode() + age;

    }

}
```

для вычисления хеша применяются поля `name` и `age`. множитель 31 тот же, что в `String`: он нечётный, и соседние значения расходятся в младших битах. объединение нескольких хеш-значений вручную может быть утомительным. во многих случаях можно просто вызвать `Objects.hash`, передав в него все необходимые поля. этот метод на выходе объединит хеш-коды своих аргументов:

```java


import java.util.Objects;  // для Objects.hash

..................................

class Person{

    private String name;

    private int age;



    Person(String name, int age) { 



        this.name = name;

        this.age = age;

    }

    @Override

    public int hashCode(){

 

        return Objects.hash(name, age);

    }

}
```

### получение типа объекта и метод getClass

метод `getClass` позволяет получить тип данного объекта. возвращаемое значение имеет класс `Class` и представляет класс времени выполнения:

```java


Person tom = new Person("Tom");

System.out.println(tom.getClass()); // class Person
```

печать этого значения даёт текст вида `class Person`. метод возвращает динамический класс объекта. статический тип переменной, через которую на объект ссылаются, может быть шире этого класса.

### метод equals

метод `equals` сравнивает два объекта на равенство. в качестве параметра метод принимает объект, с которым надо сравнить текущий, и возвращает `true`, если объекты равны, и `false`, если не равны:

```java


boolean equals(Object otherObject)
```

определения `equals` и `hashCode` должны быть совместимы: если `x.equals(y)` возвращает `true`, то `x.hashCode()` должен возвращать то же значение, что и `y.hashCode()`. из совпадения хеш-кодов равенство объектов не следует: разные по `equals` объекты могут получить один код. таблицы вроде `HashMap` используют оба метода вместе. если `equals` переопределён по полям, а `hashCode` оставлен реализации `Object`, объекты с равными полями получат разные коды идентичности и разъедутся по разным корзинам.

по умолчанию метод `equals` определяет идентичность двух ссылок на объекты и фактически сравнивает их оператором `==`:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Point a = new Point(10, 15);

        Point b = a;

        Point c = new Point(10, 15);



        boolean result = a.equals(b);

        System.out.println(result);    // true



        result = a.equals(c);

        System.out.println(result);    // false

    }

}

class Point{



    private int x;

    private int y;



    Point(int x, int y){ 



        this.x = x;

        this.y = y;

    }



    void print(){  System.out.printf("(%d, %d)", x, y); }

}
```

в программе переменные `a` и `b` хранят ссылку на один и тот же объект `Point`, который представляет точку с двумя координатами:

```java


Point a = new Point(10, 15);

Point b = a;



boolean result = a.equals(b);    // true
```

поэтому они равны.

переменная `c` хранит ссылку на другой объект, поэтому переменные `a` и `b` с одной стороны и `c` с другой не равны:

```java


Point a = new Point(10, 15);

Point c = new Point(10, 15);



boolean result = a.equals(b);

result = a.equals(c);   // false
```

в реальности оба объекта, `a` и `c`, несут одинаковые значения, хотя по идентичности ссылок они не равны. имеются две точки с одинаковыми координатами. разумнее считать их равными в силу равенства координат. в этом случае метод `equals` переопределяют:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Point point1 = new Point(10, 15);

        Point point2 = point1;



        boolean result = point1.equals(point2);

        System.out.println(result);    // true



        result = point1.equals(new Point(10, 15));

        System.out.println(result);    // true





        result = point1 .equals("hello");

        System.out.println(result);    // false



        result = point1 .equals(null);

        System.out.println(result);    // false

    }

}

class Point{



    private int x;

    private int y;



    Point(int x, int y){ 



        this.x = x;

        this.y = y;

    }



    void print(){  System.out.printf("(%d, %d)", x, y); }



    // переопределяем метод equals

    @Override

    public boolean equals(Object otherObject){

         

        // проверяем объекты на идентичноть - равенство их ссылок

        if (this == otherObject) return true;



        // проверяем, что второй объект не равен null

        if (otherObject == null) return false;



        // если классы объектов не совпадают, то они не равны

        if (getClass() != otherObject.getClass()) return false;

 

        // иначе преобразуем объект к типу Point

        Point p = (Point)otherObject;

        // и проверяем равенство их координат

        return this.x == p.x  && this.y == p.y;

    }

}
```

метод `equals` принимает в качестве параметра объект любого типа, соответственно это может быть абсолютно любой объект или даже значение `null`. в методе `equals` сначала проверяют, что текущий и второй экземпляр хранят ссылки на один и тот же объект:

```java
if (this == otherObject) return true;
```

если две переменные хранят ссылку на один и тот же объект, они равны, и остальные проверки не нужны.

далее проверяют, что второй объект не равен `null`. иначе дальше сравнивать нечего, и объекты уже не равны:

```java


if (otherObject == null) return false;
```

поскольку второй объект может представлять в реальности объект любого типа, смотрят, представляют ли объекты один и тот же класс. если не представляют, объекты не равны:

```java


if (getClass() != otherObject.getClass()) return false;
```

если объекты представляют один и тот же класс, второй объект преобразуют к целевому типу `Point` и сравнивают их координаты. проверка `getClass` делает приведение безопасным: аргумент имеет ровно класс `Point`. объект другого типа, скрытый за статическим типом `Object`, до приведения не доходит.

оператор `instanceof` позволяет упростить код. он позволяет выяснить, является ли переданный в качестве параметра объект объектом определённого класса. в этом листинге проверяется класс `Point`. если объекты принадлежат к разным классам или второй объект представляет `null`, их сравнение не имеет смысла, и возвращается значение `false`. для ссылки `null` операция `instanceof` сама даёт `false`, поэтому отдельная проверка на `null` при такой записи уже содержится в ней:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Point point1 = new Point(10, 15);

        Point point2 = point1;



        boolean result = point1.equals(point2);

        System.out.println(result);    // true



        result = point1.equals(new Point(10, 15));

        System.out.println(result);    // true





        result = point1 .equals("hello");

        System.out.println(result);    // false



        result = point1 .equals(null);

        System.out.println(result);    // false

    }

}

class Point{



    private int x;

    private int y;



    Point(int x, int y){ 



        this.x = x;

        this.y = y;

    }



    void print(){  System.out.printf("(%d, %d)", x, y); }



    // переопределяем метод equals

    @Override

    public boolean equals(Object otherObject){

         

        // проверяем объекты на идентичноть - равенство их ссылок

        if (this == otherObject) return true;



        // проверяем, что второй объект - это объект типа Point

        if (!(otherObject instanceof Point)) return false;

 

        // иначе преобразуем объект к типу Point

        Point p = (Point)otherObject;

        // и проверяем равенство их координат

        return this.x == p.x  && this.y == p.y;

    }

}
```

выбор между `getClass` и `instanceof` заметен на подтипах. `getClass` требует точного совпадения класса времени выполнения, и экземпляр подкласса не равен экземпляру суперкласса. `instanceof` истинен и для подкласса. если суперкласс сравнивает через `instanceof` только свои поля, а подкласс добавляет собственное поле, симметрия `equals` нарушается: сравнение в одну сторону и в другую начинает расходиться. вариант с `getClass` эту симметрию сохраняет.

### наследование и метод equals

при определении метода `equals` для подкласса имеет смысл сначала вызвать метод `equals` суперкласса. если проверка не пройдена, объекты не могут быть равны. если поля суперкласса равны, можно сравнивать поля объекта подкласса:

```java


class Person{

    private String name;



    Person(String name) {  this.name = name; }



    @Override

    public boolean equals(Object otherObject){

         

        if (this == otherObject) return true;

        if (otherObject == null) return false;

        if (getClass() != otherObject.getClass()) return false;

 

        Person p = (Person)otherObject;

        return this.name == p.name;

    }

}



class Employee extends Person{

    private String company;



    Employee(String name, String company) {  



        super(name);

        this.company = company; 

    }



    @Override

    public boolean equals(Object otherObject){

         

        if (!super.equals(otherObject)) return false;

        // super.equals уже проверяет, что this и otherObject представляют один и тот же класс

        Employee empl = (Employee)otherObject;

        // и проверяем равенство их координат

        return this.company.equals(empl.company);

    }

}
```

в классе `Employee` в реализации метода `equals` сначала вызывается его реализация у базового класса `Person` через `super.equals(otherObject)`. если этот вызов возвращает `true`, оба объекта как минимум представляют один и тот же класс, и значения их полей `name` равны в том смысле, в каком их сравнил суперкласс. далее сравнивают уже те поля, которые определены непосредственно в классе `Employee`. комментарий в коде фиксирует, что `super.equals` уже проверил совпадение класса, поэтому приведение к `Employee` допустимо.

сравнение `this.name == p.name` в `Person.equals` проверяет тождественность ссылок на строки. совпадение последовательности символов у двух разных объектов `String` эта запись не устанавливает. содержимое строки сравнивает `equals`, как в том же листинге сделано для поля `company`.

применение метода:

```java


public class Program{

      

    public static void main(String[] args) {

             

        Employee empl1 = new Employee("Tom", "Yandex");

        Employee empl2 = empl1;



        boolean result = empl1.equals(empl2);

        System.out.println(result);    // true



        result = empl1 .equals(new Employee("Tom", "Yandex"));

        System.out.println(result);    // true



        result = empl1 .equals(new Employee("Bob", "Google"));

        System.out.println(result);    // false



        result = empl1.equals(new Person("Tom"));

        System.out.println(result);    // false



        result = empl1 .equals(null);

        System.out.println(result);    // false

    }

}
```

вызовы показывают контракт реализации. объект равен сам себе. два объекта `Employee` с одинаковыми именем и компанией равны. разные имя или компания дают `false`. объект `Person` не равен объекту `Employee` даже при совпадающем имени, потому что `getClass` в суперклассе отвергает другой класс времени выполнения. ссылка `null` не равна ни одному объекту.
