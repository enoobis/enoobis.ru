### обработка ошибок

для асинхронных вычислений в java используется `CompletableFuture`: на результат вешаются колбэки. вычисление может завершиться исключением. задача факториала генерирует ошибку, если переданное число меньше 1:

```java


Supplier<Integer> factorialTask = () -> {



    // при некорректных данных генерируем ошибку

    if(number < 1) throw new RuntimeException("Number must be greater than 0");

    int n = 1;

    int result = 1;

    while(n <= number)  result *= n++; 

    return result; 

};
```

ошибка обрабатывается методами класса `CompletableFuture`. несколько из них:

```java


CompletableFuture<T> exceptionally(Function<Throwable, ? extends T> fn)

CompletableFuture<T> exceptionallyCompose(Function<Throwable, ? extends CompletionStage<T>> fn)
```

эти методы ставят обратный вызов на ошибку предыдущего этапа:

- `exceptionally()` вычисляет результат по ошибке, если она возникла на предыдущем этапе. обратный вызов задаёт переход `Throwable -> T`

- `exceptionallyCompose()` вызывает функцию для исключения, если оно возникло на предыдущем этапе, и выполняет возвращённый этап. обратный вызов задаёт переход `Throwable -> CompletableFuture<T>`

пример снова считает факториал:

```java


import java.util.concurrent.*;

import java.util.function.Supplier;

import java.util.function.Function;

import java.util.function.Consumer;

 

class Program{

 

    public static void main(String[] args) throws Exception{

          

        System.out.println("Main thread started...");

 

        int number = -5;  // исходное число для вычисления факториала

       

        // определяем задачу, которая вычисляет факториал

        Supplier<Integer> factorialTask = () -> {



            if(number < 1) throw new RuntimeException("Number must be greater than 0");

            int n = 1;

            int result = 1;

            while(n <= number)  result *= n++; 

            return result; 

        };

        // задача для вывода финального результата

        Consumer<Integer> printTask = result -> System.out.printf("Final result: %d\n", result);



        // задача для обработки ошибки

        Function<Throwable, Integer> printException = ex -> { 

            System.out.println(ex.getMessage());    

            throw new RuntimeException(ex.getMessage());

        };



        // определяем объект Executor, который будет выполнять задачи

        ExecutorService executor = Executors.newCachedThreadPool();

        CompletableFuture

                .supplyAsync(factorialTask, executor)

                .exceptionally(printException)

                .thenAccept(printTask);



        System.out.println("Main thread works...");

        System.out.println("Main thread finished...");

        

        executor.close();  // закрываем исполнителя

    }

}
```

основная задача цепочки, `factorialTask`, возвращает целое число, тип `Integer`.

запуск задачи и колбэков:

```java


CompletableFuture

    .supplyAsync(factorialTask, executor)

    .exceptionally(printException)

    .thenAccept(printTask);
```

- `supplyAsync(factorialTask, executor)` устанавливает асинхронную задачу и `Executor`, который её выполняет. если число для факториала недопустимо, задача генерирует исключение

```java
if(number < 1) throw new RuntimeException("Number must be greater than 0");
```

- `exceptionally(printException)` ставит обработку исключения задачей `printException`. она печатает сведения об исключении на консоль. задача факториала возвращает `Integer`, поэтому и этот колбэк возвращает `Integer`. в примере значение не возвращается: исключение генерируется повторно, и это непроверяемое исключение. повторная генерация не даёт выполниться следующему колбэку, которому нужен результат факториала

```java


Function<Throwable, Integer> printException = ex -> { 

    System.out.println(ex.getMessage());    

    throw new RuntimeException(ex.getMessage());

};
```

- `thenAccept(printTask)` : задача `printTask` принимает результат вычисления факториала и печатает его на консоль

входное число отрицательное:

```java
int number = -5;
```

при выполнении возникает ошибка. консольный вывод одного из запусков:

```bash


Main thread started...

java.lang.RuntimeException: Number must be greater than 0

Main thread works...

Main thread finished...
```

последний колбэк, `printTask`, не выполняется. основной поток при этом не прерывается, хотя обработчик снова бросает исключение. исключение остаётся внутри цепочки этапов. `main` не вызывает `get()` и не вызывает `join()`, поэтому исключение в основной поток не переходит. проверка числа короткая, и колбэк ошибки в показанной трассе успевает напечатать строку раньше сообщений `main`. `executor.close()` в конце дожидается остановки пула.

если входное число больше 0:

```java
int number = 5;
```

выполняется колбэк из `thenAccept(printTask)`, а колбэк из `exceptionally(printException)` не вызывается. `exceptionally` запускается только при исключительном завершении предыдущего этапа. при успехе этап идёт дальше по обычной ветке. вывод:

```bash


Main thread started...

Final result: 120

Main thread works...

Main thread finished...
```

повторный выброс является одной из схем. колбэк может вернуть запасной результат, если исходное значение вызвало ошибку:

```java


import java.util.concurrent.*;

import java.util.function.Supplier;

import java.util.function.Function;

import java.util.function.Consumer;

 

class Program{

 

    public static void main(String[] args) throws Exception{

 

        int age = -5;

       

        // определяем задачу, которая вычисляет факториал

        Supplier<Integer> validateAge = () -> {



            if(age > 110 || age < 1) throw new RuntimeException("Age is invalid");

            return age; 

        };

        // задача для вывода финального результата

        Consumer<Integer> printAge = result -> System.out.printf("Final age: %d\n", result);



        // задача для обработки ошибки

        Function<Throwable, Integer> printException = ex -> { 

            System.out.println(ex.getMessage());    

            return 18;  // возвращаем некоторое значение по умолчанию

        };



        // определяем объект Executor, который будет выполнять задачи

        ExecutorService executor = Executors.newCachedThreadPool();

        CompletableFuture

                .supplyAsync(validateAge, executor)

                .exceptionally(printException)

                .thenAccept(printAge);



        // закрываем исполнителя

        executor.close();  

    }

}
```

сначала в задаче `validateAge` проверяется возраст, значение переменной `age`. условие `age > 110 || age < 1` задаёт допустимый диапазон. вне диапазона генерируется исключение:

```java


Supplier<Integer> validateAge = () -> {



    if(age > 110 || age < 1) throw new RuntimeException("Age is invalid");

    return age; 

};
```

если исключение возникло, вызывается `printException`:

```java


Function<Throwable, Integer> printException = ex -> { 

    System.out.println(ex.getMessage());    

    return 18;  // возвращаем некоторое значение по умолчанию

};
```

сообщение об ошибке печатается, и метод возвращает значение по умолчанию, здесь 18.

цепочка:

```java


CompletableFuture

    .supplyAsync(validateAge, executor)

    .exceptionally(printException)

    .thenAccept(printAge);
```

исключение из `validateAge` передаётся в `printException`, и та производит конечный результат. этот результат передаётся в `printAge`. последний колбэк, `printAge`, выполняется и при ошибке. консольный вывод:

```bash


java.lang.RuntimeException: Age is invalid

Final age: 18
```

строка `java.lang.RuntimeException: Age is invalid` является сообщением обёртки. в конструктор `RuntimeException` передавался более короткий текст. откуда берётся префикс с именем класса, видно по типу `CompletionException`.

#### completionexception

исключение, которым завершаются задачи `CompletableFuture`, имеет тип `CompletionException`. класс наследует `RuntimeException` и служит обёрткой над исходным исключением. когда код задачи выполняет

```java


if(age > 110 || age < 1) throw new RuntimeException("Age is invalid");
```

в колбэк `exceptionally()` приходит не сам выброшенный `RuntimeException`, а обёртка `CompletionException`. `supplyAsync` завершает этап этим типом, если выброшенный объект ещё не является `CompletionException`. сообщение обёртки строится из `toString()` причины, поэтому в тексте виден исходный тип: `java.lang.RuntimeException: Age is invalid`. внутреннее исключение возвращает `getCause()`, метод класса `Throwable`:

```java


Function<Throwable, Integer> printException = ex -> { 

    System.out.println(ex.getCause().getMessage());    

    return 18;  // возвращаем некоторое значение по умолчанию

};
```

при таком выводе тип исключения в строке больше не печатается:

```bash


Age is invalid

Final age: 18
```

`getCause().getMessage()` возвращает строку, переданную в конструктор `RuntimeException`, без имени класса.

### завершение completablefuture

асинхронная задача `CompletableFuture` завершается двумя способами: с результатом или с неперехваченным исключением. оба исхода обрабатывает `whenComplete()`:

```java


CompletableFuture<T> whenComplete(BiConsumer<? super T, ? super Throwable> action)
```

параметр соответствует методу `accept()` функционального интерфейса `BiConsumer`:

```java
void accept(T t, U u)
```

действие ничего не возвращает и принимает два параметра. второй параметр имеет тип `Throwable`. у `CompletableFuture` первый аргумент является результатом асинхронной задачи, второй является исключением, если оно возникло при выполнении.

если результат вычислен и исключения не было, второй параметр равен `null`. если при выполнении возникло исключение, первый параметр равен `null`. для типа, у которого нормальный результат тоже бывает `null`, различитель исхода находится во втором аргументе: оба `null` означают нормальное завершение со значением `null`. в примере факториала успешный результат `null` не бывает, и ветвление по исключению однозначно.

`whenComplete` не подменяет исход этапа. новый этап завершается тем же результатом или тем же исключением. если действие само бросает исключение, а этап завершился нормально, новый этап завершается исключением действия. если этап уже завершился с исключением и действие тоже бросает, сохраняется исходное исключение задачи, а исключение действия добавляется как подавленное.

общая схема колбэка, передаваемого в метод:

```java


f.whenComplete((result, error) -> {



      if (error == null){  // если исключения нет

      

         обрабатывает результат result;

      }

      else {    // если возникло исключение



         обрабатываем ошибку error;

      }

});
```

фрагмент схемы содержит комментарии на месте веток и сам по себе не является законченной программой. пример с факториалом:

```java


import java.util.concurrent.*;

import java.util.function.Supplier;

import java.util.function.BiConsumer;

 

class Program{

 

    public static void main(String[] args) throws Exception{

          

        System.out.println("Main thread started...");

 

        // определяем объект Executor, который будет выполнять задачи

        ExecutorService executor = Executors.newCachedThreadPool();

        work(executor, 5);

        work(executor, -5);

       

        

        System.out.println("Main thread finished...");



        executor.close(); 

    }



    static void work(Executor executor, int number){

        // определяем задачу, которая вычисляет факториал

        Supplier<Integer> factorialTask = () -> {



            if(number < 1) throw new RuntimeException("Number must be greater than 0. Invalid number: " + number);

            int n = 1;

            int result = 1;

            while(n <= number)  result *= n++;

            return result; 

        };



        BiConsumer<Integer, Throwable> completedTask = (result, ex) -> {



            if (ex == null)  // если нет исключения

                System.out.printf("factorial of %d is %d\n", number, result);

            else     // если возникло исключение

                System.out.println(ex.getCause().getMessage());

        };



        CompletableFuture

            .supplyAsync(factorialTask, executor)

            .whenComplete(completedTask);

    }

}
```

основные действия собраны в методе `work()`. он принимает число для факториала и `Executor` для выполнения задач. параметр объявлен как `Executor`, а из `main` передаётся `ExecutorService`: это законное расширяющее приведение по типу параметра.

сначала задаётся задача факториала:

```java


Supplier<Integer> factorialTask = () -> {



    if(number < 1) throw new RuntimeException("Number must be greater than 0. Invalid number: " + number);

    int n = 1;

    int result = 1;

    while(n <= number)  result *= n++;

    return result; 

};
```

если переданное число меньше 1, генерируется исключение.

завершение задачи, успешное или нет, обрабатывает отдельная задача типа `BiConsumer`:

```java


BiConsumer<Integer, Throwable> completedTask = (result, ex) -> {



    if (ex == null)  // если нет исключения

        System.out.printf("factorial of %d is %d\n", number, result);

    else     // если возникло исключение

         System.out.println(ex.getCause().getMessage());

};
```

результат факториала имеет тип `Integer`, поэтому параметры имеют типы `Integer` и `Throwable`. в демонстрационных целях задача печатает результат или сообщение об ошибке. ветка выбирается по второму аргументу. `ex.getCause()` нужен потому, что из `supplyAsync` в `whenComplete` приходит `CompletionException`, а текст исходной ошибки лежит в причине.

в конце строится цепочка с этими колбэками:

```java


CompletableFuture

    .supplyAsync(factorialTask, executor)

    .whenComplete(completedTask);
```

в `main()` метод `work()` вызывается с допустимым и с недопустимым значением:

```java


ExecutorService executor = Executors.newCachedThreadPool();



work(executor, 5);

work(executor, -5);
```

оба вызова отправляют задачи в один кэширующий пул, и задачи идут параллельно. консольный вывод имеет, например, такой вид. порядок сообщений не детерминирован:

```bash


Main thread started...

factorial of 5 is 120

Main thread finished...

Number must be greater than 0. Invalid number: -5
```

строка `Main thread finished...` печатается до `executor.close()`. она состязается с выводом задач. `close()` дожидается обоих вызовов `work`, поэтому процесс не заканчивается раньше колбэков. в показанной трассе успешный факториал 120 напечатан до этой строки, а сообщение о числе -5 после неё. другой порядок тех же трёх строк тоже соответствует программе.
