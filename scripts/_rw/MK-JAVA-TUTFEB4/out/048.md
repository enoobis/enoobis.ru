обобщенный класс может стоять в иерархии наследования и как базовый тип, и как наследник. ниже разобраны варианты того, как параметр типа проходит через секцию `extends`, и как после этого устроены преобразования между параметризациями.

### базовый обобщенный класс

наследник обобщенного класса обязан указать аргумент типа базового класса в секции `extends`. аргументом может служить собственный параметр наследника либо конкретный тип.

```java

class Account<T>
{
    private T _id;
    T getId(){return _id;}
    Account(T id)
    {
        _id = id;
    }
}

class DepositAccount<T> extends Account<T>{

    DepositAccount(T id){
        super(id);
    }
}
```

конструктор `DepositAccount` вызывает конструктор базового класса и передает ему идентификатор. параметр `T` наследника подставлен в `Account<T>`, поэтому поле `_id` и метод `getId()` у наследника имеют тот же тип, что и соответствующие члены базового класса. вызов `super(id)` обязателен: явного конструктора без параметров у `Account` нет.

варианты использования:

```java

DepositAccount dAccount1 = new DepositAccount(20);
System.out.println(dAccount1.getId());
        
DepositAccount dAccount2 = new DepositAccount("12345");
System.out.println(dAccount2.getId());
```

в этом листинге аргумент типа у `DepositAccount` опущен. такое объявление является сырым типом (raw type): проверка аргументов обобщения для переменной отключается, и компилятор принимает и упакованный `int` (как `Integer`), и `String`, выдавая предупреждение о непроверяемом преобразовании. статический тип `getId()` у сырого типа совпадает со стиранием параметра, то есть с `Object`, и `println` печатает это значение через `toString()`. явная параметризация `DepositAccount<Integer>` и `DepositAccount<String>` разводит эти два случая уже на уровне типов и убирает сырой тип.

наследник может ввести и собственные параметры, сверх тех, что он передает базовому классу.

```java

class Account<T>
{
    private T _id;
    T getId(){return _id;}
    Account(T id)
    {
        _id = id;
    }
}

class DepositAccount<T, S> extends Account<T>{

    private S _name;
    S getName(){return _name;}
    DepositAccount(T id, S name){
        super(id);
        this._name=name;
    }
}
```

класс `DepositAccount<T, S>` наследует `Account<T>` и добавляет параметр `S` для поля имени. параметр `T` по-прежнему уходит в базовый класс и задает тип идентификатора, параметр `S` существует только у наследника и задает тип имени. конструктор принимает оба значения и передает идентификатор в `super`.

варианты использования:

```java

DepositAccount<Integer, String> dAccount1 = new DepositAccount(20, "Tom");
System.out.println(dAccount1.getId() + " : " + dAccount1.getName());
        
DepositAccount<String, Integer> dAccount2 = new DepositAccount("12345", 23456);
System.out.println(dAccount2.getId() + " : " + dAccount2.getName());
```

первая переменная связывает `T` с `Integer` и `S` с `String`, вторая делает наоборот. `getId()` возвращает значение первого параметра, `getName()` возвращает значение второго. числовые аргументы конструктора упаковываются в соответствующие оболочки.

отдельный случай: наследник вообще не является обобщенным и фиксирует аргумент базового класса конкретным типом.

```java

class Account<T>
{
    private T _id;
    T getId(){return _id;}
    Account(T id)
    {
        _id = id;
    }
}

class DepositAccount extends Account<Integer>{

    DepositAccount(){
        super(5);
    }
}
```

в секции `extends` записан `Account<Integer>`. все вхождения параметра базового класса для этого наследника заменены на `Integer`. конструктор `DepositAccount` передает в `super` значение того же типа, число 5, которое упаковывается в `Integer`. собственного параметра типа у `DepositAccount` нет, поэтому разные экземпляры этого класса несут идентификатор одного и того же статического типа.

вариант использования:

```java

DepositAccount dAccount1 = new DepositAccount();
System.out.println(dAccount1.getId());
```

вызов `getId()` возвращает `Integer`. новый идентификатор снаружи задать нельзя: конструктор наследника параметров не принимает и всегда передает в базовый класс одно и то же значение 5.

### обобщенный класс-наследник

базовый класс может быть обычным, без параметров типа, а обобщение появляется только у наследника.

```java

class Account
{
    private String _name;
    String getName(){return _name;}
    Account(String name)
    {
        _name=name;
    }
}

class DepositAccount<T> extends Account{

    private T _id;
    T getId(){return _id;}
    DepositAccount(String name, T id){
        super(name);
		_id = id;
    }
}
```

обращение к конструктору и членам базового класса в наследнике совпадает с наследованием обычных классов. `super(name)` передает строку в `Account`, поле `_name` и метод `getName()` имеют тип `String` независимо от параметра наследника. параметр `T` относится только к полю `_id` класса `DepositAccount` и в базовый класс не передается.

### преобразование обобщенных типов

объект одного обобщенного типа приводится к другому, когда совпадает и отношение наследования классов, и аргумент типа. для разбора достаточно тех же двух классов, связанных наследованием с общим параметром.

```java

class Account<T>
{
    private T _id;
    T getId(){return _id;}
    Account(T id)
    {
        _id = id;
    }
}

class DepositAccount<T> extends Account<T>{

    DepositAccount(T id){
        super(id);
    }
}
```

объект `DepositAccount<Integer>` приводится к `Account<Integer>`:

```java

DepositAccount<Integer> depAccount = new DepositAccount(10);
Account<Integer> account = (Account<Integer>)depAccount;
System.out.println(account.getId());
```

преобразование законно. `DepositAccount<T>` является подтипом `Account<T>` при одном и том же аргументе `T`. явное приведение в листинге допустимо, хотя для восходящего преобразования вдоль `extends` компилятор принял бы присваивание и без оператора приведения. `getId()` после присваивания по-прежнему возвращает `Integer`, потому что аргумент типа при восходящем преобразовании сохраняется.

то же приведение при разных аргументах типа компилятор не принимает.

```java

DepositAccount<Integer> depAccount = new DepositAccount(10);
Account<String> account = (Account<String>)depAccount;
```

`DepositAccount<Integer>` является подтипом `Account<Integer>` и не является подтипом `Account<String>`. обобщения в java инвариантны: совпадение аргумента типа входит в отношение подтипа. из того, что `Integer` и `String` оба ссылочные типы, приводимость `Account<Integer>` к `Account<String>` не следует, и оператор приведения положение не меняет. ошибка обнаруживается во время компиляции.
