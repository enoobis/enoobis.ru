простой список задаёт интерфейс `List`. он расширяет `Collection`: к общим операциям коллекции добавляются доступ по индексу, вставка в середину и порядок, который задаёт вызывающий код. хеш-код и компаратор этот порядок не определяют. часто используемые методы:

- `void add(int index, E obj)`: вставляет obj по индексу index. элементы, начиная с index, сдвигаются вправо

- `void addFirst(E obj)`: добавляет объект в начало списка

- `void addLast(E obj)`: добавляет объект в конец списка

- `boolean addAll(int index, Collection col)`: вставляет по индексу index все элементы коллекции col. если список изменился, возвращает true, иначе false

- `E get(int index)`: возвращает объект по индексу index

- `E getFirst()`: возвращает первый элемент

- `E getLast()`: возвращает последний элемент

- `int indexOf(Object obj)`: индекс первого вхождения obj. если объект не найден, возвращает -1

- `int lastIndexOf(Object obj)`: индекс последнего вхождения obj. если объект не найден, возвращает -1

- `ListIterator listIterator()`: возвращает `ListIterator` для обхода списка в обоих направлениях

- `static List of(элементы)`: создаёт объект `List` из переданного набора элементов

- `E remove(int index)`: удаляет объект по индексу index и возвращает удалённый объект

- `E removeFirst()`: удаляет первый элемент

- `E removeLast()`: удаляет последний элемент

- `E set(int index, E obj)`: заменяет элемент по индексу index значением obj и возвращает прежнее значение

- `void sort(Comparator comp)`: сортирует список компаратором comp

- `List subList(int start, int end)`: представление элементов с индекса start включительно до индекса end исключительно. представление связано с исходным списком: запись в него меняет исходный список

- `static List of(E... elements)`: возвращает неизменяемый список с элементами elements. конкретный тип в показанном случае: внутренний класс `java.util.ImmutableCollections$ListN`

методы `addFirst`, `addLast`, `getFirst`, `getLast`, `removeFirst` и `removeLast` попали в `List` из `SequencedCollection`, начиная с java 21. индексные `get` и `set` при неверном индексе порождают `IndexOutOfBoundsException`.

встроенная реализация `List`: класс `ArrayList`. он наследует `AbstractList` и применяет `List`. список хранится в массиве: обращение по индексу занимает постоянное время, а число элементов заранее не фиксировано. когда места в массиве не хватает, выделяется новый массив и в него копируются старые ссылки.

конструкторы:

- `ArrayList()`: создаёт пустой список

- `ArrayList(Collection col)`: создаёт список и копирует в него все элементы коллекции col

- `ArrayList(int capacity)`: создаёт список с начальной ёмкостью capacity

ёмкость: длина внутреннего массива, то есть сколько ссылок можно поместить без нового выделения. размер: число уже добавленных элементов, его возвращает `size`. при росте сверх ёмкости создаётся новый массив, элементы копируются, старый массив становится мусором. если верхняя граница известна заранее, её задают в конструкторе: копирований меньше, и вставки дешевле.

основные операции начинаются с создания списка:

```java


import java.util.ArrayList;  // импортируем класс



public class Program{

      

    public static void main(String[] args) {



      ArrayList<String> people = new ArrayList<String>();

    }

}
```

компилятор выводит аргумент типа из контекста, поэтому запись можно сократить. в объявлении `ArrayList<String>` пустые скобки `<>` берут аргумент из типа переменной. при `var` направление обратное: тип переменной берётся из конструктора, и аргумент типа пишут на `new`.

```java


ArrayList<String> people = new ArrayList<>();

// или так

var people = new ArrayList<String>();
```

### размер списка

размер даёт `size()`. возвращаемое значение имеет тип `int`:

```java


var people = new ArrayList<String>();

System.out.println(people.size()); // 0
```

### добавление

элемент добавляется методом `add`. аргумент, ссылка на добавляемый объект, записывается в конец списка:

```java


var people = new ArrayList<String>();



people.add("Tom");

people.add("Bob");

people.add("Sam");



System.out.println(people.size()); // 3
```

перегрузка `add(int, E)` вставляет элемент не в конец, а в заданную позицию. элементы правее этой позиции сдвигаются:

```java


var people = new ArrayList<String>();



people.add("Tom");

people.add("Bob");

people.add("Sam");

people.add(1, "Alice"); // добавляем элемент по индексу 1



System.out.println(people.size()); // 4
```

в выражении `people.add(1, "Alice")` строка `"Alice"` занимает индекс 1. бывший элемент с этим индексом и все следующие сдвигаются на одну позицию вправо.

у конструктора без аргументов ёмкость по умолчанию равна 10: массив такой длины создаётся при первой вставке. в момент `new` его может ещё не быть. повторные выделения дороги, потому что каждый рост копирует уже накопленные ссылки. если число элементов известно заранее или известна хотя бы верхняя граница, её передают в конструктор. список с начальной ёмкостью 16:

```java


var people = new ArrayList<String>(16);

System.out.println(people.size()); // 0
```

ёмкость и размер: разные величины. здесь зарезервировано место на 16 ссылок, а `size()` равен 0: ни один элемент ещё не добавлен. одиннадцатая вставка нового выделения не вызывает, память уже есть. за счёт этого серия вставок не тратит время на копирование массива.

ту же ёмкость можно запросить позже, методом `ensureCapacity`. размер списка вызов не меняет, увеличивается только запас внутреннего массива:

```java
people.ensureCapacity(25);
```

### добавление элементов из коллекции

когда элементов много, вставлять их по одному долго. в библиотеке есть несколько способов передать сразу набор. интерфейс `List` определяет статический `of`, и в него передаётся произвольное число объектов:

```java


import java.util.List;



public class Program{

       

    public static void main(String[] args) {

           

        // создаем список из 3 строк

        List<String> people = List.<String>of("Tom", "Bob", "Sam");



        System.out.println(people.size()); // 3

    }

}
```

переменная объявлена типом `List<String>`. фактический объект имеет тип `java.util.ImmutableCollections$ListN`, внутренний класс jdk. это неизменяемый список фиксированной длины: `add`, `set` и `remove` порождают `UnsupportedOperationException`, элемент `null` метод `of` не принимает. такой список годится как готовый набор констант. изменяемый список произвольного размера даёт `ArrayList`. его конструктор от коллекции копирует элементы в собственный массив:

```java


import java.util.List;

import java.util.ArrayList;



public class Program{

       

    public static void main(String[] args) {

           

        ArrayList<String> people = new ArrayList<String>(List.<String>of("Tom", "Bob", "Sam"));

        System.out.println(people.size()); // 3

    }

}
```

ещё один способ: статический метод `Collections.addAll`.

```java
static <T> boolean addAll(Collection<? super T> c, T... elements)
```

первый параметр: коллекция-приёмник. дальше идёт переменное число добавляемых объектов. вызов:

```java


import java.util.Collections;

import java.util.ArrayList;



public class Program{

       

    public static void main(String[] args) {

           

        var people = new ArrayList<String>();

        Collections.addAll(people, "Tom", "Bob", "Sam");

        System.out.println(people.size()); // 3

    }

}
```

отдельную коллекцию под добавляемые строки собирать не нужно: они передаются как аргументы переменной длины и по одному попадают в `add` приёмника.

### получение элементов списка

элемент по индексу возвращает `get`. для `ArrayList` это чтение ячейки массива, стоимость постоянная. индекс считается с нуля:

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {





        var people = new ArrayList<String>(16);

        System.out.println(people.size()); // 0



        people.add("Tom");

        people.add("Bob");

        people.add("Sam");

        people.add(1, "Alice"); // добавляем элемент по индексу 1





        System.out.println(people.get(0));      // Tom

        System.out.println(people.get(1));      // Alice

        System.out.println(people.get(2));      // Bob

        System.out.println(people.get(3));      // Sam

    }

}
```

### перебор списка

индексный цикл `for` сочетает счётчик с `get`. он нужен, когда в теле требуется сам индекс:

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {





        var people = new ArrayList<String>(16);

        System.out.println(people.size()); // 0



        people.add("Tom");

        people.add("Bob");

        people.add("Sam");

        people.add(1, "Alice"); // добавляем элемент по индексу 1



        for(int i =0; i < people.size(); i++){



            System.out.println(people.get(i)); 

        }

    }

}
```

цикл `for-each` обходит список как `Iterable`, без явного индекса. порядок совпадает с порядком индексов:

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {



        var people = new ArrayList<String>(16);

        System.out.println(people.size()); // 0



        people.add("Tom");

        people.add("Bob");

        people.add("Sam");

        people.add(1, "Alice"); // добавляем элемент по индексу 1



        for(String person : people){



            System.out.println(person); 

        }

    }

}
```

### изменение элемента

замена элемента: метод `set(int index, E obj)`. первый аргумент: индекс, второй: новый объект. метод возвращает прежнее значение по этому индексу:

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {





        var people = new ArrayList<String>(16);

        System.out.println(people.size()); // 0



        people.add("Tom");

        people.add("Bob");

        people.add("Sam");

        people.set(1, "Alex"); // изменяем элемент по индексу 1





        System.out.println(people.get(1));      // Alex

    }

}
```

### индекс элемента

индекс элемента ищут методами `indexOf(Object obj)` и `lastIndexOf(Object obj)`. первый возвращает индекс первого вхождения, второй возвращает индекс последнего. сравнение идёт через `equals`. если равного элемента нет, оба возвращают -1:

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {



        var people = new ArrayList<String>();



        people.add("Tom");

        people.add("Bob");

        people.add("Tom");

        people.add("Sam");



        System.out.println(people.indexOf("Tom"));      // 0

        System.out.println(people.lastIndexOf("Tom"));      // 2

    }

}
```

### удаление

удаление по значению: `remove(Object obj)`. из списка уходит первое вхождение, равное аргументу в смысле `equals`. последующие элементы сдвигаются влево:

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {



        var people = new ArrayList<String>();



        people.add("Tom");

        people.add("Bob");

        people.add("Sam");



        people.remove("Bob"); // удаляем элемент "Bob"



        for(String person : people){



            System.out.println(person);      // Tom

                                            // Sam



        }

    }

}
```

консольный вывод:

```bash


Tom

Sam
```

у `remove` есть вторая перегрузка, `remove(int index)`: аргумент считается индексом, метод возвращает удалённый элемент. для списка чисел выбор перегрузки перестаёт быть очевидным.

```java


import java.util.ArrayList;



public class Program{

      

    public static void main(String[] args) {



        var numbers = new ArrayList<Integer>();



        numbers.add(11);

        numbers.add(12);

        numbers.add(13);



        numbers.remove(12); // пытаемся удалить элемент 12 



        for(Integer n : numbers){



            System.out.println(n);



        }

    }

}
```

этот запуск завершается ошибкой. литерал `12` имеет тип `int`, и разрешение перегрузки выбирает `remove(int)` ещё до автоупаковки в `Integer`. вызов `numbers.remove(12)` пытается удалить элемент с индексом 12. в списке три элемента, такого индекса нет, и возникает `IndexOutOfBoundsException`. чтобы удалить значение 12, сначала находят его индекс и уже этот индекс передают в `remove`:

```java


numbers.remove(numbers.indexOf(12)); // удаляем элемент 12
```

если передать объектный `Integer`, например `Integer.valueOf(12)`, будет выбрана перегрузка `remove(Object)` и удалится равное значение. ячейка выбирается поиском, а индекс в аргументе больше не участвует.

метод `removeIf` удаляет сразу все элементы, для которых предикат возвращает true:

```java


import java.util.Collections;

import java.util.ArrayList;



public class Program{

       

    public static void main(String[] args) {

           

        var numbers = new ArrayList<Integer>();

        Collections.addAll(numbers, 1, 2, 3, 4, 5, 6, 7, 8);

        numbers.removeIf( num -> num % 2 == 0);

        for(var n : numbers) System.out.print(n + ", "); // 1, 3, 5, 7, 

        System.out.println(); 

    }

}
```

в `removeIf` передаётся предикат: функция от элемента списка к `boolean`. элемент удаляется, когда функция возвращает `true`. здесь условие отбирает чётные числа, то есть те, у которых остаток от деления на 2 равен 0:

```java
numbers.removeIf( num -> num % 2 == 0);
```

после вызова в списке остаются нечётные числа, их относительный порядок сохраняется.
