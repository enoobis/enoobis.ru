класс `Constructor` из пакета `java.lang.reflect` представляет один конструктор класса. через него получают сведения об объявлении и создают новые экземпляры, не записывая оператор `new` в вызывающем коде. основные методы:

- `String getName()`: возвращает имя конструктора. оно совпадает с двоичным именем класса, которому конструктор принадлежит

- `int getModifiers()`: возвращает целое число, в котором отдельные биты описывают модификаторы объявления

- `Object newInstance(Object... initargs)`: создаёт новый экземпляр класса и передаёт конструктору аргументы из `initargs`. объект на выходе имеет тип того класса, у которого взят конструктор

- `Class[] getParameterTypes()`: возвращает массив объектов `Class` с типами параметров в порядке объявления

- `Class[] getExceptionTypes()`: возвращает массив объектов `Class` для типов проверяемых исключений, объявленных в разделе `throws`

### получение конструктора

объект `Constructor` получают у объекта `Class`. конструктор не наследуется, поэтому поиск ограничен тем классом, у которого вызван метод, и в суперкласс не поднимается:

- `Constructor[] getConstructors()`: возвращает массив объектов `Constructor` для открытых конструкторов (с модификатором `public`) данного класса

- `Constructor[] getDeclaredConstructors()`: возвращает массив объектов `Constructor` для всех конструкторов данного класса, включая непубличные. если конструкторов нет, а также если объект `Class` представляет примитивный тип или массив, метод возвращает массив нулевой длины

- `Constructor getConstructor(Class... parameterTypes)`: возвращает объект `Constructor` для публичного конструктора. параметр `parameterTypes` задаёт объекты `Class`, которые идентифицируют формальные типы параметров в порядке объявления. по этой последовательности типов выбирается нужная перегрузка, если конструкторов несколько. если такого публичного конструктора нет, метод генерирует исключение `NoSuchMethodException`. отдельного исключения для отсутствующего конструктора в `java.lang` нет: и метод, и конструктор ищутся одним механизмом, поэтому исключение общее

- `Constructor getDeclaredConstructor(Class... parameterTypes)`: возвращает объект `Constructor` для конструктора с любым модификатором доступа. параметр `parameterTypes` снова задаёт формальные типы параметров в порядке объявления, и по ним выбирается перегрузка. если конструктора с такой последовательностью типов нет, метод генерирует исключение `NoSuchMethodException`

исходный класс, конструкторы которого разбираются дальше:

```java


class Person {

     

    private String name;

    private int age;



    Person(){

        this("Undefined", 1);

    }



    Person(String name, int age){ 



        this.name = name;

        this.age = age;

    }

    

    void print(){

        System.out.printf("Person. Name: %s;  Age: %d\n", name, age);

    }

}
```

у `Person` два конструктора. конструктор без параметров делегирует второму через `this("Undefined", 1)`. оба имеют пакетный доступ: модификатор `public` в объявлении не указан.

все конструкторы этого класса:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Person.class;

        Constructor[] ctors = cl.getDeclaredConstructors();

        for(Constructor ctor : ctors){



            System.out.println(ctor);

        }

    }

}
```

консольный вывод:

```bash


Person()

Person(java.lang.String,int)
```

`getDeclaredConstructors()` возвращает оба конструктора, в том числе с пакетным доступом. `toString()` печатает краткую сигнатуру: имя класса и типы параметров. порядок элементов массива спецификация не гарантирует.

один конструктор выбирают по типам параметров. типы передают объектами `Class` в том порядке, в каком объявлены формальные параметры. второй конструктор `Person` принимает `String` и `int`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Person.class;

        try{

            Constructor ctor = cl.getDeclaredConstructor(String.class, int.class);

            

            System.out.println(ctor);   // Person(java.lang.String,int)

        }

        catch(Exception ex){

            System.out.println(ex);

        }

    }

}
```

`String.class` и `int.class` задают точную последовательность формальных типов. `int.class` обозначает примитив. `Integer.class` обозначает ссылочный тип и для выбора перегрузки считается другим параметром. если последовательность не совпадает ни с одним конструктором, возникает `NoSuchMethodException`, и в примере оно попадает в `catch`.

### получение параметров

`getParameterTypes()` возвращает массив типов параметров. каждый элемент имеет тип `Class`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Person.class;

        Constructor[] ctors = cl.getDeclaredConstructors();

        for(Constructor ctor : ctors){



            // получаем имя конструктора

            String name = ctor.getName();

            System.out.print(name + "(");



            // получаем типы параметров

            Class[] params = ctor.getParameterTypes();

            for(Class p : params){  

                System.out.printf("%s, ", p.getName());

            }



            System.out.println(")");

        }

    }

}
```

консольный вывод:

```bash


Person()

Person(java.lang.String, int, )
```

у конструктора без параметров массив пуст, поэтому печатается `Person()`. у второго конструктора в массив входят `java.lang.String` и `int`. цикл ставит запятую и пробел после каждого типа, в том числе после последнего, поэтому строка заканчивается на `int, `.

новый экземпляр создаёт `newInstance`. в обобщённой форме сигнатура такая:

```java


public T newInstance(Object... initargs)

              throws InstantiationException,

                    IllegalAccessException,

                    IllegalArgumentException,

                    InvocationTargetException
```

аргументы метода становятся аргументами конструктора, по одному объекту на параметр. примитив передаётся упакованным значением и распаковывается при вызове. проверяемое исключение, выброшенное телом конструктора, оборачивается в `InvocationTargetException`. отказ в доступе даёт `IllegalAccessException`, несовместимость аргументов даёт `IllegalArgumentException`, а невозможность создать экземпляр (например, у абстрактного класса) даёт `InstantiationException`. пример создаёт объект `Person`:

```java


import java.lang.reflect.*;



public class Program{

      

    public static void main(String[] args) {

        

        Class cl = Person.class;

        try{

            Constructor ctor = cl.getDeclaredConstructor(String.class, int.class);

            Person person = (Person) ctor.newInstance("Sam", 23);   

            person.print();     // Person. Name: Sam;  Age: 23

        }

        catch(Exception ex){

            System.out.println(ex);

        }

    }

}
```

сначала получают конструктор с двумя параметрами:

```java
Constructor ctor = cl.getDeclaredConstructor(String.class, int.class);
```

затем этот конструктор вызывают и передают в `newInstance()` аргументы `"Sam"` и `23`:

```java
Person person = (Person) ctor.newInstance("Sam", 23);
```

возвращаемое значение имеет статический тип `Object` (в обобщённой форме это параметр типа `T`), поэтому его приводят к `Person`. после вызова `print()` печатает имя `Sam` и возраст `23`. для непубличного конструктора действует тот же контроль доступа, что и для полей. вызов из другого пакета или вызов конструктора с модификатором `private` требует перед `newInstance` вызова `setAccessible(true)`, иначе возникает `IllegalAccessException`. в этом примере конструктор пакетный, а класс `Program` лежит в том же пакете по умолчанию, поэтому вызов разрешён без снятия проверки.
