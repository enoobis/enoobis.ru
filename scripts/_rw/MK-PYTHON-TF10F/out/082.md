асинхронное программирование задаёт способ организации кода, при котором программа исполняет другие задачи, пока ждёт завершения операций ввода-вывода. в отличие от мультипроцессорности, которая занимает разные ядра cpu отдельными процессами, асинхронность в python исполняется в одном потоке на одном ядре. планировщик этой модели называется циклом событий (event loop). когда задача переходит в ожидание, например ждёт ответ сервера, цикл временно переключается на другую готовую задачу. как только первая задача получает данные, цикл возвращается к ней. переключение кооперативное: задача сама отдаёт управление в точке ожидания, вытеснения по таймеру, как у потоков ос, здесь нет. на задачах ввода-вывода за счёт этого держат много ожиданий при небольшом расходе ram, потому что на каждую задачу не нужен отдельный процесс и даже отдельный поток.

отличие синхронного исполнения от асинхронного передаёт такая пара:

- синхронный повар ставит чайник и неподвижно стоит у плиты 5 минут, ожидая закипания, и только потом начинает резать салат.
- асинхронный повар ставит чайник и, пока тот греется, сразу начинает резать салат. время ожидания занято другой работой.

асинхронность и мультипроцессорность решают разные классы задач:

- асинхронность: для i/o-bound задач с большим числом сетевых соединений или ожиданий (разбор тысяч веб-страниц, чат-боты, веб-серверы, обращения к базам данных). в одном потоке одновременно держат тысячи открытых соединений, потому что ожидающая соединение корутина не занимает ядро.
- мультипроцессорность (`multiprocessing`): для cpu-bound задач, где процессор непрерывно считает (рендеринг, математика, криптография). асинхронность здесь не увеличивает число ядер: пока корутина исполняет байткод без точки ожидания, цикл событий не переключается на другие задачи.

### библиотека asyncio

асинхронный код стандартной библиотеки опирается на пакет `asyncio` и два служебных слова:

- `async`: объявляет асинхронную функцию. вызов такой функции возвращает объект корутины (coroutine) и не исполняет тело.
- `await`: ставится перед вызовом другой корутины или иного ожидаемого объекта. для цикла событий это точка передачи управления: текущая корутина ждёт результат, и цикл может исполнять другие готовые задачи.

простейшая корутина:

```python


import asyncio



async def get_message():

    print("Hello...")

    return "Hello"
```

функция печатает строку и возвращает её как результат. вызов `get_message()` сам по себе тело не запускает: результатом вызова является объект корутины. это видно, если напечатать результат вызова:

```python


import asyncio



async def get_message():

    print("Hello...")

    return "Hello World"





result = get_message()

print(result)
```

консольный вывод имеет такой вид:

```bash


<coroutine object get_message at 0x7dc4d91bdd80>

<sys>:0: RuntimeWarning: coroutine 'get_message' was never awaited
```

при вызове `get_message()` строка `"Hello..."` на консоль не попадает, хотя оператор `print` в теле есть: тело ещё не исполнялось. печать результата показывает представление корутины. в показанном прогоне это `<coroutine object get_message at 0x7dc4d91bdd80>`. строка `"Hello World"` при таком вызове не появляется. одновременно интерпретатор предупреждает, что корутина нигде не ожидалась: `RuntimeWarning` с текстом `coroutine 'get_message' was never awaited`. технически это значит, что объект корутины создан и уничтожен без передачи в `await` или в планировщик цикла. предупреждение возникает при сборке мусора такой корутины.

### запуск корутины

запустить корутину можно несколькими способами. простейший для программы с одним входом состоит в вызове `asyncio.run`, куда передаётся объект корутины:

```python


import asyncio



async def get_message():

    print("Hello...")

    return "Hello World"



asyncio.run(get_message())
```

на консоль выводится строка `"Hello..."`. тело наконец исполняется, потому что `asyncio.run` передаёт корутину циклу событий.

если асинхронная функция возвращает значение, здесь строку `"Hello World"`, это значение становится результатом `asyncio.run`:

```python


import asyncio



async def get_message():

    print("Hello...")

    return "Hello World"



result = asyncio.run(get_message())     # Hello...

print(result)       # Hello World
```

при вызове `asyncio.run` выполняются следующие шаги:

- запускается новый цикл событий. задача цикла состоит в том, чтобы планировать конкурентные задачи и связывать с обратными вызовами события завершения, отмены и исключений.
- объект корутины оборачивается в задачу (`Task`).
- на завершение задачи устанавливается обратный вызов.
- задача исполняется до своего завершения.
- возвращается результат задачи, после чего цикл закрывается и связанные с ним ресурсы освобождаются.

### await

предупреждение, которое консоль выдала при вызове корутины без планировщика, выглядит так:

```bash
<sys>:0: RuntimeWarning: coroutine 'get_message' was never awaited
```

текст сообщает, что корутина не ожидается, то есть к ней не применён оператор `await` и она не передана циклу. в программе с `asyncio.run` оператор `await` на верхнем уровне не нужен: `asyncio.run` служит точкой входа всей асинхронной программы. функция создаёт новый цикл событий, запускает переданную корутину как главную задачу, а после завершения закрывает цикл и освобождает ресурсы. вызывают её из синхронного кода, обычно на самом верхнем уровне, например в блоке `if __name__ == "__main__"`. изнутри уже работающего цикла вызвать `asyncio.run` нельзя: второй цикл в том же потоке не создаётся, и возникает ошибка. пример такой ошибки:

```python


import asyncio



async def get_message():

    print("Hello...")

    return "Hello World"



async def print_message():

    result = asyncio.run(get_message())

    print(result)



asyncio.run(print_message())
```

на верхнем уровне, вне других функций, `asyncio.run` запускает `print_message()`. внутри `print_message()` вызывается вторая асинхронная функция `get_message()`, и снова через `asyncio.run`. этот фрагмент не работает. при запуске возникает ошибка:

```bash
RuntimeError: asyncio.run() cannot be called from a running event loop
```

вызов `asyncio.run(print_message())` уже запустил цикл событий. повторный `asyncio.run(get_message())` пытается запустить ещё один цикл в том же потоке, внутри первой задачи. для вызова одной корутины из другой предназначен оператор `await`.

`await` используется внутри уже запущенной корутины и ожидает завершения другой задачи или операции. оператор приостанавливает текущую корутину и возвращает управление циклу событий, пока ожидаемый объект, например другая корутина, не вернёт результат. после этого текущая корутина продолжается со следующей инструкции, а значением выражения `await` становится результат ожидания.

`await` допустим только внутри функции, объявленной через `async def`, то есть внутри другой корутины. в обычном синхронном коде, вне `async def`, оператор синтаксически запрещён. предыдущий пример с заменой внутреннего `asyncio.run` на `await`:

```python


import asyncio



async def get_message():

    print("Hello...")

    return "Hello World"



async def print_message():

    # Исопльзуем await

    result = await get_message())    # Hello...

    print(result)       # Hello World



asyncio.run(print_message())
```

вывод совпадает с ожидаемым:

```bash


Hello...

Hello World
```

у `await` на голой корутине есть точная семантика планирования: вызывающая корутина приостановлена на всё время вызова и не исполняется параллельно с вызываемой. конкурентность нескольких корутин появляется тогда, когда они оформлены отдельными задачами и цикл переключается между ними в точках ожидания. один `await` задаёт последовательность. одновременное исполнение нескольких корутин в этой точке не начинается.

### asyncio.sleep

в примере выше у `get_message` и `print_message` нет ожидания ввода-вывода, поэтому перевод их в корутины не сокращает время. в `asyncio` при этом есть операции, которые действительно отпускают цикл. базовая из них, `asyncio.sleep()`, приостанавливает текущую корутину на заданное число секунд:

```python


import asyncio



async def main():

    print("Привет...")

    # Имитируем асинхронное ожидание (например, запрос к базе данных)

    # Обычный time.sleep() здесь использовать нельзя, так как он заблокирует весь поток

    await asyncio.sleep(2)  # задержка в 2 секунды

    print("...Мир!")



if __name__ == "__main__":

    # Запуск главного цикла событий и выполнение функции

    asyncio.run(main())
```

`asyncio.sleep` регистрирует таймер в цикле событий и возвращает управление планировщику. поток при этом свободен для других задач. обычный `time.sleep` здесь непригоден: он блокирует поток целиком, и цикл событий в этом потоке не обрабатывает остальные корутины, пока задержка не кончится.

### параллельное выполнение задач

одна корутина сама по себе преимущества по времени не даёт. выигрыш появляется, когда несколько корутин ожидают одновременно. объект корутины является значением: его передают в функцию, собирают в набор и запускают вместе.

для одновременного ожидания нескольких корутин служит `asyncio.gather()`. функция принимает набор ожидаемых объектов и завершается, когда завершились все:

```python


import asyncio

import time



async def fetch_data(source_id, delay):

    print(f"[Старт] Загрузка данных из Источника {source_id}...")

    await asyncio.sleep(delay) # Имитация сетевой задержки

    print(f"[Готово] Данные из Источника {source_id} получены.")

    return f"данные {source_id}"



async def main():

    start_time = time.time()

    

    # Запускаем три задачи параллельно

    results = await asyncio.gather(

        fetch_data(1, 2),

        fetch_data(2, 3),

        fetch_data(3, 1)

    )

    

    end_time = time.time()

    print(f"Все результаты: {results}")

    print(f"Общее время выполнения: {end_time - start_time:.2f} сек.")

    

if __name__ == "__main__":

    asyncio.run(main())
```

фрагмент запускает три загрузки одновременно и измеряет общее время. корутина `fetch_data(source_id, delay)` изображает сетевой запрос с номером источника и задержкой. `asyncio.sleep(delay)` приостанавливает именно эту корутину на время задержки и освобождает поток для остальных задач того же цикла.

в `main()` три вызова `fetch_data` с задержками 2, 3 и 1 секунда передаются в `asyncio.gather`. каждый вызов создаёт корутину, а `gather` планирует их как конкурентные задачи:

```python


results = await asyncio.gather(

        fetch_data(1, 2),

        fetch_data(2, 3),

        fetch_data(3, 1)

    )
```

`asyncio.run(main())` создаёт цикл событий и запускает главную корутину. результат:

```bash


[Старт] Загрузка данных из Источника 1...

[Старт] Загрузка данных из Источника 2...

[Старт] Загрузка данных из Источника 3...

[Готово] Данные из Источника 3 получены.

[Готово] Данные из Источника 1 получены.

[Готово] Данные из Источника 2 получены.

Все результаты: ["данные 1", "данные 2", "данные 3"]

Общее время выполнения: 3.00 сек.
```

программа не ждёт завершения задач строго по очереди. задачи продвигаются одновременно: пока одна спит в `asyncio.sleep`, цикл исполняет остальные. общее время равно времени самой долгой задачи, около 3 секунд. последовательные `await` без `gather` сложили бы задержки: 2 + 3 + 1 = 6 секунд. результаты собираются в список в порядке аргументов `gather`. порядок завершения на этот список не влияет: сначала источник 1, затем 2, затем 3, хотя источник 3 заканчивается раньше всех.

тот же набор корутин можно собрать заранее, если список приходит извне:

```python


tasks = [

    fetch_data(1, 2),

    fetch_data(2, 3),

    fetch_data(3, 1)

]

results = await asyncio.gather(*tasks)
```

звёздочка в `asyncio.gather(*tasks)` распаковывает список в позиционные аргументы. семантика ожидания та же, что у прямого перечисления трёх вызовов.

### создание фоновых задач

иногда задачу запускают в фоне и сразу продолжают основной код, не ожидая её окончания в точке запуска. для этого служит `asyncio.create_task()`. функция возвращает объект `Task`, через который фоновую задачу позже останавливают или дожидаются:

- `task.cancel()`: запрашивает отмену задачи. в ближайшей точке ожидания корутина получает `CancelledError`.
- `await task`: дожидается окончания и даёт результат, если корутина что-либо возвращает через `return`. при отмене или исключении ожидание само завершается ошибкой.

пример фонового цикла на время основной работы:

```python


import asyncio



async def background_logger():

    while True:

        print("[Фон] Проверка статуса системы...")

        await asyncio.sleep(1)



async def main():

    # Создаем фоновую задачу (она начинает выполняться сразу)

    task = asyncio.create_task(background_logger())

    

    print("[Главный] Начало важной работы.")

    await asyncio.sleep(3.5) # Имитируем основную работу

    print("[Главный] Важная работа завершена.")

    

    # Отменяем фоновую задачу, иначе она будет работать вечно

    task.cancel()

    

if __name__ == "__main__":

    asyncio.run(main())
```

фоновая задача раз в секунду печатает сообщение о проверке системы, пока главная корутина изображает другую работу. `background_logger` крутится в цикле `while True`. на каждом проходе она печатает `"[Фон] Проверка статуса системы..."` и останавливается на одну секунду через `await asyncio.sleep(1)`.

главная корутина `main()` создаёт задачу `task` вызовом `asyncio.create_task()`. с этого момента задача поставлена в цикл и исполняется конкурентно с `main`. завершения фоновой задачи `main` в этой точке не ждёт.

дальше `main` печатает `"[Главный] Начало важной работы."` и приостанавливается на 3,5 секунды через `await asyncio.sleep(3.5)`. эта пауза изображает полезную нагрузку и одновременно отдаёт цикл фоновой задаче. за 3,5 секунды фоновый цикл с шагом в одну секунду успевает выполниться примерно три раза.

в конце `main` печатает `"[Главный] Важная работа завершена."` и отменяет фоновую задачу методом `task.cancel()`, иначе цикл `while True` не закончится и `asyncio.run` не сможет закрыть программу.

ожидаемый вывод:

```bash


[Главный] Начало важной работы.

[Фон] Проверка статуса системы...

[Фон] Проверка статуса системы...

[Фон] Проверка статуса системы...

[Главный] Важная работа завершена.
```

по механике `asyncio.create_task()` оборачивает корутину в объект `Task` и сразу ставит его в очередь цикла событий. исполнение идёт в том же потоке, в фоне относительно текущей корутины. отсюда два свойства.

- немедленная постановка в цикл, без ожидания через `await` в точке создания.

обычный вызов `background_logger()` только создаёт объект корутины. тело начнёт исполняться, когда кто-то выполнит `await background_logger()`, и на это время вызывающая корутина будет приостановлена до полного завершения вызова.

`asyncio.create_task(background_logger())` устроен иначе:

- задача добавляется в очередь цикла событий.
- исполнение текущей корутины сразу переходит к следующей строке и не ждёт завершения задачи.
- тело новой задачи получает управление при первой же паузе текущей корутины, то есть когда та встретит любой `await` и вернёт управление циклу.

- конкурентность (concurrency). `create_task()` позволяет вести несколько задач конкурентно на одном потоке. пока одна задача приостановлена, например на `await asyncio.sleep()`, или ждёт ответ сети, цикл переключается на другую задачу. это чередование в одном потоке. параллельного исполнения байткода python на нескольких ядрах здесь не возникает: для такой параллельности нужен отдельный процесс, как в `multiprocessing`.

без `create_task` ожидания идут последовательно:

```python


await task1()  # Ждем 3 секунды

await task2()  # Только потом ждем еще 3 секунды

# Всего уйдет 6 секунд.
```

с `create_task` задачи ведут себя конкурентно:

```python


t1 = asyncio.create_task(task1())  # Запущена в фоне

t2 = asyncio.create_task(task2())  # Запущена в фоне



await t1

await t2



# Обе задачи работают одновременно. Всего уйдет 3 секунды.
```

оба `await` в конце только дожидаются уже идущих задач. если каждая из них занимает около 3 секунд ожидания, суммарное время близко к 3 секундам. последовательное ожидание тех же двух задач заняло бы около 6 секунд.
