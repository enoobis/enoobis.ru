управление зависимостями в python задаёт состав окружения: какие дистрибутивы установлены, в каких версиях и вместе с какими транзитивными пакетами. от этого зависят воспроизводимость запуска и совместимость интерфейсов библиотек на другой машине. долгое время де-факто стандартом был менеджер `pip`. затем стали нужны средства с меньшим временем работы и с более предсказуемым разрешением зависимостей. такой программой стал uv, разработанный командой astral. установка пакетов и разрешение зависимостей вынесены в отдельный инструмент и рассчитаны на высокую скорость обеих операций.

uv является менеджером пакетов python, реализация написана на rust. задача состоит в том, чтобы сократить время трёх операций: установки пакетов, разрешения зависимостей и создания виртуальных окружений. время этих операций у uv меньше, чем у уже существующих альтернатив. по охвату он замещает пакетный менеджер `pip`, а также pip-tools, virtualenv и другие утилиты того же круга: создание окружения, фиксацию версий и установку по списку требований. отдельный исполняемый файл на rust запускается без старта интерпретатора на каждую команду.

по некоторым оценкам создание виртуального окружения через uv примерно в 80 раз быстрее, чем через `python -m venv`. установка пакетов от 4 до 12 раз быстрее без кэша и примерно в 100 раз быстрее, когда дистрибутивы уже лежат в кэше. оценки относятся ко времени выполнения. набор пакетов определяется индексом, метаданными дистрибутивов и ограничениями версий.

выигрыш по времени складывается из устройства программы.

rust компилируется в машинный код. процесс uv не поднимает интерпретатор python и не импортирует библиотеку менеджера при каждом вызове. у программы, написанной на python, эти затраты повторяются на каждой команде и на коротких операциях сравнимы с самой работой. накладные расходы на старт малы, машинный код использует процессор и диск напрямую. такая скорость для инструмента, написанного на python, недоступна.

загрузка и установка идут параллельно. пока один дистрибутив скачивается, другой уже распаковывается, и ожидание сети не складывается в одну последовательную сумму.

разрешение зависимостей устроено с расчётом на время поиска. даже на плотном графе, где у пакетов много взаимных ограничений на версии, совместимый набор находится быстро. само разрешение состоит в поиске такого набора версий, в котором одновременно выполнены и прямые требования проекта, и транзитивные требования зависимостей. если такого набора нет, менеджер сообщает о конфликте до начала установки, и окружение остаётся в прежнем состоянии.

загруженные дистрибутивы сохраняются в кэше, повторная загрузка того же артефакта не выполняется. когда кэш и каталог окружения лежат на одной файловой системе, uv связывает файлы жесткой ссылкой и не копирует байты заново. когда файловые системы разные, жесткая ссылка недоступна, и выполняется полное копирование. листинг установки ниже показывает этот переход: uv предупреждает о сбое жесткой ссылки и предлагает задать `UV_LINK_MODE=copy` или флаг `--link-mode=copy`, чтобы копирование было выбранным режимом.

### основные возможности uv

для обычного цикла управления пакетами uv дает такой набор операций:

- создание виртуальных окружений (`uv venv`). команда создаёт изолированное виртуальное окружение проекта, по роли близкое к `python -m venv`. изолированность здесь означает собственный каталог `site-packages`: пакеты среды видны процессам её интерпретатора и не попадают в системную установку. время создания меньше за счёт кэша интерпретатора и жестких ссылок, потому что дерево стандартной библиотеки не копируется целиком при каждом новом окружении.
- установка пакетов (`uv install`). пакет берётся из pypi или из локального источника, с малым временем установки. поддерживается установка по файлу `requirements.txt`.
- обновление пакетов (`uv update`). установленные пакеты переводятся на последние версии, которые ещё удовлетворяют заданным ограничениям совместимости.
- удаление пакетов (`uv uninstall`). пакеты удаляются из виртуального окружения.
- синхронизация зависимостей (`uv sync`). команда читает `requirements.in`, а в дальнейшем также `pyproject.toml`, и приводит виртуальное окружение к объявленному набору. недостающие пакеты устанавливаются, лишние удаляются. сборка тогда воспроизводима: состав среды следует из файла зависимостей и совпадает при повторном развёртывании.
- компиляция зависимостей (`uv compile`). порождается файл `requirements.txt` или аналог `requirements.lock`. в нём зафиксированы конкретные версии всех зависимостей, прямых и транзитивных. сборка по такому файлу детерминирована: повторное развёртывание получает те же версии. по назначению это аналог `pip-compile` из `pip-tools`.
- аудит зависимостей (`uv pip check`). проверяется целостность установленных пакетов и выявляются конфликты. объявленные требования и фактически установленные версии сверяются между собой. конфликт сообщается как ошибка проверки, до того как выполнение дойдёт до импорта.

в перечне команд ниже тот же `uv sync` описан через файл `uv.lock`. оба описания относятся к одной схеме. ограничения объявляются во входном файле, разрешение записывает конкретный граф версий в файл блокировки, синхронизация разворачивает этот граф в окружении. при неизменном индексе один и тот же набор ограничений дает один и тот же граф. файл блокировки сохраняет граф и после появления на индексе более новых версий, поэтому следующая синхронизация повторяет прежнюю установку.

### установка uv

установка uv простая. программа поставляется своим исполняемым файлом, отдельно от интерпретатора python. её получают установщиком с официального сайта либо через пакетный менеджер. ниже разобраны оба пути.

на linux и macos установщик загружается утилитой curl. текст сценария сразу передаётся оболочке и выполняется:

```bash


curl -LsSf https://astral.sh/uv/install.sh | sh
```

если curl не установлена, тот же установщик забирается утилитой wget:

```bash


wget -qO- https://astral.sh/uv/install.sh | sh
```

на windows ту же роль выполняет powershell. сценарий установщика скачивается и выполняется в текущем сеансе:

```bash


powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

вместо установщика используют пакетные менеджеры. установка менеджером `pip` кладёт uv в окружение того интерпретатора, которым запущен `pip`:

```bash
pip install uv
```

установка менеджером `pipx` помещает программу в отдельное окружение и добавляет исполняемый файл в `PATH`. команда `uv` тогда доступна без активации этого окружения:

```bash
pipx install uv
```

установка менеджером homebrew:

```bash
brew install uv
```

после любого из этих способов в `PATH` появляется команда `uv`. способ поставки определяет, откуда взят исполняемый файл. интерпретатор проекта и состав пакетов задаются уже последующими командами uv.

### основные команды uv

основные команды uv:

- `uv init` создаёт и инициализирует проект python с базовой структурой каталога и файлов.
- `uv venv` создаёт в текущем проекте новую виртуальную среду.
- `uv add` добавляет к зависимостям проекта пакет с именем package-name.
- `uv pip install -r requirements.txt` устанавливает все зависимости, перечисленные в файле `requirements.txt`. подкоманды группы `uv pip` совпадают с интерфейсом pip и выполняются реализацией uv.
- `uv remove` удаляет пакет из зависимостей проекта.
- `uv run script.py` запускает скрипт python или другую команду внутри проекта, в его окружении.
- `uv sync` устанавливает все зависимости из файла `uv.lock` и приводит окружение к уже разрешенному графу.

дальше тот же набор показан на коротком проекте.

### 1. создание проекта

новый проект python создаётся командой `uv init`. аргументом передаётся имя проекта. для проекта с именем hello консоль переходит в каталог, где проект должен располагаться, и выполняется команда:

```bash
uv init hello
```

в результате создаётся каталог hello следующей структуры:

- git: каталог для работы с git.
- main.py: сгенерированный файл приложения с кодом по умолчанию.
- pyproject.toml: файл конфигурации проекта. в нём задаются имя, версия, описание, требование к версии python и список зависимостей.
- README.md: описание проекта.
- .python-version содержит номер применяемой версии python. последующие команды uv в этом каталоге выбирают интерпретатор по этой записи.

это базовая структура проекта. зависимости, виртуальная среда и код наращиваются уже от неё.

### 2. создание виртуальной среды

для работы с пакетами нужна виртуальная среда. у неё собственный каталог `site-packages`, и версии библиотек проекта не записываются в системный интерпретатор. uv сам инициализирует виртуальную среду в проекте при первом запуске скриптов или при установке пакетов. ту же среду создают и явно, командой `uv venv`. аргументом передаётся имя среды. если имя не указано, по умолчанию используется `.venv`.

консоль переходит в каталог проекта, затем вводится команда `uv venv`:

```bash


eugene@Eugene:/workspace/python/hello$ uv venv

Using CPython 3.12.3 interpreter at: /usr/bin/python3.12

Creating virtual environment at: .venv

Activate with: source .venv/bin/activate

eugene@Eugene:/workspace/python/hello$
```

после выполнения в проекте создаётся каталог виртуальной среды `.venv` и служебный файл окружения. в выводе uv указан выбранный интерпретатор, в примере это cpython 3.12.3 по пути `/usr/bin/python3.12`, каталог создаваемой среды и команда активации.

для активации среды применяется одна из следующих команд. активация дописывает каталог исполняемых файлов среды в начало `PATH`, так что имена `python` и скрипты установленных пакетов разрешаются внутрь `.venv`.

- для macos и linux: `source .venv/bin/activate`. `source` выполняет скрипт в текущей оболочке, поэтому изменение `PATH` сохраняется в этом сеансе. процесс-потомок так изменить `PATH` родителя не может.
- для windows: `.venv\Scripts\activate`

### 3. установка пакетов

для установки пакетов применяется команда `uv add`. пример строится на пакете matplotlib, которым рисуют графики. для его установки выполняется команда `uv add matplotlib`:

```bash


eugene@Eugene:/workspace/python/hello$ uv add matplotlib

eugene@Eugene:/workspace/python/hello$
```

порядок в листинге существенен: сначала uv разрешает граф (строка resolved, здесь 12 пакетов), затем устанавливает дистрибутивы. при добавлении пакетов uv обновляет файл `pyproject.toml`. в нём появляется запись о добавленной зависимости:

```javascript


[project]

name = "hello"

version = "0.1.0"

description = "Add your description here"

readme = "README.md"

requires-python = ">=3.12"



dependencies = [

    "matplotlib>=3.10.5",

]
```

в секции dependencies ограничение записано как нижняя граница версии: допускается matplotlib 3.10.5 и новее, насколько это совместимо с остальным графом. такая строка является требованием проекта. конкретные версии всего дерева uv определяет отдельно и записывает их в файл `uv.lock`. в листинге установки эти версии уже закреплены: matplotlib и транзитивные пакеты contourpy, cycler, fonttools, kiwisolver, numpy, packaging, pillow, pyparsing, python-dateutil, six. файл блокировки хранит полное дерево, включая транзитивные пакеты сверх прямой зависимости, названной в команде.

если пакет в среде отсутствует, но используется запускаемым скриптом, uv установит его при запуске скрипта, когда зависимость указана в toml-файле проекта. объявления в файле тогда достаточно для установки в момент запуска.

### 4. запуск скриптов

для запуска скриптов python применяется команда `uv run`, которой передаётся имя файла скрипта. при создании проекта uv создаёт файл `main.py` с некоторым содержимым по умолчанию. скрипт выглядит так:

```python


def main():

    print("Hello from hello!")





if __name__ == "__main__":

    main()
```

здесь определена функция main, которая выводит сообщение на консоль. запуск этого скрипта:

```bash


eugene@Eugene:/workspace/python/hello$ uv run main.py

Hello from hello!

eugene@Eugene:/workspace/python/hello$
```

скрипт отрабатывает и печатает ожидаемую строку. выше в проект добавлена библиотека matplotlib. чтобы использовать её, файл `main.py` заменяется следующим текстом:

```python


import matplotlib.pyplot as plt     # импортируем функциональность модуля pyplot из пакета matplotlib



def main():

    months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]

    rates = [13.58,  15.33, 14.26, 13.92, 12.74, 12.2, 13.44, 15.63, 15.74, 17.08, 17.18, 16.66]

    

    # метка по оси X

    plt.xlabel("month")

    # метка по оси Y

    plt.ylabel("rate")

    

    plt.plot(months, rates)

    plt.show()





if __name__ == "__main__":

    main()
```

код приведен для демонстрации, поэтому разбор короткий. список months хранит сокращенные названия месяцев, список rates хранит показатели популярности.

с помощью `xlabel()` устанавливается подпись оси x, с помощью `ylabel()` устанавливается подпись оси y. в `plot()` передаются два списка: для оси x список months, для оси y список rates. `plot()` принимает набор значений, которые надо вывести на графике. с помощью `show()` график отображается в окне просмотра по умолчанию.

после изменения файла скрипт снова запускается:

```bash
uv run main.py
```
