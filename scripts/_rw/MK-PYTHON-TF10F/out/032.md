при программировании на python различают два типа ошибок. первый тип составляют **синтаксические ошибки** (syntax error). они возникают из-за нарушения синтаксиса языка в исходном коде и фиксируются ещё при разборе текста модуля, до начала выполнения. среда разработки, например pycharm, может отслеживать такие ошибки и выделять их в редакторе.

второй тип составляют **ошибки выполнения** (runtime error). они возникают уже в процессе выполнения программы. такие ошибки называют исключениями. в предыдущих темах разбиралось преобразование строки в число:

```python
string = "5"
number = int(string)
print(number)
```

скрипт выполняется успешно: строка `"5"` конвертируется в число. другой текст конвертацию не проходит:

```python
string = "hello"
number = int(string)
print(number)
```

при выполнении этого скрипта выбрасывается исключение `ValueError`, потому что строку `"hello"` нельзя преобразовать в число:

```python
ValueError: invalid literal for int() with base 10: 'hello'
```

в этом фрагменте видно, что строка не представляет число. на практике строка часто приходит от пользователя и может не совпасть с ожидаемым форматом:

```python
string = input("Введите число: ")
number = int(string)
print(number)
```

при возникновении исключения нормальный ход программы прерывается: интерпретатор ищет обработчик по стеку вызовов и, не найдя его, печатает трассу и завершает программу. для перехвата исключения служит конструкция `try`/`except`.

### try..except

формальное определение конструкции `try`/`except`:

```python
try:
	инструкции
except [Тип_исключения]:
	инструкции
```

основной код, в котором потенциально возникает исключение, помещают после слова `try`. если в этом коде генерируется исключение, выполнение блока `try` прерывается в точке выброса, и управление переходит в блок `except`. инструкции `try`, стоящие ниже точки выброса, не выполняются.

после слова `except` можно указать, какое исключение обрабатывается, например `ValueError` или `KeyError`. указание типа необязательно. на следующей строке после `except` идут инструкции блока, выполняемые при возникновении исключения.

обработка исключения на примере преобразования строки в число:

```python
try:
    number = int(input("Введите число: "))
    print("Введенное число:", number)
except:
    print("Преобразование прошло неудачно")
print("Завершение программы")
```

ввод строки:

```bash
Введите число: hello
Преобразование прошло неудачно
Завершение программы
```

при вводе строки `"hello"` вывод числа на консоль не происходит: `int` выбрасывает `ValueError`, и выполнение переходит к блоку `except`. сообщение о завершении программы печатается уже после конструкции, потому что исключение перехвачено и дальше не распространяется.

ввод корректного числа:

```bash
Введите число: 22
Введенное число: 22
Завершение программы
```

исключение не возникает, блок `except` не выполняется, оба вызова `print` внутри `try` проходят, затем печатается сообщение о завершении.

голый `except` без типа перехватывает `BaseException`, то есть почти любое исключение, включая `KeyboardInterrupt` и `SystemExit`. для ошибок самой программы обычная граница перехвата есть класс `Exception`: системный выход и прерывание с клавиатуры остаются снаружи. синтаксическая ошибка в том же модуле этой конструкцией не ловится: она поднимается на этапе компиляции модуля, и выполнение `try` не начинается. `SyntaxError`, возникший внутри `eval`, `exec` или `import`, перехватывается, потому что к этому моменту внешний модуль уже выполняется.

### блок finally

при обработке исключений можно использовать необязательный блок `finally`. он выполняется независимо от того, было ли сгенерировано исключение: и после нормального завершения `try`, и после входа в `except`, и когда исключение уходит дальше по стеку.

```python
try:
    number = int(input("Введите число: "))
    print("Введенное число:", number)
except:
    print("Преобразование прошло неудачно")
finally:
    print("Блок try завершил выполнение")
print("Завершение программы")
```

блок `finally` обычно применяют для освобождения ресурсов, например для закрытия файлов. освобождение должно произойти и при успехе, и при ошибке, поэтому его ставят в `finally`, а не в одну из ветвей.

блок `finally` исключение не обрабатывает. если использовать его без `except`, при ошибке приложение завершается аварийно. деление на ноль даёт `ZeroDivisionError`:

```python
try:
    number = 3/0    # генерирует исключение ZeroDivisionError
    print(number)
finally:
    print("Блок try завершил выполнение")
print("Завершение программы")
```

сначала выполняется тело `finally` и печатается сообщение о завершении блока `try`. затем исключение распространяется дальше, строка `print("Завершение программы")` не достигается, и программа завершается с трассой `ZeroDivisionError`.
