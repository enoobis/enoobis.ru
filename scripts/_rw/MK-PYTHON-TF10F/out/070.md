бинарные файлы, в отличие от текстовых, хранят информацию как набор байтов и не проходят декодирование в символы. при открытии бинарного файла на чтение или на запись к режиму добавляют флаг `"b"`: вместе с записью (`"w"`) это режим `"wb"`, вместе с чтением (`"r"`) это режим `"rb"`. в текстовом режиме байты перевода строки могут подменяться по правилам платформы, поэтому для копии изображения, архива или другого формата с жёсткой раскладкой байтов нужен именно двоичный режим.

при чтении файл приходит как набор байтов. в `write()` на запись тоже передаётся набор байтов, а не строка `str`. копирование файла:

```python
FILENAME = "forest.png"             # файл для чтения
NEWFILENAME = "forest_new.png"      # файл для записи

image_data = []     # список для хранения считанных данных
 
# считываем файл в список image_data
with open(FILENAME, "rb") as file:
    image_data = file.read()
    
# запись выше считанных байт в новый файл
with open(NEWFILENAME, "wb") as file:
    file.write(image_data)
    
print(f"Файл {FILENAME} скопирован в {NEWFILENAME}")
```

скрипт считывает файл, путь к которому хранится в переменной `FILENAME`. в этом примере это изображение `forest.png`. считанные байты помещаются в `image_data`. переменная сначала ссылается на пустой список, а после `read()` на объект `bytes`: присваивание заменяет список байтовой строкой. затем этот буфер записывается в файл с именем `NEWFILENAME`. содержимое одного файла оказывается во втором без перекодирования.

### модуль pickle

для бинарных файлов python предоставляет встроенный модуль `pickle`, который сводит сериализацию объекта к записи и чтению потока байтов. у модуля две основные операции:

- `dump(obj, file)` : записывает объект obj в бинарный файл file

- `load(file)` : считывает данные из бинарного файла в объект

поток `pickle` рассчитан на чтение тем же языком. если аргумент протокола не задан, `dump` использует `pickle.DEFAULT_PROTOCOL`. `load()` исполняет содержимое потока при восстановлении объекта, поэтому данные из недоверенного источника этим модулем не загружают: подделанный поток может запустить произвольный код.

сохранение значений двух переменных:

```python
import pickle

FILENAME = "user.dat"

name = "Tom"
age = 19

with open(FILENAME, "wb") as file:
    pickle.dump(name, file)
    pickle.dump(age, file)

with open(FILENAME, "rb") as file:
    name = pickle.load(file)
    age = pickle.load(file)
    print("Имя:", name, "\tВозраст:", age)
```

функция `dump` последовательно записывает два объекта в один поток. при чтении файла те же объекты последовательно снимаются функцией `load`: каждый вызов возвращает ровно один следующий объект. консольный вывод программы:

```bash
Имя: Tom 		Возраст: 28
```

в листинге переменная `age` получает значение 19, а приведённая строка вывода содержит 28. на порядок вызовов это не влияет: `load` возвращает то значение, которое ранее было передано в `dump`.

тем же способом в файл сохраняют и извлекают из него набор объектов:

```python
import pickle

FILENAME = "users.dat"

users = [
    ["Tom", 28, True],
    ["Alice", 23, False],
    ["Bob", 34, False]
]

with open(FILENAME, "wb") as file:
    pickle.dump(users, file)


with open(FILENAME, "rb") as file:
    users_from_file = pickle.load(file)
    for user in users_from_file:
        print("Имя:", user[0], "\tВозраст:", user[1], "\tЖенат/замужем:", user[2])
```

объект, записанный функцией `dump`, функция `load` возвращает в том же виде. список пользователей после чтения снова является списком списков, и поля доступны по индексу. консольный вывод:

```bash
Имя: Tom 		Возраст: 28 	Женат/замужем: True
Имя: Alice 		Возраст: 23 	Женат/замужем: False
Имя: Bob 		Возраст: 34 	Женат/замужем: False
```
