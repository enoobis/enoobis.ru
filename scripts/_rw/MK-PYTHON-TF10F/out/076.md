### форматирование дат и времени

для форматирования объектов `date` и `time` в обоих классах предусмотрен метод `strftime(format)`. метод принимает один параметр: строку формата, в которую преобразуется дата или время. класс `datetime` наследует `strftime` от `date`, поэтому тот же вызов определён и для полного момента. примеры ниже вызывают метод уже у объекта `datetime`. набор кодов совпадает с функцией `strftime` языка c. исключение составляет `%f`, микросекунды: в стандартной функции c такого спецификатора нет, его добавляет python.

для определения формата используется один из следующих кодов:

- `%a` : аббревиатура дня недели. например, `Wed` от слова `Wednesday` (по умолчанию используются английские наименования)

- `%A` : день недели полностью, например, `Wednesday`

- `%b` : аббревиатура названия месяца. например, `Oct` (сокращение от `October`)

- `%B` : название месяца полностью, например, `October`

- `%d` : день месяца, дополненный нулем, например, `01`

- `%m` : номер месяца, дополненный нулем, например, `05`

- `%y` : год в виде 2-х чисел

- `%Y` : год в виде 4-х чисел

- `%H` : час в 24-часовом формате, например, `13`

- `%I` : час в 12-часовом формате, например, `01`

- `%M` : минута

- `%S` : секунда

- `%f` : микросекунда

- `%p` : указатель `AM/PM`

- `%c` : дата и время, отформатированные под текущую локаль

- `%x` : дата, отформатированная под текущую локаль

- `%X` : время, форматированное под текущую локаль

коды `%a`, `%A`, `%b`, `%B`, `%p`, `%c`, `%x` и `%X` берут названия и порядок полей из локали. числовые коды читают поля самого объекта и от локали не зависят.

разные форматы одного и того же момента:

```python
from datetime import datetime
now = datetime.now()
print(now.strftime("%Y-%m-%d"))             # 2017-05-03
print(now.strftime("%d/%m/%Y"))             # 03/05/2017
print(now.strftime("%d/%m/%y"))             # 03/05/17
print(now.strftime("%d %B %Y (%A)"))        # 03 May 2017 (Wednesday)
print(now.strftime("%d/%m/%y %I:%M"))       # 03/05/17 01:36
```

комментарии к вызовам показывают, как одна отметка раскладывается по шаблонам: год-месяц-день, день/месяц/год с четырёхзначным и с двузначным годом, день с полным названием месяца и дня недели, а также дата вместе с часом и минутой в 12-часовом формате.

при выводе названий месяцев и дней недели по умолчанию используются английские наименования. интерпретатор стартует в локали `C`, и названия приходят из неё. чтобы использовать текущую локаль пользователя, её предварительно устанавливают модулем `locale`:

```python
from datetime import datetime
import locale
locale.setlocale(locale.LC_ALL, "")

now = datetime.now()
print(now.strftime("%d %B %Y (%A)"))        # 03 Май 2017 (среда)
```

вызов `locale.setlocale(locale.LC_ALL, "")` переключает все категории локали процесса на локаль пользователя. для названий в `strftime` нужна категория `LC_TIME`, и `LC_ALL` включает её вместе с остальными. пустая строка означает локаль по умолчанию данной системы. установка действует на весь процесс, а не на один объект даты. `setlocale` не является потокобезопасной: одновременный вызов из другого потока спецификацией не определён. комментарий в листинге показывает названия месяца и дня недели уже по русской локали.

### сложение и вычитание дат и времени

при работе с датами часто нужно прибавить к дате некоторый промежуток или, наоборот, вычесть период. для таких операций в модуле `datetime` определён класс `timedelta`. объект этого класса задаёт промежуток времени, длительность. сдвиг фиксирован в сутках, секундах и микросекундах: сутки здесь равны 86400 секундам. календарный месяц и переход на летнее время в значении `timedelta` не хранятся.

для определения промежутка времени используется конструктор `timedelta`:

```python
timedelta([days] [, seconds] [, microseconds] [, milliseconds] [, minutes] [, hours] [, weeks])
```

в конструктор последовательно передаются дни, секунды, микросекунды, миллисекунды, минуты, часы и недели. любой из аргументов можно опустить. внутри длительность нормализуется к трём целым полям `days`, `seconds` и `microseconds`. секунды лежат в диапазоне от 0 до 86399, микросекунды от 0 до 999999. часы, минуты, миллисекунды и недели отдельными полями не остаются: при создании они пересчитываются в эту тройку.

несколько периодов:

```python
from datetime import timedelta

three_hours = timedelta(hours=3)
print(three_hours)       # 3:00:00
three_hours_thirty_minutes = timedelta(hours=3, minutes=30)  # 3:30:00

two_days = timedelta(2)  # 2 days, 0:00:00

two_days_three_hours_thirty_minutes = timedelta(days=2, hours=3, minutes=30)  # 2 days, 3:30:00
```

`timedelta(hours=3)` имеет строковое представление `3:00:00`. три часа и тридцать минут дают `3:30:00`. позиционный вызов `timedelta(2)` передаёт дни, отсюда представление `2 days, 0:00:00`. два дня, три часа и тридцать минут дают `2 days, 3:30:00`. в листинге печатается только первое значение. остальные три записаны комментариями рядом с выражениями.

объекты `datetime` и `timedelta` складываются и вычитаются. сумма `datetime` и `timedelta` снова имеет тип `datetime`. разность двух значений `datetime` имеет тип `timedelta`. дата, которая будет через два дня:

```python
from datetime import timedelta, datetime

now = datetime.now()
print(now)                      # 2017-05-03 17:46:44.558754
two_days = timedelta(2)
in_two_days = now + two_days
print(in_two_days)              # 2017-05-05 17:46:44.558754
```

к результату `datetime.now()` прибавляются двое суток. время суток сохраняется целиком, включая микросекунды. комментарий фиксирует сдвиг календарной даты с `2017-05-03` на `2017-05-05` при том же времени `17:46:44.558754`.

момент на 10 часов 15 минут раньше текущего получается вычитанием этой длительности из текущего времени:

```python
from datetime import timedelta, datetime

now = datetime.now()
till_ten_hours_fifteen_minutes = now - timedelta(hours=10, minutes=15)
print(till_ten_hours_fifteen_minutes)
```

из `datetime.now()` вычитается `timedelta(hours=10, minutes=15)`. печатается стандартное строковое представление получившегося `datetime`.

### свойства timedelta

у класса `timedelta` есть свойства, через которые читается уже нормализованный промежуток:

- `days` : количество дней

- `seconds` : количество секунд

- `microseconds` : количество микросекунд

поле `seconds` хранит остаток внутри суток после выделения целых дней, от 0 до 86399. поле `microseconds` хранит остаток внутри секунды. общую длительность в секундах, куда входят и дни, и секунды, и микросекунды, возвращает метод `total_seconds()`. результат имеет тип `float`.

промежуток между двумя датами:

```python
from datetime import timedelta, datetime

now = datetime.now()
twenty_two_may = datetime(2017, 5, 22)
period = twenty_two_may - now
print("{} дней  {} секунд   {} микросекунд".format(period.days, period.seconds, period.microseconds))
# 18 дней  17537 секунд   72765 микросекунд

print("Всего: {} секунд".format(period.total_seconds()))
# Всего: 1572737.072765 секунд
```

вызов `datetime(2017, 5, 22)` создаёт полночь 22 мая 2017 года: час, минута и секунда в конструктор не переданы и равны нулю. разность этой даты и текущего момента имеет тип `timedelta`. комментарий показывает компоненты 18 дней, 17537 секунд и 72765 микросекунд, а `total_seconds()` даёт `1572737.072765`. числа согласованы между собой: 18 суток по 86400 секунд, плюс 17537 секунд, плюс 72765 микросекунд в долях секунды дают ту же сумму. если уменьшаемая дата раньше вычитаемой, знак несёт поле `days`, а `seconds` и `microseconds` остаются неотрицательными. так устроена нормализация класса.

### сравнение дат

даты, как строки и числа, сравниваются стандартными операторами сравнения:

```python
from datetime import datetime

now = datetime.now()
deadline = datetime(2017, 5, 22)
if now > deadline:
    print("Срок сдачи проекта прошел")
elif now.day == deadline.day and now.month == deadline.month and now.year == deadline.year:
    print("Срок сдачи проекта сегодня")
else:
    period = deadline - now
    print("Осталось {} дней".format(period.days))
```

операторы `<`, `<=`, `==`, `!=`, `>`, `>=` определены для двух наивных значений и отдельно для двух значений с часовым поясом. наивный `datetime` и значение с заполненным `tzinfo` в python 3 несравнимы, такое сравнение поднимает `TypeError`.

в листинге `deadline` равен полуночи 22 мая 2017 года. если текущий момент строго позже этой полуночи, печатается сообщение, что срок сдачи проекта прошёл. сравнение полей `day`, `month` и `year` стоит во второй ветке и выполняется только когда первое условие ложно. в сам день срока после полуночи первое условие уже истинно, поэтому сообщение о том, что срок сегодня, относится к моменту, который не позже полуночи и совпадает с ней по календарным полям. если момент раньше срока, разность `deadline - now` даёт оставшийся `timedelta`, и печатается поле `days`: целые сутки, без остатка часов и минут.
