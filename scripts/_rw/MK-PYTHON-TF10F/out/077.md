многопоточность: способность программы выполнять несколько задач одновременно в рамках одного процесса. у каждого потока свой стек и свой счётчик команд. адресное пространство процесса, глобальные объекты и состояние интерпретатора потоки разделяют. потоки нужны в операциях, где программа большую часть времени ждёт ответа от внешних ресурсов: скачивание файлов из интернета, чтение и запись файлов, отправка запросов к базам данных. пока один поток ждёт ответ, другой может продолжать работу. в python за работу с потоками отвечает встроенный модуль `threading`. основной класс для потока в этом модуле: `Thread`.

### главный поток

вне зависимости от того, создаются ли потоки в программе вручную, при запуске уже есть как минимум один поток: главный поток программы. этот поток возвращает встроенная функция `threading.main_thread()` в виде объекта `Thread`. в обычных условиях главным является поток, из которого был запущен интерпретатор python. `threading.current_thread()`, вызванный из него же, возвращает тот же объект. ниже этот объект читается и печатается:

```python


import threading



current_thread = threading.main_thread()

print("Main Thread:")

print(current_thread)
```

консоль выводит представление объекта, по форме близкое к следующему. число в нём при каждом запуске своё:

```bash


Main Thread:

<_MainThread(MainThread, started 124401057440256)>
```

этот вывод показывает текущее состояние потока. поля представления такие:

- `_MainThread` : имя класса в модуле `threading`. оно указывает, что это именно главный поток программы, тот, который создаётся автоматически при запуске python-скрипта. имя `"MainThread"` для этого потока стандартное. класс `_MainThread` является подклассом `Thread`. поток, созданный конструктором `Thread` без явного подкласса, имеет класс `Thread`.

- `started` : статус потока. поток уже запущен, ещё не отмечен как завершённый и в момент печати активен, то есть выполняется.

- `124401057440256` : идентификатор потока в этом запуске. в представление подставляется значение атрибута `ident`. число генерируется заново при каждом новом запуске программы. как оно соотносится с идентификатором ядра, разобрано у атрибутов `ident` и `native_id` ниже.

### свойства потоков

для объектов класса `Thread` доступен ряд атрибутов, по которым читают состояние и свойства потока:

- `name` : имя потока. фактически это строка, и используется она только для идентификации. в реальности нескольким потокам может быть присвоено одно и то же имя: уникальность имени язык не требует. на некоторых платформах имя потока устанавливается на уровне операционной системы при его запуске, чтобы имя было видно в диспетчерах задач.

- `ident` : идентификатор потока. если поток не был запущен, значение равно `None`. после запуска это ненулевое целое число. идентификаторы потоков могут быть повторно использованы при завершении одного потока и создании другого. идентификатор доступен даже после завершения работы потока. по спецификации модуля у числа нет отдельного системного смысла: это маркер потока внутри интерпретатора. им пользуются во внутренней логике программы на python, например в журнале или в качестве ключа словаря, чтобы разделять данные между потоками внутри одного приложения.

- `native_id` : нативный идентификатор потока. его назначает операционная система, ядро. значение является неотрицательным целым числом, либо `None`, если поток не был запущен. до завершения потока числом можно однозначно выделить этот поток в масштабах всей системы. после завершения значение может быть повторно использовано операционной системой. через `native_id` поток внутри python связывают с системными утилитами. если поток завис, по этому номеру его находят в системном мониторе процессов. в linux это tid в команде `top -H` или в команде `ps`. дальше поток завершают или профилируют уже на уровне ос.

- `daemon` : логическое значение. `True` означает, что поток является потоком-демоном, `False` означает обычный поток. процесс интерпретатора завершается, когда не осталось живых потоков с флагом `daemon`, равным `False`. потоки-демоны процесс не удерживают и при выходе обрываются вместе с ним. работу, которую нужно довести до конца, в том числе запись файлов и снятие блокировок, на поток-демон не оставляют.

использование свойств:

```python


import threading



current_thread = threading.main_thread()

print("Main Thread name: ", current_thread.name)

print("Main Thread id: ", current_thread.ident)

print("Main Thread native id:", current_thread.native_id)
```

пример консольного вывода:

```bash


Main Thread name:  MainThread

Main Thread id:  135968807522816

Main Thread native id: 35474
```

у потоков в python идентификатор хранят два атрибута, `ident` и `native_id`. основное различие между ними в том, кто присваивает этот идентификатор и где он используется:

- `ident` : внутренний id потока в самом python. `ident` берётся для внутренней логики программы на python. например, для логирования или в качестве ключа словаря, чтобы разделять данные между потоками внутри самого приложения. число может не совпадать с тем id, который показывает операционная система: это зависит от реализации python и от ос.

- `native_id` : реальный id потока в операционной системе. `native_id` нужен, когда поток внутри python надо связать с системными утилитами. например, если поток завис, с помощью `native_id` находят конкретно его в системном мониторе процессов. в linux это tid в команде `top -H` или `ps`, и по нему поток завершают или профилируют на уровне ос. это значение гарантированно совпадает с id, который видит ос, в том числе в диспетчере задач.

краткое сравнение этих атрибутов:

| характеристика | ident | native_id |
| --- | --- | --- |
| кто управляет | виртуальная машина python (интерпретатор) | операционная система (windows, linux, macos) |
| доступность | доступен всегда, во всех версиях python 3. | появился только в python 3.8. |
| уникальность | уникален только пока поток жив. после завершения потока python может использовать этот id повторно для новых потоков. | уникален на уровне всей ос в текущий момент времени (как pid для процессов). |
| связь с ос | может не совпадать с системным id потока (зависит от реализации python и ос). | гарантированно совпадает с id, который видит ос (например, в диспетчере задач). |

для получения идентификаторов текущего потока в модуле `threading` доступны методы `threading.get_ident()` и `threading.get_native_id()`. первая функция возвращает то же число, что атрибут `ident` у объекта `threading.current_thread()`, и объект `Thread` для этого вызова не нужен. `threading.get_native_id()` появился в python 3.8, вместе с атрибутом `native_id`, и возвращает идентификатор, назначенный ядром текущему потоку:

```python


import threading



ident = threading.get_ident()

native_id = threading.get_native_id()



print("Python ID: ", ident)

print("Native ID:", native_id)
```

### создание новых потоков

для создания новых потоков применяется конструктор класса `Thread`:

```python


class threading.Thread(group=None, target=None, name=None, args=(), kwargs={}, *, daemon=None, context=None)
```

основные параметры:

- `target` : действие, которое собственно и будет выполняться в потоке. по умолчанию равно `None`, что указывает на отсутствие вызова: с потоком не связано никакое действие. свой код тогда помещают в метод `run`, переопределённый в подклассе `Thread`.

- `name` : имя потока. по умолчанию создаётся уникальное имя вида `Thread-N`, где `N` небольшое десятичное число, или вида `Thread-N (target)`, где на место `target` подставляется `target.__name__`, если аргумент `target` указан.

в той же сигнатуре стоят `group`, `args`, `kwargs` и `daemon`. `args` и `kwargs` передают аргументы в `target`, они разобраны ниже. `group` зарезервирован для будущей группировки потоков и в текущей реализации остаётся `None`. если аргумент `daemon` не передан, новый поток наследует флаг демона у того потока, который его создаёт. у главного потока этот флаг равен `False`, поэтому поток, созданный из главного без явного `daemon`, процесс удерживает.

к примеру, поток задаётся так:

```python


import threading



my_thread = threading.Thread(target=print)

print(my_thread)
```

здесь в качестве `target`, то есть вызываемого действия, выступает встроенная функция `print()`. метод `start()` ещё не вызван, объект только создан. при выполнении программа выведет что-то наподобие следующего. статус `initial` в представлении как раз означает, что поток создан и ещё не запущен, а имя `Thread-1 (print)` собрано из порядкового номера и `print.__name__`:

```bash


<Thread(Thread-1 (print), initial)>
```

аналогично можно передать и другую, в том числе свою функцию:

```python


import threading



def my_task():

    print("Дочерний поток: Начал работу...")

    time.sleep(2)  # Имитация долгой работы

    print("Дочерний поток: Завершил работу!")



my_thread = threading.Thread(target=my_task)

print(my_thread)    # <Thread(Thread-1 (my_task), initial)>
```

печатается сам объект `Thread`, тело `my_task` при этом не вызывается. комментарий к `print` фиксирует ожидаемое представление: имя `Thread-1 (my_task)` и статус `initial`. внутри `my_task` стоит вызов `time.sleep`. в этом фрагменте модуль `time` не импортирован, и к моменту настоящего запуска функции импорт уже должен быть выполнен. создание и печать объекта до импорта проходят, потому что `target` ещё не вызван.

### запуск потока

для запуска потока применяется метод `start()`:

```python


import threading



# Функция, выполняемая в другом потоке

def my_task():

    print("Дочерний поток: Начал работу...")

    #time.sleep(2)  # Имитация долгой работы

    print("Дочерний поток: Завершил работу!")



print("Главный поток: Начал работу...")



# Создаем поток

my_thread = threading.Thread(target=my_task)



# Запускаем поток

my_thread.start()



print("Главый поток: Завершил работу!")
```

`start()` создаёт новый поток и в нём вызывает `run()`. реализация `run()` у класса `Thread` вызывает `target`, если он задан. главный поток программы запускает `my_thread` и сразу идёт дальше, не дожидаясь его окончания. результат программы недетерминирован: порядок строк зависит от того, какому потоку планировщик отдаст процессор. например, вывод может быть таким:

```bash


Главный поток: Начал работу...

Дочерний поток: Начал работу...

Дочерний поток: Завершил работу!

Главый поток: Завершил работу!
```

а может быть и таким:

```bash


Главный поток: Начал работу...

Дочерний поток: Начал работу...

Главый поток: Завершил работу!

Дочерний поток: Завершил работу!
```

во втором случае второе сообщение от главного потока может появиться раньше, чем дочерний поток завершит свою работу. чтобы устойчиво увидеть именно этот порядок, при выполнении второго потока ставят задержку по времени:

```python


import threading

import time



# Функция, выполняемая в другом потоке

def my_task():

    print("Дочерний поток: Начал работу...")

    time.sleep(2)  # Имитация долгой работы

    print("Дочерний поток: Завершил работу!")



print("Главный поток: Начал работу...")



# Создаем поток

my_thread = threading.Thread(target=my_task)



# Запускаем поток

my_thread.start()



print("Главый поток: Завершил работу!")
```

здесь в функции `my_task` с помощью `time.sleep(2)` устанавливается задержка на 2 секунды. вызов блокирует только дочерний поток. главный поток после `start()` к этой паузе не привязан и доходит до своего последнего `print`, пока `my_task` ещё стоит в `sleep`. это и даёт наблюдаемый порядок: главный поток завершает свой вывод раньше, чем `my_thread`.

у потока `Thread` также есть метод `run()`, который тоже запускает действие. прямой вызов `run()` выполняет `target` как обычную функцию в том потоке, из которого метод вызвали. в листинге ниже это главный поток программы. `start()` переносит вызов того же `run()` в новый поток.

```python


# Создаем поток

my_thread = threading.Thread(target=my_task)



# новый поток НЕ запускается, my_task выполняется как обычная функция

my_thread.run()
```

запустить один и тот же объект повторно нельзя. второй вызов `start()` возбуждает `RuntimeError`: жизненный цикл потока однократный, от создания через `initial` к `started` и затем к завершению.

### передача аргументов в функцию потока

если выполняемой в новом потоке функции требуются аргументы, для их передачи используются параметр `args` и параметр `kwargs`. `args` задаёт список или кортеж позиционных аргументов для вызова `target`. `kwargs` задаёт словарь именованных аргументов для вызова `target`. сохранённые значения попадают в вызов уже внутри `run()`, в форме `target(*args, **kwargs)`. например:

```python


import threading



my_thread = threading.Thread(target=print, args=("Hello enoobis.ru",))



my_thread.start()
```

здесь в новом потоке запускается встроенная функция `print()`, которой передаётся один аргумент, строка `"Hello enoobis.ru"`. аргументу `args` передаётся кортеж, поэтому после строки указывается запятая: `args=("Hello enoobis.ru",)`. скобки без запятой оставляют значение строкой. кортеж из одного элемента записывается с запятой. если в `args` передать саму строку, она читается как последовательность символов, и `target` получит каждый символ отдельным аргументом.

или другой пример:

```python


import threading

import time



def greet_user(name, delay):

    time.sleep(delay)

    print(f"Привет, {name}!")



# создаем два потока

thread1 = threading.Thread(target=greet_user, args=("Алексей", 1))

thread2 = threading.Thread(target=greet_user, args=("Мария", 2))



thread1.start()

thread2.start()
```

здесь создаётся и запускается два потока, каждому из которых передаётся свой набор данных, два аргумента. `greet_user` сначала ждёт указанное число секунд, затем печатает приветствие. задержка первого потока равна 1, задержка второго равна 2, поэтому в консоли сначала появляется приветствие для `"Алексей"`, затем для `"Мария"`:

```bash


Привет, Алексей!

Привет, Мария!
```

`kwargs` в этих листингах не передаётся. словарь устроен так же, как именованные аргументы обычного вызова: ключ совпадает с именем параметра `target`, значение приходит в этот параметр. позиционных значений из `args` для обоих примеров достаточно.

### ожидание завершения. метод join()

часто главному потоку требуется дождаться результатов работы остальных потоков перед тем, как завершить программу или сложить полученные данные. для этого используется метод `join()`, который есть у класса `Thread`. например:

```python


import threading

import time



def work():

    time.sleep(2)   # задержка в 2 секунды

    print("Work Thread завершил работу")

    

my_tread = threading.Thread(target=work)

my_tread.start()



# Говорим главному потоку подождать завершения остальных потоков

my_tread.join() 



print("Main Thread завершил работу")
```

благодаря строке `my_tread.join()` главный поток на этой строке останавливается и ждёт завершения потока `my_tread`. оператор `print` после `join` выполняется только тогда, когда `work` уже напечатала `Work Thread завершил работу`. соответственно, если эту строку убрать, у главного потока не останется точки ожидания, и он завершит своё выполнение ранее `my_tread`.

без аргумента `join` ждёт, пока поток не завершится. аргумент `timeout` ограничивает ожидание секундами: по истечении срока метод возвращает управление и при ещё живом потоке. после такого возврата состояние потока читают через `is_alive()`. значение, которое вернула функция потока, через `join` не передаётся. метод служит барьером по завершению, результат `target` интерпретатор отбрасывает. вызов `join` до `start` возбуждает `RuntimeError`. то же исключение возникает, когда поток ждёт сам себя: такое ожидание замкнуло бы его навсегда.

### создание группы потоков

в реальных приложениях задачи масштабируют с помощью списков. ниже создаются 3 потока, которые выполняют работу одновременно:

```python


import threading

import time



# условная функция загрузки файла

def download_file(file_id):

    print(f"Скачивание файла {file_id}...")

    time.sleep(2)

    print(f"Файл {file_id} успешно скачан!")



# список потоков

threads = []



# Создаем и запускаем 3 потока

for i in range(1, 4):

    t = threading.Thread(target=download_file, args=(i,))

    threads.append(t)

    t.start()



# дожидаемся завершения КАЖДОГО потока

for t in threads: t.join()



print("Все файлы скачаны!")
```

здесь функция `download_file()` имитирует загрузку файла, принимая в качестве параметра условный идентификатор файла. в цикле запускаются три потока, каждый добавляется в список `threads` для последующего управления. второй цикл вызывает `join` у каждого элемента и тем самым дожидается завершения каждого потока. в итоге все три условных файла начинают скачиваться одновременно. `time.sleep(2)` отпускает gil на время паузы, поэтому три ожидания перекрываются. вместо последовательного ожидания в 6 секунд, то есть 3 файла по 2 секунды, программа выполняется примерно за 2 секунды. после последнего `join` печатается строка о том, что все файлы скачаны.

### ограничение gil (global interpreter lock)

в стандартном python, в реализации cpython, существует глобальная блокировка gil (global interpreter lock). это мьютекс интерпретатора: он закрывает внутренние структуры виртуальной машины на время исполнения байт-кода. gil не позволяет нескольким потокам одновременно выполнять чистый python-код на разных ядрах процессора. в каждый конкретный момент времени только один поток может выполнять байт-код python.

поток отпускает gil на время многих ожиданий. к ним относятся блокирующий ввод-вывод, `time.sleep` и те вызовы расширений на c, которые явно снимают блокировку. поэтому три загрузки из предыдущего примера пережидают свои две секунды внахлёст, хотя байт-код вокруг `sleep` по-прежнему исполняется по очереди. задача, которая почти целиком состоит из байт-кода python, дополнительные ядра за счёт потоков не занимает: в каждый момент байт-код исполняет один поток. как часто текущий поток уступает gil другому, задаёт `sys.setswitchinterval`. значение по умолчанию равно 0.005 секунды, пять миллисекунд, и передача блокировки возможна на границе очередной инструкции байт-кода.

сборка cpython по умолчанию эту блокировку сохраняет. отдельная сборка без gil описана в pep 703 и сборкой по умолчанию не является. примеры этого раздела рассчитаны на обычную сборку. ожидание в них перекрывается между потоками. чистый счёт на байт-коде занимает в каждый момент один поток.
