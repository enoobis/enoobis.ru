**генератор** в python является функцией, исполнение которой можно возобновлять, чтобы получать следующие значения. элементы отдаются по одному. коллекция заранее не строится, поэтому оперативная память не держит всю последовательность. обычная функция возвращает значение оператором `return` и на этом завершается: кадр вызова уничтожается. генератор использует оператор `yield`. в этой точке исполнение приостанавливается, значение передаётся вызывающему, а локальные переменные и позиция в коде сохраняются в объекте генератора. следующий запрос продолжает функцию с инструкции сразу после `yield`.

генераторы используют там, где последовательность велика или потенциально не ограничена: файл, выборка из базы, сетевой поток. при `yield` вместо готового значения функция возвращает объект генератора. этот объект реализует протокол итератора: у него есть `__iter__` и `__next__`. исчерпание последовательности сообщается исключением `StopIteration`, которое цикл `for` перехватывает и превращает в обычный конец перебора.

разницу двух подходов показывают функции, отдающие числа 1, 2 и 3. обычная функция:

```python


def usual_function():

    return [1, 2, 3]
```

функция-генератор с теми же тремя значениями:

```python


def generator_function():

    yield 1

    yield 2

    yield 3
```

обычная функция строит в памяти список `[1, 2, 3]` целиком и возвращает его. при миллиарде элементов список займёт соответствующий объём ram, вплоть до отказа по памяти. генератор список не создаёт. он возвращает объект генератора. каждый запрос следующего числа исполняет тело до очередного `yield`, отдаёт значение и снова приостанавливает функцию.

значения из генератора забирает встроенная функция `next()`. она вызывает `__next__` итератора:

```python


# определение функции генератора

def generator_function():

    yield 1

    yield 2

    yield 3



# определяем объект генератора

gen = generator_function()



# получаем данные из генератора

print(next(gen))  # 1

print(next(gen))  # 2

print(next(gen))  # 3
```

генератор производит три числа, и три вызова `next` их получают. четвёртый вызов `next(gen)` завершается исключением `StopIteration`: протокол итератора так сообщает, что элементы закончились. отдельного признака «пусто» у генератора нет.

в прикладном коде `next()` вызывают редко. обычно генератор перебирают циклом `for`, который сам останавливается на `StopIteration`:

```python


# определение функции генератора

def generator_function():

    yield 1

    yield 2

    yield 3



# определяем объект генератора

gen = generator_function()



# получаем данные из генератора

for number in generator_function():

    print(number)
```

генератор уместен, когда длина последовательности заранее неизвестна или элементов слишком много, чтобы хранить их разом. ниже генератор отдаёт строчные латинские буквы по кодам ascii:

```python


# определение функции генератора

def letters():

    i = 97  # символ 'a' в ASCII

    end = 97 + 26   # код последнего алфавитного символа ACII - 'z'

    while i < end:

        yield chr(i)    # отдаем очередной символ

        i += 1



# получаем данные из генератора

for letter in letters():

    print(letter)
```

счётчик `i` начинается с `97`, кода символа `'a'`. граница `end = 97 + 26` стоит сразу за кодом `'z'`: код `'z'` равен 122, а 97 + 26 = 123. условие `i < end` поэтому отдаёт 26 символов от `'a'` до `'z'`. `chr(i)` переводит код в символ, `yield` отдаёт его вызывающему, затем `i` увеличивается на единицу. комментарий в исходнике называет `end` кодом последней буквы. фактически граница на единицу больше кода `'z'`, и буква `'z'` всё равно попадает в последовательность за счёт строгого неравенства.

### выражения генераторов

простой генератор не обязан быть отдельной функцией с `yield`. в языке есть выражения генераторов (generator expressions). синтаксически они совпадают с включениями списков (list comprehensions), только квадратные скобки заменены круглыми. включение списка ниже сразу строит в памяти список квадратов:

```python
squares_list = [x**2 for x in range(1000000)]
```

выражение генератора для того же диапазона вычисляет квадрат в момент запроса:

```python


squares_gen = (x**2 for x in range(1000000))



print(next(squares_gen))  # 0

print(next(squares_gen))  # 1

print(next(squares_gen))  # 4

print(next(squares_gen))  # 9
```

плюсы генераторов

- экономия памяти. элементы не хранятся в ram, а создаются по запросу.
- быстрый старт. первый элемент отдаётся сразу, без ожидания построения остальных.
- работа с потоком данных. тот же приём читает большой файл или журнал построчно.

минусы генераторов:

- одноразовость. пройти генератор циклом можно один раз. объект запоминает, что уже отдал значения, и повторный проход требует нового генератора.
- длина неизвестна. `len()` к генератору неприменима: чтобы узнать число элементов, их пришлось бы все произвести, а протокол итератора этого не обещает.
- нет доступа по индексу. запись вида `gen[5]` для генератора не определена. чтобы получить пятый элемент, нужно запросить предыдущие через протокол итератора.

генераторы применяют к большим объёмам данных, например к построчному чтению тяжёлого файла, и в тех случаях, когда вся коллекция не обязана одновременно находиться в памяти. если к элементам возвращаются многократно, их сортируют или ищут по индексу, хранят список: у списка есть длина, индексация и повторный обход.

### пример генератора: чтение больших файлов

практический случай: чтение большого файла, например журнала сервера на несколько гигабайт. здесь генератор ограничивает расход памяти. `readlines()` читает файл целиком и строит список строк. файл в 10 гб при 8 гб оперативной памяти приводит к `MemoryError`: интерпретатору негде разместить список. генератор читает файл строка за строкой. в памяти находится текущая строка. весь файл туда не загружается.

пусть в `server_logs.txt` нужно оставить только строки с критической ошибкой `"[ERROR]"`. скрипт:

```python


def read_file(file_path):

    # Генератор, который читает файл построчно и не забивает память

    with open(file_path, "r", encoding="utf-8") as file:

        for line in file:

            # yield отдает строку и ставит функцию на паузу,

            # пока вызывающий код не попросит следующую строку

            yield line.strip()





file_path = "server_logs.txt"



# Применяем генератор

log_generator = read_file(file_path)



for log_line in log_generator:

    if "[ERROR]" in log_line:

        print(f"Найдена ошибка: {log_line}")
```

как устроено чтение:

- конструкция `with open(...)` открывает файл и гарантирует закрытие дескриптора при выходе из блока, в том числе при исключении.
- цикл `for line in file` идёт по файловому объекту, который сам является итератором. данные с диска читаются буфером, порциями. целиком файл в память не забирается.
- `yield line.strip()` возвращает строку без крайних пробельных символов в цикл `for log_line in log_generator`.
- после обработки строки ссылка на неё в генераторе не сохраняется. следующая итерация запрашивает следующую строку, а предыдущая может быть собрана сборщиком мусора.

чтобы проверить генератор, нужен файл заметного размера. его собирает отдельный скрипт:

```python


import random



def generate_file(file_path, total_lines=1_000_000):

    

    # Варианты логов для генерации

    log_templates = [

        "[INFO] User logged in successfully.",

        "[INFO] Page loaded in 24ms.",

        "[WARNING] Database connection slow.",

        "[INFO] API request completed.",

        "[ERROR] Failed to connect to database!",

        "[ERROR] User authentication timeout."

    ]

    

    print(f"Начинаю генерацию файла {file_path}...")

    

    # Открываем файл для записи ("w")

    with open(file_path, "w", encoding="utf-8") as file:

        for i in range(total_lines):

            # Случайно выбираем один шаблон

            log_entry = random.choice(log_templates)

            # Записываем строку, добавляя индекс и перенос строки \n

            file.write(f"Line {i+1}: {log_entry}\n")

            

    print(f"Готово! Файл {file_path} успешно создан.")



file_path = "server_logs.txt"



# Запуск генератора файлов

#generate_file(file_path, total_lines=1_000_000)
```

функция `generate_file` записывает ровно 1 000 000 строк, около 50-70 мб. чтобы текст был похож на журнал сервера, шаблоны чередуются: обычные сообщения `[INFO]` и `[WARNING]` и ошибки `[ERROR]`, которые предыдущий генератор ищет. выбор шаблона делает `random.choice` из модуля `random`. запись идёт построчно в цикле, без сборки миллиона строк в один список перед `write`. вызов `generate_file` в конце скрипта закомментирован, поэтому простой запуск файла функцию не выполняет, пока строку вызова не включат.

### конвейер из генераторов (pipeline)

генераторы связывают в цепочку. промежуточные последовательности тогда не занимают память: каждый этап тянет по одному элементу из предыдущего. тот же отбор ошибок записывается компактными выражениями генераторов:

```python


lines = (line for line in open(file_path, encoding="utf-8"))

errors = (line.strip() for line in lines if "[ERROR]" in line)

for error_line in errors: print(error_line)
```

- первый генератор только читает строки

```python
lines = (line for line in open(file_path, encoding="utf-8"))
```

- второй генератор фильтрует поток и оставляет строки с ошибками. данные он берёт из первого генератора

```python
errors = (line.strip() for line in lines if "[ERROR]" in line)
```

- запуск конвейера. данные начинают двигаться по цепочке только здесь

```python
for error_line in errors: print(error_line)
```

файл не начинает читаться, пока не запущен внешний цикл `for error_line in errors`. до этого выражения генераторов лишь описывают вычисление. схема вытягивающая: потребитель запрашивает следующий элемент, и запрос проходит по цепочке до файла. по каналу в каждый момент идёт одна строка, промежуточные списки не строятся.

### асинхронные генераторы

асинхронный генератор соединяет генератор и корутину. если функция объявлена с `async` и содержит `yield`, вызов возвращает объект асинхронного генератора. он реализует асинхронный протокол итератора: `__aiter__` и `__anext__`. завершение сообщает `StopAsyncIteration`, по аналогии с `StopIteration` у обычного генератора.

по использованию асинхронный генератор близок к обычному, с двумя отличиями протокола. следующее значение даёт `anext()`. вызов `next()` к асинхронному генератору не применяется. `anext()` является сопрограммой, поэтому его вызывают средствами асинхронного кода: через `await` внутри корутины либо опосредованно из `asyncio.run`, который запускает такую корутину. пример с тремя первыми значениями:

```python


import asyncio



# определение асинхронного генератора

async def generate():

    yield 1

    yield 4

    yield 9

    yield 16



async def consume():

    # определяем объект генератора

    gen = generate()



    # получаем данные из асинхронного генератора

    print(await anext(gen))  # 1

    print(await anext(gen))  # 4

    print(await anext(gen))  # 9



asyncio.run(consume())
```

обычный цикл `for` асинхронный генератор не принимает: `__next__` у того не блокирует цикл событий и не является ожидаемым объектом. для перебора есть асинхронный оператор `async for`. он ожидает `__anext__` и завершает цикл по `StopAsyncIteration`:

```python


import asyncio



# определение функции генератора

async def generate():

    yield 1

    yield 4

    yield 9

    yield 16



async def consume():

    # получаем данные из асинхронного генератора

    async for n in generate(): 

        print(n)



asyncio.run(consume())



# Консольный вывод

# 1

# 4

# 9

# 16
```
