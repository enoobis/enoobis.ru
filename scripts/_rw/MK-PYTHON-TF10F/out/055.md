отладка - штатная часть разработки: ошибка есть и у кода, который писал опытный автор, и локализовать её по одному только тексту бывает долго. в python для этого есть встроенный отладчик, модуль pdb (python debugger). он выполняет программу по шагам, показывает значения имён, ставит точки останова и удерживает поток выполнения в заданном месте.

### назначение отладчика

частый приём, в том числе у тех, кто уже пишет на других языках, - вызовы `print()` в разных точках программы. на коротком фрагменте этого хватает. в длинной программе приём быстро перестаёт работать:

- засорение кода: временные вызовы `print()` приходится вставлять и затем удалять, и часть из них остаётся в тексте.

- отсутствие интерактивности: на время вывода нельзя изменить переменную и нельзя выполнить произвольный фрагмент, пока программа стоит на паузе.

- узкий контекст: `print()` показывает значение в одной точке. отладчик в той же точке открывает всё состояние кадра: локальные имена, аргументы и стек вызовов.

pdb закрывает эти три ограничения: интерактивная консоль открывается прямо в месте остановки или падения. у ряда сред разработки и редакторов, среди них pycharm и vs code, отладчик встроен в графический интерфейс. под этим интерфейсом те же возможности pdb: точки останова, шаги и просмотр кадра. среда пользуется механизмом трассировки интерпретатора.

активировать отладчик можно несколькими способами.

### запуск из командной строки

скрипт запускается под управлением pdb прямо из терминала. так разбирают падение: состояние программы доступно в момент сбоя, без предварительной правки исходного текста.

```bash


python3 -m pdb test.py
```

pdb запускает `test.py` и останавливается на первой исполняемой строке, до того как она выполнится. пусть в `test.py` лежит короткий код:

```python


def sum(a, b):

    result = a + b

    return result



print(sum(5, 6))
```

после `python3 -m pdb test.py` приглашение `(Pdb)` означает, что ввод читает сессия отладчика. программа в этот момент стоит.

```bash


eugene@Eugene:/workspace/python/test$ python3 -m pdb test.py

> /workspace/python/test.py(1)<module>()

-> def sum(a, b):

(Pdb)
```

выход из отладчика - команда `q`:

```bash


eugene@Eugene:/workspace/python/test$ python3 -m pdb test.py

> /workspace/python/test.py(1)<module>()

-> def sum(a, b):

(Pdb) q 

eugene@Eugene:/workspace/python/test$
```

запуск через `python -m pdb` ставит трассировку до начала модуля. первая показанная строка - та, которую интерпретатор выполнил бы следующей. приглашение принимает команды отладчика. строка, которую pdb не признал командой, выполняется как оператор python в текущем кадре, поэтому в той же консоли можно читать и менять локальные имена.

### вставка точки останова (breakpoint) в коде

остановка задаётся прямо в исходном тексте, одной строкой. выполнение доходит до неё и отдаёт управление консоли pdb.

в python 3.7 и новее для этого есть встроенная функция `breakpoint()`. это основной способ:

```python


def sum(a, b):

    breakpoint() # <--- Программа остановится здесь

    result = a + b

    return result



print(sum(5, 6))
```

в более старых версиях, и в текущих тоже, модуль pdb импортируют явно и вызывают `pdb.set_trace()`:

```python


import pdb



def sum(a, b):

    pdb.set_trace() # <--- Программа остановится здесь

    result = a + b

    return result



print(sum(5, 6))
```

оба вызова останавливают интерпретатор на своей строке и открывают ту же консоль:

```bash


eugene@Eugene:/workspace/python/test$ python3 test.py

> /workspace/python/test/test.py(3)sum()

-> result = a + b

(Pdb) q
```

выйти из отладчика и из программы можно той же командой `q`.

`breakpoint()` не привязан навсегда к pdb. функция вызывает перехватчик `sys.breakpointhook`. по умолчанию тот вызывает `pdb.set_trace`, поэтому в примерах выше открывается pdb. переменная окружения `PYTHONBREAKPOINT` подменяет перехватчик: значение `0` отключает остановку, другое имя вызывает указанную функцию. `pdb.set_trace()` этого перехватчика не спрашивает и входит в pdb напрямую. для постоянного места остановки в тексте курса достаточно `breakpoint()`.

## основные команды pdb

скрипт уже можно запустить под отладчиком. управление сессией - команды pdb:

- `n` (`next`): выполняет текущую строку и переходит к следующей в той же функции. внутрь вызываемых функций не заходит.

- `s` (`step`): выполняет текущую строку и останавливается на первом возможном шаге. внутрь вызываемых функций заходит.

- `c` (`continue`): продолжает выполнение до следующей точки останова или до конца программы.

- `l` (`list`): показывает исходный код вокруг текущей строки.

- `p` (`print()`): вычисляет выражение и печатает значение. примеры: `p user_id` или `p url`.

- `pp`: вычисляет выражение и печатает значение с форматированием, pretty print. вложенные структуры раскладываются по строкам.

- `b` (`break`): ставит новую точку останова. примеры: `b 25` на строку 25 или `b my_function` на функцию `my_function`.

- `b` с именем файла и номером строки через двоеточие: точка останова в другом файле, не в том, где сейчас стоит кадр.

- `cl`: удаляет точку останова.

- `a` (`args`): показывает аргументы текущей функции.

- `w` (`where`): показывает стек вызовов, traceback, то есть цепочку кадров, по которой программа пришла в текущую точку.

- `q` (`quit`): завершает сессию отладки и программу.

в скобках даны полные формы команд. выход из отладчика и из программы целиком выполняется и короткой командой `q`, и полной `quit`. `next` остаётся в текущем кадре и проскакивает вызов как один шаг. `step` заходит в вызов и останавливается на первой строке вызванной функции. `continue` снимает пошаговый режим до ближайшей точки либо до завершения процесса. `where` печатает стек снизу вверх по той же схеме, что и необработанное исключение, только программа в этот момент ещё жива.

ниже тот же скрипт `test.py`:

```python


def sum(a, b):

    result = a + b

    return result



print(sum(5, 6))
```

запуск командой `python3 -m pdb test.py` снова даёт приглашение `(Pdb)`: сессия отладчика открыта.

```bash


eugene@Eugene:/workspace/python/test$ python3 -m pdb test.py

> /workspace/python/test.py(1)<module>()

-> def sum(a, b):

(Pdb)
```

по умолчанию показана первая строка скрипта, здесь это `def sum(a, b)`. пошаговый проход с заходом в функции начинает команда `s` (`step`):

```bash


eugene@Eugene:/workspace/python/test$ python3 -m pdb test.py

> /workspace/python/test.py(1)<module>()

-> def sum(a, b):

(Pdb) s

> /workspace/python/test/test.py(5)<module>()

-> print(sum(5, 6))

(Pdb)
```

отладчик перешёл к строке 5, `print(sum(5, 6))`. тело функции при этом не выполнялось: оператор `def` только создаёт функциональный объект и связывает его с именем в текущей области. следующий оператор модуля - вызов `print`. повтор команды `s`:

```bash


eugene@Eugene:/workspace/python/test$ python3 -m pdb test.py

> /workspace/python/test.py(1)<module>()

-> def sum(a, b):

(Pdb) s

> /workspace/python/test/test.py(5)<module>()

-> print(sum(5, 6))

(Pdb) s

--Call--

> /media/eugene/WD10EZEX/workspace/python/test/test.py(1)sum()

-> def sum(a, b):

(Pdb)
```

отладчик вошёл в выполнение функции `sum`. метка `--Call--` означает вход в новый кадр: показана строка `def`, с которой кадр начинается, тело ещё не исполнялось. дальше несколько раз команда `s`:

```bash


eugene@Eugene:/workspace/python/test$ python3 -m pdb test.py

> /workspace/python/test.py(1)<module>()

-> def sum(a, b):

(Pdb) s

> /workspace/python/test/test.py(5)<module>()

-> print(sum(5, 6))

(Pdb) s

--Call--

> /media/eugene/WD10EZEX/workspace/python/test/test.py(1)sum()

-> def sum(a, b):

(Pdb) s

> /media/eugene/WD10EZEX/workspace/python/test/test.py(2)sum()

-> result = a + b

(Pdb) s

> /media/eugene/WD10EZEX/workspace/python/test/test.py(3)sum()

-> return result
```

функция сложила аргументы и записала результат в переменную `result`. значение смотрят, введя имя в приглашении:

```bash


(Pdb) result

11

(Pdb)
```

результат равен 11: аргументы вызова были 5 и 6. голое имя в приглашении pdb выполняет как выражение python в текущем кадре, поэтому `result` печатает то же значение, что команда `p`. ещё пара шагов `s` доходит до конца программы, сессия закрывается командой `q`:

```bash


(Pdb) s

--Return--

> /workspace/python/test/test.py(3)sum()->11

-> return result

(Pdb) s

11

--Return--

> /workspace/python/test/test.py(5)<module>()->None

-> print(sum(5, 6))

(Pdb) q
```

первая метка `--Return--` - выход из `sum`: справа от кадра подписано возвращаемое значение 11, исполняемая строка всё ещё `return result`. следующий `s` даёт выполниться `print`, на стандартный вывод попадает 11, затем `--Return--` уже у модуля: `print` вернул `None`. `q` завершает и отладчик, и процесс.

### пример: поиск ошибки

функция считает сумму элементов списка:

```python


def total(numbers):

    s = 0

    for n in numbers:

        s = s + n

    return s



print(total([1, "2", 3, 4]))
```

сложение числа и строки здесь завершается ошибкой:

```bash


eugene@Eugene:/workspace/python/test$ python3 test.py

Traceback (most recent call last):

  File "/workspace/python/test/test.py", line 7, in <module>

    print(total([1, "2", 3, 4]))

          ^^^^^^^^^^^^^^^^^^^^^

  File "/workspace/python/test/test.py", line 4, in total

    s = s + n

        ~~^~~

TypeError: unsupported operand type(s) for +: 'int' and 'str'

eugene@Eugene:/workspace/python/test$
```

traceback идёт от строки модуля с `print(total(...))` внутрь `total`, к оператору `s = s + n`. тип исключения - `TypeError`: для `+` нет операции над парой `int` и `str`. динамическая типизация откладывает эту проверку до выполнения конкретной пары объектов. чтобы посмотреть переменные в момент сбоя, в цикл ставят `breakpoint()`:

```python


def total(numbers):

    s = 0

    for n in numbers:

        s = s + n

        breakpoint()

    return s



print(total([1, "2", 3, 4]))
```

командами `n` проходят тело функции, пока не возникнет ошибка, затем вводят `p n`:

```bash


eugene@Eugene:/workspace/python/test$ python3 test.py

> /workspace/python/test/test.py(3)total()

-> for n in numbers:

(Pdb) n

> /workspace/python/test/test.py(4)total()

-> s = s + n

(Pdb) n

TypeError: unsupported operand type(s) for +: 'int' and 'str'

> /workspace/python/test/test.py(4)total()

-> s = s + n

(Pdb) p n

'2'

(Pdb)
```

на второй итерации значение `n` равно `2`, но это строка, из неё и возникает ошибка. список передан как `[1, "2", 3, 4]`: первый элемент имеет тип `int`, второй записан литералом строки. после первой итерации `s` равно 1. следующий `n` пытается выполнить `1 + "2"`, интерпретатор поднимает `TypeError` и pdb остаётся на той же строке. команда `p n` печатает `'2'` уже в кадре, где исключение произошло. точка `breakpoint()` в этом тексте стоит после сложения, поэтому на аварийной итерации до неё выполнение не доходит. остановку на этой ошибке даёт шаг `n`.
