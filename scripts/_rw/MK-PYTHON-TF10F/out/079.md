**мультипроцессорность** (multiprocessing) задаёт модель параллельного исполнения, в которой программа порождает отдельные процессы операционной системы. у каждого процесса собственное адресное пространство, и планировщик ос вправе поставить его на отдельное ядро процессора. с точки зрения модели памяти процессы изолированы: запись в объект одного процесса остаётся невидимой для другого, пока значение явно не передано механизмом межпроцессного взаимодействия.

в cpython мультипроцессорность необходима из-за **global interpreter lock** (`GIL`). `GIL` является мьютексом интерпретатора: в каждый момент времени байткод python исполняет только один поток. блокировка защищает счётчик ссылок и остальные внутренние структуры времени выполнения. отсюда семантика потоков: модуль `threading` чередует потоки, но не ускоряет чисто вычислительную нагрузку (cpu-bound) на многоядерном процессоре. `GIL` отпускается на время части операций ввода-вывода и внутри ряда расширений на c, поэтому потоки уместны там, где исполнение ждёт внешний ресурс. модуль **multiprocessing** обходит ограничение иначе. каждый дочерний процесс поднимает собственный интерпретатор со своим `GIL`, и вычислительная работа исполняется параллельно на разных ядрах.

когда уместны процессы и когда уместны потоки, определяется тем, на что уходит время задачи:

- мультипроцессорность (multiprocessing): для cpu-bound задач, то есть для вычислений, которые непрерывно занимают процессор. сюда относятся обработка изображений, математическое моделирование, разбор больших объёмов данных и аналогичная нагрузка.
- многопоточность (threading): для i/o-bound задач, то есть для операций ввода-вывода, где основное время занимает ожидание. сюда относятся запросы к сайтам, чтение файлов, работа с базами данных.

свойства мультипроцессорности, которые следуют из изоляции процессов:

- полный обход `GIL`: в работе участвуют все ядра cpu.
- устойчивость к отказу отдельного процесса: падение одного процесса не разрушает адресное пространство остальных.
- применимость к тяжёлым математическим вычислениям.

ограничения той же модели:

- расход памяти: каждый процесс получает собственное окружение интерпретатора и дополнительно занимает ram. при методе запуска spawn, принятом в windows и macos, интерпретатор поднимается заново, а аргументы сериализуются. при fork, исторически используемом в linux, страницы разделяются по семантике copy-on-write и физически копируются только при записи.
- запуск медленнее создания потока: нужны процесс операционной системы, интерпретатор и каналы обмена.
- обмен данными устроен через ipc. в модуле для этого есть `Queue`, каналы и менеджеры.

### создание процесса

основной способ создать процесс даёт класс `Process` из модуля `multiprocessing`. конструктор имеет такую сигнатуру:

```python
class multiprocessing.Process(group=None, target=None, name=None, args=(), kwargs={}, *, daemon=None)
```

параметры, которые задают, что именно будет исполняться:

- `target`: вызываемый объект, обычно функция, с которого начинается исполнение процесса. значение по умолчанию `None` означает, что отдельного вызова нет и тело процесса пусто.
- `name`: имя процесса.
- `args`: кортеж позиционных аргументов для `target`.
- `kwargs`: словарь именованных аргументов для `target`.

объект `Process` описывает задачу, исполняемую в отдельном процессе. набор методов по назначению совпадает с методами класса `threading.Thread`: запуск, ожидание завершения, опрос состояния, имя, признак демона. сходство api сознательное, при том что модель памяти у модулей разная: поток делит адресное пространство процесса, а `Process` его не делит.

простейший объект процесса создаётся так:

```python


from multiprocessing import Process    # импортируем класс Process



# Создаем объект процесса

my_process = Process(target=print, name="Print_Process", args=("Hello enoobis.ru",))



print(my_process)
```

сначала импортируется класс `multiprocessing.Process`. в конструкторе процесс вызывает встроенную функцию `print` (`target=print`), получает имя `"Print_Process"` (`name="Print_Process"`) и передаёт в `print` строку `"Hello enoobis.ru"` (`args=("Hello enoobis.ru",)`). запятая после строки обязательна: параметр `args` имеет тип кортежа. выражение `("Hello enoobis.ru")` без запятой является строкой в скобках, а не кортежем из одного элемента, и такой аргумент не соответствует контракту конструктора.

### запуск одного процесса

как и у потока `threading.Thread`, исполнение начинается методом `start()` объекта `Process`. ниже процесс печатает одно сообщение:

```python


from multiprocessing import Process     # подключаем класс Process



if __name__ == '__main__':

    # Создаем объект процесса

    my_process = Process(target=print, args=("Hello enoobis.ru",))

    

    # Запускаем процесс

    my_process.start()

    

    # Ожидаем завершения процесса, прежде чем идти дальше

    my_process.join()

    

    print("Главный процесс завершил работу.")
```

вызов `my_process.start()` порождает процесс операционной системы, и в нём выполняется `print()` со строкой `"Hello enoobis.ru"`. `join()` блокирует родителя до завершения потомка: после перехода потомка в завершённое состояние родитель продолжает исполнение со следующей инструкции. вывод программы:

```bash


Hello enoobis.ru

Главный процесс завершил работу.
```

код, который создаёт процессы средствами `multiprocessing`, помещают в блок `if __name__ == '__main__'`. защита связана со способом запуска потомка. при методе spawn дочерний процесс заново импортирует модуль. если создание процессов записано на верхнем уровне модуля, импорт снова выполнит этот код, и порождение процессов пойдёт рекурсивно. проверка `__name__` отличает исходный запуск модуля от повторного импорта. на платформах с методом fork по умолчанию рекурсия менее вероятна, но защита нужна для переносимого кода.

в созданный процесс передаётся и собственная функция:

```python


from multiprocessing import Process

import os

import time



def work(name):

    pid = os.getpid()   # получаем идентификатор процесса в системе

    print(f"[{os.getpid()}] Процесс {name} запущен.")

    time.sleep(2)   # задержка на 2 секунды - имитация работы

    print(f"[{os.getpid()}] Процесс {name} завершил работу.")



if __name__ == "__main__":

    # Создаем объект процесса

    my_process = Process(target=work, args=("Process 1",))

    

    # Запускаем процесс

    my_process.start()

    

    # Ожидаем завершения процесса, прежде чем идти дальше

    my_process.join()

    

    print("Главный процесс завершил работу.")
```

функция `work()` печатает два сообщения. идентификатор процесса на уровне операционной системы возвращает `os.getpid()`: это pid, назначенный ядром. задержка `time.sleep(2)` имитирует работу в две секунды. на это время процесс остаётся живым, но не занимает ядро вычислениями. пример вывода:

```bash


[27010] Процесс Process 1 запущен.

[27010] Процесс Process 1 завершил работу.

Главный процесс завершил работу.
```

### свойства процесса

у класса `Process` жизненный цикл наблюдают по следующим свойствам:

- `name`: имя процесса, строка исключительно для идентификации. на планирование и на права процесса имя не влияет. разным процессам допустимо одно и то же имя. если конструктор не получил имя явно, оно строится по шаблону `"Process-N1:N2:...:Nk"`, где каждое `Nk` является порядковым номером дочернего процесса относительно родительского.
- `pid`: идентификатор процесса (pid). до вызова `start()` поле равно `None`, потому что процесса операционной системы ещё нет.
- `exitcode`: код завершения дочернего процесса. пока процесс не завершился, поле равно `None`.

чтение свойств после ожидания завершения:

```python


from multiprocessing import Process



if __name__ == "__main__":

    # Создаем объект процесса

    my_process = Process(target=print, name="Print_Process", args=("Hello enoobis.ru",))

    

    my_process.start()  # Запускаем процесс

    

    my_process.join()   # Ожидаем завершения процесса



    print("name = ", my_process.name)

    print("pid = ", my_process.pid)

    print("exitcode = ", my_process.exitcode)
```

пример вывода:

```bash


Hello enoobis.ru

name =  Print_Process

pid =  40098

exitcode =  0
```

имя совпадает с переданным в конструктор значением `"Print_Process"`. если бы имя в конструктор не передали, значением по умолчанию было бы `"Process-1"`. свойство `exitcode` равно `0`, и этот код означает успешное завершение. другое числовое значение сигнализирует об ошибке. после `join()` по `exitcode` проверяют, завершился ли процесс успешно. в unix отрицательный код вида `-N` дополнительно означает завершение сигналом `N`.

### пул процессов (process pool) и метод map

если одну функцию нужно применить к длинному списку данных, отдельные объекты `Process` на каждый элемент неудобны. класс `multiprocessing.Pool` держит набор рабочих процессов и сам распределяет задачи по ядрам. пример:

```python


from multiprocessing import Pool



import time



def square_number(number):

    time.sleep(0.5)  # Имитация тяжелых вычислений

    result = number ** 2

    print(f"Число {number} возведено в квадрат: {result}")

    return result



if __name__ == "__main__":

    numbers = [1, 2, 3, 4, 5]

    

    start_time = time.time()

    

    # Создаем пул процессов (по умолчанию равен количеству ядер CPU)

    with Pool() as pool:

        # pool.map берет функцию и список аргументов, выполняя их параллельно

        results = pool.map(square_number, numbers)

        

    end_time = time.time()

    

    print(f"Результаты: {results}")

    print(f"Затраченное время: {end_time - start_time:.2f} сек.")
```

пул создаётся контекстным менеджером, чтобы время жизни рабочих процессов совпало с блоком:

```python
with Pool() as pool:
```

при входе в блок пул поднимает рабочие процессы. при выходе контекстный менеджер завершает их и дожидается остановки, поэтому процессы не остаются после конца блока. число процессов по умолчанию равно числу ядер, которое сообщает `os.cpu_count()`.

внутри блока задачи отдаются методом **map()**:

```python
pool.map(square_number, numbers)
```

первый параметр метода является действием, которое выполняется в рабочем процессе. здесь это функция `square_number`: она возводит число в квадрат, а перед этим ждёт половину секунды, имитируя стоимость вычисления.

второй параметр является итерируемым объектом. здесь это список `numbers`. метод `map` разбивает итерируемый объект на фрагменты и передаёт их в пул как отдельные порции работы. размер фрагмента задаёт параметр `chunksize`. функция вызывается для каждого элемента, а не получает фрагмент целиком одним аргументом. результаты возвращаются списком в порядке исходного итерируемого объекта: порядок выхода совпадает с порядком входа, даже если рабочие процессы заканчивают элементы в другом порядке. вызов `map` синхронный и возвращает управление только после обработки всех элементов.

пример вывода:

```bash


Число 1 возведено в квадрат: 1

Число 2 возведено в квадрат: 4

Число 3 возведено в квадрат: 9

Число 4 возведено в квадрат: 16

Число 5 возведено в квадрат: 25

Результаты: [1, 4, 9, 16, 25]

Затраченное время: 0.58 сек.
```

последовательное исполнение тех же пяти пауз по `0.5` секунды заняло бы около 2,5 секунды. на четырёхядерном процессоре тот же набор укладывается примерно в 1 секунду: четыре элемента идут одновременно, пятый занимает следующий шаг. в показанном прогоне измерено 0,58 секунды.

число запускаемых процессов задаётся аргументом конструктора `Pool`. положительное целое ограничивает размер пула. передача этого числа именно в `map` размер пула не меняет: `map` распределяет уже созданные рабочие процессы.

```python


from multiprocessing import Pool

import time

import os



def square_number(number):

    pid = os.getpid()

    time.sleep(0.5)  # Имитация тяжелых вычислений

    result = number ** 2

    print(f"[PID {pid}] Число {number} возведено в квадрат: {result}")

    return result



if __name__ == "__main__":

    numbers = [1, 2, 3, 4, 5]

    

    start_time = time.time()

    

    # Создаем пул процессов (по умолчанию равен количеству ядер вашего CPU)

    with Pool(2) as pool:

        # pool.map берет функцию и список аргументов, выполняя их параллельно

        results = pool.map(square_number, numbers)

        

    end_time = time.time()

    

    print(f"Результаты: {results}")

    print(f"Затраченное время: {end_time - start_time:.2f} сек.")
```

для наглядности `square_number` печатает идентификатор текущего процесса, полученный через `os.getpid()`. пример вывода:

```bash


[PID 41380] Число 1 возведено в квадрат: 1

[PID 41381] Число 2 возведено в квадрат: 4

[PID 41380] Число 3 возведено в квадрат: 9

[PID 41381] Число 4 возведено в квадрат: 16

[PID 41380] Число 5 возведено в квадрат: 25

Результаты: [1, 4, 9, 16, 25]

Затраченное время: 1.56 сек.
```

в прогоне участвуют ровно два процесса, с pid `41380` и `41381`. пул не создаёт процесс на каждый элемент: рабочие живут всё время блока `with` и забирают следующие числа по мере освобождения. относительно пула по числу ядер время выросло. пять задач по `0.5` секунды на двух рабочих требуют трёх последовательных шагов, около 1,5 секунды, плюс накладные расходы на передачу. в прогоне это 1,56 секунды.
