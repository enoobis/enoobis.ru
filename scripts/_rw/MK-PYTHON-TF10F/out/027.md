в предыдущей лекции класс `Employee` полностью перенимал поведение класса `Person`:

```python
class Person:

    def __init__(self, name):
        self.__name = name   # имя человека

    @property
    def name(self):
        return self.__name

    def display_info(self):
        print(f"Name: {self.__name} ")


class Employee(Person):

    def work(self):
        print(f"{self.name} works")
```

это поведение можно изменить. работнику через конструктор добавляется новый атрибут, который хранит компанию, где он работает, либо меняется реализация метода `display_info`. python позволяет переопределить поведение базового класса: метод производного класса с тем же именем находится при поиске раньше метода суперкласса.

классы меняются так:

```python
class Person:

    def __init__(self, name):
        self.__name = name   # имя человека

    @property
    def name(self):
        return self.__name

    def display_info(self):
        print(f"Name: {self.__name}")


class Employee(Person):

    def __init__(self, name, company):
        super().__init__(name)
        self.company = company

    def display_info(self):
        super().display_info()
        print(f"Company: {self.company}")

    def work(self):
        print(f"{self.name} works")


tom = Employee("Tom", "Microsoft")
tom.display_info()  # Name: Tom
                    # Company: Microsoft
```

в классе `Employee` добавляется атрибут `self.company`, который хранит компанию работника. метод `__init__()` принимает три параметра: `self`, второй для установки имени и третий для установки компании. если в базовом классе конструктор определён методом `__init__` и производный класс меняет логику конструктора, конструктор производного класса вызывает конструктор базового. в конструкторе `Employee` вызывается конструктор класса `Person`.

для обращения к базовому классу используется выражение `super()`. в конструкторе `Employee` выполняется вызов:

```python
super().__init__(name)
```

это выражение вызывает конструктор класса `Person` и передаёт в него имя работника. имя устанавливается именно в конструкторе `Person`. в самом конструкторе `Employee` записывается только свойство `company`. вызов `super()` без аргументов привязан к классу, где он записан, и к текущему экземпляру. поиск имени начинается со следующего класса в mro, поэтому из `Employee` вызов `__init__` доходит до `Person` и на конструктор `Employee` повторно не заходит.

кроме того, в классе `Employee` переопределяется метод `display_info()`: в него добавляется вывод компании работника. этот метод можно определить и так:

```python
def display_info(self):
    print(f"Name: {self.name}")
    print(f"Company: {self.company}")
```

тогда строка вывода имени повторила бы код из класса `Person`. если эта часть совпадает с методом базового класса, повторять её незачем. выражение `super()` снова обращается к реализации `display_info` в классе `Person`:

```python
def display_info(self):
    super().display_info()      # обращение к методу display_info в классе Person
    print(f"Company: {self.company}")
```

затем конструктор `Employee` создаёт объект этого класса, и у объекта вызывается метод `display_info`:

```python
tom = Employee("Tom", "Microsoft")
tom.display_info()
```

консольный вывод программы:

```consoletext
Name: Tom
Company: Microsoft
```

### проверка типа объекта

при работе с объектами операция выбирается по их типу. тип проверяет встроенная функция `isinstance()`. она принимает два параметра:

```python
isinstance(object, type)
```

первый параметр представляет объект, второй представляет тип, на принадлежность к которому выполняется проверка. если объект является экземпляром указанного типа, функция возвращает `True`. проверка учитывает наследование: экземпляр подкласса проходит её и для своего класса, и для суперкласса. экземпляр `Employee` даёт `True` и на `Employee`, и на `Person`.

далее используется иерархия классов `Person`, `Employee` и `Student`:

```python
class Person:

    def __init__(self, name):
        self.__name = name   # имя человека

    @property
    def name(self):
        return self.__name

    def do_nothing(self):
        print(f"{self.name} does nothing")


#  класс работника
class Employee(Person):

    def work(self):
        print(f"{self.name} works")


#  класс студента
class Student(Person):

    def study(self):
        print(f"{self.name} studies")


def act(person):
    if isinstance(person, Student):
        person.study()
    elif isinstance(person, Employee):
        person.work()
    elif isinstance(person, Person):
        person.do_nothing()


tom = Employee("Tom")
bob = Student("Bob")
sam = Person("Sam")

act(tom)    # Tom works
act(bob)    # Bob studies
act(sam)    # Sam does nothing
```

класс `Employee` определяет метод `work()`, класс `Student` определяет метод `study()`.

здесь же определена функция `act`. она проверяет через `isinstance`, к какому типу относится параметр `person`, и по результату проверки вызывает соответствующий метод объекта. сначала проверяется `Student`, затем `Employee`, затем `Person`. этот порядок следует из отношения подтипа. проверка на `Person` истинна и для работника, и для студента. если поставить её первой, вызовы `study` и `work` окажутся недостижимы.
