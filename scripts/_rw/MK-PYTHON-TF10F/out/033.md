### встроенные типы исключений

в предыдущем примере блок `except` без типа обрабатывал сразу все исключения, которые могут возникнуть в коде. тип обрабатываемого исключения можно указать после слова `except`:

```python
try:
    number = int(input("Введите число: "))
    print("Введенное число:", number)
except ValueError:
    print("Преобразование прошло неудачно")
print("Завершение программы")
```

здесь блок `except` обрабатывает только исключения типа `ValueError`, которые возникают при неудачном преобразовании строки в число. исключение другого класса из этого блока не перехватывается и уходит дальше по стеку.

в python выделены следующие базовые типы исключений:

- `BaseException`: базовый тип для всех встроенных исключений

- `Exception`: базовый тип, который обычно применяют при создании собственных типов исключений

- `ArithmeticError`: базовый тип для исключений, связанных с арифметическими операциями (`OverflowError`, `ZeroDivisionError`, `FloatingPointError`)

- `BufferError`: тип исключения, которое возникает, когда операцию с буфером выполнить нельзя

- `LookupError`: базовый тип для исключений, возникающих при обращении к коллекциям по некорректному ключу или индексу (например, `IndexError`, `KeyError`)

от этих классов наследуются конкретные типы исключений. встроенных исключений в python много. полный перечень приведён в [документации](https://docs.python.org/3/library/exceptions.html). ниже перечислены некоторые из наиболее частых:

- `IndexError`: исключение возникает, если индекс при обращении к элементу коллекции находится вне допустимого диапазона

- `KeyError`: возникает, если в словаре отсутствует ключ, по которому происходит обращение к элементу словаря

- `OverflowError`: возникает, если результат арифметической операции не может быть представлен текущим числовым типом (обычно типом `float`). целые числа в python имеют произвольную точность, поэтому переполнение чаще относится к вещественной арифметике

- `RecursionError`: возникает, если превышена допустимая глубина рекурсии. предел задаёт интерпретатор (по умолчанию его читают и меняют через `sys.getrecursionlimit` и `sys.setrecursionlimit`)

- `TypeError`: возникает, если операция или функция применяется к значению недопустимого типа

- `ValueError`: возникает, если операция или функция получают объект корректного типа с некорректным значением

- `ZeroDivisionError`: возникает при делении на ноль

- `NotImplementedError`: тип исключения для указания, что какие-то методы класса не реализованы. это исключение не совпадает с синглтоном `NotImplemented`, который специальные методы возвращают, чтобы интерпретатор попробовал отражённую операцию

- `ModuleNotFoundError`: возникает, когда модуль не удаётся найти при импорте директивой `import`. с версии 3.6 это подкласс `ImportError`

- `OSError`: тип исключений, которые генерируются при ошибках операционной системы (например, невозможно найти файл, память диска заполнена и тому подобное)

если в программе могут возникнуть исключения разных типов, их обрабатывают по отдельности, дополнительными ветвями `except`. при возникновении исключения python ищет подходящий блок `except` сверху вниз и выполняет первый, чей класс является классом исключения или его базовым классом:

```python
try:
    number1 = int(input("Введите первое число: "))
    number2 = int(input("Введите второе число: "))
    print("Результат деления:", number1/number2)
except ValueError:
    print("Преобразование прошло неудачно")
except ZeroDivisionError:
    print("Попытка деления числа на ноль")
except BaseException:
    print("Общее исключение")
print("Завершение программы")
```

если исключение возникло при преобразовании строки в число, его обрабатывает блок `except ValueError`. если второе число равно нулю и происходит деление на ноль, возникает `ZeroDivisionError`, и его обрабатывает блок `except ZeroDivisionError`.

тип `BaseException` представляет общее исключение: под него попадают все исключительные ситуации, включая `KeyboardInterrupt` и `SystemExit`. поэтому любое исключение, которое не является `ValueError` или `ZeroDivisionError`, в этом примере обрабатывается в блоке `except BaseException`. ветвь стоит последней. обработчик базового класса, поставленный выше обработчика подкласса, перехватил бы и подкласс, и нижние ветви стали бы недостижимы. для ошибок приложения обычно ставят `Exception`, оставляя системный выход и прерывание с клавиатуры необработанными.

если возникает исключение типа, для которого нет соответствующего блока `except`, обработчик не находится, и исключение распространяется дальше. программа завершается аварийно:

```python
try:
    number1 = int(input("Введите первое число: "))
    number2 = int(input("Введите второе число: "))
    print("Результат деления:", number1/number2)
except ZeroDivisionError:
    print("Попытка деления числа на ноль")
print("Завершение программы")
```

здесь предусмотрена обработка деления на ноль блоком `except ZeroDivisionError`. если пользователь введёт строку, которую нельзя преобразовать в число, возникнет `ValueError`. для него блока `except` нет, поэтому программа аварийно завершит выполнение. сообщение после конструкции напечатано не будет.

один блок `except` может обрабатывать сразу несколько типов. типы передают кортежем в скобках:

```python
try:
    number1 = int(input("Введите первое число: "))
    number2 = int(input("Введите второе число: "))
    print("Результат деления:", number1/number2)
except (ZeroDivisionError, ValueError):    #  обработка двух типов исключений - ZeroDivisionError и ValueError
    print("Попытка деления числа на ноль или некорректный ввод")

print("Завершение программы")
```

сравнение идёт с каждым элементом кортежа. и `ZeroDivisionError`, и `ValueError` попадают в одну ветвь и дают одно и то же сообщение.

### получение информации об исключении

оператор `as` передаёт экземпляр исключения в переменную, которую затем используют в блоке `except`:

```python
try:
    number = int(input("Введите число: "))
    print("Введенное число:", number)
except ValueError as e:
    print("Сведения об исключении", e)
print("Завершение программы")
```

пример некорректного ввода:

```bash
Введите число: fdsf
Сведения об исключении invalid literal for int() with base 10: 'fdsf'
Завершение программы
```

переменная `e` ссылается на экземпляр `ValueError`. печать `e` вызывает `str` и показывает сообщение исключения, то же, что интерпретатор включил бы в трассу: `invalid literal for int() with base 10`. аргументы конструктора исключения лежат в кортеже `e.args`. по завершении блока `except` имя `e` удаляется: так разрывается ссылка с экземпляра исключения на кадр стека, где это имя было связано.
