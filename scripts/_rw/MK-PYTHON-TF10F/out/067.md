python поддерживает множество различных типов файлов, но условно их делят на два вида: текстовые и бинарные. текстовые файлы сохраняют информацию в текстовом виде. к ним относятся, например, файлы с расширением csv, txt, html. бинарные файлы хранят байты без текстового разбора: изображения, аудио и видео. в зависимости от типа файла работа с ним отличается. в текстовом режиме методы отдают и принимают `str`, байты декодируются и кодируются, переводы строк приводятся к соглашению платформы. в бинарном режиме методы работают с `bytes`, перекодирования нет и переводы строк не подменяются.

при работе с файлами соблюдают последовательность операций:

- открытие файла с помощью метода `open()`

- чтение файла с помощью метода `read()` или запись в файл посредством метода `write()`

- закрытие файла методом `close()`

### открытие и закрытие файла

чтобы начать работу с файлом, его открывают с помощью функции `open()`. формальное определение:

```python
open(file, mode)
```

первый параметр функции представляет путь к файлу. путь может быть абсолютным, то есть начинаться с буквы диска, например `C://somedir/somefile.txt`. путь может быть относительным, например `somedir/somefile.txt`. относительный путь разрешается от текущего рабочего каталога процесса. каталог, в котором лежит скрипт, становится точкой отсчёта только если процесс запущен из этого каталога. само расположение файла скрипта относительный путь не строит. такой путь собирают отдельно, обычно от `__file__`. на windows в пути допустимы и прямые слеши.

второй передаваемый аргумент `mode` устанавливает режим открытия файла в зависимости от того, что с ним собираются делать. существуют 4 общих режима и комбинации на их основе:

- `r` (read). файл открывается для чтения. если файл не найден, то генерируется исключение `FileNotFoundError`

- `w` (write). файл открывается для записи. если файл отсутствует, то он создается. если подобный файл уже есть, то он создается заново, и соответственно старые данные в нем стираются. усечение происходит в момент открытия

- `a` (append). файл открывается для дозаписи. если файл отсутствует, то он создается. если подобный файл уже есть, то данные записываются в его конец

- `b` (binary). используется для работы с бинарными файлами. применяется вместе с другими режимами, `w` или `r`, например `rb` (чтение бинарных файлов) и `wb` (запись бинарных файлов). без `b` режим текстовый, даже если буква `t` не указана

- `r+` . файл открывается одновременно для чтения и записи. если файл не найден, то генерируется исключение `FileNotFoundError`. существующий файл не усекается, позиция начинается с начала

- `w+` . файл открывается одновременно для чтения и записи. если файл не существует, то он автоматически создается. если файл существует, то он перезаписывается

- `a+` . файл открывается одновременно для чтения и записи. если файл не существует, то он автоматически создается. если файл существует, то данные добавляются в конец файла. запись в этом режиме всегда идёт в текущий конец файла

в текстовом режиме есть параметр `encoding`. если его не передать, кодировка берётся из локали процесса и от машины к машине может различаться. для переносимого текста кодировку задают явно, чаще всего utf-8.

например, открытие текстового файла на запись:

```python
myfile = open("hello.txt", "w")
```

открытие бинарного файла на чтение:

```python
myfile = open("image.png", "rb")
```

после завершения работы с файлом его обязательно закрывают методом `close()`. данный метод освобождает все связанные с файлом используемые ресурсы, в том числе дескриптор операционной системы, и сбрасывает буфер записи. пока `close` не вызван, записанные данные могут оставаться в буфере процесса. момент закрытия через сборщик мусора не задан, рассчитывать на него как на точку закрытия нельзя.

например, откроем для записи текстовый файл `"hello.txt"`:

```python
myfile = open("hello.txt", "w")

myfile.close()
```

при открытии файла или в процессе работы с ним возможны различные исключения, например к файлу нет доступа. в этом случае выполнение не дойдёт до вызова метода `close`, и соответственно файл не будет закрыт.

исключения обрабатывают так:

```python
try:
    myfile = open("hello.txt", "w")
    try:
        print("Работа с файлом")
    finally:
        myfile.close()
except Exception as ex:
    print(ex)
```

вся работа с файлом идёт во вложенном блоке `try`. если возникнет какое-либо исключение, то в любом случае в блоке `finally` файл будет закрыт. внешний `try` ловит и ошибку самого `open`, и ошибку из внутренней части. если `open` поднял исключение, внутренний блок не начинается, а внешний `except` печатает объект исключения. если исключение возникло после успешного открытия, блок `finally` всё равно вызывает `close`, и только затем исключение идёт во внешний `except`. `finally` выполняется и при нормальном выходе из блока.

более удобная конструкция, конструкция `with`:

```python
with open(file, mode) as myfile:
	инструкции
```

эта конструкция определяет для открытого файла переменную `myfile` и выполняет набор инструкций. после их выполнения файл автоматически закрывается. даже если при выполнении инструкций в блоке `with` возникнут какие-либо исключения, то файл всё равно закрывается. файл, возвращённый `open`, является контекстным менеджером: при входе вызывается `__enter__`, его результат связывается с именем после `as`, при выходе из блока по любой причине вызывается `__exit__`, и уже он закрывает файл. `__exit__` файлового объекта исключение не подавляет, оно распространяется дальше.

так, предыдущий пример на `with`:

```python
with open("hello.txt", "w") as myfile:
    print("Работа с файлом myfile")
```
